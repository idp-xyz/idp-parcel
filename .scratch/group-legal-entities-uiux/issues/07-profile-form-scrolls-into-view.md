# 07 — 资料表单展开后滚进视野

**Parent:** [spec](../spec.md)

**What to build:** 点详情栏的主动作「登记资料修订」，应该切到法人资料签、展开登记表单，并滚到表单的位置。

- 之前没打开过法人资料签：一切正常。
- 打开过之后，再从别的签点主动作：表单展开了，却停在视野底边之外，看起来像什么都没发生。

**复现：** 选中一行，点「法人资料」签，再点「修订历史」签，最后点头部的「登记资料修订」。

**根因：** 资料区收到打开请求后，在同一个 effect 里先把表单设为展开，紧接着就滚动。这时表单还没渲染出来，内容高度不够，滚动距离被截断了。第一次能成功，是因为那时资料区挂载时就带着「已请求」的初值，表单随资料区一起渲染了出来。

**Blocked by:** None — can start immediately

**Category:** bug

**Status:** resolved

## 完成记录（2026-10-16，作者会话，前端切片直接在 main 上做）

- **落点：** 代码与票面认领同在 `e458f3a1`。
- **改了什么：** `LegalEntityProfileSection` 收到打开请求时只做两件事：把表单设为展开，并把请求号记进 `scrollRequest`。另一个 effect 按 `scrollRequest` 去滚，这时展开那一次已经提交，表单在 DOM 里，内容高度够滚。连点两次主动作，请求号每次都变，所以每次都会滚。
- **判据：** 用真浏览器（Playwright Chromium，1440×900）验证。从三种起点点详情栏「登记资料修订」，量「提交资料修订」所在表单的顶边，与详情栏滚动区的可视范围对比；判据是顶边在可视区内，且至少露出 200px。
  - ✅ 票面的复现路径（先开法人资料签，再切到身份修订签）：修前顶边在 y=834，可视区为 522–878，只露 44px；修后 y=543。
  - ✅ 从未打开过法人资料签：修前、修后都是 y=543。
  - ✅ 本来就停在法人资料签：修前 y=834，**这一种也是坏的，票面只写了第一种**；修后 y=543。
  - ✅ 三道门：`tsc -b --noEmit` 退 0，`run-tests` 530/530，`vite build` 退 0。effect 时序是布局行为，不在 node:test 的范围内，按票面靠真浏览器验证。

# 02 — 表单标签不再挂载荷路径

**Parent:** [spec](../spec.md)

**What to build:** `pages/party` 下的登记表单和发布表单，每个格子的标签后面都跟着一串载荷路径，比如 `legalEntities[0].legalEntityId`、`profiles[0].revision`。配置员读到的是一串实现名。

这条路径真正的用处，是把服务端点名的问题挂到对应的格子下面。这件事照旧，只是路径不再显示在标签上。

如果服务端点名的路径对不上任何一格，就按现有做法把路径连同问题一起显示出来，因为那时路径是有用的定位信息。

非载荷格的标签也不再带内部键名，比如法人资料区「按时点查看」后面那个 `at`。

**Blocked by:** None — can start immediately

**Category:** enhancement

**Status:** resolved

- [x] `pages/party` 下所有表单的格子标签都不含载荷路径或内部键名
- [x] 服务端点名的问题照旧挂在对应格子下；对不上任何格子的问题仍带路径显示
- [x] 三道门退 0

## 完成记录（2026-10-16，作者会话，前端切片直接在 main 上做）

- **落点：** 代码与票面认领同在 `11723d6e`。
- **改了什么：**
  - 共用格件 `Field` 的标签只显标签，路径仍用来认领问题。docblock 写明为什么不显。

  - 接受前财务控制策略、客户服务规则两张表单的子表行头不再显 `rowPath`。

- **TDD：** 没有单测。`PublicationFormFields` 引了 `@idpxyz/*`，node:test 的 CJS 链上渲染不了（见 `section-error.test.ts` 文件头），所以改用真浏览器验证。

## Comments

**收口后补记（2026-10-16，作者会话，做 03 时发现）**：标签显路径原本是有意的设计。`PublicationFormFields.tsx` 文件头写的「抬齐后一律显」出自票 [admin-write-faces/22](../../admin-write-faces/issues/22-publication-form-private-helpers-lift-to-party-shared-layer.md) 的「三处呈现上的有意变化 (a)」，理由是让操作者把公共半边列出的未认领路径与眼前的格对上。那是实施方自定的呈现取舍，原文标着「评审可以不同意」，不是用户裁决，用户已在本批拆票时认可了 02，所以本票的方向不变。

立票和实施 02 时漏看了这段文件头：`11723d6e` 改了 `Field` 的渲染，文件头那句却没跟着改，留下一句过时话。已在随后一笔改成新规则并写明取舍：未认领的路径按定义没有哪一格认领它，对上它靠子表行头的「第 n 行」和格名，不靠格旁的路径原词。

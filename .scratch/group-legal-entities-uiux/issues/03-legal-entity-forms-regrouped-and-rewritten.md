# 03 — 法人两张表单重排、说明改写

**Parent:** [spec](../spec.md)

**What to build:** 改的是「登记责任法人」和「登记资料修订」两张表单，读的人是运营配置员。

现在的问题有三个：
- 说明框写着 `POST` 端点和「表单只负责把格编对」这类实现交代。
- 几乎每个格子下面都重复一句「由服务端判」。
- 首笔登记也显示「身份更正依据」，可首笔修订根本不收更正依据。另外，「生效自」夹在依据和注册国家之间，把身份格拆散了。

本票做四件事：

- **分组**
  - 登记表单分三组：身份（法人标识、业务参与方身份、注册国家 / 地区、终身注册号）、登记（登记依据、生效自）、高级（修订号、身份更正依据）。
  - 资料表单同样分三组：资料内容、登记、高级。
- **高级组默认收起。** 如果法人标识与已取回列表里的某个在册法人对得上，也就是这是一笔更正修订，就自动展开，并说明这是该法人的下一修订。列表可能已经陈旧，所以这里只做展开，不隐藏、不锁定任何格子。
- **说明框改写。** 去掉端点和实现交代，只留下配置员需要记住的业务规则，用 party-commercial `CONTEXT.md` 的原词：
  - 首笔修订从 1 开始，此后必须连续；
  - 更正会形成新修订，并带更正依据；
  - 注册国家和注册号不作变更，号变了就是另一个法人。
- **帮助文字收口。** 「由服务端判」只在说明框里说一次。各格子下面只留能指导填写的句子。

不变的纪律：表单本地只拦编码层的问题，不裁门、不判领域规则。这条写在法人表单判读的文件头。

**Blocked by:** 02 — 表单标签不再挂载荷路径（两票改同一批格子的呈现，先去掉路径，再重排）

**Category:** enhancement

**Status:** resolved

- [x] 两张表单按上述三组呈现。高级组默认收起，法人标识对上在册法人时自动展开
- [x] 说明框里没有 HTTP 方法、端点路径或实现交代；业务规则句用 CONTEXT 原词
- [x] 各格子的帮助文字不再重复「由服务端判」
- [x] 本地校验的范围没有扩大，既有 node:test 照过；三道门退 0
- [x] 在浏览器里把两张表单各走一遍，不提交，完成记录附截图说明

## 完成记录（2026-10-16，作者会话，前端切片直接在 main 上做）

- **落点：** 代码与票面认领同在 `cc6b6141`。
- **改了什么：**
  - 表单壳 `party-registration-fields.tsx` 新增 `FormGroup`（组名、说明、两列格）和 `AdvancedGroup`（`aria-expanded` 按钮；收着时显一行摘要）。
  - `registration-form.ts` 新增纯函数 `advancedGroupOpen`，规则是：组里有问题就展开，否则按操作者的选择，操作者没点过就看是不是在册对象的下一修订。
  - 两张表单按票面分组，说明框改写成业务规则。
  - 「生效自」两处都标成「*」。领域 `NewIdentityLifecycle` 与资料修订构造都拒零时刻，旧格名「留空由服务端点名」的实际意思就是留空会被拒。
  - 法人标识格下的提示分四种情况：标识为空 / 已在册 / 列表没取到 / 不在册。列表没取到时不再说「首笔修订」。
  - `bg-idpxyz-sidebar/60` 换成实色 `bg-idpxyz-sidebar`。透明度变体在本仓不生成，见票 admin-web-group-legal-entities/15 的完成记录。
- **票面外的连带改动：**
  - **时刻格提示句：** 共用的 `WallTimeField` 格下那句从「按操作者本地时刻（…）填，送出时换成 RFC 3339 UTC」改成「按本地时刻（…）填」。这一格 `pages/party` 各登记表单共用，业务参与方等表单一并变了，都是同一个改进。
  - **候选为空时的提示：** 读面有答案但候选为空时，引用选单仍是下拉框，没有手填入口，旧提示却写着「或手填…由服务端判」。新提示不再承诺手填。这一处只改了本票两张表单传入的句子，其他表单传入的句子没动。
- **判据：**
  - ✅ 分组与高级组：真浏览器（1440×900）里，高级组默认 `aria-expanded="false"`，摘要为「身份修订号 1（建议值） · 身份更正依据不带」。法人标识填入在册的 `SYN-LE-01` 后，变成 `aria-expanded="true"`，格下提示「已在册，最新修订 身份 r1：本次登记形成它的下一修订」，修订号建议值 2。
  - ✅ 说明框里没有 HTTP 方法或端点。登记视图全页文本匹配「服务端 / RFC 3339 / POST」只命中顶栏作用域 chip（11 号票的事），表单内零处；详情栏资料表单内零处。
  - ✅ 本地校验范围没扩大：载荷与本地问题的纯函数未改，node:test 522/522（新增 `advancedGroupOpen` 一条）。
  - ✅ 三道门：`tsc -b --noEmit` 退 0，`run-tests` 522/522，`vite build` 退 0。
  - ✅ 浏览器走查：两张表单各走了一遍，没有提交。截图包括登记视图顶部、底部、在册标识展开态，以及资料表单。
- **评审：** 改动全在 `pages/**`，自查判据。
- **未验：** 「组里有问题时强制展开」只由 node:test 覆盖，没在浏览器里触发。要触发，需要在高级组收着时让修订号格出现本地编码问题，比如手填非数字后再收起。

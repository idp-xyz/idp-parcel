# 09 — 对象页与详情栏同一套结构

**Parent:** [spec](../spec.md)

**What to build:** 同一个法人，现在有两套不同的结构：

- **详情栏**：头部、生命周期条、事实条，三个签，外加主动作和「更多」菜单；
- **对象页**：只有「概要」和「时间线」两个签，资料和登记表单都塞在概要里，也没有主动作。

用户得学两套界面。

本票让对象页沿用详情栏定稿后的结构：签的名字和顺序、主动作「登记资料修订」、「更多」菜单里的动作（到业务参与方页停用、复制法人标识），以及头部信息。

对象页用的是共用的详情页模板。如果模板缺少承载这些内容的位置，补位属于共享面改动，要评审。

**签名约束：** 对象页的签名受共用模板固定词表约束（`workspace-tabs.ts`，票 admin-web-ux-alignment/04），不能逐字照搬详情栏的签名。这里的「一致」指签承载的内容和顺序一致，签名用词表里对应的那个词，例如身份修订历史放在「时间线」。

**Blocked by:** 01 — 身份修订与资料修订分开命名（签名在那里定）；06 — 详情栏头部瘦身（详情栏的定稿结构在那里定）

## 完成记录（2026-10-16，作者会话，前端切片直接在 main 上做）

- **落点：** 代码与票面认领同在 `dea994e0`。
- **改了什么：**
  - 生命周期条、停用与待补横幅、「更多」菜单从详情栏抽到 `LegalEntityHeaderParts.tsx`，详情栏与对象页各引一份，不另写第二份。
  - 对象页与详情栏一一对应：

    | 详情栏 | 对象页 |
    |---|---|
    | 头部（标识、种类、状态、副题） | 头区（标题、标识、状态、副题：参与方名称 · 参与方身份） |
    | 引用签 | 头区第二行 |
    | 事实条 + 生命周期条 | 指标带（四格 + 一格生命周期条） |
    | 概要签 | 概要签的基本信息，同一份格 |
    | 横幅 | 「需要处理」区，只在有横幅时出现 |
    | 法人资料签 | 「法人资料」区，留在概要签里 |
    | 身份修订签 | 「时间线」签 |

  - 页头动作与详情栏一致：主动作「登记资料修订」与「更多」（复制法人标识、到业务参与方页停用），外加「返回列表」。
  - 共用详情页模板新增可选受控签 `activeTab` / `onActiveTabChange`，不传时行为不变。对象页借它让主动作先回概要签，再经 `formOpenRequest` 展开并滚到表单。
- **签名：** 照改票后的判据取模板固定词表里的词。法人资料在词表里没有对应的词，所以不单独成签，留在概要签里成区。
- **判据：**
  - ✅ 签内容、签序、主动作一致：真浏览器（1440×900）里对象页的签为「概要 / 时间线」，页头为「登记资料修订 / 更多 / 返回列表」，「更多」菜单是「复制法人标识 / 到业务参与方页停用」。
  - ✅ 在对象页上直接登记资料修订：停在「时间线」签时点主动作，当前签变成「概要」，「提交资料修订」所在区的顶边在 y=308（视口 900）。探针在浏览器里拦掉了全部非 GET 请求，没有提交。

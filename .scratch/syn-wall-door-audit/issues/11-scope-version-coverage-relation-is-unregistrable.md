# 范围版本之间的覆盖关系无处登记，准入查询因此恒走保守暂停

Category: enhancement
Status: needs-triage

来源：票 02 交付过程中由 MCP-1 裁定分出（见
`.scratch/syn-wall-door-audit/issues/02-production-ownership-authority-has-no-adapter.md`
的 2026-08-21 裁定条）。**不是缺陷票**——今天的保守暂停是按 PILOT-SCOPE 明文办的诚实阻断，
本票要补的是让它有机会不保守的那份登记。

## 缺什么

`Suspensions.FindUnresumedSuspension` 现在三态回答准入：无未恢复暂停 → 开放；范围版本字面
相等 → 暂停（命中）；**有未恢复暂停但覆盖关系读不出来 → 暂停（保守）**。第三态之所以恒成立，
是因为登记册里没有任何地方记「范围版本 v1 与 v2 之间谁覆盖谁」。

`pgdomain.ScopeVersionReference` 是脱敏引用组合（客户、法人、产品、线路、伙伴等的引用），
真实值在参数登记册。从这个不透明串上**推**不出谱系——前缀、子串、版本号解析与时间序推断
一律禁止，那是从脱敏引用组合发明实例事实。所以关系只能**被登记**，不能被算出来。

## 今天的后果

登记册里只要还有一条已生效且未被恢复决定解除的暂停，任何范围版本问准入都答`暂停`。这不会把
系统钉死：一条未恢复暂停都没有时第一态成立，照常开放。但一旦有一条暂停立着，整个试点的新准入
就都拦住——这正是 PILOT-SCOPE 要的效果：

> 如果共享依赖、共同原因或证据不足导致影响范围无法可靠隔离，必须保守暂停整个试点的新准入，
> 不能仅拒绝当前报错的单个委托后继续放量。

## 要裁的

1. 覆盖关系记在哪一层：参数登记册（PAR-GOV-*）的一项，还是治理侧新增一张关系表？按 AGENTS.md
   「改试点实例状态 → 参数登记册」，倾向前者，但关系要被 `FindUnresumedSuspension` 读到就得
   在库面上有落点，两者可能都要。
2. 关系由谁登、凭什么证据登。范围版本升版本身是一次限量范围扩大的 `Go/No-Go`，覆盖关系是不是
   该作为那次决定的记录项一并落下——若是，它就不是独立登记而是 `Go/No-Go` 记录的一格。
3. 关系的形状：是「v2 承继 v1 的暂停」这种有向边，还是「v1 与 v2 互不相干」也要能显式登记。
   **两者都要能表达**——只能登「承继」的话，「确认不相干」就仍然读不出来，第三态照样恒成立。

## 红线

- **不得为了让默认路径回到「开放」而回填任何东西。** 没有租户就没有这份登记，恒走第三态是
  诚实阻断不是缺陷。
- 不得改成前缀、子串、版本号解析或时间序推断——理由见上，撞「敏感实例外置」红线。
- 关系登记不得成为一条绕过恢复决定的路：解除暂停只能靠 `RecordResumption`（原因解除证据、
  一致性核对、在途盘点、试点业务责任角色决定四件齐备）。登记一条「v2 不承继 v1」若能让 v1
  那条暂停对 v2 失效，那必须是**登记册事实**支持的结论，不是一次静默恢复。

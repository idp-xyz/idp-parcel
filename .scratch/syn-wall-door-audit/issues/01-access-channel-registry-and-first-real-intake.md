# 接入渠道登记册与首个真渠道 Intake 缺失,渠道墙想配也没处配

Category: enhancement
Status: needs-info——ADR-0072 口径的重启条件已满足，票面范围已按其 Consequences 改写（见「重启范围」）；S0 的证据缺口三项未到，未到前不进 S1

来源:SYN-WALL-DOOR-AUDIT 走通审计(基线 `49a2ab0`),对应清单 W01/W02。

## 墙

`ACCESS_CHANNEL_NOT_CONFIGURED`(403)——PS/NO/TF/VE/CC 五个上下文的 `adapters/http/unconfigured_intake.go`(`ErrAccessChannelNotConfigured`),八个业务端点在 `cmd/parcel-api/endpoints.go` 的 `assembleBusinessEndpoints` 全部装 `UnconfiguredIntake{}` + `unwired*` 编排桩。

## 现状:门四件全缺

按 ADR-0055,「空登记册就是装配点本身」:没有渠道登记册的表与迁移,没有装载口,没有写入方,没有登记口。今天「配置一个接入渠道」的唯一含义是**改装配点代码**——这在设计上是有意的(真渠道就位时逐端点替换),但它意味着 `PAR-INT-01` 的实例值没有落点,认证机制(凭据验证、来源信封铸造,ADR-0003 禁采信自报身份)整体缺席。

## 缺的最小机制件（ADR-0072 之前的票面范围，保留供下方 Comments 指认）

**这一节已被下方「重启范围」取代**，原文不删：MCP-6 的复核逐条引「票面第 1、2 件」，删了那份复核会指空。第 1 件正是 ADR-0072 维持的那条否决所禁的预拟列，读时按被取代对待。

1. 接入渠道登记册:表 + 只读装载口 + 登记口(渠道身份、凭据引用、适用客户账户/来源范围、有效区间;敏感凭据本体外置,登记册只存受控引用)。
2. 首个真渠道 Intake 实现:凭据验证 → 铸造来源信封(租户/客户账户/来源/来源请求键)→ 构造命令;替换点即 `assembleBusinessEndpoints`,路由层与处理器不动(ADR-0055 已预留)。
3. 载荷规范化摘要与准入范围装配(`PAR-GOV-03..07`)仍拦在真渠道 Intake 之前,不得绕过(ADR-0055 第五条)。

## 红线

- 不得出现任何「开发用」采信头部实现;未配置即拒的兜底在真渠道就位前不许撤。
- `PAR-INT-01` 实例值(真实渠道参数)留空是常态;本票只建门,不填值。

ADR-0055、ADR-0003、ADR-0052;`docs/product/PILOT-PARAMETER-REGISTER.md` PAR-INT-01。

## 重启范围（2026-09-01 改写，依 ADR-0072 Consequences「重启时本票范围改写为『在 `internal/accessidentity/` 按渠道证据立册与铸造信封』」）

取证基线 `1665fdb`。本节所有「当前状态」断言以该锚为准，读到时请重新取证。

### 先分清两条门槛，否则进度会被高估

- **ADR-0072 的重启门槛**是「该租户渠道的现行流程」——**已到**。候选租户现行渠道为 API：HTTP 下单入口、头部 apikey 认证、JSON 报文，字段覆盖委托、单件、申报、收寄件人与渠道代码（证据 E-02，指纹索引见 `.scratch/tenant-implementation-01/instance-register-draft.md` 证据清单；本票不复录客户名称、域名、单号与凭据）。本票据此重启。
- **参数登记册 `PAR-INT-01` 的最低证据**是四件：现行流程、委托业务标识、资料修订业务标识、重试和冲突边界。**只到两件半**。缺的那部分不卡「能不能开工」，卡的是登记册的**哪几列**与幂等语义——那是最难返工的一段，所以列为 S0。
- **`PAR-INT-01` 的登记状态上限仍是「待核验」**。按登记册的登记规则，证据完整且决定生效前不得记「已确认」；本票任何一步做完都不改变这一条。

### 本票在审计里的位置

`syn-wall-door-audit` 十五票中十四票已 `resolved`，本票是唯一未收口的一张（逐票核于 `1665fdb`）——这个数是论点本身：**门四件里挡在最前面的那一件，如今只剩它**，所以它的排期就是整条真实业务链的排期。数会随其它票变动，取证锚已写死在上一行。

### 依赖现状（三项前置的机制半边已落，实例半边未落）

- **载荷规范化摘要：机制已落**。`internal/parcelshipment/domain/payload_canonicalization.go` 按 ADR-0014 产出带形状版本的摘要（`CurrentPayloadCanonicalizationVersion`），票 14 已 `resolved`。ADR-0055 第五条拦在真渠道 Intake 之前的第一项前置，机制半边不再是缺口。
- **准入范围装配：机制已落，实例值未到**。生产归属判定的适配器在 `internal/parcelshipment/adapters/pilotgovernance/production_ownership.go`（票 02/13 已 `resolved`），但它读的那几本册所依赖的 `PAR-GOV-03..07` 在参数登记册全为「待提供」。这是 S4 的硬阻断，工程侧无法自解。
- **装配点仍全部未配置即拒**。`assembleBusinessEndpoints` 里命令面挂的是**字面量** `UnconfiguredIntake{}`，不经任何变量；隔离读准入（ADR-0078）只换查阅行的 Intake 变量，换不了命令行。真实租户今天既下不了单，也读不到自己的数据——隔离读开关 `IDP_PARCEL_ISOLATED_READ_TENANT` 只接受 `SYN-` 前缀的合成租户，填真实租户标识会让进程启动即拒。

### 步骤

#### S0 · 补齐 `PAR-INT-01` 最低证据的缺口三项

- **范围**：向客户取得重试与冲突边界、资料修订入口、凭据轮换与回调约定。**归用户 → 客户**，不是工程步骤。
- **依赖**：无。
- **验收点**：三项各有书面说明，且说明足以回答这几问——同一委托重复提交按什么判重（业务标识还是渠道请求键）、判重命中时渠道期待什么答复、资料修订走不走同一入口与同一业务标识、凭据轮换时新旧值是否有并存窗口。只回「支持幂等」不算到位：登记册的列要从这些答案里长出来。
- **本步不阻断信封铸造机制，只留一格**：来源信封四要素里的「来源请求键」就是幂等键，S0 缺的正是它该由哪个渠道字段铸成。按 MCP-1 2026-09-01 的裁决，这一格**必须显式留未决、可配置注入，不得写死默认**——留口是机制半边，选字段是实例半边。因此 S2 的铸造机制不必等 S0；等 S0 的是这一格的取值，以及 S1 里由判重与冲突语义决定的那几列。

#### S1 · 在 `internal/accessidentity/` 按 API 型渠道形状立册

- **范围**：接入渠道登记册的表与迁移、只读装载口、登记口。形状**只按 API 型渠道**立——ADR-0072 二说的是「按实际渠道形状立册」，替标准文件与门户两种尚未出现的渠道预拟列，正是那条被维持的否决所禁。
- **依赖**：S0（幂等与冲突两列的形状）；ADR-0072 一（落点与所有权）；ADR-0003（适用范围维按租户／责任法人／客户账户三级边界表达）。
- **验收点**：
  - 迁移落在 `migrations/` 下 accessidentity 自己的目录，不借用五个业务上下文任何一个的目录——所有权红线在仓储层也要看得见。
  - 凭据本体不落库，登记册只存受控引用；库里出现任何形似凭据的明文即不通过。
  - 空册可读：无行时装载口如实答「未配置」，既不报错也不用零值冒充配置（ADR-0052 的分界句在这里第二次生效）。
  - `accessidentity` 不进 CONTEXT-MAP 业务地图，不拥有业务领域语言（ADR-0072 一：它是技术能力，不是限界上下文）。

#### S2 · 凭据验证与来源信封铸造

- **范围**：验证渠道凭据 → 铸造来源信封（租户、客户账户、来源、来源请求键）→ 交给各上下文既有的 Intake 缝。
- **依赖**：S1。
- **验收点**：
  - 信封四要素无一取自请求体或自报头部。要有一条测试钉住：报文里写别人的租户，铸出来的信封不变（ADR-0003 的最高隔离边界）。
  - 提交与撤回各自铸信封，不合用——合用会让撤回被判成原提交的重放（`WithdrawalIntake` 注释里的原句）。
  - 「凭据无效」与「渠道未配置」两答可分辨：恢复动作不同，一个是换凭据，一个是去配渠道（分格判据同 ADR-0029）。
  - 渠道原始载荷 → `SubmissionPayloadSpec` 的词表落在 accessidentity 侧，不进 PS 领域包（`payload_canonicalization.go` 自证「这里一个渠道字段名都不认」）。

#### S3 · 首个端点替换（`/shipment-requests`）

- **范围**：在 `assembleBusinessEndpoints` 把这一行的字面量 `UnconfiguredIntake{}` 换成真渠道 Intake。路由层与处理器不动（ADR-0055 一已预留这条缝）。
- **依赖**：S2。
- **验收点**：
  - 只换这一行；其余命令面仍答 `403 ACCESS_CHANNEL_NOT_CONFIGURED`，由装配测试钉住「换了一口不等于全开」。
  - 隔离读开关与这一行互不顶替：两种准入形并存，谁也不能替对方放行（ADR-0078）。
  - 未配置即拒的兜底在尚未替换的端点上不撤（票面红线原条不变）。

#### S4 · 首笔真实委托穿链

- **范围**：真实客户经 API 下单 → 受理链路 → `已提交`。
- **依赖**：S3；`PAR-GOV-03..07` 实例值；实例登记册中足以受理一笔委托的最小行集。
- **验收点**：
  - 证据层级记 `P`，且该链路的任何标识上不出现 `SYN-` 前缀——合成与真实不能在同一条链上混。
  - 生产归属判定取自 pilotgovernance 册的真实行，不是隔离取值。
  - 幂等按 S0 拿到的边界作答，且答复形状与客户书面说明一致。
- **硬阻断**：`PAR-GOV-03..07` 全为「待提供」。这一条在参数到位前不可勾，也不可用合成值绕过。

#### S5 · 其余端点逐口替换

- **范围**：按业务开通顺序逐口替换剩余命令面与客户查阅面。
- **依赖**：S4。
- **验收点**：一次只换一口；每换一口，该口的传输层「未配置即拒」测试改写为真渠道测试，装配测试同步更新。未换的口答复不变。

### 不属本票

载荷规范化摘要（ADR-0072 三已拆出，票 14 `resolved`）。本票不含摘要半边，也不重新裁定它的形状版本。

若用户希望在 S0 未到前就动工：S2 的信封铸造机制不依赖幂等与冲突两列，可与 S1 拆成两票并行。但拆票改的是本票范围，属范围决定，留给用户裁。

  **一处补正：挡路的那半比先前理解的窄。** ADR-0072 **Decision 二**只说「登记册表结构与凭据

  当成已执行的事实。倒序的代价是 S2 交付时装载口那一侧只有接口没有实现，多一道缝。

  S0」，它列的四条（不采信自报身份、提交与撤回各铸不合用、两答可分辨、渠道词表不进 PS 领域包）

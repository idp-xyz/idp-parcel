# owner 复核清单：ADR-0314、0315、0316

本批三份 ADR 都是会话代决（用户授权作者会话代 owner 决），`Status` 行写着待谁复核，但没有人被指派。本页把每份要确认的决定摊开，写明认可就不用动什么、不认可要改哪里，方便复核的人直接过。三份都已进 main，代码与测试按下面的取向落地。

复核做完后的记法：在对应 ADR 的 `Status` 行标记之前那一段，把「待 X owner 复核」改写成复核结论（谁、何时、认可或要改什么）。〔代决·待 X owner 复核〕这个索引标签由 `tools/adr-index` 从那一段派生，那句「待……复核」没了标签就消失；改完跑 `go run ./tools/adr-index` 重生成索引。要推翻某个决定，按 AGENTS.md 立新 ADR 或部分停用，不改已接受 ADR 的正文。

## ADR-0314 待批准发布稿读回与摘要绑定（PC owner）

| 要确认的决定 | 不认可时要改的地方 |
|---|---|
| 批准与发布的 HTTP 载荷**必带** `expectedDigest` 与 `expectedShellDigest`，缺哪个逐格点名（旧客户端会得到 400）。这是对 ADR-0126 载荷形状的收紧 | `PublicationDraftReferencePayload` 的 `ApproveCommand` / `PublishCommand` 里的必填判断；应用层本来空串即不带前置条件，不用动 |
| 壳摘要 `PCS-1` 盖适用范围、有效区间起止、指名引用，不盖正文与身份四元。内容摘要不盖壳是 ADR-0126 的既定形状，所以壳另绑 | `PublicationDraft.ShellDigest`（domain）；组成变了要换算法版本号，旧串答 `DRAFT_CHANGED` |
| 两个读口挂**查阅读授予**：任何持查阅读的操作者都能看到未发布草稿的完整规范化文档（可能含授信额度、价格）与录入者、批准者的主体引用 | 要收窄到写授予：把 `cmd/parcel-api` 里两条读路径的面从 `operationsReadFace()` 改成登记写面，并让管理台按授予隐藏「待批准发布」入口（`useMayWriteRegistry`） |
| `DRAFT_CHANGED` 答 200 而不是 409（ADR-0022） | 批准与发布两个答复转写函数的状态码 |
| 列表按录入时刻由新到旧、`limit` 截断，超限时藏起来的是等得最久的；任一行读不回整页答 5xx；今天没有撤回或作废载体的口 | `ListOpenDrafts`；真有这么多在途稿时要立游标与撤回口，那是新票 |

## ADR-0315 授予自查读口（访问身份 owner）

| 要确认的决定 | 不认可时要改的地方 |
|---|---|
| `GET /operator-grants` 对任何持查阅读授予的操作者开放，答自己此刻的能力面与运营决定种类；没有查阅读的人与不在册同答未授予 | 若连「我持有写授予」也不该告诉只读操作者：把守口换成不依赖授予的认证件（`NewOperatorGrantsAuthenticator`），那是另一个决定 |
| 管理台只在**明确知道**没有登记册配置写授予时才收起入口，读不到、拒绝、形状不对一律「不知道」、入口照摆 | `mayWriteRegistry`（`apps/admin-web/src/pages/operator-grants.ts`）；改成「不知道就收」会让读口故障时配置员看不到入口 |
| 只用一个能力面 `REGISTRY_CONFIGURATION_WRITE` 管参与方与商业区全部写入口；`decisions` 先交出、没人用；别的区的写入口今天仍对查阅员摆出 | 推广到别区是新票：各区按自己的能力面或决定种类用同一个钩子 |
| 授予在铸造那一刻取、前端一页加载问一次，会话中途变化要整页重载才反映 | `use-operator-grants.ts` 的模块级缓存 |

## ADR-0316 逐格问题的稳定问题码（PC owner）

| 要确认的决定 | 不认可时要改的地方 |
|---|---|
| 问题码词表（含兜底 `INVALID`）与各自的参数键是**公开契约**，只增不改、不回收；原话不在承诺内 | 词表与参数键在 `publication_problem_codes.go` 的常量注释；要改含义只能立新码 |
| 多数领域错误仍落在 `INVALID`，管理台对它们继续按原话形状译 | 下一批要贴码的错误由 PC owner 点名，在对应载荷文件的构造点改用带码的原因 |
| `NOT_IN_SET` 的参数 `what` 是写死的中文格名，不是机器键；多语种时要另立稳定的格键 | 新参数键，不改 `what` |
| 管理台在页面里以字符串行带码（私有分隔符接原话）是权宜，等表单组件改成直接收问题对象时去掉 | `codedProblemLine`、`fieldProblemText`（`field-problem-text.ts`）与各表单对问题行的消费 |

## 都已验过什么

三张票各有一轮隔离评审与一轮修订；全量测试、管理台三道门、一次性库灌种子与 CI 都过；03、04、05 在演示库里有真浏览器验证（04 用查阅员与配置员两个账号对比）。没有做过的：别的区对 `/operator-grants` 的使用、读口在大量在途稿下的性能。

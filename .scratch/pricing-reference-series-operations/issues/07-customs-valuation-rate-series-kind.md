# 海关计税汇率：第三种序列种类？谁消费？

Category: enhancement
Status: resolved——裁 (c) 今天不做（2026-09-03，MCP-3，owner 授权自决）；理由与重启条件见文末「裁决」，不立 ADR（可逆：日后加一种类即可）
Blocked by: 无（裁决不依赖 01–06；实现若裁为进 parcel-pricing 则依赖 02）

## 问题

中国海关计税汇率 = 上月第三个周三的 CFETS 人民币中间价，按月固定，与结算汇率、银行牌价是不同的东西（法定值，不是商业选择）。关务旁路要算税就要它。

今天 `ReferenceSeriesKind` 是封闭集 {`FUEL_RATE`, `EXCHANGE_RATE`}，`0003` 迁移 CHECK 同步封闭；`EXCHANGE_RATE` 强制商业口径引用。拿 `EXCHANGE_RATE` 冒充海关汇率会被口径必填卡住——这是正确的墙。

## 三条路

- (a) **`parcel-pricing` 增第三种 `CUSTOMS_VALUATION_RATE`**：月度、来源 CFETS/海关总署、**不要求**商业口径；关务上下文经消费侧适配器（ADR-0025）读在用版本。理由：ADR-0013 已把「没有兄弟上下文产出的外部数值序列」整族交给计价；登记 / 复核 / 在用 / 冻结整套机制现成。代价：计价上下文承载一个自己不消费的种类。
- (b) **关务上下文自建登记册**：所有权清晰（税额归关务），代价是第二套版本化 / 复核 / 在用机制。
- (c) **今天不做**，记入 CONTEXT 或 ADR「不做的理由与重启条件」——重启条件：关务旁路的税额计算用例（`UC-CC-*`）确认需要机内计税而不是只转录海关核定值。

## 先核什么

- 关务 CONTEXT 与 ADR-0069/0070/0073：案件今天是**转录海关核定税额**还是**自算**？若只转录，(c) 即正确答案。
- 若自算：税额形成在哪个用例、按哪个时点取汇率（申报日所属月）。

## 红线

- 不改 `EXCHANGE_RATE` 的口径必填。
- 无论哪条路，真实月度取值属实例半边。

## 裁决（2026-09-03 · MCP-3，owner 授权自决）

**先核什么的答案：关务今天只转录，不自算。** `docs/domain/customs-compliance/CONTEXT.md` 把「监管核定税费」定义为本上下文**接收**的外部监管事实：Rules 写「监管接收、业务受理、监管过程决定、监管核定税费、放行结果和监管处置决定分别由合格外部事实形成，不得为了得到单一线性状态而虚构缺失结果」；税费付款协作事项「依据已接受监管核定税费……形成」，「缺少税费结果不能被解释为无需付款」——缺的时候是**未决**，不是本系统算一个出来。`internal/customscompliance/domain` 里承载税费的是 `duty_collaboration.go` 与 `duty_release.go`（协作事项与放行门禁），没有任何税额形成或汇率取用的代码；ADR-0069/0070/0073 全文不含「税额 / 计税 / 汇率」字样。

**所以 (c) 是正确答案**：机内没有消费方，第三种序列种类今天没有任何一条路会读它。(a) 会让计价上下文承载一个自己不消费、别处也不消费的种类；(b) 是为一个不存在的用例建第二套版本化机制。两条都在没有事实的地方立规则。

**重启条件（满足其一即重开本票，届时按 (a) 起步——ADR-0013 已把「没有兄弟上下文产出的外部数值序列」整族交给计价，登记 / 复核 / 在用 / 冻结整套机制现成）**：

1. 关务旁路出现**机内计税**用例（某 `UC-CC-*` 明确要求由本系统按申报价值 × 税率 × 计税汇率形成税额，而不是转录海关核定值），且该用例落进 CONTEXT；
2. 或计价侧出现按「海关计税汇率」口径计价的商业价格政策（某租户把它写进合同口径）——那时它是 `EXCHANGE_RATE` 的一种**口径**而不是新种类，先核口径引用能不能表达，再谈加种类。

**不落 CONTEXT**：parcel-pricing CONTEXT 只写拥有什么，不写不做什么；本票 resolved 作为这条「不做」的索引。**不立 ADR**：加一种序列种类是放宽一个封闭集 + 一条迁移，可逆，不属难逆转取舍。

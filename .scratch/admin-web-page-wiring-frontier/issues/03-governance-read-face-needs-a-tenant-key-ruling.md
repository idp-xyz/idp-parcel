# 治理查阅面：三张登记表没有租户维，读面形状先要裁一道键形

Category: enhancement
Status: resolved

裁决已作出（MCP-2，2026-08-26，见文末「裁决」节）：**不为治理读面开第二种隔离读准入形态，本页此刻不接线**。
本票的交付物就是那道裁决本身，不含代码改动。前半问（租户维加不加）在建表时已被裁过，见下方 2026-08-26 补记。

自[接线前沿盘点](../report.md)批 B。盘点初稿把它与票 02 归为同一批（都有 CLI、都零行、都缺查阅面），实读库结构后拆开：**键形不同，形状装不上**。键形未裁前不派。

## 事实（实读代码与演示库取证，锚 `7ce41e4`）

1. `parcel-governance-register` 的三个命令（`authority-interval`、`suspend`、`resume`）已在，第四第五类（阶段评审、接管）CLI 自己写着属第二批、未开。
2. 三张表演示库里全零行——`seed.sh` 没调用这个 CLI。
3. **三张表都没有租户列**（实测 `\d`：`authority_interval` 是 `object_scope`/`capability`/`fact_kind`/`authority` 四件加区间；`suspension_decision` 是 `suspension_id` 主键加 `scope`/`executed_by`）。
4. `pilotgovernance` **整个 `adapters/http` 包不存在**；`adapters/postgres` 五个文件全是写口，唯一的列读 `AuthorityIntervals.ListCurrent(ctx)` 不收租户参数——它是为受控登记口而设的单租户装配形状。

## 要答的那一问

`ADR-0077` 把租户放在读口方法签名上；`ADR-0078` 的隔离读准入注入的也是一个**租户**范围（`SYN-` 前缀门禁）。治理登记册没有这一维。

试点治理治的是**试点本身**、不是租户的数据，无租户维多半是对的设计——但那样一来两件事都要重答：**隔离读准入按什么放行**（今天的机制只认租户），**页面按什么隔离**。

不答就动手会得到一个「按租户过滤」的读口去查一张没有租户的表。那是本仓反复记的那个形状：**接错看着像接对**——填一个空租户或忽略该参数，答出来的恰好是当前唯一走得到的那一格正确答案，而真有第二个租户时它就错，且不会有任何东西变红。

同族先例可参：`.scratch/ve-claims-read-seams/issues/01` 记的是反过来的一种——真适配器把租户钉在装配期，多租户入口接不上，那票的裁决是**另立一个带租户维的读法、两个形状各答各的调用面、不合并**。本票要判的是治理这一格该不该有那一维，不能照抄结论。

## 勘察补记（MCP-2，2026-08-26）：前半问已经被答过了，答案在建表语句的抬头

盘点时把这一票写成「治理该不该有租户维」，那问法不成立——**已经有人裁过，而且写下来了**。`migrations/pilot_governance/0001_governance_records.sql` 第一句：

> 治理记录三表：候选版本组、阶段评审决定、生产权威区间。治理是产品级机制，没有租户维——这里登记的是「本产品此刻拿什么去评审、谁在写生产」，全部是脱敏引用，真实客户、线路与阈值留在参数登记册。

无租户不是遗漏，是设计，且理由与本票勘察时的猜测一致。**这一维不加**，本票不必再裁前半问；`ListCurrent(ctx)` 不收租户也因此是对的形状，不是单租户装配期的将就。

于是本票要答的收窄成一问，而且换了性质：

**没有租户的读面，隔离读准入按什么放行？**

`ADR-0078` Decision 一的第三条判据原文是「作用域是运营侧的授权结果——**租户维是最高隔离边界**」，Decision 三的开关注入的也正是一个租户值、由 `SYN-` 前缀门禁钉死。治理读面在这条判据上不是「满足」也不是「不满足」，是**判据落不到它身上**：它压根没有那一维。

这里有个必须点破的陷阱：判据「空洞地满足」看起来像满足。若照票 01 的办法（三条判据都对得上就直接进放行面枚举，不另开 ADR），治理这一格会以「它没有租户所以不存在跨租户泄漏」的名义混进去——那正是本票原文警告的形状，只是换了个位置：不是「按租户过滤一张没有租户的表」，而是「用一条以租户为最高边界的准入判据去放行一个没有租户的读面」。两者的共同点是**当下答案恰好正确，而正确的原因与判据说的原因无关**。

所以这一格与票 01 不同类：**它要一次 ADR 级的裁决**，因为 `ADR-0078` Decision 四把先例钉窄成「按环境选择的只有装配点上查阅行的 Intake 一件事……只此一处、只此一维」。给准入加一档「产品级脱敏登记册」的非租户放行形态，是在那句钉窄上开第二维，不是照判据填一行。

**建议（不是裁决，等用户点头或另开 ADR）**：不硬塞。两条路各自成立，代价不同——

1. **另开一条准入档**：为「产品级、脱敏、无租户」的登记册读面立第二种放行形态（开关仍是显式装配输入、仍缺省朝拦，但注入的不是租户而是「隔离环境」这一个事实本身）。好处是治理页可以接线；代价是 `ADR-0078` 那句「只此一维」当场作废，且日后每一张没有租户的表都会援引这一条。
2. **先不接，页面维持骨架并说明原因**：治理三表今天演示库里**全零行**（`seed.sh` 不调 `parcel-governance-register`），就算放行面开了，页面也只能演一个空册。接线的产品收益此刻接近零，而开先例的代价是永久的。

我倾向第二条，理由是收益侧的：本票原本被归进「阻断物为零的批 B」是因为盘点误以为它与 VE 六类同形，拆开后它其实**三件缺两件半**（无种子、无 http 包、准入无形态），而唯一的收益是一张会显示空册的页。把 `ADR-0078` 的「只此一维」用在这上面不划算——留着它，等真有一张产品级读面值得看的时候一次裁清楚。

## 裁完之后要做什么（范围预估，开工时对新 tip 重核）

- 治理种子（`seeds/governance/` 新建，`seed.sh` 加行属占号文件）；
- `ports` 伴生列表读端口 + `postgres` 读适配器（键形按裁决）；
- **整个 `adapters/http` 包**：未配置 Intake 与隔离读 Intake 一对、查询处理器；
- `cmd/parcel-api` 装配（占号）；`apps/admin-web` 的 `StageAdmissionPage` 接真。

## 一格要在票面先说清

`stage-admission` 页面概念上有五格，今天只有三格灌得进去——阶段评审与接管属 CLI 自记的第二批。这一页接出来会是**三格有内容、两格如实说明未开**，符合「不填假值」，但要在页面上如实交代，别让人以为漏了。

## 裁决（MCP-2，2026-08-26，用户授权作此裁）

**一、不开第二种放行形态。** `ADR-0078` Decision 四「按环境选择的只有装配点上查阅行的 Intake 一件事……只此一处、只此一维」维持原文不动，不为「产品级、脱敏、无租户」的登记册读面加第二档准入。上文建议里的路 1 否决。

**二、`stage-admission` 页面维持骨架，本轮不接线。** 上文建议里的路 2 采纳。页面上要如实写明不接的**原因**，而且原因不是「后端还没做」——是**这一页的数据不属于租户管理台的查阅面**（见理由三）。写「未接线」会让人以为在排期，写错了。

**三、本票以裁决交付，状态 resolved，不再挂 blocked。** 要答的那一问已经答了，答案是「不放行」。挂着 `blocked` 会让后来的人以为还在等一个没人去做的 ADR。

### 定这一裁的三条理由（按份量排，第三条是决定性的）

**理由一：判据空洞地满足，等于没有判据。** 这是补记已经点破的陷阱，此处只把它钉成裁决依据：`ADR-0078` Decision 一第三条判据的原文是「作用域是运营侧的授权结果——**租户维是最高隔离边界**」，Decision 三注入的是一个租户值、由 `SYN-` 前缀在**进程启动时**门禁钉死。治理读面没有那一维，于是没有值可以被前缀门禁检查。真放行了，安全性质会从「真实租户标识**结构上**进不来（不带 `SYN-` 就启动即拒）」降为「生产环境**记得别设**那个布尔开关」。前者是编译期/启动期性质，后者是运维纪律——这正是 `ADR-0078` Decision 三亲手拒绝过的那一类退化（「静默回落会让配置错误与刻意拦着两态可观察签名相同」）。降级发生在安全边界上，且降级本身不会有任何东西变红。

**理由二：收益此刻是零，而且不是「差一点」的零。** 复点（2026-08-26，`idp-parcel-postgres-gate` 演示库）：`pilot_governance` schema 下**八张表全部零行**——不止本票原记的三张，`stage_review`、`takeover_record`、`channel_execution`、`scope_version_relation` 同样零行。`seed.sh` 不调 `parcel-governance-register`。就算准入开了、http 包写了、页面接了，演出来的是一张**空册**，还要在旁边如实交代五格里有两格属第二批未开。用一条永久的架构先例去换一张空册，账算不平。

**理由三（决定性）：这一问问错了层，先要答的不是键形，是归属。** 本票（含标题）把它当成「读面形状/键形」问题，那是被页面已经在导航里这一事实带偏的。`apps/admin-web/src/navigation.ts` 把 `stage-admission` 放在「试点治理」分组，与租户运营页并列在同一个**租户管理台**里；而 `migrations/pilot_governance/0001_governance_records.sql` 抬头写的是「治理是产品级机制……登记的是**本产品此刻**拿什么去评审、谁在写生产」。**数据主是产品团队，不是租户操作员。** 租户操作员看「谁在写生产」既不是他的事、也不由他决定。所以正确的次序是：先答「这一页该不该长在租户管理台上」，答完才轮得到「它的读面键形是什么」。在归属未定时去给准入加一维，是拿一次不可逆的架构让步，去承载一个**可能根本不该在这里的页面**。

### 附一条要一并纠正的读法

补记末句「`ListCurrent(ctx)` 不收租户也因此是对的形状」成立，但不能被读成「读面已经有一半了」。`ports.AuthorityIntervalStore` 的原文注释写得很清楚：「ListCurrent 交回全部既有区间**供冲突预检**——重叠必须在准入前被抓住」。它是**写侧的冲突预检口**，`RegisterAuthorityInterval` / `RecordStageReview` / `GovernIncident` 三处调它都是为了写前查重。把它当查阅读面复用，正是 VE 明文避开过的形状（`internal/visibilityexception/ports/ports.go`：「ListCurrent 是查阅面独有的列表读法，派生编排用不到它，故不并进写侧接口」）。真要接，查阅读端口得另立。故本票的施工量是**三件缺三件**，不是缺两件半。

### 重开判据（三条同时成立才重开，缺一条都不重开）

1. **有行可看**：治理表在演示库里非零（`seed.sh` 调了 `parcel-governance-register`，或另有灌入路径）；
2. **有人要看，且认了受众**：明确了看这些行的是谁——若答案是产品/运维团队而非租户操作员，则连带答出承载面（见下节），不能仍然默认是租户管理台；
3. **不止一张**：届时至少有第二张同形的「产品级、脱敏、无租户」读面等着，值得一次把形态裁清楚。为一张表开一维，永远不划算。

### 若将来真要接，形状先钉在这里（省得那时重走一遍）

那时的正确动作**多半不是**给 `ADR-0078` 的隔离读准入加第二维，而是**另立承载面**——数据主是产品团队，就让它出现在产品团队够得着的地方（产品级治理控制台，或最省的：`parcel-governance-register` 加一个只读列举子命令，零 http 包、零准入改动、零页面）。这与同族先例 `.scratch/ve-claims-read-seams/issues/01` **同调而不同结论**：那票裁的是「另立一个带租户维的读法、两个形状各答各的调用面、不合并」；本票照抄的是它那句**推理形状**（调用面不同就别合并），不是它的结论。把产品级治理读面塞进租户管理台的装配点，就是那票拒绝过的「合并」。

### 本裁不动什么（防止被过度援引）

- 不改 `ADR-0078` 任何一句，不新增 ADR——**「维持原文、不开先例」不需要一份 ADR 来记**，那会把「我们决定什么都不改」写成一次变更。裁决留在本票，`ADR-0078` 由 Decision 四原文自己作数。
- 不动 `pilotgovernance` 的任何代码：写口、CLI、`ListCurrent` 冲突预检口全部照旧，它们各自形状是对的。
- 不动隔离读准入现有的放行面枚举，不动 `SYN-` 前缀门禁。
- 不否定治理表将来有查阅需求——只否定「**用租户级隔离读准入去承载它**」这一条路径。

# 103 集运成员在出发之后才识别成功，永远没人补问它本该被问的出发门禁

Category: bug
Status: needs-triage——R2 候选（上线后尽快）：识别成功之后追踪上补出了那条出发（code/74），但出发门禁（关务限制等）当初对这件实物答的是「身份未决」，之后没有人按原出发时点再问一次；本该因关务限制被阻断的包裹，追踪上显示成一次普通出发、没有阻断信号。2026-10-27 协调方据 code/74 完成记录越权风险点 1 立（用户「开，全部解决」授权）。
Blocked by: 无（code/74 已进 main）
上下文：TF（运输履约，出发门禁读数）、VE（全程追踪，补出发与阻断信号）、CC（关务限制）。
出处：code/74 完成记录越权风险点 1；与 ADR-0224 风险点 3、ADR-0225 越权风险点 4 同类，ADR-0305 是同族的"按原出发时点补问"先例。

## 现象

code/74 之后，随集运单元出发时身份未决的成员，在识别成功（或身份冲突处置成立）后，VE 会补出这件包裹的移动事实投影（`BackfillIdentifiedMemberAdapter`，只补投影、不补信号、不重问关务）。但出发那一刻的出发门禁对这件实物答的是未决（ADR-0225 越权风险点 4）；识别之后没有任何一路按原出发时点把门禁再问一遍。结果：这件包裹若本该因关务限制被阻断，追踪上只显示一次普通出发，没有阻断信号，与"出发门禁先于出发"的规则句相反。

## 期望

- 识别成功之后，对这件包裹按**原出发时点**补问出发门禁（口径比照 ADR-0305 对控制事实上补派生的做法），门禁答阻断时补出与正常出发同形的阻断信号；门禁放行时不重复出信号。
- 幂等：同一（成员，出发事实）只补问一次的结论稳定；重投只答已有结果。
- 失败分格（ADR-0029）：读不动才是未决；确定性结论不进未决哨兵。

## 要裁的

1. 谁来补问：在 `node-operations.node-intake.formed` 的扇出里再起一路由运输履约消费（比照 ADR-0305），还是并进 code/74 的 VE 补派生那一路。
2. 门禁答"阻断"时的信号形态与 VE 投影的关系（补出发已经是普通出发，这时是追加阻断信号、还是用替代关系取代那条出发）。
3. 已经补过的普通出发（上线前或本票之前形成的）是否回扫。

## 规模

中（一路新消费者 + 门禁读数复用 + 信号追加与幂等 + 真链用例）。

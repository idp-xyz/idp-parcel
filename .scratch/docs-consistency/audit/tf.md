### H1 UC-TF-004 里 `AT-TF-181` 出现两行，场景相同，结果相反

- **类别**：2
- **位置**：`docs/application/transport-fulfillment/UC-TF-004-COMMISSION-AND-ACCEPT-TRANSPORT.md` 验收表里有两行 `AT-TF-181`，场景都是「运营人员声明一个在册的实际履约段采用一份已提交的运输委托（段、委托、服务方）」。
  - 第一行：「同一份委托再被另一段采用，照常形成连线，**不改写首次开始**」。
  - 第二行：「委托的开始取已采用各段首个参与里最早的那一条，后采用的段开始得不更早就不动（`AT-TF-189` 是更早的那一格）」。
- **证据**：
  - ADR-0204 决定二：「已开始、但这一段的首个参与更早的，开始前移到这一条（依据与时刻一起换）」。
  - TF CONTEXT Lifecycles「运输委托、订舱与承运接受」：「之后再被首个参与更早的段采用，开始前移到那一条，只前移、不回到未开始」。
  - 同一 UC 的 `AT-TF-189`。
  - 代码：`domain.AdoptCommissionForSegment` 交回 `CommissionStartAdvanced`，并会改写开始。
  - 全部 TF UC 里只有这一个 AT 号重复。
- **归类**：A
- **严重度**：高。同一个号两种结果，照第一行写测试或实现会把「前移」当成缺陷。
- **建议修法**：删掉第一行（ADR-0204 前移条款之前的旧文本），只留第二行。

### H2 委托取消：CONTEXT 与 `AT-TF-092` 写的是「只停尚未消耗的下游范围、向下游发取消/释放」，现行决定与代码是整份拒、不往下游传

- **类别**：1（连带 2）
- **位置**：
  - TF CONTEXT Rules「运输委托、订舱、容量与装载」：「上游运输意图取消只对尚未消耗的下游范围发出取消或释放请求，不删除已经形成的承运接受、预占、分配、交接或履约事实；下游对象按自己的规则分别形成结果。」
  - TF CONTEXT Lifecycles「运输委托、订舱与承运接受」：「尚未消耗的运输委托或订舱范围可以取消」。
  - UC-TF-004 `AT-TF-092`：「取消到达时服务已经开始 | ……取消只处理尚可停止范围」。
- **证据**：
  - ADR-0204 决定三：「取消是整份的：委托一旦开始就整份拒，委托层面没有「只停尚未开始的成员」的部分取消；取消成立时也不向尚未消耗的订舱、预占发出取消或释放请求（风险点 9）」。
  - ADR-0204 越权风险点 9 直接点名：「`AT-TF-092`「取消只处理尚可停止范围」只在订舱这一级做到……TF CONTEXT「上游运输意图取消……」的下游那一步，今天要运营人员经取消订舱口、释放口逐个登记」。
  - 代码：`application.CommissionTransportHandler.CancelCommission` 头注照写这一点，对已开始的委托整份答 `TRANSPORT_ALREADY_STARTED`。
- **归类**：A。代码与已接受的 ADR-0204 决定三一致，CONTEXT 与 AT 写的是去处，却用了现行口吻。
- **严重度**：高。照 CONTEXT 读，取消委托之后尚未消耗的订舱与容量预占会被释放；实际上它们仍在册、仍占容量、仍可能计订舱费。
- **建议修法**：
  - CONTEXT 那条照「采用登记之后今天没有更正或解除的面，这是现状不是不变量」的写法改：今天委托取消只有整份、不向下游传，下游那一步由运营人员逐个登记，去处见 ADR-0204 越权风险点 9（票 58、37）。
  - Lifecycle 那句写明委托一级不能部分取消。
  - `AT-TF-092` 注明委托一级整份拒，「尚可停止范围」只在订舱一级。

  - ADR 只作理由引用，并按小节名引：「补记：票 65 落决定四时的补充裁定」「补记：票 66 落决定五时的补充裁定」。

### M1 `待确认`交接时控制归谁：CONTEXT Rules 与 GLOSSARY、CONTEXT-MAP 以及 CONTEXT 自己的 Lifecycle 各执一词

- **类别**：6（连带 1、4）

- **证据**：
  - `GLOSSARY.md`「权威运输交接结果」：「只有已交接转移控制，已拒收和待确认均保持此前已确认的控制关系」。
  - `CONTEXT-MAP.md`「node-operations ↔ transport-fulfillment」：「只有"已交接"结果转移控制，已拒收或待确认均保持原控制」。

- **归类**：B
- **严重度**：中
- **建议修法**：立 ADR 代决「证据已表明占有变化而身份不明」这一格：是否独立成立；成立的话归 TF 判，还是归 NO 的「控制来源链待重算」。之后把 CONTEXT 的 Rules 与 Lifecycle、GLOSSARY、CONTEXT-MAP 统一成一个口径，GLOSSARY 只引 CONTEXT。

### M2 「确认订舱需要容量保障」写成现行规则，代码没做；`AT-TF-041` 写的又是反面

- **类别**：4（连带 2）

# 02 对账的两件人工事在生产上都没有口：相对方确认不记，争议的提出与处理没有接线

Category: enhancement
Status: in-progress——2026-11-01 协调方分诊，用户裁定：争议的提出与处理做管理台入口（客服代登记、财务核实后处理、按授予收起），由票 03 承接（分支 `claude-disputes`）；相对方确认本产品不记，设计源「待确认应收」一格不做。03 进 main 时本票随之收口。此前 needs-triage——2026-11-01 由票 [01](./01-held-at-customs-and-disputed-statement-tiles.md) 作者立，待协调方分诊
Blocked by: 无（做不做、谁来提出与确认是一项用户决定）
出处：首页「今日待办」待对账一格。设计源在待对账旁写的是「待确认应收」（客户对账单待客户确认）；票 01 只数得出单上未了结的争议，而争议今天在生产上又造不出来。

## 现状（核于 `b2c1505c7`）

- **相对方确认不记。** UC-SA-003 结果契约的「对账状态」有相对方未确认、部分确认、已确认、存在争议四格，`AT-SA-074` 要求客户未回复时保持未确认。代码里没有相对方确认这件事：对账单领域对象、迁移、写口与读口都只有发布、作废与争议（`internal/settlementaccounting/domain/customer_statement.go`）。所以「未确认」与「已确认」读不出来；把未作废的单都当待确认，就是拿「没有记录」冒充「客户还没确认」。票 [admin-skeleton-closure-batch/04](../../admin-skeleton-closure-batch/issues/04-settlement-accounting-http-read-faces.md) 撤掉对账状态一栏是同一个理由。
- **争议的提出与处理没有接线。** 编排 `CutOffPublishStatementHandler` 有 `OpenDispute`、`ResolveDispute`，领域与真库用例钉着（`AT-SA-070`–`073`），但 `cmd/` 下没有任何口调用这两个方法：运营决定口、首方客户渠道、集成客户端渠道都没有。生产库上 `statement_dispute` 因此只能是空的，首页待对账一格与对账单页「只看待对账」在生产上如实答 0——是真 0，但 0 的原因是争议进不来，不是没有争议。

## 要定的

1. 争议由谁提出、经哪个口：UC-SA-003 输入契约写的是「客户或授权运营方」——客户经首方渠道、运营代录经运营决定口，还是两条都开；处理（接受、部分接受、拒绝、待复核）归哪个授予。
2. 相对方确认由谁、经哪个口记：客户门户、运营代录，还是外部对账系统回传；部分确认按费用行还是按金额范围。
3. 「客户多久不回复算待催」是不是租户取值（按红线归租户取值则留空答未配置）。
4. 定了之后：SA 补登记口与（确认的）读口，UC-SA-003 补确认的生命周期与 AT；管理台首页待对账一格再加「待客户确认」的件数，或另起一格。

在这之前首页待对账只数未了结的争议，`UC-SA-003`「给开发的交接」记着这两条缺口。

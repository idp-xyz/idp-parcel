# 16 — 目录行上给旧版收尾：截止在后继生效时点，或同起点退役

**Parent:** [spec](../spec.md)

**What to build:** 同一对象发了新版本后，旧版不会自己结束（ADR-0233）：两版区间重叠的部分解析会答「适用冲突」，要等登记方显式收尾。服务端有两个在线口（`/commercial-version-successor-cuts`、`/commercial-version-retirements`，受控 CLI `register-version-closures` 同形），管理台没有页面，15 的重叠提示指向的这一步只能去命令行做。

改法：目录行的「操作」列在「发新版本」旁加「收尾…」，点开右侧抽屉：

- **抽屉打开时重读该册**，对着此刻的册面认出旧版与可让位的后继，不用页面上那份可能已陈旧的行。后继是同一对象、同一范围、在用、生效起点不早于旧版且落在旧版此刻选用区间内的另一版；多于一个时让人选，只有一个时选上。
- **两种收尾由两版起点的先后定，界面说明落下的是哪一种**：后继晚于旧版起点，旧版截止在后继的生效时点（走 `/commercial-version-successor-cuts`，截止点取后继的起点，不由人填；要填更正依据与更正时刻）；同一起点，旧版整版退役（走 `/commercial-version-retirements`，退役时刻取登记时刻；只填依据）。
- **更正时刻在打开时就定下，不随提交重算**：同一次截止的重放靠依据与更正时刻逐字相同来认，超时后原样重发才认得出；提交时再取此刻，重发的就成了另一条。
- 确认框复述：谁被收尾、让位给谁、落下什么、依据，写明写入后没有撤回的入口；供应商协议另提醒入口不替人查在途运输委托（ADR-0231 把收尾造成的已终止、未生效两格接进实际履约未形成册，承接口是协议换版补形成）。
- 答复按服务端的答案代数说中文：已截止（回显此后的选用区间）、已退役（回显让位给谁与退役时刻）、已登记过（重放）、未受理（原因译成中文，原话收进可展开的一格）；其余答复态（未登录、未授权、传输失败）用共用的登记答案组件。
- 「收尾…」按钮只给已读到的这一页里确有后继可让位的在用版本；读面没有状态的册（信用、结算、价格政策、接单规则包）与随所属版本发布的两本册不开。

15 的已有版本提示顺带改了一处：供应商协议的读面回显被截止版本的截止点（`selectionEndsAt`），区间重叠按截止后的区间判，截止过的旧版不再与之后的新版报重叠。

不做的：撤回截止或退役（ADR-0233 决定六留给后继票）；读面没有状态或没有范围的册的收尾；批量收尾；收尾前反查在途委托。

**Blocked by:** None — 两个在线口已装配到操作者渠道的登记册 Intake，授予面同发布（`cmd/parcel-api/endpoints_commercial_version_closure.go`，`registryWriteFace`）；tops-26 确认没有人在做，PC 后端没有在途改动。

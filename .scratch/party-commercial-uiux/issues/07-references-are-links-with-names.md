# 07 — 引用可点、显示名称

**Parent:** [spec](../spec.md)

**What to build:** 参与方与商业区的表格里，引用别的对象时只有一串不能点的标识：供应商协议的「供应商」「责任法人」是 `SYN-PARTY-CARRIER-LM-01`、`SYN-LE-01`；接单规则包的服务产品、客户合同、责任法人，结算与信用政策的责任法人与相对方，合同上的接单规则包与接受前财务控制策略，渠道映射的服务产品，都一样。评估里「客户 X 有哪些合同、走哪个产品」在界面上答不出来，断在这里。

要做的：

- 引用一律画成链接。参与方与责任法人带名称（名称在上、标识小字在下）；合同、产品、规则包、策略今天没有名称，只显标识。
- 点了去那个对象所在的页，并带上检索词 `?q=<标识>` 定位到那一条：参与方 → 业务参与方页；责任法人 → 集团与法人页；客户合同 → 客户与合同页；服务产品 → 服务产品与渠道页；接单规则包、接受前财务控制策略 → 商业规则与策略页对应的册。
- 名称从业务参与方册与责任法人册取（页面各读一次，不逐行请求）；读不到或不在册时只显标识，不猜、不报错。
- 目标页都要能从地址读检索词（今天只有业务参与方页与客户账户签能）：集团与法人、客户合同签、服务产品、商业规则与策略。商业规则与策略换册时清掉检索词，免得新册被旧词筛空。
- 参与方全景里「去「客户与合同」」「去「集团与法人」」等跳转也带上检索词。

不做的：合同列表加「客户」一列（读口不带，归 spec 后续第三段）；参与方关系抽屉（ps-external-mark-relations/17 刚改过，整体改版另票）。

**Blocked by:** None — can start immediately

**Category:** enhancement

## 完成记录（2026-10-26，tops-54，前端切片，worktree `idp-parcel-pcux2`）

- **落点：** 本笔提交。
- **改了什么：**
  - 新纯函数 `ref-links.ts`：`refHash(种类, 标识)` 给去处（对象所在的页 + `?q=<标识>`；规则包与财务控制策略落到商业规则与策略页对应的册）；`nameDirectoryOf` 用业务参与方册与责任法人册建名称目录（法人取它所钉参与方的名称，悬空的不进目录）；`refName` 按种类查名，只有参与方与法人有名。
  - 新件 `RefLink.tsx`：`useNameDirectory`（两本册页面各读一次，读不到即空目录）、`RefLink`（有名称时名称在上、标识小字在下，没有只显标识或格里原字；阻止冒泡，免得同时开行详情）、`withRefLinks`（行模型里有引用的格换成链接）。
  - 两份行模型加 `refs`（列标识 → 种类 + 原值）：供应商协议的供应商、责任法人；接单规则包的服务产品、客户合同、责任法人；接受前财务控制的合同；结算政策的责任法人、相对方；接受判断时点策略的规则包；信用政策的责任法人；客户服务规则的适用对象（恰一项时才有，异常与未登记的行不挑一项去链）。
  - 页面：供应商协议、各政策册经 `withRefLinks`；合同表的接单规则包、接受前财务控制策略，交付条件里「收紧自产品」，渠道映射的服务产品，直接用 `RefLink`。政策页的名称目录提到页面层，换册不重读。
  - 目标页从地址读检索词（`useAddressKeyword`）：集团与法人、客户合同签、服务产品、渠道产品目录、供应商协议、各政策册。客户与合同页两个签共用同一个检索词（它们在一页上）。商业规则与策略换册时清掉检索词，政策册按册重挂、从已清的地址重读。
  - 参与方全景：「去「集团与法人」」「去「供应商协议」」「去「商业规则与策略」」带上参与方标识作检索词（后者落到结算政策册）；「去「客户与合同」」只到页——客户账户在第二个签，检索词会先把默认的合同签筛空。去处在 `party-overview.ts` 的 `overviewSectionHash`。
- **判据：**

## 二、客户沟通函（草案，用户复核后发出）

> 以下为可直接转发的文本。全文以「贵司」指客户、以「我方」指开发方；渠道与供应商以业务名称指称即可，不涉及仓内脱敏约束（函件不入仓，本草案不录任何真实名称）。

---

**主题：实施周前置事项确认（安全、接入、商务、参数、账号）**

贵司项目组：

为保证下周实施顺利启动，以下几件事需要贵司在实施周开始前答复或执行。按紧急程度排列。

**1. 安全：请立即轮换 API 凭据（今日）**

贵司此前提供的需求沟通材料中，下单接口抓包包含了**生产环境当前有效的 API 凭据**。我方已按安全规范隔离处理，但凭据一旦出现在沟通材料里就应视为已暴露。请贵司：
- 在贵司系统侧换发新的 API 凭据并作废旧值；
- 新凭据**不要**通过邮件、聊天工具或文档传递，请通过我们约定的受限通道交付；
- 收到贵司确认旧值作废后，我方将销毁本地所有原始抓包副本，只保留抹除凭据与收件人信息后的报文结构用于接口对接。

**2. 接入：三个接口行为问题（实施周第 1–2 天内答复）**

这三个问题决定接入层的幂等与冲突处理设计，答复越早返工越少。

- **重复提交与冲突**：同一笔委托被重复提交时，贵司系统以什么字段判定「同一笔」（贵司业务单号？我方返回的单号？两者组合？）；判定为重复时希望我方返回「已存在（幂等成功）」还是「冲突（拒绝）」；内容不同但业务单号相同时如何处理。
- **资料修订入口**：接受后修改预报数据（单号、收件人、换渠道、货物数据）是否复用同一下单接口与同一业务单号；哪些字段在哪个阶段之后不允许再改；修改是否需要贵司侧的操作人标识。
- **凭据轮换与回调**：贵司期望的凭据轮换周期与方式；轨迹/状态回调贵司希望我方推送还是贵司拉取；若推送，回调地址、签名方式、失败重试次数与间隔的期望。

**3. 商务：两项书面确认（实施周第 2 天前）**

- **结算币种**：报价表显示专线业务按人民币/KG 计价，末端渠道与清关业务按美元计价。我方建议按**业务分支分别结算**：专线分支以 CNY 结算、末端与清关分支以 USD 结算，两个分支分别出对账单、分别设结算账户、不互相折算净额。请书面确认接受此安排，或提出贵司期望的替代方案。
- **代收货款（COD）**：下单报文中存在代收币种字段。我方理解一期业务**不包含代收货款**，该字段保留但不启用。请书面确认。

**4. 参数：尚未提供的资料清单（实施第一周内陆续提供）**

- 合同与法人：签约主体法人信息、现行合同版本与有效期、合同中关于追踪/异常响应/通知/索赔赔付/费用退款的条款。
- 结算模式：预付还是账期（若两种并存，各适用于哪些业务范围）；截单周期与付款条件。
- 接单规则：贵司现行的接单校验规则（哪些情况自动接受、哪些需要人工复核、哪些拒收）；收寄资格与承诺时效规则。
- 网络与履约方：揽收与干线的实际履约方；退运路径与责任；国内节点与美国仓的法人、地址、设备（电子秤型号与校准）、现行 SOP。
- 供应商账单：末端渠道与清关服务商的账单格式、传输方式、账期与样本各一份（脱敏可）。
- 财务与通知：贵司财务系统与我方系统的交换边界（应收/应付/收付款水单以何种方式传递）；客户异常通知使用的渠道（邮件/短信/IM）。
- 异常与索赔：贵司现行的异常类型清单与处置时限、索赔与追偿的条件与时限。

**5. 业务量基线（实施第一周内）**

请提供近 90 天的：按日委托量与包裹量（分尾程/专线）、峰值日与峰值小时、每包平均扫描与轨迹事件数、退件与拦截比例、同一委托的平均包裹数。**拿不到的项请直接说明拿不到**，我方不会以行业估算代替。

**6. 实施周参与人员（实施周前）**

请提供参与实施的人员名单与角色，用于开立系统账号：运营配置员（负责录入价卡、网络、关务与商业配置）、结算/对账员、贵司项目负责人（只读复核）。现场作业人员**不需要**系统账号——过渡期现场作业按我方提供的汇总模板由贵司内勤汇总，我方受控导入（见第 7 条）。

**7. 现场作业的过渡安排**

实施周内，收货、扫码换单、装箱封签、称重等现场作业**不在系统界面上直接操作**：贵司现场按我方提供的汇总模板（随后发出）记录，由内勤每日汇总，我方受控导入系统。这是带明确拆除期限的过渡安排，专用一线作业客户端上线后停用。请贵司指定一名现场汇总责任人。

以上如有任何一项无法在建议时间内完成，请提前告知，我们据此调整实施周排期。

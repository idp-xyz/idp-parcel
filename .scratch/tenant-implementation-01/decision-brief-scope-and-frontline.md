## 裁决项 1：尾程流 = 独立面单渠道服务，与 PAR-COM-12 首发范围相抵

**裁决（2026-09-01，用户裁定，经 MCP-2 广播转达）：选 B——修订 PAR-COM-12，尾程流入首发。** 依据是[开发主线](../../docs/product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)的能力范围判据：末端面单渠道转售在目标客户群（经营跨境出口小包网络的物流企业）里是常规形态而非边缘情形，判据说它该进；PAR-COM-12 原本是一次首发范围裁剪，不是产品边界判断。**C 已明确否决**——它拿领域模型迁就范围决定，「无干线段的专线」会污染统一语言，且这种污染不可逆。

红线不放松：六家渠道报价表属实例半边，按登记规则最高到「待核验」；机制半边建的是「末端渠道取面单 + 比价择优」的能力形状，取值一律等真实价卡，不内置为常量。

**落文已办（2026-09-02，MCP-2 受用户委托）**：适用论证与决定落在 [ADR-0088](../../docs/adr/0088-label-channel-service-enters-the-first-release-service-forms.md)；`PILOT-SCOPE.md`、登记册 `PAR-COM-04`/`PAR-COM-12`/`PAR-INT-02`、矩阵 `CPS-06`/`CPS-07` 与开发主线范围约束同笔修订，PC CONTEXT 硬句与 `UC-PC-001`/`UC-PC-002` 验收行随之改写。ADR 另裁了简报没问到的一格：「一条线路」约束只作用于网络服务主链路，面单渠道服务的首发范围以登记的渠道产品与映射为界——用户若不认这一读法，改的是 ADR-0088 Decision 三。

**冲突事实**：客户需求表第一条业务流「尾程」是纯面单渠道转售——客户下单、取末端渠道面单、轨迹回传、结算，无自营现场作业。而登记册 PAR-COM-12 已确认「首发不销售独立面单渠道服务，面单渠道仅作为专线产品的履约环节」。两者正面相抵，且这不是边缘条目：尾程流带了六家末端渠道报价表与 13,092 行邮编覆盖，是客户业务的主力之一。

**选项**：

- **A. 维持 PAR-COM-12，首期只做专线流**。尾程流延后。代价：客户主力业务之一不进系统，实施价值折半，客户「按系统流程改造运营」的承诺可能动摇。收益：范围决定零改动，实施面最小。
- **B. 修订 PAR-COM-12，尾程流入首发**。代价：修订范围决定（走 PILOT-SCOPE 修订纪律）；实施面扩大——末端渠道取面单适配器从「专线的一个环节」升格为「独立产品的主链路」，六渠道适配器与比价择优的取证量全部前置。收益：客户两条主力流全覆盖。
- **C. 折中：尾程流按「专线产品的退化形态」建模试运行**。委托进同一受理链路，只是无干线与清关环节。代价：产品语义上有别扭处（「专线」无干线段），报表与毛利口径要向客户讲清；收益：不动范围决定的文字而实质承接业务，适配器建设与 B 相同但可分期。

**无论选哪项都需向客户书面确认的小项**：结算币种双币并存（专线 CNY/末端与清关 USD）与 PAR-COM-09「仅一个合同结算币种」的适用解释；下单报文中的代收（COD）字段一期不启用（PAR-COM-11 维持不适用）。

## 裁决项 2：一线作业过渡方案（专线流现场作业靠什么落地）

**裁决（2026-09-01，用户裁定，经 MCP-2 广播转达）：选 B——过渡期用管理台代录/受控批量导入顶岗**，且必须带明确的拆除期限与 ADR-0021 偏离记录。硬约束是过渡方案不得在产品上留永久痕迹：代录入口不进管理台正式 page-registry，ADR-0021「管理台无作业动词是有意设计」不因过渡而废。选 B 不触发选项 A 里那条「是否赶得上实施周」的工程评估。

**落文归 ADR-0021 地盘方，未办**：偏离记录要落成新 ADR 或 ADR-0021 补注，其中须含拆除期限。

**背景**：专线流含收货、扫码换单、电子秤、装箱封签等现场作业。机制与端点已备（node-operations、transport-fulfillment），但 ADR-0021 裁定的一线作业客户端**尚未开工**，管理台按设计没有作业动词。下周实施若含现场作业，必须选一条过渡路径：

- **A. 一线端 MVP 加速自建**：范围收到最小（扫码收货、换单、装箱封签、电子秤对接），先在线优先、离线容忍后补——注意这与 ADR-0021「离线与弱网容忍是固有要求」有偏离，需记偏离决定与补齐期限。周期以周计，是否赶得上实施周需工程评估。
- **B. 过渡期用管理台代录/受控批量导入顶岗**：现场纸单或 Excel 汇总后由内勤录入。代价：与 ADR-0021 的工作流论证相抵（管理台无作业动词是有意设计），时效与准确性受损，扫描粒度的轨迹证据缺失（影响 PAR-VIS 取证质量）；收益：零开发，下周即可运转。
- **C. 客户现有现场工具产出标准文件，经受控文件口导入**：客户旧系统继续跑现场，按约定格式导出，走受控导入。代价：与「客户按我们流程改造」的承诺方向相反，数据谱系需标注来源系统，受控导入口本身也要小量开发；收益：现场零切换风险。

无论选哪项，**accessidentity 接入层（PAR-INT-01）都是关键路径**——它不是本裁决的选项变量，而是三条路径共同的前置。票 `syn-wall-door-audit/issues/01` 已于 2026-09-01 按 ADR-0072 重启并写实范围（S0..S5），排期与验收点见该票「重启范围」节。

**「重启条件已满足」这句要说准，此前写得含混**：ADR-0072 把重启门槛括注为「该租户渠道的现行流程」，那一件已到（证据 E-02）；但参数登记册 `PAR-INT-01` 的最低证据是四件，「资料修订业务标识」与「重试和冲突边界」两件未到，它们决定登记册的列与幂等语义。两条门槛不同，前者放行开工，后者决定 `PAR-INT-01` 何时能离开「待核验」。

## 处置建议：客户证据文件的安全问题（建议尽快执行）

客户证据暂存目录（`docs/` 下以客户品牌命名的子目录，即用户 2026-08-31 经频道 4 提供的五件文档所在处）目前是**未被 git 跟踪的目录**（已核：不在任何 git 历史中）——尚未污染仓库，处置窗口还开着。其中有三类敏感内容：

1. **有效 API 凭据**：下单抓包含客户生产 apikey 明文。该凭据已被多个会话以明文读到，**轮换应作为硬性动作**：通知客户换发；抓包存档时抹除凭据头，只保留报文形状。
2. **个人信息**：抓包与表格含真实收件人姓名、电话、地址。按红线「敏感实例外置」，PII 不得进代码仓库。
3. **商业敏感**：客户全套报价成本结构、渠道供应商名单。同样不属仓库内容物。

**已就位的守卫**：MCP-2 已在 `.gitignore` 受限证据小节为该目录加守卫（2026-08-31，工作树改动、待随其提交入库），防任何会话 `git add` 时带进历史。本 feature 三件材料已同步改为**指纹索引制**（见登记册草案证据清单），全文不复录客户名称、域名、单号与凭据。

**仍归用户执行或授权的动作**：通知客户轮换 apikey（第 1 条，最急）；证据目录整体移出仓库工作区，落到受控证据存储（PAR-GOV-11 的 MinIO `idp-parcel/pilot` 建成前，至少移到仓库外的受控目录）。在外置完成前**不要执行任何会把该目录纳入提交的 git 操作**。

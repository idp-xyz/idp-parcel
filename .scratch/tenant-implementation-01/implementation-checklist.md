# 首个租户实施检查单

Category: chore
Status: in-progress——清单可勾；勾选与执行归各项自己的归属方，本文件不代勾

本清单把[决策简报](./decision-brief-scope-and-frontline.md)末节「建议的实施周节奏」展开成可逐项勾选的形态。每项标四件：**半边**（机制／实例／协调）、**归属**、**前置**、**完成判据**。判据要能被第三人判真假，「已沟通」「已了解」不算判据。

取证基线 `1665fdb`（2026-09-01）。文中所有「当前状态」断言以该锚为准；读到时请重新取证。

**半边的含义**取[开发主线](../../docs/product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)的划分，不在此复述：机制半边现在就能做，实例半边等租户证据、留空且拒绝默认值。标「协调」的既不是代码也不是租户参数，是开发方或用户要去办的一次性事务。

**登记纪律**：本清单不替客户把任何参数确认为「已确认」。按[参数登记册](../../docs/product/PILOT-PARAMETER-REGISTER.md)的登记规则，证据完整且决定生效前最高只到「待核验」；勾选本清单某项不等于该参数可以升级状态。

## A. 证据处置（最靠前，窗口仍开）

**为什么排最前**：客户证据五件现在还在仓库工作区且**不在任何 git 历史中**（`git check-ignore` 命中 `.gitignore` 受限证据小节的守卫行）。这是「尚未污染」而不是「已经安全」——窗口开着的意思是现在移走零代价，一旦被某次 `git add` 带进历史，代价从「移动文件」变成「改写历史」。A 组每一项都不依赖任何裁决，可即刻执行。

- [ ] **A1 通知客户轮换 API 凭据**（实例·归用户 → 客户）
  前置：无。
  完成判据：客户已换发新 apikey，旧值在客户侧失效；本仓与各会话临时目录中不存在旧值的明文副本。
  理由：抓包件含客户**生产环境**有效凭据明文，且已被多个会话读到。轮换是硬性动作，不是建议——读过的会话不能靠承诺忘记。

- [ ] **A2 证据目录整体移出仓库工作区**（实例·归用户）
  前置：无（不必等 A1）。
  完成判据：仓库工作区内不再存在该目录；原件落到仓库外的受控目录，且其位置以受控方式记录在案，不靠个人记忆。
  边界：`PAR-GOV-11` 的 MinIO `idp-parcel/pilot` 尚未建成，因此这一步的落点是**临时受控目录**，按登记册「临时存储不作为正式生产证据的权威源」，不得据此把 `PAR-GOV-11` 标记为就绪。

- [x] **A3 `.gitignore` 守卫行入库**（机制）— **已完成**，核于 `f95053a`
  完成判据（已达成）：守卫行已进入提交历史，`.gitignore` 工作树与 HEAD 一致；证据目录在 `git log --all` 上零命中，即从未进过任何一次提交。守卫此前只在工作树上，任何一次分支切换都可能把它带走而它保护的东西还在原地——这个窗口已经关掉。
  注意：本项完成**不解除 A2 与 A5**。守卫防的是「不小心提交」，防不住「文件还在磁盘上」。

- [ ] **A4 抓包存档脱敏后再入受控存储**（实例·归用户）
  前置：A1（轮换后原值失效，脱敏才不再是补救）。
  完成判据：存档件中凭据头已抹除，只保留报文形状与字段名；真实收件人姓名、电话、地址与真实单号不随存档进入任何共享位置。
  理由：这批抓包的价值在**报文形状**（`PAR-INT-01` 要的正是这个），形状不需要真实 PII 来表达。

- [ ] **A5 提交前置检查：不得执行会把该目录纳入提交的 git 操作**（协调·归全部会话）
  前置：无，是一条持续约束而非一次性动作。
  完成判据：A2 完成后本条自然解除；解除前每一次提交都要确认。

## F. 操作员登录门（新增项）

- [ ] **F1 在身份服务侧开立实施周操作员账号与授权**（协调·归用户）
  前置：无。
  完成判据：参与实施的操作员各自能完成管理台登录门流程。
  **边界要先说清，否则这一项会被当成「后端通了」**：管理台登录门是 OIDC authorization_code + PKCE 的公开客户端流，签发方与客户端标识是**开发方自己的部署形态**，不是租户实例参数（自证在 `apps/admin-web/src/auth/oidc.ts` 的 `ISSUER`/`CLIENT_ID` 常量注释）。它决定谁能打开控制台页面，不决定后端放不放行。

- [ ] **F2 认清实施周内管理台对真实租户的可用边界**（协调·归用户 + 工程，认知项非动作项）
  前置：无。
  完成判据：实施相关方都知道下面这件事，不在实施周现场才发现。
  **事实**（取证于 `1665fdb`）：后端查阅面今天的唯一放行形是隔离读准入（ADR-0078），其开关 `IDP_PARCEL_ISOLATED_READ_TENANT` **只接受 `SYN-` 前缀的合成租户**，填真实租户标识会让进程**启动即拒**。命令面（下单、撤回、取消、复核完成、主动拒绝、收寄登记、交付登记与更正、索赔受理、外部关务结果、价卡与序列登记）挂的是字面量未配置即拒，隔离读开关换不了它们。
  **推论**：C3 落地之前，真实租户在管理台上既看不到自己的数据，也下不了单。管理台能登录 ≠ 后端可读——F1 勾上不代表 F2 解除，解除它的是 C 组。

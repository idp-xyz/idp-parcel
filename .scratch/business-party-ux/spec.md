# 往来单位 UX：参照 Fiori 原型取长，追平公司主体那一轮的版式与用语

Category: enhancement
Status: resolved——2026-11-06 子票 01–04 全部进 main
出处：2026-11-06 用户在 5173 看往来单位问「为什么还是老的界面」；补上右栏资料（[business-party-profile/04](../business-party-profile/issues/04-detail-panel-profile.md)）之后，用户打开外来原型 `ux/IDP_Parcel_Partner_Fiori_Prototype_V1.0.html`（主树下未入库），答「需要，但不是完全照抄，你是 ux 专家，目标是专业，美观，ux 友好」。

切片：PN-02，主责 party-commercial，非关务专项。只改 `apps/admin-web/**`，走 workflow「前端切片」。机制：无新增，读口与写口都已有。产品策略：页面形态与提示语。租户取值：无。

## 评估（一句话）

功能已齐，界面落后在两处：公司主体那一轮（[company-subject-ux](../company-subject-ux/spec.md)）定下的版式与用语没有全部带到往来单位——右栏事实条还是四个大框、时刻到秒，对象页概要把抬头里的名称、编码、状态与到秒的时刻再列一遍；原型里几处「一眼看懂」的做法往来单位还没有——抬头带英文名、对象页入口看得见、空状态给下一步、列表看得出国家与角色。

## 原型的做法怎么取

| 原型 | 决定 | 理由 |
|---|---|---|
| 右栏抬头：名称下一行英文名，状态与角色成标签，一行编码、国家、生效日 | 改着用（票 01） | 英文名取此刻有效资料里的其他语言名称；编码、注册地、注册号已在 meta 行；生效、登记与资料版本照公司主体栏收成一行小字，时刻只显到日 |
| 右栏「展开详情」原地铺满 | 改着用（票 01） | 本仓对象页是工作区里的另一张标签（壳层按地址开签），不另造原地展开；把藏在「更多」里的「在新标签打开对象页」提成头部一枚图标按钮，公司主体栏同改 |
| 概览：一句关系结论 + 「补充主要联系人」提醒带「去完善」 | 改着用（票 02） | 关系结论已由头部角色标签说了，不再写一句；提醒保留并改成本仓的事实：联系人按用途标「主要」，没有单一主要联系人，所以客户提醒的是「还没有联系人」，有写授予的给「更新资料」 |
| 空状态带插图与下一步按钮 | 改着用（票 02） | 资料空状态给图标、一句话与「更新资料」，不加插图 |
| 基本资料两列字段卡 | 已有 | 资料读出卡（名称与地址、税务与开票、收款账户）已是同一思路 |
| 对象页抬头与基本资料 | 改着用（票 03） | 对象页 meta 行补注册地、注册号、外部编码，与右栏同一份；概要不再重列抬头已有的名称、编码、状态与到秒的时刻，当前来源单据移到「登记记录」的摘要里，排查用的格进技术详情 |
| 列表：类型图标、角色标签、国家 / 地区列、业务关联数 | 改着用（票 04） | 类型改成标签：我方公司与各角色各一枚，没有合作关系显弱色字；加「注册地」一列，随列表宽度出现；业务关联数要逐行读四册，不做；类型图标与角色标签重复，不加 |
| 指标卡点了即筛 | 已有 | 本页指标带与状态胶囊已能筛 |
| 卡片视图、批量勾选与导出 | 不做 | 主数据册以逐条核对为主，卡片视图不多给信息；导出另议 |
| 业务关系视图（图示） | 不做 | 「关联」签已逐条列出关系与对象，图示只是多一种画法 |
| 「编辑资料」一张表同时改身份与资料 | 不做 | 领域把身份更正与按生效时点的资料分开（CONTEXT「参与方身份」「参与方资料」），两个入口照旧 |
| 「单位归属：我方 / 外部」作可选字段 | 不做 | 我方公司由公司主体钉着算出，不是可填的格；只在是我方公司时显标签 |
| 资料待办页 | 不做（本轮） | 要逐家读资料才判得出，得另议读口 |

## 不变的决定

- 领域与写口不动；界面用语以 company-subject-ux spec 的「统一用语」表为准。
- 照旧：不摆生命周期步进；一个事实首屏只出现一处；号码类点击复制、文本类悬停复制；签带图标；我方公司不收往来单位资料。

## 0. 建议一览（非定案）

1. **设备形态**：一个应用、两档离散交互布局（手持档／工位档），不做两个应用，也不做连续响应式。保持可逆：词表、队列与协议层写成可迁出的纯 TS，若外设集成证伪浏览器路线，只重做壳。
2. **离线架构**：设备本地事实队列 + 逐对象顺序重放 + 只读参考数据缓存；**不引入通用同步引擎**。领域的事实追加模型已把冲突消解放在服务端派生层，客户端造一套合并逻辑是替领域做它明令禁止的事。
3. **工具链**：与 admin-web 同栈（Vite + React + TypeScript + Tailwind + `@idpxyz/*`）做 PWA 起步；秤／量方仪／打印等外设走 Web Serial 的可行性先用 `/prototype` 试证，证伪再谈分栈。
4. **未决十项**（§5）：四项含实例半边等租户参数，四项机制可现在定，一项需试证，一项悬于试证结果。

## 1. 设备形态：一个响应式应用还是两个

### 1.1 作业活动落在哪类设备上

[ADR-0021](../../docs/adr/0021-frontline-operations-client-is-part-of-the-product.md) 划定的范围是：扫描、点验、身份冲突处置、测量录入、集运单元与封签、作业位置移动。按 [节点作业 CONTEXT](../../docs/domain/node-operations/CONTEXT.md) 的作业位置与岗位语义，这些活动天然分成两种现场姿态：

- **走动中（手持）**：到站扫描、点验、位置移动、集运装入／移出、封签施封与核对、装卸扫描。单手持握、戴手套、看一眼就走、光线差；交互以「扫→看结果→下一件」的秒级循环为主，物理扫描头触发。
- **站定在台前（固定工位）**：客户送站的节点收寄台（[UC-NO-002](../../docs/application/node-operations/UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md) 的主场景）、测量录入（秤＋量方仪外设）、受控开封与重新封装、待识别实物登记（拍照、录入候选线索）、身份冲突的详细核对。双手、键盘、大屏、连着外设。

两种姿态的交互密度差别是真的，但**领域词表、状态机、队列与端点契约完全同一套**——这与管理台／作业端之间的分界不同质：那两端连服务的岗位都不同。

### 1.2 方案与代价

| 方案 | 内容 | 代价 | 撤销成本 |
|---|---|---|---|
| A. 连续响应式单应用 | 一套布局按视口流式适配 | 「一眼一拇指」和「双手键盘外设」硬挤一套组件密度，两头都将就；断点逻辑散在组件里，日后拆不干净 | 中——布局假设渗进组件 |
| **B. 单应用、两档离散布局（建议）** | 同一代码库，按工位注册／登录选「手持档」或「工位档」，两档各自排布局，共享全部领域层与队列层 | 比 A 多一层「档位」概念与两套页面骨架；比两应用少一条 CI、一次真机矩阵、一套发布 | 低——档位即天然切缝，日后按档拆成两应用时领域层原样搬走 |
| C. 两个应用 | 手持端与工位端分仓目录、分构建 | 两套壳、两条 CI job、两倍真机验证；`packages/` 立刻要建；版本同发布要协调三方（后端＋两端） | 低但代价前置——在没有任何真实设备参数时就付双倍 |
| D. 工位功能并入 admin-web | 收寄台／测量台做成管理台页面 | **否决**。管理台服务治理与配置岗位，无离线要求；把「工位作业不会因为网络抖动而停」（ADR-0021）挂到一个纯在线应用上，等于给管理台整体加离线改造。两端交互形态不同也是 ADR-0018 当初立 `apps/` 复数形状的理由 | — |

### 1.3 建议与理由

**建议 B。** 理由三条：

1. ADR-0021 把形态留待「按实际交互定」，而实际交互参数（租户设备族、工位布置）属实例半边，现在取不到。单应用两档保持最大可逆性——它不预支两应用的成本，也不像连续响应式那样把「一套布局服务两种姿态」的假设焊进组件。
2. 两档共享的是最重的部分：`outcome` 词表、本地队列、重放逻辑、端点客户端、三个必须有出路的屏态（§4）。这些与像素无关，拆成两应用它们也得共享——那就是 `packages/` 的第一批住户（§3.3）。
3. 判断「要不要第二个应用」的信号很清晰：若工位档的外设集成被证伪只能走原生（§3.2 的试证），届时按档拆，切缝已在。

## 2. 离线优先架构

### 2.1 领域先天条件：冲突消解已经在服务端

这一节先立一个观察，后面所有取舍都靠它：**本仓的节点作业模型是事实追加型，不是共享状态编辑型。** [节点作业 CONTEXT](../../docs/domain/node-operations/CONTEXT.md) 规定实际测量不可覆盖、来源事实必须保留、「重复、迟到、冲突、更正或有效性变化必须关联原事实和原判断，不能通过覆盖历史整理出单一结果」；[UC-NO-002](../../docs/application/node-operations/UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md) 进一步写明「迟到事实按业务发生时间参与判断，不按消息到达顺序改写控制历史」。

推论：离线客户端提交的每一条都是「已发生的物理观察」，不是「对共享对象的修改」。两台设备离线期间对同一实物各扫一次，回来重放，服务端收到两条事实并在派生层消解——冲突不是传输失败，而是一种**业务答案**（来源冲突、身份冲突），按 [ADR-0022](../../docs/adr/0022-http-status-carries-answer-formed-not-business-verdict.md) 以 2xx + `outcome` 交回。客户端因此**不需要**也**不应该**有合并逻辑：现场「不得以覆盖、合并或『最后一次扫描为准』决定正式包裹身份」是域红线，客户端造合并就是替领域违规。

重放顺序也因此降格为性能问题而非正确性问题：乱序迟到本来就是领域必须处理的常态。逐对象保序仍值得做（减少服务端派生抖动、让操作员看到的结果顺序符合直觉），但它是优化不是不变量。

### 2.2 方案与代价

| 方案 | 内容 | 代价 | 判定 |
|---|---|---|---|
| **O-A. 本地事实队列＋重放（建议）** | 每次操作＝一条事实提交，入本地持久队列（IndexedDB/OPFS），带设备侧铸造的来源身份＋业务发生时间；网络可用时逐对象顺序重放，按三类表出队；参考数据（任务、路由指令有效性、身份关联）只读缓存＋过期标记 | 要求后端端点满足 §2.3 清单；客户端要做队列持久化、重放调度、结果收件箱 | 与 ADR-0022 的出队契约一一咬合——那份 ADR 本来就是给这个形状写的 |
| O-B. 本地事实库＋双向同步引擎 | 客户端持有相关事实副本，同步协议（CRDT 或变更游标）双向合并 | 后端要出全套增量同步端点；CRDT 的自动合并语义与「冲突不覆盖、形成身份冲突」正面相撞，绕开自动合并后剩下的收益与 O-A 无异；本地副本把客户数据长期落在设备上，加重 §5-U3 | 收益配不上复杂度，否决 |
| O-C. 纯在线＋失败重试 | 薄客户端，断网时界面阻塞 | 直接违反 ADR-0021「工位作业不会因为网络抖动而停」 | 否决，列出仅为完整 |

### 2.3 对后端端点形状的反向约束清单

ADR-0021 后果段点名「幂等、冲突合并语义、本地队列与重放」会反向约束端点。逐条列出，**分清哪些已有权威口径、哪些是本简报新提待裁**：

| # | 约束 | 状态与出处 |
|---|---|---|
| R1 | 同一来源身份和内容重放必须返回原结果（`已有结果`），使 at-least-once 重放安全 | **已有口径**——UC-NO-002 一致性节；各作业写端点须一致遵守 |
| R2 | 来源身份必须能在设备端**离线铸造**：认证所得的设备／工位身份＋客户端生成的稳定引用；端点不得要求服务端预发号（预发号需要网络，与离线矛盾） | **新提待裁**——与 ADR-0022「不新造幂等键、信封来自认证结果」对齐；设备认证方案本身是未决（§5-U2） |

| R7 | 4xx／5xx 判错纪律：依赖不可用一律 5xx。判错成 4xx 会让离线客户端丢掉本该重试的请求 | **已裁**——ADR-0022 后果段点名 |

### 3.1 候选

### 3.2 试证项（建议走 `/prototype`，产物扔弃、结论回主线）

1. Web Serial 连一台真实秤读稳定重量（含断线重连）；
2. 键盘楔扫描在扫描间隔、前缀后缀、焦点被弹层抢走三种情形下的可靠性；
3. IndexedDB 队列在设备重启／浏览器被杀后的存活率与恢复时延。

### 3.3 `packages/` 触发评估（[ADR-0018](../../docs/adr/0018-product-clients-share-release-boundary-under-apps.md)：出现第二个端**且**确有共享物）

作业端落地即满足两个条件，首批共享物按「与像素无关者先行」：

- **确有、应迁**：领域状态词表与 `StatusBadgeFor`（现住 admin-web `src/domain/status.tsx`，词取权威文档原词——两端各维护一份必然分叉）；`outcome` 词表与响应信封类型（三类表、`ACCESS_CHANNEL_NOT_CONFIGURED` 等稳定错误码）；API 客户端。
- **有条件共享**：四态／未配置态组件——仅当作业端确为 web（T1）时可共享；若日后分栈，退回只共享词表与类型。
- **不共享**：admin-web 的页面模板（列表／详情／复核的交互密度是给桌面治理的）；`templates/demo.ts` 的隔离合成 `S` 数据（红线：不进任何导出面）。
- **时机**：遵守「不预建空壳」——本简报不建 `packages/`；作业端第一笔真实共享代码落地时建，第一动作是把状态词表从 admin-web 迁出并让 admin-web 反向依赖它。

## 4. 扫描首屏 UX 骨架（文字稿）

设计原则取自 ADR-0021 的立端理由：**后端能拒绝非法写入，给不出替代动作；界面的职责是让每个屏态都有出路。** 骨架围绕「扫→答→下一步动作」组织；以下三个屏态（4.3–4.5）是该 ADR 点名「第三方扫描端不知道」的三种局面，每个必须有明确出路，这是本端存在的理由本身。

### 4.1 常驻布局与「永远可扫」

- 顶栏：当前节点／工位／操作员＋网络状态（在线／离线）＋本地队列深度（离线时这是操作员唯一的「我做的事没丢」凭证，必须常显）。
- 中区：最近扫描对象的身份与当前判定，大字号、远距可读。
- 底区：当前任务上下文（有任务时显示任务范围与进度；无任务不阻塞散扫）。
- 工位档加一列外设面板：秤读数、量方结果、拍照、打印内部作业标签。
- **硬规则：界面任何时刻可接受扫描输入。** 弹层、确认框不得抢走扫描焦点；上一件的结果呈现不阻塞下一件入队。扫描由物理扫描头触发（键盘楔），摄像头仅作后备。

### 4.2 正常流

扫描→本地缓存中身份唯一命中→显示对象身份、当前控制／位置、**该对象此刻允许的动作清单**（收寄、点验、装入集运、移动位置、测量……由缓存的任务与路由指令有效性派生）→操作员选动作→一条事实入队→即时回「已记录（待同步／已确认）」→下一件。在线时确认徽标随重放结果刷新（201 即建单成立，不必解析响应体——ADR-0022 给离线客户端的信号）。

### 4.3 屏态一：身份冲突

触发：同一外部条码命中多个实物，或同一实物携带相互冲突的外部标识。

- **呈现**：「身份冲突——方向性作业已暂停」＋冲突各方记录**并列展示，各自独立**，无任何视觉暗示哪个「是对的」。
- **出路**：① 对各实物继续独立的安全作业（隔离、测量、状况记录、移动到隔离位——域规则明许）；② 登记补充线索：拍照、录入其他标识观察，作为候选关联证据入队；③ 建案或联动入口：已有 `visibility-exception` 案件时显示案件引用，无案件时提供异常信号入队；④ 物理指引：「移至隔离位」的位置引导。
- **明确禁做**：不存在「选一个为准」「合并」「以本次扫描为准」按钮。这不是界面没做完——CONTEXT 明文「现场人员不得以覆盖、合并或『最后一次扫描为准』决定正式包裹身份」，缺这个按钮是合规而非缺陷，界面上应有一行小字说明去处（等 `parcel-shipment` 身份确认）。
- **解除**：`parcel-shipment` 确认身份后版本化关联生效，本屏态自动解除并在结果收件箱留痕。

### 4.4 屏态二：待识别实物

触发：扫描无命中，或有候选但证据不足。

- **呈现**：「无法可靠识别——建立待识别实物」引导流。必填：发现位置、状况观察；可选：候选标识线索、照片。
- **出路**：① 建立永久作业记录（入队）；② 打印并绑定**内部作业标签**（域规则允许节点自行生成，此后本件可用内部标签继续扫描作业）；③ 移动到暂存位的位置引导；④ 此后该实物可继续全部安全作业，方向性作业保持阻断。
- **明确禁做**：无「创建临时包裹」入口——待识别实物不是新的客户服务身份；无「按最后扫描认定」捷径。
- **解除**：候选被确认后由后端形成版本化关联，客户端在结果收件箱提示，原记录与全部事实保留。

### 4.5 屏态三：暂停方向性作业（兼离线降级态）

触发：对象可识别，但无当前有效路由指令／指令已被替代／**离线中缓存过期无法确认指令有效性**（R9：无法确认有效即视同缺失，域规则同款处理）。

- **呈现**：对象身份正常显示；「分拣到方向、装入出运集运、装载、交出」动作灰化，每个灰化动作标注原因（无有效指令／指令已替代／离线待确认）与恢复条件。
- **出路**：① 安全作业清单保持全绿：接收、隔离、测量、状况记录、移动到暂存位；② 「移至待方向区」引导；③ 在线恢复或指令刷新后动作位自动恢复，无需操作员重扫。
- 这一屏态使离线降级不需要单独设计：断网久了参考缓存过期，界面自然退到「安全作业可做、方向性作业暂停」，与域规则对「无有效路由」的处置完全同构。

### 4.6 结果收件箱

离线入队的事实重放后可能带回非预期答案（来源冲突、身份冲突、收寄判断待确认、未配置……），而此刻实物早已离手。三类表「4xx 出队交给人」「2xx 负向 outcome 呈现给操作员」需要一个落点：

- 按 `outcome` 分组、按对象可查的收件箱；负向结果必须有下一步入口（补证据、转案件、通知工位复核）。
- 收件箱深度进顶栏徽标；谁消化它（现场岗位还是管理台分诊）是未决（§5-U7）。

### 4.7 未配置态

任一端点答 403 `ACCESS_CHANNEL_NOT_CONFIGURED` → 全屏未配置态（admin-web 先例同款）：如实说明「接入渠道未配置」与恢复动作（配置渠道参数），不重试、不入队、不伪装成网络故障。

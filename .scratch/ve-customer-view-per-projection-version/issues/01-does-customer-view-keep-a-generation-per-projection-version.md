# 客户视图要不要按投影版本各留一代，没有文档回答

Category: enhancement
Status: resolved

用户 2026-08-20 批复：由 `dead-session-salvage/issues/01` 的只读对比划出的唯一真正未决问题，
立独立票存档，**不同期开工**；不据此重开已合入实现。

## 为什么单独立票

`dca024a`（停放的平行实现）与 main（`49a2ab0`）在「客户视图基于哪一版投影」上做法相反，
且**两边都引了权威**：

| | 做法 | 自陈依据 |
|---|---|---|
| `dca024a` | `FindByVersion` 读信封指名那版 | ADR-0065 / AT-VE-161：各版各长自己的视图代 |
| main | `FindCurrent` + 版本相等守卫跳过旧版 | UC-VE-008：客户视图只基于**当前**投影形成 |

两条权威管的是**不同对象**——ADR-0065 的「版本只增不改写」管投影，UC-VE-008 管客户视图。
没有任何文档明写「客户视图是否需要按投影版本各留一代」。这一问不裁，两边就都能自称合规。

## 已定的、本票不重开

- main 形状维持（用户 2026-08-20 批复）：`FindCurrent`+守卫与 UC-VE-008 明文一致；旧版信封被
  守卫跳过，不存在「先到吃掉后到」；路线 a 的补派生由账户绑定触发、无信封版本可用，只能基于
  当前投影——`FindByVersion` 形状无处安放它。
- 「没有下一封信封时视图停在旧版」的短路不归本票，外评 03 号票在追。

## 本票要裁的

仅一问：**客户视图作为对外发布物，是否需要与投影版本一一对应的版本代**（例：投影 v1→视图代 1、
投影 v2→视图代 2 各自保留），还是只需「当前视图 + 更正/替代关系链」（今天 main 的形状，
VE CONTEXT「形成新版本并标明更正或替代关系；原发布历史保留」已保证历史不丢）。
裁断落 VE CONTEXT 或 UC-VE-008；若裁「需要」，才谈得上实现票。

## 今天的影响

零。无租户、无生产流量；main 的视图链功能完整，历史保留纪律已由 CONTEXT 句守住。

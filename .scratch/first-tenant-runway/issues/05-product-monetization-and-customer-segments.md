# 产品自身收费模型与目标客户群分层

Category: enhancement
Status: resolved——两件产出与 `docs/README.md` 入口同笔落文，四条完成判据逐条自检，见文末 Comments

取证基线 `c9835bf`。纯文档票，无代码改动，与其余票无交集。

## 缺口

**两件，都卡在同一处：**「产品就绪」的定义里写着「可以进入商务洽谈」，而洽谈需要的两样东西都不在。

**一、本仓对「卖给租户怎么收钱」零口径。** `settlement-accounting` 管的是**租户对它自己的客户与供应商**的结算，跟「我们向租户收多少」是两件事。搜遍权威文档没有任何一处谈产品自身的收费形态。

**二、目标客户群是一句话。**[开发主线](../../../docs/product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)写的是「经营跨境出口小包网络的物流企业，首发以中国出口为起运侧」。而**能力范围判据**要判的是「该模式在上述目标客户群里是**常规形态**而非边缘情形」——一句话的客户群，让「常规形态」只能靠直觉判。这条判据已经在 ADR-0021、ADR-0088 与渠道适配缝备忘里被反复引用，它的输入应该比一句话更结实。

## 做什么

**件一：新开一份收费模型文档。**[产品战略与产品蓝图 V1.0（参考）](../../../docs/reference/IDP_Parcel_Product_Strategy_Blueprint_V1.0.md)第 10 章那张多层表可以当结构起点（订阅 / 交易 / API 用量 / 产品数 / 优化收益 / 企业合同六层）。

**只借结构，不借数字。**[竞品公开事实台账](../../../docs/product/COMPETITOR-FACT-LEDGER.md)已经证过蓝图附录 A 的 15 条里有五处站不住（1 条 404、2 条被反爬挡住、2 条关键价格取不到）；台账与 `docs/README.md` 都写明它不得作为本产品定价或成本假设的依据。要引竞品价格，引台账的`已核实`行并连核对日期一起引。

新增权威文档要按 AGENTS.md 在 `docs/README.md` 补入口与职责一句。

**件二：把目标客户群拆成分层。** 蓝图 6.2 那张客户优先级表里落在本仓范围内的三类可以直接用：物流产品设计者/整合者、小包专线与货代、3PL 与集运干线运营商。逐类写出常规业务形态，作为能力范围判据的输入。

**要收窄，不要照抄。** 它表里的「跨境卖家」与「电商 ERP / SaaS 平台」本仓明确不服务，引进来会把边界搞糊——[产品基线](../../../docs/product/PRODUCT-BASELINE.md)开篇就写「本产品不是货主运输管理系统的国际运输功能包」。

## 必须守住的一格

**收费模型这份文档不进[参数登记册](../../../docs/product/PILOT-PARAMETER-REGISTER.md)。** 登记册只登真实实例；收费模型是形态结论，性质同「产品需求假设」那一节的 `PA-*` 条目——按依据强度标注，第一个真实客户到来时必须复核。写任何具体价位都属越界，哪怕标成「示例」。

## 完成判据

两份产出各自落文；客户群分层写进开发主线的「目标客户群」一节并说明它是能力范围判据的输入；收费模型文档在 `docs/README.md` 有入口；全文无任何具体价位数字；引用竞品事实处连核对日期与核对状态一起引。

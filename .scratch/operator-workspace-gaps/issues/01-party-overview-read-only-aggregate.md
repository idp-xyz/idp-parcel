## 为什么

参与方详情抽屉今天只有身份字段与修订历史。运营打开一个参与方，想知道的是「它对我们是什么」：它在哪些关系里、有没有货主客户账户、是不是
本集团的责任法人、签了哪些供应商协议、适用哪些结算政策——这些事实都已在各册、各读口上，而且都带参与方标识，只是散在四五个页面。

这不需要改模型：业务参与方是稳定身份，角色来自参与方关系，客户账户必须关联客户参与方，供应商协议的供应商是 `PartyID`，结算政策的客户
相对方解析到业务参与方册（party-commercial CONTEXT 结算政策那条）。全景只是读取时的组合，不产生新的数据所有者，也不形成第二套口径。

## 要做的

1. **抽屉分两签**：「全景」（默认）与「身份与修订」。后者装原有全部字段与修订历史，一格不改。
2. **全景五段**，各按参与方标识在已取回的行上关联——不下推查询参数、不改端点（README 列表页上列通则）：
   - **参与方关系**：`holderId` 或 `counterpartyId` 等于本参与方。每行示本方是持有方还是相对方、角色、另一方（标识 + 名称，悬空如实标）、
     适用范围、有效区间、状态。方向照页面既有说法写「持有方 / 相对方」，不替它解释成「谁是谁的客户」。数据取页面已持有的关系册答案，不另取。
   - **货主客户账户**：`customerPartyId` 等于本参与方。
   - **责任法人**：法人册 `partyId` 等于本参与方，即本参与方是不是本集团的责任法人。
   - **供应商协议**：`supplier` 等于本参与方。正文未登记的版本壳没有 `supplier`，归不进任何参与方，如实不列。
   - **结算政策**：`counterparty` 等于本参与方。
3. **每段独立四态**：读取中 / 未配置（403，写明「这不是没有」）/ 调用方问题 / 可重试错误；拿到业务答案而零条时写「册上没有以本参与方为……的记录」，
   不写成错误。一段出错不影响其余各段。
4. **计数带状态守卫**：段首条数只在该段拿到业务答案后显示；顶部摘要逐段一格，未答的段示「—」不示 0（README 列表页上列通则第六条）。
5. **每段给去处**：「去某页」写 `#/<模块id>`，标题取 `moduleInfoById`；关系段就在本页另一签，不给跳转。

## 不做

- 不接授信、余额、订单等跨上下文信号：要 `settlement-accounting`、`parcel-shipment` 按参与方的读口，不在前端拼别人的账。
- 不列客户合同：合同行的 `scope` 能不能对上客户账户未核实，核实前不猜。
- 不做待办提醒与疑似重复提示（各有待定问题，见 spec）。
- 不改任何端点、`CONTEXT.md`、ADR。

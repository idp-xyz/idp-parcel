# 02 领域：货物明细、装箱分配、平台号声明与规范化

Category: enhancement
Status: resolved——2026-11-12 进 main

依据：ADR-0373 决定二、三、六、七、八；ADR-0374 决定四；小包托运 CONTEXT「货物明细」「货物明细行」「装箱分配」「内件性质」「申报格来源标记」「销售订单引用」「外部标识关联」；UC-PS-001 `AT-PS-181`、`AT-PS-182`、`AT-PS-183`、`AT-PS-186`、`AT-PS-187` 的领域半边。

## 要做的

只动 `internal/parcelshipment/domain/`，不碰 HTTP 与 `pgx`。

- 货物明细值对象：委托级内件性质（封闭六格加「其他」说明）、1 至 999 条有序货物明细行、装箱分配（包裹，行号，数量）。
- 货物明细行的各格：品名（语言标签 → 文本，同一语言至多一条）、数量与计量单位、单价与行总价及一个币种、净重与重量单位、申报商品编码（出口侧、进口侧各至多一条）、原产国码、货主商品编码、销售订单引用（销售平台、订单号、订单行号）。在场的格原样保存客户给的串。
- 申报格来源标记封闭三格；内件性质与行里各格各带一个。
- 形状校验，违反即返回领域错误，供 03 映射成「请求形状不对」：一行一格都没有、超过 999 行、同一语言两条品名、同一口径两条编码、数量或金额不是数；装箱分配只报一部分、指不在成员集合里的包裹或不存在的行、某行各包裹数量之和不等于该行数量、报了分配而该行数量缺席。单件委托报了分配同样按「报全」核。
- 不做任何交叉核对：单价乘数量与行总价、净重与声明测量、价值与保价声明价值、编码位数、国家码格式都不判。用测试钉住「对不上照样成立」。
- 平台货件（销售平台、平台货件号、可缺的平台参考号）与每箱平台箱标号的**声明**：箱标号只指成员、一箱至多一个、同一委托里不重号、要有平台货件；号过 `NewExternalIdentifierNumber` 的入册门，销售平台名是库存得下的文本、不超过同一字节界。外部标识**种类**与关联的形成挪到 03：照 ADR-0184「只有有来源的类型进来」，种类随它的来源（接受时形成关联）一起进来，在 02 只加种类会是一个没有来源的空类型。
- 规范化：`SubmissionPayloadSpec` 加强类型的货物明细与平台号，按 ADR-0373 决定八在 `PSC-1` 上同号加可缺键（ADR-0267 决定三的前提），没报即不编码、旧载荷逐字节同前；补充 `PSU-1` 共用同一编码。装箱分配在算摘要时对着提交的成员集合再核一遍。
- 评审带出的形状规则（ADR-0373 修订后）：内件性质为「文件」时可以没有行；报全要求每个包裹至少一条；在场的格要是库存得下的文本（`storable.Text`）；没报内件性质却带标记或说明拒。

## 完成判据

- 上列形状错逐条有失败测试；「对不上照样成立」各有一条成立测试。
- `PSC-1` 的既有摘要测试原样通过，并钉一条改动前算出的摘要常量证明旧载荷逐字节同前；新内容对同一输入稳定，行序是内容、分配顺序与品名语言顺序不是，写进测试。
- 注释用中文，只写为什么；跨文件引用照 AGENTS.md「改文档」，不用行号与计数。

## 不做的

落库、HTTP、查阅与修订在 03、04、06。

## 三类归类

999 行上限与形状规则是产品机制；必填与跨字段条件是租户取值，本票不碰。

# 02 字号下限提到 12、正文提到 13，页名与对象名用 20

Category: enhancement
Status: ready-for-agent
父票：[spec](../spec.md)
Blocked by: 无——与 [business-party-redesign](../../business-party-redesign/spec.md) 各票互不相干，谁先落都行

出处：2026-11-06 [business-party-ux](../../business-party-ux/spec.md) 第二批把「字号整体放大」裁为「不做（本轮）……要动等用户决定」。2026-11-10 往来单位重构时会话把它列为待定项（只本页先行，还是全站一起），用户答「你作为国际小包业务和系统专家，根据你以往的经验帮我决定吧」。决定：全站一起，走角色表，本页不做例外。

## 为什么

- 「说明」档今天是 11 像素，用在计数徽章、角标、表单格下的提示上，写的全是中文与数字。中文笔画密，11 像素已经难读，12 是中文的实用下限。
- 正文 12 像素对整天盯着表格的运营偏小。
- 只动角色到令牌档的映射，不引新值：12、13、20 都在 `coreTypography.fontSize` 的阶梯上。

## 要做的

| 角色 | 现在 | 改后 |
|---|---|---|
| 说明 `type-caption` | 11（xs） | 12（sm） |
| 正文 `type-body` | 12（sm） | 13（md） |
| 读出值 `type-value` | 13（md） | 不变。与正文落到同一档，角色名留着：将来要再拉开，不必全站重找 |
| 区块标题 `type-section` | 14（lg） | 不变 |
| 标题 `type-title` | 16（xl） | 不变，用途收窄到栏标题与对话框标题 |
| 页名（新角色，类名在本票里定） | —— | 20（2xl）：页标题、右栏与对象页头的对象名 |
| 大数 `type-display` | 20（2xl） | 不变 |

- 改 `apps/admin-web/tailwind.config.js` 里角色到令牌档的映射，加新角色；`docs/design/admin-web-typography-roles.md`（唯一权威）的表与约定同一笔改；守卫认新角色名。
- 页标题与对象名从 `type-title` 换到新角色，逐处改（各模板与对象页头）。
- 逐模板过一遍。字大一档之后会坏的是写死高度的行与控件、被截断的表头、挤在一行里的工具条：列表模板、工作台模板、对象页、登记表单、对话框各挑两页，在 1280 与 1440 两个宽度下看。
- 「标签与正文同一档」的约定不变：字段标签随正文到 13，与读出值同大，靠颜色分主次。往来单位重构的静态页把标签画成了 12，以角色表为准。
- 密度不丢：表格行高不因此增加。

## 不在本票

- 粗体的全站盘点。往来单位重构里量过：Windows 上中文只有常规与粗体两档，半粗画出来就是粗体。那一页自己守「粗体只给页名、对象名、栏标题」；外壳与别的页要不要照此收，另议。

## 完成判据

- 三道门退 0；守卫通过；生成的 CSS 里各角色类的取值与文档的表一致。
- 浏览器：每个模板两页、两个宽度、深浅两个主题，没有截断、折行与溢出；900 高视口下列表的可见行数与改前一致，量出来写进完成记录。
- 非作者评审：动的是全站共用的配置与模板。

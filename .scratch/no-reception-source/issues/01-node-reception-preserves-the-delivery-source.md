## 裁定（2026-10-18，会话 idp-parcel-9b 代决）

方向照原稿，六问代决如下：
1. UC-NO-002 结果表「收寄判断待确认」成因里的「身份」，指交付范围或实物本身无法区分；正式包裹身份的未知与冲突，按步骤 4 归待识别。
2. 重核由 PS 关联册新形成关联时发出的信封触发，复核页人工发起作补充；不做后台扫表。这一步就是 AT-NO-026「身份后来被确认」。
3. 「同一作业实物」按租户内的作业实物标识认，外部标识观察不是实物的身份；认出同一实物在同一节点已有当前收寄时，交回那一条的结果，不另起控制起点。
4. 仅扫描的待确认之后来了明确接收或拒收，追加一版判断续办原判断（步骤 6C），不伪造确定结果。
5. 已有结果的答复带回原判断种类与当前有效版本。
6. 核对态进设备响应，只作信息格，不进 outcome 词表。
分四期落：一、来源保全（收寄记录存本次交付的规范化来源文档，三种观察都存）；二、按存下的号重核（AT-NO-026）；三、身份读不动翻成「待识别 + 未核对」（ADR-0186 写明的四个前提齐备才翻）；四、同一作业实物重复控制起点的挡法。每期各立实施票，难逆转的进 NO ADR。

## 现象（钉 main 8d22729f）

收寄记录里不存现场看到的外部标识：
- ports.ReceptionRecord、domain.NodeIntake 和 postgres 的行模型，都没有号码格；
- Handle 把 domain.CanonicalizeDeliveryPayload 交回的规范化交付文档写成了 `_`。

因此有两条要求没落实：
- UC-NO-002 步骤 1：「保全本次交付来源、原始引用、业务时间、接收时间、节点和交付方｜后续解析失败不删除来源」；
- PN-03 交接 PN03-W03：「先保全客户交付、扫描、点验、拒收和现场观察，再逐件形成…」。

由此产生的后果：

- 后果一：身份核对读不动时，没有可以落的格。
  - 若落成待识别，服务端无从重核。核验探针实测，这时行内不含现场看到的外部标识；PS 恢复后，同一来源重投只答 EXISTING_RESULT，仍是待识别，意图为零；前线导入首导退出码为 0，重跑只答重放。
  - 所以草案 C1-T1 让这一支不形成答案。
  - 零候选的待识别，今天同样无法按号重核。
- 后果二：拒收只存拒收原因；仅扫描只存键、摘要、种类和时刻；仅扫描的`收寄判断待确认`没有续办引用。UC 结果表对待确认的要求是「已知事实、控制现状、缺口、限制和续办引用」。
- 后果三：已有结果的 HTTP 答复不带原判断种类。例如仅扫描一支，重投时答复只有 outcome 一个字段。UC 对「已有结果」的要求是「原节点收寄或待识别结果」。
- 后果四：收寄键只有（租户，来源）两项。同一作业实物换个来源重扫，会形成第二条收寄、第二个控制起点。核验探针实测：同一作业实物两行，两个控制起点。这与 UC「同一实物同一客户交付边界只能形成一个当前有效节点收寄判断和一个控制起点」相抵。

另外，AT-NO-026「身份后来被 parcel-shipment 确认」在 .scratch/at-coverage-inventory.md 里列为机制候选，没有票，也没有人工关联口。

## 方向裁定（簇 C1 终裁给的方向，待本票确认）

- 来源先保全。收寄记录保存本次交付的规范化来源文档，包括外部标识观察、接收观察、证据、拒收原因、交付方、节点和发生时间。明确接收、明确拒收、仅扫描这三种观察都要存。
- 身份核对读不动时，目标形态是`待识别实物已建立`，另加身份核对态「未核对」。
  - 收寄与控制都成立：CONTEXT 规定实物控制因明确节点接收而形成。
  - 不交意图。
  - 「未核对」与零候选可以区分开，以此守住 ADR-0089「绝不交回空候选顶替」。
  - 不取「带物理事实的待确认」：CONTEXT 写明「已拒收或待确认均保持此前已确认的控制关系」，而明确接收已经取得了控制。
- 翻转有四个前提，缺一个都不翻。草案 C1-T1 定下的 5xx 答法，留到翻转那一笔再改：
  1. 来源已保全。
  2. 「未核对」处处可见：设备响应的信息格、前线导入明细、复核目录与管理台，以及 ParcelContainmentView（见 ports.ParcelContainment 头注：身份未定的在袋件，不能答`不在`）。
  3. NO 主动重核：拿存下的外部标识观察再问 PS；结果唯一，就建立版本化关联并交意图，业务时间取原收寄时刻。
  4. 有办法挡住同一作业实物重复形成控制起点，而且不只限于身份这一支。

## 要裁的问题

1. UC 结果表`收寄判断待确认`的成因里写了「身份」，指的是哪种情况？是正式包裹身份（步骤 4 已把「未知」与「冲突」导向待识别），还是交付范围或实物本身无法区分？由 NO owner 来读。
2. 重核由什么触发？候选有三种：PS 关联册新形成关联时发来的信封、后台扫表、复核页由人发起。这一步与 AT-NO-026 是不是同一步？
3. 「同一作业实物」按什么认：作业实物标识、外部标识观察，还是两者都看？认出来之后答什么？
4. 仅扫描的待确认，之后来了明确接收或拒收，怎样续办原判断？UC 步骤 6C 的要求是「只续办原判断，不伪造确定结果」。
5. 已有结果的答复，怎样带回原判断种类与当前有效性？
6. 核对态要不要放进设备响应？若放，只作信息格，不进 outcome 词表。

**ADR-0199 摘要**

- 决定一（第一期）：收寄记录带本次交付的来源文档，与判断同一行同一笔事务写下、此后不改；明确接收、明确拒收、仅扫描都存，外部标识观察原样；指纹仍是 NOC-1 收寄面那几格，证据、拒收原因、交付方只进来源文档；既有行不回填。
- 决定二（第一期）：每种判断都签判断版本；追加的一版指名前版，库面（租户，前版）唯一；已有结果带 `recordedOutcome` 与 `currentVersion` 两格信息，不进 outcome。
- 决定三（第二期）：重核只由 PS 关联册新形成关联时交出的（租户，号码）信封与复核页人工发起触发，不扫表；对象是当前有效版本为待识别、无关联、不记冲突、号码逐字相等的判断；走与收寄步骤 4 同一份身份判断；结果唯一即追加关联版，业务时间是原收寄时刻、不另起控制起点、意图一封；派生来源标识带 `IDENTITY-RECHECK/` 前缀、由被重核那一版的判断版本派生。
- 决定四（第四期）：同一作业实物按租户内的作业实物标识认；同一节点已有当前收寄时任一观察都并入（新的一种记录「并入已有收寄」，来源照存，答已有结果）；仅扫描待确认由后来的观察以前版续办；先实物锁后包裹锁。落地时部分停用 ADR-0196 决定一末句与「能力边界」一句。
- 决定五（第三期）：身份核对读不动落`待识别`加身份核对态「未核对」（`identityCheck`：`CHECKED` / `UNCHECKED`，信息格）；`ParcelContainmentView` 对未核对在袋件答`不可归属`；身份读口改经 savepoint。翻转前提缺一个都不翻；落地时部分停用 ADR-0186 决定二与决定七各一句。
- 越权风险点九项，含：代 PS owner 定交出信封；重核触发与「NO 主动重核」相抵；指纹不含证据、交付方、拒收原因；按作业实物标识认同一实物；未核对在袋件让同租户包裹答不可归属；分期次序与裁定字面不同。

# 05 责任法人业务属性建模：税号、注册国家、开票主体、结算币种、联系人

## 问题

`GroupLegalEntityRecord` 今天只有：法人标识、种类、参与方身份（名称从参与方册转写）、状态、修订、登记依据、生效自、
停用时点/依据、登记时间。**没有任何一格说这个法人是谁、在哪、以什么身份开票与结算。**

对跨境小包（首发 CN→SG）这不是装饰：

- **纳税人识别号 / 统一社会信用代码 / UEN**：关务申报（customs-compliance 的申报路径与义务目录）与开票都要它；
- **注册国家 / 地区**：决定它能在哪个关区做申报主体、受哪套税制；
- **开票主体与结算币种**：settlement-accounting 的对账单、收付款核销按责任法人归集（CONTEXT「结算与核算四页各接自己的读适配器…
  责任法人、结算账户与币种是账上的归属维」）——账上有这一维，法人册上却没有它的定义；
- **联系人 / 地址**：合同签署与通知投递。

## 要裁的（CONTEXT 层）

1. 这些属性**归谁拥有**：责任法人身份册（party-commercial）本身，还是另立「法人资料」修订链引用身份？身份册今天登的是
   「这个租户认下这个身份自某时起生效」，属性是否随身份一起修订版本化（改税号翻旧插新）。
2. 哪些是**必填不变量**（没有税号能不能登记）——不写死为生产默认，缺省朝拦还是朝放。
3. 与 `business_party_registration`（参与方册，名称在那）的分工：名称已经在参与方册，地址、联系人跟名称走还是跟法人走。
4. 敏感实例外置红线：真实税号属租户实例数据，进登记册没问题（那是租户自己的库），但**种子与文档只能出现 `SYN-` 合成值**。

## 裁决（2026-09-24，用户授权通道 3 自决）

授权同票 04。「要裁的」四问逐条定；产出照「产出」节不变。外来方案
[`IDP_Parcel_Commercial_Party_UX_V1.0.md`](../../../docs/reference/IDP_Parcel_Commercial_Party_UX_V1.0.md) 的「Tax & Registration」「Country-aware」
「Addresses 必须有 Validation 状态」「Contacts」几节作起草输入，非权威。

1. **归属：分两层，都在 party-commercial。**
   - **身份层**，随责任法人身份一起登记：注册国家 / 地区 + 终身注册号（UEN、统一社会信用代码这类一个法人只有一个、不会换的号）。登记后不修订——
     号变了就是另一个法人，停用旧的、登记新的；录错同样走停用 + 重登，不开「改号」这条路。
   - **资料层**，另立「法人资料」修订链，按法人标识引用身份：注册地址、联系人、开票资料（开票抬头等）、结算币种，以及可后办、可变的税务登记号
     （GST / VAT 之类）。按生效时点翻旧插新；对账单、发票、申报按**开立时点**读当时有效的那一版——单据开出之后资料再改，旧单据不跟着变。

   理由：身份册登的是「本租户自某时起认下这个身份」，生命周期是生效 / 停用；资料按自己的节奏变，混进身份册会让每改一次地址就翻一版身份，把
   「是谁」和「在哪、怎么开票」搅在一起。
2. **必填：登记时只拦身份层。** 注册国家与终身注册号缺一拒登（朝拦）。开票资料与结算币种不在登记时拦，在**首次开票 / 首次结算**那两道门上拦——
   法人可以先登记后补资料，但没有资料不能开票；联系人可空。注册号的类型与格式按国家配置：机制现在做（按国家的注册号类型目录 + 格式校验），各国
   规则是可配置目录，不写死为生产默认；种子只出 `SYN-` 值。
3. **与参与方册的分工：** 名称留在参与方册（今天就在那里）；注册地址与联系人跟法人走——法律意义上的地址属于法人。收寄 / 业务往来地址不在本票，
   归客户账户或将来的地址簿。
4. **敏感实例外置照旧：** 真实税号只进租户自己的库；仓库里的种子、夹具、文档只出 `SYN-` 合成值。

之后拆迁移、领域、读写口、页面票。

## 盘点（2026-11-05，演示租户 5173 实看 + 代码）

领域边界先说清：业务参与方只有**身份**这一层（名称、编码、登记依据、生效与停用，修订不可覆盖）；地址、开票、收款账户、联系人是**法人资料**，只属公司主体。所以往来单位**不做资料层**，不照搬公司主体的那几个分区。

已有：列表工作台（类型 / 状态筛选、指标头、合作关系册签）、右栏（全景 / 变更记录）、对象页（更正名称编辑态、停用对话框、全景里就地登记合作关系）、合作关系册与关系右栏（含结束：到期 / 撤销 / 替代）。

差距：

1. **对象页版式与公司主体不一致。** 公司主体：头区一行元信息（编码、注册地、注册号）、紧凑指标带、锚点分区带计数（概要 / 联系人 / 资料版本 / 登记记录 / 关联）。往来单位：四张大指标卡、一张几乎为空的「来源单据」卡（只有「停用的来源单据：未停用」）、全景挤在一张长卡里、签名「概要 / 时间线」；右栏签名又叫「全景 / 变更记录」，两处叫法不一。当前修订的登记依据藏在技术详情里。
2. **合作关系在对象页上只能登、不能结束、不能点开。** 结束（到期 / 撤销 / 替代）只在合作关系册的右栏里有。
3. **客户账户在对象页上只有一个「去客户与合同」的跳转。** 不能就地新增，不能停用（停用口已支持 `CUSTOMER_ACCOUNT`）；新增客户账户在客户与合同页上还是粘 JSON 快照，没有结构化表单。
4. **列表的「类型」把没有合作关系的单位叫「往来单位」**，与模块名同名，读不出意思；编码不在列表里显示（公司主体的列表名称下带编码）。

## 决定

- 对象页照公司主体的分区版式：头区元信息（编码、类型、当前登记依据），紧凑指标带（生效、变更版次、生效中的合作关系数、客户账户数、被引用数），锚点分区 **概要**（身份与来源单据）/ **合作关系** / **客户账户** / **关联**（公司主体、供应商协议、结算政策）/ **登记记录**（修订历史）。右栏签名与对象页同名。
- 合作关系分区：每条可点开右栏同款详情，生效中的就地「结束…」（复用 `PartyRelationshipEndActions`），已结束的收在「已结束 N 条」下。
- 客户账户分区：账户行显状态；就地「新增客户账户」（结构化表单，客户参与方锁定为本单位）；生效中的可「停用…」（对话框，种类锁定 `CUSTOMER_ACCOUNT`）。客户与合同页的「新增客户账户」视图同步换成这张表单。
- 列表：名称下带编码；没有合作关系的类型显「暂无合作关系」（筛选、页头指标同词）。

机制：无新增（全部写口与读口已有）。产品策略：页面形态。租户取值：无。

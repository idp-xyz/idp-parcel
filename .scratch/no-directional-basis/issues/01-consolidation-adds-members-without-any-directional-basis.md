出处：UC-NO-003 的业务规则「方向性作业必须取得当前有效路由指令；集运还必须取得成员级集运兼容判断」、输入表「包裹与服务」一行（`parcel-shipment` 的当前取消/终局结果）、`AT-NO-031` 与 `AT-NO-042`；NO CONTEXT「候选尚未确认时不得据此执行方向性作业」与「已取消、已经终局或当前无有效路由的包裹仍然到站时……」两条。

## 事实

`internal/nodeoperations/application/consolidate_parcels.go` 的 `ConsolidateParcelsHandler.AddMember` 在幂等闸之后只问两件事：单元在不在（`Store.FindByID`），成员此刻是否已被别的单元直接包含（`Containment.CurrentParent`）。`ConsolidateParcelsDeps` 里没有路由指令、集运兼容、服务结果或身份的读口。于是：

- 收寄记录上带 `CANCELLED/…` 或 `FINAL/…` 标记的实物（票 25 落的），加进袋照常 `MEMBER_ADDED`——标记今天没有任何消费方。
- 没有当前有效路由指令的实物照常进袋（`AT-NO-031` 要求阻止集包）。
- 待识别或身份冲突的实物照常进袋（ps-port-remainder/05 的完成记录已记过「`AddMember` 不核成员是否已识别」，那一票只为阶段读面如实答`不可归属`，没有补门禁）。

票 25 的完成记录说「标记限制后续方向性作业」此刻只体现在记录与复核目录上，缺的就是这一半。

## 要裁的问题

1. **门禁放在哪一步。** 加成员、封装、交出各自核，还是只在加成员核（封装与交出继承成员已过门）。
2. **依据从哪里来。** 服务结果：读收寄记录上的标记（收寄那一刻的快照，之后 PS 新形成的取消读不到），还是加成员时再经票 25 的 `ParcelServiceResultView` 现问。路由指令与集运兼容：network-routing 今天有没有可消费的读口，没有时是本票阻断还是答`未决`。
3. **挡下来答什么。** UC-NO-003 结果契约里的「方向性作业受阻」（对象、拟执行动作、缺少依据、当前安全作业和续办入口），与现有 `ConsolidationNotAccepted` / `ConsolidationUndecided` 两格怎么对上；依赖读不动与「依据明确不成立」要分开。
4. **已取消或终局的实物要处置时怎么走。** `AT-NO-042`「方向性处置等待授权」：授权从哪来（PS 的收寄后服务处置决定？），本票接不接。

## 不做

- 不改「标记不阻止接收」（UC-NO-002）。
- 不在 NO 判断取消或终局是否成立——那是 PS 的事，NO 只消费结果。

## 裁定（2026-10-16，Claude Code 会话，用户授权代决；产品策略，不含租户取值）

1. **门禁放在实时渠道的加成员这一步。**
   - 实时扫描入袋是动作之前的请求：现场扫这一下，系统答受阻，件就不进袋。这正是 UC-NO-003「安全结束」那一格——无有效方向依据时只完成接收后安全作业，不执行下一跳动作。
   - 前线过渡导入（`cmd/parcel-frontline-import` 的集运模板，同走 `ConsolidateParcelsHandler.AddMember`）搬的是旧系统里已经发生的成员事实，**不过门**：UC-NO-003「已经发生的错误分拣保留为事实并形成偏离，不回写为未发生」。偏离判断归 NR 的路由偏离判断，本票不替它做。两个入口怎么区分由实施定，判据是导入行不被门挡、实时口必过门。
   - 开单元、移出成员、开封、封装、关闭不过门。移出与开封是安全动作，把件拿出来永远允许。封装与交出作用于入袋时已过门的成员；入袋之后 PS 新形成的结果走 PS「收寄后服务处置决定形成 → 各对象所有者分别承接」那条路（停止或释放请求），不靠封装时重查。
2. **依据从哪里来。**
   - **身份**：成员须有已成立的正式包裹关联。今天 NO 里正式包裹 → 作业实物的映射只有收寄判断里识别成功建立的版本化关联（ps-port-remainder/05 完成记录原话）。待识别、身份冲突、查不到关联的实物答受阻（CONTEXT「候选尚未确认时不得据此执行方向性作业」、身份冲突「暂停方向性作业」）。经权威运输交接取得控制的实物怎么带上关联，实施时核清；核不清的那一格答受阻，不放行。
   - **服务结果**：加成员当下经票 25 的 `ParcelServiceResultView` 现问，不读收寄记录上的标记。标记是收寄那一刻的快照，入袋要的是此刻的结果，收寄之后才形成的终局在标记上读不到。同一个端口、同一个防腐适配器，不另开第二个读口。有取消决定或当前终局即受阻（`AT-NO-042`「方向性处置等待授权」）。
   - **路由与集运兼容**：NR 今天没有路由指令与成员级集运兼容判断的模型，也没有按包裹答当前有效路由的读口（计划适用性按计划版本存取）。NO 开一个路由依据端口，生产装配显式未配置，答受阻、缺少依据「路由依据未配置」，续办指向 [02](./02-network-routing-has-no-routing-instruction-or-consolidation-compatibility-judgment.md)。**不跳过这一格**：跳过就是替 NR 默认「兼容」，红线「不写死为生产默认」禁的正是这个；也不在 NO 里自己比下一节点，那是 NR 的判断。
3. **挡下来答什么。** 新的一格`方向性作业受阻`（`DIRECTIONAL_WORK_BLOCKED`），与`未受理`（输入或不变量不成立）、`未决`（依赖读不动）分开——依赖读不动仍答`未决`，依据明确不成立才答`受阻`。按 UC-NO-003 结果契约落册：对象、拟执行动作（加成员与目标单元）、缺少依据（封闭词表，可多项并列）、当前允许的安全作业、续办入口。同一来源重投返回同一结果，幂等与现有集运事实同口。不形成成员关系。
4. **已取消或终局实物的处置授权不在本票。** 授权来自 PS 的收寄后服务处置决定（UC-PS-006），NO 承接它要 PS → NO 的处置交接，今天不存在，另立票。本票只做「等待授权」那一半：挡住。

## 裁定修订（2026-10-16，同一会话，开工前核实；上面「裁定」原文不动）

开工前核了两件事实，第 1 条站不住：

- **今天没有实时集运入口。** `ConsolidateParcelsHandler` 在生产上只在 `cmd/parcel-frontline-import` 里构造，搬的是旧系统里已经发生的成员事实——按第 1 条本就不过门。所谓「实时扫描入袋」没有一个调用方。
- **[ADR-0021](../../../docs/adr/0021-frontline-operations-client-is-part-of-the-product.md) 已接受：离线与弱网容忍是一线作业端的固有要求**，并且「离线容忍……会反过来约束业务端点的形状」。离线设备回网后交来的每一条加成员，都是已经发生的物理动作，服务端答「受阻」时件早已进袋。同一份 ADR 还写了「后端能拒绝非法写入，给不出替代动作」——方向性作业的门属于作业端的流程，不属于写口。

修订如下：

1. **门是读面，不是写口。** 服务端按作业实物答「此刻能不能做方向性作业、缺哪几样依据」（身份、服务结果、路由依据，取法照原裁定第 2 条），作业端在动作之前查：在线时现问，离线时用缓存的参考数据把方向性动作灰掉并标出缺的依据。加成员照收照记，不因依据缺而拒。
2. **已发生而缺依据的加成员照记，并留偏离。** UC-NO-003「已经发生的错误分拣保留为事实并形成偏离，不回写为未发生」：作业事实落册时，同一笔把当时的依据判断记在旁边（缺哪几样），供复核目录与前线导入报告呈现。偏离的判断与追责归 NR 的路由偏离判断与 VE 的异常，NO 只留事实与当时的依据快照。
3. **排期。** 读面唯一的消费方是作业端，而作业端还没排进开发主线（ADR-0021「两个端都等真实落地时才建」）——读面随作业端一起建，不先建一个没人问的端点。偏离标记那一半今天就有消费方：前线导入搬进来的历史成员里若有已取消、已终局或身份未确认的件，运营现在就该在复核页上看得见。它可以先做，要不要先做由用户排。
4. 原裁定第 3 条「挡下来答什么」随第 1 条作废：写口不再有「方向性作业受阻」一格；那一格的语义挪到读面上作答。第 4 条（处置授权另立）不变。

本票因此转 `needs-info`，等两件用户决定：一线作业端何时排进开发主线；偏离标记要不要先于作业端做。

## 偏离标记半边：设计代决（2026-10-16）

依据「裁定修订」第 2 条。另与 `idp-parcel-9b` 会话的收寄口径（C1，代决）对齐，三句：已经发生的物理事实照记；跨上下文读不动不挡落册，那一格记`读不动`；读放在写事务之前。

1. **叫法：「方向依据记录」。**
   - 加成员事实落册时，同一笔记下该作业实物当时的方向依据。「方向依据」是 NO CONTEXT 原词：「不能执行没有方向依据的后续分拣、集包出运或装载」。
   - 不叫「偏离」：那是 NR 的路由偏离判断。
   - 不叫「快照」：那是封装成员快照。
   - 不叫「作业依据」：那是封装、开封、处置所引的依据。
   - NO CONTEXT 增一条术语、一条规则。
2. **身份、服务结果、路由依据三格，每格一个取值。**
   - 取值是封闭词表：`成立`、`缺少`（附原因，可并列）、`未配置`、`读不动`、`未判`（前提不成立、无从问）。记录另带判断时刻。
   - **身份**：取 NO 自己的收寄册，按作业实物查带收寄的行。
     - 恰好关联到一个正式包裹、且没有一行记身份冲突，为`成立`，带关联引用、所依收寄的来源标识与收寄版本。
     - `缺少·无收寄记录`：查不到。包括未取得控制，以及经交接进来、今天在 NO 无收寄行的实物。
     - `缺少·待识别`：只有待识别行。
     - `缺少·身份冲突`：有行记了身份冲突，或多行关联到不同的正式包裹。
     - 收寄册读错记`读不动`。
   - **服务结果**：身份成立才问，否则`未判`。
     - 经票 25 的 `ParcelServiceResultView` 现问：同一端口、同一防腐适配器，不另开读口，不解析收寄记录上的标记。
     - 无取消、无终局为`成立`。
     - 有取消决定记`缺少·已取消`，带取消引用。当前终局记`缺少·已终局`，带终局种类与版本。两者可并列。
     - PS 读错记`读不动`。
   - **路由依据**：
     - NO 开路由依据端口，生产装配显式未配置，答`未配置`，续办指向 [02](./02-network-routing-has-no-routing-instruction-or-consolidation-compatibility-judgment.md)。
     - 身份不成立时`未判`。
     - 不跳过这一格（跳过即替 NR 默认「兼容」），也不在 NO 里自比下一节点。
3. **何时判、何时落。**
   - 判断在组合根、写事务之前，用外层 ctx 在池上读；结果作参数交进 handler。
   - 只有形成新加成员事实（`MEMBER_ADDED`）时落记录，与事实同一笔、同生共死。其余结果码不落。
   - 同一来源重投（`EXISTING_RESULT`）交回落册的那一份，不重判。
   - 记录不进内容指纹，NOC-1 与旧指纹都不动；否则 PS 状态变了，重投就会成来源冲突。
4. **不挡事实。**
   - 加成员照常答 `MEMBER_ADDED`，导入行照常「已落地」，退出码语义不改。缺依据不是拒收，读不动也不是未决。
   - 偏离的判断与追责归 NR（路由偏离判断）与 VE（异常）。NO 只留事实与当时的依据。
5. **时间语义。**
   - 记录说的是「判断时刻所知」，不是「装袋那一刻」。导入的历史装袋可能早于 PS 的取消；先后归 PS 按业务时间裁，NO 不代判。呈现时发生时间与判断时刻并列。
   - 改动之前落的加成员事实不回填，读出为`未记录`，绝不显示成依据齐全。
6. **呈现。**
   - 前线导入报告：`MEMBER_ADDED` 与重放行的说明追加「缺少依据：…」与「读不动：…」。路由依据`未配置`对每一行都成立，只在汇总行说一次，不逐行标——逐行标会把真正的已取消、已终局、身份未确认淹掉。
   - 节点作业查阅：后端增「集运成员关系」一本册（CONTEXT 原词），读加成员与移出事实连同方向依据记录。
   - 两件随后：查阅换操作者 Intake（今天挂隔离读，生产答 403）归 [operator-channel/35](../../operator-channel/issues/35-remaining-operations-read-faces-take-operator-intake.md)；管理台呈现是前端切片，一人在 main 上直接做。
7. **导入顺序。** 同一批历史先导收寄、再导集运；否则成员身份落成`缺少·无收寄记录`且不重判。写进 `template.md`「导入之后」。

## 完成判据（偏离标记半边）

- 加成员落册同一笔带方向依据记录。用例点名以下各格，均照常 `MEMBER_ADDED`：
  - 身份三种缺少
  - 已取消、已终局、两者并列
  - 路由依据未配置
  - 身份不成立时另两格未判
  - PS 读不动、收寄册读不动
- 真库用例：PS 读口在 SQL 层出错（`SELECT 1/0` 那一类）时，事实照落，服务结果记`读不动`。这证明读不在写事务里。
- 重投交回原记录；两份内容指纹的钉值不变。
- 迁移：
  - `consolidation_fact` 加记录列，只许加成员行带；旧行读出`未记录`。
  - 收寄册加按作业实物的表达式索引。
  - 号按与 `idp-parcel-9b` 的约定：谁先进 main 谁用 0005。
- 前线导入报告与「集运成员关系」查阅册照上面第 6 条。
- UC-NO-003「已经发生的错误分拣保留为事实」那一句由用例点名。`AT-NO-042` 的「阻止」半边随「裁定修订」第 1、4 条改属读面。

## 完成判据（原裁定，随「裁定修订」第 1、4 条改属读面）

下列判据写于原裁定，门禁那几句已随修订挪到读面，读面随作业端排；偏离标记半边以上一节为准。

- 实时加成员：身份未确认、已取消、已终局、路由依据未配置各自答`方向性作业受阻`并落册，缺少依据逐项列出；依据全部成立才 `MEMBER_ADDED`。
- 依赖读不动答`未决`，不落受阻记录。
- 前线过渡导入的成员行不过门，照常落。

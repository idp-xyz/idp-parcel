# 集运加成员不核任何方向性依据：已取消、已终局、无路由、身份未定的实物都装得进袋

Status: ready-for-agent——2026-10-16 分诊并裁四问（用户「你帮我做决定吧」授权 Claude Code 会话代决），见「裁定」；排在 [ps-external-mark-relations/01](../../ps-external-mark-relations/issues/01-external-mark-relations-have-no-model-in-parcel-shipment.md) 之后。此前 needs-triage——2026-10-16 Claude Code 会话立（票 [operator-channel/25](../../operator-channel/issues/25-node-reception-carries-parcel-shipment-service-result-markers.md) 实施中量到）
Blocked by: 无——机制半边不挡；生产效果挂在 ps-external-mark-relations/01（身份）与 [02](./02-network-routing-has-no-routing-instruction-or-consolidation-compatibility-judgment.md)（路由依据）上
出处：UC-NO-003 的业务规则「方向性作业必须取得当前有效路由指令；集运还必须取得成员级集运兼容判断」、输入表「包裹与服务」一行（`parcel-shipment` 的当前取消/终局结果）、`AT-NO-031` 与 `AT-NO-042`；NO CONTEXT「候选尚未确认时不得据此执行方向性作业」与「已取消、已经终局或当前无有效路由的包裹仍然到站时……」两条。

取证于 `0214a62a`（2026-10-16）。

## 事实

`internal/nodeoperations/application/consolidate_parcels.go` 的 `ConsolidateParcelsHandler.AddMember` 在幂等闸之后只问两件事：单元在不在（`Store.FindByID`），成员此刻是否已被别的单元直接包含（`Containment.CurrentParent`）。`ConsolidateParcelsDeps` 里没有路由指令、集运兼容、服务结果或身份的读口。于是：

- 收寄记录上带 `CANCELLED/…` 或 `FINAL/…` 标记的实物（票 25 落的），加进袋照常 `MEMBER_ADDED`——标记今天没有任何消费方。
- 没有当前有效路由指令的实物照常进袋（`AT-NO-031` 要求阻止集包）。
- 待识别或身份冲突的实物照常进袋（ps-port-remainder/05 的完成记录已记过「`AddMember` 不核成员是否已识别」，那一票只为阶段读面如实答`不可归属`，没有补门禁）。

票 25 的完成记录说「标记限制后续方向性作业」此刻只体现在记录与复核目录上，缺的就是这一半。

## 要裁的问题

1. **门禁放在哪一步。** 加成员、封装、交出各自核，还是只在加成员核（封装与交出继承成员已过门）。
2. **依据从哪里来。** 服务结果：读收寄记录上的标记（收寄那一刻的快照，之后 PS 新形成的取消读不到），还是加成员时再经票 25 的 `ParcelServiceResultView` 现问。路由指令与集运兼容：network-routing 今天有没有可消费的读口，没有时是本票阻断还是答`未决`。
3. **挡下来答什么。** UC-NO-003 结果契约里的「方向性作业受阻」（对象、拟执行动作、缺少依据、当前安全作业和续办入口），与现有 `ConsolidationNotAccepted` / `ConsolidationUndecided` 两格怎么对上；依赖读不动与「依据明确不成立」要分开。
4. **已取消或终局的实物要处置时怎么走。** `AT-NO-042`「方向性处置等待授权」：授权从哪来（PS 的收寄后服务处置决定？），本票接不接。

## 不做

- 不改「标记不阻止接收」（UC-NO-002）。
- 不在 NO 判断取消或终局是否成立——那是 PS 的事，NO 只消费结果。

## 裁定（2026-10-16，Claude Code 会话，用户授权代决；产品策略，不含租户取值）

1. **门禁放在实时渠道的加成员这一步。**
   - 实时扫描入袋是动作之前的请求：现场扫这一下，系统答受阻，件就不进袋。这正是 UC-NO-003「安全结束」那一格——无有效方向依据时只完成接收后安全作业，不执行下一跳动作。
   - 前线过渡导入（`cmd/parcel-frontline-import` 的集运模板，同走 `ConsolidateParcelsHandler.AddMember`）搬的是旧系统里已经发生的成员事实，**不过门**：UC-NO-003「已经发生的错误分拣保留为事实并形成偏离，不回写为未发生」。偏离判断归 NR 的路由偏离判断，本票不替它做。两个入口怎么区分由实施定，判据是导入行不被门挡、实时口必过门。
   - 开单元、移出成员、开封、封装、关闭不过门。移出与开封是安全动作，把件拿出来永远允许。封装与交出作用于入袋时已过门的成员；入袋之后 PS 新形成的结果走 PS「收寄后服务处置决定形成 → 各对象所有者分别承接」那条路（停止或释放请求），不靠封装时重查。
2. **依据从哪里来。**
   - **身份**：成员须有已成立的正式包裹关联。今天 NO 里正式包裹 → 作业实物的映射只有收寄判断里识别成功建立的版本化关联（ps-port-remainder/05 完成记录原话）。待识别、身份冲突、查不到关联的实物答受阻（CONTEXT「候选尚未确认时不得据此执行方向性作业」、身份冲突「暂停方向性作业」）。经权威运输交接取得控制的实物怎么带上关联，实施时核清；核不清的那一格答受阻，不放行。
   - **服务结果**：加成员当下经票 25 的 `ParcelServiceResultView` 现问，不读收寄记录上的标记。标记是收寄那一刻的快照，入袋要的是此刻的结果，收寄之后才形成的终局在标记上读不到。同一个端口、同一个防腐适配器，不另开第二个读口。有取消决定或当前终局即受阻（`AT-NO-042`「方向性处置等待授权」）。
   - **路由与集运兼容**：NR 今天没有路由指令与成员级集运兼容判断的模型，也没有按包裹答当前有效路由的读口（计划适用性按计划版本存取）。NO 开一个路由依据端口，生产装配显式未配置，答受阻、缺少依据「路由依据未配置」，续办指向 [02](./02-network-routing-has-no-routing-instruction-or-consolidation-compatibility-judgment.md)。**不跳过这一格**：跳过就是替 NR 默认「兼容」，红线「不写死为生产默认」禁的正是这个；也不在 NO 里自己比下一节点，那是 NR 的判断。
3. **挡下来答什么。** 新的一格`方向性作业受阻`（`DIRECTIONAL_WORK_BLOCKED`），与`未受理`（输入或不变量不成立）、`未决`（依赖读不动）分开——依赖读不动仍答`未决`，依据明确不成立才答`受阻`。按 UC-NO-003 结果契约落册：对象、拟执行动作（加成员与目标单元）、缺少依据（封闭词表，可多项并列）、当前允许的安全作业、续办入口。同一来源重投返回同一结果，幂等与现有集运事实同口。不形成成员关系。
4. **已取消或终局实物的处置授权不在本票。** 授权来自 PS 的收寄后服务处置决定（UC-PS-006），NO 承接它要 PS → NO 的处置交接，今天不存在，另立票。本票只做「等待授权」那一半：挡住。

## 完成判据

- 实时加成员：身份未确认、已取消、已终局、路由依据未配置各自答`方向性作业受阻`并落册，缺少依据逐项列出；依据全部成立才 `MEMBER_ADDED`。
- 依赖读不动答`未决`，不落受阻记录。
- 前线过渡导入的成员行不过门，照常落。
- 移出、开封、封装、关闭的行为不变。
- 生产装配：身份走 NO 收寄库，服务结果走票 25 的读口，路由依据显式未配置。
- `AT-NO-042` 的「阻止」半边有用例点名。`AT-NO-031`（无当前有效路由）在 02 落地前只证到「路由依据未配置即挡」，算不上整条，随 02 再点名。

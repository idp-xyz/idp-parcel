# 09 写 `UC-WF`：出库请求到出库确认

Category: docs
Status: ready-for-agent
Blocked by: 05；平台备货一节另等 declared-goods-lines/01 进 main（ADR-0374 把平台备货改为整份出库请求提交一份委托）

依据：[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md) 的「出库请求与发出」词条与规则、「出库请求」「装箱记录」两条生命周期；ADR-0370 决定一、二、五、六；ADR-0371 决定一至六；小包托运 CONTEXT 里来源「仓配出库」与代办的各条。

## 要做的

在 `docs/application/warehouse-fulfillment/` 下写用例。建议的切法，以写成的为准：

- 受理出库请求并预占：缺货处置、组合商品展开、拆单、运营按货主授权代录。
- 波次分配、拣货、出库复核与打包；预取面单的前提与逐波次选择。
- 代办仓配出库的委托：提交、补充、资料修订、撤回与包裹取消；消费小包托运交来的接受决定、包裹取消、资料版本与委托待受控补充各信封。
- 出库确认、放行条件与更正：本产品网络、自备面单、自提各一支；放行条件随包裹下发作业端。
- 出库截单：打包前按请求、打包后逐包裹。

要在本票写进用例的 ADR-0375 约束：

- 代办那一个用例里，仓配的每一路消费者对来源不是「仓配出库」的信封直接入账收工、不答未决，各有一条 `AT-WF-*`。
- 「委托待受控补充」对各来源照交；没启用仓配的部署里由派发登记的收工路接，来源不是「仓配出库」的入账，来源是「仓配出库」的显式失败；启用时由仓配的那一路接（ADR-0375 决定三、四）。收工路的实现差距写进 UC-PS-001「给开发的交接」里「委托待受控补充」那一行。资料版本已形成与包裹取消已记录的信封不归收工路管，启用时仓配的那一路是它们的第一个消费者。

票 07 写成之后留给本票的：

- 代录的答法要对齐。票 07 把商品、入库预报与收货差异结论的代录定成「运营决定」加货主授权的依据引用，不问 `party-commercial` 的授权裁定（`BD-WF-004`），操作者没有那一种决定的授予答未授予。入库一侧的写法已经进了 CONTEXT「主数据登记」：谁有权代录是租户取值、以授予表达，没有那一种代录的授予时照接入面的答法作答；货主是决定方，货主在自己的读口看得到哪一笔是代录的与它的依据引用。出库请求的代录，CONTEXT「出库请求与发出」写的还是「谁有权代录是租户取值，没登记答未配置」，票 07 没动出库各节。本票对齐时一并改那一句，要么在用例里写明为什么不同。
- 指名在册对象的代录，货主取自所指的对象、不从载荷收，带了即坏载荷（UC-WF-003 的代录撤回、UC-WF-004 的差异结论代录）；只有新建对象的代录才从载荷带货主客户账户。出库一侧的代录照这一分法写。
- 停用的仓照常受理出库请求；一个仓都没登记的租户各写口怎么答，照 CONTEXT「主数据登记」里各条。
- 答案的名字（查无所指的仓、仓不受理、未配置、来源冲突之类）沿用票 07 各用例的，不另起同义词。

同笔改：UC-PS-001、UC-PS-002、UC-PS-005、UC-PS-006、UC-PC-003 里「仓配切片立票时承接」的各行，与 UC-VE-002「给开发的交接」里仓配履约出库确认那一段，改指到写成的 `UC-WF-*`。

## 完成判据

同票 07「完成判据」。另加两条：

- 代办的请求方、授权与未配置的答法只引用小包托运 CONTEXT，不在 UC-WF 里另写一份。
- 平台备货一节在 ADR-0374 进 main 之前不写；进 main 之后照它写，票面记下所依据的 main SHA。

# 09 写 `UC-WF`：出库请求到出库确认

Category: docs
Status: in-progress（2026-11-18 认领，分支 `cursor/wf-outbound`，从 `cursor/wf-in-warehouse` 的 `7eb267c6f` 开出）
Blocked by: 05；平台备货一节另等 declared-goods-lines/01 进 main（ADR-0374 把平台备货改为整份出库请求提交一份委托）

依据：[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md) 的「出库请求与发出」词条与规则、「出库请求」「装箱记录」两条生命周期；ADR-0370 决定一、二、五、六；ADR-0371 决定一至六；小包托运 CONTEXT 里来源「仓配出库」与代办的各条。

## 要做的

在 `docs/application/warehouse-fulfillment/` 下写用例。建议的切法，以写成的为准：

- 受理出库请求并预占：缺货处置、组合商品展开、拆单、运营按货主授权代录。
- 波次分配、拣货、出库复核与打包；预取面单的前提与逐波次选择。
- 代办仓配出库的委托：提交、补充、资料修订、撤回与包裹取消；消费小包托运交来的接受决定、包裹取消、资料版本与委托待受控补充各信封。
- 出库确认、放行条件与更正：本产品网络、自备面单、自提各一支；放行条件随包裹下发作业端。
- 出库截单：打包前按请求、打包后逐包裹。

要在本票写进用例的 ADR-0375 约束：

- 代办那一个用例里，仓配的每一路消费者对来源不是「仓配出库」的信封直接入账收工、不答未决，各有一条 `AT-WF-*`。
- 「委托待受控补充」对各来源照交；没启用仓配的部署里由派发登记的收工路接，来源不是「仓配出库」的入账，来源是「仓配出库」的显式失败；启用时由仓配的那一路接（ADR-0375 决定三、四）。收工路的实现差距写进 UC-PS-001「给开发的交接」里「委托待受控补充」那一行。资料版本已形成与包裹取消已记录的信封不归收工路管，启用时仓配的那一路是它们的第一个消费者。

票 07 写成之后留给本票的：

- 代录的答法要对齐。票 07 把商品、入库预报与收货差异结论的代录定成「运营决定」加货主授权的依据引用，不问 `party-commercial` 的授权裁定（`BD-WF-004`），操作者没有那一种决定的授予答未授予。入库一侧的写法已经进了 CONTEXT「主数据登记」：谁有权代录是租户取值、以授予表达，没有那一种代录的授予时照接入面的答法作答；货主是决定方，货主在自己的读口看得到哪一笔是代录的与它的依据引用。出库请求的代录，CONTEXT「出库请求与发出」写的还是「谁有权代录是租户取值，没登记答未配置」，票 07 没动出库各节。本票对齐时一并改那一句，要么在用例里写明为什么不同。
- 指名在册对象的代录，货主取自所指的对象、不从载荷收，带了即坏载荷（UC-WF-003 的代录撤回、UC-WF-004 的差异结论代录）；只有新建对象的代录才从载荷带货主客户账户。出库一侧的代录照这一分法写。
- 停用的仓照常受理出库请求；一个仓都没登记的租户各写口怎么答，照 CONTEXT「主数据登记」里各条。
- 答案的名字（查无所指的仓、仓不受理、未配置、来源冲突之类）沿用票 07 各用例的，不另起同义词。

票 08 写成之后留给本票的（各格的现状写在所指用例的「给开发的交接」）：

- 待出库库区归本票。UC-WF-007 的口不收所指库位在待出库库区的行，UC-WF-008 的执行与开箱同样不收，UC-WF-010 的盘点不含待出库库区的库位，UC-WF-011 的库存调整不收那里的行。拣货移入、出库截单后的回库与拆包回库，出库复核时发现破损的货怎样转次品、原分配怎么办，那里的账实不符怎样发现与处理，都在本票写。
- 实拣与分配不符、出库复核不符形成库存差异的口在本票；批准与驳回已在 UC-WF-011：这两种差异经批准以调增、调减流水在差异所在的那一格入账（上架、移库这一类搬动与转换形成的差异是从源头补入账，不在此列），批准职责规则比的提交人取形成差异的那条作业事实的操作者。差异的样子照 UC-WF-007 的写法（记所在的格与差额，指名形成它的事实与那一行），不另起一种。
- 库内作业事实对不上账时的答法已进 CONTEXT「盘点、差异与调整」，被占着的数量取不取得走已进「占用、预占与分配」里「占用不被库内的入账挤占」那一条；那一条写明拣货与出库确认按分配消耗的是自己那份占用，「不在此列」。本票写拣货与出库确认时照它，不另写一份占用规则。
- 已拣出、移入待出库库区的货不可分配，而预占要到出库确认才消耗。这一段里「可分配库存都不得少于各项占用之和」怎样成立，CONTEXT 没有明写：已拣出的那部分预占还算不算在占用之和里。UC-WF-007 的 `AT-WF-091`、UC-WF-009 的 `AT-WF-130` 与 UC-WF-010 的 `AT-WF-145` 都靠这一条判；本票写分配与拣货时把它写明，要改规则就先改 CONTEXT。
- 分配还指着已经搬走的货，规则已在仓配履约 CONTEXT「盘点、差异与调整」：补入账的同一笔里分配改落到新格，未完成的拣货改到分配现在所在的格；冻结同样跟着货走，作业锁定不跟。同一源头上的同一数量，补入账、盘亏、调减与拣货差额只入账一份，先批准的那一份入账。本票写拣货事实的口时照这几句，不另写一套扣账。
- 「未完成的拣货任务」的判据。UC-WF-010 的 `AT-WF-145` 写所涉库位上还有未完成的拣货任务时盘点不能开始；拣货任务的生命周期在本票定。
- 预占与分配在读口上的内容。UC-WF-009 的读口答预占与分配属于哪份出库请求、多少、落到了哪些格；带批号、效期或贴标别名条件的预占在各部分上占了多少、可用量怎样带出，随本票定（UC-WF-009 的 `AT-WF-132`、`AT-WF-135`、`AT-WF-136`）。
- 出库确认判不成立之后的回补。CONTEXT「出库确认」词条写不成立的「库存经批准以调增流水回补」。判不成立的口、回补落在哪个库位、归哪个入库批次在本票写；批准走 UC-WF-011，它的库存调整今天不收待出库库区的行，本票定回补落在哪里时一并定要不要放开。
- 出库前的贴标。带贴标别名条件的预占从未贴标库存里取的那部分「在出库复核之前完成贴标」（CONTEXT「占用、预占与分配」）。UC-WF-008 的商品换标按指令作，指令由货主提交或运营发起；出库前这一次贴标走不走商品换标指令、由谁发起，本票写明。
- 答案的名字再加几个沿用的：作业事实整条不成立答「作业内容不合」，整笔相抵的入账取不走答「库存不可用」，批准时重判不成立答「内容已不成立」。

同笔改：UC-PS-001、UC-PS-002、UC-PS-005、UC-PS-006、UC-PC-003 里「仓配切片立票时承接」的各行，与 UC-VE-002「给开发的交接」里仓配履约出库确认那一段，改指到写成的 `UC-WF-*`。

## 裁决（2026-11-18 会话代决）

用户说「继续」。上一问的下一步是这张票，按这张票开工。下面各条用户没有逐条确认，可以推翻。用例还没写，先把必须先落在 CONTEXT 里的几句补上，避免用例另写一套。

1. **已拣出的预占。** 拣进待出库库区的数量离开可分配库存，它上面的预占不再计入占用之和；没拣出的仍算。回库回到可分配库区时重新计入。预占仍在出库确认时消耗。这样「可分配库存不得少于各项占用之和」在拣货之后仍然成立。
2. **代录与票 07 对齐。** 出库请求的代录以授予表达，没有授予答未授予，不再答未配置。新建的从载荷带货主，指名在册请求的不从载荷带。
3. **出库前贴标。** 不另立商品换标指令。仓内作业在出库复核之前贴上所点的别名，移数与指令执行相同。
4. **出库复核发现破损。** 这一件退出分配，转为次品并移入次品库区，预占释放。不走不收待出库库区的库内作业口。
5. **出库确认不成立的回补。** 更正版本经批准以调增流水回补，落在出库确认之前的待出库库位，入库批次取被消耗的那一个。不是库存调整的提交口，操作者仍不能把调整行指到待出库库区。
6. **平台备货。** 本分支的 CONTEXT 已经写着 ADR-0374 决定五的句子（整份提交一份委托、不预取、逐箱记箱标）。用例照这些句子引用，不另写一套。main 现行的 `docs/adr/` 里这份文件不在；本分支上还在。

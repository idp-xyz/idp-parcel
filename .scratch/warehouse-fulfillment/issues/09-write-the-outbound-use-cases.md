# 09 写 `UC-WF`：出库请求到出库确认

Category: docs
Status: ready-for-agent
Blocked by: 05；平台备货一节另等 declared-goods-lines/01 进 main（ADR-0374 把平台备货改为整份出库请求提交一份委托）

依据：[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md) 的「出库请求与发出」词条与规则、「出库请求」「装箱记录」两条生命周期；ADR-0370 决定一、二、五、六；ADR-0371 决定一至六；小包托运 CONTEXT 里来源「仓配出库」与代办的各条。

## 要做的

在 `docs/application/warehouse-fulfillment/` 下写用例。建议的切法，以写成的为准：

- 受理出库请求并预占：缺货处置、组合商品展开、拆单、运营按货主授权代录。
- 波次分配、拣货、出库复核与打包；预取面单的前提与逐波次选择。
- 代办仓配出库的委托：提交、补充、资料修订、撤回与包裹取消；消费小包托运交来的接受决定、包裹取消、资料版本与委托待受控补充各信封。
- 出库确认、放行条件与更正：本产品网络、自备面单、自提各一支；放行条件随包裹下发作业端。
- 出库截单：打包前按请求、打包后逐包裹。

要在本票写进用例的 ADR-0375 约束：

- 代办那一个用例里，仓配的每一路消费者对来源不是「仓配出库」的信封直接入账收工、不答未决，各有一条 `AT-WF-*`。
- 「委托待受控补充」与资料版本已形成两类信封在仓配缺席时不落到无订阅者：做法二选一（ADR-0375 决定三），在本票与 PS owner 一起定，实现差距写进 UC-PS-001、UC-PS-002「给开发的交接」。

同笔改：UC-PS-001、UC-PS-002、UC-PS-005、UC-PS-006、UC-PC-003、UC-VE-002 里「仓配切片立票时承接」的各行，改指到写成的 `UC-WF-*`。

## 完成判据

同票 07「完成判据」。另加两条：

- 代办的请求方、授权与未配置的答法只引用小包托运 CONTEXT，不在 UC-WF 里另写一份。
- 平台备货一节在 ADR-0374 进 main 之前不写；进 main 之后照它写，票面记下所依据的 main SHA。

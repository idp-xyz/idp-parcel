# 07 写 `UC-WF`：主数据与入库

Category: docs
Status: in-progress（2026-11-12 认领，分支 `cursor/wf-inbound`，工作树 `idp-parcel-wf-inbound`）
Blocked by: 05

依据：ADR-0368 决定八「先写 `CONTEXT.md` 与 UC」；[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md) 的「货主、仓与商品」「入库与库内」词条、「入库与加工」规则与「入库预报」「收货与上架」两条生命周期；票 01 写明「不写 UC，UC 随实施切片写」。

## 要做的

在 `docs/application/warehouse-fulfillment/` 下写用例，照 [application/README](../../../docs/application/README.md)「编写约定」。建议的切法，以写成的为准：

- 维护仓配主数据：仓、库区与库位、包材；货主商品、商品别名、包装层级、组合商品的组成版本、商品申报资料；仓测尺寸重量。
- 受理入库预报、收货与上架：商品入库与整箱入库、收货差异、分次收货与完结、货主撤回预报。
- 待认领到货的登记与认领。
- 建账导入。

CONTEXT 没写、要在本票定下的：

- 货主商品由谁、经哪个面维护（货主经客户渠道，运营代录，还是两者）。
- 入库预报、撤回预报与确认收货差异各走哪个接入面，要哪项授予。
- 入库作业收费发生项的形成不在本票写，归票 10；本票的用例只写明收货确认这一作业事实，票 10 写成后回填指针。

同笔改：应用用例索引加行；CONTEXT 若缺词或缺规则，先改 CONTEXT 再写 UC。

## 完成判据

- 每个用例写明业务决定所有者、输入与结果语义、业务拒绝与未决与技术失败的区分、幂等与并发、`AT-WF-*` 验收场景。
- 规则只引用 CONTEXT 与 ADR，不复制；未确认的业务选择登 `BD-WF-*`，按机制、产品策略、租户取值归类，租户取值留空答未配置。
- 每个用例带「给开发的交接」；ADR-0375 决定一的判据（部署没启用仓配时其他上下文的答复与信封不变）与决定五的未配置（仓、库位等没登记时答未配置）在相关用例里各有一条 `AT-WF-*`。
- 只改 `.md`；进 main 前一份非作者评审；AT 盘点计数由推送方重算。

## 裁决（2026-11-12 会话代决）

取证于 main `31d1cd16b`。下面各条都是会话自问自答定的，用户没有逐条确认，可以推翻；写成的规则在[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md)与 `UC-WF-001` 至 `UC-WF-006`，本票没有新立 ADR。参照的是领星 WMS、OMS 与 OMP 的公开帮助文档，摘的要点与出处在本节末「参照的出处」；与它不同的地方逐条写明。评审之后改过的地方在各条里写明首稿是什么、为什么改，经过见「评审记录」。

1. **切成 `UC-WF-001` 至 `UC-WF-006`，上架与建账导入的批准移到票 08。** 票面建议的「受理入库预报、收货与上架」拆开写：预报是货主的决定，收货是仓的作业事实，接入面、重放身份与失败边界都不同。上架照 CONTEXT「上架」词条是库内移动，与移库、补货同一种流水，归票 08。建账导入照 CONTEXT 是一种库存调整，批准与驳回的口和别的库存调整同归票 08；UC-WF-006 只写提交，以及批准成立之后怎样入账。待认领到货的处置规则没有另立用例，登记写在 UC-WF-005 里。
2. **接入面逐口归类（票面要在本票定的两格）。**
   - 仓、库区、库位、库位类型、包材，与待认领到货的处置规则：登记册配置写，在线口与受控批量口消费同一登记用例（ADR-0085 决定一）；查阅走主数据与运营查阅读。登记不判准入范围（ADR-0100 决定四）。
   - 商品：货主经首方客户渠道维护，或运营代录，两条途径写同一条修订序列。领星是客户在 OMS 建产品、仓库可以代卖家导入，两边都有。
   - 入库预报的提交、告知更新与撤回、收货差异的结论：货主经首方客户渠道，或运营代录。领星的入库单由客户在 OMS 创建，帮助文档里没有见到仓库端代客建入库单；代录是会话加的：CONTEXT 已经让出库请求可以「由运营按货主授权录入」，没有系统对接的小货主，入库同样要有人替他录。
   - 代录一律走「运营决定」，一种代录一种授予，都带货主授权的依据引用（必带，逐字保存，不判真伪）。新建对象的代录（商品、预报的代录提交）从载荷带货主客户账户，向 `party-commercial` 只核在不在本租户；指名在册对象的代录（预报的告知更新与撤回、差异的结论）货主取自所指的对象，不从载荷收，带了即坏载荷。首稿让每一种代录都带货主客户账户；评审里代接入身份 owner 看的条件是，代录撤回与差异结论代录的货主从被指名的对象查出、不从载荷收（ADR-0151 决定二对委托侧各口的同一立场），只有新建对象的代录才把它当业务内容。修订照办，把能从在册对象取的都改成取自对象。只能由载荷指名的几口（商品代录、预报代录提交、建账导入、待认领到货的认领）评审没有异议，是作者另加的一问：它们照 ADR-0151 决定二怎样读，在各用例的交接里留给票 11 的 ADR 写明。
   - 代录记的是货主的决定：货主是决定方，操作者只是录入人；货主在自己的读口看得到哪一笔是代录的与它的依据引用，看不到录入的操作者。不问 `party-commercial` 的授权裁定，登 `BD-WF-004`；谁有权代录是租户取值、以授予表达，操作者没有那一种代录的授予时照接入面的答法作答。
   - 收货确认、仓测登记、待认领到货登记：作业事实登记，授予按（租户，作业范围），作业范围要一个新种类「仓」。`internal/accessidentity` 的作业范围种类今天是一个封闭集（`WorkScopeKind`），里面没有仓，一台设备只登记在一个作业范围上；同址的节点与仓怎么兼两边留给票 11。CONTEXT「作业端」原来只列收货（含按箱收货），本票把仓测尺寸重量与待认领到货的登记补进那一条：它们都是收货现场的动作。
   - 入库预报完结、待认领到货的认领与撤销、处置、建账导入提交：运营决定，各一种授予。
   - 用例里的客户面能力、运营决定种类、作业范围种类与作业事实类型都是暂名，定名与粒度归票 11。
3. **一个仓都没登记的租户各口怎么答：ADR-0375 决定五挂了一条读法注。** 决定五写「一个仓都没登记的租户，仓配各写口答未配置或查无所指的仓，各读口答空，不建默认仓。」哪个口答哪一种它没分；照字面，连登记仓的口也在「各写口」里，那样一个仓都没有的租户永远登记不了头一个仓。写进 CONTEXT「主数据登记」的读法：只有登记仓的那一口照常受理，那是从没登记走到登记的路，不以已有仓为前提；其余写口，指名了仓的答查无所指的仓，没指名仓的答未配置；读口答空。库位类型与包材的登记因此答未配置，库区与库位的登记答未受理（查无所指）；商品的两个写口答未配置：一个仓都没有的租户还没在用仓配，不先攒下货主的商品。首稿让由运营登记的各册都照常登记（库位类型与包材因此在没有仓时也能登记），并把它当成不必挂指针的读法；评审判这比决定五的字面宽，又没有任何东西指回 ADR-0375（阻断）。修订收窄到只剩登记仓一口，并照 [adr/README](../../../docs/adr/README.md) 的指针写法与索引里既有读法注的先例，在 ADR-0375 的 `Status` 行索引注记与 Links 各加一条前向指针；正文没动，无条款停用。README 正文没有给「读法注」立一种专门的写法，它是索引里已有的做法。CONTEXT「主数据登记」那一条在第二轮评审之后补了指回 ADR-0375 决定五的一句。
4. **主数据（UC-WF-001）。**
   - 各册只追加修订，修订号连续，新修订自登记那一刻生效。
   - 登记后不改的格：仓编码与自营仓、代理仓之分，库区的用途，库位的所属库区。领星的仓库代码、库区编码与库位编码创建后同样不可改。与它不同的地方：领星的帮助页写「仓库类型」在没有进行中的出入库单据时可以编辑修改；同一页的名词解释把自营仓、代理仓叫「仓库性质」，没有写明「仓库类型」指的是不是这一分，会话照它是来比。这里自营仓、代理仓之分登记后不改，自营仓有库存账而代理仓只收库存声明，换了等于换一套账。领星没有库存的库区可以删除，这里各册只追加修订、不删，不用的停用。
   - 停用可以再启用，只挡此后新受理的请求与新下发的选择，不要求库存为零；停用的仓照常受理出库请求，好把在库的货发完。领星停用仓库要库存为零、停用之后不可再启用；这里没照搬：要求先清空库存，就得先有别的办法挡住新入库，停用正是那个办法。
   - 库位类型取自租户登记的库位类型表，可以不带，产品不内置；优先级数字越大越优先，与领星同。
   - 仓指名同址物流节点只是指名，登记时不向 `network-routing` 核对（`BD-WF-001`）。业务时区不给就是没登记，不取租户、部署或地址所在国的默认。包材按租户登记、各仓共用。
5. **商品（UC-WF-002）。**
   - 一份修订是一份完整资料，带基准修订；基准已不是当前修订的不成立。
   - 登记后不改：商品编码、基本单位、是否组合商品；包装层级不删、折合数不改、可以追加；是否跟踪批号与效期只在没有在库库存时可改。领星的 SKU 创建后不可改。
   - 同一货主内商品编码与各别名同在一个识别空间，一个码同一时刻至多指向一个商品；按码识别取事实发生那一刻的指向。领星要求 SKU、产品条码、其他条码与 FNSKU 互不重复。别名类型封闭成商品条码与平台商品码，平台或渠道名逐字保存，产品不内置平台词表。
   - 组合商品的组件须是非组合商品（`BD-WF-005`），组成版本就是声明它的那个商品修订。
   - 不设停用与废弃（`BD-WF-002`；领星的废弃要无在途单据且库存为零），不设仓对商品的审核（`BD-WF-003`；领星是客户建产品提交仓库审核，可以按客户免审）。
   - 仓测是作业事实：按（商品，包装层级）或按在库的一箱，只追加版本，当前那一版按发生次序取、不按到达先后；照测得的单位保存，不折算。领星是新品首次入仓测量，计费以 WMS 的尺寸重量为准。
6. **入库预报（UC-WF-003）。**
   - 明细按商品编码指名，计量单位须是该商品声明的包装层级。
   - 受理之后仓、到仓方式、入库方式与明细不改，要改就在第一次收货确认之前撤回重交（`BD-WF-006`）。预计到仓时间、到货线索（柜号、跟踪号之类）与货主参考号只作告知，预报还可收货（已预报或收货中）时可以更新：整组替换，每次更新留一版，不改明细、状态与单据号；货主经首方客户渠道更新，运营可以代录。领星的 OMS 在入库单提交到待入库之后「还可编辑修改到仓方式、预计到达日期、货柜号/跟踪号、参考单号、备注、自定义箱条码（可批量填充），若是收货中及以后的状态，不支持修改」；WMS 一侧待入库还能改仓库（只在自营仓之间改），收货中还能改到仓方式、预计到达日期、货柜号/跟踪号与备注。这里与它不同的地方：仓不开，换仓是撤回重交（`BD-WF-006`）；到仓方式不开（CONTEXT「作业属性」把它列作价卡判条件要用的发生项属性，实际到仓的方式与声明不同时取哪一个留给票 10）；箱号不开，领星的自定义箱条码待入库时可改，这里箱号属明细，要改同样撤回重交——箱号只须在一份预报内不重复，与在库的重复到收货时才判，重交时可以照原样再给；备注这里没有对应的一格；告知各格在收货中仍可由货主更新，领星的 OMS 一侧收货中及以后不支持修改（分批到货时，后一批的柜号与到仓时间常在第一批收货之后才有）。首稿一格都不开；评审里代仓配履约 owner 与代产品 owner 看的意见都是有条件认可：撤回重交会换单据号，收货一开始连撤回也没有，现场要是靠单据号贴箱就对不上，除非放开只作告知的那几格；领星在待入库与收货中也都还能改。修订开了告知这三格。
   - 不设仓对预报的审核（`BD-WF-007`；领星可选仓库审核），不限定货主可用的仓（`BD-WF-008`；领星是客户绑定可用仓库）。
   - 到仓方式封闭成整柜、托盘、散箱；入库方式分商品入库与整箱入库。
   - 指名的仓没登记答查无所指的仓，停用或代理仓答仓不受理，都不改投别的仓。
   - 单据号在受理的同一笔事务里取；日期按仓的业务时区，仓的业务时区没登记的按租户的单据编号时区，都没有则照常受理、不带号、记下无号原因（ADR-0355 决定七）。类型代码与默认模板没定，留给 PN-09 开发交接。
   - 撤回只在第一次收货确认之前，与领星待入库状态「取消入库单（需在仓库收货前）」同；撤回与收货谁先，按到达本上下文的先后。
7. **收货（UC-WF-004）。**
   - 收货确认即入账，不等上架。领星是收货不生成库存、上架才生成；这一格票 01 已经裁过，本票没动。
   - 整条不成立与行级未入账分开：行的形态与入库方式不符、库位不在收货暂存库区、认得出的商品的计量单位或批号效期不成立，整条不落、不占事实身份；认不出的货与对不上预报的箱，只那一行不入账、记错货，其余的行照常入账。
   - 认得出是该货主已登记商品、只是预报没列的，照实收入账并记错货：货已经在仓里，认得出就记在账上。
   - 多收按到达先后累计、折成基本单位比，不设上限（`BD-WF-009`）；领星同样支持超收少收。少收在完结时才算。破损是收货时记为次品的数量与外箱破损的箱，待检不成差异。
   - 跟踪批号或效期的商品收货时必带；贴标别名须是该商品在事实发生那一刻有效的平台商品码别名，与按码识别取同一个时刻。首稿写的是「此刻有效」，评审指出没说是哪一刻。
   - 一份预报里一箱只收一次，与领星「一个箱子仅支持收货一次」同；货主的箱号与在库的重复、又没带仓另编的箱号，那一箱不入账，也不形成差异。它留在那条事实的逐行结果里，货主在逐次收货的读口看得到它与原因；预报受理之后箱号不改，补正在系统外商定，落到系统里是仓带上另编的箱号再收这一箱。
   - 第一条被受理的收货事实就让预报进入收货中，哪怕各行都没入账。
   - 识别码与贴标别名按事实发生那一刻的指向与有效区间解析；计量单位是不是已声明的层级、跟不跟踪批号效期，按入账那一刻的当前修订判。离线记下的收货因此可能在到达时整条答收货内容不合；设备怎样呈现与补录留给票 11。
   - 同一事实身份、内容相同的重复到达答已有结果；同一身份、内容不同的答内容冲突，在册的不变。内容按那个口的规范化形状比（ADR-0149 决定四的载荷规范化摘要）；仓测与待认领到货的登记同此。首稿写的是同一身份「不比内容」，评审指出这与 ADR-0149 决定四不合。
   - 收货事实到达时预报已取消或已完结的，原样保全为待认领到货，不入账；谁先谁后按到达本上下文的先后，不按设备的发生时间，因为撤回或完结的答复在迟到的事实到达之前已经交出。已经引用着一件待认领到货的不另建。
   - 入库时间取入账那一刻，离线迟到的收货库龄因此从入账那天起算；票 10 写仓租时核一遍。
   - 已入账的收货不改不删，收错了走库存差异与库存调整（票 08）。领星到仓扫描页的常见问题写收货时填错数量「先正常上架，再到WMS库内-产品库存-按库位查询，操作库存调整」，同一条路。
8. **完结。** 显式的运营决定，只对收货中的预报，不可逆，不自动发生，不要货主先在系统里同意（`BD-WF-011`）。领星叫「强制完结」，与卖家协商之后由仓操作，之后不可再收货。
9. **收货差异。** 按形成它的那一次收货确认、完结或开箱成份，一份至多一个现行的结论（确认或异议）；结论不改账，有异议而要改账的走库存差异与库存调整；不设超期视同确认（`BD-WF-010`）。代录的结论只在这份差异还没有结论时成立；货主本人之后经客户渠道作出的结论取代它，不论相同还是不同，被取代的照留；货主本人作出的结论不再改，代录不取代任何已有的结论。首稿是一份一个结论、谁先到算谁的；评审里代产品 owner 看的意见不认可差异结论的代录：差异的对方就是仓，替货主记「确认」的是仓这一方的操作者，只凭一条不判真伪的依据引用，而首稿让货主本人此后改不了口；它给的两条路是这一种代录另凭 `party-commercial` 的授权，或者让货主本人的结论可以取代代录的那一个。修订取后一条，没有拿掉代录（没有系统对接的小货主仍要有人替他录），改成货主本人的结论压过代录的，并让货主在读口看得到哪个结论是代录的与它的依据引用。这一条可以推翻成「差异结论不许代录」；第二轮评审里代产品 owner 看的条件之一，就是要用户本人确认保留这一种代录（见「评审记录」），这一问随本票的收口报告交给用户。
10. **待认领到货（UC-WF-005）。**
    - 只在自营仓登记，停用的仓照记；到货种类分入库到货与退件；观察与线索逐字保存，线索不是认定。
    - 认领由运营作出：入库到货的认领必须指名该货主在这个仓一份可收货的预报，之后经收货确认入账；退件的只指名货主，之后按退货入库入账。领星的认领是客户在 OMS 自己认领（认领即创建退件单），未指定客户的认领单对所有客户可见、跟踪号后 4 位隐藏；这里首版不上客户面（`BD-WF-012`），公开会把一个货主的到货线索露给别的货主。
    - 认领与撤销按调用方给的决定标识认重放，因为一件到货可以先后认领、撤销、再认领；撤销只在还没有入账引用它时成立；认领之后预报被撤回或完结的，认领不自动失效。
    - 处置规则按（租户，仓）登记、只追加修订：认领期限加期满后可用的处置方式。期限自到货发生那一刻起按经过的时间算，不按业务日，所以不依赖仓的业务时区；处置方式是租户自己的词，产品不内置。没登记答未配置，到货留在待认领。领星的认领单带失效日期、到期进已过期，仓库可以取消。
    - 处置只记决定，不改库存账，也不形成收费发生项；不设更正到货观察的口（`BD-WF-013`）。
11. **建账导入（UC-WF-006）。**
    - 提交是运营决定，带调用方给的导入标识与原因；一份对一个货主、一个自营仓。
    - 按商品编码指名，不收别名；整份成立或整份不成立；各行直接落到指名的库位，守库区相容，整箱行只落收货暂存、存储与待出库库区。
    - 声明的入库时间不晚于提交那一刻，没声明的取入账那一刻；声明不同的各成一个入库批次。领星的库存初始化导入可以指定上架日期。
    - 批准时照当下的册重判各行，有行已不成立的整份不入账、留在待批准；仓在提交之后被停用不在重判之列。已驳回的不因重投复活。
    - 导入单不上客户面（`BD-WF-014`）。
12. **重放身份。** 撤回、完结、差异结论与处置的重放身份取被指名的对象：一份预报只取消一次、只完结一次，一份差异至多一个现行的结论，一件到货只处置一次。告知更新按来源请求键认重放，代录的按决定标识认，每个被受理的更新落成一版。货主口的来源请求键随成立的取消或结论落册，已落册的键又来指名另一份的答来源冲突；各命令的前缀照 ADR-0310 决定一另取，归票 11。作业事实（收货确认、仓测、待认领到货登记）按设备签发的事实身份认重放，内容相同答已有结果，内容不同答内容冲突。
13. **入库作业收费发生项不在本票写。** UC-WF-004 只把收货确认写成作业事实，并在收货行上留了实点箱数作计量来源；发生项的形成、计量与作业属性归票 10，写成之后回填指针。
14. **CONTEXT 同笔补的。**
    - Language：「仓」写明由租户登记与它的身份；「库位」写明库位类型取自租户登记的表、可以不带、优先级数字越大越优先；「商品」补按包装层级声明尺寸与重量；「商品别名」的类型封闭成商品条码与平台商品码；「组合商品」写明组件须是非组合商品；「包装层级」写明基本单位；「入库批次」补建账导入里声明的入库时间不同的各成一个；「入库预报」补代录、到仓方式的封闭集与明细里的计量单位；「待认领到货」补对上的预报已不能收货的货。
    - Rules：新增「主数据登记」一节；「身份与边界」里待认领到货那一条；「入库与加工」补预报的校验与受理后不改、收货确认只对可收货的预报、批号效期与错货、收货差异的成份与类型、待认领到货的认领与处置、建账导入各条；「作业端」那一条。
    - Lifecycles：新增「仓、库区、库位、库位类型与包材」「收货差异」「待认领到货」「建账导入」；改「入库预报」；「收货与上架」里待认领到货那一条移进它自己的生命周期。
    - Boundaries：所有权那一条补库位类型表与待认领到货的处置规则。`Status` 行补一句，指到本票。
    - 评审之后另改：「商品别名」词条补平台或渠道名逐字保存、产品不内置平台词表；「入库预报」词条、「入库与加工」与「入库预报」生命周期写明哪几格受理之后不改、哪几格只作告知而可以更新并留版；「主数据登记」里没登记仓的那一条收窄到只有登记仓一口照常受理，代录那一条补决定方、没有授予时的答法、依据引用与货主读得到代录标记；「入库与加工」与「收货差异」生命周期补货主本人的结论取代代录的；Boundaries 里没登记仓各口怎么答的那半句改成指到「主数据登记」。「出库请求与发出」里代录的那一句没动，留给票 09。

# 08 写 `UC-WF`：库内作业、冻结、盘点与差异

Category: docs
Status: in-progress（2026-11-12 认领，分支 `cursor/wf-in-warehouse`，工作树 `idp-parcel-wf-in-warehouse`）
Blocked by: 05

依据：[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md) 的「库存账」「占用与可用量」「盘点、差异与调整」词条，「库存账与守恒」「占用、预占与分配」「盘点、差异与调整」规则，与「加工」「盘点」「库存差异」「冻结」生命周期。

## 要做的

在 `docs/application/warehouse-fulfillment/` 下写用例。建议的切法，以写成的为准：

- 库内移动与形态变化：移库、拣选位补货、形态转换、加工与拆解、商品换标、开箱。
- 冻结与解冻。
- 盘点：创建、开始（加作业锁定）、录入、完成或作废。
- 库存差异与库存调整：批准、驳回，调增调减与销毁。

CONTEXT 没写、要在本票定下的：

- 各动作是作业事实（一线作业端提交、照记）还是运营决定（要授予），逐个归类；谁批准差异与调整已写明是租户取值。
- 加工指令与商品换标指令由货主提交时走哪个接入面。
- 离线回传与库存账冲突时各动作的答法（CONTEXT 写了离线拣货的答法，其余动作没写）。

票 07 写成之后留给本票的（各格的现状写在所指用例的「给开发的交接」）：

- 上架（收货暂存、退货暂存到存储、拣选或次品库位）与待检转良品或次品的状态转换：票 07 把上架移到了这里，UC-WF-004 只写到收货入账。
- 建账导入的批准与驳回口：谁有权批准、批准权限没登记时答未配置、提交人与批准人的关系，连同验收场景。批准成立之后怎样入账已在 UC-WF-006 写定（已入账、内容已不成立、已驳回；仓在提交之后被停用不挡批准），本票与 CONTEXT「建账导入」生命周期对齐，不另写一份入账规则。
- 收错了的收货，与货主对收货差异提了异议之后要改账的，都走库存差异与库存调整；UC-WF-004 只记结论，不改账。
- 开箱时实点与箱单的差额成一份收货差异，结论照 UC-WF-004 的差异结论口作，不另开口。
- 一个仓都没登记的租户各写口怎么答，照 CONTEXT「主数据登记」里那一条；答案的名字（查无所指的仓、仓不受理、未配置）沿用票 07 各用例的，不另起同义词。
- 移入的作业事实：UC-WF-001 的 `AT-WF-008` 断言库位或库区停用之后「迟到的移入事实照记」，要等上架、移库这些移入的口写成才有口可验；本票写这些口时接住它。
- 作业事实各口的同身份重放与内容冲突照 UC-WF-004 的写法：按设备签发的事实身份认重放，内容按那个口的规范化形状比，相同答已有结果，不同答内容冲突（ADR-0149 决定四）。本票的作业事实各口同此，不另起一种答法。
- 收货差异上代录的「已确认」不是不会回退的终态：货主本人此后经客户渠道作出的结论取代它，可以改成有异议，没有期限（UC-WF-004「一致性、幂等与并发」）。本票凡拿收货差异的结论作前提或依据的口，写明代录的「已确认」之后货主本人改成有异议时怎么办（票 07 第二轮评审代仓配履约 owner 看的条件）。

## 完成判据

同票 07「完成判据」。另加一条：守恒式与占用规则只引用 CONTEXT 的原句，不在 UC 里另写一份算式。

## 裁决（2026-11-12 会话代决）

取证于 main `4f661fcd2`；首稿提交之后 main 又前进了，并入的经过与并后重验的结果见「与在途分支的交叠」与「完成记录」。下面各条都是会话自问自答定的，用户没有逐条确认，可以推翻；写成的规则在[仓配履约 CONTEXT](../../../docs/domain/warehouse-fulfillment/CONTEXT.md)与 `UC-WF-007` 至 `UC-WF-011`，本票没有新立 ADR。参照的是领星 WMS、OMS 与 OMP 的公开帮助文档，摘的要点与出处在本节末「参照的出处」；与它不同的地方逐条写明。

1. **切成 `UC-WF-007` 至 `UC-WF-011`。** 票面建议的「库内移动与形态变化」拆成两份：上架、移库、拣选位补货、形态转换、状态转换与短少登记在 UC-WF-007；加工、拆解、商品换标与开箱在 UC-WF-008。拆开的理由是对不上账时两边的答法相反（第 3 条），加工与商品换标另带指令和它的生命周期。冻结与解冻在 UC-WF-009，库存、占用与流水的读口也放在这一份：可用量要连着各项占用一起答，UC-WF-006 的 `AT-WF-079` 等的也是这个读口。盘点在 UC-WF-010。库存差异、库存调整、建账导入的批准与驳回、批准职责规则在 UC-WF-011。
2. **各动作归类，与货主提交指令走哪个面（票面要在本票定的两格）。** 分法：现场已经发生的搬动与观察是作业事实，照记；不经实物就改账的、让一批货重新可卖的、定下仓要替货主做什么的，是决定，要授予。
   - 作业事实登记（设备签发事实身份，授予按（租户，作业范围），作业范围种类「仓」）：库内移动（上架、移库、拣选位补货），形态转换，状态转换里的待检转良品、待检转次品与暂存库区里的良品转次品，短少登记，加工与拆解的执行，商品换标的执行，开箱，盘点的清点结果。
   - 运营决定（各一种授予）：次品转良品；发起与作废加工指令；发起与作废商品换标指令；冻结与解冻；盘点的创建、开始、完成与作废；库存调整的提交；库存差异、库存调整与建账导入的批准与驳回。
   - 首方客户渠道：货主提交与撤回加工指令、商品换标指令，按客户面能力授予，与入库预报是同一个面；货主读自己的指令、开箱记录、库存、占用与流水。
   - 登记册配置写：批准职责规则。
   - 领星的移库、库存调整与正次转换都是 WMS 页面或 PDA 上的操作，帮助页没有分事实与决定。
   - 用例里的客户面能力、运营决定种类与作业事实类型都是暂名，定名与粒度归票 11。
3. **事实与库存账对不上时各动作怎么答（票面要在本票定的一格）。** 写进了 CONTEXT「盘点、差异与调整」，是把那里原有的离线拣货的答法推到库内各动作上。
   - 搬动与转换（上架、移库、拣选位补货、形态转换、状态转换）照记，写口不拒：所报的数量在账上够而且没被占着的部分入账，其余的差额成一份库存差异，记在移入或转成的那一格，交人处理。整箱不拆：箱被占着的不入账，一箱成一份库存差异。
   - 整笔相抵的（加工、拆解、商品换标、开箱）不入一半：所指的投入或那一箱在账上不够或被占着时整笔不入账，答「库存不可用」，不占事实身份，指令留在原状态，账理顺之后原样重交。按组成相抵的一笔流水只入一部分就不守恒，所以这一类没有「入得进的先入」。
   - 取得走多少按入账那一刻的账判，按到达本上下文的先后串行，不按设备的发生时间。
   - 整条不成立的（库位在这个仓查不到、商品没登记、计量单位不是声明的包装层级之类）答「作业内容不合」，不落册、不占事实身份；与 UC-WF-004 的「收货内容不合」是同一种分法。
   - 运营决定在线判，整份成立或整份不成立。
   - 领星 PDA 的移库是在线校验，移库数量「不可超过可用库存」。这里的作业端容忍离线（ADR-0021），事实到达时货已经搬了，拒掉它账与实物只会差得更远，所以照记、差额交人。
4. **占用不被库内的入账挤占（CONTEXT「占用、预占与分配」新增一条）。** CONTEXT 原来只写了冻结与作业锁定成立时不得挤占预占，没有写库内的入账从一格取走数量时怎么办。新增的那一条：只取这一格没被分配、冻结或作业锁定占着的部分，取走之后受影响的每个汇总上可分配库存仍不得少于各项占用之和；拣货与出库确认按分配消耗的是自己那份占用，不在此列。它同时管把货移出可分配库存的移动、移入次品库区、加工与商品换标的投入、盘亏、调减与销毁；各用例只引用这一条，没有另写判法。领星的库存调整与移库都只动可用库存，是同一个意思。
   - 留下的一处：已拣出、移入待出库库区的货不可分配，而预占到出库确认才消耗；这一段里那条不等式怎样成立，CONTEXT 原文没有明写。本票没有替出库定，转票 09。
5. **上架、移库、补货与状态转换（UC-WF-007）。**
   - 上架是从收货暂存或退货暂存库区移到存储、拣选或次品库位的库内移动，可以分次，余下的留在暂存库区、可见但不可分配。没有上架单，也没有「上架完成」一步（`BD-WF-015`）。领星每收货一次生成一个上架单，上架单内的产品必须全部上架，上架才生成库存；这里收货确认即入账（票 01 裁过），上架只是搬动。
   - 拣选位补货是同一条行里带形态转换的库内移动，两头折成基本单位相等。不下发补货任务，也不推荐库位（`BD-WF-015`）；领星的存拣分离有缺货看板，推荐移出的库位与目标库位。
   - 入库批次随货走，库龄不变。
   - 移入的库区须与库存状态相容，移入次品库区的在同一笔流水里转为次品；领星同（「移动到次品区的产品会被转化为次品」）。
   - 待检转良品或次品、暂存库区里的良品转次品，由仓内作业记状态转换，只在收货暂存与退货暂存库区。次品转回良品是运营决定、带原因，同样只在这两种暂存库区；次品库区里的先移到暂存库区（`BD-WF-016`）。良品转待检不设（`BD-WF-017`）。领星是移库移到正品区即转为正品；这里次品回到可卖的库存要一个有授予的人作决定，CONTEXT 原来就这样写，本票补的是它只在暂存库区。
   - 库内发现破损的货不成库存差异，由仓内作业转为次品。CONTEXT「库存差异」词条原来把上架时发现的破损也列作差异；货还在、数量没变，只是状态变了，账记得出来，差异留给数量对不上的。
   - 短少登记：作业人员发现一格少了货，记一条观察，各成一份库存差异，不动账；比余额多的照记，批不批得了到批准时再判。
   - 停用的库位与仓照记移入的事实，不比发生时间与停用谁先。UC-WF-001 的 `AT-WF-008`「迟到的移入事实照记」由 `AT-WF-094` 接住。
   - 行里所指库位在待出库库区的整条不成立：那里的进出归票 09。
6. **加工与商品换标按指令作（UC-WF-008）。**
   - 指令由货主经客户渠道提交，或由运营决定发起；运营发起的原因必带，货主授权的依据引用可带（`BD-WF-021`）。加工指令固定仓、组合商品、组成版本与数量，组成版本没点名的取受理那一刻的当前修订；商品换标指令固定仓、商品、数量、现贴的别名与要换成的别名，贴上、换成与去掉都收（CONTEXT「商品换标」词条补了去标）。
   - 受理时不核库存，也不占用（`BD-WF-018`）。领星的工单「待客户提交工单，相关SKU的库存将即刻被锁定」，换标单关联的库存也算锁定库存。这里没有照搬：占用是 ADR-0368 决定五的封闭集，指令不在其中；代价是组件可能在执行之前被出库请求预占走，执行时答库存不可用。
   - 不设仓对指令的审核。领星的工单走待审核、已审核、处理完成，审核可以拒绝；这里受理即待加工或待换标，仓不做的由运营作废并带原因，货主在读口看得到是仓一侧作废的。
   - 一份指令执行一次，实做数量不多于指令数量，少于的余下不再做（`BD-WF-019`）。领星的工单把客户报的数量当参考、以仓库实际调整为准，换标服务单可以多次拣货。这里实做可以少、不可以多：多做要多消耗货主的货、多担费用，要有一份新指令。
   - 执行的事实到达之前，货主可以撤回自己经客户渠道提交的指令，运营可以作废；谁先到达算谁的，不设「仓确认开工」一步（`BD-WF-020`）。领星的工单已审核之后不支持取消，换标服务单只在待处理时可以取消。
   - 加工与拆解的投入与产出都是良品；产出形成新的入库批次，入库时间取入账那一刻。商品换标在同一笔流水里移数，入库批次与库龄不变；从未贴标库存里取的照 CONTEXT 既有的那一条不等式，不挤占不带别名条件的预占。
   - 指令不取单据号（`BD-WF-023`）。
   - 领星的工单类型由仓库自建，分关联库存与不关联库存。这里只有产品内置的加工（含拆解）与商品换标；不关联库存的服务（拍照之类）由谁提出、怎样记完成，本票没有写，转票 10。
7. **开箱（UC-WF-008）。** 仓内作业按箱记，一箱一笔：箱出，实点的商品按库存状态落到相容的库位，沿用该箱的入库批次；认不出的货不入账。实点与箱单的差额在同一笔里成一份收货差异，分法写进了 CONTEXT「入库与加工」，结论照 UC-WF-004 的差异结论口作，不另开口（票 07 留下的一条）。不要求先有货主的开箱指令（`BD-WF-022`）。领星的「库存转换」把箱库存转成产品库存，「按照入库时填写的箱子内对应sku数量自动生成产品库存。如产品库存数量有误，可转换后再调整产品库存。」；这里按实点入账，差额交货主作结论，不先照箱单入账再调。
8. **冻结与库存读口（UC-WF-009）。**
   - 冻结按格、带数量与原因，入库批次必带；只对可分配库存，数量不够或会违反占用规则时整份不成立，不冻够的那一部分。解冻整份解除（`BD-WF-024`）。不设不落到格的冻结（`BD-WF-025`），货主不能自己冻结（`BD-WF-026`）。
   - 所取的领星各页里没有见到单独的人工冻结：盘点页常见问题里的「WMS存在冻结库存」说的是盘点锁定。冻结是 CONTEXT 既有的占用，本票只写了它的口。
   - 运营按格、按箱、按汇总读库存，读各项占用与流水。货主读自己的在库量、各项占用的数量、可用量、库龄与流水，不带库位、冻结的原因与操作者（`BD-WF-027`）；销毁的流水另带货主授权的依据引用。领星的 OMS 给客户看总库存、可用库存、锁定库存与在途库存，库存流水里带出仓库端操作的盘点单与库内调整；这里同样让货主看到仓一侧改账的结果，锁定拆成预占、冻结与作业锁定分别给数。
   - 库龄照 CONTEXT「库龄」按仓的业务时区计日；仓的业务时区没登记时库龄答未配置，在库量、占用与可用量照答。
9. **盘点（UC-WF-010）。**
   - 创建不锁，开始才加作业锁定；只盘商品库存（`BD-WF-028`）；范围是所涉库位，可以另限定货主与商品；待出库库区的库位不收。领星同样是静盘、创建时「此时还不会锁定库存」、「盘点单只能盘点产品库存」，盘点类型分库位盘点与 SKU+库位盘点。
   - 能不能开始：CONTEXT 原有的是所涉库位上没有未完成的拣货任务、加作业锁定不违反占用规则，本票补「同一格库存同一时刻至多在一份盘点中的盘点里」。作业锁定只占所涉库位上范围内没被冻结的库存。领星要「需锁定库存=0且有可用库存时才可以开始盘点」；这里不要求没有任何占用：冻结着的照留，预占只要不被挤占。
   - 清点结果是作业事实，一条事实对一个库位、整库位地报，账上有而没列的格算实点为零；同一库位以发生次序最后一份为准，与仓测取当前那一版是同一种取法；不收入库批次。所涉库位都有清点结果才能完成，没清点的库位不按零算，也不按账算。
   - 清点结果到达时盘点须在盘点中，按到达本上下文的先后判：完成之后才到的离线清点答「盘点状态不符」。完成的答复已经交出、差异已经形成，不回头改；要重盘另建一份。
   - 完成是运营决定：逐格与那一刻的账比，不比入库批次，差额各成一份库存差异，解除作业锁定，不改账。领星的库存流水把盘点单列为「在wms内创建盘点单处理完成后产生的库存变动记录」，所取的各页里没有见到盘点完成与改账之间另有一步批准；这里完成只比出差额，改账要经批准（ADR-0368 决定六，CONTEXT 既有）。
   - 待盘点与盘点中都可以作废。领星是待盘点的删除、盘点中的作废；这里各册不删。
   - 盘点中从所涉库位移走的不入账、成库存差异，移入的照记；清点之后才入账的货会让差额失真，不自动剔除，差异的读口带出那一格自盘点开始以来的入账流水，交批准的人判断（`BD-WF-030`）。不设动态盘点（`BD-WF-029`）；盘点不取单据号、不上客户面（`BD-WF-031`）。
10. **入库批次怎么取、怎么归（CONTEXT「库存账与守恒」新增一条）。** 取走数量而没点名入库批次的，在其余各维相同的各格里按入库时间从早到晚取。盘盈与调增不另起入库批次：点名了的记入点名的那一个；没点名的，先取同一库位上其余各维相同的在库各格里入库时间最晚的，再取同批号与效期在这个仓有过的入库批次里最晚的，再不论批号与效期；这个商品在这个仓从没有过入库批次的不成立，改走建账导入。取最晚的那一个，是不替货主把多出来的货的库龄算长；仓租上怎样对待转票 10。点名的入库批次只须是同一货主、同一商品在这个仓有过的，不要求同批号：更正批号、效期或库存状态以一行调减加一行调增表达，调增点名原来的入库批次，入库时间因此不变。领星的批次管理写移库、调整库存「可以指定到具体批次」；它给可用库存量为零的 SKU 加库存的那一种方式，写明针对的是「有过库存流水」的 SKU，与这里从没有过入库批次的改走建账导入是相近的分界。
11. **库存差异与库存调整（UC-WF-011）。**
    - 库存调整按（货主，仓）一份提交，原因必带，各行是调增、调减或销毁，商品库存与整箱库存都收，待出库库区的不收。提交照那一刻的册与账面余额整份校验，不改账，也不占用；批准时照那一刻的账重判，整份成立或整份不成立，不成立的留在待批准。领星的库存调整是「可选三种调整方式（增加、减少、调整至），输入调整数量、备注（非必填），点击【确认】即可调整完成。」：点了就生效，备注可以空，所取的各页里没有见到批准。这里原因必带、经批准才入账（ADR-0368 决定六与 CONTEXT 既有）；没有「调整至」，提交与批准之间账会变，行里只写差多少。
    - 库存差异照形成时记下的格与差额入账，不照批准那一刻重算；盘点差异以盘盈、盘亏流水，其余的以调增、调减流水；批准时取不走全数或归不出入库批次的不入账，留在待处理；一份差异不拆。差额记多了记少了由批准的人判断：驳回，再提一份库存调整。
    - 批准只在差异所在的那一格入账。库内作业的差额记在移入或转成的那一格；货在账上若还记在源头那一格，批准之后账上会多出一份，怎样理顺由批准的人判断，UC-WF-011「一致性、幂等与并发」写了可走的路，没有替他选。
    - 销毁是库存调整的一种行：必带货主授权的依据引用，批准成立即以销毁流水出账，实物的销毁在系统外执行；货主在流水的读口看得到这笔销毁与依据引用（`BD-WF-032`、`BD-WF-033`）。领星的次品处理单由客户在 OMS 创建，处理类型分次品出库、次品销毁与次品翻新，仓库拣货之后确认销毁。这里首版没有货主提交销毁的口，货主的授权以依据引用带进来；次品翻新对着这里的次品转良品，次品出库归出库与退货的用例。
    - 收错了的收货走库存调整（票 07 留下的一条）：调整可以带所更正的作业事实与所引的收货差异，只作指名与留痕，已入账的收货流水不改不删。领星上架管理页的常见问题同是先上架、再调整库存扣减；票 07「参照的出处」里到仓扫描页的那一句是同一条路。
    - 代录的「已确认」此后被货主本人改成有异议（票 07 第二轮评审留的条件）：库存调整引用收货差异不以它的结论为前提，记下提交那一刻的结论与途径；已入账的调整不回退，待批准的照常等批准、不自动驳回，读口带出收货差异现行的结论与途径（`AT-WF-175`）。本票没有别的口拿收货差异的结论作前提。
    - 库存差异与库存调整不上客户面，批准之前不要货主确认（`BD-WF-034`）；库存调整不取单据号（`BD-WF-035`）。
12. **批准职责规则（CONTEXT 新增词条；票 07 留下的「谁有权批准、批准权限没登记时答未配置、提交人与批准人的关系」）。**
    - 批准要两样：批准的授予，与租户登记的一条批准职责规则。名字与 `party-commercial` 的「审批职责规则」、小包计价的「参考复核职责规则」分开，各是各的册。
    - 规则按租户一条、只追加修订：批准人须否与提交人为不同主体必写，可以另带库存差异的处理时限。产品不写死须两人，也不写死一人可批，与 ADR-0101 决定六对审批职责是同一立场。一种批准授予、一条规则管库存差异、库存调整与建账导入（`BD-WF-037`）。
    - 规则没登记时批准答未配置，各留在原状态，不自动调账。驳回不改账，只要批准的授予，不照规则比，规则没登记时也照常：ADR-0101 决定六拦的是批准门，驳回不改账，没有要靠分开两个身份去守的东西。
    - 规则写明须不同主体而批准人就是提交人的，答「职责规则不放行」。提交人：库存调整与建账导入取提交的操作者；库存差异取形成它的那条作业事实的操作者，盘点差异取那个库位现行那一份清点结果的操作者。两个身份每一笔都记下。
    - 处理时限自差异形成那一刻起按经过的时间算，不依赖仓的业务时区；过了的只在读口标出，不自动批准，也不自动驳回（`BD-WF-036`）。规则没登记时超没超期答未配置。
    - 登记走登记册配置写，不判准入范围；本租户一个仓都没登记时答未配置，与库位类型、包材的登记同。
    - 所取的领星各页里，库存调整与盘点完成都直接改账，没有见到批准或职责分离；这一条照的是 ADR-0368 决定六与 ADR-0101 决定六，没有领星的对照。
13. **建账导入的批准与驳回（票 07 留下的一条）。** 口在 UC-WF-011，与库存差异、库存调整共用一种批准授予与同一条批准职责规则；入账与重判照 UC-WF-006，没有另写一份。UC-WF-006 里原来指到本票的各处改成指到 UC-WF-011。
14. **一个仓都没登记的租户、停用的仓（票 07 留下的一条）。** 照 CONTEXT「主数据登记」：指名了仓的写口（库内各作业事实、指令的提交与发起、开箱、冻结、盘点的创建与清点结果、库存调整的提交）答查无所指的仓；没指名仓的（指令的撤回与作废、解冻、盘点的开始、完成与作废、批准与驳回、批准职责规则的登记）答未配置；读口答空；代理仓答仓不受理。答案的名字沿用票 07 的。停用的仓照常受理加工与商品换标指令、盘点、冻结与库存调整，CONTEXT「主数据登记」补了这半句：停用挡的是新入库，在库的货还要理清、发完。
15. **重放身份。** 作业事实各口按设备签发的事实身份认重放，内容按那个口的规范化形状比，相同答已有结果，不同答内容冲突（照 UC-WF-004，票 07 留下的一条）；答「作业内容不合」「库存不可用」「指令状态不符」「盘点状态不符」的不落册、不占事实身份，补齐或理顺之后可以原样重交。货主口按来源请求键。运营决定里新建对象的（发起指令、冻结、创建盘点、提交库存调整、次品转良品）按调用方给的决定标识或调整标识认，同一标识内容不同答来源冲突；指名在册对象的（撤回、作废、解冻，盘点的开始、完成与作废，批准与驳回）重放身份取被指名的对象。
16. **CONTEXT 同笔补的。**
    - Language：「商品换标」补去标；「库存差异」改写来源，写明库内发现破损的货不成库存差异；新增「批准职责规则」。
    - Rules：「主数据登记」补停用的仓照常受理的那几样；「库存账与守恒」里库区相容那一条补次品转回良品只对暂存库区里的次品、仓内作业记哪几种状态转换，新增入库批次怎么取怎么归的一条；「占用、预占与分配」补作业锁定占什么、同一格库存至多在一份盘点中的盘点里、冻结与作业锁定不由作业端铸，新增「占用不被库内的入账挤占」；「入库与加工」补开箱成份的收货差异怎样分、开箱转入与加工产出按实点记贴标别名，加工与拆解改成按指令作，新增商品换标按指令作的一条与开箱的一条；「盘点、差异与调整」补盘点各动作的归类与清点结果、差额逐格比、库存调整的形状，新增库内作业事实照记的一条与批准时重判的一条，批准那一条改成授予加批准职责规则；「作业端」把库内各作业事实列全。
    - Lifecycles：改「加工」「盘点」「库存差异」「冻结」，新增「商品换标」「库存调整」。
    - Boundaries：所有权那一条补批准职责规则。`Status` 行补一句，指到本票。

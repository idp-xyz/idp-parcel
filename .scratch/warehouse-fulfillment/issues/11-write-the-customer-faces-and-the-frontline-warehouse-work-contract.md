# 11 首方客户面、一线作业端与接入词表

Category: docs
Status: ready-for-agent
Blocked by: 07、08、09、10

依据：ADR-0368 Consequences「首方渠道要为货主新开入库预报、出库请求与库存查询这些客户面口」，决定六把一线作业端扩到仓内作业；ADR-0375 决定五「进仓配各面要有授予」。票 07 至 10 的用例各自点名了要哪个接入面，本票把它们收成对外契约。

## 要做的

- [首方客户 API 契约](../../../docs/api/first-party-api-contract.md)：补仓配各口（入库预报与撤回、出库请求、出库截单、自备面单补交、退货预报、加工与商品换标指令、库存与出库请求查询），重放与问题详情照该契约既有各节。
- [一线扫描离线与冲突决策简报](../../../docs/design/frontline-scan-offline-and-conflict-decision-brief.md)：仓内作业的离线动作集合、出库确认放行条件的下发与有效区间。
- 接入词表：客户面能力、运营决定种类、作业范围种类各加哪些词，写成一份 ADR（它们进 `internal/accessidentity`，归接入身份 owner）。同一份 ADR 要明说仓、库区与库位的登记走哪一族：登记册配置写与运营查阅读两族不分上下文，持有它们的操作者就能登记仓（ADR-0375 越权风险点 5），要不要为仓配另开能力面在这里定。
- ADR-0375 决定四留下的那一格：开关关着时仓配端点怎么答。本票写出两种做法各自动到 ADR-0055、ADR-0222 的哪一句，交第一张落端点的实施票定。

不动 `internal/**`。

## 完成判据

- 每个口能回指一个 `UC-WF-*`；契约里不出现 UC 没有的行为。
- 词表只加有来源的词：每个词指得到用它的那个用例。
- 只改 `.md`；进 main 前一份非作者评审，并代接入身份 owner 看一遍。

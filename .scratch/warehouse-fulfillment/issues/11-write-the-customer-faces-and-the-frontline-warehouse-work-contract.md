# 11 首方客户面、一线作业端与接入词表

Category: docs
Status: ready-for-agent
Blocked by: 07、08、09、10

依据：ADR-0368 Consequences「首方渠道要为货主新开入库预报、出库请求与库存查询这些客户面口」，决定六把一线作业端扩到仓内作业；ADR-0375 决定五「进仓配各面要有授予」。票 07 至 10 的用例各自点名了要哪个接入面，本票把它们收成对外契约。

## 要做的

- [首方客户 API 契约](../../../docs/api/first-party-api-contract.md)：补仓配各口（入库预报、告知更新与撤回、出库请求、出库截单、自备面单补交、退货预报、加工与商品换标指令、库存与出库请求查询），重放与问题详情照该契约既有各节。
- [一线扫描离线与冲突决策简报](../../../docs/design/frontline-scan-offline-and-conflict-decision-brief.md)：仓内作业的离线动作集合、出库确认放行条件的下发与有效区间。
- 接入词表：客户面能力、运营决定种类、作业范围种类各加哪些词，写成一份 ADR（它们进 `internal/accessidentity`，归接入身份 owner）。同一份 ADR 要明说仓、库区与库位的登记走哪一族：登记册配置写与运营查阅读两族不分上下文，持有它们的操作者就能登记仓（ADR-0375 越权风险点 5），要不要为仓配另开能力面在这里定。
- ADR-0375 决定四留下的那一格：开关关着时仓配端点怎么答。本票写出两种做法各自动到 ADR-0055、ADR-0222 的哪一句，交第一张落端点的实施票定。

票 07 的用例点了名、要在本票收成契约与词表的（都是暂名，出处在各用例「给开发的交接」的接入词一行）：

- 客户面能力：「商品维护」「入库预报提交」「入库预报告知更新」「入库预报撤回」「收货差异确认」「仓配查阅」。
- 运营决定种类：「商品代录」「入库预报代录」「收货差异结论代录」「入库预报完结」「待认领到货认领」「待认领到货处置」「建账导入提交」。票 08 至 10 还会加；这个封闭集由 `migrations/access_identity` 里 `operator_grant_decision_kind_decided` 那道 CHECK 守，每加一种都要重建它，收齐之后一次进词表与迁移，不分批。
- 作业范围种类「仓」；作业事实类型「收货确认」「仓测登记」「待认领到货登记」。`internal/accessidentity` 的作业范围种类今天是一个封闭集（`WorkScopeKind`），里面没有仓；一台设备只登记在一个作业范围上，请求的范围与设备登记的不同即答 `ErrDeviceNotInUse`；节点与仓同址、共用手持机时同一台设备进不了两个范围。词表的 ADR 先答这一格。
- 客户面的读：仓，商品与仓测，入库预报（含现行的告知、累计实收与单据号），逐次收货，收货差异，库存与流水。待认领到货与建账导入单首版不上客户面（`BD-WF-012`、`BD-WF-014`）。
- 货主读口上的代录标记：每个商品修订，预报的提交、各版告知与撤回，每个差异结论，各带途径；代录的另带依据引用，不带录入的操作者；被取代的代录结论照留、货主读得到。逐次收货带逐行结果，未入账的行带原因（UC-WF-002、UC-WF-003、UC-WF-004）。
- 从载荷收货主客户账户的几口：商品代录（UC-WF-002）、入库预报的代录提交（UC-WF-003）、待认领到货的认领（UC-WF-005）、建账导入的提交（UC-WF-006）。ADR-0151 决定二写「身份格只从信封与授权答复来，逐口照现有契约取，不从请求体收。」这几口是新建对象，或给还没有货主的对象指名货主，没有在册的对象可以取，货主客户账户在用例里写成业务内容；词表的 ADR 写明这几口照哪一种读。指名在册对象的代录（预报的告知更新与撤回、差异的结论）货主已经取自所指的对象。
- 登记册配置写不分上下文：持有它的操作者能登记、也能停用任何一个仓，停用会挡住这个仓新的入库预报、退货预报与建账导入（ADR-0375 越权风险点 5，UC-WF-001 的交接）。期限的出处要分清：ADR-0375 写的是「第 6、7 两点在任何生产部署打开开关之前要有答案。」，不含第 5 点；「生产上打开开关之前要有答案」是票 07 首轮与第二轮评审里代接入身份 owner 看的意见，不是 ADR-0375 的规定，也不是 owner 本人的。第二轮另指出，一个仓都没登记的租户只有登记仓那一口照常受理（CONTEXT「主数据登记」），这一口成了租户开始用仓配的唯一入口，这一点因此更要紧。词表的 ADR 回答要不要另开能力面，并写明这个期限取不取。
- 由收货事实转来的待认领到货，要不要在原预报的读口上标出「另有到货待认领」（`BD-WF-012`，UC-WF-005 的交接）。票 07 首轮与第二轮评审里代仓配履约 owner 看的意见都是要标出；第二轮另说对外承诺 PN-09 之前要有答案。
- 入库预报的告知更新是整组替换（UC-WF-003）：没带的到货线索或货主参考号就是清空。客户契约把这一句写在显眼处，或者让「告知已更新」的答复回显现行那一版（票 07 第二轮评审代仓配履约 owner 看的条件）。
- 运营代录的告知更新与货主本人的按到达先后各成一版，现行的是后到的那一版，代录的可以盖过货主本人刚交的（UC-WF-003 `AT-WF-083`）。同一位代看的意见是可以接受；定下发给作业端哪一版时要想到这一格。
- 词表的 ADR 写明粒度：入库预报的客户面能力（提交、告知更新、撤回）并不并成一项；「入库预报代录」这一种运营决定底下带决定标识的动作（代录提交、代录告知更新）共不共用一个去重空间；代录撤回不带决定标识，重放身份取被指名的预报（UC-WF-003）（票 07 第二轮评审代接入身份 owner 看的条件，范围照收尾核对收窄到带决定标识的动作）。
- 从载荷收货主客户账户的几口（见上）在词表的 ADR 接受之前不开真渠道；那份 ADR 写明货主客户账户在这几口是业务内容、向 `party-commercial` 核在不在本租户、查不到与越权探针同答（同一位代看的条件；用例今天就是这样写的）。
- 货主口各写命令的来源请求键各取命令前缀，进首方族的保留前缀表（ADR-0310 决定一）；加前缀之前先核已存的提交标识（同一份 ADR 的越权风险点 1）。
- 各写口判准入范围用的能力词与事实类型词（ADR-0180）。
- 一线作业端的下发与离线边界：库区与库位，商品、别名与包装层级，可收货的入库预报与它现行那一版告知（仓按到货线索找预报；离线时手里是哪一版），收货暂存库位。
- 离线记下的收货到达时可能整条答收货内容不合（计量单位与跟踪属性按入账那一刻的当前修订判，UC-WF-004）：设备怎样把这一格呈现给作业人员、怎样补齐重交。
- 按箱仓测「那一箱须在这个仓在库」按哪一刻判，UC-WF-002 没有写：照它的流程是到达时核，离线测完、上传之前那一箱已经出库的会答仓测未受理。定离线边界时一并定，定下之后写回 UC-WF-002（票 07 收尾核对时评审顺带指出，UC-WF-002 的交接）。
- 建账导入的提交与演示种子要不要一个受控批量口：「运营决定」面今天有没有批量口，票 07 没查。

票 08 的用例点了名、要在本票收成契约与词表的（都是暂名，出处在各用例「给开发的交接」的接入词一行）：

- 客户面能力：「加工指令提交」「加工指令撤回」「商品换标指令提交」「商品换标指令撤回」；「仓配查阅」沿用票 07 的那一个。
- 运营决定种类：「次品转良品」「加工指令」「商品换标指令」「库存冻结」「盘点」「库存调整提交」「库存调整批准」。同一种底下带决定标识的动作共不共用一个去重空间，照上面票 07 那一条一并答：「加工指令」「商品换标指令」底下是发起（带决定标识）与作废（重放身份取被指名的指令）；「盘点」底下是创建（带决定标识）与开始、完成、作废（重放身份取被指名的盘点）；「库存冻结」底下是冻结（带决定标识）与解冻（重放身份取被指名的冻结）；「库存调整批准」底下的批准与驳回都取被指名的那一份。
- 作业事实类型：「库内移动登记」「形态转换登记」「状态转换登记」「短少登记」「加工执行」「商品换标执行」「开箱」「盘点清点」。
- 登记册配置写面多一个对象：批准职责规则（UC-WF-011），对象身份是租户。受控批量口收不收它，照登记册配置写面既有各对象的做法定。
- 客户面的读：加工指令、商品换标指令与开箱记录（UC-WF-008）；在库量、各项占用的数量、可用量、库龄与流水（UC-WF-009），首版不带库位、冻结的原因与操作者（`BD-WF-027`），销毁的流水另带货主授权的依据引用。盘点、库存差异与库存调整首版不上客户面（`BD-WF-031`、`BD-WF-034`）。UC-WF-006 的 `AT-WF-079` 说的货主读库存与流水，读口写在 UC-WF-009，契约里还没有它。
- 开箱形成的收货差异：货主照 UC-WF-004 的差异结论口作结论；UC-WF-004 的读口按入库预报读差异，开箱形成的不对着入库预报，在 UC-WF-008 的开箱记录上读，两处在契约里怎样并成一个读口没有定。
- 从载荷收货主客户账户的口再加几处：库内各作业事实的行与次品转良品（UC-WF-007），运营发起的加工指令与商品换标指令、开箱（UC-WF-008），冻结（UC-WF-009），盘点的范围与清点行（UC-WF-010），库存调整的提交（UC-WF-011）。作业事实登记面上货主是行里的业务内容；运营决定面上的那几口与上面票 07 的几口是同一个问题，同一份 ADR 一并答。
- 两个身份可比（UC-WF-011 的 `AT-WF-172`）：批准职责规则比提交人与批准人，提交人可能来自作业事实登记面（清点、上架的操作者），批准人来自运营决定面。两个面上的操作者身份是不是同一个可比的标识，词表的 ADR 写明。
- 一线作业端的下发与离线边界再加：在库的格与各项占用（哪些货被分配、冻结或作业锁定占着，不能动），可选的移入目标，待加工与待换标的指令和它们固定的组成版本，箱单，盘点中的盘点与所涉库位。清点时给不给作业人员看账面数，UC-WF-010 没有定。
- 离线记下的事实到达时的几种答法怎样呈现、怎样重交：「库内作业已登记」而只入账了一部分，带逐行结果与形成的库存差异（UC-WF-007）；「库存不可用」，整笔不入账、不占事实身份、账理顺之后原样重交，与「指令状态不符」（UC-WF-008）；「盘点状态不符」，清点到达时盘点已不在盘点中（UC-WF-010）；「作业内容不合」。
- 加工指令与商品换标指令的货主口各取命令前缀的来源请求键，与上面 ADR-0310 那一条同。

不动 `internal/**`。

## 完成判据

- 每个口能回指一个 `UC-WF-*`；契约里不出现 UC 没有的行为。
- 词表只加有来源的词：每个词指得到用它的那个用例。
- 只改 `.md`；进 main 前一份非作者评审，并代接入身份 owner 看一遍。

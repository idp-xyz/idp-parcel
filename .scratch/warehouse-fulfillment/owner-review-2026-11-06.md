## ADR-0368

### ADR-0368·1 判据读法（产品 owner 一格）

**归属**：产品 owner　**结论**：有条件认可

**理由**

- 开发主线「能力范围判据」：「必须能指出一类真实存在的承运或渠道商业模式需要它，且该模式在上述目标客户群里是常规形态而非边缘情形。指不出来就不进。」三层表 3PL 行「是谁」一栏是「以仓配或集运为主业，跨境干线是其中一段」，仓配是这一层的主业，读宽有锚。读法只写在判据一处（「**仓配一项的读法**」一段），单一权威成立。
- 硬边界「任何取值仍必须由价卡或商业政策版本携带，不得内置为常量。」在 WF CONTEXT 里守住了：业务时区、库区库位、缺货处置、分配策略的采用、库龄口径、批准人与时限、包材表、增值服务项目表、代理仓协议都答未配置，与 ADR-0146 的三分一致。`PA-WF-01` 把「租户愿不愿换掉现有 WMS」如实登为假设。
- 缺口：开发主线写三层表「**它是判据里「常规形态」一词的输入**」，但 3PL 行「常规业务形态」一栏只有「多货主客户并存……；集运单元的装入、拆出与重新组合；跨法人履约……；结算按客户与按供应商两头分别成账」，一个仓配形态都没有。ADR-0368 决定一（判入）与 ADR-0370 决定七（「也不是三层的常规形态」，判出保税仓）都在拿仓配形态对这张表判常规，而表里没有可指的格——这正是三层表要消掉的「判断只能靠直觉」。

**须改**（开发主线改动，不需 ADR：只让判据的输入表跟上已接受的决定一，读法本身不变）

- `docs/product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md`「三层与各自的常规业务形态」表 3PL 行「常规业务形态」一栏，原文「……；结算按客户与按供应商两头分别成账」之后补：「；仓配：入库预报与收货上架、按货主分账的商品库存、一件代发出库（经本产品网络、货主自备面单或自提）、平台仓（如 FBA）与海外仓备货的贴标与整箱中转、退货入库」。

### ADR-0368·2 委托的新来源

**归属**：PS　**结论**：有条件认可

**理由**

- 来源本身没问题：`NewSource` 是开放必填串，来源请求键（出库请求，包裹序号）不复用，与客户渠道交来的委托受同一套接受判断。
- 授权依据没定，而且现行规则自相矛盾：
  - PS CONTEXT「来源请求身份」写它「只用于来源重放与冲突分类，不授予查询或操作权限」，所以来源不能兼作授权。CONTEXT-MAP「产品边界」写「`parcel-shipment` 只消费已授权作用域并执行自身对象过滤」，可内部上下文提交时没有接入身份给的作用域。
  - 首方的授权（ADR-0310 决定二「直客 1:1……册上绑定即授权」）在这条路上不适用。
  - PS CONTEXT「资料补充/更正请求」写「客户或授权运营角色请求形成客户原始资料新版本的业务请求。」同一份 Confirmed CONTEXT 的「来源请求身份」却写仓配履约「打包后经资料修订补正」——仓配履约两样都不是。
  - UC-PS-002、005、006 的仓配行都写「请求方与授权依据待小包托运定」。同一个根挂在提交、修订、撤回、取消四个口上。
- 「委托提交版本」要求保留「提交主体」。仓配代提交时，审计上若不分开记，看起来就是客户自己交的。

**须改**

1. **新 PS ADR**（扩 ADR-0310/0311 的请求方模型；两者都限定首方渠道，所以不停用任何条款）。PS owner 的决定是：
   - 来源为「仓配出库」的委托，其提交、资料修订、撤回与包裹取消：请求方记货主客户账户，实际提交方记 `warehouse-fulfillment`，请求证据指名出库请求与包裹序号。
   - 授权依据是 PC 授权册上的一个产品常量等级（形照 ADR-0311 的 `CUSTOMER_SELF_SERVICE`），由租户按货主授予，没授予答`未配置`。
   - 仓配履约在这个授予下即「当前有效授权代表」。
   - 停在`等待受控补充`时，续办方是仓配履约（见范围外 B）。
   - 接受判断不因来源变。
2. ADR 接受后，PS CONTEXT「资料补充/更正请求」：「客户或授权运营角色请求形成客户原始资料新版本的业务请求。」改为「客户、授权运营角色，或以货主名义代办的 `warehouse-fulfillment`（只对来源为「仓配出库」的委托）请求形成客户原始资料新版本的业务请求。」（CONTEXT 改动）
3. 「委托撤回」词条「客户或其当前有效授权代表」不改，由该 ADR 说明仓配履约何时属于此列。

### ADR-0368·3 扣减时点

**归属**：仓配履约、节点作业

**结论（仓配履约）**：认可。WF CONTEXT「库存在出库确认时按分配消耗，不等节点收寄，也不由节点收寄触发；出库确认与节点收寄是两件事实，谁也不替谁，同址时也如此」，就是按出库确认扣减的常规做法。风险点问的关联读口，CONTEXT 的回答是不要（「本上下文不读也不写节点作业的事实」），仓配履约认这个回答。

**结论（节点作业）**：有条件认可

**理由**

- 节点作业不需要读口；节点作业 CONTEXT 的「节点作业是面向小包网络流转的场站作业模型，不是完整 WMS。」与「完整 WMS 能力不属于本上下文。……」照旧成立，ADR-0006 的分界没被侵蚀。
- 仓配包裹怎么进节点没写。节点收寄是「客户送站形成的节点收寄」（CONTEXT-MAP 节点作业「拥有」）。送站预报与送站交接单来自客户渠道；授权交付关系按（交付方参与方，客户账户）问 PC（ADR-0212）。仓不是货主，也不是登记过的交付方，仓配履约又不许写节点作业的事实。实际路径只能是：包裹无预报到站，按号码认——「没有可验证交付范围时，恰一个候选、没有歧义信号且候选范围相容才是唯一命中」（CONTEXT-MAP `parcel-shipment → node-operations`）。节点作业接受这条默认路径，但它必须写明，免得日后有人加一条仓配写送站预报的路。
- WF CONTEXT「出库确认」写「本产品网络的交给同址节点、揽收或干线」。「干线」没有网络收寄的入口（见范围外 C）。

**须改**（CONTEXT 改动，不需 ADR）

- WF CONTEXT「出库确认」词条：「本产品网络的交给同址节点、揽收或干线」改为「本产品网络的交给同址节点（由节点作业按客户送站收寄，本上下文不为它开送站预报或送站交接单）或交给场外揽收」。

### ADR-0368·4 仓租计价

**归属**：PP　**结论**：认可

**理由**

- PP CONTEXT「评价对象」：「它有且只有四种：**已受理包裹**……**试算对象**……**委托**（票级）……**承运总单**（主单级）」，仓储作业收费发生项不在其中。
- 仓配材料都把这一格推给另立的 ADR：
  - ADR-0368「同笔改动的文件」写「**不**改小包计价 CONTEXT」；
  - CONTEXT-MAP 写「计价要为它立新的评价对象（仓租还要按持有期计），另立 ADR；在那之前小包计价 CONTEXT 的评价对象不含它」；
  - WF CONTEXT 写「计价为它立评价对象另立 ADR，在那之前小包计价的评价对象不含它」。
  
  PP 的所有权没被替定。
- 仓配一侧只交量与属性（「本上下文只给发生了多少，不分段、不给单价」），并写明「评价时用不用声明值由计价定」。按（货主，仓，计费日）一日一份、带库龄天数的仓租发生项，每日可以按卡单独评价：库龄段、免租期、淡旺季都是卡上条款（ADR-0260「计价条款只从价卡读」）。将来的 PP ADR 不被框死。
- 提示（不构成条件）：「作业属性」一条列的到仓方式、发运方式、包材等是举例，哪些成为价卡的条件维度归那份 PP ADR；结算的 SELL 触发缺口据票 03 在 UC-SA-002（未开验）。

### ADR-0368·5 离线拣货

**归属**：一线作业端、仓配履约

**结论（一线作业端）**：有条件认可
**结论（仓配履约）**：有条件认可（同一组改动）

**理由**

- 拣货照记与 ADR-0251「服务端对已经发生的移入与分拣一律照记」、ADR-0021「离线与弱网容忍是该端的固有要求，不是后续增强」同一立场。「离线端不铸预占与分配」守住了决定六。风险点问的「由谁、多久」，CONTEXT 答成租户取值：「谁有权批准差异与调整、差异要在多久内处理，是租户取值；没登记答未配置，差异停在待处理，不自动调账。」合红线。
- 同一份 CONTEXT 在最像一线作业的那件事实上却设了写口门。出库确认的定义是「货离开仓、交给下一程那一刻由仓内作业确认的事实」，CONTEXT 又写：
  - 「只有委托已被接受的包裹才能出库确认」
  - 「本上下文取不到面单本体，答未配置，这个包裹不出库确认」
  - 「更正还没被采用时这个包裹不出库确认」
  - 「打包出的包裹数与面单数对不上时不出库确认」
  
  门若在写口，离线或越权已经交出的件就记不进来，账上留着已经离仓的货。这正是 ADR-0251 对节点方向性作业否掉的形状——「「方向性作业受阻」是这份依据的答案，不是写口的结果」。
- 「作业端」一条列的是「收货（含按箱收货）、上架、移库、补货、加工、商品换标、开箱、盘点、拣货、出库复核与打包进入一线作业客户端」，没有出库确认与自提交付，谁来记没说。
- 没覆盖的时序：出库截单写「已分配未拣的撤销分配并释放」，可服务端不知道离线端已经拣了。拣货回传时，它的分配已不存在。

**须改**（CONTEXT 改动。ADR-0370 决定一、二只说「不出库确认」，没定门在哪一侧，ADR-0021 的部分停用已覆盖「仓配履约的仓内作业」，所以不需 ADR；若评审方坚持把 ADR-0370 那两句读成写口拒收，就要新 ADR 部分停用那两句）

1. WF CONTEXT「作业端」：「……拣货、出库复核与打包进入一线作业客户端」改为「……拣货、出库复核、打包、出库确认与自提交付进入一线作业客户端」。
2. WF CONTEXT「出库请求与发出」加一条：「出库确认的放行条件（委托已接受、面单本体已取到、预取面单的更正已采用、自备面单数对上、包裹没有有效取消）是随包裹下发、带有效区间的出库依据，由作业端判断，缺一格或出区间即暂停交出；已经交出的照记出库确认，同笔留下当时的出库依据并标出缺哪几格，交人处理，写口不拒（与 ADR-0251 对节点方向性作业同一形状）。」上列四句的「不出库确认」改为「不交出」。
3. 同节加一条：「拣货事实回传时它的分配已因出库截单撤销的，照记为移入待出库库区的库内移动，同笔生成回库任务，不算库存差异。」

## ADR-0370

### ADR-0370·1 自备面单与自提

**归属**：仓配履约、产品 owner

**结论（产品 owner 一格）**：认可。这是 3PL 一件代发的常规渠道（领星出库费按仓库物流、平台物流与自提分，只作佐证），落在 ADR-0368 决定一的读法里。本产品不形成「委托、包裹、面单交易、申报或追踪」，不担承运责任，范围没有越出仓配。前提是 0368·1 的表补上之后，这一判断才指得到格。

**结论（仓配履约）**：有条件认可

**理由**

- 自备面单写「打包出的包裹数与面单数对不上时不出库确认，交货主补正」。风险点又写「面单失效或被承运方拒收，责任在货主与承运方」，可拒收时货还在仓里。
- 生命周期没有这一格：装箱记录「自备面单：已打包 → 已贴面单（包裹数与面单数对上）→ 交给面单所指的承运方即已出库确认，记外部单号。」出库请求生命周期从「货主经客户渠道提交 → 已受理」起，没有补交面单的路。

**须改**（CONTEXT 改动）

- WF CONTEXT「Lifecycles · 装箱记录」自备面单一条改为：「自备面单：已打包 → 已贴面单（包裹数与面单数对上）或待货主补正（对不上，或承运方拒收）→ 交给面单所指的承运方即已出库确认，记外部单号；待货主补正的，货主经客户渠道为这份出库请求补交面单后回到已打包，或经出库截单拆包回库。」

### ADR-0370·2 预取面单

**归属**：PS　**结论**：有条件认可

**理由**

- 请求方：风险点原文「ADR-0310 定下的首方资料修订是客户本人提交、不涉委派」与 ADR-0310 决定二「请求方即客户本人、不涉委派」一致。UC-PS-002 行写「资料补充/更正请求的请求方没有「仓配履约代货主」这一种」。根与 0368·2 相同。
- 放不放行是租户取值：PS CONTEXT「资料修订阶段」写「允许什么由所采用接单规则包版本的资料修订允许声明说，本上下文不自带矩阵」。预取按设计先出面单（「委托接受后，面单随拣货单打印」），所以更正时委托已在「已制签或已装袋」这一格。租户没为这一格的声明测量修订写允许声明时，每一波预取都以「更正不放行」收场——撤回改提加面单作废，严格劣于不预取。WF CONTEXT 没把这些前提写成可选条件。
- 采用判断没分格：PS 的采用判断分`待补充`（「续办方是客户」）、`待复核`、`冲突`、`未决`。WF CONTEXT 只写「更正还没被采用时这个包裹不出库确认」：
  - 仓配自己发起的更正，「续办方是客户」不对；
  - `待复核`、`未决`没有时限，包裹就在仓里无限期等；
  - 仓配怎样得知采用，CONTEXT-MAP `parcel-shipment → warehouse-fulfillment` 只写了接受决定信封与撤回、取消的答复，没写资料版本。代码里有 `parcel-shipment.source-data-version.formed` 出向，没被引用。
- 撤回改提那一步：接受之后已不能撤回（「委托撤回」只在「委托尚未形成接受或拒绝决定时」），只能取消包裹。ADR-0310 决定三「取消授权规则是租户取值……没登答`未配置`，取消口对该租户不开」——没登记时，「改走打包后提交」那一步取消不了已带面单的预取委托。

**须改**

1. 0368·2 那份 PS ADR 同时写明：仓配发起的更正，`待补充`的续办方是仓配履约；采用结果怎样到仓配（资料版本已形成的信封，或对那次请求的答复）。（新 ADR）
2. WF CONTEXT「出库请求与发出」预取面单一条末尾补：「预取只在以下三格都已登记时可选：该货主有上述 ADR 定的代办授予，所采用接单规则包对「已制签或已装袋」阶段的声明测量修订有允许声明，包裹取消的授权规则已登记；任一格未配置即不预取，照打包后提交。更正的采用判断停在待补充、待复核或未决时，按租户登记的等待时限转撤回或取消；时限没登记答未配置，包裹停在仓里待人处理。」（CONTEXT 改动；这些前提是 PS 既有的租户取值，不是把预取做成租户配置，与 ADR-0370 否决「预取面单做成租户配置」不相抵）
3. CONTEXT-MAP `parcel-shipment → warehouse-fulfillment` 补一句：仓配履约以货主名义提交的资料修订，采用结果经（ADR 定的那条路）交回。

### ADR-0370·3 代理仓出库

**归属**：仓配履约、PS

**结论（仓配履约）**：有条件认可

**理由**

- ADR-0370 决定三只管出库与库存声明。「代理仓」词条写「本上下文只收它报来的库存声明，出库请求经代理仓出库转给它执行」，但「入库预报」写的是「到哪个仓」，没排除代理仓，退货预报同样。指名代理仓的入库与退货是拒、转还是不管，没有一句。
- 发生项：「出库作业……代理仓出库以代理仓报来的交接结果为来源事实」写了。仓租「按（货主，仓，计费日）每日形成一份，带日终在库的计量：按入库批次……」对没有库存账的代理仓形成不了，CONTEXT 没说。

**须改**（CONTEXT 改动，不需 ADR：决定三只覆盖出库）

- WF CONTEXT「Rules · 代理仓」加一条：「代理仓只经连接器办出库与库存声明；指名代理仓的入库预报与退货预报不受理，由货主与代理仓直接办；代理仓不形成入库作业、仓租与退货处理发生项。」

**结论（PS）**：有条件认可

**理由**：声明测量取代理仓报来的数，照常接受判断。除提交方与证据（应指名代理仓报告）外，没有新的 PS 语义。代理仓若在目的国，委托不是「国际小包服务」，见范围外 D。

**须改**：并入 0368·2 那份 PS ADR——实际提交方记 `warehouse-fulfillment`，请求证据另指名代理仓装箱结果的来源事实。

### ADR-0370·4 贴标别名

**归属**：仓配履约　**结论**：有条件认可

**理由**

- 贴标别名进了库存账的键（「按（租户，货主，仓，库位，商品，计量单位，库存状态，贴标别名，入库批次，批号，效期）记数量」），预占又写「不带贴标别名条件的出库请求只预占未贴标的库存」。可没有一处入口设这一维：
  - 「收货」：「商品入库按商品、计量单位与库存状态记实收数量」；
  - 「退货入库」：「状态按质检记良品、待检或次品」；
  - 「建账导入」：都不提。
- 后果一：FBA 退仓或退货回来的货本就贴着 FNSKU（领星有 FBA 退货换标流程，只作佐证）。按未贴标入账，就会被普通一件代发预占，带着平台标签发出。
- 后果二：定义「实际贴着作标签的那个商品别名」没说商品条码算不算。「商品别名」包括「条码、平台商品码」。若商品自带的条码算贴标别名，这类库存全部变成「已贴标」，普通请求预占不到。

**须改**（CONTEXT 改动）

1. 「收货」「退货入库」「建账导入」三条各补：「按实点记贴标别名：到货已贴平台标签的记那个别名，没贴的为空。」
2. 「贴标别名」词条补：「只取会把货限定到某一平台或渠道的别名类型（平台商品码，如 FNSKU）；商品条码等不限定渠道的标签不作贴标别名，贴上也不改这一维。」

### ADR-0370·5 整箱库存

**归属**：仓配履约、PS、CC

**结论（仓配履约）**：有条件认可

**理由**：整箱库存的键是「（租户，货主，仓，库位，箱号）」，箱号来自货主的入库预报（「整箱入库的写箱号与箱单」）。没有任何一条让箱号在（租户，货主，仓）内唯一。货主按票编 1..N 很常见，两票都有「1」号箱时：放在同一库位，账的键就撞了；按箱号预占、出库复核扫箱号也认不出哪一箱。

**须改**（CONTEXT 改动；ADR-0370 的键不变，只加唯一性）

- WF CONTEXT「整箱库存」词条补：「箱号在（租户，货主，仓）内在库期间唯一：按箱收货时与在库箱号重复的，收货不成立，交货主补正，或由仓另编箱号并记下货主原箱号。」

**结论（PS）**：认可。一箱一个包裹、一份委托，箱单作客户原始资料，接受判断照常（服务产品的重量尺寸上限照判）。PS 语义上没有 0368·2 之外的新东西。

**结论（CC）**：有条件认可

**理由**

- CC CONTEXT 两条要求：「正式申报资料快照」「保留客户原始声明、节点实测或观察、关务判断和其他合法依据之间的区别，不覆盖任何来源值」；「字段级溯源」「一个最终字段由多个来源共同形成或存在冲突时，必须保留各来源及裁决过程」。
- WF CONTEXT 在交给 PS 之前就把三份货主声明合成一份：「本单没给的申报格取商品申报资料；整箱出时货物内容取该箱的箱单，缺的申报格取箱单所列商品的商品申报资料」。关务只看得到一份「客户原始声明」，分不出哪格来自本票、哪格来自商品主档、哪格来自箱单。
- 「箱单错了，申报跟着错，关务照常判」，CC 认可的前提是 CC 看得出那是箱单值。
- 整箱多半是 B2B 备货出口，不是逐票 B2C；CC 按「监管程序」分案件，接得住，不构成条件。

**须改**（CONTEXT 与 UC 改动）

- WF CONTEXT「出库请求与发出」客户原始资料一条，「都没有的格照实空着」之前补：「每个申报格带来源标记（本单申报、箱单或商品申报资料），随客户原始资料原样交给小包托运，不合并成无来源的值。」
- UC-PS-001 仓配出库那一行「要随这条路径一起定，并与关务读申报资料的口径对齐」后补：「条目须能带来源标记，供关务字段级溯源」。

### ADR-0370·6 进追踪

**归属**：VE　**结论**：有条件认可

**理由**

- VE CONTEXT「事实类型词」表已有「`warehouse-outbound-confirmed` | `warehouse-fulfillment` | 出库确认，只对发运方式为本产品网络、已指名小包托运包裹的那一件」，唯一出处成立。「无法可靠映射时保持未归类」与「没登记就保持未归类」一致。代理仓报告由仓配认领为自己的来源事实，与运输履约认领外部承运轨迹同形。
- 但 VE CONTEXT「来源事实替代关系只能由源上下文给出，且只在同一源上下文、同一事实引用的版本之间成立。」WF CONTEXT 只给库存流水定了更正（「更正以新流水表达」），出库确认本身没有更正关系。错扫的一次出库确认会在客户追踪里永远显示「已出仓」。

**须改**（CONTEXT 改动）

- WF CONTEXT「出库确认」词条补：「错记的出库确认以更正版本表达：同一出库确认引用下的新版本指名被更正那一版，库存以调整流水回补；交全程追踪的事实随之带替代关系。」

### ADR-0370·7 保税仓

**归属**：产品 owner、CC

**结论（产品 owner 一格）**：认可

**理由**

- 目标客户群「经营跨境出口小包网络的物流企业，首发以中国出口为起运侧」；保税与监管仓要绑海关账册，三层哪一层都不以它为日常。ADR-0370 把它交给外部 WMS 协作缝，并写「客户群放宽……另立 ADR 与关务一起定」，与开发主线「客户群一旦放宽……必须重新评估」一致。
- 保留一句：「不是三层的常规形态」现在是对着一张没有任何仓配形态的表判的，0368·1 的表补齐后才能复核。

**结论（CC）**：认可

**理由**

- CC CONTEXT 里没有账册、保税或监管仓概念（grep 无命中）。关务案件按「监管程序」建，保税仓要的核注与逐单申报 CC 不建模，排除与 CC 现状一致。
- WF CONTEXT「出库确认不是关务受门禁的「出库」动作」之所以成立，正因为保税仓被排除；哪天收进来，仓的出库就变成受门禁动作，ADR-0370 已写要与关务另立 ADR。

## 范围外但必须说的

**A. 别人发起的取消，仓配看不见，会把已取消的包裹发出去（PS / 仓配履约）**

- PS 允许客户账户自己取消（PS CONTEXT「取消请求还须目标委托属请求方的客户账户」；首方取消口按 `shipmentRequestId` 指名委托，ADR-0310 决定五附带结论），货主正是仓配出库委托的客户账户。
- PS CONTEXT「包裹取消与包裹终局形成都只对`已接受`的委托开放」——取消后委托仍是`已接受`。WF CONTEXT 只认「只有委托已被接受的包裹才能出库确认」，并写「撤回与取消由本上下文以货主名义提出，成不成立以小包托运对那次请求的答复为准，这封信封不带它们」，所以会把已取消的包裹出库确认。
- PS 已有出向 `parcel-shipment.parcel-cancellation.recorded`。
- 改：CONTEXT-MAP PS→WF 一条与 WF CONTEXT 补「包裹的有效取消经包裹取消已记录的信封交到仓配履约，进出库依据」（0368·5 已把「包裹没有有效取消」列进依据）。不需 ADR，实现差距随仓配第一张 UC 的「给开发的交接」。

**B. 仓配出库委托停在`等待受控补充`时，没有人能续办（PS / 仓配履约）**

- WF CONTEXT「都没有的格照实空着：本上下文不补默认值」，让「客户可补充缺口」成为常见路径；PS「判断遇到客户可补充缺口 → 等待受控补充：补充形成同一委托的新提交版本」，授权处置选「交客户补充」也落到这里。
- 货主补不了：首方补充要带提交回执里的 `submissionVersionId`（ADR-0310 决定五），回执交给的是仓配。
- 仓配也不知道：等待态不是决定，不交接受决定信封。包裹打好包停在仓里，无人被告知。
- 改：并入 0368·2 那份 PS ADR——续办方是仓配履约，并给它一个信号（信封或读口）。WF CONTEXT 补「委托停在等待受控补充时，货主经出库请求补正，仓配履约提交新提交版本」。

**C. 「交给干线」绕开网络收寄（PS / 运输履约 / 节点作业）**

- WF CONTEXT「出库确认」列了「干线」。PS 只认「将节点收寄和场外揽收统一解释为适用的有效网络收寄结果」；SELL 计费时点挂在有效网络收寄的采用上（CONTEXT-MAP `parcel-shipment → settlement-accounting`（包裹计费时点）），面单服务的取消边界也挂在收寄上。
- 直接交干线的包裹没有收寄、没有计费时点。已在 0368·3 的条件里去掉。

**D. 「本产品网络」从海外仓或代理仓发出时不是国际小包（产品 owner / PS）**

- PS CONTEXT「委托」是「客户要求运营企业为一个或多个包裹提供同一项约定国际小包服务的业务请求」；目标客户群是「经营跨境出口小包网络的物流企业」，并写「客户群一旦放宽（例如纳入本地小包网络），依据它作出的能力范围结论必须重新评估」。
- ADR-0370 的 Context 以「海外仓的一件代发」引出自备面单与自提，代理仓多在目的国。从那里经「本产品网络」发给当地收件人是国内件：按 PS 定义不是委托，也等于放宽到本地小包网络。没有任何风险点覆盖。
- 产品 owner 二选一：
  - 写明「本产品网络」只对属于本产品国际小包服务的包裹成立，海外仓与目的国代理仓只走自备面单或自提（WF CONTEXT「发运方式」与 CONTEXT-MAP 改动，不需 ADR）；
  - 或另立 ADR 放宽客户群，并重判依它作出的结论。

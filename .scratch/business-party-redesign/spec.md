# 往来单位页重构：页头一行、视图签、类型芯片、主从分栏与页面态；类型交给读口算

Category: enhancement
Status: in-progress
出处：2026-11-10 用户在 5173 看往来单位，说「现在有点凌乱，特别是左边 header 部分，和头部的 tab」。会话先只把册签挪回页顶（分支 `cursor/business-parties-book-strip`，未进 main，不再落），用户答「左边部分我觉得还是非常的不专业……这个UI/UX你可以完整重构……先给出静态页面给我参考吧」。此后在静态页上逐轮改（去外圈留白、右栏正文留白收到与上边一致、粗体只留给标题）；要定的几项用户答「你作为国际小包业务和系统专家，根据你以往的经验帮我决定吧」，本文件的「决定」即据此写下。

切片：PN-02，主责 party-commercial，非关务专项。机制：读口随行答类别、按类别筛、给分面计数（票 08，先过票 07 的 ADR 草案）。产品策略：页面形态、页面态与提示语。租户取值：无。证据层级 S（演示租户）。

静态参考：[static-reference.html](./static-reference.html)。单文件，合成数据，不接后端；状态栏里虚线框的「演示状态」下拉切各页面态，那个下拉不是产品里的控件。版式、间距、色值与用词以它为准，本文件只写它表达不了的取舍与边界。它里面写的像素字号是目标观感，落地时取字号角色、不写像素（见「字号」）。

## 为什么重构而不是再修

命令头是几轮补丁叠出来的，问题不在哪一件摆哪（实测于 `8d6f5ffba`）：

- 册签放在标题旁，左缘随标题与说明的长度变：同一个视口下各册分别在 765、693、813 像素，切册时表格顶端上下跳 42 像素；身份册的命令头在约 1536 至 1970 宽之间折成两行，动作落到第二行。
- 带数的地方有四处（册签、指标格、状态胶囊、翻页条），四种写法；筛选有三种长相（指标格、实心胶囊、下拉）。
- 选中一行之后，左边只是一张被挤窄的表，不是为「挑一家看」设计的名录。

## 决定

| 事项 | 决定 | 理由 |
|---|---|---|
| 页头 | 一行：页名、一句说明（放不下截断）、动作。动作位置固定，不随视图换 | 列表上方每多一行就少看一行数据；位置固定才点得熟 |
| 视图 | 页头下一条通栏的签：单位名录、合作关系、我方关联。数只在签上出现一次；待办（几段待确认、几家未生效）跟在同一行右端，有才出现，点了带着筛选跳过去 | 三者是同一份主数据的三种看法，同级、要一键换；第一枚叫「单位名录」，不与页名重名 |
| 筛选 | 检索、状态下拉、类型芯片排成一行；放不下时芯片收成下拉，不折行。指标格并进类型芯片 | 一个筛选只留一个入口，每个数只出现一次；状态三个值、用得少，芯片的位置让给类型 |
| 芯片上的数 | 随检索词与状态走，不随类型自己走；摆哪几枚看整册，条件下数到零的压淡留在原位 | 点下去得到几行，芯片上就该是几；摆出来的那几枚不随打字增减，不跳 |
| 列表 | 各列定宽，余量落在行尾；图标块按类型取图标与底色；名称下一行是编码与注册地；加「合作关系」一列（段数与待确认）；翻页在表底 | 数据靠左成一块；注册地大半为空，不单占一列 |
| 主从分栏 | 选中一行后左边换成名录栏（两行一条的列表，行高 60，定宽，不可拖），右边详情通到底 | 右栏拿到整列高度；名录栏定宽，右栏概要的两列才有稳定的断点。行高比整页表格的 48 松一档：名录是拿来挑一家点开的，不是对着列读的（用户看过 52 的一版，嫌矮） |
| 右栏 | 头区一行关键事实，下面按签分；读的内容（按话题分组的字段）用卡片，数的内容（关联、登记记录）通栏；概要里合作关系只列最近几段 | 容器跟着内容的形态走；我方公司名下的关系可以上千段 |
| 联系人 | 一人一张卡：姓名、部门与职务、用途（主要联系人标出）、电话、邮箱、社交账号（平台加账号，可多个）。没有的项整行不摆；号码类的值点一下复制 | 现有资料里这些格都有（`legal-entity-contact-cards.ts`），第一版静态页只画了姓名、邮箱、电话，用户指出少了社交账号 |
| 关系图 | 「关联」签先图后表；「我方关联」选一家公司，右栏是它的关系图加按角色的汇总。画法与合成规则照现有的不变 | 现有实现就有图（`party-relationship-graph.ts`），第一版静态页把它换成了表，用户指出不该丢 |
| 写操作 | 改这家单位自己的东西（更新资料、更正名称与识别信息）= 这一页进入编辑态，保存前先核对一遍，从名录进来的退出后回名录的分栏；登记合作关系 = 合作关系一区就地填；新增往来单位 = 整页的登记视图；停用 = 对话框 | 容器照 [business-party-edit-mode](../business-party-edit-mode/spec.md) 已定的不变，这次定的是它们在新版式里的样子（票 11）。核对一步是票 11 加的：往来单位这两张表单原来点保存就直接登记，而登记之后不能改，只能再登一版 |
| 留白 | 大块面板贴边，只用分隔线；右栏正文四周同一个小留白 | 用户逐条定的：外圈不留，卡片留小而一致的 |
| 粗体 | 只给页名、右栏的单位名、名录栏标题 | Windows 上中文落到微软雅黑，只有常规与粗体两档：实测 600 与 700 画出来一样，一列名称全粗就是一条黑带；500 只让英文变粗 |
| 页面态 | 只换表格那一块，页头与页签留在原位；页签上的数等答案到了才摆；骨架照将要出现的列排；换条件、翻页、刷新时旧的一页压淡、不闪成骨架；说明块落在上三分之一；空册给下一步；没有登记权限时写入口整组不摆 | 页面不因为状态变了而整体跳；「0」是一句真话，不拿它占位 |
| 类型由谁算 | 交给读口（票 07、08、09，2026-11-12 都已进 main）：读口在行上答类别与关系段数、按类别筛、答分面计数，管理台只照着摆。票 01 的降级（装不下就不带数、类型标「只筛本页」、没读到的显示「—」）已随票 09 撤掉 | 见「类型为什么不能留在浏览器里算」 |
| 字号 | 全站一起调，走字号角色表，另票；本页不做例外 | 11 月 5 日「公司主体右栏大一档」的根子就是单页自己提了一档 |
| 别的页 | 本页先行，不动共用模板；验收后另立 spec 把这套结构收进模板、分批迁 | 共用模板的消费页多，先拿一页试 |

## 类型为什么不能留在浏览器里算

事实（取证于 `8d6f5ffba`）：

- 检索、状态、排序已经由读口做（ADR-0144）。类型不是往来单位册上的字段，是页面拿合作关系、客户账户、公司主体各册**不带条件的第一页**推出来的（`business-party-list.ts` 文件头）；一页的大小由接入面定（`isolatedReadLimit`）。
- 「谁算客户」是 CONTEXT 里的一条规则（「一个业务参与方持有客户角色，当且仅当……」），服务端没有它的实现：`git grep -c 客户角色 -- 'internal/*.go'` 没有结果，唯一的实现在管理台。
- 小包网络的往来单位册很不对称：货主客户成百上千到上万家，供应商、承运代理加起来几十家，我方公司几家。运营日常要的正是「把供应商挑出来」「有几家客户」，这两件事在多页时现在都做不到。

所以方向是读口随行答类别、能按类别筛、给各类别的家数，管理台删掉自己那一份推导。这要动 ADR-0144 的读契约（答复加分面计数），并且要对上 ADR-0372 的判据（它前一天刚把「领域规则在多行之上求出的结论」排除在状态筛选维之外），所以先有一篇 ADR：[ADR-0378](../../docs/adr/0378-business-party-reads-answer-categories-read-from-the-existence-of-rows-and-catalogue-reads-may-carry-facet-counts.md)（2026-11-12 接受，没有做评审；经过见票 07）。

## 不在本 spec

- 把这套结构收进共用模板、其余页的迁移：票 10 验收之后另立。
- 「资料版本」签的内容、合作关系视图的右栏内容：照现有实现，只换外框。各表单里的字段、校验与写口一样不动，票 11 只管它们摆在哪、长什么样。
- 1100 宽以下分栏怎么退化：静态页没画，现行页面也没有这一档；票 03 里如实记「未做」。
- 右栏「关联」签的其余各区（客户账户、供应商协议、结算政策）：与合作关系一区一样，是从各册不带条件的那一页里挑这家单位的行（`PartyOverviewSection`）。本 spec 只把合作关系一区改成读得全（票 08、09）；其余各区多页时挑不挑得全、有没有提示，这次没有核对，另议。
- 静态页的外壳（顶栏、侧栏、标签条、状态栏）是照现状画的，不在重构范围内。

## 红线

- 类型的数与类型筛选只在读得全的时候说成整册的；读不全就标明（ADR-0372 决定三）。
- 界面用词取现有词表与现行页面的原话：「暂无合作关系」「当前筛选条件下没有匹配的单位」「还没有登记任何往来单位」，不另造说法。
- 只读核对，零写请求；演示凭据与合成数据照 `scripts/demo-seeds`。

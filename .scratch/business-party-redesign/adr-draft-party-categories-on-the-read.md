# ADR 草案：业务参与方读口随行答「类别」——持有的角色与是否我方公司由读面按本上下文登记册上「有没有那样一行」导出，类别可作筛选维；目录读口的答复可按各册点名的维带分面计数

## Context

**规则在哪。** party-commercial `CONTEXT.md` 写着：「一个业务参与方持有客户角色，当且仅当它持有一段在用（候选或已生效）的客户关系，或是一个未停用货主客户账户的所属客户参与方。」其余角色由参与方关系表达；「我方公司」在 `CONTEXT.md` 里指被责任法人钉着的业务参与方。ADR-0367 决定四把客户角色定为「由在用客户关系或在用客户账户判出」，它的索引注记同时记着：后端没有任何业务逻辑读客户关系。

**实现在哪。** 这条规则今天唯一的实现在管理台（取证于 `8d6f5ffba`）：`apps/admin-web/src/pages/party/business-party-list.ts` 的 `indexPartyRoles` 与 `ourCompanyPartyIds`，输入是合作关系、客户账户、公司主体各册不带条件的第一页。在 `internal/` 的 Go 源码里检索「客户角色」没有结果。

**多页时坏在哪。** 一页的大小由接入面定（ADR-0144 决定二）。往来单位一多：

- 关系或账户排在第一页之后的单位，被推成一个角色都没有；
- 按类型的数给不出来，类型只能在已取回的那一页上筛（ADR-0372 决定三的形态）；
- 小包网络的往来单位册很不对称——货主客户成百上千到上万家，供应商与承运代理几十家——在一页里筛「供应商」，多半答出一个假的「没有」。这正是 ADR-0144 的 Context 要消灭的情形，只是它当时说的是状态与检索，类别不在册上、没被带到。

**两份现行记录管着这件事。** ADR-0144 的答复形状只有 `page`，没有分面计数。ADR-0372 把状态筛选维收窄到「由本册登记行直接读出」的状态，并把「领域规则在多行之上求出的结论」「按读取时点现算的读数」「管理台的呈现词」排除在外；类别不是状态，字面上不归它管，但它的理由（规则不出第二处定义、翻页之间不能漂、词表要是领域的）对类别同样成立，所以本草案逐条对着它写。

## 候选与反方

**甲 · 留在页内筛，只把「没读到」标出来。** 即票 [business-party-redesign/01](./issues/01-type-reads-unknown-when-the-source-registers-are-incomplete.md) 的止血形态。反方：标明了仍然筛不出、数不出；规则仍只在浏览器里。它是过渡形态，也是本草案被否时可以长期停留的形态，不是去向。

**乙 · 管理台把这几册翻页读全再算。** 反方：页大小不由调用方定（ADR-0144 决定二），读全只能一页一页翻完这几本册，每开一次页面翻一遍；规则仍只在浏览器里，换一个调用方就要再写一份。否决。

**丙 · 写面落列**（ADR-0372 决定二·1 给第一类的出路）：关系、账户、法人各处写入时维护一张「参与方 × 类别」的投影，读口按列筛。反方：几条写路径共同维护一张投影，漏一条就错；更要紧的是客户账户与责任法人的「未停用」是生效与停用时点对时钟的推导（这几册的 `status` 同此），时间流过不是一次写入，投影恰好在这一处会陈旧——ADR-0372 对第二类说的「没有落列的时机」在这里原样成立。否决；评审若判类别属于第一类，这条要重估（越权风险点 1）。

**丁 · 读面按「有没有那样一行」导出（本草案）。** 代价：业务参与方的每一问多折叠这几本册；分面计数多一次聚合；ADR-0144 的答复形状多一格。

## Decision

**一、类别的判定在领域一处。** 一个业务参与方在某一时点的**类别**是下面各项里成立的那些，一项都不成立时是「无角色」：

- 对每个参与方角色：它是一段在用（候选或已生效）的该角色关系的持有方；
- 客户角色另有一条：它是一个未停用货主客户账户的所属客户参与方（`CONTEXT.md` 原句，两条任一成立即可）；
- 我方公司：它被一个未停用的责任法人钉着。

判定写在 party-commercial 的领域包里，输入是这家单位名下各关系的角色与登记的状态、名下客户账户与钉着它的责任法人的生命周期事实、判定时点。管理台自己的那一份删掉。

**二、读面是它的镜像。** 读面在 SQL 里对折叠到最新修订的这几本册，按参与方标识逐项探「有没有那样一行」，时点取装载时点——与同一行的 `status` 同一口径（那一格今天就是 `domain.IdentityLifecycle.StatusAt` 的 SQL 镜像）。领域判定与 SQL 用同一批夹具对照测试。答的是装载时点的类别；行上不带这这几本册的事实，要别的时点的调用方自己去读那这几本册。

**三、答复行多带两样。** `categories`：多值，封闭词表为参与方角色各值加「我方公司」「无角色」两个词，永不为空。关系段数：作为持有方、作为相对方各两格（在用的、其中候选的），只是行数，不带判断。

**四、`categories` 是业务参与方册的筛选维**（ADR-0144 决定四：维内为或、值按词表校验、进游标摘要）。它与 ADR-0372 的关系：ADR-0372 把界划在「有没有那一行」与「那几行合起来怎么判」之间。类别的每一项都是一次存在性判断——行与行之间不比较、不挑选、不汇总；被探的这几本册都在本上下文、由本上下文写入、以参与方标识指回本册；判断里用到的「在用」「未停用」读的是那一行登记的状态或它自己的生命周期时点。本草案据此判它落在 ADR-0372 决定一的同一侧，不属决定二排除的那几类。这是对 ADR-0372 判据的一次延伸适用（从「以本行为键的留痕册」到「本上下文内以本行标识为外键的登记册」），接受本草案即接受这次延伸。

**五、目录读口的答复可以带分面计数。** 各册在声明里点名哪几个筛选维给分面；点名了的，答复在 `page` 之外多一格：

```json
{ "facets": { "categories": [{ "value": "CUSTOMER", "count": 1200 }], "status": [{ "value": "EFFECTIVE", "count": 1270 }] } }
```

每一维答它词表里各值的行数，条件取本次请求的 `q` 与其余各维，**不含该维自己**——点下某一格会得到几行，那一格上就是几。多值维一行可以记进多格。只有给精确 `total` 的读口给分面。没点名的册答复里没有这一格，不认识这一格的调用方不受影响。实现落在 ADR-0144 决定七的那个共用件里，不含任何上下文的词。

**六、本次点名的。** 业务参与方册：`categories` 与 `status`。参与方关系册：`status`；另加 `holderId`、`counterpartyId` 两个筛选维，供按一家单位读全它名下的关系。

**七、过渡。** 本草案落地之前，管理台照 ADR-0372 决定三在页内筛并标明（票 01）。

## Consequences

- party-commercial `CONTEXT.md` 在客户角色那一句之后补一句类别的定义：「业务参与方的类别是它此刻持有的各个角色，被未停用的责任法人钉着的另算我方公司，都不是的为无角色；类别由登记的事实读出，不是业务参与方身份上的一格。」措辞由接受时定稿。
- ADR-0144：决定五的答复形状多一格 `facets`，决定四多一种「由本上下文其他登记册的存在性读出」的筛选维。ADR-0372：判据延伸适用一次。两篇各加前向指针，正文不动。
- 业务参与方册每一问多折叠这几本册；这几本册各要一条按租户与所指参与方标识的索引。
- 管理台删掉 `indexPartyRoles`、`ourCompanyPartyIds` 与随它们的计数、页内类型筛选；类型列、类型筛选与各处的数改取读口（票 [09](./issues/09-admin-web-takes-categories-from-the-read.md)）。
- 别的上下文的读口不受影响；谁要分面计数，在自己的声明里点名即可，不必再过一篇 ADR。

## 越权风险点

1. **类别落在 ADR-0372 的哪一侧。** 本草案判「有没有那样一行」。反方可以说：被探的不是留痕册而是另外三本独立的登记册，「在用」「未停用」又各带一条判据，这已经是「几行合起来怎么判」。若评审采此说，类别属于 ADR-0372 的第一类加第二类，筛选维放不出来，去向只剩候选丙（并且要先解决时钟那一处），或者长期停在候选甲。
2. **「我方公司」「无角色」进了词表。** 它们不是参与方角色。本草案把它们与角色并在一个多值维里，是因为运营是并着看的（一家我方公司也可以对别人担任角色），而且「无角色」只能表达成「前面各项都不成立」。若 owner 认为该拆成两维（持有的角色、是否我方公司），「无角色」就要用两维的组合表达，分面给不出它的数。
3. **时钟。** 客户账户与责任法人的「未停用」随时间流过而变，同一组条件翻两页之间一行可能换类别。业务参与方、法人、客户账户各册的 `status` 筛选维今天已经是这样；本草案没有让它变得更糟，但也没有解决它。
4. **成本。** 每一问多三次折叠与一次聚合，以「按租户读、租户级规模」为前提（同 ADR-0144 越权风险点 3）。哪个租户先超出这个前提，分面要能单独关掉而不影响筛选。
5. **分面进了共用契约。** 它是加法，但各册一旦点名，调用方就会依赖那几格数。点名从小放：只为页面确实摆出来的数点名。
6. **词表的写法。** `categories` 的两个新词与两格段数的字段名没有定稿，归接受时与 HTTP 载荷的既有命名对齐。

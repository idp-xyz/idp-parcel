# 渠道账号使用授权有整套规则，却没有执行器——类型在 `internal/` 下零引用

Category: chore
Status: draft
Blocked by: 无

## CONTEXT 要求什么

`docs/domain/party-commercial/CONTEXT.md` 把它列进 Language、Rules and invariants、
生命周期与 Boundaries 四处，是本上下文写得最全的词条之一。

Language 一节的词条原文：

> **渠道账号使用授权**
> 渠道账号持有人允许运营企业在明确范围和期限内使用该账号开展业务的授权。授权必须显式、
> 可撤销并可追溯；取得账号凭据不等于取得业务使用授权。

Rules 一节三条硬句：

> 使用客户自有渠道账号前，必须存在对明确账号、授权双方、适用范围和有效期均可识别的有效授权。
> 技术上能够访问账号不能替代该授权。

> 渠道账号使用授权被撤销或到期后，不得据此发起新的业务使用；已经接受的委托不因此自动关闭或
> 取消，但其后续新交易必须重新取得当前有效授权。已经形成的交易仍保留当时有效的授权依据，
> 不得删除或改写历史。

> 委托被接受时固定其适用的服务产品版本、客户合同版本、面单服务终局规则及关闭或重开授权规则、
> 产品—渠道映射和渠道账号使用授权；某项依据对该服务形态确实不适用时，必须显式记录"不适用"
> 及原因，不能以缺失代替判断。

「渠道账号使用授权」小节的独立生命周期：

> - 授权建立时必须记录授权双方、账号、适用范围和有效期；只有在有效范围与期间内才能用于新的
>   业务决定。
> - 授权可以在到期前被显式撤销；撤销和自然到期均终止后续新使用，但不删除已经形成的授权证据
>   和交易快照。

Boundaries 一节还把它点名交给了两个下游：`parcel-shipment`「保存所引用的……授权」，
`customs-compliance`「`party-commercial` 只提供……渠道账号使用授权」。另有一句兜底：

> 渠道账号凭据和渠道接入的技术实现不属于本领域文档的决策范围；任何实现都不得把凭据等同于
> 业务授权。

## 差在哪儿不只是「少了一张表」

要紧的是这条规则**今天没有执行器**。

一个租户没有办法登记一笔授权——没有写口。既然册上不可能有行，`parcel-shipment` 那侧
「委托接受时固定渠道账号使用授权」就只有两种走法：要么这一格恒为「不适用」，要么恒为未配置。
两种都不是 CONTEXT 说的那件事：CONTEXT 要的是**显式记录"不适用"及原因**，而「因为册子不存在
所以没有值」不是一次判断，是一次缺席。这与本仓反复记的那个形状同族——**未接线看着像已接线**：
下游读到「没有授权」时，分不出是"这次确实不需要"还是"这个能力根本没建"。

按国际小包业务的实际权重，这一处是四票里最重的：**跨境小包里"客户拿自己的渠道账号、我们代下单"
是主流商业形态，不是边角。** ADR-0039 单独为它立过决策，说明这条边界当时是被认真对待的；缺的
不是共识，是执行器。

## 补与不补，各自的连带

### 若补

- **一张表至少要装**：授权双方（账号持有人 + 被授权的运营责任法人）、账号标识、适用范围、
  有效区间、撤销时刻与撤销依据。撤销与到期是两个终止成因，须分别可辨——CONTEXT 说的是
  「撤销和自然到期均终止后续新使用」，两者后果同而成因不同，合并成一个 `ended_at` 就答不出
  「这笔是被撤的还是自然到期的」。
- **约束要跟上**：撤销时刻与撤销依据「同在或同缺」，形状同本模块已有的耦合 CHECK 先例。
- **不可覆盖是这张表的核心**：CONTEXT 说「已经形成的交易仍保留当时有效的授权依据，不得删除或
  改写历史」。撤销必须是**追加一条终止事实**，不是 UPDATE 掉原行。是否沿用本上下文已有的
  修订式登记（参与方身份四表那套）须一并裁。
- **入不入 `CommercialObjectKind` 封闭集须先裁。** 授权规则（`AuthorizationRuleObject`）已经
  在集内，但那是**运营企业责任法人的授权治理**，与渠道账号使用授权不是一件事。混用会让解析
  按错的类别去找。这一裁与票 04 同形，可一并裁。
- **写侧连带最大的一块不是建表**，是谁在什么时点把授权钉到交易上：`parcel-shipment` 的委托接受
  与面单交易两处都要读它，且 CONTEXT 要求**形成新交易时独立校验当前渠道账号的新使用资格**
  ——不是复用委托接受时的快照。
- 读面连带：管理台需要一张登记页与一张目录页，形状可照 `product_channel_mapping` 那套
  （已有先例：登记写路 + 目录读面 + 显式未配置格）。

### 若不补

- 需要有人明说：首发不支持客户自有渠道账号，只支持运营企业自有账号。**这是一个正当的范围裁决**
  ——但它必须写下来，因为 CONTEXT 现在读起来像是支持的。
- 连带要改的不止一句：Language 词条、Rules 三条硬句、生命周期小节、Boundaries 里给
  `parcel-shipment` 和 `customs-compliance` 的两句，以及 ADR-0039 的适用性。
- 代价是那几条硬句继续空转，且**下游读到的"没有授权"含义不明**（见上）。

## 边界

本票**不建表、不写迁移、不动领域模型、不接端口**，只把差异摆到可裁的形状。领域模型已经建好
且不变量守得住，这一点对三条路都是资产——补的话它是现成的，不补的话它是一份可保留的设计证据。

# 07 ADR 的 Status 行里同一次停用写了两遍：标记前的旧注记与索引注记合一

Category: enhancement
Status: needs-triage
Blocked by: [03](./03-adr-index-and-at-coverage-counts-are-generated.md) 进 main
地盘：各 ADR 的 `Status` 行（只改这一行）；`docs/adr/README.md` 只经 `go run ./tools/adr-index` 重生成
出处：票 03 完成记录「越权风险点」第 2 条。

## 现状

票 03 把 README 每一行的注记原样搬进对应 ADR 的 `Status` 行，接在 `<!-- 索引注记 -->` 之后。搬之前，不少 `Status` 行自己就写着同一次部分停用，措辞与 README 那一份不同（详略、日期、有没有「**适用场景**」标签都各有出入）；有的还写着接受出处，与 README「**已接受**（……）」那段重说一遍。搬完之后两份住在同一行里，渲染出来同一件事说两遍——例如 ADR-0064 的「部分停用：后果里……正文不改写」前后各一次。

两份为什么没在票 03 里合：哪一份为准要逐份判，不是机械活；而票 03 的不变式是「注记文字不丢不改」，合并必然改字。

## 要什么

- 逐份看标记前段与索引注记重复的那些 `Status` 行（票 03 完成记录里点了号与取证 SHA），把同一次停用合成一份、留在索引注记里：两份措辞里只有一边有的事实（日期、被停条款原句、适用场景、其余各条不变）并进去，不丢。
- 标记前段写的是**本记录停用了谁**（去向）的，不是重复，不动。
- 接受出处重说的那些同此处理，或判为不合（索引里要露出接受出处、Status 前段是原始记录），二选一写进完成记录。
- 合完重生成 README；与合之前的 README 逐条对照，差异只许是合并带来的那几行，结果写进完成记录。

## 不变式

- 只动 `Status` 行；正文一字不改。
- 合并不丢事实：每份合并前后两版并排贴进完成记录或评审记录，供核对。

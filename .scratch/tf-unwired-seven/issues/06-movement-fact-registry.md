# 实际移动事实登记册——八例编排里没有一例处理实际移动

Category: enhancement
Status: draft
Blocked by: 01

## 现状（锚 `9d6063c`）

`RecordMovementFact` 在 `domain/load_assignment_movement.go`，有完整实现与测试：事实身份、
班次、种类、地点、来源、版本、发生时间、门禁放行引用，以及更正关系（`corrects` / `correctedAt`）。

**TF 八例编排里没有任何一例处理实际移动。** 无表、无端口。

而 `transport-fulfillment` 的 CONTEXT 开篇就把「实际移动」列为本上下文管理的对象之一：

> 本上下文管理国际小包网络中的场外揽收、节点间运输、具体班次与容量、外部运输委托、运输交接、
> **实际移动**和末端派送。

## CONTEXT 的相关纪律

> 路由计划和计划履约段不预占班次、容量或运输资源。运输委托、订舱、承运接受和装载分配表达
> 执行准备，也不能提前制造实际履约段。

> 车辆故障、运输中断、失联、疑似丢失或异常案件建立本身不转移控制，也不自动结束实际履约段。

> 协作事项取消、替代或缩小范围时，停止尚未消耗的委托、订舱、预占和分配范围；**已经形成的
> 权威交接、实际移动和费用责任继续保留**。

最后一句是这一票的核心：实际移动是**已发生的事实**，上游意图取消不能抹掉它。库面因此必须
不可回写，更正走版本链。

## 要做的

**表**：新开迁移。移动事实的更正关系（`corrects` / `corrected_at`）成对在场或成对缺席。
门禁放行引用（`GateClearanceReference`）可空——CONTEXT 说门禁出发可阻断，但不是每次移动都
经门禁。**可空与「没有门禁」要分得开**，别用空串表达两种含义。

**端口 + 适配器**。

**编排**：需要一个登记用例。它与票 01 的段有关系——移动事实发生在某个实际履约段的控制期内，
所以标 `Blocked by: 01`。但**移动事实不结束段**（CONTEXT：中断不结束），两者的关系是引用
不是状态机。

## 陷阱

- **别让移动事实推导控制转移。** CONTEXT 逐项列举过：扫描、车辆到场、物理装载都不能替代
  控制边界。移动是段**内**的事实，不是段的成立或结束依据。
- 别把「装载分配」（意图）与「实际装载」「实际移动」（事实）合并。领域已经把意图与事实分开，
  库面合并会让那条分立失效。

## 完工判据

`RecordMovementFact` 有生产调用路径，棘轮基线那一行可剪。

# 按 client 的可观测性：`outcome` × client 维、`requestId` 对账、暂停出声

Category: enhancement
Status: draft
Blocked by: ADR-0139 接受；ADR-0140 接受（`requestId` 进问题详情）

取证基线 `a608536d`。

## 问题

ADR-0022 Consequences 要求「监控按 `outcome` 维度统计，不按状态码」，`UC-PS-001` 可观测性一节要求分别统计各类结果且「原因维度引用稳定规则或判断标识」。这些今天都没有调用方维：一个 `REQUEST_NOT_ACCEPTED` 的尖峰看不出是哪个客户系统在发错报文。对外 API 的支持工作有一半是「你的哪次请求、答了什么、为什么」，没有 client 维与 `requestId` 对账，支持只能翻日志。

## 做什么

1. **指标加 client 维。** 首方渠道 Intake 校验过之后，把渠道行的 client 标识（不是租户、不是客户账户——那两维基数高且是隔离语义）放进请求上下文；传输层按 `outcome` × client × 路由模板计数。操作者族按操作者主体维同形，不在本票（先做客户族，形状可复用）。
2. **`requestId` 是对账句柄。** ADR-0140 Decision 三把 `middleware.RequestID` 的值放进问题详情；本票把它也放进 2xx 响应的一个头（`X-Request-Id` 或契约定的名字），并保证服务端日志与投递账（ADR-0142）都带它。集成方报障只需给 `requestId` + 时间，不需要脱敏请求体——`docs/api` 方案稿对外文档必备十项的第十项由此有落点。
3. **三格与限流的计数。** ADR-0139 Decision 四的三格、票 02 的 `429` 两格各按 client 维计数；第二格（`401`）没有 client 维（校验没过、不知道是谁），按 `iss` 是否匹配分两格计数即可——「我们发行方签的但过期」与「根本不是我们签的」恢复动作不同（换令牌 vs 查配置 / 疑似攻击）。
4. **出声的三件事进同一条通道**：webhook 订阅暂停（ADR-0142 Decision 七）、限流命中（票 02）、渠道行即将出生效区间——都是「租户运营要去做一件事」的信号，管理台客户渠道页一处列出，不散在三页。
5. **不做**：把 `outcome` 维度做成自由文本；按客户账户维出指标（隔离语义进指标标签是泄露面，ADR-0022 「不使用自由文本聚合」的同一顾虑）；SLA 数值的定义（商业参数，PC owner）。

## 验收点

- 同一 client 的一次提交，指标里能按 `outcome` × client 找到那一次；`requestId` 在响应头、服务端日志、（若触发）投递账三处一致，测试钉住头与日志两处。
- `401` 两格计数按 `iss` 匹配与否分开，测试各一。
- 管理台客户渠道页显示该 client 最近的三格 / `429` / 订阅暂停信号（读面，走 ADR-0077 通例）。

## 归 owner 复核

- client 标识进指标标签的基数是否可接受（client 数 × 路由模板数 × `outcome` 数）——部署 / 运维 owner；不可接受时降到租户维并记下代价。
- SLA 与错误预算的定义——商业参数，不在本票。

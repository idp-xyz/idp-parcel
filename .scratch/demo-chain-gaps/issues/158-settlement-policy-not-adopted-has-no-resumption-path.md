# 158 结算政策没采用的那一拍没有续办路，这件包裹在这一时点的预估客户费用形成不了

Category: enhancement
Status: ready-for-human——2026-10-27 冻结到首个租户上线之后（[上线线与冻结清单](../../launch-line-freeze-2026-10-27.md)，分级 未分级）：不挡上线，代理不认领；解冻看首个租户的真实使用或用户点名。此前 needs-info——2026-10-21 Claude Code 会话立（用户「你作为业务和系统专家自决……解决所有的问题」授权），出自票 [14](./14-buy-request-stuck-after-an-unadoptable-evaluation.md) 隔离评审第 1 条。等 SA、PC owner 裁出路。
Blocked by: SA、PC owner 的裁定（见「要裁的」）
出处：[ADR-0229](../../../docs/adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 越权风险点 13。

## 现象

包裹计费时点到来时，「包裹 → 结算账户」那条链读委托接受时固定的商业闭包，闭包上没有采用结算政策，结算答`未配置`、在 SELL 发起停办册上记停因「结算政策没采用」。这一格的答案在已固定的闭包上：结算这一侧任何一本册的登记都改不了它，运营续办口重跑读到的也是同一份闭包，照样停下。票 14 让别的停因都有了续办路，这一格没有。

## 三类

机制（出路的形状）由 SA、PC owner 裁；采用哪一份结算政策是租户取值，不由产品默认。

## 候选出路

- 重新接受：另立一份委托、另固定一份闭包，SELL 发起停办按新闭包重跑——要裁旧委托怎么收尾、同一件包裹两份委托时计费归哪一份。
- 给已固定的闭包立受控修订形：只允许补上缺的结算政策那一格，修订落库同笔交「参数已登记」，SA 按停因续办——要裁闭包「固定」这一条的例外边界。

## 要裁的

走哪一条（或别的）；裁定之前这一格照实停着、不替租户补任何一格。

## 既有票

none

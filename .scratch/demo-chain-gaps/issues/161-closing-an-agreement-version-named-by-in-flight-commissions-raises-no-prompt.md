# 161 收尾仍被在途委托指名的协议版本时没有任何提醒，换版全凭运营人员看查阅页

Category: enhancement
Status: ready-for-human——2026-10-27 冻结到首个租户上线之后（[上线线与冻结清单](../../launch-line-freeze-2026-10-27.md)，分级 R3）：不挡上线，代理不认领；解冻看首个租户的真实使用或用户点名。此前 needs-triage——2026-10-21 票 [88](./88-actual-fulfillment-not-formed-when-adoption-or-agreement-arrives-late.md) 的作者子代理立（用户「你作为业务和系统专家自决……解决所有的问题」授权）。出自 [ADR-0231](../../../docs/adr/0231-actual-fulfillment-left-unformed-is-caught-up-by-doorbells-and-a-commission-agreement-revision.md) 越权风险点 15。
Blocked by: 无

## 现象

- ADR-0231 解除了 ADR-0233 的运营约束：截止或退役一版仍被在途运输委托指名的供应商协议之后，那些委托此后结束的参与答未生效或已终止，记进实际履约未形成册、查阅页列出，承接口是委托协议换版。
- 承接是事后的：收尾入口不反查运输履约的册（上下文地图不许 PC 读 TF），TF 也没有东西在收尾发生时提醒运营人员「这几份在途委托指名的版本刚被收尾，该换版了」。在有人看查阅页、去换版之前，这些成本一直不形成，BUY 也就一直不发起。

## 要裁的

- PC 收尾成立时交一封门铃（类型、载荷只带协议对象与版本），TF 收到后按（协议对象、版本）反查指名它的在途委托，记一份「待换版」清单或直接把那几份委托列在查阅页上——TF 读自己的册，不越界。
- 或者只在 TF 一侧：未形成册上同一份委托、同一格（未生效、已终止）的条目汇成按委托的一行，查阅页按委托列，不必逐件看。
- 要不要自动换版：不要——换到哪一版、自何时起是运营决定（ADR-0231 决定三），本票只做提醒。
- 三类：门铃与反查是机制；提醒的形状是产品策略。

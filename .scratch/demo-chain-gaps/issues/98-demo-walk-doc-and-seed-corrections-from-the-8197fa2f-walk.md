## 现象（实测，钉 `8197fa2f`，只记 `S`）

**文档照写会撞上（停点一、六）**。这几处不挡路，但动线各条补记只写了自己新增的几格：

- 交接载荷：`已交接`必须带 `releasingEvidence`、`receivingEvidence` 与 `rule`，不得带 `basis`；带了答 `200 SOURCE_NOT_ACCEPTED`，答复不指名原因。动线各条交接补记只列段与节点几格。
- 交接的 `scope`：每次交接该各起一个，`version` 只给更正用。同一 `scope` 换版本号另登，节点作业当它是前一次的更正（机制缺口归 [95](./95-node-operations-reads-a-new-handover-under-the-same-scope-as-a-correction.md)），动线没写这条约定。
- 自营段：票 32 补记写「交接口带 `segment` 立段」再出发，票 62 补记第一步把上海交出与深圳口岸接收合成一次交接；拼起来，出发没有位置。
- 装载分配：重量池的分配量只收整数，`quantityFromMembers` 只许落在件数池；重量行写 `quantityFromMembers` 答 `200 INPUT_NOT_ACCEPTED`，不指名原因。演示包裹 1.5 KG。
- 集成客户端发行方：共享那只答 `invalid_client`。种子 README 只给了 `--force-recreate`，会让别的会话手里的令牌作废；各次实走都另起私有 Dex，README 没写这条路。

**后两段运输准备落空**。那次取证时段起于 20:33Z，即上海当地 04:33：

- `#2`（SZX→SIN）答 `NO_CURRENT_OPPORTUNITY`。种子物化的按日那一班到达 07:00Z，晚于窗口终点 06:00Z。
- `#3`（SIN-HUB→SIN-LM）同样答 `NO_CURRENT_OPPORTUNITY`。

后两段的窗口由前一段到达、节点处理时长与截单、连接缓冲推出，比首段窄。按日一班只接得住极少的提交时刻。

## 完成记录（2026-10-19，Claude Code 作者子代理，分支 `claude-dcg98`，基于 `5f0aa66d`）

### 接票时核实

- **停点六各条读码成立**。`FormTransportHandover` 对`已交接`要求双方证据与规则、不许带依据；编排把它答成 `SOURCE_NOT_ACCEPTED`。装载分配线格式的 `quantity` 是整数，`quantityFromMembers` 只许件数池。种子 README「集成客户端渠道」只给了 `--force-recreate`。共享集成客户端发行方此刻仍答 `invalid_client`。
- **运输准备的成因**：
  - NR `projectCandidateTime` 让每段窗口为〔离开前一节点，离开 + 该连接缓冲〕，离开时刻 = 到达 + 处理时长，过截单则从次日零点起算。
  - TF 候选条件是出发不早于窗口起点、到达不晚于窗口终点（ADR-0201 决定六）。
  - 照这两条逐秒模拟一整天的提交时刻（模拟脚本放在会话临时目录，不入库）：按日一班时，`#2` 只接得住上海当地 09:00–10:00 的提交，`#3` 一刻都接不住。模拟出的窗口与票 18、`8197fa2f` 两次实测的窗口逐格相同。

### 代决（用户授权「你作为业务和系统专家自决……解决所有的问题」）

1. **只加不改**：既有 `01`–`06` 不动（`01`、`02`、`04` 的时刻或身份有真库用例读着），新增周期安排。照票 18 先例，只调演示租户的班期，不改匹配规则；ADR-0201 文末追加补记，把「演示班期」一条用到后两段。
2. **时长与班距**：
   - 深圳→新加坡快班历时 240 分钟，取空运量级；班距不超过 120 分钟，即窗口长减历时。
   - 枢纽→末端穿梭历时 30 分钟，取同城短驳；班距不超过 90 分钟。
   - 按窗口起点在一天里的落点排出最少的班：快班 7 份，穿梭 10 份。逐份去掉都会出缺口，模拟已验。
3. **容量**：快班 2000 KG / 400 PCS，穿梭 800 KG / 160 PCS，都是合成值。两维都声明，因为种子用例要求每份周期安排声明重量与件数两池。
4. **单一权威**：取值与排法只写在种子 README 组成表新加的那一行。动线补记、ADR 补记与 `seed.sh` 注释都只指过去。
5. **种子文件号 `07`–`23`**：协调方给的号段里没有演示种子序号；`data/transport/` 下没有别的在途票，从现有最大号的下一号起。
6. **动线一条补记合写**：停点一、六的写法与三段准备合成一条，挂在第 5 步补记链末尾。各条用「上面……自此读作」改读，带实走证据的旧补记不改写。

   - 第一步 `receivedBy` 写华东场外作业范围 `SYN-OFFSITE-CN-EAST`，不另编一个承运方参与方。TF 不核这一格，演示约定写什么就是什么。

8. **私有集成客户端发行方**：走法写进种子 README「集成客户端渠道」一节，加在「重建」那一条之后。动线只指过去。

### 阻断

- **动线「每次交接用自己的 `scope`」把 `scope` 定成链身份，抢裁了票 95**。原稿说 `scope` 是「这一次交接的链身份」，还用现在时写「节点作业却当它是前一次的更正」。问题有三层：
  - 与 TF 的定义冲突：`HandoverScopeReference` 是「一次交接的共同范围（一车、一批、一次交出）」，认更正链靠更正口的回指；
  - 票 95 要裁的正是「范围是不是交接链的身份」；
  - 在途分支 claude-dcg95 已裁成反方向（ADR-0220），还在动线同一位置追加了自己的补记。

  修法：
  - 这一格改照 TF 的定义写：演示里每次交接各起一个共同范围；`version` 只给更正用，更正走更正口、回指前版。今天范围汇总按 `scope` 计，同一包裹同一 `scope` 首登两次会算两次（票 95 的后继票 99 待裁）。
  - 「链身份」与节点作业的现状描述都删了。
  - 越权风险点 5 改写；「偏离与待裁」写明与 dcg95 冲突时的合法：后进 main 的一支把两处合成一条，不得两边都保留。
  - 原先交给协调方的预案只设想了「TF 首登口拒」那条路，一并作废。

# 92 节点收寄不认交接转入立起的在身控制，同一件实物会有两份控制在身

Status: needs-triage——2026-10-19 票 [62](./62-node-control-is-established-by-handover-in.md) 的作者子代理立（用户「你作为业务和系统专家自决……解决所有的问题」授权）。出自 [ADR-0214](../../../docs/adr/0214-node-control-transfers-out-and-in-on-an-authoritative-transport-handover.md) 文末「补记：票 62 落决定七时的补充裁定」越权风险点「收寄不认交接转入立起的控制」，以及正文越权风险点「不止一份在身控制时不推进」。
Blocked by: 无（改的是收寄编排，地盘属在途会话 idp-parcel-9b，排期要与它协调）

## 现象

- 票 62 起，权威运输交接能在接收节点立 HANDOVER_IN 控制，记在节点控制转移册上。节点收寄（UC-NO-002）认「当前收寄」与控制起点只看收寄册的判断链（`Receptions.FindCurrentJudgmentsAtNode`），看不到转移册上转入立起的控制。
- 后果：一件已经经交接转入某个节点、控制在身的作业实物，若在该节点或别处又被当作客户送站收寄（误扫、退运回原节点、收寄同步滞后），收寄会另立一份 NODE_INTAKE 控制。此后这件实物有两份在身控制，转出停在 `SEVERAL_ACTIVE_CONTROLS`，转入停在 `CONTROL_STILL_ACTIVE`，要靠人对账。
- 同一类问题票 61 之前就有（同一件实物在两个节点各收寄一次），转入只是多了一条来路。

## 要裁的

- **收寄成立时认不认别处在身的控制**：收寄编排在取实物锁之后连转移册上转入立起的控制一起读；同节点在身时并入（不另起控制起点）还是答「已在节点控制之下」，别的节点在身时照立并入账一格，还是拒收。
- **并入的形状**：转入立起的控制没有收寄判断链，并进哪里——收寄册上另起一条「并入交接转入」的判断，还是只保全来源、不形成判断。
- **与 UC-NO-002 的「同一节点并入」（ADR-0199 决定四）怎样合一**：「当前收寄」是否改成「当前在身控制」。
- 三类：判法是机制，不涉租户取值。

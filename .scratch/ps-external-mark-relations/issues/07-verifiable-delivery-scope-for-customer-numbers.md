## 为什么

ADR-0184 决定六：身份核对在租户内按号码取候选，不按交付方自报收窄（自报一错，冲突就变成唯一关联）。代价（复核记录「其二」）：号只在一份已接受委托里在册时，别的实物贴着同号送站会唯一命中那一件。ADR-0195 用歧义信号收住了「另一方已提交」那一格；「另一方从未报过这个号」「另一方委托已被拒绝或撤回」两格仍是已知代价，终局方向是可验证的交付范围。

## 方向裁定（2026-10-19，会话 idp-parcel-9b 代决；细节由本票的 ADR 定）

1. **交付范围是一件可验证的事实，不是自报。** 一次送站属于哪个客户账户，凭两类证据之一：客户账户事先交来的**送站预报**（列出这一批要送的号码或作业实物，经客户渠道提交——首方客户渠道族见 ADR-0139，另一会话的 first-party-api 票在落客户渠道册与铸造器，预报的提交口应挂在那一族上），或在节点当场形成的**交接单**（交付方与客户账户的绑定由客户渠道或运营决定确认）。设备自报的交付方仍只是线索。
2. **范围参与核对的方式：消歧，不收窄。** 候选仍在租户内按号取（ADR-0184 决定六不废）；交付范围只用来判「唯一命中是否证据充分」：唯一命中的那件包裹属于本次送站可验证范围里的客户账户 → 证据充分、关联；不属于或本次送站没有可验证范围 → 这一格怎么答由 ADR 定（候选：待识别并记「范围未证」一类原因，不记冲突）。多候选时范围能否把候选消歧到一件，也由 ADR 定。
3. **授权交付关系是租户取值**：哪个交付方可以替哪个客户账户送货、预报的有效时窗，留空答`未配置`，登记册只登行不填值；演示租户在种子里配。
4. **先改 CONTEXT 再改 UC**：PS CONTEXT「按外部标识核对包裹身份」与 CONTEXT-MAP `parcel-shipment → node-operations` 同句先改，再写 ADR-0212 部分停用 ADR-0184 决定六中与之相抵的句子（照 adr/README 约定），ADR-0195 的歧义信号在范围可验证时怎样并存写明。
5. **拆票**：模型与预报册（NO 还是 PS 拥有，由 ADR 定并写理由）、预报提交口（挂首方客户渠道族，与另一会话协调）、核对时的范围判断、交接单的确认、管理台读面，各成实施票、带阻塞边；与 first-party-api 的依赖写成 Blocked by。

越权风险点：代 PS 与 NO owner 定了「消歧不收窄」与「设备自报只是线索」；owner 复核时看真实租户有没有「无预报的散客送站」需要另一条路。

### ADR-0212 要点：留给 ADR 定的各格

- **预报册归谁**：归 NO，两类证据（预报、交接单）同归一处。理由：UC-NO-002 输入语义契约把交付范围列为交付来源、权威来源是「客户接入或节点现场」；ADR-0184 复核记录「日后」与 ADR-0195 Alternatives (c) 都写由 NO 建模；预报是到货计划，不是服务请求。被否：归 PS（范围判断会有两个所有者）、并进委托（一份预报跨多份委托）。授权交付关系归 PC，是参与方关系的一种；被否：归 NO（会成为参与方关系的第二个所有者）。
- **范围未证那一格**：答`待识别实物已建立`，记候选，不记冲突，不关联，不交意图；另记交付范围核对态（已证 / 未证附原因 / 未配置），是信息格，不进 outcome。被否：记身份冲突（缺证据不是有反证，记了就接不上重核）、归收寄判断待确认（控制确实建立了）、照旧关联只打标记（错关联会进 PS 采用与 VE 投影）、开人工认定口（补救走交接单，让授权交付关系始终在环里）。
- **多候选能否消歧**：能，限有可验证交付范围时——只数范围相容的候选，恰一个且没有范围内信号即唯一命中；全部候选照记。被否：有范围也不消歧（不同客户账户同号是常态）、按范围收窄候选（ADR-0184 决定六不废）、PS 回传候选的客户账户（违背 CONTEXT-MAP）。
- **预报的确认路**：客户账户经首方客户渠道族提交，提交即自证；NO 签发预报标识；范围落到所列号码，号码级，而不是账户级；有效时窗是租户取值，空册答未配置。被否：账户级（出示错预报时会误消歧）、客户自带预报号（会跨客户撞号）。
- **交接单的确认路**：节点经作业事实登记开立、归入、关闭；逐客户账户的绑定由客户渠道确认或否认（只对已关闭的），或由运营决定「送站交接确认」依 PC 的授权交付判断确认（是 / 否 / 未配置；交付方是本人答是）；全部声称的客户账户都确认才成立。被否：部分确认即成立、运营决定不查授权交付关系、交付方自报对上授权交付关系就自动成立。
- **与歧义信号并存**：没有范围时 ADR-0195 一字照旧；有范围时信号只认范围内客户账户的`已提交`声明。被否：有范围时信号仍在租户内认、有范围时丢掉信号。
- **其余定下的**：
  - 渠道包裹件号的命中恒范围相容；范围相容比的是关联的适用范围。
  - 交付范围依据引用进来源文档、不进内容指纹。
  - 重核按此刻证据重算范围，预报时窗按原业务时间判；新增「交付范围成立」自投门铃；预报不需要触发。
  - 落地次序：翻转与演示动线改为先交预报同一笔落。

### 发现的冲突与张力（不自行改裁，留推送方与 owner）

1. **CONTEXT-MAP「不交号码的分配方、客户账户或委托」与方向裁定「范围参与核对的方式：消歧，不收窄」那一条的张力。** 判「唯一命中的那件包裹属于本次送站可验证范围里的客户账户」，必须让 PS 拿客户账户去比；范围只有一个客户账户时，「范围相容」等于告诉 NO 候选在该账户的编号空间里。ADR-0212 决定四把它读作「PS 不交出任何 NO 没给过的客户账户」，并列进它的越权风险点「范围相容在单账户范围下，等于告诉 NO 候选所属的客户账户」。CONTEXT-MAP 那句原文保留，加了「所比的客户账户由节点作业自己给出」。

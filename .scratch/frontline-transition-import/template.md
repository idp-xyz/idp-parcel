# 一线过渡汇总模板填写说明（收寄 `INTAKE-1` · 集运 `CONSOLIDATION-1`）

Category: chore
Status: 供 MCP-1 转客户内勤；示例值全为合成值（`SYN-` 前缀），不含任何真实实例

过渡期内勤用这两份模板分别汇总现场**收寄**事实与**装箱封签**事实，交开发方受控运维导入。
机制与期限见 [ADR-0089](../../docs/adr/0089-frontline-transition-controlled-import-with-structural-sunset.md)，
本文只讲怎么填。**这是过渡办法，到 2026-12-31 为止**；之后导入口启动即拒，现场作业回到
一线作业客户端。

机器侧的同一份形状在 `cmd/parcel-frontline-import/testdata/intake-v1.csv` 与
`consolidation-v1.csv`。两边换列必须同时换模板版本号——同一个号下两种列形状会让落库的
来源标记说谎。

## 文件怎么存

下面几条两份模板通用。**两类事实各存各的文件**：收寄口不认集运的列，集运口也不认收寄的列，
混在一份里整批拒。

- **CSV，UTF-8。** Excel 里选「另存为 → CSV UTF-8（逗号分隔）」。存成默认的「CSV」会因编码
  被整批拒绝（报「不是合法 UTF-8」）。文件头的 BOM 不影响，不必特意去掉。
- **一份文件一个批次。** `batchRef` 每行都写，且必须全表一致；两个批次请存两份文件。
- **列可以换顺序，但不能多、不能少、不能重复。** 列名即接口，打错的列名不会被忽略，整批拒绝
  并告诉你缺哪列多哪列。
- **表头之外至少要有一行数据。** 只有表头会被拒。

## 收寄模板（`INTAKE-1`）

### 逐列

| 列名 | 必填 | 格式 | 示例（合成值） |
|---|---|---|---|
| `templateVersion` | 是 | 固定 `INTAKE-1` | `INTAKE-1` |
| `batchRef` | 是 | 批次号，全表一致 | `SYN-BATCH-20260908-AM` |
| `factRef` | 是 | 纸单流水号，批内唯一 | `SYN-SLIP-0001` |
| `operator` | 是 | 录入这一行的内勤 | `SYN-CLERK-A` |
| `node` | 是 | 作业场站 | `SYN-NODE-SZX` |
| `deliveredBy` | 是 | 送货来的客户或授权交付方 | `SYN-CUSTOMER-1` |
| `handlingUnit` | 是 | 现场能区分的作业实物号 | `SYN-HU-0001` |
| `mark` | 见下 | 包裹外部标识（客户单号、条码） | `SYN-MARK-0001` |
| `claim` | 是 | `RECEIVED` / `REFUSED` / `SCAN_ONLY` 三者之一 | `RECEIVED` |
| `evidenceRef` | 见下 | 纸面接收凭证号 | `SYN-RECEIPT-0001` |
| `refusalReason` | 见下 | 拒收原因 | `SYN-REASON-PACKAGING-DAMAGED` |
| `occurredAt` | 是 | 现场实际发生时刻，**带时区** | `2026-09-08T09:15:00+08:00` |

**`node`、`deliveredBy` 等标识用哪套编码由实施时约定**，本说明不给默认值——填错的标识
系统认不出来，而系统替你猜一个只会把事实记到别处。

`occurredAt` 抄纸单上的现场时刻，**不要填录入时刻**。系统另有一格记「什么时候导入的」，
两者分开正是为了让这批事实以后还能说出现场什么时候发生的。格式必须是
`2026-09-08T09:15:00+08:00` 这样（日期和时间之间是字母 `T`，末尾 `+08:00` 是时区）；写成
`2026/09/08 09:15` 会被拒。

### 三态各自填什么

`claim` 记的是**现场观察到什么**，不是判断收没收成。判断由系统按观察加身份核对得出。

| `claim` | 什么时候用 | `mark` | `evidenceRef` | `refusalReason` |
|---|---|---|---|---|
| `RECEIVED` | 明确收下了，有纸面接收凭证 | 必填 | **必填** | 必须留空 |
| `REFUSED` | 明确拒收 | 必填 | 必须留空 | **必填** |
| `SCAN_ONLY` | 只扫了码、没有明确接收凭证 | 必填 | 必须留空 | 必须留空 |

三条「必须留空」不是宽松要求，填了会被拒而不是被忽略：

- **`REFUSED` 行的 `evidenceRef` 无处可登**——未收寄的记录里只留拒收原因。静默丢掉会让你
  以为凭证登进去了。
- **`SCAN_ONLY` 行有接收凭证就不是只扫码**，请改填 `RECEIVED`。
- **`RECEIVED` 行不该有拒收原因**——两件事不会同时发生，同时填说明这一行抄错了。

**没有纸面接收凭证的就填 `SCAN_ONLY`，不要为了让它「过」而编一个凭证号。** `SCAN_ONLY`
是一条真实、完整、会被保全的记录，只是不建立实物控制；编出来的凭证号是一条假事实，
而且改不掉。

## 集运模板（`CONSOLIDATION-1`）

装箱封签用另一份模板，**一行一个动作，按现场发生的先后排行**：开启在前、装入在后、封装再后。
导入按行序推进，不按时间重排——同一分钟里两行的先后只有纸单上的顺序说得清。

### 逐列

| 列名 | 必填 | 格式 | 示例（合成值） |
|---|---|---|---|
| `templateVersion` | 是 | 固定 `CONSOLIDATION-1` | `CONSOLIDATION-1` |
| `batchRef` | 是 | 批次号，全表一致 | `SYN-BATCH-20260908-PM` |
| `factRef` | 是 | 作业单流水号，批内唯一 | `SYN-WORK-0001` |
| `operator` | 是 | 录入这一行的内勤 | `SYN-CLERK-A` |
| `performedBy` | 是 | 现场动手装箱、封签的人或岗位 | `SYN-PACKER-1` |
| `action` | 是 | 六种动作之一，见下 | `SEAL_UNIT` |
| `unitRef` | 是 | 集运单元**实例**号——这一次用这个笼/袋/箱的编号，不是载具本身的号 | `SYN-CU-0001` |
| `assetRef` | 见下 | 载具引用（笼车、袋、箱） | `SYN-CAGE-01` |
| `memberUnit` | 见下 | 装入或取出的作业实物号 | `SYN-HU-0001` |
| `sealRef` | 见下 | 封签号 | `SYN-SEAL-0001` |
| `basisRef` | 见下 | 封装、开封或处置转移的作业依据 | `SYN-BASIS-SEAL-01` |
| `evidenceRef` | 是 | 纸面作业单号 | `SYN-WORKSHEET-0001` |
| `occurredAt` | 是 | 现场实际发生时刻，**带时区**，格式同收寄 | `2026-09-08T14:10:00+08:00` |

`performedBy` 与 `operator` 不是一回事：前者是现场做这件事的人，后者是把纸单录进模板的人。
就算是同一个人也两列都填。`unitRef`、`assetRef`、`performedBy` 用哪套编码由实施时约定，
本说明同样不给默认值。

### 六种动作各自填什么

| `action` | 什么时候用 | `assetRef` | `memberUnit` | `sealRef` | `basisRef` |
|---|---|---|---|---|---|
| `OPEN_UNIT` | 开始用一个笼/袋/箱装货 | **必填** | 留空 | 留空 | 留空 |
| `ADD_MEMBER` | 把一件实物装进去 | 留空 | **必填** | 留空 | 留空 |
| `REMOVE_MEMBER` | 把一件实物取出来（封装后要先开封） | 留空 | **必填** | 留空 | 留空 |
| `SEAL_UNIT` | 封装并上封签 | 留空 | 留空 | **必填** | **必填** |
| `UNSEAL_UNIT` | 授权开封 | 留空 | 留空 | 留空 | **必填** |
| `CLOSE_UNIT` | 终局关闭这个实例 | 留空 | 留空 | 留空 | 还有成员没取出时填处置转移依据；已全部取出可留空 |

「留空」是硬要求，填了会被拒而不是被忽略——填了本动作用不着的格，说明这一行抄错了动作。

- **同一个笼/袋/箱再次投入使用是新实例**：`unitRef` 换新号，`assetRef` 填同一个载具号。已关闭的
  实例不能重开。
- **重新封装不覆盖旧封签**：封装后要改成员，先一行 `UNSEAL_UNIT`，再 `ADD_MEMBER` /
  `REMOVE_MEMBER`，最后一行 `SEAL_UNIT` 用**新**封签号。旧快照与旧封签都保留，这是有意的。
- 全部成员取出后再 `CLOSE_UNIT`；成员还在里面又要关闭的，`basisRef` 填处置转移依据，
  没有依据就不能关。

### 集运行的「被拒」多出几种

除了下一节那种「同一 `factRef` 换了内容」，集运行还会因为下面几种原因被拒。它们**都是重跑
同一份不会变、要核对纸单改文件的**：

- **单元不在册**：`unitRef` 抄错，或 `OPEN_UNIT` 那一行排在了后面。
- **成员在别的单元里**：报文会点名对方单元。同一件实物同一时点只能在一个单元里，先从那里
  `REMOVE_MEMBER`，不是重试。
- **这一步现在做不得**：封装态不能装入、取出或关闭（先开封）；未封装不能开封；空单元不能
  封装；还有成员却没有处置依据不能关闭；重复装入或取出不在里面的成员。核对动作与行序。

**同一个实例号已由别的来源开过**（或同一成员已由别的来源装入）不是被拒：那一行答「重放」，
什么也不记，无需处理。

## 导入之后

两份模板的导入结果读法相同。运维会把逐行结果发回来，每行一句，末尾一行汇总。四种去向对应
四种动作：

| 去向 | 含义 | 你要做什么 |
|---|---|---|
| 已落地 | 这一行的事实已记录 | 无 |
| 重放 | 这一行之前就登过，内容一致；或（集运）这件事已由别的来源做过 | 无。重复提交同一份文件是安全的 |
| **被拒** | 同一个 `factRef` 之前登过，但内容不一样；集运行另有几种，见上 | 核对纸单。**若确实是另一件事实，换一个 `factRef`** |
| **未决** | 没能形成答案，什么都没记 | 无需改文件，等运维重跑同一份 |

**`factRef` 是这条事实的身份，不是行号。** 同一张纸单第二次录入会被认成重放（正确）；
拿一个用过的号去登另一件实物会被拒（也正确）——系统绝不覆盖已登的内容。写错了内容
想更正，**不是**改文件重登同一个号，而是按更正流程走，导入口不做覆盖。

「未决」在过渡期会**大量出现在收寄的 `RECEIVED` 行上**，这是已知情况：包裹身份核对所依赖
的那一段能力还没建成，`RECEIVED` 行今天一律未决。`REFUSED` 与 `SCAN_ONLY` 两类不经身份
核对，照常记录。运维会在每次导入开工前把这一点打印出来。集运行没有这条缝，正常情况下不会
未决。

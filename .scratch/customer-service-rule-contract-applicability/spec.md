# 客户服务规则「挂客户合同」的一格接入：合同优先解析 + 行级继承产品底座

Category: enhancement
Status: in-progress——2026-10-10 通道 1 按 /to-tickets 发布子票 02–06（拆法作者通道 3，通道 1 经用户授权认可），本 spec 转为跟踪容器，自身不再有可执行工作。此前：ready-for-agent
Blocked by: 无。设计决策已全部裁毕，权威记录为 [ADR-0176](../../docs/adr/0176-customer-service-rule-contract-tier-selection-and-inheritance.md)；建模票 [01](issues/01-service-rule-keyed-by-product-cannot-express-per-customer-claim-terms.md)。

## Problem Statement

租户买的是同一款服务产品，但大客户协议里通行**差异条款**：「未尽事项以产品标准为准，少数条款另定」。今天的产品做不到这件事——客户服务规则的适用声明虽然早已两格封闭恰一（随服务产品 / 随客户合同），但**挂合同的那一格没有可被选中的路**：

- 同一范围一旦并存「挂产品的一版」与「挂合同的一版」，闭包解析直接答`适用冲突`——合同定制版发得出去、选不出来。
- 消费侧（索赔资格）点读正文后不核「这一版挂的是不是我手上这份合同」，选择问题一旦解开，挂合同 01 的版本会被合同 02 的索赔照读。
- 合同版对某一种期限 / 某一种索赔类型无行时的行为未裁：回落产品版还是如实「该格无客户差异」，没有答案。

于是「给某户定制索赔时限与材料」只能走歪路：伪造一条产品链（新规则包 → 新产品），把客户差异写成产品差异——服务产品目录混入客户层。

## Solution

按 ADR-0176 把挂合同的一格**接入**既有机制，不新建维度、不改领域语言：

- **合同优先解析**：客户服务规则与结算政策同排第二段（合同解出之后）。闭包先取「壳 `references` 恰指名闭包解出的客户合同版本」的规则版本；没有时取挂服务产品的候选；同层多候选=`适用冲突`，两层皆零=`无适用依据`。闭包仍**唯一采纳**一版。
- **行级继承 + 版本级回落**：采纳合同版时，VE 经 PC 新的**层次读口**一次拿回合同版正文与同范围产品底座版正文（含各自在场标志），按行拼接——合同版有行用合同版，无行取底座版该行；两层皆无照既有「未登记」一维如实答。
- **只收紧不删减**：合同版行只能是继承（无行）或收紧（有行且更严）；不提供显式空行表达删减。
- **消费侧按合同点核**：正文挂合同必须等于查询携带的合同，不等落既有 `ErrUntranslatableAnswer`；挂产品的版本不核，由解析唯一性保证。

对租户的可见效果：同一产品目录不变，给合同 02 发一版只改首次索赔时限的定制规则，该户索赔答定制时限、其余各行继承产品标准；合同 01 的索赔不受影响。

## User Stories

1. 作为租户商务运营，我想给某份客户合同发布一版挂合同的客户服务规则，so that 大客户协议里的差异条款有正规表达路径，不必伪造产品链。
2. 作为租户商务运营，我想合同版只写差异行（如仅首次索赔时限），其余行自动继承同范围产品版，so that 不必把产品条款整本抄一遍再改两处。
3. 作为租户商务运营，我想在合同版里收紧材料要求（清单更短即更严的收紧方向按既有纪律），so that 差异条款只收紧不放宽的商务纪律被系统守住。
4. 作为租户商务运营，我想发布挂合同的版本时若同层已有另一版挂同一合同，系统答`适用冲突`并拒绝，so that 同一合同不会有两版规则互相竞争。
5. 作为租户商务运营，我想合同版与产品版在同一范围并存而解析不再直接冲突，so that 产品标准与客户差异可以分层共存。
6. 作为租户客服代表，我想合同 02 项下的索赔按该合同定制时限判断资格，so that 合同承诺什么系统就判什么。
7. 作为租户客服代表，我想合同版没写的期限行自动取产品标准，so that 差异条款「未尽事项以产品标准为准」的惯例被系统如实执行。
8. 作为租户客服代表，我想合同版与产品版对某一格都无行时系统答「未登记」而非编造默认值，so that 系统不替租户发明承诺。
9. 作为租户客服代表，我想系统绝不把另一份合同的规则用到我手上这份合同，so that 跨户串读不可能发生。
10. 作为系统整合方，我想解析键登记面不加新键就能吃到合同优先，so that 既有登记（含演示种子）无需迁移。
11. 作为系统整合方，我想闭包对客户服务规则仍唯一采纳一版，so that 「每种必需商业依据必须唯一适用」的硬句与续办机制不破。
12. 作为审计角色，我想已受理委托仍按受理时冻结的版本读取，so that 后续发布不影响在途索赔的资格判断。
13. 作为审计角色，我想正文与壳的适用指向不一致在发布写入前与点读后各被把一道关，so that 挂错合同的版本进不了库、进了也读不出。
14. 作为平台开发者，我想规范化文档与摘要零变化，so that PCC-1 与既有已发布版本的摘要重算不受影响。
15. 作为平台开发者，我想消费侧失败落既有错误格（`ErrUntranslatableAnswer` 一族），so that 提供方契约失败面不膨胀、调用方无需处理新错误值。
16. 作为平台开发者，我想解析与拼接的口径只有一套（解析位在 PC、拼接口在 VE 适配器），so that 不出现第二套选择逻辑。
17. 作为演示租户维护者，我想用 SYN- 数据把「合同 02 定制时限 + 继承其余行」走通并记 S 证据，so that 机制半边有可运行演示而不冒充生产依据。
18. 作为租户上线实施者，我想「哪个租户给哪个合同挂哪一版、配哪组值」保持未配置，so that 产品不替租户写死默认。

## Implementation Decisions

全部以 [ADR-0176](../../docs/adr/0176-customer-service-rule-contract-tier-selection-and-inheritance.md) 六条 Decision 为准，此处只列落地位与接口形状，不复述判据：

- **PC 域解析**：`resolutionOrder` 把客户服务规则与结算政策同排第二段；新增解析分支（合同优先候选 → 产品回落候选 → 同层多候选`适用冲突` / 两层皆零`无适用依据`）；闭包唯一采纳形态不变；解析键不新增维、不预选合同维（镜像结算政策的既有纪律）。
- **PC 层次读口（新）**：ports + postgres + application 同族于既有客户服务规则点读口——一次调用按（租户、范围、合同版本、锚点）返回（合同版正文、产品底座版正文、各自在场标志）；底座版在读口内选「同范围挂服务产品、锚点生效」的版本，多候选照`适用冲突`纪律答。既有单版点读口保留（受理时冻结引用仍走它）。
- **VE 适配器**：点读后核「正文挂合同 = 查询携带合同」，不等落 `ErrUntranslatableAnswer`；按行拼接口在此侧（合同版有行取合同版，无行取底座行，皆无落「未登记」）；VE 不自行解析。
- **只收紧不删减**：不提供显式空行；判据与保价条件、交付条件的「合同仅可收紧」纪律同源。版本级「至少一行」门禁（ADR-0104 Decision 三）继续成立。
- **规范化与摘要零变化**：选择靠壳 `references` 既有键，正文双键既有；不新增规范化文档键，PCC-1 不动。
- **两道适用核分层不变**：`ConsistentCustomerServiceRuleApplicability`（壳 ↔ 正文，发布前 + 点读后）与新的「正文 ↔ 查询合同」核分属两层、各守一边。
- **不改 CONTEXT 语言**：本次零新词；消费侧翻译分格全部落既有格（`适用冲突` / `无适用依据` / 未登记 / `ErrUntranslatableAnswer`）。

## Testing Decisions

- 只测外部行为：闭包答什么（采纳哪版 / `适用冲突` / `无适用依据`）、层次读口返回什么（两份正文 + 在场标志）、VE 每维答什么（定制值 / 继承值 / 未登记 / 错误格）；不测分支内部结构。
- **缝一（既有，首选）：PC 域闭包解析测试族。** 先例：结算政策与信用依据的解析测试（「闭包携带采纳的 ××」「同范围双命中是冲突」「零命中是无适用依据而非默认」「解析键不得预选合同维」）。新分支的合同优先、产品回落、同层冲突、两层皆零在此缝镜像先例写法。
- **缝二（既有）：VE 适配器装配测试族。** 先例：`claim_service_rules_resolution_test.go` 已覆盖「采纳无合同 / 无规则 / 正文未登记 / 他租户闭包」各失败格。新增三族挂同一缝：合同版接进后按行拼接、合同版无行取底座行、正文挂合同 ≠ 查询合同落 `ErrUntranslatableAnswer`。
- **缝三（新，唯一新增）：层次读口契约测试。** 先例：客户服务规则 postgres 往返测试族（往返、租户绑定、坏数据拒绝、目录列表）。新读口镜像其写法：在场标志正确、底座多候选照冲突纪律答、租户隔离。
- 不新增 HTTP 缝与演示脚本缝；演示种子（SYN-TENANT-01 + `SYN-` 数据）只作 S 证据，不算测试。

## Out of Scope

- **租户取值**：哪个租户给哪个合同挂哪一版、配哪组时限与材料——留空、如实答未配置；演示配置只记 S。
- **管理台表单**：服务规则表单的合同格录入与预览键，归实现票自测。
- 不改 `CONTEXT.md` 领域语言；不动闭包唯一采纳形态；不给闭包开双槽（同时采纳两版）。
- 不支持删减表达（显式空行）；不在 VE 做产品核（经回指解产品被 ADR-0176 否决）。
- Bento 持久化闸门与其余未决 `BD-*` 不在本 spec。

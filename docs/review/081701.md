重新核对到当前 HEAD `d40b03a`。结论很明确：

> `idp-parcel` 已经是较强的国际小包领域机制与持久化骨架，但还不是可运行、可配置、可交付的生产系统。

**关键问题**

1. **P1：Dispatcher 无法启动。**  
   [assemble.go](/D:/tops/idp-parcel/cmd/parcel-dispatch/assemble.go:28)始终返回 `errDispatcherNotWired`，但 [ADR-0049](/D:/tops/idp-parcel/docs/adr/0049-publish-channel-is-in-process-delivery-until-load-evidence.md:20)已经决定采用进程内直投。当前 46 个 Outbox handoff 只会积压，不会形成下游业务结果。

2. **P1：业务 API 实际不可用。**  
   [endpoints.go](/D:/tops/idp-parcel/cmd/parcel-api/endpoints.go:16)返回空清单，运行时只有 [router.go](/D:/tops/idp-parcel/internal/platform/httpapi/router.go:39)中的 `/healthz` 和 `/version`。委托提交、收寄、交付、追踪、索赔、关务结果全部无法从进程外调用。

3. **P1：跨上下文链路没有闭合。**  
   当前约 55 种事件类型、46 个生产 handoff，只有一个 `AcceptanceConsumer`，而且它也没有生产装配。数据库连接、Outbox/Inbox、Publisher、消费者路由表和关闭释放逻辑尚未形成组合根。

4. **P1：Go 模型与数据库约束不一致。**  
   Go 已支持 9 类商业对象，[commercial_version.go](/D:/tops/idp-parcel/internal/partycommercial/domain/commercial_version.go:100)包含 `CREDIT_POLICY` 和 `AUTHORIZATION_RULE`；SQL 仍限定 1～7，[0001_commercial_publication.sql](/D:/tops/idp-parcel/migrations/party_commercial/0001_commercial_publication.sql:36)会拒绝这两类写入。应新增不可变 migration，不能直接修改已发布迁移。

5. **P1/P2：索赔期限历史可能被并发覆盖。**  
   [claim_recovery.go](/D:/tops/idp-parcel/internal/visibilityexception/adapters/postgres/claim_recovery.go:478)采用删除全部历史再重插，没有乐观锁。旧快照可能擦掉已批准延期。新增的“等待补充”第三态目前也只到领域和数据库，[handle_claim.go](/D:/tops/idp-parcel/internal/visibilityexception/application/handle_claim.go:273)仍按终局二态编排。

6. **P2：接受事件存在静默吞掉风险。**  
   [acceptance_consumer.go](/D:/tops/idp-parcel/internal/networkrouting/adapters/inbox/acceptance_consumer.go:141)未强制校验 `State` 和 `SubmissionVersion`；[route_on_acceptance.go](/D:/tops/idp-parcel/internal/networkrouting/adapters/parcelshipment/route_on_acceptance.go:82)会把空或未知状态当成无需路由并标记已处理。

7. **物流产品仍未形成完整可执行配置。**  
   当前 [ServiceProduct](/D:/tops/idp-parcel/internal/partycommercial/domain/service_product.go:47)只有商业版本和 `NETWORK_SERVICE` 形态。服务范围、准入、主备线路、SLA、清关、轨迹、赔付、退件、容量和质量规则虽然在不同上下文已有机制，但尚未形成可发布、可持久化、可完整加载的产品版本组合。[CommercialAuthority](/D:/tops/idp-parcel/internal/partycommercial/adapters/postgres/commercial_authority.go:22)也明确承认价格、结算等政策持久化尚未闭合。

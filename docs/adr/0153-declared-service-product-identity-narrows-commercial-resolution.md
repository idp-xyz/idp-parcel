# ADR-0153: 委托声明的服务产品身份收窄商业解析——同一范围多个产品不再必然`适用冲突`；收窄的是对象身份不是版本

## Context

演示动线按种子原样灌时，受理链停在商业依据第一阶段：闭包 `适用冲突`，冲突依据是服务产品。发布批里 `SYN-PROD-CN-SG-EXPRESS` 与 `SYN-PROD-CN-SG-ECON` 同在 `SYN-SCOPE-01`。解析键登记面按（租户，客户账户）一行，范围写死；委托声明的服务产品只进摘要、不进键。闭包对每项依据都按范围独立解析，同一范围两个产品就答`适用冲突`。

一产品一商业范围能消掉这个冲突，但会逼租户把同一份合同、接单规则包、结算政策按产品复制。商业范围在 party-commercial 是服务、费用或控制范围，同一范围覆盖多个产品是常规形态。

## Decision

**一、取「委托声明的服务产品身份收窄服务产品候选」，不取「一产品一商业范围」。** UC-PC-002「同一客户的不同非重叠范围」说的是范围之间，不是同一范围里的产品之间。

**二、收窄的是对象身份，不是版本。** 选中哪个已发布版本仍按锚点解。[ADR-0080](./0080-commercial-closure-resolves-the-contract-first-and-keys-settlement-by-it.md)「绝不指定应当选中哪个商业版本」不被碰。`CommercialBasisQuery` 只携带引用，头注「绝不指定应当选中哪个商业版本」照样成立；产品身份不是版本。

**三、纪律与结算、信用选择器同形。** 这一维只在必需依据含服务产品时可在场，其余必缺。在场即按身份收窄；不在场照旧按范围解析——同一范围多个产品仍答`适用冲突`，那是如实的答案，不补默认产品。声明的产品在该范围没有已发布版本，答`无适用依据`。

**四、正文指名了服务产品的成员随之收窄，没指名的不受影响。** 候选里凡正文指名了另一个服务产品的一律落选；指名了委托声明的那个，或根本没指名服务产品的，照旧参选。收窄之后仍事后核对指名引用。声明的产品没有配规则包时，规则包那一项答`无适用依据`。初稿写「其余成员不另收窄，指名不同即`适用冲突`」不成立：同一范围两个产品各配一份规则包时，只收窄服务产品，规则包那一项仍会冲突；现行代码对指名不符答的是`解析未决`，不是冲突。

## Consequences

- 解析键（闭包键与逐项键）多一维：委托声明的服务产品身份。不声明时这一维缺席，已固定解析的指纹不因本维出现而改口。
- 读法归 parcel-shipment：从提交版本按封闭条目名读出，不在适配器里拼条目名。登记面仍只折（租户，客户账户）那一行；声明由另一协作者叠到已折出且必需依据含服务产品的键上。
- 闭包落库带上这一维，落在既有快照 JSON 里（声明时才写出）。不另开迁移：这一维是闭包键的一部分，键已经在那份快照里；不声明的快照不多出这一键，内容摘要不变。
- party-commercial `CONTEXT.md`「商业依据解析」与 UC-PC-002「解析键至少包含」按本记录改。

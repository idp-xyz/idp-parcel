# ADR-0002: 国际小包采用独立数据、运行与发布边界

Status: Accepted
Date: 2026-07-29

## Context

即使产品和领域模型已经独立，共用业务数据库、运行部署或发布周期仍会使国际小包与既有货主 TMS 在数据变更、故障影响和交付节奏上相互牵制。系统需要在共享运行边界和自治运行边界之间作出选择。

## Decision

国际小包拥有独立于既有货主 TMS 的业务数据库边界、运行部署边界和发布生命周期。双方不得直接读写对方业务数据结构，跨系统协作通过显式契约完成。

本决策不规定国际小包内部采用一个还是多个数据库，也不规定其内部部署拓扑或通信技术。

## Consequences

- 国际小包的数据演进、部署和发布可以独立进行，故障和变更影响更容易限定在自身边界内。
- 跨系统业务不能依赖共享表或本地事务，需要处理契约版本、同步延迟和失败恢复。
- 必要的引用数据和业务快照可能在边界两侧分别保存，并需要明确所有权和更新语义。
- 独立运行增加环境、监控、备份和发布治理成本。

## Alternatives considered

- **与货主 TMS 共用业务数据库**：便于直接查询，但会形成数据所有权混乱和高耦合变更。
- **共用部署和发布周期**：初期运维简单，但任一产品的变更都会限制另一产品的交付节奏和故障隔离。
- **独立数据库但允许跨库直接读写**：保留物理分离，却仍然形成隐蔽的数据结构耦合。

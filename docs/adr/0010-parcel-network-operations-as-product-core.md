# ADR-0010: 以小包网络运营闭环作为首发核心

Status: Accepted  
Date: 2026-08-05

## Context

`idp-parcel` 服务的是自己经营国际小包集货、分拣、干线、关务和尾程网络的物流企业。产品必须同时管理客户委托、包裹身份、网络路由、节点作业、运输履约、全程追踪和运营结算；关务是国际业务不可缺少的合规控制能力，但不拥有这些对象的生命周期。

此前以关务应用用例为首发验证锚点，连续形成了关务切片 0 至 6。该工作有效暴露了监管、授权和外部来源风险，但如果继续把它作为产品总体开发主线，会把网络运营产品误读为关务申报系统，并让包裹、节点、运输、可见性和结算能力被动围绕关务组织。

## Decision

首发产品以“客户提交 → 接受前可达性 → 委托接受 → 接受后初始路由 → 有效网络收寄 → 节点作业与运输履约 → 有效交付 → 包裹终局 → 追踪异常 → 运营结算”的网络运营闭环为主线。客户送站与场外揽收分别保留各自源事实所有者；有效交付和包裹终局也分别形成，不能压缩成一个状态。

`customs-compliance` 作为独立限界上下文和关键控制域并行建设：它拥有申报、合规判断、内部限制、监管结果和范围化门禁；只阻断其适用范围内、受监管约束的明确业务动作，不拥有包裹、节点、运输、追踪或结算事实。现有关务切片保留为该控制域的专项工作流，并嵌入端到端主链的适用节点。

首发开发采用跨上下文的纵向业务切片。每个切片必须交付可追溯的业务结果和负向结果；缺少参数时只阻断依赖该参数的生产分支，不把关务或其他单一上下文的未决状态扩大为整个产品不可用。

## Consequences

- 产品核心与国际小包运营企业的收入、责任和日常作业一致，开发顺序不再由单一监管域定义。
- 关务仍是高风险、不可逆动作的控制点，申报、放行、查验和税费门禁不会被弱化或绕过。
- 包裹、路由、节点、运输、可见性和结算必须各自形成自己的事实与生命周期，并通过明确引用协作；运输有效交付不能代替小包托运形成包裹终局服务结果。
- 端到端验收需要同时覆盖正常履约和适用关务门禁；不能只用关务用例通过证明产品已经可运营。
- 关务专项文档继续维护真实程序和证据门槛，专项完成不等于产品总体首发完成。

## Alternatives considered

- **关务优先作为产品总体主线**：监管风险暴露早，但会把网络运营产品的核心对象和开发顺序压缩成申报流程；不采用。
- **所有能力同时建设、不设主线**：表面完整，但无法确定端到端责任和首发准入范围；不采用。
- **只做包裹与面单，不建设关务控制域**：无法支撑自营国际网络的申报、限制、放行和监管证据；不采用。

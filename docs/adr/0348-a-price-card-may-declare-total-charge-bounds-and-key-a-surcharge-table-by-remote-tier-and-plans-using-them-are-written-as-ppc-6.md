# ADR-0348：价卡可对单票合计声明最低与最高收费，评价在各行收齐之后、换算与合计取整之前补一条补差行或冲减行；附加费价表可按偏远档位查档、一条规则一个费用代码；带这两处新结构的方案写规范化版本 PPC-6，其余方案仍写 PPC-5 且字节不动

Status: Accepted（2026-10-29，Claude Code 会话代产品 owner、PP owner 决（代决）：计价引擎补缺口第二刀，起因是完整合成价卡 `SYN-PLAN-CN-SG-FULL-01` 取证出的「最低收费表达不了」「偏远一档二档只能各写一条规则」两格；设计由协调方派单、作者落笔，用户未逐条过目，越权风险点待 PP owner 复核。）<!-- 索引注记 -->｜**判据**：方案可对单票合计声明下限与上限（卡币种、各端可缺、声明了金额取整时落在进位单位的整数倍上），评价在基础运费、固定规则与附加费（含互斥组裁决与百分比费用）全部收齐之后、结算币种换算与合计取整之前施加：低于下限补一条 `MINIMUM_CHARGE` 补差行（金额是差额，各行相加仍等于合计）、高于上限补一条 `MAXIMUM_CHARGE` 冲减行（方向 `DEDUCT`，金额仍为正），不触发也在解释里留一行；附加费价表可声明按偏远档位查档（一条规则一个费用代码，触发条件定哪些档位收费、价表定各档金额），解不出档位仍答 `REMOTE_TIER_UNRESOLVED`、价表缺该档答 `RATE_NOT_FOUND`，不套默认；这两处是规范化文档里的新键，照 [ADR-0267](./0267-a-key-added-to-an-already-canonicalized-body-is-a-shape-change-even-when-old-documents-stay-byte-identical.md) 决定一换号并取能表达内容的最低一版——带新结构的方案写 `PPC-6`，其余仍写 `PPC-5`、内容摘要与评价语义摘要与快照字节一个不动，本构建两版都认

Date: 2026-10-29

## Context

取证于 main `7ea1aa677`，只记 `S`。

- **最低 / 最高收费在规则里被点名、在结构里没有格子。** [PP CONTEXT](../domain/parcel-pricing/CONTEXT.md) 的规则句要求价表区间、分区、重量策略、附加费、折扣、最低 / 最高收费等「必须可解释、可复算，并由版本化规则声明」；`PricingPlanStructures` 却只有附加费规则、费用依赖、序列绑定、拒收条款、金额取整与目录绑定，评价里能改写金额的只有逐行取整与合计取整。完整合成价卡取证时，最低收费因此只能不做。
- **附加费价表只按分区与计价重量查档。** `SurchargeCalculation.resolve` 的查表分支拿评价解出的分区和方案级计价重量去 `RateTableVersion.Lookup`；评价从偏远档位目录解出的档位只经「地址类型」特征（`FeatureAddressType`，[ADR-0109](./0109-zip-classification-facts-are-owned-by-parcel-pricing-as-a-versioned-reference-catalogue.md)）被触发条件读到，金额侧读不到。再加上「同卡内一个费用代码只能有一条附加费规则」（`NewAggregatePricingPlanVersion` 对费用代码查重），偏远一档、二档在 `SYN-PLAN-CN-SG-FULL-01` 里只能各写一条规则、各占一个费用代码（`REMOTE_AREA_SURCHARGE`、`REMOTE_AREA_EXTENDED_SURCHARGE`），新增一个档位就要新增一条规则和一个码，下游的费用项目映射跟着膨胀。
- **参考设计已有同一口径。** `docs/reference` 下的 Rating Runtime 计算语义规范把 `MINIMUM_ADJUSTMENT` 定为「调整额 = max(0, 下限 − 当前额)」、默认方向 `ADD`、调整额为零默认不生成费用行，把 `MAXIMUM_CAP` 定为「冲减额 = max(0, 当前额 − 上限)」、方向 `DEDUCT`、「不得直接修改原费用行」；受控案例 `FDC-007` 至 `FDC-010` 钉了数（12 对 10 补差 0、8 对 10 补差 2、8 对 10 的封顶冲减 0、13 对 10 的封顶冲减 3）。它的「当前额」是可选基数（如 `SELECTED_CHARGES`、`TOTAL_AFTER_DISCOUNT`），本版只取折扣之后的全部费用行之和一种。参考设计不是现行规则，只作印证。
- **「无条件附加费」的核实。** 派单带来一个疑问：作者称引擎不提供无条件附加费，可 v1 售价卡 `SYN-PLAN-CN-SG-01` 的偏远附加是无条件的，是怎么装配通过的？核实结果：两个说法都对，因为说的是两种东西。`NewSurchargeRule` 要求触发条件有效，触发条件只有判定条件及其「全部成立 / 任一成立」组合，空组合被 `newCombinedTrigger` 拒绝（CONTEXT「空组合不成立」），所以**附加费规则**没有无条件写法——`SYN-PLAN-CN-SG-FULL-01` 的燃油要对每票收，只能写成「实重大于 0」这种恒真条件。v1 的偏远附加（`SYN-RULE-REMOTE-AREA`，5 CNY）不是附加费规则，而是 `FixedChargeRule`（`NewFixedChargeRule`，CONTEXT「无条件固定规则」）：固定规则本来就无条件，只能给定额，不能查表、不能按基数取百分比、没有条件最低重量。引擎有两条路——无条件定额走固定规则，要触发条件、查表、百分比走附加费规则——并不矛盾；缺的不是「无条件」，而是「按偏远档位查表」，本记录补的是后者，**不新增附加费规则的无条件写法**。
- **规范化版本只有一个常量。** `canonicalizationVersion` 是 `PPC-5`，价卡登记门、草稿读回门与评价重放门都按「等于它」判；规范化文档里新增一个键（可缺键也算）按 [ADR-0267](./0267-a-key-added-to-an-already-canonicalized-body-is-a-shape-change-even-when-old-documents-stay-byte-identical.md) 决定一是形状变化、默认换号，换号后「按内容取能表达它的最低一版」（同一条决定一）。本仓演示库与测试夹具里已存 `PPC-5` 的方案与评价，派单要求它们的摘要与解析一个字节不动。
- **评价费用行的契约。** 完成的评价首行必为基础运费，其余为固定规则行或附加费行；`Money` 不许负数，方向由 `ChargeEffect`（`ADD` / `DEDUCT`）表达；费用行之和按方向折算，经取整留痕逐步重走后必须等于合计（`validCompletedCharges`）；费用代码在一份评价内唯一。结算侧的采用适配器只读费用行的**码**与合计，费用项目映射按码认；试算响应（`estimateChargeBody`）只带码、描述与金额，不带方向。

## Decision

**一、价卡对单票合计声明总额上下限；两端各自可缺，至少声明一端。**（机制）

- 声明在方案层（`PricingPlanStructures` 的 `WithTotalChargeBounds`），不挂在任何一条规则或价表上：它说的是整票，不是某一项费用。不声明的方案，评价与引入本记录之前逐字相同。
- 金额以该卡计价币种表示，下限与上限各自必须为正，下限不高于上限（相等即一口价）。零下限等于没声明；零上限会把任何一票压成零金额，CONTEXT 不许以零金额的已完成评价表达无适用价格。
- 卡声明了金额取整时，上下限必须落在进位单位的整数倍上（按构造期判）：否则合计取整会把补足后的合计又改回下限之下、把封顶后的合计又改回上限之上，这条规则就名不副实。不声明金额取整的卡不受此限——没有取整就没有被改回去的风险。不静默把不合格的值调到最近的整倍数，登记即拒。
- 下限和上限的**数值**是租户取值，机制不给默认；演示租户的 `SYN-` 值只记 `S`。
- 费用代码是产品内置的 `MINIMUM_CHARGE` 与 `MAXIMUM_CHARGE`，价卡不另取名：下游的费用项目映射按码认，每张卡各取一个名字，同一件事在不同卡上就成了不同的码。只有方案声明了对应的一端，这个码才被占用（与基础运费、固定规则、附加费规则的码一并查重）；没声明的方案里别的规则照旧可以用同名的码，既有价卡不因本记录而失效。

**二、评价在各行收齐之后、结算币种换算与合计取整之前施加总额上下限；补的是差额，各行相加仍等于合计。**（机制）

先后固定如下，卡上不再声明顺序：基础运费 → 固定规则 → 附加费（互斥组裁决已完成，百分比费用已按各自基数算出）→ **总额上下限** → 结算币种换算与换算后取整 → 比较币种 → 合计取整。

- 合计低于下限：补一条 `MINIMUM_CHARGE` 补差行，方向 `ADD`，金额 = 下限 − 各行之和；合计变成下限。合计高于上限：补一条 `MAXIMUM_CHARGE` 冲减行，方向 `DEDUCT`，金额 = 各行之和 − 上限；合计变成上限。恰好等于下限或上限、或落在两者之间：不补行。
- **补差行是差额，不是整笔。** 基础运费那一行不被改写，各行（按方向计）相加仍等于合计，评价读回门与对账都按行工作；补一整笔等于要么改写已有行的金额、要么让行之和不等于合计，两样都破坏费用行契约。
- **冲减行的金额仍是正数。** `Money` 不许负数；「减」由方向 `DEDUCT` 表达，与既有的 `DEDUCT` 固定规则（折扣类）同一种写法，不引入负金额费用行。
- **折扣在先。** 折扣类的 `DEDUCT` 固定规则 / 附加费已经计入各行之和，下限对的是扣完之后的合计。互斥组已决出一条，被压下的规则既不进合计也不进上下限的判断。
- **补差行 / 冲减行不进任何费用依赖的基数。** 它在所有行之后产生，燃油一类按基数取百分比的费用已经算完，不会因补差而变大。
- **以卡币种声明、先于换算。** 上下限与卡币种一致，早于结算币种换算：补差行仍是卡币种的行，行之和（卡币种）等于换算前的合计；换算照旧只作用于合计。
- **取整。** 补差行 / 冲减行经逐行取整的唯一入口（与其他费用行同一个）留下自己的逐行留痕；上下限在整倍数上，所以它在整倍数上的补差经逐行取整不变。只声明合计取整的卡，补差行是精确差额，合计取整后落在上下限上。
- **不触发也留痕。** 声明了总额上下限的评价，解释里恰有一行说明各行之和相对上下限的位置（低于下限并补足、高于上限并冲减、恰好等于某一端、落在范围之内）；只在触发时才写的解释，读的人分不清「判过没触发」与「根本没判过」（CONTEXT「未命中的规则也要在解释中留痕」同一纪律）。
- 费用行新增一种类型 `TOTAL_BOUND`，码与方向固定配对（`MINIMUM_CHARGE` 配 `ADD`，`MAXIMUM_CHARGE` 配 `DEDUCT`），只能是最后一行；读回门拒绝别的组合。

**三、附加费价表可以声明按偏远档位查档；一条规则一个费用代码。**（机制）

- 查表型附加费计算多一个查档维度（`TableKey`）：缺省按评价解出的分区（既有各卡的读法，语义与规范化字节都不动），或声明**按偏远档位**——价表条目的类别键是档位（`T0`、`T1`、`T2`……），重量再在档位之内分档。档位来自评价从偏远档位目录解出的值（[ADR-0109](./0109-zip-classification-facts-are-owned-by-parcel-pricing-as-a-versioned-reference-catalogue.md)），取较大值的操作数各自带自己的维度。
- **触发条件定哪些档位收费，价表定各档收多少。** 偏远一条规则、一个费用代码；要让 `T0`（市区）不收，就让触发条件只列 `T1`、`T2`——这与既有的判据一致：触发条件成立而价表在该档位没有行，是卡上的空档，评价待判断（`RATE_NOT_FOUND`），不是规则没命中，更不是零。
- **解不出档位答现有的待判断，不套默认档。** 声明了按档位查表的方案必须同时绑定偏远档位目录（构造期判，否则永远解不出档位）；绑了之后，目录没读数、目的邮编查无条目，评价开头的解析就答 `REMOTE_TIER_UNRESOLVED`（[ADR-0109](./0109-zip-classification-facts-are-owned-by-parcel-pricing-as-a-versioned-reference-catalogue.md) 决定四，与此前逐字相同）。
- 不接分区 × 档位的联合键：没有任何证据要求，真要时另立。
- 解释里按档位查表的金额多一段「looked up by remote tier T1」；按分区查表的解释一个字不变。

**四、新结构写规范化版本 PPC-6，其余方案仍写 PPC-5；本构建两版都认。**（机制）

- 规范化文档新增两处可缺键：方案级的总额上下限，与查表型附加费计算的查档维度。照 ADR-0267 决定一换号，并取能表达内容的最低一版：**带这两处之一的方案写 `PPC-6`，其余方案仍写 `PPC-5`，文档与内容摘要一个字节不动**。
- 评价的规范化版本随它所评的方案走：`PPC-5` 的方案评出的评价摘要、快照与此前逐字相同，`PPC-6` 的方案评出的写 `PPC-6`。评价文档本身没有新键，新增的只是费用行类型取值。
- 本构建对「方案记的版本」有两道门：登记 / 草稿 / 评价重放门认 `PPC-5` 与 `PPC-6`，别的版本仍答「本构建不认」（`ErrCanonicalizationVersionUnsupported`，不是内容冲突）；方案重验要求记着的版本**等于**内容该写的最低一版——带新结构却记着 `PPC-5`、不带新结构却记着 `PPC-6` 都是读回的数据对不上，一律拒。
- 只认 `PPC-5` 的旧构建读到 `PPC-6` 的方案或评价，答「不认这一版」，不会悄悄丢键算出对不上的摘要（ADR-0267 决定一的理由）。这对滚动发布有一条运维约束，见风险点 6。

**五、不改变任何今天已算对的评价；这由结构与对拍两样保证。**（机制）

- 结构保证：新增的两处都挂在「声明了才有」的可缺位置上。不声明总额上下限的方案，评价路径上新增的判断不触发、不多一行解释、不多一个键；查表型附加费不声明查档维度即缺省按分区，查表分支取的就是此前取的那个值，解释一个字不变；方案的规范化版本、内容摘要、评价语义摘要都不经过新分支。
- 对拍保证：同一批夹具——声明了全部旧结构的合成价卡、空结构、定额与互斥组与按分区查表的附加费、百分比燃油、金额取整、目录绑定的卡，每份再配六类输入（缺尺寸、各尺寸、分区缺失、超出价表段……）并对每份评价重放——在 `git archive origin/main` 解出的树与本分支上各跑一遍，方案内容摘要、登记快照散列、评价语义摘要、评价快照散列、解释散列、重放结果逐行 diff，全部逐位相同（行数与结果见票面完成记录）；演示种子生成器重跑，既有各份种子文件逐字节不变。两样守得住的东西也写进了用例：旧形夹具的方案摘要与评价语义摘要作为字面值钉在测试里，是 origin/main 上算出来记下的。
- 演示库里已存的 `PPC-5` 价卡与评价照旧可读、可重放；演示租户的既有价卡（`SYN-PLAN-CN-SG-01`、`SYN-PLAN-CN-SG-FULL-01`）结果一字不变，新卡 `SYN-PLAN-CN-SG-FULL-03`（范围 `SYN-SCOPE-04`）是新增，不动旧的。

**六、本轮不做的。**（范围）

- 价卡导入模板（`pricecardtemplate`）表达不了总额上下限与按档位查档：**导入暂不支持**，导入形成的草稿与卡永远不带这两处，也就永远写 `PPC-5`。要经导入接，得另立模板格式的决定。
- 试算响应的费用行不带方向，管理台试算页因此会把 `MAXIMUM_CHARGE` 冲减行显示成正数（既有的 `DEDUCT` 固定规则同病）；本记录不改响应形状，见风险点 1。
- 总额上下限只对「各行之和」整票生效，不对运费一项单独设基；见风险点 0。

## Alternatives considered

- **补一整笔：把合计改写成下限，不加行。** 否决：各行之和不再等于合计，评价读回门与对账都按行工作，守不住「费用行之和按方向折算后经取整留痕等于合计」这条契约；也没有一行可让结算按码映射。
- **改写基础运费那一行的金额去顶下限。** 否决：基础运费行是价表命中的事实，改写它就让「这一行为什么是这个数」答不出，且上限没有对应的行可改。
- **负金额的冲减行。** 否决：`Money` 与 CONTEXT「费用方向（ADD / DEDUCT）」已经把「减」交给方向；引入负金额要动 `Money` 的不变量和所有费用行的校验，换不来任何新的表达力。
- **最高收费只在解释里记、让合计封顶，不出行。** 否决：行之和不等于合计，同补整笔；下游按行读到的是超过上限的各行。
- **把下限做成一条附加费规则（取较大值 / 百分比的变种）。** 否决：下限要的是「合计与下限之差」，附加费规则的计算方法只有定额、查表、百分比、序列定额与取较大值，没有一种能读「本票其余各行之和」再取差；且它会进互斥组竞争、进费用依赖的基数，语义上它是对整票的裁决，不是一项费用。
- **施加在结算币种换算之后。** 否决：上下限以卡币种声明，换算之后的合计在另一币种，要么再声明一份结算币种的上下限（同一件事两处声明），要么拿汇率反推（口径从哪来答不出）。
- **总额只算运费、不含附加费。** 本版不取：派单与 CONTEXT 说的是「单票合计」；个别承运商最低收费只对运费，需要基数声明时另立，见风险点 0。
- **把查档维度放在价表（`RateTableVersion`）上。** 否决：所有价表族的规范化文档都要加键，连基础价表也受牵连，没用到的方案也要换号；放在查表型附加费计算上，只有用它的方案受影响。
- **每档一条规则（现状）。** 否决：每档占一个费用代码，新增档位要新增规则与码，下游映射膨胀，且同一件事（偏远）在价卡里散成几条。
- **价表缺某档位时按零处理（让 `T0` 在价表里写零）。** 否决：每一票市区件都会带一条零金额的偏远费行，下游映射一个零行；零与「卡上没有这一档」是两个答案，后者该是待判断。
- **联合键（分区 × 档位）。** 否决：没有证据要求，先不付复杂度。
- **同号改形：不换号，两处新键直接记在 `PPC-5` 下（ADR-0267 决定三，首个租户实例进生产之前可行）。** 否决：演示库与测试夹具里已存 `PPC-5` 的方案、评价与快照，派单明示它们的摘要与解析不变；同号加键意味着旧构建读到带新键的文档会丢键、算出对不上的摘要而报不出是形状变了。换号按内容取最低一版，代价只是多支持一个版本。
- **给附加费规则加「无条件」写法。** 不做：固定规则已覆盖无条件定额，其余需求没有出现；开这个口会让触发条件的「空组合不成立」失去意义。

## Consequences

- `internal/parcelpricing/domain`：新增 `total_bounds.go`（总额上下限类型、施加、与方案的自洽判、费用行契约）；`PricingPlanStructures` 多一个可缺格，`SurchargeCalculation` 多一个查档维度；规范化文档多两处可缺键；方案快照多两个可缺键（`totalChargeBounds`、`tableKey`）；费用行多一种类型 `TOTAL_BOUND`。无迁移、无库表（快照是 JSON 文档，规范化列只要求非空）。
- 评价路径多一段「总额上下限」，位置固定在附加费收齐之后、换算之前；`surchargeContext` 多带评价解出的档位。
- 声明了总额上下限的卡会产生 `MINIMUM_CHARGE` / `MAXIMUM_CHARGE` 费用行：结算采用时，这两个码要有对应的费用项目映射，租户没登记则按既有口径答未配置——属租户取值，随租户上线登记。
- 管理台费用代码册追加 `MAXIMUM_CHARGE`（最高收费）；`MINIMUM_CHARGE` 已在。
- 演示租户新增 `SYN-PLAN-CN-SG-FULL-03`（范围 `SYN-SCOPE-04`）：偏远一条规则按档位查价表，加最低收费 120.99 CNY（取完整价卡一「小件市区」一票的合计，好让「刚好等于下限」有一票真能造出的包裹）。
- 价卡导入与导入形成的草稿不带这两处（决定六）；草稿读口读同一份快照形状，带 `PPC-6` 的草稿文档读得回，但目前没有任何入口产生它。

## 越权风险点

0. **总额的口径是「全部费用行之和」。**（决定一、二）个别承运商的最低收费只对运费一项、燃油另算，此时卡要的是「对哪些费用代码求和」的基数声明（与费用依赖的基数构成同形；参考设计的 `MINIMUM_ADJUSTMENT` 也把基数留作可选）。本版不声明基数，一律对整票；要接这种卡，得另立决定并按 ADR-0267 再换号。归 PP owner。
1. **补差行的呈现。**（决定二）单独一行、金额是差额、码内置；备选是补整笔或改写基础运费行，已否决。留下的缺口：试算响应不带费用行方向，管理台试算页把 `MAXIMUM_CHARGE` 冲减行显示成正数，读者要自己知道它是减项；既有的 `DEDUCT` 固定规则同病。要补，是给响应加方向字段并让页面按方向显示，属另一张票。归 PP owner。
2. **与折扣、互斥组、百分比费用的先后。**（决定二）总额上下限在这三者之后：折扣已扣、互斥组已决、燃油已按各自基数算完，补差行不进燃油基数。有承运商把最低收费算进燃油基数（「最低运费 × 燃油率」），那种卡本版表达不了，需要把总额上下限提到百分比费用之前并允许它进基数——同样是另立决定、再换号。归 PP owner。
3. **负费用行的取舍。**（决定二）不引入负金额，冲减行用方向 `DEDUCT` 表达；代价是下游任何只看金额不看方向的读法（试算页、日后新增的报表）都要自己处理方向，这与既有 `DEDUCT` 行的处境一致，没有新增。归 PP owner。
4. **价表维度扩展对下游的影响。**（决定三、六）核实出的受影响面：价卡导入模板（`pricecardtemplate`）不认新结构，**导入暂不支持**；价卡草稿读口沿用同一快照类型，带新键的草稿能读回，但目前没有入口生成；价卡目录读口（`price_card_catalog`、`operations_catalogue`）只读版本行与列，不解析规则，不受影响；价卡预览读口只数附加费规则条数，一条规则按档位查表仍数一条，管理台上看不到「按分区查还是按档位查」的区别。归 PP owner。
5. **整倍数校验可能拒掉租户的值。**（决定一）声明了金额取整的卡，下限 30.005 这类不在进位单位整倍数上的值在构造期被拒，不静默调整。租户上线时若给的就是这种值，要么改值要么改取整，由租户决定，机制不替他选。归租户上线实施与 PP owner。
6. **滚动发布的运维约束。**（决定四）只认 `PPC-5` 的旧构建读到 `PPC-6` 的价卡或评价会答「本构建不认这一版」，不会算错；所以第一张带新结构的价卡登记之前，所有会读价卡的进程必须已是新构建，回滚到旧构建后这张卡的评价会停在该答复上。归运维与 PP owner。
7. **两个内置费用代码占用了词汇。**（决定一）声明了下限（上限）的方案里，别的规则不能再用 `MINIMUM_CHARGE`（`MAXIMUM_CHARGE`）；既有价卡若已有普通规则用了这两个码，不声明总额上下限时照旧可用，声明时登记即拒。归 PP owner。
8. **触发条件与价表的双写风险。**（决定三）按档位查表的规则，哪些档位收费写在触发条件、各档金额写在价表：触发列了而价表缺这一档，评价待判断（`RATE_NOT_FOUND`）；价表有、触发没列，则这一档静默不收。构造期不核对两者，因为触发条件是任意判定条件的组合，机制不去反解它。归 PP owner 与租户配置。
9. **不接联合键。**（决定三）分区 × 档位联合定价的卡，本版表达不了。归 PP owner。

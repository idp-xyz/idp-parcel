# ADR-0261：授权授予与合同委派随所挂版本的收尾离开新的裁定——退役即不参与、截止即收窄；同一请求命中多于一条授予答适用冲突，不取首个

Status: Accepted（2026-10-21，Claude Code 会话代 PC owner 决：用户 2026-10-21 原话「需要修改文档，确保自洽，正确」，常设授权「你作为业务和系统专家自决」；票 docs-consistency/07，出处审计 [audit/pc-pp.md](../../.scratch/docs-consistency/audit/pc-pp.md) H2 与 M4（UC-PC-003 未决五），代码票 [docs-consistency/code/24](../../.scratch/docs-consistency/code/24-closed-authorization-rule-and-contract-versions-keep-granting.md) 所等的那一裁。部分停用 [ADR-0233](./0233-an-older-commercial-version-is-closed-for-a-named-successor-by-a-cut-or-a-same-start-retirement.md) 决定六一条并回答其越权风险点 6，被停原句与适用场景见「对已接受记录的作用」；ADR-0233 正文不改，只在其 Status 行与 Links 加前向指针。越权风险点见文末，待 PC owner 复核，第 3 点同时待 PS owner。）<!-- 索引注记 -->｜**折法**：裁定装载的授予先折所挂授权规则版本的收尾——版本已退役的授予不参与任何新的裁定，版本被截止的授予判用区间终点取截止点与授予自身终点中较早的一个；这个范围在这个时刻有没有现行规则，按折后的授予判。合同委派随所挂客户合同版本同一折法。与 ADR-0233 决定五给正文选法的折法同一口径，只截终点。**多条命中**：同一请求在同一刻命中多于一条授予，答`适用冲突`，不取首个、不按版本标签或装载顺序挑；委派多条命中而委派方不同亦同。已作出的裁定与消费方保存的授权规则版本引用不改写

## Context

- **收尾口对授权规则与合同都收，裁定却不看收尾。** ADR-0233 的截止与同起点退役对任何商业对象种类都收，`AuthorizationRuleObject` 也在内（`registrationjson/version_closure.go` 经 `CommercialKindFrom` 取种类）。授权裁定按授予自身区间装载：`postgres.AuthorityGrants.LoadEffectiveGrants` 只看 `effective_starts_at` 与 `effective_ends_at`，不连退役册，也不连区间更正册；`postgres.ContractDelegations.LoadEffectiveDelegations` 同样只看委派自己的区间。ADR-0233 决定六把这件事列为「不在本记录」、越权风险点 6 写明「合同委派、授权授予不随版本收尾」。PC CONTEXT「商业规则与政策版本」生命周期却说已退役的版本「停止用于新的解析和判断」，并把授权规则列在共同适用的对象里。
- **取首个命中。** 一条授予就是一版授权规则（授予册按对象与版本标签一行）。`LoadEffectiveGrants` 按 `object_id, version_label` 排序，`domain.Authorize` 取首个命中项。同起点重发 `v2`、退役 `v1` 之后，命中的仍是已退役的 `v1`，消费方保存的「所采用的授权规则版本」也就是一版已退役的规则。UC-PC-003 未决五早已指出命中顺序即装载顺序，`AT-PC-042` 留作待评审；`resolveDecider` 对合同委派同样取首个命中。
- 运营退役一版授权规则来收回某个等级的拒绝、关闭或重开权，这些权限实际上照旧生效；第一次更正错登的授权规则就会撞上。

## 候选与反方

- **授予按自身区间走，收尾口拒收授权规则与带委派的合同。** 版本壳的生命周期与授予就成了两件事，运营要改授予得另开一口逐条改区间；同起点重发的那一类更正（ADR-0233 的动因）对授权规则走不通。否决。
- **收尾时同步改写授予与委派的区间。** 授予册与委派册是只增的已发布正文，改写区间等于改正文；退役与截止本就另册留痕，装载时折进来即可。否决。
- **多条命中时按一条与顺序无关的规则采用（如取对象标识最小的一条，或取最晚生效的一版）。** 任何这类规则都是在替租户挑一版——UC-PC-001 一致性一节原句「不得依赖数据库顺序、更新时间或最高版本号自动选择」要拦的正是它；两条都答「可以」，结论不含糊，可消费方保存的那一版引用仍是挑出来的。否决。
- **多条命中时交回全部命中的版本引用。** 结论确定、引用齐全，但消费方保存的形状从一个引用变成一组，`parcel-shipment` 各适配器与决定记录都要改；同一对象两版并存本就是换版未收尾，应当收尾而不是一起记下。否决。

## Decision

**一、授予随所挂授权规则版本的收尾。**（机制）

- 裁定装载的授予先折收尾，再交给裁定：版本已退役的授予不参与任何新的裁定；版本壳上有区间更正（截止）的，授予的判用区间终点取壳上最新一条更正的终点与授予自身终点中较早的一个。只截终点，不拿更正的起点去裁授予的前段——与 ADR-0233 决定五给自带区间的政策正文的折法同一口径。
- 这个范围在这个时刻有没有现行规则（UC-PC-003 的范围加时刻判据）按折后的授予判：已退役与截止之后的授予不算现行。收尾要求后继接得住旧版此后的那一段（ADR-0233 决定四），所以一次成立的收尾不会把「已配置」变成「未配置」。
- 已作出的裁定、消费方随业务决定保存的授权规则版本引用不改写；收尾只作用于此后的新裁定（UC-PC-003「既有决定继续引用当时采用的那一版」）。

**二、合同委派随所挂客户合同版本的收尾。**（机制）

同一折法：合同版本已退役的，它声明的委派不参与新的裁定；合同版本被截止的，委派的判用区间终点取截止点与委派自身终点中较早的一个。委派只回答「谁替谁」（ADR-0116 决定三），折法不改它与授予的分工。

**三、同一请求命中多于一条授予，答`适用冲突`。**（产品策略）

- 折完收尾之后，一个请求在同一刻被多于一条授予允许，裁定答`适用冲突`：不取首个，不按版本标签、装载顺序或生效时点挑。两条是同一授权规则对象的两版（换版未收尾），还是不同对象各授一份，同一答法。
- 委派同此：多条委派命中而委派方不同，答`适用冲突`；委派方相同即同一个实际决定方，不算冲突。
- 消费方的恢复动作：保持未决，不压成`不允许`，也不当作已授权继续；交商业责任方消解——同一对象的两版经截止或同起点退役收尾旧版（ADR-0233），不同对象的重复授予见越权风险点 2。
- 这回答 UC-PC-003 未决五与 `AT-PC-042`。

三类：一、二是**机制**；三是**产品策略**；某个租户哪一版授权规则或合同何时收尾、让位给哪一版，是**租户取值**，由租户的商业责任方登记。演示租户今天没有授权规则与委派的收尾，证据只记 `S`。

## Consequences

- 代码随票 docs-consistency/code/24：授予与委派的装载折进退役册与最新一条区间更正（与 ADR-0233 给版本点读的折法同一口径）；`Authorize` 与 `resolveDecider` 多条命中答适用冲突、不取首个；`psports.AuthorizationOutcome` 加`适用冲突`一格，`parcel-shipment` 各授权适配器译出它、各编排停在各自的未决格，不落`不允许`；补同起点重发、截止与多条命中的用例。
- UC-PC-003 结果语义加`适用冲突`一格，未决五改为已裁，`AT-PC-042` 改写，新增 `AT-PC-059` 至 `061`；PC CONTEXT 收尾规则一条与「商业规则与政策版本」「客户合同版本」生命周期随之改。
- ADR-0233 的 Status 行与 Links 挂前向指针。
- 在 code/24 落地之前，生产上收尾一版授权规则或合同，挂在旧版上的授予与委派照旧生效，同起点重发时还命中已退役的那一版。

## 对已接受记录的作用

- **部分停用** ADR-0233 决定六「合同委派与授权授予随合同、授权规则版本收尾：两者按自己的区间判，今天不看版本壳的生命周期。」一条——本记录把它接上：两者随所挂版本的收尾折法见决定一、二。**适用场景**：全部授权裁定与委派解出。ADR-0233 决定六其余各条（完整替代写口、不指名后继的一般退役、延长与前移区间的更正）仍留后继票，其余各条不变。越权风险点 6「合同委派、授权授予不随版本收尾」随之回答。
- ADR-0116、ADR-0042：无条款停用。委派只回答「谁替谁」、授权答「谁可以」不变。

## 越权风险点

1. **适用冲突是授权裁定的新一格**（PC owner）。UC-PC-003 在已授权、不允许、授权规则未配置、未形成之外再加一格；首发表是空的，这一格只在换版未收尾或重复登记时出现。
2. **不同对象的重复授予退不了场**（PC owner）。收尾只认同一对象的后继（ADR-0233 决定一），不指名后继的一般退役归后继票；在那之前，另一对象重复授予的那一条只能靠为它发一版接得住的后继、再同起点退役旧版来退场。登记时就挡重复授予是另一种取法，本记录不立，它要在发布时按动作、法人、等级、范围与区间比对整册。
3. **消费方要认这一格**（PC、PS owner）。`parcel-shipment` 经 PC 裁定编排询问授权的适配器是主动拒绝、人工复核、资料修订、受控关闭与重开（同一只适配器）、撤回这几只；它们只把`授权规则未配置`与`不允许`译成 `psports.AuthorizationOutcome` 的对应格，其余错误落 `default` 交回 error，即未形成——今天若出现适用冲突，不会被读成已授权，也不会被读成拒绝，只是停在技术失败、指不出原因。code/24 落地时 `psports.AuthorizationOutcome` 加`适用冲突`一格，各 PS 编排停在各自的未决格并指名授权适用冲突（逐只见 code/24）；这改到 PS 的地盘，由 code/24 实施、PS 文档随票 10 补。
4. **截止只截终点**（PC owner）。改起点、延终点的更正今天没有生产写入方（ADR-0233 越权风险点 3），到时怎样作用到授予与委派上另裁。

# ADR-0021: 一线作业客户端属于产品，范围限于本产品拥有的节点作业

Status: Accepted  
Date: 2026-08-10

## Context

[ADR-0020](./0020-tenant-admin-client-in-product-workers-are-processes.md) 把「是否自带一线作业界面」记为未决，并写明它按 [ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md) 属机制半边、可定而未定，等的是一次明确的产品定位判断。本记录作出该判断。

此前在这一点上出过两次推断错误（[ADR-0018](./0018-product-clients-share-release-boundary-under-apps.md) 与 [ADR-0019](./0019-product-ships-tenant-facing-operator-clients.md)），都是从**业务活动**推出**交付形态**。本记录不再依赖那条路径，改用两项独立依据。

**其一，[开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)的能力范围判据**：「必须能指出一类真实存在的承运或渠道商业模式需要它，且该模式在目标客户群里是常规形态而非边缘情形」。指得出：物流企业在场站以手持设备扫描、点验、集运与封签处理跨境出口小包，是目标客户群的日常形态而非边缘情形。

**其二，行业既有做法一致且没有成功反例。** 自营网络的承运人一律自有手持端；面向物流企业的软件供应商同样把 RF／手持客户端作为产品交付的一部分。纯 API 交付确实存在于面单与费率类产品，但那类产品**不拥有节点作业**——分界正在此处，而本产品按 [ADR-0006](./0006-parcel-node-operations-not-full-wms.md) 拥有它。

**决定性理由是工作流归属，不是数据保护。** [`node-operations`](../domain/node-operations/CONTEXT.md) 规定「现场人员不得以覆盖、合并或『最后一次扫描为准』决定正式包裹身份」——这规定的是工位上的人**被允许做什么**。后端能拒绝非法写入，给不出替代动作；不知道「待识别实物」「身份冲突」「暂停方向性作业」的第三方扫描端，会把操作员卡在一个只有报错、没有出路的屏幕上，手里还拿着那个包裹。只交规则不交界面，等于要求租户把本产品的核心工作流重实现一遍。

## Decision

**一线作业客户端属于产品。** 与后端同仓、同版本发布，落在 ADR-0018 确立并经 ADR-0020 保留的顶层 `apps/` 之下。它不是可选增值项，而是与租户管理界面并列的核心交付面。

**范围限于本产品拥有的节点作业**：扫描、点验、身份冲突处置、测量录入、集运单元与封签、作业位置移动。

**明确不做**：库存账、上架、拣货、波次等完整 WMS 能力，依 ADR-0006 已排除；以及租户既有的面单打印、财务与人事。

**设备形态覆盖手持与固定工位。** 做成一个响应式应用还是两个，留待落地时按实际交互定。**离线与弱网容忍是该端的固有要求，不是后续增强**——工位作业不会因为网络抖动而停。

**开工顺序：租户管理界面先，一线作业客户端次之。** 这只是顺序不是重要性：管理界面是配置与演示的底座，而真正体现产品差异的演示面是扫描那一屏。

## Consequences

- ADR-0020 的未决项关闭。`apps/` 现有两个确认占用者，「每端一个子目录」的复数形状因此坐实，不再悬在一项未决上。
- 产品交付面从「后端 + 管理页」扩为「后端 + 管理页 + 作业端」。多语言 CI 之外新增移动／手持工具链与真机测试成本，这笔账记在本决定这一边。
- **离线容忍进入产品要求，会反过来约束业务端点的形状**——幂等、冲突合并语义、本地队列与重放。它不解除 [ADR-0017](./0017-admission-gates-judged-by-blocking-cause.md) 的闸门，但闸门开启后设计业务端点时必须一并考虑；离线是设计不出来就补不上的那类要求，事后加代价极高。
- 「不预建空壳」不变：两个端都等真实落地时才建。
- 开发方的跨租户运维后台仍不属于产品，承 ADR-0020 不变。

## Alternatives considered

- **只交付 API，作业端由租户自建。** 否决：行业内没有成功反例。纯 API 交付存在于面单与费率类产品，那类产品不拥有节点作业；本产品按 ADR-0006 拥有它。且后端能保数据、保不住流程。
- **作业端作为可选增值模块单独售卖。** 否决：它是演示与验证核心闭环的唯一手段，而产品就绪明确要求「可以演示、可以进入商务洽谈」；把唯一的核心演示面做成选购项，等于产品无法被完整展示。
- **先做管理页，作业端留待第一个租户提出再定。** 否决：这是把机制半边挂在实例半边上，ADR-0016 已裁定不成立；且离线要求会反向约束业务端点形状，越晚决定改造成本越高。
- **按完整 WMS 的作业面建设。** 否决：ADR-0006 已排除完整 WMS，且超出目标客户群的常规形态，违反能力范围判据。
- **继续保持未决。** 否决：ADR-0020 已写明它可定而未定，等的只是一次判断。继续悬置会让第一个被写出来的扫描界面以临时工具的形式出现，从而把答案默认掉——ADR-0019 已经因同类默认吃过一次亏。

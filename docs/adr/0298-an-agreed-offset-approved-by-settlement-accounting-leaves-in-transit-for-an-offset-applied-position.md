# ADR-0298：经 settlement-accounting 认可的协议抵扣凭单独登记的认可记录自`渠道在途`落入账内终局位置`已抵扣`，短款与移位上限按落账后的在途余额算，一条认可至多落一笔、一笔记账至多冲正一次

## Context

- ADR-0271 决定四把短款定为「该指令已入账报告 − 该指令自`渠道在途`移出的金额 − 经 settlement-accounting 认可的协议抵扣」，认可的抵扣额因此既不落`短款`，也没有别的去处，只能「暂留在`渠道在途`、可见为未了结」。越权风险点 6 把记账形留给 CR owner。
- 暂留的代价是`渠道在途`的意思被改了：它是「渠道已代收但尚未回到运营企业」，渠道还欠的本金；认可的抵扣一经认可，渠道已经不欠这部分了，它却还躺在这一格里。于是该格余额不再等于渠道欠款，短款上限只得写成「不超过」（`InstructionPrincipal.ShortfallCeiling` 的头注），汇付前要人工把认可的抵扣从余额里剔出去再对。
- 代码里没有这一种东西可以挂：`PostingBasisKind` 与 `FundPosition` 都是封闭词表，迁移 `subledger_posting` 的位置与依据三列各有 CHECK 封住同一份词表，ADR-0082 决定四把资金位置定为封闭六值、决定五把依据门定为四条。认可抵扣若要了结，必须新增词表成员，这是难逆转的取舍，要记录。
- 抵扣的认可、金额与协议归 settlement-accounting（CR CONTEXT「与结算的分界」）；SA 今天没有「认可抵扣」的只读口，CR 只能收到一个引用。
- 记账只追加、分户账键由依据推出（ADR-0082 决定三、六）：一条 CR 侧记账需要一行 CR 自己的册子来指名它属于哪条指令、哪本账，一个外部的不透明引用做不了这件事。

## Decision

**一、认可的协议抵扣在 CR 单独登记一册，既不是代收事实，也不是差异事项。**（机制）

- 登记的是对 settlement-accounting 认可的引用：CR 侧标识、所属代收指令、金额与币种、认可引用、认可时刻。认可、金额与协议归 settlement-accounting，CR 保存的是当时引用的那一份，不据此形成服务费或任何运营应收应付，也不在账内与本金净额。
- 它不是代收事实：四个来源层级说的是「谁报了、谁收到了这笔钱」，彼此不得推导；认可的抵扣不是收款证据，放进去会让按层级分派的入账位置与移位判断多出一个既不入账也不移位的层。
- 它不是差异事项：差异事项是待处置的异常声明，「处置结论形成」之后才落账；认可的抵扣是已经按协议了结的正常扣减，金额由认可给出而不是观察出来，没有处置流程可走。混进去会把一份正常的了结读成一项待追责的异常。
- 登记只钉引用，**不动账**：指令必须在册，币种必须是指令所属分户账的币种，登记后不可改写。落账是另一笔以本记录为依据的记账——与差异事项「先有事项再有记账」同一个分两步的理由：分户账键与按指令的上限由依据推出，调用方不传。
- 交到 CR 的口与其他 CR 登记一样是受控 CLI（`agreed-offset` 命令）。登记时 CR 不向 settlement-accounting 读：SA 没有只读口，认可引用是操作员照 SA 的认可录入的一份引用；SA 给出只读口之后照 ADR-0274 决定二的办法在登记时核对（引用在册、币种相同、同一认可下按指令拆开的各条之和不超过认可金额），那是后继记录的事，见越权风险点 1。

**二、落账自`渠道在途`落入新的账内终局位置`已抵扣`，凭认可记录。**（机制）

- 新增资金位置`已抵扣`（`OFFSET_APPLIED`）：经认可的协议抵扣从渠道还欠的本金里扣走的那部分，不再是渠道欠款，也不付给客户。它是**账内**位置、账内终局，与`已汇付`同类——ADR-0082 决定四的「去向侧没有账外位置」不变，全账总额仍恒等于入账之和，守恒仍在一条求和上核得完；本记录没有给出账外的出账记账。
- 新增依据种类`AGREED_OFFSET`，依据引用是认可记录的标识。它只支撑一种形：`渠道在途` → `已抵扣`，金额等于登记的认可额、全额一次。部分落账没有可表达的「余下部分」，余下的抵扣额会以「这条认可已处理」的样子消失；认可额变了走新的认可（决定五）。
- 依据门由四条变五条：进入`已抵扣`必须凭认可的协议抵扣，且只自`渠道在途`来；认可的协议抵扣作依据只有这一种形；离开`已抵扣`只有冲正。这几道门都做进结构——迁移 CHECK 与领域构造门各一份——不留给调用方自觉。
- 分户账键由依据推出：认可记录经指令解出键，同 ADR-0082 决定六。

**三、名下恒等式与短款公式：抵扣落账之后已在「移出」里。**（机制）

- 一条指令名下恒有：入账报告 = `渠道在途`余额 + 移进`待清分`的到账 + 落进`已抵扣`的抵扣 + 落进`短款`的差额，各项都已减去冲正回去的。全账恒有：各账内位置之和 = 入账之和，`已抵扣`在其中。
- 于是「该指令自`渠道在途`移出的金额」除到账移位与短款落账外还含抵扣落账：移位上限 = 该指令已入账报告 − 该指令自`渠道在途`移出的金额（到账移位、抵扣落账与短款落账，减去冲正回`渠道在途`的）；短款 = 该指令已入账报告 − 同一个移出的金额。ADR-0271 那条公式末尾「− 经 settlement-accounting 认可的协议抵扣」不再另减，否则落账的抵扣被减两次。
- 短款上限因此是抵扣落账后的`渠道在途`余额，由「不超过」变成准确值：该指令的到账、认可抵扣都过账之后，`渠道在途`剩下的就是渠道报了、钱没回来、又没有协议认可的那部分。

**四、抵扣额不超过该指令名下的在途款，到账先于抵扣，抵扣先于短款。**（产品策略）

- 抵扣落账的上限与到账移位同一条：不超过该指令名下的`渠道在途`，不借同账别的指令的在途款。不够时整笔停在余额不足，等该指令补一条渠道代收报告、或认可被更正为较小的额，不先落一部分。CR 不核抵扣额合不合协议——那是 settlement-accounting 的认可；CR 核的是账上有没有这么多可扣。
- 该指令有已登记而没移位的到账时，抵扣等着（余额不足）。理由同短款：到账是真实现金，抵扣先落会先吃掉在途款，真实到账的钱反而移不动；先落抵扣再移到账，与先移到账再落抵扣，终局不同，而结果不该随到达次序变，实际到账优先于认可的抵扣。
- 短款先于抵扣落账会吃掉在途款，此后抵扣答余额不足；处置是冲正多落的短款，落抵扣，再落余下的短款，终局与先抵扣再短款相同。**不为「已登记未落账的认可」给短款加闸**：认可被撤回而没落账时，闸会把短款永远挡住，得再立一个撤回记录才解得开；落账紧跟登记，操作次序（到账移位、抵扣、短款）写进 UC 即可。

**五、同一抵扣重复到达、被更正、被撤回。**（机制）

- **重复到达。** 登记按（认可引用，指令）唯一：同标识同内容答已在册，同标识异内容、或换标识登记同一份认可，都答内容冲突，不落第二行；同一份认可引用落到不同指令上是不同的行（一次回款的抵扣常按指令拆开）。落账一条认可至多一笔：同记账标识重放答已在册（先于余额守卫，来源此后被移空也一样），换记账标识再落答内容冲突。并发的两路由分户账锁排先后，取锁之后再判一次重放，库上的部分唯一索引兜住绕过锁的写入。
- **被更正（认可额变了、对象换了）。** 更正后的认可带着新的认可引用。CR 冲正旧认可已落的那一笔，再登记并落新认可；旧记录不改。
- **被撤回。** 已落账的：冲正，`已抵扣` → `渠道在途`，反向同额，原记账原样留在账上；这部分重新是渠道欠款，由到账或差异事项处置。冲正之后那条认可仍记着自己落过账——撤回的认可不能再落第二次，也不能靠冲正的冲正重新进入`已抵扣`；要重新生效走新的认可。没落账的：登记不动账，不落就没有账面效果；记录留在册上（追加式），它的认可引用不再能登记给同一条指令。
- **一笔记账至多被冲正一次。** 冲正的依据是被冲正的那一笔，两笔冲正指向同一笔，第二笔就是从别处多拿：`已抵扣`、`待清分`这些位置混着同账别的指令的钱，余额够扣不等于那是这一笔该退的。此前冲正只核反向同额与位置余额，同账别的指令在同位置有钱时重复到达的冲正会被照单落账，按指令的恒等式就破了而全账守恒看不出来。本条不限于抵扣：判重先于余额守卫，库上有部分唯一索引。冲正写错了走冲正那一笔冲正，它是另一笔的依据，不受此限。

**六、读面与结果代数。**（机制）

- 分户账目录上列、HTTP 读面、管理台分户账页各带出`已抵扣`一列；受控 CLI 新增`agreed-offset`命令；演示种子补一条认可抵扣，短款改成余下的部分。
- 结果代数不增格，每个消费方（CLI 退出码、读面、管理台）都已有落点：登记答已登记、已在册、内容冲突、依据不在册、未受理、未决；落账答已登记、已在册、内容冲突、依据不在册、未受理、余额不足、未决，各自已有退出码与 HTTP 译装。

## 手算

场景十七：报告 100、真实到账 96、经 settlement-accounting 认可的协议抵扣 3。

| 步骤 | `渠道在途` | `待清分` | `已抵扣` | `短款` | 账内合计 | 入账 |
|---|---:|---:|---:|---:|---:|---:|
| 渠道代收报告入账 100 | 100 | 0 | 0 | 0 | 100 | 100 |
| 到账移位 96 | 4 | 96 | 0 | 0 | 100 | 100 |
| 认可抵扣 3 落账 | 1 | 96 | 3 | 0 | 100 | 100 |
| 短款 = 100 − (96 + 3) = 1 落账 | 0 | 96 | 3 | 1 | 100 | 100 |
| 撤回认可：冲正 3 | 3 | 96 | 0 | 1 | 100 | 100 |

每一行账内合计都等于入账 100。最后一行是撤回之后的状态：渠道重新欠 3，由到账或新的差异事项处置，不是错账。

反例：

- **抵扣与到账合起来多于报告。** 报告 100、到账 98、认可抵扣 3：到账先移位，在途剩 2；抵扣 3 > 2，整笔答余额不足、不落一部分，账内合计仍是 100。处置是该指令补一条渠道代收报告 1（渠道少报了），或认可被更正为 2；不是把已回来的 98 退回去让位。抵扣若先于到账移位落账，则它先吃掉在途款 3，到账 98 > 97 反而移不动——所以到账先于抵扣（决定四）。
- **短款先于抵扣。** 同一指令报告 100、到账 96，先落短款 4：在途清零，认可抵扣 3 答余额不足。冲正短款 4 回到`渠道在途`，落抵扣 3，再落短款 1。终局 0 / 96 / 3 / 1，与先抵扣再短款相同。
- **同账两条指令各抵扣 3，撤回重复到达。** X、Y 各有报告 100、各落抵扣 3，`已抵扣`余 6。X 的撤回到了两次、换了记账标识：若冲正可重复，第二笔会从`已抵扣`再取 3——余额够扣——X 名下`渠道在途`变成 103，超过它的报告 100，而全账合计仍是 200，守恒看不出来；Y 的抵扣已落账，`已抵扣`里却没有它的钱了。按决定五，第二笔冲正答内容冲突，`已抵扣`余 3（Y 的），X 的在途回到 100。

## 候选与反方

- **抵扣继续留在`渠道在途`，读面把认可的抵扣额从渠道欠款里分列出来**（票「最小的诚实修法」）。否决：分列要读面去另查 settlement-accounting 的认可来算，`渠道在途`余额本身仍不等于渠道欠款，汇付前的对账仍是人工；短款上限只能写成「不超过」，抵扣落在哪一笔记账上没有账面证据。它是形定下来之前的权宜，不是形。
- **抵扣做一笔出账记账（去向是账外位置）。** 否决：与 ADR-0082 决定四「去向侧没有账外位置」相抵，全账总额不再等于入账之和，守恒要靠第二个口径核；而账内终局位置已经表达了「这部分本金离开渠道欠款、也不付给客户」。
- **抵扣作为差异事项的一种方向，或作为第五个来源层级的代收事实。** 否决：理由见决定一。
- **抵扣直接缩小代收指令金额或渠道报告金额。** 否决：与「短款不得通过缩小代收指令抹平」同一条理由，已接受的指令与事实不可覆盖，已依它们落账的记账会凭空指向一份不存在过的依据。
- **登记与落账合成一步。** 否决：合成一步要另写一个用例，复用不了记账编排里的重放、判重、按指令上限与余额守卫；落账因余额不足而整笔回滚时，认可引用也不留痕，运营看不到「认可已到、等补报告」。两步让每一格各有一个已有的答案。
- **给短款加「有已登记未落账的认可就等」的闸。** 否决：见决定四，会被一条没落账又被撤回的认可永久挡住。
- **CR 在登记时按 SA 的认可核金额上限。** 现在做不到：SA 没有只读口。写成越权风险点，不写成一个读不出来的假核对。

## 对已接受记录的作用

- **部分停用（扩成）** ADR-0271 决定二「移位上限 = 该指令已入账报告 − 该指令自`渠道在途`移出的金额（到账移位与短款落账，减去冲正回`渠道在途`的）」一句、决定四「短款 = 该指令已入账报告 − 该指令自`渠道在途`移出的金额 − 经 settlement-accounting 认可的协议抵扣」一句与「认可的抵扣额暂留在`渠道在途`、可见为未了结，不落`短款`。抵扣怎样记账（落哪一格、凭什么依据）今天未裁」两句。**适用场景**：有经认可的协议抵扣落账的指令——移出的金额含抵扣落账，短款只算抵扣落账后的在途余额，认可的抵扣额离开`渠道在途`落进`已抵扣`；没有认可抵扣的指令，两条公式的值与原句相同，决定二其余各条、决定四其余各条（含「该指令有停在余额不足的到账时不判短款」）、决定一、三、五、六不变。越权风险点 6 由本记录回答。
- **部分停用（扩成）** ADR-0082 决定四「资金位置封闭六值」与决定五「四条依据门做进结构（迁移 CHECK 与领域构造门各一份）」。**适用场景**：资金位置多一格`已抵扣`、依据门多一条「进入`已抵扣`必须凭认可的协议抵扣」；外部来源只在来源侧、去向侧没有账外位置、守恒、追加式、键由依据推出，以及原有四条依据门的原句不变。
- 一笔记账至多被冲正一次不停用任何已接受条款：ADR-0082 与 ADR-0271 都没有一句话允许同一笔被冲正多次，这是补上的缺口。
- ADR-0274 决定二的登记核对办法、ADR-0029 的分格照用；本记录不改它们。

## Consequences

- collection-remittance CONTEXT：「资金位置」词条加`已抵扣`，新增「认可的协议抵扣」词条，分户账记账、清分汇付与差异两节里移位上限、短款公式与抵扣规则按决定三、四、五改写，「分户账资金位置」「差异事项」旁补认可抵扣的生命周期。GLOSSARY「代收分户账」、CONTEXT-MAP 与 settlement-accounting CONTEXT 里的资金位置清单加`已抵扣`，settlement-accounting CONTEXT 并就近加一句 CR 登记对认可抵扣的引用（事实陈述，不规定 SA 的行为）。UC-CR-001 补输入、验收（`AT-CR-024`、`AT-CR-025`）与交接。
- 代码：领域`AgreedOffset`、`PositionOffsetApplied`、`BasisAgreedOffset` 与构造门；`InstructionPrincipal` 带出已抵扣与认可抵扣已支撑的记账，抵扣等到账；编排`RegisterAgreedOffset`与记账的认可抵扣依据、冲正判重、取锁后再判重放；端口与 Postgres 适配器；迁移 `collection_remittance/0003`；目录上列、HTTP、管理台；受控 CLI 与演示种子。
- 迁移 0003 只放开词表、加表与约束，不改已落行。存量里若有同一笔被冲正过两次的记账，建索引之前的预检列出（租户、被冲正的记账、各冲正记账）并拒绝施加、整笔迁移回滚，不代删任何一笔，要人回头看；演示租户满足全部各条。演示种子调了短款额，`--reset` 重灌即可。

## 越权风险点

1. **认可引用与金额登记时不核 settlement-accounting**（SA、CR owner）。SA 没有认可抵扣的只读口，CR 登记的认可引用与金额是录入的：录错金额会让渠道欠款少记，引用指不到任何认可也登得进。与 ADR-0274 越权风险点 5 同类；SA 给出只读口之后，登记时核引用在册、币种相同、同一认可下按指令拆开的各条之和不超过认可金额，另立记录。
2. **SA 一侧怎样消费这笔记账没有裁**（SA owner）。`已抵扣`的 3 在 SA 对应客户 COD 服务费应收的核销还是别的目标，本记录不裁；在 SA 定之前它只是 CR 一侧「本金因认可离开渠道欠款」的事实，不表示 SA 一侧已核销，两边只以认可引用交接。
3. **已抵扣的钱客户拿不到**（CR owner）。认可的抵扣从客户的代收本金里扣走，客户应付少了这部分；这是 settlement-accounting 拥有的有效协议所允许的，CR 不核协议是否真的与该客户签过，只核账上有没有可扣的钱。撤回走冲正。
4. **次序靠余额不足挡，不靠闸**（CR owner）。短款先落会让抵扣停在余额不足，要先冲正短款；到账没移位时抵扣停在余额不足，要先移位。运营得按到账、抵扣、短款的次序操作，UC 写明。
5. **没落账的认可没有撤回形**（CR owner）。登记后一直在册；它的认可引用不能再登记给同一条指令，撤回之后重新生效的要以新的认可引用登记。已落账的走冲正，不受此限。
6. **抵扣全额一次，不部分落账**（CR owner）。认可额大于在途时整笔停住等补报告，不先落一部分；只抵一部分要另登较小额的认可。
7. **一笔记账至多被冲正一次收紧了全部冲正**（CR owner）。此前能重复冲正的行为是缺口，不是一条规则；改后同一笔的第二次冲正答内容冲突。冲正写错了走冲正那一笔冲正，不受此限，但进入`短款`、`溢款`、`已汇付`、`已抵扣`的冲正的冲正仍被依据门拦下，要走各自的依据。
8. **取锁后再判一次重放对所有记账生效**（CR owner）。同一条命令并发到达时后到的一路答已在册，不再答来源被移空的余额不足；这是改了一处已有的答案，方向是更接近事实。

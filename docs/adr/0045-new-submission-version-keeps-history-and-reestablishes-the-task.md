# ADR-0045: 同一委托的新提交版本——当前版本单指针加历史追加，判断任务随版本重立

Status: Accepted  
Date: 2026-08-12

## Context

`AT-PS-036` 第一支要求「已提交委托补充普通资料 → 形成同一委托的新提交版本，保留原版本」，CONTEXT 同时钉了四条硬句：同一委托同一时刻**只有一个待判断的当前提交版本**；旧版本及其判断历史**继续保留**；每份已提交委托必须针对**当前提交版本**形成或续办独立的接受判断任务，且**原任务和判断历史不覆盖**；成员增删重组不走这条路，必须建立关联新委托。

今天的聚合是单版本单任务：`ShipmentRequest.currentVersion` 一个字段、`acceptanceTask` 一个字段，重建门用 `task.submissionVersionID == currentVersion.versionID` 钉住两者，反射守卫枚举恰好六条状态转移。「旧版本保留」在聚合内无处可放——这是实测钉红过的真洞（探针见 UC-PS-001 盘点，`52a5add` 时点）。聚合形状怎么扩是难逆转取舍：多版本切片一旦落进重建门，持久化形状与所有读口都随之定型。

## Decision

**当前版本保持单指针，历史另起追加切片；新版本落地时判断任务重立，旧任务停止而不是完成或删除。**

1. **`currentVersion` 仍是唯一「待判断版本」的表达。** 不改成版本数组加状态标记——「同一时刻只有一个待判断版本」由结构保证，比由每个读者自己筛一遍数组可靠。
2. **旧版本进 `priorVersions` 追加切片，旧任务进 `priorTasks`。** 只增不删、不可改写；「判断历史保留」的最小承载就是把它们原样留在聚合里，读口按需暴露。
3. **新版本必须携带自己的判断任务。** 旧任务转`已停止`（与撤回停止任务同一机制）：它没有办完，判成`已完成`是撒谎，删掉是抹历史。新任务钉住新版本号，重建门的 `task↔currentVersion` 不变量原样成立。
4. **成员集合必须与当前版本一致（集合等值，不看顺序）。** 增删拆并是「成员重组」，CONTEXT 判给关联新委托（`AT-PS-036` 第二、三支，另一个洞），这条转移拒绝它。
5. **新版本要有自己的来源身份与指纹。** 同一来源身份携带不同内容是接入冲突，不是新版本——补充请求必须以新的请求身份到达（先例：资料修订的 `AmendmentIdentity` 与原提交身份分开）。同身份同内容的重放由编排在来源保全层短路，不进本转移。
6. **决定边界不变。** 本转移只在`已提交`态合法；接受、拒绝或撤回已越过提交边界后，同一失效信号分别走资料修订（已接受）与关联新委托（已拒绝/已撤回），不得用新版本改写已决定的委托。
7. **版本编号由本上下文身份工厂签发**（与建单期同一 `SubmissionIdentityFactory` 责任），不收调用方自报的版本号——`BD-PS-005` 的接入侧版本关联契约属实例半边，未确认前不进领域。

## Consequences

- 反射守卫的转移名单从六条变七条，`revision_test` 表随本转移同轮加行；转移仍不动聚合 revision（ADR-0028）。
- `RehydrateShipmentRequestSpec` 增 `PriorVersions`/`PriorTasks`，重建不变量同轮补：历史任务必须全部处于`已停止`或`已完成`、历史版本号互异且不等于当前版本号。ADR-0030 的「只收已提交」不变——补充过的委托仍是`已提交`。
- `RecordedJudgmentReader.LoadRecordedJudgments(ctx, requestID)` 的读口没有版本参数，多版本后旧版本的判断会被读进新版本的决定。这是本记录明知的后续项：读口要长出版本维度（NR 判断键本就含 `SubmissionVersion`，缺口只在 PS 读口），随编排切片一起收，不在本记录定形状。
- 应用编排（来源保全、受控补充的授权、身份签发、重触发判断）另成切片；授权端口按三个既有授权端口的先例独立成格，不共用。

## Alternatives considered

- **版本数组加「当前」标记。** 否决：唯一待判断版本从结构保证退化为每个读者的筛选纪律，漏筛的读口全绿地读错版本。
- **旧任务判`已完成`或随版本删除。** 否决：没办完的任务记成完成是伪造历史；删除违反「原任务和判断历史不覆盖」。
- **复用原任务、改钉新版本号。** 否决：任务上的处理尝试与等待态属于旧版本的判断历史，改钉等于把两个版本的历史缝进一条时间线。
- **聚合外另存历史（仓储层版本表）。** 否决当前采用：重建门今天是聚合唯一的持久化契约面，历史出聚合就出了不变量的守备范围；等真实仓储落地再议归属，属可再议项而非本记录的锁定项。

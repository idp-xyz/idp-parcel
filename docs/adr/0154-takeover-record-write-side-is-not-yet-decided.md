# ADR-0154：接管记录的写侧尚未裁——先定谁可以写、写之前要有什么；不填 PAR-GOV-05..07 的租户值

Status: Accepted（2026-09-29 用户在本通道对四项都答「你自决」。通道 2 按已有的 `TakeOver` 选定，不新造前置，不填 `PAR-GOV-05..07`。写入口的实现不在本记录里。）
Date: 2026-09-29

## Context

**接管记录说的是对象级换权威，不是暂停，也不是阶段评审。** PN-08 把它写成：原权威停止写入之后，指定对象范围改由新权威承接，并留下交接证据；它不能被读成对交接前历史的改写或批量迁移。领域类型 `TakeoverRecord` 的形状与此一致：停止写入证据先行，新权威区间与在途盘点必备，类型上没有改写历史的入口。

**表已经在，读面已经在消费它，写入口没有。** `pilot_governance.takeover_record`（迁移 `0003_suspension_resumption_takeover`）按区间四维（对象范围、能力、事实类型、权威方）加生效区间唯一。表约束 `takeover_record_not_blank` 要求对象范围、能力、事实类型、权威方、停写证据、已接受事实、外部未决、实际控制、责任、下一步去空白；`takeover_record_inventory_present` 要求盘点是至少一行的数组；`takeover_record_bounds` 要求结束时刻为空或晚于开始时刻。委托侧归属适配器按权威区间找回这一行：找到了，归属才能往「其他权威」走，然后才投递交接（ADR-0128 决定二）；找不到，答交接未完成，不答其他权威。`parcel-governance-register` 没有接管子命令，用法只列出权威区间、暂停、恢复、阶段评审四类；不在这四类里的种类，报错括注「接管未开」。`Takeovers.Save` 的插入语句在 `incident_records.go`，生产进程没有调用方；应用层 `TakeOver` 只在测试里被调用。

**写侧没裁，是 ADR-0128 故意留下的。** 该记录决定五写明：本记录不裁 pilotgovernance 接管记录的语义与写侧，也不裁通往他方权威的协议、身份与交接证据（`PAR-GOV-05..07` 的实例半边）。所以「今天答接管未开」不是漏调用。

**三格参数都没有值，提供它们的人不是开发方。** 参数登记册当前都是「待提供」：

- `PAR-GOV-05` 紧急暂停的硬风险规则与值守授权。已确认的约束只到「仅限不可逆、违法、跨客户或事实完整性风险」。证据责任是运营、技术、合规。登记册已把不看租户就能判的硬风险检测划去产品策略票，把值守角色划去角色模型票；规则版本、范围、执行身份与值守分派仍是租户取值。
- `PAR-GOV-06` 恢复准入证据。已确认的约束是：风险解除不自动恢复，核对与盘点之后仍须显式决定。证据责任是运营、试点业务责任角色。
- `PAR-GOV-07` 发布回退、停止新准入与对象级接管条件。已确认的约束是：回退不自动改变业务权威；运营回退先停新增、在途原则上继续；确实无法继续时才对象级接管。自然发生的记录记 `P`，还没发生过就用隔离 `S`。证据责任是运营、技术。

开发方填这些值就是把租户取值写成生产默认。本记录不填。

**和另外三笔治理记录的关系，领域上已经分开，写侧还没说要不要互相引用。** 暂停决定停的是指定范围的新准入，在途继续，类型上不取消、不迁移。恢复必须指回一条暂停，并带核对与盘点，风险解除本身不恢复。阶段评审是 `Go/No-Go`，不改业务权威。`RecordTakeover` 不要求先有暂停行、阶段评审行，或一张已经插入的 `authority_interval` 行；区间形状嵌在接管记录里。它今天拒绝的是下面这些，少一件就返回 `ErrInvalidTakeover`：

- 停写证据去空白后为空
- 权威区间不成立：对象范围、能力、事实类型、权威方任一去空白后为空，或开始时刻为零，或结束时刻既不是零又没有晚于开始时刻
- 已接受事实、外部未决、实际控制、责任、下一步，任一项去空白后为空
- 在途盘点条目数为零
- 生效时刻为零

表约束 `takeover_record_not_blank` 覆盖的是其中的文本列，不覆盖生效时刻为零这一项；生效时刻为零由构造函数拒绝，到不了插入。

## 候选

五项里前四项曾经待裁。用户授权自决之后，选定写在 Decision。未选的留在这里，避免以后读成「这些也能做」。

### 1. 谁可以写

- **甲** 只开 `parcel-governance-register` 的进程级登记口，与暂停、恢复同形。人是登记输入里写明的身份，不新开 HTTP。
- **乙** 管理台治理页加写面。Intake 先挂未配置，隔离写再逐口放行。CLI 不开。
- **丙** CLI 先开，HTTP 另立一票。两票都不在本记录里实现。

### 2. 写之前要有什么

`RecordTakeover` 今天已经拒绝上一节列出的每一项。下面问的是写入口要不要在那些条件之外再加前置。

- **甲** 同一四维上必须已经有一条生效的权威区间登记。接管记录不代替那条区间。
- **乙** 必须引用一条尚未恢复的暂停决定。没有暂停，接管登记口拒绝。
- **丙** 不加前两问。写入口收下的形状与 `RecordTakeover` 今天收下的相同：停写证据、区间四维与开始时刻、已接受事实、外部未决、实际控制、责任、下一步、至少一条盘点、生效时刻，全都按上一节的条件成立；结束时刻只在有值时必须晚于开始时刻。少一件就拒绝。

### 3. 与暂停、恢复、阶段评审怎么相处

- **甲** 三笔记录互不引用。接管不结束暂停，恢复也不撤掉接管。各按自己的键存在。
- **乙** 接管只允许发生在一条未恢复的暂停之内，并且登记时写明它不恢复那条暂停。恢复仍走自己的决定。
- **丙** 接管登记的同时闭合旧权威区间。新区间仍要单独登记，不由接管记录顺带插入。

### 4. 能不能用合成 S 做演示

`PAR-GOV-07` 已写：还没自然发生就用隔离 `S`。这问的是种子要不要在写入口打开之后立刻造一行。

- **甲** 写入口打开后，允许给 `SYN-TENANT-01` 登一行合成接管，证据只记 `S`，不进参数登记册，不写生产默认。
- **乙** 写入口可以开，种子保持空表，直到证据责任方提供隔离演练的 `S` 或自然发生的 `P`。
- **丙** 写入口也先不开。等 `PAR-GOV-07` 有了租户值再另议。

### 5. 继续不开的后果

这一项不是实现选项，是把「先不开」的代价写明，供和第 4 项一起看。

今天找不着接管记录时，归属不答「其他权威」，ADR-0128 的交接步不会开始。表继续空着，页面如实空。`PAR-GOV-05..07` 要防的双写没有一份停写证据可查。这是现状，不是新缺陷。

## Decision

**一、谁可以写：先开 CLI，HTTP 另票。** 登记口加在 `parcel-governance-register`，与权威区间、暂停、恢复、阶段评审同一条命令面。应用层调用已经存在的 `TakeOver`，不另写一套校验。管理台写面不在本记录：它要另定 Intake 族，不挡住记录本身进得了册。

**二、写之前要有什么：不加构造函数以外的前置。** 不要求事先已有一条权威区间行，也不要求先有一条未恢复的暂停。`RecordTakeover` 今天拒绝的那些仍然拒绝：停写证据空白；区间四维任一空白、开始时刻为零、或结束时刻既非零又不晚于开始；已接受事实、外部未决、实际控制、责任、下一步任一空白；盘点零行；生效时刻为零。除此之外，`TakeOver` 已有的冲突预检保持：新区间撞上仍开着的既有区间就阻断，不关旧区间。

**三、与暂停、恢复、阶段评审：互不引用。** 接管不结束暂停，恢复不撤掉接管，阶段评审不产生接管。不在本记录里增加「必须落在未恢复的暂停之内」。新权威区间仍由 `TakeOver` 在入册后续办追加，这是现成行为，不是顺带闭合旧区间。

**四、合成演示：写入口可以开，种子不造行。** 不给 `SYN-TENANT-01` 编停写证据、继任权威或在途盘点。证据责任方提供隔离 `S` 或自然发生的 `P` 之前，`takeover_record` 保持空。空着是如实的，不是漏灌。

**五、继续不开的代价仍然成立，直到实现票落地。** 本记录接受之后、CLI 还没改之前，未知种类的报错仍括注「接管未开」，归属仍因没有行而不答「其他权威」。那是实现还没跟上，不是把决定改回去。

## Consequences

- 实现另派。实现只打开上面的 CLI，调用现成 `TakeOver`，不填 `PAR-GOV-05..07` 的规则版本、人、范围或阈值，不往种子里加接管行，不开 HTTP。
- 种子 README 在实现落地后改为「写入口已开、本包不造行」，不再写「接管未开」当作永久边界。
- 本记录不改 ADR-0128。决定五仍然有效：协议、身份与交接证据的实例值不在这里定。

# ADR-0214：节点控制按权威运输交接转出与转入——交接对象按正式包裹身份经节点自己的当前关联对上作业实物，转移记在只追加的节点控制转移册上、读控制时折叠，`已交接`转出此刻唯一在身的控制，撤回控制的更正入账待重算（UC-NO-005）

Status: Accepted（2026-10-19，Claude Code 会话代决：用户原话「你作为业务和系统专家自决……解决所有的问题」；票 demo-chain-gaps/61，统一代决见 `.scratch/demo-chain-gaps/handover-dispatch-plan.md`「代决」C2–C7 与「需要的 ADR」ADR-0214。决定七（转入）由票 demo-chain-gaps/62 实现。越权风险点见文末，待 NO owner 复核，TF owner 会签。） 决定七与决定四末条落地时的补充裁定见文末「补记：票 62 落决定七时的补充裁定」（2026-10-19）。
Date: 2026-10-19

## Context

- NO CONTEXT「节点控制」一节早已写下转出：「`transport-fulfillment` 针对明确对象形成权威运输交接的“已交接”结果；已拒收或待确认不转出控制」，以及逐对象纪律：「部分交接时，各对象分别结束或保留节点控制」。CONTEXT-MAP 的 `node-operations ↔ transport-fulfillment` 一条同调。
- 用例层没有承接：UC-NO-001、UC-NO-002、UC-NO-003 都把权威交接排除在外。UC-NO-004 已被身份冲突处置占用。
- 代码层的缺口：
  - 交接登记信封 `transport-fulfillment.transport-handover.registered` 只扇出给 VE 投影与 TF 派送发起，NO 收不到。
  - 消费侧适配器 `ControlTransferAdapter.TransferOut` 没有生产调用点，对身份靠交接对象与作业实物标识的字符串相等。交接对象是正式包裹身份或集运单元，控制挂在作业实物上，三者今天靠同名碰运气。
  - 节点控制只有收寄一个生产来源，存在收寄行的 `control` 列里；收寄册只追加，没有转出写口。
- 后果：控制从不转出，收寄编排认「当前收寄」时一直认那条旧收寄；包裹日后回到原节点，会被并进一条陈旧收寄（ADR-0199 决定四）。
- TF CONTEXT 的约束：「若证据已经表明实物占有发生变化……不能继续把已经没有实际保管能力的一方记为当前实物控制方」；同时禁止「直接把当前控制回退给早期交出方」。
- 节点维：交接记录今天没有节点。交出、接收、去向节点的声明由 ADR-0213（票 demo-chain-gaps/59 起草）补；转出本身不需要节点——节点随在身的控制一起来。

## Decision

**一、新立 UC-NO-005「按权威运输交接推进节点控制」，转出与转入同一用例；NO 经派发进程消费交接登记信封。**

- UC-NO-002、UC-NO-003 不动。
- 派发进程把交接登记信封再扇出一路给 NO，inbox 名 `node-operations/transfer-control-on-transport-handover`，与同一封信的其余各路分家：各记各的 inbox 账，哨兵名单也各自一份。不依赖本路在扇出里的位置——扇出每一路都调，一路停在未决不让别路重做。
- 消费侧适配器（ADR-0025）按信封的四维键（租户、对象、范围、版本）读回那一版，再问它有没有被同链后一版更正。信封里别的格不读。
- 交接的业务时间折到微秒再用：转移册落在 `timestamptz` 上，转出前与控制成立时刻比较的、与读回时比较的必须是同一个时刻。

**二、交接对象怎样对上作业实物。**

- 先问对象是不是本租户的集运单元。是：入账「待单元控制规则」，不推进。包裹号与集运单元号同串时按集运单元判。
- 否则按正式包裹身份，读本上下文收寄册上此刻关联到它的作业实物。只读各条判断链的当前有效版本——被重核、冲突或处置接续过的那一版上的关联不再算，与 ADR-0210 方向依据「读链头」同一读法。
  - 恰一件：推进。
  - 零件、多件：入账，不推进。
- 不按字符串比对象与作业实物。

**三、控制转移记在只追加的「节点控制转移册」上，读控制时折叠。**

- 一行是一版交接在一个方向上的处理结果：转出（OUT）或转入（IN），推进了（ADVANCED）或入账不推进（NOT_ADVANCED，带原因）。
- 主键是（租户，交接对象，交接范围，交接版本，方向）：同一版在同一方向上只处理一次。
- 收寄行的 `control` 列不改写。控制是否已转出，读时把转移册上的转出按（租户，作业实物，控制依据）折进去。按键读回收寄、认当前收寄与查阅目录都经同一个折叠读。
- 一份控制至多转出一次，由部分唯一索引守。
- 读在身控制之前取的实物锁，与收寄认当前收寄是同一把：转出与同一件实物的收寄、与同一件实物上的另一次转出串在一起。
- 查阅口 `/node-operations-records?registry=physical-control` 照行上列，推进的与没推进的同册。

**四、怎样判转出。**

- `已交接`即转出该实物此刻唯一在身的控制。收寄成立的与交接转入成立的都算。转出依据是交接给出的引用（`TRANSPORT-HANDOVER/<版本>`），时刻取交接的业务时间。
- 入账、不推进的几格：
  - 没有在身控制；
  - 不止一份在身控制；
  - 交接早于那一份控制成立——它说的是更早的一次占有。
- 拒收与待确认：零写入。
- 声明的交出节点（ADR-0213）与在身控制的节点不符时照转、记信息格。这一格随票 demo-chain-gaps/62 落，本记录不建列。

**五、交接更正。**

- 后继版仍是`已交接`，同链前版已转出过：零写入。
- 撤回控制的更正（同链前版转出过，这一版是拒收或待确认）：入账「控制来源链待重算」，带着先前那次转出。控制不自动回退。
- 被同链后一版更正了的那一版晚到：零写入，由后一版自己的信封决定。这一版自己已有一行时照「已在册」交回那一行。
- 同链认法：同一（对象，范围）的各版。认「前版转出过」不算这一版自己：并发里同一版先落了推进行的，答已在册。
- 撤回控制的更正不取实物锁，靠的是信封排队：TF 交接信封按（租户，载运对象）分区，派发一次只交出分区头，前版的推进行在这一版开读之前已经提交。绕过分区排队、让同一对象的两版并发跑，这一支可能读不到前版还没提交的转出而零写入。

**六、对信封的处置，判据同 ADR-0216 决定三：原样重投会不会改变结果。**

- 入账不重投：
  - 转出了、入账不推进的各格；
  - 已在册；
  - 零写入的各格。
  - 入账不推进各格判为「原样重投不会改变结果」，前提是收寄先于交接到达；反过来的次序见文末越权风险点「收寄晚于交接到达」，不靠重投补。
- 重投：交接登记册读不动，或还读不回这一版。这一路登自己的未决哨兵。
- 响亮失败，不入账、不登哨兵：
  - 信封键过不了本上下文的构造门；
  - 提供方记录与键不符；
  - 编排答出封闭集合以外的格。

**七、转入（HANDOVER_IN），由票 demo-chain-gaps/62 实现。**

- 只在`已交接`且声明了接收节点时，在该节点立 HANDOVER_IN 控制，落同一本转移册（方向 IN）。读在身控制已认这种行。
- 对不上作业实物就入账，不造待识别实物。待识别实物只能由现场观察建立。

## 候选与反方

- **在收寄行上改写 `control` 列的转出两格。** 否决。收寄册是只追加的判断链（ADR-0199），改写一行就是改写一次已经作出的判断；冲突版、重核版、处置版各抄着同一份控制，改一行漏一行就会读出两种答案。
- **另立控制表，收寄与转入都写进去。** 否决。收寄的控制起点今天随收寄判断同一笔落下，挪出去要动收寄编排与它的全部替身，而那是另一条在途会话的地盘。读时折叠只多一个函数，收寄编排一字不改。
- **转移册只记推进了的转出，不推进的不留行。** 否决。对不上实物、控制来源链待重算都要人看得见；不留行，它们只在日志里出现一次。
- **继续按字符串比交接对象与作业实物。** 否决。正式包裹身份属 PS，作业实物属 NO；同名只在合成夹具里成立。
- **不止一份在身控制时一并转出，或挑最新的一份转出。** 否决。说不出交接结束的是哪一份；一并转出会把漏登的那次交接一起抹掉，挑一份则另一份永远在身。
- **撤回控制的更正自动把控制交还交出方。** 否决。TF CONTEXT 明文禁止。
- **集运单元的交接逐成员转出。** 暂不。单元控制与成员「随单元受控」的规则还没立，拿单元的交接替成员逐件转出，就是替那条规则拍了板。

## 越权风险点（待 NO owner 复核，TF owner 会签）

1. **按集运单元判同串**（NO、TF）。包裹号与集运单元号同串时按集运单元入账，那件包裹的控制不转出。
2. **集运单元的交接暂不推进**（NO）。演示与真实网络里整袋交接是常态，成员的控制会一直在身，直到单元控制规则立起来。后继票 demo-chain-gaps/80。
3. **对象认法只读链头**（NO）。一码两物给先到那件追加冲突版之后，那件实物对不上、转出入账不推进。身份冲突期间交走的包裹，控制要等处置之后靠人补。
4. **不止一份在身控制时不推进**（NO）。本记录之前从无转出，同一件实物在两个节点各收寄过一次就会有两份在身；这类存量要靠人对账。
5. **交接早于控制成立入账**（NO）。离线补登、时钟偏差都可能落进这一格。
6. **同链按（对象，范围）认**（TF）。TF 若允许同一对象在同一范围下另起一条独立的交接，第二条会被当成第一条的更正：仍`已交接`时零写入。
7. **一次转出可能掩盖漏登的中间交接**（NO）。转出只看此刻在身的那一份，不核交出节点；ADR-0213 的节点声明落地后由票 62 记信息格。
8. **控制来源链待重算没有处置面**（NO、TF）。查阅口看得见，没有入口处置；对不上实物、不止一份在身控制等入账各格同。后继票 demo-chain-gaps/81。
9. **折叠在 SQL 函数里**（NO）。凡读收寄控制的语句都要经它读，直接读 `control` 列的新语句会读出未转出；本记录只改了今天的几处读口。
10. **收寄晚于交接到达**（NO、TF）。设备离线补登、收寄同步滞后都会让交接信封先到：NO 这一路落下 `NO_ASSOCIATED_UNIT` 或 `NO_ACTIVE_CONTROL` 并入账不重投，同一版主键已经在册，再投也只答已在册。收寄随后成立，按业务时间它早于交接，却不会再有信封来转出它；这件实物回到原节点时又会并进那条陈旧收寄，正是本记录要修的现象。决定六「原样重投不会改变结果」在这种次序下不成立。处置面随后继票 demo-chain-gaps/81；收寄成立时要不要反查转移册上同包裹、业务时间更晚的入账行，留给那张票裁。
11. **撤回控制的更正靠分区排队，不取锁**（NO、TF）。见决定五「撤回控制的更正不取实物锁」一条：同一对象的两版绕过分区并发跑时，可能转出了却没有待重算行。

## 补记：票 62 落决定七时的补充裁定（2026-10-19，Claude Code 会话代决：用户原话「你作为业务和系统专家自决……解决所有的问题」，待 NO owner 复核，TF owner 会签）

正文不改。决定七（转入）与决定四末条（交出节点声明不符的信息格）由票 [demo-chain-gaps/62](../../.scratch/demo-chain-gaps/issues/62-node-control-is-established-by-handover-in.md) 落地；落地时正文与方案 C5、C6、C7 都没裁、又必须定下的几格记在这里，越权风险点接正文编号续写。

- **两半的次序**（机制）：同一版交接在消费门那一笔事务里只读回一次，先转出、后转入，两半各认一次交接对象、各取一次同一把实物锁（咨询锁可重入）。节点之间直接交接时同一版既声明交出节点又声明接收节点，交出节点那一份先结束，接收节点才立得起。两半折成一个处置：任一半越出封闭集合即缺陷，读不动或读不回两半同停、整封重投；转入没有自己的未决哨兵。
- **没声明接收节点**（机制）：转入一侧零写入，不入账。交给运输方的交接本来就没有接收节点，ADR-0213 决定二「缺席是一种答案」，它不是待补的欠账；入账会让每一次正常交出都在转移册上留一行。
- **转入的判据**（机制）：对上一件作业实物之后，读它在本上下文有过的各份控制（在身的与已转出的，同样经折叠）。
  - 仍有在身控制：入账 `CONTROL_STILL_ACTIVE`，只带实物，不另立第二份。这一版的转出没推进（例如不止一份在身控制、交接早于控制成立），或别处的控制从没被交接结束，都落这一格：两份在身控制说不出实物在哪个节点，此后的转出也只能停在「不止一份」。
  - 最近一次转出晚于这一版的业务时间：入账 `HANDOVER_PRECEDES_RELEASE`，只带实物。这是晚到的旧交接（离线补登），它说的那段占有已经被更晚的交接结束；立起来就再没有交接来结束它。与转出那一侧「交接早于控制成立」同一个理由。
  - 否则在接收节点立 HANDOVER_IN 控制，成立时刻取交接的业务时间。同一版刚落的转出时刻与这一版相同，不挡转入。
- **转入立起的控制依据**（机制）：`HANDOVER-IN/` 后接交接键三件（对象、范围、版本），各写成「字节长度 + 冒号 + 原串」以斜杠相连。读控制时的折叠与「一份控制至多转出一次」都按（作业实物，控制依据）认，依据必须在同一件实物的各份控制之间唯一；TF 的转出引用 `TRANSPORT-HANDOVER/<版本>` 不够，交接版本只在（对象，范围）之内唯一，三件以斜杠直拼又不单射。不取摘要：依据会出现在查阅册上，人要读得出它是哪一次交接。铸法与 TF 派送发起的确定性任务引用同一种长度前缀（票 tf-face-algebra/09）。
- **接收节点照声明立**（机制）：节点就是交接声明的接收节点，NR 节点代码与本上下文收寄所在的节点是同一套指称，不换算，不核 NR 目录，也不核与交接参与方是否相符。
- **一次交接不转出它自己立起的控制**（机制）：转出那一半在锁下读到在身控制之后，剔掉同一条更正链在转入方向推进过的那一份。前版转出没推进（例如实物当时没有在身控制）、转入立起了控制，后继版仍`已交接`时按决定五重判转出；不剔掉，那次重判会把前版刚立起的控制转出去。
- **转入一侧的更正**（机制）：后继版仍`已交接`、同链前版已转入：零写入。撤回控制的更正（同链前版转入过，这一版是拒收或待确认）：入账「控制来源链待重算」，方向是转入，带先前立起的那一份控制（在身、不带转出——它此后被谁转出，看同一份控制依据的转出行）。立起的控制不撤，理由同决定五。节点之间直接交接被撤回时，两个方向各入账一行。
- **交出节点声明不符的信息格**（机制，决定四末条）：转移册加一列 `mismatched_releasing_node`。只在推进了的转出上出现，值是交接声明的交出节点，且它不是被转出那一份控制的节点；没声明、声明的就是那个节点、没推进、转入，都不在场。控制照转，不比交出方（参与方），也不因不符而入账。查阅口 `registry=physical-control` 以键 `mismatchedReleasingNode` 透出，不在场整键不出现。
- **读回门的「交接早于控制成立」**（机制，承接票 61 评审记录「`HANDOVER_PRECEDES_CONTROL` 的库面判据取「不晚于」」一条留下的读回门问题）：领域读回门放宽到「业务时间不晚于控制成立」，与迁移 0017 的 CHECK 同取；构造时仍取严格早于。控制成立时刻在收寄行上留到纳秒、落转移册截到微秒，读回门若取严格，设备报来亚微秒时刻时那一行合法入账会读不回。
- **存储**（机制）：迁移 `node_operations/0018` 加信息格一列及其形状、转入立起的控制成立时刻等于业务时间、转入专属的 `CONTROL_STILL_ACTIVE` 与 `HANDOVER_PRECEDES_RELEASE`，并把只属转出的无在身控制、不止一份、交接早于控制与只属转入的那两格各自收窄到方向；转入一侧的待重算须带交接转入成立的控制。端口加 `FindUnitControls`（同一把实物锁读有过的各份控制）；交接来源的答复加交出、接收节点两格。

越权风险点（续上文编号）：

12. **仍有在身控制时不转入**（NO）。漏登一次交出、或交出那一次转出没推进时，实物到了接收节点却没有控制；查阅口有那一行，节点上的作业照常，靠人对账。此后以接收节点为交出节点的交接会转出别处那一份，信息格显出不符。
13. **晚于最近一次转出不转入**（NO、TF）。离线补登的进节点交接若业务时间早于后来那次交出，就不立；这是有意的，但实物在那个节点的那段时间，查阅口看不到它的控制。
14. **转入依据由本上下文铸、不复用 TF 的转出引用**（NO、TF）。同一次交接在交出那一侧的转出引用是 `TRANSPORT-HANDOVER/<版本>`，在接收那一侧立起的依据是 `HANDOVER-IN/…`：两串指同一次交接，查阅要按交接键对，不按串对。
15. **接收节点照声明立、不核**（NO、NR）。ADR-0213 越权风险点「声明错了没人核」在这里的落地后果：拼错的节点上会立起控制；此后以正确节点为交出节点的交接仍转出它，信息格显出不符。
16. **运输方交进节点时转出一侧照常入账**（NO）。只声明接收节点的交接，转出那一半照决定四入账「无在身控制」，对不上实物时两半各入账一行。这是运输方交进节点的常态，处置面（票 demo-chain-gaps/81）会看到这类行；要不要在声明了接收节点、没声明交出节点时把转出那一半的这两格改为零写入，留给 NO owner 与票 81 一并裁。
17. **收寄不认交接转入立起的控制**（NO）。转入之后同一件实物又在某个节点形成节点收寄时，收寄编排只看收寄链，会再立一份，此后的转出停在「不止一份」。后继票 demo-chain-gaps/92。
18. **对不上作业实物的转入没有节点对账**（NO）。入账行不带声明的接收节点（列形里控制几格同在同缺），对账要回交接册取；方案「后继」所列「HANDOVER_IN 对不上作业实物时的节点对账」由票 demo-chain-gaps/91 承接。
19. **一次交接不转出它自己立起的控制，靠的仍是同链按（对象，范围）认**（NO、TF）。上文越权风险点「同链按（对象，范围）认」在这里多一个后果：TF 若允许同一对象在同一范围下另起一条独立的交接，它会被当成前一条的更正，不转出前一条立起的控制。

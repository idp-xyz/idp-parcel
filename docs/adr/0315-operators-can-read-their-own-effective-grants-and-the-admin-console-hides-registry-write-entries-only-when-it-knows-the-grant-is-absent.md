# ADR-0315：操作者可读自己此刻持有的授予；管理台只在明确知道没有登记册配置写授予时收起登记与发布入口

Status: Accepted（2026-10-26，Claude Code 会话代 owner 决，用户授权代决；票 party-commercial-uiux-backend/04。裁决能力边界：读过 ADR-0100 的授予模型、`OperatorEnvelope` 与 `OperatorMinter`、操作者绑定读口（`/operator-binding`）、参与方与商业区管理台各页的登记与发布入口；越权风险点见文末，待访问身份 owner 复核。）<!-- 索引注记 -->｜**入口**：管理台今天对查阅员也摆出全部登记与发布入口，提交才被服务端拒；前端没有地方知道「我持有什么」。**取法**：新增 `GET /operator-grants` 答本会话操作者此刻持有的能力面与运营决定种类（只答自己，主数据与运营查阅读守口）；管理台只在明确知道没有登记册配置写授予时收起参与方与商业区的登记与发布入口，答不出一律照摆，写口照旧在服务端判授予。
Date: 2026-10-26

## Context

- 授予在服务端的操作者册上（ADR-0100 决定二），`id_token` 里没有它。管理台因此无从区分查阅员与配置员：查阅员打开参与方与商业区，看到全部发布签、登记签、发新版本、收尾、停用入口，点下去才得到服务端的未授予。入口摆给做不了的人，是 UI 评估里点名的缺口。
- 操作者绑定读口（`/operator-binding`，票 group-legal-entities-uiux/11）已立先例：同一个铸造器、同一面守口、只答本会话自己的事。那张票的边界写明「读口能不能顺带答出授予集，不在本票的判据里」——本记录就是那个判据。
- 信封（`OperatorEnvelope`）铸造那一刻已经折好了生效的授予集：能力面一族与运营决定一族（作业事实登记按作业范围给、要带设备才铸，本来就不进管理台信封）。自查读口只需把信封上已有的东西交出来，不需要新的查询、迁移或授予。

## 候选与反方

- **前端收到拒绝后再隐藏。** 否决：入口已经摆出过、人已经点过，拒绝是事后；且一次拒绝不等于「没有授予」（可能是令牌过期或依赖故障）。
- **把授予集并进 `/operator-binding` 的答复。** 否决：绑定与授予是两件事，各有各的读者（顶栏只要绑定）；并进去等于每个读绑定的人都顺带收到授予，且那一口的注释与测试都把它定为「只答标识」。
- **在令牌里放授予声明。** 否决：授予由产品的操作者册持有、可随时登记与撤销；令牌由外部发行方签，改它要动发行方配置，且令牌有效期内的撤销会失真。
- **只在管理台按固定的角色名隐藏。** 否决：产品没有角色概念，只有授予面；前端自造一份「查阅员」就是第二份真相。
- **新读口，管理台只在明确知道没有时才收起（采纳）。**

## Decision

**一、授予自查读口。**（机制）

- `GET /operator-grants`，归 accessidentity，挂端点表的操作者查阅读面，认证件自带（`ownIntake`），与操作者绑定同款：以主数据与运营查阅读铸信封、不判准入范围。
- 答复 `{outcome: "OPERATOR_GRANTS_RESOLVED", grants: [...], decisions: [...]}`：`grants` 是铸造那一刻生效的能力面原词（`MASTER_DATA_AND_OPERATIONS_READ`、`REGISTRY_CONFIGURATION_WRITE`），`decisions` 是生效的运营决定种类原词；两者都是数组，没有就是空数组，不缺键、不是 null。作业事实登记不在里面（按作业范围给，不是管理台信封的整格授予）。
- 只答自己：授予取自令牌所证明的那个主体在操作者册上的行，没有按别的主体查询的参数，查询串里自报的主体与租户不算数；也不回绑定租户（那是 `/operator-binding` 的事）。
- 拒绝各态与其他操作者查阅口同口径（ADR-0100 决定四）：未配置 403、令牌不过 401、没有查阅读授予 403 `OPERATOR_NOT_GRANTED`（与不在册同答，不借自查口说出自己持有什么）、依赖读不动 503。

**二、管理台只在明确知道没有时才收起写入口。**（管理台形状，不是产品规则）

- 判读：只有业务成格且两个数组都在场才算拿到；其余各态（未配置、拒绝、依赖故障、读不到、答复形状不对）一律是「不知道」。登记与发布入口摆不摆：拿到了且 `grants` 里没有 `REGISTRY_CONFIGURATION_WRITE` 才收起；不知道就摆，让服务端去答。
- 摆不摆只是呈现，不是裁决：每个写口照旧在服务端判授予，拒绝仍是服务端的答案。前端的判读错了（授予刚登记、刚撤销，或答复过期）只会让入口多摆或少摆，不会放行或拦下任何写入。
- 一页加载问一次，答出的留在模块里，各页同时挂载只发一次、后挂载的页第一帧就拿到，不先摆出再收回；答不出不记，下次挂载再问。换授予要重新登录、整页重载。

**三、收哪些入口。**（管理台形状）

- 参与方与商业区各页的写入口：各册的发布页签与 JSON 发布页签、登记页签（服务形态、产品—渠道映射、客户账户、参与方登记）、目录行上的「发新版本」与「收尾…」及详情抽屉里的同名动作、参与方关系的撤销与到期、责任法人的登记、资料修订与停用入口，以及待批准发布抽屉里的批准与发布。地址里指向被收起的页签或视图（深链、别人发来的链接）落回读面，不留空白。
- 不在本记录：别的区（计价、网络、关务、追踪、结算……）的写入口与运营决定族——`decisions` 先交出来，那几区按各自的决定种类收入口时再用，不在这一票。

## Consequences

- `accessidentity`：`OperatorEnvelope` 多两个只读访问器 `Grants()`、`Decisions()`（拷贝）；`adapters/http` 多一个只读端点与它的认证件；无迁移、无新授予。
- `cmd/parcel-api`：端点表一行（`ownIntake`，同操作者绑定），装配函数一只。
- 管理台：`pages/operator-grants.ts`（判读）、`pages/use-operator-grants.ts`（一页一问的钩子）；参与方与商业区各页按它收起入口；`withNewVersionAction` 与 `VersionDetailDrawer` 各多一个开关。
- 查阅员与配置员的差别第一次在管理台上看得见；演示库里查阅员只看到读面。

## 越权风险点

1. **授予自查口对任何持查阅读授予的操作者开放，只答自己**（访问身份 owner）。它把「我持有哪几格」告诉持有令牌且有查阅读的人，没有按别的主体查的入口；没有查阅读授予的人拿到的与不在册同答。若日后要求连「我持有写授予」也不对只读操作者说，要把守口换成不依赖任何授予的认证件，那是另一个决定。
2. **前端把拒绝与读不到当「不知道」而不是「没有」**（管理台）。这使得读口坏了时入口全摆、与今天一样；代价是读口故障期间查阅员又看到全部入口。取向是宁可多摆：把一个其实持有授予的操作者的入口收掉，比让没有授予的人多看见几个入口伤害大。
3. **授予在铸造那一刻取、前端一页加载只问一次**（管理台）。授予在会话中途被登记或撤销，入口要等重新登录才随之变化；写口不受影响，服务端每次都重新判。
4. **`decisions` 先交出、本票不用**（访问身份 owner）。运营决定族的授予也在答复里，让后续按决定种类收入口的票不必再动这个读口；暴露面与 `grants` 同口径，没有额外信息。
5. **只收参与方与商业区**（管理台）。别的区的写入口今天仍对查阅员摆出，直到各区接这个读口；本记录不替它们裁。

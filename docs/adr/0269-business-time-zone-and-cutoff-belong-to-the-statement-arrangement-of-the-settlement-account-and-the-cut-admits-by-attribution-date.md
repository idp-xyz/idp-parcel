# ADR-0269：业务时区与截单时刻只登在结算账户的对账安排上，归属日判定与截单同用这一份；费用项目只登归属日形态，归属日随费用确认形成，截单按它纳入

## Context

- 业务时区与截单时刻归谁，已接受的记录说法不一：
  - [ADR-0158](./0158-settlement-account-register-is-an-immutable-tuple.md) 决定二：「对账周期、业务时区、截单时刻、付款条件不进这一行：前三格是对账安排，付款条件是商业结算政策，再存一份就有了第二权威」。settlement-accounting CONTEXT 的「截单快照」词条写「在结算账户的明确时区和截单时刻」，UC-SA-003 `AT-SA-062` 写「按账户时区和截单时刻形成范围」。
  - [ADR-0168](./0168-charge-attribution-date-is-a-registered-form.md) 决定二：「形态、时区与截单时刻按费用项目另册登记。」
- 代码只有后一处：`domain.ChargeAttributionRegistration` 按费用项目存 `timeZone` 与 `cutoffMinute`，登记口是 `parcel-settlement-register charge-attribution`；没有任何对账安排登记册。同一结算账户下不同费用项目可以登出不同的时区或截单时刻，一张对账单的「本期」在不同行上指不同的日界。一个租户同时服务不同时区的客户时，按费用项目登的时区也表达不了按户的差别。
- 截单不看归属日：`domain.CutStatementDraft` 只核 `charge.Stage() != ChargeConfirmed`、币种与去重；`CutOffPublishStatementHandler` 的费用清单来自命令的 `ChargeIDs`，`CutOffAt` 由调用方给；`application.JudgeChargeAttributionHandler` 在 `cmd/` 下没有构造。ADR-0168 越权风险点 3 已认下：「截单编排不调用这次判定。」CONTEXT 却把「形成结算归属日、尚未出账且落入截单快照」写成进入对账单的条件。
- 没有演示种子登过归属日形态。

## Decision

**一、业务时区与截单时刻只登在对账安排上，按结算账户一份。**（租户取值；登记形是机制）

- 对账安排按（租户、结算账户）登记，这一版写业务时区（IANA 名）与截单时刻；截单时刻的写法照 ADR-0168 决定二（当天的分钟数，0 到 1439，0 是一份登记、不是没登记），「达到截单时刻归到下一日」的判法不变。
- 归属日判定与截单都读这一份，不另存第二份。结算账户登记册照 ADR-0158 决定二不存这几格。
- 没登记答未配置，不预填时区或截单时刻，不拿服务器时区顶上。
- 对账安排可以追加新一版：新一版只作用于此后形成的归属日；已形成的归属日、已发布的对账单不随之改。
- 对账周期的日历仍不在这一册里：ADR-0168 否决「把账户周期一起算出来」的理由照旧成立。

**二、费用项目一册只登归属日形态。**（产品策略照 ADR-0168 决定一）

- 形态仍是来源发生（`SOURCE_OCCURRED`）或费用确认（`CHARGE_CONFIRMED`），按费用项目登记。
- 判定：形态选出时点，在这件费用所属结算账户的对账安排时区里落成公历日，本地时刻达到截单时刻归下一日。
- 形态或对账安排任一没有相符行，答未配置，并指名缺的是哪一册。

**三、归属日随费用确认形成，此后不变。**（机制）

- 费用确认的那一步按决定二判归属日，与确认同笔落库。确认时刻是确认判断给出的业务时点，来源发生时点出自费用的来源事实。
- 确认时判不出不挡确认：确认条件与归属日是两件事，归属日留空。
- 截单遇到归属日留空的已确认费用，当场按决定二判，判出即落库，此后同样不变。

**四、截单按归属日纳入。**（机制）

- 截单命令点名本期最后一个归属日。命令列出的费用里，归属日晚于它的不入本期，逐件指名；已出账的不再纳入。
- 归属日判不出的不入本期，答未配置并指名缺哪一册；不按调用方列出的清单放行。
- 截单时刻（命令的 `CutOffAt`）照旧记在草稿与快照上，作为截单这一动作的业务时点；它不再参与判哪一件费用属于本期。

## 候选与反方

- **时区与截单时刻留在费用项目一册，对账安排引用它。** 否决：同一账户的不同费用项目可以落进不同的日界；费用项目不分户，表达不了按客户的时区差别。
- **对账安排与费用项目一册各管一事、写明不一致时怎么办。** 否决：一张对账单只有一个「本期」，日界不止一套时不存在一条不让某件费用错期的裁法。
- **截单只读已形成的归属日，判不出的另开补判口。** 否决：运营多一步，补判与截单之间费用停着；而截单那一刻手上已有判定所需的一切。
- **截单命令只给截单时刻，由对账安排推出本期最后一日。** 否决：截单时刻按「达到即下一日」落日，恰在截单时刻截的那一刻落到下一日，本期边界差一天；周期日历又不在册上，推不出上界。
- **对账安排不设修订，照 ADR-0158 的不可变元组。** 否决：结算账户在责任法人、结算相对方、收付方向、结算币种、结算政策对象上唯一，要换时区就得另开一个这几格全同的账户，开不出来；时区换了一个账户就再也改不了。

## 对已接受记录的作用

- **部分停用** [ADR-0168](./0168-charge-attribution-date-is-a-registered-form.md) 决定二「形态、时区与截单时刻按费用项目另册登记。」一句里「时区与截单时刻」那一半：时区与截单时刻改登在结算账户的对账安排上（本记录决定一）。**适用场景**：全部归属日判定，不设例外。同句里形态按费用项目另册登记那一半，同决定「截单时刻是当天的分钟数，0 到 1439。0 是午夜这一份登记，不是没登记。不登任何租户的行，不预填时区或截单时刻。」各句（随时区与截单时刻搬到对账安排上照旧成立），与 ADR-0168 其余各条不变。
- **部分停用** ADR-0168 决定三「截单编排仍只读已经形成的归属日，本记录不改纳入与发布。」一句里「截单编排仍只读已经形成的归属日」那一半：截单遇到归属日留空的已确认费用当场判并落库（本记录决定三）。**适用场景**：只限确认时没判出归属日的那几件；已形成的归属日照旧只读不判。同句「本记录不改纳入与发布」是 ADR-0168 对它自己范围的陈述，不停用；同决定「没登记答未配置」「账户周期不由这次判定生成」与 ADR-0168 其余各条不变。
- 回答 ADR-0168 越权风险点 3「截单编排不调用这次判定。」：截单按归属日纳入（本记录决定四）。
- [ADR-0158](./0158-settlement-account-register-is-an-immutable-tuple.md) 决定二：不停用。本记录给它说的「对账安排」立了登记处，结算账户登记册照旧不存这几格。

## Consequences

- settlement-accounting CONTEXT：「结算账户、对账与争议」一节的对账安排、归属日两条随本记录改写，进入对账单的条件一条补上截单按归属日纳入。
- UC-SA-002 主流程确认一步补归属日随确认形成；UC-SA-003 输入语义契约的「结算账户」一行拆出对账安排与付款条件，元数据补未配置结束，主流程读归属日与形成纳入快照的步骤随之改，新立 `AT-SA-212`、`AT-SA-213`；UC-SA-002、UC-SA-003 的「给开发的交接」列现状缺口。
- 代码随 code/11：对账安排登记册（迁移另取号，`parcel-settlement-register` 另立登记命令），归属日判定改读它，费用项目一册的时区与截单时刻两列退场；费用确认同笔形成归属日；截单命令点名本期最后一个归属日，`CutStatementDraft` 按归属日纳入并逐件指名；`JudgeChargeAttributionHandler` 接进截单。费用项目一册今天没有任何种子行，迁移不必搬数。

## 越权风险点

1. **一个结算账户一个业务时区**（SA owner）。同一客户在两个时区出账要分两个结算账户；结算账户登记册上没有时区，两个账户在责任法人、结算相对方、收付方向、结算币种、结算政策对象上不能全同，所以要在结算政策对象上分开。
2. **对账安排换版不回改已形成的归属日**（SA owner）。换版前后形成的费用按各自形成时那一版落日，同一期里可能有两种日界；要整期统一，只能在期初换版。
3. **截单当场判用的是截单那一刻在册的对账安排**（SA owner）。确认时没判出、截单时才判的费用，用的不是确认那一刻的版本。
4. **截单时刻 0 会把每个时点都归到次日**（SA owner）。ADR-0168 决定二说 0 是午夜这一份登记，「达到截单时刻归下一日」的判法下，本地任何时刻都已达到 0 点；登记方要「按自然日落日」时不能登 0。本记录不改这一判法（ADR-0168 越权风险点 1 的那一格）。
5. **本期最后一个归属日由截单命令点名**（SA owner）。周期日历不在产品里，点错就错期出账；与今天由调用方列费用清单是同一类风险，但范围改由一个日期定、可以复核。

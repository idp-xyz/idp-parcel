# ADR-0195：唯一命中要没有歧义信号——号码同时被一份`已提交`委托声明时，节点答身份冲突；声明不进候选

Status: Accepted（2026-10-19。用户 2026-10-16 授权会话 `idp-parcel-9b`「你作为业务和系统专家你来自决」；该会话代 PS owner 与 NO owner 裁定，裁定原文落在票 [ps-external-mark-relations/05](../../.scratch/ps-external-mark-relations/issues/05-a-unique-hit-in-someone-elses-number-space-is-not-enough.md)「裁定（2026-10-18，会话 idp-parcel-9b 代决）」一节。本记录照它写成，补上实施时定下的形状；成文由该会话起的作者子代理完成。部分停用 [ADR-0184](./0184-external-identifier-relations-are-an-append-only-register-formed-with-their-source-facts.md) 决定五里「只交回包裹」一句，其余各条不变。本记录自身决定四一句由 [ADR-0211](./0211-an-ambiguity-only-identity-conflict-releases-by-recheck-once-the-declaration-is-gone.md) 停用，只限冲突来由为只因歧义信号的身份冲突，随票 no-reception-identity/07 进 main 生效；原句见本记录文末「复核记录二（2026-10-19，ADR-0211 部分停用一句」与 adr/README 该行。裁决能力边界：读过 PS `CONTEXT.md`「外部标识」「外部标识关联」的定义、外部标识的各条 Rules 与`委托`生命周期，NO `CONTEXT.md`「实物身份与事实完整性」与「待识别实物与身份关联」，CONTEXT-MAP `parcel-shipment → node-operations` 各句，UC-NO-002 的流程表、「权限、隔离与审计」与验收表，ADR-0184 及其复核记录、ADR-0185、ADR-0196 及其复核记录、ADR-0199；代码读过 PS 关联册读面 `FindParcelsByExternalIdentifier`、委托仓储的快照文档与 `Save`、委托状态 `ShipmentRequestState`，NO 收寄编排 `ReceiveDeliveredUnitHandler` 的明确接收支、身份读口 `ParcelIdentityView` 与防腐适配器。**没读** PS 采用节点收寄的适配器全文与 VE 追踪投影的消费者。）

Date: 2026-10-19

## Context

PS CONTEXT「外部标识关联」：客户账户给的号在该客户账户内算数。ADR-0184 决定六让核对不按范围收窄：现场观察只带一个号码，候选在租户内按号码取。它的复核记录「决定六与 UC-NO-002「权限、隔离与审计」」把不收窄的代价分格记下，「其二」是：号只在一份已接受委托里在册时，别的实物贴着同号送站，会唯一命中那一件，形成`节点收寄已形成`并建立控制。

会话 `idp-parcel-9b` 经生产装配 `buildReceptionOrchestration` 在真库上复现过下面的走法（合成夹具，证据只记 `S`）：

- **跨客户账户。** 客户账户一的委托已接受，客户包裹件号 N 进了册；客户账户二的委托也报了 N，只提交、未接受。客户二的实物贴着 N 送站，关联到客户一的包裹。
- **同一客户账户跨委托。** 同一客户账户两份委托都报了 N，只有第一份已接受。第二份的实物送站，唯一关联到第一份的包裹。

错关联会随同一封收寄信封进 PS 的采用：采用按关联到的包裹反查目标委托，UC-PS-003「适用资格判断」里客户账户一致那一项，对节点来源就成了自己比自己。NO CONTEXT 要求「无法可靠识别的到站实物必须建立待识别实物」，UC-NO-002 步骤 4 要「唯一且证据充分时关联」；NO 端口 `ParcelIdentityView` 的头注却写「恰一个→关联」，把「唯一」当成了「充分」，仓里没有记录论证过。

生产形态今天没有接单入口，风险是潜伏的；演示租户经隔离提交入口与派发受理链走得到`已接受`，提交入口只在同一草案内查重，所以同一客户账户那一格今天就走得到。

难逆转处：收寄册只追加，一次错关联落下就是历史，PS 的采用不回滚（ADR-0196 决定五同理）；读口的答复形状一旦有消费者就难改。

## Decision

适用范围：PS 的身份核对读口与它答出的歧义信号，NO 收寄编排明确接收支的身份判断，以及 ADR-0199 决定三的重核（它走同一份身份判断）。号码怎么形成关联、候选怎么取，都不改。

**一、歧义信号由 PS 随候选答出，判据是`已提交`。**

- PS 身份核对读口的答复有两半：此刻适用关联所标识的包裹候选，照旧；另加歧义信号，即号码此刻是否同时被本租户里一份`已提交`委托声明为客户包裹件号。
- **`已提交`是委托生命周期里唯一未终局又未接受的一格。** 接受判断任务等受控补充、等内部续办、等人工复核、等运营登记、等授权处置时，委托都仍是`已提交`，都算。已拒绝（含补充期限届满的确定性拒绝）与已撤回是终局，不算；已接受委托的号随接受形成关联，进候选，不经信号。草稿不在本上下文，无从算。
- **声明按委托上的客户包裹件号认**（ADR-0184 决定四：挂在委托上、首次提交时固定，不随提交版本重报）。号码逐字比，与候选同一口径；不按客户账户、分配方或交付方收窄，租户隔离照旧。
- **信号只是一个是否值。** 不交是哪份委托、哪个客户账户或哪件声明包裹；声明包裹不进候选。PS CONTEXT「接受前的声明包裹不是正式包裹，它的号码不进身份核对」那句改读为：不形成关联、不成为候选，只在委托仍为`已提交`时作歧义信号。

**二、两半在同一次读里取。** 候选与信号出自同一条语句、同一个快照。委托接受与它的关联写入同一笔事务（ADR-0184 决定三），所以在一个快照里，一份委托要么还是`已提交`、算信号，要么已接受、关联在册、是候选。分两次读，恰在两次之间被接受的那一份会两头都漏，唯一命中于是不带信号。

**三、NO 只认「恰一个候选、且没有信号」为唯一命中。** NO 端口的答复（`ParcelIdentityAnswer`）带候选与信号，认唯一只经它的 `Unique` 方法，编排不数候选。各格：

- **恰一个候选、无信号：** 唯一命中，照旧，含 ADR-0196 的按包裹认。
- **恰一个候选、带信号：** 不是唯一命中，与多候选同格。答`待识别`，收寄与控制成立，记身份冲突，候选记那一件；不问 PS 服务结果，不交意图。也不进 ADR-0196 那一支，因为它的适用范围是唯一命中：不按包裹读别的实物，不取（租户、包裹）咨询锁，不给先到那件追加冲突版。
- **零候选，有无信号都一样：** 待识别，不记身份冲突。声明不进候选；若记了冲突，那份委托接受之后的重核会跳过它（ADR-0199 决定三「记身份冲突的不重核」）。
- **多候选，有无信号都一样：** 身份冲突，照旧。

验收用例记为 UC-NO-002 的 `AT-NO-052`。

**四、重核继承这份判断。** ADR-0199 决定三写明重核「走与收寄步骤 4 同一份身份判断」：读同一个读口，拿同一份答复，经同一个 `Unique` 认唯一。

- 唯一候选带信号，落在重核「多候选」那一格：追加一版待识别，记那个候选与身份冲突。
- 零候选带信号，落在「零候选」那一格。
- 信号消失不交信封。声明它的委托被拒绝或撤回，信号就消失；但信号只会把唯一命中改成冲突，冲突行不经重核解除，零候选的待识别又本就不看信号。那份委托若被接受，关联册新形成关联，照 ADR-0199 决定三交出（租户，号码）信封，零候选的待识别由此重核。

**五、存储。** PS 不另建投影列：客户包裹件号只在委托快照里，读口按包含查快照里那一组。为此加迁移 0026，在委托表上建部分 GIN 索引，键是快照里客户包裹件号那一组，只收`已提交`的行；委托一经接受、拒绝或撤回就出索引。信号判据的状态取值由领域常量传参，SQL 只比较不拥有编号。

## 与已接受决定的关系

- **ADR-0184 决定五：部分停用「只交回包裹」一句。** 答复另带歧义信号。同句「不交分配方、客户账户或委托」照旧成立：信号只是一个是否值。其余各条不变。CONTEXT-MAP `parcel-shipment → node-operations` 与 PS CONTEXT「按外部标识核对包裹身份」随本记录同步。
- **ADR-0184 决定六：维持。** 候选与信号都不按范围收窄。本记录收住它复核记录「决定六与 UC-NO-002「权限、隔离与审计」」代价「其二」里对方已提交的那一格，即跨客户账户另一方的委托还没接受、同一客户账户另一份委托重复用号还没接受。对方从未报过这个号、对方委托已被拒绝或撤回，这两种情形不在本记录，仍是已知代价。终局方向是可验证的交付范围（票 05 裁定 (c)，随一线客户端收寄流程另立）。
- **ADR-0184 越权风险点 1「接受时形成」：不变。** 声明仍不形成关联、不进候选。
- **ADR-0196：不变。** 它只管唯一命中；带信号的一个候选不是唯一命中，不进它那一支（决定三）。
- **ADR-0199 决定三：不变。** 重核经同一份判断自然继承信号（决定四）。

## 越权风险点

1. **改 PS CONTEXT 的读法。** 「接受前的声明包裹……不进身份核对」改读为「不进候选、作歧义信号」，属 PS owner 的领域语言，由本会话代裁。
2. **合法的重复用号与持号一方自己的实物也答身份冲突。** 裁定要求复核时看的正是这一格。同一客户账户两份委托都报 N，第一份已接受、第二份还是`已提交`时，第一份那件真包裹到站也答身份冲突；跨客户账户同理，持号那一方的实物也答冲突。误报落在待识别加身份冲突，方向性作业暂停，要等身份冲突的处置能力（未立票）解开。取舍是宁可多一件待识别，也不关联错件：错关联会随收寄信封进 PS 的采用与 VE 的投影，冲突只是停下。收窄办法，比如同一客户账户内的重复用号不算信号，要以客户账户作检索条件；PS CONTEXT「按外部标识核对包裹身份」禁按分配方挑，本记录不做。
3. **带信号的一个候选不给先到那件追加冲突版。** 先到那件若在信号出现之前已唯一关联到那件包裹，方向依据里仍判身份成立。理由：先到那件关联时证据充分；后到那件到底是那件包裹还是声明方的包裹，说不出来，一码两物不成立。多候选那一格今天也是同样处理。
4. **信号消失后，已记的冲突不自动解除。** 声明的委托后来被拒绝或撤回，带信号时落下的冲突行照留，等身份冲突的处置能力。
5. **信号只认客户包裹件号的声明。** 渠道包裹件号随面单交易包裹结果受理形成，受理之前没有声明；客户参考号与渠道交易级号码今天不在册里（ADR-0184 决定二）。它们日后若有「接受前声明」，要不要进信号，由那一类进册的记录定。
6. **每次身份核对多查一张表。** 委托表与关联册都属 PS，查询在同一条语句里；量大时靠迁移 0026 的部分索引。

## Consequences

- PS：迁移一份（0026，部分 GIN 索引）；身份核对读口的答复由包裹列表改为两半的值（`ExternalIdentifierParcels`）。
- NO：身份读口的答复改为 `ParcelIdentityAnswer`，收寄编排认唯一改经 `Unique`；防腐适配器照转信号。端口头注「恰一个→关联」改为「唯一命中→关联」。
- 生产形态第一条接单入口上线之前，对方已提交的那一格修住；演示租户同一客户账户那一格即日修住。
- 票 04 刻画「其二」的真库用例按本记录翻转。翻转后的用例与新增的回归用例名见票 05 完成记录。
- `MECHANISM-INVENTORY.md` 的迁移份数随之变。

## Alternatives

- **(b) 客户编号空间的号不自动关联。** 不取：没有可验证的交付范围之前，客户包裹件号的唯一命中全都只记候选，票 02 的识别效果整体失效。
- **(c) 先建可验证的交付范围。** 记作终局方向，不在本记录：要 NO 先给交付范围建模，再改 PS CONTEXT「按外部标识核对包裹身份」与 CONTEXT-MAP 同句，另立记录部分停用 ADR-0184 决定六。
- **(d) 认作已知代价。** 不取：错关联会进 PS 的采用与 VE 的投影，靠一码两物检测与异常处置兜底，兜不住「只来一件」的错件。
- **声明进候选（预收寄）。** 不取：声明包裹不是正式包裹，关联到它会让 PS 采用一份未接受的委托；ADR-0184 越权风险点 1 的 owner 复核也维持「接受时形成」。
- **NO 自己去查 PS 的委托。** 不取：NO 只经 PS 的读口读，不读 PS 的表；判据也属 PS 的领域语言。
- **候选与信号分两次读。** 不取，理由见决定二。
- **信号交出委托或客户账户。** 不取：CONTEXT-MAP 禁交号码的分配方、客户账户或委托，NO 也用不上。
- **零候选带信号也记身份冲突。** 不取：重核会跳过它，那份委托接受之后这件实物就再也识别不出来。
- **带信号的一个候选走 ADR-0196 那一支。** 不取，理由见越权风险点 3。
- **只认跨客户账户的声明，同一客户账户的重复用号不算。** 不取：同一客户账户两份委托都报 N 时，同样说不出到站的是哪一件；而且要按客户账户挑，PS CONTEXT 禁。

## 复核记录（2026-10-19，不停用；决定原文不动）

越权风险点「合法的重复用号与持号一方自己的实物也答身份冲突」与「信号消失后，已记的冲突不自动解除」所等的「身份冲突的处置能力」，已由 [ADR-0210](./0210-identity-conflicts-are-disposed-by-an-operation-decision-and-the-identity-basis-reads-chain-heads.md) 定下：持「身份冲突处置」运营决定授予的人在冲突候选里指定一件或确认都不是，逐条判断链追加处置版（票 [no-reception-identity/04](../../.scratch/no-reception-identity/issues/04-identity-conflicts-have-a-disposition-and-release.md) 裁定，会话 `idp-parcel-9b` 代 NO owner 决，用户 2026-10-16 授权「你作为业务和系统专家你来自决」）。信号消失不自动解除，与 ADR-0210 决定一同向；自动解除要 PS 另交「声明的委托被拒绝或撤回」的信封，记作后续方向，未立票。本记录各条不变。

## 复核记录二（2026-10-19，ADR-0211 部分停用一句；决定原文不动）

会话 `idp-parcel-9b` 代 NO owner 与 PS owner 裁定只因歧义信号的冲突自动解开（票 [no-reception-identity/07](../../.scratch/no-reception-identity/issues/07-an-ambiguity-only-conflict-releases-when-the-declaration-is-gone.md)，授权同 Status 行，2026-10-19 用户就该票答「需要」），成文为 [ADR-0211](./0211-an-ambiguity-only-identity-conflict-releases-by-recheck-once-the-declaration-is-gone.md)。上一节复核记录写的「自动解除……记作后续方向，未立票」由它承接。自该票进 main 起：

1. **决定四**「信号消失不交信封。声明它的委托被拒绝或撤回，信号就消失；但信号只会把唯一命中改成冲突，冲突行不经重核解除，零候选的待识别又本就不看信号。」里「信号消失不交信封」与「冲突行不经重核解除」停用，**适用场景**只限冲突来由为只因歧义信号的身份冲突：PS 在声明它的委托由`已提交`转为`已拒绝`或`已撤回`时，按它声明的每个号交一封声明撤除门铃，这类冲突是重核对象，答唯一命中即解开（ADR-0211 决定二、三）。同句「零候选的待识别又本就不看信号」照旧。
2. **越权风险点**「信号消失后，已记的冲突不自动解除」随之失效，适用场景同上。

这一句停用超出那张票裁定的字面（裁定只点名 ADR-0210 与 ADR-0199），理由见 ADR-0211 越权风险点「停用 ADR-0195 一句」：它写的正是「信号消失不交信封」，不标出来就有两处相反的现行说法。决定一至三、决定五与其余越权风险点不变；信号的判据（`已提交`）与「信号只是一个是否值」都不变，声明撤除门铃同样只带租户与号码。

# ADR-0146：产品策略是机制与实例之间的第三类——判断方法、内置策略与随产品发布的参考配置归产品交付，实例半边只剩某租户的具体取值；参考配置须显式采用才生效；产品就绪加判「演示动线走通」

## Context

**ADR-0016 解开的死锁，在执行里换了个样子回来了。** 0016 把每个切片分成机制半边与实例半边：机制现在做，实例等租户。执行中「机制」被读窄了——只算形状、版本化、门禁与记录，而**规则本身的正文**被整块归进实例半边。结果是一批判断点有了端口、有了显式未配置，却没有任何一种判断方法可用：

- 参数登记册 `PAR-NET-14` 一格里同时写着「候选生成 / 过滤 / 排序规则」（路由算法）与「改善阈值、截单」（某租户的取值），整行标`待提供`；票 `nr-route-evidence-views/01` 的重启条件因此是「登记册这一行状态变化」，也就是等一个租户。
- 合成演示动线停在第五步「委托」：写入准入、生产归属、路由证据三堵墙里，后两堵都以「实例半边、不代拟」为由停着。
- 与此同时，开发主线按三项判据宣布了产品就绪（2026-08-28）。判据本身没问错，是第三条「参数显式未配置」让「没有判断方法」与「没有租户数值」长得一样。

ADR-0017 预先点名过这种误判：「把机制半边误判为实例半边而继续停滞」。它要求逐次分辨，但判据里没有给「规则正文」一个归属，逐次分辨照样会分错，这是结构性的。

**仓里已有两处按正确方式切开的先例。** ADR-0015：「通用性是文法的属性」——计价文法闭合、归产品，价卡的词汇与数值归租户。登记册 `PAR-NET-16`：比价必须在各候选算出计价重量之后、首发按成本单维择优、并列交人工，这些标「机制已确认」；只有候选集合与各维度取值`待提供`。另有一个现成的待决案例：ADR-0145 越权风险点 2 问 CN / SG 的公开注册号格式要不要作为产品随附的参考数据。

## 候选与反方

**甲 · 维持两分，只在执行上逐票纠偏。** 反方：ADR-0017 已经要求逐票分辨，照样分错；判据不给规则正文归属，纠偏永远在事后。否决。

**乙 · 开发方扮演假想租户，给每个参数填合成值。** 反方：ADR-0016 已否决——合成实例会混进证据台账，假想参数会悄悄变成默认值。本记录的参考配置不是它：参考配置不进任何租户的台账，也不自行生效（决定三、四）。否决。

**丙 · 产品预置默认值，租户可改（opt-out）。** 反方：碰红线「未确认参数不写死为生产默认」——没人改过的默认会在租户上线那天悄悄算出错账。否决。

**丁 · 三分：机制 / 产品策略 / 租户取值，参考配置显式采用才生效。** 即本记录。

## Decision

**一、三分。** 机制——形状、版本化、门禁与记录，ADR-0016 所定，不变。**产品策略**——判断方法：文法、内置策略形态、连接器形态，以及随产品发布的参考配置。**租户取值**——某个租户的具体数值、对象、人与阶段决定。机制与产品策略同属产品交付轨道，开发方现在就做；租户取值属租户试点轨道，照旧留空、拒绝默认。

**二、分界检验。** 一项内容若回答「系统遇到这类情况怎么判断」，且不看任何一个租户的客户、网络、合同就能给出答案，它是产品策略；若回答「这个租户具体是多少、是谁、是哪一条」，它是租户取值。产品策略可以内置多种形态供租户选，每种形态的判断逻辑归产品，租户只选形态、填数值。两类边界格：角色模型（有哪些角色、各能做什么）归产品策略，把人分派到角色归租户取值；公开标准的实例数据（国家与地区码、各国公开注册号格式与校验位算法、公开承运商接口）归参考配置（决定三）。

**三、参考配置显式采用才生效。** 参考配置随产品版本发布、版本化，在任何租户处都不自行生效。租户显式采用某一版，才进入该租户的登记册——采用就是一次普通登记，其依据格指向参考配置的标识与版本，不另造旁路。没采用的判断点照旧答`未配置`，今天的诚实行为不变。采用后租户可改，改过的就是租户取值。参考配置只含产品通用内容，不含任何租户的实例数据，敏感实例外置照旧。

**四、证据层级不动。** 演示租户经显式采用参考配置、配 `SYN-` 数据跑动线，只记 `S`；采用记录与演示数据都不进参数登记册。它证的是「产品能力可演示」，不是任何租户的证据。试点就绪与 PN-08 `Go/No-Go` 的主体与门槛不变。

**五、产品就绪判据改为四条**（运行定义以开发主线为准）：骨架完整、受控案例可复算两条不变；第三条由「参数显式未配置」改为「租户取值显式未配置，产品策略有执行器」——每个判断点至少有一种内置策略，或一份可显式采用的参考配置；新增第四条「演示动线走通」——在演示租户上经显式采用的参考配置，合成演示动线从建产品走到终局与结算，不停在`未配置`哨兵上（证据只记 `S`）。

**六、按新判据，产品就绪暂不成立。** PN-02 的可达性证据视图与 PN-03 的初始路由证据视图没有取数侧——票 `nr-route-evidence-views/01` 之所以停着，正是因为路由算法被归进了实例——至少这两处判断点没有执行器。其余切片按文件级证据重定级。2026-08-28 那次「达标」是按当时判据的如实记录，不改写。

**七、第一刀是路由。** `PAR-NET-14` 拆成产品策略（候选生成、硬约束过滤、排序策略族、冻结边界与已执行前缀的判定、并发裁决、自动 / 人工改路的判断结构）与租户取值（网络目录内容、阈值、日历与截单、权限分派、选用哪种排序策略）。首个内置排序策略沿 `PAR-NET-16` 已确认的「满足硬约束后按成本单维择优」。

## Consequences

- 开发主线「切片的机制半边与实例半边」一节按本记录写三分与四条判据；「机制半边现状」一节加 2026-09-24 补记，写明按新判据产品就绪暂不成立、其余切片待重定级。
- ADR-0016 的两条轨道、「租户实例为空不阻塞产品交付」、证据红线都不变；它的机制半边定义与第三条判据由本记录部分取代，正文不改写。
- 参数登记册仍是每租户上线模板，此后只装租户取值；逐行拆出的产品策略部分转工作票或写进对应 `CONTEXT.md`。以「实例半边」为由暂缓的 ADR 与票逐份重新定性：仍是租户取值的维持，属产品策略的转工作票；历史正文不改写。
- 实施拆在 `.scratch/product-strategy-boundary/`：重定级、登记册拆分与旧暂缓重新定性、参考配置的落法（先在注册号类型目录立样板，承接 ADR-0145 风险点 2 的归类）、路由第一刀、演示动线判据。
- 首方 API 四篇（ADR-0139 至 0142）按本记录属产品策略——接入渠道族与契约形态归产品，具体客户的凭证归租户；本记录不改变它们的 Proposed 状态，接受与否仍归用户。

## 越权风险点

1. **分界检验在「看似通用」处会判错。** 截单惯例、节假日历这类答案因地区或行业而异，应按参考配置处理而不是内置成策略；判错的代价是把某租户的取值写进了产品策略的默认里，评审要逐项盯。
2. **第四条判据把「演示动线走通」拉进产品就绪**，在路由、生产归属与结算的参考配置到位之前产品就绪都不成立。若商务上需要更早的里程碑，应另设一个，不放宽这一条。
3. **决定六只点名了能用证据坐实的两处**（PN-02 / PN-03 的路由证据视图）；其余切片重定级可能揭出更多。
4. **采用即登记、依据指向参考配置版本**，要求各登记册的依据格能容纳「参考配置 标识@版本」这种引用；某册依据格若有更窄的语义，需该上下文 owner 复核。
5. **公开标准的实例数据归参考配置**只是归类：首版随附哪些国家与地区、是否带校验位算法，归 PC owner 与用户定，本记录不替 ADR-0145 风险点 2 定发布范围。

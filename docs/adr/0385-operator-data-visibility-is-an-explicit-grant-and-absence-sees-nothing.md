# ADR-0385：操作者看得见的客户与仓是单独的授予；没授不是全部

Status: Accepted（2026-11-27，Cursor 会话代决：用户要按客户和仓切开操作者看得见的数据，原话「需要按客户和仓切开，不然多仓库，多客户很容易出问题」，随后「开始做吧」。代接入身份 owner 决，待接入身份 owner 复核。用户没有逐条确认。）<!-- 索引注记 -->｜**判据**：数据可见范围单独授予；空不是全部；全部写成显式的 *；看不见与查无同答。

Date: 2026-11-27

## Context

主数据与运营查阅读答的是「能不能进这一族读口」。进了之后，委托查阅与仓册今天按租户整本交出。一个租户有多个客户、多个仓时，客服、调度、仓内人员会看见不属于自己的客户和仓。

作业事实登记的范围不是这一刀：那一格管的是在哪个节点、场外或仓上登作业事实，而且不带范围的一笔会被读成把范围一并授出。准入范围管的是试点写入覆盖，不是查阅时看见哪些客户、哪些仓。把账户名单塞进客户侧的授权查询作用域，会把运营侧的人做成一份假的客户授权。

## 候选与反方

- **查阅读成立就看见本租户全部客户、全部仓。** 反方：多客户、多仓时，持有查阅读的人默认看见全部。用户已否定。
- **不授数据可见范围就当成全部。** 反方：与作业事实登记「不带范围等于全授」同一形状，漏登一笔就把整本租户交出去。否决。空是什么都看不见。
- **另做角色，把客户和仓收进角色。** 反方：授予仍是一笔一笔的能力面，不另造角色实体。否决。
- **把可见账户写进客户侧的授权查询作用域。** 反方：那一份作用域是客户渠道的授权，运营侧的人不是那份授权的主体。否决。

## Decision

### 一、数据可见范围是可授的一格，必带种类与引用

能力面字面量是 `DATA_VISIBILITY`。种类只有 `CUSTOMER_ACCOUNT` 与 `WAREHOUSE`。引用是该租户的客户账户标识或仓编码；`*` 是这一类的全部，而且必须写出来。缺种类、缺引用，或拿别的能力面带上这一格，都登不进册。

这一格不进信封的「持有某能力面」：它不是端点门。端点门仍是主数据与运营查阅读。铸造时把此刻生效的可见范围收成两份集合，放在信封上。

### 二、没授是什么都看不见；两维都有的行要两份都允许

没有生效的客户可见范围，客户这一维什么都看不见。仓同理。`*` 才是这一类全部。点名的标识只看见那些。同一类里既有 `*` 又有点名，按全部。

一行同时带着客户账户和仓时，两份集合都允许才看得见。只有其中一维的行，只按那一维切。看不见和查无是同一种答案，不说明是哪一维挡住的。

这不是作业事实登记的范围，也不是准入范围。

### 三、先接上委托查阅与仓册

委托查阅（委托列表、单份、复核队列、授权处置队列）按客户可见范围过滤。仓册的当前修订列表与一个仓的修订史按仓可见范围过滤。其余仍按整租户读出的操作者读口，要改成消费信封上的这两份集合；在接上之前它们仍是整租户，那是缺口，不是另一种规则。

## 对已接受记录的作用

无条款停用。作业事实登记「不带范围等于把范围一并授出」只适用于那一格，不适用于数据可见范围。

## Consequences

- 只持查阅读、没有数据可见范围的操作者，委托列表与仓册是空的，与没有这些对象同形。
- 要看见全部客户或全部仓，必须另登引用为 `*` 的授予。
- 管理台的授予词表从可授能力面与可见范围种类来，不在页面上抄第二份。

## 越权风险点

1. 决定三点名之外的操作者读口仍按整租户读出。归接入身份 owner 与各读口所在上下文的 owner。
2. `*` 是租户取值里的一个引用，写错就变成全部。归给操作者授予的人。

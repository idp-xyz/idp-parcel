# ADR-0026: 为产出消费者证明而写的持久化实现先于闸门通过，发布基线登记仍在闸门后

Status: Accepted  
Date: 2026-08-11

## Context

[ADR-0017](./0017-admission-gates-judged-by-blocking-cause.md) 把两道实现准入闸门按阻断理由分别裁决，业务语义闸门的机制半边就此放行，Bento 持久化技术闸门原样保留。保留的理由写得很清楚：它卡的是外部不可变工件不存在，既非机制半边也非实例半边，`ADR-0016` 对它无影响。

**那条阻断理由现在动了。** `go.idp.xyz/idp-bento-go` 的候选 tag 已经存在，本记录 `asOf` 由 Parcel 侧 `git ls-remote` 与 vanity metadata 匿名只读查询一手核验，不采信任何转述；具体候选、提交与 checksum 记在[决策简报](../design/parcel-go-first-consumer-slice-decision-brief.md)的「证据边界」与「实现准入检查」两节，本记录不复制第二份。简报此前写的「当前仍没有可用于消费者基线的不可变 `v0.1.0-rc.N` tag」因此不再准确。

**但候选存在不等于闸门通过。** 简报同一节表头明写「文档完成、测试通过或候选文件存在不能自动解锁」，该行「失效或复评触发」列又点名 RC 变化。候选出现触发的是**复评**，复评的结论仍可以是继续阻断。

复评一做就撞上两处死结。它们此前没暴露，不是因为没人走到这一步——恰恰相反：2026-07-31 的实现谱系（保留于 tag `archive/impl-baseline-20260731`）已经锁定 `v0.1.0-rc.2`、跑通消费者合同并产出过证明文件，走的正是本记录下面要裁的那条路。2026-08-07 的合并有意以文档基线为准、把该实现整支留作归档，文档一侧因而从未按那次实践更新。两处死结于是只存在于纸面：实践早已绕过，规则却还写着绕不过。

**第一处是循环。** 闸门的「精确解锁范围」写「本闸门通过后才解锁 PostgreSQL Repository、迁移、事务与 Outbox 实现」，而它的通过条件之一是适用 `PBC-*` 消费者证明——`PBC-02` 要证 Repository 合同、`PBC-03` 要证业务写入与 Outbox 同事务、`PBC-06` 要证迁移按 checksum 渲染。要通过得先写，要写得先通过。按字面执行，这道闸门永远不可能通过，而这显然不是它的本意：完成门禁第 8 条说的是「真实候选出现后，`PBC-01` 至 `PBC-09` 对同一版本和 checksum 通过，才可把该 Parcel 提交登记为 `B-06` 候选基线」——挡的是**登记**，不是键入代码。

**第二处是耦合。** 简报「下一步」第 5 条要求「等真实不可变 Bento RC、checksum 和适用消费者证明存在，**且业务语义闸门同时通过后**」才建持久化；而同一份简报「实现准入检查」节写「两道闸门相互独立」。两句在同一文件里互相否定。更要紧的是第 5 条那半句把持久化挂在业务语义闸门上，而按 ADR-0017 那道闸门现在只余实例半边阻断，卡的是开发方按定义取不到的租户参数——[ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md) 与 ADR-0017 已经裁过一次的死锁，换个位置又活了。

留着不裁，两条路都堵：动第一行 Repository 会被现行文档判为越闸；照第 5 条等下去，等的是取不到的东西。

## Decision

**为产出消费者证明而写的持久化实现，在闸门通过前即可写；把实现登记为发布基线仍在闸门后。** 闸门挡的从来不是键入代码，是**未经证明的东西取得基线地位**。这与 ADR-0017 把「端口接口」与「端口实现」分开裁是同一手法：分开的两半各自受不同约束，合在一起判就会让其中一半被另一半的理由无谓拖住。

**即刻解锁的范围**：针对精确 SemVer 候选编写 PostgreSQL Repository、迁移、事务与 Outbox 实现及其合同测试，用途限于产出 `PBC-01` 至 `PBC-09` 的证明。

**仍然禁止的范围不变**：本地框架替身、`replace`、`go.work`、浮动分支、框架源码副本与伪事务；以及在 `PBC-01` 至 `PBC-09` 对同一版本和 checksum 全部通过前，把该 Parcel 提交登记为 `B-06` 候选基线、宣称闸门已通过，或据此改写开发主线的横切缺口状态。

**Bento 技术闸门不与业务语义闸门联判。** 简报「下一步」第 5 条的「且业务语义闸门同时通过后」作废，以「实现准入检查」节「两道闸门相互独立」为准。持久化实现属机制半边，其阻断理由是外部工件，与租户参数无关；业务语义闸门的实例半边通过与否不改变本闸门的任何一项通过条件。

**闸门的通过条件一项不改。** ADR-0009、不可变候选、空缓存下载与适用 `PBC-*` 证明四项齐备才算通过。本记录只改这些证明**可以在什么时候产出**，不改它们证什么、也不降低任何一项的标准。

**候选的不可变性由 module checksum 认定，不由 tag 存在认定。** git tag 可以被移动或重打，而 `PBC-01` 与 `PBC-09` 要绑的是 `go.sum` 记录的 checksum 与 Parcel 的精确提交。任何「tag 已存在所以工件不可变」的推论不成立。

## Consequences

- 会出现一段「实现已写、闸门未通过」的时期。形状与 ADR-0017 接受的「接口已定、只有内存替身」同类，风险同样由 `PBC-*` 合同测试与 `UC-*` 承担。
- 简报「证据边界」节的前提事实、「实现准入检查」表的 Bento 行与「下一步」第 5 条须按本记录订正；订正只引用本记录，不在简报内另立口径。
- [开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)的「无持久化」「无事件机制」两项，在证明通过后才改状态。代码存在不改写缺口状态，否则主线会把未证明的实现记成已解的缺口。
- 新增一项判断成本：每次提交都要能说清这份实现处在「为证明而写」还是「已取得基线地位」。说不清就按后者处理，即视为未通过——默认方向必须偏向保守，因为反过来判错会让未证明的实现悄悄取得基线地位。
- **空缓存下载与 `PBC-01` 是两项证明，不是一项。** 热 `GOMODCACHE` 上的一次成功编译只证得了从正式 module path 精确版本编译这一半，证不到空缓存下载。复评时两项须分别取证。
- **`PBC-01` 的首次取证会把候选写进公共透明日志，这一步不可撤销。** 一手核验发现 Bento 远端当前是公开仓库，而本机 `GOPRIVATE` 为空、`GOSUMDB` 为 `sum.golang.org`。按 [Go Modules Reference](https://go.dev/ref/mod#checksum-database)，`go.sum` 里缺失的 hash 默认向公共校验库索取，而该库对未记入日志的版本「会先从源站抓取再回应」——**查询本身就是写入**，所以复评时不存在「先查一下看看记没记」这种无副作用的预检。一旦记入，该库保证某版本对应的比特不再逐日变化，「即便作者事后改动了仓库里的 tag」：这正是本记录所依赖的不可变性来源——tag 可以重打，透明日志里的条目不能改。代价是 `v0.1.0-rc.2` 这个版本号从此不能被 Bento 侧回收重用。取证前须在「接受该后果」与「先用 `GOPRIVATE`/`GONOSUMDB` 把该 module path 排除在公共校验外」之间明确选一个，并把所选连同理由写回简报闸门表；不得靠默认配置漂移成事实决定。
- 本记录不解除业务语义闸门的实例半边，不放宽任何真实客户、合同、金额、阈值或时限取值进入代码的禁止，也不改变证据层级——隔离环境形成的结果仍一律记为 `S`。

## Alternatives considered

- **等 `PBC-*` 通过后再写实现。** 否决：通过条件本身要求实现存在，字面执行是死循环。这不是保守，是把闸门读成了一条永不满足的条件。
- **先用本地 workspace 或 `replace` 开发，等候选稳定再换正式依赖。** 否决：`P-07` 明禁，且候选已经存在——此时改用 workspace 是主动放弃一个可用的证据级依赖，换来的实现还得再证一遍。
- **直接宣布闸门通过。** 否决：四项通过条件目前只有候选存在这一项有证据，其余三项没有；且直接违反「候选文件存在不能自动解锁」。
- **就地改简报，不立 ADR。** 否决：AGENTS.md 要求难逆转技术取舍走 ADR。简报此刻自相矛盾，需要一个外部权威来裁，就地改会让「谁改的、凭什么」无处可查，也违反单一权威。
- **保留「下一步」第 5 条的联判，等业务语义闸门实例半边通过。** 否决：那一半卡在开发方按定义取不到的租户参数。ADR-0016 与 ADR-0017 已就同一死锁裁过两次，第三次没有新理由。
- **把解锁范围放宽到全部持久化实现，不限于产出证明。** 否决：那等于取消闸门。限定用途是本记录能与「发布基线登记仍在闸门后」并存的前提——没有这条限定，「为证明而写」会迅速变成「反正都写了」。

# ADR-0020: 产品自带租户管理界面；后台 worker 是进程入口，一线作业界面未决

Status: Superseded by [ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md)  
Date: 2026-08-10  
Superseded: 2026-08-10

## Context

[ADR-0019](./0019-product-ships-tenant-facing-operator-clients.md) 决定产品自带面向租户的界面，并把开发方的跨租户运维后台排除在产品之外。这两条成立，在本记录中保留。它同时写入了一条不成立的：**「产品自带一线作业面，覆盖手持与桌面两种设备」**。

该条来自一次误读。业务方的表述是「至少有独立的管理页面和 workers」，起草时把 `worker` 读作一线作业人员，于是读成「管理页面，以及给作业人员用的页面」，并据此追问设备形态，把误读坐实。

**`worker` 在本仓指后台独立进程。** [Go 首个消费者切片决策简报](../design/parcel-go-first-consumer-slice-decision-brief.md)的包布局已规划 `cmd/parcel-outbox`（Outbox 发布进程），`P-11` 进一步给出它的运行生命周期、超时、退避与失败预算。自动化任务、重试与发布侧都属这一类，它们是本产品自己的进程，不是面向人的客户端。

误读发生且不易自查，有具体原因：各上下文 `CONTEXT.md` 大量描述「现场人员」「工位」「扫描」「点验」，使「worker 即作业人员」在本仓语境下读起来非常自然。**同一处推断此前已经出现过一次**——ADR-0018 把「桌面治理界面与工位手持扫描是两个应用」当作事实写入，同样是从**业务活动**推出**交付形态**。两次同源，都不是笔误。

因此本记录除更正结论外，明写 `worker` 的所指，使该词在本仓不再有第二种读法。

## Decision

**产品自带面向租户的管理界面。** 租户自己的管理人员使用，直接操作本产品拥有的领域对象，属于产品的一部分。承 ADR-0019 不变。

**后台 worker 是 Go 进程入口，落在 `cmd/`，不属于 `apps/`。** Outbox 发布、自动化任务、重试及其他常驻或定时进程沿用 `cmd/<binary>` 的既有布局，与客户端应用的落位和发布边界讨论无关。

**是否自带一线作业界面，未决。** 各上下文确实描述了现场人员在工位扫描与点验，但那是**业务活动**，不等于本产品交付一个作业端。此前两次把前者推成后者，均无业务方确认。按 [ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md)，本条属机制半边，**可以决定，只是尚未决定**——它不等真实租户，等的是一次明确的产品定位判断，判据用[开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)已有的能力范围判据。

**开发方的跨租户运维后台不属于产品，本记录不放行它。** 承 ADR-0019：它不卖给租户，且必须跨越 [ADR-0003](./0003-group-tenant-legal-entity-customer-account.md) 确立的租户数据隔离边界；授权模型、可见范围与审计留痕是一项独立决定，在此之前不得建立任何跨租户读取路径。

**租户的锚点货主客户界面不属于产品**，走 `PAR-INT-01` 登记的租户既有渠道。承 ADR-0019。

**落位与发布边界沿用 [ADR-0018](./0018-product-clients-share-release-boundary-under-apps.md) 经 ADR-0019 保留的结论**：产品内的客户端落在顶层 `apps/`，每端一个子目录；共享物落顶层 `packages/`；与后端同仓、同版本发布；`cmd/` 与 `internal/` 的现有边界不变；两个目录都等第一个真实端落地时才建，不预建空壳。**当前唯一确认的占用者是租户管理界面。**

## Consequences

- ADR-0019 由本记录取代。它关于管理界面与跨租户运维后台的结论有效并在此重述；关于一线作业界面的结论作废。
- **`apps/` 目前只有一个已确认的占用者。** 它是否需要「每端一个子目录」这个复数形状，取决于一线作业界面那项未决——若最终不自带，单一 `apps/admin/` 与当初被否决的根目录 `web/` 差别甚微。这不改变现在的动作（两者都不预建），但意味着**目录形状的最终形态仍悬在一项未决上**，不应被当作已经尘埃落定。
- 「worker」一词此后有权威所指。任何把 worker 读成人的表述都回到本记录纠正。
- 一线作业界面未决期间，**不得因为某个上下文描述了现场作业就顺手建立作业端**。那正是本记录要终止的推断路径。
- 其余代价——多语言 CI、发布节奏被后端锁住、每新增一个端按「服务谁」判断归属、凡需要跨租户可见性的一律排除——沿用前两份记录，本记录不重复。

## Alternatives considered

- **就地更正 ADR-0019。** 否决：红线要求不改写已接受记录，且该记录已推送。就地改会让「当时据什么决定」不可查，而两次同源的推断错误恰恰是这段历史里最值得留下的部分。
- **撤销 ADR-0019 的提交后重写。** 否决：同上；且同一分支上有并行会话在作业，回退共享历史的代价高于新增一条记录。
- **本记录一并决定是否自带一线作业界面。** 否决：同一个问题已被起草方推断错两次，第三次由同一方推断不会更准。它可定，但需要一次明确的产品判断，不该由一份更正记录顺带带过。
- **只更正 `worker` 的所指，保留一线作业界面的结论。** 否决：那条结论正是建立在误读之上，保留它等于让一个已知不成立的前提继续生效。
- **把后台 worker 也纳入 `apps/`，统一叫「应用」。** 否决：`apps/` 的存在理由是承载 Go 工具链管不到的非 Go 客户端；worker 是 Go 进程，`cmd/` 就是它的位置。合并会让 `cmd/` 与 `apps/` 的分界重新变得需要解释，而那正是 ADR-0018 花力气立起来的一条线。

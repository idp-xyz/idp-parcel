# ADR-0290：接受链形成决定处读到已撤回或已拒绝的委托，就放掉这份委托各版的占用——已接受绝不放，放不收口整轮回滚，确定未受理记进释放未受理册

Status: Accepted（2026-10-26，Claude Code 会话代 PS owner 裁定：协调方据用户「你作为业务和系统专家自决」授权，把票 [docs-consistency/code/102](../../.scratch/docs-consistency/code/102-an-acceptance-chain-round-that-waited-on-the-control-scope-lock-past-a-terminal-decision-leaves-a-fresh-occupation-nothing-releases.md) 定级 R1（首方撤回口上线前必修）、采票面方案 1，并裁定放不收口回滚、确定未受理记册不回滚；已撤回的委托在形成决定处单独认出而不先走完依据重校验、放不收口时用缺口自带的原因当未决原因、记不下册也回滚由作者代决。出处票 [code/99](../../.scratch/docs-consistency/code/99-withdrawal-review-and-disposition-take-the-request-row-before-the-control-scope-lock.md) 独立评审对反向时序的评估。部分停用（扩成）[ADR-0282](./0282-a-control-release-the-provider-refuses-is-registered-for-handling-instead-of-compensated.md) 决定二一句，部分停用（收窄）同一决定的另一句，读法限定 [ADR-0286](./0286-withdrawn-shipment-request-rehydration-by-snapshot-expressiveness.md) 决定六一句，被停原句与适用场景见「对已接受记录的作用」；两份正文不改，只在其 Status 行与 Links 加前向指针。越权风险点见文末，待 PS owner 复核。）<!-- 索引注记 -->｜**判据**：接受链形成决定那一步读到的委托是已撤回或已拒绝（不是本轮形成），而不是已接受。**放**：交回之前先按版本形成顺序取各版占用所在作用域的锁，再逐版按原关联释放；提供方按幂等答原释放，已接受绝不放。**三格**：已收口交`已决定`；可重试未形成（含取不到锁、读不回某一版的判断、确定未受理却记不下册）不交`已决定`，整轮回滚；确定未受理记进释放未受理册、不回滚、不留补偿引用。**窗口**：撤回、拒绝在链读委托之前提交的两种时序——链在作用域锁上排队，或链已写下未提交的冻结而首版委托没有已提交的占用让撤回取锁——都在链自己的事务里放掉；在读之后才提交的，链保存撞修订冲突回滚

## Context

- 接受链是一笔事务（消费门认领 inbox 行、链三步、形成决定、outbox 同笔）。链开头读一次委托，见到`已撤回`就停（ADR-0286 决定六）；之后施加控制、记控制结果、形成决定，都不再复核委托是否仍是`已提交`。撤回、主动拒绝、授权处置的`拒绝`与链并发时，这一读之后委托随时可以终结。
- 两种时序会让终结抢在链这一轮的冻结之前：
  - 链读到`已提交`之后在控制作用域锁（S）上排队——别的委托的控制也占这把锁，排队不罕见；撤回类路径先取到 S、保存委托、放掉当时已记录的占用并提交，链排到锁后照常施加新版本的控制，冻结账本新增一笔。
  - 链已在事务里写下冻结（未提交），形成决定那一步还没读委托时撤回提交。首版委托没有被取代版本，判断账里也没有已提交的占用，撤回类路径的取锁读回为空、不取 S，因此既不等链手里的 S；它的释放读不到链未提交的冻结，什么也不放。
- 两种时序的结局相同：形成决定那一步读到委托已终结，走「已有决定」或撞上`ErrDecisionAlreadyFormed`，原样交回`已决定`，链提交，冻结以`HELD`落库。撤回、拒绝那一路的释放在这一笔形成之前就跑完了，链开头的守卫只判一次，所以没有任何路径再放它；委托已终结，也没有补偿引用可续办，`cmd` 里没有释放入口。
- 这一笔真的锁资金：`FreezeLedger.Freeze` 用 `balance.Available()` 判够，孤儿冻结永久扣减同一（法人、账户、币种）作用域的可用余额，信用暴露同构；该客户后续请求可能被判可用余额不足；它悄无声息逐次累积，没有失效时限。它违反 `AT-PS-070`「撤回先合法提交 → 接受不得再成立，已成立的占用进入释放补偿」。
- ADR-0286 决定六说读到未撤回之后、占用形成之前撤回成立的窗口，由 PS 申报视图对已撤回的状态过滤（估价读不到已撤回委托，冻结形不成）和票 code/99（取委托行锁与控制作用域锁次序相反）「兜住」。这只覆盖估价读之前撤回成立的窗口，与锁序不相反带来的死锁；估价之后到链提交之前的窗口不在其内，code/99 也没有关上它。
- ADR-0282 决定二列了遇确定未受理时「业务事实照常成立、那一笔记进释放未受理册」的诸路：撤回、主动拒绝、授权处置的两个去向、自动拒绝、停进`等待受控补充`。接受链形成决定处读到终结委托不在其中；决定二也规定`可重试未形成`留补偿续办引用——这些路径的业务事实就是自己刚提交的那一笔，回滚它们等于改写业务结果，而本路径要放的占用有一笔是本轮刚在同一事务里占下的，回滚能把它整个撤回。

## Decision

**一、形成决定那一步读到已撤回或已拒绝（不是本轮形成）的委托，交回之前先放这份委托各版已成立的占用。**（机制）

- 两处入口同一判法：委托已有接受或拒绝决定的早退；委托已撤回（撤回不是接受也不是拒绝，`AcceptanceDecision` 对它报告缺席，单独认出来，而不是先走完依据重校验与签发决定标识才在 `Decide` 撞上边界）。`Decide` 交回 `ErrDecisionAlreadyFormed` 的分支保留为防御分支：这两种入口已认出，内存里的聚合上 `Decide` 也读不到别处刚落库的决定，正常到不了。
- 顺序同撤回类路径：先按版本形成顺序取各版占用所在作用域的锁（被取代各版在前、当前版本在后，同一作用域取一次；在链里是重入，单驱这一步时先 S 后 R 同样成立），再对各版逐一释放（命令指名那一版在前），经同一处释放定义收口。
- 提供方按幂等答原释放，同一份终结委托被重投信封时再放一次无害。接受链开头的撤回守卫保留：它在读委托那一刻挡住绝大多数撤回之后才消费的信封；本决定兜的是读之后的窗口。
- **已接受绝不放。** 接受成立时那笔冻结是合法的，转接受后流程；UC-PS-005 `AT-PS-071` 的口径不变。

**二、放的结果按恢复动作分格（ADR-0282 的三格）。**（机制）

- 已收口：往下交`已决定`，状态是委托此刻的状态，已撤回不带决定。
- 可重试未形成：不往下交`已决定`，交回未决，未决原因取缺口自带的那一格——`ControlReleasePending`，读不回某一版判断的 `RecordedJudgmentsUnavailable`，确定未受理却记不下册的 `ControlReleaseRefusalNotRecorded`；取不到锁与放不掉同格，落 `ControlReleasePending`。恢复动作是内部重试，消费门回滚重投（ADR-0094 决定一）。链是一笔事务，回滚把这一轮刚占下的冻结一起撤回。一版放不掉不挡其余各版去放，整轮仍回滚。
- 确定未受理（含释放口形不成三格之一）：那一笔记进释放未受理册待人处理，这一轮照常交回`已决定`并带出这一格，不回滚、不留补偿引用。终结委托上的确定拒收重投得到同一个答案，回滚只会让这一轮在重投里重复。这与 ADR-0282 决定三不同：那里是链开头放被取代各版，新版本还等着被判，拒收挡着它，所以响亮上抛；这里委托已经终结，没有东西可挡。
- 重投之后：已撤回的委托被链开头的守卫挡住，不再施加控制；已拒绝的委托没有开头守卫，回滚再重投会重复这一轮直到放掉，或耗尽失败预算而不提交——都不会留下孤儿。

**三、两个窗口都关上。**（机制）

- 撤回、拒绝在形成决定那一步读委托之前提交：链读到终结的委托，在自己的事务里把本轮占下的一笔连同其余各版放掉。无论链是在锁上排了队，还是已写下未提交的冻结，链自己的事务读得到自己的冻结与控制结果，这一点不依赖撤回类路径看得到什么。
- 撤回、拒绝在读之后才提交：链形成接受，保存委托撞上终局路径落下的修订，答未决 `StaleShipmentRequestRevision`，整轮回滚，链这一轮的冻结随之撤回，不会有孤儿。

**四、锁序。**（机制）

本路径只取 S、不保存委托，不持 R；取 S 的次序是版本形成顺序，与接受链开头放被取代各版、再施加当前版本，和撤回类路径保存之前的取锁同序，所以与它们之间不成环。不同委托的各版在同一对作用域上次序相反时 S 与 S 之间仍可成环，那是 `ports.PreAcceptanceControlScopeLock` 头注早已写明的、与本决定无关的遗留。端口头注加一条本路径。

## 候选与反方

- **取到 S 之后重读委托（票面方案 2）。** 否决：覆盖不到窗口（b）。撤回根本不等 S，重读的那一刻撤回可能还没提交，重读之后、链提交之前撤回才提交，冻结照样成孤儿。
- **形成决定读委托时加行写锁（带锁的读）。** 否决：同样能关上两个窗口，但要为每一轮链都多一次带行锁的读，换的是极少出现的窗口；仓储端口要新增一个加锁读，所有装配与替身跟着改。放占用已有现成的口、锁序与三格，只在委托已终结时才多做一步。
- **确定未受理也回滚。** 否决：重投得到同一个答案，已拒绝的信封会在失败预算里空转到死信，册上却没有这一笔的线索；已撤回的重投被守卫挡住，更早各版那一笔本该由终局路径记册，再记一次是幂等的。理由同 ADR-0282 决定二，业务事实不在这一轮里。
- **放不收口留补偿续办引用、仍交`已决定`。** 否决：终结委托上没有任何东西按引用重放，链提交时这一轮刚占下的冻结已成孤儿——就是本记录要修的缺口。
- **在终局路径一侧补：撤回、拒绝提交前把链未提交的冻结也扫一遍。** 做不到：未提交的写对别的事务不可见，也无从知道链是否在途。
- **只靠链开头的守卫。** 否决：守卫是读委托那一刻的先读后判，读之后到提交之前的窗口它看不见。

## 对已接受记录的作用

- **部分停用（扩成）** [ADR-0282](./0282-a-control-release-the-provider-refuses-is-registered-for-handling-instead-of-compensated.md) 决定二「适用的路：撤回、主动拒绝、授权处置的`拒绝`与`交客户补充`两个去向、自动拒绝、停进`等待受控补充`。」一句。**适用场景**：接受链形成决定那一步读到的委托已撤回或已拒绝（不是本轮形成），放的是这份委托各版已成立的占用；这一路遇确定未受理（与形不成三格之一）同样记进释放未受理册、不回滚、不留补偿引用。已接受的委托不适用——不放；决定二其余各句与决定三、决定四不变。
- **部分停用（收窄）** ADR-0282 决定二「`可重试未形成`照旧走 `ControlReleasePending`、留补偿续办引用。」一句。**适用场景**：只限「读到已撤回或已拒绝的委托而放它各版占用」这一路——它放的占用有一笔是本轮刚在同一事务里占下的，回滚能把它撤回，所以可重试未形成（含取不到锁、读不回某一版判断、拒收记不下册）不留补偿引用、交回未决让这一轮回滚；其余各路照原句。
- **读法限定**（不是停用）[ADR-0286](./0286-withdrawn-shipment-request-rehydration-by-snapshot-expressiveness.md) 决定六「守卫是未加锁的先读后判：读到未撤回之后、占用形成之前撤回成立的窗口，由 PS 申报视图对已撤回的状态过滤（估价读不到已撤回委托，冻结形不成）和票 docs-consistency/code/99（撤回、拒绝、处置与接受链取委托行锁与控制作用域锁次序相反）兜住；不为本票补并发用例。」一句里的「兜住」，按本记录「Context」读：它覆盖估价读之前撤回成立的窗口与锁序，不覆盖估价之后到链提交之前的窗口；后者由本记录决定一关上。正文不改，决定六其余各句与其余各条不变。
- **不停用** ADR-0282 决定三：链开头放被取代各版遇确定未受理仍响亮上抛；本记录是形成决定那一步，对象是终结委托，不是同一步。**不停用** [ADR-0081](./0081-acceptance-judgment-is-envelope-driven.md) 决定三：本路径不新增保持 `publish_failed` 响亮的格。

## Consequences

- `FormAcceptanceDecisionHandler` 的「已有决定」分支加释放，已撤回的委托在其入口单独认出；链在形成决定那一步多出几条停下的路：`ControlReleasePending`、`RecordedJudgmentsUnavailable`、`ControlReleaseRefusalNotRecorded` 回滚重投。**未决原因集合不新增取值**，消费门、HTTP 译装、`cmd` 装配、管理台与跨上下文读方都没有新落点（ADR-0025）：这几格本来就在集合里，恢复动作都是内部重试，停点仍是`形成决定`。
- 已撤回的委托在形成决定处一认出就交回，不先走依据重校验、不签发决定标识。这些在终结委托上没有意义——耗掉的标识没有任何决定会用。
- 已拒绝的委托被重投时：链先走到控制那一步。提供方若对施加交回已释放的冻结，控制那一步响亮失败（ADR-0282 后果就停在`等待受控补充`、占用已释放的那一版写过一例），到不了这里；到得了这里的，是本轮新占下、或提供方答原占用仍未释放的，由本决定放掉。
- 同一份终结委托每被驱一拍，形成决定那一步就按原关联对各版再请求一次释放，提供方幂等；多出的是几次对账本的读写，没有业务影响。
- 不动迁移：释放未受理册与判断账的形状不变。
- 文档：UC-PS-005「规则、补偿与并发」加一条、验收示例加三行、「给开发的交接」加一行，UC-PS-001「给开发的交接」加一行，PS CONTEXT 词条「控制项结果」与撤回一条各加一句，`ports.PreAcceptanceControlScopeLock` 头注加本路径；`.scratch/at-coverage-inventory.md` 补分桶行与追记。ADR-0282 的 Status 注记与 Links、ADR-0286 的 Status 注记与 Links 各加前向指针。

## 越权风险点

1. **确定未受理那一笔随这一轮提交落库。** 链提交时这一轮新占下的冻结仍是`HELD`，册上有一行待人处理；与 ADR-0282 越权风险点 1 同一缺口——册上的积压今天没有队列与告警。
2. **已拒绝的委托放不收口会让整轮重复。** 回滚重投重新施加控制再放，直到放掉或失败预算耗尽；已撤回的重投被守卫挡住，不受此影响。提供方长时间答不出时，已拒绝委托的信封会占用失败预算。
3. **窗口（a）（b）都靠仓储的修订闸门与读已提交隔离。** 终局路径在形成决定读委托之后才提交的那一半，依赖委托保存的版本闸门让链回滚，真库用例证了它；换成更强的隔离级别或换了仓储，这一半要重证。
4. **`cmd/parcel-dispatch` 链装配上的 `ScopeLock`、`Refusals` 与 `Release` 没有行为测试。** 漏接时，终结委托上的这一步恒回滚（取锁口没接上落 `ControlReleasePending`），响亮但不是在装配处响亮。code/99 越权风险点已记同一类缺口。
5. **已撤回的委托在形成决定处提前认出。** 与 `Decide` 撞上边界的结果相同，只是不先做依据重校验、不耗决定标识；日后若有新的撤回类状态，要在入口同步认出。
6. **取不到锁不退成无锁释放。** 取锁口没接上或取不到时这一步回滚，不尝试无锁的释放——那会重新引入与撤回类路径互等的次序；代价是装配缺口表现为重投空转，而不是静默。

# ADR-0349：价卡导入模板进位 PPT-2，补上最低 / 最高收费与按偏远档位查价表；页面表单提交的结构化工作簿是同一模板的第二种载体，译成同一个内部表示、走同一条读取路径；模板规格由读取模板的同一张列定义生成并经只读口交出

Status: Accepted（2026-10-29，Claude Code 会话代产品 owner、PP owner 决（代决）：价卡配置编辑器的后端第一步，起因是 ADR-0348 刚补的两处结构经导入接不进来，而编辑器要直接提交结构化数据、照规格画表单；设计由协调方派单、作者落笔，用户未逐条过目，越权风险点待 PP owner 复核。）<!-- 索引注记 -->｜**判据**：模板新增 `total_bounds` 表（最低 / 最高收费）与 `calculations` 的计算类型 `TABLE_LOOKUP_BY_REMOTE_TIER`（价表行的 `zone` 列写偏远档位），模板版本进位 `PPT-2` 且只增不改，`PPT-1` 文件照旧接受、读出与此前逐位相同；只有用到新结构的方案写 `PPC-6`；`application/json` 的请求体是结构化工作簿，译成与读电子表格同一个内部表示再走同一套译码与校验，来源标识为 `form:` 加规范化工作簿 SHA-256 前 12 位，草稿读口标明来自页面表单；`GET /pricing-price-card-template/spec` 由读取模板的同一张列定义生成规格；本记录停用 ADR-0348 决定六首项「导入暂不支持」的说法

Date: 2026-10-29

## Context

取证于 main `2986a040c`，只记 `S`。

- **导入接不进 ADR-0348 的两处结构。** 价卡导入模板 `PPT-1`（`internal/parcelpricing/adapters/pricecardtemplate`，表与列只在 `template.go` 的 `sheets` 与 `cardFields` 定义一次）没有「总额下限 / 上限」，也没有「附加费价表按偏远档位查档」的表达；[ADR-0348](./0348-a-price-card-may-declare-total-charge-bounds-and-key-a-surcharge-table-by-remote-tier-and-plans-using-them-are-written-as-ppc-6.md) 决定六因此写明「导入暂不支持，导入形成的草稿与卡永远不带这两处，也就永远写 `PPC-5`」，并把「要经导入接，得另立模板格式的决定」留给后来人。真实承运商价目表常有最低收费，这一格是上线线上的 R2。
- **规范化版本不挡模板。** `PricingPlanStructures` 在 ADR-0348 之后已有 `WithTotalChargeBounds` 与 `NewRemoteTierTableLookupSurcharge`；领域按内容自己取最低一版规范化版本（只有带新结构的方案写 `PPC-6`），所以模板这一层只要把两格翻译进去，不必也不该再判一遍版本。
- **价卡编辑器要的不是电子表格。** 管理台的价卡编辑器（下一步做）要把表单里填的东西直接提交，而不是在浏览器里拼一个 `.xlsx`：服务端读电子表格是一个严格子集，会**拒收**通用库默默转换的格（公式、带浮点尾数的数值格，规范第五节），浏览器侧生成件要逐一对上这些规矩；问题坐标是电子表格的行列，与表单字段没有自然映射；表单应用要照模板画，而不是在前端抄一份表与列的清单。
- **读电子表格的路径已经是单一语义路径。** `decodeWorkbook` 吃一份 `spreadsheet.Workbook`（表名、行号、列、格类型、字面量），之后的判定（必填、封闭取值、引用解析、领域构造门、问题清单与排序）都不看它从哪来。预览与录入共用这一条（ADR-0101 决定四）。

## Decision

**一、模板进位 `PPT-2`，只增不改，新增两样。**（机制）

- 新表 `total_bounds`：两列 `minimum`、`maximum`，至多一行，两端各自可缺、至少填一个。金额按主价表币种立，交 `NewTotalChargeBounds` 与 `PricingPlanStructures.WithTotalChargeBounds`。为正、下限不高于上限、卡声明了金额取整时落在进位单位的整数倍上，全由领域构造门判；构造门拒了，问题落在 `total_bounds` 那一行的格上（`CONSTRUCTION_REJECTED`），而不是整份方案上。整行空白即没声明（读取时空白行本就跳过）。说明里写明「合计低于最低收费补足到最低收费、高于最高收费封顶到最高收费」与取整整倍数的约束。
- `calculations.method` 新增取值 `TABLE_LOOKUP_BY_REMOTE_TIER`，交 `NewRemoteTierTableLookupSurcharge`，填 `tableId`。**价表不另造表**：它指的仍是 `tables` 里一张价表，价表行的 `zone` 列写偏远档位（`T1`、`T2`……），重量再在档位之内分档。`reference_catalogues` 里必须有一行 `REMOTE_TIER`，否则问题落在这一计算行的 `method` 格（`REFERENCE_UNRESOLVED`）并说清缘由——领域构造门也判这一条，但它的话是笼统的、不带坐标，所以模板层先把话说在格上，判不过就不再交构造门，免得同一件事报两遍。触发条件仍写在 `conditions`（哪些档位收费），价表定各档金额，与 ADR-0348 决定三一致。
- 模板里的数值是租户取值，模板不带默认；空白模板带新表与说明行，说明表点出 `PPT-1` 仍接受。

**二、规范化版本跟着内容走，模板不判。**（机制）

模板只把两格翻译进领域，不写版本：用到最低 / 最高收费或按档位查表的方案由领域写 `PPC-6`，其余方案写 `PPC-5`，文档与内容摘要一个字节不动（ADR-0348 决定四）。`PPT-2` 的文件不带新结构，读出的方案摘要与规范化版本与同一份内容写成 `PPT-1` 文件时逐位相同。

**三、模板版本与兼容：本构建认 `PPT-1` 与 `PPT-2`。**（机制）

- 判据是「只增不改」：`PPT-2` 没有动既有的任何表、列、取值与读法，所以旧版文件可以按旧版的表集合与取值用同一套翻译读，读出的方案、内容摘要、规范化版本与问题清单（含坐标与话）与进位之前逐位相同。文件声明哪一版（`card` 表的 `templateVersion`），就按哪一版读。
- `PPT-1` 文件里出现 `PPT-2` 才有的表（`total_bounds`）或取值（`TABLE_LOOKUP_BY_REMOTE_TIER`），答明确的问题：自哪一版起才有、这份文件是哪一版、请换用哪一版的模板并把 `templateVersion` 改成它；旧版文件里别的写错了的封闭取值，话里列的可取值仍是旧版那一套，不泄新取值。
- 不认的版本整份不收，话里列出本构建认的全部版本。回显的模板版本：读得出版本的文件回显它自己的版本，读不出的（不是工作簿、缺 `card` 表、版本不认）回显最新一版。
- 日后进位若不是只增不改，旧版就不再认（旧版缺的列无从补，补任何值都是替租户填卡），沿 ADR-0101 此前「一个构建一个版本」的理由，另立决定。
- 写出的空白模板标 `PPT-2`，文件名随版本（`price-card-import-template-PPT-2.xlsx`）；`PPT-1` 的静态模板文件仍留在管理台静态资源目录里（旧版文件仍被接受），不再由生成器重算。

**四、结构化工作簿（JSON）是同一模板的第二种载体，译成同一个内部表示、走同一条读取路径。**（机制）

- **形状。** `{"templateVersion":"PPT-2","sheets":{"<表名>":[{"<列键>":<字符串|数字|null>, ...}, ...], ...}}`。表名与列键逐字等于模板；一行一个对象；`card` 表照电子表格里 `card` 表的写法，每个字段一行，写成 `{"field":..,"value":..}`，字段要列全。
- **单一语义路径。** 服务端只做「载体 → `spreadsheet.Workbook`」这一步，然后交给与读文件同一个 `decodeWorkbook`。表、列、格的一切判定、问题码、问题坐标、排序、领域构造门都在这一步之后，JSON 路径没有任何自己的判定，也没有自己的问题码。同一份内容无论从哪个载体进来，读法、摘要与问题清单（表、行、列、码、话）逐字相同；行号的约定是数组下标 `i` 即第 `i+2` 行（第 1 行是列键行），与同一份内容写成电子表格时的行号一致。
- **载体特有的三条约定，都在译成内部表示这一步里落定。**（1）没有出现的表按只有列键行的空表算，不报缺表：电子表格里删掉一张表是要拦的失误，JSON 里没有「删」这回事。（2）`card` 表的字段要列全，缺字段仍报 `FIELD_MISSING`：字段行就是数据，缺了没有行号可指，补一行空的会让问题坐标指向调用方根本没发过的行。（3）外层的 `templateVersion` 在 `card` 表没有这一字段（或为空）时补进去，两处都写而不同则整份不收。
- **格的值。** 字符串；数字取书写的十进制字面量、不经浮点（与同样字面量的字符串读成同一格，`1e3` 这样的写法同电子表格里的文本一样答「不是十进制数」）；`null` 与缺键是空格；布尔按「格类型不对」报；嵌套的对象或数组不是合法的工作簿。
- **严格解析。** 同一对象里同名键出现两次、顶层多出键、尾随内容、嵌套过深都不收：后一个静默盖掉前一个，读到的就不是提交的。形状没过答整份不收（`FILE_NOT_WORKBOOK`，超技术上限答 `FILE_TOO_LARGE`，上限与文件同一组），与读文件一样，读不通是一种读法，不是 HTTP 错误。
- **HTTP。** `POST /pricing-price-card-previews` 与 `POST /pricing-price-card-drafts` 在 `Content-Type: application/json` 时把请求体当作结构化工作簿，租户与录入者仍只取认证信封，先认证、后读体；答复形状与电子表格路径一致。别的 `Content-Type` 与没有 `Content-Type` 照原样按 multipart 上传解，行为一字不变（本仓此处原先没有 415，原有的答复形式就是 400 `MALFORMED_REQUEST`）。

**五、来源标识：`form:` 加规范化工作簿散列前 12 位；草稿读口标明来自页面表单。**（机制）

- 先规范化：键排序、去多余空白、数字落成字符串、行数组保持原序。`sourceFileSha256` 是规范化字节的完整 SHA-256，`sourceFileName` 是 `form:` 加该散列前 12 位十六进制。被读的字节与身份取自的字节是同一份，空白与键序不同的同一份内容得同一个来源标识，数字写成 `12.50` 或 `"12.50"` 也一样。
- 草稿查阅读口（与录入口答复里的 `draft` 同形）对来自页面表单的草稿多一格 `sourceOrigin: "FORM"`；上传文件的草稿没有这一格，答复与此前一字不差。「来自页面表单」的认定是名称恰是自己散列推出的那一个（领域 `SourceFileIdentity.FromForm`），一个碰巧叫 `form:xxxx` 的上传文件名对不上自己字节的散列，不会被当成表单。
- 领域的草稿册与登记册不分载体：源文件身份就是名称加散列。同一方案同一版先用表单、再用文件（或反之）录入，源文件身份不同，在已批准之前按既有规则是修订（替换那一行），已批准之后内容固定——换载体不是重放。

**六、模板规格只读口。**（机制）

- `GET /pricing-price-card-template/spec`，挂主数据与运营查阅读（查阅行的 Intake，认证与授予照常，租户取认证信封，查询串封闭）。内容租户无关、随版本发布，但不因内容静态就免掉接入门。
- 答：本构建写出的模板版本与接受的全部版本；表清单（`name`、中文 `title`、一句话 `purpose`、`layout`、`repeatable`、`since`）；每张表的列（`key`、中文 `title`、`requirement`：`always` / `conditional` / `optional`，`description`，封闭取值的列另有 `allowedValues`，列表型的格另有 `multiValued`）。`card` 表的 `layout` 是 `FIELDS`——它的「列」是字段，工作簿里写成 `{field, value}` 行。
- **与代码集合同源。** 规格整个由 `sheets`、`cardFields` 与封闭取值登记处 `closedVocabulary` 生成，不手抄任何一张表、一列、一个取值。读取封闭取值格走的也是同一个登记处（`decoder.closedCode` 按格自带的表名与列键取，登记处里没有的列第一次读它就停），读取实际收的与规格口答的不会是两份；一个用例对每个封闭列塞词表之外的词，核译码话里列的恰是登记处的取值，并核登记处里的每一列都在该用例里出现。`conditions.unit` 的取值是重量单位与长度单位的并集（哪一类由 `source` 定，翻译处逐格判），规格口只能给并集，描述里写明。
- 增删一列，规格自动跟着变。

**七、编辑器与模板演进的关系。**（范围）

编辑器按规格口画表单、提交结构化工作簿，**不在前端保存表与列的清单**：模板增删表与列、增删封闭取值，规格口跟着变，编辑器照着重画即可。编辑器要做的是三件事——取规格口的 `templateVersion` 写进提交的外层、按 `requirement` 与 `allowedValues` 画控件、按问题的（表、行、列）把答复里的问题标回格上。仍要前端手工的是需要专门交互的结构（条件树、计算树的父子关系、价表的行集），规格只描述列，不描述怎么画树。模板进位时规格口的版本变了，编辑器应当比较自己见过的版本、不认识的提示刷新，而不是照旧提交。

**八、暂不支持的。**（范围）

- **已登记价卡反推成模板。** 模板只管「填进去」：一张已登记价卡（规范化文档）没有反向译成电子表格或结构化工作簿的路，编辑器要「打开已有价卡改一版」得另立。内容读口（`GET /pricing-price-cards/content`）交的是规范化文档，不是工作簿。
- **带指纹或摘要的版本引用**：规范第九节原有，不变。
- **一份工作簿多个方案版本**：一份工作簿恰是一张价卡的一个版本。
- **总额上下限的口径与联合键**：总额上下限只对整票全部费用行之和生效，不分基数；偏远档位只作单独的查表键，没有分区 × 档位联合键（ADR-0348 越权风险点 0、9）。这是领域未表达，不是模板缺的。
- **原始提交本体的存放**：表单草稿同电子表格草稿一样只记名称与散列，规范化工作簿的本体不存（ADR-0008 外置证据库的连接器尚无）。散列让人能核对「重交的是不是同一份」，还原不出它。

## Alternatives considered

- **新表 `remote_tier_amounts`（`ruleId`、`tier`、`amount`）加计算类型。** 否决：它只能表达每档一个金额，丢了重量分档（ADR-0348 决定三明确价表条目「重量再在档位之内分档」）；还得再造一套价表标识、行标识、币种、重量单位与有效期，或者约定去合成它们——合成出的标识与种子里的不会一样，「用模板重新表达 FULL-03 得到同一份计划与同一个摘要」就不成立。复用 `tables` 与 `rates_*` 一张新表都不要，只在 `zone` 列的说明里写明承载档位。
- **编辑器在浏览器里生成 `.xlsx` 再上传。** 否决：见 Context。服务端读电子表格的严格子集要拒收浏览器生成件里不期而至的格类型，问题坐标是电子表格的行列，前端要为此同时维护一份与服务端同步的生成逻辑和列清单。
- **JSON 路径另写一套解码（JSON 直接 → 领域构造）。** 否决：这正是语义分叉。必填、封闭取值、引用解析、问题码与排序在两处各一份，任何一边改了规则另一边就漏；「预览通过、录入却不同」那一格（ADR-0101 决定四）会从载体之间长出来。
- **JSON 路径用新端点（如 `/pricing-price-card-workbook-previews`）。** 否决：同一件事两个路径，端点表、授予与探针要各配一份；按 `Content-Type` 分流，答复形状、授予与租户来源都是同一个。代价是 `Content-Type` 成了分流键，别的类型必须照旧答原有的 400，已用例钉住。
- **JSON 路径下缺的字段、缺的表一律补空。** 取一半：缺的**表**补空（没有行号可指的地方补空不会让坐标说谎），缺的 **`card` 字段**不补（字段行就是数据，补出来的行号是调用方没发过的）。
- **不再接受 `PPT-1`，强制升级。** 否决：租户手里已有按 `PPT-1` 填好的文件，`PPT-2` 又是纯增量，保留旧版读法的代价几乎为零，拒收的代价是让运营白填。
- **规格放成前端静态文件。** 否决：那正是本记录要消灭的「前端抄一份」；静态文件与读取实际收的取值之间没有任何东西守着它们不漂开。
- **来源标识用随机编号或提交时间。** 否决：同一份内容再提交该是重放而不是新行；散列由内容定，重放判据（源文件身份相同）原样可用。
- **规格口不挂接入门（内容静态、租户无关）。** 否决：同端点表里每条读行同口径；去掉接入门是给未认证来者一张产品内部表结构的清单，即使它是静态的。

## Consequences

- `internal/parcelpricing/adapters/pricecardtemplate`：`template.go` 新增 `total_bounds` 表、列的中文名与封闭取值登记处、模板版本的先后序与可用性判；`decode.go` 先认版本再按版本挑表集合与取值，新增 `readTotalBounds` 与 `checkRemoteTierBinding`；`workbook_json.go` 是载体译法（严格解析、规范化、译成 `spreadsheet.Workbook`）；`spec.go` 生成规格；`write.go` 写 `PPT-2` 空白模板。`apps/admin-web/public/templates/` 新增 `price-card-import-template-PPT-2.xlsx`（管理台「导入价卡」签目前仍指向 `PPT-1` 那份，仍有效；换指向归编辑器那一步）。
- `internal/parcelpricing/ports`：新增 `PriceCardWorkbookReader`、`PriceCardWorkbookRejection`、`PriceCardTemplateSpec` 与 `PriceCardTemplateSpecSource`；既有的 `PriceCardTemplateReader` 一字不动。`application` 的预览与录入命令多一个 `FromForm`，构造函数多一个可选件 `WithWorkbookReader`；`domain` 新增 `NewFormSourceFileIdentity` 与 `SourceFileIdentity.FromForm`。无迁移、无库表。
- `internal/parcelpricing/adapters/http`：预览与录入的 Intake 按 `Content-Type` 分流，草稿本体多可缺的 `sourceOrigin`，新增规格口；`cmd/parcel-api` 端点表多一行 `/pricing-price-card-template/spec`（主数据与运营查阅读），装配点给预览与录入装同一个工作簿读口。
- **导入从此能造出 `PPC-6` 的价卡**（ADR-0348 此前写「导入永远写 `PPC-5`」，现不成立）：见风险点 5。
- ADR-0348 决定六首项等「导入暂不支持」的说法被本记录停用（该记录的 `Status` 与 Links 各有前向指针）；UC-PP-001 的「给开发的交接」同步改成现行。

## 越权风险点

0. **载体分叉的防范。**（决定四）JSON 路径与电子表格路径的语义是否分叉，守在两样东西上：结构上只有一个 `decodeWorkbook`，JSON 载体译成 `spreadsheet.Workbook` 后不再有自己的判定；用例上，一组同内容的卡（已校验的几张、各类带问题的写法）各写成电子表格与结构化工作簿，逐字比对读法的版本回显、受理与否、方案身份、摘要、规范化版本、登记快照里的 plan 块以及问题清单的每一条（表、行、列、码、话）。载体特有的三条约定（缺表补空、`card` 字段列全、外层版本补进）是唯一的载体差异，已在决定四与规范第十节写明。归 PP owner。
1. **规格口与代码集合同源。**（决定六）靠 `closedVocabulary` 一处登记、读取与规格都从它取，加上一个用例对每个封闭列验过；新加一个封闭取值列忘了登记，第一次读它就停（panic），不会悄悄漏。没被登记处覆盖的是「列的中文名与说明」——它们跟着 `sheets` 里同一行，不会漂开，但说明的措辞是否准确要人读。归 PP owner。
2. **`sourceFileName` 的约定。**（决定五）名称 `form:<散列前 12 位>` 是展示用的约定，不是安全边界：认定的是名称恰是自己散列推出的那个，12 位十六进制足够区分一张卡的几个版本，不防人故意造撞（名称撞了只影响「来自页面表单」这一格显示，不影响身份判等，判等看完整散列）。换载体录同一内容是修订不是重放（决定五末项），这是有意的：来源证据不同。归 PP owner。
3. **导入暂不支持项。**（决定八）列出了仍不支持的几项；最影响编辑器的是「已登记价卡反推成模板」——没有它，编辑器只能新建，不能打开一张已登记的卡改一版。是另一张票。归 PP owner 与产品。
4. **编辑器与模板演进。**（决定七）规格口让「表与列的清单」不必在前端抄，但不让「怎么画树」自动化；模板进位时编辑器若不比较版本，会照旧提交旧形状。进位只增不改时旧版提交仍被接受，所以这一格的后果是缺新功能，不是被拒。归前端与 PP owner。
5. **`PPC-6` 现在可经导入产生，滚动发布的运维约束从文档约束变成真实风险。**（决定二）ADR-0348 风险点 6 写的「第一张 `PPC-6` 价卡登记之前，所有读价卡的进程必须已是新构建」当时靠「导入永远写 `PPC-5`」少了一条入口；本记录之后任何持登记写授予的操作者都能经导入、批准、发布造出 `PPC-6` 的卡。代码里仍然没有门拦着：旧进程遇到 `PPC-6` 卡时出错即停、不会算错金额，但租户级的序列与目录登记 / 复核会整笔失败。ADR-0348 列为后续加固的「登记 `PPC-6` 价卡前要求一个显式部署开关，默认关」因此升了优先级；本记录不做，因为开关属于登记门而不属于模板。归运维与 PP owner。
6. **`PPT-1` 兼容窗口没有终点。**（决定三）只要每次进位都只增不改，旧版就一直可读，窗口不会自己关；真出现不能只增的改动要另立决定，且要先问清还有多少旧版文件在用。归 PP owner。
7. **`zone` 列承载档位的命名。**（决定一）按档位查表的价表行里，档位写在名叫 `zone` 的列里；这是为了不另造价表族而接受的命名不贴切，已在各价表行表的 `zone` 说明与计算树的 `method` 说明里写明。改名就是改列语义，要进位。归 PP owner。
8. **「一行都没填」与「明确不设上下限」不可分。**（决定一）`total_bounds` 的空白行读取时被跳过，所以没填和填了空是一回事；对一张没有最低收费的卡这就是对的，不构成问题，记在此处只为将来有人想表达「明确不设」时知道这条路走不通。归 PP owner。

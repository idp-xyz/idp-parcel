# ADR-0343：费用确认在确认同笔事务里把该件包裹的接受前占用转正式扣费，信用状况把已确认未结算进额度占用

Status: Accepted（2026-10-28，Claude Code 会话代 SA owner 决（代决）：票 launch-wiring/07，起因 psb/05 收口重走停点三——第一件终局、费用确认、对账单发布之后接受前占用仍在，第三件委托答 `AVAILABLE_BALANCE_INSUFFICIENT`；协调方按冻结清单「上线线」口径上调为挡上线。用户 2026-10-28 答「现在就接线」覆盖这一批票；本记录的取舍用户未逐条过目，越权风险点待 SA owner 复核。）<!-- 索引注记 -->｜**转出时点**：费用确认的事务里，按「费用 → SELL 评价请求 → 包裹 → 受理前估价留痕 → 控制请求 → 两本占用账」认领，这件包裹的份额整份一次转出；转出后同事务按 ADR-0181 决定三的唯一求法重算入账余额与已确认未结。**差额**：不立科目，占用离开、实际金额进已确认未结，两者之差自然落进可用余额。**授信**：信用状况的已占用额度 = 暴露账本占用 + 该作用域已确认未结；核销让已确认未结下降，额度随之恢复。**范围**：只覆盖确认；已接受委托下某件包裹取消或失败时释放它的份额不在此内。

Date: 2026-10-28

## Context

取证于 main `489db2936`，只记 `S`。

- SA CONTEXT 写了两句现行规则：「冻结后必须转为正式扣费或显式释放」「费用确认后将适用冻结转为正式扣费；取消或失败时显式释放」。代码里只有后半句的一部分——`ReleasePreAcceptanceControlHandler` 服务接受失败、拒绝、撤回一类释放；费用确认（`ConfirmChargeHandler`，ADR-0336）与对账单发布（ADR-0339）都不读写冻结账本与暴露账本。
- 后果两头同形：预付的冻结永远挂着，可用余额 = 入账余额 − 冻结 − 已确认未结；而已确认未结在没有映射或核销之前不推进，确认的钱既不在「未结」里，冻结也不放，估价与确认额的差永远不对账。授信的暴露永远挂着，付清（核销）也不放，额度在「额度 ÷ 每件估价」件后耗尽，没有任何生产绕法。
- ADR-0181 决定二、决定三已定：已确认未结 = 当前有效的已确认客户运营应收 − 指向它们的核销分配净额，由同一个函数求，调用点之一就是「确认费用的事务」，首切没做。入账余额 = 已映射收付净额 − 核销分配净额，「不把确认费用高于冻结写进入账余额的负数」。
- 一次接受前控制占用的金额是各件试算合计之和（ADR-0179 决定二），受理前估价留痕（`pre_acceptance_estimate_trace`）按控制请求逐件平铺了试算，每件带包裹标识；控制请求身份就是接受前控制的原业务关联（`controlRequestIdentity`），占用所在的结算作用域随控制结果保存在 PS 一侧，SA 一侧账本行也以（租户、法人、账户、币种、控制请求）为键。一件包裹的费用由 SELL 评价请求（`sell_evaluation_request`）形成，请求上记着包裹与费用标识。
- 费用确认只在有效交付终局时发生（ADR-0336），一件包裹的几笔费用先后确认。

## Decision

**一、转出发生在费用确认的同一笔事务里。** `ConfirmChargeHandler` 在费用定格（含重放读回已确认、并发二确落败读回赢家）之后调 `ConvertOccupationOnChargeConfirmationHandler`；它失败即错误交回、调用方事务整笔回滚——不翻成未决，因为费用行已写，翻成未决会把「确认了、占用还挂着」提交出去。对账单发布不碰占用：发布是把已确认费用列入对账单，不改变费用对占用的关系。

**二、按原业务关联认领，不重新推导。** 费用 → 形成它的 SELL 评价请求 → 包裹 → 本作用域受理前估价留痕里这件包裹挂着的各控制请求 → 各请求在冻结账本与暴露账本上的占用。作用域取费用确认时固定的责任法人、结算账户与结算币种（与占用当初保存的是同一个）。被取代版本的请求也在留痕里，是否仍占着由账本状态回答（已释放的不转）。认领不到（费用不是包裹计费时点那一路、包裹不在留痕里、占用已释放）没有可转，不是失败。

**三、转多少、何时转：这件包裹在估价里的份额，整份、一次。** 份额 = 留痕里这件包裹的试算合计，各件份额之和等于占用原金额。以（占用、包裹、占用种类）为键记一行转出册，同键再来是重放、不二转；同一件包裹后续费用再确认时份额已转出，只重算。冻结与暴露各转各的（ADR-0047 两本账互不借用，组合策略下各有一份）。账本行记「已转出金额」与「最近转出时刻」：转满标 `CONVERTED`，部分转出仍占着余额（`HeldMinor`、`ExposedMinor` 求和用「原金额 − 已转出」）；原金额与原发生时间不改写。

**四、估价与确认额的差不另立科目。** 转出让占用离开，实际确认额按 ADR-0181 决定三进已确认未结，两者之差就是自然落差：估价高于实际，可用余额回升；估价低于实际，差额同样完整入账、可用余额随之为负，不截断到占用金额（CONTEXT「最终确认费用高于冻结金额时必须完整入账」）。入账余额一列不动——它只随已映射收付与核销变化（ADR-0181 决定二），「正式扣费」在本上下文的算式里就是进入已确认未结。

**五、转出同事务重算该作用域。** 确认费用调用 ADR-0181 决定三的唯一求法（`recomputeCustomerScope`，映射、核销、撤销共用的同一个函数），不另推增量。账不平（求出已确认未结为负）沿用该函数的答案：推进失败、整笔回滚。作用域上从未登记运营余额的，这一次推进即建立该行——此后预付冻结读到的是有行的余额（入账可为 0、可用为负），不再是`余额不可用`。

**六、信用状况把已确认未结算进已占用额度。** `CreditStandings.LoadCreditStanding` 的已占用额度 = 暴露账本占用 + 该作用域运营余额行上的已确认未结（无行按 0）。没有这一条，暴露一转出额度就凭空空出来，授信客户的欠款不再占任何额度；有了它，确认把占用从暴露挪给已确认未结、额度占用不变，核销让已确认未结下降、额度恢复。逾期的判断与写入不动（ADR-0182）。

**七、部分转出的释放只放余额；转满的没有可放的东西。** 释放编排对 `CONVERTED` 的占用按`无可释放`答；对仍占着的部分转出行只放余额，已转出的部分已是正式扣费、不随释放回流。PS 一侧适配器把 `CONVERTED` 与占着同样译为成立，重放一次施加交回原占用不翻成未通过。

**八、覆盖范围到哪。** 本记录覆盖「确认」这一个转出触发。已接受的委托下某件包裹取消或失败时释放它的份额（CONTEXT「取消或失败时显式释放」的包裹粒度）没有触发口——PS 在委托已接受之后不再请求释放占用（ADR-0290「已接受的委托绝不放」），本记录不替它发明触发，转出册与账本的「部分转出、余额可放」形状已为它留好；该份额在触发口出现之前一直占着。

## Alternatives considered

- **按费用金额逐笔、转 min(费用额，余额)。** 否决：确认只在终局发生，一件包裹的费用先后确认，逐笔转会在实际低于估价时留下永远转不满、也没有「这件包裹到此为止」信号去放的尾巴；整份转则一件一次、无尾巴。代价：同一件包裹的后续费用确认之前，该件的占用已全部离开——它们在确认的同一刻进已确认未结，窗口只在事务之内，不可见。
- **转出时扣入账余额。** 否决：ADR-0181 决定二把入账余额定义为已映射收付与核销的净额，「不把确认费用高于冻结写进入账余额的负数」；扣了入账余额，核销时再等额扣一次，同一笔钱扣两遍。
- **对账单发布时转。** 否决：发布是运营决定（ADR-0339），可以不发生或晚很多；占用在费用确认时就该让位给已确认未结，否则两者同时占着一份钱。
- **作为 `charge-confirmation.formed` 信封的异步消费者。** 否决：信封本身无消费者，且异步会让「确认了、占用还挂着」成为可观察的中间态——这正是要消除的现象；与 ADR-0181 否决乙（异步投影）同理。
- **暴露账本转出后额度占用交给对账单金额承担。** 否决：对账单是可选且晚到的；额度占用要随费用确认就位，已确认未结是现成、同源、随核销下降的那一格。

## Consequences

- 迁移 `0051_pre_acceptance_control_conversion.sql`：冻结与暴露行加 `converted_minor`、`converted_at`，状态加第四格 `4=CONVERTED`，新表 `pre_acceptance_control_conversion`。
- SA CONTEXT「运营结算余额……」与「资金冻结与核销」补转出与授信额度占用的现行规则；UC-SA-002「给开发的交接」指向本记录。
- 确认费用之后的调整（计价纠错、商业让利）会改当前有效的客户应收，ADR-0181 决定三点名它也该调用同一个重算；本记录没有挂它——调整形成的事务里已确认未结在下一次映射、核销或确认之前停在旧值。
- 找不到触发口的两格留着：包裹取消或失败释放份额（决定八）；估价留痕之外形成的占用（存量）。

## 越权风险点

1. 整份、一次的转出时点（决定三）。选的是「确认时一次转完这件包裹的份额」，替代是逐笔按额转。若某租户的一件包裹有几笔终局后才逐日确认的费用，整份转让后到的费用在确认之前不占任何额度——它们本就未确认，不占；但这一取舍是会话代 SA owner 做的。归 settlement-accounting 的 owner。
2. 授信把已确认未结算进额度占用（决定六）改了 `LoadCreditStanding` 的口径。CONTEXT「客户应收方向的可用余额……再扣除冻结金额与已确认未结应收」是预付与信用共用的算式，本记录据此把授信的占用也扣已确认未结；若 owner 的意思是授信额度只由暴露占用、已确认未结另管，则此条要改。归 settlement-accounting 的 owner。
3. 首次确认建立运营余额行（决定五）使一个从未登记过的作用域从`余额不可用`变成可判（可用可为负）。归 settlement-accounting 的 owner。
4. 决定八留下的缺口：包裹取消或失败的份额没有释放触发口。这不是本记录的疏漏而是 PS 侧没有触发；是否另立触发属 parcel-shipment 与 settlement-accounting 两边的 owner。

# ADR-0341：处置请求项里系统能执行的由所有者的消费者自动执行，其余成为由小包托运持有的待人工处理项，运营人员逐项登记处理结果，登记即承接结果

Status: Accepted（2026-10-28，Claude Code 会话代 PS owner 裁定：用户 2026-10-28 答「实际业务不是所有的都系统打通的，有些可能就在我们的系统人工更新处理」并选「照这个做」，见票 [launch-wiring/05](../../.scratch/launch-wiring/issues/05-post-intake-disposition-request-consumers.md) 文末「用户裁定」；待人工处理项归小包托运持有、授予单立一种、冲突与重放的答案形状是作者代决。裁决能力边界：读过 [ADR-0332](./0332-a-post-intake-service-disposition-is-an-append-only-per-parcel-decision-chain-that-asks-object-owners-for-scoped-requests-through-an-outbox-envelope.md) 全文、PS CONTEXT 词条「收寄后服务处置决定」、UC-PS-006、运输履约一侧的消费者与旅程启动编排的代码；没有读过 NO、NR 的聚合，也没有读过管理台。越权风险点见文末，待 PS owner 复核，知会 NO、NR、TF owner 与访问身份 owner。）<!-- 索引注记 -->｜**决定的形状**：请求表里哪些动作由系统执行是随产品发布的内置策略（今天只有运输履约的两个「另起旅程」动作），其余都是待人工处理项；项在决定形成时由小包托运同笔落库，运营人员逐项登记「已处理」或「无法处理」加说明，登记即该项的承接结果，小包托运可读回。**授权**：「运营决定」族再立 `POST_INTAKE_MANUAL_ITEM_HANDLING`，租户取值，未登记没有人能登记。｜**去向**：部分停用 [ADR-0332](./0332-a-post-intake-service-disposition-is-an-append-only-per-parcel-decision-chain-that-asks-object-owners-for-scoped-requests-through-an-outbox-envelope.md) 决定四里「本记录不立「承接结果」的读回面；各所有者消费这封信封并回报承接结果属各自上下文的票（见 Consequences）。」一句

Date: 2026-10-28

## Context

- ADR-0332 把一份处置决定拆成对路由、节点、运输的范围化请求，经一封信封交出，并说各所有者承接与执行、承接结果的读回属各自上下文的票。票 launch-wiring/05 做完运输履约一半后发现：节点运营没有扣住与按退运装载的模型，网络路由没有按去向规划与释放计划的入口，运输履约没有扣住模型；让它们各自先立模型才能接，周期长，而信封因含这些项被整封答未决、卡在可见失败里。
- 实际业务不是所有环节都系统打通：扣住包裹、按退运装载、重新规划，现场往往由人在系统外办，办完要的是一个可查的记录。
- 用户裁定：系统能做的自动做，其余项进待人工处理清单，运营人员在系统里逐项登记处理结果，小包托运能读回。

## Decision

**一、请求项分两种执行方式，哪种是产品策略，不是租户取值。**

- 请求表（ADR-0332 决定三）不变。表里每个动作有一个封闭的判定「是否由系统执行」，内置在代码里：今天只有运输履约的「另起备用旅程」「另起退运旅程」由系统执行（派发进程消费信封，以链上这一版作依据启动旅程，UC-TF-007）；其余动作（节点扣住与按退运装载、路由重新规划、规划退运路径与释放计划、运输扣住）都是待人工处理项。
- 某个所有者日后有了执行器，把它的动作移出人工集合即可，下一份决定起不再生成该项；已落的项不受影响。这是随产品发布的策略，租户不配置。

**二、待人工处理项归小包托运持有。**

- 理由：请求是小包托运发的，要读回结果的也是它；决定链、取消边界锁与信封已在这里，项与决定同笔落库不需要第二个落点，也就不会丢、不会重复。把它放进节点运营或网络路由，等于替他们自造一个「接收人工登记」的模型，而这两个上下文今天没有；所有者日后有了执行器，承接事实是它们自己的，这里的项只是在它们缺席时的运营留痕。
- 项的键是（租户，包裹，决定版本，所有者，动作），外键指向决定链上那一版。项只追加；后来的决定取代了这一版，项照旧在册——包裹实物上被扣住或已装载不因链尾换了而自行消失；清单与读回面各自给出链尾版本，办之前看链尾说了什么是操作者的事。
- 项与决定追加、信封入 Outbox 同一事务。运输履约的消费者只认自己能执行的两个动作，忽略信封里其余请求项，信封照常发布；ADR-0332 评审修订里「信封含非另起旅程项整封答未决」不再成立。拦截与服务终止对运输履约的扣住同样进人工项。

**三、运营人员逐项登记处理结果，登记即该项的承接结果。**

- 结果封闭两值：已处理、无法处理；说明必填；操作者取自认证信封，处理时刻取钟，租户只取自认证结果。一项至多一份结果，不改不删。
- 授权：「运营决定」族再立 `POST_INTAKE_MANUAL_ITEM_HANDLING`，租户取值，未登记没有人能登记。与收寄后服务处置分开：形成决定的人与在现场办完事的人通常不是同一批。
- 口：`GET /post-intake-disposition-manual-items` 上列租户尚未登记的项（`?parcel=` 读回该包裹名下全部项连同结果），`POST /post-intake-disposition-manual-item-results` 登记。重放（同项、同结果说明操作者）答已登记过；同项异内容答结果冲突并读回先前那一份，不覆盖；项查无或属别的租户同一个统一不可见答案。系统执行的动作不成项，登记它是坏请求。
- 「无法处理」也是承接结果：它保留决定与结果，当前控制责任不因此消失（`AT-PS-088`）。

## 候选与反方

- **项放到各所有者上下文。** 否决：各所有者今天没有这类模型，需要他们先立；项的读回方是小包托运，跨上下文读又多一个口。所有者日后有了执行器，承接事实归它们，这里的项不冲突。
- **TF 消费者在发现非 TF 项时由它落项。** 否决：落点在派发进程里，信封重投时要靠幂等键防重，而决定形成时同笔落库不需要；且把 PS 的运营留痕写进 TF 的库违反所有权。
- **项上放状态列。** 否决：状态列会被覆盖；结果在场与否就是待处理与否，分表即可。
- **登记要求所属决定仍是链尾。** 否决：实物上的扣住不因后来的决定消失，办完了就该有地方记。

## 对已接受记录的作用

部分停用 ADR-0332 决定四里「本记录不立「承接结果」的读回面；各所有者消费这封信封并回报承接结果属各自上下文的票（见 Consequences）。」一句，其余各条不变：对系统执行的项，承接与执行仍是所有者自己的事实；对人工项，承接结果由本记录的登记面给出。ADR-0332 决定一至三、授权与请求表、信封形状不动。

## Consequences

- 新增迁移 `parcel_shipment/0034`（项与结果两表）与 `access_identity/0035`（决定种类 CHECK 加一个词）。
- 运输履约的处置消费者不再因含非另起旅程项而答未决，也不再有 `ErrPostIntakeRequestUnhandledOwner`；ADR-0332 引出的票 launch-wiring/05 的收口条件改为人工项清单与登记口生产可用。
- 演示租户种子补 `POST_INTAKE_SERVICE_DISPOSITION` 与本记录新授予的授予、准入对照与权威区间。
- 未做：监管退运转 UC-TF-001（`AT-PS-084`）仍在后；管理台页另跟。

## 越权风险点

1. 哪些动作由系统执行、哪些人工（今天除运输履约两项外全人工）是作者按各所有者现状做的产品策略取舍，待 PS owner 复核，知会 NO、NR、TF owner。
2. 待人工处理项归小包托运持有，是作者代决，待 PS owner 复核。
3. 授予单立一种而不并入收寄后服务处置，待访问身份 owner 复核。
4. 登记不要求所属决定仍是链尾、结果冲突答 409 而不覆盖，是作者的取舍；清单与读回面对每项给出派生标志「已被后来的决定取代」（决定版本小于链尾版本），被取代的项不隐藏也不自动作废，由操作者按链尾判断，待 PS owner 复核。

# ADR-0272：复核形成的路由计划从所判触发的业务时间起生效，被它替代的计划在同一刻离场；判断时刻仍取处理时钟

Status: Accepted（2026-10-21，Claude Code 会话代 NR owner 决：用户原话「你作为业务和系统专家自决……解决所有的问题」，常设授权「你作为业务和系统专家自决」；票 [docs-consistency/code/52](../../.scratch/docs-consistency/code/52-reassessment-reads-the-initial-route-row-instead-of-the-current-plan-or-no-route.md) 隔离评审 R1 的协调方裁定。无条款停用：已接受记录里没有一句定过复核形成的计划取哪个时钟生效。越权风险点见文末，待 NR owner 复核，第 1 点同时待 TF、VE owner 会签。）<!-- 索引注记 -->｜**生效**：复核形成的计划（失效线改路、改善替代、原先无路由时形成首个计划）从所判触发的业务时间起生效；改善替代时原计划在同一刻离场，失效时刻本就取触发的业务时间。判断时刻仍取处理时钟。**理由**：生效边界是业务边界，并发按权威业务时间裁决、不按到达顺序（ADR-0174）；取处理时钟时，积压之下下一次触发的失效早于生效，被离场门拒。初始路由仍按处理时钟生效，口径不一归票 code/60
Date: 2026-10-21

## Context

- NR CONTEXT 把路由计划定义为「带版本和生效边界的未来路径意图」，适用性生命周期写「候选被适用策略选中并达到业务生效边界 → 形成当前有效路由计划版本」。改路决定是「新路由版本及其业务生效边界」。
- [ADR-0174](./0174-loading-concurrency-is-judged-by-business-time.md) 决定一：改路与装载并发只比权威业务发生时间与改路生效边界，消息到达时间不进入裁决。
- [ADR-0235](./0235-route-reassessment-settles-what-a-retry-cannot-change-and-does-not-judge-triggers-older-than-the-current-position.md) 决定四：复核按所判触发的业务时间排，早于当前控制位置的触发不判。
- 代码（取证于 main `4e7874ba0`，本记录之前的代码）：
  - 复核编排形成新计划时，判断时刻与生效时刻都取处理时钟。
  - 原计划失效时，适用性的离场时刻取触发的业务时间；改善替代时取处理时钟。
  - 领域 `PlanApplicability` 的离场门：`leaveCurrent` 头注写「离场必须带依据与不早于生效的时刻」。
- 票 code/52 让复核形成的计划成为下一次复核的起点。处理积压时处理时钟走在业务时间前面：这一次形成的计划若按处理时刻生效，下一次触发的业务时间可能早于它；那次触发让它失效时，离场门拒，整封信封响亮失败。评审复现了这一格：原计划失效，形成首个计划，处理时钟比业务时间晚十小时之下再失效。
- 初始路由今天也按处理时钟生效（受理之后 NR 处理初始路由交接的那一刻）。

## Decision

**一、复核形成的计划从所判触发的业务时间起生效。**

- 适用于复核编排形成的每一份新计划：失效线上的自动改路、仍适用线上的改善替代，以及原先无当前有效路由时形成的首个计划。
- 生效时刻就是这次控制触发的业务时间：节点收寄或揽收的发生时间，交接的判断时刻。与 ADR-0235 记入复核册、用来比当前控制位置的是同一个值。
- 计划的判断时刻仍取处理时钟：它答的是「什么时候判的」，不是「从什么时候起算数」。

**二、被替代的计划在接班计划生效的那一刻离场。**

- 改善替代时，原计划的适用性在触发的业务时间转为已被替代。旧计划离场与新计划生效落在同一刻，中间不留无计划的空档，也不重叠。
- 原计划失效的离场时刻本就取触发的业务时间，不变。

**三、由此，复核形成的计划的适用性时间线落在业务时间上。**

- 复核能判的下一次触发都不早于当前控制位置（ADR-0235 决定四），也就不早于这一次形成的计划的生效时刻。离场门要求离场不早于生效，这一条对复核形成的计划恒成立，不因处理积压而拒。不覆盖本记录之前已落库的复核计划：它们按处理时钟生效，照旧可能被拒；演示库要 `scripts/demo-seeds --reset` 重灌。

## 候选与反方

- **生效取处理时钟（今天的写法）。** 否决：积压之下下一次失效被离场门拒，整封信封响亮失败、占着分区到 `ABANDONED`；而且把到达顺序带进了生效边界，与 ADR-0174 相左。
- **生效仍取处理时钟，失效时把离场时刻夹到不早于生效。** 否决：失效时刻就不再是依据到来的业务时间，审计读到的是一个没人观察到的时刻；病根是生效取错了时钟，在离场门上补救只遮住它。
- **失效与替代也改取处理时钟，整条时间线落在处理时钟上。** 否决：失效时刻是交接或收寄的业务时间，已由交接一路 `AT-NR-064` 的用例钉住；整线改取处理时钟，等于让到达顺序决定计划何时不算数。
- **生效取判断时刻与业务时间里较晚的那个。** 否决：较晚的那个通常就是处理时钟，等于回到第一条。

## 对已接受记录的作用

- 无条款停用。核过 ADR-0172、ADR-0173、ADR-0174、ADR-0215、ADR-0217、ADR-0235、ADR-0249：这几份讲改路从哪个节点生效、并发按业务时间裁决、复核按业务时间排，没有一句定过复核形成的计划取哪个时钟生效。本记录给 ADR-0174 所比的「改路生效边界」定了时间那一维的取值，节点那一维不变。

## Consequences

- 代码随票 docs-consistency/code/52：复核编排形成计划时生效取触发的业务时间，改善替代时原计划离场取同一时刻；补积压之下再失效的用例。
- NR CONTEXT「路由计划适用性」补一句引本记录；UC-NR-003 `AT-NR-053` 的「明确边界」引本记录。
- 初始路由仍按处理时钟生效，另立票 [docs-consistency/code/60](../../.scratch/docs-consistency/code/60-initial-route-takes-effect-at-processing-time-unlike-reassessment.md)。

## 越权风险点

1. **装载并发裁决接上线后，触发到处理之间的装载会被裁成「改路先有效」**（NR、TF、VE owner 会签）。ADR-0174 比装载时间与改路生效时间。生效取触发的业务时间之后，触发业务时间到处理时刻之间按旧计划发生的装载，时间晚于改路生效，会被裁成「改路先有效 → 路由偏离」；而那段时间里改路决定还没形成，装载方无从知道。今天复核编排不调用并发裁决，没有装载事实可交（ADR-0174 Consequences，票 routing-first-cut/06），这一格到不了；接线时要么给并发裁决另交「决定形成时刻」作因果依据，要么把这一段裁成因果不明。
2. **初始路由与复核形成的计划口径不一**（NR owner）。初始路由按处理时钟生效。改善替代时原计划离场取触发的业务时间；若这个时间早于初始路由的处理时刻，离场门拒、整封响亮失败。原计划失效一路本就同病。首发链路上通常撞不上：改善替代那一行落不了复核册（code/53），复核不取候选成本（demo-chain-gaps/115），受理与首个控制触发之间通常隔几小时；纯失效一路在初始路由交接积压、离线补登时撞得上。归票 code/60。
3. **生效时刻早于判断时刻**（NR owner）。复核册与查阅面上，新计划「从何时起算数」可以早于「何时判的」。读者要按本记录读这两格，不能拿判断时刻当生效时刻。新计划今天不另发信封（demo-chain-gaps/34），运输准备消费新计划时须照本记录取生效时刻。
4. **业务时间取自来源**（NR、TF、PS owner）。同 ADR-0235 越权风险点 10：来源报错的业务时间会原样成为新计划的生效时刻。

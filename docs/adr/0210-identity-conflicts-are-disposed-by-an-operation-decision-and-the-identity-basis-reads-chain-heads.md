## Context

身份冲突今天有这几种来路：一码两物（ADR-0196）、身份核对答出多个候选、恰一个候选却带歧义信号（ADR-0195）。每一种都在收寄册上落下记身份冲突的行。方向依据的身份一格（`domain.JudgeIdentityBasis`，读法定在票 no-directional-basis/01「偏离标记半边：设计代决」：「恰好关联到一个正式包裹、且没有一行记身份冲突，为`成立`」）对这件实物在册上的全部行取或，一行记了冲突，方向性作业就对它一直停住。

没有任何入口能解开它。ADR-0199 决定三：「记身份冲突的（多候选、一码两物）不重核……那要身份冲突的处置能力。」ADR-0196「Consequences」：「解除要等身份冲突的处置能力（未立票）。」ADR-0195 越权风险点「合法的重复用号与持号一方自己的实物也答身份冲突」与「信号消失后，已记的冲突不自动解除」都指向同一个缺口。

ADR-0199 第一期已经让收寄册上每一版判断都有判断版本，追加的一版指名前版，库面以（租户，前版）唯一守住「一版至多一个后继」，`Receptions.CurrentVersion` 沿后继走到头。「判断链」与「当前有效版本」因此已经可算。读收寄册的其余几面仍按行读：`Receptions.FindOtherUnitIntakes` 按包裹找别的实物的关联（ADR-0196 决定六），`ParcelContainmentView` 按包裹找在袋的已关联实物与候选实物，复核目录逐行列待识别。

运营决定的接入形状已有先例：操作者渠道的「运营决定」能力面，授予按租户 × 决定种类登记（ADR-0151 决定一）；重放与内容冲突代数按答法读（ADR-0151「复核记录（2026-10-19）」）；请求证据与操作证据不进比对（ADR-0187 决定四，经 ADR-0183「复核记录二」）。

难逆转处：收寄册只追加，处置版一落就是历史；交给 PS 的收寄意图不回滚（ADR-0196 决定五）；命令口的答复格一旦有消费者就难改。

## Decision

适用范围：身份冲突的处置（新命令口与它的编排）；方向依据身份一格的读法；按包裹读关联的两个读面 `FindOtherUnitIntakes` 与 `ParcelContainmentView`；ADR-0199 决定三的重核遇到处置版的那一格。收寄编排其余各支、ADR-0196 的判法本身、PS 的身份核对读口都不改。

**一、身份冲突只经人工处置解除。**

- **处置是一种运营决定。** 操作者渠道「运营决定」能力面多一种决定种类「身份冲突处置」，授予按租户 × 决定种类登记（ADR-0151 决定一）。谁持有这一种授予是租户取值（参数登记册 `PAR-INT-08` 的行）：仓内不写默认，生产上没有授予就答「无此决定种类的授予」；演示租户在演示种子里给演示操作者配上。
- **授予就是全部的授权门**，不另向 `party-commercial` 问授权坐标。委托侧的运营决定要问，是因为它们改变一份客户委托的去向；身份冲突处置改变的是节点自己对一件实物的身份判断。
- **不做自动解除。** 歧义信号消失之后自动解开，需要 PS 在声明的委托被拒绝或撤回时另交信封（ADR-0195 决定四写明「信号消失不交信封」），记作后续方向，本记录不做、不立票。
- **重核与再次收寄都不解除冲突。** 重核照 ADR-0199 决定三跳过记身份冲突的判断；同一实物再来一次，形成的是新的判断，不接续冲突那一版。

**二、处置的对象与两种结果。**

- **对象是一件作业实物（主实物）与调用方指名的「所处置的版本」**：操作者在复核页上看到的那一版。它必须是这件实物此刻某条判断链的当前有效版本，且这件实物各链的当前有效版本合起来判身份冲突（读法见决定五）。没有冲突的实物不能单独处置，本记录不开对未冲突关联的单独更正口。
- **处置候选**：这件实物各链当前有效版本上记的候选与关联，合起来的那一组包裹。它们都出自 PS 身份核对的答复，节点不往里添。
- **两种结果**：（甲）关联到处置候选中的一件，下称 X；（乙）确认不是其中任何一件。候选之外的包裹不能指定：节点不得自行创建或替换正式包裹身份，正式包裹只来自 PS 的答复。
- **必带处置依据引用**：去两端空白后逐字保存，不解析、不判真伪，与 ADR-0187 请求证据同一待遇。**操作者**取信封里的提交操作者，写作 `OPERATOR/<发行方>#<sub>`，与 ADR-0187 操作证据同一写法。

**三、处置落成追加版：这件实物的每条判断链各追加一版。**

- **逐链追加。** 对主实物此刻每条判断链的当前有效版本（`节点收寄已形成`与`待识别实物已建立`两种）各追加一版处置版，指名那一版为前版（ADR-0199 决定二）。只追加在所处置的那一条链上不够：身份一格读每条链的当前有效版本（决定五），留着另一条链上的旧关联，它就会替这件实物定身份。
- **两种结果的形状。**（甲）`节点收寄已形成`，带关联 X。（乙）`待识别实物已建立`，不带关联、不带候选、不记身份冲突，记下它排除的那一组包裹（就是处置候选）；第三期落地之后它的身份核对态是「已核对」。
- **收寄事实与控制照前版。** 节点、交付方、证据、接收时刻与控制都照前版那一版，业务时间是原接收时刻，不另起控制起点，与 ADR-0196 冲突版、ADR-0199 重核版同一做法。（甲）那一版照 ADR-0186 决定一向 PS 取服务结果，并记核对态。
- **处置文档**随每一版写下：所处置的版本、结果、X 或被排除的那一组、连带实物（决定四）、处置依据引用、操作者、形成时刻（取服务端时刻，载荷不带时间）。文档自带形状版本（ADR-0014）。
- **派生来源标识** `IDENTITY-DISPOSITION/<前版的判断版本>`。由前版派生而不由来源标识派生，理由同 ADR-0199 决定三：长度有界。
- **来源文档取这条链起点那一版的**，也就是这件实物自己那次送站保全的来源。不取前版的：ADR-0196 冲突版带的是后到那次送站的来源文档，作业实物与号码都可能是另一件的。起点没有来源文档的旧链，处置版也不带，此后不进重核（ADR-0199 决定一「既有行不回填」）。
- 原判断、冲突版与此前各版一字不改、永久保留。

**四、指定的那件此刻关联在别的作业实物上：同一次处置同时指明，不取「先处置那一件」。**

- 结果是（甲），而 X 此刻关联在别的作业实物上时（「此刻关联」的读法见决定八），请求必须把这些实物逐件列为**连带实物**，各带操作者看到的那一版当前有效版本。同一笔事务里，每件连带实物的每条判断链各追加一版「不是 X」的处置版，形状同（乙），排除的那一组只有 X。
- **连带实物的处置候选必须恰好只有 X。** 能走到的形状都是这样：ADR-0196 冲突版只记 X 一个候选，形成版不带候选。连带实物若还牵连别的包裹，就是它自己另有一桩冲突，答「关联对象另有归属」，那件先单独处置。
- 漏列、多列或所带版本已不是当前有效版本，都不落版，答「关联对象另有归属」，并回显此刻关联到 X 的各件实物与它们的当前有效版本。
- 结果是（乙）时不带连带实物，带了即坏载荷。
- **不取「先处置那一件」，理由有三。**
  - 中间有空窗。先把那件处置成「不是 X」、再处置主实物之前，X 不再关联任何实物；这时贴同号的第三件到站，会唯一关联到 X，意图交给 PS，而 PS 的采用不回滚（ADR-0196 决定五）。
  - 知道「这件是 X」就等于知道「那件不是 X」，本是一个决定；拆成两步，要操作者先把很可能已被 PS 采用的那件处置成「不是」，再说明为什么。
  - 那件可能根本没有冲突：它早先唯一命中了 X，后来这件以多候选或歧义信号带着 X 落成冲突。没有冲突的实物不能单独处置（决定二），「先处置那一件」就得另开一个通用的关联更正口；连带指明让对它的更正只作为一次冲突处置的后果出现。
- **取锁次序**：先作业实物（主实物与连带实物，按标识排序），后包裹（X 与这些实物此刻关联的各件包裹，按关联排序），与 ADR-0199 决定四「先实物后包裹」同一口径；第四期的实物锁未落地时只取包裹锁。（租户，前版）唯一兜底：漏锁时撞上的一方不形成答案，不会一版两个后继。

**五、方向依据的身份一格改读每条判断链的当前有效版本。**

- 只读这件实物在册上、没有后继的`节点收寄已形成`与`待识别实物已建立`两种行，其余折法不变：一行都没有为缺少·无收寄记录；有一版记身份冲突、或各版的关联指向不同的正式包裹为缺少·身份冲突；没有一版带关联为缺少·待识别（可与身份冲突并列）；其余为成立，所依收寄取带关联的那几版里业务时间最晚的一版。
- **这两种行的后继只会是这两种**（冲突版、重核版、处置版都是），所以只看这件实物带收寄的行就算得出哪一版是链头；「并入已有收寄」不是判断，不进来。
- **效果。** 处置版一落，它所在链的当前有效版本不记冲突，这一格就解开。ADR-0196 的先到那件，若冲突版指名了前版（ADR-0199 第一期之后追加的），此刻的当前有效版本就是那一版冲突版，落成缺少·{待识别, 身份冲突}，不再是缺少·身份冲突。第一期之前追加、没有前版的冲突版各自是一条链的当前有效版本，照旧判冲突，不回填。重核版带关联、是链头，照旧判成立。
- 已经落册的方向依据记录不重判（CONTEXT「事后不补判、不改记」）。
- 这一读法与处置无关也成立，先于处置落地。

**六、处置命令口。**

- **接入**：操作者渠道「运营决定」能力面的 Intake，决定种类「身份冲突处置」。信封一层各答其格（ADR-0100 决定四与 ADR-0151 决定三：发行方未配置、令牌无效、无此决定种类的授予、不在准入范围）。租户与提交操作者只从信封来，请求体带即坏载荷。
- **载荷**：主实物、所处置的版本、结果、X（只在甲）、连带实物（实物与版本，只在甲）、处置依据引用。缺格、空白、带 NUL、未知字段、甲不带 X、乙带 X 或连带实物、连带实物重复，都答 400 `MALFORMED_REQUEST`。
- **重放身份**是（租户，所处置的版本），由调用方指名，不拿服务端「此刻的当前版本」顶替（ADR-0151 复核记录里「身份前提」那一段）。经派生来源标识认出。
- **代数**（ADR-0151 复核记录里「一槽先到者胜」那一种，外加原样重放单答一格）：
  - 所处置的版本已被一次处置接续，比对格逐格相同：答`已有结果`（`EXISTING_RESULT`），回显在册的那次处置；不签新版本、不写册、不交意图。
  - 比对格不同：答「已处置」，回显在册的那次处置，差异由调用方自己比；不覆盖、不追加。
  - **比对格**：结果、X、连带实物的集合（只比实物）。处置依据引用与操作者不比，同 ADR-0187 决定四。比对格落成带形状版本的规范化摘要（ADR-0014），写进各版的内容指纹格，同一次处置的各版是同一个摘要。
  - 所处置的版本已被别的版本接续（不是处置版，例如第三件到站追加的冲突版）：答「版本已换代」，回显这件实物此刻各链的当前有效版本。
  - 重放与已处置在签发版本之前认出，不耗版本号。
- **业务拒绝**（都不写册）：「无可处置的冲突」（各链当前有效版本合起来不判身份冲突）、「不在候选之内」、「关联对象另有归属」（决定四）。指名的实物或版本在本租户查不到，与越权探针同答（ADR-0029）。
- 答复按 ADR-0022：形成了答案就是 2xx（首次形成 201，其余 200），业务判别进响应体。线上名由实施票定，答复格的划分以本条为准。
- 这一口生来自带代数，照 ADR-0151 决定三「逐口核」记在实施票里。

**七、发布意图（裁定里「一码两物里先到那件已被 PS 采用的那次」那一点）。**

- （甲）给主实物交一封收寄发布意图，除非这件实物此前已就 X 交出过：它此前哪一版`节点收寄已形成`曾关联到 X，就已交出过（原判断与重核版各交一封，处置版只在此前没交过时交）。多条链时只交一封，落在接收时刻最早的那一版上：责任起点是最早那次实际接收。
- （乙）与连带实物都不交意图。
- 已交出的意图一律不撤回，也不发撤销信号（ADR-0196 决定五）。新交的意图由 PS 按已有采用规则处理（UC-PS-003；`AdoptNetworkIntakeHandler.Handle` 头注「责任起点唯一」）；先到那件已被 PS 采用的那一次，协调仍在 ADR-0196 决定五的范围里。

**八、按包裹读关联的两个读面认「处置截断」。**

- 一行**被处置版接续过**，指沿前版往回走，有一版处置版以它为祖先。
- `FindOtherUnitIntakes`（ADR-0196 决定一、决定六）：被处置版接续过的行，它的关联不再算这件实物的关联；处置版自己带的关联照算。还没有处置过的实物，读法照旧。
- `ParcelContainmentView`：已关联那一路与候选那一路，被处置版接续过的行都不再算。
- **这两面不改读链头。** ADR-0196 冲突版在链头上去掉了关联；按链头读，两件实物还争着 X 时，贴同号的第三件会读不到任何关联，唯一关联到 X。截断只在人作了决定之后生效，此前与今天一样。
- 身份一格读链头（决定五）。处置覆盖主实物的每条链，处置之后两种读法对这件实物给出同一个答案。
- 复核目录要分得出哪一版仍是当前有效版本、哪件实物的冲突还没处置、处置了什么，由实施票做。

**九、处置之后的重核（裁定里「可再经重核」那半句）。**

- （乙）那一版不带关联、不记冲突，只要带来源文档，就照 ADR-0199 决定三是重核对象。
- **例外**：PS 的答复是唯一命中，而那一个候选在这一版排除的那一组里时，不追加，照零候选办。其余照决定三分格：多候选与带信号照旧追加冲突版；唯一命中一件没被排除的包裹照旧追加关联版。
- 不设这一格，人工重核或同号再签发一条关联（ADR-0185）交出的信封，会把这件实物关联回被排除的那件包裹；那件包裹若此刻关联在别的实物上，ADR-0196 还会给那件追加冲突版，推翻对它的处置。
- （甲）那一版带关联，不是重核对象。

**十、处置命令口另立 UC-NO-004，不并进 UC-NO-002。**

- UC-NO-002 从实物送达节点开始，到逐件形成收寄结果为止；它步骤 4 的身份判断是 PS 交回的答复。重核拿保全的号再走一次这一判断，留在 UC-NO-002。
- 身份冲突处置的触发是复核页上的人，参与者是持授予的操作者，重放身份是指名的版本，答复格自成一套。它不是步骤 4 那一判断。
- 验收编号从 `AT-NO-053` 续接。

## 与已接受决定的关系

逐句点名；各句自所列实施票进 main 起停用，此前原句照旧描述代码。

- **ADR-0196 决定四**「先到那件有原判断的关联行加追加的冲突行，落成缺少·身份冲突」：停用。**适用场景**：只限指名了前版的冲突版（ADR-0199 第一期之后追加的）。改读为缺少·{待识别, 身份冲突}（决定五）。同条「方向依据代码不改」：停用。生效：票 no-reception-identity/05。
- **ADR-0196 决定六**「按租户与包裹关联读别的作业实物的收寄，只认收寄本身带的关联」，以及决定一「这件包裹已有另一件作业实物的收寄关联」的读法：对被处置版接续过的关联停用，它们不再算那件实物的关联（决定八）。还没有处置过的实物照旧。生效：票 no-reception-identity/06。
- **ADR-0199 决定三**「重核对象」一项里「册上已有的冲突行在 `JudgeIdentityBasis` 里一直判身份冲突，重核解不开」一句：停用，它的前提随决定五不再成立（按链头读，接在冲突版后面的一版能解开这一格）。同一项的结论「记身份冲突的（多候选、一码两物）不重核」维持，理由改为决定一：冲突只经人工处置解除。生效：票 no-reception-identity/05。
- **ADR-0199 决定三**分格里「唯一，且包裹没有关联到别的作业实物 → 追加一版`节点收寄已形成`」与「唯一，但包裹已关联到别的作业实物 → 照 ADR-0196 追加冲突版」两句：停用。**适用场景**：只限被重核那一版是（乙）处置版、唯一命中的那件包裹在它排除之列（决定九）。生效：票 no-reception-identity/06。
- **ADR-0199 决定五**末项「方向依据代码不改：重核版带关联，`JudgeIdentityBasis` 照现有折法就判成立」里「方向依据代码不改」与「照现有折法」：停用。这一项的结论维持：重核版判成立，未核对行照待识别折、不另立原因。生效：票 no-reception-identity/05。
- **ADR-0195**：不停用任何一句。越权风险点「合法的重复用号与持号一方自己的实物也答身份冲突」与「信号消失后，已记的冲突不自动解除」所等的「身份冲突的处置能力」就是本记录；信号消失不自动解除，与决定一同向。
- **ADR-0151**：不停用。决定一的决定种类多一种「身份冲突处置」，照它的授予维度与答复格接入。
- **票 no-directional-basis/01**「偏离标记半边：设计代决」里身份一格「恰好关联到一个正式包裹、且没有一行记身份冲突，为`成立`」等各句：自票 05 进 main 起，按决定五读。

## 能力边界

- 不做自动解除；不开对未冲突关联的单独更正口；不处理 CONTEXT 规则里「同一实物存在相互冲突的外部标识」那一半（ADR-0196「能力边界」同样没覆盖）。
- 不撤回、不回滚 PS 的采用；VE 侧如何发现并协调，仍不在本记录。
- 不回填：第一期之前没有前版的冲突版不补前版，链起点没有来源文档的处置版不进重核。
- 只看本租户 NO 收寄册上客户送站的收寄；经交接进来、在本上下文没有收寄行的实物，没有可处置的判断。
- 处置时刻取服务端时刻；载荷不收业务时间，处置版的业务时间沿用原接收时刻。

## 越权风险点

1. **代 NO owner 定「方向依据改读链头」（裁定末尾那一条）。** 它改了票 no-directional-basis/01「设计代决」已落的读法，也改了 ADR-0196 决定四对先到那件的折法：原因集从{身份冲突}变成{待识别, 身份冲突}。owner 复核时看有没有依赖「任一行记冲突即冲突」的读面。本记录核过：`JudgeIdentityBasis` 在生产路径上只经方向依据判断编排（`DirectionalBasisJudge`）调用；`FindOtherUnitIntakes`、`ParcelContainmentView` 与复核目录不经它，自己按行读，本记录对前两面另定了截断（决定八）；已落册的方向依据记录不重判。按原因集断言的用例（一码两物与它的并发用例只断言「含身份冲突」）由票 05 逐条核。
2. **「正式身份由 `parcel-shipment` 确认」的读法。** GLOSSARY「待识别实物」写「正式身份由 `parcel-shipment` 确认」，NO CONTEXT 生命周期写「`parcel-shipment` 确认正式身份 → 建立带适用时间的版本化关联」，SCENARIOS 场景九也写 PS 确认后建立关联。身份冲突处置是节点的人在 PS 交回的候选里定「这件实物是哪一件」，本记录把那几句读成：正式包裹及其身份由 PS 给出与确认，实物与包裹之间的版本化关联归节点（CONTEXT-MAP：节点拥有「实物身份候选与冲突」）。若 PS owner 要由 PS 确认这一步，处置就得改成节点向 PS 提请求，另起记录。
3. **授予之外不问 `party-commercial`**（决定一）。若 owner 要给这一种决定配角色模型或授权坐标，归票 product-strategy-boundary/07 一类另裁。
4. **「处置截断」超出裁定字面**（决定八）。裁定只说了方向依据读链头；不截断，处置会被第三件到站或一次容纳查询推翻。截断改了 ADR-0196 决定六的读法，以及 `ParcelContainmentView` 对被处置实物的答法。
5. **「处置」一词与别处同字。** NO CONTEXT「作业授权与执行」里节点「不能凭异常案件、现场备注或操作权限自行形成处置决定」，说的是销毁、退回、移交一类改变实物去向的处置；PS 有收寄后服务处置决定与授权处置（ADR-0132），关务有监管处置决定。本记录的名称一律写全「身份冲突处置」，CONTEXT 与 GLOSSARY 写明它不是改变实物去向的处置决定。
6. **重核不再据被排除的候选关联**（决定九），改了 ADR-0199 决定三对这一格的分法。被排除的包裹仍可经多候选冲突回来，那时再处置一次。
7. **连带实物只收处置候选恰好只有 X 的实物**（决定四）。另有冲突的那件要先单独处置，那一段仍有空窗；能走到的形状里没有这一种，代价是理论上的。
8. **逐链追加会写到操作者没看过的链上**（决定三）：同一件实物在别的节点、或第一期之前留下的链。复核页要把一件实物的各链列在一起给人看，由实施票做。
9. **（甲）可能给一件已被 PS 为别的实物采用的包裹再交一封意图**（决定七）。PS 照「责任起点唯一」作答；VE 今天没有消费这种情形的路径（ADR-0196 越权风险点「PS 采用不回滚、交 VE」同一缺口），在它落地之前，只靠方向性作业门与人工协调。

## Consequences

- 操作者册的决定种类多一种；演示种子多一条授予、一条准入范围对照与一段生产权威区间。
- NO 多一个命令口、一份编排、一本处置文档（收寄表加列，迁移由实施票定号）；身份读口多读判断版本与前版；`FindOtherUnitIntakes` 与 `ParcelContainmentView` 多一层截断；重核多一格。
- 实施拆两张：[no-reception-identity/05](../../.scratch/no-reception-identity/issues/05-the-identity-basis-reads-each-judgment-chain-head.md)（身份一格读链头，可先行）与 [no-reception-identity/06](../../.scratch/no-reception-identity/issues/06-an-operator-disposes-an-identity-conflict.md)（处置本身，含管理台动作）。

## Alternatives

- **歧义信号消失即自动解除。** 裁定不取：PS 不交「信号消失」的信封；多候选与一码两物也没有对应的自动解法。记作后续方向。
- **处置改写原冲突行（清掉冲突位或补上关联）。** 不取：只追加、不覆盖（CONTEXT「重复、迟到、冲突、更正或有效性变化必须关联原事实和原判断」）。
- **另建一本身份处置册，方向依据与按包裹的读面并读两本。** 不取：这几面今天都只读收寄册，处置版放进同一本册的版本链，各面只改读法，不多一处读口。
- **只在所处置的那一条链上追加。** 不取：身份一格读每条链的链头，另一条链上的旧关联会替这件实物定身份。
- **指定的那件已关联到别的实物时，要求先处置那一件。** 不取，见决定四。
- **方向依据仍对全部行取或，处置版另带「解除」标记，折法见到处置就跳过更早的行。** 不取：裁定定了读链头；链头是 ADR-0199 已有的概念，标记是第二套口径。
- **`FindOtherUnitIntakes` 与 `ParcelContainmentView` 也改读链头。** 不取，见决定八。
- **处置命令带请求键。** 不取：所处置的版本就是天然的请求身份，原样重投必然带同一个；另加请求键，只多一种「同版本异键」要答。
- **处置口并进 UC-NO-002。** 不取，见决定十。
- **授予之外再问 `party-commercial` 授权。** 不取，见决定一与越权风险点 3。

## 复核记录（2026-10-19，ADR-0211 部分停用几句；决定原文不动）

会话 `idp-parcel-9b` 代 NO owner 与 PS owner 裁定只因歧义信号的冲突自动解开（票 [no-reception-identity/07](../../.scratch/no-reception-identity/issues/07-an-ambiguity-only-conflict-releases-when-the-declaration-is-gone.md)，用户 2026-10-16 授权「你作为业务和系统专家你来自决」，2026-10-19 就该票答「需要」），成文为 [ADR-0211](./0211-an-ambiguity-only-identity-conflict-releases-by-recheck-once-the-declaration-is-gone.md)。自该票进 main 起，下列几句停用，**适用场景**只限冲突来由为只因歧义信号的身份冲突（PS 答恰一个候选、同时答出歧义信号）：

1. **决定一**「**不做自动解除。** 歧义信号消失之后自动解开，需要 PS 在声明的委托被拒绝或撤回时另交信封（ADR-0195 决定四写明「信号消失不交信封」），记作后续方向，本记录不做、不立票。」——PS 在声明它的委托被拒绝或撤回时交声明撤除门铃，重核答唯一命中、不带信号即追加关联版，冲突随链头解开（ADR-0211 决定二、三）。
2. **决定一**「**重核与再次收寄都不解除冲突。** 重核照 ADR-0199 决定三跳过记身份冲突的判断」里重核那半句——这类冲突是重核对象。同句「再次收寄……不解除冲突」照旧。
3. **「能力边界」首项**里「不做自动解除」。

其余照旧：多候选、一码两物与来由缺席的冲突（ADR-0211 之前落下的冲突行一律不回填来由）只经本记录的处置解开；处置版不记冲突，自动解开不撤销任何处置。「Alternatives」里「歧义信号消失即自动解除」一项是当时不取的历史，不改。

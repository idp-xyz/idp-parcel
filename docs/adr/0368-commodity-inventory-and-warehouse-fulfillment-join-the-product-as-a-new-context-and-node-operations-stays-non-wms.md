## Context

[ADR-0006](./0006-parcel-node-operations-not-full-wms.md) 把场站节点与 WMS 分开：场站节点「不建设或拥有以库存为中心的完整收、存、拣、补、盘业务」，同时留了出路：「真实业务同时需要完整仓储管理时，应通过明确边界协作或另行作出领域扩展决策。」[ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md) 据此把「库存账、上架、拣货、波次等完整 WMS 能力」排除在一线作业端之外，否决「按完整 WMS 的作业面建设」的理由是「ADR-0006 已排除完整 WMS，且超出目标客户群的常规形态，违反能力范围判据。」[产品基线](../product/PRODUCT-BASELINE.md)「网络运营与场站边界」一节当时写的是「本产品不建设完整商品库存 WMS」。

「明确边界协作」那一支已写成[外部 WMS 协作缝设计备忘](../design/external-wms-collaboration-seams-design-note.md)。本记录是「另行作出领域扩展决策」那一支，起因不是新的租户证据，而是这几件：

- 开发主线把[目标客户群](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md#目标客户群)分层写出常规业务形态，其中「3PL 与集运干线运营商」一层「以仓配或集运为主业，跨境干线是其中一段」。对这一层，仓配是主业，跨境小包只是其中一段。ADR-0021 的结论是按原判据作出的，分层表自己声明「**分层不改变已按原判据作出的结论。**」，所以要按分层重判，只能由一份明确的决定来做，即本记录决定一。
- 外部设计线交来的《IDP Parcel 仓储与履约 DDD 设计评审》V0.4（[参考件](../reference/IDP_Parcel_DDD_Design_Review_V0.4.html)，非权威）把商品库存、一件代发、FBA 与代理仓写成「已确定的目标」。本仓没有任何决定这样定过；要定，归产品 owner。
- 会话评估时的建议是此刻维持 ADR-0006，理由是：冻结期只做挡上线与限量生产必需的事；以仓配为主业的租户多半已有自己的 WMS（行业判断，无一手数据）；小包场站需要的收寄、测量、集运、封签与交接证据，节点作业已经覆盖。用户要求把改边界这条路也写成可直接接受的草案，交产品 owner 定；用户当日接受。

本记录说的「纳入」指产品边界，不指首发；首发范围不变，见决定八。

## Decision

**一、判据怎么读。** 仓配（入库、存储、一件代发出库、FBA 与海外仓备货）是目标客户群里「3PL 与集运干线运营商」一层的主业，属常规形态而非边缘情形。[能力范围判据](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md#能力范围判据)写的是「承运或渠道商业模式」；本记录把它读宽到 3PL 仓配这一类物流服务商业模式，**只为仓配这一项**。判据对其余能力的读法不变，「它同样要挡住无边界扩张」的职责也不变。ADR-0021 否决理由里「超出目标客户群的常规形态，违反能力范围判据」半句由此不再成立。

**二、新立限界上下文「仓配履约」（`warehouse-fulfillment`）。**

拥有：

- 货主商品身份：货主名下的商品（SKU）、别名与包装层级；不同货主的同名 SKU 互不相干。
- 库存账与库存流水：按（租户，货主，仓，库位，商品，库存状态，批次或效期）记数量，余额只由流水派生。
- 预占：出库请求对可用量的占用、释放与消耗。
- 入库预报（ASN）、收货与收货差异、上架。
- 库内移动、拣选位补货与盘点。
- 出库请求、波次与拣货任务、复核与打包。
- 退货入库与回库处置。
- 代理仓（合作仓）报来的库存声明：带来源、时点与有效期，不冒充自营实时库存。
- 仓储作业的收费发生项：只证明作业已发生及其数量与单位，不带金额。

不拥有：

- 委托、包裹身份与客户承诺（`parcel-shipment`）；节点收寄、集运单元、节点内实物控制与交接证据（`node-operations`）；揽收、运输交接与交付（`transport-fulfillment`）。
- 货主客户账户与合同（`party-commercial`）、价格（`parcel-pricing`）、费用与对账（`settlement-accounting`）。
- 货主的库存价值与成本、采购与销售订单、补货计划。本上下文做的是 3PL 仓配，不是货主的进销存；这几样留在货主自己的 ERP 与财务里。

**三、按对象分边界，不按场地分。** 同一处设施可以同时是网络节点与仓库。商品与库存归仓配履约；包裹在节点内的收寄、控制与作业，以及集运单元，归节点作业；包裹身份仍归小包托运。打包完成之前只有库存与任务，没有包裹；打包完成、委托提交之后只有包裹。ADR-0006 的「包裹的当前节点、作业区域、暂存位置和控制方不等同于可用库存或仓储账面数量。」照旧成立，反过来也成立：库存的库位与状态不是包裹的节点控制。

**四、包裹在打包完成后经委托进入小包链路。**

- 出库请求由货主经客户渠道交来，带要求的服务产品。仓配履约打包完成时，以该出库请求所属货主客户账户的名义向 `parcel-shipment` 提交委托：打包称得的重量与尺寸作声明测量，货物内容取自出库请求的商品明细，作客户原始资料。
- 这份委托的来源是「仓配出库」，来源请求键取自（出库请求，包裹序号）。它与首方渠道交来的委托受同一套接受判断，不绕过任何接受规则。
- 库存在仓配履约自己的出库确认时扣减，不等节点收寄，也不由节点收寄触发。节点收寄是节点作业的另一件事实，两件事实谁也不替谁。
- 波次释放时先取面单、后拣货是常见做法。它要求委托在打包前提交、打包后经资料修订补正声明测量；首批支不支持这一形态，留给实施切片按第一个场景定。

**五、库存不变量。**

- 守恒：同一计量粒度下，期末在库 = 期初 + 已确认入库 + 调入 + 已批准盘盈 − 已确认出库 − 调出 − 已批准盘亏。状态转换与预占只改分类与可用量，不改实物总量。
- 可用量：预占、冻结、锁定等占用分类互不重叠时，可用 = 在库 − 各占用之和；分类有重叠的，先定交集怎么算，不得重复扣减。
- 预占在库存账内原子判定，成功的预占合计不超过可用量。不足时按出库请求适用的策略拒绝或部分分配，不静默超卖；策略是产品内置的封闭集，选哪一种是租户取值（[ADR-0146](./0146-product-strategy-is-a-third-class-between-mechanism-and-tenant-values.md)）。
- 整箱转散件这类形态转换，在同一笔流水里按货主、商品与计量单位守恒。
- 代理仓库存声明过了有效期即答「未知」，不据它做确定性承诺。
- 更正只追加：盘点差异、错收错发都以新流水表达，不改已入账流水（[ADR-0005](./0005-source-facts-effective-events-derived-state.md)）。

**六、一线作业端扩到仓内作业。** 收货、上架、移库、补货、盘点、拣货、复核打包进入一线作业客户端。离线与弱网容忍照 ADR-0021；作业事实的身份与发生时间由设备签发（[ADR-0023](./0023-work-fact-identity-and-time-are-minted-by-the-device.md)）。已经发生的拣货照记：离线拣出的件在库存账看来不可用时，照记拣货事实，形成库存差异交人处理，写口不拒——与 [ADR-0251](./0251-directional-node-work-is-paused-outside-the-validity-interval-of-the-delivered-basis-and-recorded-moves-are-never-refused.md) 对已经发生的移入与分拣一律照记是同一立场。预占是计划，不是事实，离线端不铸预占。

**七、仓储作业费经收费发生项交计价与结算。** 仓配履约只登收费发生项（作业种类、货主、数量与单位、业务时间、来源事实引用），不带金额。对货主收多少由 `parcel-pricing` 按 SELL 价卡评价，`settlement-accounting` 采用为客户运营应收。仓租按时间计（库位·天、立方·天之类），`parcel-pricing` 需要按持有期计价的新计价对象，另立 ADR。

**八、首发范围与冻结清单不变。** 本记录改的是产品边界，不是首发范围。[首发试点范围](../product/PILOT-SCOPE.md)「明确不包含」里的「首发不建设完整 WMS。」与开发主线「已确认的首发范围约束」里的「首发不包含 COD，不建设完整 WMS，不启用生产自动申报。」照旧；[上线线与冻结清单](../../.scratch/launch-line-freeze-2026-10-27.md)不因本记录解冻任何票。仓配履约照 [ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md) 的两轨制另立 PN 切片：先写 `CONTEXT.md` 与 UC，机制与产品策略半边用演示租户与 `SYN-` 数据走通、证据记 `S`；某租户的仓、库位、货主与价卡是租户取值。

## 对已接受记录的作用

- [ADR-0006](./0006-parcel-node-operations-not-full-wms.md)：本记录是它 Decision 里「真实业务同时需要完整仓储管理时，应通过明确边界协作或另行作出领域扩展决策。」一句中「另行作出领域扩展决策」那一支，Decision 本身不停用——场站节点仍不建设、不拥有以库存为中心的完整收、存、拣、补、盘业务，这些归新上下文而不归场站。部分停用其 Consequences「涉及完整仓储职责的客户场景需要与外部能力协作，不能通过不断增加场站字段隐式吸收。」一句里「涉及完整仓储职责的客户场景需要与外部能力协作」那一半，改为与外部能力或本产品的仓配履约协作；「不能通过不断增加场站字段隐式吸收」照旧。其 Alternatives 否决「**在国际小包系统内建设完整 WMS**」时说的代价「会引入库存、库位、补货和拣选等不同核心模型并显著扩大范围」，本记录照单承担，见 Consequences。其余各条不变。
- [ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md)：部分停用其 Decision「**范围限于本产品拥有的节点作业**：扫描、点验、身份冲突处置、测量录入、集运单元与封签、作业位置移动。」一句里「限于」那一层：一线作业端的范围扩到决定六列的仓内作业，H1 里同一说法随之按此读。**适用场景**：只限仓配履约的仓内作业；节点作业那部分的范围与列举照旧。同时部分停用其 Decision「**明确不做**：库存账、上架、拣货、波次等完整 WMS 能力，依 ADR-0006 已排除；以及租户既有的面单打印、财务与人事。」一句里「库存账、上架、拣货、波次等完整 WMS 能力，依 ADR-0006 已排除」那一半，一线作业端按决定六扩到仓内作业；「租户既有的面单打印、财务与人事」照旧不做。其 Alternatives 否决「按完整 WMS 的作业面建设」的理由里「超出目标客户群的常规形态，违反能力范围判据」半句，由决定一回答。其余各条不变。
- 不停用、照旧成立：[节点作业 CONTEXT](../domain/node-operations/CONTEXT.md) 的「完整 WMS 能力不属于本上下文。需要商品库存、可用量、库存价值、补货、仓储拣选或库存调整时，必须通过明确边界协作或新的领域决策处理，不能扩充节点字段隐式吸收。」本记录就是其中说的「新的领域决策」。

## Consequences

- 产品要多做的东西：商品身份、库存账与流水、预占、入库与上架、库位与库内移动、盘点、出库请求与拣货任务、复核打包、退货入库、代理仓声明，以及一线作业端上对应的作业屏。ADR-0006 否决理由说的「显著扩大范围」在这里兑现。
- 新增的跨上下文接缝：`parcel-shipment` 多一种不经客户渠道的委托来源（决定四）；`parcel-pricing` 多一类按持有期计价的计价对象（决定七）；`settlement-accounting` 多一类费用来源（决定七）；首方渠道要为货主新开入库预报、出库请求与库存查询这些客户面口。
- 自带 WMS 的租户照旧存在，外部 WMS 协作缝设计备忘的各行不因本记录作废，两条路都要维护。
- 没有 WMS 的仓配型租户得到的：库存到包裹在一个产品里走完，仓储费与运输费可在同一份对账单里出，从出库到签收可以一条线追踪。
- 产品会与成熟的 WMS 产品正面竞争。以仓配为主业的租户愿不愿意换掉现有 WMS 是商业假设，不是已知事实；已在开发主线「产品需求假设」登记为 `PA-WF-01`，第一个仓配租户到来时复核。
- 首发不受影响（决定八），但会分走首个租户上线前后的开发注意力；排期宜放在首个租户上线之后。

## Alternatives considered

- **维持 ADR-0006，按协作缝与外部 WMS 协作**（[外部 WMS 协作缝设计备忘](../design/external-wms-collaboration-seams-design-note.md)）。范围不扩，首发与首个租户上线不受干扰；以仓配为主业的租户多半保留自己的 WMS。代价是没有 WMS 的仓配型租户要另配一套，库存到包裹跨两个产品，仓储费与运输费分两处出账。会话评估时建议的是这一项。
- **把仓配做进节点作业。** 否决：ADR-0006 否决「**直接复用 WMS 库存模型表达包裹流转**」的理由「表面复用较多，却会混淆暂时控制、网络位置与仓储库存语义。」原样成立。
- **只做轻库存**（SKU 级入出库记数，不做库位与任务）。否决：租户的仓库照样要一套能指挥现场的 WMS，轻库存成了第二本对不上的账。
- **预置主流 WMS 连接器。** 与本记录不互斥，是维持现边界那一项的加强版；连接器落在协作缝备忘的缝位上，按第一个租户实际用的 WMS 定。

## 越权风险点

1. 判据读法（决定一）：把「承运或渠道商业模式」读宽到 3PL 仓配，并推翻 ADR-0021 否决理由的半句。归产品 owner。
2. 委托的新来源（决定四）：内部上下文以货主名义提交委托，是 `parcel-shipment` 一种新的、不经客户渠道的来源；来源身份、授权依据与接受判断的关系归 PS owner。
3. 扣减时点（决定四）：库存在仓配自己的出库确认时扣减，不等节点收寄。同址场景里两件事实相隔很近，要不要一个把两者关联起来的读口，归仓配与节点作业两方。
4. 仓租计价（决定七）：按持有期计价是 `parcel-pricing` 的新计价对象，可能触及价卡结构与规范化版本；归 PP owner，另立 ADR。
5. 离线拣货（决定六）：照记已发生的拣货、差异交人，与预占的原子判定之间有张力；差异由谁、在什么时限内处理，归一线作业端与仓配两方。
6. 代理仓与 FBA（决定二）：代理仓库存声明、FNSKU 换标与 FBA 入库计划进不进首批，按第一个场景定；平台规则随亚马逊变化，不内置为常量。

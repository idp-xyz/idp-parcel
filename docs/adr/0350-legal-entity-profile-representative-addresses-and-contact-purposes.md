# ADR-0350：法人资料扩展代表人、办公与通信地址、联系人用途和按用途主要联系人

Status: Accepted（2026-10-30，用户要求完善公司主体并指示「开始吧」；本轮按该范围作产品实现选择。部分停用 ADR-0145 决定三的资料内容枚举，其余规则不变。）<!-- 索引注记 --> 「有扩展内容的快照写 `shape: LEP-2`，内容摘要为 `LEP-2:<sha256>`，不与旧版混比。」一句在含社交账号时已由 [ADR-0351](./0351-contact-social-accounts-are-optional-versioned-profile-details.md) 停用，在含收款账户、语言版本或主抬头语言时已由 [ADR-0359](./0359-regulatory-registration-numbers-bank-accounts-and-multilingual-invoice-titles-on-the-legal-entity-profile.md) 停用（写 LEP-4）；其余各条不变。
Date: 2026-10-30

## Context

公司主体只记录注册地址、税号、开票抬头与姓名/邮箱/电话，无法区分法人代表和普通联系人，也不能说明找谁办理哪类事项。将这些格放进身份或结算政策会混淆所有权。

## Decision

法人资料增加选填的代表人（`LEGAL_REPRESENTATIVE` 法定代表人、`RESPONSIBLE_PERSON` 登记负责人，类型与姓名成对），以及分别选填的办公、通信地址。注册地址保持原规则；额外地址不推导与继承，不支持以办公地址覆盖注册地址。不采集身份证号，也不由此推导签约权。

联系人增加部门、职务、多用途与 `primaryFor`。产品内置用途为 `GENERAL` 通用联系、`BUSINESS` 商务、`OPERATIONS` 运营、`FINANCE` 财务、`LEGAL` 法务；它们是联络分工，不是权限、登录人或签署授权。用途集合规范排序，重复用途拒收；主要用途须属于该联系人用途，同一修订同一用途至多一位主要联系人。缺用途不自动归入通用联系，不以数组首位推断主要联系人。后续用途扩展走显式契约变更。

新格均属于同一份按生效时点修订的资料，沿既有登记、解析与历史链路；缺席即未配置。它们与既有联系人姓名之外的联系方式一样，不成为全球必填或新的开票门禁。维护提示逐项列明，不计算完整率。

持久化沿用不可变快照作为重建来源。代表人与额外地址只存在快照中，联系人扩展同时保存在现有 contacts 列与快照；不新增供搜索的镜像列。依 ADR-0267 的最低可表达版本策略：旧形状维持原无标记快照与裸十六进制摘要，作为隐式旧版长期可读，不改历史行；有扩展内容的快照写 `shape: LEP-2`，内容摘要为 `LEP-2:<sha256>`，不与旧版混比。未知形状、扩展内容与标记不相容都明确读失败，不丢新格当旧版。旧形状缺席新格保持逐字节相同，扩展字段与版本标记一并参与摘要。两个读口和受控 CLI 同步扩形。旧构建不能识别新形状，开发演示服务在停止旧读进程后统一换构建；部署不得让旧构建与新快照共用读面，回滚须有识别 LEP-2 的读取构建。

更新表单显式带入操作者选定的已登记修订，保存仍是完整新修订，不执行隐式合并。未来修订可作为编辑来源，但明确显示来源和生效时间，不作为当前资料。依据、生效时间不得从旧版自动复制为本次决定。

## Consequences

保留原有开票解析语义和单据固定引用。资料维护与真实授权、银行账户、组织、人事、附件治理仍有不同所有权；本轮不创建这些模块。新字段需要服务端与管理台共同更新；浏览器热加载不能更新正在运行的 Go 二进制。

## Alternatives

把代表人并入普通联系人会失去登记身份语义；直接给每人一个全局主要标记无法表达财务与运营分别找谁；全部放进法人身份会让联系方式变化污染身份修订。均不采用。

# ADR-0233：同一对象换版时旧版只经显式收尾离开新的选择——后继晚于旧版起点按后继生效时点截止，同起点重发按决定引用退役；两种都指名同一对象的后继，新版发布本身不收尾旧版

## Context

- **换版不收口。** PC 只增：同一对象另发一版，旧版留在册上照旧`已生效`。按范围解析的册（合同、规则包、政策……）在两版区间重叠的锚点上答`适用冲突`（[UC-PC-001](../application/party-commercial/UC-PC-001-MAINTAIN-AND-PUBLISH-COMMERCIAL-AUTHORITY.md) 一致性一节：「必须形成适用冲突或先完成明确替代边界」），该客户的委托全停在解析上；按版本点读的消费方（运输委托提交、收费发生项登记）照旧接受旧版。领域上早有 `Retire`、`SupersededBy` 与区间更正（[ADR-0038](./0038-validity-correction-keeps-original-and-relationship.md)、[ADR-0056](./0056-validity-correction-append-only-serialized-by-version-row.md)），生产上没有一个写口调它们（读码钉 `61d1470a`）。
- **截止表达不了同起点重发。** 上线就绪评估只给区间更正接一个入口、把旧版截止在新版生效时点。可新旧两版同一起点时截止点就是旧版起点，`NewEffectiveInterval` 要求终点晚于起点，这样的更正立不起来；而本票的动因（演示干线协议 `v2`、`v3` 都是对 `v1` 的同区间重发）与评估点名的「第一次更正错登的合同」多半正是同起点重发（代决复核 M17）。
- **点读口不折更正。** `LoadSupplierAgreementVersion` 的端口注释写明「区间更正也不折进来」，`SupportsProcurementAt` 只看正文区间（ADR-0202 越权风险点 5）。照此只做截止，旧版在委托提交与发生项登记两处核对上照样能用，与 ADR-0038 决定二「有更正则按更正后区间判断适用」相抵（代决复核 M16）。
- **自带区间的正文也不折。** 价格、结算、信用政策按正文自己的区间选候选（`covers`），不问壳上的更正；壳被截止，正文照旧重叠。
- **只增仓储没有事后翻状态的口。** 版本行的快照随发布固定，发布用例「到界即取效」，此后不改写。

## 候选与反方

- **新版发布即自动收尾旧版（按新版生效时点截旧版）。** 同一对象发新版不一定是为了替掉旧版（并行试点、分区生效、错发了一版要撤），自动收尾等于替登记方做了一个它没说的商业决定，且发布批是逐项独立的（AT-PC-011），后项自动改写前项的选用区间会把「批不是聚合」打穿。否决，收尾要显式。
- **只做截止，同起点重发让运营把新版改晚一刻生效再截。** 那一刻里错的旧版仍唯一可选，且「晚一刻」是登记方为凑形状造出来的业务时间。否决。
- **同起点时允许零长更正（旧版截成空区间）。** 区间值对象与库面约束都不容空区间；为它放开，等于让「不再参选」借道区间语言表达，与 CONTEXT 生命周期上的「已退役」说同一件事却用两种写法。否决，同起点走退役。
- **一口受理、由服务端按起点挑截止或退役。** 截止留着旧版的前一段，退役让旧版整版不再参选；对已经指名旧版的消费方是两种答复（未生效与已终止）。服务端替登记方挑，登记方就看不出自己落下的是哪一种。否决，两口各说各的。
- **退役做成替代（`SupersededBy`，指名后继、壳进`已替代`）。** 替代是后继版本关系的完整写口，要裁替代与区间更正、退役的先后与合并，运输履约把`已替代`读作未生效而非已终止，还牵动票 88 的委托协议换版。上线前不全裁。否决，本记录只开同起点退役，替代留后继票（决定六）。
- **退役时刻由登记方给。** 退役只管此后的新选择：倒填一个更早的时刻改变不了已经作出的决定，填一个更晚的时刻又会让它在那之前就已落选（只增仓储没有到点翻状态的口），两者都不是真话；重放还会因时刻不同撞成异内容。否决，取登记时刻。
- **点读口照旧不折，留给消费方各自问更正。** 判据就会在 TF、PS 各抄一份。否决，PC 点读口折好再交（决定五）。

## Decision

**一、换版时旧版只经显式收尾离开新的选择；新版发布本身不收尾旧版。**（产品策略）

登记方指名旧版与后继，两版必须是同一对象（同租户、同类、同对象标识）、登在同一范围。收尾有两种，由两版此刻的选用起点决定能用哪一种：后继晚于旧版起点的走截止（决定二），同起点的走退役（决定三）；后继早于旧版起点的不是换版，两种都拒。两种各一口，都是登记册配置写（[ADR-0151](./0151-unassigned-command-faces-get-their-families.md) 的定族判据：提交方是管理商业登记册的操作者，授予按登记册）：

- 在线 `POST /commercial-version-successor-cuts`、`POST /commercial-version-retirements`，挂操作者渠道的登记册 Intake；租户取认证结果，载荷自报即拒；各收受控批文自己那一节恰一项。
- 受控 CLI `parcel-commercial register-version-closures`，批文 `{"tenantId", "cuts": [...], "retirements": [...]}`，与在线口共用同一份逐项翻译。
- 一项写 `kind`、`scope`、`objectId`、`version`、`successorVersion` 与 `reference`；截止另写 `correctedAt`。对象只写一次，形状里装不下「后继是另一个对象」。

**二、截止：旧版截止在后继此刻的选用起点，落一条区间更正。**（机制）

- 落下的就是 ADR-0038、ADR-0056 的区间更正：起点取旧版此刻的选用起点，终点取后继此刻的选用起点；原版本、原正文、原区间与批准不动，修订标识随之推进。截止点不由登记方给：给了就多一处会与后继对不上的格。
- 成立条件：两版都`已生效`；截止点严格落在旧版此刻的选用区间之内（不晚于旧版起点的走决定三，不早于旧版终点的两版本来不重叠）；后继若登了自带区间的政策正文，正文须从截止点开始，否则截在壳上那一段仍会重叠或留缝；决定四的共同门。
- 更正依据与更正时刻由登记方给（ADR-0056 决定四：更正时刻是更正事实自己的时间）。同一次截止重放认出册上那一条、不追加；第一次截止之后旧版的终点已是截止点，重放判在区间检查之前。换一份依据再截同一处答不成立。

**三、同起点退役：旧版按决定引用 `已生效 → 已退役`，另册保存。**（机制）

- 两版此刻的选用起点相同时，旧版退役（领域 `Retire`），自此不再参与任何新的选择；正文、批准与原区间保留，既有委托、交易与结算继续引用它（CONTEXT 生命周期「已发布 → 已退役」）。退役记哪一版、让位给哪个后继、凭哪份决定引用、何时起。
- 退役是登记册上的独立事实，另立一张册（迁移 `party_commercial/0040`），版本行的快照不改写；装载时施加到版本上。一版只退一次，后继以外键指向同一对象的另一版。
- 退役时刻取登记时刻，不由登记方给（候选与反方末两条之一）。同一个决定（同一后继、同一决定引用）重放答已登记、回显原退役时刻；换一份决定引用或换一个后继再退答不成立——那是改写「何时、凭什么不再可选」这一段史实。

**四、两种收尾的共同门。**（产品策略）

- 两版都在本租户这一范围的册上，旧版与后继不是同一版，两版都`已生效`。已计划生效的后继在只增仓储里不会自己翻到已生效，收尾旧版会让后继生效时点之后一版都选不中。
- 后继接得住旧版此后的那一段：后继此刻的选用区间要延续到旧版此刻的选用终点，旧版登了自带区间的政策正文的，后继也要登、且正文终点不早于旧版的。否则收尾会把原本唯一选中旧版的时段变成`无适用依据`。
- 先锁旧版的版本行，再读回整册判，再写（同一笔事务）。只靠写入那一刻的行锁（ADR-0056 决定三）守不住「对整册一次读」的判据：两笔对同一旧版的收尾各自读到未收尾的册、各自判过，后提交的那条照样落下。

**五、读法：解析与点读口都按收尾之后的口径答。**（机制）

- 解析：已退役的版本不参选（通用选法本只收`已生效`）。价格、结算、信用政策按正文自带的区间选候选，壳已不在已生效即落选，壳上有区间更正即与更正后的区间取交——取交而不取代，取代会让正文起点晚于壳的那一段反被放宽；壳仍生效又没更正时照旧只看正文区间，不拿壳的原区间去收窄它（两者从未被要求相等）。整册装载在各正文之前施加退役，已退役那一版的正文不进整册。
- 按版本点读：供应商协议的版本点读口交回`已退役`的壳、只交壳；它与正文点读口都把壳上最新一条区间更正折进正文的判用区间（`SupportsProcurementAt` 照更正后的区间答），正文点读口对已退役的那一版答不再支持任何新的采购决定、终止时刻读作退役时刻。内部成本政策点读口折进退役（答「没这份正文」），它不按区间判，区间更正在那里与原区间一样不起作用。
- 运输履约与小包委托的适配器不动：运输履约的核对按既有分格把截止点之后读作未生效、把已退役读作已终止（ADR-0202 越权风险点 7 的对法），小包委托的 `agreementOf` 经 PC 正文点读口同样得到收尾之后的答复。这回答 ADR-0202 越权风险点 5 与 ADR-0209 越权风险点 5，也把 ADR-0038 决定二补到正文选法与点读口上。
- 已形成的解析记录、委托快照与交易快照不改写。收尾推进该范围的视图修订，提交前重校据此答已失效，消费方按自己的续办重解。

**六、不在本记录。**（留后继票）

- 完整的替代写口：壳进`已替代`、记后继，替代与区间更正、退役的先后与合并，运输履约对`已替代`的读法；方向照上线就绪评估——替代必须同对象、显式指名后继，不以新版生效时点自动收尾旧版。
- 不指名后继的一般退役（产品下线、错发撤回）与后继晚于旧版起点时的退役。
- 延长区间、前移起点一类的区间更正：本记录的入口只截短。
- 合同委派与授权授予随合同、授权规则版本收尾：两者按自己的区间判，今天不看版本壳的生命周期。

三类：二、三、五是**机制**；一、四是**产品策略**；某个租户的哪一版何时收尾、让位给哪一版、凭哪份决定，是**租户取值**，由租户的商业责任方登记；演示租户由种子步 110 登 `SYN-` 取值（干线协议 `v1` 让位给 `v2`、`v2` 让位给 `v3`），证据只记 `S`。

## Consequences

- PC：领域 `CutAtSuccessorStart`、`RetireAtSameStartSuccessor`、`RegisterRetirement`，`SupplierAgreement` 的 `NarrowedBy`、`EndedBy`；用例 `CloseCommercialVersionHandler`；端口 `VersionClosureRegistry`；迁移 `0040`（区间更正册的类别约束放到 1..10，客户服务规则写得进截止；新立同起点退役册）。
- [UC-PC-001](../application/party-commercial/UC-PC-001-MAINTAIN-AND-PUBLISH-COMMERCIAL-AUTHORITY.md) 增 `AT-PC-054` 至 `058`；PC CONTEXT 增一条规则。
- 演示：种子步 110 把干线协议的 `v1`、`v2` 依次退役，演示动线指名的 `v3` 不受影响。

## 对已接受记录的作用

不停用任何条款。ADR-0038 决定二与 ADR-0056 各条不变，本记录把「有更正则按更正后区间判断适用」延伸到自带区间的政策正文与按版本点读口；ADR-0202、ADR-0209 正文不改，它们的越权风险点 5 由决定五回答。

## 越权风险点

1. **退役对供应商协议读作已终止**（PC、TF owner）。运输履约既有映射把`已退役`读作已终止、且与业务时点无关。已有委托指名了旧版的，旧版退役之后为这份委托登收费发生项答已终止，要等票 88 的「委托协议换版」改指后继；88 落地之前，同起点退役一份已被委托指名的协议版本会让这份委托此后的发生项登记停住。演示的退役只动 `v1`、`v2`，动线指名 `v3`。
2. **退役按决定时间读，不按业务时点**（PC、TF owner）。CONTEXT「自退役生效时间起不再供新的商业选择」本记录读作「退役登记之后作出的新决定」，业务时点早于退役时刻的新决定同样不再可选（同起点重发时后继接着整段时间）。owner 若认为应按业务时点，按版本点读的分格要改。
3. **政策正文与壳取交**（PC owner）。今天没有生产写入方会延长区间，延长型的更正不会放宽正文。真有那一天要另裁。
4. **「接得住」只看终点**（PC owner）。后继政策正文的其余维度（结算政策六维、价格政策方向）若与旧版不同，旧版那一维的时段收尾后无依据——与发一份换了维度的新版本身的风险相同，本记录不另判。
5. **截止依据与更正时刻由登记方给**（PC owner）。倒填更正时刻不改变选用（选用按登记顺序取最后一条，ADR-0056 决定四），只影响审计读到的那一格。
6. **合同委派、授权授予不随版本收尾**（PC owner）。同起点退役一版合同之后，挂在旧版上的委派照它自己的区间适用。
7. **内部成本政策点读的答复**（PC owner，知会 network-routing owner）。已退役的那一版答「没这份正文」，与从未登正文同一格，续办不同（一个改指后继，一个补登）。
8. **同起点退役的后继本身随后又退役**（PC owner）。退役不要求后继此后一直在已生效：演示里 `v1` 让位给 `v2`、`v2` 再让位给 `v3`，链上只有末一版可选。链断（末一版也退役而没有后继）由不指名后继的一般退役引入，归后继票。

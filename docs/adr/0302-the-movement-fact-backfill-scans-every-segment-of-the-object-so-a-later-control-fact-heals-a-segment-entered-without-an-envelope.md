# ADR-0302：移动事实补派生按对象扫它有参与的每一段——对象不经信封进了段，由它的下一份控制事实补上

Status: Accepted（2026-10-26，Claude Code 会话代 VE owner 决（代决）：用户 2026-10-20 原话「要我裁定的部分，你作为业务和系统专家，请你自决吧」；票 demo-chain-gaps/136，裁定出处为代决复核报告 `.scratch/owner-review-20261020/report.md` 的 M19，其「二选一」由本记录代决取「补派生改按对象全扫」。部分停用 [ADR-0224](./0224-tracking-backfills-movement-facts-recorded-before-their-segment-when-a-control-fact-puts-the-object-in-it.md) 决定三一句并回答其越权风险点 1（被停原句与适用场景见下文「对已接受记录的作用」与 ADR-0224 的 Status 行）；ADR-0224 正文不改，只在其 Status 行与 Links 加前向指针。越权风险点见文末，待 VE owner 复核，第 1、3、5、6 点同时待 TF owner。）<!-- 索引注记 -->｜**按对象扫**：交接（转出控制的那一版）与对象级场外揽收信封上的移动事实补派生，不再只看这一次控制事实让对象进的那一段，改为扫这件对象有参与的每一段；每段上声明了它、事实发生那一刻对象在控的在册移动事实都补派生，判据与幂等键同正常路径，早已派生过的答已有结果；触发、只补这一件、只补投影与失败分格不变。**为什么不取唤醒信封**：运输履约今天没有「续办进段」那一路——同一份控制事实重放答已有版本、不碰段册，更正只替代已有参与——唤醒信封无处可挂，造续办路是运输履约的产品裁决。**补上的时点**是该对象的下一份转出控制的交接或对象级揽收；此后只剩有效交付的末段照丢。越权风险点含末段照丢、读量随段数增长、坏行波及加宽、`EnteredByPickup` 失去生产调用方
Date: 2026-10-26

## Context

取证于 main `449a25508`，只记 `S`。

- ADR-0224 越权风险点 1 记下：控制事实登记时段那一半写不进（答复带续办引用 `SegmentContinuationReference`），这一版控制事实在段里没有参与，补派生那一路找不到它进的段、入账收工；日后续办把对象补进段，若不重交那封信（同 ID 被出队吞掉），那一份出发照丢。它给的修法是二选一：续办进段成功时交一封唤醒，或补派生改按对象全扫。代决复核报告 M19 复核为应修订、立票 136，二选一留给本票。
- 读码：
  - 进段那一半只在段册读不动、写不进或实际承运商判断首版写不进时欠账（`enterFulfillmentSegment` 交回续办引用）；进段是派生的一侧，欠账不回滚来源登记，控制事实与它的信封照样落册、交出。
  - 同一份控制事实重放时，交接、对象级揽收登记与揽收执行三口都答已有版本、不碰段册（`existingResult`；票 tf-unwired-seven/08 完成记录「重放不重进段」）；更正只在段上替代凭前版入场的参与，对象从没进过段时答 `NO_PARTICIPATION_TO_REDERIVE`。所以今天运输履约没有一条路把欠着的那一半续上：对象日后进那一段，只能凭另一份控制事实（它有自己的信封，ADR-0224 已覆盖），或经信封之外的路——存量迁移、直写段册，以及日后若立的续办入口。
  - 补派生（`BackfillMovementFactsAdapter`）按对象列出它有参与的段，从入场最晚的往前逐段认「入场依据指的正是这一次控制事实」的那条参与，认到那一段就只在那一段上补。凭信封之外的路进段的那一段，入场依据不指任何一封控制事实信封，永远认不到。
  - ADR-0224「Alternatives」里「补派生每次控制事实都扫对象在全部段上的事实」一条不取作默认，理由是读量随对象走过的段数线性增长、多出来的只是「早先某次进段时补派生没跑成」那一格的自愈。
- ADR-0224 越权风险点 6（凭存量迁移、手工直写段册进段的对象不补）与 Consequences「上线前已经丢掉的出发不会自愈」是同一类缺口：对象不经任何一封控制事实信封进了段。

## Decision

1. **补派生改按对象扫它有参与的每一段。** 交接（只认转出控制的那一版，拒收与待确认照旧连段都不读）与对象级场外揽收两封信上的补派生，按对象列出它有参与的段，逐段取回，在每一段上按段列出声明了它的在册移动事实，凡事实发生那一刻这件对象在控的就补派生。不再问对象凭哪一份控制事实进的那一段：入场依据只回答「凭什么进」，补不补只看事实那一刻它在不在控，与正常路径同一条判据（`ActualFulfillmentSegment.ObjectsUnderControlAt`）。扫的次序不影响结论。
2. **其余照 ADR-0224 不变。** 幂等键与派生命令同移动事实那一路（`deriveMovementFactOnto`），早已派生过的答已有结果，不出第二个条目；只补这一件对象，同段别的对象由各自的控制事实补；只补投影，不补信号、不重问关务；失败分格同 ADR-0224 决定六——任一段读不动、按段列事实读不动、派生未决整封回滚记未决，按对象列得出的段按键答没有、列出的事实没声明那一段或某一行装不回记发布失败。
3. **不造唤醒信封，运输履约一侧不动。** 唤醒信封要挂在「续办进段成功」那一刻，而那一刻今天不存在；造一条续办路（重放要不要重进段、谁来续、续不上答什么）是运输履约的产品裁决，不在本票。按对象扫不依赖对象是怎么进的段：日后有了续办路、存量迁移或直写段册，都在这件对象的下一份控制事实到达时补上。

## 候选与反方

- **续办进段成功时交一封唤醒信封（运输履约发、全程追踪收）。** 不取：运输履约没有续办进段那一路，信封无处可挂；造一条要先裁续办的产品形状，再加一类信封、分区登记与生产方合同（ADR-0224 决定一当初为同一理由没造「段已成立」信封），而且只覆盖那一条路，存量迁移与直写段册照丢。
- **只在这一次控制事实没让对象进任何段时才全扫。** 不取：欠账的那一版控制事实，它自己的信封到达时对象还不在那一段（续办在后），那时扫什么都扫不到；补上只能发生在之后的下一份控制事实上，而那一份通常正常进了段。条件立不住。
- **有效交付信封也挂一路补派生。** 本记录不做：有效交付结束控制，末段补上要靠它；但全程追踪对有效交付那一路的消费另有分格（集运单元入账不派生等），加一路要另记一本账、另列哨兵名单。今天唯一会落进这一格的是存量迁移与直写段册，记为越权风险点 1，归 VE owner 定。
- **定时按段回扫。** 不取：没有信封驱动，要新起一类运维作业并裁它的范围与频率；存量补救若要做，与 ADR-0224「上线前已丢的出发不会自愈」那一格一起另立。

## Consequences

- ADR-0224 越权风险点 1 有了去处：进段欠账、日后经任何一条路把对象补进那一段，那一段上先于进段登记、事实那一刻它在控的出发，由这件对象此后的下一份转出控制的交接或对象级揽收补出（UC-VE-002 `AT-VE-204`）。
- 同一机制顺带补上 ADR-0224 越权风险点 6 那一格的大半（存量迁移、直写段册进段的对象，下一份控制事实到达时补），以及「上线前已经丢掉的出发」里此后还有控制事实的那些对象；此后再没有控制事实的对象仍然丢着。
- 每一份转出控制的交接与对象级揽收，在追踪侧读对象走过的每一段（整段连同全部参与）与每段上声明了它的事实；早已派生过的每一份再答一次已有结果。此前也会逐段往前读直到认出那一段，多出来的是认出之后的各段与它们的事实。
- 补派生不再用 `EnteredByHandover` 与 `EnteredByPickup` 认段。前者运输履约自己还在用；后者此后没有生产调用方，领域里那一法与它的用例原样留着。
- 验收：UC-VE-002 `AT-VE-180` 去掉「有参与的段不是这一次交接或收寄进的」那一格，新立 `AT-VE-204`；替身用例与派发真库用例在 `backfill_movement_facts_test.go`、`cmd/parcel-dispatch/movement_fact_backfill_test.go`。
- [visibility-exception CONTEXT](../domain/visibility-exception/CONTEXT.md)「追踪投影与里程碑」入账不派生那一条下的两句同一笔改成现行规则：段不在册的那一条由对象此后每一份转出控制的交接或对象级揽收补派生；补派生时没有可补的各格去掉「它参与的段不是这一次交接或收寄进的那一段」。

## 对已接受记录的作用

- **部分停用 ADR-0224 决定三一句**：「只看这一次控制事实让对象进的那一段：对象一程走几段，只取参与入场依据指的正是这一次的那一段。」与同一条末句「一次控制事实至多让对象进一段，认到就停」——改为扫这件对象有参与的每一段（决定一）。**适用场景**：只限补派生扫哪几段；决定三其余各句（唤醒是对象级的控制事实登记信封、两路各另起一路另记一本账、名次、交接只认转出控制的那一版、只补这一件对象、不订阅「段成立」）不变；同一条中间那半句「交接用 `EnteredByHandover`；揽收由运输履约领域新加 `EnteredByPickup`……进段、重派生与认都经它」不停用——两法仍是运输履约领域的认法、依据拼写仍收在那一处，只是补派生不再调用它们（越权风险点 5）。ADR-0224「Alternatives」里「补派生每次控制事实都扫对象在全部段上的事实」一条由本记录改取，那一条的未采纳理由（读量）记为本记录越权风险点 2。
- **回答 ADR-0224 越权风险点 1**，无其他条款停用；其越权风险点 6 的大半随之有了去处（Consequences）。

## 越权风险点

1. **补上要等对象的下一份控制事实，末段照丢**（VE owner、TF owner）。续办或别的路把对象补进段之后、下一份转出控制的交接或对象级揽收到达之前，追踪上一直缺这次出发；对象此后只剩有效交付时（末段），没有下一份，这次出发照丢——有效交付信封不触发补派生。要立刻补上，要么运输履约造续办进段那一路并在成功时交唤醒信封（TF owner 的产品裁决），要么给有效交付信封也挂补派生一路（VE owner）。今天运输履约没有续办进段那一路，这一格实际只落在存量迁移与直写段册上。
2. **读量随对象走过的段数线性增长**（运维）。每份控制事实都读对象有参与的每一段与每段上的事实，早已派生过的每一份再走一次已有结果的两次读；长链路、反复往返的段上事实多时一次变大，不分页。ADR-0224 越权风险点 5 加重。
3. **坏行波及加宽**（TF owner、VE owner、运维）。按段列事实时一行装不回整次报错；此前只挂住凭控制事实进那一段的对象，现在凡是进过那一段的对象，此后每一份控制事实都停在这一封上、挂在各自分区的队头。同 ADR-0224 越权风险点 8 那一处，范围变大；坏行与读不动已分开报（记发布失败），去处仍是票 89 与 114。
4. **扫到的早先各段同样按消费那一刻的册子算**（VE owner）。参与日后被更正、更正后的起点晚于事实，已补的那一份不撤，与正常路径同一缺口（ADR-0224 越权风险点 4）；对象是集运单元时，早先各段上的事实同样按消费那一刻集运成员册里记着的、事实发生那一刻的成员展开，成员关系日后被更正的，已补的也不撤。多扫的段让这一口径落到更多事实上。
5. **`EnteredByPickup` 没有生产调用方了**（TF owner）。领域那一法与它的用例留着，删不删由 TF owner 定；依据拼写的收口（`pickupParticipationBasis`）照旧被进段与重派生用着。
6. **选全扫而不是唤醒信封是本记录代决**（VE owner、TF owner）。owner 若要唤醒信封：TF 先裁续办进段的入口与形状，再由那一路交唤醒信封；本记录的全扫可以留作兜底，也可以退回 ADR-0224 决定三的只看那一段。

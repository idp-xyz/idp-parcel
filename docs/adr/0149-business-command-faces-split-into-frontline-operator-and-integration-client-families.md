# ADR-0149：主链业务命令面按提交者分两族——一线作业事实走操作者渠道族新增的「作业事实登记」能力面（人 + 已登记设备），外部结果与资金事实走集成客户端族（客户端凭据，推送源经签名 webhook）；ADR-0055 决定五两项按口逐一解

Status: Accepted（2026-09-24，用户经 IDP 队列授权通道 4「参考专业头部软件的做法，你来帮我自决吧」，承票 operator-channel/09。裁决能力边界：读过 [ADR-0100](./0100-operator-identity-is-a-product-owned-access-channel-family.md) 决定一至六与 Consequences、[ADR-0055](./0055-business-endpoint-intake-has-an-unconfigured-grade.md) 决定五、[ADR-0023](./0023-work-fact-identity-and-time-are-minted-by-the-device.md) 所定的纪律、[ADR-0091](./0091-isolated-form-extends-to-the-write-path-by-graded-switches.md) 逐口放行在 `cmd/parcel-api/endpoints.go` 头注里的装配形态、`internal/accessidentity` 的全部导出面。没读：ADR-0139 至 0142 全文（客户渠道，Proposed）、各命令口载荷的现有形状——后者逐口在实施票里核。）；**部分停用**：决定一列举里「派送任务」「段关闭」两项对管理台手工建派送任务与关段两口（`/transport-fulfillment-dispatch-task-registrations`、`/transport-fulfillment-segment-closures`）的适用已由 [ADR-0151](./0151-unassigned-command-faces-get-their-families.md) 停用——两口是运营写决定，归操作者渠道的「运营决定」能力面；派送发起口与其余各条不变
Date: 2026-09-24

## Context

ADR-0100 把操作者渠道限在登记册配置写面与目录查阅面，并把「作业事实登记、外部结果接收」与客户委托并列为客户业务命令面，说它们照旧被 ADR-0055 决定五两项未决拦着。可这两类命令的提交者都不是货主客户：作业事实由运营企业自己的一线人员在作业端（[ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md)）上形成；外部结果与资金事实由海关、报关服务商、承运商、银行这类外部系统送来。留在「客户业务命令面」一格里，生产上就没有任何一族渠道承接它们，psb/05 格 7、11、12、22 的 `403` 在生产上永远解不开。

头部物流与仓储软件在这件事上做法一致：一线扫描作业以「人 + 已登记设备」记每一笔，人经产品统一的身份提供方登录（原生应用走 authorization_code + PKCE，共享设备走设备授权许可）；系统对系统的集成是机器客户端，用 OAuth 2.0 客户端凭据，高保证场景加 mTLS 绑定；对方只能推送的，按签名 webhook 进入。幂等与冲突判定靠请求的规范化摘要，生产写入受上线范围约束。

## Decision

**一、主链业务命令面按提交者分两族；客户委托不在本记录内。** 作业事实登记（节点收寄、场外揽收与尝试、交接、移动、派送任务、交付、段关闭、有效时间判断等）的提交者是运营企业的一线人员；外部结果与外部资金事实（关务外部结果、监管凭证、承运商轨迹与首次有效收寄证据、外部资金事实）的提交者是外部系统。客户委托的提交、撤回、补充与资料修订仍归客户渠道（ADR-0139 至 0142，接受与否归用户）。

**二、一线作业事实走操作者渠道族，新增能力面「作业事实登记」。**

- 授予按租户 × 作业范围（节点、场外作业范围）登记在 ADR-0100 的操作者册里，与既有两格并列；行是租户取值。
- 一线作业端按原生应用取令牌（authorization_code + PKCE）；共享设备可用设备授权许可。凭据校验与信封铸造沿 ADR-0100 决定二、三。
- **设备单列一册**：设备标识、所属租户与作业范围、状态（登记 / 停用）。作业事实请求带已登记的设备标识；事实身份与发生时间照 ADR-0023 由设备签发，服务端不重签。信封记「操作者主体 + 设备」两件，缺一不铸。
- 答复代数沿 ADR-0100 决定四的三格，另加「设备未登记或已停用」一格（`403`，恢复动作：管设备的人去登记）。

**三、外部结果与资金事实走集成客户端族。**

- `internal/accessidentity` 增集成客户端册：客户端标识绑定唯一租户与一个来源身份（某报关服务商、某承运商、某银行），授予按事实类型登记、可撤销、带生效区间。
- 请求方持客户端凭据（OAuth 2.0 client credentials）取令牌，`parcel-api` 按 ADR-0100 决定二的方式校验；高保证场景可要求 mTLS 绑定令牌。
- 对方只能推送的，入向连接器按签名（HMAC 或对方公钥）校验后，以该集成客户端的身份铸信封；签名密钥属租户取值。
- 票 psb/09、10、12 的入向连接器项以本族为信任入口。

**四、ADR-0055 决定五两项未决按口逐一解。**

- **载荷规范化摘要**：每个命令口的载荷由所属上下文定一版规范化形状、带形状版本（先例 `PSC-1`、`PCC-1`），摘要进信封，作同身份重放与内容冲突的判据。未定形状的口不开真渠道。
- **准入范围装配**：生产形态下，铸信封前按（租户、对象范围、能力、事实类型）读 pilot-governance 当前的生产权威区间（PN-08 的记录能力）；区间不覆盖即答新格「不在准入范围」（`403`，恢复动作：阶段治理登记区间），不进业务编排。区间内容（`PAR-GOV-03..07`）是租户取值。

**五、隔离形态照旧。** operator-channel/08 按 ADR-0091 逐口放行的合成写不因本记录退场（ADR-0091 决定六）；两者是装配点上的两行，互不替代。

**六、部分停用 ADR-0100 两句里「作业事实登记、外部结果接收」那一半。** 被停的是决定四末段「客户业务命令面（委托提交与撤回、作业事实登记、外部结果接收）照旧被两项未决拦着」与决定五第一条「不给客户业务命令面开操作者渠道」对作业事实登记与外部结果接收的适用。**适用场景**：作业事实登记面与外部结果、外部资金事实接收面。客户委托那一半与 ADR-0100 其余各条不变。

## 候选与反方

- **甲 · 维持 ADR-0100 的划法，作业事实与外部结果等客户渠道。** 反方：提交者不是客户，客户渠道的信任锚与授权模型对它们不成立，等的是一个不会覆盖它们的渠道。否决。
- **乙 · 一线作业只认设备证书，不认人。** 反方：交接、签收的证明力要落到具体人员，只认设备会让共享设备上谁做的无从追溯；头部做法也是人 + 设备。否决。
- **丙 · 外部结果走共享 API Key。** 反方：密钥没有授予范围、难轮换、泄露面大；客户端凭据按客户端登记授予与撤销。否决。
- **丁 · 准入范围由各上下文在应用层各自判。** 反方：每个上下文各写一份准入就是多份第二权威；在铸信封处读一次治理区间才是单一权威。否决。

## Consequences

- 实施拆进 operator-channel 目录续编：10 设备登记与「作业事实登记」能力面；11 集成客户端册与客户端凭据校验；12 签名 webhook 入向；13 各命令口的载荷规范化形状（逐口）；14 准入范围读口与「不在准入范围」一格。
- 参数登记册：「运营操作者账户与授予」一行（operator-channel/01）同时覆盖作业事实登记能力面的授予；随 10 增「作业设备」一行、随 11 增「集成客户端与凭据」一行，都是租户取值。
- ADR-0100 按 README 部分停用机制加前向指针。

## 越权风险点

1. **部分停用 ADR-0100 的那一半**：ADR-0100 原文把作业事实登记、外部结果接收与客户委托并列；本记录判一线作业属运营企业自己的人、外部结果属外部系统，客户委托那一半不动。
2. **设备只登记标识、所属与状态**：不做设备管理（MDM），不校验设备健康。
3. **生产写入要落在治理区间内**：首个租户上线、治理登记区间之前，任何生产写都答「不在准入范围」——这是设计，不是缺陷。
4. **凭据本体属敏感实例**：客户端密钥、私钥、webhook 签名密钥都外置，产品只存客户端标识与凭据引用。
5. **规范化形状逐口定**：未定形状的口不开真渠道，真渠道因此按口逐步开，而不是一次全开。

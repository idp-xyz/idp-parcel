## Context

- [ADR-0199](./0199-node-reception-preserves-the-delivery-source-and-rechecks-pending-identities.md) 决定四「**四、同一作业实物在同一节点不另起控制起点（第四期）。**」定义「当前收寄」：「这件实物在这个节点上，有一条判断链的当前有效版本是`节点收寄已形成`或`待识别实物已建立`，且那一版的控制没有转出。」并规定：「有当前收寄时，同一实物在同一节点的任一交付观察都并入它」。
- [ADR-0214](./0214-node-control-transfers-out-and-in-on-an-authoritative-transport-handover.md) 决定七另立一种控制起点：权威运输交接`已交接`且声明了接收节点时，在该节点立 HANDOVER_IN 控制，记在节点控制转移册上。它的文末补记写「否则在接收节点立 HANDOVER_IN 控制，成立时刻取交接的业务时间。」越权风险点 17「收寄不认交接转入立起的控制」：「收寄编排只看收寄链，会再立一份，此后的转出停在「不止一份」。」后继票 demo-chain-gaps/92。
- 两份都已接受，谁也没停用谁。读 ADR-0199 的人会以为同一节点只有一个控制起点；转入之后再有一次送站，实际会有两份。补记自己说过两份的后果：「两份在身控制说不出实物在哪个节点，此后的转出也只能停在「不止一份」。」
- 代码（取证于 main `b18f662bc`）：`internal/nodeoperations/application/receive_delivered_unit.go` 的 `Handle` 只调 `Receptions.FindCurrentJudgmentsAtNode` 认当前收寄，看不到转移册；转移册由 `ports` 的 `FindUnitControls`（同一把实物锁）读，收寄不读它。
- 业务上，交接转入是权威运输交接对这件实物已经在本节点受控的确认；之后节点人员再扫到它，是同一件实物在同一个节点上的又一次观察，不是一次新的送站。

## Decision

**一、同一节点上的在身控制吸收此后的交付观察，不论它由节点收寄还是交接转入成立。**（机制）

- 同一作业实物在同一节点上已有在身的节点控制时——由节点收寄成立的（当前收寄，ADR-0199 决定四），或由交接转入在本节点成立、尚未转出的（ADR-0214 决定七）——同一实物在这个节点的任一交付观察（明确接收、明确拒收、仅扫描）都并入那一份控制。
- 并入在身份核对之前认出：不问 `parcel-shipment`、不形成新判断、不建控制、不交意图；这次送站的来源照样保全（ADR-0199 决定一）。
- 同一作业实物按本租户内的作业实物标识认，与 ADR-0199 决定四同一认法。

**二、并入交接转入控制的形。**（机制）

- 收寄记录落一行，种类为「并入在身控制」，指名被并入那一份控制的依据（交接转入铸出的 `HANDOVER-IN/…`）。它与「并入已有收寄」一样不是后继、不占前版；收寄记录种类的库面封闭集随之扩，不进 outcome 词表。
- 答`已有结果`。交接转入立起的控制没有收寄判断链，信息格带那一份控制的成立方式（交接转入）与控制依据，不带判断种类与当前有效版本。

**三、认法：收寄连同转移册一起读在身控制。**（机制）

收寄取实物锁之后，读这件实物在本节点此刻在身的各份控制：收寄行上的与转入立起的一起读，都把转移册上的转出折进去（ADR-0214 决定三「控制是否已转出，读时把转移册上的转出按（租户，作业实物，控制依据）折进去」）。锁与转出、转入是同一把，同一件实物的送站与交接串在一起。

**四、不在本记录。**

这件实物的在身控制在别的节点上时，这次送站怎样处置（照立并入账一格，还是拒收）是票 demo-chain-gaps/92 的另一问，归 NO owner。它不是 ADR-0199 与 ADR-0214 之间的矛盾：ADR-0199 决定四只管同一节点。

## 候选与反方

- **明写交接转入的控制不受「同一节点不另起控制起点」约束。** 否决：收寄会另立一份 NODE_INTAKE 控制，此后转出停在「不止一份」、转入停在「仍有在身控制」，实物在节点上照常作业，控制只能靠人对账；这正是 ADR-0199 决定四要挡的。
- **把「当前收寄」的定义改成当前在身控制。** 不采纳为写法：「当前收寄」是判断链上的词，重核、身份冲突处置与查阅都按它读；交接转入的控制没有判断链，塞进同一个词会让那几处读出一份没有判断版本的「收寄」。改的是并入的对象，不是这个词。
- **答一格新的「已在节点控制之下」。** 否决：`已有结果`说的就是这件已经处理过、不重复建立控制起点，再立一格只多一个所有调用方都要认的结果码；区别放在信息格里。
- **并入时只保全来源、不落收寄记录。** 否决：来源保全本就落在收寄记录上（ADR-0199 决定一），没有那一行，这次送站在查阅面上不可见。

## 对已接受记录的作用

- **部分停用（扩成）** ADR-0199 决定四「有当前收寄时，同一实物在同一节点的任一交付观察都并入它」一句。**适用场景**：同一作业实物在同一节点上没有当前收寄、却有交接转入在本节点立起且尚未转出的控制时——同样并入，并入的是那一份控制，形见决定二。「当前收寄」的定义、并入已有收寄的形与 ADR-0199 其余各条不变。
- **回答** ADR-0214 文末补记越权风险点 17「收寄不认交接转入立起的控制」的同节点那一半：同一节点上收寄认它、并入它，不再另立一份。转入之后在别的节点又形成节点收寄那一半不在本记录（决定四）。无条款停用，ADR-0214 其余各条不变。

## Consequences

- 代码随票 demo-chain-gaps/92：收寄编排在锁下连同转移册读本节点在身控制；有交接转入的在身控制时落「并入在身控制」一行、答`已有结果`；迁移扩收寄记录种类、加指名控制依据的一列；查阅面带出这一行；补编排与真库用例（转入之后同节点再送站、再仅扫描、再拒收，各并入、不另起控制起点，此后以本节点为交出节点的交接照常转出那一份）。
- node-operations CONTEXT 节点控制生命周期里「同一作业实物在同一节点已有当前收寄且控制尚未转出」那一条扩到交接转入的在身控制；UC-NO-002 结果语义契约「已有结果」一行与应用流程识别那一步随之扩；「给开发的交接」记今天的缺口。
- UC-NO-005 不改：它的状态行已写「收寄认转入控制待后继票」。

## 越权风险点

1. **代 NO owner 定了并入的对象**（NO owner，TF owner 会签）。若 owner 认为交接转入之后节点人员的扫描应当形成一次独立的节点收寄（例如运输方交进节点不算节点人员已接收），推翻的是决定一；那时要另裁交接转入的控制与随后的收寄控制谁让位，否则仍是两份在身控制。
2. **拒收观察也并入**（NO owner）。转入之后节点人员对同一实物答明确拒收，照 ADR-0199 决定四同样并入、不改控制；实物真的被拒之门外时，控制要由下一次权威交接结束，不由这次拒收结束。
3. **别的节点上的在身控制仍会长出第二份**（NO owner）。决定四之下，漏登一次交出、实物在另一个节点被收寄时照旧另立控制，转出停在「不止一份」，靠票 92 的另一问。
4. **信息格没有判断种类**（NO owner）。调用方若按`已有结果`的判断种类分支，读到并入交接转入的一行时那一格缺席；要按控制成立方式分辨。

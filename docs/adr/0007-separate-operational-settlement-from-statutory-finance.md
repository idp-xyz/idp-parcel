# ADR-0007: 分离物流运营结算与法定财务账

Status: Accepted
Date: 2026-07-29

## Context

国际小包运营需要在面单购买、履约、供应商对账和客户结算过程中维护预估费用、冻结余额、运营应收应付、费用争议和单票毛利。同时，同一货主客户可能由不同法人签约、采用多个币种和不同结算政策，银行资金、税务发票、坏账和总账又必须遵守法定财务边界。

需要在复用货主客户账户作为唯一财务账户、在小包系统中建设完整 ERP，以及建立独立运营结算分户账之间作出选择。

## Decision

`settlement-accounting` 建立独立于货主客户账户的结算账户。每个结算账户固定责任法人、结算相对方、收付方向、结算币种和结算政策；实际付款责任方与结算相对方不同时另行保存。多个合同只有在商业协议中的结算政策明确允许时才能归集。

小包系统拥有物流运营计价、运营应收应付、资金冻结、业务可用余额、对账、账龄、核销映射和经营指标。财务、税务、银行或支付系统继续拥有真实收付款、银行清算、法定税额与发票、会计应收应付、坏账减值、总账和法定报表。双方通过可追溯的外部事实和结果映射协作，不共同维护一个可覆盖余额。

## Consequences

- 同一货主可以按责任法人、相对方、方向、币种和结算政策隔离费用、余额与核销，避免跨责任串账。
- 小包系统可以在业务发生时进行预冻结、信用控制、供应商成本审核和经营毛利分析，而不等待总账处理。
- 法定财务系统仍是资金、税务和会计事实来源，小包系统不能凭运营记录自行认定收款、税额或坏账。
- 两类系统之间必须建立稳定的事实引用、差异对账、重试和撤销关系，集成及运营成本会增加。
- 产品界面和报表必须区分运营余额、经营口径金额与法定会计金额，不能把名称相似的结果混为一个事实。

## Alternatives considered

- **直接复用货主客户账户**：对象较少，但会混合不同法人、币种、付款责任和结算政策，无法可靠处理预付、核销和账龄。
- **在小包系统中建设完整 ERP**：能够集中处理全部财务事项，但会复制银行、税务、总账和法定会计职责，显著扩大产品边界。
- **只向财务系统导出费用**：边界简单，但无法支持面单预冻结、实时信用控制、供应商账单审核和可解释的运营毛利。

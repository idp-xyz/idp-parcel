# ADR-0017: 实现准入闸门按阻断理由分别裁决

Status: Accepted  
Date: 2026-08-10

## Context

[Go 首个消费者切片决策简报](../design/parcel-go-first-consumer-slice-decision-brief.md)（Status: Confirmed）的「实现准入检查」设了两道闸门，当前结论都是「保持阻断」：

- **业务语义闸门**，阻断理由「W01 仅有待核验候选，W02 直接参数仍待提供」；仍禁止范围含`已提交`聚合、接受任务、事件、Repository、事务、Outbox 和任何生产默认值。
- **Bento 持久化技术闸门**，阻断理由「尚无可用不可变 RC 或消费者证明」。

同一份简报据此在「下一步」写「当前只继续这一边界内的负向单元验证，不扩展生产应用合同」。

[ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md) 已裁定每个 `PN-*` 切片含机制半边与实例半边，且「租户实例为空也不阻塞机制实现」。[开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)据此把仅有契约测试的上下文分布判为「此后不再有正当理由」。

冲突不在措辞。业务语义闸门给出的阻断理由——W01/W02 的真实商业范围与接入归属参数——**整体属于实例半边**；而它禁止的范围——应用编排、Parcel 自有端口、聚合形态——**整体属于机制半边**。按闸门原文，机制半边被实例半边的缺口阻断，正是 ADR-0016 要解除的死锁。

[AGENTS.md](../../AGENTS.md) 的冲突规则已给出优先级：产品基线与 ADR 优先于设计交接。但简报仍标 `Confirmed`、闸门结论仍是「保持阻断」，未经裁决。留着不裁，任何人推进应用层都会撞上一份现行文档说禁止。

两道闸门的阻断理由性质不同，此前被同一张表掩盖：业务语义闸门卡在真实参数，属实例半边；Bento 技术闸门卡在外部不可变工件不存在，既不是机制也不是实例，是外部依赖，ADR-0016 对它无影响。

## Decision

**实现准入闸门按阻断理由的性质分别裁决，不再按闸门条目整体裁决。** 遇到任一闸门先分辨其阻断理由属机制半边、实例半边还是外部依赖，再决定它约束什么。

**业务语义闸门重述为只约束实例半边。** 机制半边即刻放行：`parcel-shipment` 的应用编排与命令处理、Parcel 自有语义端口的接口定义、`已提交`聚合的领域形态及其确定性测试替身。实例半边仍然阻断：任何真实客户、合同、线路、金额、阈值、角色或时限取值进入代码，以及任何租户流量进入生产接单。

**Bento 持久化技术闸门原样保留。** 它卡在外部不可变工件不存在，与租户参数无关。PostgreSQL Repository 实现、迁移、事务与 Outbox 仍然阻断，仍不得建立本地框架替身。

**端口接口与端口实现分开裁决。** Parcel 自有语义端口是接口，属机制半边，现在可定义；它的 PostgreSQL 适配器属 Bento 技术闸门范围，仍阻断。测试可使用 Parcel 自有端口的确定性内存替身——替的是 Parcel 的端口，不是 Bento 的框架合同，不构成简报所禁的「本地框架替身」。

**证据红线不变。** 隔离环境形成的结果一律记为 `S`，不因应用层跑通而升级。

## Consequences

- 决策简报的「实现准入检查」表与「下一步」须改为引用本记录，不在简报内另写一套口径。
- 开发主线列出的四项横切缺口中，「无应用层」不再被闸门阻断；「无持久化」与「无事件机制」仍阻断于 Bento 闸门；HTTP 业务端点在应用层成型后自然解除。
- 端口接口将先于其唯一实现存在，会有一段「接口已定、只有内存替身」的时期。形状定错的风险由契约测试与 `UC-*` 承担，不靠推迟接口定义规避。这是本决定接受的代价。
- 新增一项判断成本：每次援引闸门都要先分辨阻断理由的性质，不能照抄「保持阻断」的结论。判断错误会以两种方式出现——把外部依赖误判为实例半边而擅自放行，或把机制半边误判为实例半边而继续停滞。
- 本记录不改变任何闸门的**通过条件**，只改变它们各自约束的范围。业务语义闸门的实例半边仍须真实证据才通过。

## Alternatives considered

- **维持闸门原状，等真实参数。** 否决：这正是 ADR-0016 要解除的死锁；且这些参数按定义取不到——开发方不是任何客户合同或供应商协议的当事人。
- **直接改简报，不立 ADR。** 否决：闸门是难逆转的技术取舍，AGENTS.md 要求走 ADR。就地改会把裁决理由散落进设计交接，下次同类冲突无处可查，也违反单一权威。
- **连 Bento 技术闸门一并放开，先建本地框架替身。** 否决：它卡的是外部工件不存在，ADR-0016 不适用。本地替身会让 `PBC-*` 消费者合同失去证明意义，且简报 `P-07` 明禁 `replace` 与源码副本。
- **等 Bento RC 到位后两道闸门一起推进。** 否决：把机制半边的进度挂在开发方控制不了的外部工件上，是同一个死锁换了个理由。
- **把闸门整体降级为建议，不再作硬门禁。** 否决：闸门挡住的「不得把未确认取值写成生产默认值」「不得用伪事务冒充持久化证明」都是仍然有效的红线，降级会连带丢掉它们。

# ADR-0092: 渠道面单载荷在领域与库里只落引用，本体存放是一条未配置的出向缝；载荷记录追加不可覆盖

Status: Accepted  
Date: 2026-09-02

## Context

[ADR-0088](./0088-label-channel-service-enters-the-first-release-service-forms.md) 把面单渠道服务改为首发对客销售的独立服务形态，末端渠道随之会把**面单本体**交回来。而本仓没有地方放它：面单交易聚合上与结果有关的只有包裹级标识与结果原因，`LabelTransactionParcelResult` 四项里没有载荷，`0010_label_transaction.sql` 的列与快照文档同样没有载荷或其引用。按 `PDF`、`ZPL`（含小写）扫 `internal/` **零命中**（这个数本身是论点，取证于 `13bc515`）。

[ADR-0090](./0090-outbound-integration-result-algebra-partitioned-by-recovery-action.md) 定了出向契约，其后票 `07` 落出取面单端口的形状——一次结果可能有**多份件**，粒度可能是**批**而非包裹，格式可能是栅格也可能是指令流。落点要容下这些。

**难逆转的是「本体放哪」，不是任何一个格式取值。** 迁移与读面的形状按它定，改一次要动已经存了真实面单的库。本记录只答这一问及其直接后果。

裁决经 owner 于 2026-09-02 明确授权作出（原话「你作为业务和技术专家，你自己做全面的决策」），取证与三选项的代价对照在 `.scratch/label-channel-service-first-release/issues/09-channel-label-payload-landing.md`。

### 三条已核事实把选项空间压窄

1. **本仓今天没有任何对象存储依赖。** `go.mod` 直接依赖仍是三个（`go-chi/chi/v5`、`jackc/pgx/v5`、`idp-bento-go`），按 `s3`／`minio`／`blob`／`bucket` 扫全仓无生产命中。
2. **框架也没有文件能力。** `idp-bento-go@v0.1.0-rc.2` 的包目录按 `file`／`blob`／`storage`／`object`／`attach`／`document` 递归扫**零命中**。
3. **产品基线把「文件」划给技术组件，不划给本产品。** [产品基线](../product/PRODUCT-BASELINE.md)「独立项目边界」一节写明：公司级身份认证、审计、消息、**文件**、配置和可观测性等能力只能通过有版本及兼容性约束的技术组件复用，且技术组件不得取得本产品业务数据所有权。

### 还有一条技术事实，它比上面三条更具体

面单交易的行模型是键加 `revision` 加 `state` 加 **`snapshot jsonb`**（`0010_label_transaction.sql`），读回路径是整份快照重水合。把字节放进聚合就是放进那份 JSONB：base64 膨胀三分之一，且**每一次读回这笔交易都要把面单一起水合**——而读回的绝大多数场合（判状态、追加后续动作、派生定案）根本不看面单。这不是容量问题，是把一份冷数据焊进了热路径。

## Decision

### 一、领域与库只落**引用**，不落本体

面单交易记录的是「渠道产生了这样一份件」，由四样构成：**定位符**（本体在哪，未配置时为空）、**完整性摘要**（收到本体那一刻算出，与本体是否已存放无关）、**声明**（角色、格式、粒度，取值由渠道声明，机制不列举）、以及**覆盖范围**（粒度为批时列出该件覆盖的全部包裹，为件时恰一件）。

摘要与定位符分开是这一条的关键：**摘要证明我们确实收到过这份件，定位符回答它此刻在哪。** 合成一格会让「收到了但没处放」表达不出来，而那正是今天唯一走得到的分支。

### 二、本体存放是一条出向缝，未配置即如实作答

本体交由 `internal/platform/outbound` 那条缝上的一个存放端口，与取面单、轨迹源同一套代数（ADR-0090）。真组件就位之前它答 `NotConfigured`，交易照常记下件已产生、摘要已算、**本体无存放处**。

这不是把问题推走，是把它放回它该在的半边：文件能力属技术组件（上文事实三），而那个组件今天不存在（事实一、二）。现在引一个对象存储依赖，代价是「直接依赖只有三个」这件事——它本身被[开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)当作「参数显式未配置」的佐证在引用，票 `04` 把清点工具做成嵌套模块避的正是同一件事。

**未配置不得表现为丢弃。** 收到本体却答不出存放处时，摘要与声明照记，定位符留空并如实标注；不得静默丢掉，也不得假装存过。

### 三、载荷记录追加，不可覆盖

同一次结果的载荷不得被后来的调用顶替。重打、换单、替换各自产生**新的**载荷记录并保留原记录，更正走追加而不是就地改——形状与本仓既有的不可覆盖版本一致（客户原始资料版本、发布登记册、交付更正版本链）。

**因此库里没有「当前载荷」这一列。** 要哪一份由读面按业务规则派生，与面单交易定案是派生谓词（[ADR-0084](./0084-label-transaction-is-an-independent-aggregate-with-two-level-results.md) 决定四）同一个理由：存一列就有了第二个来源，某次追加忘了改列，两处便各说各话。

### 四、格式与角色的取值不进机制

哪家回 PDF、哪家回 ZPL、DPI 多少、一份结果里各件叫什么角色——一律实例半边（`PAR-INT-02`／`PAR-SET-03`，ADR-0088 决定五）。机制存的是渠道声明的字符串，不校验其集合，也不做成封闭枚举：做成枚举会在接第一家真渠道时被撑破，而撑破的表现是一个认不出的取值被译成零值。

**粒度是例外，它是封闭的两格。** 逐件与逐批不是渠道的自由取值，而是决定「这份件对应哪些包裹」的结构分叉，票 `07` 已在端口上定死。

## Consequences

- **真组件就位前，演示看不到面单本体。** 与九个业务端点今天一律答未配置是同一种诚实，不为演示好看而在库里种一份假面单。
- **摘要要在收到本体那一刻算。** 它是本记录唯一必须在字节还在手上时完成的动作；漏算就永久失去了「我们收到过什么」的证据，事后补不回来。
- **存放端口是第三个出向缝消费者**（取面单、轨迹源、载荷存放），ADR-0090 那套代数因此再被复用一次，不另立形。
- **库里会有同一件包裹的多条载荷记录。** 读面必须按业务规则挑，不能取「最后一条」——重打产生的新件与被替换的旧件在时间上相邻而在业务上不同。
- **本记录不解除任何闸门**，也不承诺任何真实渠道或文件组件被接入。
- **将来接入文件组件时改的是装配与那一个端口的实现，不是迁移。** 这是选引用而非本体换来的最主要一格：本体存放处变化不动业务库形状。

## Alternatives considered

- **本体入业务库（`bytea` 列或进 `snapshot jsonb`）。** 否决，两条理由各自独立成立：其一，它让本产品**拥有了文件**，与产品基线「文件能力经技术组件复用、技术组件不得取得业务数据所有权」相抵；其二更具体——聚合以整份 `snapshot jsonb` 持久化并整份重水合，字节进去就被焊进了热路径，而读回这笔交易的绝大多数场合根本不看面单。若日后确需本体入库，也应是独立表加独立读路径，那时仍要走一次新决定。
- **现在就引入对象存储依赖，本体去那里。** 否决：那个组件今天不存在于本仓，也不存在于框架（Context 事实一、二）。现在引就是替一个尚不存在的技术组件选型，且要打破「直接依赖只有三个」——而那件事本身正被开发主线当作证据引用。**等它存在时，本记录的决定二不需要改，只需把端口接上。**
- **干脆不记载荷，只记包裹级标识。** 否决：渠道确实回了件，不记就是丢掉一个已经发生的业务事实；而且重打、作废、替换要判「这一份和上一份是不是同一件」，没有摘要就判不了。
- **记载荷但只记一条「当前」，更正就地改。** 否决：正面违反票 `09` 的红线，也与本仓所有不可覆盖版本形状相反。就地改会让「客户手上那张纸是哪一版」在事后无从回答。
- **把角色与格式做成封闭枚举以便机制校验。** 否决：取值属实例半边，接第一家真渠道就会被撑破，而撑破的表现是认不出的取值被静默译成零值。粒度不在此列，理由见决定四。
- **等第一家真渠道接入时再定落点。** 否决：与 ADR-0090 的同类条一致——真渠道账号属 `PAR-INT-02`、租户尚未到位，「等」的终点不可预期；而票 `09` 现在就卡在这一问上，它下游还有面单文件生成/加工那一族。等到那天改的是既有迁移，不是空白。

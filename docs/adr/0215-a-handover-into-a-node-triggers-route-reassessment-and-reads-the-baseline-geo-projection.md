# ADR-0215：交接进入节点时路由复核——只对`已交接`且声明了接收节点的交接复核、位置取接收节点；受理后不由小包托运信封触发的复核，经消费侧适配器读受理基线那一版提交的地理投影

Status: Accepted（2026-10-19，Claude Code 会话代决：用户原话「你作为业务和系统专家自决……解决所有的问题」；票 [demo-chain-gaps/63](../../.scratch/demo-chain-gaps/issues/63-network-routing-reassesses-on-a-handover-into-a-node.md)，统一代决见 `.scratch/demo-chain-gaps/handover-dispatch-plan.md`「代决」C8、C9 与「需要的 ADR」ADR-0215。回答 [ADR-0213](./0213-a-transport-handover-declares-its-releasing-receiving-and-onward-nodes.md) 决定六「NR 交接触发的路由复核怎样取实际位置」。部分停用 [ADR-0075](./0075-customer-address-is-carried-with-the-routing-request.md) 决定一，适用场景只限受理之后、不由小包托运信封触发的复核，见 Consequences。越权风险点见文末，待 NR owner 复核，PS owner 会签。）
Date: 2026-10-19

## Context

- 权威运输交接登记之后，交接信封只投追踪投影与派送发起两路，网络与路由收不到。NR CONTEXT 认可的「当前可控节点」依据只有两种：节点收寄结果，或运输履约的权威运输交接结果。后一种此前只经小包托运的场外揽收采用进来；节点或承运方之间的交接从没到过路由。
- [ADR-0213](./0213-a-transport-handover-declares-its-releasing-receiving-and-onward-nodes.md) 让交接声明交出、接收、去向三个节点，决定六把「NR 复核怎样取位置」留给本记录。
- 复核要问关务适用性，得知道寄、收两端的国家与邮编。复核编排的携带内容（`ReassessRouteCommand.Carried`）空着时，关务只能答两端未知，复核停在看不清（`PLAN_REVIEW_INCONCLUSIVE`）。这正是票 routing-first-cut/21 修过的那个停点。
- [ADR-0075](./0075-customer-address-is-carried-with-the-routing-request.md) 决定一定下：地址随判断请求在请求期携带，`network-routing` 不建立读取 `parcel-shipment` 地址的端口。判据是同版性：判断对象是委托当前提交版本，NR 另行回读会在请求与回读之间留下异版窗口。接受决定与收寄采用两封信封都照此携带投影。交接信封由运输履约交出，运输履约不拥有也不读客户地址，带不了投影。
- 路由判断键钉在受理基线上，基线引用就是基线的提交版本标识。基线一经固定不再改写。

## Decision

**一、只对`已交接`且声明了接收节点的交接复核。**

- 网络与路由消费权威交接登记信封，按键读回那一版交接。
- 裁决是`已交接`、声明了接收节点、对象是当前已接受包裹，三者同时成立，才形成复核触发：
  - 控制依据：权威运输交接；
  - 位置：接收节点；
  - 来源版本：交接的结果版本；
  - 业务时间：交接的判断时刻。
- 其余一律入账，不复核：
  - 拒收与待确认：控制没有转移；
  - `已交接`而没声明接收节点：交给运输方之类，之后没有可控节点，位置无从取；
  - 对象不是当前已接受包裹：没有当前已接受委托声明它，或声明它的委托在受理基线里没有它，集运单元号也落这一格。

**二、受理后、不由小包托运信封触发的复核，所携地理投影由消费侧适配器读取。**

- 适配器按（租户，包裹）反查当前已接受委托，读委托聚合，取受理基线那一版提交的地理投影。
- 只取用地理维：寄、收两端的国家与邮编，与接受决定、收寄采用两封信封所携的是同一份投影。委托聚合按小包托运的读法整份读回，地址本体与身份内容不取用、不落库，投影本体也不落库。
- 投影照旧进复核的触发指纹，依据照 ADR-0075 决定三以摘要留痕。
- 判断键的基线引用取基线的提交版本标识，与初始路由、收寄复核同源。
- 适配器只用小包托运已有的两个读法：按包裹反查当前已接受委托，按来源身份读委托聚合。小包托运不为此新开端口。

**三、一版交接一个触发。**

- 关联以 `handover/` 起头，后接租户、对象、范围、版本四维，每维写成「字节长度:原串」。对象、范围、版本都是登记方给的串，可能含斜杠，直拼会让两次不同的交接撞成同一个关联。
- 同一版交接再投，答已有结果。
- 同一个关联带来另一份内容（例如委托换了受理基线之后再投），答触发冲突，入账，原触发与原结果不被覆盖。
- 更正之后仍是`已交接`：新版本承继接收节点，另成一次复核，原复核不被覆盖。依据是 UC-NR-003「来源更正或当前实测变化形成新复核，不覆盖原判断」。
- 更正成拒收或待确认：入账，不复核，也不回退已有的复核。

**四、停与走。**

- 重投：交接还读不回或登记册读不动、小包托运读不动、复核停在未决（复核登记册或路由历史读不回、证据未配置、适用性看不清、取号依赖故障）。各登本路自己的未决哨兵。
- 响亮失败：
  - 读回的交接与键不符；
  - 已接受委托自相矛盾（没有受理基线、基线那一版找不到、反查与聚合指着两份委托）；
  - 反查歧义：两份已接受委托声明同一件包裹（ADR-0060）；
  - 本适配器组出的触发过不了复核的门；
  - 服务目的未配置。

**五、派发。**

- 派发进程把权威交接登记信封另投一路给网络与路由，排在派送发起之后。本路有自己的 inbox 消费者名与未决哨兵名单。
- 复核编排的生产接法只有一份，收寄采用与交接两种触发共用：复核的是同一份路由判断，证据、自动改路事实与判断库各册的接法不该两处各写一份。

## Alternatives considered

- **每次交接都复核。** 否决：NR CONTEXT 只认节点收寄或权威交接确认的控制节点。交给运输方之后没有可控节点，位置无从取；拒收与待确认没有转移控制。
- **位置取交出节点或去向节点。** 否决：交出节点是控制结束的地方，去向是意图。取得控制的是接收节点。
- **让交接信封携带投影。** 否决：运输履约不拥有、也不读客户地址。让它读来再转交，等于把读地址的口挪进另一个上下文，暴露面更大。
- **取当前提交版本的投影。** 否决：判断键钉在受理基线上，取当前版会让复核所用的地理与判断对象异版，那正是 ADR-0075 要防的。受理后的地址修订另有去处，见越权风险点 5。
- **复核不带投影。** 否决：复核问关务只能答两端未知，复核停在看不清，演示会停在 routing-first-cut/21 修过的同一个停点。
- **网络与路由在初始路由时留存一份投影，复核时自取。** 否决：CONTEXT 硬句只许保存摘要；留存投影本体就是第二份地址存储，ADR-0075 Alternatives 第三条已否。
- **小包托运新开一个「受理基线地理投影」端口。** 暂不做：现有两个读法答得出，开新端口要小包托运 owner 立项。owner 若要收窄网络与路由能读到的面，可以改由那个端口只交投影，适配器只换一个协作者。

## Consequences

- 网络与路由：
  - 新 inbox 消费者 `network-routing/reassess-on-transport-handover`；
  - 消费侧适配器两个：`adapters/transportfulfillment` 的交接触发复核，`adapters/parcelshipment` 的 `AcceptedCarriedGeoSource`；
  - 复核编排与复核结论封闭集都不变。
- parcel-dispatch：交接登记那一行的 FanOut 加网络与路由一路，带本路未决哨兵名单；复核编排的生产接法收寄与交接两路共用。
- **部分停用 ADR-0075 决定一。**
  - 被停条款：决定一「`network-routing` 不建立读取 `parcel-shipment` 地址的端口」。
  - 适用场景：仅限受理之后、不由小包托运信封触发的路由复核，今天只有交接进入节点这一种。网络与路由经消费侧适配器读受理基线那一版提交的地理投影，只到地理维。
  - 停用理由的前提：受理基线一经固定不再改写，读回的那一版与判断键上的基线是同一版，ADR-0075 防的「判断对象与判断输入异版」在这里不存在。前提不成立的场合照旧随请求携带：可达性判断、初始路由、收寄采用触发的复核都是。
  - ADR-0075 决定二（地理维过界、身份维不过界）、决定三（依据以摘要留痕、地址本体不落网络与路由），以及决定一的其余部分，都不变。
- CONTEXT-MAP 的 `parcel-shipment → network-routing` 与 `node-operations / transport-fulfillment → network-routing` 两条边各补一句；网络与路由 CONTEXT 补一句；UC-NR-003 的触发、输入契约与验收表补 `AT-NR-064`–`069`。
- 路由复核册不列触发的控制依据与位置。要看一条复核发生在哪个节点，只能顺关联回到交接册看接收节点，另立票 [84](../../.scratch/demo-chain-gaps/issues/84-route-reassessment-register-shows-the-trigger-control-and-location.md)。
- **网络与路由一路停在未决时，整封交接信封占着分区头。** 交接信封的分区键是（租户 + 载运对象 + 类型段），见 [ADR-0074](./0074-tf-object-partitions-carry-a-port-segment-apart-from-ve-parcel-partitions.md)。扇出里任一路停在未决，整封信封都要重投，同一对象之后的交接信封排在它后面，追踪投影与派送发起都跟着推迟，最长到本路重投预算耗尽。未决的原因里有证据未配置、冻结形态未配置这类租户取值缺口，它们在预算之内不会自愈。代价与缓解见越权风险点 10。

## 越权风险点

1. **网络与路由首次从小包托运的委托聚合取地理维**（NR、PS owner）。此前只有初始路由经同一个读法读聚合，取受理基线与接受决定；从聚合里取地理投影、按包裹反查当前已接受委托都是新的，前者部分停用 ADR-0075 决定一。小包托运的委托仓储多了一个跨上下文读者，聚合或反查口改形时要顾及它。缓解：只读、只取受理基线那一版、只取地理维；owner 若要收窄，改走 Alternatives「小包托运新开一个『受理基线地理投影』端口」那条的专用端口。
2. **外包段内部的异常不触发复核**（NR owner）。交给运输方之后，直到下一次交进节点之前都没有复核；外包段内部的延误或改道只能经别的信号进来。
3. **集运单元不逐成员复核**（NR、NO owner）。对象是集运单元时入账，成员的路由此刻不复核。逐成员复核随集运单元交接的后继票。
4. **接收节点声明错了，就按错误的位置复核**（TF、NR owner）。与 ADR-0213 越权风险点 1 同源：网络与路由不核节点目录。拼错的节点不在计划上，原计划会按「实际节点与计划不符」失效。owner 若要挡，可以在复核前查节点在目录中在册，不在册时入账或记未决。
5. **受理后的地址修订不进交接复核**（NR、PS owner）。取的是受理基线那一版。受理之后经资料修订采用的新收件地址不在其中：交付地点的修订走小包托运的修订链与派送要求缝（ADR-0130），路由要等小包托运那一侧发起重判。
6. **更正之后仍`已交接`，会再复核一次**（NR owner）。更正只改判断、不改节点，于是同一位置多一条复核行。结论通常相同，复核册的行数随更正增长。
7. **撤回控制的更正不回退复核**（NR、TF owner）。交接被更正成拒收或待确认时，基于原版的复核结论照留，包括失效与改路。这与 TF CONTEXT「不直接回退」同一立场，处置面没有立。
8. **复核册看不出触发位置**（NR owner）。见 Consequences「路由复核册不列触发的控制依据与位置」那条与票 84。
9. **没有路由历史的已接受包裹会重投到预算耗尽**（NR owner）。从未形成初始路由判断的包裹，复核答未决，信封按派发预算重投之后弃置。收寄触发的复核也这样停，但两路堵住的分区不同，影响面见第 10 条。
10. **本路未决会推迟同一对象后续交接的追踪投影与派送发起**（NR、TF、VE owner）。见 Consequences「网络与路由一路停在未决时，整封交接信封占着分区头」那条。收寄触发的复核停在小包托运的分区上，牵连的是小包托运自己的信封；交接触发的复核停在运输履约每个对象的交接分区上，牵连同一封信里的追踪投影与派送发起，以及同一对象之后的每一封交接信封。[ADR-0074](./0074-tf-object-partitions-carry-a-port-segment-apart-from-ve-parcel-partitions.md) 加类型段，本来就是为了不让一封停住的交接堵住追踪投影；本记录在交接信封内部重新引入了这种牵连。[ADR-0216](./0216-delivery-dispatch-is-triggered-in-process-from-the-handover-envelope-per-object.md) 说派送发起在「下一拍」形成，这一路停住时，下一拍会推迟到本路重投预算耗尽为止。今天照样重投，理由是未决在可见性滞后与依赖故障时会自愈，而复核登记册没有「未决复核」这一行可落，入账就等于丢掉这次复核。owner 可选的缓解：
    - 未配置类未决（证据未配置、冻结形态未配置、没有路由历史）改为入账，同时记一条未决复核，不再重投。前提是复核登记册能存未决行，并有配置补齐之后的重判入口。
    - 把网络与路由一路从交接信封的扇出里拆出去，例如运输履约另发一封独立分区的信封。代价是交接登记多一封信封，多一次指纹与分区门禁的登记。
11. **两种触发分属不同分区，复核不按业务时间排序**（NR owner）。收寄采用触发的复核走小包托运的分区，交接触发的复核走运输履约的分区，谁先到网络与路由谁先处理。复核编排只拿当前路由历史判断，不比较各次触发的业务时间。例如收寄那一路重投期间被之后的交接超过，较早的位置会在较新的复核之后再判一次，并可能据此失效或改路。UC-NR-003「一致性、幂等与并发」与 NR CONTEXT 要求按业务时间裁决、不按消息到达顺序，这里没有做到。今天两次触发通常相隔数小时，较少遇到。按业务时间排序（例如复核前比较触发与当前历史的业务时间，较早的触发只入账）留给后继票。

# ADR-0046: 候选评估规则归 network-routing 领域，证据端口退为取数

Status: Accepted  
Date: 2026-08-12

## Context

`UC-NR-002` 步骤 5–7（服务区域解析、日历/截单与硬约束逐项评估）与证据判定矩阵行 5/6/7
把候选评估写成了明确的业务规则：区域**明确不覆盖**是带依据的淘汰而不是资料不足；地址缺
业务信息是**资料不足且禁用默认区域**，并要求给出「缺少内容和再次判断条件」；网络版本缺失
或损坏是`未形成判断`而不是资料不足；客户偏好只有被产品或合同**承诺**才成为约束
（`AT-NR-018/023/026/031`）。

今天这一整层评估压在 `NetworkEvidenceView.AssembleCandidates` 一个端口方法后面，仓内唯一
实现是测试替身——评估规则本体在生产代码里**不存在**（UC-NR-002 盘点钉过的「评估层洞」，
一洞三显形）。规则写在端口后面就落到了适配器手里，而 ADR-0025 定死适配器只翻译不判断；
`未形成判断`的原因分类也只剩一格 `NETWORK_EVIDENCE_UNAVAILABLE`，用例要求的「按技术或
依赖阶段分类」无从谈起。

## Decision

**候选评估规则落 `networkrouting/domain`，证据端口退为取回版本化网络事实。**

1. **领域拥有评估矩阵。** 输入是版本化网络事实（服务区域解析结果、日历与截单、硬约束、
   承诺声明），输出仍是既有的 `RouteCandidate` 与 `EvidenceGap`；`ConcludeReachability`
   保持末端三值矩阵不变。规则举证：区域明确不覆盖→带 `SERVICE_AREA_EXCLUDES_DESTINATION`
   类稳定依据的淘汰；地址缺业务信息→`资料不足`缺口并携带再次判断条件；偏好不在承诺集合
   内→不参与淘汰也不制造可达。
2. **端口从「装配已评估候选」退为「取回网络事实」。** 取数答不出仍是 error（应用层译
   `未形成判断`）；事实的取值属实例半边（真实区域表/日历/截单/线路，`PAR-NET-*` 全部
   待提供），机制先以合成事实钉住规则。
3. **`未形成判断`按评估阶段分格。** 现有一格拆为「事实取不回」与既有各格并列的评估期
   新格（按实现落地时的真实阶段命名），续办引用随原因派生的既有纪律不变。
4. **「再次判断条件」成为`资料不足`结果的一部分。** 判断内容节点名要求它；没有它，
   `资料不足`是一句没有出口的否定。
5. **分增量落地。** 每个增量独立可验：区域解析规则先行（矩阵行 5/6 与 `AT-NR-018/023`），
   随后承诺/偏好分界（`AT-NR-026`）、日历截单与硬约束逐项评估（`AT-NR-031` 关务半边随
   CC 上下文另计）。端口签名在第一个增量一并改，不留两套并行。

## Consequences

- `evidenceDouble` 与八条应用用例随第一个增量改造（盘点已列清单）；`ConcludeReachability`
  与 domain 两个测试文件不受影响；PS 侧经自己的端口消费，外形稳定即不受影响。
- 评估规则进领域后受 `internal/architecture` 三道门禁管辖（boundaries/enum 穷尽/重建门）。
- 本记录不动闸门：评估层纯机制，postgres/Outbox 不在其中（ADR-0017/0026 边界不变）。
- 真实区域/日历/截单/线路仍属实例半边：机制用合成事实钉规则，不以行业默认值填入任何
  国家、区域、线路、节点、时间（UC 生产参数节的硬句）。

## Alternatives considered

- **评估留在端口后（现状）。** 否决：规则本体永远无处落地，适配器要么违反 ADR-0025 替
  领域判断，要么规则只存在于每个测试替身的想象里。
- **评估做成独立应用服务而非领域函数。** 否决：矩阵行 5/6/7 是业务不变量（何为淘汰、何为
  资料不足、默认区域为何被禁），放应用层会让它们绕过领域门禁且无法被聚合级用例复用。
- **等真实网络参数登记后一并做。** 否决：机制/实例分裂是本仓红线，评估规则不依赖任何一条
  真实线路——正如三值矩阵当年也是先以合成候选钉住的。

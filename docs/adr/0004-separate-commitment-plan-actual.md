# ADR-0004: 分离客户承诺、计划旅程与实际事实

Status: Accepted
Date: 2026-07-29

## Context

国际小包履约过程中，客户承诺、网络计划和实际发生情况会在不同时间形成并分别变化。若使用一组可覆盖的时间、路线或状态同时表达三者，计划调整和迟到事实会改写当时承诺，系统也无法解释服务是否真正达成。

## Decision

客户承诺、计划旅程和实际事实分别表达、分别拥有历史，任何一层不得静默覆盖其他层。客户承诺采用两个显式且可追溯的形成阶段；每个阶段的形成条件和适用范围由领域模型定义，后阶段生效时仍保留前阶段承诺及其依据。

计划旅程表达当前准备如何履约，实际事实表达已经发生什么；两者均不得反向改写适用的客户承诺。

## Consequences

- 系统可以同时解释当时向客户承诺什么、后来计划如何执行以及实际发生什么。
- 计划变化和预测更新不能消除原有承诺偏差，履约判断必须引用明确的承诺阶段和实际事实。
- 产品界面、查询和报表必须清楚区分承诺、计划、预测和实际，不能只展示一个无语义的时间或状态。
- 分层和保留历史会增加数据关联、版本解释和业务培训成本。

## Alternatives considered

- **使用单一可变时间线**：实现简单，但计划或实际更新会覆盖承诺依据。
- **把当前计划视为客户承诺**：便于调度，却会使内部运营调整不当改变客户权利和服务评价基准。
- **实际事实发生后回写计划和承诺**：可以得到整齐的最终数据，但失去偏差、责任和过程审计能力。

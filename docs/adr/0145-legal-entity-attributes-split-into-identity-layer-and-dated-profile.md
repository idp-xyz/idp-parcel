# ADR-0145：责任法人的业务属性分身份与资料两层——注册国家 / 地区与终身注册号随身份登记、不作变更（录错走更正修订）；注册地址、税务登记号、开票资料与联系人归按生效时点修订的「法人资料」，对外单据开立时固定其修订引用；币种不上法人；登记只拦身份层，开票资料缺失由开立方拒开

## Context

**问题。** 责任法人册今天只登「谁」：法人标识、种类、参与方身份（名称从参与方册转写）、状态、修订、依据、生效与停用。它说不出这个法人在哪注册、以什么号纳税与开票、找谁联系。ADR-0003 把法人定为「合同责任、税务和账务边界」，账上也已经按责任法人归集（结算账户按责任法人、相对方、方向、币种与结算政策分），法人册上却没有开票要印的任何一格。首发 CN→SG 的对账单、发票与申报都要这些。

**CONTEXT 里已有的三条，决定了这次怎么切。**

- 身份登记按修订版本化、不可覆盖，「名称等内容更正形成新的登记修订」——更正已有机制。
- 预付或账期方式、结算账户都按「责任法人、相对方、合同、费用范围、币种」解析——币种已有权威，在结算政策。
- 停用不删除身份，「既有关系、账户、合同和快照继续引用原身份」——下游按引用固定历史。

## 候选与反方

**甲 · 全部属性并进身份登记，改一格翻一版身份。** 反方：身份的生命周期是生效 / 停用，资料按自己的节奏变——每改一次地址就翻一版身份，身份修订史里混满与「是谁」无关的变更，按身份修订引用的地方也会被资料变化牵动。否决。

**乙 · 全部属性另立资料链，身份上什么都不加。** 反方：注册国家与终身注册号定义的正是「这是哪一个法人」——没有它们，两个同名法人在册上无从区分，号变了还是不是同一个法人也说不清。否决（资料链保留，见决定三）。

**丙 · 采外来方案的「主体主档 + 按票绑定角色」。** 反方：它把交易各方收成一个主档，要改参与方、客户账户与委托各方的领域语言，而这里只要责任法人自己的资料；整体模型不采纳（定性见 `docs/README.md` 历史材料节）。否决。

**丁 · 身份层两格 + 资料链。** 即本记录。

## Decision

**一、身份层：注册国家 / 地区与终身注册号随责任法人身份登记。** 终身注册号指一个法人只有一个、不会换的注册号（如 UEN、统一社会信用代码），可按类型登记多个。登记时两格缺一拒登。注册号的类型与格式按注册国家 / 地区取自本上下文拥有的**注册号类型目录**；目录里没有该国家 / 地区的类型时拒登，不以默认格式代替。目录内容是实施时登记的配置，产品不带生产默认，演示种子只在合成租户下登记。目录的每个类型标明它属身份层（终身注册号）还是资料层（税务登记号），两层各只收自己那一类。

**二、两格不作变更，录错走更正。** 号变了就是另一个法人：停用旧身份、登记新身份。录错按既有「内容更正形成新的登记修订」处理，并携带更正依据——更正声明的是「它一直就是这个号」，不改写此前已开出的单据。票面裁决写的是「录错也走停用 + 重登」：那会让已挂在错号法人上的合同与快照悬空，而 CONTEXT 已有更正机制，不必另开一条路。

**三、资料层：「法人资料」按生效时点修订。** 内容为注册地址、税务登记号（可后办、可变的那类，如 GST / VAT 登记号）、开票资料与联系人。开票资料首版只含开票抬头（开票用的法人名称，可以是与参与方名称不同的语言版本）；其余开票项随开立方的实施票按需增列，不预设。修订按生效时点形成、不可覆盖，新修订自其生效时点起取代前一修订，可以登记未来生效的修订。注册地址的国家 / 地区必须与身份上的注册国家 / 地区一致。

**四、币种不上法人。** 结算币种由结算政策按责任法人、相对方、合同与费用范围解析（CONTEXT 既有），一个法人对不同客户可以用不同币种结算；在法人资料上再挂一格「结算币种」，就是同一件事的第二个权威。票面裁决把结算币种列进了资料层，本记录收回。若将来记账需要「法人的记账本位币」，那是另一件事，另议。

**五、对外单据按开立时点固定资料引用。** 对账单、发票等对外单据开立时，按开立时点解析当时有效的法人资料修订，并在单据上固定该修订的引用；此后资料再改——包括追溯生效的修订——不改写已开单据。固定引用而不是「事后按时点重读」：追溯生效的修订会让重读的答案变，而已经开出去的单据不能跟着变。

**六、登记时只拦身份层；开票资料在开立时拦。** 登记责任法人不要求法人资料——法人可以先登记、后补资料。开立时点没有有效的开票资料，本上下文对「按时点解析法人资料」答**资料不全**（明确非成功），不以默认值补齐；开立方据此拒绝开立。联系人可空。

**七、敏感实例外置照旧。** 真实注册号与税务登记号属租户实例数据，只进租户自己的库；产品仓库里的种子、夹具与文档只出 `SYN-` 合成值。

## Consequences

- party-commercial `CONTEXT.md` 已按本记录修订：Language「责任法人」补身份层两格、新增「法人资料」；Rules 增身份层登记、法人资料修订与开立时固定引用诸句；Lifecycles 增「法人资料」一节；Boundaries 拥有清单补注册号类型目录与法人资料。GLOSSARY 增「法人资料」。
- 实施拆在 `.scratch/legal-entity-profile/`：注册号类型目录、身份登记加两格、法人资料修订链与按时点解析、管理台表单与资料页。
- settlement-accounting 开立对账单与发票时固定法人资料引用、见「资料不全」拒开，要在 SA 的 `CONTEXT.md` 与开立用例里落一句——归 SA owner，随 SA 开立单据的实施票做（ADR-0143 仍为 Proposed）。
- customs-compliance 的申报主体资料是否取自法人资料、取哪几格，归 CC owner；本记录只保证法人资料能按时点解析。

## 越权风险点

1. **终身注册号「不作变更」**：个别法域的注册号在改制、迁址时会换号，本记录一律当作另一个法人。若某国家 / 地区的实践并非如此，应在注册号类型目录上把那类号标为资料层——归 PC owner 复核。
2. **注册号类型目录不带产品默认**：连首发 CN / SG 的类型也要在实施时登记。这些是公开格式，是否该作为产品随附的参考数据，归 PC owner 复核。
3. **注册地址国家须与注册国家一致**：跨境设立的分支机构可能不满足；本记录只管责任法人本身，不管分支。
4. **「开立方据此拒开」**落在 SA 与其他开立方的行为上；本记录只定 PC 的「资料不全」答复，开立方的门由各自 owner 在其 CONTEXT 里落。
5. **开票资料首版只有开票抬头**：收款账户、开票语言等是否属法人资料，本记录不裁——收款账户与结算账户（SA 拥有）的关系尤其要先理清。

# ADR-0024: 方向性作业的依据随对象下发并携带有效区间，出区间等同无有效依据

Status: Accepted  
Date: 2026-08-11

## Context

[`node-operations`](../domain/node-operations/CONTEXT.md) 已经画过一条线：

> 当前路由指令无效、缺失或已经被替代时，节点仍可执行接收、隔离、状况记录、测量和其他必要安全作业；分拣到下一方向、集包出运、装载和交出等方向性作业必须暂停，直至取得有效依据。

[扫描屏简报](../design/frontline-scan-offline-and-conflict-decision-brief.md)据此推出：**离线是「取不到有效依据」的一种原因，不是一类新情况**，因此离线可做的动作集合与这条规则允许的集合重合。这一条让 [ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md) 要求的离线容忍不必新造一套权限模型。

**但断网只是极端情形，弱网才是常态。** 现场更常见的是：依据取到过，现在问不到了——**它还算不算数**。规则原文说「直至取得有效依据」，没说已经取得的依据什么时候失效。

这个问题不能留给客户端猜，更不能用传输层指标回答。用「上次成功请求距今多久」「心跳还在不在」「连通性探测通不通」来决定操作员能不能出运，等于**让网络质量决定业务能不能做**。两者本来无关：网络好而治理已暂停时它会照旧放行，网络差而依据完全有效时它会无谓卡住整条线。

难逆转的地方在于**依据的下发形状**。它由 `network-routing`、`customs-compliance`、试点准入控制等多个上下文分别给出；一旦它们按「只给结论」的形状发出去，作业端就永远拿不到判断新鲜度所需的信息，而补这件事要同时改所有下发方。

## Decision

**方向性作业所依赖的依据，随对象下发时必须携带有效区间，不得只给结论。**

**作业端据本地时钟判断当前是否仍在区间内。** 出区间即按「无有效依据」暂停方向性作业，与断网同一处理——这不是新增一种暂停，是把 `CONTEXT.md` 已有的那一种套到一个新原因上。

**依据过期与网络不通是两件事：前者决定能不能做，后者只决定要不要入队。** 依据有效而网络不通时，方向性作业照做，产生的事实入本地队列；依据已过期时，即使网络通畅也暂停，因为「通」不等于「有依据」。

**不得以连通性替代有效区间判断。** 心跳、上次成功通信时长、连通性探测都不是依据新鲜度的证据。

**安全作业不受本记录约束。** 接收、隔离、状况记录、测量在任何情况下继续，`CONTEXT.md` 已经这样规定。

**本记录不定任何区间长度。** 真实时长由各下发上下文按其治理规则给出，属实例半边，不得内置默认值。

## Consequences

- **每个下发依据的上下文都要给出有效区间，而不只是结论。** 这是本决定的主要成本，且它落在多个上下文上，不是一处。
- **设备本地时钟因此参与门禁判断**，[ADR-0023](./0023-work-fact-identity-and-time-are-minted-by-the-device.md) 保留的时钟偏移在这里起作用。偏移会让设备过早或过晚暂停：**过早暂停是安全方向，过晚不是**——晚暂停意味着依据已经失效而包裹还在往外走。因此偏移超出容忍时应当保守暂停，宁可停错不可放错。
- **形状不是新的。** 生产归属决定已经携带 `OwnershipValidityInterval`，未来建单门禁用 `Validity().Contains(evaluatedAt)` 判断、过期即 `DECISION_STALE`（`internal/parcelshipment/domain/production_ownership.go`）。本记录把同一形状推广到下发给作业端的依据，不引入新机制。
- **弱网不再需要单独的判定分支。** 断网、弱网、通畅三种网络状态在业务上收敛为同一个问题：手上这份依据还在区间内吗。
- 新增一项判断成本：每加一类下发依据都要问它约束的是方向性作业还是安全作业。判错的方向是把安全作业也挂上区间，那会让一次过期把接收和测量一起停掉，而那正是 `CONTEXT.md` 要求必须继续的部分。
- 本记录不解除任何闸门，也不承诺任何下发端点被实现。

## Alternatives considered

- **用心跳或连通性判断依据是否仍然可信。** 否决：让网络质量决定业务能不能做。网络好而治理已暂停时会照旧放行——那是最危险的一种错，因为它看起来一切正常。
- **依据永不过期，只在联网时刷新。** 否决：治理暂停、路由失效、关务限制都可能在断网期间发生，而设备会照旧分拣出运。等重连时货已经在车上了，`CONTEXT.md` 要求的「已经发生的事实继续保留、不得回退为未发生」意味着这错误撤不回来。
- **断网即全部暂停，含安全作业。** 否决：直接违反 `CONTEXT.md`——接收、隔离、状况记录、测量必须能继续。且它把一次网络抖动变成整条线停摆，正是 ADR-0021「工位作业不会因为网络抖动而停」要挡住的。
- **由服务端在依据失效时推送通知。** 否决：断网时推不到，而那正是最需要它的时候。它可以作为区间之外的加速手段，但不能作为判据。
- **让作业端每次方向性作业前同步问一次服务端。** 否决：这等于取消离线容忍。且它在弱网下会把每一件包裹的处理时间挂在一次网络往返上。
- **区间由作业端本地配置，不随依据下发。** 否决：新鲜度要求属于给出依据的那个上下文的治理规则，配在端上等于让端替治理决定依据能用多久，且多个端会各配一套。

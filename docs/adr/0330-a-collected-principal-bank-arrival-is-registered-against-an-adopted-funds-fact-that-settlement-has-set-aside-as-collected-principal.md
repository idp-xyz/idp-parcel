# ADR-0330：一条银行回款整条认作代收本金之后只有代收与清分一个去处；运营企业真实到账凭这样的已采用事实登记，按此刻链头核币种、金额之和与每指令至多一条，移位前再核，被结算更正得容不下时不放行

## Context

- [ADR-0274](./0274-collected-principal-bank-arrival-enters-through-the-settlement-accounting-funds-adoption.md) 把运营企业真实到账接到 settlement-accounting 的唯一采用口上：代收与清分登记真实到账时，证据引用必须指向一条已采用的外部资金事实，按引用读回、核币种、核金额之和。它自己留了两个空：结算一侧怎样处置被引用的那部分没有裁（越权风险点 2），只在登记时读一次、不跟随结算一侧的更正（越权风险点 4）。
- 留着的空是资金上的洞，不只是文档上的空。一条银行回款在结算里是一条已采用事实；在被代收与清分引用为真实到账之后，结算一侧什么都不知道：运营可以把同一条事实映射到某张客户对账单或应收结算账户。只落到一个作用域的收款，没核销的部分整条记入那个作用域的入账余额（[ADR-0283](./0283-a-funds-fact-mapped-into-several-customer-scopes-is-posted-by-its-applications.md) 决定二，`r` 取事实金额减全部未撤销核销）。于是同一笔 1000.00 的银行回款，在运营余额里记一次、在代收分户账的`待清分`里再记一次，两边各自守恒、合起来重记 1000.00，只能靠线下对账发现——ADR-0274 否决「限定 ADR-0137 决定四」时说的正是这一问。
- 反方向同样成立：事实先被认作 COD 本金、再被映射到客户收款，运营余额就把受托资金当成运营企业自己的钱，可付客户余额因此虚增。
- 结算一侧守不住这件事，因为它不知道代收与清分引用了什么；代收与清分一侧也守不住，因为它不能直读结算的表，更拦不住结算之后的映射。唯一站得住的地方是把「这条事实是代收本金」记在结算一侧：结算是事实的拥有者，也是映射与核销的拥有者，认作与映射互斥只能由它在同一把锁下判。
- 事实可以被外部更正（[ADR-0285](./0285-an-external-correction-is-adopted-says-how-far-it-over-applies-and-reposts-every-scope-the-fact-reaches.md)：更正照采，不拒）。登记时撑得住的到账，之后事实被更正小了，到账之和就超过了钱；如果只在登记时核，移位记账会把银行没有交付的本金推进`待清分`。
- 并发：登记是「读名下已有到账、判合计、落册」，两路并发引用同一条事实的到账各自读到同一份已有到账，各自判够，落下去合计就超过事实金额；读到的金额也可能在落册之前被结算一侧的更正改掉。
- COD 首发不在试点范围内，今天只有演示租户经受控 CLI 登记；机制在真渠道接上之前补齐。

## Decision

**一、结算一侧：一条银行回款可以整条认作代收本金，之后只有代收与清分一个去处。**（机制）

- UC-SA-005 的资金映射目标多一格`代收本金`（`COLLECTED_PRINCIPAL`）。认作的是**一条确认到账的外部资金事实整条**：目标引用就是这条事实自己，不按金额分；资金退回与付款失败的事实不认作（退回是钱离开，认作就把一笔退回记成又一笔本金）。认作要有显式依据，同别的映射（金额相同、同一客户、同一时间都不单独证明）。
- 它回答「这条回款属于谁」，**不是核销的对象**：认作之后没有可分配的结算目标，核销指向它一律未受理；它不形成应收应付，不进任何客户应收作用域的入账余额（SA CONTEXT「COD 代收本金不进」由此有了结构：认作的事实没有落到任何作用域，对入账余额的记入为 0），累计未分配保持事实全额，在读面上看得见。
- **互斥。**一条事实认作代收本金之后不再接受任何别的映射（对账单、账户、审核应付、贷项、客户赔付、追偿认可都不行）；已有任何别的映射的事实也不再能认作代收本金；第二条认作映射同样不收——认作是事实一级的状态，不是可叠加的金额。冲突答映射冲突（`MAPPING_CONFLICT`，结算既有的一格，不增结果格）。判定在事实身份行的锁下读回该事实上全部已有映射再做，所以映射先到、认作先到、两路并发，都恰好一路成立；库上唯一索引兜住绕过锁的第二条认作。映射到任何目标因此都先取事实锁，不再只有映到对账单或账户的才取。
- **认作不可撤。**映射本是只增不改，没有撤销形；这是有意的——代收与清分一旦按这条事实登记了到账，撤销认作就会让已登记的到账失去依据，而结算看不见那边。认错了怎么办见越权风险点 1。
- **外部更正照采**（ADR-0285）对认作的事实同样成立：新版本照落、信封照出；没有核销可言，不报超核，没有作用域可重算。被更正后的链头金额，就是代收与清分此后判据读的金额。

**二、代收与清分一侧：运营企业真实到账的证据引用就是这样一条事实的引用。**（机制）

- 证据引用指向一条结算已采用、且已整条认作代收本金的外部资金事实。没采用、采用了但没认作、别的租户的同一引用，对登记方是同一件事——先去结算采用并认作——所以同答依据不在册（[ADR-0029](./0029-retrieval-failure-algebra-is-partitioned-by-recovery-action.md)：恢复动作相同则同格）；结算读不动是未决，不折成依据不在册；读口没装配同样是未决。
- 读的是事实**此刻的链头**，不是某个固定版本：登记时读到的版本钉在到账上留痕（库里一列），但它不参与重放比对，也不是判金额的依据——判金额永远读此刻的链头。运营不给版本，少一个会填错的输入。
- 判据三条，缺一不登：**币种**——到账币种等于代收指令所属那本账的币种（受理门拒，先于读结算：币种对不上是请求本身的错，不该去占结算的共享锁），也等于事实的币种（不等同样受理门拒）；**每指令至多一条**——一条已采用事实对同一条代收指令至多支撑一条真实到账（一笔银行回款对一条指令只有一次到账；同一条指令的第二笔钱来自另一次回款，引用另一条事实），换事实标识再登是内容冲突；**合计**——引用同一条事实的各条到账金额之和（含这一条、不含重放时已在册的它自己）不超过链头金额，超出的那一条答内容冲突、不落册，不自动截断。
- **次序。**重放判定（按事实标识）→ 币种门 → 取本上下文按（租户，引用）的事务级事实锁 → 锁内再判一次重放 → 经结算只读口对事实身份行取共享锁并读链头与认作状态 → 读回此引用名下已有的全部到账 → 判三条 → 钉版本落册。重放判定必须先于一切按**此刻状态**作答的门：重放的真相是「这条到账已经登了」，答案只由在册记录定；反过来排，结算把事实更正小了之后，重放一条早已登记的到账会得到内容冲突，其处置指引对已登记的请求全是假话。合计与每指令的读回在取锁**之后**：等锁期间另一路到账提交了，这一路读到它。库上唯一索引（租户、证据引用、指令）兜住绕过锁的第二条。

**三、移位之前再核一次。**（机制）

- 凭运营企业真实到账把`渠道在途`移到`待清分`，是本金第一次被当成运营企业真正收到。这一步在重放判定与取分户账锁之后、按指令的上限与余额守卫之前，再读一次它引用的事实：名下全部到账的金额之和仍不超过此刻链头金额才放行。事实被更正得容不下既有到账时答内容冲突，账面不动——它是这条到账的依据变了，不是账上钱不够，所以不答余额不足，也不被余额不足盖住。
- 没有钉版本的到账（按旧口径登记的存量，证据引用是任意字符串）与结算一侧读不到的事实答依据不在册；结算读不动、读口没装配答未决。已落的移位重放仍答已在册（重放先于这道门）；冲正已落的移位不读结算——撤回本金不需要事实撑着，且更正后的事实正是要靠冲正退回的。
- 读结算对事实身份行取共享锁，与结算一侧更正、映射、核销取的 `FOR UPDATE` 互斥：移位判过「撑得住」之后、提交之前，更正落不进来；更正排在提交之后，下一次读才看见新金额。登记同理。

**四、重复到达、换引用重登、迟到、被结算更正，各是什么答案。**（机制）

- **重复到达。**同事实标识、同内容，答已在册，合计不翻倍；先于所有按此刻状态作答的门，所以事实此后被更正小了、被读不到，重放也答已在册。同标识异内容答内容冲突，不覆盖。并发两路同一份：先到的登记，后到的在锁后读到先到那条，答已在册而不是内容冲突——同一条到账的重放不能被「同一指令已有到账」的门当成第二条。
- **换事实标识再登同一指令。**不论金额是否相同，答内容冲突（每指令至多一条）；库上唯一索引兜住并发的第二条。
- **换引用重登。**同一份到账改引用另一条已采用事实，是另一条到账的登记：另一条事实若也认作代收本金且容得下就登得进。代收与清分不推导两条事实是否是同一笔银行回款——事实引用是外部系统自己的事实身份，同一笔银行回款在结算里只有一个引用，同一引用重复采用只采用一次（ADR-0137 决定四，AT-SA-119）；银行回款被不同引用各采用一次是结算采用口的来源身份问题（越权风险点 3）。即便如此同一指令也不会移位两次：移位上限按指令算，第二条到账会撞余额不足（ADR-0271 决定二）。
- **迟到。**到账早于结算采用或认作：答依据不在册（受控 CLI 退出码 2），什么都不落；采用并认作之后重跑同一命令即可，不需要改请求。到账晚于渠道报告、晚于短款：次序规则不变（ADR-0271 决定四：该指令有停在余额不足的到账时不判短款；ADR-0298 决定四：到账先于抵扣、抵扣先于短款，先落的短款先冲正）。
- **被结算更正。**上调：之后的登记与移位用新金额，已登记的不变。下调到仍容得下名下全部到账：无事。下调到容不下：新到账进不来（内容冲突）；未移位的到账移位答内容冲突；已落的移位**不自动冲正**，也不随更正驱动任何记账——撤哪一笔是人的判断，冲正走既有的反向记账（一笔记账至多冲正一次，ADR-0298 决定五）。事实与既有到账都是追加式、不可改，所以容不下的状态要等结算再更正回去或后继记录给出到账的更正形（越权风险点 4）才解开；它是安全的停——没有无来源的本金进入`待清分`。
- 以上每一格都不增结果格：已登记、已在册、内容冲突、依据不在册、未受理、未决，各消费方（受控 CLI 退出码、HTTP 译装）都已有落点。

**五、锁序。**（机制）

- 代收与清分登记：本上下文按（租户，引用）的事实锁 → 结算一侧事实身份行共享锁 → 读 → 写。代收与清分记账：分户账锁 → 结算一侧事实身份行共享锁。结算一侧：事实身份行 `FOR UPDATE` → 金额本体 → 运营余额作用域（ADR-0285）。结算从不回头等代收与清分的锁，代收与清分取了自己的锁之后只向结算要共享锁，两边接不成环。共享锁之间不互斥：几条到账同时引用同一条事实时，它们的先后由代收与清分自己的事实锁排。

## 手算

币种 CNY，金额以分计。

**例一：一笔 1000.00 的回款拆给两条指令，重放、重登与超额。**事实 `F` = 100000，已采用并整条认作代收本金；指令 I1（600.00）、I2（400.00）、I3（0.50）各有渠道报告入`渠道在途`。

| 步骤 | 引用 F 的到账合计 | 答案 |
|---|---:|---|
| 到账 A（I1，60000） | 0 → 60000 | 已登记 |
| A 重放 | 60000 | 已在册 |
| A′（I1，换事实标识，60000） | 60000 | 内容冲突（I1 已有 A） |
| 到账 B（I2，40000） | 60000 → 100000 | 已登记（100000 ≤ 100000） |
| 到账 C（I3，50） | 100000 | 内容冲突（100050 > 100000） |

A、B 各移位：`渠道在途` 100000 → 0，`待清分` 0 → 100000；入账 100000 = 账内各位置之和，`待清分` 合计 100000 = F，一分不多。

**例二：被结算更正下调，再更正回来。**同上，A 已移位：`渠道在途` 40000、`待清分` 60000；B（40000）已登记未移位。结算把 F 更正到 90000（照采）。

| 步骤 | 判 | 答案 | `渠道在途` / `待清分` |
|---|---|---|---|
| B 移位 | 名下到账 60000 + 40000 = 100000 > 90000 | 内容冲突 | 40000 / 60000 |
| A 的移位重放 | 重放先于这道门 | 已在册 | 40000 / 60000 |
| 新到账 D（I3，1） | 100001 > 90000 | 内容冲突 | 不变 |
| 冲正 A 的移位 | 冲正不读结算 | 已登记 | 100000 / 0 |
| B 移位（冲正之后） | 合计仍 100000 > 90000 | 内容冲突 | 100000 / 0 |
| 结算把 F 更正回 100000 后 B 移位 | 100000 ≤ 100000 | 已登记 | 60000 / 40000 |

每一行账内合计都等于入账 100000。第 4、5 行说明：冲正移位不能让合计回到事实之下——到账一旦登记就一直占着事实的额度，要靠结算再更正或到账的更正形（越权风险点 4）。

**例三：同一笔钱不能既是运营余额又是代收本金。**事实 `F` = 100000，客户对账单 `S` 已确认应收 100000，只落一个作用域。

| 顺序 | 步骤 | 答案 | 运营余额记入 | 代收分户账 |
|---|---|---|---:|---:|
| 先映射 | `F` → `S` | 已映射 | +100000 | — |
|  | `F` 认作代收本金 | 映射冲突 | 100000 | — |
|  | 到账引用 `F` | 依据不在册（没认作） | 100000 | 0 |
| 先认作 | `F` 认作代收本金 | 已映射 | 0 | — |
|  | `F` → `S` | 映射冲突 | 0 | — |
|  | 到账 A（60000）、B（40000）引用 `F` | 已登记 | 0 | `待清分` 100000 |

两种顺序下，这笔 100000 的银行回款都只在一处被记一次，合计 100000。没有这条互斥，先映射再引用会在运营余额记 100000、在`待清分`再记 100000，两边各自守恒、合起来 200000。

## 候选与反方

- **结算一侧保持未分配，另立对账口径**（票面第二种选择）。否决：未分配的事实仍可被映射到对账单或账户，只落一个作用域的收款没核销的部分整条进入账余额；「对账口径」只能靠人在事后核两本账，正是 ADR-0274 否决的那种线下发现。
- **部分认作：把代收本金做成核销目标，按金额消耗事实。**否决：核销是可撤销、可重分配的关系，而代收与清分已按引用登记了到账；结算撤销了认作的那部分，代收与清分的到账就失去依据，结算却看不见那边。整条认作、不可撤，引用方的读才始终成立；一条回款混着服务费与本金时在来源侧拆成两条事实（越权风险点 2）。
- **代收与清分自己记已引用金额，并写回结算。**否决：跨上下文写；ADR-0274 的边界是只引用、不读表，更不写。
- **结算的采用信封驱动代收与清分，自动转成真实到账。**否决，同 ADR-0274：信封不知道这笔钱属于哪条指令，按指令拆分是代收与清分的判断。
- **只在登记时读，不在移位前再读**（ADR-0274 越权风险点 4 的原状）。否决：登记与移位之间可以隔很久，事实被更正小了之后移位会把银行没交付的本金推进`待清分`，而那是 CONTEXT「未实际收到的代收款不得进入`待清分`」明令不给的权力。
- **事实被更正小了就自动冲正已移位的到账。**否决：同 ADR-0285 否决「更正自动撤销超出的核销」——撤哪一笔（后到的先撤、按金额、按指令）是人的判断；自动冲正等于借资金变化改账。
- **运营登记时给事实版本，代收与清分按版本读。**否决：多一个会填错的输入，且版本固定后判据仍得读链头；留痕靠钉版本就够。
- **登记只读不取锁。**否决：两路并发各读到同一份已有合计各自判够，落下去超额；读到的金额也挡不住落册之前的外部更正。
- **一条事实对一条指令可以支撑多条到账。**否决：同一份到账换事实标识重登，在合计未超额时无从与合法的第二笔区分；而一条指令的两笔钱来自两次回款，本就各引用各的事实。

## 对已接受记录的作用

- **部分停用（扩成）** ADR-0274 决定一「代收与清分不开第二个铸造或补录入口：它登记的「运营企业真实到账」那一层代收事实，证据引用必须指向一条 settlement-accounting 已采用的外部资金事实（采用版本）。」一句。**适用场景**：运营企业真实到账的证据引用除已采用外还须是已整条认作代收本金的事实，读到的是此刻链头、版本只是登记时钉下的留痕；不开第二个铸造或补录入口、人工核实与更正先在结算采用再被引用（该决定其余各句）不变。
- **部分停用（扩成）** ADR-0274 决定二「代收与清分登记真实到账时，按证据引用向 settlement-accounting 的只读口读那一版已采用事实：不在册答依据不在册，币种与代收指令不同答受理门拒。」一句。**适用场景**：读此刻链头；「不在册」含没采用、没认作代收本金；币种同时核事实与指令所属账；读口对事实身份行取共享锁。
- **部分停用（扩成）** ADR-0274 决定二「引用同一条已采用事实的各条真实到账，金额之和不得超过该事实金额；超出的那一条答内容冲突，不落册。」一句。**适用场景**：事实金额指此刻链头金额；另加一条事实对一条指令至多一条到账；同样的合计在移位记账之前再核一次。决定二其余各句（一条事实支撑多条按指令拆开的到账、拆分不改写结算的事实）、决定三与对已接受记录的作用不变。
- **回答（无条款停用）** ADR-0274 越权风险点 2「结算一侧怎样处置被引用的那部分没有裁」：见决定一，整条认作代收本金，之后只有代收与清分一个去处。
- **回答（扩成）** ADR-0274 越权风险点 4「登记时读一次，不跟随结算一侧的更正」：登记读链头钉版本，移位前再读一次；结算更正仍不自动冲正任何已登记或已移位的到账（决定四）。
- **部分停用（改为）** ADR-0283 决定四「映到别的目标的映射不取任何一把锁。」一句。**适用场景**：映射的目标不论是对账单、账户、审核应付、贷项、客户赔付、追偿认可、金额本体还是代收本金，都先取事实身份行的锁、在锁下读回该事实上全部已有映射再插入；映到对账单或账户的映射其后按（法人、账户、币种）键序取作用域咨询锁、核销与撤销的锁序、事实身份行在全序首位，该决定其余各句不变。
- ADR-0137 决定四、[ADR-0082](./0082-collection-subledger-is-keyed-by-four-dimensions-and-posted-append-only.md) 决定四与决定五、[ADR-0271](./0271-collection-principal-enters-the-ledger-only-on-the-channel-collection-report-and-shortfall-comes-only-from-in-transit.md) 的依据门、ADR-0283 除决定四那一句外的各条、ADR-0285 的重算与更正照采、[ADR-0298](./0298-an-agreed-offset-approved-by-settlement-accounting-leaves-in-transit-for-an-offset-applied-position.md) 的认可抵扣：都照用，不停用。ADR-0298 越权风险点 1（认可抵扣登记时不核结算）不由本记录回答：认可抵扣不是资金事实，没有认作可言。

## 越权风险点

1. **认作代收本金不可撤**（SA owner、CR owner）。认错的事实（比如其实是运营企业自己的收款）在结算一侧没有出口：映射只增不改，认作之后不能再映到应收，也不能撤销。反方向同样：事实被映到了错的目标（比如误映到某张客户对账单）之后，就再也不能认作代收本金（互斥，决定一）；认作了也不能再映别处。两个方向都不可撤。今天靠认作时的显式依据与人工核对；若要给撤销形，前提是代收与清分一侧该事实名下没有任何到账，需要跨上下文的读口与后继记录。
2. **整条认作，不支持一条回款混着本金与服务费**（SA owner）。一条银行回款若同时含客户服务费与 COD 本金，要在来源侧（手工采用口，ADR-0236，或银行流水）拆成两条事实再分别映射与认作；本记录不提供按金额拆分。渠道回款通常只含代收本金（扣了渠道服务费再打款时事实金额本就是实收），所以只当边缘情形。
3. **同一笔银行回款被不同引用各采用一次，代收与清分防不住**（SA owner）。事实引用是外部系统的事实身份，结算同一引用只采用一次；若来源给了两个引用，结算会有两条事实，各自都可以被认作并支撑一组到账。代收与清分不推导两条事实是否同一笔钱（「本产品不推导」）。具体后果分两种：两条事实的到账指向**同一条指令**时，第二条到账能登记（每指令至多一条是按事实算的），但移位撞余额不足（`UNDERFUNDED`），因为移位上限按指令的在途余额算，这是唯一的网；指向**两条各有渠道报告的不同指令**时，两条到账都能登记、都能移位，`待清分`合计是这笔回款真实金额的两倍，没有任何一道门拦。原始缺陷「代收与清分自铸一份、结算也采用一份」由此实质关闭，残留的是结算采用口的来源身份去重，不是本记录新增，也不在本记录。
4. **被结算更正得容不下的状态没有出口**（CR owner、SA owner）。事实下调到容不下既有到账之和之后，新到账进不来、未移位的到账不能移位，而到账是追加式（没有更正形，code/15 未落）；冲正已移位的也不能让合计回到事实之下。出口只有结算把事实再更正回去（若那次下调本身是错的），或后继记录给真实到账的更正形。安全的停：没有无来源的本金进入`待清分`。
5. **已落的移位不随结算更正自动冲正**（CR owner）。更正发生在移位之后，已进`待清分`的本金留在那里，直到人冲正；更正的答复不带「有多少到账被它容不下」，因为结算看不见代收与清分。靠的是下一次碰这条事实的登记或移位答内容冲突。
6. **资金退回与付款撤销不驱动代收与清分**（SA owner、CR owner）。银行退回认作代收本金的那笔钱，结算一侧以另一条`资金退回`事实记，认作的事实本身不动；代收与清分的到账与移位照旧，要人核对并冲正。
7. **一条事实对一条指令至多一条到账是新收紧**（CR owner）。ADR-0274 只限金额之和；本记录再限条数，换事实标识重登同一指令即使合计没超也答冲突。真正的第二笔钱来自另一次回款，引用另一条事实。
8. **按旧口径登记的存量到账撑不起移位**（CR owner）。证据引用是任意字符串、没有钉版本的存量到账，移位答依据不在册，要为同一笔钱按引用另登一条到账（新事实标识）。COD 不在试点范围，存量只有演示租户。
9. **映射到任何目标都先取事实锁**（SA owner）。此前映到审核应付、贷项与金额本体的映射不取事实锁；现在取，为的是认作与别的映射互斥的读回与插入在同一把锁下。锁序没变（事实在全序首位），代价是这几类映射与同一条事实上的核销、更正排队。绕过事实锁的写入（只可能是直接写库）仍被库上兜住：第二条认作被唯一索引拒、目标不是事实自己的认作被 CHECK 拒；但映射写口 `FundsMappings.Save` 的 `ON CONFLICT DO NOTHING` 不带冲突目标，会把被唯一索引拒掉的第二条认作吞成「已有记录」，编排按这条映射自己的标识读不回赢家，答「映射库不可用」未决。停是对的，文案与原因不符；编排自己的路径取了事实锁、读回先于插入就判成映射冲突，走不到这里，所以不改行为。
10. **customs-compliance 的税费付款核对也读已采用事实**（CC owner）。认作代收本金的事实若被误引为关税付款证据，CC 读到的是金额、币种与付款人，不知道它是受托资金；CC 的适配器 `adopted_funds_fact_source` 按（引用，版本）读事实，不看结算的映射状态，所以认作代收本金的事实仍可能被 CC 当税费付款证据。这是既有盲区：映到客户账户的事实今天同样可被引用，本记录没有制造新的双记口子，也不更易误引。结论：不立票，本记录不动 CC 一侧；CC owner 若要在核对时排除，前提是结算给 CC 的只读口多带一格「已被整条认作代收本金」。

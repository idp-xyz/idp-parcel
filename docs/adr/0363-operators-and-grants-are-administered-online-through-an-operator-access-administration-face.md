# ADR-0363：操作者与授予在管理台登记——新设「操作者接入管理」能力面守写面与本租户操作者册的查阅，撤销不得锁死调用者自己，首个管理授予经受控命令行登记

Status: Accepted（2026-11-04，Claude Code 会话代 owner 决，用户授权代决；票 operator-access-administration/01。裁决能力边界：读过 ADR-0100 全文、ADR-0085 决定四、ADR-0315、ADR-0101，`internal/accessidentity` 的操作者册（`OperatorBinding`、`OperatorGrant`、`GrantRevocation`、`OperatorStanding`、`OperatorRegistrar`、`OperatorMinter`）、`parcel-access-register` 的翻译、`cmd/parcel-api` 的端点表与面族；越权风险点见文末。）<!-- 索引注记 -->｜**入口**：ADR-0100 立了操作者册与各能力面，登记操作者、授予与撤销却只有受控命令行；按租户列操作者的读口不存在；管理台没有操作者页。租户上线第一步要配的东西全靠实施方跑命令行。**取法**：新设可授的能力面 `OPERATOR_ACCESS_ADMINISTRATION`，守三个写面与本租户操作者册的查阅读；写面进端点表、载荷照 CLI 单项去掉租户；撤销落在调用者自己此刻生效的管理授予上拒；租户的第一个操作者与管理授予仍经命令行登，之后在管理台做。治理登记那一格照旧预留
Date: 2026-11-04

## Context

- ADR-0100 决定二把操作者册的列定死：主体绑定唯一租户，授予按能力面显式登记、可撤销、带生效区间；登记册配置写与主数据与运营查阅读两格可授，治理登记只预留。决定六把受控 CLI 定位回「受控批量口」，并写明「它今天是唯一能用的口是事故不是设计」。
- 两个月过去，操作者、授予、撤销三件仍只有 `parcel-access-register`；`accessidentity` 的 HTTP 面只有自查（ADR-0315）与作业设备册查阅。一个租户要加第二个操作者、给人授一格、撤一格，都得让实施方在数据库网络里跑命令行——这正是 ADR-0085 Alternatives 否决过的「把一项产品能力错登记为一项运维动作」。
- 谁能管别人的授予，今天没有任何一格能力面说得出：登记册配置写管的是各上下文的业务登记册，拿它去守操作者册会把「能登价卡」和「能给人授权」混成一格；预留的治理登记那一格属试点治理册（ADR-0085 决定四：无租户维，操作者授权模型特殊），本记录不碰它。
- 管理台已经按授予收起写入口（ADR-0315）；页面形态上，设置组里的作业设备册是现成的查阅页，公司主体与往来单位是现成的「工作台 + 右栏 + 登记视图」。

## 候选与反方

- **用登记册配置写守操作者册的写面。** 否决：两件事的责任人不同——能登业务数据的人不该自动能给人授权，也不该能撤别人的授予；一格混守，租户就没法把「配置员」和「账号管理员」分开。
- **用预留的治理登记那一格。** 否决：那一格是试点治理册的，无租户维、授权模型待裁（ADR-0085 决定四）；操作者册有租户维，管的是本租户自己的人，两者不是一回事。
- **第一个管理授予也在线做（自助注册首个管理员）。** 否决：没有任何已授予的人时，谁来认证这次登记？只能放一条「无人持有则任何在册操作者可登」的默认，而那正是 ADR-0101 决定六禁的「缺省朝放」。
- **允许撤销自己的管理授予。** 否决：租户只有一个管理员时，一次误操作就把整个租户锁死，恢复只能回到命令行；写入前拒掉这一种是机制能守的事。
- **新设操作者接入管理面，写面在线、首个授予走命令行（采纳）。**

## Decision

**一、新设能力面 `OPERATOR_ACCESS_ADMINISTRATION`（操作者接入管理）。**（机制）

- 可授、可撤、带生效区间，与登记册配置写、主数据与运营查阅读同列（`CapabilityFace`），迁移放开册上的 CHECK。它守三个写面与本租户操作者册的查阅读；不守任何业务登记册，持它的人不因此能登业务数据。
- 治理登记那一格照旧预留，本记录不裁它。

**二、操作者册的写面进端点表（ADR-0085 决定一那一族），读面同守。**（机制）

- `POST /operator-registrations`、`POST /operator-grant-registrations`、`POST /operator-grant-revocations`，各走 ADR-0100 决定四的三格准入（未配置 403、凭据不过 401、未授予 403），面是操作者接入管理。载荷形状归产品定（ADR-0101）：照 `parcel-access-register` 的单项、去掉 `tenantId`——租户只取自信封，带了即 400；未知键拒。答复沿用 `OperatorRegistrationOutcome` 代数，`RECORDED` 答 201、其余 200（ADR-0022）。
- `GET /operators` 交回本租户的操作者及其授予与撤销记录，外加产品词表（可授能力面、决定种类、作业范围种类）与本进程信任的发行方：管理台据此摆选项、预填发行方，不在前端抄第二份词表。
- CLI 与端点消费同一个 `OperatorRegistrar`；CLI 仍是受控批量口（ADR-0100 决定六）。

**三、撤销不得锁死调用者自己。**（机制）

- 撤销若落在调用者自己此刻生效的操作者接入管理授予上，答 `REVOCATION_WOULD_LOCK_OUT_CALLER`（代数新增一格），不写。别人的管理授予可撤；自己的其它格可撤。
- 租户只剩一个管理员时也不另加「至少保留一人」的规则：那要在写入时数全租户，而数出来的结论在并发下立不住；防自锁这一格已经挡住最常见的那次误操作，余下的归租户的治理。

**四、租户的第一个操作者与管理授予经受控命令行登记。**（产品策略）

- 实施方用 `parcel-access-register` 登第一个操作者与它的操作者接入管理授予；此后该租户在管理台登记其余操作者与授予。演示租户的配置操作者在种子里多这一条授予（S）。

**五、管理台「操作者与授予」页。**（管理台形状，不是产品规则）

- 设置组一页：工作台列操作者，右栏显绑定与授予（生效中 / 未到 / 已到期 / 已撤销），授予就地登记、撤销用对话框，「新增操作者」是登记视图；没有管理授予的人不摆写入口（ADR-0315 同款），读口答未授予时如实显状态。
- 操作者与授予页在读口答未授予时，把本人的发行方与主体标识显在状态区（从 ID token 解出、只显示），便于未在册或未授予的人交给管理员登记：主体标识是不透明串，别的路径拿不到它。管理台不另设整站拒绝页。

## Consequences

- `internal/accessidentity` 多一格能力面、一个按租户的读口、一格撤销答复；`adapters/http` 多四个端点；`cmd/parcel-api` 端点表多四行，面族多一种。
- 管理台多一页。
- 参数登记册 `PAR-INT-08` 的状态改写为「机制已有在线入口；首个管理授予仍经命令行」。
- 与登记册配置写分格之后，租户可以把「账号管理员」与「配置员」分给不同的人。

## 越权风险点

1. 新能力面的名字与粒度（一格管操作者、授予、撤销三件）：owner 若要把「登记操作者」与「授予」分开，要拆成两格并改迁移。
2. 防锁死只挡调用者自己的那一条，不保证租户至少一个管理员。
3. 未授予状态区显示主体标识：它是不透明串、不含姓名与联系方式，但 owner 若认为连它也不该显示，改回只显「未在册」。

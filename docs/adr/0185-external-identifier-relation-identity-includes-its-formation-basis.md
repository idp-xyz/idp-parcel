# ADR-0185：外部标识关联的身份含形成依据——同一分配方对同一对象再签同一个号是新的一条关联

Status: Accepted（2026-10-16，部分停用 [ADR-0184](./0184-external-identifier-relations-are-an-append-only-register-formed-with-their-source-facts.md) 决定一的键，其余各条不变。由票 [ps-external-mark-relations/03](../../.scratch/ps-external-mark-relations/issues/03-channel-parcel-numbers-from-label-results-void-and-replacement.md) 的两轴评审揭出——Standards 轴报阻断、Spec 轴报非阻断，评审者是 `/code-review` 的隔离子代理（用户 2026-10-16 改裁允许子代理）。Claude Code 会话在用户「你帮我做决定吧」「开始」的同一授权下代 PS owner 裁定。）

Date: 2026-10-16

## Context

ADR-0184 决定一把关联的键定为（租户，标识类型，分配方，号码，被标识对象），没有形成依据。票 03 让渠道包裹件号随面单交易包裹结果形成之后，这个键在两种真实情形下吞掉一条关联：

- **换单沿用原号。** 新交易（前序关系为替代）对同一件包裹受理回来的号与原交易的一样。新关联与原关联同键，写入按幂等被吞；随后「原关联转已被替代」那一行的后继指回它自己，读口排除已有终态的关联，这个仍然有效的号从此答零个候选——那件包裹在节点认不出来。
- **作废后再签同号。** 原交易的号已作废，下一笔交易又签回同一个号。新关联同键被吞，号保持作废，违反 PS CONTEXT「同一号码后来重新标识同一对象时形成新的关联，不复活旧的」。

同根的第三格：后一笔交易的作废按形成依据选原关联，同键被吞的那一条根本不存在，作废落空。

## Decision

**关联的键加入形成依据：（租户，标识类型，分配方，号码，被标识对象，形成依据）。** 每一件来源事实形成的关联各是一条，重放同一件来源事实仍按键幂等；适用变化挂在各自那一条上，作废与替代只作用于按形成依据选中的那一条。替代的后继由（分配方，号码，形成依据）回指，库上再钉一条：后继不得是被替代者自己。

客户包裹件号不受影响：它的形成依据是接受决定，一份委托只接受一次。

## Consequences

- 迁移 0025（票 03 同笔）把关联表主键加一列、适用变化表的主键与外键随之加一列、后继多一列形成依据；0024 落下的行键值不变。
- 读口照旧按号码去重交回包裹：同一件包裹因再签同号挂着两条适用关联时仍是一个候选。
- 不在本记录：终态按写入先后立住，而不是按业务时间比先后。两格：同一条关联先后收到作废与替代时，先写入的那种立住；同一笔交易上后补一条业务时间更早的作废时，库里的终态时刻仍是先写入的那一条（领域交出的是最早那条，变化行只插不改，不回头改写）。读口的答案都不受影响——两种终态都让号不再算数——只是记下的终态种类或时刻可能与业务先后不符。票 03 的完成记录如实记为已知局限。

## 越权风险点

1. **「再签同号是新关联」而不是「原关联继续适用」。** 另一种读法是：同一分配方对同一对象签回同一个号，号从未真正失效，原关联应当继续适用、不记替代。本记录不取：换单是一件新的来源事实，它的号码与旧号同值只是巧合，形成依据不同；把它并进旧关联，就丢了「这件包裹的号后来由哪笔交易背书」。若 owner 取另一种读法，改法落在替代分支（同号不写替代），键可以不动。

- owner 复核 2026-10-19 认可（用户 2026-10-16 授权「你作为业务和系统专家你来自决」，会话 idp-parcel-9b 代裁，逐条）：1. 再签同号是新关联——Decision「每一件来源事实形成的关联各是一条」守的是 PS CONTEXT「同一号码后来重新标识同一对象时形成新的关联，不复活旧的」；并进旧关联，就丢了这件包裹的号后来由哪笔交易背书，后一笔交易的作废也按形成依据选不中它（Context「同根的第三格」）；节点的答案不受影响——Consequences 写明读口按号码去重，同一件包裹挂两条适用关联仍是一个候选。

# ADR-0199：节点收寄保全交付来源——待识别实物按存下的号重核，同一作业实物在同一节点不另起控制起点，身份核对读不动在前提齐备后翻成待识别加未核对

## Context

收寄记录里不存现场看到的外部标识：`ports.ReceptionRecord`、`domain.NodeIntake` 与 PG 行模型都没有号码格，`Handle` 把 `domain.CanonicalizeDeliveryPayload` 交回的规范化文档丢掉、只留摘要。UC-NO-002 步骤 1 要求「保全本次交付来源、原始引用、业务时间、接收时间、节点和交付方｜后续解析失败不删除来源」，PN-03 交接 PN03-W03 要求「先保全客户交付、扫描、点验、拒收和现场观察，再逐件形成…」。由此落空的有：

- **身份核对读不动没有可落的格。** 落成待识别，服务端无从按号重核；ADR-0186 决定二因此让这一支不形成答案（5xx），目标形态「待识别 + 身份未核对」留给本记录。零候选的待识别今天同样无从按号重核，`AT-NO-026`「身份后来被 `parcel-shipment` 确认」没有机制。
- **拒收只存原因，仅扫描只存键、摘要、种类与时刻。** UC 结果表对`收寄判断待确认`要求「已知事实、控制现状、缺口、限制和续办引用」。
- **已有结果的答复只带 `outcome`。** UC 对`已有结果`要求「原节点收寄或待识别结果及当前有效性」。
- **收寄键只有（租户，来源）。** 同一作业实物换个来源再收，又形成一条收寄、又起一个控制起点；ADR-0196 决定一明说「同一件实物换个来源再收一次照常形成收寄」。UC「一致性、幂等与并发」：「同一实物同一客户交付边界只能形成一个当前有效节点收寄判断和一个控制起点；更正形成新判断版本。」

难逆转处：收寄册只追加，落下的行就是历史；设备答复里的格一旦有消费者就难改；PS 多交出一种信封，NO 多一个消费者。

## Decision

适用范围：UC-NO-002 收寄编排及其生产装配（`cmd/parcel-api` 的 HTTP 收寄口与 `cmd/parcel-frontline-import` 的受控批量口），第二期新立的重核编排，以及 PS 外部标识关联册的交出。方向依据代码、集运编排与承接编排不改。

裁定分四期：一、来源保全；二、按存下的号重核；三、身份读不动翻成「待识别 + 未核对」；四、同一作业实物重复控制起点的挡法。**落地次序是一、二、四、三**：第三期的前提里有一项正是第四期的挡法（见决定五）。实施票号按落地次序排，见票 no-reception-source/01 的完成记录。

**一、来源随判断保全，三种观察都存（第一期）。**

- 每条新落的收寄记录带本次交付的**来源文档**，与判断同一行、同一笔事务写下，此后不改。内容：作业实物、外部标识观察、接收观察、证据、拒收原因、交付方、节点、发生时间。明确接收、明确拒收、仅扫描都存；某格在这种观察里本就缺席（拒收没有接收证据，接收没有拒收原因）时记空串、不省键，一个形状覆盖三种观察。
- 规范化照 ADR-0014：文档自带形状版本，时刻按 UTC 写。外部标识观察原样存，不改写——在线口存设备送来的那一格，受控批量口存逐格去两端空白之后交给编排的那一格，口径见 UC-NO-002 输入语义契约下那一段与票 no-reception-identity/02。重核拿的就是这一格。
- **来源文档与内容指纹分开。** 指纹仍是 NOC-1 收寄面那几格（作业实物、外部标识观察、接收观察、节点、发生时间），幂等与冲突的分界不变，`CanonicalizeDeliveryPayload` 与无版本那一版都不动。证据、拒收原因、交付方只进来源文档、不进指纹：同一来源只在这几格上不同的重投照旧答`已有结果`，首次存下的来源文档不被覆盖。
- **既有行不回填。** 号码从未在册上留存，补不回；读面对这些行如实说「来源未保全」，重核与按号匹配都不碰它们。
- ADR-0196 追加的冲突版带引起它的那次后到送站的来源文档，与它沿用的摘要同源；文档里的作业实物因此是后到那件，不是先到那件当初的送站。

**二、每一版判断有版本，追加的一版指名前版；已有结果带回原判断种类与当前有效版本（第一期）。**

- 每种判断都签**判断版本**：形成与待识别两格就是既有的收寄结果版本，未收寄与待确认两格也签一个，同一签发器、同一命名空间。
- **追加的一版指名前版**——它接续的那条链此刻的当前有效版本。追加的一版包括 ADR-0196 的冲突版、第二期的重核版与第四期的续办版。一版至多一个后继，库面以（租户，前版）唯一守住；某条判断链的**当前有效版本**是沿后继走到头的那一版。第一期之前落下的冲突版没有前版，不回填。
- **已有结果的答复带两格信息**：原判断种类（收寄记录上的判断种类）与当前有效版本，线上字段名 `recordedOutcome`、`currentVersion`。`outcome` 仍是`已有结果`，两格不进 outcome 词表。

**三、按存下的号重核（第二期；兑现 `AT-NO-026`）。**

- **触发只有三处，不做后台扫表。**
  - PS 外部标识关联册新形成一条标识包裹的关联时，与关联同一笔事务经 Outbox 交出只带（租户，号码）的信封，信封身份由关联的键认领（ADR-0185），NO 以 inbox 消费者接收。适用终态（作废、替代）不交信封。
  - 复核页上由人对指名的一件待识别实物发起。
  - 落下未核对行（决定五）的同一笔事务给本上下文自投一封门铃，只带（租户，那一版的判断版本），信封身份由那一版认领；NO 用同一个 inbox 消费者接，重核对象只看那一件。身份核对仍读不动就交回 error，信封留在 inbox 退避重投——接替的正是翻转前设备收 5xx 退避重投、PS 恢复后自动续上的那一格。随第三期落。
- **信封是门铃，不是身份答案。** NO 收到后照旧经身份核对读口问 PS，不据信封认定身份。信封不带包裹、分配方、标识类型或委托，与 CONTEXT-MAP `parcel-shipment → node-operations`「不交号码的分配方、客户账户或委托」一致。
- **重核对象**：同租户里当前有效版本是`待识别实物已建立`、不带关联、不记身份冲突，且来源文档的外部标识观察与号码逐字相等的判断；人工发起时只看指名那一件，其余条件同此。记身份冲突的（多候选、一码两物）不重核：册上已有的冲突行在 `JudgeIdentityBasis` 里一直判身份冲突，重核解不开，那要身份冲突的处置能力。来源文档缺席的旧行不重核。
- **重核走与收寄步骤 4 同一份身份判断**，含 ADR-0196 的按包裹认与票 no-reception-identity/03 的（租户、包裹）咨询锁，不另写一套：
  - 唯一，且包裹没有关联到别的作业实物 → 追加一版`节点收寄已形成`：带关联；接收时刻与控制照原判断，**业务时间是原收寄时刻，不另起控制起点**；照 ADR-0186 向 PS 取服务结果并记核对态；交发布意图一封。
  - 唯一，但包裹已关联到别的作业实物 → 照 ADR-0196 追加冲突版，先到那件也追加。
  - 多候选 → 追加一版待识别，记全部候选与身份冲突。
  - 零候选 → 判断不变、不追加；被重核那一版若是「未核对」（决定五），追加一版「待识别 · 已核对」。
  - 身份核对仍读不动 → 不追加，交回 error：信封留在 inbox 重投，人工发起答 5xx。
- **追加版的来源标识由被重核那一版的判断版本派生**，带 `IDENTITY-RECHECK/` 前缀，撞键即重放。派生自版本而不是原来源标识，是为了长度有界：来源标识原样进意图信封的 Subject，信封有上限（票 operator-channel/54 量到的那一类）。

**四、同一作业实物在同一节点不另起控制起点（第四期）。**

- **「同一作业实物」按租户内的作业实物标识认。** 外部标识观察不是实物的身份：两件实物贴同一个号是 ADR-0196 的身份冲突，一件实物换了号仍是同一件。
- **「当前收寄」**：这件实物在这个节点上，有一条判断链的当前有效版本是`节点收寄已形成`或`待识别实物已建立`，且那一版的控制没有转出。
- **有当前收寄时，同一实物在同一节点的任一交付观察都并入它**——明确接收、明确拒收、仅扫描都一样，在身份核对之前认出，不再问 PS，不形成新判断、不建控制、不交意图。这次送站的来源照样保全：落一行，种类为「并入已有收寄」，指名并入的那一版（并入不是后继，不占前版）；答`已有结果`，信息格照决定二带那一版的判断种类与当前有效版本。「并入已有收寄」是收寄记录新增的一种，库面封闭集随之扩，不进 outcome 词表。
- **仅扫描的待确认由后来的观察续办。** 同一实物在同一节点的当前有效版本是`收寄判断待确认`时，后来的明确接收或拒收照常形成新判断（收寄、待识别或未收寄），新判断以那条待确认为前版；原待确认照留，不回头把它改成确定结果（UC-NO-002 步骤 6C「只续办原判断，不伪造确定结果」）。仅扫描之后又是仅扫描，同样追加一版待确认续办。`节点收寄未形成`之后的再次交付是另一次交付尝试，不续办那次拒收、不指名前版。
- **串行**：认同一实物之前，按（租户，作业实物）取事务级咨询锁，所有分支都取；唯一识别那一支随后再取（租户，包裹）的锁。次序固定为先实物后包裹，重核同此，两把锁不会交叉等待。
- 第四期落地之日起，部分停用 ADR-0196 决定一末句「同一件实物换个来源再收一次照常形成收寄」，以及它「能力边界」里冲突形成之后先到那件换来源再收「照常答`节点收寄已形成`、交发布意图」那一句；范围只限同一节点上有当前收寄的情形。落地前两句照旧描述代码。

**五、身份核对读不动翻成`待识别实物已建立` + 未核对（第三期）。**

- **目标形态**：收寄与控制都成立（CONTEXT：实物控制因明确节点接收而形成），来源已保全，不交意图；记录带**身份核对态**「未核对」。不取「带物理事实的待确认」：CONTEXT「已拒收或待确认均保持此前已确认的控制关系」，而明确接收已经取得了控制。
- **身份核对态只在待识别记录上**，封闭两值：「已核对」（`CHECKED`）是身份核对读口答复了，结果是零候选、多候选或冲突；「未核对」（`UNCHECKED`）是读口交回错误、没取得 PS 的答复。它让「查过了，查无此号」与「没问到」在记录上分得开，守住 ADR-0089「绝不交回空候选顶替」与 ADR-0186 决定二「不拿空候选顶替」。翻转之前落下的待识别行回填「已核对」，推定依据写在迁移头注，写法同迁移 0006。
- **核对态是信息格**：设备答复、前线导入明细、复核目录与管理台都带它，线上字段名 `identityCheck`，与 ADR-0186 的 `serviceResultCheck` 并列；`outcome` 仍是`待识别`，核对态不进 outcome 词表。设备照 `outcome` 出队（ADR-0022），未核对与已核对的待识别对设备是同一种处置。
- **`ParcelContainmentView`**：同租户里有未核对的待识别实物此刻在未关闭单元里时，凡没有已关联实物在袋的包裹都答`不可归属`，不答`不在`。未核对的在袋件可能是任何一件包裹，本上下文说不出是哪件（`ports.ParcelContainment` 头注：身份未定的在袋件不能答`不在`）。
- **身份读口在翻转那一笔改经 savepoint 隔离**，做法同 `SavepointedServiceResultView`：读不动要落册，SQL 级读错误不得把收寄那笔事务打成中止态。翻转之日起部分停用 ADR-0186 决定二「身份核对读不动：不形成答案」与决定七「身份读口不隔离」两处；决定二里「不拿空候选顶替」照旧成立，由核对态兑现。
- **翻转的前提，缺一个都不翻：**
  - 来源已保全（第一期）。
  - 「未核对」处处可见：设备答复的信息格、前线导入明细、复核目录与管理台、`ParcelContainmentView`。这一项与翻转同票落地、不单独先落：先落没有可见的东西；后落则有一段时间未核对行在各读面上被读成零候选。理由同 ADR-0186 决定七把 savepoint 与新答法绑在一票。
  - NO 主动重核：第二期的信封与人工两个触发，加随翻转落的自投门铃（决定三）。少了门铃，「关联早于读不动形成」那一格就只能靠人工续上。
  - 挡住同一作业实物重复形成控制起点，不只限于身份这一支（第四期）。
- 方向依据代码不改：重核版带关联，`JudgeIdentityBasis` 照现有折法就判成立；未核对行没有关联，照待识别折（缺少·待识别），不另立原因。

**六、不改的。** 拒收、仅扫描、零候选、多候选、身份唯一可读各支的 `outcome` 不变；服务结果读不动那一支（ADR-0186 决定一）不变；`outcome` 词表不增不减。UC-NO-002 结果表`收寄判断待确认`一格里「身份」的读法——指交付范围或实物本身无法区分，正式包裹身份的未知与冲突按步骤 4 归待识别——只落在 UC，不在本记录。

## 能力边界

- 来源冲突那一次送来的内容仍不落册。UC 结果表要求`来源冲突`保存「原来源、冲突内容、现场事实和纠正入口」，本记录不改这一格。
- 控制转出今天没有生产接线（`ControlTransferAdapter.TransferOut` 只有测试调用），「控制没有转出」在所有既有收寄上都成立：一件实物离开节点后再回同一节点，会被并入旧收寄，直到转出接上。
- 第一期之前落下的行没有来源文档，既不能重核也不参与按号匹配。第一期落地到第二期落地之间形成的关联不会补发信封，这段时间落下的零候选待识别只能人工重核。
- 只看本租户 NO 收寄册上客户送站的收寄；经交接进来的实物在本上下文没有收寄行，不在重核与并入之列。

## 越权风险点

1. **代 PS owner 定关联册新形成关联时交出信封。** PS 的写路径（委托接受、面单交易受理）每形成一条关联多一次入队；NO 会收到从未在任何节点出现过的号码，消费者对匹配不到的号码不做事。若 PS owner 不愿交出号码，替代是只交租户、NO 对全租户的待识别逐件重问，代价是每次关联形成都扫一遍本租户的待识别。
2. **未核对行由自投门铃续上（会话 idp-parcel-9b 2026-10-19 代决，授权同 Status 行）。** 裁定原话「不做后台扫表」只给了信封与人工两个触发；PS 读不动期间落下的未核对行，若号码的关联早在读不动之前就已形成，不会再有 PS 的信封，翻转前设备退避重投、PS 恢复后自动续上的那一格会变成只靠人工。取「落未核对行的同一笔事务自投一封重核门铃」（决定三）：意图驱动，一行一封，不是扫表。不取「同一来源重投时重核」：翻转后设备收到 2xx 就出队，不会再重投。不取「只靠人工」：比翻转前倒退。代价与风险：NO 既交又收这一种信封，路由要加在 `cmd/parcel-dispatch` 的路由表上；PS 长时间读不动时门铃在 inbox 里按退避堆积，堆积量等于这段时间落下的未核对行数。
3. **指纹不含证据、交付方、拒收原因。** 同一来源只在这几格上不同，今天与第一期之后都答已有结果，差异只留在设备那头。UC「同一来源身份和内容返回已有处理结果；同一身份不同内容形成冲突」读宽了会把它算冲突；扩指纹要另起形状版本并长期比对两版（ADR-0014），不在本记录。
4. **同一作业实物按作业实物标识认。** 设备或导入给两件实物配了同一个作业实物标识时，后一件被并入前一件、不形成收寄。作业实物标识在租户内唯一靠现场签发纪律，本上下文不核。
5. **未核对在袋件让同租户里没有已关联在袋实物的包裹都答`不可归属`。** 范围是租户，宽；这段时间里 PS 对这些包裹判不出「没装袋」。收窄要按号匹配，那是 PS 对号码的解释，本上下文不做。
6. **「并入已有收寄」是收寄记录新增的一种。** 读收寄册的各面（复核目录、方向依据身份一格的读口、`ParcelContainmentView`、`FindOtherUnitIntakes`）要么按种类筛，要么靠它不带收寄与控制自然读不到；第四期实施票逐面核过。
7. **第四期改变 ADR-0196 已落的行为与用例。** `TestTheSameUnitDeliveredAgainIsNotAnIdentityConflict` 钉的是「同一件实物换个来源再收一次照常形成收寄」，第四期落地后改钉并入。
8. **翻转把身份读口挪进 savepoint**，部分停用 ADR-0186 决定七的一句。那一句的理由是「身份读口读不动本就不形成答案，整笔回滚正是要的结果」，翻转之后前提不在了。
9. **分期次序与裁定字面不同。** 裁定按一二三四列期，翻转的前提含第四期的挡法，落地次序因此是一、二、四、三；若 owner 要按字面次序落，翻转就得先于挡法，与裁定自己写的前提相抵。

## Consequences

- 收寄表加列：来源文档（jsonb；第一期起新行必带，既有行为空）、判断版本、前版（库面（租户，前版）唯一）、并入版本（第四期）、身份核对态（第三期）；记录种类封闭集加「并入已有收寄」（第四期）。索引：按（租户，作业实物，节点）找当前收寄；按（租户，外部标识观察）找待重核的待识别，只覆盖待识别行。
- NO 第一次有 inbox 消费者，住 `cmd/parcel-dispatch`。PS 多一种交出的信封。
- 每次收寄多一把按作业实物的咨询锁，所有分支都取。
- 设备答复多三格信息：`recordedOutcome`、`currentVersion`（已有结果）、`identityCheck`（待识别）。
- 翻转之后，PS 读不动不再让设备卡在 5xx 重投：物理事实当场落册、设备出队；续上身份靠重核。

## Alternatives

- **来源另立一本来源事实册，判断行引用它。** 不取：幂等键与指纹今天在判断行上，挪过去后既有行要两本册各查一次；本记录要的是一来源一行，判断行带来源文档就够。代价是并入的那次送站要占一种记录种类。
- **来源只存号码。** 不取：拒收与仅扫描的待确认同样要「已知事实」，号码之外的证据、交付方、拒收原因今天都没处存。
- **把证据、交付方、拒收原因并进指纹。** 不取，见越权风险点。
- **重核后台扫表。** 裁定否决：对象是全租户的待识别，周期与负载要另定，也无从知道哪一刻值得再问。
- **同一实物按外部标识观察认，或两者都看。** 裁定否决：号码只是线索；一码两物是 ADR-0196 的冲突，一物换号仍是同一件。
- **同一实物再来时另起一条收寄，只把旧控制标为被替代。** 不取：UC 要「一个控制起点」；替代控制要动方向依据与容纳索引的读法。
- **仅扫描待确认之后的明确接收改写那条待确认。** 不取：只追加、不覆盖（CONTEXT「重复、迟到、冲突、更正或有效性变化必须关联原事实和原判断，不能通过覆盖历史整理出单一结果」）。
- **未核对落成「带物理事实的待确认」。** 不取：明确接收已经取得控制，待确认保持此前的控制关系，两者对不上。
- **身份核对态并进 outcome，新增一格。** 不取：outcome 是设备出队与分支的依据，未核对与已核对的待识别对设备是同一种处置；核对态与 ADR-0186 的服务结果核对态同为信息格。
- **身份读不动翻转先于挡法落地。** 不取：翻转之后设备当场出队，同一实物换来源重扫就形成第二个控制起点，正是翻转前提要挡的那一格。

## 复核记录（2026-10-19，ADR-0210 部分停用几句；决定原文不动）

会话 `idp-parcel-9b` 代 NO owner 裁定身份冲突的处置（票 [no-reception-identity/04](../../.scratch/no-reception-identity/issues/04-identity-conflicts-have-a-disposition-and-release.md)，授权同 Status 行），成文为 [ADR-0210](./0210-identity-conflicts-are-disposed-by-an-operation-decision-and-the-identity-basis-reads-chain-heads.md)。它对本记录：

1. **决定三「重核对象」一项**里「册上已有的冲突行在 `JudgeIdentityBasis` 里一直判身份冲突，重核解不开」一句，自票 no-reception-identity/05 进 main 起停用：身份一格改读每条判断链的当前有效版本（ADR-0210 决定五），接在冲突版之后的一版能解开它，前提不再成立。同一项的结论「记身份冲突的（多候选、一码两物）不重核」维持，理由改为 ADR-0210 决定一：身份冲突只经人工处置解除。
2. **决定三分格**里「唯一，且包裹没有关联到别的作业实物 → 追加一版`节点收寄已形成`」与「唯一，但包裹已关联到别的作业实物 → 照 ADR-0196 追加冲突版」两支，自票 no-reception-identity/06 进 main 起停用，**适用场景**只限被重核那一版是「确认不是其中任何一件」的身份冲突处置版、且唯一命中的那件包裹在它排除之列：这时不追加，照零候选办（ADR-0210 决定九）。其余分格不变。
3. **决定五末项**「方向依据代码不改：重核版带关联，`JudgeIdentityBasis` 照现有折法就判成立」里「方向依据代码不改」与「照现有折法」，自票 no-reception-identity/05 进 main 起停用。这一项的结论维持：重核版是链头、带关联，判成立；未核对行照待识别折、不另立原因。
4. 决定二的判断链与当前有效版本，是 ADR-0210 读链头与逐链追加处置版的底子，不变。

## 复核记录（2026-10-19，ADR-0211 部分停用两句；决定原文不动）

会话 `idp-parcel-9b` 代 NO owner 与 PS owner 裁定只因歧义信号的冲突自动解开（票 [no-reception-identity/07](../../.scratch/no-reception-identity/issues/07-an-ambiguity-only-conflict-releases-when-the-declaration-is-gone.md)，授权同 Status 行），成文为 [ADR-0211](./0211-an-ambiguity-only-identity-conflict-releases-by-recheck-once-the-declaration-is-gone.md)。自该票进 main 起，决定三下列两句停用，**适用场景**只限冲突来由为只因歧义信号的身份冲突：

1. 「**触发只有三处，不做后台扫表。**」里「只有三处」——多一处：PS 委托由`已提交`转为`已拒绝`或`已撤回`时，按它声明的每个号交一封只带（租户，号码）的声明撤除门铃，NO 用同一个重核消费者按号重核（ADR-0211 决定三）。「不做后台扫表」照旧。
2. 「重核对象」一项里「记身份冲突的（多候选、一码两物）不重核」——原句写在 ADR-0195 之前，括号里没列带信号的一个候选；ADR-0195 决定四把那一格落在重核「多候选」格、记冲突，此后它也归这句管。来由是只因歧义信号的冲突从此是重核对象：信号消失、答唯一命中即追加关联版（业务时间原收寄时刻、不另起控制起点、意图一封），信号仍在不追加，变成多候选或一码两物追加冲突版、来由随之更新（ADR-0211 决定二）。多候选、一码两物与来由缺席的冲突照旧不重核，理由照本记录「复核记录（2026-10-19，ADR-0210 部分停用几句」那一节。

决定三其余分格、来源文档缺席的旧行不重核、门铃不是身份答案，都不变。

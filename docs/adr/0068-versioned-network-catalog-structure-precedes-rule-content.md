# ADR-0068: 版本化网络目录结构先行——七表由 CONTEXT 硬句推导，内容列与折叠规则等 PAR-NET-14

Status: Accepted  
Date: 2026-08-20

## Context

[ADR-0053](./0053-network-fact-families-are-derived-not-registrable.md) 裁定网络事实族是推导结果不可登记，登记册只登「定义是否存在」，并把定义原语的模式留待「真有定义可登时再设计，现在不建表」。它同时预告了下一步：「下一次真要做网络定义时，先设计原语模式与解析层，再回来扩这张表；不要从事实族倒推。」

`.scratch/nr-route-evidence-views/issues/01` 把那句「现在不建表」重新摆上台面 triage：三个证据视图（`NetworkEvidenceView`、`InitialRouteEvidenceView`、`AutoRerouteFactsView`）阻在三层——规则未定且明禁默认、`NetworkEvidenceView` 缺 PS 地址提供路径、实例半边为空——而其中**目录结构这一半不依赖任何一层**。该票论证：网络目录的形状由 [network-routing CONTEXT](../domain/network-routing/CONTEXT.md) 的硬句定死，「稳定网络定义和临时网络可用性调整必须分离」「节点、连接、线路、服务区域、服务日历或路由策略发生永久变化时形成新版本，不覆盖原版本」「新版本自明确生效时间起参与适用范围内的新判断」「每个节点、网络连接和适用线路必须明确业务时区」「跨节点时间按绝对时刻比较」——列与 CHECK 从这些句子推得出来，不需要任何 `PAR-NET-*` 取值。用户 2026-08-20 批复「建」。

该票还否掉了另一条路并要求不再走：按判断键存放已发布证据快照的表**结构上填不满**——`ReachabilityJudgmentKey` 的 `asOf` 由发起方在请求期解析，任何生产者都无法预先为尚未发生的判断写好快照行（同类先例：`ve-milestone-mapping-key/issues/01`）。对的机制是**按 `asOf` 查版本化目录**：目录行带自己的有效区间，查询按判断时点选版。

0053 判「现在不建表」时，摆在桌上的方案是从九个事实族倒推表——那确实错。现在建的不是那张表：结构（身份、版本、区间、时区、方向、次序）与内容（地理覆盖、日历内容、规则正文）在这一步分开，前者是 CONTEXT 已定的机制，后者仍是 0053 不许替租户拟的开放集。

## Decision

**一、部分停用 ADR-0053 Decision 三的「现在不建表」半句。** 其「不从事实族倒推」与「内容形态不替租户拟」两条一字不动——它们正是本记录的两条护栏。0053 其余各条（事实族不可登记、登记册只登定义存在、无解析层时禁答已配置带空事实）继续有效。

**二、版本化网络目录七表落 `network_routing` schema**（迁移 `0008_network_catalog`）：物流节点、网络连接、线路、服务区域、服务日历、临时网络可用性调整、路由策略，各一张版本表。稳定六表每行带 `[effective_from, effective_to)` 生效区间（`timestamptz`，绝对时刻）；版本行只增不改；同一身份至多一个未闭区间版本由部分唯一索引担保。登记未闭新版时，前一个未闭版本按新版生效时间**接续闭合**——那不是改写历史，是「新版本自明确生效时间起参与新判断」在旧版本区间上的镜像；登记已闭区间（补历史）不触发接续。

**三、内容列一列不建。** 服务区域的地理覆盖（国家/行政区域/邮编范围「或其他」，开放集）、服务日历的营业日/节假日/服务窗口/截单内容、路由策略的规则正文（过滤、排序、冻结边界、改善阈值、改路条件与权限）全属 `PAR-NET-14`，等形态定了以**新迁移扩列**，不改已施加迁移。日历不另设业务时区列：「业务时区按各自节点/线路解释」，日历的时区就是其适用对象的时区，再存一份是第二处定义。

**四、按 `asOf` 选版，两版同时适用交回错误。** 稳定六族按区间含 `asOf` 判适用，生效当刻属新版；同一身份查出两个适用版本时交回 `ErrAmbiguousNetworkCatalog`（先例：VE 目录的 `ErrAmbiguousCatalog`），按任一条挑一个都是替网络定义的责任方作了它没作的决定。临时调整不按区间选版：同一调整身份的形成→变化→解除各成一行**历史链**，当前陈述取链上最大版本，再按其生效窗口判 `asOf`——这是「稳定网络定义和临时网络可用性调整必须分离」在选版机制上的那一半。

**五、目录修订锚随写推进，事实与修订单语句同取。** `network_catalog_revision` 每租户一行；每一笔目录写入（不分七类哪一类）在同一事务里把它 +1。读口用单条语句把七族适用行与修订一并取回——单语句单快照，事实与修订必然同版，`create_initial_route` 的提交前重校靠这个等值比对判断证据换代。「登记过与否」立在本行上：行不存在即未配置（三格答复的第二格），行存在而 `asOf` 无适用版本是「已配置、该时点无定义」——ADR-0052 的「空册与空集合可分辨」在目录层的落法，不靠「查出零行」推断。

**六、三个证据视图仍不读本目录。** 0007 的（租户+服务目的）网络定义登记册照旧为三口答三格；把目录折成逐候选事实的解析层属 `PAR-NET-14`，目录修订与视图修订的合流属解析层设计，届时再裁。参数登记册任何 `PAR-NET-*` 行状态不因本记录改变。

## Consequences

- 三口的阻断从三层收敛为一层：`PAR-NET-14` 规则正文。到位时要写的只剩解析层与内容列扩展，目录的版本、选版、修订机制不必返工。
- 会出现一段「目录可写可读、尚无人读它产出事实」的时期，与 ADR-0017 接受的「接口已定、只有内存替身」同形状。
- 目录今天没有生产写入方：迁移不种任何默认行，登记入口等真实网络定义（实例半边）。首发路径照旧停在`未配置`。
- 版本号由登记方给出，同身份重复版本号被主键挡住；版本号跨行连续性不设卡——补登历史区间是正当用法，库上强推连续会把它也挡掉。
- 已闭区间的重叠库上不挡（部分唯一索引只覆盖未闭那一半），由读口以 `ErrAmbiguousNetworkCatalog` 兜住——坏数据要修目录，不能靠挑一个版本把它藏起来。
- 内容列扩列时不得改写 `0008`：已施加迁移按校验和固定，扩列走新迁移。

## Alternatives considered

- **维持 0053 原判，等 PAR-NET-14 一起建。** 否决：结构半边由 CONTEXT 硬句定死，不依赖取值；票 01 的 triage 已论证先建结构不会因规则形态返工，等下去只是把两件事压回一件。
- **按判断键建证据快照表。** 否决：`asOf` 请求期才存在，结构上填不满；见 Context，不再重走。
- **内容列现在就拟（jsonb 或具体列）。** 否决：开放集，替租户拟形态——0053 的理由原样成立，这正是本记录保留的那半句。
- **临时调整与稳定族同用区间选版。** 否决：「必须分离」是硬句；且解除是历史事件不是对区间端点的编辑，链上追加才保得住「形成、变化和解除历史必须保留」。
- **修订锚按（租户+族）分七行。** 否决：ADR-0052 要求同一次取回的全部事实族共用同一个修订，七行拼不出一个有单一权威的修订值。
- **接续闭合改为拒绝「已有未闭版本时登记新未闭版本」。** 否决：那会把「形成新版本」这个最常见的正当动作变成两步（先闭旧、再登新），而两步之间没有任何不变量需要人来决定——生效边界本来就是新版生效时间。

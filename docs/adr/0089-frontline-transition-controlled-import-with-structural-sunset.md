# ADR-0089：一线作业过渡走受控批量导入并内置结构性拆除期限——ADR-0021 的带期限例外，管理台一个作业动词都不加

Status: 已接受（2026-09-01 用户裁定裁决项 2 选 B；2026-09-02 MCP-1 受用户委托落文并代裁细则，细则各条用户可 supersede）

## Context

[ADR-0021](./0021-frontline-operations-client-is-part-of-the-product.md) 裁定一线作业客户端属于产品，并把「管理台没有作业动词」写成有意设计：它的决定性理由是**工作流归属**——不知道「待识别实物」「身份冲突」「暂停方向性作业」的扫描端，会把操作员卡在一个只有报错、没有出路的屏幕上。同一记录把开工顺序定为「租户管理界面先，一线作业客户端次之」，那个端因此**尚未开工**。

而首个候选租户的专线流含收货、扫码换单、电子秤、装箱封签等现场作业，下周即进实施。机制与端点在 `node-operations`、`transport-fulfillment` 侧已备，缺的只是现场那一端。三条过渡路径的证据与代价见 `.scratch/tenant-implementation-01/decision-brief-scope-and-frontline.md` 裁决项 2：一线端 MVP 加速自建（与 ADR-0021 的离线固有要求偏离，周期以周计）、过渡期代录或受控批量导入顶岗（零开发，扫描粒度轨迹证据缺失）、客户旧系统导出经受控文件口导入（与「客户按我们流程改造」的承诺反向）。

**用户于 2026-09-01 裁定选 B，并附两条硬约束**：必须带明确的拆除期限与 ADR-0021 偏离记录；过渡方案不得在产品上留永久痕迹——代录入口不进管理台正式 page-registry，ADR-0021 那句有意设计不因过渡而废。裁决内容归用户；本记录是那次裁决的权威落文，其中标注为「细则」的各条由 MCP-1 于 2026-09-02 受用户委托代裁。

裁决只说到「代录/受控批量导入」这一层，两者是**不同的形状**，而选哪一个决定产品上留不留痕：代录要在管理台加作业动词与页面，正是硬约束点名要避免的；受控批量导入走独立命令行口，管理台一格不动。细则①因此在这两者中取后者。

这个例外**恰好落在 [ADR-0023](./0023-work-fact-identity-and-time-are-minted-by-the-device.md) 头上**：作业事实的身份与发生时间由设备签发。内勤从纸单抄录的事实，身份与时间都不是设备铸造的。这不是可以含糊过去的一格——[ADR-0005](./0005-source-facts-effective-events-derived-state.md) 的来源事实层正是派生与取证的地基，两类来源混在一起就再也分不开。

## Decision

1. **过渡形态是受控批量导入，不是管理台代录（细则）。** 现场按约定模板记录作业事实，内勤汇总，开发方受控运维在数据库网络内手跑导入口，灌入**既有**命令用例。**管理台不新增任何作业动词或页面，page-registry 与导航零改动。**
2. **导入口是独立受控 CLI，不是 HTTP 端点（细则）。** 形照 `cmd/parcel-*-register` 家族，落 `cmd/parcel-frontline-import`；不进 `cmd/parcel-api` 的端点表，不进任何准入放行表。这与 [ADR-0085](./0085-registry-write-faces-enter-the-endpoint-table-with-unconfigured-grade.md) 把 CLI 定为「受控批量口」的分工同向：写表单属产品能力，受控批量属运维动作，过渡属后者。
3. **结构性拆除期限内置在源码里（细则）。** 期限为 `2026-12-31T23:59:59+08:00`，写成源码常量（见 `structuralSunsetLiteral`）。过期即**启动拒绝**——退出非零、报文指名，不是警告；**没有环境变量或命令行参数可绕过**。延长期限只能 supersede 本记录并改源码发版。守卫是进程编排的第一条语句，在读参数、环境与文件之前；时钟经参数注入，测试把钟拨到期限后证明拒绝。

   一个能被运维改掉的期限不是拆除期限，是提醒——这是把它写成常量而非配置的全部理由。
4. **导入的事实必须与设备事实可区分（细则）。** 来源身份与证据引用都带 `FTI/<模板版本>/…` 前缀标记，录入操作者落在证据引用里（见 `intakeSourceID` / `intakeEvidence`）。标记落在**既有事实自己的来源/记录方表达上**，不另立旁表——来源属于事实本身，归拥有事实的上下文。**本记录是 ADR-0023 的带期限例外，标记就是例外的印记**，让派生与取证任何时候都能把这批事实单独挑出来；ADR-0023 对设备来源的那条规则本身不放宽。
5. **只灌既有用例，不造用例、不改 domain（细则）。** 某类现场事实在既有用例上找不到落点时，如实记缺口并停在那里，不为过渡拉伸既有语义、也不顺手改领域模型——难逆转取舍走 ADR，不在实现票里定。
6. **ADR-0021 的决定与论证一字不改。** 本记录不停用它任何一条：一线作业客户端仍属产品、仍待开工，离线与弱网容忍仍是它的固有要求。本记录只在它开工之前开一个带期限的口子。

## Consequences

- **扫描粒度的轨迹证据在过渡期缺失**，`PAR-VIS` 系列的取证质量因此打折。这是选 B 明知的代价，记在本决定这一边；期限到期即恢复，不设第二条延期路径。
- **四类现场事实里今天只有收寄真正可导**，逐格判定与缺口写在 `.scratch/frontline-transition-import/fact-to-usecase-mapping.md`，本记录不复述第二份。其中两处值得在此点名，因为它们各自触发了别的决定：
  - **装箱封签对得上用例，但来源标记无落点。** `node-operations` 的集运三口没有任何来源、执行方、证据与业务时间表达，而同包收寄口把来源当一等公民。按细则④⑤ 停下不导，另立票 `.scratch/no-consolidation-fact-provenance/issues/01-consolidation-commands-carry-no-source-executor-evidence-or-business-time.md`；「把来源塞进作业依据当前缀」的捷径明确否决——读的人会把它当作业依据，属「接错看着像接对」那一类。
  - **收寄可导但运行期被挡**：`ports.ParcelIdentityView` 全仓无生产实现，`RECEIVED` 行今天一律答未决且不落库。导入口接显式未配置替身（同 `cmd/parcel-api` 装配点的处置），开工前把这一点打印出来，`REFUSED` / `SCAN_ONLY` 两支不经身份核对照常落库。绝不交回空候选顶替——零候选是「查过了，查无此标识」的业务答案，拿它顶「没查」会把一件没核对过身份的实物记成已核对。
- **模板属机制半边，模板里的取值属实例半边。** 模板的字段名、必填与格式现在就定；节点标识、租户、操作者一律留空拒默认，示例行只用合成值。租户由 `-tenant` 给出而不让文件自报，依 [ADR-0003](./0003-group-tenant-legal-entity-customer-account.md) 租户是最高隔离边界。
- 期限到期后导入口启动即拒，**而一线作业客户端未必已开工**——这是有意的：那时缺的能力会立刻显形并逼出排期决定，而不是让过渡口静默续命。这条后果就是拆除期限的目的，不是它的缺陷。

## Alternatives

- **A. 一线端 MVP 加速自建。** 未采纳（用户裁决）：周期以周计、赶不赶得上实施周需工程评估，且「先在线优先、离线容忍后补」与 ADR-0021「离线与弱网容忍是固有要求，不是后续增强」正面偏离——那是设计不出来就补不上的那类要求。
- **C. 客户旧系统导出经受控文件口导入。** 未采纳（用户裁决）：与「客户按我们流程改造运营」的承诺方向相反，数据谱系还要多标一层来源系统。
- **管理台加代录页面（选 B 的另一半读法）。** 细则①否决：它要在管理台加作业动词，正是用户硬约束点名要避免的产品痕迹；而 ADR-0021 的工作流论证说的就是这类界面给不出替代动作。
- **期限做成配置项或环境变量，便于运维延期。** 细则③否决：可被运维改掉的期限不是拆除期限。过渡口的历史规律是「临时」变永久，唯一挡得住的是让延期必须经过一次 ADR 与一次发版。
- **导入口做成 `parcel-api` 的一个端点，复用装配与准入。** 细则②否决：进端点表就进了产品的对外形状，过渡痕迹从此长在产品上；受控运维手跑的一次性动作不需要网络可达面。
- **不加来源标记，事后靠导入时间窗口反查。** 细则④否决：时间窗口不是事实的属性，一次补录或重放就失效；而两类来源一旦混进同一层，ADR-0005 的派生链上再也分不出哪条事实的时间可信。

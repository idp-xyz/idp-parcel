# ADR-0345：租户启用哪些国家 / 地区与币种是租户取值，由参与方与商业的登记册承载，本轮只登记与展示、不强制；新写入入口只收内置目录里的码

Status: Accepted（2026-10-29，Claude Code 会话代产品 owner 决（代决）：用户要把基础数据维护做到“租户启用范围”这一层，设计由协调方代决、作者落笔；用户未逐条过目，越权风险点待产品 owner 复核。）<!-- 索引注记 -->｜**启用范围**：某租户运营哪些国家 / 地区、哪些币种是租户取值（[ADR-0146](./0146-product-strategy-is-a-third-class-between-mechanism-and-tenant-values.md)），登记在 `party-commercial` 的只追加登记册里，没登记即“未配置”，不套默认、不拦截；**本轮不做按启用范围强制**。**写入边界**：新登记的法人注册国家、服务区域覆盖国家，以及结算政策、结算账户、价卡、参照序列、分户账等新登记入口的币种，只收内置目录里的码，目录外答业务格；构造函数与读回不动。落实 [ADR-0335](./0335-countries-currencies-and-units-are-product-built-in-read-only-reference-data-released-with-the-code-and-unit-conversion-keeps-precision-and-is-not-yet-wired-into-pricing.md) 越权风险点 1、2 点名的后续轮次中“租户启用范围”与“码校验收紧到目录成员”两项。

Date: 2026-10-29

## Context

取证于 main `b8fe76a42`，只记 `S`。

- ADR-0335 把国家 / 地区、币种、计量单位做成产品内置的只读目录，并明说两件事留给后续轮次：某租户只收哪些国家 / 币种（启用范围），以及把码校验收紧到目录成员。当时没有为它们留任何半成品入口。
- 租户今天没有地方登记“我们运营哪些国家和币种”。基础数据页只能查目录，看不出本公司启用了哪些。
- 目录外但形状合法的码今天在各写入口被照常接受：法人注册国家只验两位大写，服务区域覆盖国家同，结算政策、结算账户、价卡等币种只验非空或三位大写。盘点见下文“盘点结果”。
- 启用范围不是公开标准，也不是“系统遇到这类情况怎么判断”的方法——它回答的是“这个租户具体运营哪些”，按 ADR-0146 的分界检验是租户取值：留空、拒绝默认值，那一格如实答“未配置”。

## Decision

**一、启用范围是租户取值；本轮只登记、读回与展示，不强制。** 某租户运营哪些国家 / 地区、哪些币种，由租户自己登记。没登记就是“未配置”：不套默认（不把“目录里全部”读成启用，也不把“没登记”读成停用），也不拦截——一个码没登记，所有写入口与业务照常接受它。本轮没有任何写入口读取启用范围；“登记后某个码被停用就拒绝新数据用它”是后续轮次的强制，见越权风险点 0。

**二、登记册归 `party-commercial`，不归 `platform`。** 登记册有租户、有生命周期（启用 → 停用 → 再启用）、有登记责任方，是租户取值的版本化登记册——`party-commercial` 正是拥有这一类登记册的上下文（注册号类型目录、参与方身份、产品—渠道映射同形）。`platform/refdata` 保持纯数据：ADR-0335 决定二给它的定位是“没有生命周期、没有写入它的业务动作”的内置目录，把租户的写入搬进去就破了这个定位，也会逼 `platform` 依赖数据库与租户模型。方向仍是 `party-commercial` 的领域包导入 `platform/refdata` 查成员，不反过来。

**三、登记册的形状：只追加、修订连续、最新生效导出。**
- 键是租户 + 种类（封闭两词 `COUNTRY`、`CURRENCY`）+ 码 + 修订；修订从 1 起连续递增，启用与停用都是追加一条新修订，不改写、不删除；撞键时按内容比，同内容是重放（已登记）、异内容是冲突，两者都是封闭代数里的答案而不是错误（[ADR-0031](./0031-owned-repository-write-outcome-is-a-closed-algebra-not-an-error.md)）。每行说：状态（封闭两词 `ENABLED`、`DISABLED`）、生效时点、来源单据（登记者写下的凭据引用，可不填，不填时是空，上限 200 字）、登记责任方、登记时间。
- 新修订的生效时点不得早于前一修订的（相等时后到者取胜）。否则“最新一行”会读成一件没人想表达的事：前一条预告了 7 月停用，后一条想取消它却写成 6 月生效，预告照样在 7 月起效。
- 此刻是启用还是停用，由“生效时点不晚于此刻的最新一行”导出，先比生效时点、再比修订，不存状态列。没有生效的行（压根没登记，或全是未来生效的）答不出来，就是“未配置”，不折成启用或停用。
- 码必须在内置目录里（`refdata.Country`、`refdata.Currency`，国家码不能当币种登，反之亦然）：目录外的码在登记口答业务格 `NOT_ACCEPTED` / `CODE_NOT_IN_CATALOGUE`（HTTP 200，业务判别进响应体，[ADR-0022](./0022-http-status-carries-answer-formed-not-business-verdict.md)），一个字节不写。读回的重建**不再核目录成员**——目录随发版变，ISO 废止一个码之后，此前合法登过的行仍读得回。
- 重放比对只看状态、生效时点与来源单据；登记责任方与登记时间是审计，不进比对（同修订同内容、不同操作者重放，答“已登记”，在册的仍是先到者）。同修订异内容答“内容冲突”，修订错位与生效时点早于前一修订各有各的封闭理由（`REVISION_OUT_OF_SEQUENCE`、`EFFECTIVE_BEFORE_PRIOR`）。

**四、写面与读面。**
- **写面是登记册配置写**（[ADR-0085](./0085-registry-write-faces-enter-the-endpoint-table-with-unconfigured-grade.md) 决定一那一族登记端点，[ADR-0100](./0100-operator-identity-is-a-product-owned-access-channel-family.md) 决定四），**不新增授予种类**：它登记的是租户的配置，不是委托侧或履约侧对某个对象作的运营决定（那一族按决定种类授予，[ADR-0151](./0151-unassigned-command-faces-get-their-families.md)），所以不走运营决定的授予形态，也就没有 `access_identity` 迁移。
- `POST /reference-data/enablement-registrations`：启用与停用同是追加一笔，所以只有一个口。载荷 `{kind, code, revision, status, effectiveFrom, source?}`；**租户与登记责任方只取自认证信封**（登记责任方写作“发行方#sub”，同 [ADR-0303](./0303-transport-fulfillment-operation-decisions-record-the-submitting-operator-as-operation-evidence.md) 决定二），载荷里带 `tenantId` 或任何自报身份的键一律按未知键拒；缺修订、缺生效时点、集外种类与状态是请求畸形（400）。答 `REGISTERED`（201）、`ALREADY_REGISTERED`、`CONTENT_CONFLICT`、`NOT_ACCEPTED` + `refusalReason`（200）。
- `GET /reference-data/enablement?kind=COUNTRY|CURRENCY`：挂“主数据与运营查阅读”，答本租户册上登过的每个码此刻的状态（`standing`：`ENABLED`、`DISABLED`、`NOT_CONFIGURED`）、最新修订号与全部历史；册上没有行的码不在结果里，“未配置”由缺席表达，端点不替登记方铺满整份目录。`kind` 必给。租户取自信封，他租户的行读不到；不分页，量以内置目录的大小为界（国家 / 地区与币种各一册）乘以人工登记的次数。
- 路径落在 `/reference-data/` 之下，是因为它的使用者是“基础数据”页；登记册的所有权在 `party-commercial`，处理器在 `internal/partycommercial/adapters/http`，由 `cmd/parcel-api` 的商业特性装配（不经 `refdatahttp`，那是 `platform` 下不依赖任何上下文的纯目录读口）。

**五、新写入入口收紧：只收内置目录里的码。** 只收紧**新登记**的写入边界，答业务格而不是 5xx：
- **法人注册国家**：登记责任法人身份时，新登记与新修订带的注册国家 / 地区不在国家 / 地区目录里，答 `NOT_ACCEPTED`（`party-commercial` 应用层 `checkLifetimeNumbers`，在按注册号类型目录判号之前）。重放与读回不经这道门。
- **服务区域覆盖国家**：登记服务区域版本的覆盖国家不在目录里，答 `REFUSED` / `COVERAGE_COUNTRY_NOT_IN_CATALOGUE`（`network-routing` 应用层 `normalizeServiceAreaCoverage`；新增一格拒绝理由，与形状不成形的 `COVERAGE_MALFORMED` 分开——恢复动作不同）。
- **币种**：结算政策版本的币种（发布载荷与受控批文两条路，另含受控 CLI 登记的商业选择键的结算币种）、结算账户、供应商应付账户、越权升级上限、价卡（价表导入的币种格）、参照序列、新开分户账；目录外的码按各入口既有的拒绝方式拒（载荷逐格问题、导入格校验问题、登记问题，均为业务格）。
- **不收紧**：记账、金额事实、资金事实、供应商账单、评价请求等事实类入口——外部真实单据可能带目录外的币种，它们不是“登记租户配置”；任何领域构造函数（`NewCurrency`、`NewCurrencyCode`、`NewRegistrationCountryCode`、`NewServiceAreaCoverage`）与读回路径；注册号类型目录登记的国家键（它是租户的登记册，不在派单点名的三类入口里）。

**六、不动构造函数与读回。** 收紧的门全在写入边界（应用层或传输译装层），领域构造函数仍只验形状。理由有二：一是构造函数同时是读回的重建门，目录随发版变，ISO 废止或更名一个码之后，若重建门查目录，已在册的行会读不回，整本册面按“坏数据”上抛；二是已有数据（演示租户之外的历史数据、合成码）照样读得回、照样参与解析与评价，收紧不制造悬空。代价是目录外的存量数据不会被这一轮清理，见越权风险点 3。

## 盘点结果

取证于 main `b8fe76a42`，只记 `S`。

- **演示种子**（`scripts/demo-seeds/data` 与 `steps`、`demo-run`）里登进库的国家码只有 `CN`、`SG`，币种码只有 `CNY`、`SGD`，**全在目录内**：种子不需要改，一次性库灌种子验过（见票面完成记录）。
- **测试夹具**里目录外的码，按用途分两类：
  - 走到被收紧入口的：法人身份与服务区域覆盖用例里的 `XA`、`XB`（ISO 用户指派码）、结算账户 / 应付账户 / 越权升级上限登记用例里的 `XTS`（ISO 测试币种码）、商业选择键用例里的 `SYN`，已改成目录内的真码（`CN`、`SG`、`CNY`）；结算政策、价卡、参照序列、分户账的既有用例本来就用目录内的币种，没有改。逐文件的清单在票面完成记录。
  - 不走被收紧入口的（注册号类型目录登记的国家键、领域包里纯形状校验的单元用例、读回路径、事实类入口的币种）：不动，它们正是“构造函数与读回不动”“事实类入口不收紧”的证据。
- 没有为了让测试通过而放宽任何一道门；每个被收紧的入口各有一条“目录外的码答业务格、目录内的码照常”的用例。

## Alternatives considered

- **登记册放进 `platform/refdata`。** 否决：违背 ADR-0335 决定二给它的“没有生命周期”的定位，且会让 `platform` 依赖数据库、租户模型与登记责任方（决定二）。
- **新建 `reference-data` 限界上下文。** 否决：ADR-0335 已否决过一次；启用范围虽有生命周期，却没有独立的领域语言和不变量，只是 `party-commercial` 已拥有的那类租户登记册的又一本。
- **放进 `platform` 的租户配置，或 `pilot-governance`。** 否决：前者没有这样的上下文；后者拥有的是试点阶段决定与暂停，不是租户的业务主数据。
- **用一张可更新的状态表（每码一行，启用 / 停用就地改）。** 否决：违背登记册只追加的做法（注册号类型目录、参与方身份等同类册都是新修订追加），事后无从回答“当时凭什么、谁、何时启用”，也无法表达“预告 7 月停用”。
- **本轮就做强制：写入时读启用范围，停用或未启用的码被拒。** 否决：“未配置”要不要等同于“不允许”是业务取舍——若等同，没登记过的存量租户一夜之间什么都不能写；若不等同，强制只拦已停用的码。两种都改变业务结果，需要产品 owner 裁决，本轮不替它选，也不留半成品入口（决定一）。
- **把启用范围登记收进运营决定那一族授予。** 否决：见决定四；运营决定按决定种类授予，是对具体对象作的决定，而启用范围是租户配置。
- **让构造函数查目录（一刀切收紧）。** 否决：见决定六；会让读回因目录更新而失败，也会无声改变已在册数据的可读性。
- **按币种 / 国家各建一张表。** 否决：两本册的形状、规则、读写面完全相同，仅有种类一词之差；分表只会复制一遍代码。

## Consequences

- 新增 `party-commercial` 的登记册（领域、编排、PostgreSQL 适配器、迁移 `0043_reference_enablement.sql`）、两个端点（登记、读回），`cmd/parcel-api` 登记两行端点；不新增授予种类、不改 `access_identity`。
- “基础数据”页的国家和地区、币种两签各多一列“启用状态”（已启用 / 已停用 / 未配置），有登记写授予者每行有启用 / 停用动作；页头说明“未登记的国家和币种不受限制，登记后才显示启用状态”。
- 新增 `refdata.CheckCountry`、`refdata.CheckCurrency`（成员判断与统一的一句话）；各写入边界用它们，措辞一处定义。
- 法人身份登记新增一道门：目录外的注册国家答未受理。已在册的目录外法人读得回，但对它登记**新修订**（含不改身份层的内容更正）时，身份层按“新修订必须带注册国家 / 地区与终身注册号”的现行规则要重新通过这道门，因此需要先带身份更正依据把注册国家更正为目录内的码。
- 服务区域覆盖、结算政策等已在册的目录外数据不迁移，继续读得回、继续参与解析与评价。
- 登记责任方与登记时间进读回，管理台的历史面可以显示；本轮管理台只显示此刻的状态与动作，不做历史面。

## 越权风险点

0. **强制拦截是后续轮次。** 本记录不让任何写入口读启用范围（决定一）。“未配置”等不等同于“不允许”、停用的码拦不拦已有的在途数据、强制发生在哪些入口，都是需要产品 owner 裁决的业务结果。归产品 owner。
1. **启用与停用只追加、不删。** 登记错了只能追加更正，不能抹掉（决定三）。要提供“撤销一条登记”的话，也只能是追加一条撤销，不是删行。归产品 owner。
2. **码目录随发版变，已启用的码若被 ISO 废止。** 册上的行照旧在、照旧读得回（决定三），读回口仍带出它；但管理台按目录逐行列出，目录里没有的码不会出现在页面上，操作者在页面上看不到它、也停不掉它。是否在页面或读回里标出“已不在目录里的已登记码”，是后续的呈现裁决。归产品 owner。
3. **收紧只在写入边界。** 目录外的存量数据（历史法人、覆盖、价卡等）不迁移（决定六）；对目录外法人登记新修订会被拒，需要先更正注册国家（见 Consequences）。是否批量清理存量，另议。归各上下文 owner。
4. **授予面沿用登记册配置写，不另开能力面。** 谁能登记启用范围与谁能登记注册号类型、产品映射是同一批人（决定四）；若日后要把启用范围收窄给更少的角色，要另开能力面。归访问身份 owner。
5. **生效时点不得早于前一修订的（决定三）。** 这排除了“登记一条补丁式的、生效时点更早的更正”的写法；要追溯更正只能用相等或更晚的生效时点。若业务需要真正的追溯更正（回写历史上某个时点的状态），要另立决定。归产品 owner。
6. **来源单据可不填（决定三）。** 其他登记册的依据格是必填；这里放宽是因为管理台表单要允许不填。若产品 owner 要求每笔登记都带依据，改为必填是一处收紧，不改历史。归产品 owner。
7. **收紧的入口清单取舍（决定五）。** 事实类入口（记账、供应商账单、资金事实、评价请求）不收紧，是因为外部真实单据可能带目录外币种；注册号类型目录登记的国家键也未收紧，因为它由租户登记、不在点名范围内。哪些入口算“登记租户配置”有判断余地，漏掉的入口可后续补门，不会破坏本记录。归产品 owner。
8. **读回不分页（决定四）。** 量以目录大小与人工登记次数为界，若日后某个码的修订数异常多，要加分页。归访问身份 owner 与产品 owner。

## Context

取证时（`main` 于 `8d6f5ffba`）的现状：

- 客户下单时每个包裹只有一组扁平的货物字段（品名、数量、申报价值、币种、原产地）。首方提交口把它们拼成规范化条目；[小包托运 CONTEXT](../domain/parcel-shipment/CONTEXT.md)「客户原始资料版本」词条当时写着版本只另外保留声明测量与地址要素，「其余条目只进摘要，不留原文」。客户报的货物在系统里没有可读的值。
- 资料修订只有寄件地、收件地与声明测量三个资料组，货物改不了；关务只持客户原始资料的版本引用，没有读货物值的口。
- 客户的订单号只能作为「客户参考号」挂在委托上，一份委托一个。
- [ADR-0370](./0370-warehouse-outbound-dispatches-by-product-network-owner-label-or-owner-pickup-and-the-remaining-warehouse-gaps-are-decided.md) 决定五与仓配履约 CONTEXT 已要求仓配交来的每个申报格带来源标记（本单申报、箱单或商品申报资料），[UC-PS-001](../application/parcel-shipment/UC-PS-001-SUBMIT-SHIPMENT-REQUEST.md)「给开发的交接」仓配出库一行写着这些条目落在哪里「要随这条路径一起定」。
- 小包托运的规范化代码头注写着：尚无领域模型的内容（当时点名寄收件范围与服务要求）拿到模型时，按 [ADR-0014](./0014-versioned-canonicalization-shape-for-content-digest.md) 开 `PSC-2`，不在 `PSC-1` 上就地扩列。[ADR-0267](./0267-a-key-added-to-an-already-canonicalized-body-is-a-shape-change-even-when-old-documents-stay-byte-identical.md) 决定三另许首个租户实例进生产之前同号改形，前提写明即可。

外部的变化让逐行资料成了刚需：欧盟自 2026-07-01 起对 150 欧元以下的低值包裹按「件」征 3 欧元关税，件按税则归类算、不按数量；美国 2026-06 无限期暂停 800 美元小额豁免，邮件渠道要申报原产国与价值；欧盟 ICS2 要求逐物品至少六位 HS 编码与具体品名；亚马逊要求每一箱都给箱内明细，不给按件收人工处理费。

货物挂在哪一层，头部系统按所处的层各不相同：电商 ERP 挂在销售订单行上；国际快递（DHL、FedEx、UPS）一票一份商品清单挂在运单上，包裹只有重量尺寸；邮政与跨境小包（UPU CN22/CN23、国内小包物流商）一单通常一件，挂在每个包裹上；FBA 头程与货代是「商业发票 + 装箱单」两层，亚马逊要逐箱明细。本记录的首稿照邮政做法挂在包裹上，随后用两种场景检验时不成立：FBA 同款多箱（五十箱同一 SKU）要把同样的品名、税号与单价抄五十遍，改一个税号要改五十处；快递式一票多件只有整票发票、不知道每箱装了什么，挂包裹就报不出来。挂在委托上加逐包裹的装箱分配，这两种都装得下，单件小包又退化成与邮政做法等价。各出处与取证日期记在票面。

## Decision

**一、货物明细归小包托运，是客户原始资料的一部分，挂在委托上。** 它是客户（或以货主名义代办的仓配履约）对这份委托装了什么的声明。它不是销售订单、不是仓配履约的商品，也不是关务的正式申报资料或申报货物项。小包托运不拥有订单，不把行解析成商品，不判断归类与合规。

**二、货物明细由内件性质、货物明细行与装箱分配三部分组成。**

- 内件性质：委托一格，封闭六格，参照 UPU CN23：礼品、文件、商业样品、退回货物、销售货物、其他；选「其他」可带一段说明。可缺。
- 货物明细行：至多 999 条，有序，相当于商业发票的行；一种货的品名、价值、编码与原产国只写在一处。上限是产品机制；某个渠道或申报口更严的上限是渠道与关务的取值。内件性质为「文件」时可以没有行（文件不逐项报货），这时也不报装箱分配；其余情形至少一行。
- 装箱分配：各包裹装了哪几行、各多少，每条记（包裹，行号，数量），相当于装箱单。
- 不另存合计。合计、按币种汇总、逐包裹的价值由需要它的消费方按行与分配算。

**三、装箱分配要么不报、要么报全。**

- 不报：单件委托不必报，唯一的包裹装着全部行；多件委托不报即整票清单，不知道每箱装了什么，快递式一票多件即此形。
- 报全：每个包裹至少一条；每一行在各包裹上的数量之和等于该行数量，该行数量必须在场，计量单位随行；每条只指这份委托声明的成员与这一版的行号，同一包裹同一行至多一条，数量是正数。单件委托报了也按这一条核。
- 只报一部分包裹、指不存在的包裹或行、数量之和对不上，答请求形状不对。这是同一份声明内部的结构，不是跨来源核对，所以与决定六的不核对口径不冲突。
- 多件委托是否必须报全由所采用接单规则包说（FBA 类服务产品与逐件报关的线路会要求），产品不内置，没配置就不判。
- 包裹被真实拆分或合并之后，装箱分配仍指声明成员，不随实物改写；消费方经包裹身份谱系把来源成员的分配推到后继包裹，推不下去（不知道拆出的哪一件装了什么）时是消费方那一格的资料缺口，由节点实测或客户更正补齐。

**四、行号是版本内的序号，修订整组替换。** 行号按声明顺序从 1 编起，不跨版本延续，也不另立行键；客户原始资料版本不可覆盖，所以（资料版本锚，委托，行号）这个引用本身稳定。资料修订以委托级资料组「货物明细」进行，内件性质、行与装箱分配一起整组替换；补充与更正都交来完整的新货物明细，显式清空清掉整组。允许声明那一格（资料组 × 阶段 × 意图）是租户取值（`PAR-COM-13`），没声明答等复核；作用于整份委托的范围按其成员中最靠后的资料修订阶段判。增删行或改分配不是增删委托成员。

**五、货物明细进客户原始资料版本保留的封闭要素内容。** 与声明测量、地址要素并列，按版本锚可读；提交版本与接受基线同样保留。它不再只进摘要。

**六、行的格，每格可缺，在场的原样保存客户给的串。**

- 品名：一组（语言标签，文本），同一语言标签至多一条；语言标签原样保存。
- 数量与计量单位：单位缺席就是没报，不默认为「件」。
- 单价、行总价与币种：一行一个币种，同时作用于单价与行总价；两格都可报，可只报一格。
- 净重与重量单位：整行的净重，即该行全部数量的合计，与 CN23 逐行净重同一口径。
- 申报商品编码：至多两条，口径封闭为出口侧与进口侧，同一口径至多一条；位数原样。
- 原产国（地区）码。
- 货主商品编码：货主自己的商品编码（SKU），不透明引用。
- 销售订单引用：这一行货出自哪张销售订单——销售平台、订单号、订单行号，三格都可缺，一行至多一个引用。合单时一份委托里的几行可以指不同订单；拆单时几份委托的行可以指同一张订单。它是引用，不是订单：小包托运不拥有、不核对、不据它找任何对象。

小包托运不校验、不换算、不交叉核对：单价乘数量与行总价、各行净重与声明测量的毛重、各行价值与保价要求的声明价值、编码位数、国家码格式，一概不判，与 [ADR-0048](./0048-declared-measurements-are-verbatim-member-profiles.md) 和「地址要素」同一条保真口径。只有形状错答请求形状不对：一行一格都没有、超过 999 行、同一语言两条品名、同一口径两条编码、数量或金额不是数、在场的格没有来源标记或带 NUL，以及决定三列的装箱分配形状错。必填与跨字段条件是接单规则包的取值（`BD-PS-006`），没配置就不判必填。

**七、申报格带来源标记，装箱分配不带。** 申报格指内件性质与行里各格。标记封闭三格，照 ADR-0370 决定五：本单申报、箱单、商品申报资料。客户渠道交来的一律是本单申报，由接入口记，不由客户声明。装箱分配说的是货在哪一箱，不是申报内容；它的出处随委托的来源：客户渠道的是客户声明，仓配出库的取装箱记录，整箱出取箱单。

**八、规范化在 `PSC-1` 上同号改形。** 货物明细、平台货件与每箱的平台箱标号成为提交规范化文档上的可缺键：没报即不编码，旧载荷逐字节同前，已存摘要与重放照旧成立；补充的 `PSU-1` 与提交共用同一编码，同样如此。前提照 [ADR-0267](./0267-a-key-added-to-an-already-canonicalized-body-is-a-shape-change-even-when-old-documents-stay-byte-identical.md) 决定三：首个租户实例进生产之前，已存摘要只在演示库与测试夹具里，进生产的构建都认得新形。首个租户实例进生产之后再改形，照 ADR-0014 换号。资料修订的规范化形状随实现照同一前提处理。首方 API 的字段形状由实现票按 [ADR-0140](./0140-first-party-api-contract-is-generated-from-endpoint-descriptors-with-url-major-version-and-problem-details.md) 定。

**九、关务按行取用，形成规则归关务。** 关务按（资料版本锚，委托，行号）取行与它的来源标记，按装箱分配把行推到包裹，形成正式申报资料时逐行溯源。把同税号、同原产地的几行并成一个申报货物项，用单价乘数量补出行总价，币种折算，选哪种语言的品名，取哪一口径的编码，按分配算逐包裹的价值，都是关务的形成规则。单价与行总价都报了却对不上时取哪一格、要不要复核，是关务的形成规则：平台折扣后对不上是常态，不当作来源冲突一律推进人工复核。需要逐包裹申报而多件委托没报装箱分配，或真实拆分之后推不下去，是关务那一格的资料缺口。并成的那一项，关务叫申报货物项（关务 CONTEXT 同名词条）。

**十、仓配按装箱记录汇成行与分配。** 仓配履约代货主提交时，这份委托所含包裹的装箱记录里每个商品汇成一行（整箱出取各箱箱单，同样按商品汇成一行），数量按商品的基本单位；装箱分配取各包裹的装箱记录（整箱出取箱单）；货主商品编码取商品编码；组合商品按组件出的按组件成行，按成品出的按成品一行。各申报格按 ADR-0370 决定五取值并带来源标记，都没有的照实空着。出库请求目前不带销售订单号，仓配交来的行这一格照实空着。

**十一、下列不在本记录。**

- FBA 头程怎样承接（一个平台货件一份委托、平台货件号与箱标号、仓配平台备货的提交方式），以及号码的界面叫法：见 [ADR-0374](./0374-dedicated-line-fba-headhaul-is-an-ordinary-shipment-request-one-platform-shipment-one-request-one-carton-one-parcel.md)。
- 货物特性与危险品（带电、液体、粉末、磁性之类）：渠道准入与航空安全的输入，消费方是路由与渠道择优，取值体系要单独定。
- 收件人税号、IOSS、EORI：收件资料或关务角色资格。
- 运费、保险费、发票号、许可证与证书号：计价与关务估价，或关务的监管凭证。
- 材质、用途、品牌、规格型号、销售链接：本期写进品名；要单列时照 ADR-0014 换规范化版本。
- 按销售订单号查委托与包裹的读口：随实现另定。

## 对已接受记录的作用

不停用任何已接受记录的条款。ADR-0370 决定五（整箱出取箱单、缺的申报格取商品申报资料、带来源标记）照旧成立，本记录给它的条目定名定形。ADR-0048 的声明测量照旧是成员级保真画像，与货物明细并列。外部标识里委托级的客户参考号照旧，与行级销售订单引用并存：前者是客户这一票的号，后者说某一行货出自哪张订单。决定十从装箱记录取，与 ADR-0368 决定四「货物内容取自出库请求的商品明细」一致：出库复核不符不打包，装箱记录就是出库请求商品明细按包裹的落实。

## Consequences

- 关务第一次能读到客户报的货物：品名、税号、原产国、价值逐行可取，欧盟按件计税、美国逐行原产国这类规则才有输入；逐件报关的线路靠装箱分配推到每个包裹。
- 一种货的值只写一处。FBA 同款五十箱是一行加五十条分配，改税号只改一处；快递式一票多件只报整票清单也收得下。
- 单件小包与首稿等价，不多一样东西要报。
- 版本里多存一段货物明细。规模由 999 行的上限封住；货物明细不是身份内容，跨上下文照旧只交引用。
- 修订是委托级整组替换。改一行要重交整组；两个请求同时改同一委托的货物明细，靠基础版本核对分先后，后到的照既有规则成冲突。
- 小包托运对行一格都不核。单价与行总价对不上、行价值合计远高于保价声明价值，这些错报要靠租户的接单规则或关务的人工复核拦。
- 合单、拆单靠行级销售订单引用表达；按订单号找回委托的读口还没有。仓配交来的行没有销售订单号。
- 规范化不换号：新键可缺、没报不编码，旧载荷的摘要逐字节同前。代价是这一次同号改形要在本记录写明前提，首个租户实例进生产之后不能再这样做。
- 带电与其他危险品在接单时仍无从按货物识别，渠道准入暂靠渠道约束与人工。

## Alternatives considered

- **货物挂在每个包裹上（本记录首稿）。** 与邮政 CN22/CN23 一件一单对齐，单件小包最直接。否决：FBA 同款多箱要把同样的值抄几十遍、改一处要改几十处；快递式一票多件只有整票发票时报不出来。
- **开 `PSC-2`。** 照 ADR-0014 默认换号，最守规矩。否决：重放分类逐字比摘要串，新旧版本的摘要永不相等，同一请求重发会被判冲突；要么给提交、补充与修订三条路各加按前缀分版本的比对，要么接受误判。首个租户实例进生产之前，ADR-0267 决定三许同号改形，可缺键又让旧载荷逐字节同前，代价最低。
- **只挂在委托上，不要装箱分配。** 与快递 API 对齐。否决：亚马逊要逐箱明细，邮政式逐件报关要知道每件装了什么。
- **委托与包裹两处都能报货物，客户任选。** 两种习惯都照顾到。否决：同一份货有两处权威，下游要先判以哪处为准，违反单一权威。
- **只改接口与表单，把条目名改成 `goods[0].*`、`goods[1].*`，领域不建模。** 改动最少。否决：行没有形状，修订、关务溯源与来源标记都无处挂；PSC-1 的头注明确不让就地扩列；版本照旧不留原文。
- **行有跨版本的身份，修订按行增删改。** 改一行只传一行。否决：要另造行键、处理行级并发合并；关务溯源用（资料版本锚，委托，行号）已经稳定；国际上的报关单与物流商的修订接口都是整份重报。
- **建一个销售订单对象，委托与包裹挂在订单下。** 电商 ERP 是这样做的。否决：订单是卖家与平台的交易，归货主；物流方只需要引用，拥有它就要跟订单的改价、退款、取消同步，那是另一个产品。
- **销售订单号挂在包裹或委托上。** 少一层。否决：合单时一个包裹里的几行出自不同订单，包裹级一个号表达不了。
- **委托级一个币种。** 与 CN23 一份报关单一个币种对齐。否决：仓配的商品申报资料逐商品带币种，强行合一就得由小包托运或仓配折算，等于改写客户的声明；折算归关务。
- **小包托运核对单价乘数量等于行总价，不等即拒。** 拦住一类错报。否决：平台折扣后行总价常常不等于单价乘数量，按算术拒单会拒掉真实订单。
- **把货物特性（带电等）一并定下。** 中国跨境小包按普货、带电、敏感分渠道是常态。否决：它的消费方与取值体系都在路由与渠道准入一侧；单独定。

## 越权风险点

1. 挂委托加装箱分配（决定二、三）：单件以外的委托多一层分配要报；分配报全的判据是逐行数量之和，计量单位随行不换算。归 PS owner 与 CC owner。
2. 保真不核（决定六）：小包托运对单价、行总价、净重与价值合计一格不核，错报要靠接单规则包与关务拦。归 PS owner 与 CC owner。
3. 委托级整组替换（决定四）：没有行级修订；并发改同一委托的货物明细，后到的成冲突。归 PS owner。
4. 内件性质（决定二）：六格取自 UPU CN23，委托一格；同一委托里的包裹性质不同时要拆委托。归 PS owner 与 CC owner。
5. 两口径编码（决定六）：只分出口侧与进口侧；有的国家另要出口退税编码或本国附加码，到时要换形状。归 CC owner。
6. 销售订单引用（决定六）：只是原样引用，不核对订单真实存在；按订单号找回委托的读口另做。归 PS owner。
7. 仓配汇行规则（决定十）：按装箱记录汇成行、数量按基本单位、组合商品按出库方式成行、出库请求不带销售订单号。归仓配履约 owner。
8. 不纳入货物特性（决定十一）：带电件在接单时无从识别。归产品 owner 与路由 owner。
9. 999 行上限（决定二）：产品机制，不是任何真实渠道的取值。归 PS owner。
10. 同号改形（决定八）：依赖首个租户实例尚未进生产这一前提；前提一旦不成立，下次改形照 ADR-0014 换号。归 PS owner。

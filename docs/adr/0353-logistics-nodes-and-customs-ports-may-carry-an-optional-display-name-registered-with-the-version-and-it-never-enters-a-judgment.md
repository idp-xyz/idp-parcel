# ADR-0353：物流节点与口岸各可随版本登记一个可选的显示名称；名称只供人辨认，不是身份、不进任何判断与出处，没登就读不到这一格、照旧以编码称呼；改名是登一个新版本；口岸册把名称并入同一起点的重放比对；两册都没有规范化正文，ADR-0267 的换号判据不适用，旧行与旧答法逐字节不变

## Context

取证于 main `b2c1505c7`，只记 `S`。

- 用户 2026-11-01 在管理台的网点与口岸页上要看到名称而不是只看到 `SYN-NODE-SHA-HUB` 这样的编码，裁定「网点、口岸各加一个可选的显示名称，随版本登记；没登名称的照旧显示编码」。页面上的「网点」就是领域里的物流节点（[GLOSSARY「物流节点」](../domain/GLOSSARY.md#物流节点)）。
- 网络目录的节点版本行（`ports.NodeDefinitionVersion`）只有身份、修订号、业务时区、生效区间与依据；运营查阅读口 `nodeVersionBody` 逐字段透出这几格。登记输入经 `registrationjson` 翻译，未知键一律拒（`decodeStrict`）。稳定定义各族可以直接登记，也可以带 `adopt` 采用参考配置（[ADR-0147](./0147-reference-configuration-ships-embedded-and-is-adopted-through-ordinary-registration.md)）；采用行只许出现身份、修订号、生效时点与 `adopt` 几个键，内容取自参考配置。参考配置按 [ADR-0146](./0146-product-strategy-is-a-third-class-between-mechanism-and-tenant-values.md) 决定三不放租户、修订号与生效时点。演示种子的四个节点修订 1 都是采用行。
- 网络目录没有重放语义：同一（租户，节点，修订号）再登由主键挡下，答错误（`RegisterNodeVersion` 头注「重复版本号由主键挡」）。每笔登记推进目录修订，路由判断提交前按目录修订重校。
- 口岸目录一版的键是（租户，口岸，生效起点），此前没有内容格；登记编排（`RegisterCandidatePort`）写口 `ON CONFLICT DO NOTHING`，撞上后按请求起点读回、逐字段比，起点相同即`已存在`，否则`内容冲突`。读口 `candidatePortBody` 只有口岸与区间。关务适用性判断的快照读口（`PortsPathsSnapshots`）取口岸与区间，目录版本引用与判断标识由它们算出。
- 两册都不存摘要，也没有规范化版本号。[ADR-0267](./0267-a-key-added-to-an-already-canonicalized-body-is-a-shape-change-even-when-old-documents-stay-byte-identical.md) 管的是「已接规范化的册（面）」加键；它决定三认的那一种进生产之后仍可同号改形的情形，正是「那一面不存摘要、两侧都从本体现算」。
- 两份 CONTEXT、GLOSSARY 与 ADR 里此前都没有节点名称或口岸名称。参数登记册：当前尚无租户实例，演示租户 `SYN-TENANT-01` 按真实租户对待（[ADR-0150](./0150-synthetic-tenant-is-treated-as-a-real-tenant-and-isolated-form-retires-per-face.md)）。

## Decision

**一、名称随版本登记，是那一版的一格内容，不另立名册。**（机制）

物流节点的名称落在节点版本行上，口岸的名称落在口岸目录的那一版上。改名是登一个新版本：节点登下一个修订号、从更晚的时点生效，口岸登一个更晚的起点；旧版本照留它当时的名称，按新版本的生效时间接续闭合（两册各自原有的换版写法，不新增）。同一版内的名称没有改写路径。

**二、名称可选；没登就读不到这一格，不拿别的顶。**（机制）

- 登记输入里名称缺席或写 `null` 即没登。给了就要成形，不成形整行拒，不截断、不去空白、不改写成别的串，也不落成没登——空白串是写坏了，不是没给（与依据格「给了就过构造门」同一条，见 `basisFrom`）。拒在翻译那一步：受控 CLI 非零退出，在线登记口答 400 `MALFORMED_REQUEST`，与依据格写坏同一格。
- 读口：没登名称的版本行上没有 `displayName` 键，不答空串，也不拿编码顶。读者（页面）照旧以编码称呼它。名称缺席是真话，与生效终点缺席即未闭同一个读法。
- 迁移之前登下的版本读成没登名称。

**三、名称的约束（产品策略）。**

- 不能是空白，首尾不能带空白（含全角空格、不换行空格）；字符串内部的空格照收。
- 至多 100 个码点（按 Unicode 码点计，不按字节、不按显示宽度）。真实的节点与口岸名称，中文名多在二十字以内，英文全称（如「XX International Airport Cargo Terminal 2 Sorting Centre」）也在六十字以内；100 给了余量，又远低于会让列表行失控的长度。行内放不下由页面截断显示，存的串不截。
- 不含控制字符（C0、C1、DEL）、格式字符（Unicode Cf，含零宽字符与双向覆盖符）与行段分隔符（U+2028、U+2029）。前两类在列表里看不出差别，却让两个看起来相同的名称不相等；双向覆盖符能让显示出来的字序与存下的不同。
- 不规范化：不改大小写、不做全半角或 Unicode 规范化。比较按存下的串逐字相同。
- 不要求唯一：两个节点可以叫同一个名字，身份仍是编码。名称不是检索之外任何读口的键。
- 库上加一条 CHECK 作第二道网（长度、非空白、首尾无空白、POSIX 控制字符）；格式字符与行段分隔符只由领域构造门拒。

**四、名称是租户取值；参考配置不带，节点的采用行可以随行给。**（机制，取值属租户）

名称是某个租户给自己网络里某个节点或口岸起的称呼，属 ADR-0146 三类里的租户取值。参考配置不带名称——它与租户、修订号、生效时点同理，不进参考配置的原文。采用一个参考配置节点时，采用行可以带 `display_name`，与它带的修订号、生效时点一样是采用方给的那几格；内容（业务时区）照旧只取自参考配置。别的族没有名称这一格：采用行带它答 `ErrAdoptedContentGiven`，直接登记行带它按未知键拒。

**五、名称不进任何判断，也不进出处。**（机制）

- 网络与路由：选版读口（`LoadDefinitionsAt`）不取名称；可达性判断、初始路由、复核、改路的候选、计划与依据都不读它。改名登一个新版本，与任何一笔登记一样推进目录修订（见 Consequences）。
- 关务：适用性判断的快照读口不取名称；作答、不可用理由、目录版本引用与判断标识与名称无关。
- 运营查阅上列（节点族）的检索词 `q` 除编码外也匹配名称，没登名称的行只按编码匹配。排序、筛选维与游标不动（[ADR-0144](./0144-catalogue-reads-share-one-cursor-pagination-sort-and-filter-contract.md)）。

**六、重放与冲突的判定。**（机制）

- 口岸册：名称是这一版的登记内容，同一起点重登时并入逐字段比对。起点与名称都相同（两边都没登也算相同）是`已存在`；名称不同是`内容冲突`，册面不动。因此迁移之前登下、没有名称的版本原样重登照旧`已存在`；给没登名称的旧版补名称，或给登了名称的版本去掉名称，都是`内容冲突`——要名称，登一个更晚起点的新版本。
- 网络目录：同一修订号再登照旧由主键挡，带不带名称都一样，先登的那一行一格不动。没有重放判定，也就不会因名称误判。

**七、与 ADR-0267 的关系：不适用，不换号也无号可换；它的两条关切逐条照顾。**（机制）

两册的登记内容都不经规范化、不存摘要，没有 ADR-0014 意义上的规范化版本，ADR-0267 决定一的换号判据管不到，本记录也不部分停用 ADR-0014。ADR-0267 要护的两样在这里这样落：

- **已存的字节与身份**：迁移只加一个可空列，不回填、不改写任何既有行；键、生效区间、排他约束、依据、目录修订一格不动。读口对没登名称的行答出的字节与加这一格之前逐字节相同（`displayName` 缺席）。
- **旧构建遇到新内容**：登记输入两侧都拒未知键，只认旧形的构建收到带名称的登记会响亮拒，不会把名称当未知键丢掉后照登。旧构建读到带名称的库行，它的查询不取那一列，答的是旧形。剩下的一格是口岸册的重放比对：滚动发布期间旧构建比对时不看名称，同一起点、不带名称的重登撞上新构建写下的带名称版本，旧构建答`已存在`而新构建答`内容冲突`——这正是 ADR-0267 决定三在进生产之后仍认的那一种（那一面不存摘要、两侧都从本体现算），差别只在旧构建比的字段少一格，答的方向是「已存在」而不是改写，册面不受影响。

**八、物流节点与口岸同一写法。**（产品策略）

两册同为可选、同为随版本、同一组约束、同一读法（读口键 `displayName`，没登即缺席）。登记输入的键名随各自登记口既有的拼写：网络目录 `display_name`，关务登记 `displayName`——同一个口不混两种拼写，比两口拼成一样更要紧。两个上下文各写一份约束检查，不共用：领域包互不依赖，`internal/platform` 只放技术设施；两边的用例各钉同一组边界。

**九、演示种子首版就带名称。**（演示租户取值，证据 `S`）

演示租户的四个节点与两个口岸各登一个中文名称，标识不变；节点由采用行给，上海枢纽修订 2 照登同一个名称。首版就带，不另登一版「补名称」：种子灌的是新库，补登一版只多一笔无意义的修订。存量演示库要 `scripts/demo-seeds/seed.sh --reset` 重灌才有名称；在没名称的旧库上重跑，节点撞同一修订号，口岸答`内容冲突`（决定六）。名称是合成的演示值，不是产品默认，也不是任何真实网络的名称。

## 候选与反方

- **另立一本名册，按编码存当前名称，可改写。** 否决：它会是网络目录与口岸目录里唯一能改写的东西，与「永久变化形成新版本，不覆盖原版本」相悖；历史版本当时叫什么就丢了；改名不留痕。用户也倾向随版本登记。
- **名称挂在身份上，不随版本。** 否决：身份层没有可登的东西（编码就是身份），改名就得换身份，牵动连接、线路、服务区域、日历里对它的引用。
- **名称必填。** 否决：名称是租户取值，没登要如实答没登，不能拒整版；既有版本与采用行会一下子都不合格。
- **名称进参考配置。** 否决：参考配置是产品发布的内容，名称是租户给自己网络的称呼（决定四）；而且改既有参考配置版本的原文会让它的发布摘要对不上。
- **没登时读口答空串，或拿编码顶。** 否决：空串让读者分不出「没登」与「登了个空的」；拿编码顶是替租户编了一个名称，页面也就分不出该不该提示补名称。
- **收下时去首尾空白、规范化。** 否决：静默改写会让存下的与登记方写的不是同一串字，重放比对也跟着变得难以解释；拒比改好，登记方改一下即可。
- **口岸册重放不比名称。** 否决：同一起点登两次、名称不同，后者答`已存在`就是把一份不同的内容说成重放，名称从此对不上登记方以为的那一个。
- **网点用 `name`、口岸用 `displayName`，或干脆复用 `title`。** 否决：`name` 在仓里多处指身份或枚举名；两册读口用同一个键，页面一套写法即可。

## 对已接受记录的作用

无条款停用。ADR-0267 决定一、三在本记录的适用与不适用见决定七；ADR-0147 决定四「租户取值（租户本身、修订号、生效时点）照旧由采用方显式给出，不代填」：名称同属租户取值，本记录决定四让节点的采用行多给这一格，是那一句的同一个读法，不构成停用。

## Consequences

- 网络与路由：迁移 `0033` 给节点版本表加可空列与 CHECK；`NodeDefinitionVersion` 多一格 `DisplayName`；登记翻译（直接行与节点采用行）、写口、运营查阅上列与检索、读口 `nodeVersionBody` 随之；选版读口不动。
- 关务：迁移 `0031` 给口岸目录加可空列与 CHECK；登记命令、写口签名、点读、上列与读口 `candidatePortBody` 随之；登记编排把名称并入比对；适用性判断的快照读口不动。
- 改名推进网络目录修订，与任何一笔登记相同：恰在提交前重校窗口里的初始路由判断会见到换代、按判断键再判一次。改名稀少，不为它另开不推进修订的写法。
- 管理台：`api.ts` 两处类型多一个可选字段。页面行首显示名称、编码进技术详情，另票。
- 演示种子首版带名称；存量演示库要 `--reset` 重灌（决定九）。
- CONTEXT：网络与路由「网络结构与适用范围」、关务「关务适用性判断」各加一条规则；GLOSSARY「物流节点」指向前者。

## 越权风险点

1. **代 NR、CC owner 定了名称落在版本行上、可选、不进判断**（NR、CC owner）。用户裁定了「随版本登记、可选、没登显示编码」，名称不进判断与出处、参考配置不带、采用行可以给是作者定的。
2. **100 个码点与字符类别是产品策略**（NR、CC owner）。若有租户的真实名称超长或要用被拒的字符，放宽是改 CHECK 与构造门，不动已登的行。
3. **口岸册的重放比对收紧了一格**（CC owner）。此前同一起点重登一律`已存在`；此后名称不同即`内容冲突`。没有名称的旧版原样重登不受影响。
4. **滚动发布期间口岸重放的答法新旧构建不一**（CC owner）。见决定七末句；它不改写册面，本记录不为它另加门。
5. **名称不唯一**（NR、CC owner）。两个节点同名时页面只靠名称分不清，要连编码一起看；本记录不在库上设唯一约束。
6. **检索匹配名称**（NR owner）。节点族上列的 `q` 多匹配一列；只按编码检索的结果不变，按名称检索能多中几行。

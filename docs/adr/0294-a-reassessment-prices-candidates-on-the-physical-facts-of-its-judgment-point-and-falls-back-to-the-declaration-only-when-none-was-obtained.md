# ADR-0294：复核与授权改路决定给候选出价取其判断点的物理事实，该取的一项也没有取得时才退回客户声明并标明；物理事实在而定不下用哪条时不退回，各段待判断

## Context

- NR CONTEXT 写的是按判断点分来源：预路由使用客户声明快照，首次收寄复核使用当时已经取得的物理事实，到站复核使用当前有效物理实测；ADR-0148 决定四第 7 条引同一句，UC-NR-003 目标与边界写「本用例必须重新使用已经发生的接货位置、控制依据和节点实测」。复核给候选出价的取数侧却与初始路由同一种装法，包裹事实一律取客户声明；取数侧端口只收判断键，不知道这是哪一种判断，也就选不了来源。
- 声明与实测不符的包裹，复核比出的成本、选出的候选与 CONTEXT 应得的不同；答案不错在结构上，错在依据，没有响亮失败，审计时从计划出处才看得出——而计划出处也不标事实出自哪里。
- `node-operations` 没有实际测量登记册（票 pp-pricing-input-seams/04），NR 读不到实测；收寄采用记录与权威运输交接随复核触发进来，都不带重量或尺寸。物理事实的来源因此还不存在，但复核该怎样用它、没有它时怎么落，是 NR 自己的规则，不必等来源。
- 票 demo-chain-gaps/115 评审时否决过「没有物理事实就把成本记成待判断」：复核一律排不了序，115 修的问题原样回来。这一格和「物理事实在而取用不定」是两件事，前者是没有，后者是有而不能挑。
- 授权角色据复核建议形成改路决定（ADR-0284）也要给候选出价，但它由操作者此刻发起，不是复核触发；CONTEXT 三个判断点里没有它。初始路由的最低成本并列由授权角色裁决（ADR-0309）则是初始路由的延续。

## Decision

**一、判断点四个，由调用方指名，不设默认；复核的判断点由触发所携的控制依据定。**（机制）

- `预路由`：初始路由判断及其最低成本并列的授权裁决。包裹事实取客户声明快照，不问物理事实来源。
- `首次收寄复核`：节点收寄与场外揽收触发的复核。物理事实截到收寄的业务时间（「当时已经取得」），晚于收寄才形成的实测不计；业务时间不变，重放得到同一份。场外揽收没有节点能称重，当时没有物理事实是常态，由决定三退回声明，不另立一格。
- `到站复核`：权威运输交接把包裹交进声明的接收节点触发的复核。物理事实取判断此刻仍有效的（「当前有效」）。
- `授权改路决定`：授权角色据建议形成的改路决定，不是复核触发。与到站复核同取判断此刻仍有效的物理事实：决定由操作者此刻发起，新计划从决定的时刻起生效（ADR-0284 决定四），按此刻的事实出价才对得上它生效的时点。
- 候选成本端口 `RouteCandidateCostSource` 的取成本口多收判断点一个参数，零值判断点不合法、取数侧据此响亮报错：每个取成本的调用点都得自己指名，漏写编译不过。

**二、有物理事实时按物理事实出价，物理事实来源是取数侧的一只端口。**（机制）

- 端口按（判断键，截至时刻）交回三格之一：一项都没取得、取得了（重量与外廓至少一项，必带事实引用）、在而定不下用哪条。读不回是依赖故障，以错误作答，不在三格里（ADR-0029）。
- 取得了的物理事实代替客户声明出价：声明不读（两项物理事实都在时）、不进事实引用。事实引用标明出自实际测量，和客户声明的引用成对，计价快照里认得出价是按哪一份算的。
- 来源是端口而不是 `node-operations` 的某个具体读口：登记册的形（对象身份、「仍有效」怎么记、多条怎么取用）是 NO owner 在票 pp-pricing-input-seams/04 里要裁的，本记录不预设；端口在 NR 消费侧适配器包里，NO 的读口立起来后写一个适配器实现它，不动取数侧其余部分。

**三、该取的物理事实一项也没有取得：退回客户声明出价，标明退回，排序照常。**（机制）

- 价与预路由同一份声明算出，依据标 `DECLARATION_FALLBACK`，不标成客户声明——审计要分得出「本来就按声明」与「该按实测而没有实测」。声明也没有则各段待判断（原有的缺格，不新增）。
- 读物理事实读不回不是「没取得」：原样上抛，复核按既有的依赖故障落法处置（无路由线回滚重投，失效线与仍适用线记候选评估未决或保留原计划）。折成「没取得」会在依赖故障时悄悄按声明出价，而且出价看上去与正常退回没有区别。

**四、物理事实在而定不下用哪条：不退回客户声明，各段待判断。**（机制）

- 同一对象同一测量项多于一条仍有效的实测、又没有已登记的取用规则时，机制不替租户挑「最近一次」或「证明力最高」（那是租户的实例半边，见票 pp-pricing-input-seams/04 形第 4 条）。这时客户声明不得顶替实测（NO CONTEXT「客户声明……不得覆盖实际测量」）：各段待判断、候选缺成本依据、没有成本出处，复核记录标 `PHYSICAL_UNRESOLVED`。
- 这是确定性的缺口，重投推不动，不进未决哨兵表；落进候选成本既有的「待判断」一格，与没登区、没挂依据同一处置（ADR-0029）。

**五、只取得一部分时逐项取，声明只补缺的项。**（机制）

- 重量与外廓各取各的：物理事实有哪项用哪项，缺的项取客户声明，依据标 `PHYSICAL_WITH_DECLARATION`，事实引用两路都在、先实测后声明。声明没有外廓则外廓缺席，依据仍是 `PHYSICAL`（没用到声明）。
- 只量到外廓而实重哪里都没有（声明也没有）：不能凭一个外廓出价，各段待判断，依据 `NONE`。

**六、包裹事实依据留痕：逐段成本出处与复核记录各记一格。**（机制）

- 依据是封闭集：`DECLARATION`、`PHYSICAL`、`PHYSICAL_WITH_DECLARATION`、`DECLARATION_FALLBACK`、`PHYSICAL_UNRESOLVED`、`NONE`。成本出处只记出了价的段，所以只收前四格；定不下与没有事实没有出价，只落在复核记录上。
- 复核记录上的依据是这次复核向取数侧要成本时取数侧交回的那一格；不形成计划的复核不留成本，候选评估是按声明还是按实测判的，只有这一格查得出。没向取数侧要过成本的复核（排序形态没声明、场外揽收仍适用线不试改善）不记，不被填成某一格。复核记录的依据不含 `DECLARATION`：那是预路由的依据，复核在任何判断点上都不按它出价，库面 CHECK 同此。
- 依据出现之前落库的成本出处，包裹事实一律取客户声明，读回为 `DECLARATION`，不另造「未知」一格。

**七、没有物理事实来源的部署如实装「一项都没取得」。**（机制）

- 生产装配里 `node-operations` 还没有实际测量登记册，物理事实来源装 `NoPhysicalParcelFacts`：复核恒走决定三，价与过渡做法同，区别是出处与复核记录如实标 `DECLARATION_FALLBACK`。它不是某个来源读空了，是根本没有来源——不假装读过一遍。
- 登记册与只读口立起来之后，换装的只有这一处。

## 候选与反方

- **没有物理事实就成本待判断（CONTEXT 字面）。** 否决：「没称过」是收寄当时的常态，场外揽收更是必然；一律待判断，复核一律排不了序、候选评估一律未决，115 修的问题原样回来。退回声明出的是一笔估价，成本比较本来就只为排候选、用完即弃（`routeCostEvidence`），标明来源即可；错的是不说。
- **退回声明但不标。** 否决：这是现状。审计分不出哪些复核按实测、哪些按声明，实测登记册接上之后更分不出「该按实测而退回了」与「本来就是声明」。
- **物理事实定不下时也退回声明。** 否决：声明顶替实测，出的价与正常出价没有区别，错得没有声响；这恰是 NO CONTEXT 硬句要防的。代价是这类复核候选评估未决，由人去登记取用规则。
- **首次收寄复核也取判断此刻。** 否决：同一次收寄触发重放或晚处理，会读到收寄之后才形成的实测，「当时已经取得」被偷换成「当前」；业务时间不变，答案才不变。
- **授权改路决定仍取客户声明（预路由那一份）。** 否决：它形成的新计划从决定时刻起生效，按受理时的声明出价，与同一时刻到站复核按实测出的价对不上，同一件包裹同一时刻两个口径。
- **每个判断点各拆一份取数侧实现。** 否决：差别只在来源与时点，成本合成、出处、币种换算一处；拆开会让两份各自漂。

## 对已接受记录的作用

- **部分停用（接上）** [ADR-0148](./0148-route-evidence-sourcing-candidate-cost-and-first-candidate-generation-form.md) 决定四第 7 条「包裹事实按 CONTEXT「预路由使用客户声明快照；首次收寄复核使用当时已经取得的物理事实，到站复核使用当前有效物理实测」取」一句：原句只说按判断点分来源，没有说物理事实缺席与取用不定时怎么办，也没有列授权改路决定；本记录接上这两处。**适用场景**：候选出价取包裹事实的各判断点；每段怎样折成价卡的区域词汇（已由 ADR-0189 接手）、NR 不自算计价重量、不自定区域与决定四其余各条不变。
- **不停用** [ADR-0284](./0284-an-authorized-role-decides-a-current-reroute-suggestion-through-an-operator-decision-face.md) 决定三（所携地理投影取法）、决定四（新计划从决定时刻起生效）：本记录只是给决定取成本多指名一个判断点。
- **读法**（不是停用）[ADR-0029](./0029-retrieval-failure-algebra-is-partitioned-by-recovery-action.md)：读不回才是未决，确定的缺口落既有的待判断；[ADR-0025](./0025-cross-context-adapters-live-on-the-consumer-side.md)：新增的依据值每个消费方有落点（见 Consequences）。

## Consequences

- 代码随票 code/66：`ports.RouteCandidateCostSource` 取成本口加判断点参数，`ports.RouteCandidateCosts` 与 `ports.ReassessmentRecord` 各加依据一格；迁移 `network_routing/0032`（复核册 `candidate_facts_basis` 列与封闭集 CHECK）；NR 消费侧适配器包加物理事实端口、合成取数侧与「没有来源」的实现；成本出处行模型多一个可缺的 `facts_basis`。
- 消费方落点：复核编排（三条线各记复核记录的依据）、授权改路决定与初始路由并列裁决（指名各自的判断点）、复核册读写、`cmd/parcel-dispatch` 与 `cmd/parcel-api` 两处取数侧装配。HTTP 译装与管理台不读这一格，运营暂时看不到它（越权风险点 4）。
- 文档：NR CONTEXT 复核成本那一条补判断点与三条落法；UC-NR-003 验收示例加 `AT-NR-106` 至 `AT-NR-110`、「给开发的交接」「复核取物理事实」一行改写；`.scratch/at-coverage-inventory.md` 补分桶行与追记。ADR-0148 的 Status 注记与 Links 加前向指针。

## 越权风险点

1. **退回客户声明而不是待判断**（NR owner，NO、PS owner 会签）。没有实测时复核按声明排序：声明严重失真的包裹，复核选出的候选可能不是实测之后会选的那一条，并据此失效、改路或形成首个计划。标明来源缓解的是审计，不是错价本身。owner 若要宁缺毋滥，改一处：把决定三退回的那一格改成待判断，其余不动；代价见「候选与反方」首条。
2. **授权改路决定取判断此刻的实测，是 CONTEXT 没列的第四个判断点**（NR owner）。CONTEXT 只列三个；这一格按生效时点类推。若 owner 认为决定应沿用建议形成那次复核的判断点，需要把触发的控制依据存进复核记录（现在不存）。
3. **逐项取（决定五）把声明与实测混在一份输入里**（NO、PS owner）。只称了重的节点，体积重用声明外廓算；声明外廓失真时，混合出的价比纯声明还偏。owner 若要禁止混用，改成物理事实不全即当没取得（走决定三），一处改动。
4. **依据只落库，运营看不到。** 复核册读面与管理台没有展示这一格；审计要查得读库。要展示是一个 HTTP 译装加管理台的改动，不在本记录。
5. **「截到收寄的业务时间」与「判断此刻仍有效」的口径取决于 NO 登记册怎样记「仍有效」**（NO owner，票 pp-pricing-input-seams/04 待裁 1）。本记录假定实测带发生时间、截至某一刻的清单可算；若 NO 裁成别的形状，端口的实现要跟着改，端口本身不变。
6. **生产装配没有物理事实来源，复核恒标 `DECLARATION_FALLBACK`。** 这是如实的，但意味着本记录落地后复核的出价与此前相同，区别只在标明；真正按实测出价要等登记册、只读口与适配器。接线仍挂在票 code/66。
7. **首次收寄复核的物理事实在 PS 与 TF 侧没有来源。** 收寄采用记录与权威运输交接都不带重量或尺寸，场外揽收无节点称重；首次收寄复核能取到的物理事实只可能来自 NO 在收寄那一刻登记的实测。PS 收寄采用要不要带「当时已取得的物理事实」（票面「另议」）本记录不做。
8. **到站复核与授权改路决定取判断此刻，回滚重投前后可能出不同的价。** 首次收寄复核截到收寄的业务时间，重放不变；其余两格在两次尝试之间若有新实测登记，后一次读到新的。回滚的那一次不落库，已落库的复核按幂等关联读回、不重算，所以只影响还没提交的那一次。

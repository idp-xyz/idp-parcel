# ADR-0053: 网络事实族是推导结果不可登记；登记册只登定义存在，无解析层时一律答未配置

Status: Accepted  
Date: 2026-08-17

## Context

[ADR-0052](./0052-network-evidence-catalogue-has-an-unconfigured-grade.md) 给两个网络证据端口加了`未配置`格，那部分已经实现并在用。但它的 Decision 四写了一句话，动手建表时发现是错的：

> 它要能承载 `NetworkEvidence` 与 `InitialRouteEvidence` 两个结构今天已声明的全部事实族：服务区解析、路由要求、路径可执行性、硬约束发现、候选段链、时间投影与承诺边界、分值、排序准则、策略引用。

**那九族不是能登记的目录行，是每次判断的推导结果。** 三条硬证据：

- 九族全部以 `CandidateID` 为轴，而候选是为这一次判断生成的。`ServiceAreaResolution` 答的是「候选 X 覆盖还是排除**这一次的目的地**」，`PathExecutability` 答的是某个排班版本对该候选可不可执行，`CandidateScores` 是该候选在各准则上已折算的可比取值。它们都不是「网络长什么样」，而是「网络对这一次判断说了什么」。
- **判断键里根本没有目的地这一维。** `ReachabilityJudgmentKey` 与 `InitialRouteJudgmentKey` 携带的是租户、客户账户、委托、提交版本、包裹、服务目的与 `asOf`。目的地要从包裹的资料里解析出来，而解析本身就是生成这些事实的那一步。按九族建表，等于给一次尚未发生、且键都还配不齐的判断预存派生结果。
- 从定义到事实之间那一层——候选怎么生成、按什么过滤、按什么排序——正是 `ports` 包注释点名的 `PAR-NET-14`，也正是它明令「不得先写一份默认实现」的东西。

登记册因此只可能存**定义原语**：服务区及其版本、排班、节点与连接拓扑、策略、排序准则、日历与缓冲。而这些原语要变成端口该交的事实，中间隔着那一层不得发明的解析。

推论直接决定今天能写什么：**在解析层存在之前，任何非空答复都是编的。** 唯一诚实的实现只有一种形状——读登记册，发现没有定义，答`未配置`。

## Decision

**一、停用 ADR-0052 Decision 四的第一句（上面引的那句），其余各条不变。** 九族是推导结果，不进登记册。0052 的三格端口、专格未决原因、修订由登记册派生、空册与空集合可分辨四条继续有效。

**二、可登记的是定义原语，不是事实族。** 原语清单同上。事实族由解析层从原语派生，解析层属 `PAR-NET-14`。

**三、原语的模式留待真有定义可登时再设计，现在不建表。** 理由与 0052 拒绝默认实现同源：没有一份真实网络定义在手，列出来的字段是替租户拟的，而模式一旦落库就按校验和固定。**本记录不圈那份模式的范围**——0052 圈过一次就圈错了，错在圈的是产物不是来源。

**四、登记册今天只登「这个范围有没有网络定义」，读口据此答三格。** 一行登记只声明范围与修订，不含原语。适配器因此只有两条出路，第三条被显式禁止：

- **查无登记 → `未配置`。** 首发唯一走得到的真实分支：没有租户就没有网络定义。
- **查到登记但本进程没有解析层 → 响亮报错。** 这是有人登记了定义而这个构建产不出事实，属装配缺口，运维看得见才对。
- **禁止：查到登记就答 `configured=true` 带空事实族。** 那会把「缺解析层」讲成「这个网络里什么都没有」，领域随即评出`无当前有效路由`——正是 0052 要挡的那件事，只是从端口层挪到了数据层。**非空答复必须有定义来源**，没有来源就不许声称已配置。

## Consequences

- `nrinbox.AcceptanceConsumer` 的依赖闭包可以被真实类型填满，C 批接线不再阻塞；接通后首发路径逐包裹停在 `ROUTE_EVIDENCE_NOT_CONFIGURED`，这是如实的。
- 派发侧照 ADR-0049 认下的代价：首条真实事件因未决而回滚重投，卡住其分区直到失败预算耗尽。它由`未配置`引起，不是接线错误。
- 登记册今天没有写入方——原语与解析层都不在，谁也登不出一份能用的定义。这不是遗漏，是第四条第二格存在的理由。
- 下一次真要做网络定义时，先设计原语模式与解析层，再回来扩这张表；不要从事实族倒推。

## Alternatives considered

- **照 0052 原文建九族表。** 否决：见 Context。存的是派生结果，且键配不齐。
- **现在就设计原语模式。** 否决：没有真实定义在手，字段是替租户拟的；且它不解 C 批的堵——有原语没有解析层，照样产不出事实。
- **查到登记就答已配置带空事实。** 否决：见 Decision 四第三条。这是本记录最要挡的一条。
- **什么都不落，只修 ADR。** 否决：MCP-3 的接线阻在缺一个 `InitialRouteEvidenceView` 实现上，而这个实现今天就能诚实地写出来。
- **整份取代 0052。** 否决：0052 的四条里三条正确且已实现，取代会把仍然有效的决定一并送进历史。

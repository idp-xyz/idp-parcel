# ADR-0196：一码两物按关联到的包裹认——后到那件答身份冲突，先到那件只追加一版身份冲突判断

Status: Accepted（2026-10-19。用户 2026-10-16 授权会话 `idp-parcel-9b`「你作为业务和系统专家你来自决」；该会话代 NO owner 裁定，裁定原文落在票 [no-reception-identity/01](../../.scratch/no-reception-identity/issues/01-one-barcode-on-two-units-forms-an-identity-conflict.md)「裁定（2026-10-18，会话 idp-parcel-9b 代决）」一节，本记录照它写成并补上实施时定下的形状。）部分停用：几句由 [ADR-0210](./0210-identity-conflicts-are-disposed-by-an-operation-decision-and-the-identity-basis-reads-chain-heads.md) 停用，随票 no-reception-identity/05、06 进 main 各自生效；被停的原句见本记录文末「复核记录二」与 adr/README 该行。另有两句由 [ADR-0199](./0199-node-reception-preserves-the-delivery-source-and-rechecks-pending-identities.md) 决定四停用，只限同一节点上有当前收寄的情形，随票 no-reception-source/04 进 main 生效；原句见本记录文末「复核记录三」与 adr/README 该行。

Date: 2026-10-19

## Context

NO CONTEXT「实物身份与事实完整性」：「同一外部条码出现在多个实物，或同一实物存在相互冲突的外部标识时，各作业实物继续独立，形成身份冲突并暂停方向性作业。」UC-NO-002 验收 `AT-NO-019`：「两件实物保持独立，形成身份冲突并暂停方向性作业」。

收寄编排（`ReceiveDeliveredUnitHandler`）只按身份核对交回的候选数分支：恰一个就关联。号码在 PS 的外部标识关联册里只标识一件包裹时，两件作业实物先后贴着它送站，两件都答`节点收寄已形成`、都关联到同一件包裹、都不记身份冲突。会话 `idp-parcel-9b` 经生产装配在真库上复现过（合成夹具，`S`）；票 no-reception-identity/01 实施时先以编排层与真库两组失败用例复现，再修。

no-directional-basis/01 的身份一格（`domain.JudgeIdentityBasis`）以「恰好关联到一个正式包裹、且没有一行记身份冲突」为成立，这一格不补，两件都会被判身份成立。

难逆转处：收寄册只追加，追加的行一旦落下就是历史；PS 可能已经采用了先到那件的收寄。

## Decision

适用范围只管 UC-NO-002 收寄编排的明确接收支、身份核对唯一指向一件包裹的那一格。多候选与零候选两格照旧。

**一、按关联到的包裹认，不按号码认。** 同租户收寄册上，这件包裹已有另一件作业实物的收寄关联（客户送站收寄），后到那件就是「同一外部条码出现在多个实物」。号码只是这一次身份核对的输入；册上已经成立的是关联，冲突是两件实物争同一件包裹。不论先到那件此刻是否仍在节点控制下。同一作业实物不在此列：同一份送站重投按幂等键走已有结果，同一件实物换个来源再收一次照常形成收寄。

**二、后到那件答身份冲突。** 答`待识别`，收寄与控制真实成立，不关联正式包裹，候选记那件包裹，记身份冲突；不向 PS 问服务结果（没有唯一成立的身份），不交发布意图。

**三、先到那件只追加一版身份冲突判断，原判断照留。** 用收寄结果的版本机制：给先到那件的收寄册追加一行待识别收寄——收寄事实（节点、送达方、证据、接收时间）与控制照原判断，换一个新签发的结果版本，去掉关联，候选记那件包裹，记身份冲突；不交意图。原判断那一行不改。同一件先到实物在册上有多行关联时，依接收时间最晚的那一行追加，与方向依据取所依收寄的次序同一个口径。追加只在后到那件这一次真落册时发生，与它同一笔事务；并发里输给另一方的那次读回赢家、不再追加。

**四、与方向性作业门的衔接。** 方向依据的身份一格读这本册：后到那件只有一行待识别且记冲突，落成缺少·{待识别, 身份冲突}；先到那件有原判断的关联行加追加的冲突行，落成缺少·身份冲突。两件都暂停方向性作业，方向依据代码不改。

**五、已被 PS 采用的那次采用不回滚，交 VE 协调。** NO 不撤回已交出的意图，也不发撤销信号；VE 侧如何发现与协调不在本记录实现。

**六、读口与存储。** 收寄库端口加 `FindOtherUnitIntakes`（按租户与包裹关联读别的作业实物的收寄，只认收寄本身带的关联，待识别行的候选不算），PG 适配器走迁移 0004 已有的 `reception_intake_association_idx`，不加迁移。读不动与身份核对读不动同样不形成答案（ADR-0186 第二条）。追加那一行的来源标识由后到那次送站的来源标识与先到那件的作业实物派生，带 `IDENTITY-CONFLICT/` 前缀；内容摘要沿用后到那次送站的。

## 能力边界

- 只认「唯一识别 + 包裹已关联到别的实物」。不覆盖：同一实物带相互冲突的外部标识（另一半 CONTEXT 规则）、唯一误关联（ps-external-mark-relations/05）、身份后来被确认（`AT-NO-026`）、冲突的处置与解除。
- 先到那件若尚未形成关联（自己也是待识别），后到那件照旧关联成立；册上没有可争的关联。
- 只看本租户 NO 收寄册上的客户送站收寄；经交接进来的实物在本上下文没有收寄行，看不到。
- 冲突形成之后，先到那件换个来源再收：后到那件的收寄行不带关联，按包裹读不到它，先到那件照常答`节点收寄已形成`、交发布意图。方向依据仍因册上的冲突行判身份冲突，方向性作业照停；冲突不随这次收寄重报，等身份冲突的处置能力。

## 越权风险点

1. **代 NO owner 定「按包裹认」。** 若 owner 要按号码认（同一号码在不同实物上出现即冲突，不论关联），需要按号码的读口与册上留号；本记录没有，改口时另起 ADR 取代第一条。
2. **在先到那件的册上追加行。** 先到那件此刻可能已被转出、已被 PS 采用；追加的一行说的是「身份此刻有冲突」，不是撤销收寄。读收寄册的面（审阅目录、记录查询）会多看到一行待识别，来源标识带前缀，人看得出它不是一次送站。
3. **派生来源标识占用了来源标识的命名空间。** 设备或导入送来恰好同形的来源标识时，那次送站按指纹比对答来源冲突；反过来派生键已被占时，编排不形成答案、不拿占位行顶替这一版冲突。
4. **并发未串行。** 两件实物在两笔并发事务里同时送站，READ COMMITTED 下互相看不到对方未提交的关联，两件可能都关联成立。本记录不加锁；要堵这一格另立票（候选做法：按租户与包裹取事务级咨询锁）。
5. **PS 采用不回滚、交 VE。** VE 侧今天没有消费这一版冲突的路径；在它落地之前，PS 那次采用照旧有效，只靠方向性作业门挡住后续动作。

## Consequences

- 先到那件被追加冲突版之后，方向性作业对两件都停；解除要等身份冲突的处置能力（未立票）。
- 每一次唯一识别多一次按包裹的读，与收寄同一笔事务。
- 多件（第三件起）再来时，各自答冲突；先到那件按每次后到的送站各追加一版。

## Alternatives

- **按号码认。** 不取：号码在 NO 册上不留存，要另建按号的册；且号码已由 PS 关联册解释过一次，再按号判冲突是第二套口径。
- **只让后到那件答冲突、先到那件不动。** 不取：先到那件在方向依据上仍判身份成立，与 CONTEXT「各作业实物……形成身份冲突」不符。
- **改写先到那件的原判断（翻成待识别或置冲突位）。** 不取：只追加、不覆盖；原判断可能已被 PS 采用，改写会让采用失去所依的那一版。
- **限于先到那件仍在节点控制下。** 不取：冲突是两件实物争同一个身份，与先到那件此刻在哪无关。
- **另建身份冲突册，方向依据并读两本。** 不取：要改方向依据读口与迁移；收寄结果本就有版本机制，追加一版待识别收寄就能让既有身份一格读出冲突。

## 复核记录（2026-10-19，决定原文不动）

1. **越权风险点 4「并发未串行」由票 [no-reception-identity/03](../../.scratch/no-reception-identity/issues/03-concurrent-deliveries-of-one-mark-serialize-on-the-parcel.md) 收住**（会话 `idp-parcel-9b` 代 NO owner 裁定）。收寄库 PG 适配器的 `FindOtherUnitIntakes` 在查询之前按（租户、包裹关联）取事务级咨询锁，锁随收寄所在的事务释放。同一件包裹上「读别的实物关联 → 落收寄」因此串行：两件贴同一个号的实物在两笔并发事务里送站时，后到那件等在锁上，先到那件提交后它才查；READ COMMITTED 下那条查询另取快照，读得到先到者的关联，于是答身份冲突，并给先到那件追加一版冲突判断，与决定二、三的先后次序同一结果。读口改为无事务即拒：锁在事务外取不住。真库并发用例（`cmd/parcel-api` 的 `TestConcurrentDeliveriesOfOneMarkSerializeOnTheParcel`）修前两件都答`节点收寄已形成`，修后如上。
2. **串行粒度是（租户、包裹），是代 NO owner 定的。** 号码唯一指向的包裹之外（零候选、多候选），编排不读别的实物关联，也就不取锁。不取唯一索引：同一件包裹允许有多行关联，同一实物多次收寄是合法的，没有可建唯一约束的列组合。不取 `SERIALIZABLE`：那要把整条收寄编排换隔离级别，牵连 PS 读口与意图入队。锁不管绕过本读口的写入。

1. **决定四两句自票 no-reception-identity/05 进 main 起停用。** 方向依据的身份一格改读每条判断链的当前有效版本（ADR-0210 决定五）。先到那件的冲突版若指名了前版（ADR-0199 第一期之后追加的），此刻的当前有效版本就是那一版冲突版，落成缺少·{待识别, 身份冲突}，不再是「先到那件有原判断的关联行加追加的冲突行，落成缺少·身份冲突」；第一期之前追加、没有前版的冲突版照原句。同条「方向依据代码不改」一并停用。两件都暂停方向性作业，这一结论不变。
2. **决定六的读法自票 no-reception-identity/06 进 main 起收窄。** 「按租户与包裹关联读别的作业实物的收寄，只认收寄本身带的关联」：被身份冲突处置版接续过的行，它的关联不再算那件实物的关联，处置版自己带的关联照算（ADR-0210 决定八「处置截断」）。还没有处置过的实物照原读法。决定一「这件包裹已有另一件作业实物的收寄关联」随之同读。
3. **「Consequences」里「解除要等身份冲突的处置能力（未立票）」**已有去处：ADR-0210，实施票 no-reception-identity/05、06。决定五「已被 PS 采用的那次采用不回滚，交 VE 协调」不变；ADR-0210 决定七写明处置不撤回已交出的意图。

## 复核记录三（2026-10-19，ADR-0199 决定四部分停用两句；决定原文不动）

ADR-0199 决定四（同一作业实物在同一节点不另起控制起点）由票 [no-reception-source/04](../../.scratch/no-reception-source/issues/04-the-same-unit-at-the-same-node-forms-no-second-control-start.md) 落地（会话 `idp-parcel-9b` 代 NO owner 裁定，授权同 Status 行）。自该票进 main 起停用本记录两句，**适用场景**只限同一节点上有当前收寄：这件实物在这个节点上有一条判断链的当前有效版本是`节点收寄已形成`或`待识别实物已建立`，且那一版的控制没有转出。

1. **决定一末句「同一件实物换个来源再收一次照常形成收寄」。** 适用场景里，换来源再来的明确接收、明确拒收与仅扫描都并入那条当前收寄：落一行「并入已有收寄」，来源照存，答`已有结果`，信息格带那一版的判断种类与当前有效版本；不形成收寄，不另起控制起点，不交发布意图。适用场景之外照原句：到了另一个节点、那条收寄的控制已转出、或这个节点上此前只有`节点收寄未形成`，再收一次照常形成收寄。同条「同一作业实物不在此列」（同一件实物再来不认成一码多物）与「同一份送站重投按幂等键走已有结果」不变。
2. **「能力边界」里冲突形成之后先到那件换来源再收「照常答`节点收寄已形成`、交发布意图」一句。** 先到那件在原节点的当前收寄此刻是追加的那一版冲突版（待识别、记身份冲突、控制照原判断），换来源再来并入它：答`已有结果`，原判断种类`待识别实物已建立`，当前有效版本是那一版冲突版，不交意图。先到那件到了另一个节点时照原句。同条其余几句不变：后到那件的收寄行不带关联、按包裹读不到它；方向依据仍判身份冲突。

两句改钉的用例：`TestTheSameUnitDeliveredAgainIsNotAnIdentityConflict`（同一节点换来源再来并入、冲突之后先到那件再来并入冲突版），`TestTheSameUnitElsewhereOrAfterARefusalFormsAFreshJudgment`（另一个节点照常形成收寄）。

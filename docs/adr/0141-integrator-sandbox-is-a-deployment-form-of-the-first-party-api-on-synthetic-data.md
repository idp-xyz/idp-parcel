# ADR-0141：集成方沙箱是首方 API 的一个部署形态，不是代码路径——同一二进制、独立数据库、独立受众、全 `SYN-` 合成数据，走真首方渠道 Intake 与真令牌校验；开发方运营的产品沙箱属机制半边、随产品就绪存在，某租户的沙箱属实例半边；沙箱证据一律记 `S`，`SYN-` 前缀门禁在沙箱里照旧，隔离写开关与沙箱是两条路不合并

Status: Proposed（**草案**，2026-09-16。用户经 IDP 队列通道 1 令「按建议继续」，本记录是通道 1 复核所列六件缺项的第二件——「[ADR-0139](./0139-first-party-customer-api-channel-is-a-product-owned-access-channel-family.md) 正确地否决了『开发用』API Key，但没回答『客户的开发者拿什么测』」。**接受与否归用户**，接受前不是依据。裁决能力边界：读过 ADR-0139、[ADR-0078](./0078-isolated-environment-operations-reads-admit-by-assembly-injection.md)、[ADR-0091](./0091-isolated-form-extends-to-the-write-path-by-graded-switches.md)、[ADR-0016](./0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md) 的标题与两轨制前提、[ADR-0140](./0140-first-party-api-contract-is-generated-from-endpoint-descriptors-with-url-major-version-and-problem-details.md) 全文，[`docs/api` 方案稿](../api/Go_Chi_Scalar_API_Documentation_Final_V1.0.md)的沙箱相关各节，`cmd/parcel-api` 的 `assembleBusinessEndpoints` 与隔离开关的装配，[开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)证据层级与产品就绪判据两节；未重读 `scripts/demo-seeds/` 的种子内容、未核对发行方（Ory Hydra 形）对多受众或多项目的实际配置方式——本记录因此只裁**沙箱的性质、隔离物与准入路径**，不裁沙箱的数据内容、重置节奏与配额）
Date: 2026-09-16

## Context

**一个对外的 API 没有沙箱，集成方只能在生产上试错。** ADR-0139 立了首方客户渠道：产品自有的发行方签发机器凭据、产品定义的契约、产品拥有的客户渠道册。它在 Decision 六里正确地否决了「绕过发行方的『开发用』API Key 或本地账号」——那条路会在生产装配里长出一条与真实认证不可分辨的路径。但否决之后留下一个没答的问题：租户的客户系统在接入之前，用什么凭据、对着哪个地址、在什么数据上验证自己的集成？方案稿把沙箱写进了 URL 规范（`sandbox-api.example.com`）、文档配置（沙箱页面允许发起测试请求）与对外文档必备十项（「沙箱说明：测试数据、生产差异、凭证边界与清理规则」），本仓没有任何一份权威记录接住它。

**本仓已有的两条隔离路径都不是沙箱，而且都不该被拉伸成沙箱。** ADR-0078 与 ADR-0091 立的隔离形态是**装配注入**：`IDP_PARCEL_ISOLATED_READ_TENANT` / `IDP_PARCEL_ISOLATED_WRITE_TENANT` 设了带 `SYN-` 前缀的合成租户，装配点上特定行的 Intake 换成注入式实现，请求里不读任何自报身份。它服务的是**没有发行方的内部演示环境**——种子包、管理台演示、隔离 `S` 场景。它刻意不做认证：ADR-0078 Decision 二「放行形态是装配注入，不是认证」。集成方要测的恰恰是认证：拿令牌、带 `aud`、被 `401` / `403` 三格答复、请求键判重、`outcome` 分流。一条不读凭据的路径测不出这些；把它改成读凭据，它就不再是 ADR-0078 定义的那个东西。ADR-0078 Decision 四另两句今天仍有效：「不得据此再添 demo/mode 类全局开关或第二个 main」。沙箱若做成生产二进制里的一个模式开关，正撞这句。

**沙箱要测的是真路径，所以它只能是同一份代码的另一次部署。** 集成方对沙箱的全部期待——同一契约、同一认证、同一答复代数、同一幂等语义——恰好等于「与生产同一二进制」。差别只在**数据与信任锚指向哪里**：另一个数据库、另一个受众（或另一个发行方）、另一个域名。这三件都是 `parcel-api` 今天已有的部署形态参数（ADR-0139 Decision 二：发行方地址、JWKS、客户 API 受众；数据库 DSN），没有一件需要新代码路径。方案稿「沙箱专属规范由同一契约确定性生成，只投影环境服务器地址」说的也是这个。

**沙箱里的数据必须全是合成的，而本仓已有合成数据的可分辨物。** ADR-0091 Decision 三：隔离形态写下的每一行，租户维与来源维带 `SYN-` 前缀，「事后可分辨靠的是事实自己的来源表达」。沙箱是同一二进制，`SYN-` 前缀门禁对它原样生效——但要说清生效在哪一层：沙箱不设隔离开关，前缀门禁守的不是开关值，而是**沙箱里登记的每一个租户、客户账户与渠道行**。这需要一条新的结构性约束，见 Decision 二。

**开发方有没有租户，沙箱都得在。** [开发主线](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)把产品就绪定义为机制半边达标；一个对外 API 的机制半边包含「集成方能在不碰生产的地方验证接入」——没有它，产品演示不了自己的契约，商务洽谈里「你们的 API 怎么接」这一问只能用文档回答。所以**开发方运营的产品沙箱**属机制半边，与首方 API 一起就绪；**某个租户自己的沙箱**（给它的客户用、带它的合成配置）属实例半边，是同一部署形态在租户环境里的又一次实例化，本记录只保证机制允许它存在。

## Decision

**一、沙箱是首方 API 的一个部署形态：同一 `parcel-api` 二进制、独立数据库、独立客户 API 受众、独立域名。** 生产装配里**不存在**任何「沙箱模式」的代码路径或开关——ADR-0078 Decision 四「不得再添 demo/mode 类全局开关」原文有效，本记录不停用它一字。沙箱与生产的差别全部落在已有的部署形态参数上：数据库 DSN、发行方地址与 JWKS、客户 API 受众（ADR-0139 Decision 二）。受众**必须**与生产不同：一枚沙箱令牌拿到生产 `aud` 不匹配即 `401`，反向亦然——这是「沙箱凭据进不了生产」的结构保证，不靠网络隔离，不靠纪律。发行方是否与生产共用一个、只分受众，还是另立一个发行方，是部署决定（见风险点）；两种做法下受众都不同。

**二、沙箱里登记的每一个租户、客户账户、操作者绑定与渠道行都带 `SYN-` 前缀，由登记面的构造门守。** ADR-0091 的前缀门禁守的是开关值；沙箱不设开关，门禁改守**登记**：沙箱部署以一个部署形态参数声明「本实例只接受合成标识」，设了它之后，任何登记写面（ADR-0085 那一族、客户渠道册、操作者册）对不带 `SYN-` 前缀的租户或客户账户标识一律拒绝登记，答复与「值不合法」同格。生产部署不设此参数，登记面对前缀无约束。参数的方向朝拦：设了只会更严，不会放宽任何事——所以它不是 ADR-0078 禁的那种「按环境选择行为」的模式开关，它只加一道门。沙箱写下的每一行因此在事实自己的来源表达上就带着 `S` 的锚，与 ADR-0091 Decision 三同一形状；把沙箱库里任何一行搬进生产库，前缀先出声。

**三、沙箱走真首方渠道 Intake，不走隔离写开关；两条路并列不合并。** 集成方在沙箱里拿到的是真令牌（发行方按沙箱受众签发）、过的是真校验（ADR-0139 Decision 二两步）、撞的是真客户渠道册（行绑定沙箱 client 到 `SYN-` 客户账户）、铸的是真 `SourceEnvelope`、走的是真编排。`IDP_PARCEL_ISOLATED_WRITE_TENANT` 在沙箱部署里**不设**——它服务的是没有发行方的演示环境，那条路今天在、以后也在（ADR-0091 Decision 六「隔离形态不因真渠道出现而自动退场」），但它与沙箱是装配点上的两行，谁也不替谁。沙箱与生产在装配点上**逐字节同形**：同一份 `assembleBusinessEndpoints`，同一组 Intake；集成方在沙箱里测过的路径就是生产里的路径。

**四、沙箱的编排前件用合成登记满足，不用假实现。** 提交编排要过生产归属（`PAR-GOV-03..07`）、商业解析、网络可达等门，沙箱里这些登记册按 ADR-0091 Decision 二的纪律填**合成行**（`SYN-` 权威区间、`SYN-` 合同与价卡），编排真的读册、真的判断；**不许写一个直接返回「已确定」的假目录**——ADR-0091 那句原样成立。种子由 `scripts/demo-seeds` 那一族的受控 CLI 灌入（ADR-0085 Decision 一「受控批量口」），沙箱种子与演示种子可以是同一份，因为两者要的都是「一套能让编排走到终局的合成世界」。

**五、开发方运营的产品沙箱属机制半边，随首方 API 一起就绪；某租户的沙箱属实例半边。** 前者由开发方部署与维护，服务于商务演示、合作伙伴接入验证与本仓自己的契约集成测试（ADR-0140 Consequences 里「契约集成测试覆盖实际响应」跑在这里）；它的租户、客户账户、client 全部是开发方自己登记的 `SYN-` 合成体。后者是某租户在其部署里再起一个同形态实例给它的客户用，登记什么合成客户、开多久，归该租户（实例半边），本记录只保证部署形态参数允许它这么做。

**六、沙箱证据一律记 `S`，不进任何准入判据。** 沙箱里跑通的任何东西——集成方的接入、契约集成测试、演示——证据层级都是 `S`（AGENTS 红线「隔离合成 `S` 只记为 `S`」）。它不构成 PN-08 任何一项的证据，不改任何 `PAR-*` 行的状态。沙箱的存在让「产品能被集成」这一机制半边判据有了可运行的证明；它证不了任何租户的任何实例。

**七、沙箱的凭据签发与撤销走与生产同一条机制。** 沙箱 client 由发行方签发、在沙箱的客户渠道册登记一行（绑 `SYN-` 租户与 `SYN-` 客户账户、带生效区间、可撤销）；登记走管理台写面（ADR-0085）或受控 CLI，与生产同一用例。沙箱 client 的有效期、配额与数据重置节奏是沙箱的运营参数，可配置、不设默认（见风险点）。**不做**「自助注册即得 client」的匿名开户——谁能拿沙箱凭据是产品决定，归 owner；机制只保证拿到的凭据除受众外与生产同形。

**八、不做的，逐条写明。**

- 不在生产二进制里加沙箱开关、沙箱路由、沙箱专用端点；沙箱与生产的可观察差别只有 `servers` 地址、受众与数据。
- 不把隔离读写开关改造成沙箱，也不在沙箱里设它们。
- 不用 OpenAPI 契约生成的 mock 服务器（Prism 类）充当沙箱——它答得出形状，答不出认证、判重、`outcome` 与三格，集成方在它上面测通的东西到生产会碎；它可以作为**契约形状预览**的补充工具，不叫沙箱。
- 不定沙箱数据的重置节奏、client 有效期、配额、是否模拟外部事实（承运商轨迹、关务结果）的注入面——各归风险点。
- 不为沙箱立第二套契约——沙箱契约是 ADR-0140 生成物加一条沙箱 `servers`，确定性投影，不另编辑。

## Consequences

- `parcel-api` 增一个部署形态参数「只接受合成标识」（名字归实施票，形状同 `IDP_PARCEL_ISOLATED_*` 的前缀纪律）；设了之后各登记写面的构造门多一道前缀检查，未设时逐字节同形。装配测试覆盖两态。
- 开发方的部署清单增一个沙箱实例：独立数据库、独立域名、独立客户 API 受众、灌演示种子；它与演示环境（设隔离开关、无发行方）是两个实例，不合并。
- ADR-0140 的文档门户在沙箱实例上以「可发起测试请求」形态构建，`servers` 只含沙箱地址；生产实例只读。契约集成测试（ADR-0140 Consequences）的运行地点是沙箱实例。
- 首方 API 的对外文档增「沙箱」一章：地址、如何取沙箱 client、数据全为合成、重置规则、与生产的差别只在受众与数据——方案稿对外文档必备十项的第八项由此有了权威落点。
- 参数登记册增行：「沙箱 client 有效期 / 配额 / 数据重置节奏」为开发方沙箱的运营参数（机制半边的运营件，仍要登记、仍不设默认）；「某租户沙箱」为实例半边，租户出现前为空。
- ADR-0078、ADR-0091 一字不改：沙箱不是隔离形态的扩展，是它旁边的另一条路。

## Alternatives considered

- **「开发用」API Key 或本地账号。** 否决：ADR-0139 Decision 六原句，理由不复述。
- **在生产二进制里加沙箱模式开关。** 否决：ADR-0078 Decision 四「不得再添 demo/mode 类全局开关」；且一个模式开关让沙箱与生产的可观察签名相同而路径不同——集成方在沙箱里测过的东西不再等于生产里的路径。
- **把 `IDP_PARCEL_ISOLATED_WRITE_TENANT` 改成读凭据、当沙箱用。** 否决：它的定义是「不采信请求里的任何自报身份」的装配注入，读凭据后它就不是 ADR-0078/0091 定义的那个东西；两个概念共用一个开关名，读的人分不出设了它是要演示还是要沙箱。
- **沙箱与生产共用数据库，靠 `SYN-` 前缀区分行。** 否决：`SYN-` 前缀是**可分辨物**，不是隔离墙（ADR-0091 Decision 三的措辞是「事后可分辨」）；ADR-0003 把租户定为最高数据隔离边界，沙箱一次误操作的爆炸半径不该覆盖生产库。
- **OpenAPI mock 服务器当沙箱。** 否决：见 Decision 八第三条。
- **等首个租户出现，用它的实例当沙箱。** 否决：把开发方的产品能力挂在租户的出现上，与 ADR-0139 否决「等 `PAR-INT-01`」同一条范畴错误；且租户的环境里跑合作伙伴的接入测试，爆炸半径落在租户身上。
- **不做沙箱，让集成方在生产上用 `SYN-` 客户账户测。** 否决：生产库里出现 `SYN-` 行是 ADR-0091 前缀门禁要挡的方向；集成方的测试流量与生产流量同库同池。

## 越权风险点（归 owner 复核）

本记录能力边界之外、实施时必须先答的几件：

1. **发行方形态**——沙箱与生产共用一个发行方只分受众，还是另立一个沙箱发行方。前者少一套运维，后者把「沙箱 client 的注册与撤销」也隔开。部署 owner 决定；两者下受众都不同，Decision 一不受影响。
2. **谁能拿沙箱 client**——合作伙伴申请由开发方审批登记、还是签约租户自助为其客户登记；产品决定，归 owner。
3. **沙箱运营参数**——client 有效期、配额、数据重置节奏；参数登记册增行，可配置不设默认。
4. **外部事实的注入面**——集成方要测 webhook（ADR-0142）就要有事实发生：承运商轨迹、关务结果、节点扫描。沙箱里这些事实从哪来（种子里预排的时间线、还是一个只在沙箱部署里存在的「合成事实注入」写面）是一件需要自己记录的事：后者若做成端点，必须过 ADR-0091 Decision 一的三条判据（全 `SYN-`、不采信自报身份、生产装配无此路径），且与 Decision 一「不加沙箱专用端点」的关系要先讲清。本记录不预裁，倾向于种子预排。
5. **契约集成测试在沙箱上跑的 CI 形态**——沙箱是长期实例还是 CI 按需拉起；影响 ADR-0140 Consequences 那一条的落法。
6. **「只接受合成标识」参数对操作者册的作用**——操作者主体是发行方 `sub`，没有 `SYN-` 前缀可加；沙箱里的操作者绑定怎么标合成（绑到 `SYN-` 租户即够，还是主体也要标），归 `accessidentity` owner。

Date: 2026-11-12

## Context

- **申报不全的估价今天照旧内部重试。** 结算答 `ESTIMATE_DECLARATION_INCOMPLETE`（申报缺了计价要的某一格）时，小包托运走内部重试：整笔回滚、信封重投、重投用完放弃，委托停在`已提交`、看不出缺什么，客户也收不到任何要补的信号。ADR-0380 决定一把这一类明写为另立（票 25），越权风险点也点名了它。
- **计价知道缺哪一格，封闭集四码。** 估价口对每张适用卡逐件点名缺项：`MEASUREMENT`（重量或量纲读不出——受理前试算的测量取客户申报，可以没报）、`POSTAL_ROUTE`（今天只在收件邮编没报时点名；寄件邮编没报照样组出空始发的路线）、`ZONE`（卡要发起方直接给分区，受理前估价从不带分区，这样的卡必点）、`ADDRESS_NATURE`（卡按收件地址性质判价，小包托运没有结构化那一格，ADR-0347 决定四，这样的卡也必点）。四码里前两种客户补得了，后两种客户补不了——那是这张卡做不了受理前估价。
- **两种客户可补的缺口今天漏过了「申报不全」的口子。** 卡带始发邮编前缀分区目录而寄件邮编没报时，计价组出空始发的路线、分区解不出（`ZONE_UNRESOLVED`），评成「有试算无合计」；卡有按尺寸判的规则而尺寸没报时同样（`DIMENSIONS_REQUIRED`）。两者经结算折成 `ESTIMATE_TRIAL_WITHOUT_TOTAL`，被 ADR-0380 决定一归进了等运营登记——续办方归错了：该补的是客户的寄件邮编和尺寸，不是运营的卡。票 25 自己举的例子（没报寄件邮编）正落在这里。
- **逐件缺项在结算一折就丢。** 结算消费计价的试算答复时，申报不全只留一个结果值，各件与缺项码全部折掉；小包托运拿到的只有一个原因码，想告诉客户「缺哪一件的哪一格」无从谈起。
- **小包托运的等待受控补充已经在用，但入口都在决定那一步。** 必要资料条件未满足（ADR-0376 决定一）与可达性资料不足都译成`无法判定`的校验、在 Decide 停进等待受控补充，缺口逐件落在任务上、查阅面按组＋件＋原因交出；受控补充重报整份内容（收寄邮编、逐件重量长宽高与单位都在载荷里）、形成新提交版本，新版本信封驱动新一轮判断。财务控制那一步今天只有等运营登记一种阶段停法（ADR-0380，照 ADR-0094 决定五先存等待再交回原因）。
- 头部系统的做法（出处同 ADR-0380 Context）：报不出价时按该谁动手分——缺重量、地址或邮编不对是下单方的事，订单停在「待补全」并写明缺什么，补好接着走；价格没配是物流商的事。

## 候选与反方

- **全部申报不全一律等客户补充。** 反方：缺分区、缺地址性质客户补不了——受控补充的载荷根本没有那两格，受理前估价也从不带它们；催客户补一件补不成的事，委托永远停着。按缺项分流。否决。
- **把估价缺项造成一项财务控制校验结果，走决定那一步既有的停法。** 反方：接受前财务控制采用结果是「一项控制执行后的结论」（PS CONTEXT 词条原话），估价没形成不是一项结论；造一项假结果让「未执行的项不是一项结果，本上下文不记它」破例。照 ADR-0380 等运营登记同一纪律在阶段上停，机制已有第二个先例。否决。
- **结算把缺项译成自己的词汇再交。** 反方：结算不拥有申报完备性的语言，译一遍只多一处要同步的封闭集；ADR-0380 决定三对原因码的纪律就是原样转交。否决。
- **计价不动，小包托运拿「有试算无合计」的评价细码来分流。** 反方：无合计的试算在结算一折细码就丢，补回来要在三个口各加一格；而且「没报」与「报了解不出」只有计价分得清——始发前缀目录对着空邮编与对着不在册的邮编，下游看到的是同一个 `ZONE_UNRESOLVED`。在源头点名。否决。

## Decision

**一、申报不全的受理前估价按缺项该谁补分流。**（产品策略）

- **客户可补的缺项**：缺测量（`MEASUREMENT`）、缺尺寸（`DIMENSIONS`，决定二新码）、缺收件邮编（`POSTAL_ROUTE`）、缺寄件邮编（`ORIGIN_POSTAL`，决定二新码）。受控补充的载荷今天就有这些格。委托停进`等待受控补充`，缺口逐件记在任务上（决定四），客户补充形成新提交版本后续办。
- **价卡一侧才解得开的缺项**：缺分区（`ZONE`，卡要发起方直接给分区，受理前估价给不出）、缺收件地址性质（`ADDRESS_NATURE`，小包托运没有结构化那一格，ADR-0347 决定四）。这不是客户的资料缺口，是这张卡做不了受理前估价：归 ADR-0380 决定一的`等待运营登记`，登一张受理前估价解得出的卡（如带分区目录的售价卡）后由计价「参数已登记」按租户续办，解得开要的仍是生效期覆盖提交接收时点的卡（ADR-0380 决定一）。
- **两类同时在场时等运营登记先**：卡不换，客户补全了它还是答不出；卡换对了之后重问，剩下客户缺口再停等受控补充。
- **一格缺项都点不出的申报不全照旧内部重试**：计价答申报不全必带缺项，走到这里只有缺陷，处置同 ADR-0380 对币种对不上的读法。

**二、计价在估价口把「卡要而申报没给」一律点名为缺项，不再评成解不出。**（机制）

- 估价口（受理前估价与试算同一口）对每张适用卡先核它要的输入在不在：卡按始发邮编前缀解分区而寄件邮编没报 → 缺项 `ORIGIN_POSTAL`；卡有按尺寸判的规则（体积重、尺寸档、尺寸条件）而尺寸没报 → 缺项 `DIMENSIONS`。这两种今天走完评价、停在 `ZONE_UNRESOLVED` / `DIMENSIONS_REQUIRED` 的「有试算无合计」，经结算折成 `ESTIMATE_TRIAL_WITHOUT_TOTAL` 落进等运营登记——答数的形状把续办方带偏了。
- 缺项码照旧是封闭集，加这两码后六码：`ZONE`、`POSTAL_ROUTE`（收件邮编）、`MEASUREMENT`、`ADDRESS_NATURE`、`ORIGIN_POSTAL`（寄件邮编）、`DIMENSIONS`（尺寸）。页面自译中文照旧。
- 多张卡各点各的缺项，逐件取各适用卡缺项的并集交出：客户看到的是「要把估价做出来还缺什么」，不是某一张卡的私账。
- 「报了但解不出」照旧评成待决或无合计：邮编报了而目录不盖它、汇率没解出一类仍归 ADR-0380 的格——那是卡与目录的事。

**三、结算把逐件缺项原样带回，不折叠、不改写。**（机制）

- 计价的估价答复逐件带缺项码；结算的试算答复与控制施加结果在申报不全时逐件原样转交（成员按申报包裹指名），原因码照旧 `ESTIMATE_DECLARATION_INCOMPLETE`。结算不拥有申报完备性的词汇，纪律同 ADR-0380 决定三「原样的原因码」。

**四、小包托运在财务控制那一步停进等待受控补充，缺口与处理尝试同笔落库。**（机制）

- 分流落在结算消费侧适配器（ADR-0380 决定一的同一落点）：申报不全按决定一分——缺项含 `ZONE` 或 `ADDRESS_NATURE` 走等运营登记那一路；其余已知缺项走等受控补充；读不懂的缺项照旧内部重试。
- 等受控补充照 ADR-0094 决定三、五与等运营登记同一纪律：先存等待（带缺口）再交回待判原因，处理尝试同笔落库。停住的这一版估价没形成、没有占用，等待受控补充的释放义务空集成立；续办照既有路——受控补充重报整份内容、形成新提交版本，新版本信封驱动新一轮判断，停住的那一版不再被判。
- 缺口记在任务上、归「接受前财务控制」组，原因码是小包托运自己的封闭集：`ESTIMATE_MEASUREMENT_MISSING`、`ESTIMATE_DIMENSIONS_MISSING` 指名申报包裹；`ESTIMATE_RECIPIENT_POSTAL_MISSING`、`ESTIMATE_ORIGIN_POSTAL_MISSING` 是委托级、不指件（收寄邮编在申报里本就是委托级要素，逐件重复点名会把一格缺口说成几件各缺）。查阅面照既有补充缺口形状（组、件、原因）交出。
- 等待落库的处理尝试照 ADR-0380 决定三另记结算原因码与这一版申报的服务产品，再另记计价点名的缺项码（原样、去重；没有缺项不记）。两路等待都记：等受控补充那一路缺口已在任务上，这一格让「上次处理」与等运营登记那一路也说得清缺什么。

**五、管理台写明缺什么、谁来补。**（产品策略）

- 等受控补充的停因例如「估价没形成：申报缺了计价要的资料（第 2 件缺重量、委托缺收件邮编）——客户补充后自动续办」；补件队列的缺口翻译补决定四那四个原因码的词条，码不与别组撞。
- 缺分区、缺地址性质走等运营登记的，写明这张卡做不了受理前估价与该登什么，例如「估价没形成：在用的卡要直接给分区，受理前估价给不出——登记一张带分区目录、生效期覆盖提交时点的售价卡后自动续办」；词取计价缺项的运营译法既有词条。续办方照旧取处理尝试上记的那一格。

## 对已接受记录的作用

- [ADR-0380](./0380-an-estimate-the-price-card-side-cannot-form-waits-for-operator-registration-and-the-attempt-records-why.md) 决定一「提交版本看不见、申报不全、没有任何一件试算、币种对不上、合计溢出照旧内部重试。」一句里「申报不全」那一半停用——改按本记录决定一分流。**适用场景**：计价点得出缺项的申报不全；一格都点不出的照旧内部重试（本记录决定一末条）。同决定「申报不全要等客户补，另立」那一格与越权风险点「申报不全照旧内部重试、用完放弃」由本记录回答。其余各条不变。
- ADR-0380 决定一把 `ESTIMATE_TRIAL_WITHOUT_TOTAL` 归等运营登记那一格不动、无条款停用：本记录决定二让「卡要而申报没给」在计价一侧先答成申报不全、走不到无合计，那一格此后剩下的才真是价卡一侧的（报了解不出、汇率没解出一类）；其越权风险点「哪几种原因算『登记解得开』是产品策略」里「试算没有合计也可能是申报缺了某一格」的顾虑由此消解一半。
- [ADR-0376](./0376-fba-submission-conditions-are-judged-as-required-documents-platform-identifiers-may-be-supplied-before-acceptance-and-rule-packages-follow-the-service-product.md) 决定一「必要资料」组与受控补充的续办路照旧，无条款停用：估价缺项不进判组、不造校验结果（候选与反方第二条），本记录只给`等待受控补充`加一个阶段上的入口。

## Consequences

- 代码随票 declared-goods-lines/26、27：
  - 计价：估价口的输入完备性点名、封闭集加 `ORIGIN_POSTAL`、`DIMENSIONS` 两码。
  - 结算：试算答复与控制施加结果逐件带缺项，原样转交。
  - 小包托运：结算消费侧适配器的分流；财务控制那一步的等待受控补充（先存等待带缺口、处理尝试同笔落库另记缺项码与迁移）；查阅面交出缺口。
  - 管理台：停因写明缺什么、谁来补，补件队列缺口词条。
- 「委托待受控补充」信封（ADR-0371 决定三）的差距照旧：代码今天连决定那一步的入口也不交这封信封，已记在 UC-PS-001 交接表、仓配切片立票时承接；本记录的新入口同受那一行管，不在票 26 扩。
- 上线：此前因申报不全被内部重试用完、放弃的委托没有等待态，上线时对这批委托一次性重驱（并进 ADR-0380 Consequences 已记的那次运维动作）。
- 多唤醒照旧（ADR-0380 越权风险点「多唤醒」）：缺分区、缺地址性质归等运营登记的委托同样被每封「参数已登记」唤醒、各多一条尝试。
- 演示不加这条路：演示租户的种子提交都带齐测量与邮编，走不到申报不全；要演示补件动线另立。

## 越权风险点

1. **谁可补的分法与先后是产品策略。** 四码归客户、两码归运营、同场时等运营登记先，代 owner 定。归小包托运与小包计价 owner。
2. **估价口统一点名改了试算的答法。** 受理前估价与试算同一口：寄件邮编、尺寸没报的卡此后答「输入不全（缺项）」，不再答「有试算无合计（`ZONE_UNRESOLVED` / `DIMENSIONS_REQUIRED`）」；读试算答复的面要跟着。归小包计价 owner。
3. **缺项取并集可能多催。** 多张卡适用时，只有某一张卡才要的格也会点给客户。归小包计价 owner。
4. **补一轮还缺会再停一轮。** 每轮新提交版本、新任务、各落缺口，没有轮数上限；客户一直不补全就一直停，届满处置照 PS CONTEXT 既有那句（租户取值，未配置即不设届满后果）。归产品 owner。
5. **头部系统做法的出处沿用 ADR-0380 的公开资料。** 归产品 owner。

# ADR-0355：单据号与内部标识分开，在单据开立事务内按产品内置、租户可改的编号规则分配

Status: Accepted（2026-11-02，Claude Code 会话起草，用户经会话逐条裁定：覆盖下文决定二的全部十一类单据、编号能力用公司平台库且先为它发版、规则由产品内置默认而租户可改；决定五的默认格式与其余各格由会话起草，用户答「继续」采纳。代 PS、SA、VE、CC、NO、TF 六个上下文 owner 决（代决）；票 document-numbering/01。整份取代 [ADR-0143](./0143-customer-statement-numbering-uses-platform-assignment.md)；部分停用 [ADR-0339](./0339-charge-confirmation-and-statement-publication-are-operator-decisions-and-a-registered-statement-cycle-cuts-on-its-closing-dates.md) 决定二一句与决定三一句。越权风险点待 SA owner 复核。）<!-- 索引注记 -->｜**入口**：运营与客户引用的「单据号」系统里没有：多数单据只有随机内部标识，几类要人手填编号，自动截单的单号由账户与截止日拼出。**取法**：单据号另成一项，内部标识与幂等照旧；十一类单据各在开立事务内经平台编号能力取号；规则一类一份产品默认，租户可登新版，只管之后开立的单据。
Date: 2026-11-02

## Context

取证于 main `a14f4f6b3` 与平台库 `idp-platform-go` 的 `f9a86f8`。

- **系统里没有「单据号」。** 现有的号有四种来路：随机内部标识（`internal/platform/identity`，`前缀-` 加 26 位 base32，委托、包裹、异常案件、关务案件、送站预报等）；库序列（只用于内部版本记录）；由别的字段派生（自动截单的 `STMT/<账户>/<YYYYMMDD>`，ADR-0339 决定三；班次）；由调用方给（订舱、运输委托、审核应付、手工发布的对账单号要人手填，送站交接单的标识由设备签发，ADR-0023）。外部方分配的号属「外部标识」（GLOSSARY），不在此列。
- **随机内部标识有它的理由。** `internal/platform/identity` 注明：标识跨租户共用一个命名空间，自增号能让一个租户从自己的号推出另一个租户的业务量，而集团租户是最高数据隔离边界（ADR-0003）；签发方不必与库协调就能担保不重，编排因而可以在事务外先取标识。这两条对主键与幂等键成立，对给人看的号不是必需。
- **运营与客户引用的是单据号。** 报给客户的运单号、发给客户的对账单号、客服登记的争议号、与承运方核对的订舱号，都要按规则出、按租户不重、开立后不变；26 位随机串人念不顺，也看不出日期与先后。
- **ADR-0143（Proposed）只覆盖对账单**，定了「平台编号能力在发布事务内分配、发布意图到单号的关系由 Parcel 持有」，卡在平台库没有可锁定版本，一直未落地。
- **平台库能力与缺口。** `go.idp.xyz/idp-platform-go` 的 `numbering` 提供模板语法（日期、财年、上下文值、流水、加扰流水、随机数、校验位）、按最细日期令牌推出的重置周期、事务内原子分配（回滚即释放、已提交号不重不空）。它的一站式入口 `Assigner.Assign` 每类单据在装配时固定一份模板、用一个时钟（默认 UTC），满足不了按租户换模板、按开立方业务时区出日期；但它公开了 `Parse`、`Template.PeriodKey`、`Template.Render` 与 `SequenceAllocator`，取号可由消费者用这几样编排。平台库与 Parcel 都依赖框架候选 `v0.1.0-rc.2`；平台库自身尚无版本标签，`go.idp.xyz` 的 vanity 也还没有它的映射。
- CONTEXT-MAP 规定：产品只复用有版本与兼容约束的公司级技术组件（例如配置），技术组件不得取得本产品领域对象的所有权。

## Decision

**一、单据号是单据上另加的一项，不是内部标识。** 单据号是本系统在单据开立时按编号规则分配、给人看、给相对方引用的业务编号。各单据的内部标识照旧做主键、幂等键与跨上下文引用，一个不动；单据号不参与幂等判重，也不是外部标识。例外是对账单：它的固定单号本来就是单据号，见决定九。

**二、带单据号的单据与开立时点。** 下列单据在所列时点取得单据号；各上下文 `CONTEXT.md` 以规则句写明本上下文的那几类，本表是本决定作出时的清单。

| 单据 | 上下文 | 类型代码 | 开立时点 |
|---|---|---|---|
| 委托（运单） | parcel-shipment | `SHIPMENT` | 草稿 → 已提交 |
| 对账单 | settlement-accounting | `CUSTOMER_STATEMENT` | 草稿 → 已发布 |
| 费用争议 | settlement-accounting | `STATEMENT_DISPUTE` | 登记 |
| 审核应付 | settlement-accounting | `AUDITED_PAYABLE` | 通过审核的金额形成审核应付 |
| 异常案件 | visibility-exception | `EXCEPTION_CASE` | 建立案件 |
| 客户索赔项 | visibility-exception | `CLAIM` | 客户提交被记录 |
| 关务案件 | customs-compliance | `CUSTOMS_CASE` | 建立案件 |
| 送站预报 | node-operations | `DELIVERY_PRE_ADVICE` | → 已登记 |
| 送站交接单 | node-operations | `DELIVERY_HANDOVER_NOTE` | 节点开立 → 开放（服务端收下开立时） |
| 订舱 | transport-fulfillment | `BOOKING` | 订舱申请登记 |
| 运输委托 | transport-fulfillment | `TRANSPORT_COMMISSION` | 草稿 → 已提交 |

客户索赔项取「提交被记录」而不取「受理」：客服在资格审核之前就要拿号与客户沟通。

**三、在开立事务内分配，开立后不变。** 取号与单据落库在同一个事务里：开立回滚，号码随之释放；已提交的号不重复、无空洞（平台库担保）。同一开立意图重放答原号——号存在单据上，重放读回，不再取号。单据开立后的换版、补件、重开不换号；作废后的替代单、拆出的关联新案件、后续关务案件是新单据，取新号。本决定生效前已开立的单据不补号。

**四、编号能力用平台库，取号由本仓编排。** 本仓经消费侧适配器只用平台库公开 API，取号这样编排：读该租户该类型此刻生效的模板 → 用开立方业务时区下的开立时刻算重置周期 → 在开立事务内经 `SequenceAllocator` 取（租户，类型代码，周期）的下一个值 → 渲染。模板语法、加扰、校验位与序列表只在平台库一处；本仓不复制其算法或 SQL，不用 `Assigner.Assign`。平台序列技术表照 ADR-0143 原定的方式作为独立平台 schema 接入迁移计划，保留来源、版本与 checksum，不并入任何业务 schema。依赖闸门沿用 ADR-0009 / ADR-0026：平台库取得精确版本、`go.sum` 校验与可复跑的空缓存下载之前，不改 `go.mod`，不加 `replace`、`go.work` 或源码副本。

**五、编号规则：产品内置默认，租户可登新版。**
- 每类单据随产品带一份默认模板（产品策略，ADR-0146），租户没登记时用它：

  | 类型代码 | 默认模板 | 样例 | 重置 |
  |---|---|---|---|
  | `SHIPMENT` | `P{yyyy}{mm}{dd}{seq:6}` | `P20261102000123` | 日 |
  | `CUSTOMER_STATEMENT` | `STMT-{yyyy}{mm}-{seq:5}` | `STMT-202611-00007` | 月 |
  | `STATEMENT_DISPUTE` | `DSP-{yyyy}{mm}-{seq:5}` | `DSP-202611-00012` | 月 |
  | `AUDITED_PAYABLE` | `AP-{yyyy}{mm}-{seq:5}` | `AP-202611-00031` | 月 |
  | `EXCEPTION_CASE` | `EX-{yyyy}{mm}{dd}-{seq:4}` | `EX-20261102-0003` | 日 |
  | `CLAIM` | `CLM-{yyyy}{mm}-{seq:5}` | `CLM-202611-00002` | 月 |
  | `CUSTOMS_CASE` | `CC-{yyyy}{mm}{dd}-{seq:4}` | `CC-20261102-0011` | 日 |
  | `DELIVERY_PRE_ADVICE` | `PA-{yyyy}{mm}{dd}-{seq:5}` | `PA-20261102-00045` | 日 |
  | `DELIVERY_HANDOVER_NOTE` | `HO-{yyyy}{mm}{dd}-{seq:5}` | `HO-20261102-00018` | 日 |
  | `BOOKING` | `BK-{yyyy}{mm}-{seq:5}` | `BK-202611-00009` | 月 |
  | `TRANSPORT_COMMISSION` | `TC-{yyyy}{mm}-{seq:5}` | `TC-202611-00004` | 月 |

  流水位数写的是最少位数，超出照常进位，不截断。
- 租户可以为某类单据登记新的规则版本（租户取值）：模板与生效时刻。新版只管生效之后开立的单据；已开立的单据号不变；版本只增不改。
- 模板须含流水令牌（`{seq}`、`{seq36}`、`{seqx}`、`{seqx36}` 之一），只有随机数或没有流水的模板拒登。
- 加扰流水（`{seqx}`、`{seqx36}`）的密钥是租户取值，从实例配置注入，不进仓库、无默认；租户模板用了加扰而该租户没配密钥，登记即拒。
- 序列键是（租户，类型代码，周期），不含模板：同一周期内换格式，流水接着数。

**六、规则册是编号技术组件的配置。** 一张册，按（租户，类型代码）存各版模板与生效时刻，只认类型代码，不拥有任何单据，也不读任何业务数据。类型代码与它的默认模板、日期时区来源由所属上下文声明，在装配时汇总；同一类型只在所属上下文定义一次。册有读口、登记口与预览口：读口列出每类单据此刻生效的规则（租户版或产品默认）与历次版本；预览口按样例流水渲染一个号，不读也不占序列；登记口要登记册配置写授予，管理台按 ADR-0315 收起。

**七、日期按开立方的业务时区。** 模板里的日期部件与重置周期按开立方业务时区下的开立时刻算：网点开立的单据按该网点的业务时区，对账单按结算账户对账安排的业务时区（ADR-0269）。没有业务时区的单据类型按 UTC（产品策略），规则册读口对每类写明所用时区。各类单据取哪个时区由实现票逐类核定并写进该上下文 CONTEXT。

**八、唯一与撞号。** （租户，类型代码，单据号）唯一，由各单据所在表的唯一约束担保。同一序列内不会撞；租户换格式后若新号与旧号相同，这一次开立不落单，答「编号规则撞号」（一个业务答案，不是故障），页面指到规则册；登记新版时预览提示可能与已用号段重叠。

**九、对账单。** 对账单的固定单号就是它的单据号，在发布事务内按 `CUSTOMER_STATEMENT` 规则分配，仍作（租户，单号）的寻址键。发布幂等从「按单号」改为「按发布意图」：同一结算账户、周期与截止版本的发布重放答原单与原号，不分配第二个号（UC-SA-003「同一发布意图不得生成两个单号」），发布意图到单号的关系由本上下文持有。由此：
- 自动截单不再从截止日拼单号，部分停用 ADR-0339 决定三中「单号与账期从截止日派生，形如 `STMT/<账户>/<YYYYMMDD>` 与 `CYCLE/<截止日>`，版本 `v1`；截单时刻取截止日的截单时刻，发布时刻取此刻。」一句的单号那一半；账期、版本与两个时刻的取法不变。
- 手工截单发布口的载荷不再收单号，部分停用 ADR-0339 决定二中「载荷照截单命令逐格收：单号、账户、账期、草稿版本、币种、费用清单、本期最后一个归属日、申报合计（按最小币单位的整数串）、截单时刻。」一句的「单号」一格；其余各格不变。
- 已发布对账单的单号不变；作废后的替代单取新号。

**十、原先手填编号的单据改由系统给号。** 订舱、运输委托、审核应付与手工发布对账单的表单不再让人填编号。载荷里今天点名内部标识的格（订舱、委托、应付标识等）保留为幂等键，由调用方（管理台在首次提交前）生成，重发落回同一项；单据号由服务端在开立时分配并在答复里交回。

**十一、呈现。** 管理台各页以单据号为主列、可按单据号检索，内部标识进技术详情；本决定生效前开立、没有单据号的单据照旧显示内部标识，技术详情注明「上线前开立，无单据号」。首方客户接口的委托提交答复与查询带上运单单据号，为新增字段，不改既有字段与语义（ADR-0140）。

## Consequences

- 生产接入在平台库取得可锁定版本、`go.idp.xyz` 能解析它之后才开始；文档与规则先落地，代码票照决定四的闸门挂阻塞边。
- 十一类单据所在的表各加一列可空的单据号与（租户，单据号）唯一约束；开立路径须在事务内，今天不在事务内的开立路径随实现票补上事务壳。
- 演示种子开立的单据按产品默认规则取号；种子不登租户规则。
- 对账单发布幂等改按发布意图，原按单号查重的那一步换成按意图查；本决定生效前截出的对账单，其意图（账户、账期、版本）照样能查到，升级后重截同一截止日答原单。
- 平台序列表成为本仓迁移计划里的一个平台技术 schema，权限与执行归本仓，资产归平台库。

## 越权风险点

1. **取号编排在本仓。** 决定四没有用平台的 `Assigner.Assign`，而是用它的公开原语自己编排；加扰键的拼法若与平台入口不同，同一模板在两处会出不同的加扰号。实现须照平台入口的拼法（密钥、租户、类型代码），并向平台库提议一个能传模板与时刻的取号入口，有了就改用它。
2. **默认流水暴露租户自己的业务量。** 默认模板用明文流水，租户的客户能从运单号推出该租户一天发多少单。这对租户之间不泄露（序列按租户分），对租户的客户是可见的；介意的租户可登记加扰模板并配密钥。
3. **新旧混显。** 不补号意味着上线前后的单据在列表里一部分显示单据号、一部分显示内部标识，检索单据号查不到老单据。
4. **换格式撞号。** 决定八只在开立时拦；租户若频繁换格式，撞号会以开立失败的形式出现在业务里，代价落在租户。
5. **UTC 兜底的日期。** 没有业务时区的单据类型按 UTC 出日期，东八区租户凌晨开立的单据会带上前一天的日期。
6. **送站交接单的号晚于设备身份。** 交接单身份由设备签发、可离线开立，单据号要等服务端收下开立才有；离线期间现场只看得到设备标识。
7. **发布幂等改键。** 对账单发布从按单号查重改为按发布意图查重；若某条既有路径依赖「同号即同单」之外的语义，换键时会暴露出来。

## Alternatives considered

- **把单据号做成主键，取代随机内部标识。** 否决：牵动全部幂等、引用与跨上下文交接；随机标识防跨租户推算、免事务协调的两条理由对主键仍成立。
- **本仓自己实现编号。** 否决：ADR-0143 与平台库 ADR-0001 都否决过第二套编号权威，模板语法与加扰会分叉成两种方言。
- **直接用平台的 `Assigner.Assign`。** 否决：它每类单据只认装配时的一份模板、只有一个时钟，满足不了租户可改与按业务时区出日期。
- **每个上下文各自一张规则册。** 否决：六张同形的册、六处管理台入口；规则是编号技术组件的配置，不是各上下文的领域语言。
- **规则必须由租户配置，没配就不编号。** 否决（用户裁定产品内置默认）：新租户上线多一步，且所有单据在配置前都没有号。
- **只用产品内置、租户不能改。** 否决（用户裁定租户可改）：租户想用自己的公司前缀就得等产品发版。
- **给上线前的单据补号。** 否决：已发给客户、承运方的单据事后多出一个号，两边对不上；内部标识照旧可查。
- **继续让人手填编号。** 否决（用户裁定）：手填既不按规则也挡不住重号。

# ADR-0271：代收本金只凭渠道代收报告自外部来源入账一次，真实到账按指令只把`渠道在途`移到`待清分`，收件人付款与渠道回款通知是旁证；`短款`只从`渠道在途`落入，`溢款`只从`待清分`落入

## Context

以下所引 collection-remittance CONTEXT 原文是本记录接受前的文字，已随本记录改写（见 Consequences）。

- collection-remittance CONTEXT 写了互相放行的入账路：「代收事实已接受 → 入账记账：自外部来源移入`渠道在途`或（真实到账时）`待清分`」与「`渠道在途` → `待清分`：渠道回款对应的真实资金事实已接受」；规则又说「资金只能自外部来源入账一次」「同一笔代收事实不得重复入账」。各来源层级各自都能入账时，这些规则守不住。
- 代码今天就是这些路都开着：
  - `application.PostSubledger` 的重放判定按记账标识（`LoadPosting(command.ID)`）。`factPostingShapeHolds` 的外部来源分支只核去向等于 `CollectionFact.IntakePosition()`、金额等于事实金额；同一条事实换一个记账标识可以再入一次。
  - `IntakePosition()` 对真实到账交`待清分`，对收件人付款、渠道代收报告、渠道回款通知都交`渠道在途`。一件包裹的同一笔钱经收件人付款、渠道代收报告、渠道回款通知各自全额入账，账上重复记。
  - 同一条真实到账既能凭它入账到`待清分`，又能再凭它把`渠道在途`移到`待清分`；移位那一支只核层级与起讫位置，金额不受事实金额约束。
  - 迁移 `collection_remittance/0001` 的 `subledger_posting` 只有主键（租户、记账标识），没有按（依据种类、依据引用）的唯一约束。
- `短款`在 CONTEXT 里同时是一个资金位置（「实收少于指令的差额已确认落在此处」）与差额本身。差额那部分钱从没进过账；按「分配守恒」（全部非外部资金位置的余额之和恒等于自外部来源入账的金额之和），`短款`里的余额只能从已经入账的本金里挪过去。生命周期「`待清分` 或 `应付客户` → `短款`」正是这么挪：`application/handler_test.go` 的短款用例把真实到账 10000 全额入`待清分`、再移 2000 到`短款`，只剩 8000 能进`应付客户`，客户少拿 2000。`discrepancyPostingShapeHolds` 不限来源位置。
- 只有一种形态下`短款`是守恒的：渠道先按报告金额入了`渠道在途`，真实到账少于报告，剩下那部分是渠道报了、钱没回来的本金，从`渠道在途`落入`短款`。演示种子 `scripts/demo-seeds/steps/350-collection.sh` 走的就是这一形：渠道代收报告全额入`渠道在途`，真实到账凭到账事实移进`待清分`，差额登短款差异事项后自`渠道在途`落入`短款`。
- `溢款`有同样的问题，方向相反：生命周期「`溢款` → `应付客户`」让溢款能归到客户应付；`溢款`若从`渠道在途`落入，未实际收到的钱就绕过「只有已接受的真实到账事实才支持推进到`应付客户`」进了客户应付。

## Decision

**一、入账只凭渠道代收报告。**（产品策略）

- 凭一条已接受的渠道代收报告，自外部来源入`渠道在途`，金额等于报告金额，全额一次。
- 渠道代收报告是渠道对这笔钱已在它手上、欠着运营企业的陈述，正是`渠道在途`这一格的意思（「渠道已代收但尚未回到运营企业」）；受托保管账从它起账，账上的每一分钱都有一个对它负责的渠道。
- 收件人付款与渠道回款通知是旁证——本记录里旁证指登记在册、不支撑任何记账的代收事实：照旧登记为代收事实、各层分别保存、不互相推导（ADR-0082 Alternatives 否决「代收事实不分来源层级，只登一个「已收金额」。」那一条），但不记账。它们与报告、到账、指令对不上时，由差异事项表达。

**二、真实到账只做移位记账，不入账；移位上限按指令算。**（产品策略）

- 凭一条已接受的运营企业真实到账，把`渠道在途`移到`待清分`，金额等于到账金额，全额一次。移位记账指凭依据把本金从一个账内位置移到另一个账内位置的记账，与自外部来源移入的入账记账相对。
- 上限按到账事实所属的指令算：同一指令已入账的渠道代收报告金额，减去该指令已移位的金额。分户账里同账别的指令的在途款不算进来——报告是按指令出的，差异要按指令追责，按账合并会让对不上的一单被别单的到账掩盖。
- 按指令不够移时停在余额不足（`UNDERFUNDED`），等对应的渠道代收报告入账后再移；不先凭到账入账、事后再补报告。到账先到、报告后到时终局与报告先到相同，结果不随到达次序变。
- 到账多于该指令已入账的报告（渠道回了比它报告的多的钱）同样停在余额不足：多出的那部分要有一条该指令的渠道代收报告把它入`渠道在途`，到账才移得动。

**三、凭代收事实的记账按依据判重，不按记账标识。**（机制）

- 同一条代收事实至多支撑一笔记账：报告一笔入账，到账一笔移位。同一记账标识重放答已有结果（`EXISTING`）；换一个记账标识再凭同一条事实记账是同键异内容，答内容冲突（`CONTENT_CONFLICT`），不记账。库上加同一口径的唯一约束，编排判重与约束一致。
- 收件人付款与渠道回款通知凭它记任何一笔都不受理。

**四、`短款`只从`渠道在途`落入。**（产品策略）

- `短款`装的是渠道已报告代收、真实到账没到并经差异事项确认的那部分本金，是运营企业对渠道的受托追收，不是客户少收的钱。只有`渠道在途` → `短款`一种形，金额等于差异事项金额；差异事项的短款金额按指令算，是该指令已入账的报告金额减去已移位金额。
- `待清分`与`应付客户`里的是已经到账、或已经归属客户的本金，不得落入`短款`。
- 指令金额与报告之差（渠道报告本身就少于指令）从没进过`渠道在途`，也就没有可挪的余额：只登差异事项、不记账，等补报告或结案处置。差异事项因此不一定有一笔对应的记账。
- 短款确认之后渠道补付的：差异事项更正后冲正那笔短款记账（`短款` → `渠道在途`，反向同额，CONTEXT「差异事项被更正」一条），再凭新到账照决定二移位。

**五、`溢款`只从`待清分`落入。**（产品策略）

- `溢款`装的是实收多于指令、经差异事项确认的那部分已到账本金，只有`待清分` → `溢款`一种入形，金额按指令算，是该指令已移入`待清分`的到账减去指令金额；它之后可以经处置归到`应付客户`，所以只能装已经到账的钱。
- 渠道报告多于指令而钱还没到的部分，留在`渠道在途`，随到账移进`待清分`之后再判溢款。

**六、本记录不改 ADR-0082 的形。** 分户账四维立键、余额只由追加式记账派生、外部来源只在来源侧、依据门、入账无法冲正，照旧。

## 候选与反方

- **按指令只入账一次，哪一层先到哪一层入。** 否决：入哪一格（`渠道在途`还是`待清分`）随到达次序变，`短款`是占位置还是只记在事项上也随次序变；同一组事实两种账面。
- **只凭真实到账入账，`渠道在途`不再记账。** 否决：`渠道在途`是词表里的一格，渠道手上欠着的本金从此在账上看不见，渠道已代收、未回款的那部分只能靠对账去查。
- **收件人付款也入账。** 否决：它是尾程执行方的作业证据，不是谁对运营企业欠这笔钱的财务陈述；与渠道代收报告同时入账就是 H3 那种重记。它在差异判断里留用。
- **`短款`只记在差异事项上，不占资金位置。** 否决：渠道报告了、钱没回来的那部分已经在`渠道在途`里，不落到一个位置上就永远挂在`渠道在途`，`渠道在途`的余额从此不再等于渠道还欠的、未处置的本金。
- **移位与短款的上限按分户账算，同账各指令的在途款合用。** 否决：报告按指令出、差异按指令追责；按账合用时，一单到账不足会被同账另一单的在途款填上，短款落在哪一单上说不清。
- **到账多于报告时，多出的那部分凭到账直接入`待清分`。** 否决：一条到账事实就既是入账又是移位，判重口径要分两半；多出的钱没有渠道陈述背书，正是决定一要防的「无来源的金额」。

## 对已接受记录的作用

- 无条款停用。[ADR-0082](./0082-collection-subledger-is-keyed-by-four-dimensions-and-posted-append-only.md) 决定四「本金只能凭一笔已接受的代收事实进账」与决定五的依据门都是必要条件，本记录在其上加入账、移位与差额来源的门，没有一句因此不成立；其 Consequences「入账无法冲正」一条照旧，本记录不给入账开冲正口。

## Consequences

- collection-remittance CONTEXT：「资金位置」词条里`短款`、`溢款`的释义，「资金只能自外部来源入账一次」「同一笔代收事实不得重复入账」「渠道代收报告与渠道回款通知只支持资金停在`渠道在途`或`待清分`」几条规则，以及「代收事实与入账」「分户账资金位置」「差异事项」各节生命周期，随本记录改写。
- 代码随 code/14：入账只收渠道代收报告、`IntakePosition()` 只对它有位置；真实到账只收`渠道在途` → `待清分`、金额等于事实金额，余额守卫另加按指令的上限；凭代收事实的记账按依据唯一（编排判重与迁移另取号的唯一约束同一口径）；短款记账来源限`渠道在途`、溢款入账来源限`待清分`；`handler_test.go` 那组短款数字改成从`渠道在途`落入。演示种子已是本记录的形，不改。
- 记账今天只经受控 CLI（`cmd/parcel-collection-register`），存量只有演示租户，`--reset` 重灌即可。

## 越权风险点

1. **没有逐指令代收报告的渠道入不了账**（CR owner）。有的渠道只在回款时附一份逐件明细，没有单独的代收报告；接这类渠道的连接器要把那份明细登成渠道代收报告，再把回款登成真实到账。自营尾程的现金交接同理。
2. **收件人付款不进账**（CR owner）。尾程已记收件人付款、渠道却迟迟不报的那段时间，账上看不见这笔钱，只在差异判断里可见；要在账上看见，须另立一格，本记录不立。
3. **到账多于该指令的报告时整笔停住**（CR owner）。移位上限按指令算：渠道一次回款合并了该指令报告之外的金额，或把别的指令的钱记在这一单上时，这一笔到账在补报告之前移不动，同账别的指令的在途款不能借来凑；运营要先补一条该指令的渠道代收报告，或把到账事实按指令拆登。
4. **换记账标识重记答冲突而不是已有结果**（CR owner）。运营重发时若换了标识，会看到冲突；这是有意的——它不是重放，答已有结果会把一次误操作伪装成成功。
5. **短款补回走冲正**（CR owner）。补回要先更正差异事项、冲正短款那一笔，再移位；差异事项的更正关系今天还落不了库（code/15），这条路要等它。

## Context

- 评价请求停下之后没有任何东西再推它（票 [demo-chain-gaps/14](../../.scratch/demo-chain-gaps/issues/14-buy-request-stuck-after-an-unadoptable-evaluation.md)）。三处同族：
  - **评价采用不了**。BUY 评价不可计价、待判断、跨币种没带换算步骤、卡没声明金额取整时，结算入账、不形成成本（ADR-0200 决定三）；SELL 那一路记`待判断`、`不可计价`或`冲突`，评价失败停在`已提交`（ADR-0190 决定五、ADR-0198 决定一）。租户补登之后，同一组来源引用再请求命中原请求，评价不可变、计价对同一份请求也不再形成第二份，这件发生项（这件包裹）永远没有预期成本（客户费用）。
  - **发起之前答`未配置`**。SELL 那一拍走「包裹 → 结算账户」链停在结算政策没采用、账户不在册、计费时点没采用，或包裹没有商业解析；BUY 那一拍停在触发册没登这个原因、登了没登费用项目。这一拍入账即散（ADR-0190 决定三、ADR-0208 决定三），补登之后不回补。
  - **计价答`未配置`被放进未决名单**。PP 按请求解析价卡零命中、多卡同时适用、造不出计价输入快照，三格都登在派发的未决哨兵里，重投到失败预算耗尽信封即 `ABANDONED`；租户隔天登了卡，信已弃，结算那一侧的请求永远停在`已提交`、看不出卡在哪。
- 先例：[ADR-0094](./0094-undecided-retry-is-decided-by-resume-path-with-a-fourth-grade-for-operator-registration.md) 决定四在小包托运那一侧立过「参数已登记」——登记动作同笔交信封，消费门按租户取等待队列逐份重驱，不采用定时扫描；它的判据是**重试、客户补件、人工复核都推不动、只有一次登记动作推得动的，不该烧失败预算**。
- 与 PS 那一侧不同的一点：评价不可变、计价按回指至多为一份请求形成一份评价（计价迁移 `0010_evaluation_request_reference.sql`），所以评价那一侧停下之后**不能**按同一份请求重问——要另起一份请求。
- M15（另一协调会话并进本票）：BUY 触发册不设修订，先登了没有费用项目的一行、再来补登答冲突（ADR-0208 决定三与越权风险点 4），「费用项目没登」那一格永远发不出「参数已登记」。

## Decision

**一、请求按代次排成链，续办另起新一代（机制）。**

- BUY 与 SELL 两本评价请求册各加三格：代次、前一代、续办依据。唯一约束从自然键换成（自然键、代次）；前一代上另有唯一约束——一份请求至多一个下一代，同一封信重投、两路续办并发，库上只落一份。前一代经外键指回同一本册。
- 首代没有前一代；续办出来的各代必须指名前一代并带续办依据。发起停办经续办重跑之后发出的第一份请求也是首代，带依据、不指前一代。
- 下一代问的是同一个问题：SELL 照抄包裹、结算账户与结算币种、计价范围、计费时点、来源事实、计价基准时点，**不重走**「包裹 → 结算账户」链——账户与采用都是不可变元组（ADR-0158、ADR-0190 决定三），重走答的还是同一组；BUY 照抄主要范围、计算目的与三件合格来源引用，请求方是固定名 `settlement-accounting/evaluation-resumption`。费用标识与预期成本版本标识照旧由请求派生（ADR-0190 决定五、ADR-0200 决定二），下一代派生新标识。
- 旧请求与旧评价一个字不改：前一代的结论、停因与它的评价原样留着，是这条代次链的历史。按自然键读回的是最新一代。

**二、续办依据（机制）。** 一次续办凭的什么记在续办出来的那一代上（发起停办重跑后仍停着，记在发起停办上）：一次参数登记（种类加那封「参数已登记」信封的标识），或一次运营续办（运营人员给的续办引用）。**同一个依据对同一条代次链至多续办一次**：同一封信重投、同一条运营命令重跑，续办出来又停下的那一代不会被同一个依据再推一代。

**三、停因（机制）。** 停因是封闭集，分三段，记在册上，续办按它取等待队列：

- 发起之前（SELL）：结算政策没采用、结算账户不在册、计费时点没采用、包裹没有商业解析；（BUY）：没登这个原因、登了没登费用项目。
- 计价没形成评价（两路）：没有在用价卡、多于一版同时适用、造不出计价输入快照。
- 评价采用不了（两路）：评价待判断、不可计价、评价冲突、评价失败、卡没声明金额取整；（只 BUY）跨币种没带换算步骤；（只 SELL）费用行映不全或映到多个费用项目。
- 评价待判断按缺的是什么再分格，缺的东西不同，解得开它的登记就不同：目录读不出（分区、偏远档位）、序列读不出（参考序列、汇率）、价表上没有这一段、包裹事实不全（尺寸、包裹特征）；问题项为空、不止一类或是读口不认的词，落笼统的那一格。分格由结算读计价评价的那一层按计价的问题项译出，计价不知道结算怎么分。

具体落法：

- SELL 请求册的状态格是停因的粗分，加`未形成`一格：计价没形成评价与评价失败都记`未形成`。停下的各格必须带停因，库上的 CHECK 守配对。
- BUY 请求册没有状态格：采用不了的各格由形成那一半记停因，形成了的由派生的版本标识可查。
- **计价答不出评价的三格移出未决名单**：PP 入账，同笔交一封「评价未形成」（租户、请求、方向、停在哪一格、给人读的说明）；结算消费它，在请求上记停因（SELL 记`未形成`）。请求不在册上、册上另有结论都是两侧矛盾，上抛为发布失败。**真正的依赖读不动照旧是未决**：请求读不回、价卡解析读口或输入读口答不出、铸造口与评价库故障、交「评价未形成」暂时失败。
- 迁移前已记成`待判断`的 SELL 请求，当时没记是哪一种，标「停因未记」，价卡、序列、目录、映射四类登记都续办它；迁移前停在`已提交`而实际卡住的请求从行上看不出来，不回补（越权风险点 7）。

**四、发起之前停下的那一拍记进发起停办册（机制）。** 两本册按自然键一行——SELL 按（租户、包裹、计费时点），BUY 按（租户、发生项、有效性版本）——记下那一拍的输入（SELL：来源事实与计价基准时点；BUY：发生项的原因、业务时间与它固定的供应商协议）、停因、停下时刻与依据。它不是请求：此刻请求要的账户、币种、计价范围、费用项目都答不出，往请求册里塞一行缺格的请求会让按标识回读的计价落空。同一自然键再停一次换上这一次的停因、时刻与依据；这一拍有了请求就不再等着，那一行留作来路。不记的：`采用了别的时点`（这一户登的那一行就是不在这一拍计费，采用册不可变，记了也永远不会续办）、修订版不发起、未受理、未决。记不下答未决、整笔回滚——入账而没记下，正是此前的「入账即散」。

- SELL 那一拍停在计费时点没采用时，链已走到账户：册上记下那一户，补登采用时只续办那一户的。别的停因走不到户，这一格为空。
- 续办重跑时这一户答`采用了别的时点`（同一件包裹两拍都停在计费时点没采用，补登的采用只认其中一拍）：那一拍本就不计费，不是停下，发起停办落终止、不再进队列。不落终止，它会一直满足「等着」的口径，每来一次采用登记就重跑一次、再答一次同样的话。同一自然键日后又停一次，终止清掉、重新等着。

**五、参数登记同笔交「参数已登记」，结算按停因续办（机制；哪类登记解得开哪些停因是产品策略）。**

- 登记种类封闭集。交信封的登记口与落点：
  - 结算账户登记——沿用既有的「结算账户已登记」，结算多一路续办门（排在小包托运那扇作用域续办门之后）。
  - SELL 计费时点采用、费用项目映射、BUY 触发册三本评价参数册——落行（`已登记`与`重放`）同笔交「评价参数已登记」，`冲突`不交。
  - 计价价卡登记（含草稿发布）——同笔交「参数已登记」，带卡的计价范围与方向；序列与目录复核**通过**（含免复核代写的那一份）同笔，先问绑了这一条序列（这一份目录）的卡在哪些计价范围、哪一路上，一面交一封；没有卡绑它就一封不交，退回不交。内部方向的卡不交：结算的评价请求只有 BUY 与 SELL 两路。
- 哪类登记解得开哪些停因由领域一处定（判据：登了之后同一个问题再问一次可能得到不同答案）：

  | 登记 | 解得开的停因 |
  |---|---|
  | 结算账户 | 结算账户不在册 |
  | SELL 计费时点采用 | 计费时点没采用 |
  | BUY 触发册 | 没登这个原因、登了没登费用项目 |
  | 费用项目映射 | 映射不全、停因未记 |
  | 价卡 | 没有在用价卡、多于一版同时适用、不可计价、评价冲突、评价失败、取整未声明、目录读不出、序列读不出、价表没有这一段、缺换算步骤、笼统待判断、停因未记 |
  | 序列 | 序列读不出、缺换算步骤、笼统待判断、停因未记 |
  | 目录 | 目录读不出、价表没有这一段、笼统待判断、停因未记 |

  目录读不出与序列读不出都认价卡：计价答这两格有两条来路——卡绑了目录（序列）却没映到、缺一期读数，或卡根本没绑目录（汇率序列）、请求也没带分区。后一条来路上，序列与目录信封只按绑了它的卡交面，落不到这张卡的范围上，只有绑了它的新一版卡解得开。价卡信封本就按范围与方向收窄，序列照样不推缺区。价表没有这一段另认目录：卡绑了目录、目录把邮编映到了错区时，补一版目录解得开（越权风险点 1）。

  哪一类登记都解不开的四格：结算政策没采用的答案在委托接受时固定的商业闭包上，结算这一侧的登记与运营续办重跑读到的都是同一份闭包，今天**没有续办路**（越权风险点 13）；包裹没有商业解析、计价输入不可得、包裹事实不全缺的是小包托运或运输履约那一侧的事实，那一侧补上之后由运营续办口点名（决定六）。
- 信封必带收窄格，续办只取这一次登记解得开的那几件，不按种类把整个租户里同停因的件推一遍。哪一类带哪几格由领域一处定（`EvaluationParameterKind.Narrowing`）：计价三类带计价范围与方向；BUY 触发册带发生项原因；SELL 计费时点采用带户；结算账户与费用项目映射不带（理由与代价见越权风险点 4）。缺了必带格的信封是毒丸：放宽去推正是收窄要挡的，重投也长不出那一格。
- 续办门按租户取等待队列：停因在这一类登记解得开的名单里；这条代次链上任一代凭这封信续办过、或发起停办凭它重跑过的不取；再按信封带的收窄格筛——计价范围只取问这个范围的请求（发起停办没有计价范围，整支不取），方向只取那一路，发生项原因只取 BUY 那一路里原因是它的，户只取 SELL 那一路里落在这一户的。逐件各开一笔事务：停下的请求另起下一代并交请求信封，发起停办按记下的输入原样重跑发起编排（成了是首代，又停在发起之前就换上这一次的停因与依据，答`采用了别的时点`就落终止）。队列按（停下时刻、种类、键）的位置往后翻页、不足一页即到底：办过却没写回的件（重跑被拒、撞上矛盾、未决）仍满足「等着」的口径，每页重读队首会被它们占满、把后面的挡住。
- 「等着」的口径：发起停办——没有落终止，且这一拍还没有任何一份请求；请求——带停因、还没有下一代。
- 未决哨兵只收会自愈的：队列读不动、某一件续办时某个依赖答不出。某一件撞上矛盾（队列交出的件回读不到、记下的输入重跑被拒、信封被确定性拒收）压过未决上抛。

**六、运营续办口（机制）。** `parcel-settlement-register evaluation-resume`：按方向点名一件包裹（SELL）或一版发生项（BUY），续办引用必填；同一个引用重跑是重放。一次续办跑在一笔事务里，任一件未决整笔回滚、同一个引用重跑。它给两类件用：缺的事实在任何一本参数册之外的（包裹没有商业解析、计价输入不可得、包裹事实不全——小包托运或运输履约那一侧补上之后来点名），以及登记的信封漏了、没推到的。停因不设限，运营人员看过停因、确认缺的已经补上才来点名；它不登任何租户取值，缺的没补上，续办只会照实再停一次。它**不是**结算政策没采用的出路：重跑读到的是同一份固定闭包，照样停下（越权风险点 13）。

**七、BUY 触发册纳入修订形（产品策略）。** 停用 ADR-0208 决定三「册不设修订」。册按（租户、原因）排版次，读口取最新一版。最新一版没登费用项目时，可以追加一版带费用项目的；任一版再交一次是重放；已登的费用项目换成另一个仍答冲突——那会让已经按旧费用项目形成的预期成本与此后形成的对不上，换法要 owner 另裁。旧版留在册上作历史，不改写。追加的那一版同笔交「评价参数已登记」，停在「登了没登费用项目」上的发生项由它续办。

三类：

- **机制**：代次与续办依据、停因的记法、发起停办册、两类信封、续办门与运营续办口、未决名单的划法。
- **产品策略**：停因的分段与待判断的分格、「哪类登记解得开哪些停因」那张表与各类登记的收窄格；`采用了别的时点`不记发起停办、重跑答它就落终止；下一代不重走结算账户链；BUY 触发册只允许补空格这一种修订。
- **租户取值**：结算账户、计费时点采用、费用项目映射、触发册的原因与费用项目、价卡、序列与目录的在用版本——仍是租户自己登，本记录不替任何一格填默认值；`未配置`照实答，续办只在补登之后发生。演示租户经种子登 `SYN-` 值，证据只记 S。

## 对已接受记录的作用

各记录正文不改，只在 Status 行与 Links 加前向指针、被停条款写进索引注记，其余各条不变。

- **ADR-0190**：
  - 决定一「自然键（租户、包裹、计费时点）只守幂等」——自然键加代次唯一（本记录决定一），同一件包裹在所采时点只**发起**一次照旧，续办出来的各代不是又一次发起。
  - 决定五「计价侧没形成评价（未配置、适用冲突、输入不可得）时不发评价已记录信封，请求停在「已提交」」——计价改交「评价未形成」，请求记`未形成`连同停因（本记录决定三）。
  - 越权风险点 3「请求卡死」由本记录作答。
- **ADR-0198**：决定一「评价失败，请求停在`已提交`，入账不重投」中「请求停在`已提交`」——改记`未形成`、停因评价失败（本记录决定三）；入账不重投照旧。越权风险点 1、2 在本路部分作答：失败与没形成评价分得出了；缺的是哪个费用代码仍不落库。
- **ADR-0200**：决定三「评价停下的各格入账，不重投，不改记任何册」中「不改记任何册」——在 BUY 请求册上记停因（本记录决定三）；入账不重投照旧。越权风险点 1、3 由本记录作答。
- **ADR-0208**：决定三两句——「补登之后，已入账的那一份不回补」：那一拍记进发起停办册、补登后续办（决定四、五）；「册不设修订：同原因换一个费用项目或给没登的行补登，都答冲突」：触发册纳入修订形，没登费用项目的那一版可追加一版带费用项目的（决定七）。**适用场景**：同原因换一个已登的费用项目仍答冲突。越权风险点 4 由本记录作答。

## 候选与反方

- **同一份请求重问计价，不另起一代。** 计价按回指至多为一份请求形成一份评价，评价不可变；采用那一段停下的请求重问只会命中原评价。计价没形成评价的那几格倒是能按同一份请求重问，但两种停法续办出两种形状，读的人要分辨哪份请求问过几次。否决：两路一个续办形状。
- **在原请求上改记结论、补上费用。** 改写了「这份请求当时得到了什么答案」，历史与评价对不上。否决。
- **计价自己记停办、自己按价卡登记重形成。** 结算那一侧的请求仍停在`已提交`、看不出卡在哪；采用那一段停下的仍要结算另起请求，两处各管一半。否决：停因只记在请求册上一处。
- **定时扫描停着的请求重驱。** ADR-0094 决定四否决过：没有登记时重驱只会再停一次，扫描周期也是一项租户取值。否决。
- **答`未配置`仍按未决重投、只把失败预算放大。** 重投永远等不来一次登记，放大只是把 `ABANDONED` 推后。否决。
- **发起之前停下的那一拍也写进请求册（账户、计价范围等格可空）。** 计价按标识回读请求会落空，请求册上每一个读口都得为缺格分支。否决：另立发起停办册。
- **一次参数登记续办全部停着的，不按停因筛。** 不相干的登记（另一个范围的卡、另一本册）会给每一份停着的请求多推一代、照样再停。否决：按停因筛，再按信封带的收窄格筛。
- **序列与目录登记按种类续办、不收窄。** 汇率按日喂进来，一个租户停在缺区上的请求每天都会被推一代、照样再停，代次链被无意义的历史淹没。否决：计价按绑了它的卡交各面，待判断再按缺的是什么分格，序列解不开缺区。
- **按停着的请求当时选中的那一版卡收窄（而不是绑了它的全部卡）。** 结算的请求上没有卡的版本，按计价基准时点重选一次卡就是在结算这一侧替计价选卡。否决，代价见越权风险点 4。
- **「评价未形成」与「参数已登记」同分区排队。** 能保证「这份请求停在没卡」先于「卡登了」被结算处理；但同一租户停着的请求可以成千上万，排进租户那一条队就要一拍一封地等。否决，代价见越权风险点 5。
- **运营续办做成管理台运营决定（新决定种类）。** 要新开 access_identity 决定种类、端点与 Intake，本票先给受控进程入口兜底。留作后继，见越权风险点 8。

## 越权风险点

1. **停因与登记种类的对照是产品策略**（SA、PP owner）。例如不可计价与评价失败只认价卡登记，目录读不出认目录与价卡、序列读不出认序列与价卡（卡没绑那一类时只有新一版卡解得开），映射不全只认映射登记。价表没有这一段代决认价卡与目录：它多半出自卡，但卡绑了目录、目录把邮编映到错区时补一版目录也解得开；目录复核按绑了它的卡收窄、不按日喂，多推的代价小，owner 若认为错区该另立一格（例如由计价把「查表落空的分区出自目录」写进问题项），改的是领域一处那张表；待判断的分格按计价的问题项译，分不出的落笼统那一格、三类计价登记都推。owner 若认为某一格另有恢复方（例如不可计价也可能因目录补齐而变），改的是领域一处那张表；计价日后多一种问题项，结算读口不认就落笼统那一格，要有人来定它归哪一格。
2. **发起停办续办出来的是首代，不是「回指前一代」**（SA owner）。发起之前那一拍没有请求可回指；代次链从第一份请求起，那一拍按自然键与发起停办册对上。
3. **下一代不重走结算账户链**（SA owner）。SELL 下一代照抄前一代的账户、币种与计价范围。今天账户册与采用册都不可变，答案相同；日后若给两册加修订，下一代仍按旧账户问，届时另裁。
4. **收窄到哪一层**（PP、SA owner）。
   - 序列与目录按「绑了它的卡」的计价范围与方向收窄，不分卡的版本与适用期：结算的请求上没有卡的版本，按基准时点重选就是替计价选卡。于是同一范围上另一版卡（没绑这条序列的那一版）问到的请求，停在序列读不出上也会被推一代，再停一次、多一代历史。
   - 求范围要把这个租户的全部卡读一遍、逐张整图重验，一次复核问一次；卡多的租户这一步慢，且任一张卡快照读不回会让这次复核整笔未决。
   - 结算账户登记不收窄：「结算账户已登记」那一封与小包托运共用，载荷只有租户与种类、不带账户键。停在账户没登的那一刻账户键（法人、相对方、方向、币种、政策）其实已求出、记得下，缺的是信封上可比的那一格。代价是每登一户（含应付户）都把全租户停在账户没登上的发起停办重跑一遍；多推的那几拍照样停着，只换上这一次的依据与时刻。要收窄得在发起停办上记账户键、信封带键（至少带方向），另裁。
   - 序列按「绑了它的卡」收窄，不按缺的是哪一条：一张卡同时绑汇率（按日喂）与燃油（按周、按月喂）时，停在燃油读不出上的请求会被每天的汇率复核推一代、照样再停，直到燃油那一期登进来。要收窄得在请求上记缺的是哪一条序列（计价的问题项里本带序列标识），另裁。
   - 费用项目映射登记不收窄：停下的请求上记的是映射不全，没有记缺哪一个计价费用代码；多推的请求多一代、照样停在映射不全。要收窄得在请求上记缺的代码，另裁。
   - 笼统的待判断三类计价登记都推。
5. **竞态**（SA、PP owner）。「评价已记录」「评价未形成」与「参数已登记」不在同一分区：若租户恰在评价形成与结算记停因之间登了参数，续办门先到时那一份还没停下、不被取，要等下一次登记或运营续办。
6. **要换一版卡才解得开的几格，今天续办不出评价**（PP owner）。取整未声明、不可计价、评价冲突、价表没有这一段（缺重量段）都要新一版卡。计价按（租户、范围、方向、目的、时点）选卡：与旧版同期间的新一版答适用冲突，期间不重叠的新一版又不覆盖停着的请求的计价基准时点。所以价卡登记照表续办这几格，下一代要么停在适用冲突、要么仍停在原格，等票 [demo-chain-gaps/150](../../.scratch/demo-chain-gaps/issues/150-price-card-has-no-controlled-cut-off-for-a-superseded-version.md)（已升 R1）给卡一个受控的截止口。首周的四格里，只有缺区（目录补登）与汇率晚到（序列喂进）会自动续办出评价；缺重量段等 150；缺尺寸（包裹事实不全）没有哪一类登记解得开，只能等小包托运那一侧补上尺寸之后运营续办。
7. **迁移前卡住的请求不回补**（SA owner）。迁移前停在`已提交`而实际已卡住的（计价答不出评价按未决耗尽、评价失败）从行上看不出来，不在续办队列里，也不能经运营续办口点名——续办只推带停因的请求，推`已提交`的会与计价那一侧还在路上的评价撞出两笔费用。迁移前的`待判断`标「停因未记」。上线前没有租户，演示库可重灌。
8. **运营续办只有受控进程入口**（SA owner）。没有管理台页面、没有运营决定种类、没有「停着的都有谁」的查阅读口，运营要知道停了哪些今天只能查库；另立票 [demo-chain-gaps/151](../../.scratch/demo-chain-gaps/issues/151-stalled-evaluation-queue-has-no-operator-view.md)。
9. **`采用了别的时点`不记发起停办，重跑答它就落终止**（SA owner）。这一户登的采用不可变，记了也永远不会续办；停在计费时点没采用的那一拍、补登的采用是另一种时点时，同理落终止。若 owner 日后给采用册加修订，这两处都要回头补：首到时不记的那一拍、落了终止的那几行都不会因采用改了而再等。
10. **BUY 触发册只允许补空格**（SA owner）。已登的费用项目换成另一个仍答冲突。
11. **评价失败只认价卡登记**（PP、SA owner）。失败若出自计价自己的缺陷，换一版卡续办只会多一代失败；修好缺陷之后走运营续办。
12. **续办门里一件矛盾让整封落发布失败**（SA owner）。已续办的那几件不回滚；重投时它们因有了下一代或请求而不再被取，矛盾那一件反复撞到失败预算耗尽。
13. **结算政策没采用今天没有续办路**（SA、PC owner）。这一格的答案在委托接受时固定的商业闭包上：结算这一侧任何一本册的登记都改不了它，运营续办重跑读到的是同一份闭包、照样停下。这件包裹在这一时点的预估客户费用今天形成不了。出路归 SA 与 PC owner——例如重新接受（另立一份委托、另固定一份闭包），或给已固定的闭包立一个受控的修订形——两样今天都没有；去向记在票 [demo-chain-gaps/158](../../.scratch/demo-chain-gaps/issues/158-settlement-policy-not-adopted-has-no-resumption-path.md)。

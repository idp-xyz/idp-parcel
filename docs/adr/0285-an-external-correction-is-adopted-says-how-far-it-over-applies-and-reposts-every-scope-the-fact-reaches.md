# ADR-0285：外部更正先锁事实身份行再数未撤销核销的合计，照采、不拒，新金额低于合计时答复带出超核金额，并在同一事务里重算这条事实落到的全部客户应收作用域

Status: Accepted（2026-10-26，Claude Code 会话代 SA owner 裁定：协调方据用户「你作为业务和系统专家自决」授权，把票 [docs-consistency/code/92](../../.scratch/docs-consistency/code/92-a-funds-fact-correction-below-its-applied-total-is-adopted-silently.md)「要裁的」两条裁为——超核是更正结果上的一个字段、不是新的拒绝格，不建待处理册；更正是否算 ADR-0181 决定一的重算点、重算哪几个作用域、锁序怎么接进全序由作者代决。出处票 [code/12](../../.scratch/docs-consistency/code/12-funds-mapping-has-no-compensation-or-recovery-targets.md) 第二轮评审 N3。部分停用（扩成）[ADR-0181](./0181-posted-balance-is-recomputed-in-the-funds-mapping-transaction.md) 决定一一句与 [ADR-0283](./0283-a-funds-fact-mapped-into-several-customer-scopes-is-posted-by-its-applications.md) 决定三一句，被停原句与适用场景见「对已接受记录的作用」；回答 ADR-0283 越权风险点 4，无条款停用；两份正文不改，只在其 Status 行与 Links 加前向指针。越权风险点见文末，待 SA owner 复核。）<!-- 索引注记 -->｜**判据**：外部系统拥有资金事实，更正照采，不因超核拒收；新金额低于事实上未撤销核销的合计即超核，差额随更正的结果交回（`FundsResult.OverAppliedMinor`），不是新的结果格，不改 HTTP 状态码，不自动撤销任何核销。**锁**：更正先对事实身份行 `FOR UPDATE`（与核销、撤销、映射同一把，全序首位），取到再读、再数合计；事实落到的客户应收作用域在落版本行之前按键序取齐。**重算**：更正也是 ADR-0181 决定一的重算点，同一事务里重算事实落到的全部客户应收作用域，不论金额升降，不逐个判 P 动没动；某个作用域账已不平（已确认未结按账求出为负）、推进不了时，更正照采，该作用域跳过、留在原值，答复点名它（`FundsResult.UnreconciledScopes`），其余作用域照推。**答复**：HTTP 响应体 `overAppliedMinor`（仅超核时在场）与 `unreconciledScopes`（仅有作用域被跳过时在场），状态码仍是 201；受控 CLI 说「累计超核 X」（与映射、核销答复同一句话）并点名被跳过的作用域；读面上的累计未分配为负、不截成 0。不建待处理册，超核靠读面与这些答复发现。

Date: 2026-10-26

## Context

- [ADR-0181](./0181-posted-balance-is-recomputed-in-the-funds-mapping-transaction.md) 决定一把入账余额的重算放在拥有那次变化的用例事务里，列了采用并映射、核销、核销撤销这几个点；[ADR-0283](./0283-a-funds-fact-mapped-into-several-customer-scopes-is-posted-by-its-applications.md) 决定三按这几个点逐一定了重算哪几个作用域。外部更正（`UC-SA-005`、`AT-SA-114`「外部事实金额被更正 → 保留原版本，按新有效版本重算差额和核销」）不在其中：更正落版本行、交采用信封，什么都不推进。
- 入账余额的 P 取事实链头的金额：收款只落到一个作用域时记 d + r 且不超过事实金额，落到几个作用域时只记 d 且不超过事实金额，退回扣 d + r 且不超过事实金额（ADR-0283 决定二）。链头金额一变，每个作用域的 P 都可能跟着变，可更正这一步不推进，`operational_balance` 停在更正前的数上，直到同作用域下一次映射、核销或撤销才跟上。预付冻结读可用余额，以入账余额为基数的比例额度读 `posted_minor`，这段时间两处读的都是旧数。
- 更正照采是对的：外部财务或支付系统拥有真实收付款事实（SA `CONTEXT`「运营余额、收付款与坏账」），本上下文拒收一条银行已经更正的金额，等于自己的账与银行的账不一致。可采下来之后，事实上未撤销核销的合计可能多于新金额（超核）：更正自己的答复什么都不说；资金事实册读面的累计未分配为负、不截成 0，映射与核销的答复说「累计超核 X」，这是今天仅有的信号。对同一事实再交核销一律答 `APPLICATION_IMBALANCE`，没有一格告诉操作员该先撤哪一笔。
- 事实身份行上的锁只护住了核销一侧：核销取 `FOR UPDATE`，更正落版本行时外键对身份行取的 KEY SHARE 与它互斥，于是核销读到的一定是更正之后的金额。更正这一侧若要数合计，那把 KEY SHARE 来在读之后，晚了：更正读到的合计看不见与它并发、已先拿到身份行锁的那笔核销（票 code/12 第二轮评审 N3，第三轮改准了 `LockFundsFactApplications` 头注）。
- 作用域的账可以已经不平：确认之后的价格纠错贷记不核已核销分配（库不拦，`UC-SA-002` 也不核），已确认应收会降到已核销分配之下，作用域的已确认未结按账求出为负，推进失败。这不是更正造成的——更正不动已核销分配，也不动已确认应收。
- [ADR-0022](./0022-http-status-carries-answer-formed-not-business-verdict.md)：HTTP 状态码只答有没有形成答案，业务判别在响应体。[ADR-0029](./0029-retrieval-failure-algebra-is-partitioned-by-recovery-action.md)：确定性拒绝不进未决，读不动才是未决。

## Decision

**一、更正照采，超核不拒绝；超核是更正结果上的一个字段，不是新的结果格。** 超核金额 = 事实上全部未撤销核销的合计 − 新有效版本的金额，不为正即 0。它在 `FundsResult.OverAppliedMinor` 上随更正的答复交回；更正本身成立，结果格仍是已采用（HTTP 201），字段只在大于 0 时有话说。

- HTTP：响应体的 `overAppliedMinor`，仅超核时在场，状态码不变（ADR-0022）。采用与更正两口共用的响应形，管理台手工登记口随之带出。
- 受控 CLI：更正的答复说「事实 X 累计超核 N」，与映射、核销答复同一句话；退出码不变，更正是已采用。管理台登记答案示出同一句。
- 重放同一次更正答`已存在`时带出此刻的超核：响应丢了、操作员重交仍能看到这个信号；两次答复之间若有核销撤销，数会不同，后一次才是此刻的。只有此刻的链头才有超核可说，被后来的更正取代的那一版（重放首版）不带。重放不重算，也不重新判作用域账平不平。
- 不自动撤销任何核销。撤哪一笔是人的判断，核销撤销本是另一个入口（`UC-SA-005` 核销撤销/重分配，不借资金变化创建金额调整），超核的续办就是用它。

**二、锁：更正先对事实身份行取锁，取到再读、再数合计。** 锁是 `ports.FundsFactApplicationLock` 那一把，与核销、撤销、映射同一把，在资金侧全序的首位；锁后另起一句求未撤销核销的合计，等锁的那一路读得到先到那笔已提交的核销。事实不在册答`未受理`，锁读不动答未决（资金事实库不可用）。

- 事实落到的客户应收作用域（决定三）按（法人、账户、币种）键序，在落版本行之前取齐；其后版本行插入、`operational_balance` 的 upsert、采用信封入队这些隐式的行锁都落在作用域锁之后。更正取的锁是全序（事实 → 金额本体 → 运营余额作用域）的子序列：事实 → 作用域，不碰金额本体。
- 没有被受理的更正（回指非链头、事实未采用）只取事实锁，不取作用域锁，什么都不落。事实还没映射到任何客户应收作用域时更正无账可算，同样只取事实锁。
- 先对事实锁、后落版本行，更正与核销在事实身份行上排队，先后哪一种都落到自洽的终态：更正先到，核销读到更正后的金额，越过它即答分配失衡；核销先到，更正数得进这一笔，超核金额是终态的已核销合计减新金额。

**三、更正也是重算点：落版本行之后、交采用信封之前，在同一事务里重算这条事实经对账单或账户映射落到的全部客户应收作用域。** 求法照 ADR-0181 决定二、三，仍是 `recomputeScope` 那一个函数。

- 不论新金额比旧的高还是低都重算：金额变，只落到一个作用域的收款没核销的部分与封顶、退回的 d + r 与封顶都随之变；落到几个作用域的收款只在金额越过某个作用域的 d 时才动。逐个判哪个作用域的 P 真动了，要么把求 P 的 SQL 搬到应用层，要么多开一个读口；多重算一个同值的作用域只是推进它的截至时点，不改任何数。取全部，不判。
- 收付之外的事实（付款失败）不进任何客户应收作用域，不重算。信用状况行读的是已确认费用的到期画像，不读资金事实的金额，更正不重算它。
- **作用域账已不平时，该作用域跳过，更正照采。** 事实落到的某个作用域，已确认未结按账求出为负（`ErrNegativeConfirmedUnsettled`）时，重算推进不了：这个作用域不推进、入账余额与已确认未结留在原值，其余作用域照推，版本行照落、采用信封照出。答复点名被跳过的作用域（法人、账户、币种；`FundsResult.UnreconciledScopes`）：HTTP 响应体的 `unreconciledScopes`，状态码仍是 201；受控 CLI 点名并说入账余额没有跟着新金额推进，退出码仍是 0；管理台登记答案示出同一句。跳过发生在任何写之前，不会把事务打进中止态。
- 那个作用域留在旧值，直到账回平后下一次碰到它的映射、核销、撤销或更正，那一次按当时的链头金额重新推进。要人核对指向它的核销与调整——撤掉多出的核销，或补正调整——答复里的点名就是续办的入口。
- 别的错误（时钟回拨致推进答未推进、事实库读不动）照旧整笔回滚：版本行不落、信封不出，与映射、核销同形。

**四、不建待处理册。** 超核的事实靠这几处信号发现：资金事实册读面上的累计未分配为负（不截成 0，一直在、可查）、更正的答复（HTTP 响应体与受控 CLI）、之后对同一事实的映射与核销答复。没有一本册把超核的事实列出来等人撤销。

**五、存量不回填。** 本记录之前已经更正过的事实，它落到的作用域要等下一次映射、核销、撤销或更正碰到时才按新金额重算。首发前库里只有演示租户的合成数据，可以接受。

## 候选与反方

- **超核时拒收更正（新结果格或`未受理`）。** 否决：外部系统拥有资金事实，拒收就是本系统与银行账不一致；而且拒收后外部重投永远同一个结果，更正永远进不来，超核反而没人看见。
- **把超核做成采用编排的一个新结果格。** 否决：更正本身成立，格会让「已采用而且超核」靠两个格合成；每个结果格的消费方（HTTP 译装、CLI 退出码表、管理台词表）都要多开一格。字段只在有话说时在场，不认识它的消费方原样工作。
- **更正自动撤销超出的核销。** 否决：撤哪一笔（后到的先撤、按金额、按目标）是人的判断；自动撤等于借资金变化改核销关系。
- **待处理册。** 否决：超核的续办是核销撤销，入口已有；读面上的负数是持久的、可查的状态，不会因为没人看而消失，一本册还要再设「处理完」的出口。与 [ADR-0282](./0282-a-control-release-the-provider-refuses-is-registered-for-handling-instead-of-compensated.md) 不同：那里没有别的持久信号，这里有。
- **只靠落版本行时外键的 KEY SHARE 排队，不另取锁。** 否决：那把锁来在读之后，合计读的是旧账，见 Context。
- **用咨询锁代替身份行锁。** 否决：咨询锁挡不住不取它的写入方，同票 code/12 的结论。
- **更正提交后另起一笔事务去重算。** 否决：同 ADR-0181 决定一否决乙的理由——预付冻结在估价形成时读余额，更正提交与余额跟上之间没有一格可答「账已更正、余额还没跟上」。账不平的作用域留在旧值是有名有姓的一格——答复点名它（决定三）——不是无声的落后。
- **作用域账不平时更正整笔回滚。** 否决：不平不是更正造成的，把更正拦在内部账之外，外部系统拥有的资金事实就永远进不来，HTTP 上它还会按 5xx 无限重投（ADR-0022）；理由同上面否决「超核时拒收更正」。ADR-0283 否决「全部作用域重算」的理由也正是一个作用域的不平会把别的作用域上的操作拦成账不平。
- **只重算超核时的作用域，或只重算 P 真动了的作用域。** 否决，见决定三：升也要重算，逐个判的代价大于多重算一个同值的作用域。

## 对已接受记录的作用

- **部分停用（扩成）** ADR-0181 决定一「`UC-SA-005` 在采用并映射、核销、核销撤销各自的事务里，按下面的求法重算该作用域的入账余额与已确认未结，并推进 `operational_balance`。」一句。**适用场景**：重算点在采用并映射、核销、核销撤销之外加上外部更正（形成新版本的那次事务），重算的是这条事实落到的全部客户应收作用域；决定二的求法、决定三「函数只有一个」与其余各条不变。
- **部分停用（扩成）** ADR-0283 决定三「只重算这一笔改了 P 或 W 的作用域，照 ADR-0181 决定一在拥有那次变化的事务里重算。」一句。**适用场景**：只限外部更正这一个重算点——它取事实落到的全部客户应收作用域、不逐个判 P 动没动；映射、核销、撤销照原句，决定三下的各条（含「别的作用域不碰」与账不平的答复带作用域身份）对它们不变。更正碰到的作用域若账已不平，该作用域跳过、答复点名，不拦更正，见决定三末条与越权风险点 2。
- **回答（无条款停用）** ADR-0283 越权风险点 4「外部更正不重算」：更正这一步现在推进作用域，见决定三。
- ADR-0283 决定二「一个作用域从一条事实上记到或扣掉的都不超过事实金额，外部更正把金额改到已核销合计以下（超核）时也是。」与决定四的锁序（事实身份行在前、作用域按键序）照用，不停用：更正推进作用域之后，「超核时也封顶」才落在更正之后的入账余额上。

## Consequences

- 代码随票 code/92：`MapExternalFundsHandler.CorrectFact` 先取事实锁再读、数合计、取齐作用域锁、落版本行、重算、交采用信封；`FundsResult.OverAppliedMinor`；HTTP 响应体 `overAppliedMinor`；受控 CLI 更正的答复；管理台登记答案示出超核。`ports.FundsFactApplicationLock` 与 `SettlementApplications.LockFundsFactApplications` 的头注改准——更正侧不再「得自己先取锁」，它走这同一把。不加迁移。
- SA `CONTEXT`「运营余额、收付款与坏账」补一条规则句。`UC-SA-005` 补并发一条，状态行与交接节里指向本票的缺口行随之去掉；`AT-SA-114` 现在两半都有测试点名（事实是引用与保留原版本，新版本重算与超核）。
- 更正的事务现在与同一事实上的核销、撤销、映射在身份行上排队，持锁时间含重算几个作用域。更正少见，核销与映射在这条事实上排的时间不会成为瓶颈。
- 更正在每个账平的作用域上推进 `operational_balance` 的截至时点，即使数没变：时钟回拨致「同键只准往前」答未推进时更正整笔回滚（`ErrPostingNotAdvanced`），与映射、核销同形。

## 越权风险点

1. **超核没有待处理册，只能靠读面发现**（协调方裁、作者记）。超核的事实靠资金事实册上累计未分配为负、更正的答复、之后对它的映射与核销答复发现；没有一本册把它们列出来。更正答复里的数是更正那一刻的快照，之后别的核销撤销会改变超核，不会更新；读面上的负数才是此刻的。若 owner 要一本册（或事实册上的「只看超核」筛选）让它们等人撤销，只加读面，不动本记录的锁与重算。
2. **账不平的作用域留在旧值**（作者代决）。更正本身不动 W 与已确认应收，造不出不平；事实落到的作用域若已经不平，更正照采、那个作用域跳过，答复点名它（HTTP `unreconciledScopes`、受控 CLI、管理台）。代价是那个作用域的入账余额停在更正前的数上，与更正后的金额对不上，直到账回平后下一次碰到它才跟上；这段时间预付冻结读到的可用余额是旧的。读面没有单独列「哪些作用域停在旧值」，只有这一次答复点了名；重放更正不重新判，也就不再点名。若 owner 要读面上能查到停在旧值的作用域（例如运营余额行带一个「待重算」标记），那是另一份读面，不动本记录的锁与重算。
3. **不逐个判 P 动没动**（作者代决）。落到几个作用域的收款，更正只在金额越过某个作用域的 d 时才真改那里的数，其余作用域被多重算一次、数不变。账不平的作用域里 P 其实没变的那几个，也会被点名成「没推进」；若 owner 要精确，可在 `CustomerDirectionNets` 旁加一个按作用域算 d 的读口，更正只重算金额越过它的那几个。
4. **存量停在旧值**：本记录之前更正过的事实，作用域要等下一次碰到才跟上。首发前只有演示租户；有真实租户再换口径要一条按作用域全量重算的运维路径，今天没有（同 ADR-0283 风险点 5）。
5. **作用域咨询锁的键是哈希**：更正一笔取几个作用域时，撞上同一把锁的两个作用域会让锁的先后不再跟着键序，最坏由库的死锁检测拒掉其中一笔、答未决重试；不错账（同 ADR-0283 风险点 7）。
6. **重放带出此刻的超核**，两次答复在其间有撤销核销时会不同。

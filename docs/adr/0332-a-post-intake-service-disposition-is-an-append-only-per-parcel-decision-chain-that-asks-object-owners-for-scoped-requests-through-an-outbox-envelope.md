# ADR-0332：收寄后服务处置决定是每个包裹一条只追加的决定链，去向封闭为继续、拦截、改送、退运、服务终止，只经信封向各对象所有者提出范围化请求，授权是「运营决定」族新立的一种

Date: 2026-10-28

## Context

- PS CONTEXT 写了收寄后服务处置决定的语言、规则与生命周期：包裹越过适用取消边界后不得回退为`已取消`，只能由有权主体按包裹形成明确决定，决定向路由、节点、运输、关务、结算等对象所有者提出范围化请求，各所有者分别承接与执行。代码只有取消编排在越界时记下的一格`待处置`，这一格连请求方、授权依据、原因都没有保全，决定人看不到自己在回应谁的什么请求。
- TF 的另起旅程（UC-TF-007）以服务处置决定作依据种类，引用的正是 PS 一侧还不存在的这份决定。
- [ADR-0295](./0295-a-cancellation-order-conflict-is-resolved-by-an-operator-decision-that-either-sets-the-cancellation-aside-or-refers-the-boundary-fact-to-its-source.md) 决定三之一让一份被认定依据不成立的取消不再是有效取消，并明说客户侧已收到的`包裹已取消`怎么改口属收寄后服务处置，只交出口。这类请求没有`待处置`记录，却同样等一份回应。
- 谁有权决定、哪些去向对哪个产品可用，是租户取值（`PAR-COM-05/06/17`、`PAR-NET-11/13/14/15`），未登记答未配置。

## Decision

**一、决定是每个包裹一条线性的只追加链。**

- 版本从 1 起；后一份取代前一份成为当前决定，前面的一字不动。撤回、更正都是在链尾追加一份（例如追加`继续`撤回此前的拦截）。主键（租户，包裹，版本），库内 CHECK 把链钉成线性，不分叉。
- 每份决定固定：包裹、去向、来源（`CUSTOMER_REQUEST` 回应一份客户停止请求，必须指名它；`OPERATOR_INITIATED` 运营自己发起，必须不指名）、实际决定方（认证出的操作者，格式 `发行方#sub`）、依据（必填，决定人核对产品、合同、客户授权、限制与可执行性后的结论或证据引用；本上下文只要求在场，够不够由各所有者承接时各自判）、生效时间（追加时刻，没有另行约定的生效时刻）、责任范围（决定时在册的责任起点版本）。
- 决定链尾以外，命令带「决定人看到的前一版」：与链尾对不上答`前一份已变`并读回链尾，让并发的两个决定人不互相覆盖。同一决定人带同样内容重发，读回先前那一份（`已决定过`），不追加、不再发信封。一份客户请求至多被一份决定回应（库内唯一约束）；之后要改，是追加一份运营发起的更正。
- 前提：包裹此刻有责任起点（越过取消边界），且没有当前有效终局或有效取消。没有责任起点答`未越过边界`（确定的拒绝，不是未决：取消走取消编排）；已有终局或有效取消答`终局成立`并指名它（新需求建立关联委托，不重开原结果）。读口读不动是答案未形成，整笔失败让人重来，不当作未决。
- 决定与同一包裹上的取消、收寄采用、终局采用、冲突解开共用包裹取消边界锁，决定的前提正是它们在锁里写的东西。

**二、授权：「运营决定」族新立 `POST_INTAKE_SERVICE_DISPOSITION`，租户取值，未登记答未配置。**

- 与授权处置、取消先后冲突解开分开授予：这一种改的是一件已在网络手里的包裹的实物去向与后续服务，认错了会让包裹被扣、被退或被终止服务。租户与决定人只取自认证结果，不从请求体收；谁持有是租户取值，未登记时没有人能决定，不默认任何角色。
- 决定走 `POST /post-intake-disposition-decisions`；运营按租户查阅等回应的停止请求走 `GET /post-intake-disposition-requests`（操作者主数据与运营查阅读面），逐字段给出请求键、包裹、来路、请求方四件、当前决定链版本。查阅面里没有动作。命令指名的请求查无、属别的租户或不是一份待回应的停止请求，同一个统一不可见答案（404）。

**三、处置去向是封闭集合：继续、拦截、改送、退运、服务终止。**

- **继续**：不改变服务，是对一次停止请求的明确答复，也是对此前拦截等决定的撤回；不请求任何所有者。
- **拦截**：在当前控制方处扣住、不再向前移动；请求节点`在控制处扣住`、运输`不再安排向前移动`。
- **改送**：同一收件关系内改去另一个交付去向，必带目的地引用（本上下文只记引用，由交付去向所有者解读）；请求路由`按目的地重新规划`、运输`另起备用旅程`。换收件人、客户账户或产品属服务变更，形成关联新委托，不在这里。
- **退运**：普通或商业退运，另起关联但独立的退运旅程；请求路由规划退运路径、节点按退运装载交出、运输另起退运旅程。监管退运由监管处置决定经 `UC-TF-001` 承接，这里的退运不冒充它，信封的依据种类恒为服务处置决定。
- **服务终止**：终止后续服务；请求路由释放尚未消耗的计划、节点扣住、运输不再安排移动。实物去向另需一份退运等决定；终局服务结果只在所有者的执行结果满足合同终局规则时由 UC-PS-004 形成。
- 所有者请求表是代码里的封闭表。没有任何一个去向直接改写所有者的对象，也没有一个去向倒退原旅程或形成「停止中」之类的包裹总状态；委托汇总不读决定。

**四、决定只经信封向对象所有者提出范围化请求，与决定留痕同笔。**

- 决定追加与信封入 Outbox 在同一事务（[ADR-0094](./0094-undecided-retry-is-decided-by-resume-path-with-a-fourth-grade-for-operator-registration.md) 决定四）。信封事件类型 `parcel-shipment.post-intake-disposition.decided`，信封 ID 由（租户，包裹，决定版本）认领，一个版本至多一封；分区取（租户，包裹，口名段），同一包裹的决定链按版本先后一条队，不与同包裹的取消、采用、终局信封同队。
- 载荷（版本 1）带包裹、决定版本与所取代的版本、去向、来源、回应的请求、目的地、责任范围、与原旅程的关系（改送、退运为关联但独立的新旅程，其余不变）、依据种类与依据引用（指名链上这一版）、对各所有者的请求清单、生效时刻。决定人与依据正文不进信封，留在决定表。
- 各所有者承接与否、怎么执行、拒绝与否都是它们自己的事实。本记录不立「承接结果」的读回面；各所有者消费这封信封并回报承接结果属各自上下文的票（见 Consequences）。

**五、等回应的请求有两个来路，待处置记录保全请求本身。**

- 取消编排越界时记`待处置`，同时保全请求方、授权依据、原因与请求的业务时间（`parcel_cancellation` 待处置那一支的在场件矩阵放宽：四列要么全空、要么全在）。0033 之前落下的记录四列为空，读方只当成「当时没有保全」，不当成没有请求方。
- 被取消先后冲突解开决定认定依据不成立的取消（ADR-0295 决定三之一）同样等一份回应，来路标 `CANCELLATION_NOT_UPHELD`。
- 「已被回应」是有一份决定的请求键指名它，不是请求记录上的状态列。包裹已有当前终局的请求不在等回应清单里，不让它堆成永远清不掉的行。

## 候选与反方

- **不立决定链，只在待处置记录上改一个状态列。** 否决：状态列会被覆盖，更正与撤回没有留痕，也没有地方放决定人、依据与责任范围；CONTEXT 要求每个包裹的明确决定可审。
- **处置去向另加「销毁」「免除费用」等。** 否决：CONTEXT 明说任何必要依据缺失时不默认退运、销毁、继续或免除费用；封闭集合先取 CONTEXT 词条已点名的五个，加一个去向是新 ADR 的事。
- **一份决定一条信封发给所有者，每个所有者一封。** 否决：一份决定的范围化请求是一件事，拆开会让「请求发出一半」成为可能；一封信封带请求清单、各所有者各取自己的，与同笔落地一致。
- **决定直接调各所有者的应用口执行。** 否决：违反上下文所有权，PS 不拥有路由、节点、运输的对象；ADR-0004 的承诺、计划、实际事实分离也要求执行结果是所有者自己的事实。
- **监管退运也走本决定。** 否决：监管处置的决定方与门禁不同，必须经 `UC-TF-001`；本决定的退运恒为普通或商业退运，依据种类不可冒充。

## 对已接受记录的作用

不停用也不改写任何已接受记录。ADR-0295 决定三之一留的出口（取消依据不成立之后客户侧怎么改口）由本记录接住：那类请求进等回应清单，由本记录的决定回应。

## Consequences

- 新增迁移 `access_identity/0028`（决定种类 CHECK 加一个词）与 `parcel_shipment/0033`（待处置记录保全请求四件、等回应的部分索引、`post_intake_disposition_decision` 表）。
- 新增生产入口 `POST /post-intake-disposition-decisions` 与 `GET /post-intake-disposition-requests`，装配在 `cmd/parcel-api`；管理台页另跟。
- 各所有者对信封的承接（TF 另起备用或退运旅程并以链上这一版作依据、NO 扣住与按退运装载、NR 重新规划与释放）、承接拒绝的保留（`AT-PS-088`）与监管退运转 `UC-TF-001`（`AT-PS-084`）不在本记录范围，由各上下文另票承接；在那之前信封入队后无人消费，决定本身仍成立、可审。
- 授予是租户取值：租户一登记即生效，未登记时没有人能决定，等回应清单照常可查。

## 越权风险点

1. 去向封闭五个、各去向的所有者请求表（尤其服务终止同时请求节点扣住与运输不再移动）由作者按 CONTEXT 词条提出，待 PS owner 认可；知会 NO、TF、NR owner 核对请求动作的名字与粒度。
2. 授予单立一种而不并入授权处置，是作者对职责不同的判断，待访问身份 owner 复核。
3. 决定链的「前一份已变」与「请求已被回应」两个确定答案、以及终局或有效取消在册时答`终局成立`而不是拒绝，是作者的取舍，待 PS owner 复核。
4. 信封载荷不带决定人与依据正文，是作者出于「不扩散自由文本」的取舍，待 TF owner 复核消费侧是否需要。

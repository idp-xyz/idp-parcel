# ADR-0283：一条资金事实落到几个客户应收作用域时，每个作用域只按指向它的核销分配记入入账余额；没核销的收款不计入任何作用域，没核销的退回在每个作用域都先扣

Status: Accepted（2026-10-26，Claude Code 会话代决，代 SA owner 裁定：协调方据用户「你作为业务和系统专家自决」授权，把票 [docs-consistency/code/94](../../.scratch/docs-consistency/code/94-a-funds-fact-mapped-into-several-scopes-is-posted-in-full-in-each.md)「要裁的」裁为乙；乙的条款、资金退回没核销那一截的记法、币种不同的作用域算不算一个由作者代决。出处票 [code/12](../../.scratch/docs-consistency/code/12-funds-mapping-has-no-compensation-or-recovery-targets.md) 第三轮轻评审 N-a。部分停用（收窄）[ADR-0181](./0181-posted-balance-is-recomputed-in-the-funds-mapping-transaction.md) 决定二两句，被停原句与适用场景见「对已接受记录的作用」；ADR-0181 正文不改，只在其 Status 行与 Links 加前向指针。越权风险点见文末，待 SA owner 复核。）<!-- 索引注记 -->｜**判据**：一条事实经对账单或账户映射落到的客户应收作用域个数，币种与事实不同的也算一个。**一个**：全额记入，不变。**几个**：每个作用域只记指向它的未撤销核销分配（对账单分配与账户分配都算）；收款没核销的部分不计入任何作用域，退回没核销的部分在每个作用域都先扣。**重算**：映射、核销、撤销都在自己的事务里重算这条事实落到的全部作用域，一个变几个的那一笔里原作用域的入账余额会降。**锁**：事实身份行在前，作用域咨询锁按（法人、账户、币种）键序。**读面**：资金事实册带出作用域个数与没记进任何作用域的未分配，受控 CLI 答复在多作用域时说出未分配停在哪。

Date: 2026-10-26

## Context

- [ADR-0181](./0181-posted-balance-is-recomputed-in-the-funds-mapping-transaction.md) 决定二把入账余额定为 P − W：P 是该作用域已采用并已映射的客户方向真实收付净额，W 是指向该作用域客户应收的核销分配净额，未分配就是这个差。作用域是租户、责任法人、结算账户、币种。SA `CONTEXT`「运营余额、收付款与坏账」照此成文，并要求不同责任法人、结算账户和币种默认不共用余额。
- 代码在一个作用域之内按事实去重（票 code/12「入账余额按事实去重是既有缺陷，本批顺修」），但每个作用域各算各的：同一条事实只要有一条映射落在这个作用域的对账单或账户上，这个作用域就按链头全额记。评审手算：收款 5000 映到账户 acct-1 下的对账单（作用域 A），又映到账户 acct-2（作用域 B），全部核到那张对账单之后 A 入账 0，B 仍入账 5000。预付冻结读可用余额，以入账余额为基数的比例额度读 `posted_minor`，两处都按多出来的钱放行，没有任何提示。
- 映射可以合法地指向几个作用域：同一付款人一笔款付两个账户，要先把这笔款映到两边，再核销分配。映射不是核销（CONTEXT「真实收付映射」），映射只说「这笔钱与哪个结算身份相关」，分配由核销显式判断。
- 核销分配沿映射走：每一片指名一条映射，目标与那条映射一致（`domain.ApplySettlement`）。所以一片分配指向哪个作用域，就是它沿的那条映射落在哪个作用域上。
- 资金退回是钱离开。SA `CONTEXT`「退回与撤销按反向映射离开」，`AT-SA-112` 要求追加反向资金映射和核销撤销，不删除原收款引用。
- 资金侧的锁按一个全序取：事实身份行 → 金额本体行 → 运营余额作用域咨询锁（票 code/12 修订轮）。映射原先只取一个作用域的锁，不取事实锁。

## Decision

**一、判据是这条事实落到几个客户应收作用域。** 对账单映射经那张对账单落到它的应收结算账户上（单与账户同币种），账户映射落到那个应收结算账户本身。映到审核应付、贷项或两格金额本体的映射不是客户应收作用域，不计数。币种与事实不同的作用域也算一个：它从这条事实上记不到钱，可这条映射本身说明这笔钱该归谁还没分清，不能因此让另一个作用域按全额放行。

**二、只落到一个作用域：照旧全额。** 那个作用域取链头金额，一条事实映到它的几个目标只算一次。ADR-0181 决定二原样适用。

**三、落到几个作用域：每个作用域只记指向它的分配。**

- 指向该作用域、尚未撤销的核销分配净额（借加贷减）记作这条事实在该作用域上的收付净额。对账单分配与账户分配都算指向该作用域，判据是分配沿的那条映射落在哪个作用域上。
- 收款没核销的部分不计入任何作用域。已映射到几个作用域、还没有任何核销的那段时间，每个作用域记 0：钱没分到谁头上之前，哪一边都不按它放行。
- 退回同一条规则，方向取反：指向该作用域的分配从该作用域离开。退回没核销的部分（事实金额减它全部未撤销核销的合计，不低于 0）在每个作用域都先扣。退回是钱离开，没分清从谁那里离开之前，每一边都按「可能是我」扣；记 0 等于在每个作用域都当钱没走，可用余额偏大，正是本记录要堵的那一类。
- 撤销一笔核销，它那几片离开所指的作用域，回到没核销的部分，照上面两条记。
- W 与已确认未结的求法不变：W 仍只加总指向该作用域对账单、尚未撤销的核销分配。

一条事实一旦全部核销，各作用域分到的加起来就是它的全额，与只落到一个作用域时的总数相同；不同的只是在核销之前，没有哪个作用域替它先记。

**四、重算点照 ADR-0181 决定一，范围是这条事实落到的全部作用域。** 映到对账单或账户的映射、核销、核销撤销，各在自己的事务里重算这条事实落到的全部客户应收作用域；核销与撤销另加对账单分配指向的作用域。事实从一个作用域变成几个的那一笔映射，原作用域的 P 从全额变为按分配，入账余额会降，就在这一笔里跟上，不等下一次碰到它。

**五、锁：事实身份行在前，作用域按键序。** 映到对账单或账户的映射先锁事实身份行，再插映射行，再按（法人、账户、币种）的键序锁这条事实落到的全部作用域咨询锁；核销与撤销照 code/12 定下的全序，作用域之间同一个键序。两笔映射把同一条事实同时映到两个作用域，不在事实锁上排队就各自只看见自己那一条映射，各按全额记。映到别的目标的映射不取任何一把锁。

**六、读面让没记进任何作用域的未分配看得见。** 资金事实册（`GET /settlement-funds-applications` 与管理台收付款核销页）每条事实带出它落在几个客户应收作用域上，以及落在几个作用域时还没分到任何一个作用域头上的累计未分配。受控 CLI `parcel-settlement-register` 的映射、核销与撤销答复在多作用域时说出这一截停在哪：收款未计入任何作用域，退回每个作用域都先扣。不新建页，不另设待处理册：续办是把钱核到作用域上，现有核销入口就是续办入口。

**七、存量不回填。** 首发前库里只有演示租户的合成数据，演示种子只把一笔收款映到一个账户，值不变。已经落在几个作用域上的事实，那几个作用域在下一次映射、核销或撤销时按本记录重算。

## 候选与反方

- **甲：一条事实已映射到某个客户应收作用域，再映到别的作用域就答`未受理`。** 否决：实现最小，但挡掉同一付款人一笔款付两个账户的合法场景，那一笔只能停在一个账户上再线下挪。
- **照旧每个作用域按全额。** 否决：钱只到一次却在几处各当一次用，碰钱且静默。
- **没核销的收款按映射数平分，或归给最先映射的那个作用域。** 否决：都是在猜归属。UC-SA-005「未分配」一格「不按金额或到期日猜测归属」，平分与先后同属猜。
- **另立一本「待分作用域」的余额。** 否决：SA `CONTEXT`「未分配就是这个差，不另列一本账」；本记录只改各作用域怎样记这条事实，不新增一本账。
- **退回与收款一样，没核销的部分各记 0。** 否决：见决定三退回那一条。
- **映射只重算新落到的那个作用域，原作用域等下一次碰到时再跟上。** 否决：原作用域的入账余额停在全额上，正是那段时间里可用余额多出来；ADR-0181 决定一要在拥有那次变化的事务里重算，这一笔映射就是原作用域那次变化的所在。

## 对已接受记录的作用

- **部分停用（收窄）** ADR-0181 决定二「已采用并已映射的客户方向真实收付：收款进入，退回与撤销按反向映射离开。净额记为 P。」一句与「入账余额 = P − W。未分配不是第三本要再加一次的账：P − W 剩下的就是尚未核销分配的已映射收付。」一句。**适用场景**：一条事实经对账单或账户映射落到两个及以上客户应收作用域时——它在每个作用域上的 P 只记指向该作用域、尚未撤销的核销分配，收款没核销的部分不计入任何作用域，退回没核销的部分在每个作用域都先扣；于是这条事实没核销的部分不再是某一个作用域 P − W 的一部分。只落到一个作用域的事实照两句原样；W 的求法、已确认未结、决定一的重算点与 ADR-0181 其余各条不变。
- ADR-0181 决定一照用，不停用：一条事实从一个作用域变成几个的那一笔映射，就是原作用域入账余额那次变化的所在，在这一笔里重算原作用域正是「在拥有那次变化的用例事务里重算并推进」。[ADR-0182](./0182-receivable-account-is-a-funds-mapping-target.md) 决定一「按 ADR-0181 决定二的 P − W 推进该作用域入账余额」同理照用，P 的求法随上一条收窄。

## Consequences

- 代码随票 code/94：`CustomerReceiptPostings.CustomerDirectionNets` 的 P 按事实落在几个作用域上分两种记法；映射收成作用域的口径收成一处，P、新读口 `FactCustomerScopes` 与资金事实册的作用域计数共用；`MapExternalFundsHandler.Map` 映到对账单或账户时先锁事实身份行，`Map`、`Apply`、`Reverse` 都重算这条事实落到的全部作用域；资金事实册、HTTP 读面、管理台与受控 CLI 带出决定六那几格。不加迁移。
- SA `CONTEXT`「运营余额、收付款与坏账」补一条规则句：落到几个作用域的事实按分配记入，未核销的收款与退回各怎么记，一个变几个的那一笔重算全部作用域。
- 多作用域的退回在核销之前，各作用域扣的加起来大于退回金额：每个作用域的可用余额是那一边的下界，合起来偏小。要人把退回核到它真正离开的那个作用域上才各归各位。
- 一条事实落到几个作用域时，对它的核销与撤销会重算它落到的每个作用域；其中一个作用域的账已不平（已确认未结为负）时，对这条事实在别的作用域上的核销也一起答账不平。

## 越权风险点

1. **退回没核销的那一截在每个作用域都先扣**（作者代决）。协调方裁的是「同一规则——按指向各作用域的分配记」；本记录对分配那部分照办，对没核销的那一截取保守方向。作用域可用余额会偏小、可能挡住冻结。若 owner 要退回与收款一样没核销各记 0，只改 P 的一项，读面与 CLI 的说法随之改。
2. **币种与事实不同的作用域也算一个**（作者代决）。一笔 USD 收款映到 USD 账户又映到 CNY 账户，USD 账户只记分配。若 owner 认为不同币种的映射本就无效、不该影响计数，改作用域计数的口径即可。
3. **兼映到应付、贷项或金额本体的事实仍按全额记入它唯一的那个客户应收作用域**：这几格不是客户应收作用域，不计数；核到它们上面的那部分仍在客户作用域的全额里。同类缺口，本记录不改；把客户收款同时映到供应商或赔付一侧本身就与「默认不做应收应付净额抵销」相抵。
4. **外部更正不重算**：单作用域事实的全额随链头变，多作用域退回没核销的那一截也随链头变，更正这一步都不推进作用域，归票 [code/92](../../.scratch/docs-consistency/code/92-a-funds-fact-correction-below-its-applied-total-is-adopted-silently.md)。
5. **存量停在旧值**：本记录之前已落在几个作用域上的事实，那几个作用域在下一次映射、核销或撤销之前停在全额上。首发前只有演示租户，种子是单作用域；有了真实租户再换口径要一条按作用域全量重算的运维路径，今天没有。
6. **重算范围变宽**：落到几个作用域的事实，其中一个作用域账已不平时，对这条事实在别的作用域上的核销与撤销也一起答账不平；续办与账不平那一格相同，先核对那个作用域的核销与调整。
7. **求 P 每次把本租户全部映射收成作用域**，没有索引，量大时要加。

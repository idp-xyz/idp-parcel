## Context

- [ADR-0014](./0014-versioned-canonicalization-shape-for-content-digest.md) 决定「规范化版本的变化必须来自规范化结构的变化」，Consequences 写「每次变化都要新增一个规范化版本并长期支持它」。它的索引注记记过同号改形（ADR-0177、0201、0202），各以「没有需要回放的已保存摘要」为前提，并写明「此后任何一册再改规范化形状照本记录换号」。前提的取法不一样：ADR-0177 决定三说「本仓今天没有任何租户的生产数据，已登记的只有演示种子与测试夹具」，ADR-0201、0202 靠迁移在表里有行时拒绝施加。
- [ADR-0126](./0126-commercial-publication-digest-is-computed-server-side-per-register-and-approval-comes-through-a-pending-carrier.md) 决定一：「加册不换号：换号只在既有册的文档形状变化时发生（ADR-0014），一册从「没接」到「接了」不改任何已算出的字节。」
- [ADR-0129](./0129-credit-ratio-base-is-declared-on-the-credit-policy-content.md) 决定一在已接的信用政策一册里加键不换号：「PCC-1 不换号：`canonicalCreditPolicyBody` 加键 `ratioBase,omitempty`（ADR-0126 决定一「各册接进同一个 `PCC-1` 不换号」同法）；金额正文的规范化文档因此一字不变，既有摘要不动。」它援引的是加册那一条，情形不同；它也没有按停用机制在 ADR-0014 上挂指针。
- [ADR-0176](./0176-customer-service-rule-contract-tier-selection-and-inheritance.md) 决定五反把它当先例：「PCC-1 一字不改（若要改则按加 omitempty 键不换号的先例另核）」。[ADR-0177](./0177-customer-contract-names-its-customer-account-and-the-closure-narrows-by-it.md) 决定三已对客户合同一册显式偏离这一先例：「这是对 ADR-0176 决定五所记先例（「若要改则按加 omitempty 键不换号的先例另核」）的一次显式偏离」；ADR-0176 上没有这条指针。
- [ADR-0209](./0209-supplier-agreements-declare-charge-occurrence-conditions-and-registration-judges-by-them.md) 决定三遇到同一种情形（供应商协议一节加可缺的收费发生条件，不带条件的旧文档逐字节不变）却换号：「改的是供应商协议一节的形状，照 ADR-0014 换号。」它的候选与反方写了理由：「只认 `PCC-1` 的构建读到带条件的文档时会把条件当未知键丢掉，算出的摘要与列上对不上却报不出是形状变了。」它也点了同号加键的先例：「先例：服务产品册加交付条件一节、客户合同册加客户账户一键」。
- 于是仓里并存相反的换号做法：ADR-0014、0126、0209 一边，ADR-0129、0176 与只在代码头注或提交说明里写了理由的几次同号改形另一边，没有记录裁过谁先谁后。下一位给 PCC、PPC 或 TFC 加可缺键的作者，照哪边做都能找到撑腰的先例。
- 清点（取证于 main `c89830c72`）：对各上下文以 json 结构体标签定形的规范化正文（`internal/*/domain` 下各 `*canonicaliz*.go`、计价的 `fingerprint.go` 与参考序列、参考目录登记册），按提交列出给既有文档加、删、改键而规范化版本号不变的各次；新开一面（一个新的 `face` 或新的一册）与同一提交里换了号的不算。结果见决定四。PS、NO、CC、SA 与其余前缀（`NRS`、`NID`、`DPR`、`GRP`、`ESRC`、`PPT`、`PRC`）没有清点得出的同号改形；NO 收寄来源文档加可验证交付范围那一次换了号（`NRS-1` 到 `NRS-2`）。
- 代码事实：`internal/partycommercial/domain/publication_canonicalization.go` 折回存下的文档走 `RehydratePublicationContent`，用 `json.Unmarshal` 解码、不拒未知键——ADR-0209 说的「当未知键丢掉」在这一处成立。参数登记册：「当前尚无租户实例，全部行保持空模板」（[PILOT-PARAMETER-REGISTER](../product/PILOT-PARAMETER-REGISTER.md)），本仓的已存摘要只在演示库与测试夹具里。

## Decision

**一、已接规范化的册（面），文档的键集变化就是形状变化，默认照 ADR-0014 换号。**（机制）

- 加键、删键、改键名或改键的取值形状都算，可缺键（`omitempty`）也算。
- 不带新内容的旧文档逐字节不变，只保证已存摘要照旧对得上；读到新文档的旧构建会把新键当未知键丢掉，再算出一个对不上的摘要，却说不出是形状变了。换号让旧构建对新文档答「不支持」，而不是答错。
- 换号之后按内容取能表达它的最低一版（ADR-0209 决定三的做法）：不带新内容的文档仍写旧版、逐字节不变，带新内容的写新版。
- 适用于各上下文的规范化版本（PCC、PPC、PRS、TFC、PSC、NOC 等），不只 party-commercial。

**二、加册不是形状变化，照旧不换号。**（机制）

一册从没接到接上（ADR-0126 决定一），或同一前缀下新开一面：旧构建本来就没有那一册（面）的规范化，册上不会有它写下的摘要可比，接上不改任何已算出的字节。

**三、同号改形只在写明前提时成立。**（机制）

前提是两件同时成立：没有要按旧形回放的已存摘要；也没有不认新形的构建会读到新文档。分两个阶段：

- **首个租户实例进生产之前**：已存摘要只在演示库与测试夹具里，改形让它们失配的，随 `scripts/demo-seeds/seed.sh --reset` 重灌即消；进生产的每个构建都已认得新形，旧构建读新文档那一格到不了生产。这一阶段同号改形可以，但要写明。这一阶段对全产品一次结束：首个租户实例进生产那一刻起，不按实例、不按册划分——演示租户此后与真实租户同样对待（ADR-0150），它的库也不再是可以随手重灌而不计的存量。
- **进生产之后**：只认一种——那一面不存摘要、两侧都从本体现算。迁移在表里有行时拒绝施加（ADR-0201、0202 上线前用过的做法）在生产上不算：表空只说明此刻没有存量，挡不住滚动发布、回滚或多版本并存时不认新形的构建读到新写下的摘要，ADR-0209 要避的正是这一格。除这一种外，一律照 ADR-0014 换号。

写明的方式照 ADR-0177、0201、0202 的形：在记录里写前提，并部分停用 ADR-0014 Consequences「每次变化都要新增一个规范化版本并长期支持它」一句，适用场景只限那一次改形。只写在代码头注或提交说明里不算写明。上线前阶段可以同号，不等于该同号：ADR-0209 在这一阶段照换号，同样合规。

**四、既往各次逐次认定，前提都成立，不回头换号。**（机制）

已由记录自记、ADR-0014 注记已挂的：ADR-0177（客户合同加 `customerAccount`）、ADR-0201（容量池加维度）、ADR-0202（运输委托与订舱两册）。ADR-0129 给信用政策加 `ratioBase`，前提写在它同句「金额正文的规范化文档因此一字不变，既有摘要不动」，但没在 ADR-0014 上挂指针，由本记录认定为它对那一句的部分停用。

其余各次没有任何记录写过，由本记录认定，各自是对 ADR-0014 那一句的一次部分停用，适用场景只限那一次：

## 候选与反方

- **旧文档字节不变就不换号（ADR-0129、0176 那一边），不分阶段。** 否决：它只顾了已存摘要，没顾旧构建读新文档；本仓的折回口不拒未知键，丢键是静默的。进生产之后，滚动发布、回滚或多个进程版本并存时，这一格就会出现。
- **一律换号，连上线前与没有已存摘要的那一册也换。** 否决：ADR-0014 的代价论证（「代价在此刻支付最低」）正是为没有存量的时刻留的；没有存量时换号只多一个要长期支持的版本，换不来任何可比性。
- **既往各次上线前补换号。** 否决：理由见决定四；它们的前提都成立，补换号只让演示库上已存的串对不上，换不来生产上的任何保护。
- **改折回口拒未知键，就可以不换号。** 不采纳为替代：拒未知键让旧构建响亮失败，可它报的是文档坏了，不是形状变了、该换构建；换号后旧构建答的是本构建不认这一版，恢复动作明确。两者可以并存，拒未知键另作加固，不在本记录。

## 对已接受记录的作用

- **部分停用** ADR-0014 Consequences「每次变化都要新增一个规范化版本并长期支持它」一句。**适用场景**：只限决定四表里各次同号改形，前提各见表；此后任何一册（面）再改形，照决定一换号或照决定三写明前提。ADR-0014 其余各条不变；它的索引注记另加一条读法，写明决定一、三。
- ADR-0129 决定一「PCC-1 不换号」本身是对 ADR-0014 那一句的部分停用，ADR-0129 正文没写；本记录认定，指针补在 ADR-0129 的 Status 行前段（去向）与 ADR-0014 的索引注记（来向），适用场景仅限信用政策一册加 `ratioBase` 一键那一次。
- **部分停用** ADR-0129 决定一括注「（ADR-0126 决定一「各册接进同一个 `PCC-1` 不换号」同法）」一句作为不换号理由的效力。**适用场景**：只停这一层理由——加册与在册加键不是同一情形；决定一「PCC-1 不换号」的结论不变，成立的理由改为同句「金额正文的规范化文档因此一字不变，既有摘要不动」与上线前阶段（决定三）。ADR-0129 其余各条不变。
- **部分停用** ADR-0176 决定五括注「若要改则按加 omitempty 键不换号的先例另核」一句。**适用场景**：此后任何一册的规范化文档要加键（含可缺键），照决定一换号或照决定三写明前提，不再按这一先例另核；决定五「PCC-1 一字不改」本身照旧成立（ADR-0176 那一次确实没加键）。ADR-0177 决定三对客户合同一册那一次的显式偏离，此前没在 ADR-0176 上挂指针，随本记录一并补在 ADR-0176 的索引注记与 Links。ADR-0176 其余各条不变。
- ADR-0126：无条款停用。决定二照用它决定一的「加册不换号」。
- ADR-0209：无条款停用。决定一照用它决定三与候选与反方的理由；它在上线前阶段照换号，与决定三相合。

## Consequences

- 代码不改：决定四表里各次与 ADR-0129 那一次都认作前提成立的同号改形，`PCC-2` 与 `NRS-2` 是决定一的做法。`publication_canonicalization.go` 里信用政策正文那段头注与本记录一致，不改。
- ADR-0014、0129、0176 的 Status 行与 Links 补指针，见「对已接受记录的作用」。
- 此后改任何一册（面）的规范化文档：按决定一换号；要同号改形，按决定三在记录里写明前提并挂停用指针。
- 首个租户实例进生产时（PN-08 对它作出 `Go`），决定三的上线前阶段对全产品结束；此后的同号改形只认那一面不存摘要、两侧从本体现算那一种，其余一律换号。
- 不改 CONTEXT：规范化版本是摘要的技术合同，不进领域语言。

## 越权风险点

1. **代 PC、PP、TF owner 定了全仓的换号判据**（PC、PP、TF owner）。决定一对各上下文的规范化版本一体适用；某个上下文若要进生产之后仍可缺键不换号，要另立记录说清它的折回口怎样认出形状变了。
2. **既往各次照上线前阶段认定**（PC、PP、TF owner）。决定四表里可缺键那几次与 ADR-0129 那一次，旧构建读新文档会丢键；本仓到今天没有生产实例、没有滚动发布，这一格没有到过生产，也不会到——进生产的构建都认得这些键。若有哪个环境把演示库与测试夹具之外的数据带进了上线（例如租户的预生产库），那几次的前提要对那个环境重核。
3. **清点只核了以 json 结构体标签定形的正文**（各 owner）。按字符串拼接定形的摘要（例如 `ESRC`、`GRP`、`DPR`）只核了提交历史里摘要函数有没有动过；漏网的同号改形，照决定三补记。[ADR-0123](./0123-decimal-canonical-spelling-is-a-value-invariant-and-digests-compare-canonical-spellings.md) 决定四「不换规范化版本。」不在清点之内，也不构成决定一的反例：它改的是值的写法（「本记录不动 `fingerprint.go` 里任何文档形状」），不是文档的键集。
4. **进生产之后只认不存摘要那一种**（PC、PP、TF owner）。迁移闸那一种在生产上不算，表空的册改形也要换号，多一个要长期支持的版本；「那一面不存摘要、两侧从本体现算」由作者在记录里指名那一口与它的比对方式，评审逐口核。
5. **折回口不拒未知键**（PC owner）。决定一的理由建立在这一事实上；它本身是一处可加固的地方，本记录不改，留给 PC owner 判要不要另立票。

# ADR-0013: 由计价拥有版本化的外部数值序列并在评价内完成币种换算

Status: Accepted  
Date: 2026-08-07

## Context

真实价卡引入了两类高频变动、来源在运营企业之外的数值：承运商每周公布的燃油费率，以及把美元采购价卡换算为人民币结算金额所需的汇率。两者都不是承运商规则的一部分，也都不由本产品任何一个限界上下文生产。

同行价卡是采购侧的美元成本，而客户侧按人民币结算。若销售价使用独立的人民币价卡，则不需要换算；但[小包计价上下文](../domain/parcel-pricing/CONTEXT.md)已允许 `SELL` 在规则明确时引用一次冻结的 `BUY` 评价，真实形态是成本加成。成本加成意味着 `SELL` 评价的输入是一份美元 `BUY` 评价而输出必须是人民币，换算发生在形成 `SELL` 评价的那一刻，无法后移。

这需要一个此前不存在的决定。既有原则出自 [ADR-0012](./0012-parcel-pricing-context-within-idp-parcel.md) 的 Decision——`parcel-pricing`「只消费其他上下文提供的事实快照」——但燃油费率与汇率没有产出它们的兄弟上下文：燃油率的权威在承运商官网，汇率牌价的权威在财务侧与银行。它们不适用「向兄弟上下文取快照」这一模式，需要明确由谁承担版本化与可重放的责任。本记录只限定该句的适用范围，不取代 ADR-0012，也不改变它划定的边界。

## Decision

定义**计价参考序列**：按业务时点解析、不可覆盖、被版本清单引用的外部数值序列。燃油费率与汇率是它的两个实例。

`parcel-pricing` 拥有该序列的登记、版本化、发布治理和按计价基准时点的解析结果，**但不生产其数值**，也不选定其商业口径。数值来自承运商公布费率或财务侧牌价；汇率的牌价类型、取值时点规则和加点规则由 `party-commercial` 的商业价格政策版本化声明。计价只登记来源标识、生效区间与取值，并在评价时按计价基准时点解析、写入版本清单。

币种换算在形成评价时完成，计价按结算币种输出，并在解释中保留原币金额、汇率序列版本引用和换算步骤。`settlement-accounting` 保存该换算步骤作为换算依据，不重算也不改用其他汇率；报告币换算与汇兑差额仍由 `settlement-accounting` 形成。

## Consequences

- 「同一评价输入、版本清单与内容摘要产生相同结果」这条不变量覆盖到最终结算币种金额，而不是只覆盖原币数字。争议复核可以在单一上下文内重建金额。
- 燃油率必须表达为承运商当周公布费率与价卡折扣系数的乘积，两者都写入版本清单；只保留乘积结果视为解释不完整。
- 计价的消费面扩大到一类没有内部所有者的外部事实。这不改变 [ADR-0007](./0007-separate-operational-settlement-from-statutory-finance.md) 的边界：真实收付款、银行清算、法定税额与总账仍在财务系统，计价既不认定资金事实也不形成汇兑差额。
- 参考序列是来源事实，其被采用的取值经版本清单固定后才进入评价，与 [ADR-0005](./0005-source-facts-effective-events-derived-state.md) 的来源事实与派生结果分层一致。
- 计价必须知道结算币种。该值已由 `party-commercial` 随商业依据提供，不新增来源。
- 序列取值的具体实例——牌价来源、加点规则、燃油当周费率与折扣系数——由[参数登记册](../product/PILOT-PARAMETER-REGISTER.md)的 `PAR-SET-11` 承接，本记录不确定任何数值。
- 登记一期取值本身是一次来源事实断言，不是无责任的转抄。证据要求与责任归属由[小包计价上下文](../domain/parcel-pricing/CONTEXT.md)的不变量确定，实例状态登记在 `PAR-SET-11`。

## Alternatives considered

- **由 `settlement-accounting` 承担换算**：边界看似更干净，费用金额本就归结算。但 `PricingEvaluation` 会不再是可复算的最终价格，争议复核需要跨两个上下文重建金额，且结算侧的换算未必被版本化，确定性不变量只能覆盖到原币。
- **`SELL` 使用独立的人民币价卡，不做换算**：确实不需要参考序列。但这与真实的成本加成形态不符，会要求为每一次采购价变化维护一套平行的销售价卡。
- **把燃油费率与汇率分别建模**：两者都是高频变动、来源在外、必须被版本清单锁定才能重放的数值序列，分别建模会产生两套版本化与解析规则。
- **在评价时读取当前费率与汇率**：实现最简，但重放会取到与原评价不同的值，直接违反不可覆盖与可重放。

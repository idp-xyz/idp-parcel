## Context

ADR-0195 让「号码另有一份`已提交`委托声明」的唯一命中落成身份冲突：恰一个候选带歧义信号，答待识别、记身份冲突、候选记那一件。PS CONTEXT「歧义信号」写明声明它的委托「一经拒绝或撤回就不再算」——信号是 PS 此刻的事实，会消失。

信号消失之后，这件实物其实可以唯一关联，却没有自动的路：

- ADR-0210 决定一只给了人工处置一条解开的路，「不做自动解除」，并把自动解除记作后续方向。
- ADR-0199 决定三「记身份冲突的（多候选、一码两物）不重核」，经 ADR-0210 复核记录改了理由、结论维持；ADR-0195 决定四把带信号的那一格落在重核「多候选」格，同样记冲突、同样不重核。
- ADR-0195 决定四写明「信号消失不交信封」：PS 根本不告诉节点信号没了。

于是信号来得快去得也快的场景（客户先报错号、马上撤单重报）会堆出一串人工活，每一件都要持授予的人去点。

记身份冲突的行今天不分来由。恰一个候选的冲突行可能是只因歧义信号，也可能是一码两物——后到那件与给先到那件追加的冲突版都只记一个候选；而信号从不落册。不先把来由记下，就分不出哪一行能交给自动解开。

难逆转处：收寄册只追加，自动解开追加的关联版一落就是历史，随之交出的收寄意图进 PS 的采用、不回滚（ADR-0196 决定五）；PS 多交一种信封、NO 多一扇消费门，有了消费者就难改；收寄表的新列一旦有行就是历史。

## Decision

适用范围：NO 收寄、重核与身份冲突处置三只编排落下的判断（记不记冲突来由）；ADR-0199 决定三的重核对象与触发；PS 委托由`已提交`转为`已拒绝`或`已撤回`的那一次保存。身份核对读口、歧义信号的判据、ADR-0196 的判法、处置本身都不改。

**一、冲突落下时记来由。**

- **来由封闭三值**，记在判断上，只随身份冲突在场：
  - **只因歧义信号**（`AMBIGUITY_ONLY`）：PS 答恰一个候选，同时答出歧义信号。
  - **多候选**（`MULTIPLE_CANDIDATES`）：PS 答多个候选，带不带信号都是这一格（ADR-0195 决定三「多候选，有无信号都一样」）。
  - **一码两物**（`ONE_MARK_ON_TWO_UNITS`）：号码唯一指向的包裹已关联到另一件作业实物（ADR-0196）。后到那件，与给先到那件追加的冲突版，都记它。
- **分格的次序**：一码两物只从唯一命中那一支来；多候选压过信号——信号消失之后它仍是多候选，交给自动解开就解错了；剩下的恰一个候选带信号就是只差信号的那一格。
- **记在哪几版上**：收寄落下的冲突、重核追加的冲突版、ADR-0196 给先到那件追加的冲突版，都按上面分格记。身份冲突处置版不记冲突，也就不带来由；不记冲突的各版都不带。
- **既有冲突行来由缺席，不回填。** 迁移无从推定：恰一个候选的冲突行两种来路都有，信号从不落册；推错一行，就把一桩一码两物的冲突交给自动解开。缺席的照旧只经人工处置解开。
- **存储**：收寄表加一列来由，库面守取值封闭、不记冲突的行不带；记冲突的行不强制带（既有行就是那个形状）。迁移 `node_operations/0012`。
- **来由是信息格**：复核目录的待识别行与人工重核口的答复带它（线上名 `identityConflictCause`，取值原名），复核页据它分得开「信号消失后可再重核」与「只经处置解开」。它不进 outcome 词表，也不进内容指纹。

**二、只有只因歧义信号的冲突可以自动解开，且只经重核。**

- **重核对象放宽**：同租户里当前有效版本是`待识别实物已建立`、不带关联、**不记身份冲突或冲突来由是只因歧义信号**，且来源文档的外部标识观察与号码逐字相等。人工指名与按号找同此。来由是另两格或缺席的冲突行照旧不重核，答「记着身份冲突」。
- **重核照旧走与收寄同一份身份判断**：同一个读口、同一个 `Unique`（ADR-0195），含 ADR-0196 的按包裹认与（租户，包裹）锁、ADR-0210 决定九的排除。被重核那一版是只因歧义信号的冲突时，各格：
  - **唯一且无信号、包裹没关联到别的实物** → 追加一版`节点收寄已形成`：带关联，前版是冲突那一版，业务时间是原收寄时刻、控制照原判断，不另起控制起点；照 ADR-0186 取服务结果；收寄意图一封。方向依据的身份一格读链头（ADR-0210 决定五），冲突随链头解开；冲突那一版原样留着。
  - **唯一，但包裹已关联到别的实物** → 照 ADR-0196 两边各追加冲突版，来由记一码两物。
  - **仍是恰一个候选带信号** → 不追加，答「仍带歧义信号」。这是重核结果的新一格（线上名 `STILL_AMBIGUOUS`），形成了答案，不进收寄 outcome 词表。再追加一版同样的冲突，链上只多一行，冲突一点没变。
  - **多候选** → 追加冲突版，来由记多候选。
  - **零候选（带不带信号）** → 判断不变、不追加，冲突照留（ADR-0199 决定三零候选那一格）。
  - **身份核对仍读不动** → 不追加，交回 error（ADR-0199 决定三）。
- **按号找的存储**：按号找待重核的部分索引重建，部分条件放进来由为只因歧义信号的冲突行；查询谓词与它逐字同形（迁移 0012）。

**三、触发：PS 在声明消失时交门铃。**

- **何时交**：一份带客户包裹件号的委托由`已提交`转为`已拒绝`或`已撤回`时，与状态变化同一笔事务，按它声明的每个号各交一封；两件声明包裹报了同一个号只交一封。拒绝含规则形成的拒绝、主动拒绝、授权处置的拒绝；补充期满的确定性拒绝今天没有单独的编排，落地时同样走这一处。
- **落在委托仓储保存那一处**：委托离开`已提交`的每一次转移都经它落库，与关联已形成门铃同一个落点（ADR-0199 决定三「PS 外部标识关联册新形成一条标识包裹的关联时，与关联同一笔事务经 Outbox 交出只带（租户，号码）的信封」）。判据是保存前后两个状态：保存那一条语句同时交回预期版本那一行原来的状态。已终局的委托再保存一次不响；撞版本冲突的那一笔什么都不写，也不响。
- **信封形状**：
  - 事件类型 `parcel-shipment.customer-parcel-number-declaration.retired`；载荷只有租户与号码，不带委托、客户账户、声明包裹或撤下的原因（CONTEXT-MAP 那一条禁交号码的分配方、客户账户或委托；ADR-0184 决定五「不交分配方、客户账户或委托」）。
  - 信封 ID 是（租户，委托，号码）的定长指纹，经 `outboxintent.FingerprintEventID`，口名 `customer-parcel-number-declaration-retired`：一份委托只离开`已提交`一次，重放撞同一个 ID 不出第二封。
  - 分区键与关联已形成门铃同一个式子、同一个口名（租户与号码的定长指纹）：同一个号的两种门铃排一条队。两种都叫 NO 按这个号重核同一批行，分两条队并发，两笔重核会在同一行上抢着追加。
  - Subject 原样带号码，越过上限或带控制字符时换成号码的摘要，与关联已形成门铃同一个做法。发生时刻是撤下那一刻的决定时刻，记录时刻是保存时刻。
- **NO 用已有的重核消费者接**：同一个消费者名多一扇门，`cmd/parcel-dispatch` 路由表多一行。门铃按号重核，重核对象与关联已形成门铃同一组（决定二）：同号的零候选待识别多问一次 PS，答案照旧不追加；不另立一问只找冲突行，重核对象只留一份定义。
- **接受不交本门铃**：接受形成关联，交的是关联已形成门铃；重核时那件或成多候选（持号那一侧仍在册）、或成唯一（那一侧已不在），本记录不另起触发。
- **人工重核口**（`PENDING_IDENTITY_RECHECK`）对只因歧义信号的冲突行同样放开，答法见决定二。
- **门铃不是身份答案**：NO 收到后照旧经身份核对读口问 PS，不据信封认定身份。

**四、与人工处置的关系。**

- 已经人工处置过的链，链头是处置版、不记冲突，不在本记录放宽的那一格里；确认都不是的处置版照 ADR-0210 决定九照常重核。
- 自动解开不撤销任何处置，也不需要处置：它追加在冲突那一版之后，处置截断（ADR-0210 决定八）只认处置版。
- 自动解开不经运营决定、不留操作者；冲突那一版与追加的关联版都在判断链上，来由与前版可审。

## 与已接受决定的关系

逐句点名；各句自票 no-reception-identity/07 进 main 起停用，此前原句照旧描述代码。**适用场景**一律只限冲突来由为只因歧义信号的身份冲突：多候选、一码两物与来由缺席的冲突照原句。

- **ADR-0210 决定一**「**不做自动解除。** 歧义信号消失之后自动解开，需要 PS 在声明的委托被拒绝或撤回时另交信封（ADR-0195 决定四写明「信号消失不交信封」），记作后续方向，本记录不做、不立票。」：停用。同条「**重核与再次收寄都不解除冲突。** 重核照 ADR-0199 决定三跳过记身份冲突的判断」里重核那半句：停用；「再次收寄不解除冲突」照旧。同记录「能力边界」首项里「不做自动解除」：停用。理由：信号是 PS 此刻的事实，那份委托被拒绝或撤回，PS 再答出的就是唯一命中；原句的前提「PS 不交信号消失的信封」由决定三补上。同记录「Alternatives」里「歧义信号消失即自动解除」一项是当时不取的历史，不改。
- **ADR-0199 决定三**「**触发只有三处，不做后台扫表。**」里「只有三处」：停用，多一处 PS 声明撤除门铃（决定三）；「不做后台扫表」照旧。
- **ADR-0199 决定三**「重核对象」一项里「记身份冲突的（多候选、一码两物）不重核」（结论经 ADR-0210 复核记录维持、理由改为冲突只经人工处置解除）：停用。原句括号只列多候选与一码两物，写在 ADR-0195 之前；ADR-0195 决定四把带信号的一个候选落在重核「多候选」格、记冲突，此后那一格也归这句管，本记录停的正是这一格。多候选、一码两物与来由缺席的冲突照旧不重核。
- **ADR-0195 决定四**「信号消失不交信封。声明它的委托被拒绝或撤回，信号就消失；但信号只会把唯一命中改成冲突，冲突行不经重核解除，零候选的待识别又本就不看信号。」里「信号消失不交信封」与「冲突行不经重核解除」：停用；「零候选的待识别又本就不看信号」照旧。同记录越权风险点「信号消失后，已记的冲突不自动解除」随之失效，适用场景同上。
- **ADR-0196**：不停用。一码两物的冲突照旧只经处置解开；本记录只给它的冲突版记来由。
- **ADR-0184 决定五**「不交分配方、客户账户或委托」：不变，新信封同样只带租户与号码。
- **ADR-0186**：不变。自动解开追加的关联版照它取服务结果、记核对态。

## 能力边界

- 只解只因歧义信号这一格。多候选、一码两物与来由缺席的冲突照旧只经身份冲突处置（UC-NO-004）。
- 不回填既有冲突行的来由。
- 号码另有一份`已提交`声明时不解（信号仍在）；声明它的委托被拒绝或撤回的同时号码在册的关联也没了（作废、被替代）时，重核答零候选，冲突照留。
- 只认客户包裹件号的声明：渠道包裹件号没有接受前声明（ADR-0195 越权风险点「信号只认客户包裹件号的声明」），不在本门铃。
- 不撤回、不回滚已交出的意图；自动解开交出的那一封由 PS 按已有采用规则处理。
- 管理台复核页的重核按钮与新结果格不在本记录：今天它按 `identityConflict` 把冲突行的重核置灰，不认 `STILL_AMBIGUOUS` 的原名（页面对未收录的 outcome 照原名示出）。随前端切片补。

## 越权风险点

1. **代 NO 与 PS owner 定「撤单即自动解开」。** 客户撤单重报同号的场景下，那件实物会在没有人看过的情况下关联到第一份委托的包裹。owner 复核时看是否要求这类自动解开也进复核目录供人事后核。
2. **代 PS owner 定 PS 多交一种信封。** 每份带号的委托被拒绝或撤回都入队，号多半从未在节点出现过，NO 对匹配不到的号不做事。门铃落在委托仓储保存那一处、以保存前后两个状态判，而不是在各条拒绝与撤回编排里各交：日后若有绕过委托仓储改委托状态的写路径，它不会响。
3. **冲突来由的分格次序由本会话定。** 多候选压过信号，一码两物只从唯一命中来。恰一个候选的冲突行在本记录之前一律不回填，它们哪怕实际是只因歧义信号，也只经处置解开。
4. **信号仍在不追加，零候选也不追加。** 唯一候选换了一件、仍带信号时，那一版记的候选会旧；零候选时冲突照留，候选同样会旧。两格都只等人工处置或下一次答出唯一。不取「信号仍在时也追加一版刷新候选」：每一封门铃都会追加一行同样的冲突。
5. **声明撤除门铃按号重核同一组对象。** 同号的零候选待识别也被多问一次 PS；量大时这是门铃的放大，代价是 PS 读口的负载。
6. **新增重核结果一格 `STILL_AMBIGUOUS`。** 管理台不认它的原名，见能力边界末项。
7. **停用 ADR-0195 一句**，超出裁定字面（裁定只点名 ADR-0210 与 ADR-0199）。那一句写的正是「信号消失不交信封」，不标出来就有两处相反的现行说法。

## Consequences

- NO：收寄表加一列与两条约束、重建一本部分索引（迁移 `node_operations/0012`）；收寄记录多一格冲突来由；重核对象放宽一格、重核结果多一格；重核消费者多一扇门；复核目录的待识别行与人工重核答复多一格信息。
- PS：委托仓储保存那一条语句交回原状态；多交一种信封。
- `cmd/parcel-dispatch` 路由表多一行；分区主体登记多一行。
- UC-NO-002 新增验收 `AT-NO-062`。
- `MECHANISM-INVENTORY.md` 的迁移份数随之变。

## Alternatives

- **不记来由，凡恰一个候选的冲突都重核。** 不取：一码两物里先到那件的冲突版也是恰一个候选，而且候选就是它自己关联着的那件包裹。重核时按包裹读别的实物，后到那件不带关联、读不到，先到那件就会唯一关联回去，冲突只在一侧解开。
- **回填既有冲突行的来由。** 不取，理由见决定一。
- **NO 不等 PS 的信封，自己定时重核冲突行。** 不取：ADR-0199 决定三「不做后台扫表」；无从知道哪一刻值得再问。
- **声明撤除门铃另立一问，只找只因歧义信号的冲突行。** 不取：重核对象就得有两份定义；多问几行零候选的代价小于两套口径。
- **信封在各条拒绝与撤回编排里各交。** 不取：规则形成的拒绝、主动拒绝、授权处置的拒绝与撤回各写一遍，日后多一条拒绝路径漏交是静默的；落在仓储保存那一处，与关联已形成门铃同一个落点。
- **以保存后的状态为判据，不读原状态。** 不取：裁定说的是「由`已提交`转为」，判的是转移；已终局的委托再保存一次不是撤下。
- **声明撤除门铃另起分区。** 不取，理由见决定三「信封形状」分区键那一项。
- **信号仍在时也追加一版冲突、刷新候选。** 不取，见越权风险点「信号仍在不追加，零候选也不追加」。

「能力边界」末项与越权风险点「新增重核结果一格 `STILL_AMBIGUOUS`」所说的管理台缺口，由同一张票在评审后补上（会话 `idp-parcel-9b` 评审要求，授权同 Status 行）：复核页待识别实物区加「冲突来由」一列（三值各一句，来由缺席的冲突行写「来由未记」）；「重核」动作对来由为只因歧义信号的冲突行放开，其余来由与来由未记的冲突行照旧只给「处置」；重核答复认 `STILL_AMBIGUOUS`，写作「仍有未决的同号声明——暂不能关联，判断不变」。判读在 `apps/admin-web/src/pages/operations/identity-conflict-cause.ts` 与 `identity-recheck.ts`，落成见票 [no-reception-identity/07](../../.scratch/no-reception-identity/issues/07-an-ambiguity-only-conflict-releases-when-the-declaration-is-gone.md) 完成记录。两处原句此后只作当时的事实记录。

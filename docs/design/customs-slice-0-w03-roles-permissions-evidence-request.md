状态：业务取证执行模板；只定义角色资格、委派、权限和规则凭证的核验要求，不维护参数当前值

本文执行[关务切片 0](./customs-slice-0-business-development-handoff.md)中的 `CC-S0-W03`，覆盖 `PAR-CUS-03` 和 `PAR-CUS-04`。真实参与方、用户、角色、委派、权限、规则、凭证、当前状态和证据索引仍只在[首发试点参数与证据登记册](../product/PILOT-PARAMETER-REGISTER.md)中维护。

本文不保存真实姓名、账号凭据、证书正文、受限法规内容或组织内部权限表，也不规定 API、数据库字段、RBAC 实现、审批界面、认证系统或部署方式。

## 前置关系与边界

`CC-S0-W01` 必须先固定客户、责任法人、产品、合同和线路适用范围；`CC-S0-W02` 必须先固定出口/进口程序、服务方、来源和外部身份。W03 可以提前收集候选角色和规则文件，但在前置范围确认前不能形成生产权限。

W03 负责把已确认的治理依据实例化为关务案件和提交版本采用的角色/资格快照，并核验每个关务动作的权限。它不取得下列所有权：

- `party-commercial` 拥有参与方、法人、商业关系、委派、角色权限等级和渠道账号授权的版本生命周期；W03 只引用并保存实际采用快照。
- `node-operations`、`transport-fulfillment` 或其他执行上下文拥有各自的实际作业、运输和物理执行权限及事实；W03 只能核验关务执行协作、交接和核对权限，不能授予实际执行权限。
- 承运商拥有外部监管舱单的形成、提交和更正权限；W03 不能授予本产品查询、重发、更正或替代承运商舱单的权限。
- 银行、支付或财务系统拥有实际付款事实；`settlement-accounting` 形成实际代垫和客户回收判断；W03 只核验税费义务、付款协作和逐动作放行门禁的业务权限。
- 监管机构拥有最终监管决定权；W03 不能用内部角色或规则替代外部监管结果。

## 角色语言

同一参与方可以承担多个角色，但每个角色必须分别登记资格、适用范围和有效期。一个登录用户也可能被委派多个业务角色，但不能因此合并不同动作的权限。

| 角色 | 必须核验 | 不能自动推导 |
|---|---|---|
| 货物相关主体 | 与货物、包裹、客户声明或法定义务的关系 | 申报、授权或实际提交权限 |
| 进出口责任主体 | 对具体方向和监管程序承担的法定/合同责任 | 账号持有人或报关服务方身份 |
| 申报人 | 有资格代表指定范围形成申报行为 | 监管结果解释或实际发送权限 |
| 报关服务方 | 委派关系、服务范围和有效期间 | 对客户资料、运输事实或监管决定的所有权 |
| 申报渠道账号持有人 | 账号身份、持有关系和使用授权 | 账号凭据以外的业务权限或外部结果所有权 |
| 税费法定义务人 | 具体程序、申报范围和税费义务依据 | 实际付款或运营代垫成立判断 |
| 实际付款方 | 合格付款资格、适用范围和授权 | 银行已到账事实或客户回收结果 |
| 运营责任法人 | 对客户、程序和业务动作承担的法人责任 | 集团租户、操作组织或所有节点执行权限 |
| 关务判断/复核角色 | 对特定规则、范围和时点作出判断或复核的资格 | 提交授权、实际提交或监管结果 |
| 承运商外部舱单责任方 | 外部舱单形成、提交和来源事实责任 | 本产品关务案件或本产品申报权限 |

“请求方”“实际决定方”“授权使用方”“实际执行方”和“结果解释方”是不同职责维度。可以由同一参与方承担其中多个维度，但每次具体动作都必须保留实际采用的分工。

## 逐动作权限矩阵

证据包必须按客户账户、责任法人、监管程序、进出口方向、案件/申报单元或外部引用范围和有效时间填写以下动作。没有适用动作时，记录有权威依据的不适用，不保留空的生产权限。

| 动作 | 请求方 | 判断/复核方 | 授权方 | 实际执行方 | 结果解释/核对方 | 必须证明 |
|---|---|---|---|---|---|---|
| 建立关务案件 | 业务请求方 | 关务资格复核方 | 适用责任角色（如有） | 关务应用编排 | 关务 | 程序、方向、客户/法人范围和建案资格 |
| 形成申报单元与正式资料 | 客户/运营请求方 | 关务判断或人工复核方 | 适用资料/申报责任角色 | 关务应用编排 | 关务 | 成员范围、字段来源、资格和规则依据 |
| 申报就绪判断 | 业务请求方 | 唯一就绪判断责任方 | 不把就绪当授权 | 关务判断机制 | 关务复核方 | 当前资料、角色、凭证、口岸/渠道和限制门禁 |
| 提交授权 | 授权请求方 | 就绪和资格复核方 | 明确授权角色 | 授权使用方 | 关务审计/复核方 | 目标、范围、版本、动作、权限等级和有效期 |
| 实际提交 | 提交执行请求方 | 提交前门禁复核方 | 有效提交授权方 | 有实际提交权限的执行方 | 结果接收用例 | 当前就绪、授权、账号、渠道和凭证依据 |
| 原提交查询 | 查询请求方 | 查询资格复核方 | 适用查询授权方 | 原提交查询执行方 | 结果接收用例 | 原尝试、渠道、范围和真实查询能力；不创建新提交 |
| 结果解释与复核 | 结果接收方 | 结果解释/冲突复核方 | 适用结果处理权限方 | 关务结果处理方 | 关务 | 来源、代码映射、结果层、范围、时间和更正关系 |
| 来源关联与关联修正 | 来源接收方 | 关联复核方 | 适用关联修正方 | 关务关联处理方 | 关务 | 唯一案件/单元/外部引用关联和修正依据 |
| 来源响应冲突处置 | 冲突发现方 | 冲突复核方 | 明确冲突决定方 | 关务冲突处理方 | 关务 | 冲突两侧、责任来源、当前判断和依赖门禁 |
| 外部监管舱单引用接收 | 受控来源接入方 | 来源/范围关联复核方 | 关务引用接受方 | 关务接收处理方 | 关务 | 承运商来源、身份、版本、范围和权限；不含舱单提交 |
| 外部舱单当前采用复核 | 复核请求方 | 当前采用复核方 | 适用关务决定方 | 关务引用处理方 | 关务 | 版本优先、变更关系和不按最后到达覆盖 |
| 后续动作分类与目标建立 | 业务请求方 | 动作分类复核方 | 后续动作决定方 | 后续动作编排 | 关务 | 补充、更正、撤销、重报和替代的程序依据 |
| 查验/扣留/处置协作事项 | 监管结果接收方 | 关务范围复核方 | 协作事项决定方 | 关务协作处理方 | 关务执行核对方 | 决定范围、交接权限和回接证据 |
| 节点/运输实际执行 | 执行请求方 | 相应执行上下文复核方 | 相应执行授权方 | 节点、运输或其他执行方 | 相应上下文及关务核对方 | W03 只引用外部执行权限核验，不由关务授予 |
| 税费付款门禁核对 | 付款协作请求方 | 税费/资金核对方 | 逐动作门禁复核方 | 外部付款或财务执行方 | 关务与结算各自核对方 | 法定义务、付款覆盖、资金事实和拟执行动作 |
| 案件关闭/重开权限 | 关闭/续办请求方 | 逐义务关闭复核方 | 关闭/重开决定方 | 关务案件编排 | 关务/审计 | `PAR-CUS-06` 的责任来源和当前授权；W03 不形成生命周期决定 |
| 结果导出与最小披露 | 导出请求方 | 范围/客户隔离复核方 | 导出授权方 | 受控导出方 | 关务审计方 | 客户、法人、程序、范围和敏感字段权限 |

矩阵中的“实际执行方”不等于“提交授权方”，“结果解释方”不等于“监管决定方”。任何一列缺少真实依据时，相应动作必须保持未配置或未受理。

## 委派与账号授权证据

每项委派或账号授权至少要证明：

- 授权双方、责任法人、参与方和具体角色。
- 授权的动作集合、客户账户、监管程序、方向、对象/范围和有效期间。
- 是否允许再委派、代为请求、代为决定、代为提交、代为查询或导出；未明确的能力不能推定允许。
- 授权形成、变更、暂停、撤销和自然到期的来源、版本、生效时间和历史关系。
- 渠道账号持有人、账号使用授权和实际提交权限的区别；凭据可用不代表业务授权可用。
- 形成具体决定或提交尝试时，如何重新核验当前角色、适用客户授权、程序范围和硬限制。

登录成功、管理员组、企业类型、岗位名称、历史成功操作、渠道账号可访问或同事口头许可都不能单独构成授权。跨客户、跨责任法人、跨方向或跨程序的授权不能扩大解释。

## 规则与监管凭证证据

### 规则来源与自动提交政策

`PAR-CUS-04` 的证据必须为每条适用规则提供：

- 官方或受控规则来源、版本、生效区间、适用时间和适用辖区/程序。
- 出口、进口和内部合规规则的独立适用关系；相邻方向或相似国家的规则不能直接复制。
- 禁限运、归类、原产地、申报价值、监管条件、合报资格和凭证适用性的判断依据。
- 补充、更正、撤销、重报、替代、查验、扣留、处置、税费和放行门禁对规则的影响。
- 自动规则形成判断的范围、依据、人工复核条件和版本历史。

首发生产不启用自动申报。自动规则可以形成已明确授权范围内的判断或待人工处理结果，但不能替代逐次提交授权、实际提交权限或监管机构决定。

### 监管凭证

每类凭证必须单独登记：

- 签发机构、凭证持有人、凭证身份、不可变版本、适用辖区和程序。
- 适用商品/范围、有效期、使用次数或额度、计量单位和占用时点。
- 使用成立、未使用、部分使用、释放、核销、失效和迟到更正分别由哪个权威结果形成。
- 凭证版本、提交版本、授权使用和外部结果之间的关系。
- 附件或扫描件只能作为证据，不能替代凭证身份和适用性判断。
- 额度冲突、超用、来源更正、付款结果变化或规则版本变化时的处理责任。

没有权威凭证身份、适用范围、有效期、占用单位或使用/释放依据时，不能以附件存在、页面显示、当前余额或操作员判断形成生产占用、释放或核销。

## 权限与规则边界样本

W03 至少准备以下可脱敏复核场景；复杂外部交互本身仍由 `PAR-CUS-05` 提供验证环境：

| 场景 | 必须证明 |
|---|---|
| 同一用户兼任申报人和复核人 | 每次动作仍按当前角色、范围和授权核验，不因用户相同而合并结果 |
| 可登录渠道账号但没有实际提交权限 | 请求未受理或门禁阻断，不读取越权资料、不发送 |
| 有提交授权但就绪判断已失效 | 提交前阻断，保留授权历史，不消费授权或凭证 |
| 有批准权限但没有实际提交权限 | 批准和实际提交分开，不能由批准按钮代替发送资格 |
| 出口权限用于进口 | 按方向/程序范围阻断，不能复用相邻方向授权 |
| 原提交查询权限用于外部监管舱单 | 拒绝本产品舱单查询/重发，不改变外部引用 |
| 承运商外部舱单关联权限用于舱单提交 | 拒绝越界动作；只能接收、关联和当前采用复核 |
| 节点或运输执行权限缺失 | 关务只能形成待交接或未配置结果，不能授予实际执行权限 |
| 自动规则判断为就绪 | 仍需有效逐次提交授权和实际提交权限 |
| 凭证附件存在但身份/额度未确认 | 保持凭证前提未决，不占用、不释放、不核销 |
| 委派在提交前撤销或到期 | 重新核验当前权限并阻断后续动作，历史快照不被覆盖 |
| 跨客户或责任法人请求导出 | 最小范围拒绝或部分返回，不泄露其他客户是否存在 |

## 登记册动作与阻断

本工作单不建立新的参数状态。证据可以分批提交，但只有角色资格、委派、动作矩阵、规则版本、自动政策、凭证语义、有效期间和适用范围完整，并取得有权决定后，登记册责任方才可更新 `PAR-CUS-03` 或 `PAR-CUS-04`。

以下任一情况存在时，相应判断或动作生产分支保持未配置：

- 角色、资格、委派或账号授权不能绑定到明确客户、责任法人、程序、方向和有效期。
- 请求、判断、授权、实际提交、结果解释、执行交接或导出权限缺少独立责任方。
- 规则来源、版本、生效区间或适用时点不明，或出口/进口规则被相互推导。
- 自动提交政策未确认，或生产自动申报尚未明确禁用/授权边界。
- 凭证身份、范围、有效期、额度、占用、释放或核销权威结果不明。
- 将承运商舱单提交、节点/运输执行、实际付款或监管决定权限误归于关务。

一个动作未就绪只阻断该动作及其依赖分支；不能因管理员权限或其他动作已确认而放行，也不能把一个角色的确认复制到其他角色。

## 给开发的交接

证据未确认时，开发可以实现：

- 角色、资格、委派、账号授权和逐动作权限的稳定引用与版本历史。
- 请求方、判断/复核方、授权方、实际执行方和结果解释方的分离表达。
- 客户/法人/程序/方向/对象范围隔离，权限缺失、范围不符、授权失效、规则未决和技术未形成等安全结果。
- 自动判断与人工授权分层、凭证适用性骨架、未配置和测试验证入口。

开发仍然不得：

- 以角色名、岗位名、管理员组、登录成功或账号凭据生成万能权限。
- 以有提交授权推导已就绪、实际提交成功、监管接收或放行。
- 以关务权限授予节点/运输实际执行、银行付款或承运商外部舱单提交。
- 在首发生产启用自动申报，或在规则/凭证未确认时写入默认国家、程序、阈值、额度、时限和动作顺序。
- 把权限矩阵当作领域生命周期状态或覆盖历史授权决定。

W03 完成后仍须按具体生产分支完成 `PAR-CUS-01/02/05` 及其余参数和验证门槛，才能进入渠道或国家专属详细设计和生产准入。

## 首轮提交清单

证据可以按角色、动作、方向和程序分批提交；完成 W03 交叉核验前，汇总证据必须覆盖：

- 参与方、法人、申报人、报关服务方、账号持有人、税费义务人、实际付款方和运营责任法人的资格与范围。
- 逐动作请求、判断、复核、授权、实际提交、查询、结果解释、关联、冲突、协作、导出和关闭/重开权限矩阵。
- 委派、账号使用授权、撤销/到期、再委派和生效/失效版本关系。
- 出口、进口和内部规则来源、版本、生效区间、适用时点及自动提交政策。
- 监管凭证身份、持有人、范围、有效期、额度/次数、占用和使用/释放/核销依据。
- 越界、冲突、并发、权限失效和跨客户隔离样本，以及各自责任方。

提交后由业务核验方逐项形成结论，再由登记册责任方更新唯一当前状态。工作单、登录测试或单个正常授权样本不能证明生产权限和规则已经准入。

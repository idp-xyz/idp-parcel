## 验证边界

### 纳入

- 独立商业选择锚点下的唯一命中、无适用依据、适用冲突和解析未决。
- 同一合成货主同时存在预付和账期两个不重叠范围时的独立解析。
- 预付估价/冻结、账期信用暴露/限制、费用确认、收款和核销之间的事实分层。
- 规则或财务依赖不可用时的未决与安全续办。
- 结果的版本、适用范围、判断时点、当前修订和来源索引。

### 不纳入

- 真实客户、合同、法人、账户、金额、币种、费率、信用额度或付款记录。
- 银行、支付、税务、发票、总账、渠道或客户通知的真实调用。
- 任何真实委托的接受、拒绝、生产归属、运输、关务或外部指令。
- MinIO/S3 的部署和访问设计；本切片只保存可审计证据索引语义。

### 当前执行边界

本切片是未来业务契约和隔离测试向量，不是当前生产编码授权。当前只允许命名夹具、纯业务规则/值对象和负向单元测试；不得创建 `party-commercial` 或 `settlement-accounting` 的生产应用端口、持久化对象、Repository、事务或 Outbox，不得调用真实冻结、信用、应收、收款或核销协作。合成结果始终标记为隔离 `S`，生产结论保持 `No-Go / 待参数化`。

### S01-W01 合成商业发布契约

商业发布仍按 `party-commercial` 的独立对象边界表达，不合并成一个可覆盖的“大配置”。本工作包的测试夹具覆盖客户账户、责任法人、服务产品、客户合同、接单规则包、预付政策和账期政策七类对象；每个对象都独立拥有对象类型、稳定对象标识、版本、适用范围引用、有效区间、夹具版本、内容摘要、当前修订和隔离证据等级。

- 对象生命周期按 `DRAFT -> APPROVED -> PUBLISHED` 验证。发布必须有批准引用、批准时间、发布引用和发布时间；发布时间不得早于批准时间。
- 发布登记以 `对象类型 + 对象标识 + 版本` 定位。相同语义内容的重复发布只返回原发布关联；相同版本但内容摘要、范围、有效区间、夹具版本或当前修订变化时形成冲突，原发布不可覆盖。
- 同一合成货主可以同时发布预付和账期政策版本；本工作包只证明两类独立版本可以被保全，不执行适用范围解析、不判断重叠，也不形成冻结、信用、费用或接受结果。
- 所有结果固定为隔离 `S`。该测试契约不创建商业主数据端口、发布后台、审批服务、Repository、事务、Outbox、报价或结算对象。

对应测试文件为 `internal/partycommercial/domain/commercial_publication_contract_test.go`，它是测试包，不代表生产 `party-commercial` 实现已经获准。

### S01-W02 合成两阶段解析契约

第一阶段只选择商业基线，不形成接受、拒绝、计价、冻结、信用或渠道选择。完整解析键至少包含 `TenantID + CustomerAccountID + LegalEntityCandidate + ServiceOrControlScope + Purpose + CommercialSelectionAnchor + AnchorPolicyVersion + RequiredBasisSlot`；计价请求还必须包含 `PriceDirection`，`BUY`、`SELL` 和 `INTERNAL` 不能共用解析结果。结算控制请求只能表达“需要解析该控制范围的结算控制政策”，不能由调用方预先指定 `PREPAID` 或 `TERMS`，否则会绕过同范围重叠冲突。客户回填的业务时间不是商业选择锚点，也不能恢复在独立锚点下已经失效的合同。

| 结果 | 成立条件 | 可回显 | 禁止推导 |
|---|---|---|---|
| `UNIQUE_RESOLVED` | 每个必需依据恰有一个已发布且在锚点下有效的版本，引用闭包完整 | 解析标识、选择锚点及策略版本、对象类型/标识/版本、有效区间、当前修订、判断时间和隔离证据索引 | 不等于接受、计价成功、冻结成功或信用通过 |
| `NO_APPLICABLE_BASIS` | 权威读取成功，并明确证明当前完整解析键下没有适用候选；已到期或明确不覆盖的版本不算候选 | 解析标识、选择锚点、判断时间、稳定原因和隔离证据索引 | 不携带采用版本或逐项 `asOf`，不由 `party-commercial` 形成客户拒绝 |
| `APPLICABILITY_CONFLICT` | 同一完整解析键和锚点下存在两个以上已确认适用候选，或引用组合不相容 | 冲突候选的对象类型/标识/版本、适用区间、当前修订、权威视图修订、判断时间和隔离证据索引 | 不按最高版本、更新时间、存储顺序或客户级默认模式任选；第三个候选暂不可读也不能掩盖已经成立的确定性冲突 |
| `RESOLUTION_PENDING` | 锚点策略、权威读取、权威视图修订、新鲜度或必需依赖暂时不可确定，且尚不能证明唯一或冲突 | 处理阶段、稳定原因、缺失依赖、权威视图修订、尝试/续办关联、判断时间和隔离证据索引 | 不冒充零候选、技术拒绝或业务拒绝 |

`INPUT_NOT_ACCEPTED` 和 `STALE` 不属于上述候选计数结果。前者表示最小租户、客户、范围或锚点身份尚未建立，此时不得查询候选；后者表示消费方提交决定前，已解析对象的当前修订发生变化，旧快照只能保留为历史，必须重解，重解不可用时保持未决。

SYN-COM-01 和 SYN-COM-02 共享同一客户账户、责任法人、服务产品、合同和接单规则包基线，只让预付/账期政策及其控制范围不同；这证明模式由范围解析得出，而不是客户级永久属性。SYN-COM-03 在同一基线上让两类政策覆盖同一控制范围，调用方不能通过指定结算模式避开冲突。

第二阶段只在第一阶段得到 UNIQUE_RESOLVED 后执行，并严格分成三步：已选且已发布的规则包版本拥有每类下游判断的 asOf 语义和策略版本声明；消费方针对当前提交形成具体 asOf 值；相应权威提供方校验并回显实际 asOf、策略版本、判断标识、采用版本、有效区间、范围引用、夹具版本、当前修订和判断时间。声明不能临时附着在候选或请求上，调用方也不能自行发明规则包没有声明的策略；权威回显必须与第一阶段快照完全一致，不同判断的时点必须独立保存，不得压成一个全局时间。

政策版本自身的范围引用必须与解析请求的服务/控制范围一致；不能通过候选元数据把范围 A 的政策重新标记为范围 B。单个候选同时携带预付和账期政策，同样属于适用冲突，不能伪装成唯一引用闭包。

相同完整输入和相同权威视图/对象修订重复解析，返回相同解析语义和解析标识；范围、用途、价格方向、锚点策略、对象修订或候选集合变化时必须重新解析。提交前校验必须按原查询重解或校验范围级权威视图修订，不能只检查已采用对象自身；唯一解析后新增同范围候选时，旧结果立即成为 `STALE`。所有输出固定为隔离 `S`，且只存在于测试侧契约中。

对应测试文件为 `internal/partycommercial/domain/commercial_resolution_contract_test.go`。它复用 `S01-W01` 发布夹具，只建立内存候选和结果代数，不创建生产商业解析端口、Repository、事务、Outbox、客户级 `paymentMode` 或真实合同查询。

### S01-W03 合成接受前财务控制契约

本工作包只消费 `S01-W02` 唯一解析出的商业依据。控制请求不能自行指定同一范围的 `PREPAID` 或 `TERMS`，也不能从客户账户名称推导结算模式。每次结果必须保存提交版本、稳定业务关联、结算账户/币种、策略版本、实际 `asOf`、当前修订、判断时间、估价或暴露范围、夹具版本和隔离证据索引。

| 控制结果 | 形成条件 | 可继续动作 | 禁止推导 |
|---|---|---|---|
| `FROZEN` | 预付依据有效、估价可用且冻结提交确定成功 | 等待接受决定；接受失败按原关联释放 | 不等于费用确认、收款、核销或接受 |
| `RETAINED_AFTER_ACCEPTANCE` | 接受成立，或结果不确定但查询确认冻结仍合法 | 保留冻结并转接受后流程 | 不重新冻结或回写接受决定 |
| `RELEASED` | 接受确定未成立、撤回/放弃或依据失效，且释放确定成功 | 保留冻结和释放历史 | 不表示退款或真实资金退回 |
| `CREDIT_WITHIN_POLICY` | 账期信用权威明确在策略范围内 | 将独立结果交给接受判断 | 不等于已付款、应收确认或无条件接受 |
| `CREDIT_RESTRICTED` | 额度、暴露、逾期或暂停规则形成限制 | 按接单规则转人工/拒绝/未决 | 不回滚已发生运输或费用 |
| `CONTROL_PENDING` / `COMPENSATION_PENDING` | 权威读取、提交、查询或释放暂时不可确定 | 保留尝试和续办关联 | 不默认放行、拒绝或重复副作用 |

预付和账期结果保持独立。同一请求键携带不同金额、范围、账户、币种、模式或版本时形成结构化冲突且不产生第二次冻结。提交返回不确定时先查询接受决定和冻结状态；只有确认接受未成立才释放，释放失败或不确定时保持补偿未决。账期分支只形成信用暴露/业务限制，不创建冻结。

对应测试文件为 `internal/settlementaccounting/domain/financial_control_contract_test.go`。它是隔离 `S` 测试替身，不代表生产结算模型或财务适配器已经获准；测试显式断言不产生费用、应收、收款或核销事实，也不调用外部端点。

## 业务契约

### 两阶段解析

1. 第一阶段以独立商业选择锚点唯一解析客户、责任法人、服务产品、合同和接单规则包。结果只能是唯一基线、无适用依据、适用冲突或解析未决。
2. 第二阶段由已选规则包声明各项下游判断的 `asOf` 选择策略；每个权威提供方返回实际采用的值和版本。不得让待选规则包决定自身选择时点，也不得用一个全局时间替代不同判断。
3. 必需商业依据缺失、不可读取或当前修订不可确认时保持未决；权威明确零候选时返回无适用依据，多个适用候选时返回冲突。任何单项成功都不会自动接受委托。

### 财务事实分层

- 预付冻结是接受前资金控制结果；它不等于费用确认、客户付款或核销。
- 账期信用是信用暴露和业务限制结果；它不等于客户已付款或形成应收。
- 费用确认、客户运营应收、收款和核销分别由其拥有者形成，不能由本切片合并成一个“支付成功”。
- 预付与账期范围可以并存，但同一金额或控制范围只能唯一命中一种模式；重叠必须阻断。

### 未决与重试

依赖不可用、当前修订不可确认和读取失败保留原输入与处理尝试，返回稳定的未决原因和续办关联；权威明确版本已过期且没有其他适用候选时返回无适用依据，不能伪装成技术未决。相同完整解析输入与相同当前修订返回原解析语义；范围、用途、价格方向、独立锚点或当前修订变化时重新解析。客户回填的 `requestEffectiveAt` 不参与商业版本选择，`occurredAt`/`receivedAt` 也不能替代独立商业选择锚点。

| `S01-AT-01` | 唯一预付基线命中 | 只返回预付商业依据，保存政策版本和范围；控制结果由后续切片形成 |

| `S01-AT-03` | 预付/账期范围重叠 | 返回适用冲突，零控制结果落账 |
| `S01-AT-04` | 权威读取成功且无适用范围 | 返回无适用依据，不使用客户级默认；读取失败另按 `S01-AT-05` 保持未决 |
| `S01-AT-05` | 依赖读取失败 | 保留处理尝试，结果可安全查询和续办 |
| `S01-AT-06` | 提交结果不确定 | 不重复冻结、释放或业务提交；查询原关联后再决定补偿 |
| `S01-AT-07` | 版本在提交前失效 | 丢弃旧判断，重新解析；重判不可用时保持未决 |
| `S01-AT-08` | 合成输出隔离 | 不调用真实财务端点，不产生真实应收、应付、收款或核销 |

## 开发禁止项

- 不建立客户级 `paymentMode` 或预付/账期永久互斥枚举。
- 不把冻结、信用、费用确认、收款和核销压成一个状态或布尔值。
- 不以“没有真实配置”为理由写入生产默认账户、额度、费率、币种或有效期。
- 不用自由文本或技术异常替代结构化冲突、无依据和未决结果。
- 不在商业上下文创建真实委托、生产归属、运输、关务或客户通知事实。
- 不把 `parcel-pricing` 的可执行价卡版本当作 `party-commercial` 的客户、合同或政策主数据；商业发布测试只保留隔离 `S` 版本。

## 证据和准入结论

本切片完成只能说明合成语义和开发测试契约已具备。`PAR-COM-08`、`PAR-SET-01`、`PAR-SET-02`、`PAR-COM-14` 和 `PAR-COM-15` 的真实实例仍为待提供状态；生产结论保持 `No-Go / 待参数化`。任何未来真实分支必须重新提交 W03 证据、执行正式矩阵场景，并由 PN-08 形成阶段决定。

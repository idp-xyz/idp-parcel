# `BD-PP-001` 不可计价结果语义决策简报

状态：**未决**。本简报只提出问题、拆分子问题并列出选项与后果，不作决定，也不构成可实现的规则。未确认前不得把任何一个选项实现为产品默认行为。

决定方：计价与结算业务责任方（结果形态）；产品与治理（是否属计价范围）。

## 要决定什么

**当计价规则明确表明某一票不可计价时，`parcel-pricing` 应当形成什么结果？**

这里说的是规则给出了否定答案，不是缺依据。例如价卡写明超过某重量的包裹不予承运，或声明某类物品属违禁不予计费。

## 为什么现在提

[小包计价上下文](../domain/parcel-pricing/CONTEXT.md)的价格评价生命周期目前只有三个出口：

| 出口 | 现有定义 | 能否表达「规则说不行」 |
|---|---|---|
| 已完成 | 输入、规则和计算结果完整并保存版本清单与解释 | 否——没有可成立的金额 |
| 待判断 | 事实、商业依据、规则或依赖**不足**，补齐后可重新评价 | 否——定义写明是「不足」，且承诺补齐后可重评 |
| 冲突 | 同一必需范围存在**互斥**规则、区间或版本候选 | 否——规则并不互斥，它一致地给出否定 |

三个都不成立，于是这类结果目前只能被挤进「待判断」。这会产生一个具体的坏后果：调用方读到「补齐后可重新评价」，就会持续补数据、持续重试，而这票无论补什么都不会有价格。

第二个坏后果更隐蔽：如果实现方为了让流程走下去，形成一条金额为 0 的**已完成**评价，这条评价会一路流进 `settlement-accounting`，变成一笔「确实算过、就是不收钱」的费用依据。金额 0 与不可计价在账上是两件完全不同的事。

外部参考设计对这一点有明确约束（计算语义 §1.5）：产品准入失败属于业务不可计费，必须形成失败结果并保留准入判断引用，**不得为不可承运产品生成金额为 0 的已完成评价**。本仓可以不采纳它的状态命名，但这条禁止值得单独考虑。

第三，这件事和当前的 `BLOCKING` 项直接相关。[`SRC-DISC-001`](./pp-s03-w01-golden-case-source-evidence-request.md) 的分歧本质是：超限包裹到底按附加费收 2025 美元，还是按违禁品罚 5000 美元、根本不该承运。两种解释需要两种不同的评价出口，而现在只有一种。[转录本](./pp-golden-case-transcript.md)里的 `BND-019`/`BND-020` 正是 `Unauthorized` 在 150 LB 上下的边界判定。

## 决定前必须先分开的三个子问题

合在一起谈会得出错误结论。

### 子问题一：「规则说不行」和「没有规则覆盖」是同一件事吗

- 价卡写明「超过 150 LB 不予承运」——规则给出了否定答案。
- 价卡的重量档只排到 150 LB，一票 151 LB 落在档位之外——规则没有给出答案。

现行 CONTEXT 把后者归入「区间空档 → 待判断」，前者无处可归。如果两者合并为同一出口，就再也分不清「补数据能解决」和「补数据也没用」。如果分开，则需要两套语义而不是一套。

### 子问题二：不可承运的来源有三处，它们是同一个结果吗

| 来源 | 拥有者 | 例子 |
|---|---|---|
| 承运商价卡限制 | `parcel-pricing`（价卡内容） | 超过重量/尺寸上限不予承运 |
| 服务产品适用范围 | `party-commercial` | 该产品不服务此目的地 |
| 客户合同约定 | `party-commercial` | 合同排除某类货物 |

计价只拥有第一处。如果希望三者产出一个统一的「不可承运」结论，那么这个概念的所有者就不是计价，本简报的问题也要改写成跨上下文问题。

### 子问题三：这个出口该不该由计价承担

**反方**：准入判断已经由 [`UC-NR-002`](../application/network-routing/UC-NR-002-ASSESS-PARCEL-REACHABILITY.md) 的接受前可达性和 `party-commercial` 的产品适用条件在接单阶段完成。计价只应在「已经确定可计价」的输入上运行，不必自带否定出口，边界更干净。

**正方**：计价不只服务接单。它还服务估价、成本预测、争议复核和回放。回放一票历史上被判超限的包裹时，「待判断」是错误答案——那次评价当时就有确定结论。而且限制条款写在价卡里，别的上下文无法代替计价去读它。

## 选项与后果

| 选项 | 内容 | 代价与风险 |
|---|---|---|
| A | 评价生命周期新增终态「不可计价」，携带否定依据与版本清单 | 语义最清楚，回放可重现；状态机多一个出口，须定义谁有权产生它、下游如何消费，并回答子问题一是否再细分 |
| B | 不新增终态，把判断前移到接单与可达性，计价永不遇到此输入 | 计价边界最干净；但估价、争议复核和回放三个消费场景失去确定答案，且价卡限制需要在计价之外被重新表达一遍，有制造第二套口径的风险 |
| C | 仍形成已完成评价，但金额缺省而非 0，另附独立的「不可承运结论」 | 不动状态机；但「已完成」与「无金额」并存容易被下游误读，且需要额外规则禁止把缺省当 0 |
| D | 维持现状，归入「待判断」 | 零改动；但与「待判断」的现有定义直接矛盾，会诱导无限重试，且无法阻止金额 0 的变通实现。列出仅供对照，不建议 |

## 可以先单独采纳的一条

无论最终选 A、B 还是 C，下面这条都成立，且不依赖出口形态的选择：

> 不得以金额为 0 的已完成评价表达不可计价。

它堵的是一个具体失败模式，代价近乎为零。是否先行确认这一条，可以与主选项分开决定。

## 与 `SRC-DISC-001` 的关系：可分，不要绑死

出口语义是机制问题，某一笔金额究竟是罚款还是禁运是业务裁决。两者互不阻塞：

- 先定出口语义，裁决到达时直接落位；
- 先出裁决，出口语义仍需另行决定。

把两者绑在一起只会让彼此互相等待。

## 需要什么证据才能定

1. 真实价卡中「不予承运」条款的实际形态——是拒绝承运，还是以罚金形式收费。这一条同时会推进 `SRC-DISC-001`。
2. 锚点客户合同对超限或违禁包裹的约定——拒收、退运，还是加收。
3. 是否存在「接单通过、计价阶段才发现不可承运」的真实流程。若不存在，选项 B 的说服力显著上升。

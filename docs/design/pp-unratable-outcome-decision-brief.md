# `BD-PP-001` 不可计价结果语义决策简报

状态：**机制已确认**（2026-08-07）。语义与不变量已写入[小包计价上下文](../domain/parcel-pricing/CONTEXT.md)，消费侧已同步 [`UC-SA-002`](../application/settlement-accounting/UC-SA-002-CALCULATE-CONFIRM-AND-ADJUST-OPERATIONAL-CHARGES.md)。**排除规则已实现**（见[实现排期](#实现排期)）：`不可计价`终态与排除规则随附加费执行完成后一并落地，复用同一套触发条件语法。**各档阈值与违禁品类仍待价卡证据**，未登记前不得把任何具体阈值实现为产品默认值——当前代码不含任何阈值常量，阈值只能由价卡版本携带。

决定方：仓库所有者在本次会话中明确授权按实际业务直接定案；本简报记录决定内容与依据，供业务责任方复核。本决定只确认机制，不确认任何金额、重量上限或违禁清单。

## 要决定什么

**当计价规则明确表明某一票不可计价时，`parcel-pricing` 应当形成什么结果？**

这里说的是规则给出了否定答案，不是缺依据。例如价卡写明超过某重量的包裹不予承运，或声明某类物品属违禁不予计费。

## 为什么现在提

[小包计价上下文](../domain/parcel-pricing/CONTEXT.md)的价格评价生命周期目前只有三个出口：

| 出口 | 现有定义 | 能否表达「规则说不行」 |
|---|---|---|
| 已完成 | 输入、规则和计算结果完整并保存版本清单与解释 | 否——没有可成立的金额 |
| 待判断 | 事实、商业依据、规则或依赖**不足**，补齐后可重新评价 | 否——定义写明是「不足」，且承诺补齐后可重评 |
| 冲突 | 同一必需范围存在**互斥**规则、区间或版本候选 | 否——规则并不互斥，它一致地给出否定 |

三个都不成立，于是这类结果目前只能被挤进「待判断」。这会产生一个具体的坏后果：调用方读到「补齐后可重新评价」，就会持续补数据、持续重试，而这票无论补什么都不会有价格。

第二个坏后果更隐蔽：如果实现方为了让流程走下去，形成一条金额为 0 的**已完成**评价，这条评价会一路流进 `settlement-accounting`，变成一笔「确实算过、就是不收钱」的费用依据。金额 0 与不可计价在账上是两件完全不同的事。

外部参考设计对这一点有明确约束（计算语义 §1.5）：产品准入失败属于业务不可计费，必须形成失败结果并保留准入判断引用，**不得为不可承运产品生成金额为 0 的已完成评价**。本仓可以不采纳它的状态命名，但这条禁止值得单独考虑。

第三，这件事和当前的 `BLOCKING` 项直接相关。[`SRC-DISC-001`](./pp-s03-w01-golden-case-source-evidence-request.md) 的分歧本质是：超限包裹到底按附加费收 2025 美元，还是按违禁品罚 5000 美元、根本不该承运。两种解释需要两种不同的评价出口，而现在只有一种。[转录本](./pp-golden-case-transcript.md)里的 `BND-019`/`BND-020` 正是 `Unauthorized` 在 150 LB 上下的边界判定。

## 决定摘要

| 问题 | 决定 |
|---|---|
| 「规则说不行」与「没有规则覆盖」是否同一结果 | **分开**。前者为新出口，后者仍为待判断 |
| 不可承运的三个来源是否合并为一个结果 | **不合并**。计价只表达价卡侧排除 |
| 该出口由计价承担还是前移到接单 | **由计价承担** |
| 出口形态 | **选项 A：新增终态**，命名为「不可计价」 |
| 零金额禁令 | **采纳** |

## 三个子问题的决定与依据

合在一起谈会得出错误结论，所以逐个定。

### 子问题一：「规则说不行」和「没有规则覆盖」是同一件事吗

- 价卡写明「超过 150 LB 不予承运」——规则给出了否定答案。
- 价卡的重量档只排到 150 LB，一票 151 LB 落在档位之外——规则没有给出答案。

现行 CONTEXT 把后者归入「区间空档 → 待判断」，前者无处可归。

**决定：分开。** 依据是运营侧要做的事完全不同。规则说不行，运营要做的是联系客户、退运或改渠道，这是一个业务动作触发点；规则没覆盖，运营要做的是补价卡、补分区或找采购要报价，这是一个数据缺口。责任人不同、补救方式不同、时限也不同，合成一个出口会让两类工单混进同一个队列。

代码现状与该决定一致：档位查不到映射为 `PENDING` 加 `RATE_NOT_FOUND`，属待判断，保持不变。新出口只承载明确排除。

### 子问题二：不可承运的来源有三处，它们是同一个结果吗

| 来源 | 拥有者 | 例子 |
|---|---|---|
| 承运商价卡限制 | `parcel-pricing`（价卡内容） | 超过重量/尺寸上限不予承运 |
| 服务产品适用范围 | `party-commercial` | 该产品不服务此目的地 |
| 客户合同约定 | `party-commercial` | 合同排除某类货物 |

计价只拥有第一处。

**决定：不合并，计价只表达价卡来源那一处。** `party-commercial` 已经有「无适用依据 / 适用冲突 / 解析未决」三分并在用，产品适用范围与合同排除由它承担。若让计价出口吸收这两类，计价就开始拥有商业适用性，与 CONTEXT 明写的「不拥有客户合同、供应商协议、商业适用性」直接冲突。需要统一「这票不能做」视图的消费方在应用层合成，不在领域层合并。

这条决定同时给「不可计价」定了确切外延：它只意味着**按已解析的可执行价卡无法形成价格**，不意味着这票不能被承运。

### 子问题三：这个出口该不该由计价承担

**反方**：准入判断已经由 [`UC-NR-002`](../application/network-routing/UC-NR-002-ASSESS-PARCEL-REACHABILITY.md) 的接受前可达性和 `party-commercial` 的产品适用条件在接单阶段完成。计价只应在「已经确定可计价」的输入上运行，不必自带否定出口，边界更干净。

**正方**：计价不只服务接单。它还服务估价、成本预测、争议复核和回放。回放一票历史上被判超限的包裹时，「待判断」是错误答案——那次评价当时就有确定结论。而且限制条款写在价卡里，别的上下文无法代替计价去读它。

**决定：由计价承担。** 决定性依据来自本产品的真实流程，不是偏好。

接单判断依据的是**客户申报**的重量与尺寸；权威实测由 `node-operations` 在有效网络收寄之后形成（[`UC-NO-003`](../application/node-operations/UC-NO-003-PROCESS-CONSOLIDATE-AND-SEAL-PARCELS.md) 的测量环节）。一票申报 20 LB、实测 160 LB 的包裹，接单时一切正常，超限只有在计价拿实测事实去撞价卡时才暴露。这不是边缘情况，而是超限在自营网络里最常见的发生方式。

因此「准入在接单前判完、计价只在可计价输入上运行」在本产品是事实错误，选项 B 出局。

## 出口形态：选定 A

| 选项 | 内容 | 结论 |
|---|---|---|
| **A** | 评价生命周期新增终态，携带排除依据与版本清单 | **采纳**。语义清楚，回放可重现，与既有三个出口互不重叠 |
| B | 不新增终态，判断前移到接单与可达性 | 否决。与实测后置的真实流程矛盾，见子问题三 |
| C | 仍形成已完成评价，但金额缺省而非零，另附独立结论 | 否决。「已完成」在本上下文意味着结果完整可被结算采用，与无金额并存必然被误读 |
| D | 维持现状，归入「待判断」 | 否决。与「待判断」现有定义直接矛盾，会诱导无限重试 |

### 命名：「不可计价」，不叫「不可承运」

计价无权断言一票能不能被承运——那是产品与运输的判断。它能断言的只是按该价卡无法形成价格。用「不可承运」会让本上下文的结论越界，也会与 `party-commercial` 的产品适用范围结论撞车。

### 一个代码事实使这个新出口成为必需，而不只是更清楚

`internal/parcelpricing/domain/evaluation.go` 的 `EvaluationStatus` 已经有第四个取值 `FAILED`，且确实在产生：请求不合法（`INVALID_REQUEST`）、负数总额（`NEGATIVE_TOTAL`）、计算失败（`CALCULATION_FAILED`）。也就是说 `FAILED` 已经被占用为**技术或结构失败**。

把「不可计价」塞进 `FAILED`，会让一个确定的业务结论和一次系统故障共用一个状态，下游再也分不清「这票本就不该有价格」和「系统这次算不出来」——前者要走业务处置，后者要重试和报警。所以新增出口不是取舍偏好，是既有实现留下的必然结果。

顺带补上一处文档落后于代码的地方：`FAILED` 此前从未写进 CONTEXT。本次一并把它记为「未形成」，使四个出口在文档里齐全。

### 零金额禁令：采纳

> 不得以金额为零的已完成评价表达不可计价、不可承运或无适用价格。

它堵的是最可能发生的变通实现——为了让流程走下去造一条 0 元成功评价，那条评价会一路流进结算变成「确实算过、就是不收钱」的费用依据。已写入 CONTEXT 不变量。

## 与 `SRC-DISC-001` 的关系：比预想的更可分

出口语义是机制问题，某一笔金额究竟是罚款还是禁运是业务裁决，两者互不阻塞。

核对转录本后这一点更清楚了：`SRC-DISC-001` 对应的案例 `ERR-012` 标题是「Unauthorized 费用在源价卡中 2025 与 5000 冲突，**禁止发布**」，错误码 `SOURCE_RATE_CARD_CONFLICT_UNRESOLVED`。也就是说，这条差异在参考设计里也是**发布期的价卡内容冲突**，不是逐票评价的准入结论。映射到本仓，它落在定价方案与价表版本生命周期的「草稿 → 已校验」校验失败，与评价出口无关。

所以裁决 `SRC-DISC-001` 不会改变本决定，本决定也不预判该裁决。

## 仍待证据的部分

机制已定，下列内容仍需真实价卡与合同证据，未登记前不得实现为默认值：

1. **排除条款目录**：真实价卡里哪些条款构成明确排除（重量上限、尺寸上限、违禁品类），以及各自的判定口径。

   **本项原为「等目录到位才能设计排除规则」，已按能力范围判据拆分。** 原文把两件事捆在一起：排除规则这个**建模对象**，和目录里的**实例值**。按[开发主线的能力范围判据](../product/PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)，「超尺寸或超重上限直接拒收」是可命名的常规渠道条款形态（本节下文即其出处），机制指得出来，因此**排除规则可以在没有真实价卡时建模**。仍待价卡的只有实例值：各档阈值与违禁品类，它们和其他取值一样由价卡版本携带，不得内置为常量。

   排除条款在真实渠道条款中确实以「拒收」形态出现，形态与本决定一致。公开可见的美线小包渠道条款把尺寸分成三档处置：超过第一档加收固定附加费，超过第二档加收更高附加费，**超过最高档直接拒收**；判定量正是最长边与「长 + 宽×2 + 高×2」。这印证了两点：排除是价卡条款的常规组成而非边缘情形，且它与超限附加费共用同一套特征谓词，只是效果不同——一个加钱，一个使价格不成立。该观察来自公开渠道页面，只说明形态，不构成任何阈值参数，实例值仍按本节要求取证。

   **此处原写「与 `parcel-pricing` 已实现的最长边与长加围特征同形」，一度更正为「长加围并未实现」，现已重新成立。** 该更正写于 `FeatureSource` 只有 `LONGEST_SIDE` 一个取值时；此后特征来源补到最长边、次长边、长加围、体积、实重五项，阈值支持长度、体积与重量三种量纲，`R40` 的「实重超 67.5 KG」已可表达。共用谓词这一判断始终不变，如今也已兑现：排除规则读的就是附加费那一套触发条件。CONTEXT 声明的十项中，分区、地址类型与服务选项三项分类特征仍未实现，它们需要相等而非比较，与本项排除条款的判定量（重量与尺寸上限）无关。
2. **排除依据的结构**：排除结果需要携带哪些引用（条款标识、价表版本、单元格坐标或规则标识）才足以支撑争议复核。

   **本项已不待证据。** 支撑争议复核所需的三样——触发的规则标识、命中的判定条件、版本清单——概念都已存在于本上下文，不依赖任何真实价卡即可确定。单元格坐标属源价卡转录的溯源信息，归 [`PP-S03-W01`](./pp-s03-w01-golden-case-source-evidence-request.md) 一线，不进评价结果。
3. **合同侧约定**：锚点客户合同对超限或违禁包裹的处理——拒收、退运还是加收。它决定运营侧承接这个结论的流程，但不改变计价的出口语义，因此不阻塞本上下文实现排除规则。

### 实现排期

**已实现。** 本节此前列的两条约束都已了结，其中第二条的预判是错的，记在这里以免再犯：

- **执行门禁在前——已满足。** 方案一旦声明任何结构，评价此前直接返回`未形成`（`PLAN_STRUCTURES_NOT_EXECUTABLE`），因此排除规则必须排在附加费执行之后；提前实现只会得到一条保证让评价`未形成`的规则。计价规则模型的七步实施顺序全部落地后该门禁已空，这条约束随之解除。
- **规范化版本要批——预判有误，实际不需要。** 此前判「给 `PricingPlanStructures` 增加排除规则是形状改动，按 [ADR-0014](../adr/0014-versioned-canonicalization-shape-for-content-digest.md) 要新增一个规范化版本」。实际不是：排除规则在规范化方案文档里是一个 `omitempty` 的可选字段，不声明排除的方案输出逐字节不变，既有摘要继续可比。判据与 [ADR-0015](../adr/0015-closed-grammar-open-vocabulary-for-multi-carrier-rating.md) 的 `Amended by` 一致——看规范化形状是否改变，不看是否新增概念。同批的换算步骤后来也按同一理由未升版本。

**「唯一可以先做且零成本的是补齐特征来源」也已完成**，且它确实是共同前提：排除规则复用了附加费的同一套触发条件语法，只是效果不同——一个加钱，一个使价格不成立。

## 本决定不包含

- 不裁决 `SRC-DISC-001`，不改变任何案例的证据层级或阻断状态。
- 不定义 API、字段、错误码或对外状态名。
- 不新增 `UC-PP-*`；本仓当前没有计价应用用例，计价由 `UC-SA-002` 编排。
- 不新增 ADR：这是领域语言与生命周期的补充，不是难以逆转的架构取舍，按改文档规则落在 `CONTEXT.md`。
- 不改动 `internal/parcelpricing/domain` 的状态枚举。当前没有任何规则能产生「不可计价」，加一个无人产生的取值只会制造无法测试的空位；等排除规则按上文排期落地时一并加。该理由不随阻塞解除而失效——枚举取值要和产生它的规则同时出现，不能先于它。**该条已由排除规则那次实现兑现**：枚举取值与产生它的规则同批加入，CONTEXT 生命周期与代码之间那处已知的不一致随之收口。

相邻观察，不属本决定：`NEGATIVE_TOTAL` 现在归入 `FAILED`（技术失败），但扣减规则超过运费总额更像规则或数据冲突。是否改判留待有真实折扣规则时再看。

# 仓配履约（`warehouse-fulfillment`）

Status: Provisional（2026-11-06 由 Cursor 会话代决写成：用户原话「你作为业务和系统专家，参考领星的系统，你帮我决定吧」与「你全权」。各条参照领星 WMS 与领星 ERP 的公开帮助文档拟定，取舍与参照记在[票 warehouse-fulfillment/01](../../../.scratch/warehouse-fulfillment/issues/01-write-the-warehouse-fulfillment-context.md)；语言与规则待仓配履约、小包托运、小包计价、结算与经营核算和一线作业端 owner 复核。）

本上下文管理 3PL 仓配：货主商品、库存账与库存流水、占用与分配、入库预报与收货上架、库内移动与盘点、出库请求与拣货、出库复核、打包、出库确认与截单、退货入库与回库处置、代理仓库存声明，以及仓储作业的收费发生项。它回答“哪个货主的哪种商品，在哪个仓哪个库位、什么状态、有多少、被谁占着”，以及“仓里对这些货实际做了什么”。

仓配履约做的是 3PL 仓配，不是货主的进销存：库存只记数量、位置与状态，不记成本与价值，也不管采购、销售订单与补货计划。商品库存与包裹是两种身份：打包完成、提交委托之前只有库存与作业任务，提交之后只有包裹（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定三）。首发不包含本上下文的能力（ADR-0368 决定八）。

本文件是 `warehouse-fulfillment` 语言、规则与生命周期的权威来源。跨上下文术语以[统一领域语言](../GLOSSARY.md)为准，所有权关系以[领域上下文地图](../CONTEXT-MAP.md)为准。规则与实现的差距见各 UC「给开发的交接」。

## Language

### 货主、仓与商品

**货主**  
跨上下文定义见 [GLOSSARY「货主客户账户」](../GLOSSARY.md#货主客户账户)。本上下文说“货主”一律指一个货主客户账户：商品、库存账、入库预报、出库请求与收费发生项都按它分，本上下文不另立货主档案；不同货主客户账户的库存互不相通。
_Avoid in this context_: 货权人、店铺、客户（单说）

**仓**  
仓配履约经营的一处存储与作业场所，带地址与业务时区，分自营仓与代理仓。仓是本上下文的身份，不是 `network-routing` 的物流节点；与物流节点同址时可以指名那个节点，两个身份不合并（ADR-0368 决定三）。仓的业务时区是租户取值。
_Avoid in this context_: 物流节点、场站、仓库组织

**自营仓**  
作业由本产品一线作业端执行、库存由本上下文逐笔记账的仓。

**代理仓**  
由合作方经营、本上下文只收它报来的库存声明的仓；它的作业不在本上下文执行，库存不进库存账。
_Status_: provisional（ADR-0368 越权风险点 6）

**库区**  
仓内按用途划分的一组库位。库区用途是产品内置的封闭六种：收货暂存、存储、拣选、次品、退货暂存、待出库。各仓划哪些库区、各有哪些库位是租户取值。
_Avoid in this context_: 作业区、暂存区（节点作业的说法）

**库位**  
跨上下文定义见 [GLOSSARY「库位」](../GLOSSARY.md#库位)。本上下文里库位属于一个库区，库存账按它记位置；库位带库位类型（货架、地堆、托盘位之类，租户维护）与优先级，类型用于按库位计仓租，优先级用于分配。
_Avoid in this context_: 仓位、货位、作业位置

**商品**  
货主名下按货主给的商品编码识别的一种货（SKU），身份是（租户，货主，商品编码）；不同货主的同一编码互不相干。商品声明基本单位与包装层级、是否跟踪批号与效期，带商品申报资料与仓测尺寸重量。
_Avoid in this context_: 产品（与“服务产品”相混）、货品

**商品别名**  
同一货主内只指向一个商品的另一个识别码：条码、平台商品码（FNSKU、MSKU 之类）等，带类型与可选的有效区间。别名不跨货主解析；一个别名对多个商品的组合商品不建模，由货主在交来请求之前展开。

**包装层级**  
商品声明的计量单位层级（件、内盒、箱之类），每一层写明折合多少个基本单位。库存账按计量单位记数；层级之间的转换是形态转换。

**仓测尺寸重量**  
仓在商品首次收货时实测的单位尺寸与重量，可以按包装层级各测一份。本上下文的体积与重量计量一律用它，不用货主声明的那份；还没测的，依赖它的计量如实答未测量。

**商品申报资料**  
货主为商品声明的申报品名、HS 编码、原产国、申报单价与币种。它是货主的声明性资料：本上下文保存它，提交委托时原样带入客户原始资料，不判断归类与合规（归 `customs-compliance`）。

### 库存账

**库存账**  
按（租户，货主，仓，库位，商品，计量单位，库存状态，入库批次，批号，效期）记数量的账。一格的余额只由库存流水派生，不另存可改写的余额。

**库存流水**  
改变库存账的唯一方式。一笔流水记一格或成组几格的数量增减、原因与来源事实引用；原因是封闭集：收货、退货入库、期初导入、库内移动、形态转换、状态转换、出库确认、盘盈、盘亏、调增、调减、销毁。已入账的流水不改不删，更正以新流水表达（[ADR-0005](../../adr/0005-source-facts-effective-events-derived-state.md)）。

**库存状态**  
货的品质与可售性分类，产品内置封闭三格：良品、待检、次品。它是库存账的一维；改状态要记一笔状态转换流水，不改实物总量。
_Avoid in this context_: 可用（“可用量”是算出来的数，不是状态）、正品、残次品

**入库批次**  
一次收货、退货入库或期初导入为一个商品形成的批次，带入库时间；同一次入账、同一商品、同一批号与效期的数量同属一个入库批次。库龄与先进先出都据它；状态转换、库内移动与形态转换不另起入库批次。
_Avoid in this context_: 批次（单说，与作业批次、提交批次相混）、上架批次

**批号**、**效期**  
只在商品声明跟踪时才有值：批号是生产方或货主给的生产批号，效期是失效日期。不跟踪的商品这两维为空。
_Avoid in this context_: 批次

**库龄**  
一个入库批次自入库时间起在仓的天数，按仓的业务时区计日：入库当天算第 1 天，日终仍在库才计当天，所以出库当天不计。

**库龄口径**  
仓租发生项把在库量归到哪些入库批次：按实际入库批次（流水实际消耗的入库批次），或按理论先进先出（不管实际拣了哪一批，把在库量归到最近的几次入库）。两种都是产品内置，用哪一种是租户取值。

### 占用与可用量

**可分配库存**  
能被预占的那部分在库：存储或拣选库区里的良品，以及次品库区里的次品（只给要出次品的出库请求）。收货暂存、退货暂存与待出库库区里的库存，以及待检库存，都不可分配。

**占用**  
对某一格可分配库存的数量占用。占用不是库存账的一维，不改实物总量，只减可用量。产品内置封闭三种：预占、冻结、作业锁定，三者互不重叠（ADR-0368 决定五）。

**预占**  
出库请求对可用量的占用，在库存账内原子判定。预占按（货主，仓，商品，库存状态，请求点名的批号或效期条件）成立，不落到库位；分配时落到库位与入库批次，出库确认时消耗，截单或请求终结时释放。

**冻结**  
运营决定让一格库存暂不可分配的占用，带原因（如货主要求停售、质量争议），只经解冻决定解除。

**作业锁定**  
盘点进行中对所涉库位库存的临时占用，盘点完成或作废即解除。

**可用量**  
可分配库存减去各项占用。占用互不重叠，直接相减；可用量是算出来的数，不是状态。

### 入库

**入库预报**  
货主经客户渠道交来的到货通知：到哪个仓、预计到仓时间、到仓方式（整柜、托盘、散箱之类）与商品明细（商品、预报数量、可选的批号与效期、箱数）。预报不是库存，也不承诺实收。

**收货**  
仓对一批到货清点后确认的实收事实：按商品、计量单位与库存状态记实收数量。收货确认即入账：以收货流水进入收货暂存库区，形成入库批次。
_Avoid in this context_: 收寄（节点作业的说法）、签收

**收货差异**  
实收与入库预报不一致的部分（多收、少收、错货、破损），逐商品记类型与数量，交货主确认。库存只按实收入账，差异不改实收。

**待认领到货**  
到了仓却认不出属于哪个货主或哪份预报的货。它只登记到货与观察，不进任何货主的库存账；认领给某个货主之后，才按收货入账。

**上架**  
把收货暂存或退货暂存里的库存移到存储、拣选或次品库位的库内移动。上架不改数量与入库批次。

**库内移动**  
库存在库位之间的移动：上架、移库、拣选位补货、拣货移入待出库库区、截单回库与拆包回库。每次移动是一笔成组流水，移出与移入数量相等。

**拣选位补货**  
从存储库位向拣选库位的库内移动；需要拆箱时，同一笔流水里带形态转换。

**形态转换**  
同一商品在包装层级之间的转换（如一箱转为二十四件），在同一笔流水里按货主、商品与计量单位守恒，折成基本单位前后相等（ADR-0368 决定五）。

### 出库

**出库请求**  
跨上下文定义见 [GLOSSARY「出库请求」](../GLOSSARY.md#出库请求)。本上下文里它带商品明细（商品、数量、要出的库存状态、可选的批号或效期条件）、收件人与地址、要求的服务产品与本单申报值；属于一个货主客户账户，从一个仓发出。

**缺货处置**  
可用量不够满足出库请求时怎么办，产品内置封闭三种：整单等待（不预占，等可用量够了再判）、部分预占（先占有的，缺的部分补到再占，全部占齐才进波次）、拒绝（答缺货，请求终结）。用哪一种是租户取值，可以按货主选。

**分配**  
波次释放时把预占落到具体库位、入库批次与数量上，生成拣货任务。分配不超过它所属的预占。

**分配策略**  
分配时按什么顺序选入库批次与库位。入库批次的顺序是产品内置封闭三种：先到期先出（按效期）、先进先出（按入库时间）、指定批号（请求点名）；库位先按库区（拣选先于存储）、再按库位优先级。随产品发一份参考配置：跟踪效期的商品先到期先出，其余先进先出；租户经普通登记采用（[ADR-0147](../../adr/0147-reference-configuration-ships-embedded-and-is-adopted-through-ordinary-registration.md)）。

**波次**  
为拣货把一组出库请求的分配合在一起的作业归组，按什么归组（商品、服务产品、库位之类）由仓定。波次不取得出库请求的身份，也不是节点作业的作业批次。
_Avoid in this context_: 作业批次、提交批次

**拣货任务**  
按分配从某个库位拣出某商品某数量、移入待出库库区的作业任务；完成即记一笔库内移动流水。实拣与分配不符时按实拣记，差额形成库存差异（ADR-0368 决定六）。

**出库复核**  
打包前按出库请求逐件核对拣出的商品与数量。核对不符的不打包：退回重拣，或形成库存差异。
_Avoid in this context_: 复核（单说：在别的上下文是重新审、重新判）、验货

**打包**  
把出库复核通过的货装成一个或多个包裹，称重量方、记所用包材；每个包裹在出库请求内有包裹序号。打包完成即为这个包裹提交一份委托。

**装箱记录**  
打包时按包裹序号记下装了哪些商品、多少、包材与称得的重量和尺寸。委托提交后它指名小包托运的委托与包裹；本上下文不另立包裹身份。

**仓配出库提交**  
打包完成时以出库请求所属货主客户账户的名义向 `parcel-shipment` 提交委托：来源「仓配出库」，来源请求键是（出库请求，包裹序号）；称得的重量与尺寸作声明测量，收件人、商品明细与申报值作客户原始资料。它与客户渠道交来的委托受同一套接受判断（ADR-0368 决定四）。

**出库确认**  
包裹离开仓、交给下一程（同址节点、揽收或干线）那一刻由仓内作业确认的事实。库存在这一刻按分配消耗，预占随之消耗；出库确认之后这件货不再归本上下文。
_Avoid in this context_: 出库（单说：在 `customs-compliance` 是节点上受门禁约束的交出动作）、发货

**截单**  
货主撤回尚未出库确认的出库请求或其中的包裹。仓配履约逐件判定截单成立与否，成立的按所处阶段释放预占、撤销分配，或回库。

### 盘点、差异与调整

**盘点**  
按库位、或按商品加库位清点实物并与账比对的作业。本上下文的盘点是静盘：开始时对所涉库位的库存加作业锁定，结束时解除。
_Avoid in this context_: 在场核对（节点作业的说法）

**库存差异**  
账与实物不符的部分：盘点差异、实拣与分配不符、上架或出库复核时发现的短少与破损。差异交人处理：经批准的以新流水改账，未批准的不改账（ADR-0368 决定六）。

**库存调整**  
盘点之外改账的决定，如找回、调增调减、期初导入、销毁。调整带原因，经批准后以流水入账；期初导入可以带声明的入库时间，库龄据此计。

### 退货

**退货预报**  
货主告知将有退件到仓的通知，带原包裹的外部标识或跟踪号与预计的商品。没有预报的退件照样可以到仓。

**退货入库**  
退件到仓后的登记、清点与质检。按退货预报或本上下文的装箱记录认出货主与商品，认不出的建待认领到货；清点结果以退货入库流水进入退货暂存库区，形成新的入库批次，状态按质检记良品、待检或次品。

**回库处置**  
退货入库之后，按货主指令或租户规则对每件货定去向：良品上架回可分配库存、转次品入次品库区、销毁，或经新的出库请求退还货主。处置由运营决定，执行以流水入账。

### 代理仓

**代理仓库存声明**  
代理仓按时点报来的货主库存数量，带来源、声明时点与有效期。它不是自营实时库存，不进库存账；过了有效期答「未知」，不据它做确定性承诺（ADR-0368 决定五）。
_Status_: provisional（ADR-0368 越权风险点 6）

### 收费发生项

**仓储作业收费发生项**  
跨上下文定义见 [GLOSSARY「仓储作业收费发生项」](../GLOSSARY.md#仓储作业收费发生项)。本上下文里一份发生项带作业种类、货主、仓、业务时间、来源事实引用，以及一组计量与作业属性。

**作业种类**  
收费发生项的种类，产品内置封闭六种：入库、出库、仓租、退货处理、增值服务、销毁。各种类对应哪些作业由本上下文定义；收不收、怎么收是价卡的事。

**计量**  
发生项里的一组（数量，单位），如票、箱、托、件、千克、立方米、库位·天。本上下文只给发生了多少，不分段、不给单价。
_Avoid in this context_: 计费量、计费重量（`settlement-accounting` 的词）

**作业属性**  
价卡判条件要用的发生项属性，如到仓方式、服务产品、包材、库存状态、库区用途、库位类型。属性只描述作业，不含价格。

**增值服务项目**  
增值服务发生项指名的服务，如贴标、换标、拍照、质检、加固；项目表由租户登记，没登记的项目不形成发生项。

## Rules and invariants

### 身份与边界

- 商品库存与包裹是两种身份，按对象分边界、不按场地分：打包完成、委托提交之前只有库存与作业任务，之后只有包裹。库存的库位与状态不是包裹的节点控制；包裹的节点控制与作业位置也不是库存（ADR-0368 决定三）。
- 本上下文的货主就是货主客户账户；商品、库存与请求都挂在它下面，不另立货主档案，也不跨货主客户账户合并库存。
- 仓、库区与库位是本上下文的身份。仓与物流节点同址时只互相指名，不合并；节点作业的作业位置不当库位，库位也不进节点作业的位置关系。
- 认不出货主或预报的到货与退件建为待认领到货，不冒充任何货主的库存；认领之后才入账。
- 商品身份是（租户，货主，商品编码）；别名在同一货主内只指一个商品，不跨货主解析。
- 本上下文不记库存成本与价值，不管货主的采购、销售订单与补货计划（ADR-0368 决定二）。
- 凡按日计的（库龄、仓租计费日、日终在库）都按仓的业务时区；仓的业务时区没登记时这些都答未配置。

### 库存账与守恒

- 余额只由库存流水派生。已入账的流水不改不删；收货短少、错发、盘点差异这类更正都以新流水表达。
- 守恒：同一计量粒度下，期末在库 = 期初 + 收货 + 退货入库 + 期初导入 + 已批准的盘盈与调增 − 出库确认 − 已批准的盘亏、调减与销毁。库内移动、状态转换与占用只改位置、分类与可用量，不改实物总量；形态转换折成基本单位守恒（ADR-0368 决定五）。
- 仓间调拨不另立对象：调出是调出仓的出库确认，调入是调入仓的收货，ADR-0368 决定五守恒式里的调出、调入即此。
- 库存只放在与状态相容的库区：存储与拣选库区只放良品，次品库区只放次品，收货暂存、退货暂存与待出库库区三种状态都可以放，待检只在这三种暂存库区。移入次品库区的库存在同一笔流水里转为次品；次品转回良品要一笔单独的状态转换，由有授权的运营决定作出。
- 入库批次只由收货、退货入库与期初导入形成，入库时间取入账那一刻（期初导入取声明的入库时间）；状态转换、库内移动与形态转换不另起入库批次。

### 占用、预占与分配

- 三种占用互不重叠，可用量直接相减；同一可用量不得被重复占用。
- 预占在库存账内原子判定，成功的预占合计不超过可用量；不足时按缺货处置办，不静默超卖（ADR-0368 决定五）。缺货处置没选时答未配置，请求停在待预占。
- 预占只落到（货主，仓，商品，库存状态，批号或效期条件），不落库位；分配在波次释放时把它落到库位与入库批次，分配合计不超过预占，顺序按租户采用的分配策略。分配策略没采用时答未配置，不分配。
- 预占在出库确认时消耗，在截单、拒绝或请求终结时释放；只释放属于这份出库请求、还没消耗的部分。
- 冻结只经解冻决定解除。作业锁定随盘点完成或作废解除；所涉库位上还有未完成的拣货任务时，盘点不能开始。
- 离线端不铸预占与分配：预占是计划，不是事实（ADR-0368 决定六）。

### 入库

- 入库预报不是库存；库存只因收货确认入账。
- 收货确认即以收货流水进入收货暂存库区，形成入库批次；上架是之后的库内移动。
- 收货差异逐商品记录并交货主确认；库存只按实收入账，差异的认定不回改实收。
- 商品首次收货时测仓测尺寸重量。还没测不阻断收货与上架，但依赖体积与重量的计量答未测量，不用货主声明的尺寸重量顶替。

### 出库

- 一份出库请求属于一个货主客户账户、从一个仓发出、带要求的服务产品。每个打包完成的包裹以（出库请求，包裹序号）为来源请求键、以来源「仓配出库」提交一份委托，与客户渠道交来的委托受同一套接受判断，不绕过任何接受规则（ADR-0368 决定四）。
- 声明测量取打包时称得的重量与尺寸；客户原始资料取出库请求的收件人与本单申报值，本单没给的申报格取商品申报资料。两处都没有的格照实空着：本上下文不补默认值，也不判归类与合规。
- 出库复核不符的不打包。
- 委托被拒绝或撤回的包裹不出库：拆包回库，或经运营决定换新的包裹序号重新打包提交；同一来源请求键不复用，原装箱记录照留。
- 只有委托已被接受的包裹才能出库确认。服务要求面单时，面单由小包托运的面单交易给出，本上下文只打印与粘贴，不改变它代表的交易。
- 库存在出库确认时按分配消耗，不等节点收寄，也不由节点收寄触发；出库确认与节点收寄是两件事实，谁也不替谁，同址时也如此（ADR-0368 决定四）。
- 出库确认之后，这件货的取消、去向与处置归 `parcel-shipment` 与网络各上下文，本上下文不再截单。
- 截单逐件判定：未分配的释放预占；已分配未拣的撤销分配并释放；已拣出的截单回库后释放；已提交委托的，先按小包托运的规则撤回或取消那份委托，成立后拆包回库，小包托运不放行时这一件截单不成立。截单回库与拆包回库都是库内移动，不是退货入库。
- 委托在打包之后提交。波次释放时先取面单、后拣货的形态首版不支持，要不要支持由实施切片按第一个场景定（ADR-0368 决定四）。
- 出库请求一律经委托进入小包链路。货主自带面单发出、货主自提这类不经本产品网络的出库不建模；要建，先另立 ADR 扩 ADR-0368 决定四。一份出库请求拆成几次发出（拆单发货）同样不建模。

### 盘点、差异与调整

- 盘点是静盘：开始时对所涉库位库存加作业锁定，结束时解除。
- 盘点结果与账的差额形成盘点差异；经批准形成盘盈或盘亏流水，未批准不改账。
- 盘点之外的调整同样带原因、经批准后入账。
- 离线拣出的件在账上不可用时照记拣货事实，差额形成库存差异交人处理，写口不拒（ADR-0368 决定六，与 [ADR-0251](../../adr/0251-directional-node-work-is-paused-outside-the-validity-interval-of-the-delivered-basis-and-recorded-moves-are-never-refused.md) 对已经发生的作业照记是同一立场）。
- 谁有权批准差异与调整、差异要在多久内处理，是租户取值；没登记答未配置，差异停在待处理，不自动调账。

### 退货

- 退件按退货预报或本上下文的装箱记录认出货主、原出库请求与商品；认不出的建待认领到货。
- 退货入库形成新的入库批次，库龄从退货入库起算；它不冲回原出库确认，原出库请求的结果不变。
- 回库处置逐件作出、逐件执行；未处置的货留在退货暂存库区，不可分配。

### 代理仓

- 代理仓库存声明不进库存账，不与自营仓库存相加成一个数。
- 声明过了有效期答「未知」；不对过期或缺失的声明预占，也不据它承诺（ADR-0368 决定五）。
- 怎样对代理仓下出库、FBA 的换标与入库计划、整箱不拆的箱库存，首版都不建模，按第一个场景定（ADR-0368 越权风险点 6）。

### 收费发生项

- 本上下文只登收费发生项，不带金额；对货主收多少由 `parcel-pricing` 按 `SELL` 价卡评价，`settlement-accounting` 采用为客户运营应收（ADR-0368 决定七）。计价为它立评价对象另立 ADR，在那之前小包计价的评价对象不含它。
- 各种类在作业事实发生时形成：入库在收货确认时按每次收货形成；出库在出库确认时按每个包裹形成；退货处理在退货入库与回库处置时形成；增值服务在服务完成时形成；销毁在销毁入账时形成。
- 仓租按（货主，仓，计费日）每日形成一份，带日终在库的计量：按入库批次给出数量、仓测体积、库存状态、库区用途与库龄天数，按库位给出占用的库位、库位类型与连续占用天数。库龄段、免租期、淡旺季与单价都在价卡里，不在这里。库龄口径没选时不形成仓租发生项，答未配置。
- 体积与重量类计量一律取仓测尺寸重量；未测的如实答未测量，不用货主声明的顶替。
- 同一作业事实至多形成一份发生项，重放答已有的那一份。发生项形成之后不改写；来源事实被更正时追加更正版本，指名被更正的那一份。

### 作业端

- 收货、上架、移库、补货、盘点、拣货、出库复核与打包进入一线作业客户端；离线与弱网容忍照 [ADR-0021](../../adr/0021-frontline-operations-client-is-part-of-the-product.md)，作业事实的身份与发生时间由设备签发（[ADR-0023](../../adr/0023-work-fact-identity-and-time-are-minted-by-the-device.md)），见 ADR-0368 决定六。

## Lifecycles

### 入库预报

- 货主经客户渠道提交 → 已预报：固定仓、到仓方式、预计到仓时间与商品明细。
- 已预报 → 收货中：第一次收货确认；一份预报可以分几次收货。
- 收货中 → 已完结：仓确认这份预报收货结束，没到的数量记为少收。
- 已预报 → 已取消：货主在第一次收货确认之前撤回；收货开始之后不能撤回，只能按收货差异了结。

### 收货与上架

- 到货清点 → 收货确认：按商品、计量单位与库存状态入账到收货暂存库区，形成入库批次，与预报比出收货差异。
- 收货暂存 → 已上架：移到存储、拣选或次品库位；可以分几次上架，没上架的部分留在收货暂存，可见但不可分配。
- 待认领到货 → 已认领：认给一个货主之后按收货入账；认不出的留在待认领，怎么处置归租户规则。

### 出库请求

- 货主经客户渠道提交 → 已受理：固定仓、商品明细、收件人与地址、服务产品与本单申报值。
- 已受理 → 已预占、部分预占、待预占或已拒绝：按可用量与缺货处置原子判定。待预占与部分预占的请求在可用量变化时再判。
- 已预占 → 已分配：波次释放时分配并生成拣货任务。
- 已分配 → 已拣货：拣货任务全部完成，实拣不符的差额形成库存差异。
- 已拣货 → 已打包：出库复核通过、逐包裹打包，每个包裹提交一份委托。
- 已打包 → 已出库：全部包裹出库确认，或其余包裹已截单回库。
- 截单成立 → 已取消（全部截回）或部分取消；已出库确认的包裹不受影响。
- 已拒绝、已取消与已出库都是终态。

### 装箱记录

- 打包 → 已打包：记包裹序号、商品与数量、包材与称得的重量尺寸。
- 已打包 → 委托已提交：以（出库请求，包裹序号）提交委托，记下小包托运的答复。
- 委托已提交 → 委托已接受，或委托未接受（被拒绝或撤回）。
- 委托已接受 → 已出库确认：库存按分配消耗。
- 委托未接受 → 已拆包回库，或换新的包裹序号重新打包；原装箱记录照留。
- 截单 → 委托撤回或取消成立后拆包回库。

### 盘点

- 创建 → 待盘点：固定所涉库位与商品，这时不锁定。
- 待盘点 → 盘点中：所涉库位上没有未完成的拣货任务时开始，加作业锁定。
- 盘点中 → 已盘点：录入清点结果，算出盘点差异，解除作业锁定。
- 已盘点 → 差异已批准（盘盈、盘亏流水入账）或差异已驳回（不改账）。
- 盘点中 → 已作废：解除作业锁定，不形成差异。

### 库存差异

- 形成 → 待处理：记来源（盘点、拣货、上架或出库复核）、所在的格与差额。
- 待处理 → 已批准：以盘盈、盘亏或调整流水入账；待处理 → 已驳回：不改账。

### 退货入库

- 到仓 → 已登记：按退货预报或装箱记录认货主，认不出的转待认领到货。
- 已登记 → 已清点：清点与质检结果以退货入库流水进入退货暂存库区，形成入库批次。
- 已清点 → 已处置：逐件回库处置，全部处置完即结束。

### 冻结

- 运营决定 → 已冻结：固定格、数量与原因。
- 已冻结 → 已解冻：解冻决定作出，数量回到可用量。

### 代理仓库存声明

- 收到 → 有效：带来源、声明时点与有效期。
- 有效 → 已过期：过了有效期，答「未知」。
- 有效或已过期 → 已被取代：同一来源对同一格报来更新的声明。

## Boundaries and ownership

- `warehouse-fulfillment` 拥有货主商品身份、商品别名、包装层级、仓测尺寸重量与货主声明的商品申报资料，仓、库区与库位，库存账与库存流水，占用与分配，入库预报、收货与收货差异、待认领到货、上架、库内移动与形态转换，出库请求、波次、拣货任务、出库复核、打包与装箱记录、出库确认与截单，盘点、库存差异与库存调整，退货预报、退货入库与回库处置，代理仓库存声明，以及仓储作业收费发生项。
- `party-commercial` 拥有货主客户账户、合同与服务产品；本上下文引用它们，不另立货主档案。
- `parcel-shipment` 拥有委托、包裹身份、面单交易与客户承诺；本上下文以货主名义提交委托、保存答复，不取得委托或包裹的所有权。委托提交之后，包裹的撤回、取消与处置按小包托运的规则办。
- `node-operations` 拥有节点收寄、作业位置、节点控制与集运单元；同址时出库确认与节点收寄各记各的，本上下文不读也不写节点作业的事实。
- `transport-fulfillment` 拥有揽收、运输交接、交付与退运旅程；退件交付到仓是它的交付，到仓之后的退货入库归本上下文。
- `customs-compliance` 拥有正式申报资料、归类与合规判断；本上下文只把货主声明的申报资料原样带进委托。仓配出库不是关务受门禁的“出库”动作；保税仓这类受监管的仓首版不建模。
- `parcel-pricing` 评价仓储作业收费发生项，`settlement-accounting` 形成费用与客户运营应收；本上下文不带金额，也不据它们改写发生项。
- `visibility-exception` 只投影事实所有者已接受的事实。仓内事实进不进客户全程追踪，等它定下采用口径再说，在那之前不直插投影。
- 跨上下文的提供与消费关系以 [CONTEXT-MAP「关系约束」](../CONTEXT-MAP.md#关系约束)为准。

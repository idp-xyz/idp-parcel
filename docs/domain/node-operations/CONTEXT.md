# 节点作业（`node-operations`）

Status: Confirmed

本上下文管理国际小包物流节点内已经发生的实物接收、控制、测量、分拣、集拆、封装、开封、暂存、装卸、点验和交接侧作业。它回答“节点实际看到了什么、控制了什么、放在哪里、做了什么”，但不拥有客户委托、正式包裹身份、路由计划、运输交接结论、监管决定、异常责任或结算结果。

节点作业是面向小包网络流转的场站作业模型，不是完整 WMS。包裹或集运单元的节点控制、作业位置和在场核对结果不等于商品库存、库存可用量、库存价值或库存调整。

本文件是 `node-operations` 语言、规则与生命周期的权威来源。跨上下文术语以[统一领域语言](../GLOSSARY.md)为准，所有权关系以[领域上下文地图](../CONTEXT-MAP.md)为准。

## Language

**作业实物**  
节点能够在现场区分并对其记录作业事实的物理对象。作业实物可以关联正式包裹、集运单元或可复用载具，也可以暂时无法识别。作业实物记录不是新的客户服务身份，不能替代 `parcel-shipment` 拥有的包裹身份。

**待识别实物**  
节点已经实际发现或取得控制，但尚不能可靠关联正式包裹或集运单元的作业实物。待识别实物具有永久作业记录；识别成功后通过版本化关联连接正式对象，不删除原记录，也不复制其已经发生的事实。

**实物控制**  
明确节点或运输履约范围当前对作业实物承担保管和后续作业责任，并有能力阻止未经授权处置的业务关系。实物控制不是所有权、库存所有权、客户责任或仅由位置推断的状态。

**节点收寄**  
客户或其授权交付方在物流节点直接交付作业实物，节点完成明确接收并取得控制的业务结果。节点收寄可以成为网络服务有效收寄的来源；客户提交、委托接受、到站扫描、卸载或发现实物本身都不等于节点收寄。

**节点侧交接证据**  
节点为运输交接形成的备货、点验、扫描、装载、卸载、交出或接收观察。节点侧交接证据可以支持 `transport-fulfillment` 形成跨节点与运输方的权威交接结果，但自身不等于该结果。

**作业位置**  
物流节点内部用于表达作业区、暂存区、工位、容器或其他实际放置关系的层级位置。当前位置依据有效位置和包含关系事实派生；作业位置不是 `network-routing` 拥有的物流节点，也不是 WMS 库位或库存账。

**作业任务**  
要求对明确对象、范围和作业依据执行节点动作的工作指令。作业任务独立于路由指令、作业批次和实际作业事实；任务完成只能由符合任务范围的有效事实派生，不能由按钮或计划时间单独认定。

**作业批次**  
为组织一组节点作业任务或实物而建立的临时逻辑归组。作业批次不取得成员身份、物理控制、集运成员关系或运输责任，也不等于提交批次、集运单元、舱单或班次。

**集运单元实例**  
在一次装入、封装、交接、运输、接收和拆出周期中，用于临时组合包裹或其他允许成员的可识别物理作业整体。实例拥有独立身份、成员历史和封签历史；同一实体载具的下一次使用必须创建新实例。

**可复用载具**  
可以跨多个使用周期重复使用的袋、笼、箱、托盘或其他物理设备身份。可复用载具与每次集运单元实例分离；载具身份连续不允许复用已关闭实例的成员、封签或控制历史。

**集运成员关系**  
明确作业实物在适用时间内直接位于某一集运单元中的物理包含关系。关系必须记录形成、变更和解除事实；同一对象在同一时点最多只有一个直接物理父级，全部层级不得形成循环。

**封装成员快照**  
集运单元封装时冻结的成员关系版本及作业依据。封装后改变实物成员必须先形成开封事实，再形成移入、移出和重新封装事实；重新封装创建新的快照，不覆盖原快照。

**封签记录**  
针对一次封装保存的封签标识、状态、施封依据和观察历史。封签证明力取决于连续且相符的封签证据；缺失、破损或不一致时，原成员快照只能作为待核对范围，不能证明成员已经逐件到站。

**实际测量**  
节点对明确作业实物在特定时间、位置和作业依据下取得的重量、尺寸、数量或其他物理测量事实。实际测量不可覆盖；当前有效实测依据有效性、对象范围和业务规则派生，客户或供应商计费重量由 `settlement-accounting` 另行形成。

**物理状况观察**  
节点对包装破损、渗漏、变形、封签状态或其他可观察状况形成的事实。观察描述当时看到什么，不直接认定损坏原因、责任方、赔付责任或监管结论。

**在场核对**  
针对节点当前预期控制、作业位置和集运成员关系，与实际扫描或清点事实进行的范围化核对。核对逐对象形成匹配、缺失、多出和位置差异，不生成库存可用量、库存价值或库存调整。

**节点作业限制**  
节点基于现场安全、实物状况或身份不确定性，对明确对象和动作形成的本地限制。节点作业限制不能改变客户合同、包裹身份、路由计划或监管结论，也不能替代其他来源的硬限制及其解除决定。

**受控开封**  
节点依据范围明确的当前有效授权，对已封闭包裹或集运单元执行开封、观察和重新封装的作业。授权来源拥有是否允许的决定，节点只拥有实际执行和证据事实。

**内部作业标签**  
仅用于节点识别、分拣、位置或作业控制的标签。内部作业标签不等于正式包裹标识、承运商面单、路由计划、运输凭证或监管标签。

## Rules and invariants

### 实物身份与事实完整性

- 无法可靠识别的到站实物必须建立待识别实物，不得冒充正式包裹、集运单元或库存项目。
- 待识别实物识别成功后保留原作业身份和全部事实，通过带有适用时间、依据和替代关系的关联连接正式对象；关联更正不能删除原观察和原判断。
- 同一外部条码出现在多个实物，或同一实物存在相互冲突的外部标识时，各作业实物继续独立，形成身份冲突并暂停方向性作业。现场人员不得以覆盖、合并或“最后一次扫描为准”决定正式包裹身份。
- `node-operations` 保存真实拆分、合并、重新包装及其来源实物、发生时间、位置和作业依据；`parcel-shipment` 据有效事实决定是否创建新包裹身份及身份谱系。节点不能自行创建或替换正式包裹身份。
- 已取消、已经终局或当前无有效路由的包裹仍然到站时，节点必须如实保存接收、控制和其他已发生事实；这些事实不自动重开服务、不恢复路由，也不撤销既有终局。
- 扫描、人工操作、设备测量和外部节点回传首先作为来源事实保存。重复、迟到、冲突、更正或有效性变化必须关联原事实和原判断，不能通过覆盖历史整理出单一结果。

### 接收、控制与交接

- 实物控制只因明确节点接收或权威运输交接的“已交接”结果形成、转移或结束；已拒收或待确认均保持此前已确认的控制关系。扫描、作业位置、装载、卸载和车辆到达不能单独转移控制权。
- 客户将实物直接交到节点时，`node-operations` 拥有节点收寄结果；上门揽收或其他场外交接由 `transport-fulfillment` 拥有。`parcel-shipment` 消费相应有效网络收寄结果形成责任起点和正式承诺判断。
- 节点与运输方之间的跨边界交接结果由 `transport-fulfillment` 唯一拥有。`node-operations` 只拥有备货、点验、装卸及节点侧交出或接收证据；双方必须引用同一交接范围，不共同编辑一个结果。
- 交接按明确对象逐一判断并允许部分成立。整批、整车或整单交接结果只能由成员结果派生，不能以一个总结果覆盖短少、多出、拒收或待确认对象。
- 封签连续且相符的封闭集运单元被有效接收后，可以形成单元控制及成员“随单元受控”的派生判断，但不能伪造成员逐件扫描或逐件实收。
- 封签缺失、破损或不一致时，可以如实接收并控制集运单元实物，同时记录状况和实施隔离；不得依据原封装成员快照推导成员已经到站或随单元受控。授权开封后按实物逐件形成匹配、缺失、多出、身份不明和位置差异。
- 自营和外包节点使用相同的接收、控制和交接语义。外部过程不可见时只保存可靠获得的边界事实和来源，不虚构合作方内部扫描、位置、任务或控制转换。

### 集运、封装与载具

- 集运成员关系按实际移入、移出和包含事实形成，不得由舱单、总单、作业批次、路由兼容判断或装载分配直接推定。
- 集运包含关系必须无循环；每个作业实物同一时点最多一个直接物理父级。嵌套集运时通过直接父级链路派生间接包含，不复制多条当前直属关系。
- 封装冻结当时成员快照。封装后的成员变化必须依次保留开封、成员变化和重新封装事实，并形成新封签记录；任何历史快照和封签都不得被新版本覆盖。
- 集运单元实例贯穿一次完整使用周期。授权开封、重新封装和换签可以发生在同一实例中；全部成员已经移出，或剩余成员已通过明确处置转移后，实例才能显式终局关闭。
- 已关闭集运单元实例永久终局，不得重开、清空后复用或承载新成员。可复用载具再次投入使用时创建新的集运单元实例并关联同一载具身份。
- 作业批次只用于组织工作，不能代替集运单元、成员关系、封装快照或交接范围。

### 作业授权与执行

- 作业任务必须引用明确对象、动作、节点、适用依据和范围。路由指令、运输卸载要求、监管限制或异常处置请求可以成为任务依据，但不等于任务已经完成。
- 任务完成、部分完成或未完成依据当前有效作业事实逐对象派生；任务取消、指令失效或重新下达不删除已经发生的事实。
- 当前路由指令无效、缺失或已经被替代时，节点仍可执行接收、隔离、状况记录、测量和其他必要安全作业；分拣到下一方向、集包出运、装载和交出等方向性作业必须暂停，直至取得有效依据。
- 节点可以对明确对象形成范围化本地安全限制，但只有限制来源责任方可以解除相应限制。节点限制不得扩大为客户合同、监管、渠道或整个委托范围的决定。
- 销毁、退回、监管移交、服务终止或其他处置决定与物理执行分离。节点只执行当前有效、范围明确的授权决定，并保存执行事实；不能凭异常案件、现场备注或操作权限自行形成处置决定。
- 对已封闭包裹执行受控开封，必须引用当前有效且范围明确的关务查验、安全检查、客户约定、异常处置或紧急安全权限。节点保存开封前状况、原封签、授权来源、执行人、时间、内容物观察、差异、重新封装和新封签事实，但不取得授权来源所拥有的决定权。
- 节点可以自行生成和更换内部作业标签。正式包裹标签、承运商面单、路由标签或监管标签只有在所属上下文形成有效指令后才能打印、粘贴、遮盖或移除；节点保存新旧标签观察和物理操作，不能自行改变标签代表的身份、交易、路由或监管含义。
- 物理装载和卸载是节点实际作业事实，不等于 `transport-fulfillment` 的装载分配、运输交接、出发或到达结果。

### 测量、位置、状况与核对

- 每次实际测量必须保留对象、测量项、结果、单位、发生时间、位置、来源和作业依据。更正或判定无效通过关联事实表达，不覆盖原结果。
- 当前有效实测按明确业务规则从仍有效的实际测量派生。客户声明、监管申报、客户计费重量和供应商计费重量均不得覆盖实际测量，节点也不形成最终计费重量。
- 作业实物的当前位置依据有效位置事实和当前集运包含层级派生。把包裹装入集运单元后不得同时维护一条相互冲突的独立当前位置；拆出后由新的位置事实形成当前位置。
- 作业位置只支撑网络场站内的查找、暂存和作业，不建设商品库存、批次库存、库存所有权、可用量、库存价值、补货、拣货波次或库存调整。
- 在场核对的预期范围来自当前控制、作业位置和集运成员关系，实际范围来自扫描或清点事实。匹配、缺失、多出和位置差异不能直接覆盖控制、位置或成员历史；需要调查和责任处理时由 `visibility-exception` 建立案件。
- 物理状况观察只表达可见事实。损坏原因、责任归属、索赔和赔付结论分别由拥有相应判断的上下文形成，节点不得把观察直接升级为责任结论。

## Lifecycles

### 待识别实物与身份关联

- 发现无法可靠识别的实物 → 建立待识别实物，保存发现、位置、状况和适用控制事实。
- 获得候选标识 → 保存候选关联和依据；候选尚未确认时不得据此执行方向性作业。
- `parcel-shipment` 确认正式身份 → 建立带适用时间的版本化关联；待识别实物记录和既有事实继续保留。
- 原关联被更正或出现标识冲突 → 保留原关联判断，形成替代或失效关系并重新派生当前关联，不删除实物历史。

### 节点控制

- 尚未控制 → 节点控制成立：客户直接送站形成有效节点收寄，或 `transport-fulfillment` 的权威交接结果确认控制已经转入节点。
- 节点控制期间：位置、测量、分拣、集拆、封装和其他作业分别形成事实；任何单项事实都不重新定义控制起点。
- 节点控制 → 控制转出：`transport-fulfillment` 针对明确对象形成权威运输交接的“已交接”结果；已拒收或待确认不转出控制，备货、装载或节点侧交出扫描本身也不结束控制。
- 部分交接时，各对象分别结束或保留节点控制；批次、集运单元或车辆范围不形成一刀切的控制结果。

### 集运单元实例

- 创建实例 → 开放装入：实例关联可复用载具（如有），成员按实际移入事实形成。
- 开放装入 → 已封装：冻结成员快照并形成封签记录。
- 已封装 → 授权开封：保存原封签状态，允许逐件核对或成员变化。
- 授权开封 → 重新封装：形成新的成员快照和封签记录；原快照、原封签和变更过程继续保留。
- 成员全部移出或剩余成员已有明确处置 → 显式终局关闭；关闭后不得恢复开放或接受新成员。
- 封签异常只改变证明力并触发隔离、开封和核对，不自动关闭实例，也不把原成员快照变成实际到站清单。

### 作业任务与事实

- 形成任务：固定对象、动作、范围和当时适用依据。
- 执行作业：逐对象保存来源事实，经校验后形成有效作业事件。
- 任务结果：依据当前有效事件派生完成、部分完成或未完成；迟到事实、更正和有效性变化可以形成新判断版本。
- 任务失效、取消或被替代时，停止尚未执行的授权范围；已经发生的作业事实和原任务依据永久保留。

### 当前有效实测和当前位置

- 新测量或位置观察形成来源事实，不直接覆盖当前结果。
- 来源事实被接受、冲突、失效或更正时，按适用规则重新派生当前有效实测或当前位置。
- 每次派生结果必须能够追溯其事实依据；历史测量、位置和原派生判断均不删除。

## Boundaries and ownership

- `node-operations` 拥有节点收寄、待识别实物、节点内实物控制与位置关系、作业任务与批次、扫描、测量、状况观察、分拣、集拆、封装、开封、重封、内部作业标签、装卸、在场核对和节点侧交接证据。
- `node-operations` 拥有集运单元实例、可复用载具作业引用、集运成员关系、封装成员快照、封签记录及实例终局；不拥有总单、舱单、班次或运输资源。
- `party-commercial` 拥有节点经营参与方、责任法人、合作伙伴、合同和授权规则的身份及版本；节点事实引用实际责任法人、合作伙伴和授权依据，但不修改商业关系。
- `parcel-shipment` 拥有委托、正式包裹身份、身份谱系、外部标识业务关联、客户资料和服务结果；节点提供收寄和真实物理拆合事实，不自行改变这些对象。
- `network-routing` 拥有物流节点网络身份、路由计划、集运兼容判断和路由指令；节点拥有指令执行事实。无有效路由时可以继续安全作业，但不能执行没有方向依据的后续分拣、集包出运或装载。
- `transport-fulfillment` 拥有场外揽收、班次、装载分配、运输资源、节点与运输方的权威交接结果、实际移动、出发和到达；节点拥有物理装卸、点验及节点侧证据，双方不得共同编辑同一结果。
- `customs-compliance` 拥有监管查验授权、关务限制、放行和监管处置决定；节点只保存依授权完成的开封、查验协作、隔离、重封和移交执行事实。
- `visibility-exception` 拥有异常信号、异常案件、损坏原因和责任判断；节点只提供扫描、差异、状况和处置执行等来源事实。
- `settlement-accounting` 拥有客户计费重量、供应商计费重量、费用和成本分摊结果；节点只提供不可覆盖的实际测量和作业成本依据。
- 完整 WMS 能力不属于本上下文。需要商品库存、可用量、库存价值、补货、仓储拣选或库存调整时，必须通过明确边界协作或新的领域决策处理，不能扩充节点字段隐式吸收。

# 参与方与商业（`party-commercial`）

Status: Confirmed

本上下文管理国际小包业务中的参与方身份、商业关系、客户账户、服务产品、客户合同、供应商商业协议、销售与采购价格规则、渠道产品关系和渠道账号使用授权。它向交易和结算上下文提供在明确时间有效的商业依据，但不拥有客户委托、面单交易、实际履约或结算结果。本文件是 `party-commercial` 语言、规则与生命周期的权威来源。

跨上下文术语以[统一领域语言](../GLOSSARY.md)为准；本上下文在[领域上下文地图](../CONTEXT-MAP.md)中的所有权不得由实现方式改变。

## Language

**业务参与方**  
参与国际小包商业关系或履约关系的企业、组织或个人，具有稳定身份，但不因一次交易角色而被永久定义为货主、代理商或承运商。同一参与方可以在不同交易中承担不同角色。

**货主客户账户**  
运营集团租户内面向一个货主客户建立的业务隔离与商业关系边界。它不是运营法人、经营组织或登录用户；集团、法人和客户账户的三级边界遵循 [ADR-0003](../../adr/0003-group-tenant-legal-entity-customer-account.md)。

**服务产品**  
运营企业面向货主客户定义和销售的国际小包服务。服务产品表达运营企业对外提供的能力、适用条件和责任，不等同于外部渠道提供的产品。

**网络服务产品**  
由运营企业组织自己的集货、节点、干线、关务和尾程网络履约的服务产品形态。“网络产品”是它的简称，不建立独立于服务产品的第三套产品目录。

**面单渠道服务**  
运营企业面向客户提供渠道下单、面单取得以及适用查询、渠道作废或渠道退款协助，但不默认组织实物网络履约的服务形态。它可以由服务产品对外销售，但不等同于外部渠道服务方提供的渠道产品，也不虚构运营企业已经收寄包裹。

**面单服务终局规则**  
服务产品版本和客户合同版本对面单渠道服务终局边界、取消权结束条件、适用结果以及关闭或重开继续尝试所需授权作出的商业定义。规则必须明确授权角色、适用范围、关闭责任来源和硬限制前置条件。渠道确认受理、面单文件返回和正式承诺生效不默认等于服务终局；本规则不代替针对具体包裹形成的继续尝试决定。

**服务产品版本**  
服务产品在一次明确发布中形成、具有独立身份和适用范围的商业定义版本。

**渠道产品**  
由承运商直营渠道、承运商代理商、转售商或聚合平台等渠道服务方提供的可采购或可调用服务。渠道产品不等同于运营企业服务产品、实际承运商或一次具体面单交易。

**产品—渠道映射**  
服务产品版本与一个或多个可用渠道产品之间，带有适用条件和有效期的版本化商业关系。映射定义候选范围，不代表某次交易已经选择或使用了其中一个渠道产品。

**客户合同版本**  
运营企业责任法人与明确货主客户账户在一个适用期间内接受的商务和服务条件。客户合同独立于服务产品版本演进；服务产品发布新版本不会自动修改既有客户合同。

**客户服务规则版本**  
服务产品或客户合同在明确期间内采用的追踪披露、异常响应、客户更新、通知义务、索赔期限和最低材料等服务规则。它表达可复用的商业责任和差异化条件，不拥有具体追踪投影、异常信号、案件、通知或索赔结论。

**供应商商业协议版本**  
运营企业责任法人与明确供应商、代理商或其他服务提供方在一个适用期间内接受的采购服务、价格、结算和责任条件。它不等于一次实际运输委托、订舱、履约事实或供应商账单。

**价格规则版本**  
在明确适用范围和期间内形成销售价格、采购价格或法人间结算价格的商业规则。价格规则只定义如何计价，实际采用版本、计价输入和金额结果由交易快照及 `settlement-accounting` 分别保存。

**结算政策**  
商业协议对结算币种、收付方向、预付或账期方式、对账周期、付款条件、信用约束、税务处理依据和允许归集范围作出的版本化约定。它为结算账户提供商业依据，但不拥有运营余额、对账单或核销结果。

**渠道约束**  
客户合同或客户明确授权对可用渠道范围作出的限制。渠道约束可以保留运营企业在允许范围内的选择权，也可以指定一个渠道产品；指定渠道产品时，该次适用选择被锁定。

**渠道账号使用授权**  
渠道账号持有人允许运营企业在明确范围和期限内使用该账号开展业务的授权。授权必须显式、可撤销并可追溯；取得账号凭据不等于取得业务使用授权。

## Rules and invariants

- 服务产品、服务产品版本、渠道产品、产品—渠道映射和客户合同版本是不同业务对象，不能使用一个“产品配置”同时替代其身份与生命周期。
- 一个服务产品版本可以映射一个或多个渠道产品；运营企业对客户销售服务产品时，不得因此把某个渠道产品永久写成该服务产品的唯一实现。
- 网络服务产品是服务产品的一种服务形态，不是与服务产品、渠道产品并列的第三类产品对象。
- 网络服务产品与面单渠道服务必须分别表达服务责任。网络服务以有效网络收寄结果及适用资格校验作为责任起点；面单渠道服务不虚构运营企业收寄，其责任来源于面单交易绑定的账号和合同，运输观察从实际承运商收寄事实开始。
- 面单服务终局规则必须显式定义正常终局边界和取消权结束条件。允许实际承运商收寄前取消的产品，不得把更早发生的渠道受理或面单返回定义为不可回退终局。
- 首个面单渠道服务产品采用跨同一包裹全部相关面单交易的默认终局规则。除已经形成的有效取消结果外，实际承运商首次有效收寄即形成终局；否则必须同时满足：该包裹当前受控关闭已经生效且未被重开，全部相关面单交易均已定案，并且不存在任何有效或结果待确认的面单结果。此时才可依据明确失败、成功作废或接受时固定规则下的不可逆失效形成终局。客户合同需要改变该默认规则时必须形成明确、版本化且不与取消权冲突的条件。
- 面单服务终局规则必须定义哪些业务角色在什么条件和依据下可以关闭或重开继续尝试，以及授权的适用范围和有效期间；每项关闭或重开决定都必须由已授权业务角色明确形成，系统不得仅依据客观条件、复核时间、提醒或暂时没有下一笔交易自动形成关闭或重开。授权规则没有明确或只是暂时没有下一笔交易时，不得据此推断受控关闭或包裹终局；包裹终局仍由已确认的终局规则和有效事实派生。
- 请求方、实际决定方和关闭责任来源必须分别表达并记录。关闭权限与重开权限必须分开表达：授权运营角色可以形成关闭，重开必须由同级或更高授权角色形成，带原因并关联原关闭决定；“同级或更高”指版本化授权规则中的重开权限等级，不是人事职级。因货主指令形成的关闭，重开必须有同一货主账户新的有效授权；因运营企业操作形成的关闭，按适用的同级或更高重开权限规则处理。渠道服务方和代理商不能仅凭渠道角色直接重开。
- 监管、禁限运、安全暂停、渠道账号撤销或到期等硬限制由其来源责任方拥有解除权。限制属于原关闭责任来源或明确覆盖拟重开的完整面单服务范围时，商业授权只能在解除有效后支持新的重开决定；只覆盖单一渠道的限制不阻止包裹级重开，但继续禁止该渠道的新选择或新使用。业务角色不能绕过仍适用的限制或以重开代替限制解除，解除本身也不自动重开。
- 受控关闭不因预计复核时间到达或授权规则后来到期自动恢复；预计复核时间只形成提醒、待办或升级。单个渠道停用、账号失效、映射到期和渠道产品不可用只影响对应渠道范围的新选择或新使用，不自动形成包裹级受控关闭；渠道范围恢复只恢复候选资格，也不自动重开已经受控关闭的包裹。
- 受控关闭不等于取消、渠道作废、渠道退款或终局，也不得要求既有面单交易全部定案后才能生效；它只授权 `parcel-shipment` 阻止权威业务截断边界后的新重试、替代和换单。既有面单交易的查询、确认、渠道作废、渠道退款和定案不受该关闭阻断。
- 重开授权只适用于当前不存在有效终局服务结果的原服务范围，并只允许面向未来形成新的面单交易；它不能删除原关闭历史、复活旧交易或追溯认可关闭期间违反规则形成的交易。当前有效终局存在期间的新服务需求不属于原服务重开。
- 产品—渠道映射按有效期版本化。新增、调整、到期或替代映射不得覆盖历史映射，也不得追溯改变已经形成的委托、渠道选择或面单交易。
- 客户合同、供应商商业协议与服务产品分别版本化。新服务产品版本不自动修改既有客户合同或供应商协议；任何一方采用新条件时必须形成明确的协议版本依据。
- 客户服务规则必须按服务产品和客户合同明确适用范围、有效期间及责任方。追踪披露、异常响应、通知义务、索赔期限和最低材料可以具有客户差异，但不得把内部异常检测阈值、事实有效性或最终赔付金额写成客户可以直接覆盖的商业配置。
- 客户服务规则版本变化只影响其声明生效范围内的新判断。`visibility-exception` 保存具体案件、通知和索赔实际采用的规则依据；后续商业变化不得覆盖已经形成的响应目标、披露决定、通知内容或索赔资格历史。
- 销售价格规则、采购价格规则和法人间结算价格规则分别表达。一个方向的价格变化不得改写另一方向，也不得把实际供应商账单金额反向写成采购价格规则。
- 供应商商业协议定义可复用的采购条件、价格和结算责任；`transport-fulfillment` 保存实际运输委托采用的协议与履约条件快照，`settlement-accounting` 形成供应商预期成本、账单匹配和审核应付。
- 结算政策必须明确允许哪些合同版本归入同一结算账户。不同责任法人、相对方、收付方向或币种不得通过宽泛的客户或供应商关系自动归集。
- 商业价格规则必须声明含税、未税或税务不适用，并引用适用税务分类；法定税码、税率、税额和发票结果仍由财税系统拥有。
- 信用政策和人工费用调整授权按责任法人、业务角色、费用类型、金额或比例形成版本。政策只提供业务判断依据，不直接修改结算余额或形成调整金额。
- 已发布的服务产品版本不得原地覆盖。后续修改通过新版本表达，旧版本继续作为历史委托和交易的商业依据。
- 对网络服务产品，客户可以通过渠道约束限定允许范围，运营企业只能在该范围内选择；客户指定明确渠道产品时，具体交易不得静默改用其他渠道产品。
- 指定渠道产品形成的锁定优先于一般性的预先服务替换授权。只有客户针对该锁定另有明确变更授权时，才能形成显式渠道变更；监管或安全暂停只能阻断并进入显式处置，不能静默回退到其他渠道。
- 渠道产品锁定只固定该次交易采用的渠道产品，不据此锁定底层承运商或实际承运商；后两者仍分别以渠道明确结果和履约事实确定。
- `party-commercial` 决定可复用的渠道候选范围、合同约束和授权是否有效，但不把候选关系伪装成实际选择。委托级约束快照、具体渠道选择和锁定结果由拥有该交易的上下文记录并固定。
- 使用客户自有渠道账号前，必须存在对明确账号、授权双方、适用范围和有效期均可识别的有效授权。技术上能够访问账号不能替代该授权。
- 渠道账号使用授权被撤销或到期后，不得据此发起新的业务使用；已经接受的委托不因此自动关闭或取消，但其后续新交易必须重新取得当前有效授权。已经形成的交易仍保留当时有效的授权依据，不得删除或改写历史。
- 委托被接受时固定其适用的服务产品版本、客户合同版本、面单服务终局规则及关闭或重开授权规则、产品—渠道映射和渠道账号使用授权；某项依据对该服务形态确实不适用时，必须显式记录“不适用”及原因，不能以缺失代替判断。后续发生渠道选择、面单交易或继续尝试决定时，再固定该次决定实际使用的映射和授权依据，并保留它们与委托接受时快照的关系。
- 商业快照只证明历史决定当时所依据的产品、合同、映射和授权，不构成未来关闭、重开或新交易的永久执行许可。形成具体关闭或重开决定时，都必须重新校验实际决定方的当前角色授权和适用客户授权；形成关闭决定时记录当前硬限制及其适用范围，限制存在本身不禁止形成关闭；形成重开决定时还必须确认原关闭责任来源对应或覆盖完整面单服务范围的限制已经解除。形成新交易时必须独立校验当前渠道产品、映射和渠道账号的新使用资格。
- 服务产品版本退役只停止其参与新的商业选择，不终止已经接受的委托，也不改写既有交易。因监管、安全或其他硬约束产生的暂停必须单独记录依据和适用范围，不能用产品退役代替。
- 渠道产品停止商业可用或相关映射到期，只将其排除在新的渠道选择之外，不删除历史依据，也不自动关闭包裹。已经接受的委托若锁定该渠道产品但尚未形成交易，不得静默替换；必须依据针对该锁定的明确变更授权或进入显式处置。渠道产品或映射恢复可用只恢复候选资格，不自动重开包裹。
- 渠道账号持有人、渠道服务方、合同与结算相对方、底层承运商、实际承运商和责任承担方必须分别表达；承运商代理商是业务关系和交易角色，不是永久企业类型。
- 使用客户自有账号不会自动形成运营企业自己的渠道采购、渠道退款权利或供应商审核应付；相关责任必须来自明确合同，实际金额结果由 `settlement-accounting` 形成。

## Lifecycles

### 服务产品版本

- 草稿 → 已发布：商业定义完成并被批准用于新的适用业务。
- 已发布 → 已退役：自退役生效时间起不再供新的商业选择，但已经接受的委托继续引用原版本。
- 已发布版本内容需要变化时，创建新的草稿并发布为新版本，不修改原版本。
- 面单服务终局边界、取消权条件或关闭与重开授权条件发生变化时必须形成新的服务产品或客户合同版本，不得追溯改变已接受委托的适用规则或具体决定。
- 监管或安全暂停与草稿、发布、退役生命周期正交。暂停是否影响既有业务取决于其明确依据和适用范围，不得从“退役”状态推断。

### 产品—渠道映射

- 映射在其明确有效期和适用条件内参与新的渠道决策。
- 映射发生变化时形成新版本；旧版本到期或被新版本替代后仍作为历史决策依据保留。
- 已经固定到委托或交易的映射依据不因后续映射变化而重新求值。

### 客户合同版本

- 商务或服务条件发生变化时形成新的客户合同版本，不覆盖原版本。
- 每个合同版本只在其明确适用期内用于接受新的委托或形成新的商业决定。
- 合同版本到期或被后续版本替代，不改变已经接受委托所保存的合同依据。

### 客户服务规则版本

- 草稿 → 已发布：固定追踪披露、异常响应、客户更新、通知和索赔条件及其适用范围。
- 已发布 → 已生效：由服务产品或客户合同在明确期间引用；具体业务保存实际采用依据。
- 已生效 → 已到期或已替代：停止用于新的判断，既有案件、通知和索赔历史继续引用原版本。

### 供应商商业协议版本

- 供应商商业协议在批准生效后，才能用于新的采购决定和供应商预期成本计算。
- 采购服务、价格、结算或责任条件变化时形成新版本，不覆盖原版本。
- 协议版本到期、终止或被替代后，不改变已经形成的运输委托、履约事实、供应商账单主张或审核应付依据。

### 渠道账号使用授权

- 授权建立时必须记录授权双方、账号、适用范围和有效期；只有在有效范围与期间内才能用于新的业务决定。
- 授权可以在到期前被显式撤销；撤销和自然到期均终止后续新使用，但不删除已经形成的授权证据和交易快照。

## Boundaries and ownership

- `party-commercial` 拥有业务参与方身份、参与方关系、运营集团与法人、货主客户账户以及客户和供应商商业关系。
- `party-commercial` 拥有服务产品及其版本、面单服务终局规则、运营企业责任法人的授权治理、版本化角色权限等级、合同委派、关闭责任来源规则、关闭与重开的条件和硬限制适用规则及其依据版本、渠道产品目录身份与商业适用性、产品—渠道映射、可复用渠道约束、客户合同版本、供应商商业协议版本、渠道账号持有人关系和渠道账号使用授权；它不拥有具体包裹的关闭或重开请求、决定及其证据。
- `party-commercial` 拥有销售价格规则、采购价格规则、法人间结算价格规则、结算政策、税务分类依据、信用政策和人工调整授权规则的商业版本，但不拥有依据这些规则形成的实际计价、余额、对账或核销结果。
- `parcel-shipment` 拥有客户委托、包裹、包裹级面单继续尝试决定、委托级服务责任与渠道约束快照、面单交易、具体渠道选择和锁定结果，并保存所引用的产品、合同、映射、授权及交易角色快照；它不能修改这些商业对象的版本生命周期。
- `network-routing` 只消费已经确定的服务要求和适用约束形成路由计划，不拥有服务产品—渠道产品的商业映射。
- `transport-fulfillment` 拥有外部运输委托、承运接受、实际采用的供应商协议与履约条件快照、成本来源依据，以及实际承运商和收寄、交接、运输、交付事实；它不拥有供应商商业协议和采购价格规则的版本生命周期。
- `customs-compliance` 按关务案件和提交版本形成具体货物相关主体、进出口责任主体、申报人、报关服务商、申报渠道账号持有人、税费法定义务人、实际付款方和运营责任法人的角色与资格快照；`party-commercial` 只提供参与方与法人身份、报关服务商关系、委派和渠道账号使用授权，不拥有具体关务判断或监管结果。
- `visibility-exception` 拥有追踪投影、异常信号和案件、响应目标、客户披露及通知决定、客户索赔项和追偿事项；`party-commercial` 只拥有服务产品、客户合同及客户服务规则版本，不能直接形成或修改这些实际业务结果。
- `settlement-accounting` 拥有运营应收、供应商预期成本、账单匹配、审核应付、客户费用退款、供应商费用贷项、成本、结算账户、运营余额和经营指标；它引用商业协议与责任依据，但不能回写客户合同、供应商协议、价格规则、渠道关系或交易快照。
- `customs-compliance` 及其他适用责任方拥有监管或硬限制的来源决定；`party-commercial` 可以据此限制产品或渠道的商业可用性，但不能取得监管决定所有权。
- 渠道账号凭据和渠道接入的技术实现不属于本领域文档的决策范围；任何实现都不得把凭据等同于业务授权。

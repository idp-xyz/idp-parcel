# UC-PC-002 按范围与时点解析商业依据

状态：稳定业务骨架待实现；真实商业选择锚点策略、对象版本和新鲜度参数待提供

## 目标与边界

本用例从消费方提交明确租户、货主客户账户、责任法人候选、服务/费用或控制范围和商业选择锚点开始，到 `party-commercial` 返回唯一适用的参与方关系、服务产品、合同、接单规则包、结算政策、商业价格政策、价格方向和定价方案绑定，或者返回无适用依据、适用冲突、解析未决或输入未受理为止。

解析采用两阶段机制。第一阶段使用独立于候选接单规则包的商业选择锚点，唯一选出商业基线；第二阶段才由已选规则包声明各下游判断的 `asOf` 策略，消费方形成逐项时点并由相应权威上下文校验回显。这样避免让规则包决定其自身的选择时间。

本用例包含：

- 校验租户、客户账户、责任法人、服务范围和商业选择锚点的来源与策略版本。
- 唯一解析参与方关系、服务产品、客户合同、接单规则包、结算政策、财务控制、商业价格政策、价格方向、定价方案绑定及其他必需政策；同一客户的不同非重叠范围可以解析到不同结算方式或价格方向。
- 返回解析标识、判断时间、选择锚点、对象版本、有效区间、当前修订标识和依赖闭包。
- 区分零匹配、多匹配、权威依赖不可用、重复、结果过期和提交前失效。

本用例不执行：

- 形成委托接受/拒绝、可达性、财务控制、计价、渠道选择或履约决定。
- 根据客户回填时间恢复已失效合同、产品、关系、授权或信用资格。
- 在多个候选中按最高版本、更新时间、数据库顺序或人工偏好任选一条。
- 将无适用依据、适用冲突或依赖失败统一返回为“客户不合格”。

## 两阶段解析契约

| 阶段 | 输入 | 输出 | 失败边界 |
|---|---|---|---|
| 第一阶段：选择商业基线 | 租户、客户账户、责任法人候选、服务/费用范围、计算目的、独立商业选择锚点及其策略版本 | 唯一参与方关系、产品、合同、接单规则包、结算政策、财务策略、商业价格政策、价格方向、定价方案绑定和其他必需商业版本 | 锚点缺失/非法、零匹配、多匹配、引用冲突或权威未决 |
| 第二阶段：形成逐项 `asOf` | 第一阶段选出的规则包、当前提交版本和各判断类型 | 各判断的 `asOf` 语义和值及策略版本 | 未配置、值不合法、规则包失效或消费方无法形成值 |
| 权威校验与回显 | 逐项 `asOf`、对象范围和规则引用 | 各上下文自己的判断标识、判断时间、采用版本、有效区间和当前修订 | 结果过期、范围不符、依赖失败或来源冲突 |

商业选择锚点的真实语义由独立、版本化的首发策略确定，并登记在 `PAR-COM-14`。未确认前必须保持显式未配置；不得临时选用来源发生时间、客户请求时间、系统当前时间或待选规则包作为默认锚点。

## 解析结果语义

| 结果 | 业务含义 | 消费方动作 |
|---|---|---|
| 唯一已解析 | 每项必需商业依据恰有一个适用版本，引用闭包完整 | 保存解析引用与快照，继续各自业务判断 |
| 无适用依据 | 权威商业版本证明当前范围没有适用对象 | 由消费方按自身规则判断拒绝、未受理或其他结果；PC 不代替决定 |
| 适用冲突 | 一个必需依据有多个候选或引用组合不相容 | 阻断依赖该依据的新决定，交商业责任方修正 |
| 解析未决 | 权威来源、当前修订或必要依赖暂时不可确定 | 保存缺口并安全续办，不默认通过/拒绝 |
| 输入未受理 | 最小租户、客户、范围或锚点身份无法建立 | 不查询或泄露候选商业对象 |
| 依据未解析 | 消费方回指的解析标识不指向一份它可用的原解析 | 回第一阶段重新解析；不重试同一次调用 |
| 已失效 | 原解析引用在消费方提交决定前已被新修订推翻 | 重新解析；不能继续使用或覆盖原历史 |

第二、三阶段按解析标识回指既有解析时，取回失败的结果按消费方的**恢复动作**分格，不按 PC 观察到的失败原因分格：读取本身没完成形成`解析未决`，「该标识从未签发」与「它属于另一个客户账户」一律形成`依据未解析`。两者对调用方是同一件事，分开会让一串标识挨个问就能枚举同租户下其他客户账户的解析。`输入未受理`仍只用于查询发生之前就无法建立身份或标识的那一支。依据见 [ADR-0029](../../adr/0029-retrieval-failure-algebra-is-partitioned-by-recovery-action.md)。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---:|---|---|---|
| 1 | 消费方 | 提供显式范围和由独立策略形成的商业选择锚点 | 锚点策略未配置时停止在输入边界 |
| 2 | `party-commercial` | 校验租户、客户账户、责任法人候选和访问范围 | 不泄露其他客户/租户候选 |
| 3 | `party-commercial` | 按锚点解析参与方关系、服务产品和合同 | 零个/多个候选分别返回无依据/冲突 |
| 4 | `party-commercial` | 解析合同引用的接单规则包、结算政策、财务策略、商业价格政策、价格方向和定价方案绑定；结算/价格依据按金额、费用或控制范围判断唯一适用性 | 引用闭包不完整时未决或冲突 |
| 5 | `party-commercial` | 固定解析标识、判断时间、锚点、版本、有效区间和当前修订 | 返回不可覆盖解析结果 |
| 6 | 消费方 | 依据已选规则包为每类下游判断形成 `asOf` 语义和值 | 不使用一个全局时间代替 |
| 7 | 各权威上下文 | 校验逐项时点并形成自己的判断与回显 | 不把 PC 解析当作业务结果 |
| 8 | 消费方 / `party-commercial` | 业务决定提交前校验解析和关键结果仍相容 | 失效则重解，无法重解保持未决 |

## 一致性、缓存与并发

- 解析键至少包含租户、客户账户、责任法人候选、服务范围、商业选择锚点及适用对象类型；请求结算依据时还必须包含能够区分合同、服务/费用或控制范围的业务维度。缓存不得省略这些维度，也不得缓存一个客户级预付/账期默认值。
- 请求计价依据时，解析键还必须包含计算目的和价格方向；同一范围的 BUY、SELL 与 INTERNAL 解析和缓存不能互相复用。
- 当前修订标识只用于检测权威视图变化，不代替对象版本。相同解析输入与相同修订可以返回原结果；新修订必须重新检查是否仍相容。
- 发布、退役、撤销、替代和解析并发时，已提交的历史业务决定保留原快照；尚未提交的新决定必须使用当前有效解析或保持未决。
- 依赖调用超时与权威确认“无适用依据”是不同结果。缓存过期、读取失败或修订无法确认只能形成解析未决。
- 解析成功不授予未来永久许可。关闭、重开、新交易、费用或履约决定仍按其业务时点重新校验当前所需授权和限制。

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-PC-017` | 锚点、产品、合同和规则包唯一适用 | 返回完整解析、版本、区间和修订标识 |
| `AT-PC-018` | 商业选择锚点策略未配置 | 解析未决，不选系统当前时间默认 |
| `AT-PC-019` | 客户回填早期业务时间试图使用已失效合同 | 不恢复旧资格，仍按独立选择锚点解析 |
| `AT-PC-020` | 同一范围没有适用合同 | 返回无适用依据，不由 PC 形成委托拒绝 |
| `AT-PC-021` | 同一范围两个合同同时命中 | 返回适用冲突，不任选最高版本 |
| `AT-PC-022` | 合同唯一但引用规则包未发布 | 返回解析未决，不默认规则通过 |
| `AT-PC-023` | 规则包选出后为网络与财务声明不同 `asOf` | 分别形成并校验，不压成全局时间 |
| `AT-PC-024` | 相同输入和修订重复解析 | 返回原解析语义，不产生新商业版本 |
| `AT-PC-025` | 解析后合同退役，但委托接受已提交 | 历史决定保留原快照，不追溯改写 |
| `AT-PC-026` | 解析后合同被当前修订替代，接受尚未提交 | 原解析失效并重解；无法重解保持未决 |
| `AT-PC-027` | 权威读取超时 | 返回解析未决，不冒充无适用依据 |
| `AT-PC-028` | 其他客户账户探测合同 | 范围拒绝且不泄露候选；按标识回指时，答案必须与探测一个从未签发的标识**完全一致**，仅拒绝不足以满足本项 |
| `AT-PC-029` | 解析成功但接受前可达性失败 | PC 结果保持商业解析，接受决定由 PS 形成 |
| `AT-PC-030` | 请求独立面单渠道服务 | 按已发布的面单渠道服务产品版本与客户合同解析商业依据，与网络服务同一两阶段机制；无适用产品或合同时返回无适用依据，不因服务形态另设答案，也不把网络服务产品当作面单渠道服务的候选（`PAR-COM-12`） |
| `AT-PC-031` | 同一货主的预付范围与账期范围由合同、费用范围和有效期间明确区分 | 分别返回各自唯一结算政策；不把客户标成一个全局模式，也不把两个范围合并 |
| `AT-PC-032` | 同一金额或接受前控制范围同时命中预付与账期政策 | 返回适用冲突并阻断依赖该依据的新决定；不任选一种模式或套用客户默认值 |
| `AT-PC-035` | 同一客户范围分别请求 SELL 计费和 BUY 成本 | 返回各自独立的商业政策、方向和定价方案绑定，不复用另一方向结果 |
| `AT-PC-036` | 合同和价格政策唯一，但绑定价卡版本已退役且无替代 | 返回解析未决或无适用依据，不选择最新价卡兜底 |

## 给开发的交接

消费者端口必须返回结构化的唯一成功、无适用依据、适用冲突、解析未决、输入未受理、依据未解析和已失效结果，不能只返回对象或通用错误。第一阶段解析与第二阶段逐项 `asOf` 必须在类型和测试中可见；结算政策结果必须携带解析得到的预付/账期方式和明确适用范围，调用方不得预选方式，也不能退化成客户布尔字段。当前实现闸门未解除前不得建立伪造的生产商业数据适配器。

隔离 `S` 的当前开发契约见 [`PN02-S01`](../../design/pn-02-synthetic-commercial-and-financial-control-development-handoff.md) 和 [`commercial_resolution_contract_test.go`](../../../internal/partycommercial/domain/commercial_resolution_contract_test.go)。该测试只验证结果代数、两阶段顺序和提交前失效，不代表生产解析端口已经准入。

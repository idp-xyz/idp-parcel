# UC-PC-001 维护并发布商业权威依据

状态：稳定业务骨架待实现；真实主数据来源、批准角色、商业对象和版本参数待提供

## 目标与边界

本用例从有权商业角色或受控外部主数据源提交参与方关系、客户账户、服务产品、合同、供应商协议、规则或政策变更开始，到 `party-commercial` 建立稳定身份/关系、发布不可覆盖商业版本、明确拒绝或冲突，或者保存本次尚未形成权威结果为止。

它不是通用后台 CRUD。每种商业对象保持独立身份、版本和批准责任；一次导入或发布批次只负责处理归组，不能把客户、合同、产品、价格和规则合并为一条可覆盖配置。

本用例包含：

- 保全来源、来源版本、内容摘要、请求方、批准依据和期望生效区间。
- 建立或关联运营集团租户、责任法人、业务参与方、货主客户账户和时态参与方关系。
- 分别校验并发布服务产品、客户合同、供应商协议、接单规则包、财务控制策略、商业价格政策、定价方案绑定、结算、信用和授权规则版本。
- 校验跨对象引用闭合、有效区间、唯一适用性及替代/退役关系。
- 处理重复、来源冲突、并发发布、撤销、到期、替代和有效性更正。

本用例不执行：

- 接受或拒绝客户委托、选择具体渠道、形成运输委托、计价、冻结、结算或客户通知。
- 通过直接改表、覆盖已发布正文或删除历史来修正商业依据。
- 为缺少的客户、法人、合同、产品、价格、权限、币种、阈值或有效期生成生产默认值。
- 将外部主数据“同步成功”直接解释为本上下文已经批准和发布。

## 商业对象发布单位

| 对象 | 必须独立保存 | 主要引用约束 |
|---|---|---|
| 参与方与关系 | 稳定参与方、双方、角色、方向、范围、依据和有效区间 | 法人、客户、供应商、代理和账号关系不能靠企业类型推断 |
| 货主客户账户 | 租户、客户参与方、隔离范围和当前有效性 | 不是责任法人、合同或登录组织 |
| 服务产品版本 | 产品身份、服务形态、责任、适用范围、版本和生效区间 | 新版本不自动修改客户合同 |
| 客户合同版本 | 客户账户、责任法人、产品引用、服务/结算条件和有效区间 | 必须引用适用规则包和财务控制策略或明确不适用依据 |
| 供应商协议版本 | 供应商参与方、责任法人、服务、采购、结算和责任范围 | 不等于具体运输委托或供应商账单 |
| 商业价格政策与定价方案绑定 | 价格方向、合同/协议、产品/渠道和费用范围、计价基准时点、结算/税务约束、可执行方案引用、有效区间和批准 | 不发布价表或执行评价；BUY/SELL/INTERNAL 不隐式继承 |
| 其他规则或政策版本 | 类型、正文、适用键、有效区间、依赖、批准和替代关系 | 接单、财务控制、结算、信用和授权规则保持独立 |

## 结果语义

| 结果 | 业务含义 | 禁止行为 |
|---|---|---|
| 已建立 | 稳定身份或参与方关系已经成立 | 把建立关系等同合同或授权发布 |
| 已发布 | 不可覆盖版本已经获准供声明范围的新选择使用 | 原地编辑正文或追溯改写历史 |
| 已计划生效 | 版本已发布但尚未到达明确生效边界 | 提前用于生产解析 |
| 已退役/撤销/替代 | 对新的适用业务停止使用，历史引用继续有效 | 自动取消委托、交易或结算结果 |
| 重复 | 同一来源身份和摘要已经形成原结果 | 创建第二版本或第二发布意图 |
| 来源冲突 | 同一来源身份携带不同内容 | 最后写入覆盖 |
| 适用冲突 | 同一解析键与时点会出现多个必需候选 | 任意挑选、以排序掩盖冲突 |
| 发布未决 | 批准、引用、证据或当前权威不足 | 默认发布或默认拒绝 |

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---:|---|---|---|
| 1 | 商业接入 | 保全来源、版本、摘要、对象类型、范围和业务时间 | 重复返回原结果；冲突不覆盖 |
| 2 | `party-commercial` | 校验租户、责任法人、客户账户、参与方及请求方授权 | 身份或授权不足保持未决/拒绝 |
| 3 | `party-commercial` | 按对象类型校验正文、来源证据和必要引用；价格政策校验方向、方案绑定和商业适用范围 | 不把多个对象合并为一份配置，也不把价卡工件当合同正文 |
| 4 | `party-commercial` | 评估有效区间、既有版本、替代关系和唯一适用性 | 会产生歧义的版本不得激活 |
| 5 | 有权批准角色 | 对明确对象、版本、范围和生效边界形成批准或拒绝 | 备注、导入成功或技术账号不替代批准 |
| 6 | `party-commercial` | 原子保存单一对象版本、关系、审计和发布意图 | 批次中其他对象失败不回滚合法版本 |
| 7 | `party-commercial` | 推进当前修订标识并发布版本/有效性变化引用 | 消费方据此检测旧解析是否失效 |

## 一致性、幂等与更正

- 同一商业对象版本只能发布一次。正文变化创建新版本；有效性更正必须保留原版本、原判断和更正关系。
- 商业价格政策与可执行价卡分别发布。`party-commercial` 只批准商业适用性和定价方案绑定；`parcel-pricing` 负责价表/规则工件的依赖闭合、确定性校验和可执行发布。任一侧未就绪都不能产生生产评价。
- 发布批次不是聚合。合同、产品和规则可以在一次操作中提交，但各自拥有独立结果；引用尚未发布时，依赖对象保持未决而不是建立悬空生产引用。
- 同一解析键即将出现适用区间重叠时，必须形成适用冲突或先完成明确替代边界；不得依赖数据库顺序、更新时间或最高版本号自动选择。
- 退役、到期、撤销或替代只影响相应生效边界后的新解析。既有委托、交易、费用和案件继续保存实际采用版本。
- 外部主数据源被替换时，先固定旧新来源身份和权威区间；技术切换不自动改变业务版本，也不能用重导覆盖历史。
- 发布结果不确定时按稳定请求关联查询；只有已证明同一业务幂等时才续办，不重复批准或发布。

## 给开发的交接

实现应按业务对象提供语义化命令与 Repository，不建立一个可以修改任意商业表的通用配置接口。首个生产持久化仍受 `PN02-W01/W03` 真实证据和技术门槛阻断；可以先实现纯领域版本、不变量、冲突分类和命名夹具，不得预置真实商业默认值。

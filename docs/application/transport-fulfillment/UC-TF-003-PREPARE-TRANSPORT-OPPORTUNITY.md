# UC-TF-003 准备常规运输机会、班次与容量

状态：稳定业务骨架待实现；真实班次、资源、容量维度和计划段参数待提供

## 目标与边界

本用例从 `network-routing` 提供当前有效计划履约段，或运营人员提出一项可关联到计划段的常规运输需求开始，到 `transport-fulfillment` 形成具体运输机会、班次、资源版本、容量池和可供后续委托/订舱使用的准备范围为止。

本用例只形成运输执行准备，不形成运输委托的承运接受、实物控制、权威运输交接、实际履约段、实际移动或交付。

本用例包含：

- 把路由计划和计划履约段转换为具体日期级运输机会，不把周期模板当作班次。
- 按实际适用维度建立资源与容量池，区分硬限制、软容量和运营缓冲。
- 对申请范围、可用范围、预占候选、装载候选和释放边界保留版本。
- 在无路由、路由冻结、容量不足、限制未决或前置准备不完整时形成明确待补充/不可用结果。
- 为 `UC-TF-004` 提供可解释的运输机会和容量依据。

本用例不执行：

- 运输委托、订舱申请、承运接受或供应商账单确认。
- 节点测量、分拣、集运、封签、节点侧装载或权威运输交接。
- 实际承运商识别、出发、移动、到达、派送、交付或包裹终局。
- 路由计划创建、改路、客户承诺调整、关务决定或限制解除。

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 运输机会已准备 | 有明确日期、方向、服务范围、需求量快照和可执行条件，可进入委托/订舱 | 计划段、班次、资源版本、成员/测量版本、各维需求量、容量维度、适用规则和对象范围 | 不得表示承运商已接受或实物已接收 |
| 部分准备 | 只有部分对象、维度或范围具备条件 | 已准备与未准备范围、数量、原因和续办入口 | 不得用批次结果覆盖成员差异 |
| 容量待确认 | 资源存在但容量或规则尚未形成权威结果 | 输入版本、缺口、候选机会和复核入口 | 不得以行业默认容量继续分配 |
| 当前机会不可用 | 明确硬限制、资源缺失或能力规则拒绝当前机会 | 适用规则、对象范围、决定方和业务时间 | 不得把技术失败或暂时未响应写成业务拒绝 |
| 无当前运输机会 | 当前路由仍有效但没有合格机会 | 所有候选和淘汰依据、剩余范围和续办位置 | 不得创建占位班次或虚构失败运输 |
| 已有结果 | 同一计划、范围和版本已经处理 | 原班次、容量和发布意图引用 | 不得重复建立班次或重复扣减容量 |
| 结果冲突 | 同一机会身份携带不同范围/规则/资源版本 | 原输入、冲突范围和纠正入口 | 不得按最后到达覆盖原结果 |
| 未形成 | 业务请求合法但处理未完成 | 失败阶段、已形成对象和恢复引用 | 不得伪装为不可用或已取消 |

## 容量与班次规则

- 周期运行安排或模板不是具体班次；明确日期、时间范围、方向和服务范围后才形成独立班次身份。
- 重量、体积、件数、托盘位、袋位、舱位等维度分别维护，除非有已登记且可追溯的换算规则，不强制折成单一容量数字。
- 申请量、可用量、预占量、分配量、释放量和实装量分别保存；本用例只形成机会和可供后续使用的范围，不提前写成预占或实装。
- 容量判断必须比较同一维度、单位和判断时点的需求量快照与容量版本。成员或当前有效测量变化时形成新需求快照，并在预占、分配、舱单冻结和出发前重新校验；未重评时不得沿用旧结论。
- 物理安全和法规上限是硬限制，普通运营授权不能突破。商业软容量只有在版本化阈值和授权范围内才可超配，并形成缺口和后续处置。
- 资源替换形成新版本，不改变班次身份；实际采用资源由后续事实确定。
- 首个有效出发或移动前可以取消或替代班次；之后只能形成中断、改降、折返或其他实际结果。
- 具体运输机会不可用不等于逻辑路由失效；仍有后续机会时交由运输履约重新分配，只有剩余旅程不可行时才请求路由复核。

## 一致性、权限与恢复

- 同一计划段、业务范围和规则版本只能形成一个当前有效准备结果；批量请求按对象和容量维度允许部分成功。
- 运输准备不能修改路由计划、客户承诺、节点事实或关务限制；所有输入采用快照和来源引用。
- 班次创建、资源分配、容量规则和软超配授权分别校验，调度登录权限不能推导承运接受或实际承运资格。
- 跨客户共同班次只共享允许运输执行所需的最小范围；候选、容量和业务量不得泄露其他客户信息。
- 结果提交不确定时查询原班次/容量结果和发布意图，不重复建立班次或再次扣减容量。
- 资源或容量事实更正形成新版本；原判断和原准备历史继续保留。
- 需求量快照变化不覆盖原申请。尚未消耗范围重新准备；已经接受、预占、分配或实装的范围分别形成差异和后续释放、补量、换班或升级处置。

## 给开发的交接

实现必须把“计划履约段 → 运输机会 → 班次/资源 → 容量准备”分别建模，不能使用一个可覆盖的 `transport_status` 或 `capacity` 字段代替多个业务对象。容量守恒和对象级范围是后续承运接受、装载、交接和结算引用的基础。

完成本用例只证明运输机会与容量准备可被解释和续办，不证明运输委托已接受、实物已交接、实际承运已成立、运输已经开始或包裹已经终局。

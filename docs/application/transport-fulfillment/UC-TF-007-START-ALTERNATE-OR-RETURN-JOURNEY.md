# UC-TF-007 启动备用伙伴或普通退运旅程

状态：稳定业务骨架待实现；真实备用伙伴、授权、退运路径、责任和生产适用范围待提供

## 目标与边界

本用例从原运输机会不可继续、授权业务角色决定采用备用伙伴，或已形成可验证的普通/商业退运处置决定开始，到 `transport-fulfillment` 建立关联但身份独立的新运输准备/实际履约旅程，并保留原旅程当前结果为止。

本用例不拥有备用伙伴切换或退运处置的商业决定来源。系统可以提供候选、影响、责任和成本依据，但必须由当前有效授权下的业务角色明确形成采用决定；监管退运仍由 [`UC-TF-001`](./UC-TF-001-ACCEPT-AND-FULFILL-REGULATORY-TRANSPORT-DISPOSITION.md) 按监管协作范围承接，不能通过本用例绕过。

本用例包含：

- 固定原旅程、原控制、未完成对象、候选伙伴/退运路径、影响和决定依据。
- 保存决定方、授权、原因、新旧伙伴、协议、责任、价格/成本来源和生效范围。
- 请求 `network-routing` 为新服务目的或剩余旅程形成新路由/计划段。
- 调用常规运输准备、委托、订舱、交接和实际履约用例形成新旅程。
- 对原旅程形成中断、提前终止、已交接或其他实际结果，不倒退原历史。
- 将原旅程已经发生的订舱、取消、尝试或履约收费发生项，与替代/退运新旅程的发生项分别关联，供结算形成完整预期成本。
- 对未准入生产的退运分支只保存必要引用或进行 `R/S` 验证，不产生真实外部指令或金额。

本用例不执行：

- 自动选择或静默切换供应商。
- 修改原路由、原班次、原委托、原交接、原移动、原交付、客户承诺或包裹身份。
- 形成监管退运决定、关务解除、客户赔付、供应商追偿或结算金额。
- 将拒收、失败尝试或异常案件自动解释为退运决定。

## 业务规则

- 首发日常分配只使用每个外包环节的主伙伴；备用伙伴仅用于受控异常切换，系统不得自动或静默替换。
- 采用决定必须保存实际决定方、当前授权、原因、对象范围、新旧伙伴、合同/价格依据和生效时间。
- 普通退运必须先由适用产品/合同责任方识别需求并形成处置决定；本用例只核验其当前有效性、范围和执行授权，不把拒收、失败或异常自动升级为决定。
- 已经开始的实际履约不得取消或覆盖；原段按事实形成中断、交接、提前终止或继续执行结果。
- 备用伙伴承担的是新运输准备或新的实际履约范围；不能只修改原委托的伙伴字段来伪造切换。
- 退运需求、退运决定、新路由、新运输委托、交接和实际退运分别形成；拒收、失败、异常或客户消息都不能自动生成退运决定。
- 普通/商业退运使用常规运输主链；监管退运必须由 `UC-TF-001` 消费监管协作事项。
- 实际退运建立关联但独立的新旅程，不使原路线、交接、移动、交付或包裹结果倒退。
- 原旅程中已经发生的订舱、取消、尝试、交接或运输范围继续归属原旅程；替代伙伴、改送或退运新发生的范围归属新旅程。新旅程不得把原成本来源迁移到新伙伴，也不得用新旅程成功覆盖原旅程费用责任。
- 原旅程与新旅程的运输收费发生项分别交给 `settlement-accounting` 形成供应商预期成本；是否免收、贷记、分摊或抵销只能依据明确采购规则形成追加金额结果，不能在运输履约内自动净额处理。
- 未纳入生产或没有真实路径时，模拟结果不得产生真实外部指令、供应商责任、费用或金额。

## 一致性、权限与恢复

- 同一决定版本、对象范围和服务目的只启动一个新旅程；重复请求返回原结果。
- 决定更正、原段继续移动和新段交接并发时按业务时间、控制边界和已发生事实裁决，不按消息顺序覆盖。
- 采用决定、运输准备、外部提交、权威交接和实际移动分别授权；任何单一权限不能替代其他动作权限。
- 跨客户共同事故可以共享内部原因，但采用决定、客户责任、合同、对象和新旅程必须按客户隔离。
- 新旅程保存成功但发布失败时只重试原发布意图；不得再次发送真实委托或创建第二旅程。
- 来源更正保留原候选、原决定和原旅程历史，并形成新的当前判断或后续处置。

## 首发试点叠加条件

- `PAR-NET-10` 提供备用伙伴、候选资格、协议、价格、授权和切换 SOP。
- `PAR-NET-11` 提供普通退运的产品/合同责任、真实路径、伙伴能力、费用和交接规则。
- `PAR-NET-14/15` 提供新服务目的、路由重评、冻结边界、已执行前缀和新旧控制边界；`PAR-INT-03/07` 提供外部来源及新委托/订舱交互。
- `PAR-SET-03` 提供原伙伴和替代/退运伙伴分别适用的供应商协议、运输收费发生条件和结算责任；不得沿用原伙伴协议解释新伙伴范围。
- 备用切换默认使用 `S`，自然发生时才补 `P`；退运只有在真实路径已纳入并自然发生时进入 `P`。
- 未确认时不得默认伙伴、自动选择权重、退运责任、路径、费用、权限或外部动作。

## 给开发的交接

实现必须把“候选 → 授权决定 → 新路由 → 新运输准备 → 新权威交接 → 新实际履约段”串成显式关系，同时永久保留原旅程。不要通过修改原伙伴、倒退原状态或复制原实际事实表达切换/退运。

完成本用例只证明受控备用或退运旅程能够安全启动，并能把原旅程与新旅程的成本来源分别交给结算。包裹最终服务结果仍由 [`UC-PS-004`](../parcel-shipment/UC-PS-004-FORM-PARCEL-FINAL-SERVICE-OUTCOME.md) 依据有效责任结果形成。

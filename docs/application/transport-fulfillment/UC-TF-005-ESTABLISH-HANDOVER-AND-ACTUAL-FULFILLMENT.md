# UC-TF-005 形成权威运输交接与实际履约

状态：稳定业务骨架待实现；真实节点/运输方交接、实际承运商、移动事实和外部可见范围参数待提供

## 目标与边界

本用例从节点侧交出、运输方接收或其他适用边界证据到达开始，到 `transport-fulfillment` 按载运对象形成权威运输交接、实际承运商判断、实际履约段、出发/移动/到达及下一次控制边界为止。

本用例是运输事实的唯一权威形成入口。节点扫描、车辆离场、装载分配、外部状态码、单证列入或消息到达都只是来源证据，不能单独替代权威交接。有效交接成立前，原控制方继续承担控制；已开始的实际履约段不能取消回未开始。

本用例包含：

- 收集节点、运输方、封签、点验、交出和接收证据，并逐对象裁决已交接、已拒收或待确认。
- 只为已交接对象建立实际履约段和履约参与关系；对封签集运单元形成受控派生，不伪造成员逐件事实。
- 依据保留原始来源的有效证据判断实际承运商；证据不足时保持待确认。
- 记录出发、实际移动、到达、资源变化、中断、折返、改降和控制责任变化。
- 在下一次权威交接或有效交付后结束相应对象的履约参与关系。
- 以稳定事实引用交给追踪、异常、节点、路由和包裹终局消费方。
- 外包段上的参与结束之后形成实际履约的运输收费发生项，不在交接编排里形成：段已采用运输委托的，由本上下文随交接与有效交付信封自动形成（[ADR-0218](../../adr/0218-actual-fulfillment-occurrences-form-from-handover-and-delivery-envelopes.md)）；采用晚于参与结束、或委托换了协议版本时，由采用与换版的门铃补形成，没形成的留痕在实际履约未形成册上（[ADR-0231](../../adr/0231-actual-fulfillment-left-unformed-is-caught-up-by-doorbells-and-a-commission-agreement-revision.md)）；其余经运营决定另行登记（[ADR-0207](../../adr/0207-transport-charge-occurrences-are-registered-by-an-operation-decision-and-handed-off-in-the-same-transaction.md)）。

本用例不执行：

- 节点作业、节点物理装卸、封签制作或成员变更。
- 路由计划选择、容量规则、客户承诺、关务决定、异常案件或费用结算。
- 派送任务和 POD 有效性判断（由 [`UC-TF-006`](./UC-TF-006-PERFORM-DELIVERY-AND-CAPTURE-POD.md) 负责）。
- 包裹终局、客户取消或服务终止。

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 权威交接已形成 | 明确对象控制转移到运输方 | 双方证据、对象范围、业务时间、结果版本和控制边界；交出门禁读数（五格、问关务时的交出意图、逐对象依据或本侧缺什么） | 不用整批汇总覆盖成员差异；不因读数阻断、未决或读不动拒收交接 |
| 权威交接已拒收 | 本次交接不成立，原控制继续 | 拒收对象、原因、来源和后续入口 | 不等于取消、退运或交付 |
| 权威交接待确认 | 证据不足或冲突无法裁决 | 全部来源、冲突范围、当前控制和复核入口 | 不因装载/离场/消息顺序转移控制 |
| 实际履约段已成立 | 已交接对象进入共同运输控制范围 | 履约段、对象参与关系、实际承运/未知、起点和依据 | 不从订舱或单证推导 |
| 实际承运商已确认 | 有效证据明确真实执行方 | 责任主体、来源、业务时间和判断版本 | 不把签约方/品牌/代理商自动改写 |
| 实际承运商待确认 | 控制成立但身份证据不足 | 已知控制范围、未知期间和补证入口 | 不虚构伙伴内部网络 |
| 移动/到达事实已形成 | 运输事实发生并可引用 | 对象/段、位置、业务时间、资源、来源和更正关系；出发另带门禁读数（五格、逐对象依据或本侧缺什么） | 不形成交付或关务完成；不因读数阻断、未决或读不动拒收出发 |
| 控制边界已结束 | 下一次交接、有效交付或明确终止成立 | 结束原因、对象范围、时间和后续责任 | 不用班次关闭或异常案件代替 |
| 运输收费发生项已形成 | 外包段上已结束的参与满足采用协议的发生条件 | 采购责任法人、服务方、协议快照、原因、段、成员、数量/单位、业务时间、发生条件依据与登记者、有效性（自 [ADR-0209](../../adr/0209-supplier-agreements-declare-charge-occurrence-conditions-and-registration-judges-by-them.md) 起依据是「按协议声明判」，数量与单位由协议的数量形定；断言期形成的项另带断言人与原话） | 不形成价格、预期成本、账单主张、应付或付款 |
| 运输收费发生项未配置 / 协议不计此原因 | 采用的那一版协议没声明这个原因的收费发生条件，或明说不计费 | 作答的那一版协议 | 不形成发生项；没声明不读成不适用，不计费不读成自营 |
| 未形成 | 事实保存或派生未完成 | 已形成事实和恢复引用 | 不伪装为未移动 |

## 交接与实际履约规则

- 权威交接按载运对象形成，允许部分成功；整袋/整笼/整箱只有在封签连续且相符时才能派生“随单元受控”，不能伪造成员逐件接收。
- 封签缺失、破损或不一致时，可以判断集运单元本身的交接，但成员只保留来源链和责任主张，当前实物控制形成待确认/冲突并等待开封和实际核对；不得继续把已经没有保管能力的原节点记为成员当前控制方。
- 扫描、点验、签字、车辆离场、物理装载、卸载、位置变化或外部状态码中的单项都不能在没有合格规则时自动转移控制。
- 实际履约段由首个有效收寄或权威交接成立；只有已交接对象形成履约参与关系，其他对象不得被段级状态吞并。
- 实际承运商与渠道服务方、签约服务商、代理商、底层品牌和结算相对方分离；证据不足时允许未知，后续有效证据只形成新的身份判断版本。
- 班次首个有效出发/移动前可以取消或替代；开始后只能形成中断、折返、改降或后续旅程，不能回写为未开始。
- 停运、失联、车辆故障或异常案件不自动结束控制；没有下一次交接、有效交付或明确终止依据时当前责任继续存在。
- 出发一律落册，门禁读数与出发同一笔保存。问门禁的对象取声明的段里出发那一刻在控的参与，起讫取班次方向，时点取出发的业务时间；适用哪些受门禁动作、三源怎么折由 `customs-compliance` 答，本用例只翻译。设备自报的「要不要门禁」不读，出示的放行凭据只作证据（[ADR-0205](../../adr/0205-departure-gate-is-a-pulled-reading-recorded-with-the-movement-fact-not-a-refusal.md)）。在控对象是集运单元时，按 `node-operations` 集运成员关系里出发那一刻的直接成员逐件问，单元那一格取成员里最重的一格（[ADR-0225](../../adr/0225-the-departure-gate-reading-asks-through-consolidation-unit-members-at-the-moment-of-departure.md)）。
- `已交接`一律落册，交出门禁读数与那一版同一笔保存；问哪一份意图、何时不问、更正怎么读，照 [ADR-0213](../../adr/0213-a-transport-handover-declares-its-releasing-receiving-and-onward-nodes.md) 决定四与文末补记。

- 出发之前，执行方可以按班次、可缺的段与拟出发时点问一次门禁：交回与随后同参出发同一套读数，本用例不落任何记录，也不据它拒收随后的出发；那条出发照样在它自己那一刻重问、与读数同一笔落册。能报出发的就能问（[ADR-0219](../../adr/0219-a-device-previews-the-departure-gate-before-departing-and-reads-what-the-departure-will-record.md)）。
- 退运、替代和改路后的新履约段拥有独立身份并关联原旅程，不倒退原段、原承诺或原交付。
- 补形成只补以下一次权威交接或有效交付结束的参与，交回自动形成的同一个形成后半，所以与自动形成落在同一个身份上；明确终止结束的照旧人工登记（[ADR-0231](../../adr/0231-actual-fulfillment-left-unformed-is-caught-up-by-doorbells-and-a-commission-agreement-revision.md) 决定二）。

## 一致性、幂等与并发

- 同一对象、交接身份和来源版本只形成一个有效交接结果；同一移动事实重复到达不重复累计里程或转移控制。
- 门禁读数是登记时问来的判断，不是登记方报的内容：同一出发或同一交接同内容重投交回首次读数、不另记、不重问，此刻关务答得不同也不判成冲突。
- 早期交接更正必须沿后续交接、移动、到达和交付关系重新评估控制来源链；后续事实继续不可覆盖。当前实物方明确而来源链矛盾时保存控制冲突，不把控制简单回退给早期原方。
- 交接与取消、容量释放、改路和异常并发时按业务时间、有效边界和已发生事实裁决，不按消息顺序覆盖。
- 交接事实保存成功但派生/发布失败时从同一事实恢复，不要求再次交接或重复移动。
- 部分交接、对象拒收和未知承运商不回滚同一段中其他对象已经成立的结果。
- 任何人工更正保留原证据、原判断、原因、决定方和生效时间；不能直接编辑当前控制字段绕过版本。
- 跨客户共同运输只向执行方提供当前履约所需的最小范围，不能通过整批汇总暴露其他客户。门禁读数回给执行方时只列没得出放行的对象，规则见 TF CONTEXT「实际移动与出发门禁读数」（[ADR-0237](../../adr/0237-gate-readings-show-the-executor-only-the-objects-that-did-not-pass.md)）。

## 首发试点叠加条件

- `PAR-NET-08`、`PAR-NET-13/15` 提供主履约方、节点/运输来源、交接、控制和责任边界；`PAR-INT-03` 提供外部交接、实际承运和移动来源，`PAR-INT-07` 只提供上游运输准备交互引用。
- `PAR-NET-04..06` 提供节点控制、集运、封签和节点侧交出证据；`PAR-NET-14` 提供计划段和执行边界。
- 适用关务限制只由 `PAR-CUS-01..04` 或其他限制源提供最小门禁投影，不在本用例内解除。出发与交出门禁读数的跨区判断依赖 `PAR-CUS-08` 节点关务区域；未登记时按 ADR-0206 决定二作答，本用例照记读数。
- `PAR-NFR-02/04/06` 提供事件规模、新鲜度、处理和恢复目标。
- 未确认时可以实现逐对象结果、未知承运商、封签派生、冲突和恢复骨架；不得默认“车辆离场即交接”或外部状态码映射。

## 给开发的交接

实现必须把“节点/运输方来源证据 → 权威交接结果 → 实际承运商判断 → 履约参与关系 → 实际履约段 → 移动事实”分开保存；出发门禁读数随出发保存，是关务答复的记录，不是第二套门禁判断。禁止使用一个 `in_transit` 或 `handover_status` 覆盖对象差异，也禁止由段级状态反向生成包裹交付或终局。

完成本用例只证明运输控制和实际履约事实可追溯；派送交付、POD、退运和包裹终局由后续用例分别形成。

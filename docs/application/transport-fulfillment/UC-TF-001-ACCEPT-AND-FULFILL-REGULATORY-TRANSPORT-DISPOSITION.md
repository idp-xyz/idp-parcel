# UC-TF-001 承接并履行监管运输处置

状态：开发基线草案；监管运输承接、独立退运旅程、权威交接和移动事实边界已形成，真实退运路径、运输责任、承运能力和交接参数待提供

## 目标与边界

本用例从 `transport-fulfillment` 收到 `UC-CC-008` 针对明确载运对象、运输动作、起止责任范围和当前有效监管依据形成的运输协作事项开始，到运输履约逐范围形成承接结果，依据有效路由计划和责任关系建立监管运输委托，形成承运接受、装载分配、权威交接、实际履约段及移动事实并回接关务，或者明确形成待补充、拒绝、冲突、未受理或技术未形成为止。

本用例只处理需要真实移动的监管协作，例如送往指定查验或保管地点、监管保管移交和监管退运。原地查验、原地扣留、节点开封、隔离、销毁或只需节点现场执行的动作由 [UC-NO-001](../node-operations/UC-NO-001-ACCEPT-AND-EXECUTE-CUSTOMS-NODE-COLLABORATION.md) 承接，不建立运输履约。

本用例包含：

- 校验关务协作事项、监管依据引用、载运对象、移动动作、起止责任范围、当前有效性和运输授权。
- 逐载运对象形成已承接、部分承接、待补充或拒绝结果。
- 对监管退运建立与原旅程有关联但身份独立的新旅程，不倒退原路由、交接、移动、交付或申报历史。
- 引用 `network-routing` 形成的当前有效计划，建立运输委托、订舱、承运接受、容量/装载分配和实际履约段。
- 与节点作业共同核对交接范围，由运输履约唯一形成逐对象权威运输交接结果和后续实际移动事实。
- 将承接、运输对象、交接、出发、到达和实际移动事实的稳定引用回接 `UC-CC-008`。
- 处理部分承接、部分交接、部分移动、取消、替代、重复、冲突、迟到、更正和恢复。

本用例不执行：

- 形成、解释、更正或解除监管查验、扣留、处置、放行或内部合规限制。
- 把扣留决定本身解释为移动授权；扣留范围只有在当前有效依据明确允许或要求移动时才能形成运输动作。
- 形成节点开封、隔离、清点、重封、销毁、装卸或节点侧交出事实。
- 把路由计划、运输委托、订舱、承运接受、装载分配、物理装载、到达或运输任务完成解释为关务处置核对完成。
- 回退原旅程、删除已经发生的交接/移动/交付事实，或把监管退运改写为原旅程的反向状态。
- 修改客户资料、申报资料、包裹身份、费用、异常责任、关务案件或客户通知。

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 监管运输协作已承接 | 运输履约接受明确对象和移动责任 | 事项、对象、移动范围、起止责任、责任方、授权和版本 | 不得表示运输已经开始 |
| 监管运输协作部分承接 | 只有部分对象或移动范围具备条件 | 已承接、未承接范围及逐项原因 | 不得用整批结果扩大范围 |
| 监管运输协作待补充 | 请求合法但必要对象、地点、授权、路由或责任不足 | 已知边界、缺口和续办入口 | 不得创建占位旅程或移动事实 |
| 监管运输协作已拒绝 | 明确规则证明运输方不承担相应范围 | 拒绝范围、依据、决定方和业务时间 | 不得把技术失败或暂时不可用伪装成拒绝 |
| 独立监管旅程已建立 | 对已承接范围建立新运输委托和旅程 | 与原旅程关系、新身份、对象、计划、责任和版本 | 不得倒退原旅程或表示已交接 |
| 权威运输交接已形成 | 节点与运输方对明确对象达成控制转移结果 | 双方证据、逐对象结果、业务时间和交接版本 | 装载、扫描或承运接受不能单独代替 |
| 监管运输履约事实已形成 | 形成实际履约段及出发、移动、到达事实 | 对象、实际承运、履约段、位置/节点、时间、来源和更正关系 | 不得直接形成处置核对完成 |
| 当前剩余范围已停止 | 协作取消、替代或收缩后停止尚未出发且可停止的范围 | 新旧依据、停止范围、已发生事实和后续责任 | 不得删除已经交接或移动的事实 |
| 监管运输协作冲突 | 合格请求、授权、范围或事实无法裁决 | 全部冲突输入、原结果和复核入口 | 不得按最后到达或运输便利选择 |
| 未受理 | 主体、范围、对象或权限不能合法关联 | 最小原因和纠正入口 | 不得泄露越权范围 |
| 未形成履约结果 | 技术处理未完成 | 请求、失败阶段、已形成对象和恢复引用 | 不得伪装成运输拒绝、失败或未移动 |

## 承接与履约规则

- 纯现场查验、原地扣留和节点处置不进入本用例。扣留只有在明确当前授权要求或允许移动到指定责任范围时，才形成监管运输协作。
- 监管退运建立关联但身份独立的新旅程，引用适用新路由、责任和关务依据；原旅程的计划、交接、移动、交付和终局事实永久保留。
- 承接、路由形成、运输委托、订舱、承运接受、容量预占、装载分配、节点装载、权威交接、出发、到达和关务核对分别存在。
- 节点作业拥有物理装卸和节点侧证据；`transport-fulfillment` 只有在双方合格证据满足交接规则时形成逐对象权威交接结果。整批交接由成员结果派生。
- 一条监管协作可由零个、一个或多个实际履约段完成，每个载运对象通过履约参与关系关联适用计划段和实际段。
- 部分承接、部分交接和部分移动必须逐对象保留，未覆盖范围不能被旅程或批次汇总吞并。
- 协作事项在出发前取消或替代时停止可停止范围；已完成权威交接或已经移动的范围不得回退，只能依据新决定形成后续控制与履约安排。
- 到达指定地点只证明运输事实；是否满足监管处置要求及监管义务是否终结仍由 `UC-CC-008` 和真实监管结果判断。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---:|---|---|---|
| 1 | 运输协作接入 | 校验请求、租户、法人、客户、事项、对象和权限 | 未受理时最小披露 |
| 2 | `transport-fulfillment` / `UC-CC-008` | 确认事项当前有效且确实要求真实移动 | 纯节点动作转 `UC-NO-001`；不建运输对象 |
| 3 | `transport-fulfillment` | 核对对象、起止地点、移动授权、责任、能力和当前控制 | 逐范围承接、部分承接、待补充或拒绝 |
| 4 | `network-routing` | 为新监管旅程形成可用路由计划 | 无计划保持待补充，不复制原旅程 |
| 5 | `transport-fulfillment` | 建立运输委托、订舱、承运接受和装载分配 | 形成准备对象，不形成交接或移动 |
| 6 | `node-operations` / `transport-fulfillment` | 核对逐对象交接证据 | 运输履约形成已交接、拒收或待确认 |
| 7 | `transport-fulfillment` | 形成实际履约段、履约参与及出发、移动、到达事实 | 保存实际范围、承运责任和来源 |
| 8 | `transport-fulfillment` | 发布承接、旅程、交接和履约事实稳定引用 | `UC-CC-008` 形成处置执行核对 |

## 一致性、权限与恢复

- 相同事项版本、对象、移动范围和请求身份重复到达时返回已有承接、旅程和当前结果；相同身份内容不同形成冲突。
- 同一交接或移动事实经多个通道重复到达时按来源身份、业务语义和版本去重，不重复转移控制或累计范围。
- 协作取消/替代与交接或出发并发时，以已经发生的权威事实为边界，停止尚可停止范围并保留全部输入。
- 承接、运输准备、承运接受、权威交接、事实更正和结果发布分别授权；运输账号、车辆调度或节点登录权限不能互相推导。
- 跨客户范围逐对象隔离，运输方只获得履行当前移动所需的最小信息；整批汇总不得泄露其他客户监管原因。
- 事实已经保存但派生或发布失败时从同一事实恢复，不要求重复交接、出发或移动。发布失败只重试同一发布意图。

## 首发试点约束

- 只有 `PAR-NET-11` 已确认真实路径、责任、伙伴能力、费用和交接规则的监管退运或运输处置才能进入生产。
- 真实节点、执行方、动作、权限和证据复用 `PAR-CUS-01..05`、`PAR-NET-04..06`、`PAR-INT-03` 和 `PAR-NFR-06`；不新增猜测默认值。
- 若锚点线路首发不包含真实监管运输处置，必须以 `R/S` 验证边界并记录生产剩余风险，不为验收主动制造退运、扣留或监管移动。

## 验收示例

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-TF-001` | 当前有效监管退运决定、明确对象及新路由均有效 | 形成独立退运旅程和运输准备对象，保留与原旅程关系，不倒退原历史 |
| `AT-TF-002` | 协作只要求原地查验、原地扣留或节点销毁 | 不建立运输委托，交由 `UC-NO-001` 处理现场动作 |
| `AT-TF-003` | 扣留范围没有明确移动授权 | 保持原控制，不因扣留本身创建运输任务 |
| `AT-TF-004` | 对象、起止地点、移动授权、责任或路由缺失 | 形成待补充，不创建占位旅程、交接或移动事实 |
| `AT-TF-005` | 运输协作已承接且完成订舱/承运接受，但尚未交接 | 各准备结果分别保存，不形成权威交接或实际移动 |
| `AT-TF-006` | 一批对象只有 P1 完成交接并移动，P2 被拒收 | 逐对象保存 P1 交接/移动与 P2 拒收，批次不显示整体完成 |
| `AT-TF-007` | 节点已装载并扫描交出，但双方证据尚不足 | 保持权威交接待确认，节点事实不制造控制转移 |
| `AT-TF-008` | 退运旅程出发或到达 | 只形成新旅程实际履约事实；原旅程和交付事实不回退 |

| `AT-TF-010` | 请求、交接或移动事实重复、冲突、迟到或更正 | 保留来源和版本，幂等或形成冲突/新有效事实，不按最后到达覆盖 |
| `AT-TF-011` | 运输已到达监管指定地点 | 回接到达事实，由 `UC-CC-008` 核对；不形成处置完成、放行或案件关闭 |
| `AT-TF-012` | 事实已保存但派生或发布技术失败 | 保留事实和恢复引用，返回未形成结果；不伪装成承运拒绝、运输失败或要求重复移动 |

## 生产参数与待决风险

- `PAR-NET-11`：监管退运或移动的真实路径、责任、伙伴能力、费用和交接规则。
- `PAR-NET-04..06`：起止节点、节点作业能力和控制边界。
- `PAR-CUS-01..05`：监管动作、对象范围、授权、执行方、证据和复杂分支验证环境。
- `PAR-INT-03`：外部运输/节点事实来源、身份、更正和结果层语义。
- `PAR-NFR-06`：运输承接、事实新鲜度、批量和恢复目标。

真实值未确认前，只能实现显式待补充、回放或模拟骨架，不得默认起止地点、运输方、移动权限、完成证据、时限或失败后果。

完成本用例只证明监管运输处置能够在明确授权下形成独立履约，并把真实交接和移动事实安全回接关务。监管决定、处置执行核对、放行和案件终结仍由其权威流程拥有。

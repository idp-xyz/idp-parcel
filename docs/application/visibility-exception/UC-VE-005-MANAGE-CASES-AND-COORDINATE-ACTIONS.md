# UC-VE-005 管理异常案件并协调处置请求

状态：稳定业务骨架待实现；响应目标、处置授权和目标上下文交接参数待提供

## 目标与边界

本用例从 `UC-VE-004` 已建立或关联的异常案件开始，到案件完成分派、接单、响应、关闭、受控重开或重复归并，并对需要其他上下文执行的动作形成处置请求为止。

本用例拥有案件协调关系和请求历史，不拥有改路、节点作业、运输、关务、限制、费用或消息的实际决定。请求发送、目标上下文接受、部分执行和实际完成分别记录；任何一个结果都不能冒充另一个结果。

| 响应结果 | 分派、接单、首次行动、下一行动、客户更新和解决目标分别形成 |

## 主流程

1. 校验案件根对象、当前影响范围、责任团队和响应策略仍适用。
2. 形成分派并等待接收方接受；转派只有接收后生效，原历史保留。
3. 记录首次响应、下一行动、等待条件、升级和客户更新，不以等待替换主状态。
4. 需要业务动作时生成结构化处置请求，固定目标上下文、范围、原因、证据和期望时限。
5. 接收目标上下文的接受、拒绝、补充要求、部分执行和实际完成；更新请求范围，不改源事实。
6. 范围缩小、改派或方案变化时形成请求取消/替代意图，并等待目标方按未消耗范围返回取消结果；旧请求在确认前仍不得被当作已停止。
7. 案件内必需动作完成，且全部未完成请求已继续等待、明确移交或完成取消/替代核对后，才形成关闭结论；关闭不关闭源案件或外部义务。
8. 关闭后新事实属于同一因果链/责任/处置范围时受控重开并形成新响应周期；独立原因建立关联新案。
9. 发现重复案件时指定主案，核对范围和未完成请求，将请求明确移交主案或完成取消核对后，再将重复案以“已归并”结论关闭。

## 规则、权限与隔离

- 案件主生命周期只使用 `待响应 → 处理中 → 已关闭`；等待、监控、升级和转交是工作条件。
- 案件责任团队负责协调，不等于原因方、履约责任方、客户赔偿责任方或供应商追偿责任方。
- 影响范围必须显式、版本化；不能因同一集运单元、班次、舱单、客户或伙伴自动继承。
- 关闭、重开、归并和响应目标变更都保留原决定、证据、范围和绩效；重开不复活委托、路由、关务、限制、运输、面单或财务对象。
- 处置请求只能提出目标动作；目标上下文拥有接受、拒绝和实际执行决定，部分执行只关闭明确完成范围。
- 请求受理有效期届满只阻止尚未接受范围被新接受；已接受范围的执行逾期只触发升级。取消、替代、案件关闭或归并都不能撤销目标上下文已经形成的事实。
- 共同案件按客户账户和责任法人隔离，当前处理方只能看到获授权范围。

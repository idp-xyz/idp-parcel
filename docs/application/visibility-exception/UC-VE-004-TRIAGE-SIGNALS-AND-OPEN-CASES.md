# UC-VE-004 分诊异常信号并建立案件

状态：稳定业务骨架待实现；异常清单、分诊阈值、责任团队和响应目标待提供

## 目标与边界

本用例从已接受事实、`UC-VE-002`/`UC-VE-003` 的投影/缺口结果或参与方上报开始，到形成不建案、待人工分诊、关联既有案件或新案件为止。它覆盖通用网络、节点、运输、交付、来源和可见性异常；关务异常仍由 `UC-VE-001` 消费已接受关务事实。

本用例不执行改路、拦截、重作业、重新履约、重新申报、放行、解除限制、费用调整或客户消息；不形成原因、合同责任、赔付或最终追偿金额。

## 输入和结果语义

| 输入/结果 | 业务语义 |
|---|---|
| 信号 | 类型、对象/范围、规则版本、判断时间、事实依据、可信度、影响和发作期 |
| 不建案 | 当前资料/影响不满足建案条件，保留复核条件和信号历史 |
| 待人工分诊 | 可信度、重复关系或影响不足以自动决定；不按最高严重度处理 |
| 已关联案件 | 同一因果链和共同处置范围已有案件；不重置响应周期 |
| 新案件 | 固定根对象、版本化影响范围、责任团队、优先级和响应策略；主状态为待响应 |
| 共同案件 | 一个根原因影响多个对象/客户，范围按客户账户和责任法人分区 |

## 主流程

1. 保全信号来源、对象范围、事实版本、发现时间和请求身份。
2. 校验输入来自已接受事实或有效投影；原始报文、截图、客户意见和技术超时不能直接成为业务异常。
3. 按 `PAR-VIS-04/05` 判断类型、可信度、影响、重复、连续发作期和恢复条件。
4. 检索同对象、因果条件和责任范围内的现有信号/案件；同期重复更新发作期。
5. 形成不建案、人工复核、自动建案或关联结果；建案不自动停单、认责或披露。
6. 建案时固定根对象、显式影响范围、责任团队、当前处理条件和 `PAR-VIS-06` 响应目标。
7. 跨客户共同原因使用一个内部根案时，分别保存各客户/法人影响范围和后续披露入口。

## 规则、权限与恢复

- 高可信、高影响且命中版本化规则才可自动建案；资料不足、可能重复或关联不明必须人工分诊。
- 严重度和处置优先级分别保存，均不自动形成限制、责任或赔付。
- 案件责任团队承担协调责任，不代表原因方、履约责任方或赔偿责任方。
- 范围扩大、缩小、排除、拆出、关闭、重开和归并均保留版本与历史；重开不自动重开委托、路由、关务、运输、面单或财务对象。
- 同一请求身份重复返回原结果；身份携带不同客户、范围或规则版本形成冲突，不按最后到达覆盖。

## 首发约束与验收

`PAR-VIS-04/05/06` 未确认时只做骨架、回放、影子或人工分诊。`VIS-04` 必须按矩阵完成 `R+S+P` 分层证据；`P` 只使用锚点线路自然发生的正常主链和已纳入生产范围，不为取证主动制造高风险异常。批量、关闭重开和归并按 `VIS-05/06/08` 的证据层级执行。

## 给开发的交接

把“信号 → 发作期 → 分诊 → 案件 → 影响范围/响应目标”分别建模，并支持不建案、待分诊、部分范围和冲突结果。完成本用例不证明源动作、客户披露、责任结论或金额完成。

# UC-VE-007 管理证据、客户索赔与外部追偿

状态：稳定业务骨架待实现；索赔/复核期限、最低证据、责任规则、追偿动作和外部协作条件待提供，首发以受控模拟为主

## 目标与边界

本用例从异常案件、客户索赔提交或外部追偿条件成立开始，到形成可追溯证据项、逐索赔项的资格/补充/撤回/责任/复核结果，以及供应商、实际承运商或保险追偿事项的通知、主张、对方响应和责任结论为止。

`visibility-exception` 拥有证据引用与评价、客户索赔项、追偿通知/主张、对方响应和责任结论。客户赔付及供应商/保险追偿金额只由 [`UC-SA-007`](../settlement-accounting/UC-SA-007-SETTLE-CLAIMS-AND-RECOVERY-AMOUNTS.md) 形成；外部资金事实由财务、银行或支付来源拥有，只有 [`UC-SA-005`](../settlement-accounting/UC-SA-005-MAP-EXTERNAL-FUNDS-AND-APPLY-SETTLEMENT.md) 可以在本产品内形成运营到账映射与核销。

客户索赔、客户赔付、供应商追偿和保险追偿不合并为一个净结果。索赔撤回不消除异常事实或独立追偿，追偿通知已提交、对方接受责任、追偿金额已形成和真实到账也不得统称为“追偿成功”。

## 输入和结果语义

| 输入/结果 | 业务语义 |
|---|---|
| 证据项 | 来源、提供方、取得时间、适用范围、类型、版本、有效性和访问范围；收到不等于内容成立 |
| 索赔提交批次 | 一次提交的业务归组，不拥有统一资格、责任、撤回或赔付结果 |
| 客户索赔项 | 固定客户账户、合同责任范围、目标包裹/服务范围和索赔类型，逐项审核与复核 |
| 索赔期限依据 | 首次索赔、资料补充和结论复核分别保存规则版本、起算事件、业务日历/时区、截止时间和延期历史 |
| 索赔撤回 | 经授权客户对明确索赔项停止后续审核的请求及结果；不等于责任不成立，也不删除原提交和证据 |
| 追偿事项 | 针对一个明确责任相对方和责任依据的独立业务事项，拥有自身范围、期限、证据和责任结论 |
| 追偿通知/主张动作 | 预先通知、正式主张或补充主张的独立动作，分别保存内容、期限、要求的提交/送达/确认结果和尝试历史 |
| 对方响应 | 已接收、要求补充、审核中、全部接受、部分接受、拒绝或无响应；它是责任判断依据，不是金额或到账 |
| 金额与资金引用 | VE 只引用 `UC-SA-007` 的金额和 `UC-SA-005` 的到账/核销结果，不创建或覆盖它们 |

## 主流程

1. 校验租户、责任法人、货主客户账户、参与方、目标对象、操作授权和适用合同/协议范围。
2. 保全客户、伙伴、节点、运输、关务和交付材料，形成证据项并记录版本、冲突、有效性及可披露范围。
3. 接收索赔提交批次，按客户账户、授权、合同、首次索赔期限、目标范围、重复关系和最低材料逐项判断资格。
4. 材料不足时形成限期补充；处理材料到达、延期申请/批准和期限届满，按当前有效规则重新形成资格结果。
5. 处理客户逐项撤回。最终责任结论前有效撤回终止后续审核；结论或金额已经形成时，只能通过适用复核和结算调整改变当前结果。
6. 对符合资格的索赔项形成全部成立、部分成立、不成立或当前无法认定的责任结论；异议或关键新证据按复核期限和授权形成新结论版本。
7. 在追偿条件成立时，按供应商、实际承运商、保险或其他责任关系独立建立追偿事项，不等待客户索赔、赔付或异常案件关闭。
8. 按协议或保险条款分别准备预先通知、正式主张或补充主张，固定相对方、责任范围、内容、期限和义务完成条件。
9. 对外提交后分别记录渠道接受、送达、对方确认、失败、重试和有效延期；期限届满时依据合同要求进行失权复核。
10. 接收并保全对方响应，按响应范围、事实、协议和证据形成或复核外部责任结论；无响应不自动形成接受或拒绝。
11. 把当前有效责任结论和证据依据交给 `UC-SA-007` 形成金额；仅引用 `UC-SA-005` 返回的实际到账映射与核销结果，不把前序结果冒充资金结果。

## 客户索赔规则

- 首次索赔期限、资料补充期限和结论复核期限相互独立。补充延期不得重置首次索赔期限，复核也不能增加包裹、索赔类型或责任范围。
- 资料补充必须固定缺少材料、补充范围、通知依据和当前截止时间。材料已到达后重新判断完整性，不能把上传动作直接解释为已经补齐。
- 延期申请、内部批准和有效延期分别记录。只有适用合同/规则允许且有权决定方批准明确范围和新截止时间时才形成期限新版本；不得通过倒填使逾期材料变为按时提交。
- 补充期限届满只触发资格复核。规则明确届满后果时，才形成不予受理或依据现有材料继续审核；规则缺失、延期尚未决定或起算事实有争议时保持待决定并升级。
- 最终责任结论前，授权客户可以逐项撤回；批次撤回必须展开到每个索赔项。撤回保留原提交、证据和处理历史，不修改异常案件，不取消供应商或保险追偿。
- 最终责任结论或金额形成后，撤回请求不能覆盖既有结果。责任是否改变由受控复核决定，金额差额由 `UC-SA-007` 处理，实际资金差额和核销由 `UC-SA-005` 处理。
- 复核期限必须按合同规定的结论通知、送达或可获取事实起算。起算事实无法确认时保持期限待判断；超过期限且无有效延期或恢复依据时，只形成不受理复核，不改写原结论。
- 撤回后重新提交仍是新索赔项，必须重新执行首次索赔期限、授权、范围和重复检查，不能借撤回重置期限或制造重复赔付。

## 外部追偿规则

- 一个追偿事项只针对一个责任相对方及一组可明确裁决的责任依据。供应商、实际承运商和保险方向分别建项，不能用净责任掩盖任一方向。
- 准备完成不等于已提交；已提交不等于已送达；渠道接受不等于对方确认。哪一层满足期限义务必须引用适用协议或保险条款，不能使用系统默认。
- 预先通知和正式主张是不同外部动作。一个动作按时完成不能自动满足另一个动作，也不能用后续正式主张倒填遗漏的预先通知。
- 提交失败或送达失败是动作结果，不是对方拒绝责任。期限内可以按规则重试或更换获准渠道，每次尝试和内容版本都必须保留。
- 延期只有在合同/保险条款允许并取得其要求的有权相对方确认或其他有效依据时生效。内部批准、口头预期或已发送延期请求不能单独延长外部期限。
- 期限届满后必须按要求的提交、送达或确认结果复核是否失权。只有依据充分时才形成失权结论；送达、延期或条款解释仍有冲突时保持待判断，不按系统时间自动失权。
- 对方要求补充、审核中、部分接受、全部接受和拒绝分别保留范围、理由和证据。无响应只形成逾期或待跟进，不自动表示接受、拒绝或责任成立。
- 对方响应可以支持 VE 形成新的责任结论版本，但不能形成最终金额。`UC-SA-007` 形成的追偿金额仍不是到账；只有 `UC-SA-005` 采用有效外部资金事实后才能形成运营到账映射和核销。
- 客户索赔撤回、客户不获赔或客户尚未提出索赔，都不自动取消已经有独立合同依据的外部追偿。

## 权限、隔离与审计

- 证据查看、索赔受理、延期批准、撤回确认、责任裁定、复核、追偿提交和失权判断分别授权；案件责任团队身份不能自动取得责任裁定或延期权限。
- 每个索赔项只能属于一个货主客户账户和明确合同责任范围。跨客户共同事故可以共享内部证据引用，但索赔、责任结论和客户披露必须隔离。
- 每个外部动作必须记录责任法人、相对方、协议/条款版本、范围、期限版本、内容版本、提交/送达/确认结果、失败、延期和决定方。
- 证据对外披露必须使用授权范围或脱敏版本，不复制出来源不明附件；外部响应也不能泄露其他客户或无关责任方向。
- 首发未纳入真实索赔/追偿时，只在与生产账本、真实客户通知和外部主张隔离的回放/模拟中验证，不形成真实责任、金额或资金结果。

## 首发约束与验收

即使真实索赔/追偿未纳入首发，也必须确认足以支持 `VIS-09 S` 的脱敏合同规则、最低证据、期限起算与届满后果、责任边界和模拟数据，并登记剩余风险。只有能力明确纳入且自然发生时才使用 `P`，不得用模拟通过替代真实客户、供应商或保险协作。

## 给开发的交接

把证据项、索赔批次、索赔项、三个独立期限、撤回、责任结论、追偿事项、外部通知/主张动作、对方响应、金额引用和到账/核销引用分别建模。完成本用例只证明 VE 的资格、外部动作和责任链可追溯，不证明赔付或追偿金额已经形成，更不证明资金已经收付或核销。

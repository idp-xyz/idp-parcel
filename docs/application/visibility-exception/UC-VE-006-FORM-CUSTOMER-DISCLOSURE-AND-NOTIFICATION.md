# UC-VE-006 形成客户可见异常并管理通知结果

状态：稳定业务骨架待实现；客户合同、披露策略、模板、授权和渠道参数待提供

## 目标与边界

本用例从内部信号/案件和客户合同范围开始，到形成逐客户可见异常、通知决定、内容快照、通知义务判断，并接收消息能力的提交、接受、送达、失败和客户确认结果为止。

本用例拥有异常披露决定和通知义务判断，不拥有消息渠道技术结果，也不修改源事实、异常案件责任、关务限制、运输事实或索赔结论。普通里程碑、ETA、终局和更正的授权查询由 [`UC-VE-008`](./UC-VE-008-PROVIDE-CUSTOMER-END-TO-END-TRACKING-VIEW.md) 负责；普通查询不会自动触发本用例。`UC-VE-001` 的关务披露使用同一分层规则，但仍是关务专项入口。

## 输入和结果语义

| 输入/结果 | 业务语义 |
|---|---|
| 客户可见异常 | 按服务产品、合同、客户账户和授权范围形成的隔离视图，不是内部案件副本 |
| 通知决定 | 固定目标客户、对象范围、内容快照、披露依据、要求时限和适用渠道 |
| 草稿/待授权 | 内容已生成但尚未取得发布授权；不向生产渠道提交 |
| 渠道结果 | 提交、渠道接受、送达、失败和客户确认分别成立 |
| 通知更正 | 追加新内容或替代关系，原内容和原义务历史保留 |

## 主流程

1. 读取案件/投影的当前有效影响范围、客户合同、服务规则和客户授权。
2. 按客户账户和责任法人切分范围，过滤其他客户、敏感调查和未确认责任信息。
3. 判断是否满足披露条件；不满足时形成暂不披露或待复核结果。
4. 生成最小内容草稿和通知义务判断，固定模板/规则版本和目标时限。
5. 默认等待授权角色确认；只有批准范围才形成提交意图或自动发布决定。
6. 将提交意图交给消息能力，分别记录提交、渠道接受、送达、失败和客户确认。
7. 按策略重试或升级失败；内容更正追加发布，不删除原通知。

## 规则、权限与隔离

- 严重度、案件存在或消息渠道可用不自动要求客户通知；披露由合同、影响、可信度和策略共同决定。
- 客户视图只包含当前客户账户及其授权对象；不得泄露其他客户身份、数量、调查、敏感监管信息或未确认责任。
- 默认人工确认；自动发布只适用于已批准、标准化、范围稳定且通过影子验证的内容。
- 消息提交/接受不等于送达，送达不等于客户已阅读或确认；合同要求的相应结果未成立时通知义务仍未满足。
- 客户确认或异议不直接修改源事实、案件责任、限制或索赔结论。
- 已批准的客户可见异常可以作为 `UC-VE-008` 的只读展示输入；客户查询、门户展示和主动通知仍是不同结果，查询不能代替本用例的披露决定、送达或确认。

## 首发约束与验收

`PAR-VIS-07` 和适用 `PAR-INT-06` 未确认时只生成草稿和隔离模拟，不使用临时人工发送冒充渠道就绪。`VIS-07`/`VIS-10` 按 `S+P`/`P` 分层取证。

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-VE-099` | 案件存在但合同不要求披露 | 形成暂不披露，不自动发消息 |
| `AT-VE-100` | 客户影响明确但需要授权 | 形成草稿和待授权，不提交渠道 |
| `AT-VE-101` | 内容包含其他客户或未确认责任 | 过滤/改写为批准的最小内容 |
| `AT-VE-102` | 批准范围允许自动发布 | 保存自动决定依据，只发布批准范围 |
| `AT-VE-103` | 消息渠道接受 | 只记录接受，不推定送达 |
| `AT-VE-104` | 渠道返回送达 | 满足送达层义务，不推定客户确认 |
| `AT-VE-105` | 合同要求客户确认但只有送达 | 通知义务保持待确认 |
| `AT-VE-106` | 投递失败 | 保留失败尝试，按策略重试或升级 |
| `AT-VE-107` | 内容因新事实需要更正 | 追加更正/替代通知，原内容不删除 |
| `AT-VE-108` | C1/C2 同一共同案件 | 分别形成隔离内容，不暴露对方范围 |
| `AT-VE-109` | 客户确认或提出异议 | 形成客户结果，不改写案件或源事实 |
| `AT-VE-110` | 通知提交结果保存失败 | 返回未形成和恢复引用，不伪装为渠道失败 |
| `AT-VE-111` | 关务专项披露 | 由 `UC-VE-001` 进入，本用例不绕过关务事实接受 |
| `AT-VE-112` | 自动发布规则停用 | 停止自动提交，历史通知和义务保留 |

## 给开发的交接

把客户可见异常、披露决定、内容快照、消息尝试、渠道接受、送达、失败和客户确认分别建模。不要把普通追踪查询建成异常通知的前置或结果。完成本用例只证明披露和通知结果分层，不证明客户已经阅读、同意责任或源业务动作完成。

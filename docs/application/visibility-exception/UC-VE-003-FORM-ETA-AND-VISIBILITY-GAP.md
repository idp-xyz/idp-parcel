# UC-VE-003 形成 ETA 与可见性缺口判断

状态：稳定业务骨架待实现；观察窗口、ETA 质量和 ETA 对客可见门槛待提供

## 目标与边界

本用例从 `UC-VE-002` 已形成的追踪投影、服务/合同规则和适用履约段观察要求开始，到形成内部 ETA、ETA 客户可见性判断或可见性缺口结果为止。

ETA 是对未来里程碑的预测；可见性缺口只表示明确预期观察在窗口内未取得。两者都不能覆盖客户承诺、路由计划、实际履约、交付结果或包裹终局。本用例不编排客户追踪视图，不形成异常披露或主动通知，也不发送客户消息。

## 输入和结果语义

| 输入/结果 | 业务语义 |
|---|---|
| 当前投影 | 目标对象、有效事实、里程碑、来源新鲜度和不确定性 |
| 预期观察 | 服务/线路/履约段、目标里程碑、预期来源和适用区间；没有预期就不形成缺口 |
| ETA 已形成 | 保存输入事实、规则/模型版本、预测时点、预计范围和可信度；不等于承诺 |
| ETA 未形成 | 信息不足、冲突、未达内部 ETA 形成最低要求或不适用；保存理由，不用计划时间填充 |
| ETA 客户可见性判断 | 针对明确货主客户账户、服务产品、合同、预测对象和目标里程碑范围，引用候选内部 ETA 版本，保存质量评价及对客门槛版本、合同/客户服务规则版本、判断结果、理由、判断时点、判断版本和替代关系；结果为客户可见 ETA、ETA 不可见或 ETA 可见性待判断。客户可见时另保存获准对客表达和停止展示边界 |
| 缺口观察中 | 窗口未届满；保存起点、截止时间和当前证据 |
| 缺口已形成 | 窗口届满仍未获得预期信息；不直接判为延误、停止或遗失 |

## 主流程

1. 读取当前投影、服务产品、合同、承诺和适用履约段范围。
2. 判断目标里程碑是否存在明确预期；不适用则返回不适用。
3. 选择 `PAR-VIS-02/03` 规则版本并固定判断时点。
4. 依据已接受事实形成内部 ETA，或分别保留承运商预测与内部预测。
5. 检查输入完整性、来源新鲜度、覆盖和内部 ETA 形成最低要求；不足时形成 ETA 未形成。
6. 对已形成的内部 ETA，采用 `PAR-VIS-03` 的质量门槛并结合 `PAR-COM-07` 的适用服务产品、客户合同和客户服务规则形成判断：条件明确满足时形成客户可见 ETA，条件明确不满足时形成 ETA 不可见，适用规则、合同或证据缺失或冲突时形成 ETA 可见性待判断。
7. 比较预期观察、窗口和已取得事实；窗口未到保持观察，届满才形成缺口。
8. 分别保存内部 ETA、ETA 客户可见性判断和缺口版本。客户可见 ETA 只允许进入 `UC-VE-008` 的候选输入；本用例不校验具体查询请求方的对象授权，也不形成客户视图、客户可见异常、主动通知、消息提交、送达或客户确认。

## 规则与首发约束

- ETA 新版本不修改预计/正式承诺、路由计划或实际事实；新 ETA、质量门槛、合同或客户服务规则版本生效时必须形成新的 ETA 客户可见性判断和替代关系，原判断不覆盖。
- 客户可见 ETA 只表示该 ETA 版本具备进入授权客户视图的资格；是否出现在某次查询中仍由 `UC-VE-008` 按客户账户、对象授权和 `PAR-VIS-09` 普通追踪公开规则编排。ETA 不可见或可见性待判断时不得以内部 ETA、计划时间或客户承诺填充。
- 外部不透明履约段没有承诺的内部扫描不构成缺口；来源整体中断优先形成来源级信号及影响范围。
- 缺口恢复和再次发生分别保留发作历史，不自动关闭或重开案件。
- `PAR-VIS-02/03` 未确认时只做回放、影子或内部校准；达到质量与合同门槛并经 `Go/No-Go` 后才允许对客。

# UC-VE-001 协调关务异常并管理客户披露

状态：开发基线草案；关务事实接收、异常信号/案件、处置协调、客户披露决定和消息结果边界已确认，真实异常类型、分诊、响应、披露和渠道参数待提供

## 目标与边界

本用例从 `visibility-exception` 收到 `customs-compliance` 已经接受、范围明确且来源可追溯的关务事实、判断或协调交接开始，到本上下文依据当前有效规则形成或更新异常信号，完成分诊并按需建立/关联异常案件、提出处置请求、形成客户可见异常与客户异常通知决定，接收消息能力返回的渠道结果，或者明确形成无需信号、无需建案、暂不披露、待分诊、待授权、冲突、未受理或技术未形成为止。

本用例包含：

- 接收关务案件、申报结果、结果待确认、查验/扣留/处置、执行差异、税费付款核对、放行门禁、内部合规限制、案件关闭/重开等已经由关务所有者形成的稳定事实或判断引用。
- 依据版本化异常类型和识别规则，独立形成异常信号或明确当前无需信号，不把每项关务过程事实都自动解释为异常。
- 对信号的可信度、影响、重复关系、资料完整性和处置必要性进行分诊，形成关联既有案件、建立案件、人工复核或不建案结果。
- 对需要关务、节点、运输、结算或其他上下文处理的范围形成结构化处置请求，保存发送、接受、部分接受、拒绝、待补充和实际结果关系。
- 依据客户合同、服务产品、客户影响、信号可信度和披露规则，独立形成客户可见异常、客户异常通知决定、内容快照或暂不披露/待授权结果。
- 将通知提交消息能力，并分别接收渠道接受、送达、失败和客户确认结果；依据通知义务判断是否已经满足。
- 处理迟到、更正、冲突、恢复、重复、跨客户共同原因、已披露内容更正、异常案件关闭与受控重开。

本用例不执行：

- 接收或解释原始监管消息、形成/修改监管决定、关务限制、放行、税费、付款核对、处置执行核对或关务案件生命周期结果。
- 把外部状态码、消息超时、操作员意见、客户投诉或消息渠道结果直接提升为关务事实。
- 因异常信号、严重度、案件建立、客户授权、通知发送或异常关闭自动暂停业务、解除限制、改路、重新申报、执行节点/运输动作或调整费用。
- 把处置请求已发送或被接受解释为源业务动作已经完成。
- 把内部异常案件、调查内容、未确认责任、其他客户范围或受限监管信息直接披露给客户。
- 把通知已生成、已提交或渠道已接受解释为已送达或客户已确认。
- 形成客户赔付、供应商/保险追偿金额、实际收付款、运营核销或法定财务结果。

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 关务输入已接收 | 合法输入进入异常评估 | 来源事实/判断版本、范围、接收和采用依据 | 不得表示异常已经成立 |
| 当前无需异常信号 | 已配置规则未把当前输入识别为风险/偏差 | 采用输入、规则版本、判断时间和范围 | 不得删除历史信号或阻止后续重评 |
| 异常信号已形成/更新 | 当前条件满足版本化异常规则 | 信号类型、对象、发作期、依据、可信度、影响和版本 | 不得自动停单、认责、建案或披露 |
| 信号待分诊 | 可信度、影响、重复关系或资料不足 | 已知边界、缺口和责任入口 | 不得按最严重结果处理 |
| 当前不建案 | 分诊明确当前无需持续案件 | 信号、分诊依据、判断方和复核条件 | 不得等同于信号不存在或问题已解决 |
| 异常案件已关联 | 分诊确认当前信号或输入应由一个既有开放案件持续响应、调查或协调 | 既有案件、信号/输入、关联依据、适用范围和当前响应周期 | 不得重复建立案件、重置响应周期，或把关联解释为问题已经解决 |
| 异常案件已建立 | 分诊确认需要新的持续响应、调查或协调案件 | 根对象、版本化影响范围、责任团队、优先级、响应策略和建立依据 | 不得形成业务限制、责任结论或客户披露 |
| 异常案件已关闭 | 案件内必需动作已完成，且问题已恢复、确认无法恢复、判定不成立或剩余事项已明确移交，形成关闭决定 | 关闭结论、依据、影响范围、未决事项、移交关系、决定方、关闭时间和原响应周期 | 不得修改源事实、解除来源限制、关闭关务案件，或等待索赔、赔付、追偿和结算全部完成 |
| 异常案件已受控重开 | 已关闭案件出现足以影响原结论的新事实，且仍属于同一因果链、责任范围和处置范围，形成新的响应周期 | 新事实、原关闭决定和依据、重开理由、适用范围、决定方式、重开时间及新旧响应周期关系 | 不得覆盖原关闭、重置历史绩效，或自动重开关务案件、限制、委托、路由、面单交易和财务事项 |
| 关联新异常案件已建立 | 新事实属于独立原因、独立责任范围或已经分离的处置范围，建立具有自身身份和生命周期的新案件 | 原案件、新案件、关系类型、拆出范围、建立依据、责任团队和响应策略 | 不得通过重开吸收独立事件，不得修改原案件身份、范围历史或关闭决定 |
| 重复异常案件已受控归并 | 确认案件重复后指定主案件继续处置，重复案件以关闭结论“已归并”关闭并关联主案件 | 主案件、重复案件、重复判断依据、影响范围、未决事项、证据、通知、处置请求和各自响应周期历史 | 不得删除重复案件、把“已归并”实现为第四主状态、重置响应周期或丢失原绩效历史 |
| 处置请求已形成 | 向源上下文提出明确动作和范围 | 目标、动作、对象、原因、依据、时限和请求版本 | 不得表示请求已接受或动作已完成 |
| 处置结果已回接 | 源上下文返回接受/拒绝/部分/待补充或实际结果引用 | 请求、范围、来源结果和剩余责任 | 不得改写源结果或用部分结果关闭整体 |
| 当前暂不披露 | 规则明确当前不适合对客披露 | 客户、范围、依据、复核条件和决定时间 | 不得理解为内部案件不成立 |
| 客户披露待授权 | 已具备候选内容但需要有权角色确认 | 客户、对象、内容草稿、依据、所需授权和时限 | 不得提交生产消息渠道 |
| 客户异常通知已形成 | 对明确客户形成披露决定和内容快照 | 客户、对象范围、披露依据、内容版本、渠道要求、决定方和时限 | 不得表示渠道已接受、已送达或客户确认 |
| 通知义务已满足/未满足/待确认 | 依据合同要求和消息结果形成当前业务判断 | 通知决定、渠道尝试、送达/确认要求、结果与判断版本 | 不得修改异常、关务事实或客户责任 |
| 已有异常/披露处理结果 | 相同请求身份、关务输入版本和业务内容已经形成异常评估、案件协调或披露处理结果 | 原请求、采用输入、信号/分诊/案件/披露结果和当前有效性 | 不得重复形成信号发作期、案件、响应周期、处置请求、披露决定或消息提交意图 |
| 异常/披露请求冲突 | 同一请求身份携带不同客户、关务事实版本、对象范围、案件、处置目标或披露内容 | 原请求、全部冲突内容、已有结果和纠正入口 | 不得按最后到达覆盖、选择任一内容继续，或伪装成未受理或技术未形成 |
| 未受理 | 请求或访问不能合法关联 | 最小原因和纠正入口 | 不得泄露其他客户或受限监管内容 |
| 未形成异常/披露结果 | 技术处理未安全完成 | 请求、失败阶段、已采用输入和恢复引用 | 不得伪装成无需信号、不建案、暂不披露或发送失败 |

同一案件在同一次生命周期决定边界内，`异常案件已关闭`与`重复异常案件已受控归并`互斥；归并时案件主状态仍形成已关闭，“已归并”只作为关闭结论。`异常案件已受控重开`与`关联新异常案件已建立`对不可分范围互斥；同一来源包含可以明确分离的因果、责任或处置范围时，可以逐范围分别形成结果。重开后的主状态必须依据责任承接和当前处理条件确定为待响应或处理中，不设默认状态。

## 主流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---:|---|---|---|
| 1 | 关务异常接入 | 校验主体、租户、法人、客户、关务范围、输入身份和权限 | 未受理时最小披露 |
| 2 | `visibility-exception` | 确认输入由关务所有者接受且当前版本/范围可用 | 原始、待关联或冲突输入不提升为事实 |
| 3 | `visibility-exception` | 按异常规则识别、更新或结束信号发作期 | 形成无需信号、信号或待分诊 |
| 4 | `visibility-exception` | 判断可信度、影响、重复关系、资料和处置必要性 | 不建案、人工复核、关联既有案件或建立新案件 |
| 5 | `visibility-exception` | 固定案件影响范围、责任团队、响应目标和下一行动 | 不修改关务事实或形成限制 |
| 6 | `visibility-exception` → 源上下文 | 对需要业务动作的范围形成处置请求 | 分别等待接受和实际执行结果 |
| 7 | `visibility-exception` | 独立判断客户可见性、敏感范围、披露内容和授权 | 暂不披露、待授权或形成通知决定 |
| 8 | 消息能力 | 对已授权通知执行渠道提交并返回分层结果 | 接受、送达、失败和确认分别回接 |
| 9 | `visibility-exception` | 依据通知要求和渠道结果形成义务判断 | 满足、未满足或待确认；失败按规则恢复/升级 |
| 10 | `visibility-exception` | 处理来源更正、恢复、新影响范围和已披露内容变化 | 新投影/信号/案件判断及追加更正通知 |
| 11 | `visibility-exception` | 依据案件必需动作、当前结论、新事实、因果链、责任范围、处置范围和重复关系处理案件生命周期 | 分别形成关闭、受控重开、关联新案或受控归并；互斥结果逐范围判断，不驱动关务及其他源对象生命周期 |

批量和跨客户共同原因必须逐客户、逐对象及逐披露范围返回结果。内部可以共享一个共同异常案件，但客户可见异常、通知内容和消息结果必须按客户隔离；一项越权、待分诊或发送失败不回滚其他合法结果。

## 一致性、幂等与并发

- 相同请求身份、相同关务输入版本和相同业务内容返回已有结果；相同身份携带不同范围、客户、事实版本或披露内容时形成冲突。
- 同一关务事实经多条交接路径到达时复用事实身份和既有信号/分诊，不重复建立发作期、案件或通知。
- 同一对象、信号类型、因果条件和连续影响期重复命中时更新同一发作期；恢复后再次命中形成关联新发作期。
- 相同案件生命周期请求与相同依据返回已有关闭、重开、关联新案或归并结果；相同请求身份携带不同案件、范围、结论或依据时形成冲突，不重复关闭、建立响应周期、新案或归并关系。
- 关务更正、异常案件关闭和消息投递并发时分别保全各层事实；已经提交或发布的内容不能被静默删除，变化形成追加更正或替代通知。
- 处置请求被接受与源事实更正并发时保留两者，重新判断剩余适用范围；不得把接受结果改写成未发生。
- 结果已形成但发布事件首次失败时只重试同一发布意图，不重复建案、处置请求、披露决定或消息提交。

## 权限、隔离与审计

- 异常规则发布、分诊、自动/人工建案、案件处置、关务处置请求、披露决定、自动发布、人工授权和敏感内容查看分别授权。
- 客户服务、关务、异常运营、系统管理员或消息渠道权限不能互相推导；客户同意不能授权披露其他客户或受限监管信息。
- 内部跨客户案件按责任法人和货主客户账户分区保存影响范围。任何客户视图、通知、导出和错误信息只能包含目标客户授权范围。
- 审计至少关联关务输入及版本、异常规则、信号发作期、分诊、案件/影响范围、责任团队、处置请求、客户/合同/披露规则、通知内容快照、决定方、消息尝试、结果、业务时间和更正关系。
- 日志和技术错误不得记录不必要的监管原因、货物敏感信息、调查细节、其他客户身份或完整通知内容。

## 首发试点约束

- 首发只启用 `PAR-VIS-04` 已登记且能够可靠识别、明确影响对象、具有责任团队和处置路径的关务相关异常类型。
- 自动建案必须满足 `PAR-VIS-05`；未配置或未完成回放/影子验证时进入人工分诊，不采用宽松默认值。
- 响应目标和客户披露分别依据 `PAR-VIS-06/07`。默认通知草稿经授权确认，只有明确批准的严格范围可以自动发布。
- 正常关务事实和试点期间自然发生的异常使用 `P` 证据；不得为验收主动制造监管拒绝、查验、扣留、税费冲突、执行失败或客户恐慌，未自然发生时采用 `R/S`。

## 验收示例

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-VE-001` | `UC-CC-006` 提供已接受、范围明确的关务结果 | 形成关务输入接收，随后按异常规则判断；接收本身不形成信号或案件 |
| `AT-VE-002` | 只有原始监管消息、截图或操作员备注，尚未被关务接受 | 不形成关务事实、异常信号或对客披露，交回关务来源流程 |
| `AT-VE-003` | 只有技术送达/监管接收且不存在适用异常条件 | 形成当前无需异常信号，不把技术层结果解释为失败或清关异常 |
| `AT-VE-004` | 结果待确认但仍在已配置观察窗口内 | 保持观察，不提前形成逾期信号或客户通知 |
| `AT-VE-005` | 结果待确认超过有效观察窗口 | 形成对应可见性/异常信号并进入分诊，不推定拒绝、扣留或遗失 |
| `AT-VE-006` | 两项已接受关务结果冲突且关务尚不能裁决 | 保留冲突引用并形成适用信号；不选择更宽松或更严重来源 |
| `AT-VE-007` | 真实程序正常形成查验决定 | 只有命中已登记异常/客户影响规则时才形成信号或披露；查验不自动等于履约失败 |
| `AT-VE-008` | 扣留或限制只覆盖 P2 | 信号、案件和披露最多覆盖 P2；同单、同袋或同客户其他范围不自动继承 |
| `AT-VE-009` | `UC-CC-008` 形成执行部分覆盖、差异或证据不足 | 形成对应信号/分诊并按需建案，不修改处置核对或声称监管完成 |
| `AT-VE-010` | `UC-CC-009` 形成付款关联冲突或门禁长期未决 | 形成适用信号和协调入口，不修改付款、代垫、回收或放行判断 |
| `AT-VE-011` | `UC-CC-011` 存在当前有效内部合规限制 | 可以形成客户影响信号，但异常案件和通知不能解除限制 |
| `AT-VE-012` | 信号高可信、高影响且命中已生效自动建案规则 | 分别形成`异常案件已建立`或`异常案件已关联`，固定责任团队和响应目标；不自动披露或停单 |
| `AT-VE-013` | 信号资料不足、可能重复或影响不明 | 进入人工分诊，不自动建立案件或按最严重等级处理 |
| `AT-VE-014` | 分诊明确无需持续处置 | 形成当前不建案及复核条件；信号和事实历史继续保留 |
| `AT-VE-015` | 同一条件在连续影响期重复命中 | 更新同一信号发作期，不重复建案、重置响应时间或重复通知 |
| `AT-VE-016` | 信号条件恢复 | 结束发作期并保存依据；关联案件、限制和关务事项不自动关闭 |
| `AT-VE-017` | 同一监管或渠道故障影响多个客户 | 可建立一个内部共同案件并版本化影响范围，不为每个包裹复制共同案件 |
| `AT-VE-018` | 跨客户内部案件覆盖 C1/P1 与 C2/P2 | 两个客户分别形成可见范围和披露判断，互不暴露身份、数量和内容 |
| `AT-VE-019` | 案件需要关务补充查询或重新申报判断 | 形成结构化处置请求；发送、接受和实际关务结果分别保存 |
| `AT-VE-020` | 关务只接受处置请求中的 P1，拒绝 P2 | P1 进入待执行并等待实际关务结果，P2 保留拒绝/续办；不将部分接受汇总为完成或关闭 |
| `AT-VE-021` | 处置请求已接受但尚无实际业务结果 | 保持等待实际结果，不把接受解释为已改路、已重报、已放行或已解除 |
| `AT-VE-022` | 异常案件满足关闭条件，但关务限制、扣留或义务仍有效 | 形成`异常案件已关闭`并只关闭异常协调；关务对象继续按其权威结果有效 |
| `AT-VE-023` | 内部案件已建立但当前披露规则不允许通知 | 形成暂不披露及复核条件，不把案件详情复制给客户 |
| `AT-VE-024` | 客户影响明确且合同要求通知，但需要人工确认 | 形成客户披露待授权和内容草稿，未授权前不提交生产渠道 |
| `AT-VE-025` | 内容包含受限监管原因、其他客户或未确认责任 | 删除或替换为批准的最小披露内容，不能越权发布 |
| `AT-VE-026` | 明确批准范围允许自动发布 | 按适用规则形成通知决定和提交意图，保存自动决定依据；不扩展到其他类型/客户 |
| `AT-VE-027` | 消息渠道接受通知 | 只记录渠道接受；未取得送达证据时通知义务仍按规则待确认或未满足 |
| `AT-VE-028` | 合同要求送达且消息能力返回已送达 | 形成通知义务已满足；不推定客户已阅读、确认或同意责任 |
| `AT-VE-029` | 合同要求客户确认但只有送达结果 | 通知义务保持待确认或未满足，送达不能代替客户确认 |
| `AT-VE-030` | 投递失败后按规则重试或切换渠道 | 保留每次尝试和同一通知意图，不重复形成异常案件或披露决定 |
| `AT-VE-031` | 已发布内容因关务更正需要修改 | 保留原内容，形成追加更正或替代通知，不静默删除历史披露 |
| `AT-VE-032` | 案件关闭后同一因果链、责任范围和处置范围出现足以影响结论的新关务事实 | 形成`异常案件已受控重开`并建立新响应周期；保留原关闭及绩效历史，不自动重开关务案件 |
| `AT-VE-033` | 新事实属于独立原因、责任或处置范围 | 形成`关联新异常案件已建立`；新案拥有自身责任团队和生命周期，不用重开吸收独立事件 |
| `AT-VE-034` | 相同关务事实版本、请求和业务内容重复到达，或同一请求身份携带不同客户、范围、事实版本或披露内容 | 前者形成`已有异常/披露处理结果`；后者形成`异常/披露请求冲突`，不重复信号、案件、处置请求或通知，也不把冲突伪装成未受理或技术未形成 |
| `AT-VE-035` | 关务案件关闭/重开与异常案件关闭/重开交错发生 | 两套生命周期独立保存；任何一方不自动驱动另一方 |
| `AT-VE-036` | 分诊、建案、披露或发布在结果提交前技术失败 | 返回未形成异常/披露结果并保留恢复引用，不伪装成不建案、暂不披露或消息失败 |
| `AT-VE-037` | 分诊发现两个开放异常案件实际属于同一因果链和共同处置范围，且确认其中一个为重复案件 | 形成`重复异常案件已受控归并`：指定主案件继续处置，重复案件以“已归并”结论关闭并关联主案；保留双方编号、范围、证据、通知、处置请求、响应周期和绩效历史，不产生第四主状态 |

## 生产参数与待决风险

- `PAR-VIS-04`：首发关务相关异常类型、可靠来源、影响对象、责任团队和处置路径。
- `PAR-VIS-05`：分诊、去重、发作期和自动建案规则及回放/影子证据。
- `PAR-VIS-06`：首次响应、下一行动、客户更新和解决目标。
- `PAR-VIS-07`：披露条件、敏感范围、模板、渠道、通知义务、人工/自动授权和更正规则。
- `PAR-CUS-01..07`：真实关务程序、结果语义、处置、付款、案件和限制范围。
- `PAR-INT-06`：客户异常通知渠道及渠道接受、送达、失败和确认结果层。
- `PAR-NFR-06`：异常评估、消息新鲜度、批量和恢复目标。

真实值未确认前，不得预建默认异常类型、观察窗口、严重度、自动建案阈值、客户披露内容、通知时限、渠道优先级或重试次数。

完成本用例只证明关务已接受事实能够被异常上下文安全消费，形成独立的协调和客户披露决定，并正确解释消息渠道结果。监管决定、关务限制、物理执行、金额和消息投递事实仍由各自所有者形成。

# UC-VE-002 接收事实并形成全程追踪投影

状态：稳定业务骨架待实现；真实来源覆盖、映射版本和冲突样本待提供

## 目标与边界

本用例从各源上下文提交已经接受、范围明确且可追溯的事实或有效性变化开始，到 `visibility-exception` 形成标准追踪里程碑、物流/控制/关务/交付等维度投影和摘要，或明确返回重复、冲突、未归类、待补充或未形成结果为止。

本用例不接受原始报文、截图、自由备注或客户意见为事实，不修改源事实、路由、节点、运输、关务、交付、包裹终局或费用，也不形成 ETA、异常案件、客户通知或普通客户查询结果。客户全程追踪视图由 [`UC-VE-008`](./UC-VE-008-PROVIDE-CUSTOMER-END-TO-END-TRACKING-VIEW.md) 在本投影之上按客户账户和对象授权形成。

## 主流程

1. 保全来源身份、原始引用、对象范围、业务时间、有效时间和接收时间。
2. 校验来源上下文已接受事实，并按 `parcel-shipment` 核对永久身份、外部标识版本和谱系。
3. 选择当前适用的事实映射版本；没有可靠映射则形成未归类。
4. 按事实类型、权威范围、业务时间、有效时间和因果顺序分别派生各维度，不压缩成单一状态。
5. 对重复、迟到、更正和冲突形成追加版本。更正按源上下文给出的替代关系登记，被替代条目保留但不参与派生。替代链分叉一律无法裁决（[ADR-0245](../../adr/0245-a-forked-supersession-chain-is-never-ordered-by-business-time-and-stays-pending-in-the-projection-version.md)）：前身与各后继留在投影版本内、标明分叉关系、不参与派生，那一条事实流保持待确认；跨源或跨事实引用的冲突无法裁决时同样保持待确认；都不按最后消息覆盖。
6. 返回投影已形成、部分、未归类、冲突、已有结果、入账不派生或未形成结果，供 ETA、异常和客户全程追踪视图用例消费。

## 规则、权限与隔离

- 不能建立全局来源排名；裁决必须引用事实类型、控制范围、时间和源上下文权威范围。
- 集运、同批或共同来源不合并包裹身份；拆分/合并沿 `parcel-shipment` 谱系继续投影。
- 外部不透明履约段只展示已知入口、出口和实际获得的里程碑，不虚构伙伴内部节点。
- 跨客户投影按客户账户和责任法人隔离；共同来源事故不泄露其他客户对象或数量。
- 投影规则版本变化不得删除原映射、原判断或已发布客户信息。

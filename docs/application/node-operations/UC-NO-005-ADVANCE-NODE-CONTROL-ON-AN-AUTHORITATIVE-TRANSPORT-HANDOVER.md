# UC-NO-005 按权威运输交接推进节点控制

状态：转出一半已实现（票 demo-chain-gaps/61）；转入一半已定、待票 demo-chain-gaps/62 实现；集运单元的交接与控制来源链重算的处置面待后继票

## 目标与边界

本用例从 `transport-fulfillment` 登记一版权威运输交接开始，到 `node-operations` 依据这一版推进作业实物的节点控制、或入账说明为什么不推进为止。机制与取舍以 [ADR-0214](../../adr/0214-node-control-transfers-out-and-in-on-an-authoritative-transport-handover.md) 为准，本用例只组织输入、结果、流程与验收。

「权威运输交接」指 `transport-fulfillment` 针对明确载运对象形成的交接判断（`已交接`、`已拒收`、`待确认`）。它不是 [UC-NO-006](./UC-NO-006-ESTABLISH-A-VERIFIABLE-DELIVERY-SCOPE.md) 的「送站交接单」：后者是客户送站时节点开立的单据，用来成立可验证交付范围，与控制转移无关。

本用例包含：

- 把交接对象（正式包裹身份或集运单元）对上本上下文的作业实物。
- 交出节点那一侧的控制转出（转出一半）。
- 接收节点那一侧的控制成立（转入一半，票 demo-chain-gaps/62）。
- 交接更正对已推进控制的处理：不回退，入账待重算。
- 节点控制转移册的落册与查阅。

本用例不执行：

- 形成或更正权威运输交接本身：它属 `transport-fulfillment`（[UC-TF-005](../transport-fulfillment/UC-TF-005-ESTABLISH-HANDOVER-AND-ACTUAL-FULFILLMENT.md)）。
- 客户直接送站形成的节点收寄与控制：它属 [UC-NO-002](./UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md)。
- 节点侧交出扫描、装载与点验：它们是节点侧证据，不转移控制（[UC-NO-003](./UC-NO-003-PROCESS-CONSOLIDATE-AND-SEAL-PARCELS.md)）。
- 集运单元的单元控制与成员「随单元受控」：规则未立，本用例对集运单元只入账。
- 控制来源链的重算与处置：本用例只入账「待重算」。
- 路由复核：交接触发的复核属 `network-routing`。

## 参与者与协作

| 参与者或上下文 | 本用例职责 | 明确不负责 |
|---|---|---|
| `transport-fulfillment` | 形成交接判断，交出引用式信封；按键提供那一版与它的后继 | 不知道节点控制怎样推进 |
| 派发进程 | 把交接登记信封扇出给 NO 这一路 | 不判控制 |
| `node-operations` | 认交接对象，取实物锁，判转出或入账，落转移册；读控制时折叠转出 | 不改写交接结果，不改写收寄判断 |
| 运营查阅者 | 在查阅口看转移册，含入账不推进的各格 | 本用例里没有处置入口 |

## 启动条件

- 交接登记信封已入派发进程的 outbox；NO 这一路已装在派发进程里。
- 作业实物经 UC-NO-002 的收寄（或本用例转入一半）在某个节点有过控制。没有也照常运行，入账「无在身控制」。
- 不需要任何租户取值。

## 输入语义契约

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |
|---|---|---|---|
| 交接键 | 交接登记信封 | 租户、载运对象、交接范围、结果版本 | 四维缺一即毒丸；只用来读回那一版，信封里别的格不读 |
| 交接判断 | `transport-fulfillment` 交接登记册 | 裁决；`已交接`时的转出引用；交接的业务时间；有没有被同链后一版更正 | 按四维键读，必须带版本 |
| 作业实物 | 本上下文收寄册 | 此刻关联到交接对象这件正式包裹的作业实物 | 只读各条判断链的当前有效版本上的关联 |
| 在身控制 | 收寄册与转移册 | 这件实物此刻在身的各份控制 | 读前取实物锁，经折叠读 |

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 控制已转出 | `已交接`，对上一件作业实物，它恰有一份在身控制，交接不早于它成立 | 转移册一行：交接键、方向 OUT、被转出的那一份控制（节点、来源、依据、成立时刻）、转出引用、转出时刻（交接的业务时间）、记录时刻 | 改写收寄行；把控制交给接收方（那是转入一半） |
| 入账不推进 | 对不上一件作业实物（零件、多件、集运单元），或对上了却没有、不止一份在身控制，或交接早于在身控制成立 | 原因；对上了的带作业实物；交接早于控制成立时带那一份控制 | 猜一件实物、挑一份控制、一并转出 |
| 控制来源链待重算 | 同链前版转出过控制，这一版把它更正成了拒收或待确认 | 原因与先前那次转出 | 把控制回退给交出方 |
| 已在册 | 同一版在同一方向上已有一行 | 交回那一行 | 第二行 |
| 零写入 | 拒收、待确认（同链没转出过）；后继版仍`已交接`而前版已转出；这一版已被后一版更正 | 无 | 任何转移行 |
| 未决 | 交接登记册读不动或还读不回 | 无 | 按信封猜裁决 |

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 派发进程 | 交接登记信封扇出到 NO 这一路；消费门按 inbox 认重复 | 重复跳过；毒丸拒收入账 |
| 2 | `node-operations` | 按四维键读回那一版，问它有没有后继 | 读不动或读不回：未决重投；已被更正：零写入 |
| 3 | `node-operations` | 这一版在转出方向上已有一行 | 交回已在册 |
| 4 | `node-operations` | 不是`已交接`：同链前版转出过则入账待重算，否则零写入 | 结束 |
| 5 | `node-operations` | `已交接`：同链前版转出过则零写入；否则认交接对象 | 集运单元、零件、多件：入账不推进 |
| 6 | `node-operations` | 对上一件：取实物锁，读它此刻在身的各份控制，锁下再认一次更正链 | 前版在锁外刚转出：零写入 |
| 7 | `node-operations` | 按领域判：转出，或入账（无在身控制、不止一份、交接早于成立） | 落转移册一行 |
| 8 | `node-operations` | 转移行与消费门的已处理同笔提交 | 投递失败只重投同一封信 |

转入一半（票 demo-chain-gaps/62）：`已交接`且交接声明了接收节点时，对上作业实物后在接收节点立 HANDOVER_IN 控制，落同一本转移册（方向 IN）；对不上就入账，不造待识别实物；没声明接收节点就不立。

## 读控制

- 收寄行的控制不改写。按键读回收寄、认当前收寄（UC-NO-002 据它判并入）与查阅目录，都把转移册上的转出折进去读。
- 转出之后同一件实物再送到同一节点，不再并入旧收寄，而是形成新的收寄与控制起点。

## 一致性、幂等与并发

- 重放身份是（租户，交接对象，交接范围，交接版本，方向），由交接登记册指名。
- 读在身控制前取的实物锁，与收寄认当前收寄是同一把：同一件实物的转出与送站串在一起，两份交接并发到达只转出一次，后到的一方入账「无在身控制」。
- 一份控制至多转出一次，库面再守一遍。
- 同一条更正链按（对象，范围）认。

## 权限、隔离与审计

- 没有人工入口：触发只来自交接登记信封。查阅口沿用节点作业查阅页的操作者渠道读权限。
- 全部读写带租户；跨租户的交接键读不回。
- 转移册永久保留，推进的与没推进的同册列出（`/node-operations-records?registry=physical-control`）。

## 首发试点叠加条件

- 不需要租户取值。合成 `S` 证据走演示租户 `SYN-TENANT-01` 的一次性库。
- 集运单元整袋交接是常态时，转出停在入账，直到单元控制规则立起来（后继票）。

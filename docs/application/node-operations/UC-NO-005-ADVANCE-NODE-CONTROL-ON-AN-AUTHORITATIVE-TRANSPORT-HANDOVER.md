# UC-NO-005 按权威运输交接推进节点控制

状态：转出一半已实现（票 demo-chain-gaps/61）；转入一半与交出节点声明不符的信息格已实现（票 demo-chain-gaps/62）；集运单元的交接、控制来源链重算的处置面、对不上作业实物的转入对账与收寄认转入控制待后继票

## 目标与边界

本用例从 `transport-fulfillment` 登记一版权威运输交接开始，到 `node-operations` 依据这一版推进作业实物的节点控制、或入账说明为什么不推进为止。机制与取舍以 [ADR-0214](../../adr/0214-node-control-transfers-out-and-in-on-an-authoritative-transport-handover.md) 正文与文末「补记：票 62 落决定七时的补充裁定」为准，本用例只组织输入、结果、流程与验收。

「权威运输交接」指 `transport-fulfillment` 针对明确载运对象形成的交接判断（`已交接`、`已拒收`、`待确认`）。它不是 [UC-NO-006](./UC-NO-006-ESTABLISH-A-VERIFIABLE-DELIVERY-SCOPE.md) 的「送站交接单」：后者是客户送站时节点开立的单据，用来成立可验证交付范围，与控制转移无关。

本用例包含：

- 把交接对象（正式包裹身份或集运单元）对上本上下文的作业实物。
- 交出节点那一侧的控制转出（转出一半）。
- 接收节点那一侧的控制成立（转入一半，票 demo-chain-gaps/62）。
- 交接更正对已推进控制的处理：不回退，入账待重算。
- 节点控制转移册的落册与查阅。

本用例不执行：

- 形成或更正权威运输交接本身：它属 `transport-fulfillment`（[UC-TF-005](../transport-fulfillment/UC-TF-005-ESTABLISH-HANDOVER-AND-ACTUAL-FULFILLMENT.md)）。
- 客户直接送站形成的节点收寄与控制：它属 [UC-NO-002](./UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md)。
- 节点侧交出扫描、装载与点验：它们是节点侧证据，不转移控制（[UC-NO-003](./UC-NO-003-PROCESS-CONSOLIDATE-AND-SEAL-PARCELS.md)）。
- 集运单元的单元控制与成员「随单元受控」：规则未立，本用例对集运单元只入账。
- 控制来源链的重算与处置：本用例只入账「待重算」。
- 路由复核：交接触发的复核属 `network-routing`。

## 参与者与协作

## 启动条件

- 交接登记信封已入派发进程的 outbox；NO 这一路已装在派发进程里。
- 作业实物经 UC-NO-002 的收寄（或本用例转入一半）在某个节点有过控制。没有也照常运行，入账「无在身控制」。
- 不需要任何租户取值。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 控制已转出 | `已交接`，对上一件作业实物，它恰有一份在身控制，交接不早于它成立 | 转移册一行：交接键、方向 OUT、被转出的那一份控制（节点、来源、依据、成立时刻）、转出引用、转出时刻（交接的业务时间）、记录时刻；声明的交出节点不是那一份的节点时另记声明的那一个 | 改写收寄行；把控制交给接收方（那是转入一半）；因交出节点不符而不转 |
| 控制已转入 | `已交接`且声明了接收节点，对上一件作业实物，它没有在身控制，最近一次转出不晚于这一版 | 转移册一行：交接键、方向 IN、在接收节点立起的 HANDOVER_IN 控制（依据由交接键铸出、成立时刻取交接的业务时间）、记录时刻 | 造待识别实物；在实物仍有在身控制时另立一份 |
| 入账不推进 | 对不上一件作业实物（零件、多件、集运单元）；转出一侧对上了却没有、不止一份在身控制，或交接早于在身控制成立；转入一侧对上了却仍有在身控制，或最近一次转出晚于这一版 | 方向与原因；对上了的带作业实物；交接早于控制成立时带那一份控制 | 猜一件实物、挑一份控制、一并转出、另立第二份 |
| 控制来源链待重算 | 同链前版在这个方向推进过控制，这一版把它更正成了拒收或待确认 | 方向、原因，与先前那次转出或先前立起的那一份控制 | 把控制回退给交出方；撤掉转入立起的控制 |
| 已在册 | 同一版在同一方向上已有一行，含这一版此后被同链后一版更正、并发里同一版另一方先落了行 | 交回那一行 | 第二行；把这一版自己的推进行认成「前版已转出」 |
| 零写入 | 拒收、待确认（同链在这个方向没推进过）；后继版仍`已交接`而前版在这个方向已推进；这一版已被后一版更正、自己没有行；转入一侧没声明接收节点 | 无 | 任何转移行 |
| 未决 | 交接登记册读不动或还读不回 | 无 | 按信封猜裁决 |

## 读控制

- 收寄行的控制不改写。按键读回收寄、认当前收寄（UC-NO-002 据它判并入）与查阅目录，都把转移册上的转出折进去读。
- 转入立起的控制只在转移册上。读一件实物在身的控制时，收寄行上的与转入立起的一起读、同样折叠；它被此后的交接转出时，转出行按同一份控制依据指着它。
- 转出之后同一件实物再送到同一节点，不再并入旧收寄，而是形成新的收寄与控制起点。

## 一致性、幂等与并发

- 重放身份是（租户，交接对象，交接范围，交接版本，方向），由交接登记册指名。
- 读在身控制前取的实物锁，与收寄认当前收寄是同一把：同一件实物的转出与送站串在一起，两份交接并发到达只转出一次，后到的一方入账「无在身控制」。
- 一份控制至多转出一次，库面再守一遍。
- 同一条更正链按（对象，范围）认；认「前版转出过」不算这一版自己。
- 撤回控制的更正不取实物锁，靠同一对象的交接信封同分区排队：前版的推进行在这一版开读之前已经提交（ADR-0214 决定五）。
- 转入与转出取的是同一把实物锁，同一笔里先后各取一次；同一件实物两次交进不同节点并发到达时，最后在身的只有一份。
- 一次交接不转出它自己立起的控制：后继版仍`已交接`时重判转出，同链转入立起的那一份不在候选里。
- 入账不推进各格不重投，前提是收寄先于交接到达。收寄晚于交接到达时那一格永久留着，不靠重投补（ADR-0214 越权风险点「收寄晚于交接到达」，处置面随后继票）。

## 权限、隔离与审计

- 没有人工入口：触发只来自交接登记信封。查阅口沿用节点作业查阅页的操作者渠道读权限。
- 全部读写带租户；跨租户的交接键读不回。
- 转移册永久保留，推进的与没推进的同册列出（`/node-operations-records?registry=physical-control`）。

## 首发试点叠加条件

- 不需要租户取值。合成 `S` 证据走演示租户 `SYN-TENANT-01` 的一次性库。
- 集运单元整袋交接是常态时，转出停在入账，直到单元控制规则立起来（后继票）。

| `AT-NO-122` | 转入之后同一交接被更正成拒收（节点之间直接交接时两侧都推进过） | 两个方向各入账「控制来源链待重算」，转入一侧带先前立起的那一份；控制不回退，立起的不撤 |
| `AT-NO-123` | 查阅节点控制转移册上的转入与信息格 | 转入行带控制四件、不带转出两件；推进了的转出在交出节点不符时带 `mismatchedReleasingNode`，相符时整键不出现 |
| `AT-NO-124` | 同一件实物两次交进不同节点的`已交接`并发到达 | 实物锁把两路串起来；不论谁先到，最后在身的只有一份，是业务时间晚的那一次立的 |
| `AT-NO-125` | 一件包裹经节点收寄、交进下一个节点、交给运输方、再交进下一个节点 | 每一步转移册各落其行，最后在身的只有最后那个节点立起的一份；最初那条收寄读出已转出 |

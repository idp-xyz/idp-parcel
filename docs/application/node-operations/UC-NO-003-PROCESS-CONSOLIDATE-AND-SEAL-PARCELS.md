# UC-NO-003 执行正常节点作业、集运与封签

状态：稳定业务骨架已形成；真实作业清单、设备、规则、权限和非功能参数待提供

## 目标与边界

本用例从物流节点已经对明确作业实物取得控制开始，到节点完成适用的识别、位置、扫描、测量、状况记录、分拣、集运、封装和封签作业，并形成可供后续运输交接使用的节点侧证据为止。

本用例是国际小包网络的场站作业，不是完整 WMS。节点掌握实物控制、作业位置和集运成员关系，但不形成商品库存、库存可用量、库存价值、补货、拣货波次或库存调整。

本用例包含：

- 为明确对象和动作形成作业任务，并使用作业批次组织执行。
- 保存每次不可覆盖的扫描、测量、位置和状况来源事实。
- 派生当前有效实测和当前位置，并把实测变化交路由复核。
- 在当前有效路由指令和集运兼容判断下执行方向性分拣与实际集运。
- 建立集运单元实例、成员关系、封装成员快照和封签记录。
- 受控开封、成员变化、重新封装和换签时保留全部历史。
- 为后续运输交接提供备货、点验、装载或交出侧证据。

本用例不执行：

- 节点收寄或运输方到站时的权威交接结论；节点收寄见 [`UC-NO-002`](./UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md)。
- 正式包裹身份、包裹谱系、客户承诺或终局服务结果。
- 路由计划、改路决定、集运兼容判断或路由指令。
- 班次、容量、订舱、装载分配、权威运输交接、实际移动或交付。
- 正式关务申报、监管授权、异常责任、计费重量或费用。

## 启动条件

- 节点已经通过客户直接收寄或权威运输交接取得明确实物控制。
- 作业实物具有稳定身份；正式包裹尚不能确认时使用待识别实物，不创建临时包裹。
- 每项任务能够引用节点、对象、动作、范围和当前有效依据。
- 方向性作业必须取得当前有效路由指令；集运还必须取得成员级集运兼容判断。
- 设备、测量、身份、分拣、集运和封签真实规则未配置时，只运行稳定骨架或受控 `R/S`。

没有当前有效路由不阻止接收、隔离、状况记录、测量和在场核对。它必须阻止分拣到下一方向、面向下一段的集运、集包出运、装载和交出。

## 作业阶段

### 1. 识别、位置与安全作业

- 对每件现场可区分实物建立或关联作业实物。身份未知或冲突时继续使用待识别实物。
- 保存到达观察、扫描、状况和位置事实；任何一项都不能单独修改正式身份或控制。
- 无有效方向依据时，只允许接收、隔离、状况记录、测量、在场核对和其他必要安全动作。
- 已取消或终局实物的服务结果不被现场事实重开；退回、销毁、移交或其他处置等待明确决定。

### 2. 测量与路由复核

- 每次重量、尺寸、数量或其他测量都保存对象、单位、设备/来源、发生时间、位置和依据。
- 更正、校准问题或无效判断通过关联事实表达，不覆盖原测量。
- 当前有效实测按已登记规则派生，并提交 [`UC-NR-003`](../network-routing/UC-NR-003-REASSESS-ROUTE-AFTER-NETWORK-INTAKE.md) 复核当前路线。
- 客户声明、正式申报资料、客户计费重量和供应商计费重量均不得写回节点实测。

### 3. 分拣与集运

- 方向性分拣必须引用当前有效路由指令；指令失效后停止尚未执行范围。
- 拟组合包裹必须先取得 `network-routing` 的成员级集运兼容判断。部分成员不兼容不回滚其他合格成员。
- 兼容判断只允许执行，不自动建立成员。实际移入才形成集运成员关系。
- 每个作业实物同一时点最多一个直接物理父级，全部包含链无循环。
- 作业批次只组织任务，不取得成员、控制、位置或运输责任。

### 4. 封装、开封与重封

- 封装时冻结当时直接成员快照并形成封签记录。
- 封装后变化成员必须先形成授权开封，再保存移入/移出并重新封装；新快照和封签不覆盖旧历史。
- 封签缺失、破损或不一致降低批量证明力，不能依据原快照推导成员已经到站或随单元受控。
- 集运单元全部成员移出或剩余成员已有明确处置后才能终局关闭；关闭实例不得重开或复用。
- 可复用袋、笼、箱或托盘再次使用时创建新集运单元实例。

### 5. 交接准备

- 节点可以形成备货、点验、物理装载、交出扫描等节点侧证据。
- 节点侧证据不等于装载分配、权威运输交接、出发或实际移动。
- PN-04 的 `transport-fulfillment` 必须基于同一对象范围形成唯一权威交接结果；已拒收或待确认不转移控制。

## 一致性、幂等与并发

- 同一来源身份和内容返回已有事实；同一身份不同内容形成冲突，不按最后扫描覆盖。
- 每次测量、位置、成员变化、封装、开封和封签都有独立事实身份；业务重试不得重复形成。
- 同一对象同一时点最多一个直接物理父级；并发移入不同单元只能一个成功，另一方读取冲突。
- 封装与成员变化并发时，只有一个成员版本进入快照；未纳入变化必须形成后续开封/重封或冲突。
- 路由变化与分拣并发时按路由指令生效边界裁决；已经发生的错误分拣保留为事实并形成偏离，不回写为未发生。
- 任务取消或被替代只停止尚未执行范围；已发生事实永久保留。
- 结果提交不确定时按稳定来源、任务、对象和单元查询，不盲目重做物理动作。

## 权限、隔离与审计

- 任务、开封、重封、标签和处置必须在明确节点、对象、动作和授权范围内执行。
- 普通节点角色不能修改正式包裹身份、客户资料、路线、监管决定、异常责任或计费重量。
- 多客户包裹可以在规则允许时物理集运，但客户身份、合同、可见数据、申报资料和结算责任保持隔离。
- 审计至少关联控制、作业实物、正式身份或候选、任务、批次、来源、设备、测量、位置、路由指令、兼容判断、成员、快照、封签、执行方、授权和发布状态。
- 日志、标签和指标只包含作业所需最小信息，不把跨客户货物和申报明文暴露给非授权岗位。

## 首发试点叠加条件

- `PAR-NET-04..06` 必须提供真实节点顺序、自营节点、作业清单、控制边界、数据来源、设备与校准、待识别隔离、测量、分拣、集运和封签证据规则。
- `PAR-NET-14` 提供路由复核、指令生效和集运兼容规则。
- `PAR-COM-02` 仅用于跨客户集运隔离模拟；真实客户数据不能作为测试便利数据。
- `PAR-NFR-02/03/04/06` 提供包裹量、集运规模、扫描放大和节点流程目标。
- `PAR-COM-13` 只在接受后客户资料变化影响作业时消费；客户新资料不能覆盖节点实测。
- 真实参数未确认时可以实现任务/事实分层、不可覆盖测量、位置派生、无路由安全分支、成员不变量和封装版本骨架；不得配置默认设备精度、重量阈值、分拣口、袋型、封签规则或作业时限。

| `AT-NO-040` | 已关闭集运单元或同一载具再次使用 | 原实例不重开；新使用创建新实例 |
| `AT-NO-041` | 客户资料值与节点实测不同 | 两者分别保留，下游独立判断，不做覆盖对平 |
| `AT-NO-042` | 已取消或终局包裹仍在节点 | 如实作业和控制，不恢复服务；方向性处置等待授权 |
| `AT-NO-043` | 同一来源事实重复或内容冲突 | 重复返回原结果；冲突保留双方并停止自动派生 |
| `AT-NO-044` | 路由变化与旧指令下分拣并发 | 保留实际分拣，形成偏离并停止旧指令未来授权 |
| `AT-NO-045` | 节点完成备货、点验和物理装载 | 只形成节点侧证据，不形成权威交接、出发或实际运输 |
| `AT-NO-046` | 跨客户集运隔离模拟 | 物理成员可共存，客户资料、责任、查询和审计保持隔离 |

## 给开发的交接

实现必须分别表达作业任务、作业批次、来源事实、有效作业事实、当前实测/位置、集运单元、成员关系、封装快照和封签记录。一个通用 `warehouse_status`、库存表或可覆盖成员清单不能满足本用例。

当前代码没有 `node-operations` 模块、设备接入、作业持久化或事件闭环。可以先实现对象身份、不变量、显式未配置和纯业务场景；真实生产写入必须等待节点参数、路由端口和技术门槛。

完成本用例只到节点侧交接准备。节点与运输方之间的唯一权威交接、班次、容量、实际履约和移动继续由 PN-04 负责。

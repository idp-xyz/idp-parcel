# UC-NO-001 承接并执行节点监管协作

状态：开发基线草案；节点承接、作业任务、现场执行事实和关务回接边界已形成，真实监管程序的动作、执行方、授权和证据参数待提供

## 目标与边界

本用例从 `node-operations` 收到 `UC-CC-008` 针对明确节点、对象、范围和动作形成的当前有效关务执行协作事项开始，到节点逐范围形成承接结果，依据已承接范围形成作业任务并保存实际执行事实，向关务回接稳定事实引用，或者明确形成待补充、拒绝、冲突、未受理或未形成结果为止。

本用例包含：

- 校验协作事项、来源决定引用、对象、动作、节点、责任范围、当前有效性及节点执行授权。
- 按节点实际控制、在场范围、作业能力和授权逐对象形成已承接、部分承接、待补充或拒绝结果。
- 对已承接范围形成节点作业任务，固定对象、动作、范围、节点和作业依据。
- 保存开封、呈验、隔离、测量、清点、观察、重封、保管移交、销毁、退运装载和节点侧交出等实际执行事实。
- 依据当前有效事实逐对象派生任务完成、部分完成或未完成，不以操作按钮形成完成。
- 将承接结果、任务和执行事实的稳定引用回接 `UC-CC-008`，由关务形成处置执行核对。
- 处理重复、冲突、迟到、更正、取消、替代、部分执行及发布恢复，保留全部历史。

本用例不执行：

- 接收、解释、形成、更正或解除监管查验、扣留、放行或处置决定。
- 创建或修改关务执行协作事项、处置执行核对、内部合规限制或关务案件结果。
- 把协作事项、承接决定、任务建立、任务完成、隔离、位置变化或执行方备注解释为监管结果或监管义务终结。
- 形成运输委托、订舱、承运接受、权威运输交接、实际移动、退运到达或原旅程回退。
- 修改包裹身份、客户资料、正式申报资料、路由计划、费用、异常责任或客户通知。

节点承接只表示节点在明确范围内接受现场作业责任；节点执行事实只表达现场实际做了什么。是否覆盖监管决定要求仍由 `UC-CC-008` 核对，监管决定是否变化仍由外部监管结果流程拥有。

## 启动条件

- 协作事项已经由 `UC-CC-008` 形成，能够引用已接受的当前监管决定及明确对象、动作、范围、来源和当前有效性。
- 目标节点、作业实物或正式对象关联能够被节点合法识别；无法可靠识别的现场实物仍按待识别实物规则管理，不能为完成协作而强行认领包裹身份。
- 节点责任法人、执行角色、作业能力和适用授权可以校验。普通节点登录、异常处理或管理员权限不能代替开封、销毁、移交等动作授权。
- 对象尚未在场、控制关系待确认、授权依据缺失或真实程序要求的作业条件不足时，可以形成待补充或待执行结果，不创建虚假执行事实。
- 在不可逆动作实际开始前重新确认采用的协作事项版本仍为当前。依赖不可用时暂停尚未执行范围，不按旧缓存继续销毁、移交或退运装载。

## 结果语义契约

| 结果 | 业务含义 | 必须返回或可查询的依据 | 禁止行为 |

| 节点协作已承接 | 节点在明确范围内接受现场作业责任 | 协作事项、对象、动作、范围、节点、责任角色、授权和续办引用 | 不得表示任务已完成或监管义务终结 |
| 节点协作部分承接 | 只有部分对象或动作具备承接条件 | 已承接范围、未承接范围、逐项原因和续办入口 | 不得用整批状态吞并未承接范围 |
| 节点协作待补充 | 请求可合法关联，但必要对象、动作、授权或作业条件不足 | 已知范围、缺口、责任方和补充入口 | 不得创建占位执行事实 |
| 节点协作已拒绝 | 节点依据明确责任、能力、安全或范围规则不承担相应作业 | 被拒范围、业务依据、决定角色和时间 | 不得把技术失败或暂时不可用伪装成拒绝 |
| 节点作业任务已形成 | 已承接范围获得明确节点工作指令 | 对象、动作、范围、节点、作业依据、任务版本和执行授权 | 不得表示动作已经发生 |
| 节点执行事实已形成 | 节点保存实际发生的动作、观察和证据 | 对象、实际范围、动作、业务时间、位置、执行角色、来源和任务引用 | 不得直接形成关务核对或解除结果 |
| 节点任务部分完成或未完成 | 当前有效事实只覆盖部分任务，或明确动作未能执行 | 已执行范围、剩余范围、失败/未执行事实及当前任务版本 | 不得把剩余范围隐藏在任务汇总中 |
| 当前剩余范围已停止 | 协作事项取消、替代或范围收缩后停止尚未执行动作 | 新旧事项、停止范围、生效时间和已发生事实 | 不得删除任务、执行事实或反向恢复实物 |
| 节点协作冲突 | 同一请求身份或当前范围存在无法裁决的事项、动作或版本冲突 | 全部冲突输入、既有结果和复核入口 | 不得按最后到达选择 |
| 节点协作未受理 | 主体、租户、法人、客户、节点、事项、对象或权限不能合法关联 | 最小校验依据、原因、时间和责任交接 | 不得泄露越权对象是否存在 |
| 节点协作结果未形成 | 技术处理未安全完成 | 请求、失败阶段、已有结果和恢复引用 | 不得伪装成拒绝、待补充、任务失败或执行完成 |

## 承接与执行规则

- 节点按不可再分的对象和动作范围形成承接结果。同一请求可以部分承接，但每个范围只能有明确当前结果，批量汇总不能覆盖逐项结果。
- 协作事项必须指向节点能够合法处理的现场动作。查验、扣留和处置按关务来源语义保持区分；节点不能因为都包含“隔离”或“移交”而将它们合并。
- 查验协作可以形成开封、呈验、观察和重封事实，但节点观察不是监管查验结论。扣留可以形成控制、隔离和保管移交事实，但任何节点事实都不能解除扣留。
- 销毁、监管移交、退运装载或其他不可逆动作必须具有当前有效、对象和范围明确的授权。事项有效但节点不具备责任、能力或安全条件时，形成拒绝或部分承接，不通过人工备注绕过。
- 节点承接、任务形成、执行开始、部分执行、失败事实和任务结果分别保存。任务完成只由当前有效执行事实派生，不由计划时间、页面按钮或执行人员声明单独形成。
- 节点实际销毁、清点或移交只记录实际对象与数量。事实少于、超过或不匹配请求范围时如实保存，由 `UC-CC-008` 形成处置执行核对；节点不能补齐数字或替换对象使其相等。
- 物理装载、节点侧交出或接收观察仍是节点事实；跨节点或运输方的控制转移只能由 `transport-fulfillment` 的权威交接结果形成。
- 节点基于现场安全形成的必要隔离或紧急动作按其真实授权记录。若并非依据当前关务协作事项执行，不能事后归入该事项以制造监管执行覆盖。
- 协作事项被取消、替代或缩小范围时，停止未开始或尚可停止的范围；已经发生的开封、销毁、移交、装载及其他事实继续保留，并回接关务重新核对。
- 来源事实迟到、更正、失效或冲突时保留原事实和原任务判断，形成新的有效事件及任务结果版本，不按最后消息覆盖。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 节点协作接入 | 校验请求主体、租户、法人、客户、节点、协作事项和对象范围 | 越权或无法关联时未受理；不读取越权对象 |
| 2 | `node-operations` / `UC-CC-008` | 确认事项当前有效、动作与范围明确，识别重复、替代和冲突 | 重复返回已有结果；冲突保持；失效事项不新建任务 |
| 3 | `node-operations` | 核对对象关联、在场、控制、节点能力、责任和承接授权 | 逐范围形成已承接、部分承接、待补充或拒绝 |
| 4 | `node-operations` | 为已承接范围固定作业任务、动作、节点、依据和执行授权 | 形成任务；不形成执行事实 |
| 5 | 节点现场执行角色 | 按当前任务执行现场动作并保全来源事实 | 逐对象形成完整、部分、失败、冲突或更正事实 |
| 6 | `node-operations` | 校验来源事实并形成有效作业事件，派生任务结果 | 形成完成、部分完成或未完成；不形成关务核对 |
| 7 | `transport-fulfillment` | 对涉及控制跨边界转移的范围形成权威运输交接与后续移动事实 | 节点只保留装卸和节点侧证据 |
| 8 | `node-operations` | 发布承接、任务和执行事实的稳定引用 | `UC-CC-008` 接收后按监管决定形成核对 |
| 9 | `UC-CC-008` / `visibility-exception` | 对部分覆盖、差异、事实冲突、证据不足或长期未决继续处理 | 不反向修改节点事实，不以异常关闭完成监管义务 |

## 最小业务提交边界

- 节点承接决定、采用的协作事项版本、对象/动作范围、责任与授权、任务、实际事实、任务结果、审计和发布意图必须形成可恢复的受保护业务结果。
- 承接成功但任务形成失败时保留承接及恢复引用，不以新请求身份重复承接。
- 实际事实已经保存但任务派生或发布失败时保留事实，从同一事实恢复；不得要求现场重复执行不可逆动作。
- 结果提交成功但首次发布失败时只重试同一发布意图，不重复创建任务、执行动作或重置业务时间。

## 一致性、幂等与并发

- 同一协作事项版本、对象、动作、范围和请求身份重复到达时返回已有承接、任务和当前执行结果。
- 同一请求身份携带不同事项版本、对象、动作、节点或范围时形成冲突，不按最后到达覆盖。
- 同一现场事实通过设备、人工或外部节点来源重复到达时按来源身份、业务语义和适用时间去重，不重复累计数量或完成范围。
- 两个任务并发覆盖同一不可并行对象或互斥动作时保留双方请求并形成冲突；未获裁决前不重复执行。
- 协作事项更正、取消或替代与现场执行并发时，保留已越过实际执行边界的事实，停止剩余范围并形成新的任务判断。
- 批量作业逐对象形成结果；单项失败、拒绝或未决不回滚其他对象合法承接和已发生事实。

## 权限、隔离与审计

- 协作承接、任务安排、受控开封、销毁/移交等不可逆执行、事实更正和结果发布分别校验权限；节点管理员、设备操作或异常处理权限不能互相推导。
- 跨客户合报只向节点披露履行当前动作所需的对象范围。客户资料、货物观察、证据和任务结果继续按客户、法人、案件及协作范围隔离。
- 审计至少关联协作事项及版本、来源决定引用、对象、动作、范围、节点、责任法人、承接决定、决定角色、授权、任务、执行角色、来源事实、有效事件、任务结果、更正/替代关系和发布时间。
- 日志和错误保持最小披露，不记录无关客户资料、监管原因或跨客户证据；未受理结果不得确认越权对象是否存在。

## 可观测性与恢复占位

- 能够从任一节点承接决定回溯协作事项、任务和全部实际事实，也能由任一实际事实回溯其任务、授权和回接结果。
- 分别统计已承接、部分承接、待补充、拒绝、冲突、未受理、未形成，以及任务待执行、部分完成、未完成和完成；不只统计“监管作业完成率”。
- 恢复验证覆盖承接后任务未形成、不可逆事实已保存但发布失败、事项取消与执行并发、重复事实、部分范围、跨客户越权和事实更正。
- 真实处理目标、积压阈值、批量规模和恢复要求由已登记非功能参数提供；未确认前保持显式未配置。

## 首发试点约束

- 只对已登记锚点节点、监管程序、动作、责任角色和证据能力形成生产承接；未登记分支保持待补充、拒绝或仅用于回放/模拟。
- 正常节点协作可使用自然发生的生产事实验证；查验、扣留、销毁、冲突、越权和取消等不得为验收主动在生产制造监管风险。
- 真实动作、执行方、权限、完成证据和差异语义未确认时，可以实现承接、任务、事实保全和显式未决骨架，但不得向现场发出生产不可逆动作或宣称监管执行完成。
- 监管退运在真实退运路径和运输责任未登记时只形成节点可执行的安全保管或待交接结果，不创建虚假装载、交接或移动事实。

## 验收示例

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-NO-001` | 当前有效查验协作事项明确指向节点控制的 P1 及受控开封、呈验和重封动作 | 节点承接 P1 并形成作业任务；不形成查验结果、放行或处置核对 |
| `AT-NO-002` | 请求覆盖 P1、P2，但节点只控制并能合法处理 P1 | P1 已承接，P2 待补充或拒绝并保留原因；不以整批承接扩大范围 |
| `AT-NO-003` | 请求缺少明确对象、动作、节点或必要授权依据 | 形成待补充，不创建任务或执行事实，不根据同袋、同客户或备注猜测 |
| `AT-NO-004` | 操作员有节点登录权限但没有当前有效开封、销毁或移交授权 | 相应范围未受理或拒绝；登录权限不能推导监管作业权限 |
| `AT-NO-005` | 节点依扣留协作将 P1 隔离并保持控制 | 保存控制、位置和隔离事实；不形成扣留解除、监管放行或永久完成 |
| `AT-NO-006` | 处置要求销毁 100 件，现场只确认并实际销毁 80 件 | 保存 80 件实际事实，任务为部分完成并保留剩余 20 件；不补齐数量或形成关务已覆盖 |
| `AT-NO-007` | 节点完成退运装载和节点侧交出扫描 | 只形成装载与节点侧证据；控制是否转移由运输履约形成权威交接结果 |
| `AT-NO-008` | 相同事项版本、对象、动作和请求重复到达 | 返回已有承接和任务，不重复开封、销毁、移交或累计数量 |
| `AT-NO-009` | 同一请求身份携带不同对象、动作或范围 | 形成节点协作冲突并保留两次输入，不按最后到达覆盖 |
| `AT-NO-010` | 协作事项在执行前取消或替代 | 停止未执行范围并保留承接和任务历史，不制造执行事实 |
| `AT-NO-011` | 协作事项在部分不可逆执行后取消或缩小范围 | 保留已发生事实，停止剩余范围并回接当前结果，不把实物或任务回退为未发生 |
| `AT-NO-012` | 现场事实迟到、更正或多个合格来源相互冲突 | 保留原事实和原判断，形成新有效性/冲突判断；不按最后到达覆盖 |
| `AT-NO-013` | 跨客户合报事项只允许节点处理 C2/P2 | 只承接和披露 P2 必要范围；C1/P1 不被自动开封、执行或展示 |
| `AT-NO-014` | 事实已保存，但任务派生或发布发生技术失败 | 保留原事实和恢复引用，形成未形成结果；不伪装成拒绝、任务失败或要求现场重做 |

## 生产参数与待决风险

本用例复用现有登记项，不新增猜测参数：

- `PAR-CUS-01..05`：真实程序的动作语义、范围、执行方、权限、证据、差异和安全验证环境。
- `PAR-NET-04..06`：目标节点、自营节点、节点作业能力、控制边界和现行作业方式。
- `PAR-NET-11`：真实监管退运涉及的路径、责任和交接规则。
- `PAR-INT-03`：外部节点或执行方可提供的实际事实来源和业务语义。
- `PAR-NFR-06`：批量、恢复和处理目标。

上述真实值未确认前，不得使用默认动作、默认授权、默认数量、默认完成证据或默认执行方进入生产。

## 开发拆分建议

1. 协作事项稳定引用、当前有效性和逐对象/动作范围校验。
2. 节点承接决定及已承接、部分承接、待补充、拒绝、冲突、未受理和未形成结果。
3. 已承接范围到节点作业任务的形成，不复制监管决定所有权。
4. 开封、隔离、观察、清点、重封、销毁、移交和退运装载等实际事实保全。
5. 任务结果派生、事实更正、迟到、冲突及事项取消/替代并发。
6. 权威运输交接边界、关务回接、审计、隔离和恢复。
7. `AT-NO-001` 至 `AT-NO-014` 的应用、领域和恢复测试骨架；真实动作和证据使用显式未配置状态。

完成本用例只证明节点能够安全承接明确的关务现场协作并提供真实执行事实。处置是否覆盖监管决定、监管义务是否终结以及扣留或限制是否解除，仍由各自权威流程独立判断。

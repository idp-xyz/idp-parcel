# UC-NO-006 建立送站的可验证交付范围

状态：稳定业务骨架已定（ADR-0212），待实现；授权交付关系、预报有效时窗与各项授予待租户提供

## 目标与边界

本用例从客户账户经客户渠道交来送站预报，或节点在一次送站上开立送站交接单开始，到这次送站在 `node-operations` 有了可验证交付范围（或如实答出为什么没有）、落在范围里仍待识别的作业实物经重核续判为止。机制与取舍以 [ADR-0212](../../adr/0212-a-customer-number-hit-needs-a-verifiable-delivery-scope.md) 为准，本用例只组织输入、结果、流程与验收。

本用例解决「这一次送站可验证地属于哪些客户账户」一个问题。它不决定是否接收、是否取得控制，那是 [UC-NO-002](./UC-NO-002-RECEIVE-CUSTOMER-DELIVERED-PARCEL.md) 的事；它不创建或改变委托、包裹与客户承诺；它不登记授权交付关系，那归 `party-commercial`。

本用例包含：

- 客户账户提交、撤回送站预报。
- 节点开立送站交接单，收寄时带上它，把待识别实物归入它，关闭它。
- 交接单对每个声称的客户账户的绑定：客户账户经客户渠道确认或否认；持授予的运营操作者依授权交付关系确认。
- 范围成立时，交接单名下仍待识别的作业实物经重核续判。

本用例不执行：

- 身份核对本身与收寄判断（UC-NO-002）。
- 身份冲突处置（[UC-NO-004](./UC-NO-004-DISPOSE-AN-IDENTITY-CONFLICT.md)）。
- 授权交付关系的登记、变更与撤销（`party-commercial` 的参与方关系）。
- 预报有效时窗的登记：它走登记册配置写面与受控批量口，不在本用例。
- 客户查看交接单明细的客户面读口。
- 节点与运输方之间的交接（`transport-fulfillment`）。

## 参与者与协作

| 参与者或上下文 | 本用例职责 | 明确不负责 |
|---|---|---|
| 客户账户（经首方客户渠道） | 提交、撤回自己的送站预报；对声称了自己的送站交接单确认或否认 | 不替别的客户账户确认，不改节点事实 |
| 节点收寄岗位（作业事实登记） | 开立、关闭送站交接单；收寄时上报交付范围依据引用；把待识别实物归入交接单 | 不确认绑定，不决定正式包裹身份 |
| 持「送站交接确认」授予的运营操作者 | 依授权交付关系确认交接单对某个客户账户的绑定，给出交付方参与方与依据引用 | 不否认绑定（那是客户账户的话），不在授权交付关系之外确认 |
| `node-operations` | 签发预报标识，保存预报与交接单，判范围是否成立，范围成立时触发重核 | 不创建或替换正式包裹身份 |
| `party-commercial` | 按（租户，交付方参与方，客户账户，开立节点，开立时刻）答授权交付判断 | 不替节点确认绑定 |
| `parcel-shipment` | 重核时照 UC-NO-002 步骤 4 答身份 | 不拥有可验证交付范围 |

## 启动条件

- 首方客户渠道族已配置，客户端持送站预报提交、送站预报撤回、送站交接确认中相应的授予（参数登记册 `PAR-INT-13`）。未配置、未授予各答其格（ADR-0139 决定四）。
- 运营操作者持「送站交接确认」授予（`PAR-INT-08`），这一种运营决定的准入范围已登记（`PAR-INT-11`）；节点设备在「作业事实登记」能力面上已登记。
- 预报有效时窗（`PAR-NET-18`）与授权交付关系（`PAR-NET-17`）是租户取值。没有登记时如实答未配置，仓内不写默认时长、默认交付方或默认放行。
- 演示租户 `SYN-TENANT-01` 在演示种子里配，证据记 `S`。

下表定义业务语义，不是 API、消息或数据库字段清单。

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |

| 预报撤回 | 首方客户渠道信封与载荷 | 预报标识、接入请求标识 | 只能撤自己客户账户的预报；别的账户的预报与查无此预报同答 |
| 交接单开立 | 作业事实登记 | 设备签发的交接单标识、节点、交付方线索、声称的客户账户（至少一个）、开立时刻 | 声称与交付方线索都只是线索 |
| 收寄时的依据引用 | 节点现场 | 送站预报或送站交接单的种类与标识 | 随 UC-NO-002 的交付来源保全，不进内容指纹 |
| 归入 | 作业事实登记 | 交接单标识、作业实物 | 交接单开放；实物在同一节点有当前收寄，此刻待识别、不带关联、不记身份冲突 |
| 关闭 | 作业事实登记 | 交接单标识 | 关闭冻结成员 |
| 客户渠道结论 | 首方客户渠道信封与载荷 | 交接单标识、结论（确认或否认）、接入请求标识 | 客户账户取自信封，须在声称之列；只对已关闭的交接单 |
| 运营决定确认 | 操作者渠道信封与载荷 | 交接单标识、客户账户、交付方参与方、依据引用 | 交付方参与方是 `party-commercial` 的参与方标识；依据引用逐字保存、不判真伪 |

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 送站预报已登记 | 客户账户的预报落册，标识已签发 | 预报标识、客户账户、节点、预计送达时刻、号码集合、交付方线索、来源请求键、形成时刻 | 委托、包裹、客户承诺或节点收寄 |
| 送站预报已撤回 | 预报此后不再成立范围 | 撤回时刻与来源请求键 | 回滚此前据它形成的关联 |
| 送站交接单已开立、已归入、已关闭 | 交接单与成员的作业事实落册 | 交接单标识、节点、交付方线索、声称的客户账户、成员与各自的形成方式、开立与关闭时刻 | 绑定已确认 |
| 绑定已确认 | 某个声称的客户账户的绑定已确认 | 确认途径（客户渠道或运营决定）、确认方、交付方参与方与依据引用（运营决定时）、时刻 | 其余客户账户也已确认 |
| 绑定已否认 | 客户账户经客户渠道否认 | 否认时刻与来源请求键 | 交接单作废或成员被拒收 |
| 可验证交付范围已成立 | 声称的客户账户全部已确认 | 成立时刻；同一笔事务里的重核门铃 | 回滚已形成的关联 |
| 已有结果 | 同一事实或同一结论原样重投 | 回显在册结果 | 新版本、新门铃 |
| 已有结论 | 绑定已有结论，又来不同的结论 | 回显在册结论 | 覆盖 |
| 不在授权交付关系内 | 运营决定确认时 `party-commercial` 答否 | 拒绝原因 | 确认 |
| 未配置 | 运营决定确认时，本租户一条授权交付关系都没登记，交付方又不是该客户账户所属参与方本身 | 拒绝原因 | 默认放行 |
| 交接单状态不符 | 客户渠道对未关闭的交接单作结论；向已关闭的交接单归入；归入的实物不合条件 | 拒绝原因 | 改写交接单或实物 |

信封一层的「发行方未配置」「令牌无效」「未授予」「不在准入范围」与坏载荷，客户面照 ADR-0139 决定四、操作者面照 ADR-0151 决定三与 ADR-0100 决定四作答，不读册、不写册。指名的预报、交接单或实物在本租户查不到，与越权探针同答。授权交付判断读不动时不形成答案。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 首方客户渠道 | 认证客户端，核授予与准入范围；租户与客户账户取自信封；载荷形状不合即拒 | 信封各格或坏载荷直接作答 |
| 2 | `node-operations` | 按来源请求键认预报的重放与冲突；首次则签发预报标识、落册 | 答送站预报已登记，回显标识；撤回同理，只撤自己账户的 |
| 3 | 节点收寄岗位 | 送站没有预报、或预报覆盖不到时，开立送站交接单；收寄时上报依据引用（预报标识或交接单标识） | 收寄照 UC-NO-002 进行，身份按当时的可验证交付范围判 |
| 4 | 节点收寄岗位 | 把同一节点上缺可验证交付范围而待识别的实物归入开放的交接单；清点完毕关闭交接单 | 归入是追加事实，不改写来源 |
| 5A | 客户账户 | 对已关闭、声称了自己的交接单确认或否认 | 绑定已确认或已否认 |
| 5B | 运营操作者 | 指名交接单、客户账户、交付方参与方与依据引用，确认绑定 | `node-operations` 向 `party-commercial` 问授权交付判断：是即确认，否答不在授权交付关系内，未配置答未配置 |
| 6 | `node-operations` | 声称的客户账户全部已确认时，范围成立，同一笔事务自投门铃 | 任一被否认，交接单不再成立范围，成员可另行归入 |
| 7 | `node-operations` | 门铃到达，对交接单名下当前有效版本仍为待识别、不带关联、不记身份冲突的作业实物重核；向范围已成立的交接单归入实物时，只重核那一件 | 照 UC-NO-002 步骤 4 判：唯一且证据充分即追加关联版，业务时间取原接收时刻、不另起控制起点，交发布意图一封 |

## 一致性、幂等与并发

- 预报的提交与撤回按来源请求键认重放，来源请求键由首方族的推导口自接入请求标识取：同键同内容答已有结果，同键不同内容答来源冲突。
- 交接单的开立、归入、关闭按设备签发的事实身份认重放（ADR-0023）。
- 同一交接单的同一客户账户至多一个结论；同结论重投答已有结果，异结论答已有结论并回显。
- 范围成立与门铃在同一笔事务里；重核取锁的次序与 UC-NO-002 的收寄、重核相同，同一版本至多一个后继由库面兜底。
- 一件作业实物的依据取它最后归入的交接单，没有归入过的取收寄来源里的引用；归入不改写来源，也不回滚已形成的关联。

## 权限、隔离与审计

- 客户账户只能对声称了自己的交接单作结论，只能撤自己的预报。指名别的账户的对象，与查无此对象同答，不泄露别的客户账户是否在声称之列。
- 运营操作者只能确认，不能否认；确认必须指名交付方参与方，并由 `party-commercial` 的授权交付关系支持，交付方是该客户账户所属参与方本身时除外。
- 设备上报的交付方与交接单上的声称都只是线索，不据它们自动成立范围。
- 审计至少关联预报或交接单、客户账户、节点、交付方线索、确认途径与确认方、交付方参与方、依据引用、成立时刻与重核门铃。
- 依据引用只作证据，不以明文进日志或指标；客户地址、联系人、货物内容不进预报与交接单。

## 首发试点叠加条件

- `PAR-NET-17` 登记授权交付关系，`PAR-NET-18` 登记预报有效时窗；`PAR-INT-13` 登记客户端的三格授予；`PAR-INT-08` 与 `PAR-INT-11` 登记「送站交接确认」的授予与准入范围。
- 真实参数未确认时，可以实现预报、交接单、确认与重核机制，以及显式未配置与受控 `S`；演示租户的取值只在演示种子里。

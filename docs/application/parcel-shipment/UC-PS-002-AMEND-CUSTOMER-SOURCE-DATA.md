# UC-PS-002 补充或更正已接受委托的客户原始资料

状态：开发基线草案；稳定业务边界已形成，允许字段、阶段规则和授权入口由 `PAR-COM-13` 与待确认业务决策管理

## 目标与边界

本用例从已接受委托或包裹的客户、或被授权代表客户的运营角色提出资料补充/更正请求开始，到 `parcel-shipment` 形成可追溯的客户原始资料新版本、明确拒绝/未受理结果，或者记录本次尚未形成业务结果为止。

本用例包含：

- 校验目标委托、包裹、资料范围、请求方、实际决定方、授权和请求所依据的源版本。
- 保全原始请求、原因、来源、来源发生时间（`occurredAt`）、系统接收时间（`receivedAt`）和资料适用时间（`requestEffectiveAt`）。前两者是来源信封元数据，不单独形成冲突；资料适用时间属于规范化资料内容。
- 形成不可覆盖的客户原始资料新版本，并派生当前可供下游消费的资料版本采用判断。
- 区分资料补充、资料更正、来源版本更正/撤销、无变化重复请求、业务拒绝（未获授权、不允许）、等复核、输入未受理、请求冲突与未决（含本方提交未完成）。
- 支持逐包裹、逐字段和批量部分成功，同时维持跨客户、法人、委托和包裹范围隔离。
- 将新版本引用交给关务、路由、节点或结算上下文重新作出各自判断。

本用例不执行：

- 修改委托接受基线、客户账户、责任法人、合同、服务产品、寄收件关系的共享约束或包裹身份。
- 自由增删已接受委托成员；新增服务件进入关联新委托，对已有成员只能通过 [`UC-PS-006`](./UC-PS-006-CANCEL-PARCEL-OR-COORDINATE-POST-INTAKE-DISPOSITION.md) 逐包裹请求取消或停止服务，并形成适用的包裹取消或收寄后服务处置结果。
- 覆盖节点实测、重新包装、实际收寄、装袋、运输、监管事实、正式申报资料、提交版本或最终费用。
- 自动换单、重新包装、改路、重新申报、提交授权、重新提交、放行、解除内部限制、重开案件或重新计费。
- 直接判定客户资料真实与否、关务专业结论、运输可行性、节点作业结果或财务金额。

## 输入语义契约

输入是稳定业务语义，不是 API、文件或数据库字段清单。省略字段表示“不变”，不表示清空；显式清空必须由字段和阶段规则允许。

| 输入组 | 客户或代理可声明 | 权威来源 | 最低业务语义 |
|---|---|---|---|
| 来源信封 | 否 | 接入适配器与接入来源 | 请求身份、来源主体、来源发生时间（`occurredAt`）、系统接收时间（`receivedAt`）、原始内容或不可变引用、重试关系；两类时间不进入规范化内容摘要 |
| 目标范围 | 是 | 客户请求，目标身份由 `parcel-shipment` 解析 | 委托、包裹、字段或资料组范围；不得以批次、袋、总单或客户名称模糊指代 |
| 基础版本 | 是 | 客户请求引用，现行版本由 `parcel-shipment` 核对 | 请求方认为正在修订的源版本或明确“补充缺失资料”的基准 |
| 修订意图 | 是 | 客户请求 | 补充、更正、显式清空、来源更正或撤销关系及原因 |
| 资料内容 | 是 | 客户原始声明 | 寄收件、货物、申报原始资料和服务要求范围内的声明内容 |
| 业务时间 | 可声明 | 适用业务规则与 `parcel-shipment` | 资料何时在业务上成立或适用；不能仅以接收时间替代 |
| 授权上下文 | 否 | `party-commercial` 与接入身份 | 客户账户、责任法人、委托关系、实际决定方、授权角色、委派和有效时间 |

客户资料版本必须关联明确委托或包裹范围。跨客户批量请求只是操作归组，每个目标分别判断、分别形成结果，不能形成批量级当前资料状态。

## 资料范围与阶段边界

具体字段、字段组、阶段和允许动作由 `PAR-COM-13` 与真实合同、产品、线路和关务规则登记。允许声明（`ADR-ALLOW`）在这一格登记为不允许答不允许（`DISALLOWED`），未声明答等复核（`AWAITING_REVIEW`），读不回答未决；阶段判不出也答未决，不默认最早阶段（`ADR-STAGE`）。不能以系统便利推断允许。

| 业务阶段 | 可形成的结果 | 不能由本用例自动完成 |
|---|---|---|
| 已接受、尚未收寄 | 补充或更正客户原始资料新版本 | 修改接受基线、成员、承诺、路由或服务产品 |
| 已收寄或已测量 | 保留客户声明新版本并关联节点差异 | 覆盖实测、作业、身份或计费事实 |
| 已制签或已装袋 | 形成新源版本并通知相关消费方重新判断 | 自动换单、重包、拆袋、重封或改路 |
| 关务资料形成中、尚未提交 | 供 `UC-CC-002` 形成新的正式资料版本 | 自动形成就绪、授权或提交 |
| 已提交关务 | 由 `UC-CC-007` 分类补充、更正、撤销重报或替代 | 修改或重发既有提交版本 |
| 案件已关闭或服务已完成 | 保全迟到版本及其适用时间 | 自动重开案件、回退运输、承诺或结算 |

## 结果语义契约

资料修订编排（`AmendCustomerSourceDataHandler`）的结果。代码列是应用结果枚举的原名，接 HTTP 时即 `outcome`。

| 结果 | 代码 | 业务含义 | 必须保留的依据 | 禁止行为 |
|---|---|---|---|---|
| 已记录 | `RECORDED` | 新版本已形成；答复同带该范围此刻的采用判断（PS CONTEXT 词条「当前客户资料版本采用判断」）：`已采用`即已记录并采用，下游按新版本锚消费；`待复核`即基础版本过期、与当前版本在同一范围重叠，新版本保全但不推进采用，等授权复核角色合并 | 请求、原始内容、基准版本、版本范围、原因、业务/适用时间、决定方、授权快照和关系；采用判断与所采用的版本 | 不得改写接受基线、旧版本或下游正式资料；不得按最后到达覆盖 |
| 等复核 | `AWAITING_REVIEW` | 所采用规则包版本的允许声明在这一格（资料组 × 阶段 × 意图）未声明，不形成版本（`ADR-ALLOW` 决定三） | 请求、资料范围与所判阶段 | 不得推断允许，也不得答成业务拒绝 |
| 未获授权 | `NOT_AUTHORIZED` | 委托在请求方可见范围内，但请求方对这处资料没有修订授权（`ADR-AUTH`） | 授权判断依据、请求方 | 不得在委托不存在或属别的客户时作答——那是统一不可见 |
| 不允许 | `DISALLOWED` | 请求越出接受基线成员集合，或允许声明把这一格登记为不允许 | 结构化原因、规则版本、适用时间 | 不得删除原始请求或写成技术失败 |
| 已有结果 | `ALREADY_HANDLED` | 同一请求身份与相同内容已经形成结果 | 原请求和已有版本/结果关联 | 不得重复形成版本 |
| 请求冲突 | `SOURCE_CONFLICT` | 同一请求身份携带不同内容、范围、基准或资料适用时间（`requestEffectiveAt`） | 原请求、冲突字段和纠正入口 | 不得把 `occurredAt`/`receivedAt` 的变化当作冲突，也不得按最后到达覆盖 |
| 未决 | `UNDECIDED` | 授权服务、阶段事实或允许声明读不回，授权规则未登记，资料修订阶段判不出，或本方的版本提交、标识签发、下游交接没有落成（[ADR-0256](../../adr/0256-technical-non-formation-is-a-reason-of-undecided-not-an-outcome-of-its-own.md)） | 续办引用与未决原因，原因是 `SHIPMENT_REQUEST_UNAVAILABLE`、`SOURCE_DATA_AMENDMENT_AUTHORITY_UNAVAILABLE`、`SOURCE_DATA_AMENDMENT_AUTHORITY_RULES_NOT_CONFIGURED`、`SOURCE_DATA_AMENDMENT_STAGE_FACT_UNAVAILABLE`、`SOURCE_DATA_AMENDMENT_STAGE_UNDETERMINED`、`SOURCE_DATA_RULE_UNAVAILABLE`、`SOURCE_DATA_VERSION_IDENTITY_UNAVAILABLE`、`AMENDED_REQUEST_NOT_SAVED`、`STALE_SHIPMENT_REQUEST_REVISION`、`SOURCE_DATA_VERSION_NOT_HANDED_OFF`、`SOURCE_DATA_AMENDMENT_AUTHORITY_APPLICABILITY_CONFLICT` 之一；末一码是授权适用冲突（同一刻多于一条授予允许、或委派方不同的多条委派命中，[ADR-0261](../../adr/0261-authority-grants-and-contract-delegations-follow-the-closure-of-their-version-and-several-hits-are-an-applicability-conflict.md)），与授权规则未登记并列，续办同归运营登记（收尾旧版或撤去重复的那一条） | 不得返回已采用或业务拒绝；依赖答不出不交人工复核，授权规则未登记与授权适用冲突都不答未获授权 |

输入未受理与统一不可见不是资料修订编排的结果，在接入与 HTTP 层作答：

| 情形 | 作答 | 禁止行为 |
|---|---|---|
| 输入未受理：目标范围、来源或修订意图立不起来 | 接入答 `400 MALFORMED_REQUEST`，不形成修订请求结果 | 不得创建占位版本或跨客户猜测目标 |
| 委托查无、跨租户或跨客户 | 统一不可见结果，`404` 加上下文统一不可见码（[ADR-0022](../../adr/0022-http-status-carries-answer-formed-not-business-verdict.md)） | 不得区分不存在与他人的，不得答业务拒绝 |

`已记录`、`已采用`只表示 `parcel-shipment` 的资料版本判断完成，不表示下游已经采用。下游必须按各自上下文的业务时间和门禁重新判断。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 接入适配器 | 认证入口并保全请求、原始内容、来源时间和接收时间 | 无法保全时不形成任何结果（没有形成答案），不进入资料版本处理 |
| 2 | `parcel-shipment` | 识别重复、重试、内容冲突和关联请求 | 相同内容返回已有结果；不同内容进入请求冲突 |
| 3 | `parcel-shipment` | 解析客户账户、委托、包裹、字段范围和基础版本 | 范围或意图不可解释时输入未受理；委托查无、跨租户或跨客户答统一不可见结果 |
| 4 | `party-commercial` / `parcel-shipment` | 校验请求方、实际决定方、授权角色、委派和适用时点 | 请求方无修订授权答未获授权；授权服务答不出或授权规则未登记答未决（带原因与续办引用），不交人工复核 |
| 5 | `parcel-shipment` | 校验接受基线共享约束、成员和包裹身份不变量 | 增删成员、改账户/法人/合同/产品/服务范围答不允许并转关联路径 |
| 6 | `parcel-shipment` | 按字段、范围、阶段和规则判断补充、更正、显式清空或来源更正 | 先判资料修订阶段（判不出答未决，不默认最早阶段），再问允许声明：登记为不允许答不允许，未声明答等复核，读不回答未决 |
| 7 | `parcel-shipment` | 形成不可覆盖客户原始资料版本及其关系 | 记录原因、基准版本、对象范围、业务时间、决定方和授权快照 |
| 8 | `parcel-shipment` | 派生当前资料版本采用判断 | 只覆盖明确范围；基础版本过期且与当前版本重叠时停在`待复核`；不删除旧版本，不产生下游专业结果 |
| 9 | `parcel-shipment` | 将版本引用交给适用下游 | `UC-CC-002`、`UC-CC-003`、`UC-CC-007`、路由、节点或结算分别重新判断 |
| 10 | 接入适配器 / 下游责任方 | 返回版本结果或提供查询 | 发布失败只重试同一发布意图，不重复形成资料版本 |

## 下游交接边界

| 下游 | 新资料版本的消费方式 | 明确不允许 |
|---|---|---|
| `UC-CC-002` | 对未提交范围引用新的客户原始资料版本，形成新的正式申报资料版本 | 直接修改客户原始资料、覆盖旧正式资料或假定已就绪 |
| `UC-CC-003` | 对受影响申报单元重新评估申报就绪，保留旧判断历史 | 由资料补充自动恢复就绪、授权或提交 |
| `UC-CC-007` | 对已提交范围分类补充、更正、撤销重报或替代，决定是否建立后续动作 | `UC-PS-002` 不创建新的提交版本或重发外部申报 |
| `UC-CC-010` | 关闭或已完成后保全资料版本，由其判断原案后续办、重开或不改变生命周期 | 资料版本自动重开案件或回退关闭决定 |
| `node-operations` | 将客户声明与实测差异作为输入，继续由节点拥有测量和作业事实 | 客户版本覆盖实测、收寄、装袋或重包事实 |
| `network-routing` | 重新判断资格、剩余路由或资料影响 | 自动改路、恢复旧路线或覆盖已发生移动 |
| `parcel-pricing` / `settlement-accounting` | `parcel-pricing` 依据新资料和已解析依据形成新的评价；`settlement-accounting` 再按费用确认条件判断费用影响 | 资料版本直接覆盖评价、最终费用或对账结果 |

客户资料更正不自动解除 `UC-CC-011` 的内部合规限制，不自动改变外部监管结果、放行门禁或异常案件；这些结果仍由其责任用例重新判断。

## 版本、并发与迟到规则

- 同一请求身份、相同规范化内容摘要、相同目标范围和基础版本的重试返回已有结果；不能创建第二个资料版本。规范化摘要必须包含资料适用时间（`requestEffectiveAt`）的值及缺失/显式存在状态。
- 同一请求身份携带不同内容、范围、基础版本或 `requestEffectiveAt` 形成请求冲突；`occurredAt`/`receivedAt` 变化只追加来源观察，不单独形成冲突，不得按最后到达覆盖。
- 请求引用过期基础版本且与当前版本存在重叠字段时，形成冲突或待复核；只有登记了明确合并规则的非重叠范围才可合并，首发默认保持待复核。
- 资料版本提交顺序由明确的领域顺序、基础版本关系和业务有效时间裁决；消息到达、数据库写入或客户端时间不能单独决定当前版本。
- 资料来源被更正、撤销或确认无效时，保留原版本并追加关系，重新派生当前资料版本采用判断；不删除历史。
- 资料适用时间早于接收时间的迟到请求，按适用规则重新派生受影响的当前判断；不能把历史接受基线、正式申报资料或提交版本改写成使用了迟到版本。不得用 `occurredAt` 或 `receivedAt` 默认补齐缺失的 `requestEffectiveAt`。
- 已形成的物流、关务、监管、财务和承诺事实不因资料版本变化回退。需要重新申报、换单、重包、改路或调整费用时，由对应上下文形成新的决定和版本。
- 部分成功只在明确对象和字段范围内成立；批量操作不得形成“全部已采用”或“全部已拒绝”的总结果。

## 权限、隐私与审计

- 请求方、实际决定方和授权角色分别记录；登录操作人不能替代实际决定方，客户请求也不能越过运营企业或合同授权边界。
- 每次版本必须关联集团租户、责任法人、客户账户、委托、包裹和明确字段/资料范围，跨客户合报不得扩大可见范围。
- 客户只能看到自身授权范围内的请求、版本和结果；错误、查询、导出和批量回执不得泄露其他客户的资料或限制。
- 审计至少包括原始请求、来源、请求/接收/业务/适用时间、目标解析、基础版本、旧新内容或不可变引用、原因、规则版本、决定方、授权快照、版本关系、下游交接和发布结果。
- 人工纠错必须形成新请求和新版本；不得直接覆盖接受基线、源版本、当前判断或下游结果。
- 资料内容按最小必要原则披露；日志和指标使用关联标识，不输出不必要的地址、货物或申报明文。

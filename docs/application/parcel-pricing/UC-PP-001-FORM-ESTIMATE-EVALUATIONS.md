# UC-PP-001 按假设包裹形成试算评价

状态：机制已实现——试算编排、按评价请求形成评价、价卡收尾各有生产编排，`/pricing-estimates` 已装配；参考复核按租户复核职责规则判那一格待实现（见「给开发的交接」）。租户的真实价卡、计价参考目录与序列待提供（租户取值，未登记即答价卡未配置）

## 目标与边界

运营（销售、客服、产品）在包裹尚不存在时，为一件假设包裹问「按此刻在用的价卡，它在某一主要范围、某一价格方向下各被怎么计价」。本用例对每张适用价卡各形成一份针对试算对象的评价，交回评价状态、金额、费用组成、版本清单与解释，供比价与估价。

本用例拥有：受理试算声明、取适用价卡、逐卡造试算输入并形成纯评价、汇总逐卡结果。

本用例不拥有，也不形成：

- 报价、锁价、接受或任何客户承诺（[PP CONTEXT](../../domain/parcel-pricing/CONTEXT.md)「评价对象为试算对象时……不得形成客户承诺」）。
- 费用、预估费用、应收应付——`settlement-accounting` 不得据试算评价形成任何金额（同上）。唯一的例外是接受前估价：结算把委托当前提交版本逐件试算的合计用作冻结与信用暴露的控制金额（[ADR-0179](../../adr/0179-pre-acceptance-control-amount-is-estimated-by-settlement-from-per-parcel-sell-trial-evaluations.md)），那一路不经本用例。
- 择优：多张卡各自的评价之间没有优劣，择优归 `network-routing`（[CONTEXT-MAP](../../domain/CONTEXT-MAP.md) `parcel-pricing → network-routing`）。
- 试算留痕：本用例的试算评价不入评价册、不交任何下游（[ADR-0152](../../adr/0152-operator-estimate-is-a-pricing-use-case-computed-not-recorded-and-never-handed-to-settlement.md) 决定二）；接受前估价的逐件试算由结算发起，同样不入评价册。

## 试算声明

发起方声明下列各项，本用例一格不给默认（[ADR-0152](../../adr/0152-operator-estimate-is-a-pricing-use-case-computed-not-recorded-and-never-handed-to-settlement.md) 决定五）：

- **主要范围**与**价格方向**；计算目的按领域配对表随方向取得。
- **计价基准时点**：选哪一版价卡、解析哪一期序列与哪一版目录读数都按它。
- **实重**（值与单位）与可缺的**尺寸**（三边与单位）。
- **分区**与**邮编路线**（始发、目的）：哪张卡用哪一种由卡自己的目录绑定决定，见下方流程第 3 步。
- 可缺的**结算币种**。

租户只从操作者信封来；声明里出现租户或任何身份格即为畸形声明。

## 结果语义

| 结果 | 含义 | 发起方的恢复动作 |
|---|---|---|
| 已形成 | 逐卡交回结果，卡与卡之间不排序、不标首选 | 读每张卡的评价 |
| 价卡未配置 | 该租户在此范围、方向、时点下没有适用价卡 | 去登记价卡，或换范围、方向、时点 |
| 价卡适用冲突 | 同一方案身份两版同时适用，交回候选 | 交价卡治理责任方裁，本用例不挑 |
| 未受理 | 声明不成形（缺必需项、方向不认识、带了身份格……） | 改声明 |
| 未决 | 价卡、序列或目录读不回，指名停在哪一步 | 稍后重试 |

「已形成」下逐卡一格：

- **已评价**：交回那份试算评价。评价自己的状态（完成 / 待判断 / 不可计价 / 冲突 / 计算失败，`COMPLETED` / `PENDING` / `UNRATABLE` / `CONFLICT` / `FAILED`）原样透出，本用例不折成别的说法；「待判断」与「不可计价」是评价答案，不是本用例的失败（[PP CONTEXT](../../domain/parcel-pricing/CONTEXT.md) 不可计价与待判断诸句）。
- **输入不全**：这张卡要的某一格发起方没给（例如卡绑了分区目录而声明没有邮编路线），点名缺哪一格；别的卡照算。

## 应用流程

1. **受理**：校验声明各项成形、方向可配对、没有身份格。不成形即未受理，不再往下。
2. **取适用价卡**：按（租户、价格方向、主要范围、计价基准时点）取全部适用价卡。零张即价卡未配置；同一方案身份两版同时适用即价卡适用冲突，交回候选。读不回即未决。
3. **逐卡造试算输入**：
   - 卡绑了分区目录：用声明的邮编路线，分区由目录解析；没有邮编路线即这张卡输入不全。
   - 卡没绑分区目录：用声明的分区；没有分区即这张卡输入不全。卡另绑了偏远档位目录时还要邮编路线。
   - 试算对象引用与评价标识由租户、声明各项与卡的版本引用确定性派生；证据层级记 `S`（ADR-0152 决定五）。
4. **逐卡补齐读数**：按卡的绑定解析在用序列与目录版本、按计价基准时点与邮编路线取读数，与正式评价走同一件实现（ADR-0152 决定三）；查不到的读数照正式评价的处置冻结进输入，由纯函数如实落待判断。读不回即未决。
5. **逐卡形成纯评价**，不入册、不交付。
6. **汇总**：交回已形成，逐卡结果并列。

## 一致性与幂等

- 本用例不写任何册，没有并发写冲突；重复声明得到相同的试算对象引用与评价标识。
- 同一声明在不同时刻可能得出不同结果：在用的价卡、目录或序列版本可能已换版。每份评价自带版本清单，复核照清单重算（[PP CONTEXT](../../domain/parcel-pricing/CONTEXT.md) 确定性与回放诸句）。
- 试算评价与正式评价在同一形成时刻、同一版本清单下结果相同：两者补齐读数走同一件实现。

## 验收示例

1. **单卡完成**：合成租户在某范围下只有一张在用 `SELL` 卡且未绑目录；声明给了分区与实重。结果已形成，一格已评价，状态完成，金额按卡的规则、版本清单指向那一版卡。
2. **多卡并列**：同一范围、`BUY` 方向下两家供应商各有一张适用卡。结果已形成，两格已评价，各带自己的版本清单；两格之间没有顺序含义，响应里没有「首选」。
3. **缺邮编路线**：两张卡一张绑了分区目录、一张没绑；声明只给了分区。结果已形成：绑目录的那张输入不全、点名邮编路线；另一张已评价。
4. **没有卡**：该范围、方向、时点下没有适用卡。结果价卡未配置，不交回任何评价。
5. **同一方案两版重叠**：结果价卡适用冲突，交回两版候选，不评价任何一版。
6. **结算不可见**：任一试算之后，评价册与结算侧都没有新增任何记录。
7. **身份自报**：声明里带租户格。结果未受理。

## 按评价请求形成评价：答不出时与补登之后

试算之外，计价还按结算交来的评价请求形成正式评价。选卡的收尾折法与本用例同一套（[ADR-0234](../../adr/0234-an-older-price-card-version-leaves-new-selections-only-through-an-explicit-closure-for-a-named-successor.md)），无价卡、适用冲突各成一格；冲突的判法不同：本用例只在同一方案身份两版同时适用时答适用冲突，不同方案各一张卡并列各自评价，正式评价则把多于一版同时适用——不同方案各一版也算——一律答适用冲突，不评价任何一版。正式评价答不出、或租户补登参数之后怎样交回结算，由 [ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 定；本节只列计价这一侧的验收，结算那一侧见 [UC-SA-002](../settlement-accounting/UC-SA-002-CALCULATE-CONFIRM-AND-ADJUST-OPERATIONAL-CHARGES.md) `AT-SA-188` 至 `AT-SA-199`。

| 编号 | 场景 | 期望结果 |
|---|---|---|
| `AT-PP-001` | 请求还读不回、价卡或输入读口答不出、铸造口或评价库故障 | 是未决：入账回滚、信封重投；这几格是派发未决名单里仅有的哨兵（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定三） |
| `AT-PP-002` | 请求所在范围下没有在用价卡、多于一版同时适用、或造不出计价输入快照 | 不形成评价、入账不重投，同笔交一封「评价未形成」（租户、请求、方向、停在哪一格、说明）；一份请求至多一封，重投不翻倍；不再按未决耗尽失败预算（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定三） |
| `AT-PP-003` | 登记一版价卡（含草稿发布），或重放同一版 | 与价卡行同一事务交「参数已登记」，带卡的计价范围与方向（内部方向的卡不交）；同一版重放一封；冲突与规范化形状不同不交；交不出整笔回滚（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定五） |
| `AT-PP-004` | 一版序列或目录复核通过（含免复核由连接器代写的那一份） | 与复核行同一事务，按绑了它的卡的计价范围与方向各交一封「参数已登记」（同一范围同一方向的几版只交一次，内部方向不交）；没有卡绑它一封不交；退回的那一版不交、也不问绑定；问不出绑定整笔未决（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定五） |
| `AT-PP-005` | 停在「没有在用价卡」的请求，租户补登了卡之后由结算续办出下一代 | 计价按下一代选到那张卡、形成回指下一代的评价并交评价已记录；上一代仍没有评价（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定一、五） |
| `AT-PP-006` | 交「评价未形成」失败 | 暂时不可用是未决，入账跟着回滚、下一次重投再交；被框架确定性拒收是硬失败，不进未决名单（[ADR-0229](../../adr/0229-a-stalled-evaluation-request-resumes-as-a-new-generation-on-parameter-registration.md) 决定三） |

## 价卡收尾：换版时旧版离开新的选择

试算与按评价请求形成评价都按范围选卡，同一方案两版同时适用即答适用冲突。旧版怎样经指名后继的截止或退役离开新的选择、收尾怎样续办停着的请求，由 [ADR-0234](../../adr/0234-an-older-price-card-version-leaves-new-selections-only-through-an-explicit-closure-for-a-named-successor.md) 定；本节只列计价这一侧的验收。截止点、退役时刻都由服务端定，哪一版何时让位给哪一版是租户取值。

| 编号 | 场景 | 期望结果 |
|---|---|---|
| `AT-PP-007` | 同一方案两版重叠（后继晚于旧版起点），把旧版截止在后继起点 | 截止点取后继的起点；截止点之前选旧版、起选后继，在用解析与适用装载同答；发布时的版本行与重放用的点读不变；管理台目录回显截止点与后继（[ADR-0234](../../adr/0234-an-older-price-card-version-leaves-new-selections-only-through-an-explicit-closure-for-a-named-successor.md) 决定二、五） |
| `AT-PP-008` | 后继不晚于旧版起点（同起点重发，或连起点一起改正），旧版退役 | 任何时点都只选后继；退役时刻取登记时刻；已退役的那一版不再算作绑着序列或目录的卡；管理台目录回显退役时刻与后继（决定三、五） |
| `AT-PP-009` | 同一后继、同一依据的收尾重放 | 截止认出册上那一条、回显原截止点，退役回显原时刻，一行不多写、信封不多一封；换一份依据截同一处或再退答未受理（决定二、三） |
| `AT-PP-010` | 收尾不成立：旧版或后继不在本租户的册上、后继换了计价范围或方向、截止落在旧版起点上或终点后、退役的后继晚起、后继到不了旧版终点、任一版已退役；在线口自报租户、截止点或退役时刻；没有登记册配置写授予 | 答未受理带原因、一行不写、一封不交；在线口答请求畸形或 403，没有授予时载荷一个字节不读（决定一至四） |
| `AT-PP-011` | 同一旧版上并发的两次收尾 | 后到者停在旧版行锁上，先到者提交后它读到已收尾的旧版、答未受理；册上一行（决定四） |
| `AT-PP-012` | 停在只有新一版卡解得开的停因上的请求（如价表没有这一段），租户登了同一方案的新一版、再收尾旧版 | 收尾同笔交一封价卡种类、带旧版计价范围与方向的「参数已登记」，标识与两版各自登记那一封不同；后继登记那一封续办出来的那一代停在适用冲突，收尾那一封续办出的下一代选到后继、形成评价；前几代与它们的评价不改写（决定四、六） |

## 计价条款从哪里来

评价按范围选卡，体积系数、金额取整与换算所用的汇率序列都只从选中的价卡读，不分价格方向；商业价格政策的定价方案绑定与口径不参与（[ADR-0260](../../adr/0260-an-evaluation-selects-its-price-card-by-scope-and-reads-its-pricing-terms-only-from-the-card.md)）。

| 编号 | 场景 | 期望结果 |
|---|---|---|
| `AT-PP-013` | 一张在用 `SELL` 卡声明了自己的体积系数与金额取整、绑了一串汇率序列；同范围的销售方向商业价格政策另有一份不同的口径 | 试算与正式评价都按卡上的系数算体积重、按卡上的策略取整、用卡绑定序列的在用版本按计价基准时点换算；政策上那一份不改变结果，版本清单里没有任何商业依据引用（ADR-0260 决定一至三） |

## 序列与目录复核：复核者由租户的复核职责规则定

人工复核一版计价参考序列或目录时，复核者须否不同于登记者、须持哪一格授予，按租户登记的参考复核职责规则判；规则未登记时复核不放行（[ADR-0262](../../adr/0262-reference-series-and-catalogue-review-duty-separation-is-a-tenant-governance-rule.md)）。

| 编号 | 场景 | 期望结果 |
|---|---|---|
| `AT-PP-014` | 租户没有登记参考复核职责规则，操作者复核一版手工登记的序列或目录 | 答未配置，不落复核行，那一版不进在用；不按默认双人或默认单人放行（ADR-0262 决定一） |
| `AT-PP-015` | 规则要求不同主体，登记者本人复核；或规则不要求不同主体，登记者本人复核；或规则要求某一格授予而复核者没有 | 第一种答须换人（`NEEDS_ANOTHER_REVIEWER`）、不落复核行；第二种落复核行，通过即自复核时刻起在用；第三种答复核者不合格、不落复核行；经受控 CLI 复核而规则要求某一格授予时，不论复核者是谁，一律答复核者不合格（批文带不出授予集）（ADR-0262 决定一） |
| `AT-PP-016` | 租户对某一来源声明了免人工复核，连接器登记一版序列后代写复核；租户没有登记参考复核职责规则；另一来源的绑定把登记者填成了连接器身份 | 代写复核不读规则，规则未登记时照常落复核行、那一版自复核时刻起在用；登记者等于连接器身份的那一份答 `NEEDS_ANOTHER_REVIEWER`、不落复核行（ADR-0262 决定一） |

## 给开发的交接

- 分层落在 `internal/parcelpricing`：试算编排与补齐读数的共用件在 `application`；编排依赖里没有评价库写口与交付口（结构保证，ADR-0152 决定二）；`EvaluatePricingHandler` 改用共用件、行为不变。
- 入口在 `internal/parcelpricing/adapters/http`：`cmd/parcel-api` 端点表把 `/pricing-estimates` 挂在操作者渠道的计价查阅读（`operatorRegistries.pricingOperationsRead`）——试算不写任何册、不形成生产事实，不挂登记册配置写；接口字段与错误码按 ADR-0152 决定七与 ADR-0022 定，不在本用例。
- 真实价卡、目录与序列属租户取值（[参数登记册](../../product/PILOT-PARAMETER-REGISTER.md) `PAR-SET-02/03` 等），未提供时本用例如实答价卡未配置，不预置任何卡。演示租户 `SYN-TENANT-01` 的种子卡只作 `S` 走通。

# UC-WF-016 出库截单

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁可以代录截单与各项授予待租户提供

## 目标与边界

本用例从货主撤回尚未出库确认的出库请求或其中的包裹开始，到预占释放、分配撤销、已拣出的货回库，或已提交的委托先撤回、取消为止。打包前按整份、打包后按包裹、已出库确认的不再受理，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「出库截单」「出库请求与发出」为准，本用例只组织输入、结果、流程与验收。

本用例解决「货还没离开仓，货主不要这一件了」一个问题。出库确认之后的取消不在本用例。

本用例包含：

- 打包前撤回整份出库请求。
- 打包后逐包裹撤回。
- 已提交委托的，先按小包托运的规则撤回或取消，成立后拆包回库。
- 拣货事实晚到、分配已经撤销的：照记移入待出库，同笔生成回库任务。

本用例不执行：

- 出库确认之后的取消（UC-WF-015 不再把这样的请求交进本用例）。
- 退货入库。回库与拆包回库是库内移动。
- 委托撤回成不成立的判断。那是小包托运对 UC-WF-014 那次请求的答复。

## 启动条件

- 部署已打开仓配开关。关着时各口不提供业务答复。
- 一个仓都没登记的租户，截单答未配置。
- 代录要有「出库请求代录」授予，没有答未授予。指名在册请求的，货主取自那份请求。

## 结果语义契约

| 结果 | 业务含义 | 必须留下 | 明确不是 |
|---|---|---|---|
| 已取消 | 整份截回 | 未分配的预占释放；已分配未拣的分配撤销并释放 | 已出库确认的包裹不在内 |
| 部分取消 | 打包后截回一个包裹 | 该包裹拆包回库 | 其余包裹继续 |
| 截单不成立 | 委托撤回或取消不被放行 | 货与委托保持原状 | 不先拆包 |

| 已有结果 | 同一请求或同一包裹的同一撤回重投 | | |
| 状态不符 | 已经出库确认，或整份已经取消 | 不改账 | |

## 应用流程

1. 看请求或包裹所处的阶段（`WF-RULE`）。
2. 未分配：释放预占，整份已取消。
3. 已分配未拣：撤销分配并释放预占。
4. 已拣出未提交委托：生成回库。货回到可分配库区后释放预占。
5. 已提交委托：先经 UC-WF-014 撤回或取消。放行则拆包回库。不放行则这一件截单不成立。
6. 晚到的拣货：分配已撤销的，照记移入待出库并生成回库任务。

## 一致性、幂等与并发

- 货主口按来源请求键加命令认重放。代录按决定标识认。
- 同一包裹上的截单与出库确认串行。先出库确认的，截单答状态不符。
- 释放只释放还没消耗的部分（`WF-RULE`）。

## 权限、隔离与审计

- 货主只撤回自己的请求。
- 代录的依据引用逐字保存，货主读得到。
- 判准入范围。对照没登答不在准入范围。

## 首发试点叠加条件

演示租户的代录授予在演示种子里配，证据记 `S`。没配时代录截单答未授予，货主自己的撤回不受影响。

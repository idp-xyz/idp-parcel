# UC-WF-002 维护货主商品并登记仓测尺寸重量

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；各货主的商品资料、谁有权代录与各项授予待租户提供

## 目标与边界

本用例从货主经客户渠道交来一份商品资料修订（或运营按货主授权代录），或仓内作业登记一次仓测开始，到修订落册、仓测追加一版（或如实答出为什么没有）为止，另含商品的查阅。商品资料怎样修订、哪些格登记后不改、识别码怎样不相撞、仓测怎样留版，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「主数据登记」为准，本用例只组织输入、结果、流程与验收。

本用例解决「这个货主有哪些商品，各用哪些码识别、怎样计量，仓实测到的尺寸重量是多少」一个问题。它不判断归类与合规，那归 `customs-compliance`；它不改库存账。

本用例包含：

- 货主经首方客户渠道登记商品、追加修订：基本单位与包装层级、是否跟踪批号与效期、商品别名、组合商品的组成与出库方式、商品申报资料、货主声明的尺寸重量。
- 运营按货主授权代录同一份修订。
- 仓内作业登记仓测尺寸重量：按（商品，包装层级），或按在库的一箱。
- 运营与货主查阅商品与仓测。

本用例不执行：

- 商品的停用、废弃与仓对商品的审核（`BD-WF-002`、`BD-WF-003`）。
- 库存账的任何改动：改跟踪属性只看这个商品有没有在库库存，不动库存。
- 申报资料的归类与合规判断。
- 按组成加工或拆解：那是库内作业。
- 仓测对此前已形成的收费发生项的作用：归收费发生项的用例。
- 向一线作业端下发商品与别名：归一线作业端的契约。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 本租户至少登记了一个仓；一个都没有时商品的两个写口答未配置，仓测登记答查无所指的仓（`WF-RULE`，`ADR-OPT` 决定五）。
- 货主口：首方客户渠道族已配置，客户端持「商品维护」授予（参数登记册 `PAR-INT-13`）。代录口：操作者持「商品代录」这一种运营决定的授予（`PAR-INT-08`）。仓测：操作者持这个仓的作业范围授予，设备已登记在用（`PAR-INT-08`、`PAR-INT-10`）。未配置、未授予各答其格。
- 三个面的写都判准入范围（`PAR-INT-11`）；对照没登的租户照各族的规则答不在准入范围。
- 谁有权代录是租户取值。代码与迁移不带任何默认的商品、别名、包装层级或代录人。
- 演示租户 `SYN-TENANT-01` 的商品在演示种子里配，证据记 `S`。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 商品修订已登记 | 新修订落册，自登记那一刻生效 | 商品身份、修订号、完整资料、提交途径（货主或代录）、来源请求键或决定标识、代录的操作者与依据引用、登记时刻 | 此前据旧修订形成的事实被改写；归类或合规已判 |
| 已有结果 | 同一接入请求（代录是同一决定标识）、内容相同的重投；仓测是同一事实身份、内容相同的重复到达 | 回显在册结果 | 新修订、仓测的第二版 |
| 来源冲突 | 同一接入请求（代录是同一决定标识）、内容不同 | 无 | 覆盖在册的修订 |
| 内容冲突 | 仓测的同一事实身份已在册，这一次的内容与在册的不同 | 无；在册的那一版不变 | 覆盖在册的那一版；追加第二版 |
| 基准过期 | 基准修订不是当前修订：别人已先落了新修订，没带基准而商品已登记，或带了基准而商品还没登记 | 无；回显当前修订号，没登记的答没登记 | 合并两份修订 |
| 不可改的格 | 改了登记后不改的格，或商品有在库库存时改是否跟踪批号、效期 | 无；指出哪一格 | 就地改写；代为迁移库存 |
| 识别码冲突 | 商品编码或别名在同一货主内同一时刻已指向别的商品，或同一份资料里一个码出现两次 | 无；指出哪个码 | 改指或抢占那个码 |
| 资料内容不合 | 包装层级、组成、目录码或有效区间不成立 | 无；逐格指出 | 取默认值、代为折算 |
| 未配置 | 本租户一个仓都没登记 | 无 | 代建仓 |
| 仓测已登记 | 这次仓测追加为一版 | 对象、数值与单位、仓、设备与操作者、发生时间与序号、接收时间 | 此前各版被改写；已形成的收费发生项被改写 |
| 查无所指的仓 | 仓测登记指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓 |
| 仓不受理 | 仓测登记指名的仓是代理仓 | 无 | 改记到别的仓 |
| 仓测未受理 | 对象查不到（商品没登记、包装层级没声明、箱不在库）；单位、数值不成立 | 无；指出哪一格 | 代建商品或包装层级 |

信封一层的「发行方未配置」「令牌无效」「未授予」「设备未登记或已停用」「不在准入范围」与坏载荷，客户面照 ADR-0139 决定四，运营决定面照 ADR-0151 决定一、三，作业事实登记面照 ADR-0149 决定二、四作答，不读册、不写册。查阅不判准入范围。代录指名的货主客户账户在本租户查不到，与越权探针同答。客户面读别的货主的商品编码，与查无此商品同答。

业务拒绝、未决与技术失败分开：来源冲突、内容冲突、基准过期、不可改的格、识别码冲突、资料内容不合、查无所指的仓、仓不受理与仓测未受理都是已形成的答案，册不变时原样重交得同一个答案；未配置是租户取值没到，不是拒绝；代录时 `party-commercial` 读不动，或册读写不动，都不形成答案，不折成拒绝。

## 一致性、幂等与并发

- 货主口按来源请求键认重放。来源请求键由首方族的推导口自接入请求标识取，标识只在这一种命令内唯一（ADR-0310 决定一）。代录口按调用方给的决定标识认重放。
- 同一商品只有一条修订序列，货主口与代录口写的是同一条。两笔都基于同一修订的并发修订至多一笔落册，另一笔答基准过期。
- 识别码的唯一在落册那一笔里判：两个商品并发抢同一个码，至多一个落册，另一个答识别码冲突。
- 改是否跟踪批号、效期与收货入账并发时按落册先后：修订先落，之后的收货照新修订判；收货先入账，修订答不可改的格。
- 仓测按设备签发的事实身份认重放（ADR-0023），内容按这个口的规范化形状比（ADR-0149 决定四）：同一身份、内容相同的重复到达答已有结果，不追加第二版；同一身份、内容不同的答内容冲突，在册的那一版不变。查无所指的仓、仓不受理与仓测未受理的不落册，不占事实身份。
- 当前那一版仓测按发生时间与设备序号定序，不按到达先后：迟到的旧仓测照记为一版，不顶掉更晚发生的那一版。
- 商品修订自登记那一刻生效。按码识别商品取事实发生那一刻的指向（`WF-RULE`），离线事实迟到时按它发生那一刻在用的修订解析。

## 权限、隔离与审计

- 货主只能维护与查阅自己客户账户的商品。商品身份带货主，别的货主的同一编码是另一个商品，读不到也撞不上。
- 代录要「商品代录」授予，不另问 `party-commercial` 的授权裁定（`BD-WF-004`）。操作者只进操作证据，不成为商品的所有者；代录的每一笔记下录入的操作者与依据引用。货主的读口对每个修订带出提交途径，代录的另带依据引用，不带录入的操作者。
- 仓测要这个仓的作业范围授予与已登记在用的设备。
- 依据引用不以明文进日志或指标。商品申报资料是货主的声明性资料，只对该货主与本租户的运营可见。
- 审计至少关联商品、修订号、提交途径、来源请求键或决定标识、操作者与依据引用；仓测关联对象、仓、设备、操作者与发生时间。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 三个面的写照各族判准入范围。某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定；仓配的写落在治理登记册的哪个对象范围随它一起没有定，本用例不替它定。
- 真实的商品资料与代录授予没有时，可以实现修订、识别码、代录留痕与仓测的机制，以及显式未配置与受控 `S`；演示租户的取值只在演示种子里。

## 待确认业务决策

以下项目不改变本用例的修订序列与所有权边界：

| ID | 待确认决策 | 归类 | 当前建议 | 影响 |
|---|---|---|---|---|
| `BD-WF-002` | 商品要不要能停用或废弃 | 产品策略 | 首版不设：商品登记后一直在，不删不停；不想再收，货主不再预报即可 | 设的话要定有在库库存、有在途单据时能不能停；不设的代价是识别空间只增不减，登错的商品编码一直占着那个码 |
| `BD-WF-003` | 货主新建或修改商品，要不要经仓审核才生效 | 产品策略；开不开审核是租户取值 | 首版不设审核，修订登记即生效 | 设的话多一个待审核的状态与一种运营决定 |
| `BD-WF-004` | 运营代录除了授予与依据引用，要不要另凭货主在合同上的委派 | 产品策略 | 首版只要代录那一种运营决定的授予与依据引用，不问 `party-commercial` 的授权裁定；商品、入库预报与收货差异结论的代录同此 | 要的话，`party-commercial` 的授权动作要为仓配的代录添词，代录多一次授权裁定与一格授权未配置。`party-commercial` 的「合同委派」写着「运营角色代客户提出请求而没有委派时，该请求没有实际决定方，不得以登录操作人顶替。」委派是按它的授权动作声明的，今天的授权动作里没有入库一侧的代录，所以首版落在它之外：代录不把操作者记成决定方，只记录入人与货主授权的依据引用，货主在自己的读口看得到每一笔代录 |
| `BD-WF-005` | 组合商品的组件能不能是组合商品 | 产品策略 | 首版不做多级组合，组件须是非组合商品 | 做的话要定展开层数与环的检测 |

待定格按三类归：

- 机制：修订序列与基准、同一货主内的识别空间、组成版本、代录留痕、仓测的留版与定序、未测量与没登记仓的如实答法。现在做完。

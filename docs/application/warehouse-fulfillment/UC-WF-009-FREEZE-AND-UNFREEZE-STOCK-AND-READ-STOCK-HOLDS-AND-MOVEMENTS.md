# UC-WF-009 冻结、解冻并查阅库存

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁有权冻结与解冻、仓的业务时区、各项授予待租户提供

## 目标与边界

本用例从运营决定冻结一格库存开始，到解冻决定作出、这些数量回到可用量为止，另含运营与货主对库存账、各项占用、可用量与库存流水的查阅。冻结占什么、何时不成立、怎样解除，各项占用怎样互不重叠，可用量怎样得出，库龄怎样计日，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「库存账」「占用与可用量」各词条、「占用、预占与分配」与「冻结」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「这格货先别分出去，以及此刻有多少货、被什么占着、还能用多少，怎样如实答」一个问题。冻结不动库存账：不记流水，货不挪地方，库存状态不变。

本用例包含：

- 运营冻结一格商品库存里的一个数量，或一箱整箱库存，带原因。
- 运营解冻。
- 运营查阅库存账（按格与按箱）、各项占用、可用量与库存流水。
- 货主查阅自己的在库量、各项占用的数量、可用量、库龄与库存流水。

本用例不执行：

- 预占与分配：归出库的用例。作业锁定随盘点加与解（[UC-WF-010](./UC-WF-010-COUNT-STOCK.md)）。
- 挪动或处置冻结着的货：冻结着的数量不被移走、转换、加工、换标或调减，各用例各有答法（[UC-WF-007](./UC-WF-007-PUT-AWAY-MOVE-REPLENISH-AND-CONVERT-STOCK.md)、[UC-WF-008](./UC-WF-008-PROCESS-AND-RELABEL-GOODS-ON-INSTRUCTION-AND-UNBOX-CARTONS.md)、[UC-WF-011](./UC-WF-011-RESOLVE-STOCK-DISCREPANCIES-AND-APPROVE-STOCK-ADJUSTMENTS.md)）。
- 部分解冻（`BD-WF-024`）、不落到格的整体停售（`BD-WF-025`）、货主自己冻结（`BD-WF-026`）。
- 代理仓库存声明的查阅：归代理仓的用例；它不进库存账，也不与自营仓的库存相加。
- 入库预报、出库请求等单据的查阅：各归各的用例。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 冻结与解冻：操作者持「库存冻结」这一种运营决定的授予；运营查阅要「主数据与运营查阅读」授予（参数登记册 `PAR-INT-08`）。货主查阅：首方客户渠道族已配置，客户端持「仓配查阅」授予（`PAR-INT-13`）。未配置、未授予各答其格。
- 冻结与解冻判准入范围（`PAR-INT-11`）；对照没登的租户照运营决定面的规则答不在准入范围。查阅不判。
- 冻结只对自营仓的库存账；停用的仓照常可以冻结与解冻（`WF-RULE`）。
- 仓的业务时区是租户取值；没登记时库龄答未配置，在库量、占用与可用量照答（`WF-RULE`）。
- 一个仓都没登记的租户：冻结答查无所指的仓，解冻答未配置，读口答空（`WF-RULE`，`ADR-OPT` 决定五）。
- 演示租户 `SYN-TENANT-01` 的仓、在库库存与授予在演示种子里配，证据记 `S`。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 已冻结 | 所指的数量（或那一箱）从此不可用，直到解冻 | 冻结标识、格或箱、数量、原因、决定标识、操作者、时刻 | 库存账变了；货被挪走了；库存状态变了 |
| 冻结不成立 | 所指的不是可分配库存；那一格没被占着的数量不够；或冻结成立会违反占用规则（`WF-RULE`） | 无；指出哪一种 | 冻结够的那一部分；挤占已成立的预占 |
| 冻结内容不合 | 所指的库位、商品、入库批次或箱在这个仓查不到 | 无；指出哪一格 | 代建库位或商品 |
| 已解冻 | 冻结解除，数量回到可用量 | 解冻的操作者、时刻与说明；原冻结照留 | 库存账变了 |
| 已有结果 | 同一决定标识、内容相同的重投；已解冻的冻结再被解冻 | 回显在册结果 | 第二份冻结 |
| 来源冲突 | 同一决定标识、内容不同 | 无 | 覆盖在册的冻结 |
| 查无此冻结 | 指名的冻结在本租户查不到 | 无 | 泄露别的租户的冻结 |
| 查无所指的仓 | 冻结指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓 |
| 仓不受理 | 冻结指名的仓是代理仓 | 无 | 改冻别的仓 |
| 未配置 | 解冻到达时本租户一个仓都没登记 | 无 | 代建仓 |

读口答读那一刻的账。运营的读口：按格答货主、商品、计量单位、库存状态、贴标别名、批号、效期、库位、入库批次与它的入库时间、数量与库龄；按箱答货主、箱号、库位、箱单、入库批次与入库时间；占用答冻结（哪一格、多少、原因、谁在何时冻的）、作业锁定（哪一格、多少、哪一份盘点）、预占与分配（哪份出库请求、多少、落到了哪些格）；按汇总答（货主，仓，商品，库存状态）上的在库量、可分配库存、各项占用与可用量；流水答原因、各格的增减、来源事实引用、发生时间与入账时刻。货主的读口只答自己客户账户的：各商品按仓、计量单位、库存状态、贴标别名、批号、效期与入库批次的在库量、入库时间与库龄，分可分配与不可分配；预占、冻结与作业锁定各占了多少；可用量；整箱的箱号、箱单、入库时间与是不是被占着；流水的原因、数量、时刻与来源事实的种类，销毁的另带货主授权的依据引用。货主的读口不带库位，不带冻结的原因与操作者（`BD-WF-027`）。

可用量照 `WF-LANG`「可用量」得出；读口上的可用量与预占的原子判定用同一个算法，本用例不另写算式。库龄照 `WF-LANG`「库龄」按仓的业务时区计日，仓的业务时区没登记时这一格答未配置。

信封一层的「发行方未配置」「令牌无效」「未授予」「不在准入范围」与坏载荷，运营决定面照 ADR-0151 决定一、三，客户面照 ADR-0139 决定四作答，不读册、不写册。查阅不判准入范围。货主的读口筛选别的货主的商品，读到的是空。

业务拒绝、未决与技术失败分开：冻结不成立、冻结内容不合与来源冲突都是已形成的答案；未配置是租户取值没到，不是拒绝；册读写不动不形成答案，提交方原样重交。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 操作者渠道 | 认证操作者，核「库存冻结」授予与准入范围；租户与提交操作者取自信封；载荷形状不合即拒 | 信封各格或坏载荷直接作答 |
| 2 | `warehouse-fulfillment` | 按决定标识认重放与冲突 | 答已有结果或来源冲突；都不是则继续 |
| 3 | `warehouse-fulfillment` | 核指名的仓：在本租户已登记、是自营仓；核所指的格或箱查得到 | 没登记答查无所指的仓；代理仓答仓不受理；查不到答冻结内容不合 |
| 4 | `warehouse-fulfillment` | 在库存账内原子判定：所指的是可分配库存、那一格没被占着的数量够、冻结成立之后不违反占用规则 | 成立的落册，答已冻结，库存账不变；否则答冻结不成立 |
| 5 | 运营操作者 | 解冻：指名一份冻结 | 本租户一个仓都没登记答未配置；已冻结的进入已解冻，数量回到可用量；已解冻的答已有结果；查不到答查无此冻结 |
| 6 | 运营操作者或货主 | 查阅库存、占用、可用量与流水 | 如实答读那一刻的账；货主只读得到自己客户账户的 |

## 一致性、幂等与并发

- 冻结在库存账内原子判定（`WF-RULE`），与预占、作业锁定和同一格上的入账串行：并发争同一批可用量的，成立得下的那一个成立，后到的不成立。冻结不满足占用规则时不成立，不挤占已成立的预占。
- 冻结按调用方给的决定标识认重放：同一标识、内容相同答已有结果，内容不同答来源冲突。解冻的重放身份取被指名的冻结：一份冻结只解冻一次，已解冻的再被解冻答已有结果。
- 冻结只经解冻决定解除（`WF-RULE`）：不因过了多久、仓被停用或那一格之后的入账而自动解除。冻结着的数量不被别的入账取走，所以它不会比那一格的余额多。
- 冻结整份成立或整份不成立，不冻够的那一部分；解冻整份解除。
- 读口答的是读那一刻的账，不是承诺：读到的可用量之后可能被预占或冻结占走，要占住只能经出库请求的预占或冻结。
- 读口上的余额由库存流水派生（`WF-RULE`），与流水对得上；已入账的流水不改不删，更正只以新流水出现在流水里。

## 权限、隔离与审计

- 冻结与解冻要「库存冻结」授予；谁持有是租户取值。每一笔记下操作者与时刻。
- 库存账按租户隔离、按货主分：货主只能读自己客户账户的库存、占用的数量与流水，别的货主的格、箱与流水读不到。
- 冻结的原因逐字保存，只在操作者面；它可能写着争议与内部判断，不上客户面，也不以明文进日志或指标。
- 审计至少关联冻结、格或箱、数量、原因、冻结与解冻的操作者与时刻。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 冻结与解冻照运营决定面判准入范围。某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定；仓配的写落在治理登记册的哪个对象范围随它一起没有定，本用例不替它定。
- 真实的库存、时区与授予没有时，可以实现冻结的原子判定、解冻与读口的机制，以及显式的未登记答法与受控 `S`；演示租户的取值只在演示种子里。

## 待确认业务决策

以下项目不改变本用例「冻结只占可用量、不动库存账，读口如实答」的边界：

| ID | 待确认决策 | 归类 | 当前建议 | 影响 |
|---|---|---|---|---|

| `BD-WF-025` | 要不要不落到格的冻结：按货主或商品整体停售，新入库的货也自动不可用 | 产品策略 | 首版不设：冻结按格，整体停售要对在库的每一格各冻一份，之后入库的货不会自动被冻 | 设的话占用多一种粒度，要定它与预占的原子判定怎样合在一起 |
| `BD-WF-026` | 货主能不能自己冻结自己的库存 | 产品策略 | 首版不设：货主在系统外提出，运营冻结并在原因里写明 | 设的话客户面多一个写口，要定货主冻的与运营冻的谁能解 |

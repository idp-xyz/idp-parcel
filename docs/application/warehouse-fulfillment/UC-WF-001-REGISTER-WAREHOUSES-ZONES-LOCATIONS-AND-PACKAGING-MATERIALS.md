# UC-WF-001 登记仓、库区、库位与包材

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；各仓、库区、库位、库位类型、包材与各项授予待租户提供

## 目标与边界

本用例从运营操作者提交一笔仓、库区、库位、库位类型或包材的登记修订开始，到这笔修订落册（或如实答出为什么没落）为止，另含这五册的查阅。哪些格登记后不改、停用挡什么，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「主数据登记」为准，本用例只组织输入、结果、流程与验收。

本用例解决「这个租户有哪些仓，仓里怎样划库区与库位，打包用哪些包材」一个问题。它不维护货主商品，不搬动库存，也不把仓与 `network-routing` 的物流节点合成一个身份。

本用例包含：

- 仓、库区、库位、库位类型与包材的登记：首次登记、改资料、停用与再启用，各是一笔新修订。
- 经受控批量口成批登记。
- 运营查阅这五册；货主的客户系统查阅本租户的仓。

本用例不执行：

- 货主商品的维护与仓测尺寸重量的登记（[UC-WF-002](./UC-WF-002-MAINTAIN-OWNER-GOODS-AND-RECORD-WAREHOUSE-MEASUREMENTS.md)）。
- 待认领到货处置规则的登记（[UC-WF-005](./UC-WF-005-REGISTER-CLAIM-AND-DISPOSE-OF-UNCLAIMED-ARRIVALS.md)）。
- 仓配其余租户取值的登记：重量与体积类计量的单位、库龄口径、缺货处置、分配策略的采用、增值服务项目表、差异与调整的批准权限。它们各随用到它们的用例写。
- 向一线作业端下发库区与库位：下发的内容、有效区间与离线边界归一线作业端的契约。
- 移库：停用一个库位不移走它上面的库存。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复，受控批量口拒绝执行。
- 操作者渠道已配置；登记要「登记册配置写」授予，查阅要「主数据与运营查阅读」授予（参数登记册 `PAR-INT-08`）。未配置、令牌无效、未授予各答其格（ADR-0100 决定四）。
- 货主查阅仓：首方客户渠道族已配置，客户端持仓配查阅的授予（`PAR-INT-13`）。
- 五册的每一行都是租户取值。代码与迁移不带任何默认的仓、库区、库位、库位类型或包材；没登记时各读口如实答空。一个仓都没登记的租户，只有登记仓的口照常受理，那是从没登记走到登记的路（`WF-RULE`，`ADR-OPT` 决定五）：库位类型与包材不指名仓，这时答未配置；库区与库位指名的仓查不到，答未受理（查无所指），这就是登记面上的「查无所指的仓」。
- 演示租户 `SYN-TENANT-01` 的仓、库区、库位、库位类型与包材在演示种子里配，证据记 `S`。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 已登记 | 这笔修订落册，自登记那一刻生效 | 对象身份、修订号、修订的全部内容、登记责任方、登记时刻 | 此前已形成的事实被改写；上面的库存被移走 |
| 已登记（重放） | 同一对象同一修订号、内容相同的重投 | 无：回显在册的那一份 | 新修订 |
| 内容冲突 | 同一对象同一修订号、内容不同 | 无 | 覆盖在册的修订 |
| 未受理：修订错位 | 修订号不是在册最新修订的下一个；首次登记的修订号不是 1 | 无；回显在册最新修订号 | 跳号落册 |
| 未受理：不可改的格 | 新修订改了登记后不改的格：仓的自营仓、代理仓之分，库区的用途，库位的所属库区 | 无；指出哪一格 | 就地改写 |
| 未受理：查无所指 | 指名的仓、库区或库位类型在本租户查不到，或库位指名的库区不属于同一个仓 | 无；指出哪一格 | 代建所指的对象 |
| 未受理：所指已停用 | 库位新指名的库位类型已停用 | 无 | 沿用旧类型 |
| 未受理：内容不合 | 国家或单位不在内置目录、单位的类别不对、业务时区认不出、数值不为正 | 无；指出哪一格 | 取默认值或代为折算 |
| 未配置 | 登记库位类型或包材时本租户一个仓都没登记 | 无 | 代建仓；先存下这一行等仓登记 |
| 查阅结果 | 本租户此刻在册的行，带当前修订与是否停用 | 无 | 空册等于未配置 |

信封一层的「发行方未配置」「令牌无效」「未授予」与坏载荷，操作者面照 ADR-0100 决定四、客户面照 ADR-0139 决定四作答，不读册、不写册。登记册配置写面不判准入范围：登记一个修订不形成生产事实（ADR-0100 决定四）。别的租户的仓、库区、库位与库位类型在本租户一律答查无所指，不泄露是否存在。空册的查阅答空列表，不答未配置（ADR-0077 决定四）。

业务拒绝、未决与技术失败分开：内容冲突与各种未受理都是已形成的答案，册不变时原样重交得同一个答案；未配置是租户取值没到（还没登记仓），不是拒绝，登记仓之后原样重交照常受理；本用例没有未决；册读写不动不形成答案，不折成拒绝，提交方原样重交。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 操作者渠道 | 认证操作者，核「登记册配置写」授予；租户与登记责任方取自信封；载荷形状不合、带集外词或自带租户即拒 | 信封各格或坏载荷直接作答 |
| 2 | `warehouse-fulfillment` | 按（对象身份，修订号）找在册的修订：有且内容相同答已登记（重放），有而内容不同答内容冲突 | 都不是则继续 |
| 3 | `warehouse-fulfillment` | 登记库位类型或包材的，先看本租户有没有登记过仓；再核修订号与在册最新修订连续，核不可改的格，核所指的仓、库区与库位类型，核目录码、时区名与数值 | 一个仓都没登记答未配置；其余任一不成立答未受理并给理由；册都不变 |
| 4 | `warehouse-fulfillment` | 落册 | 答已登记；新修订自这一刻生效，停用与再启用照 `WF-RULE` 只作用于此后 |
| 5 | 受控批量口 | 对批文逐行重复步骤 2 至 4 | 逐行作答 |
| 6 | 查阅方 | 运营按册查阅当前修订与修订史；货主的客户系统查阅仓 | 如实答列表，空册答空列表 |

## 一致性、幂等与并发

- 重放与冲突按（对象身份，修订号）与修订内容判，不看登记责任方与登记时刻：换一个操作者原样重投仍是重放。
- 同一对象的修订串行落册。并发提交同一修订号的两笔，至多一笔落册，另一笔按内容答已登记（重放）或内容冲突；修订号不连续的不落。
- 受控批量口逐行独立：整份批文原样重投，已落的行答已登记（重放），当初未受理或答未配置的行照当下的册重判。
- 查阅读已落册的修订，不承诺读到在途的写。
- 停用自落册那一刻生效。此前已受理的单据、已下发的任务与已在库的库存不受影响；此后到达的、已经发生的作业事实照记（`WF-RULE`）。

## 权限、隔离与审计

- 登记册配置写与主数据与运营查阅读两族不分上下文，持有它们的操作者就能登记或查阅仓（`ADR-OPT` 越权风险点 5）；要不要为仓配另开能力面不在本用例定。
- 租户只从信封来。五册都按租户隔离；库位类型与包材在租户内各仓共用，库区与库位属于一个仓。
- 货主的客户系统只读得到仓（仓编码、名称、地址、自营仓或代理仓、是否停用）。仓不按货主分，本租户的各货主读到同一份。
- 每笔修订带登记责任方与登记时刻；修订史只追加，停用与再启用都看得出是谁在何时作的。
- 仓的地址是经营场所地址。日志与指标里只带仓编码，不带地址正文。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 某个租户在生产上启用仓配怎样经 PN-08 的阶段准入，`ADR-OPT` 越权风险点 7 留着没定，本用例不替它定。
- 真实的仓、库区、库位、库位类型与包材没有时，可以实现登记机制、未登记的如实答法与受控 `S`；演示租户的取值只在演示种子里。

| `AT-WF-007` | 停用一个有在库库存、有已受理入库预报的仓；之后再启用 | 停用的修订落册；在库库存与已受理的入库预报不变，已预报的照常收货，出库请求照常受理；停用期间新交的入库预报与建账导入答仓不受理（UC-WF-003、UC-WF-006）；再启用之后照常受理 |
| `AT-WF-008` | 停用一个有库存的库位与一个库区；一台设备在停用之前已离线记下把货移入那个库位，事实在停用之后才到 | 停用落册，上面的库存不动；此后读可选的移入目标不含它们；那条已经发生的作业事实照记，不拒 |
| `AT-WF-009` | 一个仓都没登记的租户：运营查阅五册；货主的客户系统查阅仓；登记库位类型；登记包材；登记库区；登记仓；之后把登记库位类型的同一修订原样重交 | 两种查阅各答空列表，不答未配置，也不出现默认仓、默认库区、默认库位、默认库位类型或默认包材；库位类型与包材答未配置，库区答未受理（查无所指）并指出仓那一格，都不落册；登记仓答已登记，不以已有仓为前提；重交答已登记（`ADR-OPT` 决定五，ADR-0077 决定四） |
| `AT-WF-010` | 操作者渠道的发行方未配置；令牌无效；操作者没有「登记册配置写」授予；持授予登记；只持「登记册配置写」而没有查阅授予的操作者去查阅 | 前三种各答其格，不读册、不写册；持授予的照常登记，全程不判准入范围；没有查阅授予的答未授予 |
| `AT-WF-011` | 经受控批量口登一份含仓、库区、库位若干行的批文，其中一行修订错位；整份原样重投 | 逐行按批文次序作答：错位那一行答未受理（修订错位），其余落册；重投时已落的行答已登记（重放），不多登一份 |
| `AT-WF-012` | 部署没打开仓配开关：调用本用例的登记口与查阅口；运行受控批量口；同一部署跑其他上下文的全套用例 | 各端点不提供业务答复，也不折成 404；受控批量口拒绝执行；其他上下文各用例的答复与交出的信封，和没有仓配代码时相同（`ADR-OPT` 决定一、四） |
| `AT-WF-013` | 货主的客户系统查阅仓：持仓配查阅的授予；没有授予；想读库区、库位、库位类型或包材 | 持授予的答本租户在册的仓，带仓编码、名称、地址、自营仓或代理仓与是否停用；没有授予答未授予；客户面没有另外四册的读口 |

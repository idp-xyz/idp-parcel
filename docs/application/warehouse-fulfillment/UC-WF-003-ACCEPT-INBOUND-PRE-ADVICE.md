# UC-WF-003 受理入库预报

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁有权代录、仓的业务时区、单据编号规则与各项授予待租户提供

## 目标与边界

本用例从货主经客户渠道提交入库预报（或运营按货主授权代录）开始，到预报进入已预报并取得单据号，或在第一次收货确认之前被撤回为止，另含预报的查阅。预报写什么、受理之后不改、撤回到哪一刻为止，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「入库与加工」与「入库预报」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「货主告诉仓将有什么货、以什么方式到」一个问题。预报不是库存，也不承诺实收；收货、收货差异与完结归 [UC-WF-004](./UC-WF-004-CONFIRM-RECEIPT-AND-CLOSE-OUT-AN-INBOUND-PRE-ADVICE.md)。

本用例包含：

- 货主提交入库预报：商品入库或整箱入库。
- 货主在第一次收货确认之前撤回预报。
- 运营按货主授权代录提交与撤回。
- 预报进入已预报时取得单据号。
- 货主与运营查阅预报。

本用例不执行：

- 收货确认、收货差异与完结（UC-WF-004）。
- 受理之后修改预报内容（`BD-WF-006`）；仓对预报的审核（`BD-WF-007`）。
- 退货预报：归退货的用例。
- 指名代理仓的入库：代理仓不受理入库预报，由货主与代理仓直接办。
- 没有预报的到货：归 [UC-WF-005](./UC-WF-005-REGISTER-CLAIM-AND-DISPOSE-OF-UNCLAIMED-ARRIVALS.md)。

| `party-commercial` | 代录时答指名的货主客户账户在不在本租户 | 不拥有入库预报 |
| 单据编号（技术组件，经本上下文的适配器） | 在受理的同一笔事务里给出单据号 | 不拥有预报，不读业务数据 |

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 货主口：首方客户渠道族已配置，客户端持「入库预报提交」「入库预报撤回」中相应的授予（参数登记册 `PAR-INT-13`）。代录口：操作者持「入库预报代录」这一种运营决定的授予（`PAR-INT-08`）。未配置、未授予各答其格。
- 两个面的写都判准入范围（`PAR-INT-11`）；对照没登的租户照各族的规则答不在准入范围。
- 仓由租户登记，商品由货主登记。指名的仓没登记答查无所指的仓，代码与迁移不带默认仓，也不改投别的仓；一个仓都没登记的租户，撤回答未配置（`WF-RULE`，`ADR-OPT` 决定五）。
- 仓的业务时区、租户的单据编号时区与编号规则都是租户取值；时区都没有时照常受理，只是不带单据号（`ADR-NUM` 决定七）。
- 演示租户 `SYN-TENANT-01` 的仓、商品与授予在演示种子里配，证据记 `S`。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 已预报 | 预报受理，仓、到仓方式、入库方式、预计到仓时间与明细就此固定 | 预报标识、单据号（或无号原因）、货主、仓、全部内容、提交途径、来源请求键或决定标识、代录的操作者与依据引用、受理时刻 | 库存、实收承诺、到仓预约 |
| 已取消 | 预报在第一次收货确认之前被撤回 | 撤回时刻、途径、来源请求键、代录的操作者与依据引用 | 已到仓的货被退回；单据号被释放或复用 |
| 已有结果 | 同一接入请求（代录提交是同一决定标识）、内容相同的重投；已取消的预报再被撤回 | 回显在册结果与原单据号 | 第二份预报、第二个单据号 |
| 来源冲突 | 同一接入请求（代录提交是同一决定标识）、内容不同 | 无 | 覆盖在册的预报 |
| 查无所指的仓 | 指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓、改投别的仓 |
| 未配置 | 撤回时本租户一个仓都没登记 | 无 | 代建仓 |
| 仓不受理 | 指名的仓已停用，或是代理仓 | 无；指出是哪一种 | 改投别的仓 |
| 预报内容不合 | 明细里有不成立的行 | 无；逐行指出 | 丢掉不成立的行、受理其余 |
| 收货已开始 | 撤回时预报已在收货中或已完结 | 无；回显预报当前状态 | 冲回已入账的库存 |
| 查无此预报 | 指名的预报在这个货主名下查不到 | 无 | 泄露别的货主的预报 |
| 编号规则撞号 | 取单据号时跳过到上限仍撞上已用的号（`ADR-NUM` 决定八） | 无：这一次不落预报，取过的流水随事务回滚释放 | 预报已受理、单据号已占 |

信封一层的「发行方未配置」「令牌无效」「未授予」「不在准入范围」与坏载荷，客户面照 ADR-0139 决定四，运营决定面照 ADR-0151 决定一、三作答，不读册、不写册。查阅不判准入范围。代录指名的货主客户账户在本租户查不到，与越权探针同答；指名别的货主的预报，与查无此预报同答。

业务拒绝、未决与技术失败分开：来源冲突、查无所指的仓、仓不受理、预报内容不合、收货已开始与编号规则撞号都是已形成的答案；未配置是租户取值没到，不是拒绝；代录时 `party-commercial` 读不动，或册与单据编号读写不动，都不形成答案，不折成拒绝，提交方原样重交。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 首方客户渠道或操作者渠道 | 认证，核授予与准入范围；租户取自信封，客户面的货主客户账户取自信封；载荷形状不合或带集外词即拒 | 信封各格或坏载荷直接作答 |
| 2 | `warehouse-fulfillment` | 代录的：经消费侧适配器向 `party-commercial` 核指名的货主客户账户在本租户 | 查不到与越权探针同答；读不动不形成答案 |
| 3 | `warehouse-fulfillment` | 按来源请求键（代录提交按决定标识）认重放与冲突 | 重放答已有结果并回显原单与原号，不再取号；冲突答来源冲突 |
| 4 | `warehouse-fulfillment` | 核指名的仓：在本租户已登记、在用、是自营仓 | 没登记答查无所指的仓；停用或代理仓答仓不受理 |
| 5 | `warehouse-fulfillment` | 逐行核明细 | 任一行不成立答预报内容不合，整份不受理 |
| 6 | `warehouse-fulfillment` | 在同一笔事务里落预报为已预报并取单据号：日期按仓的业务时区，仓没登记按租户的单据编号时区，都没有则不带号、记下无号原因 | 答已预报；跳号到上限仍撞号答编号规则撞号，整笔回滚 |
| 7 | 货主或运营操作者 | 撤回：指名预报 | 本租户一个仓都没登记答未配置；预报是已预报则进入已取消；已取消的答已有结果；收货中或已完结答收货已开始 |
| 8 | 查阅方 | 读预报的状态、明细、单据号与累计实收 | 没有单据号的带出无号原因 |

## 一致性、幂等与并发

- 提交按来源请求键认重放。来源请求键由首方族的推导口自接入请求标识取，标识只在这一种命令内唯一（ADR-0310 决定一）；代录提交按调用方给的决定标识认。
- 取号只在认过重放、确定要落预报的那一步，与落预报同一笔事务；重放读回原号，不取第二个（`ADR-NUM` 决定三）。
- 撤回的重放身份取被指名的预报：一份预报只取消一次，已取消的再被撤回，不论哪条途径、哪个接入请求，都答已有结果。货主口的来源请求键随成立的取消落册；已落册的键又来指名另一份预报的，答来源冲突。
- 撤回与这份预报的第一次收货确认按到达本上下文的先后判，同一份预报上串行，只成立一个（`WF-RULE`）。撤回先成立，那条收货事实照 UC-WF-004 转成待认领到货；收货先成立，撤回答收货已开始。
- 受理之后预报内容不改。商品之后追加修订、仓之后被停用，都不回改已受理的预报。

## 权限、隔离与审计

- 货主只能提交、撤回与查阅自己客户账户的预报。
- 代录的提交与撤回是同一种运营决定「入库预报代录」；谁持有是租户取值，不另问 `party-commercial` 的授权裁定（`BD-WF-004`）。代录的每一笔记下录入的操作者与依据引用，操作者只进操作证据。
- 依据引用不以明文进日志或指标。到货线索与货主参考号逐字保存，只对该货主与本租户的运营可见。
- 审计至少关联预报、单据号、货主、仓、提交途径、来源请求键或决定标识、操作者与依据引用、受理与撤回的时刻。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 两个面的写照各族判准入范围。仓配的写落在治理登记册的哪个对象范围、某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定，本用例不替它定。
- 真实的仓、商品、时区与代录授予没有时，可以实现受理、取号、撤回与代录留痕的机制，以及显式的未登记答法与受控 `S`；演示租户的取值只在演示种子里。

待定格按三类归：

- 机制：受理校验、来源请求键与决定标识的重放、同事务取号与无号的如实答法、撤回与收货的先后、代录留痕。现在做完。
- 产品策略：到仓方式的封闭集，入库方式分商品入库与整箱入库；入库预报单据号的类型代码与默认模板；`BD-WF-006` 至 `BD-WF-008` 的当前建议。随产品内置。
- 租户取值：仓的业务时区、租户的单据编号时区与编号规则；谁持有「入库预报代录」授予与客户端的能力授予。留空；时区都没有时照常受理、不带单据号，没有授予照各族的答法。

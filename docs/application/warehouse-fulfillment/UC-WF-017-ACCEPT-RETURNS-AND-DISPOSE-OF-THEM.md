# UC-WF-017 退货预报、退货入库与回库处置

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁有权代录与各项授予待租户提供

## 目标与边界

本用例从货主告知将有退件到仓，或退件已经到仓开始，到退货入库入账、逐件回库处置完为止。认货、入库批次、处置与库内作业的先后，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「退货」「退货入库」与「主数据登记」为准，本用例只组织输入、结果、流程与验收。

本用例解决「退回来的货是谁的、进哪、然后怎么办」一个问题。原出库确认不在这里冲回。

本用例包含：

- 货主提交退货预报，以及没有预报的退件照样到仓。
- 退货入库：认出货主与商品，清点质检，进入退货暂存库区。
- 认不出的建待认领到货；认领之后再入库，引用那件到货。
- 回库处置：良品上架、转次品、销毁，或经新的出库请求退还货主。

本用例不执行：

- 待认领到货的认领与处置口（[UC-WF-005](./UC-WF-005-REGISTER-CLAIM-AND-DISPOSE-OF-UNCLAIMED-ARRIVALS.md)）。本用例只在认不出时建那一件。
- 良品上架与转次品的库内流水（[UC-WF-007](./UC-WF-007-PUT-AWAY-MOVE-REPLENISH-AND-CONVERT-STOCK.md)）。处置只指名去向。
- 销毁的批准与入账（[UC-WF-011](./UC-WF-011-RESOLVE-STOCK-DISCREPANCIES-AND-APPROVE-STOCK-ADJUSTMENTS.md)）。
- 退还货主的出库请求（[UC-WF-012](./UC-WF-012-ACCEPT-AND-RESERVE-AN-OUTBOUND-REQUEST.md)）。
- 指名代理仓的退货预报。代理仓不受理，由货主与代理仓直接办（`WF-RULE`）。

## 启动条件

- 部署已打开仓配开关。关着时各口不提供业务答复。
- 停用的仓不受理新的退货预报（`WF-RULE`）。已在库的退货仍可清点与处置。
- 指名的仓没登记答查无所指的仓。一个仓都没登记时，预报答查无所指的仓；没指名仓的处置答未配置。
- 代录要有「退货代录」授予，没有答未授予。

## 应用流程

1. 预报：核仓。代理仓答仓不受理。停用的仓不受理新预报。
2. 到仓登记：按预报或装箱记录认货主与商品。认不出则建待认领到货。
3. 清点质检：退货入库流水进入退货暂存，新入库批次，库龄从这一刻起算（`WF-RULE`）。
4. 处置逐件作出。执行上架或转次品时货已不在退货暂存，答内容已不成立。销毁交给 UC-WF-011。退还货主交给 UC-WF-012。

## 一致性、幂等与并发

- 预报按来源请求键认重放。入库按事实身份认。处置按决定标识认。
- 同一件上的两份处置串行，先落的成立，后到的答已有结果或来源冲突。
- 没有处置就把货移出退货暂存的，UC-WF-007 照记，本用例不改那笔流水。

## 权限、隔离与审计

- 货主只提交自己的预报与处置指令。
- 代录的依据引用逐字保存，货主读得到。
- 判准入范围。对照没登答不在准入范围。

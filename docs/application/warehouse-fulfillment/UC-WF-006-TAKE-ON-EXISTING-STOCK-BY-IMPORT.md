# UC-WF-006 建账导入

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁有权提交与批准、各仓的库位与各货主的商品待租户提供

## 目标与边界

本用例从运营操作者为一个货主在一个仓提交一份建账导入开始，到这份导入经批准、各行在同一笔里记进库存账，或被驳回为止。建账导入是一种库存调整：它提交时固定什么、批准时怎样入账、入库批次与入库时间怎样取，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「入库与加工」里建账导入的规则、「库存账与守恒」与「建账导入」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「系统切换或货主移仓时，仓里已有的货怎样一次记进库存账」一个问题。它不是收货：不对入库预报，不经收货暂存，不形成收货差异。

本用例包含：

- 运营提交一份建账导入：货主、仓、原因与各行，商品行与整箱行都可以有。
- 提交时整份校验，成立的进入待批准，不改账。
- 批准成立时的入账：各行直接落到指名的库位，形成入库批次，入库时间取声明的那一刻。
- 批准时已不成立与驳回的结果。
- 运营查阅建账导入。

本用例不执行：

- 批准与驳回的口、谁有权批准与没登记时的答法：归库存调整的用例，本用例只写批准成立之后建账导入怎样入账。
- 建账导入之外的库存调整（找回、调增调减、销毁）与盘点差异。
- 日常到货：走入库预报与收货确认（[UC-WF-003](./UC-WF-003-ACCEPT-INBOUND-PRE-ADVICE.md)、[UC-WF-004](./UC-WF-004-CONFIRM-RECEIPT-AND-CLOSE-OUT-AN-INBOUND-PRE-ADVICE.md)）。
- 代理仓的库存：代理仓只收库存声明，不进库存账。
- 占用：建账导入不带预占、冻结或作业锁定。
- 为导入的货补登商品、库位：商品与库位须先登记（[UC-WF-001](./UC-WF-001-REGISTER-WAREHOUSES-ZONES-LOCATIONS-AND-PACKAGING-MATERIALS.md)、[UC-WF-002](./UC-WF-002-MAINTAIN-OWNER-GOODS-AND-RECORD-WAREHOUSE-MEASUREMENTS.md)）。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 已提交待批准 | 这份导入落册，货主、仓与各行就此固定，等批准 | 导入标识、货主、仓、原因、各行的全部内容、提交操作者与时刻 | 库存账已变；可用量已变 |
| 已有结果 | 同一导入标识、内容相同的重投 | 回显在册的导入与它此刻的状态 | 第二份导入 |
| 来源冲突 | 同一导入标识、内容不同 | 无 | 覆盖在册的导入 |
| 查无所指的仓 | 指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓 |
| 仓不受理 | 指名的仓已停用，或是代理仓 | 无；指出是哪一种 | 改投别的仓 |
| 导入内容不合 | 有不成立的行 | 无；逐行指出 | 丢掉不成立的行、受理其余；代建商品或库位 |
| 已入账 | 批准成立：各行在同一笔里以建账导入流水进入指名的库位，形成入库批次 | 批准的操作者与时刻、各行的流水与入库批次引用 | 经过了收货暂存；对上了某份入库预报；形成了收货差异 |
| 内容已不成立 | 批准时有行已不成立：整份不入账，留在待批准 | 无；逐行指出 | 入账其余的行；自动改行 |
| 已驳回 | 这份导入不入账，终态 | 驳回的操作者、时刻与说明 | 库存账已变 |

信封一层的「发行方未配置」「令牌无效」「未授予」「不在准入范围」与坏载荷，照 ADR-0151 决定一、三作答，不读册、不写册。查阅不判准入范围。指名的货主客户账户在本租户查不到，与越权探针同答。

业务拒绝、未决与技术失败分开：来源冲突、查无所指的仓、仓不受理、导入内容不合与内容已不成立都是已形成的答案；留在待批准是未决，不是失败；提交时 `party-commercial` 读不动，或册读写不动，都不形成答案，提交方原样重交。

## 一致性、幂等与并发

- 提交按调用方给的导入标识认重放：同一标识、内容相同答已有结果并回显此刻的状态，内容不同答来源冲突。已驳回的导入不因重投复活；要再导，用新的导入标识。
- 一份导入整份成立或整份不成立：提交时任一行不成立，整份不落；批准时任一行已不成立，整份不入账。入账在同一笔事务里，流水与入库批次同笔形成。
- 提交到批准之间册会变：库位被停用，同号的箱经收货入了库，商品改了是否跟踪批号。批准时照当下的册重判，不凭提交时的校验入账（`WF-RULE`）。内容已不成立的导入留在待批准：让它不成立的情形消失之后可以再批准，否则驳回后重交。仓在提交之后被停用不在重判之列：停用只挡此后新提交的导入，已经提交的照常可以批准（`WF-RULE`）。
- 入库批次照 `WF-LANG`：同一商品、同一批号与效期、声明的入库时间相同的各行同属一个，声明的入库时间不同的各成一个，一箱整箱一个。入库时间取声明的那一刻，没声明的取入账那一刻。
- 批准与同一批库位、箱号上的收货入账并发时按落册先后：箱号的唯一在入账那一笔里判，后到的那一个不成立。
- 建账导入不带占用：入账之后，落在存储或拣选库区的良品即是可分配库存，照占用规则参加预占。

## 权限、隔离与审计

- 提交要「建账导入提交」授予；谁持有、谁有权批准都是租户取值。提交人与批准人的关系归库存调整的用例。
- 导入按租户隔离，货主只从载荷指名并经 `party-commercial` 核对；商品按该货主的商品编码解析，不跨货主。
- 建账导入只在操作者面；货主经库存与流水的读口看到入账的结果，导入单本身不上客户面（`BD-WF-014`）。
- 审计至少关联导入、货主、仓、原因、提交操作者、批准或驳回的操作者与时刻、各行的流水与入库批次。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 提交照运营决定面判准入范围。仓配的写落在治理登记册的哪个对象范围、某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定，本用例不替它定。
- 真实的库位、商品与批准权限没有时，可以实现提交校验、批准时重判与同笔入账的机制，以及显式的未登记答法与受控 `S`；演示租户的取值只在演示种子里。

| `AT-WF-076` | 同一商品的两行声明了不同的入库时间；另两行声明的相同；一行没声明；一箱整箱声明了入库时间 | 声明不同的各成一个入库批次，相同的同属一个；没声明的入库时间取入账那一刻；整箱一箱一个入库批次、入库时间取声明的那一刻 |
| `AT-WF-077` | 提交之后、批准之前：一行指名的库位被停用；同号的箱经收货入了库；一个商品改成了跟踪批号；之后库位再启用，再批准；另一份导入提交之后仓被停用，再批准 | 前三种批准时都答内容已不成立并逐行指出，整份不入账，导入留在待批准，库存账不变；库位再启用之后批准答已入账；仓被停用的那一份照常答已入账，停用只挡此后新提交的导入 |
| `AT-WF-078` | 一份待批准的导入被驳回；之后同一导入标识原样重投；换一个导入标识把同样的内容再交 | 第一种进入已驳回，库存账不变；重投答已有结果并回显已驳回，不复活；换标识的照新的一份办，答已提交待批准 |
| `AT-WF-079` | 运营读一份导入的状态与各行；货主的客户系统找建账导入的读口；入账之后货主读自己的库存 | 运营读到状态、各行与入账的流水引用；客户面没有建账导入的读口；货主经库存的读口看到入账的结果 |
| `AT-WF-080` | 操作者没有「建账导入提交」授予；请求自带租户或提交操作者；本租户没登准入范围对照 | 依次答未授予、坏载荷、不在准入范围；都不读册、不写册 |

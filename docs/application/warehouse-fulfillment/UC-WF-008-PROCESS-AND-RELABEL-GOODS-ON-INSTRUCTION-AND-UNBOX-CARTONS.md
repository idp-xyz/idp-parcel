# UC-WF-008 按指令加工与商品换标并开箱

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；谁有权发起与作废指令、各项授予待租户提供

## 目标与边界

本用例从货主经客户渠道提交一份加工指令或商品换标指令（或运营决定发起）开始，到仓内作业照指令做完、投入与产出在同一笔流水里入账，或指令被作废为止；另含仓内作业把一箱整箱库存开箱转成商品库存。指令固定什么、执行怎样相抵、产出与转入的货取哪个入库批次、账上不够时怎么办、开箱的差额怎样成收货差异，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「入库与加工」「库存账与守恒」「占用、预占与分配」「盘点、差异与调整」与「加工」「商品换标」「收货差异」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「仓把货变了个样——组成成品、拆回组件、换了标签、整箱开成散件——账怎样在同一笔里相抵」一个问题。这几种作业整笔成立或整笔不成立：账上不够或被占着时不入账，不预支。

本用例包含：

- 货主提交、撤回加工指令（加工或拆解）与商品换标指令；运营决定发起，运营作废。
- 仓内作业执行指令：一份指令执行一次，投入与产出（换标的移出与移入）在同一笔流水里入账。
- 所指的库存在账上不够或被占着时整笔不入账，指令留在原状态。
- 开箱：一箱一笔，箱出，商品按实点入；实点与箱单的差额成一份收货差异。
- 货主与运营查阅指令与开箱记录。

本用例不执行：

- 声明组合商品与它的组成（[UC-WF-002](./UC-WF-002-MAINTAIN-OWNER-GOODS-AND-RECORD-WAREHOUSE-MEASUREMENTS.md)）。
- 包装层级里的箱转件：那是形态转换（[UC-WF-007](./UC-WF-007-PUT-AWAY-MOVE-REPLENISH-AND-CONVERT-STOCK.md)），不是开箱。
- 对开箱形成的收货差异作结论：照 [UC-WF-004](./UC-WF-004-CONFIRM-RECEIPT-AND-CLOSE-OUT-AN-INBOUND-PRE-ADVICE.md) 的差异结论口作，本用例不另开口。
- 出库请求带贴标别名条件时，出库复核之前的贴标：归出库的用例。
- 形成加工与增值服务收费发生项：归收费发生项的用例，本用例只留下加工入账与换标入账这两种作业事实。
- 让指令占住库存（`BD-WF-018`）、一份指令分几次执行（`BD-WF-019`）、仓确认开工（`BD-WF-020`）、开箱指令（`BD-WF-022`）。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 货主口：首方客户渠道族已配置，客户端持「加工指令提交」「加工指令撤回」「商品换标指令提交」「商品换标指令撤回」中相应的授予（参数登记册 `PAR-INT-13`）。运营口：操作者持「加工指令」或「商品换标指令」这一种运营决定的授予（`PAR-INT-08`）。执行与开箱：操作者持这个仓的作业范围授予，设备已登记在用（`PAR-INT-08`、`PAR-INT-10`）。未配置、未授予各答其格。
- 三个面的写都判准入范围（`PAR-INT-11`）；对照没登的租户照各族的规则答不在准入范围。
- 指令只对自营仓；停用的仓照常受理指令，执行与开箱也照常（`WF-RULE`）。组合商品与它的组成由货主声明（UC-WF-002），代码与迁移不带默认的组成。
- 一个仓都没登记的租户：提交、发起、执行与开箱都指名仓，答查无所指的仓；撤回与作废答未配置；读口答空（`WF-RULE`，`ADR-OPT` 决定五）。
- 演示租户 `SYN-TENANT-01` 的仓、组合商品、别名、设备与授予在演示种子里配，证据记 `S`。

## 输入语义契约

下表定义业务语义，不是 API、消息或数据库字段清单。下文说「指名一格」，是给出商品编码、计量单位、库存状态、贴标别名（没贴为空）、批号与效期（不跟踪的不带）与库位；货主取自所指的指令；入库批次可以点名，没点名的照 `WF-RULE` 的取法取。

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |
|---|---|---|---|
| 加工指令（货主） | 首方客户渠道信封与载荷 | 租户与货主客户账户（取自信封）、仓编码、种类（加工或拆解）、组合商品编码、组成版本（可选）、数量、货主参考号（可选）、接入请求标识 | 租户与客户账户只从信封来，请求自带即坏载荷；种类取加工或拆解，别的词即坏载荷；指名的商品须是该货主已登记的组合商品；组成版本以声明那份组成的商品修订指名，没带的取受理那一刻的当前修订；数量按成品的基本单位计、为正；参考号逐字保存，不判唯一 |
| 商品换标指令（货主） | 首方客户渠道信封与载荷 | 仓编码、商品编码、计量单位、数量、现贴的别名、要换成的别名、批号与效期（可选）、货主参考号（可选）、接入请求标识 | 商品须是该货主已登记的商品；计量单位须是它声明的包装层级；数量为正；两个别名至少带一个、互不相同，现贴一侧空着是没贴，要换成一侧空着是去标；带了的须是该商品的平台商品码别名，要换成的那一个须在受理那一刻有效；批号、效期只在商品跟踪它时可带 |
| 指令撤回（货主） | 首方客户渠道信封与载荷 | 指令标识、接入请求标识 | 只能撤自己客户账户经客户渠道提交的指令 |

| 加工执行 | 作业事实登记（设备与操作者取自信封） | 设备签发的事实身份、发生时间与序号；仓；指令；实做数量；投入各行（指名一格与数量）；产出各行（商品编码、计量单位、贴标别名、批号与效期、目标库位、数量） | 一条事实对一份指令；仓须是指令的仓；实做数量为正、不多于指令数量；投入的格须是良品，产出记良品；投入与产出照指令固定的组成版本和实做数量相抵（`WF-RULE`）；产出的计量单位须是声明的包装层级，跟踪批号、效期的必带，贴标别名须是事实发生那一刻有效的平台商品码别名；各库位须在这个仓、不在待出库库区，产出不落次品库区 |

| 开箱 | 作业事实登记 | 设备签发的事实身份、发生时间与序号；仓；货主客户账户；箱号；实点各行（扫到的识别码、计量单位、库存状态、数量、批号与效期、贴标别名、目标库位） | 一条事实对一箱；箱号逐字比；识别码逐字保存，按该货主、取事实发生那一刻的指向解析；认得出的商品，计量单位须是它声明的包装层级，跟踪批号、效期的必带，贴标别名须是它在事实发生那一刻有效的平台商品码别名；目标库位须在这个仓、不在待出库库区、与库存状态相容；实点可以一行都没有 |
| 查阅 | 操作者渠道或首方客户渠道信封 | 指令标识，或筛选（仓、种类、状态、时间）；开箱记录按箱号或时间 | 客户面只读得到自己客户账户的 |

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 指令已受理 | 一份加工指令或商品换标指令落册，进入待加工或待换标，内容就此固定 | 指令标识、货主、仓、全部内容、固定的组成版本、发起途径、来源请求键或决定标识，运营发起的操作者、原因与依据引用，受理时刻 | 库存够；库存已被占住；取得了单据号 |
| 指令内容不合 | 指令里有不成立的格 | 无；指出哪一格 | 代建商品、组成或别名 |
| 指令已作废 | 待加工或待换标的指令作废，不入账 | 作废是哪一侧作的、时刻、来源请求键，运营作废的操作者与原因 | 已经做了的实物被还原 |
| 撤回不成立 | 货主要撤的这份指令是运营决定发起的 | 无；回显发起途径 | 代为作废 |
| 指令状态不符 | 撤回或作废时指令已加工或已换标；执行的事实到达时指令不在待加工或待换标 | 无；回显当前状态 | 冲回已入账的流水；照样入账 |
| 加工已入账 | 执行成立：投入与产出在同一笔加工或拆解流水里入账，产出形成新的入库批次，指令进入已加工 | 事实身份、设备与操作者、发生时间与序号、接收时间、实做数量、投入与产出各行、流水与入库批次引用 | 指令数量都做完了；收费发生项已形成 |
| 换标已入账 | 执行成立：各格的数量在同一笔商品换标流水里移到贴标别名不同的格，指令进入已换标 | 事实身份、设备与操作者、发生时间与序号、接收时间、各行与流水引用 | 入库批次或库龄变了；收费发生项已形成 |
| 开箱已入账 | 一箱在同一笔开箱流水里转成商品库存：箱出，商品按实点入；实点与箱单有差额的，同笔成一份收货差异 | 事实身份、设备与操作者、发生时间与序号、接收时间、箱号、实点各行与逐行结果、流水引用、形成的收货差异 | 差异已被货主确认；箱单被改了 |
| 库存不可用 | 所指的投入、要换标的库存或那一箱在账上不够，或被占着：整笔不入账，指令留在原状态 | 无；指出哪一格 | 入账够的那一部分；预支；自动换一格取 |
| 作业内容不合 | 整条执行或开箱的事实不成立，一行都不入账 | 无；逐行指出 | 丢掉坏行、入账其余 |
| 已有结果 | 同一接入请求、同一决定标识或同一事实身份，内容相同的重投；已作废的指令再被撤回或作废 | 回显在册结果 | 第二份指令、第二次入账 |
| 来源冲突 | 同一接入请求或同一决定标识、内容不同；已随一次撤回落册的来源请求键，又来指名另一份指令 | 无 | 覆盖在册的指令 |
| 内容冲突 | 同一事实身份已在册，这一次的内容与在册的不同 | 无；在册的事实不变 | 覆盖在册的事实；第二次入账 |
| 查无此指令 | 指名的指令在这个货主名下查不到；运营或设备指名的指令在本租户查不到 | 无 | 泄露别的货主或别的租户的指令 |
| 查无此箱 | 开箱所指的箱不是该货主在这个仓在库的箱 | 无 | 代建箱 |
| 查无所指的仓 | 指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓、改投别的仓 |
| 仓不受理 | 指名的仓是代理仓 | 无 | 改投别的仓 |
| 未配置 | 撤回或作废到达时本租户一个仓都没登记 | 无 | 代建仓 |

「开箱已入账」里每一行有自己的结果：已入账；未入账、认不出的货，记错货。实点与箱单怎样分成多收、少收、错货与破损，照 `WF-RULE` 里收货差异的分法，本用例不另写；实点与箱单相符、也没有次品的不形成差异。「作业内容不合」是整条事实的结果：仓不是指令的仓，实做数量多于指令数量或不为正，投入与产出不相抵，投入的格不是良品、不是指令的商品或贴着的别名与指令不符，产出或转入的计量单位、批号效期、贴标别名或目标库位不成立。

信封一层的「发行方未配置」「令牌无效」「未授予」「设备未登记或已停用」「不在准入范围」与坏载荷，客户面照 ADR-0139 决定四，运营决定面照 ADR-0151 决定一、三，作业事实登记面照 ADR-0149 决定二、四作答，不读册、不写册。查阅不判准入范围。运营发起指名的货主客户账户在本租户查不到，与越权探针同答；货主口指名别的货主的指令，与查无此指令同答。

业务拒绝、未决与技术失败分开：指令内容不合、撤回不成立、指令状态不符、作业内容不合、内容冲突与来源冲突都是已形成的答案；库存不可用不是把已经做了的作业一笔勾销，是这一刻账上入不了，指令留在原状态、事实可以原样重交；未配置是租户取值没到，不是拒绝；运营发起时 `party-commercial` 读不动，或册读写不动，都不形成答案，设备与提交方原样重交。

## 一致性、幂等与并发

- 货主的指令提交按来源请求键认重放。来源请求键由首方族的推导口自接入请求标识取，标识只在这一种命令内唯一（ADR-0310 决定一）；运营发起按调用方给的决定标识认。
- 撤回与作废的重放身份取被指名的指令：一份指令只作废一次，已作废的再被撤回或作废，不论哪一侧、哪个接入请求，都答已有结果。货主的撤回先看这份指令是不是经客户渠道提交的，不是的答撤回不成立。货主口的来源请求键随成立的撤回落册；已落册的键又来指名另一份指令的，答来源冲突。
- 执行与开箱按设备签发的事实身份认重放（ADR-0023），内容按各口的规范化形状比（ADR-0149 决定四）：同一身份、内容相同的重复到达答已有结果，不追加第二次入账；内容不同的答内容冲突。作业内容不合、库存不可用、指令状态不符、查无此指令、查无此箱与查无所指的仓的不落册，不占事实身份：账理顺之后，同一条事实可以原样重交。
- 一份指令执行一次：第一条成立的执行让指令进入已加工或已换标，实做少于指令数量的也是；之后别的事实身份再来执行，答指令状态不符。
- 同一份指令上的撤回、作废与执行串行判，按到达本上下文的先后，不按设备的发生时间。作废先成立的，迟到的执行答指令状态不符、不入账；实物已经做了的，由运营另发一份指令，仓照实再登记一次。
- 一笔入账整份成立或整份不成立（`WF-RULE`）：不入账够的那一部分，也不自动换一格取。取得走多少按入账那一刻的账判。
- 组成版本在受理时固定，商品之后追加修订不回改已受理的指令。计量单位是不是已声明的包装层级、跟不跟踪批号与效期，按入账那一刻的当前修订判；要换成的别名与产出、转入的贴标别名按事实发生那一刻的有效区间判。
- 产出的入库批次与入库时间在入账那一刻形成，不取设备的发生时间；开箱转入的商品沿用该箱的入库批次与入库时间（`WF-RULE`）。停用的库位作产出或转入的目标照记。
- 开箱形成的收货差异与收货确认形成的是同一种对象：一次开箱一份，待货主确认，结论不改账，货主本人与代录的先后照 UC-WF-004。

## 权限、隔离与审计

- 货主只能提交、撤回与查阅自己客户账户的指令，只能读自己的开箱记录。
- 运营发起的指令，决定方是运营，不是代录：记下操作者、原因与依据引用；货主在读口看得到这一份是运营决定发起的与原因，带了依据引用的也看得到。依据引用不以明文进日志或指标。
- 运营作废货主提交的指令，记下操作者与原因；货主在读口看得到是仓一侧作废的与原因，不带操作者。
- 执行与开箱要这个仓的作业范围授予与已登记在用的设备；谁持有各项授予是租户取值。
- 开箱里认不出的货留下扫到的码与数量，不记到任何别的货主名下：别名不跨货主解析。
- 审计至少关联指令、货主、仓、发起与作废各笔、执行的事实、设备与操作者、流水与入库批次、开箱的箱与形成的收货差异。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 三个面的写照各族判准入范围。某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定；仓配的写落在治理登记册的哪个对象范围随它一起没有定，本用例不替它定。
- 真实的组合商品、别名、设备与授予没有时，可以实现指令受理、整笔入账、账上不够时不入账与开箱比出差异的机制，以及显式的未登记答法与受控 `S`；演示租户的取值只在演示种子里。

| `AT-WF-126` | 一个仓都没登记的租户：提交或发起指令；设备交来执行或开箱的事实；撤回或作废一份指令；读口 | 前两种答查无所指的仓；撤回与作废答未配置；都不落册，不建默认仓；读口答空（`ADR-OPT` 决定五） |
| `AT-WF-127` | 客户端没有「加工指令提交」授予；只持提交授予去撤回；操作者没有「加工指令」授予；只持「加工指令」授予去发起商品换标指令；设备未登记或已停用；操作者没有这个仓的作业范围授予；请求自带租户或客户账户；本租户没登准入范围对照 | 各答其格，不读册、不写册 |
| `AT-WF-128` | 部署没打开仓配开关：调用指令的提交口、撤回口、运营发起与作废口、执行口、开箱口与读口；同一部署跑其他上下文的全套用例 | 各端点不提供业务答复，也不折成 404；其他上下文各用例的答复与交出的信封，和没有仓配代码时相同（`ADR-OPT` 决定一、四） |

## 待确认业务决策

以下项目不改变本用例「按指令作、整笔相抵、账上不够不入账」的边界：

| ID | 待确认决策 | 归类 | 当前建议 | 影响 |
|---|---|---|---|---|
| `BD-WF-018` | 指令受理时要不要占住所指的库存 | 产品策略 | 首版不占：占用是产品内置的封闭集，指令不在其中；执行时账上不够或被占着就不入账，指令留在原状态 | 不占的代价是组件可能在执行之前被出库请求预占走。要占，得在 ADR-0368 决定五的封闭集之外另立一种，并定它与预占的先后 |
| `BD-WF-019` | 一份指令能不能分几次执行 | 产品策略 | 首版一份指令执行一次，实做少于指令数量的余下不再做；要再做，另发一份指令 | 分次的话指令多一个执行中的状态，要定什么时候算做完 |
| `BD-WF-020` | 指令要不要「仓确认开工」一步，开工之后货主不能撤回 | 产品策略 | 首版不设：执行的事实到达之前都可以撤回或作废，先后按到达本上下文的先后 | 不设的代价是仓已经动手而指令被撤回时，做了的实物要由运营另发指令照实登记。设的话多一种运营决定与一个状态 |
| `BD-WF-021` | 运营决定发起的指令要不要必带货主授权的依据引用 | 产品策略 | 首版不要求：原因必带，依据引用可带 | 加工与换标会让货主担费用；必带的话没有依据的发起答坏载荷，仓自己要做的（纠错之类）也得写一个依据 |
| `BD-WF-022` | 开箱要不要先有货主的开箱指令 | 产品策略 | 首版不设：开箱由仓内作业按箱记，货主的要求在系统外传达 | 设的话照加工指令的样子多一种指令与它的客户面口 |
| `BD-WF-023` | 加工指令与商品换标指令要不要取单据号 | 产品策略 | 首版不取：以指令标识与货主参考号识别 | 取的话照 ADR-0355 决定二在 CONTEXT 写明开立时点，各多一个单据类型 |

待定格按三类归：

- 机制：指令的受理与组成版本的固定、来源请求键与决定标识的重放、撤回与作废、按事实身份认重放、整笔入账与账上不够时不入账、开箱比出收货差异。现在做完。
- 产品策略：指令不占库存、一份指令执行一次、实做数量不多于指令数量、投入与产出都是良品；运营发起的指令决定方是运营、原因必带；开箱由仓内作业按箱记；`BD-WF-018` 至 `BD-WF-023` 的当前建议。随产品内置。
- 租户取值：各货主的组合商品、组成与别名；谁持有「加工指令」「商品换标指令」授予、仓的作业范围授予与客户端的能力授予。留空；没有授予照各族的答法。

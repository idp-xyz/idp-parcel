# UC-WF-015 确认出库并更正

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；放行条件所依赖的面单、代办与更正采用待租户提供

## 目标与边界

本用例从货已打包、放行条件交给作业端开始，到仓内作业确认货已离开，库存按分配消耗为止，另含把一次出库确认更正为不成立之后的回补。哪一刻算离开、三种发运方式各看什么、离线交出的怎样照记、不成立的货回到哪，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「出库确认」「出库请求与发出」与「装箱记录」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「这件货什么时候算离开这个仓」一个问题。委托的接受不在本用例，截单不在本用例。

本用例包含：

- 本产品网络、自备面单、自提三支出库确认。
- 放行条件随包裹下发，带有效区间。
- 离线或越权已经交出的照记。
- 更正版本：改时点，或判这次出库确认不成立并回补。
- 代理仓报来的交接结果：确认发出，不消耗本上下文的库存账。

本用例不执行：

- 节点收寄。出库确认不等它，也不由它触发（`WF-RULE`）。
- 出库确认之后的取消与去向。本产品网络的归小包托运与网络各上下文，自备面单与自提的归货主。
- 操作者把库存调整的行指到待出库库区。回补不是那一个口（`WF-RULE`）。

## 启动条件

- 部署已打开仓配开关。关着时各口不提供业务答复。
- 一个仓都没登记的租户，出库确认答未配置。
- 在线交出时，本产品网络要委托已接受、包裹没有有效取消、面单本体已取到、预取的更正已采用。自备面单要包裹数与面单数对上。缺一格不交出（`WF-RULE`）。

## 应用流程

1. 在线交出：核放行条件。缺格则不交出。
2. 成立：按分配消耗库存，预占随之消耗，装箱记录进入已出库确认。
3. 离线或越权已经交出：照记，标出缺的格，交人处理。
4. 更正判不成立：经批准回补，落点与入库批次照 `WF-RULE`。批准人与批准职责规则同 UC-WF-011，这一路不打开「库存调整可指向待出库库区」。
5. 代理仓的交接结果：请求进入已发出，不消耗本账。

## 一致性、幂等与并发

- 出库确认按事实身份认重放。更正按被更正的那一版认，一版只更正一次。
- 消耗与回补在库存账内串行。同一数量不消耗两次。
- 出库确认之后本用例不再受理对这件货的截单（`WF-RULE`）。

## 权限、隔离与审计

- 作业事实只接受持有该仓作业范围的设备。更正是运营决定，要有相应授予，没有答未授予。
- 货主在流水读口看得到消耗与回补，看不见放行条件的内部格。

## 首发试点叠加条件

演示租户的放行各格在演示种子里能配齐的配齐，证据记 `S`。面单本体没配置时，本产品网络的在线交出答未配置，不出库确认。

# UC-WF-005 登记、认领与处置待认领到货

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；各仓的处置规则、谁有权认领与处置、各项授予待租户提供

## 目标与边界

本用例从仓内作业登记一件认不出货主或预报的到货（或一条收货事实因预报已不能收货而转来）开始，到这件到货被认领给一个货主并有入账引用它，或按租户登记的处置规则处置为止，另含处置规则的登记与到货的查阅。到货怎样登记、认领指名什么、何时还能撤销、处置凭什么，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「入库与加工」里待认领到货的规则与「待认领到货」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「货到了仓却不知道是谁的，怎么留下、怎么认、认不了怎么办」一个问题。待认领到货只登记到货与观察，不进任何货主的库存账。

本用例包含：

- 仓内作业登记待认领到货：入库到货或退件。
- 收货事实到达时预报已不能收货的，由 [UC-WF-004](./UC-WF-004-CONFIRM-RECEIPT-AND-CLOSE-OUT-AN-INBOUND-PRE-ADVICE.md) 转来。
- 运营认领：指名货主，入库到货的另指名一份可收货的入库预报；撤销认领。
- 核对引用到货的入账：入库到货经收货确认，退件经退货入库。
- 运营登记各仓的处置规则，并按规则处置。
- 运营查阅待认领到货。

本用例不执行：

- 认领之后的入账本身：入库到货的收货确认归 UC-WF-004，退件的退货入库归退货的用例。
- 退件按退货预报或装箱记录认货主：归退货的用例，认不出的才登记到这里。
- 向货主公开待认领到货、由货主自己认领（`BD-WF-012`）。
- 更正已登记的到货观察（`BD-WF-013`）。
- 处置的实物执行：处置只记决定，不改库存账，也不形成收费发生项。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 到货登记：操作者持这个仓的作业范围授予，设备已登记在用（参数登记册 `PAR-INT-08`、`PAR-INT-10`）。认领与撤销、处置：操作者各持「待认领到货认领」「待认领到货处置」这一种运营决定的授予。处置规则的登记要「登记册配置写」授予，查阅要「主数据与运营查阅读」授予（`PAR-INT-08`）。未配置、未授予各答其格。
- 到货登记、认领、撤销与处置都判准入范围（`PAR-INT-11`）；对照没登的租户照各族的规则答不在准入范围。处置规则的登记不判准入范围（ADR-0100 决定四）。
- 到货只在自营仓登记：代理仓的作业不在本上下文执行（`WF-LANG`）。
- 处置规则是租户取值。代码与迁移不带默认的认领期限或处置方式；这个仓没登记时处置答未配置，到货留在待认领。
- 一个仓都没登记的租户：到货登记答查无所指的仓，处置规则的登记答未受理（查无所指），认领、撤销与处置答未配置，读口答空（`WF-RULE`，`ADR-OPT` 决定五）。
- 演示租户 `SYN-TENANT-01` 的处置规则、设备与授予在演示种子里配，证据记 `S`。

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 到货已登记 | 一件待认领到货落册，进入待认领 | 到货标识、仓、到货种类、观察与线索、存放处、设备与操作者、发生时间与序号、接收时间；由收货事实转来的保全原事实 | 这批货归线索里的货主；库存账已变；取得了单据号 |
| 已认领 | 到货认给一个货主，入库到货的另指名了一份预报 | 货主、预报、决定标识、操作者、时刻 | 库存已入账；预报的累计实收已变 |
| 认领已撤销 | 到货回到待认领 | 撤销的操作者、时刻、原因与决定标识；原认领照留 | 原认领没有发生过 |
| 已处置 | 到货按规则作出处置，不再认领 | 处置方式、所据的规则修订、操作者、时刻、说明 | 库存流水；收费发生项 |
| 已有结果 | 同一事实身份重复到达；同一决定标识、内容相同的重投；到货已这样认领、又来指名相同的认领；已处置的到货以同一方式再处置 | 回显在册结果 | 第二件到货、第二次认领、第二次处置 |
| 来源冲突 | 同一决定标识、内容不同 | 无 | 覆盖 |
| 已有认领 | 到货已认领，又来一个指名不同的认领 | 无；回显在册的认领 | 改认 |
| 认领不成立 | 入库到货没指名预报，或指名的预报不属于该货主、不在这件到货所在的仓、已不能收货；退件指名了预报 | 无；指出哪一格 | 代建预报；改指别的预报 |
| 撤销不成立 | 已有入账引用这件到货 | 无 | 冲回已入账的库存 |
| 到货状态不符 | 认领时到货已处置；处置时到货已认领，或已按另一种方式处置；撤销时到货不在已认领 | 无；回显当前状态 | 代为撤销或改处置 |
| 处置不成立 | 认领期限没到，或处置方式不在这个仓在用的规则里 | 无；指出哪一种 | 提前处置；换成规则里别的方式 |
| 未配置 | 处置时这个仓没登记处置规则；或认领、撤销、处置到达时本租户一个仓都没登记 | 无；指出没登记的是哪一样，到货留在待认领 | 取默认期限或默认方式；代建仓 |
| 查无此到货 | 指名的到货在本租户查不到 | 无 | 泄露别的租户的到货 |
| 查无所指的仓 | 到货登记指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓 |
| 仓不受理 | 到货登记指名的仓是代理仓 | 无 | 改记到别的仓 |

处置规则的登记照 [UC-WF-001](./UC-WF-001-REGISTER-WAREHOUSES-ZONES-LOCATIONS-AND-PACKAGING-MATERIALS.md) 的登记结果作答：已登记、已登记（重放）、内容冲突，以及未受理的修订错位、查无所指与内容不合，含义相同，对象身份是（租户，仓）。

信封一层的「发行方未配置」「令牌无效」「未授予」「设备未登记或已停用」「不在准入范围」与坏载荷，作业事实登记面照 ADR-0149 决定二、四，运营决定面照 ADR-0151 决定一、三，登记册配置写面照 ADR-0100 决定四作答，不读册、不写册。查阅不判准入范围。认领指名的货主客户账户在本租户查不到，与越权探针同答。

业务拒绝、未决与技术失败分开：认领不成立、撤销不成立、到货状态不符与处置不成立都是已形成的答案；未配置是租户取值没到，不是拒绝，到货照留；到货留在待认领是未决，不是失败；认领时 `party-commercial` 读不动，或册读写不动，都不形成答案，设备与提交方原样重交。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 仓内作业人员 | 在一线作业端登记到货；设备签发事实身份、发生时间与序号 | 作业事实登记面认证设备与操作者，核作业范围与准入范围 |
| 2 | `warehouse-fulfillment` | 同一事实身份已在册答已有结果；否则核指名的仓，落册为待认领 | 答到货已登记；仓没登记答查无所指的仓，是代理仓答仓不受理 |
| 3 | `warehouse-fulfillment` | 收货事实到达时预报已取消或已完结（UC-WF-004）：把原事实保全为一件入库到货 | 进入待认领，原预报与货主只作线索 |
| 4 | 运营操作者 | 认领：指名货主，入库到货的另指名预报 | 经消费侧适配器向 `party-commercial` 核货主客户账户；核预报属于该货主、在这个仓、可收货；答已认领或认领不成立 |
| 5 | 仓内作业人员 | 入库到货：对认领所指的预报确认收货并引用这件到货（UC-WF-004）；退件：按退货入库入账 | 入账留下对到货的引用；引用的到货不在已认领，或认给的不是这份预报，那条收货事实不成立 |
| 6 | 运营操作者 | 撤销认领 | 没有入账引用的回到待认领；已有入账引用的答撤销不成立 |
| 7 | 运营操作者 | 登记或修订这个仓的处置规则 | 照登记结果作答；新修订只作用于此后的处置 |
| 8 | 运营操作者 | 处置：指名到货与处置方式 | 规则没登记答未配置；认领期限没到或方式不在规则里答处置不成立；成立的进入已处置 |
| 9 | 运营操作者 | 查阅到货与各仓的处置规则 | 如实答到货、观察、线索、认领与撤销各笔、入账引用与处置 |

## 一致性、幂等与并发

- 到货登记按设备签发的事实身份认重放（ADR-0023）：同一身份重复到达答已有结果，不比内容。指名的仓没登记或是代理仓的不落册，不占事实身份。
- 认领与撤销按调用方给的决定标识认重放：同一标识、内容相同的重投回显当初的结果，不看到货此刻的状态；内容不同答来源冲突。一件到货可以先后被认领、撤销、再认领，所以到货本身不作这两种决定的重放身份。
- 同一件到货上的认领、撤销、处置与引用它的入账串行判，按到达本上下文的先后：并发的两个认领只成立一个，另一个按指名相不相同答已有结果或已有认领；认领与处置并发只成立一个，另一个答到货状态不符。
- 撤销与引用这件到货的入账并发：入账先落，撤销答撤销不成立；撤销先落，那条收货事实照 UC-WF-004 答收货内容不合。
- 认领那一刻核预报可收货；之后预报被撤回或完结的，认领不自动失效，引用它的收货事实照 UC-WF-004 答收货内容不合，也不另建一件到货，运营撤销之后重新认领。
- 处置的重放身份取被指名的到货：一件到货只处置一次。处置按那一刻这个仓在用的那一版规则判，所据的修订记在处置上；规则之后的新修订不回改已作出的处置。
- 认领期限自到货发生那一刻起、按经过的时间算（`WF-RULE`），不按业务日，所以不依赖仓的业务时区；由收货事实转来的到货，取那条收货事实的发生时间。

## 权限、隔离与审计

- 待认领到货不属于任何货主，只在操作者面、按租户隔离；客户面没有它的读口。
- 线索不是认定：线索里的货主读得到，账上不记，也不据它放开任何货主的读权限。
- 认领与撤销、处置各要自己那一种运营决定的授予，登记处置规则要「登记册配置写」授予；谁持有是租户取值。每一笔记下操作者与时刻。
- 观察里可能带外箱面单上的收件人或发件人信息，不以明文进日志或指标。
- 审计至少关联到货、仓、设备与操作者、认领与撤销各笔、引用它的入账、处置与所据的规则修订。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 到货登记、认领、撤销与处置照各族判准入范围。仓配的写落在治理登记册的哪个对象范围、某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定，本用例不替它定。
- 真实的处置规则与授予没有时，可以实现登记、认领、撤销与处置的机制，以及显式未配置与受控 `S`；演示租户的取值只在演示种子里。

待定格按三类归：

- 机制：到货的保全、认领与撤销、入账对到货的引用校验、处置规则的登记与按规则处置、未配置的如实答法。现在做完。

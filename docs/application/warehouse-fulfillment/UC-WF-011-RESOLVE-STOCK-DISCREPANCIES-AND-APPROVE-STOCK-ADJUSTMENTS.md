# UC-WF-011 处理库存差异并批准库存调整

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；批准职责规则、谁有权提交与批准、各项授予待租户提供

## 目标与边界

本用例从一份库存差异形成、或运营提交一份库存调整开始，到它经批准以新流水改账，或被驳回为止，另含建账导入的批准与驳回、批准职责规则的登记。差异与调整怎样入账、批准时怎样重判、取走与记入的数量归哪个入库批次、谁能批准，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「盘点、差异与调整」「库存账与守恒」「占用、预占与分配」与「库存差异」「库存调整」「建账导入」各条生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「账与实物不符，或账记错了，谁说了算、怎样把账改过来」一个问题。差异的形成与调整的提交都不改账；改账只在批准成立的那一笔里，已入账的流水不改不删。

本用例包含：

- 运营提交库存调整：货主、仓、原因与各行（调增、调减或销毁），商品库存与整箱库存都可以。
- 批准与驳回：库存差异、库存调整与建账导入共用一套口。
- 批准时照那一刻的账重判，成立的在同一笔里入账。
- 批准职责规则的登记：批准人须否与提交人为不同主体，库存差异的处理时限。
- 运营查阅库存差异、库存调整与批准职责规则。

本用例不执行：

- 库存差异的形成：盘点差异归 [UC-WF-010](./UC-WF-010-COUNT-STOCK.md)，库内作业的差额与短少登记归 [UC-WF-007](./UC-WF-007-PUT-AWAY-MOVE-REPLENISH-AND-CONVERT-STOCK.md)，实拣与分配不符、出库复核不符归出库的用例。
- 建账导入的提交、校验与入账规则（[UC-WF-006](./UC-WF-006-TAKE-ON-EXISTING-STOCK-BY-IMPORT.md)）：本用例只给它批准与驳回的口。
- 收货差异的结论（[UC-WF-004](./UC-WF-004-CONFIRM-RECEIPT-AND-CLOSE-OUT-AN-INBOUND-PRE-ADVICE.md)）：结论不改账；货主有异议、仓复点之后要改账的，在本用例提交库存调整。
- 判一次出库确认不成立：归出库的用例；不成立之后的回补是一笔调增，落在哪里随它定。
- 待出库库区里的调整：那里的货连着分配与装箱记录，归出库的用例。
- 销毁的实物执行；销毁与各作业的收费发生项；回库处置（退货的用例）。
- 向货主公开库存差异与库存调整（`BD-WF-034`）。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 操作者渠道已配置；提交要「库存调整提交」、批准与驳回要「库存调整批准」这两种运营决定的授予，登记批准职责规则要「登记册配置写」授予，查阅要「主数据与运营查阅读」授予（参数登记册 `PAR-INT-08`）。未配置、未授予各答其格。
- 提交、批准与驳回判准入范围（`PAR-INT-11`）；对照没登的租户照运营决定面的规则答不在准入范围。批准职责规则的登记不判准入范围（ADR-0100 决定四）。
- 批准职责规则是租户取值。代码与迁移不带默认的规则，不取「须两人」，也不取「一人可批」；没登记时批准答未配置（`WF-RULE`，`ADR-DUTY` 决定六）。
- 库存调整只对自营仓的库存账；停用的仓照常可以提交与批准（`WF-RULE`）。
- 一个仓都没登记的租户：提交答查无所指的仓，批准、驳回与批准职责规则的登记答未配置，读口答空（`WF-RULE`，`ADR-OPT` 决定五）。
- 演示租户 `SYN-TENANT-01` 的批准职责规则与授予在演示种子里配，证据记 `S`。

## 输入语义契约

下表定义业务语义，不是 API、消息或数据库字段清单。下文说「指名一格」，是给出商品编码、计量单位、库存状态、贴标别名（没贴为空）、批号与效期（不跟踪的不带）与库位，货主取这份调整的货主；入库批次可以点名，没点名的照 `WF-RULE` 的取法取。

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |
|---|---|---|---|
| 库存调整 | 操作者渠道信封与载荷 | 调整标识、货主客户账户、仓编码、原因、各行；所更正的作业事实与所引的收货差异（可选） | 租户与提交操作者只从信封来，请求自带即坏载荷；调整标识由调用方给；货主客户账户是业务内容，须在本租户查得到；原因必带，逐字保存；一份调整对一个货主、一个仓，至少一行；所更正的作业事实须在本租户在册、发生在这个仓，所引的收货差异须属于这个货主、这个仓，两者只作指名与留痕 |
| 商品库存的行 | 载荷 | 种类（调增、调减或销毁）、指名一格、数量；销毁的行另带货主授权的依据引用 | 商品按商品编码指名，须是该货主已登记的商品；计量单位须是它声明的包装层级；数量为正；跟踪批号、效期的必带，不跟踪的不带；贴标别名带了的须是它的平台商品码别名，不看有效区间；库位须在这个仓、不在待出库库区；调增的库位须在用，库存状态须与库位所在的库区相容；同一格在一份调整里只出现一次，不论入库批次；调减与销毁所指的格在提交那一刻的余额须够，被没被占着到批准时再判；调增须照 `WF-RULE` 归得出入库批次；依据引用必带，逐字保存、不判真伪 |
| 整箱库存的行 | 载荷 | 种类、箱号；调增的另带库位；销毁的另带货主授权的依据引用 | 箱号逐字比；调减与销毁的箱须是该货主在这个仓在库的箱，不在待出库库区；调增的箱须是该货主在这个仓在过库、此刻不在库的箱，库位须在这个仓的收货暂存或存储库区、在用；一箱在一份调整里只出现一次 |
| 批准 | 操作者渠道信封与载荷 | 所指的一份库存差异、库存调整或建账导入；说明（可选） | 批准人取自信封；货主与内容取自所指的那一份，不从载荷收（`ADR-OPS` 决定二），带了即坏载荷 |
| 驳回 | 同上 | 所指的那一份；原因 | 原因必带，逐字保存 |
| 批准职责规则修订 | 操作者渠道信封与载荷（登记册配置写） | 修订号；批准人须否与提交人为不同主体；库存差异的处理时限（可选） | 对象是本租户的那一条规则，租户取自信封；每个修订是一份完整的规则；须否只收是或否，必写；处理时限带了的须是一段为正的时长 |
| 查阅 | 操作者渠道信封 | 差异标识或调整标识，或筛选（货主、仓、来源、状态、超没超期）；批准职责规则的各修订 | 只在操作者面；客户面没有这些读口 |

## 结果语义契约

| 结果 | 业务含义 | 必须保存 | 禁止推导 |
|---|---|---|---|
| 已提交待批准 | 这份调整落册，货主、仓、原因与各行就此固定，等批准 | 调整标识、货主、仓、原因、各行的全部内容、所更正的作业事实、所引的收货差异连同那一刻的结论与途径、提交操作者与时刻 | 库存账已变；库存已被占住；可用量已变 |
| 调整内容不合 | 有不成立的行，或所更正的作业事实、所引的收货差异对不上 | 无；逐行指出，调增归不出入库批次的指出改走建账导入 | 丢掉不成立的行、受理其余；代建商品或库位 |
| 已入账 | 批准成立：库存差异照记下的格与差额以盘盈、盘亏、调增或调减流水入账，进入已批准；库存调整各行在同一笔里以调增、调减、销毁流水入账；建账导入照 UC-WF-006 入账 | 批准的操作者、时刻与说明，提交人，所据的批准职责规则修订，各笔流水与所取或所归的入库批次 | 实物与账已相符；销毁的实物已执行；形成差异的作业事实被改写 |
| 内容已不成立 | 批准时照那一刻的册与账重判不成立：要取走的数量已不够或被占着，要记入的已归不出入库批次或与册不合 | 无；逐行指出，留在原状态 | 入账成立的那一部分；自动改数量；自动驳回 |
| 已驳回 | 这一份不入账，终态 | 驳回的操作者、时刻与原因 | 库存账已变；差异没有发生过 |
| 职责规则不放行 | 批准职责规则写明批准人须与提交人为不同主体，而这次的批准人就是提交人 | 无；留在原状态 | 换一个身份代批；跳过规则 |
| 未配置 | 批准时本租户没登记批准职责规则；或批准、驳回、登记批准职责规则时本租户一个仓都没登记 | 无；指出没登记的是哪一样，留在原状态 | 取「一人可批」或「须两人」作默认；自动调账；代建仓 |
| 已有结果 | 同一调整标识、内容相同的重投；已批准或已入账的再被批准；已驳回的再被驳回 | 回显在册结果 | 第二份调整、第二次入账 |
| 来源冲突 | 同一调整标识、内容不同 | 无 | 覆盖在册的调整 |
| 差异状态不符、调整状态不符、导入状态不符 | 已驳回的再被批准；已批准或已入账的再被驳回 | 无；回显当前状态 | 复活已驳回的那一份；冲回已入账的流水 |
| 查无此差异、查无此调整、查无此导入 | 所指的那一份在本租户查不到 | 无 | 泄露别的租户的差异、调整或导入 |
| 查无所指的仓 | 提交指名的仓在本租户没登记；本租户一个仓都没登记时同此 | 无 | 代建仓 |
| 仓不受理 | 提交指名的仓是代理仓 | 无 | 改投别的仓 |

批准职责规则的登记照 [UC-WF-001](./UC-WF-001-REGISTER-WAREHOUSES-ZONES-LOCATIONS-AND-PACKAGING-MATERIALS.md) 的登记结果作答：已登记、已登记（重放）、内容冲突，以及未受理的修订错位与内容不合，含义相同，对象身份是租户；本租户一个仓都没登记时答未配置，与库位类型、包材的登记同。

信封一层的「发行方未配置」「令牌无效」「未授予」「不在准入范围」与坏载荷，运营决定面照 ADR-0151 决定一、三，登记册配置写面照 ADR-0100 决定四作答，不读册、不写册。查阅不判准入范围。指名的货主客户账户在本租户查不到，与越权探针同答。

业务拒绝、未决与技术失败分开：调整内容不合、内容已不成立、职责规则不放行、各种状态不符与来源冲突都是已形成的答案；内容已不成立与职责规则不放行之后那一份留在原状态，情形消失或换人之后可以再批准；未配置是租户取值没到，不是拒绝；待处理与待批准是未决，不是失败；提交时 `party-commercial` 读不动，或册读写不动，都不形成答案，提交方原样重交。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 |
|---|---|---|---|
| 1 | 操作者渠道 | 认证操作者，核所用的那一种授予与准入范围；租户与操作者取自信封；载荷形状不合即拒 | 信封各格或坏载荷直接作答 |

## 一致性、幂等与并发

- 提交按调用方给的调整标识认重放：同一标识、内容相同答已有结果并回显此刻的状态，内容不同答来源冲突。已驳回的调整不因重投复活；要再调，用新的调整标识。
- 批准与驳回的重放身份取被指名的那一份：一份只批准一次、只驳回一次。已批准或已入账的再被批准、已驳回的再被驳回都答已有结果；已驳回的再被批准、已批准或已入账的再被驳回答状态不符。同一份上并发的两个决定串行判，先落的成立。
- 提交不改账，也不占用（`WF-RULE`）：提交之后那些数量照常可以被预占、冻结、盘点或移走，所以批准时照那一刻的账重判。取不取得走，照 `WF-RULE`「占用不被库内的入账挤占」那一条判，本用例不另写一份判法。
- 一份库存调整整份成立或整份不成立：提交时任一行不成立，整份不落；批准时任一行已不成立，整份不入账。入账在同一笔事务里，各行的流水同笔形成。一份库存差异同样不拆：记下的差额取不走全数时，不入账其中一部分。
- 库存差异照形成时记下的格与差额入账，不照批准那一刻的账重算：差额说的是那一次清点或那一条作业事实与账差了多少，形成之后那一格正常的进出不改它。差额记多了还是记少了，由批准的人判断：驳回，再提一份库存调整。
- 批准只在差异所在的那一格入账，不动别的格。库内作业的差额记在移入或转成的那一格（UC-WF-007）；这批货在账上若还记在源头那一格（被占着没取走的），批准之后账上会多出一份：先把源头理顺，或驳回之后以一份带调减行与调增行的库存调整一起改。批准哪一份、怎样理顺，本用例不替批准的人判断。
- 取走的数量没点名入库批次的从早到晚取；盘盈与调增归哪个入库批次照 `WF-RULE`：不另起入库批次，库龄随所归的那一个。更正批号、效期或库存状态的，以一行调减加一行调增表达，调增点名原来的入库批次，入库时间不变。这个商品在这个仓从没有过入库批次的，调增不成立，改走建账导入（UC-WF-006）。
- 批准职责规则只追加修订；批准照那一刻现行的修订判，所据的修订记在这次批准上，之后的新修订不回改已作出的批准。比的是两个操作者身份：库存调整与建账导入取提交的操作者；库存差异取形成它的那条作业事实的操作者（`WF-RULE`），盘点差异是那个库位现行那一份清点结果的操作者。驳回不改账，只要批准的授予，不照规则比（`WF-RULE`）。
- 处理时限自差异形成那一刻起、按经过的时间算，不按业务日，所以不依赖仓的业务时区；照读那一刻现行的修订算。过了时限的只在读口标出，不自动批准，也不自动驳回（`WF-RULE`）。规则没登记时超没超期答未配置；登记了而没带时限的，差异不算超期。
- 库存调整引用收货差异只是指名与留痕，不以它的结论为前提：没有结论的、已确认的、有异议的都可以引用，也可以不引用。提交时记下那一刻的结论与途径。代录的「已确认」此后被货主本人改成有异议（UC-WF-004）：已入账的调整不回退，待批准的照常等批准，不自动驳回；读口带出收货差异现行的结论与途径，要再改账另提一份调整。
- 批准与同一批格上的作业事实、预占、冻结和盘点的开始串行判，按到达本上下文的先后。

## 权限、隔离与审计

- 提交要「库存调整提交」授予，批准与驳回要「库存调整批准」授予，三种对象同一种批准授予；登记批准职责规则要「登记册配置写」授予。谁持有是租户取值。
- 持有批准授予不等于可以批准自己提交的：须不须不同主体由批准职责规则说了算，产品不写死（`WF-RULE`）。提交人与批准人两个身份每一笔都记下、可比，不论规则怎么写。
- 库存差异与库存调整只在操作者面、按租户隔离；调整的货主只从载荷指名并经 `party-commercial` 核对，商品按该货主的商品编码解析，不跨货主。货主经库存与流水的读口（[UC-WF-009](./UC-WF-009-FREEZE-AND-UNFREEZE-STOCK-AND-READ-STOCK-HOLDS-AND-MOVEMENTS.md)）看到入账的结果：盘盈、盘亏、调增、调减与销毁各笔，销毁的另带货主授权的依据引用；差异与调整本身、它们的原因不上客户面（`BD-WF-034`）。
- 调整的原因、驳回的原因与批准的说明逐字保存，只在操作者面，不以明文进日志或指标。
- 审计至少关联库存差异或库存调整、货主、仓、来源事实、提交人、批准或驳回的操作者与时刻、所据的批准职责规则修订、各笔流水与入库批次，以及批准职责规则各修订的登记人与时刻。

## 首发试点叠加条件

- 仓配不在首发范围（[ADR-0368](../../adr/0368-commodity-inventory-and-warehouse-fulfillment-join-the-product-as-a-new-context-and-node-operations-stays-non-wms.md) 决定八）；本用例属 PN-09，不进首发试点的任何准入。
- 提交、批准与驳回照运营决定面判准入范围。某个租户怎样经 PN-08 的阶段准入启用仓配，`ADR-OPT` 越权风险点 7 留着没定；仓配的写落在治理登记册的哪个对象范围随它一起没有定，本用例不替它定。
- 真实的批准职责规则与授予没有时，可以实现提交校验、两个身份的比较、批准时重判与同笔入账的机制，以及显式未配置与受控 `S`；演示租户的取值只在演示种子里。

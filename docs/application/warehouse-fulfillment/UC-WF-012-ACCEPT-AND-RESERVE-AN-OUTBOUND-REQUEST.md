# UC-WF-012 受理出库请求并预占

状态：用例已写成，待实现（PN-09，首发之外的可选能力）；缺货处置、谁有权代录、仓的业务时区与各项授予待租户提供

## 目标与边界

本用例从货主经客户渠道提交出库请求（或运营按货主授权代录）开始，到请求按可用量预占、被拒绝，或在分配之前被拆成几份新的出库请求为止。请求写什么、缺货时怎么办、预占落到哪一层、拆单到哪一刻为止，以[仓配履约 CONTEXT](../../domain/warehouse-fulfillment/CONTEXT.md)「出库请求与发出」「占用、预占与分配」与「出库请求」生命周期为准，本用例只组织输入、结果、流程与验收。

本用例解决「货主要从哪个仓出什么货、先占住可用量」一个问题。分配、拣货、打包与发出不在本用例。

本用例包含：

- 货主提交出库请求：商品明细或箱号，带发运方式。
- 按可用量预占；不够时按租户选定的缺货处置办。
- 按组件出的组合商品在受理时展开。
- 尚未分配的请求由货主拆单，或由运营按货主授权代录拆单。
- 运营代录新建出库请求。
- 货主与运营查阅出库请求、预占与分配。

本用例不执行：

- 波次、分配、拣货、出库复核、打包与贴标（[UC-WF-013](./UC-WF-013-RELEASE-A-WAVE-PICK-CHECK-AND-PACK.md)）。
- 以货主名义向小包托运提交委托（[UC-WF-014](./UC-WF-014-ACT-FOR-THE-OWNER-ON-A-WAREHOUSE-OUTBOUND-SHIPMENT.md)）。
- 出库确认（[UC-WF-015](./UC-WF-015-CONFIRM-WAREHOUSE-OUTBOUND.md)）与出库截单（[UC-WF-016](./UC-WF-016-CANCEL-AN-OUTBOUND-REQUEST-OR-PARCEL.md)）。
- 指名代理仓之后的转发与代理仓答复：受理到已转代理仓为止，其后归代理仓的用例。

## 启动条件

- 部署已打开仓配开关（`ADR-OPT` 决定四）。关着时本用例各口不提供业务答复。
- 货主口持相应的客户面授予。代录口持「出库请求代录」。没有授予答未授予。
- 指名的自营仓或代理仓没登记答查无所指的仓，不建默认仓。一个仓都没登记的租户，提交答查无所指的仓；拆单与代录答未配置（`WF-RULE`，`ADR-OPT` 决定五）。
- 停用的仓照常受理出库请求（`WF-RULE`）。
- 缺货处置没选定答未配置，请求停在待预占（未配置）（`WF-RULE`）。

## 结果语义契约

| 结果 | 业务含义 | 必须留下 | 明确不是 |
|---|---|---|---|
| 已预占 | 可用量够，整份占上 | 单据号、预占落到的各部分 | 还没分配到库位 |
| 部分预占 | 缺货处置是部分预占，先占有的 | 已占与未占的数量 | 没占齐不进波次 |
| 已拒绝 | 缺货处置是拒绝 | 原因是缺货 | 不留预占 |
| 待预占（未配置） | 缺货处置没选定 | 请求停在这里 | 可用量变了也不自动再判 |
| 已拆单 | 原请求终结，新请求各自重新预占 | 新请求指名原请求 | 原请求上的预占已释放 |
| 已有结果 | 同一来源请求键、内容相同 | 回显此刻的状态 | 不再预占一次 |
| 内容冲突 | 同一来源请求键、内容不同 | 在册的那一份不变 | |
| 查无所指的仓 | 仓没登记 | 不落册 | 不改投别的仓 |
| 未授予 | 没有相应授予 | 不落册 | |
| 未配置 | 缺货处置没选定，或一个仓都没登记时的拆单与代录 | 提交若已形成请求则停在待预占（未配置） | 不替租户选一种缺货处置 |
| 坏载荷 | 代录没带依据引用，或指名在册的请求又带了货主 | 不落册 | |

读口答每份预占属于哪份出库请求、数量、是否已分配、分配落到哪些格。带批号、效期或贴标别名条件的，答在满足条件的那部分上占了多少。 [UC-WF-009](./UC-WF-009-FREEZE-AND-UNFREEZE-STOCK-AND-READ-STOCK-HOLDS-AND-MOVEMENTS.md) 的读口照这个答。

## 应用流程

1. 核发运方式、仓、明细与按发运方式必带的各格。不成立答坏载荷或查无所指的仓，整份不落。
2. 按组件出的组合商品展开成组件行（`WF-RULE`）。
3. 在库存账内原子预占。够则已预占；不够则按缺货处置给部分预占或已拒绝；没选定则待预占（未配置）。
4. 拆单只对尚未分配的请求成立。各份合起来不等于原请求的答坏载荷。
5. 查阅照册答，不改账。

## 一致性、幂等与并发

- 货主口按来源请求键认重放：相同答已有结果，不同答内容冲突。
- 代录新建按调用方给的决定标识认。拆单按被拆的那份请求认。
- 预占与别的占用在库存账内串行判，不静默超卖（`WF-RULE`）。
- 商品库存的预占不落库位；整箱按箱号预占（`WF-RULE`）。

## 权限、隔离与审计

- 货主只提交、拆、读自己的请求。
- 代录的依据引用逐字保存。货主在自己的读口看得到哪一笔是代录的。
- 两个面都判准入范围。对照没登答不在准入范围。

# UC-CC-010 关闭、受控重开关务案件并建立后续案件

状态：开发基线草案；案件关闭、受控重开和后续案件的稳定业务机制已形成，真实程序的义务目录、责任承接规则和权限参数待提供

## 目标与边界

本用例负责两个相互衔接但不能混同的业务入口：一是对进行中的关务案件逐项核对当前申报、阻断性限制、监管处置和其他应履行义务，在全部义务已经终结或剩余责任已被有效承接后形成关闭决定；二是在已关闭案件收到迟到监管事实后，判断该事实仍属于原案件固定身份内的同一监管程序，还是形成独立监管义务，并据此形成受控重开决定或建立关联后续关务案件。两类处理都保留原关闭、原申报、原监管结果和已经发生的物流、资金及结算事实。

本用例包含：

- 按案件固定身份和适用程序形成版本化关务案件关闭核对，盘点每项当前申报、限制、监管处置、税费及其他应履行义务。
- 为每项在册义务形成关闭依据项，分别记录义务、范围、责任来源、采用事实或规则版本，以及已终结、已移交、未解决或冲突的结论。
- 对尚未终结但真实程序允许后续处理的责任，形成明确的剩余关务责任移交，并等待接收责任方对范围和续办引用作出有效承接；仅发送通知或创建待办不构成移交完成。
- 仅在全部适用关闭依据项均为已终结或已被有效承接时，由有权责任角色形成关务案件关闭决定，并保存决定范围、关闭责任来源、采用依据、生效时间和审计历史。
- 接收 `UC-CC-006`、`UC-CC-008`、`UC-CC-009` 或其他权威来源已经保全的迟到事实，识别其与原案件固定身份、原关闭依据项和原监管程序的关系。
- 接收 `UC-PS-002` 在案件关闭后形成的客户原始资料版本，先保全其来源和业务有效时间，再判断它是否影响原案义务、同一程序续办或独立后续义务。
- 对仍属于原监管程序且未改变案件固定身份的迟到事实，依据相关原关闭责任来源及当前有效授权形成受控重开决定。
- 对独立补税、稽核、申诉或其他后续监管义务，或者改变监管辖区、进出口方向、监管程序或法定义务身份的事项，建立关联后续关务案件并保留触发事实和关系。
- 处理重复请求、并发事实、关闭期间迟到消息、批量部分成功、来源冲突、未授权、业务未决和技术未形成结果。

本用例不执行：

- 建立首次关务案件、组建申报单元、形成正式申报资料、判断申报就绪、授权提交或对外申报；后续案件的固定身份建立复用 [UC-CC-001](./UC-CC-001-ESTABLISH-CUSTOMS-CASE.md) 的建案规则。
- 接收、解释或修改原始监管响应；迟到监管事实仍先由 [UC-CC-006](./UC-CC-006-RECEIVE-AND-RECONCILE-EXTERNAL-RESULTS.md) 保全并形成适用结果。
- 创建、解除或覆盖内部合规限制，也不以案件关闭或重开代替限制来源的解除决定。
- 不把客户原始资料版本直接解释为申报更正、重开依据或义务终结；必要的关务动作仍由 `UC-CC-007` 分类。
- 执行查验、扣留、移交、销毁、退运或其他物理处置，也不把执行方完成标记当作义务终结。
- 形成实际付款、资金退回、客户代垫回收、客户收款、核销、运营结算或法定财务结果。
- 关闭异常案件、作业任务、运输任务、付款事项、结算事项、申报单元或监管决定。
- 因预计复核时间、SLA 到期、长期无新消息、运输完成、交付完成、付款完成、监管放行、人工勾选或管理员意愿自动关闭或重开案件。

关务案件关闭是对当前在册义务是否已经终结或被有效承接的业务决定，不是“清关成功”。受控重开是对原案件继续承担同一监管程序责任的决定，不是修改历史；后续案件则承载独立义务，不是原案的另一个状态。

## 七类对象必须分离

| 层次 | 对象或结果 | 本用例职责 | 不得推导 |
|---|---|---|---|
| 义务来源事实 | 申报、限制、监管决定、执行核对、税费、付款核对及其他义务事实 | 只读引用来源身份、版本、范围、适用时间和当前有效性 | 不得由案件状态改写来源事实 |
| 关闭核对 | 关务案件关闭核对及关闭依据项 | 对每项在册义务形成已终结、已移交、未解决或冲突结论 | 单项完成不得推导整案可关闭 |
| 责任承接 | 剩余关务责任移交及接收结果 | 固定责任、范围、来源方、接收方、接受结果和续办引用 | 发送消息、创建待办或口头同意不得推导已承接 |
| 关闭决定 | 关务案件关闭决定 | 在全部关闭依据项合格后形成业务关闭 | 不得推导法定追溯期结束、监管事实删除或物流回退 |
| 迟到事实分类 | 迟到事实与原案件固定身份、原关闭依据和义务身份的关系判断 | 形成同一程序续办、独立义务或关系未决结论 | 不得因用户偏好选择重开以规避新案 |
| 重开决定 | 受控重开决定 | 按相关原关闭责任来源和当前授权恢复原案件继续处理 | 不得撤销原关闭决定或修改关闭期间事实 |
| 后续案件 | 新关务案件及与原案的后续关系 | 对独立义务建立自己的固定身份、责任范围和生命周期 | 不得覆盖原案、继承不适用的授权或回退履约事实 |

界面可以汇总显示上述关系，但不得以一个可手工维护的“清关状态”“关闭来源”或 `closed` 标记代替逐义务核对、关闭决定和重开决定。

## 启动条件

- 关闭请求必须指向一个进行中的关务案件，并能够取得该案件固定监管身份、当前申报、有效限制、监管处置、税费及其他适用义务的可追溯清单。
- 义务是否终结必须由该义务的权威来源、真实程序规则和适用时间共同证明。监管放行、付款完成、交付完成或一段时间没有消息都不能单独证明全部义务终结。
- 尚存责任只有在真实程序允许后续处理，并且责任、范围、来源方、接收方、接受结果和续办引用均明确时，才可以作为已移交参与关闭核对。
- 关闭决定方、关闭责任来源以及适用客户、法人、程序和范围必须来自已登记权限；系统管理员或案件编辑权限不自动拥有关闭决定权。
- 迟到事实必须先被合格来源保全。事实内容、来源、适用时间或案件关系仍不确定时，可以登记待分类，但不能自动重开或建立后续案件。
- `UC-PS-002` 形成的客户资料版本也必须先保全和分类；资料版本本身不自动改变关闭核对、重开或后续案件结果。
- 原案受控重开只适用于监管辖区、进出口方向、监管程序和法定义务身份均保持不变的同一程序续办；任一固定身份改变或形成独立义务时必须建立关联新案。
- 重开权限必须按受影响关闭依据项追溯相关原关闭责任来源，并使用重开决定时当前有效的授权规则。多个来源要求冲突或不能完整覆盖受影响范围时保持待决定。

## 输入语义契约

下表定义稳定业务输入，不是 API、事件 Schema、数据库字段或任务清单。

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |
|---|---|---|---|
| 关闭或续办请求 | 请求方 / 应用编排 | 稳定请求身份、目标案件、请求类型、明确范围、原因和业务发生时间 | 相同请求可查询；同一身份不同内容形成冲突 |
| 案件固定身份 | `customs-compliance` | 案件、监管辖区、进出口方向、监管程序、法定义务范围、责任法人和客户范围 | 只读比较；不能为适配迟到事实原地修改 |
| 在册义务清单 | 各权威用例和来源 | 每项申报、限制、监管处置、税费及其他义务的身份、范围、责任来源、版本、适用时间和当前有效性 | 不以单一案件状态、页面标记或汇总完成代替逐项清单 |
| 义务终结依据 | 各义务责任来源 / 适用规则 | 明确义务、范围、结束结论、采用事实或规则版本、决定方和适用时间 | 缺少权威依据时为未解决，不猜测终结 |
| 剩余责任移交 | 来源责任方与接收责任方 | 责任身份、范围、移交原因、来源方、接收方、接受结果、续办引用和适用时间 | 请求已发送不等于接受；拒绝、超范围接受或无续办引用不能支持关闭 |
| 决定授权 | `party-commercial` / 适用关务规则 | 关闭或重开决定角色、责任来源、授权范围、版本、有效期间和委派依据 | 在决定形成时重新校验；历史关闭授权不自动支持当前重开 |
| 原关闭历史 | `customs-compliance` | 关闭决定、关闭核对版本、逐项关闭依据、责任来源、决定方、生效时间和当时授权 | 不得覆盖、删除或只保留当前状态 |
| 迟到事实或客户资料版本 | `UC-CC-006`、`UC-PS-002` 等权威来源 | 来源身份、事实身份、明确范围、业务/适用/接收时间、更正关系和当前有效性 | 消息到达顺序不决定是否重开；原始事实先保全后分类 |
| 已发生跨上下文事实 | 节点、运输、资金、结算等所有者 | 已完成作业、交接、移动、交付、付款、回收或其他稳定事实引用 | 只用于保护历史和判断影响，不得由重开或新案撤销 |

## 结果语义契约

| 结果 | 业务含义 | 必须返回或可查询的依据 | 禁止行为 |
|---|---|---|---|
| 关闭核对已形成 | 已对当前在册义务逐项形成版本化结论 | 案件、核对版本、基准时点、完整义务清单、逐项来源和结论 | 不得等同案件已关闭 |
| 案件可关闭 | 每项适用义务均已终结或被有效承接 | 全部关闭依据项、责任承接接受结果、适用规则和决定入口 | 不得自动形成关闭决定或忽略决定授权 |
| 案件关闭未决 | 至少一项义务未解决、冲突或责任承接未被有效接受 | 未决义务、缺口、冲突、责任来源、影响范围和续办入口 | 不得创建关闭标记、虚构责任承接或将未决转为技术失败 |
| 剩余责任已承接 | 接收责任方在有效授权和明确范围内接受后续责任 | 移交双方、责任、范围、接受结果、续办引用、适用时间和版本 | 不得表示责任已经履行完毕，也不得扩大到未接受范围 |
| 关务案件已关闭 | 有权责任角色基于当前合格核对形成业务关闭决定 | 关闭决定、核对版本、逐项依据、关闭责任来源、决定方、授权、生效时间和审计 | 不得删除事实、终止法定追溯、解除限制或回退履约 |
| 已有关闭结果 | 相同请求和相同业务内容已经形成关闭决定 | 原请求、原关闭决定、采用核对及当前适用性 | 不得创建第二个决定或重置关闭时间 |
| 迟到事实待分类 | 事实已保全，但无法确定是否属于原程序续办或独立义务 | 迟到事实、候选关系、缺口、冲突和复核入口 | 不得自动重开、自动建案或忽略事实 |
| 关务案件已受控重开 | 迟到事实仍属于原案件固定身份内的同一程序，并形成合法重开决定 | 迟到事实、原关闭决定、受影响关闭依据项、相关原关闭责任来源、当前授权、决定方和生效时间 | 不得撤销原关闭、修改历史提交或回退已发生事实 |
| 后续关务案件已建立 | 独立义务已有自身固定身份和责任范围，并与原案及触发事实关联 | 新案件、原案件、关系类型、触发事实、固定身份、包裹/客户范围和角色资格快照 | 不得把原案改为进行中、复制不适用授权或合并客户责任 |
| 当前事实无需改变案件生命周期 | 迟到事实不产生原案续办或独立关务义务，或者只是已记录事实的合格重复 | 事实、关系判断、采用规则、适用范围和决定依据 | 不得删除事实或把该结论解释为事实无效 |
| 关闭或续办请求冲突 | 同一请求身份携带不同案件、事实、范围、原因或决定内容 | 原请求、新请求、冲突内容和纠正入口 | 不得按最后到达覆盖 |
| 关闭或续办请求未受理 | 请求主体、租户、法人、客户、案件、事实或权限不能合法关联 | 最小校验依据、原因、时间和责任交接 | 不得泄露越权案件或事实是否存在 |
| 未形成关闭或续办结果 | 技术处理未完成，无法安全形成核对、关闭、重开或后续案件 | 请求、失败阶段、已采用输入、已有结果和恢复引用 | 不得伪装成业务未决、关闭成功、重开成功或后续案件已建立 |

`案件可关闭`是关闭核对的结论，`关务案件已关闭`是有权角色形成的生命周期决定；二者不能合并。对一项不可再分的义务范围，`迟到事实待分类`、`关务案件已受控重开`和`后续关务案件已建立`是互斥的当前处理结果；同一来源事实包含可分离范围时，可以分别形成原案重开和后续案件。新的权威事实可以触发新的判断版本，但不覆盖此前结果。

## 关闭、重开与后续案件规则

- 关闭核对必须覆盖基准时点全部在册义务，并按义务身份和明确范围形成关闭依据项。义务类型只是分类，不能用“申报完成”“已放行”或一个总开关代替逐项核对。
- 每个关闭依据项只能采用已终结、已移交、未解决或冲突之一作为当次结论。已移交必须引用有效承接；未解决或冲突必然阻止当前关闭。
- 责任移交只有在真实程序允许、接收责任方明确接受且续办责任可追溯时成立。通知送达、任务创建、抄送外部服务方、预计后续处理或默认超时接受均不成立。
- 关闭决定必须绑定一个仍为当前的关闭核对版本。核对完成后出现新的义务事实、限制、处置变化、税费更正或承接撤回时，原核对失效并重新判断，不得继续提交旧核对。
- 关闭责任来源必须按各关闭依据项保存，关闭决定还要保存实际决定方和授权依据；不得用一个全局来源抹平多项义务的不同责任来源。
- 案件关闭不删除未结或历史事实，不关闭申报单元、限制、处置、付款、结算、异常或物流对象，也不表示法定留存、稽核或追溯期已经结束；案件关闭或重开均不代替 `UC-CC-011` 的限制解除决定。
- 已关闭案件的任何迟到事实先作为新的来源事实保存。只有该事实与原案件固定身份、原程序及原义务关系能够确定后，才能形成重开或后续案件决定。
- 受控重开必须指向原关闭决定和受影响关闭依据项，尊重相关原关闭责任来源，并在重开时校验当前有效授权。原来源已不存在、授权不完整或多来源冲突时保持待分类/待决定，不由管理员代替。
- 监管辖区、进出口方向、监管程序或法定义务身份改变，或者事实形成独立补税、稽核、申诉或其他监管义务时，必须建立后续案件；不能通过重开或编辑原案吸收。
- 同一迟到来源事实包含可分离范围时，逐义务范围分别判断：仍属原程序的范围可以受控重开，独立义务范围建立后续案件。来源消息级别不得被强制二选一，也不能用其中一个结果覆盖另一范围。
- 后续案件复用首次建案的固定身份、角色资格和隔离规则，但必须保存原案、触发事实和关系类型；它不继承原案的当前限制、授权或已完成结果，除非权威规则明确要求并形成新的适用关系。
- 重开或建立后续案件只恢复或创建关务处理责任。已经发生的节点作业、运输交接、实际移动、交付、付款、资金退回、客户回收和结算事实继续有效，由各自所有者依据新事实决定是否形成后续动作或调整。
- `UC-SA-001` 在案件关闭后形成实际代垫判断、客户回收、借/贷调整、客户收款映射或核销关系，不自动产生关务重开或后续案件。只有结算所引用的新来源事实同时形成新的监管义务，并经本用例完成迟到事实分类后，才可能触发关务生命周期变化。

## 应用流程

### 正常关闭

| 步骤 | 责任方 | 应用动作 | 结果与下一步 | 权威依据 |
|---|---|---|---|---|
| 1 | 关闭请求方 / `customs-compliance` | 校验请求主体、租户、法人、客户、案件身份和关闭权限 | 越权或最小身份不成立时未受理 | `ADR-SCOPE` |
| 2 | `customs-compliance` | 确认案件正在进行，识别相同请求、已有关闭、内容冲突和并发变化 | 重复返回已有结果；冲突不覆盖 | `ADR-FACT`、`CC-LIFE` |
| 3 | `customs-compliance` / 各义务来源 | 以明确基准时点盘点当前申报、限制、监管处置、税费及其他适用义务 | 形成完整在册义务清单；来源不可用时保持未决 | `CC-RULE` |
| 4 | `customs-compliance` | 逐义务采用权威事实、规则版本和当前有效性形成关闭依据项 | 已终结进入合格项；未解决或冲突阻止关闭 | `CC-RULE`、`ADR-FACT` |
| 5 | 来源责任方 / 接收责任方 | 对允许后续处理的剩余责任发起并明确接受范围化移交 | 接受后形成已移交依据；拒绝、未响应或超范围接受仍未决 | `CC-RULE` |
| 6 | `customs-compliance` | 汇总当前核对，确认全部依据项均已终结或有效移交，并检查核对版本仍为当前 | 形成案件可关闭或案件关闭未决 | `CC-LIFE` |
| 7 | 有权关务责任角色 | 基于当前核对、各关闭责任来源和有效授权形成关闭决定 | 形成关务案件已关闭；不修改其他对象 | `CC-RULE` |
| 8 | `customs-compliance` | 提交关闭决定、逐项依据、责任来源、审计和发布意图 | `UC-VE-001` 等下游可观察关闭事实，但不得据此回退或自动关闭/重开自身对象；异常案件变化也不级联关务案件 | `ADR-FACT`、`VE-HANDOFF` |

### 迟到事实续办

| 步骤 | 责任方 | 应用动作 | 结果与下一步 | 权威依据 |
|---|---|---|---|---|
| 1 | `UC-CC-006`、`UC-PS-002` 等权威来源 | 保全并关联关闭后到达的监管、义务事实或客户资料版本 | 事实先存在且历史不覆盖；无法关联时不进入生命周期决定 | `CC-RESULT`、`PS-SOURCE`、`ADR-FACT` |
| 2 | `customs-compliance` | 校验案件、事实、租户、法人、客户范围和续办权限 | 越权或最小身份不成立时未受理 | `ADR-SCOPE` |
| 3 | `customs-compliance` | 比较迟到事实与原案件固定身份、原关闭决定、受影响关闭依据项和义务身份 | 形成同一程序续办、独立义务或待分类 | `CC-RULE`、`CC-LIFE` |
| 4A | 有权关务责任角色 | 对同一程序续办，按相关原关闭责任来源及当前授权形成受控重开决定 | 原案重新打开，原关闭和关闭期间事实保留 | `CC-LIFE` |
| 4B | `customs-compliance` / `UC-CC-001` | 对独立义务，按首次建案规则固定新案件身份、范围和角色资格快照 | 后续案件已建立，原案保持关闭 | `CC-CASE`、`CC-LIFE` |
| 5 | `customs-compliance` | 保存迟到事实分类、重开或后续案件决定、关系、审计和发布意图 | 对应后续申报、处置、税费或其他用例从合法案件入口续办 | `ADR-FACT` |

批量关闭或迟到事实批处理必须逐关务案件形成独立结果。允许部分案件关闭、部分保持未决、部分重开或部分建立后续案件；汇总结果不得制造一个关务案件的“部分关闭”，也不得因一案失败回滚其他案件已经合法形成的决定。

## 最小业务提交边界

- 正常关闭时，关闭核对、逐项关闭依据、有效责任承接引用、关闭决定、采用授权、审计和发布意图必须形成可恢复的受保护业务结果。
- 责任承接由接收责任方独立形成时，本用例只保存稳定接受结果引用；接受结果迟到不能被伪装为拒绝或默认接受，后续恢复必须沿用原移交身份。
- 受控重开时，迟到事实引用、分类判断、原关闭决定、受影响依据项、相关原关闭责任来源、当前授权、重开决定、审计和发布意图必须一致可追溯。
- 建立后续案件时，新案件固定身份、原案关系、触发事实、责任范围、角色资格快照和发布意图必须形成一个可恢复结果；建立失败不得把原案改为已重开。
- 结果已提交但首次发布失败时只重试同一发布意图，不重复关闭、重开、承接责任或建立第二个后续案件。

## 一致性、幂等与并发

- 同一请求身份和相同业务内容重复到达时返回已有核对、关闭、重开或后续案件结果；同一身份携带不同案件、事实、范围或决定内容时形成请求冲突。
- 同一迟到事实经回调、文件、查询或人工导入重复到达时复用来源事实身份和已有分类，不重复重开或建立后续案件。
- 关闭核对与新外部事实、限制形成/解除、处置核对、税费更正或付款核对并发时，先保留各自事实；旧核对失效或形成并发冲突，不得让关闭提交覆盖新事实。
- 关闭决定与责任承接撤回并发时，按各自业务发生时间、适用时间和权威规则形成新判断；已形成决定和撤回事实都保留，不按消息到达先后删除任一方。
- 重开决定与独立义务建案请求并发时，以迟到事实的固定身份和义务关系为依据形成一个当前分类；冲突时保持待分类，不允许原案和后续案件同时无依据承载同一义务。
- 多项迟到事实可以分别触发原案重开和后续案件，但每项事实与义务范围必须明确关联；原案已因一项事实重开，不表示其他独立事实也应吸收进原案。
- 已关闭、重开后再次关闭以及后续再次重开都形成新的决定和核对版本，历史关闭周期永久保留，不更新原关闭时间或原决定内容。

## 权限、隔离与审计

- 关闭请求、义务终结确认、责任移交、责任承接、关闭决定、迟到事实分类、受控重开决定和后续案件建立分别授权；任何一个权限都不能由其他权限、系统管理员身份或页面编辑能力推导。
- 关闭和重开均在决定形成时校验集团租户、运营责任法人、客户账户、监管程序、案件范围、责任来源和当前有效授权。跨客户合报只披露履行共同监管责任所必需的范围。
- 重开必须记录请求方、实际决定方、相关原关闭责任来源、当前授权依据和受影响范围；“同级或更高权限”只有在登记规则明确时才成立，不能写成全局默认。
- 审计至少关联案件身份、关闭周期、关闭核对版本、每项义务及范围、来源事实/规则版本、终结或移交结论、移交双方和接受结果、关闭决定、迟到事实、分类判断、重开决定或后续案件关系、业务时间、适用时间和记录时间。
- 日志和错误保持最小披露，不暴露其他客户、法人、案件、税费、监管原因、资格或处置细节。未受理结果不得确认越权对象是否存在。

## 可观测性与非功能验收占位

- 能够从任一关闭决定回溯完整义务清单、逐项依据、责任承接、决定方和授权，也能从任一重开或后续案件回溯迟到事实、原关闭决定及分类依据。
- 分别统计关闭请求量、可关闭量、未决量、各类未决义务、责任承接待确认、关闭决定量、迟到事实量、待分类量、受控重开量、后续案件量、未受理、冲突、技术未形成和发布恢复结果。
- 时效分别记录关闭请求至核对形成、核对至关闭决定、移交请求至承接结果、迟到事实接收至分类、分类至重开或后续案件形成；具体目标值待真实规模和责任方确认。
- 恢复测试必须覆盖核对后新事实到达、承接结果迟到、关闭提交成功但发布失败、同一迟到事实重复到达、重开与后续建案竞争、后续建案失败及跨客户越权。
- 数据保留期、法定追溯期、迟到事实观察期、批量规模、并发量和服务目标未确认前均保持显式未配置，不填入推测默认值。

## 首发试点约束

- `P` 生产主链必须实现：单案件完整义务盘点、逐项关闭依据、明确责任承接结果、人工授权关闭、关闭历史查询，以及新事实与关闭并发时阻止错误关闭。
- `R/S` 最小骨架必须验证：关闭后迟到事实保全、同一程序受控重开、独立义务建立后续案件、重复/冲突处理和不回退已发生事实。真实自然发生时保留生产证据，不得为验收主动制造监管风险。
- 首发不要求自动关闭、自动重开、批量自动分类、复杂跨来源授权策略或多级审批；未配置分支保持待确认或人工复核，不使用宽松默认值。
- 正常关闭只针对关务案件。异常、作业、运输、付款、结算和客户通知仍按各自用例与责任方独立处理。
- 真实义务目录、可移交事项、接收责任方、关闭责任来源、关闭/重开权限和后续案件身份规则由 `PAR-CUS-06` 提供；未确认前不得宣称相应程序已经生产就绪。

## 验收示例

| 编号 | Given / When | Then |
|---|---|---|
| `AT-CC-296` | 进行中案件的当前申报、限制、处置、税费及其他义务可完整盘点 | 形成版本化关闭核对和逐项关闭依据；不只读取一个案件状态 |
| `AT-CC-297` | 全部适用义务均有权威终结依据 | 关闭核对形成`案件可关闭`；仍不自动生成关闭决定 |
| `AT-CC-298` | 一项申报结果仍待确认 | 该依据项为未解决，案件保持进行中并返回原提交查询或续办入口 |
| `AT-CC-299` | 存在仍有效且覆盖当前范围的内部合规限制 | 该依据项未终结并阻止关闭；异常关闭、外部放行或管理员勾选不能代替解除 |
| `AT-CC-300` | 限制来源形成只覆盖部分范围的有效解除 | 已解除范围更新依据，剩余范围仍阻止关闭；不汇总为全部解除 |
| `AT-CC-301` | 查验执行方标记完成，但处置核对仍为部分覆盖或证据不足 | 处置义务保持未解决；执行完成标记不关闭案件 |
| `AT-CC-302` | 税费已核定但付款义务或放行前置关系仍未决 | 对应义务保持未解决；不以核定、付款申请或交付完成关闭案件 |
| `AT-CC-303` | 监管已经放行，但仍有独立内部限制或后续资料义务 | 只将放行相关义务按依据核对，其他义务继续阻止关闭 |
| `AT-CC-304` | 真实程序允许一项剩余责任后续处理，来源方向明确接收方发起移交 | 形成待承接移交；通知送达或待办创建不构成已移交 |
| `AT-CC-305` | 接收方在有效权限和完整范围内接受责任并提供续办引用 | 形成`剩余责任已承接`，该关闭依据项可记为已移交；不表示责任已履行完毕 |
| `AT-CC-306` | 接收方拒绝、未响应、只接受部分范围或缺少续办引用 | 未接受范围保持未解决，案件不得关闭 |
| `AT-CC-307` | 所有依据项均已终结或有效移交，且决定方当前授权有效 | 形成不可覆盖关闭决定，保存逐项依据、责任来源、决定方、授权和生效时间 |
| `AT-CC-308` | 相同关闭请求和相同内容再次到达 | 返回已有关闭结果，不形成第二决定或重置关闭时间 |
| `AT-CC-309` | 同一关闭请求身份携带不同义务范围或决定内容 | 形成请求冲突，不按最后到达覆盖原请求或决定 |
| `AT-CC-310` | 关闭核对完成后、关闭决定提交前到达新的有效限制或监管事实 | 原核对失效或形成并发冲突，重新盘点；不得用旧核对关闭 |
| `AT-CC-311` | 案件已关闭后检查原申报、限制、处置、税费、付款、结算和物流事实 | 全部历史及所有权保持；关闭不删除、解除、撤销或回退任何对象 |
| `AT-CC-312` | 用户仅凭监管放行、付款完成、运输完成、交付完成、SLA 到期或长期无消息请求关闭 | 拒绝据此直接关闭；必须完成逐义务核对和授权决定 |
| `AT-CC-313` | 关闭请求包含多个独立案件，其中部分满足、部分未决 | 逐案返回关闭或未决结果；不回滚已合法关闭案件，也不形成单案“部分关闭” |
| `AT-CC-314` | 已关闭案件收到合格来源的迟到更正事实 | 先保存新来源事实及其时间、范围和更正关系，不覆盖原决定或因已关闭而忽略 |
| `AT-CC-315` | 迟到事实的来源、范围或与原案关系尚不能确定 | 形成`迟到事实待分类`和复核入口，不自动重开或建案 |
| `AT-CC-316` | 迟到事实仍属于原监管辖区、方向、程序和法定义务身份内的同一程序续办 | 进入受控重开判断，不因案件已关闭建立无关新案 |
| `AT-CC-317` | 同一程序迟到事实关联到原关闭决定和受影响依据项，相关原关闭责任来源及当前授权均允许 | 形成受控重开决定，原案重新打开并保留原关闭及关闭期间事实 |
| `AT-CC-318` | 操作员有案件编辑权限但没有相关重开授权 | 重开请求未受理或待授权，不由管理员身份、编辑权限或人工备注绕过 |
| `AT-CC-319` | 多个受影响关闭依据项的原责任来源要求冲突，或授权未完整覆盖范围 | 保持重开待决定并记录冲突；不选择最宽松来源 |
| `AT-CC-320` | 迟到事实改变监管辖区、进出口方向、监管程序或法定义务身份 | 不允许重开吸收；按固定身份规则建立关联后续案件 |
| `AT-CC-321` | 迟到事实形成独立补税义务 | 建立拥有独立义务范围的后续案件，原案保持关闭；实际付款和客户回收仍由各自所有者形成 |
| `AT-CC-322` | 迟到事实形成独立稽核、申诉或其他后续监管义务 | 建立关联后续案件并保存关系类型、触发事实和自身生命周期 |
| `AT-CC-323` | 建立后续案件时固定身份或必要责任角色证据不足 | 后续建案条件不足或未形成，原案仍关闭；不得改为重开规避缺口 |
| `AT-CC-324` | 同一迟到事实重复投递或经不同传输方式再次到达 | 复用来源事实和已有分类，不重复重开或创建第二后续案件 |
| `AT-CC-325` | 同一迟到事实被并发请求分别主张为重开和后续案件 | 按固定身份与义务关系形成唯一当前分类；无法裁决时保持冲突，不同时无依据承载 |
| `AT-CC-326` | 原案已因事实 F1 重开，随后事实 F2 形成独立义务 | F2 仍建立关联后续案件，不因原案当前进行中被强行吸收 |
| `AT-CC-327` | 重开后再次完成义务并申请关闭 | 形成新的关闭核对和关闭决定周期，保留第一次关闭、重开和全部中间事实 |
| `AT-CC-328` | 受控重开后存在已完成节点作业、运输移动、交接、交付或付款 | 事实继续有效；只形成必要后续关务责任，不回退或撤销这些事实 |
| `AT-CC-329` | 后续案件建立后需要新申报、处置或税费处理 | 从后续案件合法入口进入对应用例；不修改原案件的提交和结果历史 |
| `AT-CC-330` | 迟到事实经权威判断只是已记录事实的合格重复且不产生新义务 | 形成`当前事实无需改变案件生命周期`，保留事实关系但不重开或建案 |
| `AT-CC-331` | 关闭决定提交成功但发布失败，随后恢复 | 只重试同一发布意图，不重复关闭、重置生效时间或重复交接责任 |
| `AT-CC-332` | 后续案件建立过程中技术失败 | 返回未形成结果和恢复引用；原案保持关闭，不伪装成重开或建案成功 |
| `AT-CC-333` | 越权主体请求关闭、查看迟到事实、重开或建立后续案件 | 请求未受理并最小披露，不确认其他客户或法人对象是否存在 |
| `AT-CC-334` | 跨客户合报案件执行关闭或续办 | 共同监管范围可核对，客户资料、税费、责任、权限和可见性逐客户隔离 |
| `AT-CC-335` | 检查本用例直接形成或修改的业务对象 | 只形成关闭核对/依据、责任移交引用、关闭决定、迟到事实分类、重开决定、后续案件及关系；不形成监管事实、限制解除、物理执行、资金或结算结果 |
| `AT-CC-336` | 同一迟到来源事实包含仍属原程序的范围 R1 和形成独立义务的范围 R2 | R1 依据合法决定受控重开原案，R2 建立后续案件；逐范围保留关系，不把整条消息强制归为一种结果 |
| `AT-CC-337` | 原案已经历关闭 C1、重开、再次关闭 C2，随后又收到同程序迟到事实 | 新重开决定精确引用使当前关闭期成立的 C2 及受影响依据项；C1 和全部中间周期继续保留 |
| `AT-CC-338` | 原案重开或后续案件建立后检查旧就绪、提交授权、凭证适用性、门禁及父子案件生命周期 | 不自动复活旧判断或授权；后续动作按当前规则重新判断，原案与后续案件关闭/重开互不级联 |

## 生产参数与待决风险

| 待决项 | 未确认时的安全行为 | 生产阻塞影响 |
|---|---|---|
| 各真实程序的在册义务目录和终结依据 | 只能形成可解释的未决关闭核对，不自动关闭 | 阻塞对应程序正常关闭 |
| 哪些剩余责任允许移交、接收责任方及有效承接语义 | 未接受前一律保持未解决 | 阻塞含剩余责任案件关闭 |
| 关闭决定角色、逐项关闭责任来源和授权范围 | 不允许管理员或通用关务角色代替 | 阻塞生产关闭决定 |
| 同一程序续办与独立义务的判定依据 | 迟到事实保持待分类，不自动重开或建案 | 阻塞关闭后自动续办 |
| 重开决定角色、原关闭责任来源约束及冲突处理 | 保持待授权或待决定 | 阻塞生产受控重开 |
| 后续案件的固定身份、关系类型和角色资格来源 | 复用建案条件不足/未形成结果，不创建占位案件 | 阻塞生产后续建案 |
| 法定留存、追溯和迟到事实观察要求 | 保留全部历史，不以案件关闭触发删除 | 阻塞归档与数据生命周期设计，不阻塞业务事实保全 |
| 批量规模、并发基线和关闭/续办服务目标 | 保留参数化与可观测占位，不承诺数值 | 阻塞容量与性能验收 |

以上参数统一登记在 [首发试点参数与证据登记册](../../product/PILOT-PARAMETER-REGISTER.md)；未确认值不得以国家、口岸、角色、期限或自动决策默认值写入实现。

## 开发拆分建议

### `P` 首发生产主链

1. 单案件关闭请求、完整在册义务盘点和逐项关闭依据。
2. 剩余责任移交、明确承接结果和未决阻断。
3. 人工授权关闭决定、关闭周期、审计和历史查询。
4. 关闭核对与新事实并发控制，以及已提交结果的发布恢复。
5. `AT-CC-296` 至 `AT-CC-313`、`AT-CC-327`、`AT-CC-331`、`AT-CC-333` 至 `AT-CC-335` 的生产测试骨架。

### `R/S` 回放或模拟骨架

1. 关闭后迟到事实保全、分类待确认和同一程序受控重开。
2. 独立补税、稽核、申诉或身份变化时建立后续案件。
3. 重开/后续案件竞争、重复事实、技术恢复和既有事实保护。
4. `AT-CC-314` 至 `AT-CC-326`、`AT-CC-328` 至 `AT-CC-330`、`AT-CC-332`、`AT-CC-336` 至 `AT-CC-338` 的可重复验证。

### 后续版本

1. 仅在真实程序和业务量支持后引入自动关闭建议、自动迟到事实分类或批量自动续办；最终决定是否允许自动形成仍需独立授权依据。
2. 多级关闭/重开审批、复杂跨来源授权合并、跨案件责任批量承接和长期归档策略。
3. 任何增强都不得退化为可手工修改的 `closed` 字段，或形成一个跨监管、物流、资金与结算的总完成状态。

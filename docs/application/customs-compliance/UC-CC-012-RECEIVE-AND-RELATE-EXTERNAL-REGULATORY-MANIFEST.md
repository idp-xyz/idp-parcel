# UC-CC-012 接收并关联承运商外部监管舱单

状态：开发基线已形成；首发出口和进口监管舱单均由承运商形成并提交，本产品只接收外部引用、版本、范围、关系和来源事实，真实承运商责任主体、来源契约和结果语义待提供

## 目标与边界

本用例从承运商或其受控传输来源提供一项监管舱单外部引用、版本、范围或更正关系开始，到 `customs-compliance` 对该来源形成已接受外部监管舱单引用及明确关联，或者形成待关联、解释未决、冲突、未受理或技术未形成为止。

首发出口和进口监管舱单均由承运商在外部形成并向监管渠道提交。`idp-parcel` 不建立本地监管舱单草稿、提交版本或提交尝试，也不代表承运商更正、撤销、替代或再次提交。

本用例包含：

- 识别当前监管程序中承担监管舱单形成与提交责任的承运商角色、来源身份和适用范围；不能从签约方、渠道品牌、代理商或实际承运商身份自动推导。
- 保全承运商提供的外部监管舱单身份、版本、形成/提交来源事实、监管程序、方向、适用范围、业务时间和更正/替代关系。
- 将外部监管舱单引用与明确出口或进口关务案件、申报单元、运输总单、运输舱单、班次或载运对象建立可追溯关系；这些对象继续保持独立身份。
- 区分承运商报告的已形成、已提交与监管机构已经接收、业务受理或形成监管决定；只有合格来源证明对应监管层次时，才交给 [UC-CC-006](./UC-CC-006-RECEIVE-AND-RECONCILE-EXTERNAL-RESULTS.md) 形成相应外部监管事实。
- 保存外部舱单更正、撤销、替代、范围扩大或缩小的来源历史和当前采用关系，不覆盖原引用、原成员范围或既有监管与物流事实。
- 处理重复、同身份不同内容、来源乱序、先到引用、迟到更正、部分范围、跨客户范围、关联修正、批量部分成功、越权和发布恢复。

本用例不执行：

- 组建、编辑、确认或冻结监管舱单内容，不生成本地监管舱单提交版本、提交授权或提交尝试。
- 代表承运商向监管渠道提交、查询、催办、撤销、更正、替代或再次发送监管舱单。
- 把运输舱单复制、改名或转换为监管舱单；运输舱单继续由 `transport-fulfillment` 拥有。
- 因承运商报告已提交而形成监管接收、业务受理、查验、税费、放行或处置结果；这些结果必须由 `UC-CC-006` 按来源权威解释。
- 因监管舱单成员关系推定实际装载、交接、移动、客户合报资格、申报单元组成或客户可见范围。
- 修改关务案件、申报单元、运输总单、运输舱单、班次、包裹身份、实际装载或运输事实。

外部监管舱单引用是本产品对承运商外部业务对象的受控引用及关系判断，不是本产品拥有的监管舱单。引用已接受不表示承运商已经提交，更不表示监管机构已经接收、受理或放行。

## 启动条件

- 首发出口和进口监管舱单的外部形成与提交责任已经确认为承运商；具体责任承运商、适用程序和来源资格分别由 `PAR-CUS-01/02/03` 登记。
- 来源必须能够证明其代表该承运商或其受控传输路径，并提供可保全的外部业务身份或来源引用；登录成功、文件名、邮件主题或人工备注不能单独证明来源资格。
- 外部舱单必须至少能够识别监管程序、进出口方向和候选适用范围。无法确定这些业务边界时可以保全来源，但不能形成已接受引用。
- 运输总单、运输舱单、班次或载运对象可以尚未投影可见；来源先到时保留待关联，不创建占位运输对象或关务案件。
- 承运商关系、渠道或实际承运商后续变化不覆盖外部舱单形成时的责任来源；每个新版本按其业务适用时间和当时有效责任重新判断。

## 结果语义契约

| 结果 | 成立条件 | 必须保留 | 明确不表示 |
|---|---|---|---|
| 外部监管舱单引用已接受 | 来源资格、外部身份、程序、方向、版本或稳定变更关系及最小范围均可确定 | 来源、外部身份/版本、责任承运商、程序、方向、范围、业务时间、接受判断和关联 | 本产品形成或提交；监管已接收、受理或放行 |
| 外部监管舱单已关联 | 已接受引用能与明确关务和运输对象逐范围唯一关联 | 引用、对象、关联范围、依据、决定方式和时间 | 这些对象身份相同；舱单成员已装载或合报资格成立 |
| 外部监管舱单待关联 | 来源合格，但当前不能唯一关联关务案件、运输对象或范围 | 来源、外部身份、候选关系、缺口和续办入口 | 可以按最近客户、班次或运输舱单猜测 |
| 外部监管舱单解释未决 | 来源角色、身份、版本、程序、方向、范围、形成/提交语义或变更关系无法权威解释 | 原始来源、已知语义、缺口、影响范围和复核入口 | 已提交、已撤销、已替代或已失败 |
| 外部监管舱单冲突 | 同一来源身份/版本内容冲突，或合格来源关系无法裁决 | 全部冲突来源、原判断、候选范围和复核入口 | 允许最后到达覆盖或选择范围更大的来源 |
| 外部监管舱单来源未受理 | 来源、责任承运商、租户、法人、程序、方向或访问范围不合法 | 最小安全证据、拒绝依据和时间 | 可泄露候选客户、案件、运输对象或舱单内容 |
| 外部监管舱单结果未形成 | 来源已安全保全，但业务结果提交因技术原因未完成 | 来源记录、失败阶段、已完成步骤和恢复引用 | 业务待关联、业务未决或承运商提交失败 |
| 批量逐项结果 | 同一来源信封包含多个外部舱单、版本或范围 | 每项分别形成接受、关联、未决、冲突、未受理或未形成 | 整批成功代表每项监管成功 |

## 关联、版本与结果分层规则

- 外部舱单身份必须来自责任承运商认可的稳定业务身份。运输舱单号、总单号、班次号或本产品内部编号只有在真实来源规则明确时才能作为关联依据，不能默认等同外部监管舱单号。
- 关联必须同时满足程序、进出口方向、责任承运商、适用时间和明确范围。只有一个候选客户、班次或运输舱单不构成充分依据。
- 一个外部监管舱单可以合法关联多个关务案件、申报单元、客户或运输对象，但每个关系必须保存明确范围；跨客户共同舱单不得形成共享客户可见内容或混合结算责任。
- 同一来源身份和版本携带相同内容重复到达时返回已有结果；携带不同内容时形成来源冲突。来源明确声明更正或替代时形成新版本和关系，不覆盖旧版本。
- 更正、撤销或替代只改变其明确覆盖的引用和关系。未覆盖范围及其他独立外部舱单继续有效，已经发生的申报、监管、装载、交接和移动事实不被删除或回退。
- 承运商报告已形成只证明其源业务对象形成；报告已提交只证明承运商声明已经向外发送。监管接收、业务受理、查验、税费、放行和处置必须由 `UC-CC-006` 依据对应结果层的合格来源形成。
- 如果承运商传递可验证的监管回执或决定，本用例先形成或定位外部舱单引用，再将来源结果交给 `UC-CC-006`；两边提交边界独立，任一失败不得让另一边伪装成功。
- 外部舱单成员、运输舱单成员、装载分配和实际装载分别存在。差异可以被比较和交接处理，但任何一层不得反向覆盖另一层历史。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 | 权威依据 |
|---|---|---|---|---|
| 1 | 承运商来源接入 | 校验最小来源安全边界并保全来源身份、原始业务语义和时间 | 不合格来源未受理；合格来源进入解释 | `ADR-SCOPE`、`ADR-FACT` |
| 2 | `customs-compliance` | 校验当前程序、方向、责任承运商角色和来源资格 | 资格不明保持未决；不从运输角色自动推导 | `PC-ROLE`、`CC-RULE` |
| 3 | `customs-compliance` | 识别外部身份、源版本、相同重复、同身份冲突或明确更正/替代关系 | 重复返回已有；冲突保留；变化建立版本关系 | `CC-RULE`、`ADR-FACT` |
| 4 | `customs-compliance` | 解释承运商已形成、已提交、已更正、已撤销或已替代等来源语义 | 只形成来源明确表达的层次，不制造监管结果 | `CC-LANG`、`CC-RULE` |
| 5 | `customs-compliance` | 按程序、方向、时间和明确范围匹配关务案件及申报单元 | 唯一合法关系成立；否则待关联或冲突 | `CC-RULE`、`ADR-SCOPE` |
| 6 | `customs-compliance` / `transport-fulfillment` | 读取运输总单、运输舱单、班次、载运对象和版本，形成逐范围关系判断 | 只保存稳定引用；不复制或修改运输对象 | `TF-MANIFEST`、`ADR-FACT` |
| 7 | `customs-compliance` | 形成已接受外部引用、业务关联和当前采用关系，提交审计与发布意图 | 发布失败只恢复同一结果，不要求承运商换标识重报 | `CC-LIFE`、`ADR-FACT` |
| 8 | `UC-CC-006` | 对来源中另行携带的监管回执或决定按权威层次接收和解释 | 形成独立外部监管事实；不修改外部舱单来源历史 | `CC-RESULT` |

批量信封逐外部舱单、逐版本和逐范围执行步骤 2 至 8。一项未决、冲突、未受理或技术未形成不回滚其他已经合法形成的引用和关系，批量汇总没有监管事实效力。

## 最小业务提交边界

- 来源记录、责任承运商依据、外部身份/版本、程序、方向、明确范围、变更关系、接受判断、关务/运输关联、当前采用关系、审计和发布意图必须形成可恢复的受保护业务结果。
- 来源已经保全但关联处理失败时，从同一来源记录恢复，不要求承运商换外部身份重发，也不创建本地监管舱单或提交尝试。
- 引用和关系已形成但发布失败时，只重试同一发布意图；不得重复形成引用、重放承运商提交或重复触发监管结果处理。
- 外部监管结果由 `UC-CC-006` 独立提交。引用形成成功、结果处理失败或相反情况均保留各自事实和恢复入口，不使用跨用例总状态覆盖。

## 一致性、幂等与并发

- 同一来源、外部身份、版本和内容重复到达时返回已有结果；同一来源身份/版本携带不同内容形成冲突。
- 来源先于关务或运输对象投影到达时保持待关联；对象可见后继续同一关联请求，不创建第二外部引用。
- 更正、替代、撤销和原版本乱序到达时全部保留，当前采用关系由来源版本、业务适用时间和明确变更关系派生，不按接收顺序决定。
- 外部舱单范围与运输舱单、实际装载或关务案件范围并发变化时，各所有者先保存自身事实，再形成新的关系或差异判断；不锁定或回写源对象。
- 关联修正必须保留原关系、错误依据、修正原因、决定方和生效时间；不得静默移动到另一个客户、案件或运输对象。
- 同一外部舱单被多个客户或案件并发认领但缺少明确范围时保持关联冲突，不以先到请求取得全部范围。

## 权限、隔离与审计

- 来源接入、来源解释、人工关联、关联修正和结果导出分别授权；系统管理员、运输编辑或关务提交权限不能自动取得人工关联权限。
- 承运商来源只能作用于其被授权的法人、程序、方向、客户和运输范围。越权来源未受理且不得确认候选对象是否存在。
- 跨客户外部舱单允许在内部保存共同引用，但每个客户的包裹、申报范围、异常披露和结算责任必须隔离；共享视图不得暴露其他客户身份和内容。
- 审计至少关联来源、外部身份/版本、责任承运商、程序、方向、范围、变更关系、接受判断、关务/运输关联、人工决定、业务时间和记录时间。
- 日志和错误保持最小披露，不记录不必要的寄收件、货物、监管原因或其他客户内容。

## 首发试点约束

- 首发出口和进口均只启用承运商外部形成与提交模式，不实现本地监管舱单草稿、授权、提交、查询或再次发送。
- 正常生产必须验证一个真实外部监管舱单引用、来源版本、关务/运输关联及至少一种实际来源结果；具体承运商、程序、渠道和范围由 `PAR-CUS-01/02/03` 与 `PAR-INT-03` 提供。
- 更正、替代、范围冲突、跨客户共同舱单和乱序分支未自然发生时使用 `R/S`；不得为了验收向生产监管渠道提交虚假舱单或制造错舱单。
- 真实来源未确认前，不预设外部标识格式、版本号规则、成员粒度、查询能力、结果代码、等待窗口、重试次数或自动关联阈值。

## 验收示例

| 编号 | Given / When | Then |
|---|---|---|
| `AT-CC-376` | 首发出口程序收到责任承运商提供的外部监管舱单身份、版本、程序、方向和明确范围 | 形成已接受外部监管舱单引用及来源关系；不创建本地舱单、提交版本或尝试 |
| `AT-CC-377` | 首发进口程序收到同类合格来源 | 按独立进口程序形成引用和关系；不沿用出口案件、来源或结果解释 |
| `AT-CC-378` | 运输舱单和外部监管舱单使用相同外部文本标识 | 仍保留两个业务身份并建立关系；不合并对象或生命周期 |
| `AT-CC-379` | 来源只提供一个外部编号，但程序、方向或范围不足 | 保全来源并形成解释未决；不按唯一客户或最近班次猜测 |
| `AT-CC-380` | 外部引用可唯一关联一个关务案件、申报单元和运输范围 | 形成逐对象、逐范围关系并保留依据；不修改任何源对象 |
| `AT-CC-381` | 同一外部引用可能关联两个客户或两个班次且无明确范围 | 形成待关联或冲突，不以先到请求取得全部范围 |
| `AT-CC-382` | 外部监管舱单列入 P1，但尚无实际装载或交接事实 | 只形成舱单成员关系；不推定 P1 已装载、已交接或已运输 |
| `AT-CC-383` | 承运商报告外部监管舱单已形成 | 只保存承运商形成事实；不形成已提交、监管接收或业务受理 |
| `AT-CC-384` | 承运商报告已向监管渠道提交 | 保存承运商提交来源事实；不推定监管机构已经接收或受理 |
| `AT-CC-385` | 承运商同时传递来源可验证的监管接收结果 | 先关联外部引用，再交给 `UC-CC-006` 独立形成监管接收事实 |
| `AT-CC-386` | 只有承运商页面文案或人工备注声称监管已受理 | 不提升为监管事实；按来源真实权威层次保持报告或未决 |
| `AT-CC-387` | 同一来源身份、版本和内容重复到达 | 返回已有引用、关系和当前结果，不重复发布或触发下游 |
| `AT-CC-388` | 同一来源身份和版本携带不同内容 | 形成来源冲突并保留两份内容；不按最后到达覆盖 |
| `AT-CC-389` | 承运商明确提供 V2 更正 V1 | 形成新版本和更正关系，保留 V1、原范围和原结果历史 |
| `AT-CC-390` | V2 只更正 P2 范围 | 只调整 P2 当前采用关系，其他未覆盖范围保持原版本关系 |
| `AT-CC-391` | 承运商明确撤销 V1 | 保存撤销来源事实并结束适用关系；不删除 V1 或回退既有监管、装载和运输事实 |
| `AT-CC-392` | V2 明确替代 V1，但 V1 的监管结果迟到 | 两个版本及迟到结果均保留，按来源、适用时间和替代关系判断；不丢弃迟到事实 |
| `AT-CC-393` | 同一外部监管舱单覆盖 C1/P1 与 C2/P2 | 允许共同内部引用，但逐客户范围和可见内容隔离，不混合合同或结算责任 |
| `AT-CC-394` | 当前签约方、渠道品牌、代理商和实际承运商身份不同 | 只采用 `PAR-CUS-01/02/03` 登记的舱单责任承运商，不自动选择任一其他角色 |
| `AT-CC-395` | 技术中介代表责任承运商传输来源 | 保存实际责任承运商和传输来源两个角色；中介不因传输取得舱单形成责任 |
| `AT-CC-396` | 承运商关系在舱单形成后发生变化 | 历史引用继续保存形成时责任依据；新版本按其适用时间重新校验 |
| `AT-CC-397` | 来源先到，关务案件或运输舱单尚未可见 | 来源保持待关联；对象可见后续办同一记录，不创建占位或第二引用 |
| `AT-CC-398` | 人工发现原关联错误并具有修正权限和充分证据 | 保留原关系及错误依据，形成新的有效关联；不静默覆盖历史 |
| `AT-CC-399` | 无权用户尝试把引用关联到其他客户案件 | 未受理且不泄露候选对象；原引用和关系不变 |
| `AT-CC-400` | 一个批量来源中部分舱单合法、部分未决或冲突 | 逐项返回结果，已合法引用不回滚，批量汇总不形成监管结果 |
| `AT-CC-401` | 外部舱单范围与运输舱单范围不同 | 保留两层范围并形成差异/复核入口；不修改任一舱单成员历史 |
| `AT-CC-402` | 实际装载与两个舱单范围均不同 | 实际装载继续由物流所有者保存；本用例不以任一舱单覆盖实装事实 |
| `AT-CC-403` | 关务案件已关闭后收到外部舱单更正 | 先保存更正和关系，再由 `UC-CC-010` 判断是否受控重开或建立后续案件 |
| `AT-CC-404` | 承运商无法提供查询能力或当前状态 | 不推定未形成、未提交或已失败，也不由本产品发起本地再次发送 |
| `AT-CC-405` | 操作员尝试编辑外部舱单内容或点击本地提交 | 拒绝本地形成/提交路径；只能保存合格外部来源和授权关联决定 |
| `AT-CC-406` | 为关联外部结果而尝试创建占位提交版本或提交尝试 | 不允许；外部引用通过本用例形成，监管结果通过 `UC-CC-006` 关联该引用 |
| `AT-CC-407` | 引用和关系提交成功，但发布首次失败 | 业务结果保持有效，只恢复同一发布意图，不重复接收或要求承运商重报 |
| `AT-CC-408` | 来源已保全，但关联结果技术提交失败 | 返回未形成及恢复引用，不伪装成业务待关联、业务未决或承运商提交失败 |
| `AT-CC-409` | 来源属于未授权法人、程序、方向或客户范围 | 来源未受理并最小披露；不读取或确认越权对象 |
| `AT-CC-410` | 检查本用例直接形成或修改的对象 | 只形成来源接受、外部监管舱单引用、版本/变更关系、业务关联和当前采用关系；不形成本地监管舱单、提交尝试、监管结果或物流事实 |

## 生产参数与待决风险

| 参数 | 待提供内容 | 未提供时的处理 |
|---|---|---|
| `PAR-CUS-01` | 出口舱单责任承运商、程序、外部身份/版本、范围、形成/提交语义、更正/替代及结果来源 | 出口外部引用保持未配置，不建立本地形成路径 |
| `PAR-CUS-02` | 进口舱单责任承运商、程序及与出口独立的同类语义 | 进口外部引用保持未配置，不从出口规则推导 |
| `PAR-CUS-03` | 来源接收、人工关联、关联修正、结果解释和导出权限 | 未授权操作未受理，不能用管理员默认权限 |
| `PAR-CUS-05` | 重复、冲突、乱序、更正、替代、跨客户和部分范围的回放/模拟证据 | 复杂分支不得宣称生产就绪 |
| `PAR-INT-03` | 承运商外部监管舱单及相关结果的主要生产来源和能力 | 不预设接口、文件、门户或人工入口 |
| `PAR-NFR-06` | 来源新鲜度、批量、积压和恢复目标 | 不预设等待窗口、重试次数或性能承诺 |

完成本用例只证明本产品能够安全引用和关联承运商外部形成的监管舱单。承运商仍拥有形成与提交责任，监管机构仍拥有监管决定，运输履约仍拥有运输舱单和实际物流事实。

# UC-CC-009 核对税费付款、代垫回收与放行门禁

状态：开发基线草案；监管税费、外部付款、客户代垫回收和放行结果的所有权边界已确认，真实程序的付款条件、关联规则、回收条件和放行门禁参数待提供

## 目标与边界

本用例从 `UC-CC-006` 已接受、已关联且范围明确的监管核定税费，或真实程序明确形成的当前范围无需付款依据开始，接收银行、支付或财务系统拥有的外部资金事实引用，形成税费付款协作事项、逐范围税费付款核对和绑定拟执行动作的放行门禁核对，并把付款方、税费、付款核对和合同责任输入交给 `settlement-accounting` 独立判断实际代垫及客户代垫回收。后续监管放行、监管更正、监管补缴要求或监管税费退回决定仍由 `UC-CC-006` 接收；追加付款、资金退回、付款撤销或外部资金事实更正由资金事实来源形成。本用例分别回接这些结果，或者明确保持付款条件未决、待付款、外部资金待关联、覆盖/差额/有效性待核对、客户回收输入交接待确认、门禁未满足、门禁待确认、未受理或未形成结果。

本用例包含：

- 固定监管核定税费版本，或明确的当前范围无需付款依据，以及申报范围、法定义务、适用时间和真实程序要求的付款条件；没有税费结果不能被解释为无需付款，不用一个“应付税费”覆盖后续更正。
- 形成范围明确的税费付款协作事项和责任交接目标，但不生成银行支付指令、支付交易或实际付款结果。
- 接收实际付款、付款失败、部分付款、追加付款、资金退回、付款撤销或外部资金事实更正等来源事实引用，并按真实程序和明确范围形成税费付款核对；监管补缴要求和监管税费退回决定仍作为监管外部结果接收。
- 区分法定义务人、实际付款方、运营责任法人和最终承担费用的客户；任何角色都不从企业类型、合同相对方或付款账号自动推导。
- 把付款方、监管核定、外部资金事实引用、付款核对和合同责任输入交给 `settlement-accounting`，由 `UC-SA-001` 独立确认实际代垫是否成立，再决定客户代垫回收；关务服务费用由 `parcel-pricing` 依据销售价格依据形成纯评价，再由 `settlement-accounting` 采用独立费用项目形成，不因代垫成立自动生成。
- 分别判断当前范围是否需要付款，以及付款是否构成当前拟执行动作的放行前置条件；仍需付款但不阻断当前动作时，付款义务继续保留。
- 按当前监管程序、拟执行动作、适用监管边界、税费付款核对、关务限制、监管处置和其他前置条件形成逐范围放行门禁核对；门禁满足不生成监管放行，也不能复用于其他动作或监管边界。
- 关联 `UC-CC-006` 已接受的税费更正、部分放行、监管补缴要求或监管税费退回决定，并处理追加付款、资金退回、付款撤销、迟到付款、重复付款、来源冲突、案件关闭后事实和并发变化，保留全部版本和原事实。

本用例不执行：

- 接收或解释原始监管响应；监管核定税费、放行、监管补缴要求、监管税费退回决定和来源更正仍由 [UC-CC-006](./UC-CC-006-RECEIVE-AND-RECONCILE-EXTERNAL-RESULTS.md) 接收并分层形成。
- 发起、授权、撤销或重试银行、支付或财务系统的真实付款；这些系统拥有实际付款、付款失败、追加付款、资金退回、付款撤销、外部资金事实更正和清算事实。
- 直接形成客户代垫回收、报关服务费、客户收款、核销、发票、法定税额、会计应收或总账结果；运营金额由 `settlement-accounting` 拥有。
- 形成监管放行、解除监管限制或内部合规限制、关闭或重开关务案件；本用例只能形成放行前置条件的内部核对和后续交接。付款覆盖或门禁满足不能代替 `UC-CC-011` 的来源解除决定。
- 直接放货、出库、装载出发、跨关务区域移动或交付；节点和运输履约只消费与当前对象、拟执行动作和监管边界匹配的门禁与外部监管结果。
- 用客户预收、运营余额、付款申请、付款页面、银行待处理状态、结算回收或异常关闭替代实际付款事实或监管放行。

税费付款协作只是关务侧对监管税费义务、付款事实和放行前置条件的受控关联。监管核定、实际付款、客户代垫回收、放行门禁核对和外部监管放行必须分别保留。

## 七层对象必须分离

| 层次 | 对象/结果 | 本用例职责 | 不得推导 |
|---|---|---|---|
| 监管税费 | 已接受监管核定税费、法定义务及版本 | 只读引用当前有效版本、明确范围和更正关系 | 不得由付款金额或客户合同反推监管核定 |
| 付款协作 | 税费付款协作事项、责任交接目标和付款要求依据 | 形成范围化核对入口并保存当前责任安排 | 不等于支付指令、付款交易或资金清算 |
| 外部资金事实 | 实际付款、付款失败、部分付款、追加付款、资金退回、付款撤销或外部资金事实更正 | 接收合格来源引用并保留来源语义 | 不得由付款申请、客户预收或运营余额制造 |
| 关务付款判断 | 税费付款核对及逐范围覆盖、缺口、冲突和失效 | 按真实程序比较监管核定与外部资金事实 | 不得修改监管核定或外部资金事实 |
| 运营回收 | 客户代垫回收、服务费用、调整、客户收款和核销 | 向 `settlement-accounting` 交接责任依据并接收稳定结果引用 | 不得由关务直接形成或用净额覆盖原税费/付款 |
| 放行门禁判断 | 绑定申报范围、拟执行动作和监管边界的放行门禁核对，并消费 `UC-CC-011` 的当前限制判断 | 形成当前动作的内部前置条件判断并等待 `UC-CC-006` 外部结果 | 门禁满足不得生成放行、解除限制或复用于其他动作 |
| 外部监管结果 | `UC-CC-006` 已接受的监管放行、更正或其他结果引用 | 只读关联外部结果并更新本地门禁关系 | 不得由本用例修改外部结果或反推付款/回收 |

同一页面可以展示七层关系，但不得维护一个“税费状态”或“清关状态”覆盖它们。监管核定增加、付款已覆盖、客户已经偿还和监管已经放行是四个不同结论。

## 启动条件

- 当前税费义务依据已经唯一关联关务案件/申报范围：要么是 `UC-CC-006` 已接受且保存法定义务人、币种、金额、版本、业务适用时间和当前有效性的监管核定税费，要么是真实程序对当前范围明确形成的无需付款依据。没有税费消息或缺少结果不得解释为无需付款。
- 真实程序是否要求付款、付款是否构成当前拟执行动作的放行前置条件、允许的付款人/范围/币种及覆盖判断规则分别来自登记依据；无法确定时可以形成未决协作事项，但不得假设统一“先税后放”或“先放后税”。
- 实际付款事实来自银行、支付、财务或真实程序认可的合格来源，并保留来源身份、外部业务引用、付款人、金额、币种、业务时间和当前有效性。来源未提供且程序不要求的维度明确记录为未提供；程序要求而来源未提供时核对保持未决；程序尚未登记是否要求时核对不进行——见 CONTEXT Rules「税费、放行与案件闭环」段（`CC-RULE`）。
- 客户合同、运营责任法人、法定义务人、实际付款方和最终承担费用的客户可以逐项关联；无法关联时不形成客户代垫回收或跨客户金额分配。
- 付款事实无法关联当前监管税费时只形成待关联或冲突，不按相同金额、同一客户、同一包裹、最近时间或人工选择直接认定覆盖。
- 缺少监管核定税费且没有明确无需付款依据，而只有付款页面、客户预收、付款申请或银行待处理状态时，不形成当前税费付款覆盖或放行门禁满足。已有明确无需付款依据时，只能跳过当前付款条件，其他门禁仍独立核对。
- 关务付款核对、客户回收输入交接、门禁核对和外部结果接收分别授权；拥有付款账号、结算权限或节点出库权限不能互相推导。

|---|---|---|---|

| 付款义务与门禁关系规则 | `customs-compliance` 适用规则 | 当前范围是否需要付款、付款是否参与当前拟执行动作的门禁，以及允许范围/付款人/币种和覆盖条件 | 两项判断分别形成；未登记时保持未决，不使用全局默认顺序 |

| 外部资金事实 | 银行/支付/财务或程序认可来源 | 来源身份、外部业务引用、付款人、金额、币种、业务时间、当前有效性和来源结果语义 | 付款申请、技术受理或页面状态不冒充资金事实 |
| 付款关联依据 | 当前程序/外部来源 | 税费身份、付款引用、申报或法定义务范围、分配关系和有效时间 | 金额相等不能单独作为关联；无权威依据时待关联 |
| 客户回收输入 | `party-commercial` / `customs-compliance` / 外部资金系统 | 合同责任、付款方、税费和付款核对引用、责任法人、客户账户、结算账户、币种和确认条件 | 由结算确认实际代垫是否成立并独立决定回收金额与生命周期；关务不形成代垫依据 |
| 当前放行前置条件 | `customs-compliance` | 申报范围、拟执行动作、监管边界、付款条件、限制、监管处置、资料义务和其他真实程序要求的当前判断 | 逐条件、逐范围、逐动作保存；未登记条件不臆造为满足，也不复用其他动作的结论 |
| 外部放行与更正 | `UC-CC-006` | 放行结果、明确范围、条件、来源、适用时间和当前有效性 | 外部结果只读引用；本用例不得制造或覆盖 |
| 既有核对历史 | `customs-compliance` | 协作事项、外部资金事实引用、付款核对、门禁版本、客户回收输入交接和差异 | 防止重复关联、重复客户回收输入交接和覆盖历史 |
| 客户隔离范围 | `ADR-SCOPE` | 集团租户、责任法人、客户账户、案件、申报和逐包裹范围 | 合报时仍逐客户、逐包裹保存税费和责任范围 |

## 结果语义契约

| 结果 | 业务含义 | 必须返回或可查询的依据 | 禁止行为 |
|---|---|---|---|
| 税费付款协作事项已形成 | 当前税费义务依据已形成范围化付款核对入口 | 税费版本或明确无需付款依据、法定义务范围、付款要求来源、责任交接目标和版本 | 不得生成支付指令、外部资金事实或客户回收 |
| 当前范围无需付款 | 监管税费结果或真实程序规则明确当前范围没有需要履行的付款 | 税费结果或规则依据、范围、适用时间、判断时间和责任角色 | 不得由“没有税费消息”推导，也不得解释为其他门禁已满足、已经放行或客户合同责任不存在 |
| 待付款 | 当前范围需要付款，但尚无可关联的合格实际付款事实 | 税费版本、待付范围、金额/币种、责任目标和续办入口 | 不得用付款申请、客户预收或运营余额标记已付 |
| 外部资金事实已接收 | 合格来源提供了实际付款、付款失败、追加付款、资金退回、付款撤销或外部资金事实更正 | 来源、外部引用、结果语义、付款人、金额、币种、业务时间和有效性 | 不得直接推导税费已覆盖、客户已回收或已经放行 |
| 外部资金事实待关联 | 外部资金事实存在，但不能权威关联到明确税费版本和范围 | 外部资金事实、候选范围、缺口、冲突和核实入口 | 不得仅按金额、客户、包裹或到达顺序自动匹配 |
| 税费付款核对无覆盖 | 当前税费版本要求的付款范围没有得到适用外部资金事实覆盖 | 未覆盖范围、税费版本、已检查的外部资金事实和核对版本 | 不得把存在付款事实、错误币种或错误范围解释为已经覆盖 |
| 税费付款核对部分覆盖 | 只有部分税费金额或范围得到合格付款事实覆盖 | 已覆盖范围、剩余范围、税费版本、付款事实和核对版本 | 不得把部分覆盖汇总为已覆盖或自动扩大付款分配 |
| 税费付款核对已覆盖 | 当前税费版本要求的付款范围已有适用付款事实覆盖 | 税费版本、付款事实、关联依据、逐范围金额/币种和核对版本 | 不得生成监管放行、客户回收或其他限制解除 |
| 税费付款差额不足 | 可关联付款事实低于当前要求或遗漏必须范围；覆盖状态可同时为部分覆盖或已覆盖 | 已付、应付、缺口、币种、范围和续办入口 | 不得截断监管核定、制造监管补缴或释放门禁 |
| 税费付款差额超额 | 可关联付款事实超过当前税费要求；覆盖状态可同时为已覆盖 | 税费、付款、超额范围、来源和核实/资金退回入口 | 不得把超额覆盖其他税费、客户或案件 |
| 税费付款冲突 | 合格来源、付款关联、付款人、币种、金额或有效性相互矛盾且无法裁决 | 全部冲突事实、冲突前判断、影响范围和复核入口 | 不得按最后到达、人工偏好或有利结果覆盖 |
| 税费付款覆盖失效 | 已参与核对的付款在全部或部分范围被资金退回、付款撤销、外部资金更正或证明不再适用 | 原付款、失效事实、受影响范围、原核对和新判断 | 不得删除原付款或静默维持受影响范围的已覆盖判断 |
| 客户回收输入已交接 | 结算已接收付款方、税费、外部资金事实、付款核对和合同责任输入 | 税费/付款引用、付款方、客户责任、责任法人、结算目标和交接结果 | 不得表示实际代垫、客户代垫回收、收款或核销已经形成 |
| 付款不构成当前动作前置条件 | 真实程序明确付款即使尚未完成，也不阻断当前拟执行动作 | 程序规则、申报范围、拟执行动作、监管边界、判断时间和责任角色 | 不得解释为无需付款、其他动作可继续、其他门禁已满足或监管已经放行 |
| 放行门禁待满足 | 当前对象、拟执行动作和监管边界的一个或多个真实前置条件尚未满足 | 当前条件、未满足范围、拟执行动作、监管边界、来源、续办入口和核对版本 | 不得生成放行、扩大到未覆盖对象或阻断无关动作 |
| 放行门禁已满足 | 当前程序要求的内部前置条件对明确范围和拟执行动作已满足 | 税费付款核对、其他条件判断、范围、拟执行动作、监管边界、规则和版本 | 只可进入外部结果等待/复核；不得生成监管放行或复用于其他动作 |
| 放行门禁冲突或待确认 | 当前对象、拟执行动作和监管边界的条件事实相互冲突、来源未决或无法形成权威判断 | 全部条件事实、冲突、范围、拟执行动作、监管边界、最后可确认边界和复核入口 | 不得按最宽松结果放行、按最严格结果改写来源事实或扩大到其他动作 |
| 外部放行结果已回接 | `UC-CC-006` 已接受明确范围的监管放行或更正 | 外部结果、范围、条件、适用时间、门禁版本和关系 | 不得覆盖付款、回收、限制或物流事实 |
| 当前事项无需继续 | 当前税费或付款要求被权威取消/替代，或范围已明确移除 | 新旧结果、范围、适用时间、未处理范围和关系 | 不得删除已发生付款、核对或回收历史 |
| 未受理 | 请求主体、租户、法人、客户、案件、税费、付款事实或权限不能合法关联 | 最小校验证据、原因、时间和责任交接 | 不得读取或泄露越权税费、付款或客户金额 |
| 未形成税费/门禁核对 | 技术处理未完成，无法安全形成协作事项或判断 | 请求、失败阶段、已采用输入、已有结果和恢复引用 | 不得伪装成待付款、付款失败、门禁未满足或已放行 |

`外部资金事实已接收`是外部资金来源事实的接收结果；税费付款核对同时包含覆盖状态（无覆盖、部分覆盖、已覆盖）、差额状态（无差额、不足、超额或待确认）和有效性状态（有效、失效、冲突或待确认），三个维度不能实现为互斥总状态。实际代垫成立判断和客户代垫回收属于结算结果；`外部放行结果已回接`仍是监管外部结果。这些结果不能互换。

## 税费付款与放行核对规则

- 税费核定版本、监管补缴要求、监管税费退回决定、外部资金事实、付款关联、税费付款核对、客户代垫回收和放行结果分别追加保存。各自的更正、资金退回、付款撤销和客户代垫回收调整只能形成新版本和关系，不能覆盖原税费、原付款或原回收。
- 一个税费版本可以由零个、一个或多个付款事实覆盖；一个付款事实只有在真实程序及来源关联允许时才可以分配到一个或多个税费范围。任何多对多关系必须保存逐范围金额、币种和依据。
- 付款金额相同、付款人在案件角色中出现、同一客户、同一包裹、同一申报单元、最近业务时间或人工选中都不能单独构成权威关联。
- 付款申请、技术受理、银行待处理、账户扣款通知、监管收讫确认和最终清算可以是不同来源层。只有真实程序认可的结果层才能参与相应税费付款核对，前一层成功不自动生成后一层事实。
- 监管补缴要求和监管税费退回决定作为监管外部事实分别保留；部分付款、付款失败、追加付款、资金退回、付款撤销、超额、错误币种、错误范围、重复付款和外部资金事实更正作为资金来源事实分别保留。不得把它们压缩成“已缴/未缴”或用当前余额覆盖历史。
- 法定义务人、实际付款方、运营责任法人和最终承担费用的客户分别记录。运营企业实际付款不自动证明客户应偿还；客户直接付款也不改变法定义务人或生成运营企业代垫回收。
- `settlement-accounting` 依据付款方、外部资金事实、关务税费及付款核对和有效合同责任确认运营企业是否实际代垫，再决定客户代垫回收。回收可以晚于税费核定或付款核对，回收失败、部分回收、客户收款和核销都不改变监管税费或放行门禁。
- 放行门禁只检查真实程序对当前申报范围、拟执行动作和监管边界明确要求的条件。付款义务与付款是否构成当前动作的前置条件分别判断；门禁已满足只说明该动作的内部已知条件具备，不表示监管机构已经放行，也不能复用于其他动作。
- 已接受外部放行与本地门禁判断不一致时，两者都保留并形成差异/复核，不得删除放行结果、伪造付款或绕过仍有效的其他限制。
- 税费、付款或放行事实迟到时，按业务发生时间、适用时间、当前有效性和更正关系形成新核对版本；不得按消息到达顺序覆盖。
- 案件关闭后事实仍属于原监管程序时，交由 [UC-CC-010](./UC-CC-010-CLOSE-REOPEN-AND-ESTABLISH-FOLLOW-UP-CASE.md) 依据原关闭决定、逐项原关闭责任来源和当前授权决定受控重开；形成独立补税、稽核、申诉或其他义务时建立后续案件。本用例不自行重开或建案。
- 受控跨客户合报可以共享监管申报范围，但税费、付款分配、客户责任、回收和可见范围必须逐客户成员保留；汇总付款不得把一方金额自动覆盖另一方义务。

## 应用流程

| 步骤 | 责任方 | 应用动作 | 结果与下一步 | 权威依据 |
|---|---|---|---|---|
| 1 | 关务税费接入 | 校验请求主体、租户、法人、客户、案件、税费或付款事实身份 | 越权或无法关联时未受理；不读取越权金额 | `ADR-SCOPE` |
| 2 | `customs-compliance` / `UC-CC-006` | 确认监管核定已接受、当前有效并具有明确范围和法定义务，或确认真实程序对当前范围存在明确无需付款依据 | 待关联、解释未决或冲突时不形成付款覆盖；缺少税费消息不作为无需付款依据 | `CC-RESULT`、`CC-RULE` |
| 3 | `customs-compliance` | 识别税费更正、监管补缴要求、监管税费退回决定、取消/替代、重复请求和并发变化 | 形成当前税费义务依据及关系；不覆盖历史 | `ADR-FACT`、`CC-LIFE` |
| 4 | `customs-compliance` | 按真实程序分别确定当前范围是否需要付款，以及付款是否构成当前拟执行动作的放行前置条件 | 形成付款协作事项、无需付款、付款不构成当前动作前置条件或未决；不假设统一顺序 | `CC-RULE` |
| 5 | `customs-compliance` | 确认责任交接目标、法定义务人、实际付款安排和核对范围 | 形成范围化协作入口；不创建支付交易 | `CC-LANG`、`ADR-FIN` |
| 6 | 银行/支付/财务系统 | 形成并提供实际付款、付款失败、追加付款、资金退回、付款撤销或外部资金事实更正 | 本用例接收稳定来源引用；不复制资金所有权 | `ADR-FIN` |
| 7 | `customs-compliance` | 按税费版本、外部引用、范围、付款人、金额、币种、业务时间和真实规则关联 | 分别形成覆盖、差额和有效性三个维度；无法权威关联时保持外部资金事实待关联 | `CC-RULE`、`ADR-FACT` |
| 8 | `customs-compliance` → `settlement-accounting` | 交接付款方、监管核定、外部资金事实引用、付款核对和客户责任输入 | 结算形成自身接收结果；不由关务形成实际代垫判断或回收金额 | `SET-RULE`、`ADR-FIN` |
| 9 | `settlement-accounting` / `UC-SA-001` | 按付款方、资金事实、关务核对和合同责任确认实际代垫，再形成客户代垫回收或调整；服务费另按独立费用规则处理 | 返回稳定结果引用；不改写税费、外部资金事实或放行 | `SET-LANG`、`SET-RULE` |
| 10 | `customs-compliance` | 按申报范围、拟执行动作和监管边界汇集税费付款核对、限制、监管处置和其他真实前置条件 | 形成动作匹配的门禁待满足、已满足、冲突或待确认 | `CC-RULE` |
| 11 | `UC-CC-006` | 接收监管放行、更正或其他后续外部结果 | 本用例关联门禁与外部结果；不制造放行 | `CC-RESULT` |
| 12A | `UC-CC-010` | 对迟到或关闭后关务事实判断原案件受控重开或建立关联后续案件 | 只改变关务案件生命周期；不修改付款、门禁、放行或异常案件 | `CC-CASE`、`ADR-FACT` |

## 最小业务提交边界

- 税费付款协作事项、税费义务依据、付款义务和动作门禁关系判断、责任交接目标、外部资金事实引用、逐范围付款核对、客户回收输入交接、动作门禁核对和发布意图必须形成可恢复的受保护业务结果。
- 外部资金事实、实际代垫成立判断、客户代垫回收和外部放行由各自所有者形成；本用例只保存稳定引用、实际采用版本和核对依据，不复制或修改源事实。
- 外部资金事实已接收但核对未完成时，保留来源引用并从同一输入恢复；不得要求外部系统换业务标识重报或把技术失败改成付款失败。
- 付款核对或门禁提交成功但首次发布失败时，只重试同一发布意图；不得重复形成客户回收输入交接、重复分配付款或重复触发放行动作。
- 税费更正、付款撤销和门禁核对并发时，已形成事实继续保留；按业务时间、有效性和关系形成新的当前判断，不回滚已发生资金或物流事实。

## 一致性、幂等与并发

- 同一税费版本、范围、付款条件和协作请求重复到达时，返回已有事项、付款核对和门禁判断，不创建第二事项。
- 同一请求身份携带不同税费版本、范围、付款人、金额、币种或条件时形成请求冲突，不按最后到达覆盖。
- 同一外部资金事实通过回调、文件、查询或人工关联重复到达时，按来源身份、外部业务引用、版本和业务语义去重；不重复增加付款覆盖或客户回收输入。
- 外部资金事实迟到、更正、资金退回或付款撤销时，形成新核对版本并保留原覆盖判断；不删除原付款、不按最后到达覆盖。
- 税费更正与付款并发到达时，分别保留税费和付款事实，先建立各自有效性和关系，再形成当前核对；不得让金额恰好相等决定关联顺序。
- 一个税费范围允许多个付款事实部分覆盖；一个付款事实分配到多个税费范围必须具有真实程序或来源提供的明确分配依据。
- 同一付款事实被两个案件或客户范围并发认领时保持分配冲突或待复核；没有权威依据前不得选择一个或同时视为有效覆盖。
- 客户回收输入交接、结算结果或外部放行迟到不回写付款核对历史；只形成新的跨上下文关系和当前判断。

## 权限、隔离与审计

- 税费结果接收、付款义务判断、付款与动作门禁关系判断、外部资金事实关联、付款核对复核、客户回收输入交接、门禁核对和外部放行接收分别授权；付款账号权限、结算权限、关务权限和节点放货权限不能互相推导。
- 人工角色不能创建实际付款、把付款申请改成付款成功、把客户预收改成监管付款、把代垫回收改成监管核定，或把门禁满足改成监管放行。
- 税费、付款、核对、客户责任和门禁按集团租户、责任法人、客户账户、案件、申报范围和币种隔离；跨客户合报只披露履行当前税费义务所需共同范围。
- 审计至少关联税费身份/版本或明确无需付款依据、案件/申报/包裹范围、法定义务人、实际付款方、运营责任法人、客户责任、付款条件规则、外部资金事实、逐范围分配、核对版本、客户回收输入交接、拟执行动作、监管边界、门禁条件和外部放行结果。
- 日志和错误不记录不必要的银行账号、支付凭据、客户金额、跨客户范围或监管原因；未受理、未决和冲突保持最小披露。

## 可观测性与非功能验收占位

- 从税费义务依据、付款协作、外部资金事实、付款关联、付款核对、客户回收输入交接、动作门禁判断到外部放行具有稳定关系。
- 分别观测税费义务依据确认、付款义务判断、付款与动作门禁关系判断、外部资金事实接入、关联、核对、回收输入交接、动作门禁复核和结果回接的耗时与失败位置。
- 分别统计当前范围无需付款、付款不构成当前动作前置条件、待付款、外部资金事实待关联；覆盖状态按无覆盖/部分覆盖/已覆盖统计，差额状态按无差额/不足/超额/待确认统计，有效性状态按有效/失效/冲突/待确认统计；另统计客户回收输入交接待处理、门禁待满足/已满足/冲突/待确认、未受理和未形成，不得只统计“已缴税率”或“清关成功率”。
- 监控没有税费消息被解释为无需付款、付款申请冒充实际付款、金额相等自动关联、跨客户付款串用、部分付款覆盖全部税费、资金退回或付款撤销后受影响范围仍保持覆盖、客户回收冒充监管付款、门禁满足制造放行、跨动作复用门禁、外部放行绕过其他限制和迟到事实覆盖历史等不变量违规。
- 恢复盘点区分：税费义务依据待确认、付款义务待决、付款与动作门禁关系待决、事项待交接、外部资金事实待关联、付款核对待形成、覆盖/差额/有效性各维度待确认、客户回收输入交接待确认、动作门禁待复核、待外部放行、外部结果已回接和关系更新失败。
- 处理响应、付款事实新鲜度、外部期限提醒、批量窗口和恢复目标由真实程序、财务接入能力和 `PAR-NFR-06` 提供，不填写未经证据确认的数值。

## 首发试点约束

- 只处理 `PAR-CUS-01`、`PAR-CUS-02`、`PAR-CUS-03`、`PAR-CUS-04`、`PAR-INT-05` 和适用 `PAR-SET-*` 已登记范围内的真实税费程序、资金来源、客户合同和结算账户。
- 正常税费、真实付款和放行主链路使用生产事实验证；部分付款、监管税费退回决定、资金退回、付款撤销、重复付款、来源冲突、迟到更正和关闭后事实使用 `PAR-CUS-05` 允许的脱敏历史回放、正式测试环境或隔离模拟。
- 生产交接前必须确认税费和付款来源、结果层、外部业务引用、付款人、币种、分配语义、放行条件、客户责任和财务系统交换边界；不得以页面可见、金额相等或历史惯例代替。
- 真实程序未明确付款义务、付款与拟执行动作的门禁关系、付款覆盖结果层、监管补缴/税费退回语义、资金退回/付款撤销语义或其他放行前置规则前，可以实现事项、来源引用、范围化核对和未决骨架，但不得宣称税费已付或门禁已满足。
- 客户代垫回收只有在合同责任、责任法人、结算账户、币种和确认条件已登记，且 `settlement-accounting` 已确认实际代垫成立时才能进入生产结算；否则只保留客户回收输入交接待决，不创建虚假客户应收。

| `AT-CC-285` | 客户代垫回收后来发生客户代垫回收调整、核销撤销或坏账处理 | 结算形成追加调整或反向关系；不把客户资金变化改写为监管税费退回决定、资金退回或付款撤销 |
| `AT-CC-286` | 一笔实际付款覆盖两个税费版本或范围，来源提供明确分配 | 按明确分配形成逐范围付款核对；没有分配依据时保持外部资金事实待关联，不按比例猜测 |
| `AT-CC-287` | 合报付款涉及两个客户，但只明确 C2/P2 的付款责任和分配 | 只核对 C2/P2 并向相应结算范围交接；C1/P1 不被自动覆盖、收费或披露 |
| `AT-CC-288` | 付款事实迟到，此前门禁判断为待满足 | 按业务时间和当前有效性形成新付款核对与门禁版本；原判断和期间事实保留 |
| `AT-CC-289` | 税费更正和付款事实并发到达 | 分别保存两类事实并按版本、适用时间和关系形成当前核对；不让到达顺序或金额相等裁决 |
| `AT-CC-290` | 操作员手工点击“已缴税”但没有合格实际付款事实 | 拒绝形成付款覆盖；保留未受理/未决依据，不生成门禁满足或放行 |
| `AT-CC-291` | 节点或运输方试图凭付款页面、结算回收或异常关闭绕过当前门禁 | 继续阻断明确受限方向性动作；不修改节点、运输、付款、回收或外部监管事实 |
| `AT-CC-292` | `UC-CC-006` 接受明确范围的外部监管放行或放行更正 | 关联外部结果、付款核对和门禁版本并逐范围更新当前判断；不覆盖付款、回收、其他限制或物流事实 |
| `AT-CC-293` | 检查本用例直接形成或修改的业务对象 | 只形成税费付款协作事项、外部资金事实引用、税费付款核对、客户回收输入交接和动作化放行门禁核对；不形成监管核定、实际付款、实际代垫判断、客户回收金额、外部放行、物理执行或案件关闭 |
| `AT-CC-294` | 当前税费仍需后续付款，但真实程序明确付款不阻断 P1 的当前出库动作 | 保留待付款义务，并形成付款不构成 P1 当前出库动作前置条件及动作门禁判断；不解释为无需付款，也不扩大到装载出发、跨监管区域移动或交付 |
| `AT-CC-295` | 当前范围没有监管税费消息，但真实程序提供了可追溯的明确无需付款依据 | 依据该规则形成当前范围无需付款并继续核对其他门禁；没有消息本身不构成依据，且不得据此生成监管放行 |

## 生产参数与待决风险

以下内容不改变监管税费、资金事实、运营回收和放行结果的所有权边界，但在真实值提供前阻塞生产付款核对、客户回收输入交接或门禁判断：

| 参数或决策 | 当前状态 | 对本用例的影响 |
|---|---|---|
| `PAR-CUS-01`、`PAR-CUS-02` | 出口/进口税费结果、付款义务、监管补缴要求、监管税费退回决定、放行关系和范围语义待提供 | 无法实例化生产税费付款协作和门禁核对 |
| `PAR-CUS-03` | 税费复核、付款关联、客户回收输入交接、逐动作门禁复核和外部结果处理权限待提供 | 无法证明职责分离和最小权限 |
| `PAR-CUS-04` | 税费版本、法定义务、付款覆盖、监管税费退回决定、更正和逐动作放行前置规则待提供 | 不能生产判断付款覆盖或动作门禁满足 |
| `PAR-CUS-05` | 部分/超额/错误付款、冲突、资金退回、付款撤销、迟到、关闭后和恢复验证环境待提供 | 无法验证复杂分支与防重复关联 |
| `PAR-INT-05` | 财务/支付系统身份、实际付款结果层、外部引用、交换方向、资金退回和付款撤销语义待提供 | 无法接收权威资金事实或恢复关联 |
| `PAR-SET-01`、`PAR-SET-08` | 客户结算账户、合同币种、付款方资格、责任与回收确认条件待提供 | 无法形成生产客户代垫回收 |
| 税费—付款关联矩阵 | 各程序允许的付款人、范围、币种、分配、部分/超额和结果层待确认 | 只能保留待关联和范围化核对骨架 |
| 放行前置条件矩阵 | 各程序、申报范围、拟执行动作和监管边界中付款、资料、限制、处置及其他条件的关系待确认 | 不能生产宣称动作门禁已满足或请求放行复核 |
| `PAR-NFR-06` | 付款事实新鲜度、外部期限提醒、批处理和恢复目标待提供 | 无法确定生产提醒、积压和恢复验收门槛 |

不得以付款申请、客户预收、运营余额、支付页面、结算回收、节点扫描、异常关闭或内部状态字符串替代监管税费义务依据、外部资金事实、税费付款核对和外部监管放行。当前稳定实现策略是：先固定监管税费版本或明确无需付款依据，再分别判断付款义务和付款与当前动作门禁的关系，独立接收资金事实，逐范围形成付款核对与客户回收输入交接，最后按拟执行动作核对放行门禁并等待外部监管结果。

## 开发拆分建议

真实参数未齐备前，可以按以下顺序实现：

1. 已接受监管核定税费、版本、更正关系、法定义务人和逐对象范围模型。
2. 税费付款条件、不适用/未决、协作事项、责任交接目标和权限边界。
3. 外部资金事实引用、来源结果层、业务身份、去重和待关联处理。
4. 税费—付款逐范围关联，以及覆盖、差额和有效性三个正交维度的核对判断。
5. 付款方、税费、付款核对和客户合同责任输入向 `settlement-accounting` 的交接，以及结算实际代垫/回收结果的稳定引用。
6. 按申报范围、拟执行动作和监管边界形成税费付款、限制、处置和其他前置条件的放行门禁核对，以及 `UC-CC-006` 外部放行回接。
7. 税费更正、监管补缴要求、监管税费退回决定、追加付款、资金退回、付款撤销、迟到、案件关闭后、并发和跨客户合报分支。
8. 权限、隔离、审计、发布意图、可观测性和恢复。
9. `AT-CC-258` 至 `AT-CC-295` 的应用、领域、财务接入、结算交接和恢复测试骨架；实际代垫和回收判断以 `UC-SA-001` 的 `AT-SA-001..034` 覆盖，真实付款、回收、门禁和非功能参数使用显式未配置状态。

完成本用例只证明监管税费能够与外部资金事实逐范围核对，客户回收输入能够安全交给结算，放行前置条件能够按拟执行动作形成不冒充监管结果的门禁判断。实际资金、`UC-SA-001` 的实际代垫成立判断和客户运营金额、以及监管放行仍由各自责任方拥有；本关务控制域的完整性和专项开发顺序以[关务与贸易合规专项开发基线](../../product/CUSTOMS-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)为准，而不是继续增加关务状态。

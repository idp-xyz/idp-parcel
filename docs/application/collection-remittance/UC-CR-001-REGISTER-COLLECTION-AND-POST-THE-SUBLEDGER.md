# UC-CR-001 登记代收义务与事实、记代收分户账并形成回汇批次

状态：开发基线；登记与记账编排已实现，经受控 CLI（`cmd/parcel-collection-register`）落库，尚未实现的格见「给开发的交接」；COD 首发不在试点范围（`PAR-COM-11`），汇率、回汇周期、手续费与支付通道等实例参数一律未配置

## 目标与边界

本用例从一项客户代收服务要求成立、渠道或银行一侧的代收来源事实到达开始，到 `collection-remittance` 登记代收指令与代收事实、在代收分户账上追加记账、登记差异事项、形成回汇批次并交出汇付主张为止。它把代收本金在受托保管口径下的去向推进到一个封闭答案；规则、不变量与生命周期以 [collection-remittance CONTEXT](../../domain/collection-remittance/CONTEXT.md) 为准，本用例只引用。

本用例包含：

- 登记代收指令：固定金额、币种、责任法人、货主客户与代收渠道，引用客户代收服务要求依据。
- 开立代收分户账：按（货主客户，责任法人，币种，代收渠道）四维立键并保存受托依据。
- 接受代收事实：声明来源层级（收件人付款、渠道代收报告、渠道回款通知、运营企业真实到账）与来源证据引用，追加登记、不可覆盖。
- 追加分户账记账：入账、真实到账移位、认可抵扣落账、清分、汇付、差额落账与冲正；分户账键与币种由依据推出，不由调用方给。
- 登记差异事项：短款或溢款，只登事项、不落账。
- 登记 `settlement-accounting` 认可的协议抵扣：只钉认可引用到一条指令上、不落账；落账是凭它的一笔记账（`渠道在途` → `已抵扣`）。
- 形成回汇批次并交出汇付主张。
- 运营查阅代收分户账册（`/collection-subledgers`）。

本用例不执行：

- 形成或修改客户合同、客户代收服务要求、包裹身份或履约侧原始收款证据；它们分别归 `party-commercial`、`parcel-shipment`、`transport-fulfillment`。
- 铸造外部资金事实，或把一条资金事实认作代收本金：运营企业真实到账经 `settlement-accounting` 的唯一采用口进入本产品，认作代收本金（以及它与运营余额的互斥）也在结算一侧判，本用例只按采用引用登记那一层代收事实（[ADR-0274](../../adr/0274-collected-principal-bank-arrival-enters-through-the-settlement-accounting-funds-adoption.md)、[ADR-0330](../../adr/0330-a-collected-principal-bank-arrival-is-registered-against-an-adopted-funds-fact-that-settlement-has-set-aside-as-collected-principal.md)）。
- 形成 COD 服务费、有效协议允许的抵扣金额或任何运营应收应付；它们归 `settlement-accounting`，本用例只登记对它认可的抵扣的引用，也不读 `settlement-accounting` 核对那份引用。
- 执行付款、清算或确认客户已收到汇款；汇付主张不等于真实付款。
- 换算币种：一本账内不发生换算，本上下文不持有汇率。

## 结果语义契约

结果码取 `internal/collectionremittance/application` 的 `Outcome.String()`；受控 CLI 的退出码按处置动作分组，取自 `cmd/parcel-collection-register` 的 `answer`。`UNDERFUNDED` 与 `BATCH_CLOSED` 只出自记账（`PostSubledger`），`HANDED_OVER` 与 `ALREADY_HANDED_OVER` 只出自交出汇付主张（`HandOverBatch`）；其余各格各编排都可能答。

| 结果 | 结果码 | 退出码 | 业务含义 | 禁止行为 |
|---|---|---|---|---|
| 已登记 | `REGISTERED` | 0 | 本次落册或落账 | 不表示付款、到账或汇付成立 |
| 已在册 | `EXISTING` | 0 | 同键已在册、内容逐字段相同，是重放；重放判定先于余额守卫与批次收口 | 不再落账，不重新判余额 |
| 已交出汇付主张 | `HANDED_OVER` | 0 | 批次进入`已交出汇付主张`（`HANDED_FOR_PAYMENT`） | 不表示外部付款已执行 |
| 已交出过 | `ALREADY_HANDED_OVER` | 0 | 批次此前已交出 | 不是一次新的推进 |
| 未受理 | `NOT_ACCEPTED` | 1 | 输入缺格、形状不对，或记账形状不是该依据允许的那一种，或溢款事项金额少于按指令算的溢款 | 不落任何记录；CLI 译装被拒同样答 1 |
| 内容冲突 | `CONTENT_CONFLICT` | 2 | 同键已在册但内容不同 | 绝不覆盖既有登记 |

## 主流程

| 步骤 | 责任方 | 处理 | 结果 |
|---:|---|---|---|
| 1 | `collection-remittance` | 登记代收指令（`RegisterInstruction`）；已在册时读回逐字段比 | 已登记、已在册、内容冲突、未受理或未决 |
| 2 | `collection-remittance` | 开立指令所属的分户账（`OpenSubledger`） | 已登记、已在册、内容冲突、未受理或未决 |
| 3 | `collection-remittance` | 接受代收事实（`AcceptFact`）：指名的指令必须在册；真实到账另走采用事实门——重放判定、币种门、取本上下文按引用的事实锁、锁内再判重放、经结算只读口读事实此刻的链头、读回此引用名下已有的到账判合计与每指令至多一条、钉版本落册（ADR-0330） | 已登记、已在册、内容冲突、依据不在册、未受理或未决 |
| 4 | `collection-remittance` | 记账（`PostSubledger`）：先判重放，再解依据、定分户账与形状，凭代收事实的按依据判重，凭真实到账的移位再读一次它引用的事实、核名下全部到账之和仍不超过此刻链头金额，读回账面按指令判上限、按账判余额，最后落账；同一笔事务内读回与落账看同一份快照 | 已登记、已在册、内容冲突、依据不在册、余额不足、批次已交出、未受理或未决 |
| 5 | `collection-remittance` | 依据 `settlement-accounting` 已认可的协议抵扣登记认可的协议抵扣（`RegisterAgreedOffset`），再以它为依据追加抵扣记账（回到步 4）；次序是到账移位、抵扣、短款 | 认可已登记、已在册、内容冲突（含同一份认可换标识再登记）、依据不在册、未受理或未决；抵扣另由记账落到`已抵扣` |
| 6 | `collection-remittance` | 实收与指令不一致时登记差异事项（`RegisterDiscrepancy`），再以事项为依据追加差额记账（回到步 4） | 事项已登记、已在册、内容冲突、依据不在册、未受理或未决；差额另由记账落到`短款`或`溢款` |
| 7 | `collection-remittance` | 形成回汇批次（`FormBatch`），分户账必须已开立；汇付记账逐笔引用批次（回到步 4） | 已登记、已在册、内容冲突、依据不在册、未受理或未决 |
| 8 | `collection-remittance` | 交出汇付主张（`HandOverBatch`） | 已交出汇付主张、已交出过、依据不在册、未受理或未决 |

## 生命周期与控制分支

各对象的状态与转移以 CR CONTEXT「Lifecycles」为准。本用例只补编排上的约束：

- 入账只凭渠道代收报告：自外部来源入`渠道在途`，金额等于报告金额，一条报告至多一笔；收件人付款与渠道回款通知是旁证、不记账（ADR-0271 决定一）。
- 真实到账只做移位记账：`渠道在途` → `待清分`，金额等于到账金额，上限按到账所属的指令算，不够时答余额不足（ADR-0271 决定二）；移位之前它引用的事实此刻仍要容得下名下全部到账之和，容不下答内容冲突、账面不动（ADR-0330 决定三）。
- 真实到账登记的判据在事实此刻的链头上：币种同时等于账与事实，各条到账之和不超过链头金额，一条事实对一条指令至多一条；重放先于这些门，事实此后被结算更正小了也答已在册；结算的更正不自动冲正任何已登记或已移位的到账（ADR-0330 决定二至四）。
- 次序：真实到账要结算先采用并整条认作代收本金，之后才登记；早到的到账答依据不在册、不落册，采用并认作之后重跑同一份。
- 认可的协议抵扣落账：`渠道在途` → `已抵扣`，金额等于登记的认可额、全额一次，一条认可至多一笔；不超过该指令名下`渠道在途`，该指令有未移位的到账时等到账先移位；短款与移位上限按抵扣落账后的在途余额算（ADR-0298）。
- 认可被更正：冲正旧认可已落的那一笔，登记并落新认可；被撤回：冲正已落的那一笔，撤回的认可不能再落（ADR-0298）。
- 冲正是原记账的反向同额，一笔记账至多被冲正一次；入账不能冲正，来源侧记错走追加更正事实（ADR-0082 Consequences）。

## 一致性、幂等与并发

- 每次调用一个命令一笔事务，环境事务由受控 CLI 给出；写口在环境事务之外即拒。余额守卫依赖读回账面与落账看同一份快照。
- 同键同内容答已在册，同键异内容答内容冲突；比对在编排里按读回的记录逐字段比，不按到达顺序覆盖。
- 凭代收事实的记账按依据判重：同一条事实至多支撑一笔记账，换记账标识再凭同一条事实记账是内容冲突（ADR-0271 决定三）。判重先于余额守卫，与库上的唯一约束同一口径。认可的协议抵扣、冲正同一口径：一条认可至多落一笔，一笔记账至多被冲正一次（ADR-0298）。
- 记账取分户账锁之后再判一次重放：同一条命令并发到达时，后到的一路答已在册，不在来源已被移空的账面上答余额不足。
- 回汇批次状态单向推进；状态不参与重放比对。

## 权限、隔离与审计

- 今天只经受控 CLI 写入，运营方操作员在数据库网络内手跑；运营查阅 `/collection-subledgers` 经操作者渠道认证，授权边界只有租户。
- 按租户隔离；分户账四维键隔离客户、责任法人、币种与代收渠道，不同维的本金不得记进同一本账。
- 记账只追加；任何已落账记账都不修改或删除，原记账及其依据永久保留。

| `AT-CR-006` | 渠道代收报告已接受，自外部来源入账 | 入`渠道在途`，金额等于报告金额，一条报告至多一笔；收件人付款或渠道回款通知入账答未受理 |

| `AT-CR-008` | 同一条代收事实换一个记账标识再记一次 | 答内容冲突，不落第二笔 |

| `AT-CR-010` | 记账金额超过来源位置余额 | 答余额不足，确定没落账；该位置有钱之后重跑同一命令落账 |

| `AT-CR-013` | 汇付记账凭批次：`应付客户` → `已汇付`；批次交出汇付主张之后再来一笔新成员；重放交出之前的成员 | 第一笔落账；新成员答批次已交出；重放答已在册 |
| `AT-CR-014` | 交出汇付主张两次；交出一个不在册的批次 | 第一次答已交出汇付主张，第二次答已交出过；不在册答依据不在册 |
| `AT-CR-015` | 登记差异事项 | 事项落册，账面不变；差额要另有一笔以事项为依据、金额等于事项金额的记账 |

| `AT-CR-017` | 报告 100、真实到账 96、经 `settlement-accounting` 认可的协议抵扣 3（场景十七） | 渠道代收报告入`渠道在途` 100；到账移 96 到`待清分`；认可的抵扣 3 自`渠道在途`落入`已抵扣`；差异事项短款 1（= 100 − 96 − 3），自`渠道在途`落入`短款`；`渠道在途`清零，账内各位置之和仍是入账 100 |

| `AT-CR-019` | 来源侧更正一条代收事实 | 追加更正事实并回指原事实，原事实与原记账原样保留（回指格未实现，见「给开发的交接」） |
| `AT-CR-020` | 运营企业真实到账的证据引用指不到结算已采用的外部资金事实，或指到了一条采用了却没整条认作代收本金的事实；到账币种与代收指令所属账或与事实不同；或引用同一条已采用事实的各条到账之和超过该事实此刻的金额；一笔 1000.00 的回款按指令拆成 600.00 与 400.00 | 依次答依据不在册（两种同格）、未受理（受理门拒）、内容冲突，都不落事实；拆分合计恰好等于事实照登，登记时钉读到的链头版本（ADR-0274 决定二、ADR-0330 决定二） |
| `AT-CR-026` | 重复到达与换标识重登：同一份真实到账两次（含并发两路同一份）；同标识改金额；同一条指令换事实标识再登同一条事实（含金额更小）；事实此后被结算更正小了再重放 | 重放答已在册、合计不翻倍，并发两路同一份恰一条；改金额与换标识重登答内容冲突、不落第二行（库上唯一索引兜并发）；更正之后重放仍答已在册（重放先于按此刻状态作答的门）；并发六路各引用同一条事实、合计只容三条时恰三路登记 |
| `AT-CR-027` | 被结算更正与迟到：事实被更正小到容不下名下既有到账之和时登记新到账、移位未移位的到账；已落的移位重放；冲正已落的移位；更正回去之后再移位；没有钉版本的存量到账与结算一侧读不到的事实的移位；结算读不动或读口未装配 | 新到账与未移位的到账答内容冲突、账面不动（`待清分` 不增），已落的移位重放答已在册，冲正不读结算照落，更正回去后移位落账；存量到账与读不到的事实答依据不在册；读不动或未装配答未决；账内各位置之和始终等于入账（ADR-0330 决定三、四） |
| `AT-CR-021` | 归集截点之后才进入`应付客户`的本金被记进一个回汇批次 | 不归入该批：批次只收归集截点前已处于`应付客户`的本金，要归集它就形成新批次（未实现，见「给开发的交接」） |
| `AT-CR-022` | 登记或记账时依赖故障 | 答未决，重跑同一命令续办；不伪装成任何业务答案 |
| `AT-CR-023` | 运营查阅代收分户账册：册为空；读口故障 | 前者答空列表；后者答 `NO_ANSWER_FORMED`，不折成空册 |
| `AT-CR-024` | 登记认可的协议抵扣：同一内容两次；同标识改金额；换标识登记同一份认可（同认可引用、同指令）；同认可引用落到另一条指令；指令不在册；币种不是那本账的币种 | 依次答已登记与已在册、内容冲突、内容冲突、已登记、依据不在册、未受理；登记不动账，已抵扣仍为 0 |
| `AT-CR-025` | 认可抵扣落账：该指令有未移位的到账；抵扣额大于该指令名下在途；重放与换记账标识再落；撤回（冲正）第一次与第二次；撤回的认可再落；短款先于抵扣已吃掉在途款 | 到账未移位时与抵扣大于在途时答余额不足、确定没落账；重放答已在册，换标识答内容冲突；第一次冲正落账、第二次答内容冲突；撤回的认可再落答内容冲突；短款已吃掉在途款时抵扣答余额不足，冲正多落的短款后可落 |

# UC-SA-001 判定关务实际代垫并形成客户代垫回收

状态：开发基线草案；实际代垫、客户责任、回收本金和调整边界已确认，真实合同责任、结算账户、币种及资金事实来源参数待提供

## 目标与边界

本用例从 `UC-CC-009` 向结算交接一组范围明确、来源可追溯的监管税费、付款核对和外部资金事实引用开始，到 `settlement-accounting` 针对明确金额范围形成实际代垫成立、不成立、待判断或冲突结果，并在实际代垫与客户承担责任均成立时形成客户代垫回收及客户运营应收，或者形成后续调整、明确不成立、待判断、冲突、未受理或技术未形成为止。

本用例包含：

- 接收并独立校验关务税费、付款核对、外部资金事实、付款方、运营责任法人、客户账户和合同责任版本，不把交接成功当成业务成立。
- 逐税费义务、逐资金事实和逐金额范围判断运营企业是否实际为他方承担付款。
- 在实际代垫成立后，独立判断客户是否依据有效合同承担回收责任。
- 形成客户代垫回收本金、费用明细和客户运营应收之间的可追溯关系。
- 对部分付款、超额付款、多义务分配、多客户合报、币种换算、补缴、税费更正、付款撤销和资金退回形成逐范围结果。
- 对已经形成的客户代垫回收追加借项或贷项调整，不覆盖原判断、原回收或已发布对账单。
- 保持关务案件关闭、实际资金收付、客户收款与核销、监管放行和法定会计结果相互独立。

本用例不执行：

- 形成或修改监管核定税费、法定义务人、监管付款要求、税费付款核对、监管放行或关务案件状态。
- 形成、撤销、更正或伪造银行、支付或财务系统拥有的实际资金事实。
- 形成客户合同、客户承担责任、价格规则、结算政策或人工调整授权规则。
- 把客户预付、监管税费、运营企业付款或付款核对中的任一单项直接解释为实际代垫或客户回收。
- 把客户代垫回收解释为客户已经付款、已经核销、已经开票或已经形成法定会计应收。
- 自动形成报关服务费、代垫服务费或其他服务收入；服务费按独立费用项目和价格规则形成。

## 五层事实必须分离

| 层次 | 所有者 | 本用例使用方式 | 不得推导 |
|---|---|---|---|
| 监管核定与法定义务 | `customs-compliance` / 监管来源 | 引用当前适用税费版本、范围、币种和法定义务人 | 不等于实际付款或客户责任 |
| 外部资金事实 | 财务、银行或支付系统 | 引用付款、退回、撤销和更正的稳定身份、付款方、金额和有效性 | 不因接收或入账直接成为代垫 |
| 实际代垫成立判断 | `settlement-accounting` | 结合付款方、义务范围、资金事实和合同责任逐金额判断 | 不自动等于客户可回收金额 |
| 客户代垫回收 | `settlement-accounting` | 依据实际代垫和客户最终承担责任形成运营金额责任 | 不等于客户已经付款或监管放行 |
| 收款、核销与法定财务 | 外部资金系统 / `settlement-accounting` / 财税系统 | 独立接收并映射到未结项 | 不改写代垫和回收的成立历史 |

| 外部资金事实 | 财务/银行/支付系统 | 事实身份/版本、付款方、收款方、原币金额、业务时间、有效性及撤销/更正/退回关系 | 不复制为本地付款事实；重复来源不得重复计入 |
| 付款核对 | `UC-CC-009` | 税费版本覆盖、法定义务覆盖、程序付款义务覆盖及各自范围 | 只作为关务核对依据，不代替结算责任判断 |
| 商业责任 | `party-commercial` | 运营责任法人、客户账户、合同版本、最终承担责任、限额/比例/免赔及生效时间 | 不以当前合同覆盖历史；未配置时保持待判断 |
| 结算依据 | `settlement-accounting` / `party-commercial` | 结算账户、方向、币种、换算来源和适用时点 | 账户或换算依据不明确时不得猜测入账 |
| 既有结算历史 | `settlement-accounting` | 已有判断、回收、调整、截单快照、对账单、收款映射和核销 | 用于幂等、差额和后续账期判断，不可覆盖 |

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 结算输入已接收 | 来源和范围可以进入判断 | 交接、采用版本、对象、金额范围和接收时间 | 不得表示代垫或回收成立 |
| 实际代垫成立 | 运营企业已对明确义务和金额范围实际替他方付款 | 税费、资金事实、付款方、责任依据、原币金额、判断版本 | 不得自动生成服务费或监管放行 |
| 实际代垫不成立 | 合格依据证明该范围不是运营企业替他方付款 | 负向依据、范围、金额和版本 | 不得用资料缺失伪装为不成立 |
| 实际代垫待判断 | 事实、责任、范围、分配或币种依据不足 | 已知边界、缺口和续办入口 | 不得先入客户应收 |
| 实际代垫冲突 | 合格输入对相同金额责任互相矛盾 | 全部冲突输入、冲突范围和复核入口 | 不得按最后到达或有利结果选择 |
| 客户代垫回收已形成 | 客户对已成立实际代垫负有运营金额责任 | 回收身份、客户、结算账户、原币/结算币、计算依据、费用和应收关系 | 不得表示客户已付款、已核销或已开票 |
| 客户代垫回收不成立 | 实际代垫不成立或合同明确客户不承担 | 负向责任依据和明确范围 | 不得删除实际付款或代垫历史 |
| 客户代垫回收待判断 | 实际代垫已成立但客户责任、账户或金额规则未决 | 已成立代垫范围、待决责任和续办入口 | 不得暂按默认客户入账 |
| 客户代垫回收调整已形成 | 新事实导致已形成回收需要追加借项或贷项 | 原回收、调整原因、新旧依据、差额和适用账期 | 不得覆盖原回收或已发布对账单 |
| 当前无需调整 | 新输入未改变当前有效金额责任 | 比较版本、范围和结论 | 不得制造零额费用掩盖重复输入 |
| 未受理 | 请求或访问不能合法关联 | 最小原因和纠正入口 | 不得泄露其他客户、法人或案件信息 |
| 未形成结算结果 | 技术处理未完成 | 请求、失败阶段、已采用输入和恢复引用 | 不得伪装成不成立、待判断或冲突 |

部分付款不形成一个吞并全部范围的“部分代垫”状态。已经证明的金额范围可以成立，剩余范围分别保持待判断、不成立或尚无付款事实；超出监管税费和合同责任范围的金额不得为了对平自动转为客户代垫回收。

## 主流程

| 步骤 | 责任方 | 处理 | 结果 |
|---:|---|---|---|
| 1 | `settlement-accounting` | 校验租户、责任法人、客户、权限、交接和对象范围 | 形成已受理或未受理 |
| 2 | `settlement-accounting` | 采用明确版本的税费、付款核对、资金事实和合同责任 | 形成结算输入版本；缺失保持待判断 |
| 3 | `settlement-accounting` | 按税费义务、资金事实和金额范围建立合法分配关系 | 明确已分配、未分配和冲突范围 |
| 4 | `settlement-accounting` | 判断付款方是否以运营企业责任实际替他方付款 | 形成实际代垫成立、不成立、待判断或冲突 |
| 5 | `settlement-accounting` | 对成立范围判断客户最终承担责任和可回收边界 | 形成回收成立、不成立或待判断 |
| 6 | `settlement-accounting` | 形成客户代垫回收、费用明细和客户运营应收关系 | 保存计算展开、币种、账户和依据版本 |
| 7 | `settlement-accounting` | 与既有判断、回收、调整和账期历史比较 | 无变化保持原结果；变化追加调整 |
| 8 | `settlement-accounting` | 发布稳定结果供关务核对引用、客户对账及后续核销使用 | 发布失败只重试同一意图，不重复金额 |

批量处理必须逐客户、逐税费义务和逐金额范围形成结果。单项待判断、冲突、未受理或技术失败不得回滚其他已经合法形成的结果，汇总也不能成为新的金额事实。

## 一致性、幂等与并发

- 相同请求身份和相同内容返回既有结果；相同身份携带不同税费、资金、客户、责任或金额范围时形成请求冲突。
- 同一外部资金事实通过回调、文件或人工核实重复到达，只能被采用一次；更正必须形成新来源版本。
- 一笔付款有明确权威分配时逐范围处理；没有充分依据却被多个案件、客户或税费义务并发认领时保持分配冲突。
- 税费更正和资金更正并发到达时先分别保全来源，再依据业务适用时间、当前有效性和版本形成新判断，不按接收顺序覆盖。
- 结算截单或对账单发布与迟到事实并发时，已进入不可覆盖快照的金额保持不变，差额进入后续账期调整。
- 结果已形成但事件首次发布失败时，业务结果仍有效，只重试同一发布意图。

## 权限、隔离与审计

- 关务交接、结算输入采用、代垫判断、客户回收形成、人工调整和核销分别授权；关务权限、财务系统访问权或客户服务权限不能互相推导。
- 全部对象按集团租户、责任法人、货主客户账户、结算账户、关务案件及明确金额范围隔离。
- 跨客户合报只能消费已经按客户权威分配的税费和资金范围；不能按包裹数、客户数或总金额平均分摊监管义务。
- 审计至少保留请求方、决定方、采用版本、业务时间、实际处理时间、计算展开、授权依据、旧结果、新结果、原因和发布恢复记录。
- 未受理、冲突和技术错误只披露纠正所需最小信息，不暴露其他客户或法人金额。

## 首发试点约束

- 只有 `PAR-CUS-01/02/04` 已登记的税费程序、`PAR-SET-01` 已建立的客户结算账户和 `PAR-SET-08` 已确认的代垫/回收规则才能进入生产。
- 复杂多付款分配、跨客户合报税费、付款撤销、监管税费退回和真实资金退回优先使用 `R/S` 验证；真实自然发生时保留 `P` 证据。
- 首发不因缺少实例参数预建默认比例、限额、币种、汇率、付款责任、调整权限或服务费规则。

## 验收示例

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-SA-001` | 合法关务交接到达 | 只形成结算输入接收和处理入口，不直接形成实际代垫或客户回收 |
| `AT-SA-002` | 只有监管税费核定，没有运营企业资金事实 | 保持实际代垫待判断或不成立范围，不形成客户回收 |
| `AT-SA-003` | 只有付款事实，不能关联明确税费义务 | 保持待关联/待判断，不把付款自动记为代垫 |
| `AT-SA-004` | 客户预付余额足以覆盖税费 | 预付不证明运营企业已经实际代垫，不形成代垫判断 |
| `AT-SA-005` | 运营责任法人实际付款，合同明确客户最终承担 | 对明确金额形成实际代垫和客户代垫回收、费用及客户运营应收 |
| `AT-SA-006` | 客户或收件人直接付款，运营企业无付款责任 | 实际代垫不成立，不形成客户代垫回收 |
| `AT-SA-007` | 运营企业付款但合同明确由其最终承担 | 可以保留资金与成本关系，但不形成客户代垫回收 |
| `AT-SA-008` | 付款事实完整但客户责任版本不明确 | 可形成适用的实际代垫判断，客户回收保持待判断 |
| `AT-SA-009` | 税费 100、合格运营付款 80 | 只对 80 金额范围成立，其余 20 保持未付或待判断 |
| `AT-SA-010` | 税费 100、运营付款 120 | 最多按合格税费和责任范围判断；超额 20 不自动回收 |
| `AT-SA-011` | 税费、付款或结算账户币种不同且无有效换算依据 | 保持客户回收待判断，不使用当前汇率或默认币种 |
| `AT-SA-012` | 一笔付款有权威依据分配到多个税费义务 | 逐义务、逐金额形成判断，合计不超过资金事实有效范围 |
| `AT-SA-013` | 一笔付款被多个义务认领且无分配依据 | 形成分配冲突，不抢先入账或按比例猜测 |
| `AT-SA-014` | 跨客户合报税费已权威分配给 C1 和 C2 | 只按各客户明确范围判断和入账，客户数据与金额保持隔离 |
| `AT-SA-015` | 合同存在已确认的比例、限额或免赔规则 | 保存实际采用规则和计算展开，回收金额可与实际代垫不同 |
| `AT-SA-016` | 实际代垫成立且产品另有代垫服务费 | 本用例只形成本金回收；服务费走独立费用规则 |
| `AT-SA-017` | 监管税费上调且尚无追加付款 | 保留原判断，新增加金额保持待付款/待判断；不覆盖原回收 |
| `AT-SA-018` | 监管税费下调但尚无真实资金退回 | 形成新税费依据和必要的回收调整判断，不假设资金已经退回 |
| `AT-SA-019` | 收到监管税费退回决定但没有资金退回事实 | 不形成资金已退或客户已退款结果 |
| `AT-SA-020` | 合格资金退回事实关联原代垫 | 形成新判断版本和适用贷项调整，不覆盖原付款与回收 |
| `AT-SA-021` | 原付款被外部系统撤销或更正 | 保留原来源与判断历史，按新有效事实追加回收调整 |
| `AT-SA-022` | 相同交接和来源版本重复到达 | 返回既有判断和回收，不重复费用或应收 |
| `AT-SA-023` | 相同请求身份携带不同客户、税费或金额 | 形成请求冲突，不按最后到达覆盖 |
| `AT-SA-024` | 税费更正与资金更正并发到达 | 分别保全后按有效版本重判，不依赖接收顺序 |
| `AT-SA-025` | 同一付款被两个客户并发认领 | 保持分配冲突，未裁决前不形成任一客户回收 |
| `AT-SA-026` | 回收已形成但结果事件首次发布失败 | 原结果保持有效，只恢复同一发布意图，不重复客户应收 |
| `AT-SA-027` | 对账单发布后收到迟到税费或资金更正 | 原对账单不变，差额进入后续账期调整 |
| `AT-SA-028` | 后续收到客户真实付款并完成核销 | 只新增收款映射和核销关系，不把原回收改写为“已回收” |
| `AT-SA-029` | 关务案件已关闭后收到合法结算输入 | 仍可形成代垫判断或回收调整，不要求先重开关务案件 |
| `AT-SA-030` | 结算调整改变客户应收但未产生新监管义务 | 不自动重开关务案件或回退监管放行 |
| `AT-SA-031` | 操作员无目标客户或责任法人的结算权限 | 未受理并最小披露，不读取或形成金额结果 |
| `AT-SA-032` | 技术处理在结果提交前失败 | 返回未形成结算结果，不伪装成业务不成立或待判断 |
| `AT-SA-033` | 批量含成立、不成立、待判断、冲突和越权范围 | 逐范围返回结果；合法结果不被局部失败回滚，汇总不泄露越权信息 |
| `AT-SA-034` | 检查本用例直接形成或修改的对象 | 只形成结算输入采用、实际代垫判断、客户回收/调整、费用和运营应收关系；不形成监管、资金、合同、收款或法定财务事实 |

## 生产参数与待决风险

| 参数 | 待提供内容 | 未提供时影响 |
|---|---|---|
| `PAR-SET-01` | 客户结算账户、责任法人、相对方、方向和币种 | 不能形成生产客户运营应收 |
| `PAR-SET-08` | 可代垫义务、付款方资格、客户责任、金额边界、币种换算、部分/超额付款、补缴、退回、撤销、更正和调整授权 | 不能生产判断实际代垫和客户回收 |
| `PAR-CUS-01/02/04` | 真实税费程序、法定义务、付款与退回语义 | 不能确认税费版本及其适用范围 |
| `PAR-INT-05` | 财务、银行或支付事实来源、身份、更正和撤销语义 | 不能把外部资金事实用于生产判断 |
| `PAR-NFR-06` | 结算处理、发布和恢复的非功能目标 | 不能形成生产运行基线 |

完成本用例只证明关务税费与外部资金事实能够被结算独立解释为实际代垫，并在客户责任成立时形成可调整的运营回收。监管税费、实际资金、客户收款、核销、发票和总账继续由各自责任方拥有。

# UC-SA-004 接收、匹配并审核供应商账单

状态：供应商成本、账单主张、金额范围匹配和审核应付编排已形成；真实供应商协议、账单入口、账期、币种、容差和审核授权待提供，生产分支保持 `No-Go / 待参数化`

## 目标与边界

本用例从 `transport-fulfillment` 已形成的履约/供应商协议快照和供应商通过唯一主入口提交的账单主张开始，建立供应商账单来源、按金额范围与内部预期成本的匹配关系，并分别形成未匹配、部分匹配、差异、争议、拒绝和审核应付结果。

本用例包含：

- 接收并保全供应商账单、对账文件或其他可验证的收费主张及其版本。
- 依据采购协议、实际履约、计费重量和内部预期成本建立一对多、多对一和部分金额匹配。
- 对无争议金额先行审核，对争议或证据不足金额保持待审、争议或拒绝。
- 处理供应商追加主张、贷项、账单更正和迟到账单，追加新关系而不覆盖原主张或原审核应付。
- 将审核应付和供应商费用贷项作为两个独立、稳定且相互关联的结果提供给对账、经营分析和外部财务交换引用，但不形成真实付款或静默净额。

本用例不执行：

- 修改供应商合同、采购价格、履约事实、测量事实或外部账单原文。
- 把供应商预期成本当作供应商账单主张，或把账单到达自动变成审核应付。
- 形成银行付款、供应商已收款、法定发票、总账或集团合并抵销。
- 用成本分摊转移供应商债权债务；分摊由 [`UC-SA-006`](./UC-SA-006-ALLOCATE-COSTS-AND-DERIVE-OPERATING-RESULTS.md) 另行处理。

| 输入组 | 权威来源 | 最低业务语义 | 使用约束 |

| 既有结算历史 | `settlement-accounting` | 已匹配、审核、争议、贷项、付款映射和账期状态 | 只用于差额与幂等，不修改历史 |

## 结果语义契约

| 结果 | 业务含义 | 必须保留 | 禁止行为 |
|---|---|---|---|
| 主张已接收 | 账单来源和范围进入处理 | 原文引用、版本、接收时间和业务账期 | 不表示匹配或应付 |
| 未匹配/部分匹配/已匹配 | 账单金额与内部成本的范围关系 | 每个金额片段、候选依据、已用/剩余金额 | 不按总额或包裹数平均吞并 |
| 差异/争议 | 主张与协议、履约或成本依据不一致 | 差异金额、原因、证据、责任和处理入口 | 不把差异自动接受或拒绝 |
| 审核应付 | 明确金额范围通过协议、履约和费用审核 | 审核版本、金额、责任法人、结算账户、方向、币种和依据 | 不表示供应商已付款或已收款 |
| 供应商费用贷项 | 依据更正或贷项对既有主张/应付追加形成贷记金额 | 贷项身份/版本、结算账户、原主张/应付关系、金额与借贷方向、原因、审核/采用结果、当前有效性和适用周期 | 不另建一个净额审核应付，不改写原账单行或静默净入原审核应付 |
| 追加主张 | 供应商对原账单范围追加新的收费主张 | 新主张身份/版本、与原主张关系、金额、范围、原因和适用周期 | 不因提交而自动形成审核应付 |
| 待审/冲突/未受理/未形成 | 分别表示证据不足、认领冲突、权限不合法或技术未完成 | 缺口/冲突/失败阶段和续办入口 | 不用零额或最后到达结果掩盖 |

## 主流程

| 步骤 | 责任方 | 处理 | 结果 |
|---:|---|---|---|
| 1 | `settlement-accounting` | 校验来源伙伴、责任法人、账期、账户、币种和权限 | 已受理或未受理 |
| 2 | `settlement-accounting` | 保全账单版本并解析行、金额、范围和更正关系 | 主张已接收或待解析 |
| 3 | `settlement-accounting` | 读取采购协议、BUY `PricingEvaluation`、履约事实、计费重量采用快照和预期成本 | 匹配候选或待判断 |
| 4 | `settlement-accounting` | 按金额范围建立一对多、多对一、部分和未匹配关系 | 匹配结果、差异或冲突 |
| 5 | 授权审核责任方 | 对无争议范围形成审核应付；争议范围形成待审/争议/拒绝 | 审核应付或负向结果 |
| 6 | `settlement-accounting` | 接收供应商更正、贷项、追加主张和迟到主张 | 追加结果，不覆盖历史 |
| 7 | `settlement-accounting` | 分别发布稳定审核应付和供应商费用贷项引用及其关联，供对账、经营分析和外部财务交换消费 | 发布成功或可恢复失败 |

## 一致性、幂等与并发

- 相同供应商、账期、主张身份和版本重复到达返回原接收/匹配/审核结果；同一身份内容变化形成版本冲突。
- 同一主张金额被多个内部成本范围认领时，只有存在明确多对多依据才可分配；否则保留冲突。
- 账单匹配与内部成本更正并发时分别保留来源，再按有效版本形成新匹配或调整，不按接收顺序覆盖。
- 承运商账单认定或账单代码映射不能修改物理测量和原 BUY 评价；需要重算时由 `parcel-pricing` 以新的输入快照/评价形成新依据，再由本用例追加匹配或差异。
- 无争议范围可先审核，争议范围不阻塞其他金额，也不得被整单结论吞并。
- 审核应付或供应商费用贷项结果已形成但事件发布失败时，只分别重试原结果的同一发布意图，不重复形成应付、贷项或净额结果，也不把一方发布成功推定为另一方已发布。
- 批量账单逐行/逐金额范围返回结果，局部拒绝或技术失败不回滚其他合法审核范围。

## 权限、隔离与审计

- 账单接收、匹配规则采用、争议决定、审核应付、贷项和发布分别授权；供应商不能直接写入审核结果。
- 按集团租户、责任法人、供应商、结算账户、账期、方向和币种隔离；跨客户合报必须有明确合同与金额分配依据。
- 审计至少记录原账单引用、协议/履约/成本版本、匹配候选、金额分配、差异、争议、审核人、决定人，以及贷项身份/版本、借贷方向、原应付关系和发布恢复记录。
- 供应商可见回执只披露其自身主张和明确范围，不暴露其他伙伴或客户金额。

## 验收示例

| ID | 场景 | 预期结果 |
|---|---|---|
| `AT-SA-079` | 供应商账单从唯一主入口到达 | 保全原主张和版本，只形成接收，不自动形成应付 |
| `AT-SA-080` | 账单格式/账期无法识别 | 形成待解析或未受理，不创建占位账单 |
| `AT-SA-081` | 预期成本存在但供应商未提交主张 | 保留预期成本，不伪造供应商账单 |
| `AT-SA-082` | 主张与履约和协议完全匹配 | 对明确金额形成已匹配并可进入审核 |
| `AT-SA-083` | 主张金额只部分有内部成本依据 | 已匹配与未匹配金额分开保留 |
| `AT-SA-084` | 一条主张对应多个实际履约段 | 按金额范围建立多对多关系并守恒 |
| `AT-SA-085` | 多条主张对应一个履约段 | 只有合同允许且范围明确时匹配，否则保持冲突/待审 |
| `AT-SA-086` | 账单金额高于协议/预期成本 | 差异范围进入争议或待审，不自动接受超额 |
| `AT-SA-087` | 无争议金额和争议金额同在一张账单 | 无争议范围可先审核，争议范围独立保留 |
| `AT-SA-088` | 审核人员无金额授权 | 形成未受理/待授权，不形成审核应付 |
| `AT-SA-089` | 审核通过部分账单 | 只对通过金额形成审核应付，其他范围保持原状态 |
| `AT-SA-090` | 供应商贷项更正已审核金额 | 原主张/应付保留，追加具有稳定身份、结算账户、借贷方向和原应付关系的贷项及其审核/采用结果，并分别发布下游引用；不另建净额审核应付 |
| `AT-SA-091` | 迟到账单属于已关闭账期 | 进入后续账期并关联原履约/账期，不重开原账单 |
| `AT-SA-092` | 同一主张重复到达 | 返回原结果，不重复匹配或审核 |
| `AT-SA-093` | 同一身份携带不同金额 | 形成版本冲突，不按最后到达覆盖 |
| `AT-SA-094` | 同一金额被两个客户并发认领 | 保持范围冲突，未裁决前不形成任一客户应付 |
| `AT-SA-095` | 履约事实被更正 | 保留原匹配，按新有效事实追加差异/调整 |
| `AT-SA-096` | 供应商账单币种与协议币种不同且无换算依据 | 保持待判断，不用当前汇率猜测 |
| `AT-SA-097` | 供应商已收到运营方付款通知 | 仍只形成外部事实引用/待核销，不把通知当审核或付款事实 |
| `AT-SA-098` | 审核应付或供应商费用贷项发布失败 | 原审核/贷项结果有效，只恢复各自同一发布意图，不把一方发布成功推定为另一方已发布 |
| `AT-SA-099` | 批量含通过、争议、拒绝和技术失败行 | 逐范围返回，合法通过行不回滚 |
| `AT-SA-100` | 检查本用例形成的对象 | 只形成主张、匹配、争议、审核应付和贷项；不形成付款、发票或成本分摊 |

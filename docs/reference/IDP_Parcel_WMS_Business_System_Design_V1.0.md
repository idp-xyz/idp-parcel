## 0. 阅读与决策状态

### 0.1 设计出发点

- 目标是面向国际小包的集货、分拨、中转、换单和交接，主要处理已打包包裹及其箱、袋、托盘和笼车等物流单元。
- 根据本次讨论，首期推荐作为 IDP Parcel 内部边界清晰的业务模块，复用现有可用的客户、合作伙伴、渠道、运单、权限和基础资料；是否采用同进程、同库、独立服务以真实工程为准。
- 不将 IDP Prism 设为该模块运行前提。需要商品 SKU 库存、复杂仓储或客户已有 Prism 时通过接口协同；小包作业不能伪造商品库存来实现收货。
- 未来是否将小包 WMS 作为可独立部署、单独销售的产品尚未决策。本稿设计可替换的边界，但不宣称拆分已经完成或无需迁移。
- IDP BIP 与 IDP EER 已有独立产品及完成开发的背景；外部集成和复杂执行可评估复用既有能力，需逐接口核实。本稿不推定 BIP 已接入 WMS，不把 BIP 或 EER 自动设为每次现场扫描的强制同步依赖。
- 本稿为评审建议，业务条件、合同要求、技术方案和 SLO 须由实际业务负责人、架构负责人及客户/承运商确认；没有确认前的建议不得写成既有生产事实。

## 1. 产品边界与业务对象

### 1.1 本模块解决什么问题

- 自营或经授权的操作点接收不同客户的包裹，避免无预报件丢失归属线索。
- 支持包裹逐件、物流箱袋逐单元和授权的汇总方式作业，明确扫描覆盖范围。
- 为分拣、装载、交接、复核、异常和账单提供来源可追踪的操作事实。
- 使 Parcel 的运单、渠道、轨迹和计费能引用仓内事实，而不篡改申报、历史报价或外部回执。

### 1.2 不属于本模块的权威职责

| 领域 | 权威职责 | WMS 的职责 |
| --- | --- | --- |
| 订单/包裹 | 商业请求、运单及 Parcel 正式包裹身份 | 引用已存在包裹；无预报先存现场作业件，之后建立可审计关联 |
| 产品/渠道/采购合同 | 可售服务、渠道、合同、注入方案、版本及规则 | 获取授权的可作业信息并保留使用时版本；按授权返回建议或异常，不私改合同 |
| 报价/结算 | 计费重、价卡计算、费用账单与财务确认 | 保存原始测量、作业数量及可计费证据；发起重算请求，不能自动覆盖账单 |
| 运输/轨迹 | 运输计划、承运商确认、交付、运输事件归一 | 输出实际现场事件；仓库出库不等于承运商接收或消费者签收 |
| 清关 | 申报主体、分类、申报版本、提交和回执 | 根据授权获取“放行/暂停/待确认”等作业约束；不凭扫描自动认定完成申报 |
| Prism 或其他 WMS | 自己授权经营的商品库存和仓内作业 | 仅按合同/集成边界交换指令及事实，不能双写同一现场事实 |

### 1.3 集成模式及事实归属

| 模式 | 作业执行 | 来源和权威 | Parcel 显示 |
| --- | --- | --- | --- |
| Parcel 内置 WMS | 本模块员工或授权合作方 | 本模块的已提交作业记录为本系统现场事实 | 引用或投影现场结果 |
| 外部仓库 | 合作方 WMS | 合作方回执为该方声明；本地保存原文、来源、验证结果 | 展示来源、事件时间、收到时间与核验状态 |
| 同一链路混合 | 每个设施/环节事先指定执行方 | 对同一个设施、同一个作业事实有明确主责，不允许两套系统各自覆盖 | 按来源与可信度显示，可对账 |

一次订单可以经过多个节点，不同节点的作业权威可以不同。扫描、发送交接、接收确认是不同事件；不得仅因存在一个来源的“完成”就合成另一方的确认。

### 1.4 术语

| 术语 | 精确定义 |
| --- | --- |
| Shipment / 运单 | Parcel 中的运输业务对象；一票与物理件数的关系以具体业务为准 |
| Parcel / 包裹 | Parcel 正式业务中的单件；具有稳定内部身份和可关联的外部标识 |
| 现场作业件 StationPiece | 某一次到仓过程中被识别或暂存的物理件记录；可以暂未关联 Parcel，同一包裹多次进仓形成多次访问/记录 |
| 箱袋 Container | 特定装箱或装袋实例；与可重复使用的笼车资产分开。基于已有全域蓝图，Bag、Sack、Pallet、ULD、Container 均属物流装载单元，不将无预报单件误命名为 Bag |
| Location | 实际作业设施或区域，支持站点、作业区、暂存位，不假设都需要 SKU 库位 |
| 注入方案 | 合同、渠道与交付/计费范围的组合；一处设施与多个方案可能关联，生效期和责任独立 |
| 预报 | 尚未发生或未确认到仓的期待；不是收货事实 |
| 交接 | 交出方与接收方的事实和凭据；双方可以部分完成或存在差异 |
| 物流清单 Manifest | 运输或承运商规定的数据清单；不是仓内箱袋，也不自动等于海关申报批次 |
| FNSKU | 某些 FBA 商品库存识别信息；普通小包业务不得强制填写 |

## 2. 端到端流程与例外路径

本流程支持不同路线组合；不把装袋、换单、外部承运商下单或海外仓设为每票必经步骤。

~~~mermaid
flowchart TB
  A["预报或无预报"] --> B["到仓与认领"]
  B --> C{"允许继续作业"}
  C -- "是" --> D["测量与分拣"]
  C -- "否" --> E["暂扣与处理"]
  E --> C
  D --> F{"需要装箱袋"}
  F -- "是" --> G["装载与封闭"]
  F -- "否" --> H["出库与交接"]
  G --> H
~~~

海外场景从目的节点收货重新开始：接收箱袋或逐件 → 复核/拆箱 → 条码关联 → 可选面单生成或导入 → 打印及贴标确认 → 出库与接收方确认。仅扫描袋码不能证明袋内每个包裹已逐件验收。

### 2.1 到仓：预报件

1. 根据有权限的设施、客户、标识来源和外部参考号查询候选；单一可靠候选提示确认，多候选进入人工消歧。
2. 生成或更新该次到仓作业件并记录扫描事实；扫描结果不自动证明已经完成交接签收，具体签收以协议和用户动作定义。
3. 保留实际来源单号、实物状态、设施、操作人、时间、设备、工作站及指令标识。
4. 如果上游取消、已退回或不属于本节点，提示原因并隔离或交由授权人员处理；不删除到仓事实。

### 2.2 到仓：无预报或条码无法匹配

1. 在操作员已授权租户/设施内建立待认领作业件，客户可为空；记录扫描值和类型，必要时记录照片与外包装观察。
2. 查重只在合适的动作上下文内判定；相同条码但存在多位客户或多个候选时不得直接绑定。
3. 由授权人员依据客户证据执行认领/撤销认领；关联到 Parcel 时记录操作人、原因、关联前后对象和时间。
4. 未认领件默认隔离；能否临时移动、测量或接收，依据站点授权策略。没有身份、渠道或合规条件时不可自动发出。
5. 原始扫描和认领历史追加保留；同一实物重复出现的合并须依据证据，不可把不确定记录自动吞并。

### 2.3 测量与检查

- 秤重、量方、目视破损、限制物品标识及必要图片逐项记录；原始测量与人工修正分开。
- 分别记录客户申报、现场原始测量、授权复核结果和计费模块采用的计费重；每项有单位、精度、来源、设备、时间、操作人及版本。
- 规则异常应允许形成暂扣或复核，避免因设备数据不合理直接改变渠道或费用。
- 对尺寸、重量、特殊货物和清关放行的判断只使用经授权的规则与已知证据；缺失是 UNKNOWN，不等于通过。

### 2.4 分拣与复核

- 按客户、国家/邮区、产品/渠道、节点、计划、截止时间、货物属性与授权约束匹配生效规则；订单规则和仓内规则分别版本化。
- 决策顺序：合法可作业及有效信息检查 → 可用目标匹配 → 明确优先级 → 建议/人工确认 → 记录规则版本与结果。
- 无匹配、多条最高优先级并列或必要信息未知时，禁止按列表顺序任意选择；进入异常或授权处理。
- 是否允许跨客户、跨渠道或跨注入方案混装，由业务、承运商、设施与合规规则共同决定；不得写死“全部可混”或“永远不能混”。
- 扫描分拣时显示目标区域/格口与异常提示；电子分拣与人工搬运事实可分别确认。

### 2.5 装箱袋和暂存

- 支持包裹直接出库，也支持装入箱、袋或其他物流单元；实际包装关系与逻辑运输分组分别维护。
- 同一物理件在同一时刻最多有一个有效直接物理父级；箱中袋、袋中包裹等允许按规则嵌套，禁止循环关系。
- 装入必须检查已授权作业、封闭状态、兼容规则和有效位置；跨操作员并发时对冲突进行原子判定。
- 拆袋、移除、重新装载、解封保留时间、原因、操作人和前后关系。重复使用的笼车资产与每次装载实例分离，不复用历史事实。
- 清单可按单件或箱袋核对；只扫描外箱时，系统不得把未观察的所有内件标记为已逐件确认。

### 2.6 出库与部分交接

1. 创建交接计划及版本化预期清单，允许一个物理收货方按已获准的规则接收多个业务计划。
2. 仓库逐件、逐容器或授权汇总方式确认交出，产生已交出清单及证据；支持分批交出。
3. 接收方可逐件确认或仅确认汇总数量。逐件确认才能形成对应单件的“对方已确认”；汇总确认只表明数量声明，不虚构逐件回执。
4. 比较计划、交出和接收三类信息，分别记录短少、多出、未核对与争议。未交件可继续补交。
5. 完成条件由合同和责任方确认配置；交出进度与接收/对账进度独立表达，不得因为一方提交就强推两方一致。例如已交出 97/100 件、收方仅汇总确认 96 件时，交出仍为部分完成，同时存在接收差异。

### 2.7 换单与标签

- Parcel/经授权外部服务负责渠道或外部购买面单决定；WMS执行现场扫描、获取已有标签、打印、贴标复核并记录结果。
- 旧标识、新标识、标签版本、关联的 Parcel/作业件、来源和有效期构成可追踪关系；历史不删除，不以新号覆盖旧号。
- 申请面单、外部已创建、文件已获取、打印已提交、打印结果未知、人工贴标已确认和接收方已接收是不同事实。
- 外部调用超时为 UNKNOWN。只有对方具备可靠幂等键、查询或确认机制时按约定重试；不能盲目再次购买。
- 打印机断开或超时不等于标签未打印；重打需显示风险并记录原因，不自动产生第二个物流订单。

## 3. 数据所有权与共享

### 3.1 权威映射

| 数据 | 拟定权威 | 共享方式 | 不变量 |
| --- | --- | --- | --- |
| 租户、组织、法人、客户、合作方 | Parcel 已有权威模块；真实归属待审计 | 内部应用接口或授权查询 | 客户角色不等于租户，合作仓和承运商可为不同主体 |
| 国家、单位、地址 | Parcel 或既有主数据权威 | 引用标准代码及有效版本 | 不以显示名称作为唯一关系；敏感字段按岗位授权 |
| 运单、正式包裹、客户参考 | Parcel | 稳定内部 ID 引用；外部别名独立管理 | 订单中 P1 等展示序号不能作为全平台唯一 ID |
| 渠道、产品、合同、分区、注入方案 | Parcel 相关域 | 按策略输出 WMS 所需字段与版本 | 物理仓库、合同计费起点、目的地 Zone 不做一对一假设 |
| 仓库、区域、设备、仓内任务 | WMS，设施基础信息可复用/引用公共场所 | WMS 写入及授权共享 | 同一设施可服务多个业务方案；仓库与渠道关系有生效区间 |
| 扫描、测量、暂存、箱袋、交接事实 | WMS 或经授权外部执行方 | 事务提交后向 Parcel 返回事实 | 不覆盖客户申报、报价快照和承运商的接收声明 |
| 客户售价、采购价、账单 | Parcel 计费/财务 | 接收测量和作业计费依据 | 无确认时不自动补收，不覆盖已核准历史 |

对外或跨系统交换使用受控接口和对应鉴权；WMS 可投影必要信息以便作业，但投影不是源系统权威。单库联合查询可供授权报表，关键写操作必须经过拥有者的业务规则。

### 3.2 标识与范围

- 包裹内部 ID、订单内显示序号、客户订单号、承运商跟踪号、箱袋码和设备编号是不同对象。
- 外部标识解析需考虑租户、客户/发码方、标识类型、系统来源、有效时间和关联对象；既要允许多个别名，也不能假定所有外部条码全局唯一。
- 如果一个别名存在多个同样有效的候选，返回 AMBIGUOUS 并要求授权人工消歧；不能自动选第一个。
- 客户参考号的唯一范围须按业务合同明确。默认建议至少按租户、客户及来源约束；不同客户允许相同参考号。
- 用内部 ID 或受控复合键关联，不将演示原型中的 P1/P2 当作全局唯一身份。
- 若使用 GS1 SSCC，按真实申请主体和规范分配校验；平台内部编码不因长度类似就声称是 GS1 SSCC。[S1]

### 3.3 主要对象和约束

以下为逻辑对象，不代表真实数据库现有表名。

| 对象 | 关键属性 | 关系与约束 |
| --- | --- | --- |
| Warehouse | tenant_id、经营方、地点、时区、启停 | 引用统一场所；与注入方案可多对多且有有效期 |
| StationPiece | piece_id、warehouse_visit_id、parcel_id 可空、claim_state、arrival_state | 代表一次现场作业，不确定来源不得伪造正式包裹 |
| IdentifierAlias | type、value、issuer、source、owner_scope、valid_from/to、target | 同值可在不同作用域存在；模糊匹配要消歧 |
| ScanObservation | command_id、action、subject_ref、source、event_at、recorded_at、actor、device | 扫描事实与业务确认分离；有撤销/纠错依据 |
| Measurement | type、value、unit、source、device、captured_at、quality、supersedes | 原始值不覆盖，复核和作废追加记录 |
| Container | kind、container_id、warehouse、status、seal/version | 物理实例；可循环笼车资产单独管理 |
| Membership | parent_id、child_kind/id、effective_from/to、action/evidence | 单一有效直接父级；验证无循环；保留历史 |
| SortDecision | rule_version、input_refs、target、reason、decided_at | 只做获得授权的现场决定；渠道重选由拥有者批准 |
| Handover / Line | plan_version、sender、receiver、objects、actual_dispatch、ack | 计划/交出/接收事实分离；支持部分和汇总回执 |
| ExceptionCase | type、object、priority、state、owner、hold_action、evidence | 暂扣与异常可并存；需要原因、权限及解除条件 |
| LabelAttempt | label_ref/version、provider_status、print_attempt、print_status、operator | 购单、文件、打印和贴标事实分开，未知不能造成功 |
| ChargeEvidence | charge_basis、operation_id、quantity、source_version | 只证明发生了什么，不自行成为应收账单 |
| Audit / Integration event | stable event_id、aggregate_id/version、occurred_at、received_at、tenant、source | 保存因果关系；必要时可靠发布，不承诺跨系统恰好一次 |

### 3.4 多层装载规则

包裹可以在袋内，袋可以在笼车内；真实的直接父级不得在同一时刻冲突。作业区和运输清单是位置或逻辑集合，不是物理父级。解除绑定应闭合旧关系并新增记录；不得覆盖历史来制造从未发生过的移动。

因节点转运或重新包装，可以先后处于不同父级或不同设施；必须有可追溯的交接或纠正依据。外部袋扫描未展开内部件时，只记录袋级观察。


## 4. 状态模型与不变量

### 4.1 使用多个状态维度

| 维度 | 建议值 | 负责领域 | 说明 |
| --- | --- | --- | --- |
| 认领 | UNMATCHED、AMBIGUOUS、MATCHED、CLAIM_REVOKED | WMS | 关联前允许未知客户；撤销是新事实，不删历史 |
| 到仓 | OBSERVED、RECEIPT_PENDING、ACCEPTED、REJECTED | WMS/协议指定方 | OBSERVED 是现场观察，ACCEPTED 须有收货确认依据 |
| 现场位置 | IN_STATION、IN_CONTAINER、DISPATCHED、LOCATION_UNKNOWN | WMS | 与异常、交接、运输状态并存 |
| 业务异常 | OPEN、ON_HOLD、RESOLVED、CLOSED | WMS/异常域 | ON_HOLD 限定受影响动作，不能静默改为通过 |
| 箱袋 | OPEN、SEALED、REOPENED、DISPATCHED、CLOSED | WMS | 允许按授权重开并记录，不允许修改封闭后的既有明细 |
| 交出进度 | PLANNED、PARTIAL_DISPATCHED、DISPATCHED | WMS/运输域 | 按计划和实际交出批次派生；可在尚有未交出的件时接收其他批次的回执 |
| 接收/对账进度 | ACK_PENDING、PARTIAL_ACK、DISPUTED、CONFIRMED | WMS/运输域 | 与交出进度并存；确认范围和证据粒度必须明确，汇总确认不等于逐件确认 |
| 外部面单 | NOT_REQUESTED、REQUESTED、READY、FAILED、UNKNOWN、VOIDED | 物流领域/外部渠道 | READY 是文件/单号有效，不代表打印或贴标 |
| 打印与贴标 | NOT_PRINTED、PRINT_PENDING、PRINTED_CONFIRMED、PRINT_UNKNOWN、APPLIED_CONFIRMED | WMS/打印执行方 | PRINT_UNKNOWN 不等于未打印；贴标需现场确认 |
| 运输 | 由 Parcel 运输/轨迹域定义 | Parcel | WMS 出库不自动等同真实运输、清关或签收 |

状态值为契约建议；实际集成时先映射现有 Parcel 状态和事件语义。状态派生不得抹掉事件来源、原始值和历史。

### 4.2 核心不变量

| 编号 | 规则 |
| --- | --- |
| INV-01 | 客户预报、现场观察、收货确认、交出声明、对方接收和最终签收分别记录，不能互相推导成已经发生。 |
| INV-02 | 无预报作业件可未关联 Parcel；缺少授权的客户归属或出库依据时不能伪造正式包裹和交接结果。 |
| INV-03 | 包裹稳定内部身份与每一次作业访问、外部单号、承运商标签相互区分。 |
| INV-04 | 一个有效实物只允许一个直接物理父级；逻辑批次不是物理装载关系；历史移动与封袋操作可追溯。 |
| INV-05 | 收货、分拣、装袋、出库、收方接收均可按单件、物流单元或授权汇总级产生，但证据精度不能被提升成未执行的单件确认。 |
| INV-06 | 相同命令重试与不同环节的合法重复扫描分开。结果只对相同命令幂等，不能对包裹一生只允许一次扫描。 |
| INV-07 | 原始测量、授权修正、申报重量、计费重和财务账单相互区分；原有报价快照不被仓库测量覆盖。 |
| INV-08 | 现场作业成功不代表外部请求成功；请求超时、打印未知、回传待核实均可存在。 |
| INV-09 | 规则决策记录使用的规则版本、生效时间、适用范围、输入和原因；实际事件可追加纠正，不通过改旧记录伪造历史。 |
| INV-10 | 数据和命令始终受租户、企业、客户、站点、岗位及责任方授权约束。 |
| INV-11 | WMS 出库不等于承运商接收，更不等于进口放行、最终派送或签收。 |
| INV-12 | 设计以单一现场执行权威为前提；外部合作方声明及汇总回执应注明来源和确认精度。 |

### 4.3 代表性状态转换

| 资源 | 前状态 | 命令 / 事实 | 目标状态 | 前置条件及拒绝 |
| --- | --- | --- | --- | --- |
| 到仓作业件 | 不存在 | 扫描 OBSERVE | OBSERVED | 设施、操作人有权限；允许无预报；写入命令 ID |
| 到仓作业件 | OBSERVED | 确认收货 | ACCEPTED | 身份或可受理例外明确、协议允许；不匹配可保持待认领 |
| 认领 | UNMATCHED/AMBIGUOUS | 认领 | MATCHED | 选定唯一授权候选并留证；不可跨租户 |
| 认领 | MATCHED | 撤销认领 | CLAIM_REVOKED | 有权限、原因、影响分析；已交接不可静默抹去 |
| 箱袋 | OPEN/REOPENED | 封袋 | SEALED | 内容、渠道及约束检查通过；保存明细版本 |
| 箱袋 | SEALED | 解封 | REOPENED | 授权、原因和旧封签；如已外部交接需责任方确认 |
| 交接（交出） | PLANNED/PARTIAL_DISPATCHED | 交出部分明细 | PARTIAL_DISPATCHED/DISPATCHED | 实物可交，已交集不重复；实际数量小于计划不造丢失结论 |
| 交接（接收） | ACK_PENDING/PARTIAL_ACK | 提交对方汇总确认 | PARTIAL_ACK/DISPUTED/CONFIRMED | 对应批次已有交出事实；允许其他批次尚未交出；确认仅限约定的汇总粒度，禁止推导单件确认 |
| 交接（接收） | ACK_PENDING/PARTIAL_ACK | 提交逐件确认 | PARTIAL_ACK/DISPUTED/CONFIRMED | 对应批次已有交出事实；每项身份及来源有效；短少、多出保留差异 |
| 异常 | ON_HOLD | 解除暂扣 | RESOLVED | 授权、原因、证据和所需外部许可 |
| 标签 | REQUESTED | 外部超时 | UNKNOWN | 记录原请求，不无条件再创建；查询/人工核实 |

### 4.4 事实纠正

错误数据以纠错动作追加，引用被纠正的记录并说明原因、操作人、时间和审批。查询投影可展示最新有效值，同时可追溯原记录。已经真实交接、打印、预报或外部申报的副作用不通过回滚软件字段假装未发生；按相应的撤销、截单、补偿或人工处理流程执行。

## 5. 测量、计费与财务协同

### 5.1 四种重量

| 类型 | 来源 | 修改权限和用途 |
| --- | --- | --- |
| 申报重量 | 客户下单 | 原始客户申报与报价输入；修订须版本化 |
| 原始实测重量 | 电子秤、DWS、人工 | 保留设备和原值，不直接改历史报价 |
| 复核采用重量 | 授权人员或合规流程确认 | 引用原实测或修正记录；质量及审批状态可查 |
| 计费重量 | Parcel 计费域按合同和实际依据计算 | 可按采购/销售/前程分别计算，保留规则及版本 |

尺寸、测量单位、除数、进位、最低收费、逐件/合票及费用基数以所选合同为准；不得把一个渠道的规则强加给所有渠道。[S2]

### 5.2 示例：申报 0.8 kg，实测 0.95 kg

以下为可复算的虚构教学参数，不是承运商价格。

- 一件包裹申报 0.800 kg，原报价时使用该值。
- 仓库秤重 0.950 kg；记录原始实测和设备来源。
- 若该示例合同不计材积、100 g 向上进位、每 kg 100 元、无最低费和其他附加费：原计费 0.8 kg / 80 元；复核后计费 1.0 kg / 100 元；差额 20 元。
- 系统建立重算申请或候选版本；当前客户报价快照和原始账单不变。是否产生应收、何时通知或补收，按合同及授权审批处理。
- 当尺寸、地址、规则、最小收费、采购/销售条款、币种或包裹数量不同时，上述结果不适用，应重新完整计算。

### 5.3 操作费证据

换标、拍照、包装、仓租等作业是否收费，由计费域、合同和授权规则决定。WMS 最低输出：作业类型、对象、实际数量、单位、发生时间、客户/设施、规则或任务版本、操作人与证据。账单冲正和已收款核销由既有财务域执行；不能因为重复消息重复计费。

## 6. 现场角色、权限及数据安全

### 6.1 角色与作用域

| 角色 | 主要权限 | 约束 |
| --- | --- | --- |
| 客户/货主 | 查看授权预报、包裹、差异与账单 | 不访问其他客户或供应商成本 |
| 收货员 | 到仓扫描、现场观察、授权范围内收货与测量 | 仅分配仓库；不修改合同/价卡 |
| 分拣员 | 查看当前任务、分拣、装袋 | 只显示完成任务所需资料 |
| 交接员 | 生成/确认交出清单、记录凭据 | 不能代表接收方虚构确认 |
| 仓库主管 | 复核、认领、异常处理、授权解封 | 高风险动作需原因和可配置审批 |
| 物流运营 | 渠道、运输和外部协调 | 不直接改 WMS 审计事实 |
| 财务 | 处理应收应付、账单和差异 | 不通过财务页面覆盖实测或实物动作 |
| 合作仓/承运商 | 接收授权任务、提交自身声明 | 租户、机构、设施和作业限定，不得代表另一方 |
| 租户管理员/审计 | 配置权限、审阅日志 | 权限管理与业务审计分离，紧急访问留痕 |

最终角色可映射现有 IAM，不预设已有授权结构。权限至少评估租户、企业、客户关系、作业仓、资源、动作、字段与有效期；订单号不可作为授权凭证。

### 6.2 隐私、导出与设备

- 仓内作业屏只显示作业需要的收件信息；电话号码和地址按角色及场景脱敏，不展示采购底价或利润。
- 照片及打印文件按业务必要性保留，访问授权和下载审计须配置；保留期限、跨境传输和删除策略由部署地区、合同及适用规则确认。
- 扫码枪按输入设备处理；秤/DWS、打印机需支持设备身份、单位、校准状态、错误码和恢复策略。自动设备必须经过适配和现场验证，不能将任何型号宣称已兼容。
- 手工修改重量、跳过复核、认领争议件、解封、撤销、导出敏感清单等应记录原因、操作者、时间与授权依据。

## 7. 规则配置与时间

### 7.1 规则生命周期

草稿 → 校验 → 审批/发布 → 生效 → 停用/到期。每条规则具备作用域、条件、决策、优先级、有效期、版本、创建与发布记录。测试环境与生产规则区分；生产运行必须可解释命中和拒绝原因。

- 条件可包括租户、客户、仓库、渠道、目的地、邮编、货物属性、测量、时间、上游状态及业务授权。
- 缺失必要条件为 UNKNOWN；无命中或最高优先级并列阻止自动确定，进入待处理。
- 按客户及承运商协议定义混装、整箱或单包交接、容器上限与禁配；先校验合规/责任，再考虑效率。
- 仓内规则可建议目标区域，不可直接改变运输采购合同或重写已确认标签。
- 规则变更对未完成业务的适用点必须明示；已发生动作保存原版本，重新决策新增版本并留历史。

### 7.2 时间及截止

记录实际发生时间、系统接收时间及来源，采用可比较的绝对时间并保存原始时区；仓库营业和截单使用正确 IANA 时区及有效业务日历。遇到夏令时重复或不存在的本地时间应要求明确处理，不静默猜测。迟到、乱序和冲突的外部事件保留原始数据并触发对账；事件展示可重排，不能凭收到顺序覆盖更可靠的事实。

### 7.3 仓库与注入方案关系

仓库是物理设施；运输交接点、承运商注入点、合同计费起点与 Zone 为不同概念。相同设施可用于多合同/渠道，不同方案可以具有不同有效期、资格、责任、费用和目的地约束。WMS 只消费获得授权的作业指令，不自动从仓库邮编重算合同起点。


## 8. 接口、事件与一致性契约

### 8.1 同应用与外部接入

- Parcel 内部可按真实架构使用进程内接口和一个本地事务；不能假定已经采用任何框架、数据库版本或服务拆分。
- 外部系统调用使用认证授权的版本化 API、文件或事件适配；复用现有 BIP 的适配能力前须完成接口、数据映射、权限、回执和故障联测。
- 必须保持来源系统、来源账号、原始单号、原始事件和可信状态；未知来源不得作为已确认交接。
- 本模块的命名和路径均为候选示例，不代表已存在。兼容真实工程时采用项目既有 API 风格并维护版本治理。
- 若需对接合作仓，明确可查询、可提交哪些动作、字段范围、是否逐件回执、失败补偿、版本和 SLA；仅支持汇总回执的合作方按汇总证据展示。

### 8.2 建议命令/查询清单

| 方法/路径（示意） | 用途 | 成功结果和重要约束 |
| --- | --- | --- |
| POST /v1/wms/receipt-observations | 记录到仓扫描或现场观察 | 201：返回作业件、认领/观察状态；未匹配不伪造 Parcel |

| POST /v1/wms/containers | 创建物流箱袋或装载实例 | 201：生成内部实例；外部码可关联 |
| POST /v1/wms/containers/{id}/memberships | 扫描装入 | 201：记录物理直接父级；并发冲突返回 409 |
| POST /v1/wms/containers/{id}/seal | 封袋 | 200：保存内容版本；缺少许可或状态不符拒绝 |

    "value": "DEMO-UNMATCHED-123",

### 8.4 接收方只确认总数的示例

场景：仓库逐件交出 97 件；接收方只能提供总数 96 件。以下是服务端保存并计算的汇总视图示例，不是可由客户端直接写入的完整请求；交出数量、差异和核验结果依据已有证据计算。

~~~json
{
  "handover_id": "HO-001",
  "acknowledgement_type": "AGGREGATE",
  "sender_dispatched_count": 97,
  "receiver_declared_count": 96,
  "receiver_identity": "CARRIER-01",
  "evidence_ref": "POD-DEMO-01",
  "piece_level_acknowledgement": false,
  "reconciliation": "UNIDENTIFIED_DIFFERENCE",
  "difference_count": 1
}
~~~

系统应显示“数量差异 1 件，具体包裹待核实”，而不是宣称某个指定包裹已收到或已丢失。如果后续获得有效逐件回执，追加明细并重新对账；不覆盖原始汇总回执。

`receiver_identity` 须由已认证主体推导，或与该主体的受权关系核验；不能信任调用方任意填写接收方。操作员录入的纸质或口头声明应标明录入人、证据和核验状态；未验证的手工记录不能冒充接收方已认证回执。

### 8.5 错误、状态码和恢复语义

| 场景 | 建议结果 | 必须行为 |
| --- | --- | --- |
| 身份无效/越权 | 401/403 或按现有安全规范隐藏资源 | 不泄露其他客户的包裹、合同或价格 |
| 必填字段/单位非法 | 400 | 不写入成功作业 |
| 状态不支持、并发父级冲突 | 409 | 返回可处理的原因和当前版本；不部分成功 |
| 相同幂等键不同请求 | 409 IDEMPOTENCY_CONFLICT | 不执行新请求 |
| 存在多个匹配对象 | 扫描观察可成功记录；业务匹配为 AMBIGUOUS | 不自动绑定，呈现授权消歧流程 |
| 货物条件未知或规则冲突 | 422 或待处理任务 | 说明可继续处理的动作；不宣称放行 |
| 外部请求已受理仍在处理 | 202 + 操作查询地址 | 请求状态与实际运输状态分离 |
| 外部调用超时/结果不确定 | UNKNOWN/待核实 | 按对方契约查询和对账，禁止盲目再购单 |
| 上游/设备短暂不可用 | 明确失败或待重试 | 不将未提交动作显示成已成功 |

实际 HTTP 状态码以现有工程规范为准，但不得丢失上述语义。

### 8.6 事件和投影

业务操作与需发送的集成事件应在同一本地事务中可靠记录；后续投递允许重试，消费方根据 event_id 和业务版本去重、校验并处理乱序。Outbox 不保证端到端恰好一次，外部副作用仍需对方的幂等、查询或人工对账。[S3][S4]

| 事件（示例） | 语义 | 不得推导 |
| --- | --- | --- |
| WarehouseArrivalObserved | 设施现场观察到某件/箱袋 | 客户已正式交付或承运商已接收 |
| WarehouseReceiptAccepted | 收货方按授权规则确认接收 | 已选最终运输渠道 |
| MeasurementRecorded | 原始测量事实及来源 | 已批准计费或已向客户收费 |
| ContainerMembershipChanged | 物理装入或移除关系改变 | 所有内容均已由承运商接收 |
| WarehouseDispatchConfirmed | 仓库确认交出指定实物 | 对方确认接收、清关或签收 |
| HandoverAcknowledged | 接收方给出逐件或汇总声明 | 超出声明精度的逐件事实 |
| LabelPrinted / LabelPrintUnknown | 特定打印尝试的结果 | 标签已实际贴在正确包裹 |
| WarehouseExceptionOpened | 指定对象有异常 | 可以自动取消或销毁货物 |

示例事件封套：

  "event_id": "evt-demo-0001",
  "event_type": "MeasurementRecorded",
  "schema_version": "1.0",
  "tenant_id": "TENANT-DEMO",
  "aggregate_type": "Measurement",
  "aggregate_id": "MEA-001",
  "aggregate_version": 1,
  "occurred_at": "2026-11-05T02:16:00Z",
  "recorded_at": "2026-11-05T02:16:02Z",
  "source": "WMS",
  "correlation_id": "cmd-20261105-0002",

    "station_piece_id": "SP-001",
    "measurement_id": "MEA-001",
    "quantity": "0.950",

    "quality": "RAW"

~~~

事件只包含消费方必须的数据；不默认广播收件人手机、完整地址或采购价格。

## 9. 持久化、并发与迁移建议

### 9.1 设计假设

在真实工程未核对前，不冻结技术栈或物理表名。可采用模块化单体共享现有数据库或与现有服务边界兼容的方案；同库不意味着跨域任意改表。内部组合操作若在同一数据库和同一事务边界内，可按真实实现使用原子事务；跨系统不能假设一个本地事务覆盖外部设备或承运商。

### 9.2 建议约束

- 使用服务器生成的稳定内部 ID；外部编号有来源、类型、所有者及有效期；客户参考唯一范围按租户/客户/来源与合同设计。
- 命令结果和业务变更在同一事务边界保存；相同 ID 与相同内容重放安全，不同内容冲突。
- 有效物理直接父级采用数据库约束及并发控制，形成关系之前检查父子租户、设施、允许嵌套和循环；多资源锁顺序统一以避免死锁。
- 计划清单、实际交出清单、接收方声明、核对结果分别保存，支持数量和单件精度；不能让应交数量覆盖实交。
- 金额、重量、尺寸按合同需要使用适当精度和单位；复核、货值、财务规则版本与舍入点明确，不用演示浮点行为作为生产账本方案。
- 租户与客户/合作方不是同义词；跨域关联和导出需同时执行数据范围授权。
- 重要作业、证据、状态转换、重发、人工修复留审计；纠正记录指向原事实。

### 9.3 从原型迁移前的核对

1. 盘点真实包裹及运单的 ID 稳定性、外部标识作用域和现有 API；不能使用演示数据的 P1/P2 作为全局主键。
2. 检查客户参考号的约束是否适合多客户；演示导入按参考号全局判重的行为不能直接假定为生产规则。
3. 对历史订单缺少真实分件、渠道或注入事实的情况标记 UNKNOWN，不从整票重量推断每一件重量，不拼造承运商子单号。
4. 将现有交接的计划、实交、实收字段及状态做映射；演示原型的“数量必须一致、整单改运输中”不能直接替代部分交接。
5. 核对原始报价快照与财务凭据的现有权威与版本，保证新增测量不会覆盖；未能解释的历史数据进入人工核对。
6. 设计灰度启用、双读对账、切换与回退，以及试点组织、站点和设备范围。任何真实数据迁移须另有可执行计划与验证。

## 10. 页面与作业体验

### 10.1 管理端

| 页面 | 主要操作 | 必须显示 |
| --- | --- | --- |
| 仓内工作台 | 按仓/班次查看待收、异常、待分拣、待交 | 数据时间、单位、权限范围；指标不能混淆票和件 |
| 到仓与预报 | 查询预报、扫描、待认领、收货差异 | 来源、候选匹配数量、到仓与确认区别 |
| 包裹作业详情 | 逐件查询扫描、测量、位置、异常、箱袋 | 身份别名、事件时间/来源、原始与纠正 |
| 分拣及规则 | 规则草稿、模拟、发布、目标和冲突 | 生效版本、作用域、命中依据、最高冲突 |
| 箱袋 | 建立、装入、移出、封闭、解封、拆箱 | 直接父级、内容版本、操作历史 |
| 出库与交接 | 计划、部分交出、对方确认、对账 | 预计/实交/接收分开；单件/汇总精度 |
| 异常工作台 | 暂扣、分派、认领、证据、释放 | 当前限制动作、责任人、时效和处理日志 |
| 维护与审计 | 仓库、区域、设备、岗位、事件源与权限 | 配置生效版本、权限和变更依据 |

### 10.2 PDA / 扫码工作站

1. 选择仓库、工作站和作业模式；模式标识必须清楚，避免把收货扫码误当出库扫码。
2. 连续扫描时给出声音/颜色/文字反馈，成功、待认领、重复命令、冲突和暂扣的提示不同；不能只依赖颜色。
3. 展示必要的识别、渠道和目的地信息，明确数量/重量单位；不同岗位隐藏无权字段。
4. 不因界面关闭就声称动作已提交；显示已保存、等待提交、结果未知及失败，可查询当前包裹结果。
5. 大规模设备接入前，在真实仓库验证扫码速度、打印可靠性、网络和错误恢复。

### 10.3 离线和不可用策略

P0 默认在线确认；客户端断网时不得显示服务端已提交。仓库应有经主管批准的人工应急 SOP 和事后核对入口。读取缓存时标记“非实时”。

P1 若需离线，须另行验证设备身份、离线授权有效期、命令稳定 ID、队列加密、补传排序、冲突、超期回收和人工复核。离线不能擅自购买/作废外部面单、确认对方接收或自动产生财务收费；外部副作用必须有明确回执。


## 11. 集成边界与产品协同

### 11.1 IDP Parcel 内部

| Parcel 能力 | WMS 输入/输出 | 约束与待核验 |
| --- | --- | --- |
| 商业主体和客户 | 查询客户、合作方、角色和授权 | 不新建第二套客户主账；真实模型待审计 |
| 运单与包裹 | 预报、客户参考、包裹 ID 和历史标识 | 同一 Parcel 可多次进仓；未知件先作为现场作业件 |
| 渠道与方案 | 产品、渠道、节点、规则版本及作业约束 | WMS 的格口策略不擅自变更运输承诺 |
| 追踪 | 发送来源可识别的收货、分拣、交接事实 | 轨迹域保留原始事件并区分来源，不能把出库翻译为签收 |
| 计费 | 发送实测、复核和操作费证据 | 价卡与账单由计费域负责；异常不可自动覆盖快照 |
| 异常及客服 | 双向关联异常对象和处理任务 | 仓内处理关闭不自动关闭运输/财务争议 |
| 身份与审计 | 复用现有有效身份、权限及审计能力 | 真实能力必须核验，不默认前端演示身份可用 |

### 11.2 BIP、Prism 与 EER

- BIP：面向合作方、外部 TMS/WMS、承运商等连接时，优先评估现有 BIP 已有连接器、映射、认证、重试和审计；缺口增量解决。单次仓内扫描是否需要经过 BIP 以现有部署和业务可靠性需求为准，不设无条件同步依赖。
- Prism：处理客户已有的复杂商品库存、库位和仓内履约；具体对接须以既有协议和仓库责任为准。Parcel 小包仓作业不能覆盖 Prism 已确认的库存事实。
- EER：作为已开发的企业执行基础设施，可评估用于长时异常、审批或跨域协调，前提是 EER 的目标、业务命令和验证契约已经核验；扫描、称重等日常事务不强制经过 AI 或 EER。
- 任何外部设备或实时控制器的安全控制保留在其责任边界；系统不能把上层业务状态直接当成设备物理动作成功。

### 11.3 适配与回调验收

每家外部系统需有对接档案：API/文件版本、身份授权、请求和响应样例、唯一键规则、事件级别、回调签名/认证、重试、时区、单位、状态映射、撤销语义、容量和对账责任。异步处理应保留原始回执、规范化结果、来源、映射版本、未映射队列及人工处理记录。

一个外部系统只有箱袋级别的到货，系统显示“箱袋已到货/件级未复核”，不推定箱内所有包裹都已扫描。汇总接收的数量差异不定位到具体包裹。

## 12. 可用性、监控与数据治理

| 项目 | 验收/度量方式 | 目标如何确定 |
| --- | --- | --- |
| 扫描链路 | 从扫描提交到服务器返回可核验结果的 P50/P95/P99、错误率、重复率 | 根据真实设备、网络和业务峰值试测后约定 |
| 吞吐 | 件/小时、设备/站点并发、峰值队列和成功写入 | 区分订单/包裹/箱袋，按场景、班次和货型建立基线 |
| 交接差异 | 计划、实交、接收的件级及汇总差异 | 记录差异数量、未识别数量、关闭时长，不直接把未到件当丢件 |
| 异常处理 | 暂扣量、待认领时长、超时任务及原因 | 各仓确认责任方与工单时限 |
| 集成 | 事件延迟、失败、重试、积压、去重冲突和对账差异 | 由每个合作方接口契约规定 |
| 恢复 | 系统/设备不可用、数据库故障和恢复演练 | 部署前确认 RPO/RTO、可用性及人工 SOP |
| 权限 | 租户、客户、仓和字段越权测试 | 每次发布和权限变更回归 |
| 数据留存 | 配置、删除、证据、防篡改和恢复演练 | 依据适用地区、合同和企业政策设定 |

上述是需要建立的指标体系，不代表任何现有效率、容量或服务水平已经达标。设备型号和网络条件应进入测试报告。

| A23 | 98 件中 1 件破损 | 保留 1 件异常，其他符合条件的 97 件可继续 |
| A24 | 计划 100 件，部分交出 97 件 | 97 条有交出事实，剩余待处理；不需要填假数凑齐 |
| A25 | 仓库交出 97，收方仅汇总确认 96 | 展示数量差异 1、具体单件未确定；不虚构 96 条逐件确认 |
| A26 | 收方提供 96 条有效逐件回执 | 按逐件关联，剩余及额外回执分别核对；留来源和事件时间 |
| A27 | 已交出后用户试图删除并重建 | 保留历史；后续截单/补交/纠错必须形成新事实与权限记录 |
| A28 | 换单前扫描旧标 | 查到受权包裹及旧标签版本；不凭条码自动越权 |
| A29 | 外部买单超时 | 状态 UNKNOWN，保留原请求并查询/对账，不盲目创建第二订单 |
| A30 | 打印机提交后回执超时 | PRINT_UNKNOWN，不能标为未打印；重打留原因且不再次购单 |
| A31 | 处理费事件重送两次 | 费用依据只记一笔业务事实；正式应收由计费域规则产生 |
| A32 | 已生成报价后实测变化 | 生成候选重算和差额，原报价快照及账单不可被覆盖 |
| A33 | 跨渠道和客户混装 | 有明确合同、责任和设施授权时按规则允许；未授权时给出可解释拒绝 |

### 13.4 合作方、时间、安全与恢复

| 编号 | 场景 | 通过标准 |

### 13.5 测试层级

- 领域规则：身份消歧、状态转换、金额/单位、物理父级不变量。

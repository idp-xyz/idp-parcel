# 1　系统边界与工作约定
## 1.1 当前能够完成什么
可维护注入节点、合同计费起点、分区方案与起讫映射、产品规则、采购／销售价卡、客户专属价、附加费、客户额度、供应商与合同；可逐件录入包裹，比较报价并说明拒绝原因；可模拟下单成功、明确失败与结果未知；可记录交运、轨迹冲突处理、售后申请和采购账单核对。

## 1.2 使用前必须知道什么
| 项目 | 当前口径 |
| --- | --- |
| 数据保存 | 核心业务数据保存在当前浏览器标签页的 sessionStorage；刷新通常保留，关闭会话后不保证保留 |
| 维护中心 | 来源、映射、通知和成员的部分设置仅保存在页面运行状态；刷新会重置 |
| 日期 | 大量初始场景以 2026-09-10 为演示业务日期；不等于实际今天 |
| 身份与权限 | 页面展示管理员身份和角色配置；没有完整登录、服务端权限或审批隔离 |
| 外部服务 | 不发送真实承运商请求，不进行支付、退款、索赔赔付或消息通知 |
| 支持范围 | 内置美国、德国、英国、日本、澳大利亚示例；不是全球地址和邮编数据库 |

建议先用演示数据完成闭环，再输入自己的教学参数。修改价卡、汇率与附加费后，应重新试算；不要将截图中的旧金额当作最新报价。涉及真实经营的数据，应在正式接入与校验完成后再迁移。

## 1.3 推荐分工
运营负责包裹、地址、交运与异常事实；定价负责区域、重量规则、附加费和售价；采购负责渠道、合同与成本；财务负责账单凭证、差异和损益。以上是业务分工建议，当前原型不强制执行职责分离。

# 3　基础配置与首次业务闭环
## 3.1 推荐配置顺序
1. 在供应商与合同确认供应商已启用，协议账户与渠道供应商一致；建立有效的采购合同。
2. 在渠道资源确认已有渠道启用、目的地正确、时效和每日容量合理。新建供应商不会自动生成可调用的渠道。
3. 在交货与注入方案建立节点及合同方案，再在国家与计费分区建立分区方案和起讫映射。采购和销售分别维护；另建附加费／禁运清单。测试同一收件地址在不同合同起点的命中结果。
4. 在物流产品中选择覆盖国家、候选渠道、允许货物、单件最大实重、最低毛利率及选择策略。
5. 建立采购价卡与销售价卡，绑定各自分区方案、目的地范围；采购卡还须选择合同与注入方案。补齐每个 Zone 的重量价表、进位、最低收费和有效期。
6. 在 Surcharge 附加费配置附加费范围、计费基础、叠加关系与生效日期；特别核对燃油费是否包含其他固定费用。
7. 在客户与授信确认客户启用、结算方式和可用额度；需要专属价时关联该客户。
8. 使用报价试算核对正常、偏远、禁运、进位边界、材积和额度不足场景。

## 3.2 第一次演练
使用初始数据选择星河跨境、美国产品、邮编 90001、商业地址及 1 件 0.8 kg／25×18×10 cm 包裹，业务日期选择 2026-09-10，始发中国 200000、当地计划交货时间 10:00。若要复现第 21 章金额，将渠道限定为 Landmark · 美国标准。完成试算，阅读采购与销售分解，补齐收件信息后选择成功模拟并创建。

随后到订单详情核对逐件信息与报价快照；到揽收与交接选择同渠道、同交货方案订单，填写交接参考号与实际件数；最后在结算与产品收益录入一笔教学采购实收并完成核对。全过程不使用真实面单发货。

完成标志：能解释为什么选中该渠道、每笔费用从何而来、订单执行结果是什么，以及采购预估与实际录入之间的差异。不要只检查“总价有数字”。

# 4　国家地址、分区方案与 Zone
国家与邮编用于标识地址；Zone 是某个计费分区方案中的收费分类。同一国家可分多个 Zone，多个国家也可归入同一 Zone。同名 Zone 2 在不同方案中不是同一个计费对象。

## 4.1 地址 分区与清单分别维护
| 对象 | 含义与操作 |
| --- | --- |
| 国家地址规则 | 原型支持国家的格式提示；不代表全球地址库或真实服务可达性 |
| 计费分区方案 | 采购／销售方向、适用渠道、目的地或起讫模式、日期、版本及合同来源 |
| 起讫映射 | 在所选方案中，将合同计费起点和目的地映射到某个 Zone |
| 附加费／禁运清单 | 独立的邮编集合；按方向、渠道、注入方案与日期限定，用于附加费触发或拒绝 |

入口：国家与计费分区 → 计费分区方案 → 选择／新建方案 → 维护映射 → 测试起讫地址 → 发布 → 关联价卡。先保存草稿、补齐映射，再发布。CSV 的完整字段和操作见附录 C。

## 4.2 命中与缺价处理
先选择候选交货／注入方案及唯一适用价卡，再在该价卡绑定的分区方案内查区。起讫模式使用合同计费起点＋目的地；目的地模式使用所选合同方案的目的地规则。物理节点地址不自动替代合同计费起点。

邮编统一转大写并去掉空格、连字符。目的地前缀与数字范围是“或”，排除前缀先排除该行。数字范围两端包含，按对应长度的数字前段匹配。前缀和范围都为空，是该方案内明确录入的全国映射。

多条映射命中时，显式优先级数值最大者胜出；最高并列即报冲突。不会按前缀长度、录入顺序或区域名称猜选。不同方案中相同优先级互不冲突。

无匹配 Zone，或已命中的 Zone 没有费率，默认停止该方案报价。仅当价卡配置了本方案内的兜底 Zone、对应费率及合同依据时才允许兜底，并记录使用原因。显式全国映射与“缺价兜底”是两种不同规则。

采购 Zone 和销售 Zone 独立解析。采购偏远费是否触发，也不能直接复制为客户销售偏远费。禁运清单命中时拒绝其作用域内的报价，不能用兜底价绕开。

示例：演示承运商 A 向美国 10001 派送，LAX 合同起点命中 Zone 8，EWR 合同起点命中 Zone 2；销售仍可使用美国东部分区。该映射为教学合同假设，不是承运商真实分区表。

# 5　价卡建立、发布与版本
| 字段组 | 字段与用途 |
| --- | --- |
| 基本范围 | 名称、采购／销售、币种、有效起止日期、状态、备注 |
| 采购关联 | 渠道、采购合同、一项或多项注入方案；合同与方案币种必须与价卡一致 |
| 销售关联 | 物流产品；客户为空为标准售价，指定客户为专属售价 |
| 分区绑定 | 绑定本方向分区方案及目的地国家；费率 Zone 必须属于该方案 |
| 缺价兜底 | 默认关闭；启用须明确兜底 Zone、费率及合同原因，不能跨方案借区 |
| 重量规则 | 区域、计费模式、阶梯、首续重、最大计费重 |
| 计费参数 | 材积除数、进位克数、逐件／合票、每票最低收费 |
| 附加费模式 | 当前初始价卡使用独立规则；进入 Surcharge 附加费维护费用 |
| 治理字段 | 草稿／已发布／已停用、版本、变更原因、历史记录 |

操作：价卡与重量阶梯 → 新建或复制 → 基本信息 → 区域与重量 → 计费与附加 → 试算与版本。复制先产生草稿，检查关联对象和日期后再发布。切换分区方案会清空原 Zone 费率关联，须重新添加；不会仅因 Zone 代码相同就沿用旧价格。发布前补齐区域，消除重量空档、重复区间及冲突的生效价卡；提交时填写能说明业务原因的文字。

采购卡在渠道、合同、注入方案、目的地国家和有效期范围相交时冲突；销售卡在产品、客户、国家和有效期相交时冲突。不同注入方案或不相交国家可使用不同价卡。发布时检查冲突，完整报价还会再次要求唯一适用价卡，不能依赖列表顺序。客户专属销售价优先于产品标准销售价；如果已选专属价不能覆盖目的地区域，系统不会自动换成另一张标准价卡，需修复专属价或调整其生效范围。

价卡试算使用所选目的地、邮编与注入方案，测试日期为当前编辑卡的生效首日，尺寸固定为 25×18×10 cm。需要任意日期、尺寸、完整准入和多方案比较时使用报价试算页。价卡级试算不等于整条履约方案已通过服务范围、容量和授信检查。

历史版本用于查看变更和恢复编辑起点。将历史配置恢复为草稿后，仍需重新核验再发布。原订单报价快照不因当前价卡变化而重新计价。产品基本资料版本与产品规则修改记录是两套行为：规则修改写审计记录，但当前实现不自动增加产品资料版本号。

独立附加费模式下，旧的内嵌燃油、操作和偏远字段不再重复计收。最低收费仍属于价卡基础计费步骤，并非在 Surcharge 中再加一次。

# 6　计费顺序与重量口径
采购与销售各使用自己的分区方案和价卡独立执行以下步骤。自主注入的前程还可使用自己的材积与进位参数，因此三者计费重可能不同。前程计算方式见附录 D。

| 顺序 | 运算与判断 |
| --- | --- |
| 1 | 为每个候选方案选择唯一价卡；采购与销售分别按日期、合同起点、目的地解析 Zone |
| 2 | 每件计算材积重，取实重与材积重较大值，得到原始计费重 |
| 3 | 按逐件或合票规则向上进位，检查区域最大计费重 |
| 4 | 按所选重量模式算基础运费，逐件模式先算各件再相加 |
| 5 | 基础运费不足每票最低收费时补差，得到附加费计算的基础金额 |
| 6 | 匹配附加费范围与条件，计算固定费用并处理互斥组 |
| 7 | 形成燃油等百分比费用的基数，计算并处理百分比规则组 |
| 8 | 得到网络段价卡小计；自主注入另加前程与注入费，端到端不重复加费；再换算 CNY |
| 9 | 用完整采购成本比较销售价，校验毛利、额度、渠道及方案容量，排序可用方案 |

长度单位为 cm，业务重量显示常用 kg，内部重量采用整数 g。材积重先将“长×宽×高÷材积除数”得到的公斤数转换为克并向上取整。除数为 0 表示不计材积；支持 5000、6000。

逐件计费：每件分别取大、进位和套价；合票计费：先累计各件取大后的原始克数，再对整票进位并套一次价。不能先把一票的实重与总体积分别合计后取大来替代当前逐件取大逻辑。

产品单件最大重量检查的是实重；价卡区域最大重量检查的是进位后的计费重。材积较大或进位后超限，仍可能被拒绝。所有范围检查和报价应使用最终输入，不能只看秤重。

# 7　三种重量报价与阶梯编辑
| 模式 | 计费方法 | 适用理解 |
| --- | --- | --- |
| 区间整重 | 找到计费重所在阶梯，用整份计费公斤数乘该档单价 | 阶梯只选择单价，不拆分重量 |
| 分段累进 | 各段落入的公斤数分别乘该段单价，最后相加 | 每个阶梯只收费其覆盖重量 |
| 首重续重 | 首重费加超出首重的续重份数乘续重费；份数向上取整 | 不足一份续重按一份计 |

阶梯使用下限不含、上限包含。例如 0—0.5 kg 对应大于 0 且不超过 0.5 kg。比较的是进位后的计费重。阶梯必须从 0 连续覆盖到最大计费重，不得有空档、重叠或重复区域。

编辑入口：价卡 → 区域与重量 → 选择本分区方案的 Zone → 选择模式 → 编辑阶梯或首续重。新增区域可能复制当前模板，必须重新核对价格；批量应用参数前确认目标区域。至少保留一个有效区域费率。

重量 CSV 表头为：from_kg,to_kg,price_per_kg。文件不超过 200 KB、最多 100 个阶梯；公斤最多三位小数，最终转换为整数克。导入后检查连续性、币种及最大计费重，再进行边界试算。该导入用于当前区域的阶梯，不是完整价卡批量导入。

教学例：单价 0—0.5 kg 为 100 元/kg，0.5—30 kg 为 120 元/kg，进位 100 g。实重 0.501 kg 会进位至 0.6 kg；整重方式为 72 元，累进方式为 50＋12＝62 元。实重恰为 0.5 kg 时，仍落在第一档，为 50 元。

教学例：首重 0.5 kg／20 元，续重 0.2 kg／6 元，实重 0.701 kg 先按 100 g 进位为 0.8 kg。超出首重 0.3 kg，需要两份续重，总额 32 元。

# 8　Surcharge：规则字段与适用范围
Surcharge 是基础运费之外的独立费用规则。费用“类别”用于识别和筛选；实际计算由触发条件、单位、金额、币种和叠加设置决定。只把名称改成“超长费”不会自动产生长度判断。

| 字段 | 业务含义 |
| --- | --- |
| 代码、名称、类别 | 代码用于识别规则；类别包括燃油、偏远、操作、住宅、超长、超重、超围长、旺季、地址更正、再派送、退件、其他 |
| 采购／销售 | 确定成本侧还是客户收费侧；两侧需分别配置 |
| 价卡范围 | 可选多张价卡；为空表示在其他条件满足时不限价卡 |
| 区域范围 | 选择同方向的计费 Zone 或地址清单，按对象 ID 判断；任一命中即可 |
| 注入方案范围 | 可限定一项或多项方案；为空表示不再缩小其他字段定义的范围 |
| 客户范围 | 指定客户适用；为空表示所有符合其他条件的客户 |
| 触发条件／阈值 | 确定何时收费；长度为 cm，超重阈值为 kg |
| 单位／金额 | 每票、每命中包裹、每计费 kg 或百分比 |
| 币种 | 价卡币种、CNY 或 USD；百分比也按所选币种处理上下限 |
| 百分比基数 | 基础运费（含最低补差），或再加允许参与燃油的固定费用 |
| 参与燃油基数 | 固定费用是否计入扩展基数；不是自动再加一笔燃油 |
| 最低／最高金额 | 针对整条规则金额限制；最高为 0 表示不封顶 |
| 规则组／组合方式 | 叠加、取高、按优先级选择；空组不互斥 |
| 优先级 | 按优先级组内数值越大越优先；最高并列会报冲突 |
| 阶段、日期、启用 | 报价时或账单确认；有效期两端包含；停用不参与新计算 |
| 版本、原因、备注 | 记录修改依据；备注不改变计算公式 |

适用关系：同一字段内多项是“或”；价卡、区域、注入方案、客户、日期和触发条件之间是“且”。留空范围会扩大适用对象，保存前务必检查。

# 9　Surcharge：触发条件与数量
| 触发条件 | 判定与重要边界 |
| --- | --- |
| 始终适用 | 在规则范围内直接触发，例如每票操作费 |
| 偏远地址 | 命中当前方向、渠道、注入方案及日期适用的偏远清单；不是全平台通用属性 |
| 住宅地址 | 使用显式住宅／商业选择；未知信息不应默认为已核实 |
| 超长 | 每件最长边严格大于阈值；等于阈值不触发 |
| 超重 | 每件实重严格大于 kg 阈值，使用实重而非材积或计费重 |
| 超围长 | 各边排序后，最长边＋2×其余两边之和严格大于阈值 |
| 地址更正／再派送／退件 | 仅账单确认阶段，且相应事件被确认后才参与计算 |
| 人工确认事件 | 仅账单确认阶段，由试算中的确认事实触发 |

| 计费单位 | 数量如何取得 |
| --- | --- |
| 每票 | 至少有包裹触发时计 1；同一规则不会按件重复 |
| 每命中包裹 | 只计满足该规则触发条件的包裹数量 |
| 每计费 kg | 使用整票计费公斤数，即使只有部分包裹触发 |
| 百分比 | 使用选定金额基数；不以包裹数量代替金额 |

例如一票三件，仅一件长度超过阈值：每命中包裹 40 元，收费 40 元；每票 40 元，同样收费 40 元；每计费 kg 3 元且整票计费重 8 kg，则收费 24 元，而不是只取超长那一件的重量。

偏远费“每票一次”只对单条规则成立。两条不同代码、同时生效、没有互斥设置的偏远规则，仍可能各收费一次。应通过价卡范围、有效期或规则组避免意外重复。

报价阶段不收地址更正、再派送、退件等待确认费用，界面可能提示潜在费用。提示不代表已发生、已入账或已经为客户锁价。

# 10　叠加、取高、豁免与规则发布
## 10.1 规则计算顺序
先计算固定金额类规则并处理组内取舍，再将其中允许参与燃油的费用加入扩展基数，最后计算百分比类规则。百分比费用不会互相递归计收。自主前程与注入费用不会自动进入末端燃油基数；若真实合同要求对前程计燃油，应另行扩展前程费率模型，不能把当前末端燃油规则当作全程燃油。固定费用组与百分比费用组分别处理，不用于跨类型比较“哪个更高”。

“叠加”保留全部命中规则；“取高”保留转换到价卡币种后金额最高的规则，金额相同再比较优先级；“按优先级”保留最高优先级规则，最高并列会阻止确定结果。重叠的同一组应保持组合方式、阶段和费用类型一致。

## 10.2 客户豁免的可复核做法
1. 将普通收费规则与客户豁免规则放入同一个“按优先级”组。
2. 普通规则覆盖正常客户范围；豁免规则仅选目标客户，保持价卡、触发条件及日期正确。
3. 豁免规则金额设为 0、最低金额设为 0，并设置更高优先级。
4. 用目标客户和普通客户各试算一次。目标客户应显示零金额豁免依据，普通客户仍正常收费。

不能只把普通规则停用来实现单个客户豁免，这会影响其他客户。也不能把零元豁免放入“取高”组，因为普通正金额规则仍会胜出。

## 10.3 编辑与验证
Surcharge 附加费 → 规则列表 → 新建／复制 → 适用范围 → 触发与计费 → 叠加与生效 → 填写原因 → 保存并确认启用状态。新建、复制通常从停用草稿开始；保存成功不等于所有场景都已生效。

在“附加费试算”选择价卡、客户、地址类型、日期和包裹；多注入采购价卡还须选择对应注入方案；需要验证事后费用时切换账单确认并勾选事件。该页使用同规格多件输入，异规格多件应在完整报价／创建订单页验证。参数变化后重新试算，最后查看“版本与变更”确认保存记录。

# 11　附加费、最低收费与币种案例
以下均为独立教学参数，不是承运商费率。除明确说明外，金额币种为 CNY，未列出的费用为零。

| 案例 | 输入与步骤 | 结果 |
| --- | --- | --- |
| 最低收费 | 两件基础费各 20；每票最低 100；补差 60；燃油仅按 100 的 12%；操作费每件 3 | 40＋60＋12＋6＝118.00 |
| 扩展燃油 | 最低补差后基础 100；固定费 20 且参与燃油；燃油 10% 按扩展基数 | 100＋20＋12＝132.00 |
| 互斥取高 | 两条命中固定费 25、40，位于相同取高组 | 仅收 40.00 |
| 旺季公斤费 | 生效期内、整票计费重 1.3 kg；每计费 kg 3 元 | 3.90 |
| 美元最低费 | 原始附加费 USD 10；规则最低 USD 12；价卡 CNY；汇率 7.18 | 12×7.18＝86.16 |
| 美元封顶费 | 原始规则金额 USD 30；最高 USD 20；价卡 CNY | 20×7.18＝143.60 |
| 事后地址更正 | 报价基础总额 100；更正费 15，账单确认阶段 | 首报 100；确认事件试算 115 |

金额限制先在规则自身币种内作用于整条费用，再四舍五入到分；随后换算到价卡币种并再次保留两位小数。百分比规则先将金额基数折到规则币种后计算比例，再应用该规则的最低／最高金额。

整张价卡的最低收费只补基础运费，不保证最终全包价恰好等于最低金额；附加费在最低补差之后继续增加。每条附加费的最低金额也是规则级限制，不是每件分别应用最低额。

USD 价卡总额转为 CNY 时，使用当前演示 USD/CNY 汇率。采购和销售先独立完成本币计费，再比较统一币种；不能把采购 USD 数字直接从销售 CNY 数字中扣除。

# 12　报价试算、方案选择与毛利
入口：报价试算 → 客户、产品、始发地址、目的地、计划交货／注入日期与当地时间 → 货物、地址类型及逐件包裹 → 计算。可限定渠道、注入方案；选择全部时逐方案比较。同一渠道有多个注入方案时，每个方案独立列出。

| 检查对象 | 当前主要条件 |
| --- | --- |
| 客户与产品 | 启用、国家与货物符合；单件实重不超产品上限 |
| 渠道与方案 | 产品关联、启用、节点可用、始发前缀和目的地覆盖、日期有效、未超过当地截单 |
| 采购商业关系 | 有效供应商与合同；账户对应、合同币种一致 |
| 采购价卡 | 按渠道／合同／方案／国家／日期得到唯一已发布卡，并解析其采购 Zone |
| 销售价卡 | 按产品／客户／国家／日期选择专属价优先，否则标准价；独立解析销售 Zone |
| 地址与包裹 | 清单范围有效、未禁运，重量进位后有相应阶梯 |
| 经济与资源约束 | 完整成本下毛利达标、额度覆盖售价，渠道和方案票数容量可用 |

预估毛利＝销售 CNY 总额－完整采购 CNY 总额。预估毛利率＝预估毛利÷销售 CNY 总额×100%。这不是在成本上加价的加成率。实现先保留两位小数再与门槛比较，等于门槛可通过；销售为零时按 0% 处理。

最低采购成本策略比较前程、注入操作、网络段基础运费及适用附加费之和。最短运输时效使用方案时效范围的起始天数，相同再比成本；不使用工作日日历、节假日、实时拥堵或历史准时率。Zone 数字小不意味着完整成本低。

输入时间按候选节点时区的当地时钟解释，不进行时区转换。18:00 截单时，18:00 可通过，18:01 拒绝；超过截单不会自动顺延到次日。要比较同一绝对时刻跨时区注入，应在真实系统中加入带时区时间戳与运输计划推算。

渠道容量按同渠道、同业务日期票数占用；方案容量进一步按同注入方案统计。明确失败和取消不占用，结果未知占用；一票多件仍算一票。预览不锁定容量，创建前重新校验。旧种子订单缺少方案身份时，无法完整归属到方案容量，不能把它当作真实运力台账。

新订单保存节点、方案、合同起点、分区版本、映射、价卡、附加费、汇率与决策副本。修改输入或配置后需重新试算；历史快照不随新规则改变。旧演示订单缺少的证据不会被补造。

# 13　创建订单：三个步骤
## 13.1 客户与包裹
选择客户、国家、产品、始发国家与邮编、计划交货／注入日期与当地时间、目的地邮编、货物类型及地址性质。需要只查看一个方案时使用渠道和注入方案筛选。逐件输入实重、长宽高、品名、HS、数量、申报金额和原产地；支持最多 20 件，异规格包裹应分别录入。重量必须为正，尺寸须完整。

当前每件包裹只有一组报关品项字段；数量表示该品项数量，不表示包裹件数。HS 仅检查 6—10 位数字格式，不确认商品归类正确；默认棉 T 恤、编码和申报数据只是示例，必须按实际教学内容替换。

可保存为草稿后返回修改。草稿不生成真实运单，不占用客户报价额度；继续创建时应再次试算。

## 13.2 报价选择
逐候选查看节点与控制范围、合同计费起点、采购 Zone、销售 Zone 及地址清单；比较前程与网络段成本、销售、毛利、计费重和附加费；展开被拒绝方案的原因。点击报价卡选择的是渠道＋注入方案＋采购／销售价卡的组合。若没有报价，先检查日期、区域、重量、合同、毛利和额度，不要靠重复点击绕过约束。

## 13.3 确认创建
补齐收件人、详细地址、城市和联系电话，核对包裹及收费，完成确认。系统会重新检查费用和配置变化；发生价格或版本变动时应返回重新确认。

| 演示结果 | 订单表现 | 下一步 |
| --- | --- | --- |
| 成功 | 生成演示运单及逐件信息，进入待交运 | 核对件数后进入交运 |
| 超时／结果未知 | 不确定是否已创建，不提供可用真实运单 | 使用结果核实流程，不能直接重复采购 |
| 明确失败 | 记录失败，不保留该次信用占用 | 查明原因后再处理业务 |

不要把返回页面、刷新或重新点击视为取消。需要取消时使用订单支持的取消入口，并核对最终状态。承运商真实幂等、查单和撤销接口尚未接入。

# 14　订单中心、导入与导出
订单中心可搜索、筛选、打开详情并查看草稿。详情包含订单概览、逐件数据、成本与决策、执行记录及任务。核对一票多件时，以包裹明细为准，不用主单号推断所有包裹已经签收。

## 14.1 CSV 导入
入口：订单中心 → 导入 → 选择 CSV → 预检 → 查看有效行与错误行 → 导入有效草稿。文件不超过 1 MiB、最多 500 行数据；一行生成一个单件订单草稿。

| 必需表头 | 示例 | 说明 |
| --- | --- | --- |
| reference | TRAIN-001 | 客户参考号；文件内及已有草稿／订单中不得重复 |
| customer | 星河跨境 | 必须与已有客户名称匹配 |
| country | 美国 | 使用支持的国家名称 |
| postal | 90001 | 按国家校验；文本格式保留前导零 |
| weight_kg | 0.8 | 正数，转换为克时取整数 |
| length_cm | 25 | 正数 |
| width_cm | 18 | 正数 |
| height_cm | 10 | 正数 |

表头名称必须准确；按名称读取，列顺序可调整。CSV 单行示例：TRAIN-001,星河跨境,美国,90001,0.8,25,18,10。此示例顺序与上表一致。

导入不包含完整收件地址、逐件多品项报关、货物类型或显式产品选择。原型按目的地已有数据初始化产品与演示日期，品名等也使用默认值。导入文件也没有注入点或分区列，不会固定 Zone；打开草稿后补全始发、计划交货日期／时间并选择有效方案。导入后必须逐项核对、补全并重新报价，不能直接当作完整生产订单。

## 14.2 导出注意
订单导出可用于教学记录，面单导出按包裹展示。当前订单 CSV 的“单件重量kg”是遗留表头：新订单存储的该值实际为整票总实重。使用包裹明细复核，切勿再乘件数。发现错误导入行时修正源文件，仅重导尚未存在的参考号。

# 15　揽收、交接与实际注入事实
入口：揽收与交接 → 选择同渠道、同交货／注入方案的待交运订单 → 核对订单数、包裹件数和实重 → 填写交接参考号与实际件数 → 确认交运。

同一渠道的 LAX 和 EWR 方案必须分批。旧订单没有方案身份时标为历史未记录，不能当作已知注入点与新订单混批。实际件数须与期望件数一致；短少或重复时先核查实物和选择，不填虚假件数。

| 交运字段 | 业务含义 |
| --- | --- |
| 订单数／包裹件数 | 本批票数及各票包裹数量之和 |
| 实重 | 包裹实重汇总，不是采购或销售计费重 |
| 渠道／注入方案 | 执行采购渠道、计划方案及节点代码，导出时保留关联 |
| 交接参考号 | 交接凭据的关联编号 |
| 操作人／时间 | 在原型中登记该动作的人与时间 |

确认后记录批次并进入运输中演示状态。这不等于承运商真实扫描，也不会自动登记“实际注入已经发生”。面单标记 DEMO／NOT FOR SHIPPING，逐件核对即可，不用于真实发货。

## 15.1 登记实际节点与费用差异
订单详情 → 执行与处理 → 登记实际节点与费用差异。只在具有运输事实的适用状态开放。选择实际节点、实际发生日期，填写凭据编号和情况说明后保存。

系统在同渠道、同合同范围内寻找该节点的唯一方案，按实际日期及当前保存的价卡、分区和附加费重算采购；保存独立的事实与重算快照。原采购、原销售、原报价快照均保留，不自动补收客户或改写订单采购金额。

若实际节点没有匹配方案、价卡不唯一、方案未生效或缺价，仍可保留事实与“需人工核价”原因。该重算不是历史合同的时间旅行，也不是供应商正式账单；不重新采购，不自动改派，不预订新设施。

已发生运输不能软件回滚。后续退运、拦截、改派和账单调整，应分别依据承运商确认与财务流程处理；记录实际节点不意味着有权任意改变运输路线。

# 17　异常处理与售后申请
## 17.1 下单结果未知
订单详情／异常工作台 → 打开待核实任务 → 选择核实结果。仍未知时保留待核实，不再次下单；确认已创建时补回演示运单并进入待交运；确认未创建时转为失败，释放此次信用占用。当前三种结果均为模拟输入，不是系统自动向承运商查证。

## 17.2 一般异常任务
指定负责人，记录问题、证据和下一步；需要继续处理时保留任务，已经完成时填写完成说明。完成任务不会自动把包裹改成已签收，也不会代替退运、改派或赔付。

待交运订单可按页面支持取消，确认后变为已取消并释放此次额度占用。已交运订单应进入售后处理；不要通过修改订单软件状态否认实际运输已经发生。

## 17.3 退件与索赔
退件与索赔 → 新建申请 → 选择符合条件的已履约订单 → 选择退件或索赔 → 填写理由、负责人及金额 → 提交。索赔金额必须大于零。每次推进状态都应补充处理备注。

| 状态 | 操作含义与下一步 |
| --- | --- |
| 待审核 | 检查订单、诉求和资料；转入供应商确认 |
| 待供应商确认 | 等待事实、责任和处理方案；记录批准或驳回 |
| 已批准 | 记录认可的处理结果，后续可关闭 |
| 已驳回 | 记录拒绝理由，处理完毕后可关闭 |
| 已关闭 | 当前申请流程结束；不代表已支付或实物已退回 |

售后状态与运输状态分开维护。批准索赔不会自动转账，批准退件不会自动改变路由；原型没有真实供应商处理、退款或赔付接口。对账时不要把申请金额当作已经发生的财务事实。

# 18　采购账单核对与差异说明
入口：结算与产品收益 → 采购账单核对 → 录入账单 → 选择尚未录入的已确认订单 → 填写账单参考号、实际采购金额（CNY）及来源说明 → 保存待核对 → 检查差异 → 填写核对说明并保存状态。

明确失败、已取消及结果未知订单不应作为该入口的正常已确认采购记录。当前每个订单录入一笔当前采购账单，不支持多供应商、多次调账或多币种明细账单合并引擎。

| 项目 | 计算／含义 |
| --- | --- |
| 原预估采购 | 订单中的采购预估金额；有快照的新单可查看原计算依据 |
| 实际采购 | 用户录入的 CNY 金额，不由承运商接口自动获取 |
| 差异金额 | 实际采购－原预估采购；正数表示成本增加，负数表示减少 |
| 待核对 | 金额已经录入，但业务核对尚未完成 |
| 已核对 | 用户确认本笔账单；用于当前产品损益口径 |

核对顺序：先比订单和账单参考号，再比币种、重量、区域、计费日期、基础费、附加费及调整项。真实差异必须由账单与证据解释，不能只按总差额反推费用名称。

当前详情中的“重量调整费（示例）”和“附加服务费（示例）”分别将差额乘 65% 和 35%。它们只是界面演示占位，不读取真实称重或附加费规则，不能作为拆账凭证。

当前表格对负差额可能显示“—”，详情正负号也可能不够清晰。应使用实际采购减原预估的结果或带符号的导出数值，不把“—”理解为零。保存核对备注会覆盖该账单原备注，原型没有完整不可变的逐行调账账本；关键依据应保留在独立记录中。

# 19　收入、损益与客户授信
## 19.1 三种金额口径
| 视图 | 当前纳入规则与含义 |
| --- | --- |
| 报价毛利 | 销售报价减采购报价；用于选择渠道，不是已实现利润 |
| 客户销售 | 排除已取消、明确失败及结果未知订单后的确认订单收入；没有收款核销 |
| 产品损益 | 仅已核对采购账单关联订单；收入使用这些订单的销售金额，成本使用实际采购金额 |

产品损益不是全公司的净利润：没有自动纳入人工、仓租、税费、汇损、赔付及其他间接费用。没有已核对账单的订单不进入该视图；不能用全量销售收入减部分已核对成本来计算同一口径毛利。收入为零时比例不具比较意义，界面可显示“—”。

## 19.2 客户可用额度
月结可用额＝信用额度－期初已用－本次会话业务中仍占用信用的订单销售金额。预付可用额＝预付余额－仍占用的订单销售金额。占用金额使用客户销售 CNY 报价。

报价需要可用额大于或等于本单售价；草稿和试算不占用。创建成功及结果未知保留占用；明确失败不保留；确认取消释放。初始历史订单没有逐笔占用标识，其期初占用以客户“期初已用”表示，避免再次把所有历史收入重复扣减。

示例：月结额度 50,000，期初已用 12,000，没有新增占用时可用 38,000。创建售价 85.64 的订单后，可用 37,914.36；该订单确认取消后恢复 38,000。

签收或账单已核对不会自动释放信用占用。当前没有应收、收款、预付款充值流水或完整信用结算机制；客户余额与额度是演示维护字段，不代表银行资金。不要把修改余额当作实际到账。

# 23　常见问题与排查路径
| 问题 | 优先检查与处理 |
| --- | --- |
| 没有可用报价 | 查看被拒绝原因；依次查客户、产品国家、日期、价卡、区域、合同、重量、毛利、额度及容量 |
| 邮编在国家内仍无价 | 查候选方案、合同起点、分区版本与 Zone 费率；无显式合同兜底就停止 |
| 同一地址出现不同 Zone | 检查是否比较了不同合同起点或不同分区方案；这可能是正常结果 |
| Zone 2 反而更贵 | 比较完整前程、注入操作和网络段费用，不能只按 Zone 数字选 |
| 更换物理节点但 Zone 没变 | 检查合同计费起点是否仍相同；不会按节点地址擅改合同起点 |
| 导入分区后突然无价 | 导入将该方案置为草稿；核查、发布后关联价卡才恢复报价 |
| 多注入采购卡试算报缺方案 | 在试算中显式选择该卡适用的注入方案 |
| 偏远费没有出现 | 查地址清单方向、渠道／方案、日期、排除项，以及 Surcharge 的范围与互斥组 |
| 偏远费收了两次 | 查是否有两个独立有效规则；“每票”不能防止两条规则各收一次 |
| 0.501 kg 比 0.5 kg 贵很多 | 查进位后是否跨档；区间整重对整份重量使用新档单价 |
| 采购与销售计费重不同 | 查两张价卡的材积除数、进位和逐件／合票设置 |
| 燃油费不等于基础费乘比例 | 查是否包含最低补差和参与燃油的固定费，以及最低／最高额 |
| 住宅费不对 | 查住宅／商业选择，不要从地址文本或邮编自行推断 |
| 豁免仍收费 | 查客户范围、同组、按优先级、较高优先级以及最低金额是否为零 |
| 改价后旧订单金额没变 | 历史订单保留创建时快照；新配置用于新试算，旧单不自动重算 |
| 账单更正费没自动入账 | 附加费试算只展示条件计算；实际账单当前需要人工录入 |
| 已签收后额度没恢复 | 签收不等于结算；原型没有自动收款核销与占用释放机制 |
| 表上差异是“—” | 可能是负差异的显示限制；用实际减预估或导出数值复核 |
| 设置刷新后丢失 | 部分设置只有内存状态；核心业务也只在浏览器会话内保存 |
| 导入客户不存在 | 使用准确的已有客户名称；先维护客户再导入 |
| 导入后品名不对 | CSV 不含完整报关字段；打开草稿替换默认示例并补齐地址 |

持续无法复现时记录页面、订单／价卡代码、业务日期、输入包裹、错误提示、最近修改与预期结果。不要在错误报告中填写真实密码或承运商密钥。

# 24　口径限制、术语与依据
## 24.1 不宜直接用于经营判断的展示
概览“近 7 天”当前实际上使用全部订单汇总，“今天”和图表日期也以固定演示日期生成。概览预估毛利可能含失败、取消及结果未知订单；不能作为确认收入或已实现利润。“已签收占比”是当前签收订单占比，不是准时交付率；“待交运包裹”卡片数值实际为待交运订单票数。

金额使用 JavaScript 数值并在指定步骤保留两位小数，适合演示规则；未实现生产级十进制定点账务、币种精度配置、税额舍入或多国税费规则。申报金额不是自动计算关税、增值税或保险费的输入引擎。

分区发布只做本地格式、关联和日期等检查；实际查区会拦截最高优先级冲突。尚未做所有邮编组合的覆盖证明、全量重叠扫描或真实设施资格验证。映射单行保存立即增加版本并影响新报价；批量导入则转为草稿，二者的生效操作不同。

当前未实现全球邮编库、完整多品项报关、燃油指数自动更新、多币种账单行、多次调账、应收应付核销、真实标签与轨迹接口、多租户权限、后台通知和可持久化的多人业务数据库。这些应在正式产品化时另行设计与验收。

## 24.2 术语速查
| 术语 | 本手册定义 |
| --- | --- |
| Zone／地址清单 | 特定分区方案内的计价分类／附加费或禁运的地理条件 |
| 注入节点／计费起点 | 实际交付设施／合同约定用于查区的起点，两者可能不同 |
| 分区方案／起讫映射 | Zone 的命名与版本范围／从合同起点、目的地得到 Zone 的规则 |
| 实重／材积重／计费重 | 秤重／按体积换算重量／取大并按规则进位后的收费重量 |
| 价卡／Surcharge | 基础区域重量收费配置／独立的附加费用规则 |
| 最低补差 | 基础运费达到每票最低收费所需增加的金额 |
| 报价快照 | 创建当时的费用、价卡、附加费及部分决策依据副本 |
| 结果未知 | 请求结果尚未确定；不能当作明确失败 |
| 预估毛利／账单毛利 | 报价收入减报价采购／同范围订单收入减已核对实际采购 |

| 字段 | 操作与检查 |
| --- | --- |
| 名称、覆盖国家 | 名称面向使用者；报价目的地必须与产品覆盖一致 |

| 时效／承诺 | 描述服务预期；当前不会按节假日生成准确承诺到达日 |
| 启用状态 | 停用产品不参与新报价；历史订单仍保留原记录 |
| 单件最大实重 | 以 g 存储；限制每个包裹，不是整票总重 |
| 允许货物 | 普货或普货与内置电池；不能据此推断其他危险品均可承运 |
| 最低毛利率 | 以销售额为分母的百分比门槛，当前使用两位小数比较 |
| 选择策略 | 最低采购成本或最短运输时效；均先通过约束再排序 |

## A.2 客户与授信

月结填写信用额度及期初已用；预付维护演示余额。金额按 CNY 口径理解，可用额由系统扣除仍占用的订单计算，不应手工再减相同订单。联系人不触发消息发送；客户专属价格在销售价卡中维护，客户例外收费在 Surcharge 客户范围中维护。

名称用于 CSV 客户匹配，因此导入前核对拼写；内部客户 ID 用于配置关联。更改结算方式或金额后重新检查可用额，当前没有真实授信审批、付款记录或回款自动更新。

# 附录 B　供应商、合同与渠道维护
## B.1 供应商与采购合同
入口：供应商与合同 → 供应商／合同 → 新建或编辑 → 核对关联账户和日期 → 保存 → 回到采购价卡关联合同 → 完整报价验证。

| 对象／字段 | 用途与核验 |
| --- | --- |
| 供应商名称、类型 | 确认采购相对方；渠道提供方名称需要对应 |
| 协议账户 | 表示采购业务账户；不是接口密码或登录授权 |
| 账户别名 | 便于识别办公室、协议或经营主体；不改变账户匹配 |
| 供应商启用 | 停用会影响依赖该供应商的采购可用性 |
| 合同名称、供应商 | 标识本次采购依据，并明确归属供应商 |
| 合同账户 | 应与供应商配置对应；不一致会使相关采购校验失败 |
| 合同有效期 | 报价日期必须在有效期内，含起止日 |
| 合同币种 | CNY 或 USD；对应采购价卡须使用同币种 |
| 结算条件 | 记录约定文字；原型不会自动生成付款计划或应付账期 |
| 合同启用 | 关闭后影响新报价；旧订单快照不自动改变 |

合同续期后仍需检查价卡有效期；价卡延长也不会自动延长合同。存在合同不表示已取得技术接入能力。真实凭证轮换、授权和结算主体管理需要生产系统另行实现。

## B.2 渠道资源
当前支持编辑已有渠道的启用状态、时效及容量。供应商／服务信息用于查看，新增供应商不会自动新增承运商适配器或渠道。

时效填写清楚范围，例如 6—9 天；具体报价使用注入方案中的时效，只比较起始天数。渠道模板时效变更不会自动改写已保存方案，需在交货与注入方案中同步维护。每日容量按票数限制，不按公斤、件数或实时舱位计算；结果未知订单也保留占用。

# 附录 C　注入方案与分区导入操作
## C.1 节点与方案配置
先在“交货与注入方案 → 节点档案”登记节点，再切换方案页新建方案。节点代表设施，方案代表在特定采购合同下如何使用该设施。多个合同可以使用同一节点，不能因此共享价卡身份。

| 字段组 | 必填内容与检查 |
| --- | --- |
| 节点档案 | 代码、名称、国家、邮编、地址、时区、启用状态及说明 |
| 商业关联 | 采购渠道、有效合同、物理节点；币种与合同和采购卡一致 |
| 控制范围 | 自主注入，或端到端采购；按实际合同权限选择 |
| 合同计费起点 | 起点国家、邮编和条款依据；与实际节点独立保存 |
| 服务范围 | 始发国家、始发邮编前缀、目的地国家列表 |
| 时间与容量 | 生失效日期、节点当地截单时间、预计时效、每日票数容量、启用 |
| 前程参数 | 每票固定费、每 kg 单价、每件注入操作费、前程材积系数与合票进位 |
| 治理 | 变更原因及递增版本；核查关联已发布卡是否仍有效 |

端到端合同由供应商组织海外注入，不代表平台可以控制其海外节点。此模式额外前程和注入费用必须为零，防止与合同总价重复。自主注入应确认采购、实际交付资格与责任，再分别建模前程和网络段。

修改节点地址不会自动修改方案的合同计费起点；修改合同起点后应对关联方案重新查区、核价。停用节点会排除依赖该节点的新候选，不会抹掉历史订单中的节点副本。

## C.2 起讫分区 CSV
入口：国家与计费分区 → 选择方案 → 导出。按导出的十列顺序编辑再导入，文件不超过 500,000 字节。文本字段保留邮编前导零；多值用竖线分隔，数字范围使用“起点..终点”。

| CSV 列名 | 用法 |
| --- | --- |
| origin_country | 合同起点国家；目的地模式可留空 |
| origin_prefixes | 起点邮编前缀；起讫模式必填，可多值 |
| destination_country | 目的地国家；使用原型中的国家名称 |
| destination_prefixes | 目的地邮编前缀，可多值 |
| destination_ranges | 数字范围，例如 80000..87999；两端包含 |
| exclude_prefixes | 排除邮编前缀，仅排除此映射行 |
| zone_code | 所选方案内的 Zone 代码；不跨方案复用身份 |
| zone_name | 新 Zone 的可识别名称 |
| priority | 非负整数；值大优先，不按行顺序 |
| active | true 或 false，保留启用／暂停状态 |

导入先检查各行，成功后整体替换所选方案的映射、递增版本并设为草稿；其他方案保留。旧 Zone 定义保留，新 Zone 不会自动获得价格。关联价卡暂不报价，需补价、抽查典型及边界地址，再在维护方案中发布。

同一 Zone 可由多个国家的映射引用；但还需在价卡目的地范围、产品和候选方案覆盖中允许这些国家。当前内置产品、渠道以单一国家为主，不能仅加一行映射就推断具备全球服务。

# 附录 D　同址多注入：完整计算与复核
## D.1 一键复现
打开本包 HTML → 报价试算 → 点击“同址多注入” → 计算。客户星河跨境，美国产品，始发中国 200000；收件美国 10001，商业地址，普货；2026-09-10，当地 10:00；一件 1 kg，10×10×10 cm。该预设限定演示承运商 A，展示 LAX 与 EWR 两个方案。

材积重＝10×10×10÷6000＝0.166667 kg，内部向上取整为 167 g。取实重与材积重大值后为 1,000 g，按 100 g 进位仍为 1 kg，落在大于 0.5、至 1 kg（含上限）阶梯。

| --- | --- | --- |
| 物理节点／合同计费起点 | LAX／美国 90001 | EWR／美国 07001 |
| 相同目的地 | 美国 10001 | 美国 10001 |
| 采购分区方案 | 演示承运商 A 起讫方案 | 同一方案，不同起点映射 |
| 采购 Zone | Zone 8 | Zone 2 |
| 网络段基础价 | 1 kg × 78＝78.00 | 1 kg × 40＝40.00 |
| 每票最低补差 | 最低 20，补差 0 | 最低 20，补差 0 |
| 网络段操作费 | 每件 3，共 3.00 | 每件 3，共 3.00 |
| 网络段小计 | 81.00 | 43.00 |
| 前程固定费 | 18.00 | 60.00 |
| 其他前程／注入费 | 每 kg 和每件注入费均为 0 | 同左 |
| 完整采购成本 | 99.00 | 103.00 |
| 独立销售 Zone | 美国东部分区 | 美国东部分区 |

两项均通过 8% 示例最低毛利门槛。按最低完整采购成本策略选 LAX，尽管它的采购 Zone 数字更大。若去掉前程 18／60 而只比 81／43，会得到错误的选择依据。

销售基础单价已经在种子卡生成时保留两位小数：105×客户折扣 0.96×东部分区系数 1.08＝108.864，保存为 108.86。计算按已保存价卡执行，不反推一个未舍入的隐藏单价。

## D.2 前程与附加费公式
自主前程计费重＝ceil（逐件 max（实重 g，前程材积重 g）之和 ÷ 前程进位 g）× 前程进位 g。
前程与注入费用＝每票固定费＋前程计费 kg×每 kg 单价＋包裹件数×每件注入操作费。
完整采购＝前程与注入费用＋网络基础运费＋最低补差＋最终计收的网络附加费。端到端方案仅使用合同网络价卡总额，额外前程为零。

独立教学变体：仅给 EWR 加一条报价阶段、每票 10 CNY、非燃油基数的操作附加费，范围限定该方案及采购卡。EWR 网络段变为 53、完整采购 113；LAX 仍为 99。此时 EWR 毛利仅 0.86／0.76%，完整报价因 8% 门槛排除；不是附加费没有生效。单卡或附加费试算可查看收费依据，修改需保存并重新计算。

## D.3 计划与实际不一致
先按 LAX 创建成功订单，再按该方案交运；到执行与处理登记实际节点 EWR、日期 2026-09-10、凭据及原因。使用未修改初始配置时，重算采购为 103，原采购 99，差异＋4；原销售仍是 113.86。

页面保留原始报价并追加事实和重算记录。这个＋4 只是按当前保存规则复核的差异，仍需供应商实际账单确认；不能据此自动给客户补收 4 元。实际节点无合同方案或历史价卡不可用时保留人工核价提示，不能套一个相邻节点价格。

## 0. 文档控制

### 0.1 文档目标

本文件给出国际小包计费与结算平台的完整最终方案，统一回答以下问题：

1. 平台解决什么业务问题，不解决什么问题；
2. 上游 OMS、WMS、TMS、CRM、财务系统与本平台之间如何分工；
3. 承运商采购价、平台成本、客户销售价和财务应收应付如何分离；
4. 不同客户、渠道、仓库、国家、Zone、重量段和合同条款如何表达；
5. 实重、体积重、计费重量、超尺寸最低重量和多件聚合如何计算；
6. 基础费、住宅费、偏远费、燃油费、超重费和其他附加费如何组合；
7. 报价结果、业务收费认定和正式财务账如何分层；
8. 价卡如何导入、测试、审批、发布、追溯和回滚；
9. 承运商复称、复测、延迟附加费、贷项和重复账单如何对账；
10. 系统如何保证确定性、可解释性、可回放、安全性和高性能。

### 0.2 文档使用边界

本文件可以直接作为以下工作的上游输入：

- 领域模型设计；
- 数据模型设计；
- API Contract 设计；
- Rating Runtime 技术设计；
- 管理后台产品设计；
- MVP 范围拆分；
- 测试黄金样例设计。

本文件不是最终数据库 DDL、OpenAPI 文件或代码级实现说明。字段精度、索引、事务边界和错误码应在后续专项文档中冻结。

### 0.3 版本决策

V1.2 相比 V1.1 完成以下结构性修订：

- 采购定价与销售定价不再使用错误的单链继承；
- 将计算结果、业务费用认定和财务账本分为三层；
- 将费用的 Scope、Basis、Method 完全分离；
- 增加多件包裹计费聚合策略；
- 将物理测量事实与承运商计费认定事实分离；
- 增加几何计算策略；
- 增加承运商公布价、折扣矩阵和最低净收费模型；
- 增加系统上下文、数据权属和集成边界；
- 增加多租户、安全、职责分离和字段级权限；
- 增加对账容差、账单修订、Credit Note 和 Debit Note；
- 增加双时间版本语义；
- 优化编译计划复用，避免客户与渠道组合爆炸。

# 第一部分：执行摘要与系统边界

## 1. 最终结论

国际小包业务最合适的方案不是万能规则引擎，也不是简单的 Excel 价卡数据库，而是：

> **以渠道产品和客户合同为入口，以版本化价格目录和计费策略为配置基础，以确定性 Rating Runtime 为计算内核，以费用认定、财务账本、周期结算和承运商对账形成商业闭环的独立定价基础设施。**

完整能力组合如下：

```text
产品准入
+
价格目录
+
合同策略解析
+
确定性单票计费
+
报价管理
+
费用认定
+
财务费用账本
+
周期性结算
+
承运商账单复核
+
价卡治理
```

系统核心边界：

```text
渠道产品决定：能不能走
价格目录决定：可用的公布价、净价、费率和指数是什么
客户合同决定：使用哪套销售方案、测量口径和商业条款
Rating Runtime 决定：本次请求如何得到确定性价格明细
Quote 决定：向客户承诺什么价格以及有效到何时
Charge Assessment 决定：业务上最终认定应收或应付哪些费用
Financial Ledger 决定：哪些费用正式形成财务债权债务
Settlement 决定：周期返利、最低承诺和月度调整
Reconciliation 决定：承运商实际账单是否正确、差异由谁承担
```

## 2. 系统范围

### 2.1 范围内

- 承运商和运输产品；
- 起运仓、服务路由和目的地区域；
- 渠道准入和重量尺寸限制；
- 采购价格、内部价格和客户销售价格；
- 重量 × Zone、国家 × 重量、首重续重和阶梯价格；
- 体积重、实重、计费重量和最低计费重量；
- 包裹级、票级、多件和多段费用；
- 住宅、偏远、超重、超尺寸、不规则包装、燃油、签名等附加费；
- 客户合同、参数覆盖、费用豁免和价格绑定；
- 报价、预估成本、实际成本和客户账单；
- 多币种与汇率快照；
- 月度返利、最低消费和周期结算；
- 承运商账单导入、匹配、差异和争议；
- 价卡导入、校验、回测、审批、发布和回滚。

### 2.2 范围外或通过外部服务提供

除非后续专项立项，本平台不直接负责：

- 订单履约和订单状态主数据；
- 仓库作业和出库执行；
- 运输轨迹和节点跟踪；
- 面单购买和承运商下单；
- 商品完整主数据；
- 通用财务总账；
- 银行收付款；
- 复杂进口关税计算引擎；
- 通用工作流平台；
- 面向所有行业的规则引擎。

税费、关税和 DDP 垫付费可以作为外部计算结果接入，也可以在后续扩展为独立 Tax & Duty Context，但不得与基础运费计算混在一个不可治理公式中。

## 3. 核心设计原则

### 3.1 领域化而非无限通用化

采用有限、稳定、可组合的国际小包领域能力覆盖绝大多数业务。真正无法表达的少数算法通过受控函数扩展，而不是开放任意脚本。

### 3.2 确定性

相同的输入快照和版本集合必须得到完全相同的结果。单票计费不得依赖人工审批、非确定性推理、未版本化远程配置或运行中的月累计状态。

### 3.3 计算与财务分层

计算出一个金额，不代表已经形成应收或应付。必须分离：

```text
Rating Evaluation
→ Quote / Estimated Result
→ Charge Assessment
→ Financial Posting
```

### 3.4 成本与销售分离

采购价和销售价是两个独立价格域。销售价格可以独立定价，也可以显式引用采购计算结果进行加价，但不能通过隐式继承将两者耦合。

### 3.5 规则版本不可变

已发布版本不可直接修改。所有更正必须创建新版本，并保留业务生效时间和系统记录时间。

### 3.6 结果可解释

任何金额必须能够追溯至：

- 输入事实；
- 数据来源；
- 合同与策略解析结果；
- 价表条目；
- 费用基数；
- 费率；
- 舍入过程；
- 规则与函数版本。

### 3.7 单票计费与周期结算分离

单票 Rating 只处理当前运单可确定的费用；月度货量返利、最低承诺和周期佣金由 Settlement 单独计算。

### 3.8 配置优先但不追求零代码

建议覆盖比例：

| 能力 | 建议占比 | 维护角色 |
|---|---:|---|
| 标准价表和标准策略 | 65% | 运营 |
| 参数化合同覆盖 | 20% | 运营/产品 |
| 决策表 | 10% | 高级运营/产品 |
| 受控函数 | 5% | 研发 |

# 第三部分：产品、价格目录与合同模型

## 6. Product & Eligibility

### 6.1 核心对象

```text
Carrier
CarrierAccount
ServiceProduct
ServiceRoute
Warehouse
DestinationCoverage
ServiceConstraint
ProductCapability
RestrictedCommodityRule
```

### 6.2 Service Product

一个服务产品至少描述：

- 承运商；
- 承运商账号；
- 服务代码；
- 服务等级；
- 起运仓或起运区域；
- 目的国家和区域；
- 住宅、商业、PO Box 支持；
- 单件或多件能力；
- 重量、尺寸、体积和周长限制；
- 签名、成人签名、退件和改址能力；
- 禁限运品；
- 生效和停用时间。

### 6.3 准入结果

准入检查必须先于计费，输出结构化结果：

```json
{
  "eligible": false,
  "reason_code": "MAX_LENGTH_EXCEEDED",
  "actual": {"value": 112, "unit": "IN"},
  "limit": {"value": 108, "unit": "IN"},
  "constraint_version": "UPS-GROUND-CONSTRAINT-V4"
}
```

准入失败不应返回一个“高价”代替不可承运状态。

## 7. 价格角色与价格域

### 7.1 价格角色

```text
CARRIER_TARIFF
承运商公布价或标准价

BUY
平台采购成本价

INTERNAL
内部核算或组织间结算价

SELL
客户销售价

PUBLIC
对外标准报价价
```

### 7.2 采购定价域

采购成本可以通过以下方式得到：

1. 承运商净价表；
2. 承运商公布价 + 基础运费折扣；
3. 公布附加费 + 附加费折扣；
4. 最低净收费保护；
5. 合同固定价；
6. 第三方服务商传入的已确认成本。

### 7.3 销售定价域

销售价格可以通过以下方式得到：

1. 独立销售价卡；
2. 标准销售价卡 + 客户折扣；
3. 采购 Rating Result + 固定加价；
4. 采购 Rating Result + 百分比加价；
5. 采购成本反推目标毛利；
6. 采购费用透传 + 特定费用重新定价；
7. 客户专属组合价。

### 7.4 禁止错误继承

不得使用以下隐式链条：

```text
Buy Plan → Sell Plan → Customer Plan
```

正确关系是：

```text
Carrier Tariff ──可选引用──→ Buy Pricing Plan ──→ Buy Rating Result

Independent Sell Rate Plan ─────────────────────────────┐
                                                        ├→ Sell Rating Result
Buy Rating Result + Pricing Transformation Policy ──────┘

Customer Contract → 绑定 Sell Plan / Transformation / Overrides
```

销售方案引用采购结果时，必须显式声明引用关系、引用费用范围和采购版本，不得通过对象继承自动耦合。

## 8. Pricing Plan 模型

### 8.1 Pricing Plan

```text
PricingPlan
├── plan_id
├── price_role
├── owner_scope
├── carrier_account_scope
├── service_product_scope
├── route_scope
├── currency
├── valid_time
├── system_time
├── version
├── composition_mode
└── status
```

### 8.2 组合模式

```text
DIRECT_NET_RATE
直接使用净价表

PUBLISHED_DISCOUNT
公布价 + 折扣矩阵 + 最低净收费

INDEPENDENT_RATE
独立价格方案

COST_PLUS
引用采购结果后加价

TARGET_MARGIN
根据目标毛利反推售价

PASS_THROUGH_WITH_OVERRIDE
部分采购费用透传，部分重新定价
```

### 8.3 PUBLISHED_DISCOUNT 模型

```text
Published Tariff Lookup
        ↓
Base Freight Discount Matrix
        ↓
Minimum Net Charge
        ↓
Surcharge Published Rate
        ↓
Surcharge Discount Policy
        ↓
Net Buy Charge
```

示例语义：

```text
净基础运费 = MAX(
    公布基础运费 × (1 - 折扣率),
    最低净基础收费
)
```

折扣矩阵可以按以下维度配置：

- 服务产品；
- Zone；
- 重量段；
- 费用代码；
- 日期；
- 承运商账号。

## 9. 有限价表家族

系统使用有限、可校验、可编译的价表家族，不采用运行时任意 EAV 多维模型。

### 9.1 FLAT

固定金额。

### 9.2 PER_UNIT

```text
数量 × 单位价格
```

### 9.3 WEIGHT_ZONE

```text
计费重量 × Zone → 金额或费率
```

### 9.4 COUNTRY_WEIGHT

```text
目的国家 × 重量区间 → 金额或费率
```

### 9.5 REGION_WEIGHT

```text
国家组/区域组 × 重量区间 → 金额或费率
```

### 9.6 FIRST_CONTINUE

```text
首重价 + CEILING((计费重量 - 首重) / 续重单位) × 续重价
```

必须声明：

- 当重量小于等于首重时的行为；
- 续重是否向上取整；
- 续重增量；
- 最低收费。

### 9.7 TIERED_BANDED

命中一个区间后，整段数量使用该区间价格。

### 9.8 TIERED_PROGRESSIVE

不同区间分别累计计费。

### 9.9 INDEXED

基于版本化指数：

- 燃油；
- 汇率；
- 旺季费率；
- 其他公开指数。

### 9.10 PUBLISHED_DISCOUNT

公布价、折扣和最低净收费的组合价表。

### 9.11 CUSTOM_LOOKUP

仅用于少量特殊查表。必须声明固定输入 Schema、输出 Schema、覆盖检查和版本。

### 9.12 价表发布校验

- 区间不得重叠；
- 必须声明边界是否包含；
- 必须检测空档；
- 必须有明确币种和单位；
- 必须有生效时间；
- 必须检测异常跳价；
- 必须支持黄金用例。

## 15. Geometry Profile

### 15.1 目的

统一处理长度排序、尺寸取整、周长、体积和边界条件，避免不同规则各自解释尺寸。

### 15.2 结构

```yaml
geometry_profile:
  input_unit: CM
  normalized_unit: IN
  dimension_ordering: SORT_DESC
  dimension_rounding:
    stage: BEFORE_GEOMETRY_RULES
    mode: CEILING
    increment: 1
  volume_formula: LONGEST * SECOND * SHORTEST
  girth_formula: LONGEST + 2 * SECOND + 2 * SHORTEST
  irregular_shape_policy: BOUNDING_BOX
```

### 15.3 必须明确

- 长宽高是否自动降序；
- 尺寸何时换算；
- 尺寸何时舍入；
- 周长公式；
- 软包装和不规则包装如何测量；
- 边界使用 `>`、`>=`、`<` 还是 `<=`；
- 承运商扫描尺寸与仓库尺寸冲突时按什么目的选择。

# 第六部分：结果分层、报价与财务语义

## 27. 三层结果模型

### 27.1 Rating Evaluation

纯计算结果，用于：

- 即时报价计算；
- 预估成本；
- 模拟；
- 历史回放；
- 价格比较。

特点：

- 结果不可变；
- 不代表债权债务；
- 可以过期；
- 可以产生多个版本；
- 包含完整计算明细和证据。

### 27.2 Charge Assessment

业务费用认定，用于：

- 实际承运商成本认定；
- 客户最终收费认定；
- 补扣款；
- 调整；
- 争议暂挂。

特点：

- 表示业务已认定或待审核费用；
- 可以被冲销或替代；
- 不允许直接改原行；
- 可以等待财务入账。

### 27.3 Financial Charge Ledger

正式财务费用账本，用于：

```text
ACCOUNTS_RECEIVABLE
ACCOUNTS_PAYABLE
DEBIT
CREDIT
REVERSAL
WRITE_OFF
```

特点：

- 不可变；
- 通过冲销而非修改；
- 与发票、结算单和财务凭证关联；
- 不保存未被业务认定的模拟费用。

# 第十部分：验收、风险与冻结决策

## 52. 业务验收标准

- 95%以上目标价卡无需修改代码；
- 标准价卡可在一个工作日内导入、校验和发布；
- 客户差异优先通过参数和覆盖表达；
- 采购价和销售价可以独立版本化；
- 报价不自动形成财务账；
- 每个结果可解释到费用行和价表条目；
- 历史结果可按原版本回放；
- 多件聚合口径明确；
- 承运商账单差异可追溯到 Assessment 和费用代码；
- 周期返利不影响单票确定性。

## 53. 技术验收标准

- 所有金额使用 Decimal；
- 所有重量、尺寸和体积携带单位；
- 所有正式计算保存输入快照和版本签名；
- 已发布规则不可修改；
- API 支持幂等；
- 费用依赖无环；
- 策略冲突发布前发现；
- 缓存丢失不影响正确性；
- 回放一致率 100%；
- 租户数据隔离；
- 审批职责分离；
- 敏感成本字段具备权限控制。

## 54. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| 过度抽象 | 有限价表家族和标准策略 |
| 客户配置爆炸 | 基础计划复用 + 稀疏覆盖 |
| 采购与销售耦合 | 两个独立价格域，显式引用 |
| 计算结果误当财务账 | Evaluation、Assessment、Ledger 三层 |
| 尺寸边界不一致 | Geometry Profile |
| 承运商账单覆盖测量事实 | Assessment Fact 独立建模 |
| 多件计费歧义 | Aggregation Profile |
| 规则历史不可重现 | 双时间版本和不可变发布工件 |
| 对账噪声过多 | Tolerance Policy |
| 账单重复或修订 | 幂等、Revision、Credit/Debit Note |
| 计划缓存组合爆炸 | Base Plan + Sparse Override + Signature Cache |
| 成本泄露 | 租户隔离、RBAC、字段级权限 |
| 周期规则污染实时计算 | Rating 与 Settlement 分离 |

## 55. 冻结的架构决策

以下原则在 V1.2 冻结：

1. 本项目是独立国际小包领域系统；
2. 不建设万能规则引擎；
3. 单票 Rating 必须确定性；
4. 采购与销售为独立价格域；
5. 销售引用采购结果必须显式；
6. 固定宏观阶段，阶段内使用受控费用依赖图；
7. 价表采用有限家族；
8. 物理测量和承运商计费认定分离；
9. Geometry、Weight、Aggregation 分别建模；
10. Scope、Basis、Method 分离；
11. Rating Evaluation、Charge Assessment、Financial Ledger 分层；
12. 单票计费与周期结算分离；
13. 所有正式规则使用双时间不可变版本；
14. 承运商对账是核心闭环；
15. 多租户、安全和职责分离属于基础能力；
16. 事件总线可选，不是运行前提。

## 56. 前后自洽审查结果

### 56.1 价格语义审查

- 采购计划与销售计划已分离；
- 销售价可以独立或显式基于采购结果；
- 不存在隐式 Buy → Sell 继承；
- 毛利计算基于两个独立结果。

### 56.2 结果语义审查

- 模拟和报价只产生 Rating Evaluation；
- 业务确认后产生 Charge Assessment；
- 财务确认后才产生 Financial Ledger；
- 冲销和调整不修改原记录。

### 56.3 事实语义审查

- 物理测量是 Measurement Fact；
- 承运商最终认定是 Carrier Assessment Fact；
- 地址和地理分类独立版本化；
- 计算快照冻结所选事实。

### 56.4 费用语义审查

- Scope 只表示费用作用对象；
- Basis 只表示计算基数；
- Method 只表示算法；
- Fuel、Discount、Tax 等 Treatment 独立；
- 费用依赖发布时校验。

### 56.5 时间语义审查

- 业务生效时间与系统记录时间分离；
- 追溯调价创建新版本；
- 历史结果不被新规则覆盖；
- 是否追溯补差由影响分析和费用调整完成。

### 56.6 系统边界审查

- Shipment、Package、Customer 等主数据由上游系统负责；
- 本平台保存计费快照和价格事实；
- 本平台不替代 OMS、WMS、TMS 或财务总账；
- 外部系统故障不得导致使用猜测价格。

### 56.7 运行时审查

- 单票热路径无人工审批；
- 不实时访问月累计状态；
- 不依赖未版本化外部指数；
- 缓存只优化性能，不成为正确性来源；
- 同输入同版本可完全回放。

## B.4 计算

```text
实际重量 → 转换为 LB

计费重量 → 取最大值并向上取整
基础费 → WEIGHT_ZONE 查询
住宅费 → PACKAGE / FIXED
燃油费 → SELECTED_CHARGES / PERCENTAGE
```

## B.5 输出层次

```text

```

```

```

```text

```

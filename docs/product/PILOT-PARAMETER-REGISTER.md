## 当前取证状态

- 当前没有可登记的真实客户、合同、账户、线路、伙伴或业务交易；`CUST-PILOT-01`、`LEGAL-ENTITY-PILOT-01` 和 `LANE-PILOT-01` 仅是未来受控映射的预留标识，不代表实例已经存在或已经选定。
- 在真实实例提供前，只能使用 `SYN-*` 合成对象、隔离测试账户和受控模拟（`S`）验证规则、生命周期、冲突、幂等和跨客户隔离；合成结果不能升级为历史回放（`R`）或真实生产（`P`）。
- 产品设计决定仍然有效：同一货主可有预付与账期两个独立政策范围；本决定不是现实客户事实，也不选择首发生产分支。任何依赖真实合同、账户、金额、币种、时效或外部伙伴的能力继续保持 `待提供` 或 `No-Go`。

## 登记规则

- 每项真实值必须同时具有证据引用、证据责任、适用范围、版本或有效时间；口头说明和行业估算不能直接转为“已确认”。
- 机密合同、个人信息、账号凭据和受限监管资料不得复制到本文件，只登记企业级受控证据库中的文档、对象或配置标识、版本及访问责任。
- 已确认的范围约束与真实实例值分别记录。“只选择一个锚点客户”不等于具体客户已经确认。
- 一个参数存在多个候选时保持“待决策”，不得把候选列表当作当前有效值。参数变化形成新版本或新登记记录，不覆盖原证据。
- “当前登记”必须以以下一种状态开头：`待提供`、`待核验`、`待决策`、`已确认`、`本期不适用`、`已失效`；冒号后可以补充当前值或下一动作。只有证据完整且决定已经生效时才能标记为 `已确认`。
- 表内场景 ID 只说明主要影响范围；执行时仍须检查矩阵中所有引用该参数的实际场景。
- 一个参数包含多个证据组成或业务分支时，受控证据包可以逐组成核验，但本表当前状态保持保守汇总；未完成组成必须明确其适用分支和阻断范围。只有当前登记所覆盖的全部适用组成均已确认或具有权威不适用依据时，整体才能标记为`已确认`。分支局部准入不能被解释为该参数其他范围已经就绪。

### 脱敏标识与受控映射

- 共享文档中的真实客户、线路及其他敏感业务实例只使用稳定且不包含可识别实例信息的脱敏标识。可采用 `<对象类型>-PILOT-<序号>` 格式，例如 `CUST-PILOT-01`、`LANE-PILOT-01`；示例只说明格式，不表示相应实例已经确认。
- 脱敏标识只是文档与证据之间的关联键，不是客户账户、参与方、线路、节点或其他领域对象的新身份，也不得替代来源系统中的永久业务标识。
- 脱敏标识与真实实例的映射必须保存在项目文档之外、经指定的企业级受控证据库中。登记册只记录映射或证据索引的标识、版本、有效时间和访问责任，不记录真实名称、账号凭据或受限内容。
- 同一真实实例在本次试点中保持同一脱敏标识；映射更正必须保留版本历史。实例被替换时分配新标识，旧标识不得复用或改指另一实例。

### 权威证据存储

- 正式试点证据和脱敏映射采用自建 MinIO S3 兼容对象存储，并在其中建立独立的逻辑命名空间 `idp-parcel/pilot`；项目仓库只保存可审计的证据索引，不保存真实映射或受限证据副本。
- `idp-parcel/pilot` 只是证据存储边界，不是客户、参与方、线路、节点或其他领域对象的身份，也不取得任何业务上下文的数据所有权。
- 登记册中的证据索引定位到平台、命名空间、对象标识和版本；不能只引用个人持有的文件、邮件或临时链接。
- 当前没有可复用的企业 S3 兼容对象存储平台；MinIO 的建设和运维由基础设施责任方负责，不在本登记册细化。平台尚未登记前，不得把证据存储标记为已就绪。
- 具体平台、命名空间、访问责任和生效版本在 `PAR-GOV-11` 中回填；临时存储不作为正式生产证据的权威源。

## 参数就绪门槛

### 进入渠道或国家专属详细设计前

- `PAR-COM-01`、`PAR-COM-03`、`PAR-COM-05`、`PAR-COM-06`、`PAR-COM-13` 至 `PAR-COM-17` 已确认。
- `PAR-NET-01` 至 `PAR-NET-09`、`PAR-NET-12` 至 `PAR-NET-15` 已确认适用真实值；`PAR-NET-10/11` 按备用伙伴和退运是否纳入生产分别确认或登记权威不适用依据。
- `PAR-CUS-01` 至 `PAR-CUS-07` 和 `PAR-INT-01` 至 `PAR-INT-07` 已确认或具有明确本期不适用依据。
- `PAR-NFR-01` 至 `PAR-NFR-05` 已取得真实基线，不以行业估算代替。

### 进入限量生产前

- 所有 `P` 证据场景的前置参数已经确认并通过相应准入检查。
- PN-03 的生产候选分支必须已经确认 `PAR-COM-16`、`PAR-NET-13`、`PAR-NET-14` 和适用的 `PAR-NET-04..07`；使用外部场外揽收来源时还必须确认 `PAR-INT-03`。未启用的收寄模式须有权威不适用依据，不能以未配置代替。
- PN-04 的生产候选分支必须已经确认 `PAR-COM-17`、`PAR-NET-08/09/12/15`、`PAR-INT-07` 和适用的 `PAR-INT-03`；逐包裹取消、收寄后处置和取消/收寄并发必须完成 `CPS-12 S`。启用备用伙伴或退运生产分支时还必须分别确认 `PAR-NET-10/11`，未启用时登记权威不适用依据。只有场外揽收而尚未进入节点或下一运输边界的对象，不得用揽收结果冒充 PN-04 后续交接、移动或交付证据。
- `PAR-GOV-03` 至 `PAR-GOV-07` 已生效，且同一范围不存在两个生产权威写入方。
- `PAR-VIS-04` 至 `PAR-VIS-07` 已完成回放或影子校准，不把未批准规则直接用于自动建案或自动通知。
- PN-06 的生产候选分支必须已经确认 `PAR-VIS-01..09` 及适用的 `PAR-INT-03/06`；普通客户追踪必须完成授权查询和跨客户隔离，不能直接暴露内部投影。ETA 未达到质量/合同门槛时只保留内部结果，可见性缺口不得冒充延误或遗失。即使索赔/追偿不进入生产，`PAR-VIS-08` 也必须确认足以完成 `VIS-09 S` 的三个期限、最低证据、撤回/复核、外部动作、责任边界和模拟数据；`PAR-VIS-08/09` 与 `VIS-09 S` 均不得以 `N/A` 绕过，真实索赔/追偿生产分支另须确认当前有效真实参数。

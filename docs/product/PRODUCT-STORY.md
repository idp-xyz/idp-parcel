# 产品故事:卖给谁、解决什么、凭什么赢

状态:已确认的对外叙事口径。能力事实、范围与验收一律以[产品基线](./PRODUCT-BASELINE.md)、[首发开发主线](./PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)与[首发试点范围](./PILOT-SCOPE.md)为准;本文只引用不复制,不定义任何规则。它服务的是「产品就绪 = 可以演示、可以进入商务洽谈」里洽谈那一半。

## 一句话定位

IDP Parcel 是卖给**经营跨境出口小包网络的物流企业**的运营软件产品:把「客户委托 → 网络收寄 → 路由 → 运输履约 → 关务合规 → 追踪异常 → 计价 → 运营结算」的全链业务,数字化成一套可解释、可回放、可审计的多租户系统。首发对客服务形态是网络服务;目标客户群与首发范围的权威口径在[首发开发主线](./PARCEL-NETWORK-FIRST-RELEASE-DEVELOPMENT-BASELINE.md)与[首发试点范围](./PILOT-SCOPE.md)。

## 客户的痛,与我们的答法

每条痛用客户的话说,答法指向本产品真实存在的机制,不空喊。

- **渠道与规则碎片化**:每家渠道一套计费、一套轨迹、一套异常口径,产品经理靠 Excel 和老师傅经验管产品。→ 版本化登记册:服务产品、客户合同、供应商协议、价卡、参考序列、网络目录全部按不可覆盖版本受控发布,统一领域语言贯穿各限界上下文([领域上下文地图](../domain/CONTEXT-MAP.md))。
- **一票赚不赚钱,月底才知道**:报价与成本两本账,靠人拉表。→ 纯计价评价:`BUY`/`SELL` 方向隔离、逐候选评价、版本清单可复算可回放([小包计价上下文](../domain/parcel-pricing/CONTEXT.md));运输收费发生项 → 供应商预期成本 → 账单匹配 → 核销的结算链([结算与经营核算上下文](../domain/settlement-accounting/CONTEXT.md))。
- **轨迹不统一,客户问不出所以然**:每家承运商一套状态码。→ 里程碑映射版本化登记,内部投影与客户视图分层,披露按客户合同分级([全程追踪与异常上下文](../domain/visibility-exception/CONTEXT.md));映射不到的事实如实标未归类,不硬凑时间线。
- **异常靠人盯**:延误、丢件、卡关靠客服翻邮件。→ 信号 → 分诊 → 案件 → 处置请求 → 客户通知的机制链;分诊规则版本化,自动建案只来自规则命中,不来自猜测。
- **对账靠人肉**:供应商账单、客户账单两头对,差异说不清归属。→ 供应商账单到达不等于应付、匹配与审核分步;客户对账单按截单快照发布密封;真实收付显式映射后才核销。
- **多客户数据不敢开放查询**:→ 租户是最高数据隔离边界([ADR-0003](../adr/0003-group-tenant-legal-entity-customer-account.md)),客户查询按账户授权作用域隔离,运营查阅与客户披露分开授权。

## 凭什么赢

- **每个判断可解释、可回放。** 评价带版本清单,投影带版本链,决定带依据引用;重放用原版本,不读当前值。审计问「当时为什么这么判」,系统答得出——这是行业里普遍缺失的能力。
- **没有假默认值。** 未配置的参数如实答未配置([ADR-0055](../adr/0055-business-endpoint-intake-has-an-unconfigured-grade.md)),演示数据只以合成 S 层级出现并如实标注;上线那天不需要先排「开发默认值」的雷。
- **机制与实例分两半。** 产品能力(规则、判断、版本化、门禁)先行,租户的真实参数后填;换一个租户不改代码,填参数登记册。两轨制的完整决定见 [ADR-0016](../adr/0016-product-delivery-and-tenant-pilot-as-parallel-tracks.md)。
- **边界清晰,长期可演进。** 各限界上下文拥有自己的语言与数据所有权;加真实渠道对接、加 AI、换商业形态,动的都是边缘,不动内核。

## AI 路线的立场

Agent 自动运营物流业务的前提,是每个判断可解释、每条规则版本化、每次执行留记录——这正是本产品的地基本身。所以我们**不预建 AI 机制**:登记册、评价回放、执行记录就是将来 Agent 消费的接口,守住可回放可解释的红线就是对 AI 路线最好的准备。外部愿景参考见 [IDP Parcel 聚合平台 PRD(参考)](../prd/idp-prd-v0.1.0.md)与[产品战略与产品蓝图 V1.0(参考)](../reference/IDP_Parcel_Product_Strategy_Blueprint_V1.0.md),两份均非权威;后者把 MCP 归为 Agent 接口而非自主执行本身,与本节立场同向,可在对外场合引它作外部印证。

## 商业形态兼容声明

首发按软件产品卖给物流企业(租户)。若将来转向聚合平台形态——平台方自己作为运营者聚合渠道与货主——变的只是租户是谁,各上下文、租户隔离与证据纪律一个不改。定位分叉不构成架构风险,不需要预先下注。

## 今天能演示什么(如实)

- 管理台哪些页已接线,一律以 `apps/admin-web/src/page-registry.tsx` 的接线登记处为准:`liveIds` 是接线事实本身,`readinessOf` 由它派生就绪度。本文不再抄第二份名单——上一版在这里抄了页名与页数,页登记此后继续长而这一句没跟着改,于是它自己变成了旧话。就形状说,委托主链、主数据目录、运营查阅、结算与治理四族各有已接线页,读面的未配置态均已验收;数据态展示候合成种子与隔离环境读面准入。
- 演示数据一律为隔离合成 S:经登记 CLI 灌入本机库,页面如实标注,证据层级记 S,不冒充生产。
- 生产路径在接入渠道登记(`PAR-INT-01`,见[参数登记册](./PILOT-PARAMETER-REGISTER.md))之前一律 403 未配置——这是刻意的诚实,不是缺陷。
- 端到端演示动线以[合成 `S` 演示动线脚本](../design/synthetic-demo-journey-script.md)为准:那里逐步写明看哪页、取哪个端点、讲哪句,以及动线如实停住的位置与各堵墙的哨兵、成因与重启条件。本文不复述动线状态,免得再出现上一条那种旧话。

## 演进路线

- **首发**:单锚点租户试点。产品就绪(机制半边达标、可演示)与试点就绪(某租户填满实例半边并走完 PN-08)两轨并行,互不冒充。
- **中期**:多租户常规化;真实承运商/渠道对接按[渠道适配缝设计备忘](../design/channel-adapter-seams-design-note.md)的缝位逐票进入,进入判据是能指出目标客户群里常规形态的真实商业模式,外部可核的形态证据登在[竞品公开事实台账](./COMPETITOR-FACT-LEDGER.md)(引用须连该条的核对日期与核对状态一起引)。
- **远期**:AI/EER 集成,消费本产品的登记册与执行记录,不另建第二套事实。

# 类型可达性棘轮基线。每行「包 类型名」，`#` 起注释。
#
# 这里躺着的是**此刻容忍的**「生产代码顺着任何一条路都碰不到」的导出领域类型，不是「应当
# 如此」的清单。冻结它是为了让门禁能判方向：名单变长要有人写一行理由，名单里的条目失效要
# 有人剪掉。判据与量法见 production_type_reachability_ratchet_test.go 头注；它与函数名棘轮
# （production_wiring_baseline.txt）各守一族，**两边互不改写**——那边按名字前缀排除的
# `New*`、按包内裸标识符也算引用因而不响的工厂，正是这边要看见的东西。
#
# 加一条时把理由写在它上面：它经哪个导出入口才拿得到、那个入口在等谁。你在加的当下知道，
# 三个月后来读的人不知道。
#

# 为空（本目录无他人在途改动），父提交 `37bea80`；提交后在 detached worktree 上检出复验的记录在
# 票 .scratch/mechanism-executor-triage/issues/05 的 Comments。**这个 63 只对那个提交成立**，
# 下一个改名单的人在自己那一刻的 HEAD 上重数，别拿这里的数加减。
#
# 首版没有一条是「零引用的死码」：63 条**全部**至少经一个导出入口可取得，只是那个入口本身零
# 生产调用。所以每条理由行的形状都是「经 X 取得，X 在等谁」。它们分三类，先分清再读：
#   一、X 在函数名棘轮基线里——同一个缺口的类型侧影子，随 X 接线自然出名单，理由行在那边。
#   二、X 是 `New*`——函数名棘轮按前缀排除的那一格（票 mechanism-executor-triage/04 的论证），
#       这边是它唯一被看见的地方，理由行要在这里写全。
#   三、X 只有包内调用——函数名棘轮把包内裸标识符也算引用，所以那边不响；类型侧看它是包外
#       从不经手。这一类里混着「该改小写」（票 04 点名的 Resolution）与「该接执行器」两种，
#       **门禁不替它们分**，由各上下文所有者在自己的票里答。
#
# 与函数名基线同一条纪律：**理由行写「等谁、那一层何时落」，不写「切片还没到」。**

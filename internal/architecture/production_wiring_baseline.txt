# 生产接线棘轮基线。每行「包 名」，`#` 起注释。
#
# 这里躺着的是**此刻容忍的**未接线领域工厂，不是「应当如此」的清单。冻结它是为了让门禁能判
# 方向：名单变长要有人写一行理由，名单里的条目失效要有人剪掉。
#
# 加一条时把理由写在它上面——你在加的当下知道它归哪个 PN 切片、为什么现在还不接，而三个月
# 后来读的人不知道。
#
# 初版这 33 条实测于 2026-08-21，两套独立方法各数一遍同得 33 且名单逐条相同：一套是 git 侧
# 正则（排注释行、cmd 计数），一套是本门禁的 go/ast 解析。**当日随后删掉两条死代码为 31；
# 同日晚随审计票 14 新增两条（PS 载荷规范化摘要一对），现为 33；2026-09-01 随票 08 面单
# 交易域模型新增三条为 36，同日票 08 的仓储落地后重建那条接上生产调用路径剪掉，记为 35；
# 2026-09-02 随 label-channel/06 写侧编排落地剪掉面单交易那两条，现为 32**
# ——这句逐次记增减而不是只写一个数，是因为下一次增减时只改一处会让另一处变错。
#
# **而它已经错过一次，留在这里当实例。** 2026-09-02 剪那两条之前实测条目数为 34，而上一句
# 当时写着「现为 35」——某次增减只改了名单没改这句。所以上面的 32 是**剪后实测**得来的，
# 不是拿 35 减 2 算出来的；照那句算会得 33，继续错下去。逐次流水账防不住这个，它只是让
# 错误可追；**下一个改名单的人请重数一遍再改这句**。
#
# 下面那些理由行的取证强度曾经不齐：初版逐条读过签名与调用点的只有 parcel-pricing 与
# party-commercial 两组、以及 AssessSafeHandoff 与 FormSupplierExpectedCost 两条，其余按组写。
# 2026-08-24 已逐条补核（锚 b44dd51，方法与逐条结果见 production-wiring-ratchet-gate 票 01
# Comments 末条）：组注释的语义断言逐条成立；唯一例外（DecideDisclosure 的包外测试引用）与
# 几处组注释计数失配已就地改在各组注释里。
#
# 一件初版就该说清的事：这 33 条里 25 个**连 domain 包都没出过**——不只是没有生产调用点，
# 而是没有应用层用例、没有适配器、没有端口，包外零引用。按本仓机制先行实例后到的顺序，切片
# 还没开工的能力本来就该是这样。**所以这份名单不是一张缺陷清单，是一条基准线**；它里面有多
# 少是「接过线后来烂了」、多少是「切片还没到」，本门禁分不出，也不打算分。

# 入口总表

对照 main `d118b4f83`（2026-11-12），由代码读出：管理台页面取自 `apps/admin-web/src/navigation.ts`，接口取自 `cmd/parcel-api/endpoints_*.go` 的登记处。这一页是清单，不受行数上限约束；页面或接口增减时照代码重列。

它回答「产品有哪些能操作的地方，今天各能做到哪」。

**状态怎么定的**：逐页沿代码追它调到的接口，再对后端已知的缺口。

- **可用**（32 页）：页面上有写操作，页面说明的事能做完。
- **部分可用**（6 页）：能做一部分；缺的那部分或者有接口没页面，或者后端没有入口。
- **只能看**（12 页）：页面只调读口。
- **本机**（4 页）：不调后端。

这是静态分析，没有逐页点过。「可用」说的是页面接到了真实的写接口，不是每个按钮都验过。

## 有接口、没有页面的操作

后端已经有生产入口，管理台没有任何一页调它，现在只能直接调接口或走演示脚本。清关、账务、异常三组的决定口已接进各自页面的「运营决定」签（照提示填 JSON 提交，不是引导式表单），不在下表。运营决定类 71 个里有 28 个、登记类 73 个里有 22 个是这样。

| 领域 | 没有页面的操作 |
|---|---|
| 清关 | 内部合规限制的建立与逐项决定、节点关务区域登记 |
| 运输 | 运输委托的提交、换版与取消，订舱的提交与取消，段采用委托及撤回，容量池登记、预占与释放，班次与周期安排登记，装载分配，揽派任务登记，派送触发与重问，揽收与派送尝试结果确认，实际承运商首次有效收寄判断，收费发生项的登记与失效，参与终止，段关闭，承运商主单与外部承运凭证登记，监管处置承接，备用或退运旅程启动 |
| 运单 | 取消顺序冲突裁决、面单继续尝试的关闭与重开 |
| 网点 | 协作承接、送站预报时窗的登记与收口 |
| 产品与价格 | 价卡退役与后继截断、评价回放、参考目录的登记与复核 |
| 合作伙伴 | 渠道账号使用授权的登记与撤销、参与方关系替代、注册号类型的登记与停用 |

作业事实登记的 18 个接口本来就不给管理台用，由一线作业端调。

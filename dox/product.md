# 产品

## 卖给谁，解决什么

`idp-parcel` 是国际小包网络运营系统，卖给自己经营国际小包网络的物流企业，支撑它面向客户提供国际小包服务并组织实际网络履约。它不是货主运输管理系统的国际运输功能包。

**本仓开发的是卖给物流企业的软件产品，开发方不是运营企业。** 文档里的「运营企业」一律指购买产品的租户；锚点货主客户是租户的客户。价卡、客户合同、供应商协议、业务量基线都是租户与其相对方之间的文件，开发方不持有。

它把「客户委托 → 网络收寄 → 路由 → 运输履约 → 关务合规 → 追踪异常 → 计价 → 运营结算」全链做成一套可解释、可回放、可审计的多租户系统。对着租户的日常难处：

- 渠道与规则碎片化：服务产品、客户合同、供应商协议、价卡都按不可覆盖版本受控发布。
- 一票赚不赚钱月底才知道：`BUY`/`SELL` 方向隔离的纯计价评价，可复算可回放；收费发生项到供应商预期成本、账单、核销成链。
- 轨迹不统一：来源代码经版本化映射形成标准里程碑，内部投影与客户视图分层。
- 异常靠人盯：信号、分诊、案件、处置请求、客户通知分层，自动建案只来自规则命中。
- 对账靠人肉：账单到达不等于应付，真实收付显式映射后才核销。
- 多客户数据不敢开放：集团租户是最高数据隔离边界，货主账户之间业务隔离，查询按账户与对象授权。

## 首发包含什么，不包含什么

包含（这些约束的是某个租户首次上线的范围，不是长期产品能力的永久禁止）：

- 服务形态是网络服务与面单渠道服务的明确组合。两种形态分别表达责任，一份委托属哪种按其采用的服务产品版本判断。
- 一个真实锚点货主客户，另加一个只用脱敏或合成数据的受控测试账户，验证客户隔离与跨客户场景。
- 一条成熟主线路：单一起运区域、单一出口路径、单一进口路径、单一目的国或服务区域。这条约束作用于网络服务主链路；面单渠道服务以登记的渠道产品与产品—渠道映射为界。
- 混合履约：至少一个自营的集货或分拣节点，至少一个外部合作伙伴执行的干线、关务或尾程环节。
- 一个责任法人、一个客户合同结算币种、一种生产委托接入渠道、一个与现有财务系统的集成边界；每个伙伴每类事实一种主要生产数据源。
- 多份供应商价卡并存，对同一票逐候选形成 `BUY` 评价后按成本单维择优；时效只作资格，不进排序。这是内部成本决策。备用伙伴切换由系统给候选、授权业务角色确认，不自动切换。
- 关务申报由系统校验就绪，每次提交由授权业务角色明确确认。出口和进口监管舱单由责任承运商在外部形成并提交，本产品只接收外部引用。
- 异常发现、异常案件、证据保全、客户异常通知和普通货主客户全程追踪查询要生产化；退运生产化到需求、决定、关联和交接。
- 上线分三个执行阶段：历史数据回放 → 影子运行比对 → 限量生产，再以正式验收评审。阶段升级由租户责任法人指定的试点业务责任角色作 `Go/No-Go`，不随日期或指标自动升级。

不包含：

- 多条试点线路；为未来国家、客户或渠道预建未经确认的差异化功能。
- 完整 WMS。仓配履约是可选能力，在首发之外，不计入产品就绪。
- COD（向收件人代收货款本金的服务，首发试点不启用）；生产自动申报。
- 采购过程：向承运商询价、竞价、招标、授予都不做，系统从供应商最终价卡开始。
- 对客户的价格承诺：报价有效期、锁价、报价接受不进首发。
- 银行账、支付清算、法定税务、总账或完整财务 ERP。
- 客户索赔、客户赔付、追偿的真实生产闭环：保留领域边界并完成受控模拟，不要求真实发生。

## 主链与切片

主链从一份网络服务委托的提交开始。阶段不是全局状态机，每个上下文拥有自己的生命周期。

1. 委托接入、生产归属、商业解析、接受前可达性与决定：形成接受、拒绝、决定前撤回或尚未决定，接受时固定基线。
2. 接受后初始路由与复核：后续变化形成新路线版本。
3. 有效网络收寄与节点作业：客户送站或场外揽收形成收寄来源，节点形成测量、作业、集运和封签事实。
4. 适用关务控制：只阻断受门禁约束的出库、移动、交付或提交动作。
5. 取消或处置、运输履约、交付与包裹终局。
6. 普通追踪、异常与客户披露。
7. 计价与结算。

切片是产品主线，不是微服务拆分。各切片做到哪看 [README「各切片做到哪」](./README.md#各切片做到哪)。

| 切片 | 是什么 | 主责上下文 |
|---|---|---|
| PN-01 | 范围、责任与治理基础 | [pilot-governance](./contexts/pilot-governance.md) |
| PN-02 | 商业权威、生产归属、接受前可达性、委托与包裹身份 | [party-commercial](./contexts/party-commercial.md)、[parcel-shipment](./contexts/parcel-shipment.md)、[network-routing](./contexts/network-routing.md) |
| PN-03 | 接受后路由、有效网络收寄与节点作业 | [network-routing](./contexts/network-routing.md)、[node-operations](./contexts/node-operations.md)、[transport-fulfillment](./contexts/transport-fulfillment.md) |
| PN-04 | 包裹取消与收寄后处置、运输履约、交付与包裹终局 | [transport-fulfillment](./contexts/transport-fulfillment.md)、[parcel-shipment](./contexts/parcel-shipment.md) |
| PN-05 | 关务合规控制 | [customs-compliance](./contexts/customs-compliance.md) |
| PN-06 | 普通追踪、异常与客户披露 | [visibility-exception](./contexts/visibility-exception.md) |

PN-05 是控制域：可以阻断特定动作，但不产生全程统一状态。PN-08 是试点治理与跨上下文编排，不拥有委托、包裹、路由、节点、运输、关务、追踪或结算事实。代收与清分（[collection-remittance](./contexts/collection-remittance.md)）不归任何首发切片。

## 机制、产品策略、租户取值

每个切片有两半。机制半边是产品必须具备的能力，实例半边是把某个租户的真实情况填进去。两半之间还有产品策略，它和机制一样归产品交付。

| 类 | 是什么 | 开发方怎么办 |
|---|---|---|
| 机制 | 规则、判断、版本化、门禁与记录形态 | 现在就做完 |
| 产品策略 | 判断方法：文法、内置策略、连接器形态，以及随产品发布的参考配置 | 现在就做完 |
| 租户取值 | 某个租户的具体数值、对象、人与阶段决定 | 留空，拒绝默认值，那一格答`未配置` |

**分界检验**：不看任何一个租户的客户、网络、合同就能回答的判断方法，归产品策略；「这个租户具体是多少、是谁、是哪一条」归租户取值。角色模型归产品策略，人到角色的分派归租户取值。公开标准的实例数据（国家与地区码、公开注册号格式、公开承运商接口）归参考配置。

机制与产品策略怎么做：外部系统对着公开规范、沙箱或模拟源接，用演示租户 `SYN-TENANT-01` 加 `SYN-` 数据走通，证据记 `S`。演示租户由 `scripts/demo-seeds` 灌入，开发与演示共用，代码按真实租户对待它。

参考配置不是默认值：它随产品版本发布，租户显式采用某一版才生效；没采用的判断点照旧答`未配置`。租户取值属租户上线时的实施，登进[参数登记册](../docs/product/PILOT-PARAMETER-REGISTER.md)。

两个就绪是顺序关系，互不替代：

- **产品就绪**：八个首发切片的机制半边与产品策略全部达标。判据四项——骨架完整；受控案例可复算；租户取值显式未配置且产品策略有执行器；演示动线走通。
- **试点就绪**：某个租户把实例半边填满并走完 PN-08。`Go/No-Go` 由该租户作出，开发方作不了。机制达标不等于任何租户可以上生产，某租户实例进入生产只来自登记册证据加 PN-08 `Go`。

证据层级：

- `P` 真实生产：来自真实客户、合同、线路和生产配置，或明确纳入限量生产范围的真实委托、账期与外部协作。
- `R` 历史数据回放：来源可追溯的脱敏历史事实，不产生新的外部业务指令或真实金额。
- `S` 受控模拟：与生产账本和外部生产渠道隔离的合成数据、正式测试环境或受控测试账户。
- `N/A` 本期不适用：已明确排除或经证据证明不适用，必须记录依据和决定方，不能用空白代替。

`S` 只记为 `S`，不升级：产品就绪不让它变成 `P`，读了真实输入的隔离输出也不算 `P`。影子运行是执行阶段，不是第五种证据层级。
